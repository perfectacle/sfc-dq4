# 2026-10-25-54: バイキルト 와 「힘 모으기」 비트, スクルト 의 상한

앞 일지([2026-10-25-48](2026-10-25-48-stats-ai.md))에서 남긴 표 세부 가운데 バイキルト 가 켜는 비트를 어디서 읽는지, 능력치 주문의 양을 두 배로 하는 `11:$AC4C` 의 조건, 수비력 상한을 실측으로 풀었습니다. バイキルト(전투 플래그 `15`)와 ちからを ためる 계열(플래그 `1B`)은 둘 다 보통 공격 데미지를 두 배로 하고, 겹치면 네 배입니다. `1B` 는 능력치 주문의 더하는 양도 두 배로 합니다. スクルト 는 처음 수비력을 거듭 더하고 999 에서 멈춥니다. 결과는 [dq4-data-format.md](../docs/dq4-data-format.md#전투-플래그와-두-배) 에 있습니다.

## 1. 실험 틀

앞 일지와 같은 1장 필드 세이브스테이트(`work/dq4-stats/stats-cristo-field.mss`)에서 `$615A`=4 로 5장 AI 를 켜고, 조우 비교 `18:$9D09` 를 메모리에서 `CLC; NOP` 으로 바꿔 걸음마다 전투를 냅니다. 무리는 전투 시작 `18:$A11A` 에서 スライム 8마리(HP 1023)로 덮습니다. 이번에는 `statspc.lua` 의 `PCPOKE` 를 하나 더 붙여, 행동 처리 입구 `11:$8C78` 에서 전투 RAM 의 비트를 켜 두었습니다.

```sh
PCPOKE="A11A@18:6E45=00,FF,FF,FF,08,00,00,00;8C78@11:7215=20" … AT=8C78 LOG="0096,7324,7274:112" statsstack.lua
```

`11:$8C78` 줄과 다음 줄 사이에 몬스터 HP(`$7274 + 14n` 의 +10-11)가 줄어든 만큼이 그 행동의 데미지입니다.

## 2. バイキルト 비트를 읽는 곳

`$7215` 한 바이트만 읽기를 잡는 프로브 [statsram.lua](../tools/lua/statsram.lua) 를 새로 만들었습니다. probe/reads.lua 는 PRG ROM 읽기만 세서 RAM 은 볼 수 없었습니다.

```
pc=80F8 b=12 7215 n=1      (전투 시작의 초기화)
pc=9858 b=10 7215 n=233
pc=BAC5 b=11 7215 n=3
pc=9726 b=10 7215 n=2
```

거의 모두 `10:$9858` 하나였습니다. 이것은 전투원 상태 비트를 보는 공용 함수이고, 플래그 번호 `$76` 으로 바이트와 마스크를 정합니다. `10:$985A` 에서 `$76` 과 마스크를 모으니 `10`~`15` 가 Y = 5·마스크 `01`~`20`, `18`~`1C` 가 Y = 6 이었습니다. バイキルト 는 플래그 `15` 입니다. 스택을 48바이트 찍어 부른 곳을 따라가니 보통 공격 루틴의 `11:$9788`(`BRK 46 93 15`)였고, 서 있으면 `11:$9807` 이 데미지 `$7361/$7362` 를 `ASL/ROL` 합니다.

## 3. 두 배 조건 `11:$AC4C`

`11:$AC4C` 는 일행이면 플래그 `1B`(`$7216` bit3)를, 몬스터면 다른 x3 호출을 봅니다. 플래그 `1B` 를 끄는 `11:$AC2A` 는 행동마다 불리는데, 행동 ID 가 `3E`·`3F`·`F3`·`F4`(ちからを ためている, おおきく いきを すいこんだ, ちからを ためた)면 끄지 않습니다. 곧 「힘을 모은 다음 행동 하나」가 두 배입니다. 보통 공격도 `11:$90CE` 에서 같은 조건으로 두 배가 됩니다.

勇者 혼자 작전 5 로 싸운 데미지입니다(씨앗 셋을 합침).

```
없음        31~36
バイキルト  62~72 (모두 짝수)
1B          60~72, 한 번 144
둘 다       116~144 (모두 4의 배수)
```

능력치 주문은 일행 넷의 `1B` 를 켜고 작전 4 로 싸워 보았습니다. ピオリム 이 41 → 123, スクルト 가 20 → 60, スカラ 가 26 → 104 로 더하는 양이 두 배였고, 쓴 사람의 비트는 꺼졌습니다(`7216:08>00`).

## 4. スクルト 의 상한

AI 가 고른 행동을 쓰는 `13:$9110` 에서 `$75DB` 를 `22`(スクルト), 대상 `$75DA` 를 `00` 으로 늘 바꾸었습니다. 수비력 20·22·24·26 이 한 번에 20·22·24·26 씩 늘었으니, 더하는 양은 지금 수비력이 아니라 처음 수비력입니다. 약 2만 프레임 이으니 넷 모두 999 에서 멈췄습니다.

```
18332 [860, 946, 999, 999]
20884 [980, 999, 999, 999]
21628 [999, 999, 999, 999]
```

## 틀렸던 것들

- 처음에는 スクルト 를 `$75DB` 만 바꿔 강제로 썼는데, 대상이 몬스터로 남아 일행 수비력이 그대로였습니다. スカラ·スクルト 는 대상이 몬스터면 몬스터 수비력 쪽 갈래를 탑니다.
- `11:$8C78` 은 행동마다 한 번이 아니라 대상마다 여러 번 닿습니다. 행동 단위로 볼 때는 `13:$9112` 를 씁니다.

## 남은 것

- 몬스터 쪽 「두 배」 비트(`BRK 29 C3 0B`)와, ちからを ためる 행동이 플래그 `1B` 를 켜는 장면을 실제 전투로 보기. 회심일 때 バイキルト 를 건너뛰는지.
- 작전마다 7바이트 표(`13:$BB53`~), 후보 비교 `13:$AB92`, 공격 후보 점수 식, トルネコ·ライアン·アリーナ·작전 4 규칙.
- ザオラル·フバーハ·マホトラ 의 양, 몬스터 바이트 21 bit2-0, `$8D1B` bit7·`$8D9A`, `$618E` bit6·레코드 8.
