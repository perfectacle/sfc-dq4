# 2026-10-25-31: 얻는 물건 통합 표·장소별 값·숨는 가게 인물

[2026-10-25-25 일지](2026-10-25-25-shop2.md) 에서 남긴 것을 이어 풀었습니다. 상자·발밑·タンス·つぼ·대화로 받는 물건을 합친 「맵·자리 → 얻는 것·플래그」 롬 전체 표(238줄), 카지노·メダル 왕 경품과 가게 창 값을 정하는 `15:$B2F7`, 들어갈 때 숨는 가게 인물, 여관 곱수의 마차 자리와 그룹 `10` 갈래, 교회 おつげ·되살리기·물건 맡기기, 발밑 특수 이벤트 넷입니다. 결과는 [dq4-shop-format.md](../docs/dq4-shop-format.md) 에, 표는 `fc/dq4/tools/dq4chest.py loot` 에 있습니다. 새 프로브는 `fc/dq4/tools/lua/shopprice.lua`(가격 함수의 입출력)입니다.

## 1. 대화로 주는 물건 찾기

대화 스크립트 문장에는 물건을 주는 명령이 없어서([dq4-script-format.md](../docs/dq4-script-format.md)), 호출 문장이 부르는 뱅크 `15` 루틴을 봤습니다. 먼저 롬 전체에서 「아이템 넣기」 `BRK 2E 73` 과 골드 쪽으로 보이는 `BRK 4B 73`, 그리고 `JSR $B0B1` 을 찾았습니다.

```
002e73 17 11:B259 12:912B … 15:A97E 15:AA7F 15:AB48 15:AB9C 15:AEB3 15:B0BB 15:BADC 15:BEC3 1C:8863 1D:A748 1E:B5D3
004b73 7  15:9DA5 15:9EB7 15:A060 15:A091 15:A1CA 15:BAB5 15:BD9A
20b1b0 7  15:9E33 15:9E95 15:A51D 15:AC4B 15:ACBE 15:AF07 15:AF2A
```

`15:$B0B1` 은 `BRK 65 33` 으로 빈 자리를 찾고 `BRK 2E 73` 으로 넣는 「아이템 A 주기」, 바로 뒤 `$B0C2` 는 `BRK 66 73` → `BRK 30 73` 의 「빼기」 였습니다. `15:$A051`(대화 `04C`)은 ぎんのめがみぞう 를 빼고 `$70`=`61`, `$71`=`00`, A=`A8` 로 `BRK 4B 73` 을 불렀는데, 0x61A8 = 25000 이고 스크립트 대사가 「25000ゴールド」 라 `4B` 를 골드 더하기로 읽었습니다.

호출 대상 루틴을 `dq4talk.call_tags` 처럼 따라가며 이 넷과 바로 앞의 `LDA #n` 을 모으니 처음에는 `15:$AE4E`(대화 `13B`, てんくうのつるぎ)가 빠졌습니다. 루틴 첫머리의 `BRK 46 93 07` 을 3바이트로 읽어 다음 바이트 `07` 에서 해석이 끊겼기 때문입니다. [뱅크 호출 문서](../docs/dq4-bank-format.md#특수-형식)의 표대로 `x3` 형식 길이(`93` 은 BRK+4, `83` 은 +5, `C3`·`D3` 은 +4)를 따로 두니 17개 루틴이 나왔습니다. 카지노(`046`)와 メダル 왕(`15A`)은 아이템이 A 로 정해지지 않았는데, 둘 다 `15:$A988` 에서 `$07C5` = 1 로 가게 목록 로더 `15:$B217` 을 불러 그 장소의 무기 목록 줄을 경품으로 씁니다.

맵마다 인물 레코드의 스크립트에서 이 루틴을 부르는 길을 찾아 조건을 붙였고, 상자·발밑·タンス·つぼ 와 합쳐 238줄이 되었습니다.

```
uv run python fc/dq4/tools/dq4chest.py rom/dq4.nes loot | tail -1
238줄: 발밑 25, 상자 160, タンス·つぼ 27, 대화 26
```

## 2. 경품 값과 `15:$B2F7`

경품의 값을 찾으려고 メダル 왕 루틴이 고른 아이템을 넘기는 `JSR $B2F7` 을 따라가니, 뱅크 `15` 함수 `3` 이 장소마다 값을 따로 정하고 있었습니다. 그룹 `18` 은 はがねのつるぎ 10·うまのふん 2, 그룹 `22` 는 메달 1·4·6·20, `04/01` 은 표 `15:$B375` 의 코인 값, 그 밖은 아이템 가격입니다. 가게 창 그리기 `16:$AD60` 도 `BRK 03 5F` 로 이 함수를 부릅니다.

`shopprice.lua` 로 함수에 들어갈 때의 아이템과 나올 때의 값을 적으며 세 곳에서 말을 걸었습니다.

```
04/01 5A 30 / 59 500 / 22 1000 / 66 2500 / 50 4000 / 45 50000
22/00 17 1 / 4E 4 / 1C 6 / 4F 20
18/00 53 8 / 06 10
```

화면의 창 숫자도 같았습니다. 카지노에서 코인 `FFFF` 로 まほうのせいすい 를 고르면 코인이 `FFE1`, 소지품 셋째 칸이 `5A` 가 되었고, メダル 왕은 `$62A2` = 30 에 메달 1개를 들고 가면 31 이 되었다가 てんばつのつえ(1) 를 받은 뒤 30 이 되었습니다. `dq4shop.py` 의 목록 출력이 이 값(메달·코인 단위)을 쓰게 했습니다.

## 3. 대화로 받는 물건 실측

왕좌의 방 세이브스테이트에서 `talk.lua` 의 `TID` 로 왕의 대화 번호를 바꿔 돌렸습니다. `0FA`(てんくうのかぶと)는 처음엔 `$6295` 에 `10` 만 켜지고 물건이 없었습니다. 루틴 `15:$AC25` 가 `$6295` bit3 이 꺼져 있으면 일행 검사(`15:$9AF8`)를 먼저 하기 때문이라, `$6295` = `08` 로 두니 소지품에 `4B` 가 들어오고 `$6295` = `1C` 였습니다. `127` 은 `$6298` = `40` 으로 두면 さいごのカギ(`73`)와 `$6298` = `60` 이었습니다. 이런 루틴 안 검사(예/아니오, 아이템, 일행, 플래그)를 표에 「루틴 안」 으로 붙이게 했습니다.

`0AD`(たからのちず)는 예/아니오 두 번 뒤 「では　もんだいじゃ！」(`0955`)로 문제가 이어져 받기까지 가지 못했습니다.

## 4. 들어갈 때 숨는 인물

앞 일지에서 말을 걸지 못한 `16/00` 무기점과 `17/00` 떠돌이 상인을, 워프 뒤 `SLOT` 으로 불러 보니 「そのほうこうには…」(`02F0`)만 나왔습니다. 인물 표를 덤프하니 그 슬롯들의 자리가 (80,80) 이었고, `probe/writes.lua` 로 보니 맵에 들어간 지 87프레임에 `1C:$A037` 이 `$6F68` 에 `80` 을 썼습니다. `1C:$A010` 이 장소 표 `1C:$ABF5` 에서 지금 장소를 찾아 포인터 `1C:$AC8A` 로 뛰고, 그 장소 루틴이 `1C:$A035` 로 슬롯 자리 네 바이트를 `80` 으로 씁니다.

`warp.lua` 의 `AFTER` 로 그 네 바이트를 레코드 자리로 되돌리고 말을 걸었습니다.

```
16/00 슬롯 08 (17,03) 대화 055, $615A=04: cond 1 cond 1 svc 01 → $07BD = 01 02 09   표와 같음
17/00 슬롯 08 (07,17) 대화 0DA: msg 099D … → $07BD = 06 23 07 2A 33 49            표와 같음
```

## 5. 여관 곱수의 마차와 그룹 `10`

`02/00` 여관에서 `shopcall.lua AT=BFB5,BFBB` 로 1인 값과 곱수를 봤습니다. `shopcall.lua` 는 뱅크를 가리지 않아 같은 CPU 주소의 다른 뱅크 실행까지 적으므로 `bank=15` 줄만 봤습니다.

```
$6172=87, 레코드 7 +00=80                       BFBB A=01
같은 것 + $618E=20                              BFBB A=02
같은 것 + $618E=21                              BFBB A=02
$618E=20, $6172~$6173=87 88, 7·8 +00=80         BFBB A=03
```

마차 자리는 `$618E` bit5 가 켜져 있으면 셉니다. 그룹 `10` 은 밤에만 나오는 여관 인물(15,11)이 있어 주인공 Y 가 `12`·`13` 이 됩니다. `$62ED` = `90` 으로 들어가 말을 걸면 1인 값이 `0A`, 낮 인물에게 Y `1C` 에서 걸면 `05` 였습니다.

## 6. 교회와 맡기는 곳

おつげ 는 메뉴 2번째를 고르는 입력 시간을 두 번 고친 끝에 화면을 얻었습니다. ライアン 경험치 5 에서 「あと 7の　けいけんちで」 로 2레벨 경험치 12 와 맞았고, 159(2레벨을 넘김)에서는 「あと 10000000の」 이었습니다. 되살리기는 6바이트 레코드(`$616B`=`8A`)의 `+05` 를 `E2`·`C6`·`05` 로 바꿔도 셋 다 10G 였습니다.

물건 맡기기는 교회 인물의 대화 값을 `shoppoke.lua` 로 `04` 로 바꿔 열었습니다. どうぐ 를 고르면 「おかえしするとき　てすうりょうを 10ゴールド　いただきます。」 가 나오고, 「はい」 면 SRAM 에서 `$61DB` 만 아이템으로, `$61DC` 가 `FF` 로 바뀌었습니다. `15:$B3B2`·`$B3C9` 를 읽어 보관함이 `$61DB` 부터 128칸이고 장비 비트를 지워 넣는 것을 확인했습니다.

## 틀렸던 것들

- `dq4talk.brk_len` 을 그대로 썼다가 `BRK 46 93 07` 을 3바이트로 읽어 てんくうのつるぎ 루틴을 놓쳤습니다. `x3` 형식 길이는 `b2` 마다 다릅니다.
- 숨는 인물은 레코드의 조건(장·플래그 비트)으로 안 실리는 줄 알았는데, 인물 표에는 실린 뒤 장소별 루틴이 자리를 `80` 으로 지우는 것이었습니다.
- `ED` 를 처음에는 `SET` 으로 `$627D` 를 켜고 워프했는데, 도착했을 때 `$627D` 가 `00` 이라 「なにも　みつからなかった」 만 나왔습니다. 도착 뒤에 쓰는 `AFTER` 로 바꾸니 단추 이벤트가 나왔습니다.
- 원래 저장소의 `dq4shop.py people` 이 `dq4talk.alt_entries` 를 찾지 못해 멈췄습니다. 진행 목록 함수가 `dq4map.event_entries`·`records_at` 으로 옮겨 가서, `dq4shop.npc_lists` 로 감싸 두 도구가 같이 쓰게 했습니다(176곳 그대로).

## 남은 것

- 들어갈 때 인물을 숨기는 장소별 루틴(`1C:$ABF5`/`$AC8A`)이 각각 무엇을 보는지. 맡기는 곳·`05/01` 방어구·`0E/00`·`46/01` 교회·`17/00` 무료 숙박에게는 말을 걸어 보지 않았습니다.
- 그룹 `FE`(`15:$BEF4`)를 부르는 곳(세 방법으로 찾아도 없음).
- 여관 곱수에서 `$618E` bit7 일 때, 맡긴 물건 찾기의 수수료.
- 대화로 받는 물건 가운데 실측하지 않은 줄, たからのちず 문제, 맵 이벤트 `1D:$A748` 의 장소.
- 발밑 `EE` 의 이벤트 내용.
