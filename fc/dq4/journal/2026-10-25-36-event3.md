# 2026-10-25-36: 인물 블록 명령 해석기, 마차·배·열기구, 5장 끝과 엔딩

[23 일지](2026-10-25-23-event2.md) 의 「남은 것」 을 이어 풀었습니다. 인물 블록을 실행하는 `1F:$D884` 의 명령 60가지(`00`~`30`, `80`~`8A`)를 길이와 뜻까지 풀어, 롬 전체 블록 2131개를 못 읽는 명령 없이 명령 단위로 푸는 `fc/dq4/tools/dq4npcblock.py` 를 만들었습니다. 블록 명령이 메시지를 띄우고 플래그를 쓰는 장면 두 곳을 플래그를 맞춰 일으켰고, 마차·배·열기구 자리를 화면 장면으로 확인했고, 5장 끝 조건을 써 넣어 엔딩과 스태프 롤까지 갔습니다. 결과는 [dq4-npcblock-format.md](../docs/dq4-npcblock-format.md) 와 [dq4-save-format.md](../docs/dq4-save-format.md) 에 있습니다.

## 1. 처리기 표 두 개

`1F:$D884` 는 `($7060:$7080)` 의 바이트를 읽어 `31` 미만이면 `1F:$DEF5`, bit7 이면 `1F:$DF57` 의 워드로 뜁니다. 표를 펼치니 `00`~`30` 은 49개, `80` 쪽은 `80`~`8A` 11개였습니다. `8B` 자리부터는 `07AD`·`4805` 처럼 코드 바이트라 표가 거기서 끝납니다.

처리기들은 끝이 세 가지였습니다. `$DDCD`~`$DDD6`(포인터를 4·3·2·1 바이트 넘김)을 부르고 `JMP $D884` 로 같은 프레임에 다음 명령을 하는 것, 넘긴 뒤 `$DDE3`(`PLA PLA RTS`)로 이 프레임을 끝내는 것, 넘기지 않고 끝내는 것입니다. 넘기는 바이트 수가 곧 명령 길이입니다. 마지막 종류는 같은 명령을 다음 차례에 다시 하므로 `2B`(돌아다니기)·`2A`(서 있기)처럼 블록 끝에 놓이는 명령이었습니다.

```
1F:DC09  20 2e dc JSR $DC2E      27 m lo hi: [hi:lo] |= m
1F:DC0E  91 52    STA ($52),Y
1F:DC10  20 cd dd JSR $DDCD      4바이트 넘김
1F:DC13  4c 84 d8 JMP $D884      이어 감
```

이동은 `24 x y`(목표 자리, `$71A0`/`$71C0`)와 `03`(목표로 한 걸음, 닿으면 넘어감)의 짝이 1041번·1038번으로 가장 많았습니다. 고리는 `82 n`(횟수, 되돌아갈 주소 저장)과 `81`, 점프는 `83 d`(상대)·`84 lo hi`(절대), 메시지는 `26 lo hi` 였습니다. `22 n` 은 뱅크 `1C` 의 패턴을 `$0530`~`$0533` 에 두는데, 그 값을 읽는 `1F:$CA41` 이 패턴 바이트의 위 4비트를 패드 입력 `$14` 에 넣고 있었습니다. 일행을 패드를 누른 것처럼 걷게 하는 자동 장면입니다.

## 2. 롬 전체를 명령 단위로

디코더를 블록1·2 와 이벤트 목록까지 돌렸습니다.

```
블록 2131개(본문 주소가 다른 것 2117개), 명령 5010개
못 읽은 명령 0개, 블록 끝을 넘는 명령 0개
점프·부름 대상: 블록 안 명령 머리 209곳, 그 밖 263곳
```

블록 밖으로 뛰는 263곳은 모두 `84` 였고, 대상이 모두 같은 뱅크의 다른 블록의 명령 머리였습니다. 밤 블록이 낮 블록의 고리를 함께 쓰는 식입니다. 처리기 표에 있지만 롬의 블록에 안 쓰이는 명령도 `04`·`0D`·`21`·`29`·`80`·`85`·`86` 일곱 가지 보였습니다.

## 3. 실행한 명령과 맞추기

롬만 봐서는 길이가 맞는지 알 수 없어서, `1F:$D892`(명령 바이트를 읽는 곳)에 실행 콜백을 거는 `fc/dq4/tools/lua/npcblock.lua` 를 만들었습니다. 슬롯 `$51`, 포인터, 그때 걸린 PRG 뱅크와 인물 표 X·Y·방향을 적습니다. `dq4npcblock.py trace` 가 이 기록을 읽어, 실행된 주소가 디코드한 명령 머리인지, 다음 주소가 길이·점프로 예측한 것인지, `03` 을 마칠 때 `24` 의 칸에 서 있는지 봅니다.

처음 돌린 워프 기록에서 세 번 어긋났는데, 출발 맵(왕좌의 방)의 슬롯 기록을 도착 맵까지 끌고 간 탓이었습니다. 프로브가 `$63`/`$64` 가 바뀔 때 `map` 줄을 적게 하고 거기서 슬롯 상태를 지우자 어긋남이 없어졌습니다. 맵 12곳 워프와 장면 몇 개를 더해 19개 기록을 맞췄습니다.

```
기록한 명령 2027개 중 디코드한 명령 머리 2027개, 이어진 명령 1813번 중 예측과 같은 것 1813번,
목표 칸에 닿아 03 을 마친 것 231번 중 그 칸에 선 것 231번
```

## 4. 블록이 메시지를 띄우고 플래그를 쓰는 장면

2장 세이브스테이트에서 B 를 세 번 눌러 창을 닫은 상태를 출발점으로 삼았습니다. 장 시작 세이브스테이트는 머리 장면 중이라 워프가 안 됩니다. `$6284` bit6(エンドール 대회 뒤)을 켜고 `01/01` 로 들어가면 이벤트 목록 `1C:$8930` 이 실립니다. 그 슬롯 6 의 블록은 `26 88 03`, `27 08 87 62`, `2F` 입니다.

```
100 DBF8 A=03 X=06            (26: 메시지 번호를 $058A 에)
121 8656 A=88 X=03            메시지 0388 ブライ「これは　きっかいな！
345 DC0E A=08 X=06 6287=00    (27: $6287 |= 08)
629 ...            6287=08
```

`$6287` & `18` 은 2장 끝 조건이라, 빈 성의 방 두 곳에서 ブライ 의 대사를 보면 장이 끝나는 흐름으로 보입니다. 1장 쪽은 바트랜드 왕좌의 방 레코드 20 의 왕 장면(`26 0301` → `22 13` → `24`·`03` → `26 0302` → `27 10 7e 62`)을 `$627E` 를 지운 채 들어가 끝까지 봤습니다. `82 0C 01 81` 에서 `01` 이 12번 실행됐고, 끝난 SRAM 의 `$627E` 는 `10` 이었습니다.

## 5. 마차·배·열기구

`$618E` 를 읽는 곳은 뱅크 `10` 에 몰려 있었습니다. `10:$91EF` 가 `ROL` 세 번으로 bit5 를 C 에 꺼내 「마차가 있나」 를 보고, 마을에 들어갈 때 `10:$91C6` 이 아래 3비트가 0 이면 그룹과 필드 자리를 `$618F`·`$6191`/`$6192` 에 두고 1 로 합니다. 2장 상태에서 `$615A` 를 4, `$618E` 를 `20` 으로 두고 エンドール 입구로 들어가니 그대로 됐고, 나오자 다시 `20` 이 됐습니다. bit5 를 끈 채로는 아무것도 쓰지 않았습니다.

배·열기구 쪽은 `1F:$CBF8` 에서 실마리를 얻었습니다. A 를 눌렀을 때 `$42`/`$43` 이 `$6197`/`$6198` 과 같으면 `BRK 08 EF` 로 타고, `$0515` 가 2 인 동안 내리는 곳을 찾습니다. 필드 0 (67,66) 옆 (68,66) 에 열기구를 두고 한 칸 걸어 A 를 누르자 `$0515` 가 2 가 되고 산을 넘어 북쪽으로 9칸 날았습니다. `$6195`/`$6196` 은 걸어 들어가는 칸의 물체 종류가 `83` 일 때 비교하는데(`1F:$CFCA`), 물 칸 (67,67) 에 두고 아래로 걷자 `$0515` 가 1 이 되어 물 위로 나갔습니다.

## 6. 5장 끝과 엔딩

`1A:$B8C2` 는 디스어셈블러가 `ROL $EB` 로 읽었지만 실제로는 `BRK 26 EB 20` 이었습니다. `$62A1` bit5 를 보고 `$63` 이 `2D` 면 `1A:$9BFC` 로 갑니다. 그룹 `2D` 는 ルーラ 마을 레코드 `01` 의 맵이고, 레코드 번호를 장소 이름 목록에 대면 てんくうじょう 입니다.

`$9BFC` 가 부르는 `1A:$9DC9` 는 `$6288`·`$62A5` 의 bit7 을 켜고 `$618E` 를 `21`, 열기구 자리를 (`89`,`86`), `$0515` 를 2 로 둡니다. 그 뒤 `1A:$9E17` 이 `$69`/`$6A` 의 목록을 한 줄씩 읽어 맵을 싣고, bit7 이 선 줄은 `$7E00` 에 패드 바이트를 복사해 `$0530` 장치로 일행을 움직입니다. 2장 상태에서 `$615A`=`04`, `$6282`=`F0`, `$62A1`=`20` 을 쓰고 `2D/00` 으로 워프했습니다.

```
48    B815 → B8C2 → 9BFC
2505  9E17  6288=80 62A5=80 618E=21 6197=89 6198=86 0515=02
5672  map 01/00   6097 map 01/01   6413 map 01/02   9653 map 02/01   12460 map 04/00
15504 map 17/00   16974 map 15/00  17466 map 15/03  20917 map 14/02

```

맵이 바뀐 차례가 `dq4event.py ending` 이 푼 목록 10줄과 같았습니다.

## 7. 플래그 뜻 표

`flags --xref` 의 교차 참조에 장소 이름을 붙이려고, 맵 그룹 → ルーラ 마을 레코드 → 장소 이름 목록의 번호로 이었습니다. 1~4장 「どこへ」 첫 화면의 다섯 이름이 레코드 번호와 같은 순번이라 이 연결을 썼습니다. `flags --meaning` 은 한 비트 플래그 184개마다 확인한 13개는 `[확인]` 과 뜻을, 나머지는 쓰는 곳 하나의 맵·장소 이름과 대사 첫 줄을 `[추정]` 으로 찍습니다. 인물 블록 쪽 교차 참조는 바이트 모양 대신 디코더를 써서 48곳에서 51곳이 됐습니다.
