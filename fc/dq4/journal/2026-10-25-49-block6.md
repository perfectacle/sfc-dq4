# 2026-10-25-49: 블록·맵의 남은 것 — 필드 3 갈래, オーりン의 문, 목적지 바꾸기 18번

블록·맵의 「남은 것」 가운데 실험으로 갈 수 있는 것을 풀었습니다. `$65` = 3(闇の世界)에서 달라지는 곳 11곳, 4장 잠금 2 문의 `BRK 63 63 03`, 天空 장비와 せかいじゅのは 검사가 ふくろ를 보는지, 실측하지 않았던 旅の扉 두 칸과 출구 목적지 바꾸기 갈래 전부, 타일 애니메이션 프레임 순서와 `$629A` 흔들기입니다. 결과는 [dq4-block-format.md](../docs/dq4-block-format.md) 의 「타일 애니메이션」·「필드 3」·「출구 칸 연결」·「せかいじゅのは」·「문과 열쇠」, [dq4-field-format.md](../docs/dq4-field-format.md) 의 「필드 3 갈래」에 있습니다. 디코더 `dq4block.py` 의 틀린 곳 하나(`45/05` 목적지의 n)도 실측으로 찾아 고쳤습니다.

실험은 모두 1장 왕좌의 방 세이브스테이트(天空 검사만 `dq4-debugB-start.mss`)에서 [warp.lua](../tools/lua/warp.lua) 로 옮긴 뒤 툴킷 `probe/trace.lua` 를 겁니다.

```sh
DRIVER=$PWD/fc/dq4/tools/lua/warp.lua MAP=04/02 X=06 Y=0E DIR=0 \
  AFTER="615A=03;616B=89;610F=80;6114=C6" \
  SEQ="wait:30,a:6,wait:30,down:6,wait:10,down:6,wait:10,down:6,wait:10,a:6,wait:200,a:6,wait:200" \
  TAIL=4000 MAXF=900 TRACE=B381,B38E,B3A2,B3B7,B32A SHOT_DIR=$PWD/work/o1 \
  "$MESENCE" --testrunner --nes.ramPowerOnState=AllZeros "$PWD/rom/dq4.nes" "$LIBDIR/probe/trace.lua"
```

명령 창은 「はなす じゅもん / つよさ どうぐ / そうび さくせん / とびら しらべる」 2열이라, 「とびら」는 A → 아래 셋 → A, 「しらべる」는 A → 아래 셋 → 오른쪽 → A 입니다.

## 1. 4장 문: `BRK 63 63 03` 은 オーりン

`1E:$B381` 은 `$615A` = 3 이면 A=`09` 로 `BRK 63 63 03` 을 부르고, C=1 이고 문이 잠금 2 이면 `BRK 07 6F 52` 와 메시지 `BRK A5 3B` 뒤 `$B32A`(열기)로 갑니다. 메시지 03A5 를 풀어 보니 답이 나왔습니다.

```text
--- 03A5
カギが　かかっている！
▼
しかし　オーりンが　カギを　こじあけた。
```

인물 번호 `09` 는 [대화 스크립트](../docs/dq4-script-format.md#인물-번호) 에서 이미 オーりン으로 확인한 손님 번호입니다. `07 6F 52` 는 창 `52`(가게·여관과 같은 메시지 창)를 여는 호출입니다. 셋째 바이트 `03` 은 `$6E0A` 로 가서 `10:$8241`~`$82D8` 에서 일행을 셀 때의 조건이 됩니다. bit0 이면 레코드 바이트 0 bit7(살아 있음), bit1 이면 바이트 0 bit6 꺼짐을 요구하고, bit7·bit6 이 꺼져 있어 걷는 자리도 마차 자리도 셉니다. 天空 검사의 `40` 은 bit6 이라 마차를 빼는 것입니다.

`04/02` (06,0D)의 `96` 앞에서 다섯 번 했습니다.

| 넣은 것(도착 뒤) | `1E:$B38E` 의 C | 결과 |
| --- | --- | --- |
| `$615A`=3, 둘째 자리 `89`, `$610F`=`80`, `$6114`=`C6` | 1 | 03A5, `$6C0C` = `79 72 02 69`, 문 열림 |
| 같은 オーりン을 마차 자리 `$6172`(`$618E`=`20`) | 1 | 열림 |
| オーりン 레코드 바이트 0 = `00` | 0 | 열쇠 검사 `$B3B7` |
| オーりン 없음 | 0 | `$B3B7` |
| `$615A`=2 | (부르지 않음) | `$B3B7` |

## 2. ふくろ는 보지 않는 검사, 보는 검사

天空 검사(`08:$B75D`)의 효과 `66` 은 일행 레코드의 소지품만 봅니다. 디버그 B 일행에서 하늘 장비 없이 ふくろ(`$61DB`~)에 `37 44 4B 21 FF` 를 넣고 `2D/00` (0C,07)에서 위로 걸으니 `08:$B777` 에서 C=0 으로 걸렸습니다. 넣지 않은 실행과 같습니다.

せかいじゅのは 쪽 `1E:$BC20` 은 ふくろ를 봅니다. 개수는 `BRK 06 5F`(`15:$B3B2`)가 `$61DB` 부터 `FF` 까지 세고, 끝에서부터 비교합니다.

```text
ふくろ 57 FF  : 442 BC32 → 442 B43B   (받지 못함, 라이안 소지품 82 A6 FF)
ふくろ FF     : 442 BC30 → 442 B434   (라이안 소지품 82 A6 57)
```

## 3. 旅の扉 두 칸과 목적지 바꾸기

남은 旅の扉 두 칸은 예측대로였습니다.

```text
2B/00 (12,1D) 에서 오른쪽 → 63=44 64=00 44=02 45=02
3E/02 (1C,04) 에서 위   → 63=3E 64=00 44=12 45=15
```

`08:$B397` 의 갈래는 `links` 결과에서 그 목적지로 가는 칸을 골라, 칸 옆에 서서 플래그를 켜고 끈 두 번씩 밟았습니다. 처음에는 `15/03`·`34/03`·`42/01` 로 가는 칸이 없다고 봤는데, `links` 가 플래그 0·낮으로 계산해 `15/03` 은 이미 `15/02` 로, `34/03` 은 `34/02` 로 바뀐 채 찍히고 있었습니다. `exit_links(..., night=True)` 처럼 조건을 넣어 다시 찾으니 `15/00` (13,01)·`34/01` (1D,06)이 나왔습니다. 그룹 `18` 은 필드 입구 쪽(`08:$AF51`)이라 필드 0 (7C,35)에서 위로 걸었습니다.

18번이 모두 같았지만, 첫 판 디코더 예측 하나는 틀렸습니다. `45/01` (1C,12)에 `$62AA` = `02` 를 두면 디코더는 `45/07` n 2 를 냈는데 게임은 (06,0F)에 섰습니다. `45/07` 의 칸 순번을 보니 2번이 (1E,0D), 3번이 (06,0F)이고, 코드도 `08:$B41D` 에서 순번을 7 로 쓴 뒤 `LDA #$03 / RTS` 로 n 을 3 으로 돌려줍니다. `exit_special()` 을 고쳤습니다.

## 4. `$65` = 3 을 보는 곳

`$65` 를 3 과 견주는 코드를 롬 전체에서 바이트 꼴(`A5 65 C9 03` 등)로 찾으니 11곳이었습니다. 필드 3 (23,2C)에 워프한 덤프를 `compare` 로 보니 블록 표·CHR 은 0 다름인데 nametable 이 596타일이나 달랐습니다. 다른 칸은 모두 디코더가 블록 01 로 본 칸이고, 화면에는 블록 18 의 타일(`E4`~`E7`)이 있었습니다. 찾은 곳 가운데 `0F:$D487`·`$EBD9`·`$ED5C` 가 바로 그 일을 합니다.

```text
0F:D483  CMP #$01 / BNE      ; 블록 01 이고
0F:D487  LDX $65 / CPX #$03  ; 필드 3 이면
0F:D48D  JSR $C891           ; 난수
0F:D490  CMP #$FA / LDA #$18 / BCC → 18, 아니면 19
```

`Map.block()` 에 이 갈래를 넣자 차이는 상태 창 64타일과 19 로 그려진 한 칸 4타일만 남았습니다.

팔레트는 시각과 상관없이 8번 묶음이었고, 팔레트 3 돌리기를 trace 로 따라가니 RAM 은 16프레임마다 `26 06 16` → `16 26 06` → `06 16 26` 으로 돌지만, PPU 에는 `$0606`, `$0608`, `$0607` 순서로 써서 끝 덤프의 PPU 팔레트 3 이 `16 06 26`(RAM `16 26 06`)이었습니다. `1D:$8D26` 은 2프레임마다 `$7500` 번 타일부터 4타일의 스프라이트 그림을 `1D:$8D6D`·`$8DAD` 로 번갈아 바꿉니다(필드 0 에서는 0번).

`1E:$938D` 는 필드 3 으로 나올 때 인물 슬롯 `0A`~`11` 을 (22~25, 1E~20)에 둡니다. 덤프의 `$6F6A`~ 가 그 값이었고, (23,22)에서 위로 걸으니 (23,21)에서 `0F:$CFF4`(X = `02`, 슬롯 `0C`)를 지나 멈췄습니다. 화면에는 그 줄에 반짝이는 블록만 있고 인물 그림은 없어서, `45/00` 입구 앞의 보이지 않는 막이입니다.

## 5. 타일 애니메이션과 흔들기

맵 종류 `0E`(`12/00`, 블록 14)에서 `1D:$8C7D` 의 원본 주소를 찍었습니다.

```text
$3C=07 → $871E   $3C=17 → $875E   $3C=27 → $879E   $3C=37 → $87DE
$3C=47 → $881E   $3C=57 → $885E   $3C=67 → $889E   $3C=77 → $88DE   $3C=87 → $871E
```

흔들기는 처음에 도착 뒤 `AFTER` 로 `$629A` = `80` 을 넣었더니 아무 일도 없었습니다. 맵에 들어갈 때 `08:$B6BD` 가 bit7 을 끄기 때문이고, 도착 세이브스테이트에서 `eventwalk.lua` 의 `POKEAT` 로 40프레임 뒤에 쓰니 돌았습니다.

```text
41 8CF3 0508=80 0509=00 → 42 0508=81 0509=00
51 8CF3                 → 52 0508=82 0509=01
61 8CF3                 → 62 0508=81 0509=02
```

`1D:$8D1D` 의 짝 `00 00 01 FF 02 FE 04 FC` 에서 앞 값을 더한 화면이 한 프레임 보이고, 다음 프레임에 뒤 값을 더해 제자리로 돌아옵니다.
