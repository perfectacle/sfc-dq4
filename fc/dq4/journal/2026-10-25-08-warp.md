# 2026-10-25-08: 장면 이동(워프) 도구

1장 왕좌의 방 세이브스테이트 하나에서 아무 맵·필드 자리로 옮겨 조작 가능한 세이브스테이트를 만드는 `tools/lua/fc/warp.lua` 를 만들었습니다. 사용법과 원리는 [dq4-warp.md](../../dq4-warp.md) 에 있습니다.

## 1. 장소를 바꾸는 루틴 찾기

화면·인물·출구 표까지 정상으로 실리게 하려고, `$63`/`$64`/`$44`/`$45` 를 직접 쓰지 않고 게임이 맵을 바꿀 때 지나는 길에 올라타기로 했습니다. 두 전환을 다시 봤습니다.

- 문·계단: [출구와 인물 일지](2026-10-25-03-exits-npcs.md) 에서 `1B:$8050`~ 가 `$05A0` 에서 도착 자리를 옮기는 것을 봤습니다. 그 앞 `1B:$8014`(BRK `1B` 함수 0)는 슬롯 1, 슬롯 0 순서로 `$6F60`/`$6F80` 을 출구 표와 비교합니다. 슬롯 1(일행)이 출구 위에 있으면 넘어가지 않는 것으로 보입니다(코드 읽기).
- 맵 가장자리: 성 앞마당 세이브스테이트에서 필드로 걸어 나가며 쓰기를 잡았습니다.

```
0063-0065 pc=AF96 prg=22F96 first=655 n=1 addr=0065 val=00
0042-0045 pc=B093 prg=23093 first=655 n=1 addr=0042 val=A4
0042-0045 pc=B099 prg=23099 first=655 n=1 addr=0043 val=2E
```

`08:$B06A` 에 들어갈 때 스택을 찍는 프로브로 호출 사슬을 거슬러 올라가니 `0F:$CE34` → BRK `1E` 함수 2(`1E:$9155`) → `1E:$9290` → BRK `08` 함수 9(`08:$B06A`) 였습니다. `1E:$9155` 는 걸음마다 `$44`/`$45` 를 폭 `$3F`·높이 `$40` 과 비교해 밖이면 필드로, 아니면 출구 검사로 갑니다.

## 2. 올라타는 자리

- 맵: 출구 표 `$05A0` 은 RAM 이라 주인공 둘레 네 칸을 출구로 써 두고 한 걸음만 걸으면 됩니다. 그 뒤는 진짜 출구를 밟은 것과 같습니다.
- 필드: 걸음 직후 `1E:$9155` 에서 `$3F` 를 0 으로 두면 어떤 걸음이든 맵 밖이 됩니다. `$3F` 는 `$9166` 에서 바로 되돌리고, `08:$B09B` 에서 `$65`/`$42`/`$43` 을 목적지로 바꿉니다.

갈고리는 모두 그 주소에서 `$0507`(현재 뱅크)이 맞을 때만 움직이게 했습니다. 같은 CPU 주소가 다른 뱅크에서도 실행되기 때문입니다.

## 3. 확인

맵 6곳과 필드 3곳으로 옮겼습니다. 맵은 로드 직후 인물 표와 출구 표가 디코더와 모두 같았습니다.

```
== town 04/00 (11,09)
f154 도착(map) 63=04 64=00 65=00 42=A4 43=2E 44=11 45=09 28=0B
인물 표(슬롯 6~) 와 15명 중 0 다름
RAM $05A0 과 같음
```

`0E/00` 의 (15,0E) 에 위를 보고 서게 한 뒤 A 두 번으로 말을 거니 `16:$8656` 에 메시지 `07C1`(「おれは　いやだ！」)이 들어왔고 화면에도 대사 창이 떴습니다. 필드 0 의 (67,67) 에서 위로 두 칸 걸으면 입구 (67,65) 를 밟아 `04/00` 에 들어갔습니다.

## 틀렸던 것들

- `warp.lua` 를 프로브의 `DRIVER` 로 쓸 때 처음에는 `SEQ` 가 끝나면 바로 멈춰서, 프로브가 `MAXF - 1` 에 쓰는 결과 파일이 생기지 않았습니다. `MAXF` 가 있으면 거기까지 기다리게 했습니다.
