# 2026-10-26-23: 손님 동료의 AI, 쓰이지 않는 창 항목, ラナルータ·배·48/09, 시간 멈춤과 2배, 대화로 거르는 앞뒤 비트

창·블록·상점 쪽 남은 것을 게임 안에서 닫았습니다. `10:$BAE1` 은 손님 동료가 몬스터 AI 로 움직일 때 타는 갈래였지만, 고치지 않은 롬의 손님 행동 칸에는 이 갈래를 부를 주문이 없었습니다. 창 항목 `25` 와 걸러내기 `04` 는 롬 전체를 훑어 쓰는 곳이 없다는 것을 확인했습니다. ラナルータ, 물가에서 배 타기, `48/09` 갈래, `$6E44` bit7 의 나머지 두 곳, パルプンテ 의 시간 멈춤과 2배 보상은 실측했습니다. `dq4shop.py hidden` 에는 대화 스크립트의 조건으로 확인한 앞뒤 비트 관계 4쌍을 넣었습니다. 결과는 [dq4-bank-format.md](../docs/dq4-bank-format.md#83-이-도는-장면), [dq4-text-format.md](../docs/dq4-text-format.md#쓰는-창이-없는-항목-25), [dq4-field-format.md](../docs/dq4-field-format.md), [dq4-map-format.md](../docs/dq4-map-format.md), [dq4-encounter-format.md](../docs/dq4-encounter-format.md#시간-멈춤과-2배), [dq4-shop-format.md](../docs/dq4-shop-format.md) 에 있습니다.

## 1. 손님 동료는 몬스터 AI 로 움직인다

처음에는 혼란을 의심했습니다. 1장 첫 전투에서 ライアン 의 상태 플래그 `12`(`$7215` bit2)를 프레임마다 켜고 AI 루틴에 훅을 걸었는데, 「こんらんしている」(`0014`)만 나오고 전투원 0 은 뱅크 `10` 의 AI 로 들어가지 않았습니다.

그다음 손님을 넣어 봤습니다. 손님 레코드 9 를 オーりン 으로 채우고 필드 전투를 일으키는 드라이버 [guestai.lua](../tools/lua/guestai.lua) 를 새로 만들었습니다(조우 강제는 `uibattle.lua` 와 같고, 명령마다 A 를 누르며 `HOOK` 에서 `$96`·`$0B` 를 적음).

```sh
SET="616B=89;610F=80;6110=6400;6114=C6" fc/dq4/tools/dq4warp.sh work/hf2 field 0 A4 32
STATE=$PWD/work/hf2/warp.mss SET="6114=C9" HOOK="10:B497" MAXF=2500 SHOT_DIR=$PWD/work/gC9 \
  "$MESENCE" --testrunner --nes.ramPowerOnState=AllZeros "$PWD/rom/dq4.nes" "$PWD/fc/dq4/tools/lua/guestai.lua"
```

전투원 1(손님)이 `11:$8368` → `10:$ACAA` → `$AF2B` → `$B497` 을 지났습니다. 바이트 5 를 `C5`~`D2` 로 바꾸면 평가하는 행동 ID 가 그 번호의 몬스터 레코드 행동 칸과 같았습니다(`C9` = `3E 43 44`, `D2` = `6F 4F 43 52`). 손님 레코드의 바이트 5 가 곧 몬스터 레코드 번호입니다.

그런데 `C3`~`D5` 의 행동 칸에는 べホマラー·べホマズン 의 번호 `28`·`29` 가 없습니다. 메모리상 PRG 에서 레코드 `C9` 의 첫 두 칸만 `A8 29` 로 바꾸니, 다른 것을 억지로 바꾸지 않고도 손님 차례마다 `$BAE1` 이 돌았습니다.

```text
355 pc 10:B497 96=01 0B=2C
355 pc 10:BADB 96=01 0B=2C A=00
355 pc 10:BAE1 96=01 0B=2C X=01
355 pc 10:BAE6 96=01 0B=2C X=01
355 pc 10:BAE1 96=01 0B=2C X=00
355 pc 10:BAE6 96=01 0B=2C X=00
```

## 2. 쓰는 창이 없는 항목과 걸러내기 `04`

`dq4text.window_layout` 으로 창 레코드 115개의 본문과, 본문이 부르는 문자열 항목 안의 `A5` 까지 모두 펼쳤습니다. 항목 `25` 를 쓰는 창은 없습니다. 그룹 0 문자열 항목 중 `A5` 를 품은 `7E` 는 표 끝을 넘어 코드 바이트를 읽은 것이었습니다. 걸러내기 `04` 는 `$6E0A` 에 쓰는 명령 33곳을 모두 보았고, 값이 BRK 인자·`00`·`40`·`80`·되돌리기뿐이었습니다. BRK 인자 쪽에서 bit2 가 든 것은 데이터 뱅크 `0B` 에만 있었습니다.

## 3. ラナルータ 와 배

디버그 B 상태에서 ブライ 에게 ラナルータ 비트와 MP 를 주고 주문으로 썼습니다.

```text
필드 0   12:A728 C=0 → A77A      끝 62ED=8C
02/00    A77A                    끝 62ED=8C
0D/00    A728 C=1 → A77E         02C5 しかし なにも おこらなかった。
2C/00    A784                    004B しかし ここでは なにも おこらなかった！
```

やみのランプ 와 막는 조건·메시지가 같았습니다. 배는 `$6195`/`$6196` = `A8 89`, `$628E` = `01` 로 두고 필드 0 (A8,88)에서 아래로 걸었습니다.

```text
434 0F:CFD6 42=A8 43=88 0527=00
449 0F:CE7B 43=89 0527=01 0515=00   → 탐
594 0F:D01C 43=89 0527=00 0515=01   → 위로 걸어 내림
```

## 4. `48/09` 갈래

앞 기록에는 「그룹 `48` 은 `12:$B971` 표에 없다」 고 적었습니다. [dq4cpu.py](../tools/dq4cpu.py) 로 `12:$B6DD` 를 그룹 `48` 의 맵 10개 × 64×64 자리에서 돌려 보니, `48/08` 의 (09,0D) 등 네 칸이 `48/09` 로 갔습니다. 5장 시작 상태로 `48/08` (09,0E)에 워프해 위로 걸었습니다.

```text
474 1E:86AD 64=08 44=09 45=0D
486 1E:86BB 64=09 45=08 → 86C5    (48/09 갈래)
540 1D:A321                       (블록 이벤트 28)
582 1E:86BB 64=07 44=04 45=0F → 86CE
```

## 5. `$6E44` bit7 의 남은 두 곳

`13:$8094` 는 디버그 B 필드 전투에서 봤습니다. 작전 0 은 `$6E80` = `00` 이었고, `$6E44` = `80` 을 쓰면 작전 0·2 가 `06`, 작전 3 은 `03` 그대로였습니다. `10:$B0EF` 는 スライム 의 바이트 21 을 `87`(늘 혼란)로 두고 넷과 싸워 `10:$B0F8` 의 A 를 셌습니다. `00` 은 16번 중 2번이 7(にげだした)이었고, `80` 은 45번 중 0번이었습니다.

## 6. 시간 멈춤과 2배

パルプンテ 칸을 `03`(`D8`)으로 고정하고 한 번 공격한 뒤 ぼうぎょ 로 턴을 넘겼습니다.

```text
350  11:89E6 → 8A28   96=05 72E6=C0   (몬스터 차례 건너뜀)
594  11:8A0C          96=00 72E6=C0 → 80
881  11:8A0C          96=00 72E6=80 → 40
1168 11:8A0C          96=00 72E6=40 → 00
1208 msg 0189 じかんが うごきだした！
1503 msg 004C (몬스터 공격 다시)
```

`E3` 은 `$72E5` bit0 을 켭니다. 이 비트를 쓴 채 이기면 경험치 +4 → +8, 골드 +8 → +16 이었습니다(`12:$87EB`·`$8858`).

## 7. 대화로 거르는 앞뒤 비트

일지 62 에서 이야기 차례로 묶은 관계는 틀렸습니다. 이번에는 대화 스크립트가 뒤 비트를 켜는 문장에 닿으려면 앞 비트가 켜져 있어야 하는 쌍만 골랐습니다(뒤 비트를 켜는 곳이 그 하나뿐이고 앞 비트를 끄는 곳이 없을 때). 4쌍이 나왔고 `hidden` 출력에서 바뀐 줄은 `00/00` 인물 0 하나입니다. 그 쌍(`$6295` bit5 → `$6294` bit0)은 5장 `00/00` 의 ホイミン(대화 `0C9`)에게 말을 걸어 확인했습니다. `$6294` = `00` 이면 `$6295` 가 그대로였고, `01` 이면 `20` 이 되었습니다.

## 틀렸던 것들

- 「혼란한 일행은 몬스터 AI 로 움직인다」: 혼란한 ライアン 은 뱅크 `10` AI 를 타지 않았습니다. 몬스터 AI 를 타는 일행 쪽 전투원은 손님입니다.
- 「그룹 `48` 은 나가기 표에 없다」: 맵 (00,00) 에 맞는 칸이 없었을 뿐이고, `48/08`·`48/09` 의 네 칸씩이 표에 있습니다.
- ホイミン 의 자리를 도구가 찍은 십진 (10,24) 그대로 16진으로 읽고 워프해 「だれもいない」 가 나왔습니다. 실제 자리는 16진 (0A,18)입니다.

## 남은 것

- 앞뒤 비트 관계는 대화 스크립트가 켜는 비트만 봅니다. 뱅크 코드가 켜는 비트의 앞 조건은 아직 뽑지 않았습니다.
- 시간 멈춤에서 명령을 받는 `11:$834F` 의 갈래는 1명 일행이라 다른 동료가 건너뛰는지 보지 못했습니다(코드 읽기).
- 그룹 `FE` 는 대화 호출과 `RTS` 주소까지 찾아도 부르는 곳이 없습니다(정적 검색).
