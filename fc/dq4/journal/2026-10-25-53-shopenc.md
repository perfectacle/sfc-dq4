# 2026-10-25-53: 들어갈 때 옮겨지는 인물, 이벤트 전투 비트, へんげのつえ, 3장 공사비를 게임 안에서

상점·조우 쪽의 남은 세부를 풀었습니다. 들어갈 때 숨는 조건에서 진행상 나올 수 없는 조합을 걸렀고, 숨김 말고 인물을 옮기는 36줄을 덤프와 맞췄습니다. 장이 넘어갈 때 보관함이 비는 것, `$6E44` bit7(이벤트 전투)이 몬스터 HP 와 パルプンテ 를 바꾸는 것, へんげのつえ 모습이 풀리는 때와 모습 표, 장 중간 저장 칸 불러오기, 3장 공사비·가게 사기를 실측했습니다. 결과는 [dq4-shop-format.md](../docs/dq4-shop-format.md) 와 [dq4-encounter-format.md](../docs/dq4-encounter-format.md) 에 넣었습니다.

## 1. 숨김 조건에서 나올 수 없는 조합 거르기

`dq4shop.py hidden` 은 장소 루틴을 기호로 돌려 조건을 원자(플래그 비트, 장 = n, 밤…)의 곱의 합으로 줄입니다. 원자끼리 아무 관계가 없다고 보니 `[$6282&10 켜짐 & 5장]` 처럼 한쪽이 다른 쪽을 뜻하는 줄이 그대로 남았습니다.

관계는 둘만 넣었습니다. 하나는 장 시작 루틴이 `$6282` 를 장마다 `00 80 C0 E0 F0` 으로 쓰는 것(실측된 표)에서 나오는 「`$6282` bit7~4 ⇔ `$615A` ≥ 1~4」 입니다. 다른 하나는 이야기 장면 플래그(`dq4flags.STORY`)입니다. 롬에서 그 비트를 켤 수 있는 곳을 `dq4event.flag_xref` 로 세어 하나뿐이면, 그 비트가 켜져 있다는 것은 그 장면을 지났다는 뜻이므로 그 장 이후입니다. 장 끝 `1A:$B92C`~ 가 끄는 비트(`$6291` bit7, `$6288` bit7, `$6286` bit2, `$6285` bit7·6, `$6281` bit6)는 그 장 안에서만 켜져 있습니다.

```
$6286 04 3 only      ← トム 의 아들이 돌아옴. 3장 끝에 꺼짐
$6292 01 5           ← 마차 주인에게 보석을 보임
…                    (43개)
```

Quine–McCluskey 의 「나올 수 없는 칸」에 이 관계로 어긋나는 칸을 더하자 16줄이 짧아졌습니다(`1D/00` 의 `[$6292&01 켜짐 & 5장]` → `[$6292&01 켜짐]` 등). `--raw` 로 예전 출력을 볼 수 있습니다.

## 2. 옮김 36줄을 덤프와 맞추기

숨김은 앞 일지에서 (80,80) 인 슬롯으로 비교했지만, 자리·방향·간격·상태를 쓰는 36줄은 비교하지 않았습니다. 인물이 들어오자마자 걷기 시작하므로 `warp.lua` 의 끝 덤프로는 자리를 볼 수 없습니다. 그래서 장소 루틴과 장 줄(`1C:$AD32`)이 끝나는 `1C:$9EB4` 에서 `atpc.lua` 로 메모리를 떴습니다. 그때 `$0507` 이 `1C` 인 것도 확인했습니다.

`hidden G K --compare` 가 덤프의 값으로 맞는 길을 고르고, 길의 효과에서 열마다 값을 예측합니다. `$7006&FC|02` 처럼 원래 값의 일부만 바꾸는 효과는 바꾼 비트만 봅니다.

```
0F/00 낮 인물 14명, 맞는 길 1개
덤프 (80,80): [2, 3, 4, 5, 6]  예측 숨김: [2, 3, 4, 5, 6] — 같음
  인물 0 X $6F66 = 07  예측 07 — 같음
  인물 0 방향 $7006 = 02  예측 02(마스크 03) — 같음
옮김 열 4개 중 다름 0
```

36줄마다 조건이 참이 되게 장·플래그·밤을 `SET` 으로, 주인공 X·Y 조건은 도착 자리로 맞춰 29번 워프했습니다. `37/00`·`0B/00` 은 옮김 열이 하나도 안 잡혔는데, 덤프의 `$6289` 가 `00` 이었습니다. 이 바이트는 맵에 들어갈 때 지워집니다. `statspc.lua` 로 `1C:$A010` 에 닿을 때 써 넣어 다시 떴고, `2B/00` 의 `$6285` 갈래도 같은 방법으로 하나 더 떴습니다. 덤프 33개에서 36줄이 모두 한 번 이상 참이었고 옮김 열 112개가 다름 0, 숨김 298명이 모두 같았습니다.

## 3. 장이 넘어갈 때 보관함

`15:$B39C`(보관함·맡긴 돈 비우기)는 장 초기화 `12:$8EAE` 끝에서 부른다고 코드로만 보았습니다. 1장 끝 조건 플래그와 보관함 `53 06 FF`, 맡긴 돈 5 를 써 넣고 바트랜드 성 앞으로 워프해 장 끝을 일으켰습니다.

```
863 8EAE b=12 …
863 90E9 b=12 …
863 B39C b=15 … 61DB=5306FF 625B=0500
끝: 61DB ff0000 625B 0000 615A 01
```

## 4. `$6E44` bit7 을 읽는 두 곳

`10:$A4E3` 은 몬스터 칸을 채울 때 값 H(`$7E/$7F`)에서 rand((H >> 2) + 1) 을 빼는데, bit7 이면 건너뜁니다. 몬스터 HP 로 보였습니다. 1장 필드에서 전투로 가는 같은 입력에 앞 기다림만 여덟 가지로 바꾸고, HP 를 쓰기 직전의 `$7E` 를 봤습니다. `10:$A4E3` 에서 `$6E44` = `80` 을 쓴 쪽은 15마리가 모두 몬스터 표 HP 였고(スライム 8, はさみくわがた 9), 그대로 둔 쪽은 같은 몬스터가 0~2 낮았습니다.

`11:$B8A0`·`$B8AB` 는 표 둘(`$B926` 27바이트, `$B941` 15바이트) 가운데 하나에서 난수로 값을 고릅니다. 값이 `D5`~`F5`·`57` 이라 전투 행동 ID 로 보았고, 바로 앞에 `CMP #$34`(주문 パルプンテ)가 있었습니다. 처음에는 `textmodoki.lua` 의 `FORCE=34` 로 행동을 바꿨지만 처리기 `11:$AE13` 만 돌고 `$B8A0` 에는 닿지 않았습니다(5절). 이 갈래는 차례 처음의 `11:$B861` 이 행동 번호를 따로 읽어 `34` 와 비교합니다. 그래서 메모리상 PRG 에서 비교 값 `34` 를 `43`(공격)으로 바꾸고 공격을 골랐습니다.

```
보통 33번:  17:F1 0D:E3 19:F5 02:D7 … 1A:57   모두 A = $B926[X]
이벤트 25번: 07:E5 02:DB 0E:F3 …              모두 X ≤ 0E, A = $B941[X]
```

이벤트 전투에서는 행동 12가지(`D5 D7 D9 DA DC DD E0 E2 E9 ED F5 57`)가 빠집니다.

## 5. へんげのつえ 가 풀리는 때와 모습 표

`1E:$9817`(`$6296` 지우기)을 부르는 곳은 `1E:$8ED2`·`$92F9` 둘이었습니다. 앞은 `1E` 함수 01·32(필드 → 맵), 뒤는 함수 33·3E(맵 → 필드, `$41` bit7 일 때) 안입니다. `$6296`/`$6297` = `78 A5` 를 써 두고 세 가지로 걸었습니다.

| 걸음 | 지난 곳 | `$6296` |
| --- | --- | --- |
| 성 앞 → 필드 | `$92E3` → `$92EC` → `$9817` → `$97B8` | `51` → `00` |
| 필드 → 성 앞 | `$8EC5` → `$8EC8` → `$9817` → `$97B8` | `77` → `00` |
| 왕좌의 방 → 성 앞(문) | `$8ED6` 만 | `67`(걸음마다 줄기만) |

모습 표 `1E:$B079` 는 사람 37칸, 몬스터 15칸입니다(`dq4encounter.py henge`). 사람 쪽 처음 아홉 칸은 일행 그림 `00`~`08` 이고, 몬스터 쪽에는 여우·개·고양이·말·スライム 그림이 들어 있습니다.

## 6. 장 중간에 저장한 칸 불러오기

앞 일지의 불러오기 실측은 장 처음 칸 하나였습니다. 성 앞마당에서 교회로 걸어가 기도로 저장하고 리셋해 불러왔습니다. 처음에 `$6E41` = `7F`, `$6BEB` = `32`, `$6E05` = `80` 을 써 두었습니다.

```
2475 A3A1 b=1E 6291=80 63=0000 …
2475 A3BA b=1E 6291=C0 63=0200 44=0516 6E41=7F 6E05=80
2475 A5AD b=1E …
2475 A3C9 b=1E 6291=C0 63=0200 44=0516 6E41=00 6BEB=00 6E05=00
```

저장 자리로 돌아가는 `1E:$A3A1` 뒤에도 `$A3BA` → `$A5AD` 가 돌았고 장 초기화는 돌지 않았습니다.

## 7. 3장 공사비와 가게를 게임 안에서

앞 일지는 3장 터널을 `$6286` bit5·`$6287` bit7 을 써 넣고 지났습니다. 이번에는 대화로 했습니다. 대화 `04D`(가게 주인)는 3장이고 `$6286` bit6 이면 35000G 로 가게를 팔고, `06C`(굴 노인)는 `$6286` bit5 면 60000G 를 받습니다.

1장 왕좌의 방 세이브스테이트에 장·`$6282`·`$6286` = `40`·골드 100000 만 써 넣었습니다.

| 차례 | 한 것 | 결과 |
| --- | --- | --- |
| 1 | `04/08` (03,04) 에서 위의 가게 주인에게 말 걸고 「はい」 | `0862` → `0865`, `$6286` = `60`, 골드 65000 |
| 2 | 필드 (79,5C) 로 나가 아래로 들어가 `42/00` (12,0B) 에서 노인에게 「はい」 | `0892` → `0896`, `$6287` = `40`, `$6285` = `10`, 골드 5000 |
| 3 | 다시 나갔다 들어와 같은 노인 | `0898`, `$6287` = `C0` |
| 4 | `04/01` 에 들어감 | `$6286` = `61` |
| 5 | `04/00` (06,1D) 에서 ネネ | `08A0`·`08A2`·`08A3`, `$62AA` = `08` |
| 6 | 필드 (79,5C) 에서 아래로 | `42/01` (05,0F) |

가게를 산 뒤 화면이 ネネ 의 가게 장면으로 넘어가 대사가 이어지므로, 그다음 워프 전에 B 로 창을 닫아야 했습니다. 맵 → 필드 워프는 `warp.lua` 의 `KEY` 쪽으로 한 걸음 걸을 수 있어야 해서 `04/00` (05,1C) 에서는 `left` 로 했습니다.

## 틀렸던 것들

- `textmodoki.lua` 의 `FORCE` 로 행동을 `34` 로 바꾸면 パルプンテ 가 될 줄 알았습니다. `FORCE` 가 바꾸는 것은 `11:$8C85` 의 분기용 A 뿐이고, パルプンテ 효과는 차례 처음의 `11:$B861` 이 행동 번호를 다시 읽어 고릅니다.
- `$6289` 를 `SET` 으로 써 두면 맵에 들어가도 남는 줄 알았습니다. 맵 → 맵 워프에서도 지워졌고 `$6285` 는 남았습니다.
- 이야기 진행 순서([dq4-story-format.md](../docs/dq4-story-format.md#장마다-진행-순서--플래그))의 3장은 「가게를 삼 → 가게를 열고 왕에게 인사(`$6286` bit6)」 순서입니다. 그런데 대화 `04D` 는 `$6286` bit6 이 있어야 가게를 팔았습니다. 왕의 인사가 가게를 사기 전에 있어야 합니다.
