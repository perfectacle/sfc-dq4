# 2026-10-25-03: 출구와 인물

맵에 들어갈 때 채워지는 출구 표와 인물 표가 롬의 어디서 오는지 찾아 디코더에 넣었습니다. 결과는 [dq4-map-format.md 「출구 표」·「인물」](../../dq4-map-format.md#출구-표-05a0) 에 있습니다.

## 1. 출구는 연결 표에서

앞마당에서 왕좌의 방으로 들어갈 때 `05A0-05FF` 쓰기를 잡으니 `1B:$8145`~`$81B3` 이 한 바이트씩 채우고 `1B:$821B` 가 끝에 `FF` 를 썼습니다. 읽던 표는 맵마다 있는 것이 아니라 10바이트짜리 **연결** 125개였습니다. 끝점 하나가 (그룹, 순번, X, Y, 플래그)이고, 현재 장소와 같은 끝점이 있으면 반대쪽이 목적지가 됩니다. 문 하나를 양쪽 맵이 함께 씁니다.

```
$ uv run python tools/dq4map.py rom/dq4.nes exits 02 01 --compare end.ram
출구 (0F,24) → 02/00 도착 (12,0A) 플래그 82
출구 (10,24) → 02/00 도착 (13,0A) 플래그 82
RAM $05A0 과 같음
```

## 2. 인물 표

같은 구간에서 `1C:$99E9` 가 `$6F60`·`$6FA0` 에, `$99F5` 가 `$6F80`·`$6FC0` 에 21번씩 썼습니다. 열마다 32칸인 인물 표이고, 슬롯 0~5 는 주인공 쪽이었습니다. 레코드 포인터 `$DA/$DB` 는 `1C:$9B08` 이 뱅크 05 `$8000 + 그룹 × 2` 에서 꺼낸 뒤, 순번만큼 `00` 으로 끝나는 목록을 건너뛰어 정했습니다.

레코드 길이는 첫 바이트의 비트로 정해지고(`1C:$9B71`), 뒤에 길이 바이트가 붙은 블록이 한두 개 옵니다. 블록 안에는 `24 0e 1f 03` 같은 4바이트가 되풀이되는데, 인물이 오가는 칸 좌표로 보입니다.

로드 직후(`1C:$9890`) 인물 표를 `tools/lua/fc/atpc.lua` 로 덤프해 비교했습니다.

```
인물 표(슬롯 6~) 와 21명 중 0 다름     # 왕좌의 방 02/01
인물 표(슬롯 6~) 와 13명 중 0 다름     # 앞마당 02/00
```

인물 목록을 그룹마다 끝까지 읽으면 71곳 모두 다음 그룹 포인터에서 끝났습니다(레코드 944개).

## 틀렸던 것들

- 게임을 조금 돌린 뒤의 RAM 과 비교했더니 몇 명의 좌표가 한 칸씩 달랐습니다. 돌아다니는 인물이라 로드 직후로 시점을 옮겼습니다.

## 남은 것

- 인물 레코드의 나머지 바이트(겉모습 등)와 블록 안 스크립트(움직임·대화) 형식.
- 밤·이벤트용 대체 목록(`1C:$9D0E`), 연결 끝점 플래그의 위 비트.
