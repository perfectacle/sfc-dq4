# 2026-10-25-57: 동료 AI 의 칸 평가 루틴, 아이템 후보, 후보 비교와 작전 7칸 표

앞 일지([2026-10-25-48](2026-10-25-48-stats-ai.md))에서 남긴 동료 AI 의 뼈대를 뱅크 `13` 코드로 더 읽었습니다. 칸마다 뛰는 평가 루틴의 주소 표, 주문이 없는 인물도 쓰는 아이템 후보 표, 후보끼리 견주는 두 루틴(`13:$AB92`·`$AC63`), 작전 번호로만 찾는 7바이트 표 열 개(`13:$BB53`~)가 무엇을 하는지입니다. 이번 것은 모두 코드 읽기이고 전투로 재지 않았습니다. 결과는 [dq4-data-format.md](../docs/dq4-data-format.md#칸-평가-루틴과-후보-비교) 에 있고, `fc/dq4/tools/dq4data.py ai` 가 새 표를 찍습니다.

## 1. 칸마다의 평가 루틴

`13:$A54D` 는 칸의 주문을 쓸 수 있는지 본 뒤 이렇게 뜁니다.

```
13:A559  LDA $75E8 ; ASL ; TAX
13:A55E  LDA $A626,X ; STA $86 ; LDA $A627,X ; STA $87   ; 인물마다 표
13:A568  LDA $0D ; ASL ; TAY                              ; 칸 번호
13:A56C  LDA ($86),Y ; STA $88 ; INY ; LDA ($86),Y ; STA $89
13:A582  LDY $6E80 ; CPY #$04 ; BEQ 돌아감 ; JMP ($0088)
```

`13:$A626` 의 포인터는 クリフト `$A64E`, ミネア `$A636`, マーニャ `$A666`, ブライ `$A67E` 입니다. 표를 펼치면 같은 종류의 주문이 같은 루틴을 씁니다.

```
クリフト: ザキ=9554 ザラキ=9569 マホトーン=9BBB マヌーサ=9BBB スカラ=9FE2 スクルト=A00D ホイミ=980B … ザオラル=9E31 ザオりク=9E35
マーニャ: メラ=951B メラミ=951B メラゾーマ=951B ギラ=9533 … イオ=9548 … マホトラ=9EC3 ルカニ=9F5A ドラゴラム=9FB8
ブライ:   ヒャド=951B ヒャダルコ=9533 ヒャダイン=9548 マヒャド=9533 … ルカニ=9F5A ルカナン=9F76 ピオりム=9F8D バイキルト=9FC7
```

공격 주문은 대상 범위(하나, 무리, 전체)로 세 루틴(`$951B`·`$9533`·`$9548`)에 나뉩니다.

## 2. 아이템 후보

인물 루틴이 사이사이 부르는 `13:$A6C6`·`$A6CA`·`$A6CE`·`$A6D2` 는 `X` 만 0·2·4·6 으로 다른 같은 루틴(`13:$A6D4`)입니다. 그 인물의 소지품 8칸(레코드 +13~+1A)을 하나씩 `13:$A747 + X` 의 포인터가 가리키는 목록과 견줍니다.

```
13:A717  LDA ($00),Y ; CMP #$FF ; BEQ 없음 ; CMP $7355 ; BEQ 찾음 ; INY×4
13:A72A  INY ; LDA ($00),Y ; STA $75D3      ; 행동 ID
         INY ; LDA ($00),Y ; STA $86 ; INY ; LDA ($00),Y ; STA $87 ; 평가 루틴
```

```
묶음 0: いかづちのつえ>83@9533 てんばつのつえ>84@9533 まどろみのけん>85@9BA6 ほのおのつめ>86@951B … せいじゃくのたま>9D@9BBB
묶음 1: しゅくふくのつえ>8B@98E9 ちからのたて>8F@98BC やくそう>94@98AC けんじゃのいし>A0@990E
묶음 2: まんげつそう>98@9DEC
묶음 3: みなごろしのけん>8A@9F76
```

공격 아이템은 같은 효과의 주문과 같은 평가 루틴을 씁니다(いかづちのつえ 는 ベギラマ 처럼 `$9533`). 주문이 없는 トルネコ·ライアン·アリーナ 의 `13:$B049` 는 이 네 번과 `13:$B0E0` 만 부릅니다.

```
13:B049  JSR $9584 ; JSR $A6C6 ; JSR $A6CA ; JSR $A6CE
13:B055  JSR $9135 ; BCC + ; JSR $91A0 ; JSR $A6D2
13:B060  JSR $B0E0 ; JMP $9110
```

그래서 이 셋은 목록의 아이템을 지녔을 때만 보통 공격 말고 다른 것을 고를 수 있습니다.

## 3. 후보 비교

`$75DB`(고른 행동)에 쓰는 곳을 모으니 회복과 되살리기는 각자 견주는 루틴이 따로 있었습니다. 회복 점수 `13:$9948` 의 끝 `JMP $AB92` 가 그 하나입니다.

```
13:AB92  LDA $00 ; ORA $01 ; BEQ 버림          ; 점수 0
13:AB98  LDA $75DB ; CMP #$FF ; BEQ 바꿈        ; 처음 후보
13:AB9F  JSR $AC09 ; BCC 버림                  ; $04/$05 < $75C1+2k
13:ABA4  JSR $ABF7 ; BCC 버림                  ; $7C≠1 이고 $8C/$8D < $75E6/$75E7
13:ABA9  … $75D4 − $00 : 음수면 바꿈, 0 이면 $8B ≤ $75E5 일 때 바꿈
```

`$75C1 + 2k` 는 앞 일지에서 작전 × 인물 표 `13:$BAD5` 로 쌓는다고 본 받을 피해입니다. 곧 회복량(모자란 HP 로 자른 것)이 그 대상이 이번 턴에 받을 피해에 못 미치면 회복 후보로 두지 않습니다. 앞 일지의 「`$75C1` 을 쓰는 곳」이 여기였습니다.

キアリク·ザオラル·ザオリク·メガザル 의 평가 루틴은 끝에서 `13:$AC63` 을 부릅니다.

```
13:AC63  LDA $75DB ; CMP #$29 ; BCC + ; CMP #$2D ; BCC 버림   ; ホイミ~ベホマラー 면 그대로
13:AC6E  CMP #$2E ; BCC + ; CMP #$33 ; BCC ++ ; + LDA #0 ; STA $75E6
13:AC7E  LDA $8C ; CMP $75E6 ; BCC 버림 ; (바꿈)
```

## 4. 작전 7칸 표

`13:$BB53`~`$BB98` 은 앞 일지에서 「작전마다 7바이트」로 적었지만, 읽는 곳을 모으니 시작 주소가 7씩 다른 표 열 개였고 모두 `LDX $6E80 ; CMP 표,X` 꼴이었습니다.

```
13:$BB53 13:$A2DF フバーハ   작전 0-6: 04 0A 0A 01 08 10 02
13:$BB6F 13:$A0A1 スカラ     작전 0-6: 04 08 0C 02 03 10 03
13:$BB76 13:$A07F スクルト   작전 0-6: 03 05 05 01 02 10 02
13:$BB92 13:$AB8C           작전 0-6: 66 33 8C 01 FF 01 A0
```

フバーハ 의 `13:$A276` 은 몬스터 8마리 × 6칸에서 행동 레코드 +6 의 bit7·6 이 서고 bit5 가 꺼진 칸의 가중치를 더해 줄인 값을 `$BB53[작전]` 과 견줍니다. いのちをだいじに(3)는 문턱이 가장 낮고 じゅもんをつかうな(5)는 가장 높습니다. 다른 표도 대체로 같은 꼴입니다.

## 틀렸던 것들

- `13:$BB53`~ 을 「작전마다 7바이트 레코드」로 보았습니다. 작전 번호 하나로 열 개 표를 하나씩 찾는 꼴이라 레코드가 아니라 7칸 표의 묶음입니다.
- トルネコ·ライアン·アリーナ 의 루틴에 고르는 규칙이 따로 있으리라 보았지만, 주문 칸 대신 아이템 묶음만 보는 같은 틀이었습니다.

## 남은 것
