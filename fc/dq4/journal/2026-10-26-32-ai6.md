# 2026-10-26-32: 동료 AI 의 회복·되살리기 비교, 보조 주문 문턱, 숨결 내성과 갑옷, トルネコ 의 みる, 레코드 8 레벨업

앞 일지([2026-10-26-22](2026-10-26-22-ai5.md))가 코드 읽기로 남긴 동료 AI·표의 빈칸을 전투와 필드 실측으로 닫았습니다. 회복 대상을 고르는 조건과 `13:$AB92` 의 비교 규칙을 561번의 기록으로 맞췄고, 되살리기 `13:$AC63` 의 우선순위, ドラゴラム·バイキルト·スカラ·スクルト 의 문턱을 표를 바꿔 가며 확인했습니다. 「갑옷 단계」로 적었던 `BRK 22 B3` 는 몬스터의 숨결 내성이었고, 갑옷 쪽 감소는 따로 쟀습니다. `$8D9A` bit4-0 은 トルネコ 의 「みる」가 말할 줄이었고, `$618E` bit6 에서 레벨업이 레코드 8 을 올리는 것도 보았습니다. 결과는 [dq4-data-format.md](../docs/dq4-data-format.md) 의 레벨업, 위력, 아이템, 동료 AI 절에 있습니다.

## 1. 실험 틀

앞 일지와 같은 1장 필드 세이브스테이트(`work/dq4-stats/stats-cristo-field.mss`)에서 `$615A`=4, `$615B`=작전으로 AI 를 켜고, 걸음마다 전투를 내는 롬 바이트(`18:$9D09` → `CLC; NOP`)와 무리를 바꾸는 `PCPOKE`(`18:$A11A`)를 그대로 썼습니다. 일행 레코드는 HP·MP 999, 20레벨로 써 넣고, 낮춘 HP 나 죽음은 `13:$AE11` 에 건 `PCPOKE` 로 턴마다 다시 써 넣었습니다.

```
PCPOKE="A11A@18:6E45=00,FF,FF,FF,08,00,00,00;AE11@13:603E=96,00;AE11@13:607A=2C,01" \
 ROMONCE="61D09=18,EA;6004A=FF;6004C=FF;6004B=60;60055=03;60057=03" ONCE="615A=04;615B=00;…" \
 AT=9112,9813,AB92,ABCA,ABF6,AC63 LOG="75DB,75D3,75E8,0082,0000:2,0004:2,75C1:8,007C,007B,008A:8,75E5:3,75D4:3,…" statsstack.lua
```

앞 일지에서 레코드 HP 를 낮춰도 회복 평가 `13:$999C` 가 불리지 않았다고 했지만, ミネア 의 HP 를 100/999 로 두니 첫 턴에 クリフト 가 `13:$9948` → `$999C` → `$AB92` 를 거쳐 ミネア 에게 ベホマ 를 골랐습니다. 전투 HP 는 레코드 그대로였고, 회복이 불리려면 아래 대상 조건을 넘어야 했습니다.

## 2. 회복할 대상 `13:$9B0D`

`13:$99C5` 가 일행 넷마다 `13:$9B0D` 를 불러 급함 2비트를 `$7B` 에, 대상 수를 `$7C` 에 둡니다. 코드로 세운 규칙은 「살아 있고, ⌊16 × HP / 최대 HP⌋ ≤ 13, HP < 받을 피해 p 면 2, HP − p < ⌊최대 HP / 4⌋(작전 3 은 / 3)면 1」입니다. `13:$9813`(대상을 다 정한 뒤)에서 `$7B`·`$7C`, p 가 든 `$8A`~`$91`, 일행 HP 와 레코드 `+00` 을 기록해 견줬습니다.

```
A00 9813 7B=04 7C=01 HP 500/150/999/300 p=0          ; ミネア 만 1 (150 < 249)
A03 9813 7B=44 7C=02                                  ; 작전 3: ブライ 300 < 333 도 1
E3  9813 7B=00 HP 900 p=0498(1176)                    ; ⌊16×900/999⌋ = 14 > 13
E4  9813 7B=02 HP 870 p=0498                          ; 13, HP < p → 2
19판 333번 모두 규칙과 같음
```

처음 맞춘 판에서 24번이 어긋났는데, 첫 턴에 쓰러진 クリフト 가 그 뒤 대상에서 빠진 것이었습니다. `PCPOKE` 가 HP 만 다시 써 넣고 `+00` 은 그대로 두어서, 기록에 `+00` 을 더하니 모두 맞았습니다.

## 3. 회복 비교 `13:$AB92`

`$AB92` 는 점수 0 이면 버리고, 모자란 HP 를 회복량으로 자른 `$04` 가 그 대상의 받을 피해 `$75C1 + 2k` 보다 작으면 버리고, 대상이 둘 이상이면 `$8C/$8D` 를 고른 후보의 `$75E6/$75E7` 과 견준 뒤, 점수를 `$75D4` 와 견줍니다. 바로 뒤에 `$ABCA`(바꿈)에 닿는지로 결과를 나눴습니다.

```
(acc, 점수가 큼)        147     (rej, 점수가 작음)          244
(acc, 같고 MP ≤)         58     (rej, $04 < 받을 피해)       54
(rej, $8C/$8D < $75E6)   46     (rej, 같고 MP >)             12
```

561번이 모두 맞았습니다. 견주는 키는 `$75D4` 한 바이트뿐이라, 앞서 고른 것이 24비트 키를 가진 공격 후보여도 그 첫 바이트와 견줍니다. `$8D` 의 bit5-4 에는 대상의 급함이 OR 되어 있어(`10`·`20`), 대상이 여럿이면 더 급한 사람의 회복을 덜 급한 사람의 회복이 밀어내지 못합니다. `$8C` 는 `00 04 05 19 1A 26` 같은 값이 나왔는데 앞 계산이 남긴 것으로 보이고 뜻은 정하지 못했습니다.

## 4. 되살리기 `13:$AC63`

ブライ 를 턴마다 `+00` = `00`, HP 0 으로 써 넣고 `$AC63`·`$AC85`(바꿈)를 기록했습니다.

```
R1 クリフト  AC63 75DB=14 75D3=30 → AC85   AC63 75DB=30 75D3=31 → AC85   9112 31   ; ザラキ → ザオラル → ザオリク
R1 ミネア    AC63 75DB=17 75D3=30 → AC85   9112 30                       ; ラリホー → ザオラル
R2 マーニャ HP 150   AC63 75DB=2B 75D3=30 (바꾸지 않음)  9112 2B           ; ベホマ 그대로
R5 작전 3, ミネア 혼자 MP 10   AC63 75DB=17 75D3=32 → AC85   9112 32       ; メガザル
```

`$8C` 는 キアリク 2, メガザル 3 이고, ザオラル 은 0 이 되어야 할 것처럼 보였지만 기록에서는 1 이었습니다. `13:$9E31` 의 `LDA #$00` 뒤 `BNE` 는 Z=1 이라 건너뛰지 않고 `$9E35` 의 `LDA #$01` 까지 내려갑니다. 그래서 ザオリク 은 ザオラル 을 `1 ≥ 1` 로 밀어냅니다. 58번 모두 규칙과 같았고, ベホマ 를 고른 뒤 온 38번은 한 번도 바꾸지 못했습니다.

## 5. ドラゴラム·バイキルト·スカラ·スクルト

보조 주문은 `13:$9135` 를 지날 때(고른 것이 보통 공격이고 처치 비율이 4번 넘게 칠 만큼일 때)만 평가합니다. 그래서 주문 비트를 그 주문만 남겨 보통 공격이 고르게 했습니다.

ドラゴラム 은 마릿수 문턱이었습니다. `13:$A1F2` 가 メタルスライム·はぐれメタル·メタルキング 을 셉니다.

```
D1 작전0 メタルスライム 3  A22D A=03 → A239(못 넘음)   9112 03
D2 작전0 メタルスライム 4  A22D A=04 → A23B → A4DC      9112 28
D8 같음 3, 4FB5A=03        A22D A=03 → A23B             9112 28
D6 メタルキング 1          A23B                          9112 28
```

バイキルト 의 둘째 문턱은 「가장 HP 가 많은 몬스터를 그 사람이 몇 번에 쓰러뜨리나 × 16」이었습니다. 처음에는 スライム 수비력을 `FF` 로 둔 판이라 데미지 어림이 0 이 되어 v 가 `FFFF` 로 넘쳤고, HP 를 391 로 낮춘 뒤에도 9135 를 지나지 못했습니다. 9135 는 ブライ 자신의 공격이 약해야 지나므로 ブライ 의 힘을 10, ライアン 의 힘을 200 으로 두었습니다.

```
V1 A155 0082=02 0002=8701(H 391) 0094=6300(⌊(200−2)/2⌋) → A15F 0002=3F00   ; 16×391/99 = 63
V3 H 1200 → 0002=C100 > 80                                                  ; 고르지 않음
K1 작전0 BB7D=18 ≤ 3F ≤ 80 → 9FD3 A=02, 9112 25(ライアン 에게 バイキルト)
K2 BB7D[0]=50 → 고르지 않음
```

スカラ·スクルト 는 クリフト 가 일행마다 센 값이 `01 01 00 00` 일 때 작전 3 의 문턱 `01` 은 둘이 넘어 スクルト, 작전 2 의 `05` 는 아무도 넘지 못했습니다. 문턱을 `00` 으로 두면 넷 다 넘어 スクルト(센 수 4), `FF` 로 두면 첫 문턱(`68` < `FF`)에서 멈췄습니다.

## 6. 숨결: `BRK 22 B3` 와 갑옷

`13:$B4D4` 의 `BRK 22 B3` 를 갑옷 단계로 적었는데, `dq4bank.py call` 로 풀면 x3 형식 `10:$ABBF` 로 필드 `22`(내성)를 읽는 호출이었습니다. 바로 앞 `BRK 07 1F`(`11:$A301`)는 대상 `$7363` bit7 이 서면(몬스터) C=1 이라, 이 갈래는 숨결을 몬스터가 받을 때만 옵니다. 장비 8가지(장비 없음 포함)로 ブライ 가 숨결을 28번씩 받은 판에서는 `13:$B4D7` 에 한 번도 오지 않았습니다.

그래서 `dq4-ch1-battle.mss` 에서 둘째 턴 행동을 숨결로 바꾸고 スライム 의 ギラ·ヒャド 자리만 0~3 으로 두었습니다.

```
불 4F  r=0 B4D7 A=00 → B492 7361=62(98)    r=1 4A(74)   r=2 32(50)   r=3 01
얼음 52 r=0 7E(126)                         r=1 5F(95)   r=2 40(64)   r=3 01
```

`⌊값 × (FF C0 80 00)[r] / 256⌋ + 1` 과 모두 같았습니다. 갑옷 쪽(`13:$B4E8`)은 장비한 갑옷·방패·투구를 그 순서로 찾아 처음 나온 하나만 `13:$B540` 의 7개와 견줍니다.

```
ドラゴンメイル     B511 A=32 → B495 7B → 51(123 → 81)    28번 모두 ⌊×170/256⌋
ドラゴンシールド   B511 A=43 → 86 → 58(134 → 88)          28번
まほうのほうい     B511 A=34 → 그대로                      28번(숨결 비트 없음)
かわのよろい + ドラゴンシールド   B511 안 옴 → 그대로      28번
```

## 7. トルネコ 의 みる

`$8D9A` bit5-0 을 읽는 `12:$9587` 은 `12:$9370` 에서 인물이 5(トルネコ)이고 하위 창의 둘째 줄일 때 가는 갈래였습니다. トルネコ 혼자인 필드에서 どうぐ 를 여니 하위 창이 「つかう みる わたす すてる」였고, みる 를 고르니 「[F6]は [F7]を てにとって みさだめた。」(`02D3`) 뒤에 비트마다 한 줄이 나왔습니다.

```
02 どうのつるぎ(1B)   02D4 0490 03C3 02D9     ; ぶき / 특별한 효과 없음 / 나도 장비 / 팔면 …ゴールド
53 やくそう(0D)       049C 02DE 02D9          ; くすり / 쓰면 없어짐 / 값
69 ちいさなメダル(09)  04A9 02DA 02DB          ; ふしぎな もの / 값을 모름
67 やみのランプ(15)    02D8 02DF 02DA 02DB     ; どうぐ / 여러 번 씀 / 값을 모름
```

bit4 종류, bit3 아이템마다의 한 마디, bit2 소모 여부, bit1 장비, bit0 값입니다. 아홉 가지 꼴 모두 켜진 비트의 줄만 나왔습니다. 아이템 127개의 값에 bit5 가 선 것은 없습니다.

## 8. `$618E` bit6 과 레코드 8 의 레벨업

레코드 0·8 을 1레벨·경험치 5000 으로 두고 `$618E`=`40`, `$6186`=`88 82` 로 スライム 하나와 싸웠습니다.

```
L8 ($618E=40)  12:9DB3 A=00 ×4   끝 SRAM: 레코드 8 5레벨 경험치 5001 / 레코드 0 1레벨 5000
L0 ($618E=00)  12:9DB3 A=00 ×4   끝 SRAM: 레코드 0 5레벨 경험치 5001
```

인물 번호 0 의 곡선으로 레코드 8 을 올렸습니다.

## 틀렸던 것들

- `BRK 22 B3` 를 「갑옷 단계」로 읽었지만 몬스터 내성 필드 읽기였습니다. 갑옷 감소는 `13:$B4E8` 의 다른 갈래입니다.
- ザオラル 의 `$8C` 를 코드만 보고 0 으로 여겼지만 `BNE` 가 건너뛰지 않아 1 이었습니다.
- 앞 일지의 「레코드 HP 를 낮춰도 회복 평가가 불리지 않음」은 전투 HP 가 다른 곳에 있어서가 아니었습니다. 레코드 HP 로 바로 평가합니다.
- 첫 갑옷 실험은 몬스터 행동 번호 자리에 행동 ID(`4F`)를 넣어 숨결이 나오지 않았습니다. 행동 번호는 ID − `11` 인 `3E`·`41` 입니다.
- バイキルト 를 보려고 スライム 수비력을 `FF` 로 둔 채였다가 데미지 어림 0 으로 v 가 넘쳐 대상이 없었습니다.

## 남은 것

- 회복 비교의 `$8C` 가 무엇을 남긴 값인지, バイキルト 의 `$94` 를 줄이는 몬스터 조건(`13:$A42F`), スカラ 첫 문턱 값(`$77D0`)의 뜻.
- `$618E` bit6 을 켜는 장면(제품판 코드에 없음).
