# 2026-10-26-22: 동료 AI 의 MP 예산 식, ザオラル·フバーハ 의 양, マホカンタ 갈래, 작전 4 표본, 내성 값 1·2, 아이템 플래그와 `$618E` bit6

앞 일지들([2026-10-25-59](2026-10-25-59-stats-ai3.md), [2026-10-25-68](2026-10-25-68-resist.md))이 남긴 동료 AI·표의 빈칸을 전투와 필드 실측으로 채웠습니다. MP 예산 `$75EF` 를 식으로 세워 기록과 맞췄고, 죽음을 레코드 `+00` bit7 로 만들어 ザオラル·ザオリク 를 보았고, フバーハ 의 숨결 반감, マホカンタ 로 후보를 버리는 `13:$AB59`, 작전 4 의 고른 뽑기(514번), 내성 값 1·2 의 확률을 15칸 모두 쟀습니다. 아이템 `$8D1B` bit7·`$8D9A` bit6 은 필드 「つかう」로 뜻을 확인했고, `$618E` bit6 은 걷는 일행 목록을 바꾸는 스위치였습니다. 결과는 [dq4-data-format.md](../docs/dq4-data-format.md) 의 동료 AI·성공률과 내성·아이템·레벨업 절에 있습니다.

## 1. 실험 틀

앞 일지와 같은 1장 필드 세이브스테이트(`work/dq4-stats/stats-cristo-field.mss`)에서 `$615A`=4, `$615B`=작전으로 AI 를 켜고, 일행을 勇者 없이 クリフト·ミネア·マーニャ·ブライ(20레벨, HP·MP 999, 주문 비트 모두)로 두었습니다. 勇者 가 없으면 전투 첫 창(たたかう·さくせん·にげる)만 A 로 넘기면 되므로, 패드는 「왼쪽·오른쪽 걷기 → A → B」만 되풀이합니다. 세이브스테이트가 필드 명령 창을 연 채라 처음에 B 를 한 번 누릅니다.

```
DRIVER=fc/dq4/tools/lua/statspc.lua PCPOKE="A11A@18:6E45=00,FF,FF,FF,08,00,00,00;AE11@13:603D=00,00,00" \
 PCNEXT=fc/dq4/tools/lua/statspoke.lua ROMONCE="61D09=18,EA;6004A=FF;6004C=FF;60055=FF,FC,FF,FC,FC;6004F=32,32,32,32,32,32" \
 ONCE="615A=04;615B=00;601F=80,E7,03,…;616A=81,82,83,84" SEQ="wait:10,b:4,wait:20,left:8,right:8,a:2,wait:6,b:2,wait:6,…" \
 AT=9112,AE6B,AF0F LOG="75DB,75E8,6E80,7368,007B,75EF,0094:2" … statsstack.lua
```

`PCPOKE` 를 `13:$AE11`(인물마다 AI 가 예산을 셀 때)에 걸면 턴마다 레코드를 다시 써 넣을 수 있어, 죽은 동료·낮은 HP·`$72E7` 을 유지하는 데 썼습니다.

## 2. MP 예산 `$75EF`

`13:$AE11` 은 일행 넷 가운데 레코드 `+00` bit7 이 서고 bit6 이 꺼진 사람마다 256 을 `$94` 에 더하고, `1024 − $94` 에 `$BB06[4 × 작전 + 인물]` 을 곱해 256 으로 나눈 뒤 `$BB22` 를 더해 `$7368` 에 둡니다. `13:$AECA` 가 그 인물이 쓸 수 있는 주문 가운데 가장 비싼 MP `$7B` 를 찾고, `$7368 × $7B / 32` 가 `$75EF` 입니다.

```
작전 0  AF0F 7368=40 7B=14 75EF=28 (クリフト)   7368=32 7B=0C 75EF=12 (ミネア)   7368=46 7B=12 75EF=27   7368=3C 7B=0B 75EF=14
작전 3  AF0F 7368=16 7B=14 75EF=0D             7368=16 7B=0C 75EF=08           7368=4D 7B=12 75EF=2B   7368=4D 7B=0B 75EF=1A
ミネア 죽음, 작전 0  AE6B 0094=0003(=0300)  AF0F 7368=5E 75EF=3A   ; 64 + 30
ミネア 죽음, 작전 3  AE6B 0094=0003         AF0F 7368=34 75EF=20   ; 22 + 30
```

넷이 성하면 `$BB22` 그대로, 하나가 쓰러지면 `$BB06` 만큼 늘어 비싼 주문을 덜 깎습니다.

## 3. ザオラル·ザオリク

앞 일지에서 HP 0 으로 둔 동료는 죽은 것으로 치지 않았습니다. 레코드 `+00` 을 `00` 으로 두니 クリフト 가 첫 턴에 ザオリク 를 골랐고, ミネア 가 `+00` = `80`, HP 999 로 일어났습니다. ザオラル 를 보려고 クリフト 의 MP 를 15 로 묶고 턴마다 ミネア 를 다시 죽였습니다.

```
A02E A=49 603D=000000   A06E 603D=800000   A073 603D=80F301   ; 난수 49 → 성공, HP 0x1F3 = 499
A02E A=A2 603D=000000                                          ; 난수 A2 → 실패
씨앗 둘 23번: 난수 < 80 14번 모두 성공(HP 499), ≥ 80 9번 모두 실패
```

앞 일지의 「`80` 미만이면 실패」는 거꾸로였습니다. `CMP #$80` 뒤 `BCC` 가 성공 갈래입니다.

## 4. フバーハ

スライム 의 행동 번호를 모두 `3E`(はげしい ほのお, 80~100)로 두고 `13:$B48C`(데미지를 정한 뒤)·`$B48F`(フバーハ 처리 뒤)에서 `$7361` 을 보았습니다. `$72E7` 은 턴마다 `13:$AE11` 에서 bit4 를 켰습니다.

```
bit4 꺼짐 58번: 85→85 90→90 95→95 …
bit4 켜짐 64번: 85→42 96→48 95→47 99→49 …   ; 모두 ⌊값/2⌋
```

작전 4 실험에서 ミネア 가 フバーハ 를 고른 다음 턴의 `$72E7` 이 `08` → `18` 로, 주문이 이 비트를 켜는 것도 보였습니다.

## 5. マホカンタ 와 `13:$AB59`

スライム 의 칸 하나를 マホカンタ(행동 번호 `1A`)로, MP 를 255 로 두었습니다. 한 마리와 싸우니 マホカンタ 를 건 뒤로 マーニャ 의 주문이 `$AB59` 에 오지 않았습니다. 기록해 보니 `$75E1` 은 쌓이지만 점수 `$00` 이 0 이라 `13:$A9C2` 첫 검사에서 버려졌습니다. 그래서 4마리로 늘려 무리·전체 주문이 「걸린 놈과 안 걸린 놈」을 함께 맞게 했습니다.

```
AB91 A=8C 75D3=08 75E1=7800 0D=99 605C=C800  ; イオナズン, HP 200 → 120×256/200 = 153 > 8C 버림
AB91 A=8C 75D3=07 75E1=6800 0D=85            ; イオラ 104 → 133 ≤ 8C 바꿈
AB91 A=8C 75D3=08 75E1=7800 0D=1E 605C=E703  ; HP 999 → 30
329번: 75E1≠0 43번(바꿈 32, 버림 11) 포함 모두 식과 같음

## 7. 내성 값 1·2

```
06r1 p=D8 rand=09 0016   06r2 p=66 rand=09 0016   03r1 p=D8 rand=F3 0018 …
1Fr1 p=FF  1Fr2 p=B2    18r1 p=FF  18r2 p=B2     20r1 p=D8  20r2 p=66

## 8. 아이템 플래그

`$8D1B` bit7 을 읽는 `12:$AE51` 과 `$8D9A` bit6 을 읽는 `12:$B546` 은 필드 どうぐ 의 つかう 갈래입니다. クリフト 혼자인 필드에서 소지품 첫 칸만 바꿔 「どうぐ → クリフト → 아이템 → つかう」를 눌렀습니다.

```
02 どうのつるぎ     AE98 019E 02C5      ; bit7 꺼짐: つかった！ → なにも おこらなかった
11 いかづちのつえ   AE98 019E 02C5
53 やくそう         AE56 B54E B554 019E 02CA   ; bit7, $8D9A bit6 → 동료 창
56 キメラのつばさ   AE56 B554 01A8
61 ちからのたね     AE56 B554 019E 01B3
1E マグマのつえ     AE56 B554 019E 004B        ; ここでは なにも おこらなかった
```

bit7 은 「필드에서 효과가 있음」, `$8D9A` bit6 은 「대상을 고름」(꺼져 있으면 쓰는 사람 자신)이었습니다. `$8D9A` bit5-0 을 읽는 `12:$9587` 은 창 `14` 의 특수한 갈래라 닿지 못했습니다.

## 9. `$618E` bit6 과 레코드 8

bit6 을 읽는 곳(`10:$8243`·`$938E`·`$A1D5`, `11:$BA0D`, `12:$9C1D`, `13:$8A3B`, `1E:$B172`)은 모두 일행 목록 위치에 `1C` 를 더하거나 勇者 레코드를 8 로 바꿉니다. `$618E`=`40` 에 `$6186` 을 채워 싸웠습니다.

```
$6186=82,83           → ミネア·マーニャ 가 싸움($616A 의 넷이 아님)
$6186 비움            → 전투 빈 창에서 멈춤(앞 일지가 본 것)
$6186=80,82 / 88,82   → 勇者 HP 111(레코드 0) / 222(레코드 8)
```

`$618E` 에 쓰는 13곳 가운데 bit6 을 켜는 것은 없었습니다.

## 10. 몬스터 바이트 21 bit2-0

필드 읽기 입구 셋(`10:$A67C`·`$A687`·`$A69F`)에서 필드 번호 `$6E59` 가 `26`~`28` 일 때만 스택을 남기는 프로브로 전투를 처음부터 끝까지 돌렸습니다. 바이트 21 의 셋 가운데 `27`(시작 상태 확률)만 왔고 `28` 은 한 번도 오지 않았습니다. `$6E59` 에 상수를 쓰는 곳에도 `28` 은 없습니다.
