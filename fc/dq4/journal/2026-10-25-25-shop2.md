# 2026-10-25-25: 가게 인물 전체 표·교회·맡기는 곳·상자 나머지

[2026-10-25-10 일지](2026-10-25-10-shop.md) 에서 남긴 것을 이어 풀었습니다. 스크립트를 거쳐 가게를 여는 인물까지 넣은 「인물 → 가게」 롬 전체 표(기본 목록 124줄, 이벤트로 바뀌는 목록까지 176줄), 여관 곱수가 세는 것, 교회·맡기는 곳의 메뉴와 요금, 그룹 `FE` 의 정체, 무기점 덧붙임 두 곳, 상자 개수 표가 맞지 않던 곳, 열린 상자 블록(`08:$8710`), 상자·발밑 특수 내용입니다. 결과는 [dq4-shop-format.md](../docs/dq4-shop-format.md) 에, 표는 `fc/dq4/tools/dq4shop.py people`, 상자는 `fc/dq4/tools/dq4chest.py` 에 있습니다. 새 프로브는 `fc/dq4/tools/lua/shopreads.lua`(SRAM 을 읽는 명령 모으기)와 `shopprg.lua`(메모리에 올라온 PRG 바꾸기)입니다.

## 1. 스크립트로 여는 가게 찾기

[대화 스크립트 해석기](../docs/dq4-script-format.md)(`dq4talk.classify`)로 맵마다 인물 레코드를 모두 풀어, 나무에서 서비스 문장 `12 n` 을 찾았습니다. 그런데 앞 일지에서 본 `02/00` 방어구점(대화 번호 `0D`)이 나오지 않았습니다.

```
uv run python fc/dq4/tools/dq4talk.py rom/dq4.nes id 0D
  스크립트 15:8082-808C
    if counter
      call+2 15:9D2A 8B 07
    else
      msg 078B  なにか　おかいものですか？ …
```

서비스 문장이 아니라 호출 문장으로 `15:$9D2A` 를 부르고, 그 루틴이 주인공 Y(`$45`)가 `16` 이 아니면 `JMP $B851`(방어구점)로 갑니다. 그래서 스크립트의 호출 대상 100곳을 `kr_patch.fc.dis6502` 의 명령 길이로 따라가(분기 양쪽, `JMP`·`JSR`) 가게 입구에 닿는지 봤습니다.

```
9D2A ['3']
ADB7 ['1', '2', '3', '5']
```

`15:$ADB7` 은 말을 건 인물의 지금 X·Y 로 교회·도구·방어구·무기를 고릅니다. 대상 목록을 다시 보니 `$B558`(교회 안쪽), `$B847`(무기점 안쪽), `$BF30`(여관 안쪽), `$A6B0`(무료로 재움)처럼 가게 루틴 안을 바로 부르는 것도 넷 있었습니다. 이 여섯을 `dq4shop.CALL_SERVICES` 로 두고 `people` 이 맵 279곳을 돌게 했습니다.

```
가게 인물 121곳          직접 92, 스크립트 20, 호출 9
여관 33, 교회 23, 방어구 21, 도구 21, 무기 19, 맡기는 곳 2, 무료 숙박 2
```

그 사이 대화 해석기에 밤 모습(대화 번호와 자리가 덧붙은 바이트에서 옴)과 이벤트 플래그로 바뀌는 인물 목록(`1C:$9D0E`)이 들어와서, 레코드마다 낮·밤을 따로 풀고 바뀌는 목록도 돌게 했습니다. 밤 모습인데 스크립트의 낮 갈래로만 가게를 여는 길은 뺐습니다. 기본 목록 124줄(인물 118명), 바뀌는 목록까지 176줄이 됐습니다. 밤에만 나오는 가게가 6줄 있었고, `09/00` 무기점 인물은 밤에 (02,16) 으로 옮겨 다른 목록을 팝니다.

## 2. 워프로 말 걸어 보기

[장면 이동 도구](../docs/dq4-warp.md)로 인물에서 1칸·2칸 떨어진 네 자리에 서서(카운터 너머 조건은 2칸) 말을 걸고, `shopcall.lua AT=B550,B84A,B851,B858,BBF0,BF28,BFB5,BFBB` 로 가게 입구와 여관 값을 봤습니다. 처음에는 `$9CBF` 만 봤는데, `$ADB7` 은 `$9CBF` 를 지나지 않고 가게로 바로 뛰어서 놓쳤습니다.

```
t1 04/09 (04,04): 9CBF A=03  RAM $07C5=03 $07C4=3 $07BD=33 38 2E — 표 같음
a1r 19/00 (14,0C): B858 A=02  RAM $07C5=02 $07C4=4 $07BD=53 54 58 5E — 표 같음
a2r 1F/00 (08,0A): BF28 A=06 BFB5 A=08 BFBB A=01
a4u 11/00 (10,1C): B84A A=01  RAM $07C5=01 $07C4=5 $07BD=04 0D 19 0A 0F — 표 같음
b2u 0F/00 (11,0E): BFB5 A=04 BFBB A=01                  ($627B=10 으로 둠)
```

`1B/00` 의 `$ADB7` 인물은 인물 표 슬롯 `0B` 의 자리(`$6F6B`/`$6F8B`)를 도착 뒤에 바꾸고 그 앞에 서서 말을 걸었습니다.

```
m4 (1C,13): B550 교회
m1 (1D,13): B851  $07BD=2A 34 32 48 49 — 표 같음
m2 (1D,12): B858  $07BD=56 5E — 표 같음
m3 (1E,13): B84A  $07BD=07 16 18 15 — 표 같음
```

`08/01` (07,09) 는 `$B558` 로 들어가 `$B550` 에 닿지 않았지만 화면에 교회 메뉴가 떴습니다. `16/00` 무기점 둘과 `17/00` 떠돌이 상인 등은 1장 세이브스테이트에서 인물 표 슬롯이 `80 80`(없음)이라 말을 걸 수 없었습니다.

## 3. 여관 곱수

앞 일지에서 `$3D` 를 바꿔 실패한 곱수를 다시 봤습니다. `shopreads.lua` 로 여관 대화 동안 `$6000`~`$62FF` 를 읽는 명령을 모으니, 값을 계산하는 프레임에 뱅크 10 이 `$616A`~`$616D`(걷는 일행)와 `$60B5`(ライアン 레코드 `+00`), `$618E` 를 읽었습니다.

```
10:8288 616A 86 1 228
10:829F 60B5 80 1 228
10:8288 616B 00 1 228
10:8288 616C 00 1 228
10:8288 616D 00 1 228
```

[저장 데이터 문서](../docs/dq4-save-format.md)의 인물 레코드를 보고 `SET` 으로 일행을 바꾸어 `15:$BFBB` 의 A 를 봤습니다. 자리 bit7 과 레코드 `+00` bit7 이 둘 다 켜진 사람만 세었고, HP 는 보지 않았고, 다섯째 자리 `$616E` 는 세지 않았습니다. `$616B`=`90`(레코드 번호 `10`)은 레코드 주소가 `$6001`+30×번호가 아니라 `10:$9FBA` 표(`10` → `$6139`)에서 와서 세지 않았습니다.

## 4. 교회와 맡기는 곳

`02/00` 교회 메뉴는 「おいのりをする / おつげをきく / いきかえらせる / どくのちりょう / のろいをとく / やめる」입니다. `15:$B550` 의 갈래를 읽어 요금 계산을 찾고, 요금을 `$E2`~`$E4` 에 넣고 부르는 `15:$B78E` 를 `probe/trace.lua` 로 잡았습니다.

```
되살리기 레코드 7 L5:  00E2=1E   (30)
           L10:        00E2=6E   (110)
           L30:        00E2=8E 00E3=03   (910)
해독 +00=A0:           00E2=05
저주 E みなごろしのけん L10: 00E2=2C 00E3=01 (300)
```

되살리기는 L² + 10 을 10 으로 나눠 버리고 10 을 곱합니다(`15:$B6A0`~`$B6C2`). 해독은 레코드 `+00` bit5 가 켜진 인물만, 저주 풀기는 저주받은 아이템을 장비한 인물만 대상이었습니다. `04/0E` 교회는 저장·おつげ 가 없는 창 `70` 이었습니다.

맡기는 곳 인물은 1장에서 말을 걸 수 없어서, 교회 인물에게 말을 걸 때 `shoppoke.lua AT=9962 POKE=0000=04` 로 대화 값을 맡기는 곳으로 바꿨습니다. 1000G 단위로 `$625B` 에 쌓이고 수수료는 없었습니다.

## 5. 그룹 FE

`$63` 에 `FE` 를 쓰는 곳은 `15:$BF02` 하나였습니다. `15:$BEF4`(뱅크 15 함수 `17`)가 장소를 `FE/FE` 로 바꾸고 난수로 여관(1/16)이나 도구점을 엽니다. 부르는 곳은 롬에서 찾지 못해서, `shopprg.lua` 로 메모리의 PRG 를 바꿔 여관 갈래를 이 함수로 돌렸습니다.

```
PRG="55CCA=4CF4BE"                 w1 … w43: $07C5=02 $07BD=53 54 55 56, $63/$64 = FE/FE (8번 모두)
PRG="55CCA=4CF4BE;57F0E=C9FF"      「ひとばん 10ゴールドですが」
```

## 6. 무기점 덧붙임

`16/00` 은 무기점 인물이 없어 교회 인물을 `$00`=`01` 로 무기점으로 바꿨습니다. `$62E7`~`$62E9` 를 켠 만큼 `0B`·`04`·`23` 이 붙었습니다. `09/00` 은 낮(`$62ED` < `78`)에 `06 23 07 10`, 도착 뒤 `$62ED`=`80` 으로 바꾸면 표의 `07 18` 이었습니다. 밤으로 들어가면 (04,0B) 에 아무도 없어 처음에는 밤에는 무기점이 없다고 봤는데, 밤 모습의 자리가 (02,16) 이었고 거기서 `07 18` 을 팔았습니다.

```
e0 []           $07BD=01 02 09
e1 [62E7=01]    $07BD=01 02 09 0B
e3 [62E7=010101] $07BD=01 02 09 0B 04 23
n2 62ED=77      $07BD=06 23 07 10
n4 도착 뒤 80   $07BD=07 18
nnu 밤, (02,17)에서 위  $07BD=07 18
```

## 7. 상자 개수 표가 맞지 않던 곳

개수 표에만 있던 `48/xx` 는 맵 목록에 없는 것이 아니라 `dq4map.maps` 가 그룹 표의 마지막 그룹을 세지 못한 것이었습니다(다음 그룹 포인터로 개수를 셈). 레코드를 맵 번호 `FF` 앞까지 읽으니 `48/00`~`48/09` 10개가 앞 맵 끝에 이어 풀렸고 상자 칸 수가 표와 같았습니다.

`3D/01`·`40/01`·`40/03` 은 다음 장소와 상자 칸이 거의 같은 쌍둥이 맵이었습니다. 개수 표 검색(`1E:$B741`)이 「지금 장소 이상인 첫 줄」에서 멈추므로 다음 장소와 같은 순번을 씁니다. 열어 보니 플래그도 내용물도 다음 장소의 그 상자였습니다(`3D/01` (02,09) → #130 くさりがま).

## 8. 열린 상자 블록

`08:$8710` 이 넣는 정의 `18 11` 의 모양 레코드 `011` 은 `14 00 04`, 곧 종류 `04` 상자 블록입니다. `$0568` 을 쓰는 곳을 찾으니 `1E:$B7CA` 가 상자를 연 칸을 이 블록으로 바꿉니다.

```
3D/01 (02,09)  열기 전 03, 연 뒤 0F, $0568 = 0F
               $626D=20 으로 두고 들어감: 0F
```

## 9. 특수 내용

상자 특수 값 7가지를 모두 열어 봤습니다. `FE`·`FD` 는 전투, 나머지는 아이템이 들어왔고, `EF` 는 같은 방의 다음 상자(빈 상자)까지 열었음으로, `EE` 는 칸을 블록 `19` 로 바꾸고 `$627D` 비트 `08` 을 켰습니다.

발밑 특수 값은 처음에 `E1` 만 나왔습니다. 루틴을 읽으니 많은 값이 `$3D`(주인공이 보는 방향)가 0 인지 봅니다. 워프 기본 방향이 아래(2)였던 것이라, 위를 보고 다시 서자 `E9`·`E7`·`E6`·`E5` 가 나왔고 `F1` 은 `$615A`=`04`(5장)에서 나왔습니다.

```
g6 1C/01 (03,02) 3D 0  items 82 a6 62    $6277 = 08
g9 20/00 (06,06) 3D 0  gold 100          $6277 = 01
g4 0F/00 (03,18) 3D 0  items 82 a6 65    $6277 = 20   (615A=04)
```

## 틀렸던 것들

- 스크립트의 서비스 문장만 보면 가게 인물이 다 나온다고 봤는데, `02/00` 방어구점처럼 호출 문장으로 가는 곳이 9곳 있었습니다.
- 가게가 열렸는지를 `15:$9CBF` 에 닿는지로만 봤더니 `$ADB7`·`$B558` 처럼 `$9CBF` 를 건너뛰는 길을 놓쳤습니다.
- 1장 세이브스테이트에서 `$3D` 는 0 이라 앞 일지에서 일행 수 후보로 봤는데, 보는 방향이었습니다(여관 뒤 `15:$A70B` 가 `$DD & 3` 을 씀). 워프로 아래를 보고 서면 2 입니다.
- `shopprg.lua` 로 `15:$BF0E` 를 바꿀 때 PRG 오프셋을 `$55F0E` 로 잘못 셌습니다(`$BF0E` & `3FFF` = `3F0E`, 맞는 값은 `$57F0E`).
- `09/00` 에 밤으로 들어가 (04,0B) 에 무기점이 없으니 밤에는 가게가 닫힌다고 봤는데, 인물이 밤 자리 (02,16) 으로 옮긴 것이었습니다.
- 셸에서 `LIBDIR=…;` 로만 두고 `export` 하지 않아 `seq.lua` 가 아무것도 남기지 않은 적이 있습니다.

## 남은 것

- 1장에서 인물 표에 나오지 않는 가게 인물들(16/00 무기점, 17/00 떠돌이 상인, 맡기는 곳 등)에게 실제로 말 걸기.
- `15:$BEF4`(그룹 `FE`)를 부르는 곳.
- 여관 곱수에서 마차 자리와 `$618E`, 그룹 `10` 여관의 `$45` < `$14` 갈래.
- 교회 おつげ 계산, 되살리기 레코드 9 이상, 맡기는 곳 물건 맡기기.
- 발밑 특수 `E4`·`E8`·`EC`·`ED`·`EE` 의 이벤트 내용.
