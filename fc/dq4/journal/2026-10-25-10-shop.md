# 2026-10-25-10: 상점·여관·보물상자

가게 창의 품목 목록과 여관 값, 가게 인물이 고르는 가게 종류, 그리고 보물상자·발밑 숨은 물건의 위치·내용물·열었음 플래그를 풀었습니다. 무기 20줄·방어구 20줄·도구 24줄, 여관 31줄, 상자 160개, 발밑 25곳입니다. 결과는 [dq4-shop-format.md](../docs/dq4-shop-format.md) 에, 디코더는 `fc/dq4/tools/dq4shop.py`·`fc/dq4/tools/dq4chest.py`, 실험 스크립트는 `fc/dq4/tools/lua/shopwalk.lua`(칸 경유 보행)·`shopcall.lua`(PC 도달 기록)·`shoppoke.lua`(PC 도달 때 RAM 쓰기)에 있습니다.

## 1. 품목 목록 찾기

1장 성 아래 마을(`02/00`)의 무기점은 こんぼう·どうのつるぎ·いばらのむち·くさりがま 를 팝니다. 아이템 ID 로 `01 02 09 04` 입니다. 마지막 바이트에 bit7 을 켠 `01 02 09 84` 를 롬에서 찾으면 `18:$B41A` 한 곳이 나옵니다(bit7 없이는 없음). 앞의 두 바이트가 `02 00`(그룹·순번)이었고, `18:$802C` 에 `$B418` 을 가리키는 포인터가 있었습니다.

성 앞마당 세이브스테이트에서 `shopwalk.lua` 로 무기점 앞 (0D,18)까지 걷고 `seq.lua` 로 말을 걸면서, `shopcall.lua` 로 `$C3EA`(다른 뱅크 바이트 읽기) 가운데 A = `18` 인 호출을 모았습니다.

```
C3EA A=18 X=DA Y=00 ret=BFCE bank=15 ptr=802C
C3EA A=18 X=DA Y=00 ret=BFCE bank=15 ptr=B418
C3EA A=18 X=DA Y=01 ret=BFCE bank=15 ptr=B41A
C3EA A=18 X=DA Y=03 ret=BFCE bank=15 ptr=B41A
```

부르는 곳은 뱅크 15 의 `$BFC6`(`$DA` 포인터로 뱅크 18 을 읽는 짧은 함수)이고, 그 위가 `15:$B217` 입니다. `$07C5` − 1 을 두 배 해 `$802C` 표에서 목록 포인터를 꺼내고, `15:$B2CB` 로 지금 장소 줄을 찾아 품목을 `$07BD` 에 담습니다. `probe/writes.lua` 로 보니 `$07C5` 는 `15:$B85D` 가 `01` 을, `$07BD`~ 는 `15:$B249`·`$B255` 가 씁니다.

`15:$B2CB` 는 첫 바이트가 `FF` 면 바로 맞은 것으로 하고, 아니면 `$63`·`$64` 와 차례로 비교합니다. 틀리면 bit7 이 켜진 바이트까지 건너뜁니다. 그래서 줄 = 그룹, 순번, 품목들(마지막에 bit7)이고, 목록 끝 표시가 없어 무기 → 방어구 → 도구 목록이 한 덩어리로 이어지며 도구 목록 끝의 `FF` 줄에서 멈춥니다.

## 2. 가게 종류는 대화 값

`$B85D` 앞을 따라가면 `15:$B84A`(1)·`$B858`(2)·`$B851`(3)이 `$07C5` 를 정하고, 이들을 부르는 곳은 `15:$9CBF` 의 비교 사슬입니다. 그 위 `15:$9962` 는 대화 결과 `$00:$01` 이 7 미만일 때만 여기로 보냅니다. `probe/trace.lua TRACE=9962 LOG=0000,0001` 로 `02/00` 의 다섯 사람에게 말을 걸었습니다.

```
무기점   0000=01        도구점 0000=02        여관 0000=06
교회     0000=05        방어구점 0000=0D
```

`4`(`15:$BBF0`)는 메시지 `0238`「ここは もちものと おかねの あずかりじょです。」를 내는 맡기는 곳, `5`(`15:$B550`)는 `021B`「…わが きょうかいに どんな ごようじゃな？」 교회, `6`(`15:$BF28`)은 `0231`~`0237` 여관입니다. 방어구점의 `0D` 는 스크립트 `0D − 7`(`15:$98F6` 표, `15:$8082`)로 갔고, `shopcall.lua` 로 보니 그 뒤 `15:$B851` 에 닿았습니다.

`dq4map.py npcs 02 00` 의 인물 머리를 보니 바이트 4 가 무기점 `01`, 도구점 `02`, 교회 `05`, 여관 `06`, 방어구점 `0D` 로 대화 값과 같았습니다. 대화 번호의 위 3비트는 머리 바이트 1 의 bit4-2 입니다([대화 스크립트 형식](../docs/dq4-script-format.md#대화-번호)). 가게 인물은 그 비트가 0 이라 바이트 4 가 곧 가게 종류입니다.

## 3. 다른 마을 가게

`dq4shop.py G K` 가 대화 번호 1~6 인 인물을 내게 하고, [장면 이동 도구](../docs/dq4-warp.md)로 그 인물 바로 아래 칸에 위를 보고 내린 뒤 말을 걸었습니다.

```sh
SET="6157=E803" SEQ="a:6,wait:30,a:6,wait:150,a:6,wait:150" TAIL=60 \
  fc/dq4/tools/dq4warp.sh work/sv12w 12/00 0F 04 0
uv run python fc/dq4/tools/dq4shop.py rom/dq4.nes 12 00 --compare work/sv12w/end.ram
```

```
RAM $07C5=01 $07C4=5 $07BD=02 09 0B 04 05 — 표 같음      (12/00 무기)
RAM $07C5=02 $07C4=6 $07BD=53 54 55 56 58 47 — 표 같음   (04/00 도구)
RAM $07C5=01 $07C4=6 $07BD=0F 06 10 07 33 49 — 표 같음   (13/00 무기)
RAM $07C5=03 $07C4=6 $07BD=26 27 2D 3D 3E 47 — 표 같음   (0C/00 방어구)
```

골드를 1000 으로 둔 것은 가게 창 옆 금액을 넉넉히 보려는 것뿐입니다. 네 창의 가격과 `02/00` 무기점 창까지 27품목이 [아이템 가격 공식](../docs/dq4-data-format.md)과 모두 같았습니다. `13/00` 무기점은 みかわしのふく·てっかめん 도 팔아서, 목록이 종류별로 갈리지 않는다는 것도 화면으로 봤습니다.

## 4. 여관 값

`15:$BF71` 은 `BRK 87 8F` 로 뱅크 18 함수 07 의 주소 `$B5CD` 를 `$DA` 에 꺼내고(호출하지 않는 형식), 거기서 (그룹, 순번) 3바이트 줄을 찾습니다. `shopcall.lua AT=BF99,BFB5,BFBB` 로 `02/00` 여관을 보면

```
BF99 A=00 X=DA Y=01 ptr=B5CD
BFB5 A=04 X=DA Y=02 ptr=B5CD       1인 값 4
BFBB A=01 X=DA Y=02 ptr=B5CD       BRK 62 23 01 이 돌려준 곱수 1
```

이고 화면은 「ひとばん 4ゴールドですが」였습니다. 워프로 `13/00`·`0C/00` 여관에 가 보니 표대로 2G·6G 였습니다.

## 5. 상자는 블록 종류

앞마당에서 しらべる 하면서 `probe/reads.lua` 와 `$C3EA` 기록을 보니 `1E:$B3FE` 가 발밑 블록의 `$6F40`[블록] 을 읽고, 그 값 & 7F 가 `04` 이면 상자 처리(`1E:$B447`)로 갑니다. `08:$B67F` 의 목록도 `04 00` 이었습니다.

`$6F40`~`$6F5F` 를 쓰는 곳을 `probe/writes.lua` 로 잡으니 맵 로드 때 `08:$8464` 였고, 값은 `08:$80FF` 가 블록 레코드 표에서 꺼낸 셋째 바이트였습니다. `TRACE=8464 LOG=0016,000A,000B,000C` 로 32개를 다 받아 롬에서 계산한 값과 맞췄습니다(`dq4chest.block_kinds`).

상자의 순번은 맵 안에서 가로 줄 순서로 앞에 있는 종류 `04` 칸 수(`08:$B4E5`)에, 개수 표(`1E:$BDBE`)에서 앞 장소들의 상자 수를 더한 값입니다(`1E:$B741`). 내용 표(`1E:$BDC0`)를 이 순번으로 읽고, 열었음 비트는 `$625D` + 순번 >> 3 입니다.

## 6. 상자 열어 보기

워프로 상자 칸에 서서 しらべる(`a`, `right`, `down` 세 번, `a`)를 했습니다.

```
02/01 (02,16)  ライアンは たからばこを あけた！ なんと いのちのきのみを みつけた！   $625D 00 → 08
02/01 (03,16)  ライアンは 160ゴールドを てにいれた。   $625D 00 → 04, 골드 0032 → 00D2
03/02 (14,02)  なんと ふうじんのたてを みつけた！      $625E 비트 10
```

`dq4chest.py 02 01 --compare end.sram` 은 상자 #4 만 「열었음」입니다. 발밑은 `03/03` (04,03) 에서 いのちのきのみ, `0B/00` (08,1E) 에서 ちいさなメダル 가 나왔고, `probe/writes.lua WATCH=6200-62FF` 로 보니 주웠음 비트 `$6272` = `80` 은 메시지 창을 닫을 때 `1E:$B599` 가 씁니다.

`dq4chest.py check` 로 맵 269개 모두에서 종류 `04` 칸 수를 개수 표와 비교했습니다.

```
3D/01: 상자 칸 1, 표 0 — 표에 없어 3D/02 와 같은 순번
40/01: 상자 칸 4, 표 0 — 표에 없어 40/02 와 같은 순번
40/03: 상자 칸 5, 표 0 — 표에 없어 40/04 와 같은 순번
맵 269개, 개수 표 82줄(상자 160개), 다름 3, 맵 목록에 없는 장소 48/01 48/02 48/05 48/06 48/07
```

## 틀렸던 것들

- 블록 기술자를 고를 때 맵 번호를 7비트로 잘랐더니 맞지 않는 맵이 많았습니다. `08:$B70B` 가 `AND #$3F` 를 하므로 6비트가 맞습니다.
- `$6F40` 을 모두 롬에서 계산할 수 있다고 봤는데, `02/00` 블록 `12` 는 롬 값 `80` 이 로드 뒤 `04` 로 바뀌어 있었습니다. `08:$8710`(BRK `11 87`)이 맵에 들어갈 때 블록 정의를 고칩니다.
- `shopwalk.lua` 가 마지막 칸에서 방향을 눌러 돌아서게 했더니, 걸음 직후라 돌아서지 않아 말이 걸리지 않았습니다(`$9962` 에 닿지 않음). 돌아서기·말 걸기는 `seq.lua` 로 따로 합니다.
- 여관의 `$DD` = `$3D` | 80 을 보고 `$3D` 가 일행 수라고 봐서 `$3D` = 3 으로 바꿔 봤습니다. 매 프레임 쓰든 `15:$BF99` 에서 한 번 쓰든(`shoppoke.lua`) 여관 대화 대신 「そのほうこうには だれもいない」가 나와서, `$3D` 는 곱수가 아닙니다. 곱수는 `BRK 62 23 01` 의 결과입니다.

## 남은 것

- 스크립트를 거쳐 가게를 여는 인물까지 넣은 가게 인물 전체 표(`dq4talk.py` 와 묶기).
- 교회·맡기는 곳의 요금과 메뉴, 여관 곱수(`10:$80D1`)가 무엇을 세는지.
- 그룹 `FE` 가 어디인지, `16/00`·`09/00` 무기점 덧붙임을 화면으로 확인.
- `check` 의 다른 3곳과 표에만 있는 `48/xx` 5곳, `08:$8710` 이 바꾸는 블록.
- 상자·발밑 특수 내용(`E0`~`FF`)의 처리.
