# 2026-10-25-24: 블록 속성의 지형 효과·문과 열쇠·카운터

[블록 일지](2026-10-25-16-block.md)와 [속성 값 일지](2026-10-25-17-block-props.md)에서 「통행」과 값 목록까지 풀어 둔 블록 속성 `$6F40` 의 나머지 뜻을 찾았습니다. 걸음 뒤 분기의 값 11개, 밀리는 바닥, 느린 칸, 바닥 피해, 떨어지는 칸의 목적지 표, 리프트, 「とびら」와 열쇠, 카운터 너머 대화, タンス·つぼ·팻말 표입니다. 롬 전체 맵·필드의 속성과 칸을 JSON 으로 내보내는 명령도 붙였습니다. 결과는 [dq4-block-format.md](../docs/dq4-block-format.md) 의 「지형 효과」·「기계가 읽는 지도」 절에 있습니다.

## 1. 속성을 읽는 곳 모두 찾기

롬 전체에서 `LDA $0594`·`LDA $6F40,X` 꼴을 찾았습니다. 고정 뱅크에 9곳, `1E` 에 12곳, `1D`·`08` 에 몇 곳입니다. 하나씩 따라가니 값마다 읽는 루틴이 달랐습니다.

```
0F:$CA81  CMP #$10 / CMP #$14 → $14 = $CB1A[prop&3]   밀리는 바닥
0F:$E9E7  CMP #$31 → $052F = 1 또는 4                   느린 칸
1E:$996B  CMP #$01 / CMP #$02                           바닥 피해
1E:$80DD  CMP #$27 / CMP #$17 → 한 칸 더 앞             카운터
1E:$8349  CMP #$14 / CMP #$24                           문
1E:$BB12  CMP $BBAA,X (2B 2A 28 30)                     タンス·つぼ·팻말
```

같은 블록 속성이라도 맵 종류마다 뜻이 다른 것은 아닙니다. 값 자체는 맵 종류와 상관없이 한 루틴이 정합니다. 다만 `97`(`17`)처럼 「잠금 3 의 문」과 「카운터」 양쪽 범위에 드는 값도 있습니다.

## 2. 바닥 피해와 밀리는 바닥

[워프 도구](../docs/dq4-warp.md)로 해당 칸 옆에 내려 놓고 `probe/watch.lua` 로 좌표·HP(라이안 `$60B6`)를 프레임마다 기록했습니다.

```sh
DRIVER=$PWD/fc/dq4/tools/lua/warp.lua MAP=16/00 X=14 Y=03 DIR=1 SEQ="right:16,wait:30,left:16,wait:30,right:16,wait:30" \
  WF=1 WT=1100 MAXF=1100 WATCH="0044,0045,60B6:2,0594" SHOT_DIR=$PWD/work/poison \
  "$MESENCE" --testrunner --nes.ramPowerOnState=AllZeros "$PWD/rom/dq4.nes" "$LIBDIR/probe/watch.lua"
```

```
171 0044=15 0045=03 60B6=001B 0594=01
186 0044=15 0045=03 60B6=001A 0594=01     # 01: 1
271 0044=15 0045=03 60B6=0019 0594=01
 79 0044=03 0045=0F 60B6=001B 0594=02
124 0044=03 0045=0F 60B6=000C 0594=02     # 02: 15 (왕좌의 방의 막힌 방)
177 0044=03 0045=0E 60B6=0000 0594=02     # 두 걸음째 0, 죽음
```

밀리는 바닥은 `36/00` 에서 오른쪽을 한 번 눌렀더니, 버튼을 놓은 뒤에도 8프레임마다 한 칸씩 (0C,06) → (0F,06) → (0F,07) → (10,07) → (10,0A) 로 가서 멈췄습니다. 통행 지도의 `G`(10)·`H`(11)·`I`(12)·`J`(13)를 위·오른쪽·아래·왼쪽으로 놓고 짠 길과 같습니다. 이때 `$0584`·`$0585` 가 `01 10`(1픽셀, 16프레임) → `02 20` 으로 바뀌어 보통 걸음의 두 배 속도였습니다.

`31`(마을·성 29곳에 쓰임)은 `0E/00` 성문 칸에서 쟀습니다. 위로 걸어 들어가는 한 칸이 22프레임으로 보통의 16프레임보다 길었습니다. `$052F`(한 픽셀마다 기다리는 프레임)가 8픽셀마다 4 가 됩니다.

## 3. 떨어지는 칸

`05`·`0B` 는 `1E:$8676` 이 떨어지는 연출을 한 뒤 `BRK 2C 2F`(`12:$B6DD`)로 목적지를 정합니다. 그룹 몇 개는 코드로 따로 정하고, 나머지는 `12:$B971` 의 표를 그룹·순번·좌표 조건으로 찾고, 없으면 필드로 나갑니다. 표 형식을 읽고 `fall()` 로 짠 뒤 세 칸을 걸어 봤습니다.

```
3C/01 (03,04) 0B → 예측 3C/03 같은 좌표   결과 63=3C 64=03 44=03 45=04
31/02 (0C,10) 0B → 예측 31/03 (0F,12)      결과 63=31 64=03 44=0F 45=12
31/02 (01,0A) 05 → 예측 필드, 왼쪽 한 칸   결과 28=00 42=A4→A3
```

## 4. 리프트

`0F` 를 「스위치」로 짐작했지만 밟아 보니 다른 맵으로 옮겨졌습니다. `1E:$8700` 이 부르는 `1E:$894A` 가 `1E:$89C8` 표에서 지금 (순번, x, y) 와 짝이 되는 자리를 찾아 옮깁니다. 그룹 `45` 에서만 그 전에 `$62AA` 를 뒤집습니다.

```
38/00 (15,02) → 38/01 (17,02), 그 뒤 $45 가 11 → 02 로 8프레임마다 줄어듦
45/04 (26,17) → 45/06 (09,0D), $62AA 00 → 10, $45 1C → 0D
```

옮긴 뒤 주인공이 15칸 아래에서 목적지까지 올라오는 것으로 보아 오르내리는 바닥으로 봅니다.

旅の扉(`0A`)는 `1E/00` (05,03) 에서 약 300프레임 뒤 `1F/00` (03,03) 에 섰습니다. 목적지를 정하는 `08:$B22E` 는 아직 풀지 않았습니다.

## 5. 「とびら」와 열쇠

명령 창을 띄워 보니 8칸 가운데 7번째가 「とびら」였습니다(`1E:$80B0` 의 명령 표 7번 = `1E:$B2A6`). 이 루틴은 앞 칸의 값을 `1E:$B3C8` 의 16바이트에서 찾아 잠금 단계(줄)를 정하고, 일행이 가진 열쇠 가운데 가장 센 것(`1E:$B3D8` = `71 72 73`)과 비교합니다.

왕좌의 방의 막힌 방 문(03,0C)(`95`, 잠금 1)에서 해 봤습니다. 명령 창 커서는 `down` 세 번이면 「とびら」입니다.

```
열쇠 없음: 「かぎを　もっていない。」, $6C0C = FF
AFTER="60CA=71"(とうぞくのカギ): 246 $6C0C=79 83 01 07, 그 뒤 (03,0D) 로 들어감
```

`$6C0C` 의 `79 83` 은 맵 버퍼 주소 `$7983` = (03,0C), `01` 은 순번, `07` 은 연 뒤의 블록입니다. 문을 연 채 계단으로 위층 `02/02` 에 갔다 돌아오자, `$7983` 이 롬 값 `0C` 로 풀린 뒤 2프레임 안에 `07` 로 다시 쓰였습니다. 맵을 그릴 때 `1E:$A0D6` 이 목록을 다시 적용합니다.

## 6. 카운터와 タンス·つぼ·팻말

「はなす」(`1E:$80C0`)는 앞 칸에 인물이 없으면 그 칸 속성이 `27`·`17` 일 때 한 칸 더 앞을 봅니다. 왕좌의 방 (1B,10) 에서 위로 말을 거니 카운터(`A7`) 너머 (1B,0E) 의 인물이 대답했습니다.

인물이 없으면 `1E:$BAEA` → `$BB10` 이 앞 칸 속성을 `2B 2A 28 30` 과 비교합니다. `2B`(タンス)·`2A`(つぼ)는 `1E:$BCED` 의 7바이트 표를 그룹·순번·좌표로 찾습니다. 표 27항목의 좌표가 모두 그 맵의 `AA`·`AB` 칸에 떨어져서 형식이 맞다고 봤고, 왕좌의 방 タンス (1D,1A) 를 「しらべる」로 열어 확인했습니다.

```
561 60C8=FF 53 A6 82     # やくそう(53)가 빈 칸에
593 6274=40              # 표의 플래그 $6274 bit6
```

팻말(`28`)은 `1E:$BBB6` 의 두 표를 좌표로만 찾습니다. 맵 쪽 9항목은 롬 맵의 `A8` 칸 9개와 하나씩 맞았고, 필드 0 (A6,30) 에서 위로 읽자 표대로 03D9 「あやしいものを　みつけたら　おしろまで！　バトランドおう。」가 나왔습니다.

## 7. JSON 내보내기

SFC DQ5 엔진에 블록 속성을 대응시킬 때 쓰려고 `dq4block.py json` 을 만들었습니다. 맵 269개·필드 3개마다 블록 속성 32개와 칸 배열(그늘 바꾸기 뒤의 `$7800`), 떨어지는 칸의 목적지, 속성 값 43가지의 뜻, 위의 표들을 한 파일(약 1.5MB)에 담습니다.

```sh
uv run python fc/dq4/tools/dq4block.py rom/dq4.nes json
# work/dq4block.json: 맵 269, 필드 3, 속성 값 43가지
```

## 틀렸던 것들

- [속성 값 일지](2026-10-25-17-block-props.md)는 `02/01` 의 `02` 칸에 워프하자 「どこからともなく　こえがきこえる……。」 이벤트가 돌아 데미지를 못 봤다고 적었습니다. HP 를 같이 찍어 보니 첫 걸음에 27 → 12, 둘째 걸음에 0 이 되어 죽은 것이었고, 그 문장은 죽었을 때 나오는 메시지입니다.
- `0F` 를 「그룹 45 의 스위치」로 짐작했습니다. `$62AA` 를 뒤집는 것은 그룹 `45` 에서만이고, 하는 일은 짝이 되는 자리로 옮기는 리프트였습니다. 그룹 `38`·`47` 은 플래그 없이 옮깁니다.
- 속성 값 일지는 `3C/01` 에서 `13` 이 아래로 밀었다고 적었습니다. `13` 은 왼쪽이고, 밀려 간 (15,04) 가 `12`(아래)라 그다음부터 아래로 간 것입니다.
- 문은 열쇠를 가지고 부딪히면 열리는 줄 알았습니다. 막힌 칸에 부딪히면 `0F:$D0A8` 이 소리만 내고, 문은 「とびら」나 열쇠 「どうぐ」로만 엽니다.

## 남은 것

- 旅の扉 목적지 루틴 `08:$B22E`(표 `08:$B974`)의 형식.
- 리프트 레코드 넷째 바이트(`$7F`)의 뜻.
- 연 문 목록 `$6C0C` 을 지우는 때(이벤트 `1D:$AEAE`·`$B379` 말고).
- 문 모양 네 가지가 바꾸는 블록(`08:$8796`), 3장의 잠금 2 문(`1E:$B381`), 속성 `33` 의 조건, 떨어질 때 `$07BA` 의 뜻.
- 아무 루틴도 따로 읽지 않는 막힌 값(`A9`·`AD`·`AE`·`AF`·`B2`·`85`)끼리의 차이.
- 밤·장소 팔레트 예외, 애니메이션 블록 처리, 성 앞 워프 nametable, 맵 종류 `0F` 블록 1F 의 물 애니메이션(블록 일지에서 넘어온 것, 이번에 손대지 않음).
