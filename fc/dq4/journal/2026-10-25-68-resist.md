# 2026-10-25-68: 몬스터 내성 칸 15개를 전투로 확인

몬스터 레코드의 내성 2비트 칸 15개가 각각 어느 주문에 듣는지 전투로 하나씩 확인했습니다. 칸 이름(`dq4data.py` 의 `RESIST_NAMES`)은 모두 맞았고, 어긋나 보였던 것은 도구가 내놓는 값의 순서 때문이었습니다. 결과는 [dq4-data-format.md 의 성공률과 내성](../docs/dq4-data-format.md#성공률과-내성) 에 있습니다.

## 1. 의심한 까닭

[27 일지](2026-10-25-27-stats2.md) 는 칸 이름을 코드(`13:$B80B` 의 행동 ID → 칸)로 붙였고, 전투로 확인한 것은 ヒャド 하나였습니다. 그런데 NDS 몬스터 표를 FC 와 맞대 보니 NDS 에서 メラ 를 막는 자리가 FC 의 「イオ」 칸과 153/156 맞았습니다. FC 쪽 이름이 틀렸는지, 맞대는 쪽이 틀렸는지 가려야 했습니다.

## 2. 실험

1장 첫 전투 세이브스테이트(`dq4-ch1-battle.mss`, ライアン 혼자 vs スライム·おおみみず)에서 둘째 턴에 ライアン 이 こうげき 를 고른 직후(550프레임) 행동 칸 `$7324` 를 주문 ID 로 바꿨습니다. 그러면 こうげき 로 고른 スライム 무리에 그 주문을 씁니다. MP(`$60B8`)와 スライム HP(`$727E`)는 매 프레임 채웠습니다. 내성은 롬의 スライム 레코드 바이트 15~19(PRG `60055`~)를 같은 때 바꿨는데, 주문을 쓸 때 롬에서 바로 읽으므로 전투 중에 바꿔도 먹었습니다. `13:$B71D`(확률 p)와 `16:$8656`(메시지 번호)을 기록했습니다.

```
ONCEAT=550 ONCE="7324=00" ROMONCE="60055=0C,00,00,00,00" NEXT=$LIBDIR/seq.lua \
POKE="60B6=00;60B7=01;60B8=FF;60B9=00;727E=FF;727F=03" AT=8656,B71D LOG=7363,00 \
STATE=$PWD/work/state/dq4-ch1-battle.mss DRIVER=$PWD/fc/dq4/tools/lua/statspoke.lua \
SEQ="wait:56,a:4,…(30번)" TAIL=400 MAXF=900 SHOT_DIR=$d \
"$MESENCE" --testrunner --nes.ramPowerOnState=AllZeros $PWD/rom/dq4.nes $PWD/fc/dq4/tools/lua/statsstack.lua
```

칸 c 마다 그 칸 이름의 주문으로 두 번 돌렸습니다. 한 번은 `13:$B736[c]` 가 가리키는 자리만 3, 나머지 0. 한 번은 그 자리만 0, 나머지 14자리 3.

```
칸 2 メラ 00     그 자리만 3: 015E となえた → p=00 → 0018 きかなかった
                 그 자리만 0: 015E          → p=FF → 0016 ダメージ
칸 0 イオ 06     그 자리만 3: p=00 → 0018 (スライム), p=FF → 0016 (おおみみず)
칸 8 ザキ 13     그 자리만 3: p=00 → 0019 しななかった    그 자리만 0: p=FF → 0167 いきのねを とめた
```

15칸 모두, 그리고 같은 칸을 쓰는 ラリホーマ·ザラキ·ルカナン 도 같은 모양이었습니다. 다른 칸을 모두 3 으로 두어도 그 주문은 들었으므로, 주문마다 읽는 자리는 하나뿐이고 이름표대로입니다.

## 틀렸던 것들

- FC 칸 이름이 틀렸다는 가설: 아니었습니다. `monster_fields()` 의 내성 목록은 필드 `22` 번호(1, 2, 3, 5, …) 순서로 값을 늘어놓아, 칸 순서(`13:$B736` = `03 02 01 07 06 05 …`)와 다릅니다. 이 목록을 `RESIST_NAMES` 와 순서대로 짝지으면 첫 값(실제 メラ)에 「イオ」, 셋째 값(실제 イオ)에 「メラ」가 붙습니다. NDS 대조의 「イオ」 자리가 メラ 를 막은 것은 이 때문으로 보입니다. 헷갈리지 않게 키 이름을 `resist_fields` 로 바꾸고, 칸 이름과 짝지을 때는 `resists()` 를 쓰라고 적었습니다.
- 처음에는 `$7324` 를 매 프레임 덮었는데, 세이브스테이트의 첫 턴이 どうぐ 로 골라져 있어 주문이 ライアン 자신에게 갔습니다(ザキ·メガンテ 로 ライアン 이 죽어 교회로). 둘째 턴 こうげき 를 고른 뒤 한 번만 쓰도록 바꿨습니다.

## 남은 것

- 내성 값 1·2 의 확률(`D8`·`66`)은 ヒャド 로만 전투에서 봤습니다. 다른 칸도 같은 표(`13:$B803`)를 쓰는 것은 코드 읽기입니다.
