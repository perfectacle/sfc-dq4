# 2026-10-25-13: 대사 제어 바이트와 롬 뱅크 지도

[대사 일지](2026-10-25-01-text.md) 에서 뜻을 몰랐던 제어 바이트를 게임에 아무 메시지나 띄우는 프로브로 하나씩 확인하고, 대사 밖 문자열·폰트·BRK 특수 형식을 풀었습니다. 그리고 PRG 뱅크 32개가 각각 무엇인지와 빈 자리를 세어 롬 지도를 만들었습니다. 결과는 [dq4-text-format.md](../docs/dq4-text-format.md), [dq4-bank-format.md](../docs/dq4-bank-format.md), [dq4-rom-map.md](../docs/dq4-rom-map.md) 에 있습니다.

## 1. 제어 처리기 표

`16:$8091` 은 글자 바이트가 `8D` 이상이면 `~바이트 × 2` 로 `16:$80AF` 표를 찾아 뛰어갑니다. 메시지 2633개에 실제로 나오는 제어 바이트를 세니 `ED`~`FF` 중 13종이었습니다.

```
ED 16:$81BF 메시지    6
EE 16:$8198 메시지   31
F6 16:$820A 메시지  469
FC 16:$80F7 메시지 1980
...
```

처리기를 읽으니 셋으로 나뉘었습니다. 줄바꿈·기다림(`F9`~`FF`), 치환(`F2`~`F8`, `EF`), 그리고 소리·쉼·연출(`ED`, `EE`, `F4`, `F1`). 치환 처리기는 인자를 메시지 안에서 읽지 않고 `$F9` 부터의 RAM 목록에서 하나씩 꺼냈습니다(`16:$82E9`). 메시지를 화면에 띄워 확인하려면 이 RAM 도 원하는 값으로 써야 했습니다.

## 2. 아무 메시지나 띄우기

`fc/dq4/tools/lua/textforce.lua` 를 만들었습니다. 메시지 출력 `16:$8656` 에 들어가는 순간 X:A(메시지 번호)를 `MSG` 로 바꾸고, 같은 순간 `ARGS` 의 RAM 값을 씁니다. 창 줄 버퍼 `$06AA` 가 바뀔 때마다 기록합니다. 왕좌의 방에서 왕에게 말을 걸면 원래 `060A` 가 나오는데, 이것을 바꿔 띄웠습니다.

```
MSG=000C ARGS=F9=00,FD=39,FE=30,FF=00
112 ライアンは / 12345ポイントのけいけんちをかくとく。
MSG=0072 ARGS=0554=10,0555=12,0556=FF
104 ミネアは　かくの　カードをひいた！
```

`F8` 은 `$FD`~`$FF` 의 24비트 숫자(0x3039 = 12345), `EF` 는 `$0554` 에 준비된 글자열이었습니다. `015E`(`〈F6〉は〈F5〉を となえた！`)에 `F9=01` 을 주니 `あああは　メラを` 가 나왔습니다. 인자 둘이 차례로 쓰여 `F6` 이 `$F9`(동료 1), `F5` 가 `$FA`(=0, 주문 0 `メラ`)를 가져간 것입니다. 이름 목록의 ID 가 목록 순번 − 1 이라는 것도 여기서 다시 맞았습니다.

몬스터 이름은 전투 세이브스테이트에서 띄웠습니다. 이 전투에는 スライム 와 おおみみず 가 하나씩 있습니다.

```
MSG=001F ARGS=F9=80 → しかし　スライムＡは　ねむっている！
MSG=001F ARGS=F9=89 → しかし　おおみみずＢは　ねむっている！
```

`F6` 인자의 bit7 이 몬스터, 아래 3비트가 칸, bit3-6 이 `Ａ`~`Ｈ` 였습니다.

## 3. 시간이 걸리는 제어

창 줄 버퍼가 바뀐 프레임을 나란히 놓고 간격을 봤습니다. `038F` 의 `ぐ[F4]　ぐふっ！` 는 `ぐ` 뒤 33프레임 멈췄습니다. `F4` 는 30프레임 쉼입니다(`LDX #$1E ; JSR $C90C`).

`EE` 는 뒤 바이트 하나를 더 읽습니다. 소리 루틴 `1F:$C01F` 에 걸어 두니 `030A`(`EE 1A`)에서 A=`1A` 로 불리고 글이 201프레임 멈췄다가 이어졌습니다. 일행이 늘 때의 팡파르입니다. `0449`(`EE 4E`)에서는 A=`8E` 였습니다. `40` 이상이면 `40` 을 더해 효과음으로 내고 기다리지 않습니다.

`ED` 는 전투 중에만 뜻이 있었습니다. 나오는 메시지 6개가 모두 `ぐふっ！[ED]` 로 적이 쓰러지는 대사입니다. 전투에서 `0465` 를 띄우니 `1E:$8D18`(숨김)과 `$8D2C`(보임)가 몬스터 칸 0 에 6번씩 번갈아 불렸습니다. 4프레임마다 찍은 화면에서 몬스터 자리 화소 수가 525 → 484 → 516 으로 바뀌었습니다.

## 4. 줄과 들여쓰기

앞 일지에 남긴 「`＊「` 뒤 `FC` 가 줄을 바꾸지 않는」 까닭은 들여쓰기였습니다. `FC` 는 커서가 들여쓰기 칸(`$55`)에 있으면 아무것도 하지 않습니다. 줄을 시작할 때 `16:$85FF` 가 앞 8글자 안에 `「` 가 있는지 보고 `$55` 를 2 로 둡니다. `＊「` 를 찍으면 커서가 2 라 `FC` 가 그냥 지나갑니다.

`F1` 은 이 들여쓰기를 0 으로 되돌립니다. `0389` 에서 クリフト 의 대사 줄은 2칸 들여 찍히고, `F1` 뒤 `しかし　へんじは　なかった……。` 만 0칸에서 시작했습니다. 메시지 첫 바이트가 `F1` 이면 한 가지를 더 합니다. 마을 사람과 말할 때(`$058B ≥ 5`) 게임은 메시지 앞에 `＊「` 를 저절로 붙이는데, `F1` 로 시작하면 붙이지 않습니다. 메시지 `0500` 이후 1507개 중 `＊「` 로 시작하는 것은 하나도 없고 146개가 `F1` 로 시작합니다.

창 폭은 `$54` 로, RAM 덤프에서 필드 `16`(22칸), 전투 `18`(24칸)이었습니다. 커서가 폭에 닿으면 `16:$838B` 가 저절로 줄을 바꿉니다. 메시지 본문에서 22칸을 넘는 줄은 전투 문구 10개(23~24칸)뿐이었습니다.

## 5. 대사 밖 문자열과 폰트

명령 창을 연 nametable 에서 `コマンド`, `はなす`, `じゅもん`, `つよさ`, `さくせん` 을 찾으니, 롬 `16:$B07D` 부터의 바이트가 압축 없이 그대로 들어 있었습니다. 탁점도 대사처럼 앞 바이트 `3D` 이고 화면에서 윗줄에 찍혔습니다. 이 문구들은 창 정의 표 `16:$A572` 가 가리킵니다. 전투 문구는 대사와 같은 메시지(`019E`, `001A`, `004C` …)로 `16:$8656` 을 지났습니다.

폰트는 CHR `$1000` 의 타일 앞 8바이트를 PRG 에서 찾았습니다. 글자 바이트 `00`~`8C` 141개가 모두 `18:$B840 + 글자 × 8` 과 같았고, 둘째 평면은 0 이었습니다. 왕좌의 방, 전투, 명령 창, 이름 입력 장면의 CHR 이 모두 그랬습니다.

## 6. BRK 특수 형식

BRK 처리기 `$C408` 을 끝까지 읽었습니다. `b2` 의 아래 4비트가 `B` 인 형식은 넷이었습니다. `0B`~`BB` 는 메시지 `(b2>>4):b1` 찍기, `CB`·`DB`·`EB` 는 `$627B` 플래그 켜기·끄기·검사(BRK+4 로 복귀), `FB` 는 소리입니다. 대사 글자마다 들리는 소리가 `BRK 96 FB` 였습니다. 왕좌의 방 700프레임에서 `EB`(검사)가 7번, 전투에서 `x3` 이 779번 지났습니다.

`x3` 의 인자 길이는 불린 함수가 정했습니다. 뱅크 `10` 함수 `02`~`09` 는 둘씩 같은 코드를 쓰고 `$77` 을 `33`·`53`·`73`·`93` 과 비교합니다. `n` 이 홀수면 BRK+3, 짝수면 셋째 바이트까지 읽습니다. 앞 일지에서 본 네 곳(`00 56 33`, `00 01 73`, `00 62 63 40`, `00 62 23 40`)이 모두 이 규칙과 맞았습니다.

## 7. 롬 뱅크 지도

`probe/cover.lua` 와 `probe/reads.lua` 를 다섯 장면(부팅, 보행, 전투, 왕좌의 방 대화·명령 창, 필드 조우)에서 돌렸습니다. 뱅크별 실행 수를 `fc/dq4/tools/dq4bank.py rom cover` 로 합쳤습니다.

```
boot   0F:433 10:13 19:2 1A:1047 1F:1444
battle 0B:29 0F:235 10:1976 11:1930 12:486 13:140 14:727 16:2142 18:148 19:1 1D:205 1F:1622
enc    08:23 0B:26 0F:1796 10:1254 11:279 12:471 14:1439 16:2045 18:691 19:1 1A:7 1D:349 1E:238 1F:1740
```

`11`, `13` 은 전투에서만, `1A` 는 부팅에서 주로 돌았습니다. 데이터 뱅크는 형식 문서의 디코더 범위와 CHR 덤프 타일 대조로 정했습니다. 타일 640개 중 440개가 `0C`, `0D`, `0E` 에 압축 없이 있었습니다.

뱅크 끝을 보니 바꿔 끼우는 뱅크는 모두 `$BFD8` 부터 같은 40바이트였습니다. `SEI ; INC $BFDF ; JMP $FF8E` 와 `" DRAGON QUEST IV"`, 벡터입니다. 대사와 맵의 비트열이 `$BFD8` 에서 다음 뱅크로 넘어가는 까닭이 이것입니다. 그 앞까지 FF 가 이어진 자리를 `fc/dq4/tools/dq4bank.py rom free` 로 세니 롬 전체에 1.9KB 쯤이었습니다.

고정 뱅크 `0F` 와 `1F` 는 `$C03D`~`$E549` 가 같고 `$E54A`~`$FF09` 가 달랐습니다. 소리 데이터 뱅크 `19` 를 읽는 코드는 모두 `1F` 쪽의 다른 영역에 있었습니다.

## 틀렸던 것들

- 처음엔 `$06AA` 버퍼를 전투에서도 22칸 줄로 풀었습니다. 그러자 `おおみみず` 의 탁점이 `み` 에 붙었습니다. 전투 창은 폭이 24칸이었습니다.
- 폰트를 올리는 루틴을 CHR `$10B0`(「あ」) 쓰기로 잡으려 했습니다. 부팅 100~126프레임의 쓰기는 타이틀 그림이었고, 그때 읽힌 `18:$BCF8` 은 라틴 대문자 글꼴이었습니다. 대사 폰트 `18:$B840` 을 옮기는 루틴은 찾지 못했습니다.

## 남은 것

- 메시지에 없는 제어 `F0`, `F2`, `F3`, `FA`, `FD` 는 코드 읽기만 했습니다. `F6` 의 `もどき` 갈래도 화면에서 보지 못했습니다.
- 창 정의 표 `16:$A572` 의 창 명령(`80` 이상) 뜻.
- 폰트를 CHR 로 옮기는 루틴.
- BRK 메시지 형식(`0B`~`BB`)과 플래그 켜기·끄기(`CB`, `DB`)를 실행 중에 잡지 못했습니다.
- 뱅크 `06`, `07` 의 내용, 코드 뱅크의 함수 표 길이, 이번 장면에서 실행되지 않은 코드의 자리.
