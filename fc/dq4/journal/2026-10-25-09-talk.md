# 2026-10-25-09: 인물 대화 스크립트

인물에게 말을 걸었을 때 나오는 메시지 번호를 롬만으로 내는 해석기를 풀었습니다. 인물 레코드에서 대화 번호를 꺼내고, 번호에 따라 서비스·예/아니오·메시지 하나·스크립트로 갈라지며, 스크립트는 조건·플래그·메시지 문장으로 된 작은 언어입니다. 결과는 [dq4-script-format.md](../docs/dq4-script-format.md) 에 있습니다.

## 1. 대화 진입 찾기

출발점은 메시지 출력 `16:$8656`(X:A = 메시지 번호)입니다. 왕좌의 방 세이브스테이트에서 왕에게 말을 걸며 `probe/trace.lua` 로 `$8656` 과, 뱅크 15 커버리지에서 찾은 `$98F8` 을 같이 찍었습니다.

```
33 98F8 prg=798F8 A=00 X=01 Y=03
53 98F8 prg=598F8 A=FD X=01 Y=04
76 98F8 prg=558F8 A=1A X=1A Y=22
84 8656 prg=58656 A=0A X=06 Y=04
```

같은 CPU 주소 `$98F8` 이 다른 뱅크에서도 실행됩니다. 뱅크 15(PRG `558F8`)로 들어온 것만이 대화이고, 그때 A = `1A` 가 왕의 인물 슬롯이었습니다. 메시지는 `060A` 입니다.

## 2. 대화 번호

`$98F8` 은 BRK 로 `1C:$96C7` 을 불러 인물 레코드에서 값을 꺼낸 뒤 `$9962` 에서 갈라집니다. 코드를 따라가니 대화 번호 = 머리 바이트 1 의 bit4-2(위 3비트) + 바이트 4(아래 8비트)이고, 갈래는 네 가지였습니다.

- `000`~`006`: 서비스(`$9CBF`). 무기점·도구점·방어구점·여관 등.
- `007`~`160`: `$9642` 의 포인터 표로 스크립트 346개.
- `161`~`178`: 메시지 하나를 내고 예/아니오, 대답에 따라 다음 두 메시지 중 하나.
- `179`~: 메시지 하나. 메시지 = 번호 − `161` + `500`. 왕은 `26B` → `060A` 입니다.

## 3. 스크립트 문장과 조건

`$9BA8`(문장 하나 실행)과 `$9B38`(건너뛰기)의 길이 규칙을 그대로 옮겨 `fc/dq4/tools/dq4talk.py` 의 파서를 만들었습니다. 바이트 bit6 이 켜지면 메시지, `07` 은 조건, `18`·`17`·`19` 는 이벤트 플래그 `$627B+i` 에 OR·AND·대입, `12` 는 서비스, `00`·`01` 은 뱅크 15 루틴 호출, `3E`·`3F` 는 블록과 스크립트 끝입니다. 조건은 `$99CE` 가 종류(아래 6비트)마다 다른 루틴을 부르고 bit7 이 결과를 뒤집습니다. 조건 뒤가 `06` 이면 블록, 아니면 문장 하나가 갈래이고, 이어서 `0B` 가 오면 else 갈래입니다.

스크립트 346개를 모두 읽었을 때 모르는 바이트가 나오지 않을 때까지 표를 늘렸습니다.

```
$ uv run python fc/dq4/tools/dq4talk.py rom/dq4.nes all
인물 860명, 대화 번호 568가지: msg 290, script 269, service 5, yesno 4
스크립트 346개를 풀어 못 읽은 명령 0개
```

## 4. 실측 프로브

`fc/dq4/tools/lua/talk.lua` 는 뱅크 15 의 `$98F8`(진입: 슬롯·Y), `$9A4C`(조건 결과), `$9CBF`(서비스), 뱅크 16 의 `$8656`(메시지)을 `talk.txt` 에 찍고, 진입할 때 CPU 메모리를 `talk_N.bin` 으로 남깁니다. `dq4talk.py compare` 가 그 덤프의 플래그·장·시간으로 조건을 풀어 예측한 메시지와 기록을 맞춥니다.

처음에는 인물에게 걸어가 말을 거는 드라이버(`fc/dq4/tools/lua/talkseek.lua`)를 만들었습니다. 막힌 칸을 걸어 보며 배우는 너비 우선 탐색인데, 인물이 돌아다녀서 성 앞에서는 5명에게만 닿았습니다. 그래서 프로브에 `SLOT` 을 두어, 아무 인물에게나 말을 건 순간 `$98F8` 의 A 를 원하는 슬롯으로 바꿨습니다. 한 자리에서 맵의 모든 인물을 돌릴 수 있습니다. 다른 마을은 [워프 도구](2026-10-25-08-warp.md)로 인물 바로 아래 칸으로 옮겨 말을 걸었습니다(인물이 움직이기 전에 걸도록 도착 직후 A).

```
$ fc/dq4/tools/dq4talk.py rom/dq4.nes compare work/f04/0C
04/00 슬롯 0C 대화 161: 기록 0500 0501 / 예측 0500 0501 → 같음
$ fc/dq4/tools/dq4talk.py rom/dq4.nes compare work/f12/06     # 여관 주인, 바로 앞
12/00 슬롯 06 대화 011: 기록 0529 / 예측 0529 → 같음
```

## 5. 카운터 너머

12/00 여관 주인(대화 `011`)의 스크립트 첫 조건 `02` 는 `$E9` 가 0 인지 봅니다. `$E9` 는 진입 때 Y 입니다(`$992F`). 주인의 왼쪽·오른쪽·위·아래와 두 칸 아래에서 말을 걸어 보니, 바로 옆에서는 Y = `22` 로 잡담 `0529`, 카운터 너머 두 칸 아래에서는 Y = `00` 으로 서비스 6(여관, 메시지 `0231`·`0233`)이었습니다.

```
202 talk 06 1 00
209 svc 06
215 msg 0231
```

## 6. 장 번호와 플래그

조건 `16` 은 `$615A` = n − 1 입니다. 1장 세이브스테이트의 `$615A` 는 `00` 이라 「5장」 갈래가 실린 왕좌의 방 인물이 모두 1장 대사를 냅니다. 워프 도구의 `SET="615A=04"` 로 장 번호만 바꾸고 다시 돌리니 17명 모두 5장 대사(`0A41`~`0A4C`, `0645`)로 바뀌었고 예측과 같았습니다.

플래그 켜기는 성 앞 노인(대화 `00A`)으로 확인했습니다. 「따라가 볼까」 에 「はい」 를 고르면 `18 0E 10` 이 실행되어 `$6289`(`$627B+0E`)가 `00` → `10` 이 됩니다. 다시 말을 걸면 첫 조건 `1B 0E 10` 이 참이 되어 `0789` 가 나올 것입니다(코드 읽기, 두 번째 말 걸기는 아직 안 해 봄).

예/아니오는 04/00 의 대화 `161` 에서 「いいえ」 를 골라 `0502`(= 질문 + 2)가 나오는 것을 봤습니다.

## 7. 결과

맵 4곳, 인물 57명, 말 걸기 86번에서 기록과 예측이 모두 같았습니다.

| 맵 | 인물 | 다름 |
| --- | --- | --- |
| 02/01 왕좌의 방(1장, 5장으로 바꾼 것) | 21, 17 | 0 |
| 02/00 성 앞 | 5 | 0 |
| 12/00 마을 | 16 | 0 |
| 04/00 마을 | 15 | 0 |

일행 조건(`03`)이 걸린 5장 인물 3명은 롬만으로 조건을 풀지 못해, 기록된 조건 결과를 따르고 나머지 갈래가 맞는지만 봤습니다.

## 틀렸던 것들

- `$98F8` 이 실행될 때마다 대화라고 봤는데, 같은 CPU 주소가 다른 뱅크(PRG `798F8`·`598F8`)에서도 돕니다. `$0507`(현재 뱅크)로 PRG 오프셋을 확인해 뱅크 15 만 잡게 했습니다.
- 조건 `02` 를 처음에는 「말 건 방향」 으로 봤습니다. 실제로는 카운터 너머인지(진입 때 Y = 0)였습니다.
- 서비스 문장 `12` 뒤에도 스크립트가 이어진다고 봤는데, `$9CBF` 로 간 뒤 상점·여관이 끝나면 대화가 끝납니다. 여관 기록에서 서비스 뒤 메시지가 모두 여관 대사였습니다.

## 남은 것

- 일행 조건 `03`·`13`(뱅크 10 함수 6·7), 아이템 조건 `11`, 조건 `1E` 의 뜻.
- 서비스 0·4·5 의 정체. 호출 문장(`00`·`01`) 126곳이 부르는 루틴.
- 밤의 갈래와 밤 인물 목록에서의 대화 번호. 겉모습 비트와 화면 그림, 레코드 바이트 2.
- `1C:$96CE` 가 장소 3A/04 에서 순번을 03 으로 바꾸는 까닭.
