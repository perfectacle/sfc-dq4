# 2026-10-25-47: 창의 쪽 나누기 바이트와 x3 `83` 이 도는 자리

지난번에 「값은 보지 않는다」고 적은 창 본문 바이트 `B1`~`BC` 가 실제로는 한 쪽에 보일 줄 수였습니다. 메모리에서 그 바이트 하나를 바꾸니 ルーラ 행선지 창의 줄 수가 그대로 바뀌었습니다. 뱅크 호출 `x3` 의 `83` 형식이 쓰인 두 자리 중 `10:$BAE1` 은 몬스터 AI 가 べホマラー·べホマズン 을 평가하는 루틴 안이었고, 그 갈래를 억지로 지나게 해 BRK+5 복귀를 실측했습니다. 결과는 [dq4-text-format.md](../docs/dq4-text-format.md#본문-바이트) 와 [dq4-bank-format.md](../docs/dq4-bank-format.md#83-이-도는-장면) 에 있습니다.

## 1. `B1`~`BC` 는 한 쪽의 줄 수

쪽을 자르는 `16:$9752` 는 `$03D5` 의 낮은 니블을 더할 뿐 바이트 값을 쓰지 않아 보였습니다. `$03D5` 에 쓰는 곳을 찾으니 창을 열 때 레코드를 훑는 `16:$961D` 가 있었습니다.

```text
16:9621  LDA ($EE),Y / INY
16:9624  CLC / ADC #$43 / BCS $961D      ; BD 이상은 건너뜀
16:9629  ADC #$0C / BCC $961D            ; B1 미만은 건너뜀
16:962D  ADC #$00 / ORA $03D5            ; b − B0 을 낮은 니블에
```

처음 만난 `B1`~`BC` 의 `b − B0` 이 `$03D5` 에 들어가고, 이 바이트를 읽을 때 `$03D2` = min(`$03D1` + n, 줄 수)가 됩니다. 레코드를 보면 ルーラ `16` 이 `B5`, 전투 주문 `34`~`36` 이 `B3`(2열 3줄 = 주문 6개), 전투 시험 몬스터 목록 `4E` 가 `BC` 로, 화면에 보이던 줄 수와 같습니다.

확인은 디버그 B 모드 시작(`dq4-debugB-start.mss`)에서 창 `16` 을 강제로 열고, PRG `5A80E` 의 `B5` 를 메모리에서 바꿔 띄운 것입니다. 새 프로브 `textx3.lua` 의 `PRGPOKE` 가 바꾸고, `THEN=textitem.lua` 로 기존 프로브를 이어 돌립니다.

```sh
THEN=textitem.lua PRGPOKE="5A80E=B3" WIN=16 DRIVER=$LIBDIR/seq.lua STATE=$PWD/work/state/dq4-debugB-start.mss \
  SEQ="wait:30,a:4,wait:60" TAIL=200 EVERY=0 MAXF=320 WATCH="d0=03D0,d1=03D1,d2=03D2,d5=03D5,f5=00F5" \
  SHOT_DIR=$PWD/work/pgB3 "$MESENCE" --testrunner --nes.ramPowerOnState=AllZeros $PWD/rom/dq4.nes \
  $PWD/fc/dq4/tools/lua/textx3.lua
```

```text
B5: end d0=1E d1=00 d2=05 d5=05 f5=60
B3: end d0=1E d1=00 d2=03 d5=03 f5=60
B8: end d0=1E d1=00 d2=08 d5=08 f5=60
```

행선지 30개(`1E`) 중 3·5·8개가 보였고 화면도 `ブランカ`·`エンドール`·`ボンモール` 세 줄이었습니다. `BD`·`BE` 는 `16:$961D` 가 건너뛰고, 롬의 창 레코드에 쓰는 곳이 없습니다.

## 2. `10:$B500` 표는 몬스터 AI 의 평가 루틴

`x3` `83` 이 든 `10:$BADB` 를 가리키는 `10:$B52A`·`$B52C` 는 `10:$B4D2` 에서 시작하는 120칸 주소 표의 일부였습니다. 이 표를 쓰는 곳은 `10:$B497` 하나이고, 행동 ID `$0B` × 2 로 찾습니다. 그러면 두 칸은 행동 `2C`(べホマラー)·`2D`(べホマズン)입니다. [AI 종류](../docs/dq4-data-format.md#ai-종류) 1~3 의 몬스터가 칸마다 쓸모를 묻는 루틴입니다.

롬에서 두 주문을 가진 몬스터는 はしりとかげ·スライムべホマズン 둘인데 모두 AI 종류 0 이라 이 루틴을 부르지 않습니다. 그래서 1장 첫 전투에서 몬스터 행동 칸 `$6D8C`~`$6D97` 을 `28`(→ 행동 `2C`)로 두고 `probe/trace.lua` 로 보았습니다.

```text
  11 BADB prg=43ADB A=80 000B=2C …
  11 B497 prg=43497 A=03 000B=2C …
```

AI 종류 1 인 スライム 에서 `10:$BADB` 가 돌았지만, 첫 명령 `BMI` 가 A = `80`(`$7300,X`, 몬스터 쪽)으로 `$BAF2` 로 갔습니다. `$BAE1` 은 bit7 이 꺼진 쪽, 곧 일행 쪽 전투원일 때의 갈래입니다. `textx3.lua` 의 `REGS="43ADB:a=00,ps=06"` 로 그 자리에서 A 와 플래그를 바꾸었습니다.

```text
prg=43AE1 cpu=BAE1 6B 83 02 n=26 ret=+5:26 first=109
```

26번 모두 BRK+5 로 돌아와, 코드만 읽고 적은 `83` 의 길이(셋째·넷째 바이트를 인자로)가 맞았습니다.

둘째 자리 `11:$BC2B` 는 부르는 곳이 없던 게 아니라 `11:$BC0C` 의 분기 대상이었습니다. 그 루틴 `11:$BC02` 는 전투 いれかえ 를 끝내는 `11:$BB91` 이 마차에서 들어올 동료(`$7358`, 창 `3B` 에서 고름)로 부릅니다. 5장 필드 전투에서 いれかえ 를 해야 볼 수 있어 이번에는 코드 읽기로 남겼습니다.

## 틀렸던 것들

- 창 `B1`~`BE` 의 값은 쓰이지 않는다고 적었습니다. 쪽을 자르는 루틴만 보고, 값을 미리 넣어 두는 `16:$961D` 를 놓쳤습니다.
- 몬스터 행동 칸을 べホマラー 로 바꾸면 `$BAE1` 이 돌 줄 알았습니다. 그 갈래는 일행 쪽 전투원용이라 몬스터로는 지나지 않았습니다.
- `11:$BC21` 을 부르는 `JSR` 을 찾다가 없다고 적었습니다. 같은 루틴 안 `BCC` 의 분기 대상이었습니다.

## 남은 것

- `10:$BAE1` 이 실제로 도는 장면: 일행 쪽에서 `10:$B497` 을 부르는 경우가 있는지(동료 AI `13:$9212` 쪽).
- `11:$BC2B`: 5장 필드 전투에서 마차 동료와 いれかえ.
- `B0` 이 켜는 `$F5` bit0 의 효과, 걸러내기 값 `08`·`80`·`40`, 값 번호 `4A`, 목록 `DC`, 곁 창 `0F` 의 틀, 화면에서 못 본 루틴 항목은 그대로 남음.
