# 2026-10-25-40: 적 조우의 남은 것 3

[앞 일지](2026-10-25-32-encounter3.md)가 남긴 조우 문제를 마저 풀었습니다. 특수 전투 01 을 부르는 곳, デスパレス 의 マネマネ 와 へんげのつえ, `$6E44` 의 bit7 과 값 3, 3장 터널을 진행 플래그로 지나기, 불러오기 때의 `1E:$A5AD` 입니다. 앞 형식 문서에 적었던 인물 블록 명령 길이 표의 틀린 줄도 고쳤습니다. 결과는 [dq4-encounter-format.md](../docs/dq4-encounter-format.md) 에 있습니다.

## 1. 명령 길이 표를 버리고 인물 블록 해석기로

앞 형식 문서는 `21` 명령을 찾으려고 인물 블록 명령 길이를 직접 세어 표로 두었습니다. 그 표의 「`80`, `81` = 끝」 이 틀렸습니다. `81` 은 `$7180` 횟수를 줄여 0 이 아니면 되돌아가고, 0 이면 다음 명령으로 이어 갑니다. 끝이 아닙니다. 그 사이 [dq4-npcblock-format.md](../docs/dq4-npcblock-format.md) 가 명령 표 전체를 실측과 함께 정리했으므로, 형식 문서의 길이 표는 지우고 그 문서로 이었습니다.

`dq4encounter.py scripts` 도 자기 길이 표 대신 `dq4npcblock` 의 `all_blocks`·`decode` 를 씁니다. 앞에는 맵 목록(뱅크 05)만 풀었는데, 이제 이벤트 목록(뱅크 1C)까지 들어갑니다.

```
블록 2117개(본문 주소가 다른 것), 명령 5010개, 못 읽은·넘친 명령 0, 명령 21 0번
```

이벤트 목록의 블록에도 `21` 은 없습니다.

## 2. 특수 전투 01

01 은 06 과 같은 どぐうせんし 한 마리입니다. 부르는 곳을 네 가지로 찾았습니다.

- 일반 호출의 모든 꼴: `b1` & 7F = 01, `b2` = `88`~`8F`(아래 4비트 3·B 빼고). 롬 전체에서 37곳이 나왔고, `00 01 8F` 30곳 말고 7곳은 데이터나 다른 명령의 피연산자였습니다(`08:$81E2` 의 `STA $0100,Y ; DEY` 등).
- `$A1AD` 를 직접 뛰는 `JSR`·`JMP`: 없음. 뱅크 18 함수 표 `$8002` 하나뿐입니다.
- `BRK` 자리(또는 그 1~3바이트 앞)로 뛰는 분기·점프: 상자 `1E:$B868` 의 `LDA #00 ; BEQ` 하나. 나머지 맞은 바이트는 이벤트 표의 포인터였습니다.
- A 를 계산하는 곳: 투기장 `LDA $B024,X`(X = `$6287` & 7)는 X 가 5~7 이면 표 뒤의 `20 0B D2` 를 읽고, デスパレス 는 `TYA`(Y = `1C`~`21`)입니다.

어디에도 01 은 없습니다. 롬에 남은 쓰이지 않는 칸으로 봅니다.

## 3. マネマネ 와 へんげのつえ

マネマネ(겉모습 `36`)는 `03/00` 에 없었습니다. 그룹 03 의 다른 맵을 `dq4talk.py` 로 훑으니 `03/01` (05,14) 와 `03/02` (09,15) 에 있었습니다. `03/01` (06,14) 로 워프해 왼쪽에 말을 걸었습니다. 이번 실험용으로 프로브 [fc/dq4/tools/lua/encwatch.lua](../tools/lua/encwatch.lua) 를 새로 만들었습니다(특수 전투 진입, デスパレス 대화, `$6296`·`$6297`·`$6E44` 쓰기와 읽기, 메시지, `1E:$A5AD`).

```
202 talk 36 03 01 00 00      15:B10E, 겉모습 36
209 msg 0446                 くふふ！ うまそうな　にんげんだわい！
232 look 1D                  08:B752 Y = 1D
353 a1ad 1D
```

다음은 대화 앞 검사 `15:$B132` 입니다. `BRK 1B EB FF` 는 `$6296` 이 0 인지, `BRK 1C EB 80` 은 `$6297` bit7 을 봅니다. 두 값을 써 넣고 말을 걸었습니다.

| `$6296` `$6297` | 메시지 | 전투 |
| --- | --- | --- |
| `78 80` | `0758` | 없음 |
| `01 A5` | `0758` | 없음 |
| `78 05` | `0448` おのれ！　くせものめ！ | `1D` |
| `00 80` | `0446` | `1D` |

`$6296` 을 쓰는 곳은 셋뿐이었습니다. `1E:$B031` 이 `78`, `1E:$9E71` 이 걸음마다 하나씩 줄이고, `1E:$981E` 가 0 으로 지웁니다. `1E:$B02F` 를 부르는 곳을 찾지 않고 바로 써 봤습니다. へんげのつえ(아이템 `68`)를 ライアン 소지품 첫 칸에 넣고 どうぐ → つかう 를 고르니 `1E:$B02F` 를 지나 `$6296` = `78` 이 됐습니다. `$6297` 은 쓸 때마다 달랐습니다.

```
-- 40: ... w6297 A5 7B071 | talk 36 03 01 78 A5 | msg 0758
-- 41: ... w6297 4C 7B071 | talk 36 03 01 78 4C | msg 0447 | look 1D | a1ad 1D
-- 42: ... w6297 C4 7B071 | talk 36 03 01 78 C4 | msg 0758
```

12번 중 bit7 이 켜진 10번은 그냥 대화였고, `4C` 인 2번만 싸움이 났습니다. `1E:$B052` 를 읽으면 그룹 03 에서는 난수 < `C0` 일 때 모습 표의 뒤쪽(몬스터) 칸을 고르고 bit7 을 붙입니다. 사람 모습이 되면 「くせものめ！」 하고 덤벼드는 셈입니다. `$6296` = `02` 로 두고 두 걸음 걸으면 `01`, `00` 이 되고, 0 이 될 때 `1E:$97B8` 이 겉모습을 되돌립니다.

## 4. `$6E44` 의 값 3 과 bit7

값 3 을 넣는 곳은 모두 전투 중(뱅크 11)이고, bit1-0 을 읽는 `11:$8D9B` 는 값마다 C 를 다르게 돌려줍니다. 시작 메시지 고르기 `12:$84E9` 는 3 을 0 처럼 넘깁니다. 그래서 「이번 차례에 누가 움직이나」 로 보고 걸어서 난 전투의 `$A123` 에서 `$6E44` 를 `03` 으로 바꿔 봤습니다.

```
00: 216 msg 0005 | 334 msg 004C | 354 msg 0016 | ... | 499 w6E44 00 46A81
03: 216 msg 0005 | 326 w6E44 00 46A81 | 398 msg 004C | ...
```

`03` 은 첫 차례에 아무도 공격하지 않고 `11:$AA81` 이 0 으로 지운 뒤 둘째 차례부터 싸웠습니다. 앞 일지가 「메시지가 더 나오지 않았다」 고 적은 것은 이 빈 차례였습니다.

bit7 은 전투 끝 `18:$A19F` 가 `BMI` 로 보고, 꺼져 있을 때만 `BRK 15 EF` 를 부릅니다. 이 함수 `1E:$A1C9` 는 맵을 다시 그리고 음악을 되돌리는 쪽입니다. 앞 일지는 bit7 을 켠 전투의 메시지·경험치·골드만 보고 차이가 없다고 했는데, 이긴 뒤의 화면을 보지 않았습니다. 1장 첫 전투 세이브스테이트에서 `$6E44` 를 `00`·`80` 으로 두고 이겨 보니, `00` 은 `1E:$A1C9` 를 지나 필드로 돌아왔고 `80` 은 그 함수를 지나지 않고 검은 화면에 명령 창이 떴습니다. 특수 전투는 늘 bit7 이 켜져 있고, 부른 이벤트가 전투 뒤 화면을 스스로 그립니다.

## 5. 3장 터널을 진행 플래그로

앞 일지는 `$615A` 를 바꾸고 워프해 그룹 42·21 을 봤습니다. 이번에는 3장 시작 세이브스테이트의 플래그로 해 봤습니다. 먼저 `$62AA` bit3 을 켜는 곳을 찾았습니다. 절대 주소 쓰기는 `15:$9D83` 하나였고, 그 앞 `15:$9D68` 은 2장 마을의 병사(대화 `035`) 것이라 3장과 상관이 없어 보였습니다. `15:$9D83` 을 가리키는 바이트를 다시 찾으니 대화 스크립트 `call 15:9D83` 이 하나 더 있었습니다. 3장 ネネ(대화 `075`)가 「いま　しらせがきて どうくつが　かいつうしたって！」 뒤에 부르는 것입니다.

그 앞 조건 `$6286` bit0 은 `1C:$9C8C` 가 켭니다. 진행 목록을 고르는 `1C:$9C6F` 가 `$6287` bit7(굴 파는 노인에게 공사비를 낸 것)이면 `04/01` 에 들어갈 때 켭니다.

3장 시작 세이브스테이트는 처음 장면(ネネ 의 대사, 이벤트 `2F`)이 돌고 있어 워프의 첫걸음이 먹히지 않았습니다. A 를 눌러 장면을 넘기고 걸을 수 있는 상태를 만든 뒤 `$6287` = `80` 을 써 `04/01` 로 들어가니 `$6286` 이 `01` 이 됐습니다. 그런데 `04/00` 의 ネネ 자리(06,1C)에는 아무도 없었습니다. 인물 표 슬롯 `12` 가 (80,80) 이었습니다. 들어갈 때 인물을 치우는 `04/00` 루틴 `1C:$A3B9` 가 3장 낮에 `BRK 0B EB 20`(가게를 산 것)이 꺼져 있으면 슬롯 `12` 를 치웁니다. 밤의 `04/08` 에서도 같은 까닭으로 없었습니다. `$6286` = `20` 도 함께 써 넣고 다시 했습니다.

```
04/01 도착 뒤      6286=21 6287=80 62AA=00
ネネ 에게 말 걸기   msg 08A0 | msg 08A2 | msg 08A3      6286=21 6287=80 62AA=08
```

필드 (79,5D) 로 들어가면 bit3 이 켜진 상태에서는 `42/01` (05,0F), 켜기 전 상태에서는 `42/00` (05,0B) 였습니다.

`42/01` 을 지나 장 끝까지 걸어 보는 데서 막혔습니다. 처음에는 seq 입력을 시간으로 맞춰 걸었는데 (11,06) 에서 멈췄습니다. 화면을 보니 사람이 바로 옆에 서 있었습니다. `dq4npcblock.py 42 01` 을 보니 레코드 00·01 이 (12,04) → (12,06) → (0A,06) → (0A,0C) → (05,0C) → (05,0F) 로 걸어 나가 사라지는 이주민이었습니다. 일행이 걷는 길을 거꾸로 걸어오고, 마주 서면 둘 다 멈춥니다.

`encwatch.lua` 에 맵 좌표를 차례로 맞추며 걷는 `ROUTE` 를 넣었습니다. 옆 칸 (03,0D) 에 비켜 서서 기다렸는데, 1400프레임은 모자라 다시 (0A,06) 에서 마주쳤습니다. 두 사람의 걸음 간격(`$7040` 위 4비트)이 6 이라 느리게 걷기 때문입니다. 4300프레임을 기다리니 둘이 (05,0F) 에서 `08`(숨고 빼기)을 하고 사라졌고, 그 뒤 걸어서 (1F,02) 에 닿자 장 끝 메시지가 나왔습니다.

```
... n6=05 n7=05 | n6=81 n7=05 | n6=81 n7=81     두 사람이 빠짐
x=03 y=0C ... x=1D y=02 | x=1F y=02
4927 route 끝 1F 02 | 5261 msg 037C               こうして　トルネコは…
```

같은 3장 상태로 필드 (B2,4E) 에서 위로 걸어 `21/00` 에 들어가 아래로 걸으니 (00,0E) 에서 멈췄습니다. 3장 진행으로는 사막 여관 남쪽에 갈 수 없습니다.

## 6. 불러오기와 `1E:$A5AD`

전원을 켜고 A 를 40프레임마다 누르니 「ぼうけんをする」 → 「ぼうけんのしょ　1：あああ」 를 골랐습니다. MesenCE 테스트러너가 넣어 주는 SRAM 의 칸입니다. 163프레임에 `12:$AC47` 이 플래그 영역을 옮겼고 493프레임에 `1E:$A3BA` → `$A5AD` 가 돌았습니다. 300프레임에 지울 값들을 일부러 써 두고 다시 했습니다.

```
493 a5ad 01 03 7F 32 80      $0515 $6E42 $6E41 $6BEB $6E05
493 a3c9 00 00 00 00 00
```

불러오기에서도 지웁니다. 다만 이 칸은 1장 처음에 저장된 것이라(메시지 `0300`·`0301` 로 장 시작 장면이 이어짐) 장 중간에 저장한 칸으로는 보지 못했습니다.

## 틀렸던 것들

- 명령 길이 표의 「`81` = 끝」. 앞 일지는 `81` 에서 블록 풀기를 멈춰 그 뒤 명령을 보지 않았습니다. 새 해석기로 블록 끝까지 다시 세어도 `21` 은 0번이라 결론은 같았습니다.
- `$6E44` bit7 은 「차이 없음」 이 아니었습니다. 이긴 뒤 화면을 보지 않아 놓쳤습니다.
- `$62AA` bit3 을 켜는 대화가 2장 병사 하나뿐이라고 처음에 생각했습니다. 그 루틴의 중간(`15:$9D83`)을 부르는 다른 스크립트가 있었습니다.
- 3장 상태로 `04/00` 에 들어가면 ネネ 가 있을 줄 알았습니다. 들어갈 때 인물을 치우는 장소별 루틴이 가게 플래그를 봅니다.
- `$C000` bit5 를 처음에 거꾸로 읽었습니다. `AND #$20 ; BEQ` 는 bit5 가 꺼져 있을 때 건너뜁니다.

## 남은 것

- `$6E44` bit7 을 읽는 나머지 곳(`10:$A4E3` 경험치 쪽, `11:$B8A0`·`$B8AB` 음악·그림 표 등)이 바꾸는 것.
- `1E:$9817`(`$6296` 지우기)을 부르는 때, へんげのつえ 모습 표 `1E:$B079` 의 값과 그림.
- 장 중간에 저장한 칸(`$6291` bit7)을 불러올 때의 `1E:$A5AD`.
- 3장의 공사비·가게 두 단계를 게임 안에서 하는 것(지금은 그 두 플래그만 써 넣음).
