# 2026-10-25-02: 마을·던전 맵

마을·성·던전 맵 269개의 블록 배치를 롬에서 푸는 디코더를 만들었습니다. 결과는 [dq4-map-format.md](../docs/dq4-map-format.md) 에 있습니다.

## 1. 맵이 풀리는 곳

앞마당에서 왕좌의 방으로 들어가는 120프레임 동안 쓰기 프로브를 `6000-7FFF` 에 걸었습니다. `0F:$E5D4` 가 `$7800` 부터 1155번, `0F:$E74E` 가 그 안에 1020번 썼습니다. 같은 구간 읽기 프로브에서는 `0F:$E625` 가 뱅크 `09` 를 1650번 읽었습니다.

`$E618` 은 한 비트씩 읽는 루틴이었고, `$E549` 부터가 해제기였습니다. 처음에 블록 값 하나로 맵을 다 채우고, 2비트 명령으로 사각형·점·길을 그립니다. 길은 방향을 돌고, 갈림길을 쌓아 두었다가 돌아오는 거북이 그리기였습니다.

## 2. 그대로 옮겨 맞춰 보기

해제기 진입(`$E549`)과 해제 직후(`$E560`)에 RAM 을 덤프하는 `fc/dq4/tools/lua/atpc.lua` 를 만들었습니다. 진입 때 값은 포인터 `09:$850F`, 폭 `$20`, 높이 `$24`, 위치 11비트, 블록 5비트였습니다. 어셈블리를 따라 옮긴 디코더 결과를 `$E560` 덤프와 비교했습니다.

```
02/01: 1152 바이트 중 0 차이
02/00: 1558 바이트 중 0 차이
```

`$E560` 은 프레임 안에서 두 번 지났는데, 첫 번째는 다른 맥락이라 두 번째 덤프가 맞았습니다.

## 3. 맵 표

폭·높이를 쓰는 `0F:$E957` 앞에서 `08:$B6C8` 이 `BRK 81 7F` 로 뱅크 17 함수 1 의 **주소**를 꺼내고, `$63` 번째 그룹 포인터, 그 안 `$64` 번째 3바이트 레코드(맵 번호, 데이터 포인터)를 읽었습니다. 그룹 표는 `FFFF` 로 끝나고 그룹이 74개, 레코드가 269개였습니다. 데이터 뱅크는 (그룹, 순번) 범위로 `09`·`0A`·`0B` 가 갈립니다.

전부 풀어 해제가 끝난 자리가 다음 맵 시작과 같은지 봤습니다.

```
맵 269개, 경계 268곳 중 0곳 다름
```

## 4. 출구 표 다시 보기

[첫 일지](2026-10-24-01-fc-env.md) 에서 출구 표 `$05A0` 의 +2, +3 을 모른다고 남겼습니다. 왕좌의 방에서는 `02 00`, 앞마당에서는 `02 01` 이었고, 그게 목적지의 (그룹, 순번)이었습니다.

## 틀렸던 것들

- `$0028` 을 맵 번호로 봤는데, 269개 맵에 70가지 값뿐이었습니다. 장소는 (`$63`, `$64`)이고, `$0028` 은 레코드 첫 바이트(맵 종류)입니다.
- 처음 비교에서 그룹 `00/00` 을 왕좌의 방으로 잘못 짚어 717바이트가 달랐습니다. 왕좌의 방은 `02/01` 입니다.
