# 2026-10-25-16: 맵 블록·타일·팔레트·통행

맵 해제 결과(`$7800`, 칸마다 블록 번호)가 화면의 8×8 타일·팔레트가 되는 과정과, 걸을 때 칸이 막히는지 정하는 블록 속성을 풀었습니다. 맵 종류 49가지(필드 포함 전부)에서 롬만으로 만든 블록 표·CHR·BG 팔레트가 MesenCE 덤프와 같습니다. 결과는 [dq4-block-format.md](../docs/dq4-block-format.md), 디코더는 [fc/dq4/tools/dq4block.py](../tools/dq4block.py) 입니다.

## 1. nametable 은 누가 쓰나

1장 세이브스테이트 세 개(왕좌의 방·성 앞·필드)에서 `end.nt`(nametable 덤프)를 뽑아 `dq4map.py` 의 `$7800` 과 나란히 놓으니, 블록 하나가 2×2 타일로 들어가 있었습니다. PPU 큐를 쓰는 곳을 `probe/writes.lua` 로 찾아 `0F:$EB23`(블록 → 타일 4개)에 닿았고, 그 타일 번호는 RAM `$7600`+블록×4 에서 읽습니다. `$7600` 에 쓰는 곳을 다시 찾으니 맵에 들어갈 때 도는 `08:$84E9` 였습니다.

```sh
DRIVER=$LIBDIR/seq.lua STATE=$PWD/work/state/dq4-ch1-throne.mss SEQ="down:150,left:16,down:300" TAIL=300 \
  EVERY=0 FROM=1 WATCH=7600-76FF,6F20-6F5F MAXF=760 SHOT_DIR=$PWD/work/wr-load \
  "$MESENCE" --testrunner --nes.ramPowerOnState=AllZeros $PWD/rom/dq4.nes $LIBDIR/probe/writes.lua
```

## 2. 블록 정의와 모양 레코드

`08:$8055` 가 맵 종류(`$0028`) × 64 로 블록 정의 2바이트 32개를 고르고, `08:$80D5` 가 그 2바이트에서 11비트 모양 레코드 번호를 만들어 3바이트 레코드(CHR 번호, 모양·뱅크, 속성)를 읽습니다. 모양 번호는 「첫 타일에서 나머지 세 타일이 몇 타일 떨어져 있나」 표의 번호입니다. 그림은 뱅크 `0C`·`0D` 에 압축 없이 있고 `0F:$C7E1` 이 16바이트씩 PPU `$1000`+타일×16 으로 복사합니다. 같은 그림 주소는 한 번만 올립니다(`08:$823D`).

맵에 들어간 직후(`08:$853B`)를 잡기 위해 PC 가 닿을 때 CPU 메모리·CHR·nametable·팔레트를 덤프하는 [fc/dq4/tools/lua/blockload.lua](../tools/lua/blockload.lua) 를 만들었습니다. 롬만으로 만든 `$7600`·`$76C0`·`$6F20`·`$6F40` 과 올린 CHR 타일을 이 덤프와 비교하는 것이 `dq4block.py compare` 의 첫 줄입니다.

```
맵 종류 0D: 블록 표 0 다름, CHR 타일 101개 중 0 다름
```

## 3. 안 맞던 칸들

처음 비교에서 어긋난 곳이 몇 군데 있었고 하나씩 루틴을 찾았습니다.

- 맵에 쓰이지 않은 블록은 올리지 않고(`08:$8487`), 처음 비는 블록 칸에 타일 `FC`~`FF` 짜리 정의를 넣습니다(`08:$8710`). 맵에 쓰인 블록 표시는 `1E:$A046` 이 만듭니다.
- 1장이 아니면 블록 정의 `00 17` 이 `00 12` 로 바뀝니다(`08:$808E`). 필드의 블록 16 이 그랬습니다.
- `$7800` 자체가 푼 직후와 달랐습니다. `1E:$9F47` 이 벽 아래 칸을 그늘 진 블록으로 바꿔 씁니다.
- 집 안에 들어가면 바깥이 검게 그려집니다. 칸 위 3비트(구역)가 주인공 칸과 다르면 블록 20·21 로 그립니다(`0F:$D4E6`).
- 화면 왼쪽 위 좌표가 맵 왼쪽 밖(`$7C`=`FB`)일 때 어긋났는데, 좌표를 8비트로 감싸지 않은 디코더 쪽 잘못이었습니다.

## 4. 통행

`$6F40` 을 읽는 곳을 모두 찾아 `0F:$D088` 에 닿았습니다. 걸으려는 칸의 블록 속성을 `$0594` 에 넣고 bit7 이면 못 갑니다. `83` 은 소리 없이 막히고 배를 탄 상태(`$0515`)에서만 지나갑니다.

확인은 걷기로 했습니다. 왕좌의 방, 워프로 만든 마을·동굴·탑·성 상태, 필드에서 네 방향으로 200프레임씩 누르고 끝 좌표를 통행 지도로 예측한 자리와 비교했습니다.

```
throne-step left pred=0C 15 3 block 1E prop 80 got=end x=0C y=15
0E_00 right pred=0E 2C 4 block 0C prop AF got=end x=0E y=2C
34_00 left pred=0C 14 2 block 00 prop 80 got=end x=0C y=14
field-step right pred=AD 2D 10 block 06 prop 80 got=end p=AD q=2D   # 필드 좌표 $42/$43
3C_01 left pred=19 04 8 special 13 got=end x=19 y=0C
```

32번 가운데 막힌 칸 앞에서 멈춘 23번이 모두 맞았습니다. 나머지는 인물에 막히거나(3), 맵 가장자리·출구로 나가거나(5), 미끄러지는 바닥(`13`)에서 밀려난 것(1)입니다.

왕좌의 방에서 속성 `08` 인 블록 11 까지 길 찾기로 걸어가니 맵이 `02/02`(위층)로 바뀌었습니다. `0F:$CEB1` 이 걸음을 마친 칸의 속성을 11개 값과 비교해 출구 검사 등으로 나눠 보냅니다.

같은 곳(`0F:$D08E`)에 `0F:$C000` 바이트 bit7 이 0 이면 버튼을 누르고 있는 동안 벽을 통과하는 분기가 있습니다. 롬 값은 `FF` 라 꺼져 있습니다.

## 5. 팔레트

덤프의 BG 팔레트 12바이트를 롬에서 찾으니 필드 것은 `1E:$A2E3` 에 그대로 있었고, 마을 것은 3바이트 묶음으로 흩어져 있었습니다. 마을 쪽은 `0E:$BB55`(맵 종류·밤·장소 예외 → 세트 번호)와 `0E:$802B`(세트 → 색 묶음 4개)를 따라 만들었습니다.

## 6. 워프로 맵 종류 전부

[워프 도구](../docs/dq4-warp.md)로 맵 종류마다 첫 맵 하나씩(48가지)에 들어가 덤프를 비교했습니다. 들어오는 출구가 없는 맵은 통행 지도에서 맵 가운데에 가까운 걸을 수 있는 칸을 골라 좌표를 줬습니다.

```sh
fc/dq4/tools/dq4warp.sh work/bt2/04_01 04/01 0F 09
uv run python fc/dq4/tools/dq4block.py rom/dq4.nes compare work/bt2/04_01
```

여기서 새로 나온 것:

- 맵 종류 `01`·`06`·`0E`·`2C`·`2D` 등은 몇 블록의 CHR 이 롬과 달랐습니다. 그 그림은 뱅크 `1D` 에 있었고, `1D:$802A` 가 맵 종류별로 애니메이션 블록과 프레임 그림 주소를 정합니다.
- 맵 종류 `2D`(블록 8개가 애니메이션)에서는 `$7600` 이 어긋났습니다. 애니메이션 블록은 같은 그림 주소를 찾지 않고 늘 새 타일 4개를 받는다고 두니 맞았습니다. 1D 의 애니메이션 루틴이 블록 첫 타일부터 이어진 4개를 덮어쓰기 때문에 필요한 동작입니다.
- `00/00` 은 블록 10·11·14·15 의 속성이 `A2` 였습니다. 쓴 곳을 찾으니 `08:$8A2A` 의 장소별 속성 고치기 표였습니다.
- 정의가 없는 블록의 attribute 가 어긋났는데, 그 블록은 빈 타일 `00` 이라 팔레트가 보이지 않으므로 비교에서 뺐습니다.

결과는 블록 표·팔레트·`$7800` 이 성 앞(`02/00`, 성문 연출)만 빼고 0 다름, CHR 은 `33/03` 의 타일 4개만 달랐습니다. nametable 은 34가지가 0 다름이고 나머지는 상태 창·대화 창이 덮은 곳만 달랐습니다.

## 틀렸던 것들

- 성 앞의 블록 10·11·14·15 가 롬 정의와 다른 것을 처음에는 로드 루틴의 다른 분기로 봤습니다. 로드 직후 덤프는 롬과 같았고, 56프레임 뒤 `1B:$8706`(성문 연출)이 바꾼 것이었습니다.
- 필드에서도 장소별 속성 고치기(블록 01 → `80`)가 도는 줄 알았는데, 그 분기는 `$65` = 3 일 때만 갑니다.

## 남은 것

- 애니메이션 블록이 같은 주소의 타일을 찾지 않게 하는 코드 위치.
- 밤 팔레트와 장소별 팔레트 예외(낮 덤프만 확인).
- 지형 값 `01`·`02`·`05`·`0A`·`0B`·`0F` 의 실제 효과, 막힌 값(`A7`~`AF`, `B0`)끼리의 차이.
- 열쇠로 문(`A0`) 열기, 카운터 너머 대화.
- 성 앞 워프 덤프의 nametable 차이(걸어 들어간 덤프는 0 다름).
- 맵 종류 `0F` 블록 1F 의 물 애니메이션이 목록 밖에서 붙는 경로.
- 미끄러지는 바닥(`10`~`13`)의 방향 규칙.
