# 2026-10-25-28: 이벤트 표와 진행 목록·마차·손님·움직임

[앞 일지](2026-10-25-19-talk2.md)의 「남은 것」 을 풀었습니다. 호출 문장이 넘어가는 이벤트 표 `1C:$BF74` 의 50개를 모두 강제로 돌려 전투·플래그·일행·장소를 표로 만들었고, 진행 플래그로 인물 목록을 고르는 규칙을 맵 디코더로 옮겨 되돌리는 갈래까지 실측했습니다. 마차를 셀지 정하는 `$618E` 의 다른 값, 손님 인물 번호 8·9, 인물 움직임 니블의 뜻, 그림 번호 목록, 맵 이벤트 `1D:$B74D` 도 정리했습니다. 결과는 [dq4-script-format.md](../../dq4-script-format.md) 와 [dq4-map-format.md](../../dq4-map-format.md#진행-목록) 에 있습니다.

## 1. 이벤트 번호를 바꿔 넣기

이벤트 입구는 `1C:$AD5F` 하나입니다. A 를 두 배 해서 `$BF74` 의 워드로 점프합니다.

```
1C:AD5F  0a       ASL A
1C:AD60  aa       TAX
1C:AD61  bd 74 bf LDA $BF74,X
...
1C:AD6B  6c 00 00 JMP ($0000)
```

표를 읽으니 `00`~`31` 의 50개는 `$AD6E`~`$BEDC` 를 가리키고, `32` 부터는 `$BFD8` 의 조각(바꿔 끼우는 뱅크마다 같은 리셋 조각·문자열)이었습니다. `talk.lua` 에 `EV` 를 더해 이벤트 입구에서 A 를 바꾸고, 이벤트 플래그·장소·일행 자리·시간에 쓰는 것을 `w` 줄로 찍게 했습니다. 1장 왕좌의 방에서 왕에게 대화 `016`(이벤트 `00` 을 부르는 스크립트)을 걸고 A 를 50가지로 바꿔 돌렸습니다.

```
231 ev1C 15
231 w 616B 84 93CD     ブライ 가 걷는 자리 2 에
231 w 6292 10 C4D8     플래그 켜기
```

전투 이벤트는 특수 전투 `18:$A1AD` 로 들어가 거기서 멈췄습니다(이기지 못함). 그래서 전투 뒤에 켜는 플래그는 코드로 읽었습니다. 같은 루틴을 정적으로 따라가는 `dq4talk.py events` 를 만들어 두 결과를 나란히 냈습니다.

```
14 1C:B5F7  전투 0E; 플래그 켬 $6294&01 $6291&04  ← 0C6
   실행: 전투 0E; 메시지 0005
24 1C:B9F1  플래그 켬 $6292&1C $6294&40; 플래그 봄 $6292&10; 인물 숨김 09 0A 0C  ← 0B0 0B8 1E:B143
   실행: 플래그 $6292=1C $6294=40; 일행 $616B=81 $616C=87 $616D=84
기록 50개, 전투 번호 다름 0
```

상수 전투 23개가 모두 같았습니다. 전투가 아닌 것은 동료 합류(`0D`·`15`·`17`·`18`·`24`·`2A`), 인질(`1B`·`1F`), トルネコ 의 가게(`09`), 꿈(`1C`), 무술 대회(`03`, 상대를 `$6287` 로 고름), 결계 넷(`25`~`28`), 장소 옮기기(`2C`·`2F`·`30`) 등이었습니다. 메시지 첫 줄로 장면을 붙였습니다.

## 2. 상수가 아니던 14곳

앞 일지에서는 이벤트를 부르는 루틴 46개 중 14개가 번호를 상수로 넘기지 않는다고 셌습니다. 다시 보니 셋으로 나뉘었습니다.

- `15:$B0F6` 은 `$B0FF` 와 같은 이벤트 입구인데 표에 없어 놓쳤습니다(`LDA #$18`·`JMP $B0F6`).
- `LDA #$18`·`BNE`·`LDA #$11` 처럼 늘 건너뛰는 갈래를 양쪽 다 따라가 엉뚱한 번호를 붙였습니다.
- 잠 루틴 9개는 `LDA #$1C`·`STA $DD`·`BRK 07 CF` 였습니다. 5장(`$615A` = 4)의 12/00 에서 잘 때만 꿈 이벤트 `1C` 로 갑니다.

```
15:A763  ad 5a 61 LDA $615A
15:A766  c9 04    CMP #$04
...
15:A780  a9 1c    LDA #$1C
15:A782  85 dd    STA $DD
15:A784  00 07 cf BRK 07 CF
```

`call_tags` 가 A 의 마지막 상수를 기억하고, `LDA #n` 바로 뒤의 `BNE` 는 한쪽만 따라가게 고쳤습니다. 이제 36개 루틴이 모두 번호를 냅니다. 대화에서 부르지 않는 이벤트는 다른 뱅크의 `LDA #n` + `BRK 07 CF` 13곳(뱅크 1D 12곳, 1E 1곳)에서 찾았고, `0A`(`RTS` 하나)·`10`·`20`·`2D` 는 부르는 곳을 찾지 못했습니다.

## 3. 맵 이벤트 `1D:$B74D`

`1D:$B74D` 는 `$B8CA` 의 6바이트 12줄에서 그룹·장·순번이 맞는 줄을 찾습니다. 바이트 2 를 인물 번호로 일행에서 찾고, 바이트 5 의 인물 슬롯과 일행 자리를 맞바꾸는 것으로 읽혔습니다. 5장 04/01 의 카지노 マーニャ(대화 `08F`)로 확인했습니다.

```
1508 ev1D 00
슬롯 3  $7020 80 → 00      일행 줄의 マーニャ 가 보이게 됨
슬롯 6  (10,03) → (80,80)  카지노의 マーニャ 가 숨음
```

처음에는 일행 레코드가 죽은 상태(1장 상태에는 ミネア·マーニャ 레코드가 비어 있음)라 「ミネア 가 일행에 있음」 조건이 거짓이었습니다. 레코드 바이트 0 bit7 을 켜고 다시 돌렸습니다.

## 4. 진행 목록을 맵 디코더로

`1C:$9D0E` 표로 목록을 고르는 함수를 `dq4map.py` 로 옮겨 `npcs` 가 플래그를 받게 했습니다(`dq4talk.py` 는 같은 함수를 import). 되돌리는 조건 `1C:$9C6F` 의 갈래마다 워프로 들어가 인물 표를 셌습니다.

```
02/01 낮 보통 목록                       $6283=80, $6287=80
인물 표(슬롯 6~) 와 21명 중 17 다름, 인물 표에서 FF 가 아닌 슬롯 21(그중 숨은 80 9)
15/02 낮 보통 목록                       $6282=10, $6295=02
04/01 낮 보통 목록                       $6282=50 → $6286 = 01
02/03 낮 진행 목록 1C:9331               $6282=10(02/03 은 되돌리지 않음)
```

인물 수는 8가지 모두 맞았습니다. 「다름」 은 걷는 인물 때문입니다. `$62A5` bit7 은 켠 채로 워프가 출구를 타지 않아 확인하지 못했습니다. 이 값은 뱅크 1A(`1A:$9DF3`)가 켜고, 출구·맵 쪽 여러 곳이 봅니다.

## 5. 마차와 손님

`10:$8498` 을 끝까지 읽으니 「?」 로 두었던 값도 RAM 만으로 정해졌습니다. 아래 3비트 1 은 `$41` bit7·`$07BA`·`$618F` = `$63`, 2 는 `$41` bit7·`$6193` = `$63` 을 봅니다. 마차에 죽은 アりーナ 를 두고 대화 `01D`(「なんと　ひめさまが……！」)로 9가지를 돌렸습니다.

```
618E=20            cond 1    618E=22 6193=02    cond 1
618E=21 618F=02    cond 1    618E=22 6193=03    cond 0
618E=21 618F=03    cond 0    618E=23            cond 0
618E=21 0041=00    cond 0    618E=21 07BA=04    cond 0
618E=A0            msg 0454  このままでは　はなすことが　できない！
```

bit7 은 조건까지 가지 않고 말 걸기를 막았습니다. 손님(레코드 9, `$610F`)은 바이트 5 로 인물 번호를 정합니다. `C5` = 8, `C6` = 9, `E9` = `2C` 로 바꿔 대화 `148`·`0DC` 를 돌렸고, 6번 모두 디코더와 같았습니다.

## 6. 움직임 니블

`1C:$9A74` 를 다시 읽으니 n < 8 이면 `$7040` = n << 4 | n 이었습니다. 걸음은 `0F:$D63E` 에서 `$7040` 을 줄이다 아래 니블이 0 이 되면 위 니블로 다시 채우고 한 걸음 걷습니다. 위 니블은 간격이고, 0 이면 걷지 않습니다. 왕좌의 방에서 12명의 `$7040` 을 바꾸고 1800프레임 동안 자리가 바뀐 횟수를 셌습니다.

```
00:0  11:10  22:4  33:4  44:5  55:2  66:0  77:3  88:1  99:2  AA:2  FF:0
```

n ≥ 8 은 같은 n 을 쓰는 인물에게 차례 번호를 붙여 출발을 엇갈리게 합니다. 왕좌의 방의 n = 8 넷이 `81`~`84` 였습니다.

## 7. 그림 번호 목록

그림을 다시 그리므로 필요한 것은 「어느 인물이 어느 그림 번호인지」 입니다. `dq4talk.py looks` 가 롬의 모든 인물 레코드를 그림 번호로 모읍니다. 126가지가 나왔습니다.

```
그림 0F: 인물  29  장소 23 (01/01 02/01 02/02 04/06 04/07 05/01 …)  そなたの　かつやくを　きたいしているぞ。
그림 11: 인물 183  장소 79 (00/00 00/00밤 00/01 00/01밤 00/03 00/03밤 …)  うつら　うつら……。
그림 24: 인물  20  장소 16 (0F/00 0F/00밤 13/00 13/00밤 16/00 16/00밤 …)  わんわん。
```

그림을 읽는 `08:$85D3` 은 번호를 고친 뒤(`48`~`4F` → `00`~`07`, `53` 이상 − `0B`) `08:$979B` 의 24바이트를 읽습니다. 그 형식은 풀지 않았습니다.

## 틀렸던 것들

- 「움직임 1 = 제자리」 는 틀렸습니다. 1 은 가장 자주 걷는 값이고 제자리는 0 입니다. 앞 일지에서 `$7040` = `11` 로 바꾼 인물이 서 있었던 것은 다른 까닭(막힌 자리 등)으로 보입니다.
- `$618E` 의 아래 3비트가 마차의 맵을 봐서 RAM 만으로 못 정한다고 보았는데, 보는 값(`$41`, `$07BA`, `$618F`, `$6193`)이 모두 RAM 에 있었습니다.
- 이벤트를 부르는 루틴 14개가 「A 를 다른 데서 받는다」 고 셌지만, 실제로는 다른 입구(`$B0F6`)와 `STA` 를 사이에 둔 상수였습니다.
- 진행 목록 실험에서 「FF 가 아닌 슬롯」 만 셌더니 앞 맵에서 남은 (80,80) 9칸까지 인물로 셌습니다. 숨은 인물을 따로 세게 고쳤습니다.
- 여러 MesenCE 를 동시에 돌려 워프하니 대부분 결과 폴더가 비었습니다. 워프는 한 번에 하나씩 돌렸습니다.
- 이벤트 `2F` 의 기록에 옮겨 간 맵에서 일어난 이벤트 `30` 이 섞였습니다. 기록을 다음 이벤트 입구에서 끊었습니다.

## 남은 것

- 이벤트 표: 전투를 이긴 뒤의 갈래(플래그·메시지)는 코드 읽기. 인물·OAM 만 움직이는 이벤트(`05`·`06`·`07`·`0B`·`10`·`19`·`21`·`2D`·`2E`)는 부르는 대화의 맵에서 다시 돌려 봐야 함. 부르는 곳을 못 찾은 `0A`·`10`·`20`·`2D`. `$0530`(보통 `8F`)의 뜻.
- 맵 이벤트 `1D:$B8CA` 의 나머지 11줄.
- `$618E` 아래 3비트·`$618F`·`$6193` 을 게임이 언제 바꾸는지.
- 그림 번호 → CHR: `08:$979B` 의 3바이트 × 8 형식.
- 걸음 간격의 단위와 걷는 방향을 고르는 곳(`0F:$D884`).
- `$6287` bit7 로 되돌린 02/01 에서 인물 9명을 숨기는 곳, `$62A5` bit7 갈래의 실측.
- `1C:$96CE` 가 3A/04 에서 `$64` 를 바꾸는 까닭.
