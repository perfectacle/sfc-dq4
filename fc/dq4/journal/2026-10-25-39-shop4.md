# 2026-10-25-39: 들어갈 때 숨는 인물 전부·맡기는 곳 찾기·무료 숙박

[2026-10-25-31 일지](2026-10-25-31-shop3.md) 에서 남긴 것을 이어 풀었습니다. 맵에 들어갈 때 인물을 숨기거나 옮기는 장소 루틴 74곳(`1C:$A010`)과 장 줄 하나(`1C:$AD32`)를 기호로 돌려 인물마다 조건을 내는 디코더를 만들고 워프 덤프 112개와 맞췄습니다. 말을 걸어 보지 않았던 5장 맡기는 곳 둘, `05/01` 방어구점, 창 `70` 교회 둘, `17/00` 무료 숙박을 실측했고, 맡긴 물건을 찾을 때 수수료, `$618E` bit7 일 때의 여관, 발밑 `EE`, 대화로 받는 물건 넷을 더 확인했습니다. 결과는 [dq4-shop-format.md](../docs/dq4-shop-format.md) 에 있고, 디코더는 `fc/dq4/tools/dq4shop.py hidden` 입니다.

## 1. 장소 루틴을 기호로 돌리기

`1C:$A010` 은 표 `1C:$ABF5` 에서 지금 장소를 찾아 포인터 `1C:$AC8A` 로 뛰는 것까지 앞 일지에서 봤습니다. 74곳의 루틴은 `$A058`~`$ABF4` 에 3KB 쯤 이어져 있고, 거의 같은 꼴입니다.

```
1C:A0D6  BIT $6287
1C:A0D9  BVS $A0E5
1C:A0DB  LDX #$00
1C:A0DD  JSR $A035        ; 인물 0 숨김
...
1C:A111  BRK 07 eb 10     ; $6282 & 10 (4장 끝냄)
```

`BRK n EB m` 플래그 검사를 3바이트로 읽으면 다음 바이트에서 해석이 어긋나므로 [뱅크 호출 문서](../docs/dq4-bank-format.md)의 길이(`dq4talk.brk_len`)로 읽었습니다. 쓰는 명령은 `LDA`/`LDX`/`LDY`, `CMP`/`CPX`, `AND`/`ORA`, `BIT`, `LSR`, 분기, `JSR`/`JMP`, `STA abs,X` 정도라, 레지스터를 수나 기호(`$615A`, `$627E&0E` 따위)로 들고 분기마다 양쪽으로 갈라 가는 작은 해석기를 짰습니다. `1C:$A035` 는 숨김, `1C:$A04A` 는 (A, Y) 로 옮김, `1C:$A044` 는 밤 판정으로 따로 다룹니다.

처음 돌린 결과는 조건이 너무 길었습니다. `0F/00` 의 인물 하나에 「또는」 으로 이은 곱이 열 개씩 붙었는데, `$627B&70 = 30` 과 `$627B&40 꺼짐` 이 서로 다른 것으로 남아서였습니다. 같음 비교는 비트마다 나누고(`$627B&70 = 30` → bit4 켜짐·bit5 켜짐·bit6 꺼짐), 장 = n·주인공 X = n 같은 수 조건은 0~FF 를 다 대어 함께 설 수 있는 조합만 남긴 다음, 원자 조합 전부의 진리표에서 콰인–매클러스키로 줄였습니다. 원자는 한 루틴에 많아야 열 개 남짓이라 금방 끝납니다.

```
0F/00 1C:A058
  인물 0((03,18) 대화 005) X=07 Y=15 방향=$7006&FC|02 간격=00: [주인공 X = 07]
  인물 1((17,01) 대화 02F) 숨김: [$627B&10 켜짐 & $627B&40 꺼짐]
  인물 14(밤 (07,0C) 대화 008) 숨김: [$627B&20 꺼짐] 또는 [$627B&10 꺼짐] 또는 [$627B&40 켜짐] 또는 [$6285&01 켜짐] 또는 [밤 & 아이템 76 있음]
```

`1C:$A010` 을 부르는 곳(`1C:$9EAE`)을 보니 바로 뒤에 `1C:$AD32` 도 부르고, 그 앞에서 `$62A5` bit7(엔딩 장면)이면 둘 다 건너뜁니다. `$AD32` 는 (그룹, 순번, 장, 인물) 표로 「그 장이 아니면 숨김」 을 하는데 줄은 `1F/00` 하나뿐이었습니다.

## 2. 덤프와 맞추기

예측을 확인하려고 `hidden G K --compare DIR` 을 붙였습니다. 덤프의 플래그·장·시간·주인공 자리로 맞는 길을 고르고, 인물 표에서 자리가 (80,80) 인 슬롯과 비교합니다.

```
w17a 17/00 낮 인물 12명 덤프 (80,80): [2]           예측 숨김: [2] — 같음
w17b 17/00 ($6282=F0)  덤프 (80,80): []            예측 숨김: [] — 같음
w16b 16/00 ($6280=04)  덤프 (80,80): [0, 13, 15]   예측 숨김: [0, 13, 15] — 같음
w0Fa 0F/00 낮 인물 14명 덤프 (80,80): [2, 3, 4, 5, 6]  예측 숨김: [2, 3, 4, 5, 6, 14, 15, 16] — 다름
```

`0F/00` 의 14~16 은 밤에만 있는 인물 번호라 낮 목록 길이를 넘는 것이었습니다. 실은 목록 길이 안만 보게 고치니 같았습니다. 그 뒤 말을 걸러 들어간 덤프까지 11곳(장소 루틴이 있는 곳 8) 112개가 모두 같았습니다. 왕좌의 방에서 대화 번호만 바꾼 덤프 5개는 맵에 새로 들어가지 않아 뺐습니다.

가게 인물에는 `people` 이 이 조건을 「들어갈 때」 로 붙입니다. 진행 플래그 목록의 인물은 그 목록을 고른 플래그를 참으로 두고 어긋나는 곱을 뺍니다.

```
17/00 (07,17) 대화 0DA 호출 15:B847 → 무기: … / 들어갈 때 숨김 [$6282&10 꺼짐]
04/00 (06,1C) 대화 075 스크립트 [chapter 05 & counter & 낮] → 맡기는 곳 / 들어갈 때 숨김 [3장 아님 & 5장 아님] 또는 [$6286&20 꺼짐 & 낮 & 5장 아님]
```

## 3. 말을 걸어 보지 않았던 가게

인물에서 1칸·2칸 떨어진 여덟 자리에 그 인물 쪽을 보고 내려 말을 거는 실험을 한꺼번에 돌렸습니다(`shopcall.lua` 로 가게 입구를 봄).

```
04/00 (06,1C) 5장: (06,1A) 에서 9CBF BBF0        「おかねですね。 1000ゴールドたんいで あずかります。」
04/08 (03,03) 5장 밤: (01,03) 에서 9CBF BBF0
05/01 (1E,1D) 5장: 다섯 자리에서 B851, $07BD = 2F 2D 28 3F 47 4A — 표 같음
0E/00 (0C,18): 네 자리에서 B550 B558, 메뉴 いきかえらせる / どくのちりょう / のろいをとく / やめる
46/01 (03,02): 다섯 자리에서 B550 B558, 같은 메뉴
```

맡기는 곳 둘은 5장의 ネネ(대화 `075`)가 카운터 너머에서 서비스 `04` 를 여는 것이었습니다.

`17/00` (02,14) 의 무료 숙박은 일행에 인물 `02`·`03` 이 있어야 합니다. `SET` 으로 `$616A` = `82` 를 쓰면 워프가 「진입 루틴이 돌지 않음」 으로 실패해서 도착 뒤(`AFTER`)에 썼습니다. 예/아니오 창까지 간 덤프에서 이어 A 를 누르니 `15:$A6B0` 에 들어왔고 골드는 그대로, `$62ED` 가 `28` 이 되었습니다. 처음 두 번은 같은 조작에 「そのほうこうには　だれもいない。」 만 나왔는데, 입력 길이를 바꾸어 다시 처음부터 돌린 탓에 그사이 주인이 걸어 나간 것으로 보입니다. 예/아니오까지 간 `end.mss` 에서 이어 가니 됐습니다.

## 4. 맡긴 물건 찾기

`04/00` 5장에서 `SET` 으로 보관함 `$61DB` 를 채우고 「ひきとりにきた → どうぐ」 로 찾았습니다. 처음에는 A 를 하나 더 눌러 맡기기 쪽으로 갔습니다. 인사말 뒤 메뉴가 바로 열려 그 A 가 「あずけにきた」 를 골랐기 때문입니다.

```
보관함 06 FF: BDFD → BEC3 A=06 → BECE A=0A → B3F2   골드 100 → 90, 소지품 3 = 06, 보관함 FF
보관함 53 FF: 같음                                    골드 100 → 90, 소지품 3 = 53
```

`15:$BECC` 의 `LDA #$0A` 뒤 `BRK 4C 73`(골드 빼기)이라 수수료는 아이템과 상관없이 10G 입니다. 보관함을 비우는 `15:$B39C` 는 뱅크 `15` 함수 `5` 이고, `BRK 05 5F` 로 부르는 곳은 장 초기화 루틴 끝(`12:$90E9`)과 `12:$ABBC` 였습니다.

## 5. `$618E` bit7 일 때 여관

앞 일지에서는 `$618E` = `A0` 이면 여관 값 계산에 닿지 않았습니다. 이번에도 `$618E` = `80` 만 쓰면 A 를 눌러도 명령 창이 열리지 않았습니다. `$618E` 를 읽는 곳을 찾으니 `1E:$B16A` 가 bit7 이면 일행 자리 번호에 4 를 더해 `$616E`~ 를 걷는 일행으로 씁니다. 그 자리를 채우고 다시 말을 걸었습니다.

```
$618E=80, $616E~=87 88(살아 있음)           BFBB A=02
같은 것 + $618E=A0, 마차 $6172=89           BFBB A=02
$618E=20, 같은 자리 값                      BFBB A=02   ($616A 의 ライアン + 마차)
```

bit7 이면 `$616E`~ 쪽을 세고 마차는 세지 않습니다(`10:$84A4`). 처음 한 번은 여관 주인 위 칸에서 위를 보게 내려(방향 `0`) 아무 데도 닿지 않았는데, 아래(`2`)로 고치니 됐습니다.

## 6. 그룹 `FE` 와 `1D:$A748`

`15:$BEF4`(뱅크 `15` 함수 `17`)을 부르는 `BRK 17/97 5x` 꼴은 세 곳이고, 두 곳은 인물 목록 데이터 안이었습니다. 남은 `12:$84AA` 는 `BRK 17 5F` 뒤 `PLA` 다섯 번과 `RTS` 가 있어 코드 꼴이지만, 그 주소를 가리키는 바이트가 롬에 없었습니다.

おうごんのうでわ → とうぞくのカギ 를 하는 `1D:$A748` 은 루틴 `1D:$A732` 안이고, 이 루틴은 인물 블록 이벤트 표 `1D:$B639` 의 `3E` 였습니다. `dq4event.py events` 로 보니 이 이벤트를 쓰는 블록은 `0F/00` 밤 슬롯 18 하나(메시지 `0367` 「こうして　にせものの　ひめ　メイたちは…」)입니다. 밤에 `$627B` 를 네 가지로, 소지품에 `76` 을 넣고 들어가 기다렸지만 이벤트는 돌지 않았습니다.

## 7. 발밑 `EE` 와 대화로 받는 물건

`3D/06` (04,03) 은 상자 `EE`(てつのきんこ)와 발밑 `EE` 가 같은 칸입니다. 상자를 열면 칸이 블록 `19` 로 바뀌어 상자가 아니게 되므로, 같은 칸에서 다시 しらべる 하면 발밑 표로 갑니다.

```
263  B447 (상자)  → B7F2 A=0A
848  B7F2 A=19   (칸을 블록 19 로)
1218 B4DB → B830 (발밑 EE)  「…このばしょに　もどすがよい。」 「てつのきんこを　もとにもどしますか？」
2496 B83C → B7F2 A=03 → B863 A=6B   「ライアンは　たからを　もとにもどした！」
$627D 08 → 00, $6270 10 → 00, 소지품에서 6B 가 빠짐
```

금고를 제자리에 돌려놓는 이벤트입니다. 상자 열었음 비트도 꺼져 다시 열 수 있습니다.

대화로 받는 물건은 왕좌의 방에서 `TID` 로 네 줄을 더 돌렸습니다. `04C` 는 3장·소지품 `6D` 로 골드 +25000·`$6286` = `80`, `065` 는 キメラのつばさ 를 가져가고 `$6280` = `04`, `13F` 는 せかいじゅのしずく 와 `$629B` = `04`, `052` 는 `$6284` = `04`(일삯 변수가 0 이라 골드는 그대로)였습니다. `13B` 는 소지품에 `14` 를 넣어도 바뀌지 않았습니다.

## 틀렸던 것들

- 기호 해석기에서 분기의 한쪽이 앞의 조건과 어긋나면 그 길을 버려야 하는데, 처음에는 그 자리에서 멈춘 길을 결과에 넣었습니다. 조건이 빈 「숨김」 줄이 생겨서 알았습니다.
- `$618E` bit7 이면 여관에서 마차를 다르게 셀 것이라고 봤지만, 실제로는 걷는 일행 자리 자체가 `$616E`~ 로 바뀌는 것이었습니다.

## 남은 것

- 진행 플래그끼리의 관계를 몰라, 숨김 조건에 실제로는 없는 조합이 섞일 수 있음. 옮김·방향·간격 36줄은 덤프 비교에 넣지 않음.
- 그룹 `FE`(`15:$BEF4`)에 닿는 길, `12:$84AA` 의 `BRK 17 5F` 에 닿는 길.
- `15:$B39C` 가 장 시작마다 도는지의 실측.
- 대화 `13B`·`0AD` 와 나머지 대화로 받는 물건 줄의 실측.
- `0F/00` 밤 이벤트 `3E`(`1D:$A748`)를 실제로 돌리는 조건.
