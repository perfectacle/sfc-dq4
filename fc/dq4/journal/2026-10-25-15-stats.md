# 2026-10-25-15: 주문·레벨업·몬스터·아이템 표

일행 레코드, 경험치·능력치 성장 곡선과 레벨업 규칙, 주문의 소비 MP·배우는 레벨, 장 시작 능력치, 몬스터 레코드의 나머지 바이트, 아이템 종류·장비 인물을 찾았습니다. 결과는 [dq4-data-format.md](../docs/dq4-data-format.md) 에 있고, `fc/dq4/tools/dq4data.py` 에 `spells`·`levels` 를 더하고 `items`·`monsters` 를 넓혔습니다.

1장에는 ライアン 혼자뿐이고 주문도 없어서, 다른 인물·다른 장은 RAM 이나 메모리 위의 롬 바이트를 바꿔 만들었습니다. 이를 위해 Lua 세 개를 새로 썼습니다.

| 스크립트 | 하는 일 |
| --- | --- |
| [statspoke.lua](../tools/lua/statspoke.lua) | 세이브스테이트를 불러온 뒤 `ONCEAT` 프레임에 한 번만 RAM(`ONCE`)이나 PRG ROM(`ROMONCE`)에 쓰고 `seq.lua` 를 돌림 |
| [statsstack.lua](../tools/lua/statsstack.lua) | PC 가 `AT` 에 닿을 때마다 레지스터, `LOG` 주소 값, 스택(부른 곳)을 기록 |
| [statsreads.lua](../tools/lua/statsreads.lua) | PRG 오프셋 범위를 읽을 때마다 읽은 명령·오프셋·스택을 기록. `$C3EA` 처럼 여러 표를 읽는 공통 루틴 뒤에서 어느 바이트를 읽는지 볼 때 |

## 1. 일행 레코드

첫 전투 세이브스테이트에서 A 만 눌러 이기며 ライアン 둘레 RAM 을 보니 `$60B6` 이 맞을 때마다 1B→1A→19 로 줄고, 이긴 뒤 `$60C5` 가 늘었습니다. 경험치에 1000 을 넣고(`statspoke.lua`, `ONCE="60C5=E8,03,00"`) 싸우니 `$60BA` 가 1→2→3 으로 오르며 바로 뒤 바이트들이 바뀌었습니다.

```
f01300 exp=0003EC lv=02 st=010D0407 hm=001B
f01500 exp=0003EC lv=02 st=010F0409 hm=001E
```

`$60B5` 가 30바이트 레코드의 시작이고, 같은 크기로 앞에 7칸이 더 있어 `$6001 + 30 × 번호` 이었습니다. 「つよさ」 화면을 열어 보니 ちから 7, すばやさ 4, たいりょく 13, かしこさ 1, うんのよさ 2, さいだいHP 27, こうげき力 19, しゅび力 14 로 RAM 의 `07 04 0D 01 02`, `1B` 와 맞았습니다. こうげき力 19 = 힘 7 + どうのつるぎ 강도 12, しゅび力 14 = 속도 4 / 2 + かわのよろい 강도 12 라서 앞 일지에서 「화면 미확인」이던 아이템 강도도 이것으로 확인했습니다.

인물 번호 순서는 `10:$85B6` 의 이름 표(クリフト, ミネア, マーニャ, ブライ, トルネコ, ライアン, アリーナ)와 같고, 0 이 勇者 입니다. 레코드의 나머지 자리는 같은 날 [dq4-save-format.md](../docs/dq4-save-format.md#인물-레코드-6001--30--번호) 에 정리되었습니다.

## 2. 성장 곡선

`probe/writes.lua` 로 레코드에 쓰는 곳을 찾으니 `10:$8453`(더하기 루틴)이었고, 스택을 따라가니 뱅크 `12` 의 `$9D36`~`$9F40` 이 레벨업 처리였습니다. 그 안의 `12:$9FC6` 은 `$A108` 포인터 표로 인물별 5·6바이트 레코드를 읽고, `$A266` 비율 표로 레벨마다 증가분을 쌓습니다. 이 구조는 북미판 분석 자료([references.md](../references.md#dq4fc))의 성장 공식 설명을 참고해 짐작했고, 주소와 동작은 일본판 코드에서 다시 읽었습니다. 코드 그대로 `dq4data.curve` 를 만들고 게임이 계산한 값과 맞춰 보았습니다.

레벨업 때 `12:$9DE7`(목표값), `$9E09`(기준 증가분과 난수), `$9E23`(증가량), `$9D64`(다음 레벨 경험치), `$9E8C`(지혜 보정), `$9F06`(주문 습득)을 `statsstack.lua` 로 기록했습니다.

```sh
ONCE="60C5=20,4E,00" AT=9DE7,9E09,9E23,9D5D LOG="0A,0B,00:2,72:2,04:2,8A:2,6E09,09" \
  MAXF=8700 ... statsstack.lua      # ライアン 경험치 20000, A 연타
```

증가량은 `기준 × $8A / 121` 이었고 `$8A` 는 `10:$A241` 의 난수(0~15 난수 32개의 합에서 112 를 뺌)였습니다. 체력 다음에 HP 를 올릴 때 기준이 곡선 증가분이 아니라 `$6E09`(방금 오른 체력 × 2)인 것도 이 기록에서 보였습니다.

ライアン 경험치를 7 과 8 로 두고 4 를 주는 전투를 이기면 11 은 1레벨, 12 는 2레벨이 되어 곡선의 2레벨 값 12 와 맞았습니다.

## 3. 다른 인물을 레벨업시키기

필드 세이브스테이트에서 인물 레코드를 1레벨 곡선 값으로 써 넣고 `$616A`(일행 순서)를 `80 | 번호` 로 바꾸면 그 인물이 선두로 걷고 싸웠습니다. 경험치 5000 을 넣고 오가다 전투를 만들어 A 를 400번 누르는 실행을 슬롯 0~5·7 에 대해 돌렸습니다.

```
{'target': 626, 'delta': 626, 'gain': 626, 'cap': 0, 'exp': 143, 'bonus': 56, 'spell': 56} bad 0
```

목표값·기준 증가분·증가량·다음 레벨 경험치(일행 8명 모두)가 계산과 같았고, 끝 레코드의 능력치는 처음 값 + 기록한 증가량과 같았습니다. 다만 목표값을 넘은 경우(증가 0~1)는 한 번도 나오지 않았습니다.

## 4. 주문

배우는 주문은 `12:$9E93` 이 `$A118`(64비트 마스크)과 `$A124`(레벨 바이트)를 읽어 정했습니다. 레벨 바이트 bit7 이 선 주문은 `$6DFF`(지혜 보정 0~2)만큼 늦게, 경계에서는 반쯤 확률로 배웠습니다. 3절의 기록에서 실제로 배운 주문 56건이 이 규칙의 「반드시」 집합을 포함하고 「반쯤」 집합 안에 있었습니다(クリフト 는 2레벨 ホイミ, 4레벨 スカラ …).

소비 MP 는 クリフト 를 5레벨까지 올린 상태를 세이브스테이트로 남겨(`work/stats-cristo-field.mss`) 필드에서 ホイミ 를 쓰며 찾았습니다. MP 가 7→4 였고, 그때 `probe/reads.lua` 에 `13:$B95B` 가 PRG `4F990`(`13:$B990` = `$B967 + 29`)을 읽는 것이 잡혔습니다. 그 바이트 `23` 을 메모리에서 바꿔 같은 입력을 돌렸습니다.

```
byte 23: mp=0007 → 0004
byte 25: mp=0007 → 0002
byte 2B: mp=0007 (MP 가 모자라 못 씀)
```

아래 5비트가 MP 이고, 위 3비트는 `13:$B937`·`$B949` 가 따로 꺼내 쓰는 대상 정보였습니다.

## 5. 장 시작 능력치

ライアン 의 1레벨 곡선 HP 는 26 인데 실제는 27 이라, 장 시작 루틴을 찾았습니다. 전원부터 이름 입력까지는 레코드에 쓰는 곳이 없었고, 이름을 정한 뒤 `12:$8EB5`~`$90DA` 가 썼습니다. 이 루틴은 `$615A` 가 장 번호이고 `$9136` 이 그 장과 같은 인물만 만듭니다. 이름 입력 세이브스테이트에서 루틴이 돌기 직전(430프레임)에 `$615A` 를 0~4 로 바꾸어 돌리니 장마다 다른 인물이 나왔습니다.

```
615A=1 → 616A 87, 골드 100, 1·4·7번 (クリフト, ブライ, アリーナ)
615A=3 → 616A 83, 골드 100, 2·3번 (ミネア, マーニャ)
```

능력치와 MP 를 곡선 1레벨 값, HP 를 `$A296`, 아이템을 `$9192` 로 계산한 값과 레코드 8개, 골드 다섯 장이 모두 같았습니다. 장 초기화 표 전체와 디버그 장 고르기로 본 장 번호는 [dq4-save-format.md](../docs/dq4-save-format.md#장-시작) 에 있고, 여기서 더한 것은 능력치 5비트가 성장 곡선 레코드의 초깃값이라는 점입니다.

## 6. 몬스터 레코드

`statsreads.lua` 로 전투 동안 `18:$8046`~ 를 읽는 곳을 모으니 거의 모두 `$C3FD` 였고, 스택을 보니 `10:$A6D9`(바이트 읽기)를 거쳐 `10:$A67C` 의 필드 표로 갈렸습니다. 필드 번호마다 바이트 위치·길이와 처리 루틴이 있어, 바이트 4·5·6·7 은 각각 바이트 15·16·17·18 의 bit1-0 을 위 비트로 붙이고, 바이트 8 은 bit6-0 과 bit7 을 나누고, 15 이후는 2비트씩 떼어 쓰는 것을 코드로 읽었습니다.

전투 세이브스테이트의 RAM `$7274` 부터 14바이트씩 スライム `03 09 00 05 00 … 08`, おおみみず `02 0A 00 06 00 … 0B` 가 있어 속도(바이트 2)·공격력(5)·수비력(6)·HP(4)가 확인되었습니다. 필드에서 전투가 나기 전에 1장 몬스터 12종의 바이트 15·16·17 아래 비트를 메모리에서 세우니 전투 RAM 의 위 바이트가 따라 섰습니다.

```
patch=0: 7274: 03 09 00 05 00 …   7282: 02 0A 00 06 00 … 0B 00
patch=1: 7274: 03 09 02 05 01 …   7282: 02 0A 02 06 01 … 05 01
```

드롭은 이기는 장면에서 `12:$9217` 이 바이트 8·20 을 읽었습니다. 바이트 8 을 `55`, 바이트 20 을 `40`(확률 칸 0)으로 바꾸고 이기니 소지품 빈칸에 `55`(せいすい)가 들어왔고, 바꾸지 않으면 들어오지 않았습니다.

## 7. 아이템 종류와 장비 인물

`10:$8B1E` 는 아이템 ID 를 경계 `24 3D 46 50` 과 비교해 종류를 돌려주고, `10:$8B3B` 는 `$8C9C` 의 인물 비트로 장비 여부를 정했습니다(드레스 넷은 여자 인물만). 표를 찍어 보면 てつのつめ 는 アリーナ, てつのおうぎ 는 マーニャ, せいぎのそろばん 은 トルネコ 만 서 있고, 장 시작 때 장비한 아이템은 모두 주인의 비트가 서 있습니다. `$8D1B` 위 비트는 저주 장비만 선 비트, 소모품만 선 비트가 보여 뜻을 짐작했지만 화면으로 확인하지는 못했습니다.

## 8. 배운 주문 비트

장 시작 세이브스테이트 다섯 개(`dq4-ch{1..5}-start.mss`)의 레코드 +1B~+1D 를 보니 ホイミ 만 아는 クリフト·ミネア 가 `02 00 01`, メラ·ヒャド·ニフラム 만 아는 マーニャ·ブライ·勇者 가 `01 00 00` 이었습니다. 장 시작 루틴이 부르는 `BRK 38 0F` 를 따라가니 `10:$9123` 이 `$9150`(전투)·`$9192`(필드) 목록에서 주문의 자리를 찾아 그 자리 번호(필드는 +16)의 비트를 켰습니다. クリフト 전투 목록은 スカラ, ホイミ, マヌーサ … 순이라 ホイミ 가 bit1, 필드 목록 첫 칸이 ホイミ 라 bit16 입니다. 3절에서 ホイミ·スカラ 를 배운 クリフト 5레벨 상태는 `03 00 01` 로 맞았습니다.

## 틀렸던 것들

- 레코드를 만들 때 최대 HP 를 곡선(체력 × 2)으로 넣었는데, 실제 장 시작 값은 따로 둔 표 `$A296` 에서 왔습니다(ライアン 26 이 아니라 27). 레벨업 검증은 처음 값과 상관없어 영향이 없었습니다.
- 레벨업 루틴이 0번을 처리할 때 `$618E` bit6 이면 8 을 쓰는 것을 「여자 勇者 의 성장 곡선 8번」로 읽었는데, 8 은 레코드 번호로만 쓰이고 곡선 번호(`$09`)은 0 그대로였습니다. 경험치 표가 8명 × 5바이트뿐인 것과도 맞습니다.
- `$615A` 를 이름 입력 세이브스테이트를 불러온 직후(5프레임)에 바꾸면 결과가 늘 1장이었습니다. 이름을 정할 때 다시 0 이 되어서, 장 시작 루틴 직전에 바꾸어야 했습니다.

## 남은 것

- `$8D1B`·`$8D9A`·`$8E19` 플래그와 사용 효과 번호의 뜻, 장비 판정의 화면 확인.
- 주문 대상 비트의 화면 확인, 주문 위력 표, メガンテ·マホトラ 같은 특수 MP 처리.
- 몬스터 MP(바이트 3)의 실측, 행동 번호·내성·바이트 20·21 나머지의 뜻, HP 난수 규칙.
