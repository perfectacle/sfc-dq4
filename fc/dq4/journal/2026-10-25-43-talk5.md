# 2026-10-25-43: 이긴 전투 뒤의 이벤트, 말 걸기 앞 검사, 맵 번호의 위 2비트, `$62A5`

[앞 일지](2026-10-25-35-talk4.md)의 「남은 것」 을 차례로 풀었습니다. 특수 전투를 RAM 으로 이기게 해 전투가 있는 이벤트 18개의 뒤 갈래를 확인했고, 부르는 곳을 못 찾던 이벤트 `10`·`20` 의 호출처를 찾았습니다. `48/09` 가 곧바로 필드로 나가는 까닭과 맵 번호 bit7·bit6, `$0520`, 02/01 의 9명을 숨기는 곳, `$62A5` 갈래, 자동 입력 바이트열, 인물 걸음 간격도 실측했습니다. 결과는 [dq4-script-format.md](../docs/dq4-script-format.md) 와 [dq4-map-format.md](../docs/dq4-map-format.md) 에 있습니다.

## 1. 이벤트 `10`·`20` 은 대화 스크립트 밖에서 불린다

`dq4talk.py events` 는 대화 스크립트의 호출 문장과, 다른 뱅크의 `LDA #n` + BRK `07 CF` 만 부르는 곳으로 셌습니다. 롬 전체에서 이벤트 입구로 가는 길을 다시 찾았습니다. BRK `07 CF` 말고도 뱅크 1C 안의 `JMP $AD5F` 와 뱅크 15 의 이벤트 입구 `$B0F6`·`$B0FF` 가 있습니다.

```
1C:BEF7  a9 10    LDA #$10
1C:BEF9  4c 5f ad JMP $AD5F      ← 이벤트 31(전투 1A) 끝에서 이벤트 10 으로
15:B159  a9 20    LDA #$20
15:B15B  20 f6 b0 JSR $B0F6      ← 말 걸기 앞 검사 15:$B10E 에서 이벤트 20
```

`15:$B10E` 는 대화 번호를 꺼낸 직후, 갈래 전에 늘 불리는 루틴이었습니다. 그룹 `03`(デスパレス)에서 へんげのつえ 로 몬스터 모습이 아니면, 겉모습으로 전투 번호(`1C` + 표 순번)를 정하고 이벤트 `20` 으로 싸움을 겁니다. 같은 때 머지된 [2026-10-25-42 일지](2026-10-25-42-encounter4.md)가 이 갈래와 へんげのつえ(`$6296`·`$6297`)를 이미 풀어 두었습니다. 여기서는 `talk.lua` 로 이벤트 쪽에서 봤습니다. `03/01` 로 워프해 겉모습 `35` 인 슬롯 6 에게 말을 걸었습니다.

```
190 talk 06 1 22
197 msg 0446
223 ev1C 20
223 battle 20        ← 표 2A 36 37 0D 35 34 의 4번째 + 1C
```

`$6296` = `01`, `$6297` = `80`(몬스터 모습)을 주면 이 검사를 지나 대화 `12F` 가 그대로 나왔습니다. 이벤트 `0A` 는 `RTS` 하나뿐이고 롬 어디에서도 부르지 않습니다. `dq4talk.py events` 가 두 길을 같이 세게 고쳤습니다.

## 2. 특수 전투를 이기게 하기

이벤트 표의 「전투 뒤」 갈래는 지금까지 코드 읽기였습니다. 1장 ライアン 으로는 거의 모든 특수 전투에서 지기 때문입니다. `fc/dq4/tools/lua/talkwin.lua` 를 새로 만들었습니다. `talk.lua` 를 감싸, 특수 전투 입구(`18:$A1AD`)를 지난 뒤 매 프레임 적 8칸의 HP(`$727E` + 14n)가 1 보다 크면 1 로 낮춥니다.

처음에는 HP 만 낮췄는데 이벤트 `00` 의 おおめだま 가 수십 번을 맞아도 쓰러지지 않았습니다. 메시지를 보니 `0007`(「ミス！ ダメージをあたえられない」)였습니다. 수비력이 높아 피해가 0 이었던 것입니다. 수비력(+3)도 0 으로 두니 한 번에 쓰러졌습니다. 일행이 지는 전투(`28`)도 있어 일행 HP 도 채우게 했습니다.

```
151 ev1C 00
151 battle 05
2559 w 6283 80 C4D8
2634 msg 0320        ← 「この　おれさまが　まけるとは……」
2923 w 6288 80 C4D8
```

왕좌의 방에서 대화 `016` + `EV` 로 전투가 있는 이벤트 18개를 모두 이겼습니다. 이긴 뒤 켠 플래그·메시지가 코드 읽기와 모두 같았고, `31` 은 이긴 뒤 이벤트 `10` 으로 이어졌습니다. 이벤트 `02` 만 디코더가 메시지를 `004D` 로 냈는데 실제로는 `034D`(「かいぶつを　やっつけたという　しらせは」)였습니다. 디코더가 BRK `04 6F` 의 X 를 버리고 A 만 썼기 때문이라 고쳤습니다. `LDA 플래그 / ORA #m / STA` 로 켜는 플래그(`02` 의 `$627F` bit7, `01` 의 `$6280` bit6, `03` 의 `$6285` bit5)도 세게 했습니다.

## 3. `48/09` 와 맵 번호의 위 2비트

`48/09` 의 인물은 (00,00)에 선 보이지 않는 레코드 하나이고, 블록은 `8A 28` 뿐입니다. 블록 이벤트 `28`(`1D:$A321`)이 소리 `93` 과 일행 연출(`1E[30]`) 뒤 맵을 나갑니다(`1E[2F]`). 나가는 곳은 `12[2C]` 가 그룹으로 정하는데, 그룹 `48` 은 그 표에 없어 지금 필드 자리로 나갑니다.

```
95  A321 63=48 64=09          ← 블록 이벤트 28
95  8C84 55=F3 56=04 57=02 58=1E
125 86AD                      ← 맵 나가기
f755 끝 63=48 64=09 44=A4 45=2C   ← 워프 전 필드 자리
```

`$6285` bit2 가 켜져 있으면 (90,D9)로 바꾼 뒤 나가는데, `$6285` = `04` 로 다시 하니 필드 (90,D7)이었습니다(방향 보정으로 2 줄임).

맵 레코드 첫 바이트의 위 2비트는 `$0550` 에만 남고 `$0028` 에서는 지워집니다. `$0550` 을 읽는 곳은 둘뿐이었습니다. bit7 은 `0F:$D44C`(맵 밖 칸)가 봅니다. 꺼져 있으면 맵 밖은 늘 `$0520`(맵 머리 바이트 2 의 아래 5비트)이고, 켜져 있으면 (X & 7, Y & 7) 무늬로 `$0520` 과 `$0582` 를 섞습니다. 5장 시작(`14/00`, 맵 번호 `85`)에서 걸으며 trace 하니 맵 밖 칸 50번이 모두 무늬대로 `03`·`04` 로 나뉘었습니다. bit6 은 `08:$B71C` 가 보고, `$41` bit7 일 때 이동 주문·아이템 루틴 `1E[24]` 가 실패하게 합니다(코드 읽기). 동굴·탑이 대부분인 124곳에 켜져 있습니다.

## 4. 02/01 의 9명과 `$62A5`

진행 목록을 되돌린 02/01 에서 뒤 9명이 (80,80)인 까닭을 찾으려고 `$6F66`~`$6F9F` 에 `80` 을 쓰는 곳을 잡았습니다. 18번 모두 `1C:$A035` 였고, 이것을 부르는 것은 장소별 루틴 `1C:$A010` 이었습니다. 같은 때 머지된 [2026-10-25-40 일지](2026-10-25-40-shop4.md)가 이 74곳을 `dq4shop.py hidden` 으로 이미 풀어 두었습니다. 02/01 은 `$627E` bit4(1장 첫 장면을 봄)면 인물 12~20 을 숨깁니다.

```
02/01 1C:A171
  인물 12((11,17) 대화 008) 숨김: [$627E&10 켜짐]
```

`1C:$A010` 을 부르는 `1C:$9EA6` 은 `$62A5` bit7 이면 손질을 통째로 건너뜁니다. 앞 일지에서는 `$62A5` 를 켠 채로 워프하면 출구를 타지 않아 확인하지 못했습니다. 이번에는 `$9EA6` 에 들어오는 순간에만 `80` 을 쓰고 `$9EB4` 에서 되돌렸습니다. 그러자 숨기는 쓰기가 없어지고 21명이 모두 섰습니다.

## 5. 자동 입력 바이트열과 걸음 간격

자동 입력을 쓰는 장면 중 방향이 든 패턴은 엔딩·5장처럼 만들기 어려운 곳에 있습니다. 그래서 1장 왕 장면의 `22 13`(멈춤뿐)을 메모리에서만 `22 0E` 로 바꿨습니다(`PRGPOKE`). 패턴 `0E` 는 `44 33 43 …` 입니다.

```
580 84 06 8074 pad=00 xy=10,1A   ← $DAB9 가 둠
596 83 06 8074 pad=40 xy=0F,1A   ← 왼쪽
613 82 06 8074 pad=40 xy=0E,1A
630 81 06 8074 pad=40 xy=0D,1A
646 83 05 8075 pad=10 xy=0D,19   ← 위
663 82 05 8075 pad=10 xy=0D,18
680 81 05 8075 pad=10 xy=0D,17
697 83 04 8076 pad=40 xy=0C,17   ← 왼쪽
```

아래 니블 n 은 `$DB0B` 를 부르는 횟수이고, 한 번에 한 걸음입니다. 둘째 항목부터는 n 걸음(`33` → 위 3걸음)이고, 첫 항목은 `$DAB9` 가 둔 값에서 시작해 한 걸음 적습니다(`44` → 왼쪽 3걸음).

인물 걸음은 왕좌의 방 900프레임을 `npcblock.lua` 로 기록해 간격을 셌습니다. `$7040` 위 니블이 3 이면 48~49프레임, 4 면 64~65, 8 이면 128~130 이었습니다. 위 니블 하나가 16프레임입니다.

- 이긴 뒤 레벨이 열 번 넘게 올라 메시지가 길어져, 처음 6200프레임으로는 이벤트 8개의 뒤 갈래까지 가지 못했습니다. 14000프레임으로 다시 돌렸습니다.
