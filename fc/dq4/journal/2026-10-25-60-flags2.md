# 2026-10-25-60: 아이템 사용·대화 조건·동료를 맞춰 [추정] 66개를 30개로

[56 일지](2026-10-25-56-event6.md) 가 남긴 `[추정]` 66개를 이어서 줄였습니다. 이번에는 BRK 플래그 명령이 아닌 쓰기(아이템 사용 처리기의 `STA $62xx` 등)를 찾고, 쓰는 곳의 조건을 읽어 일행·소지품·앞 플래그를 맞춘 뒤 장면을 돌렸습니다. 결과는 `[확인]` 154, `[추정]` 30 입니다. 표는 [dq4-story-format.md 의 4차](../docs/dq4-story-format.md#4차-아이템-사용대화-조건동료-맞추기) 에 있습니다.

## 1. 「검사하는 곳만 있는」 비트의 쓰는 곳

`flags --meaning` 은 `00 n CB m` 모양만 쓰는 곳으로 셉니다. 그래서 `$627D` bit0, `$627F` bit0, `$6281` bit5, `$6283` bit0·bit1 은 검사만 있는 것으로 보였습니다. 롬 전체에서 그 바이트에 대한 절대 주소 쓰기(`8D`·`0D`·`EE` …)를 찾으니 다섯 곳이 나왔습니다.

```
12:B1DF  STA $627D   ← 아이템 70 かやくつぼ 처리기, 00/01 의 정한 자리
12:B232  STA $6283   ← 아이템 75 さえずりのみつ, 01/01 (09,08)
12:B321  STA $6283   ← 아이템 78 おうのてがみ, 05/01 (11,08)
1E:919F  STA $6281   ← 그룹 01 에서 필드로 나감
1E:9D7C  STA $627F   ← 2장 필드 4걸음째 ブライ
```

아이템 처리기는 `12:$AF16` 이 ID 를 `12:$B6BB` 목록에서 찾아 `12:$B679` 표의 주소로 뜁니다. 그 자리에 워프해 소지품 빈 칸에 아이템을 넣고 どうぐ → 아이템 → つかう 를 눌렀습니다. 4장 キングレオ 성에서 かやくつぼ 를 쓰자 bit0 이 켜졌고, 그것을 기다리던 슬롯 06 병사의 블록(56 일지에서 막혔던 이벤트 `11`)이 bit1 을 켜고 걸어 나가 숨은 뒤 bit2 를 켰습니다.

```
563  w 627D 00>01 pc=B1DF bank=12
632  w 627D 01>03 slot=06       ← 블록 27
1751 w 627D 03>01 slot=06       ← 블록 28
1783 w 627D 01>05 slot=06       ← 블록 27
```

같은 방법으로 おうじのてがみ(`$6280` bit0)와 せいなるたねび(`$6293` bit4)도 켰습니다. せいなるたねび 는 자리 말고도 앞 칸의 속성이 `32` 여야 해서, `31/00` 에 한 번 들어가 `$7800` 과 속성 표 `$6F40` 을 덤프해 (0C~0D,0C~0D) 의 불 칸을 찾고 (0C,0B) 에서 아래를 보게 했습니다.

## 2. 대화와 동료

대화로 켜는 비트는 대화 번호를 바꿔 거는 `TID` 로 돌렸는데, 대개 일행 조건이 걸려 있었습니다. 손님 동료는 레코드 9(`$610F`)의 바이트 5 로 인물 번호가 정해지므로, 바이트 0 = `80`, 바이트 5 = 번호 + `BD` 로 두고 일행 자리에 `89` 를 넣었습니다.

- スタンシアラ 왕(대화 `0FA`): パノン(`0D`)을 둘째 자리에 두면 그냥 끝나고(`09F6`), 첫 자리에 두자 「パノン「おことばですが」(`09F7`) 뒤 `$6295` bit3·bit2 가 켜졌습니다.
- 天空城 `46/00`: ルーシア(`0E`)를 데리고 들어가면 이벤트 `83` 이 「ああ ここは てんくうじょう！」 뒤 `$629B` bit1 을 켭니다.
- ガーデンブルグ 인질(대화 `128`): `$6299` 는 비트 하나가 아니라 bit7 + 인물 번호였습니다. 고른 동료의 레코드 바이트 0 을 `00`(죽음)으로 두면 그때만 bit6 이 켜집니다.

ヒルタン 의 문제(대화 `0AD`)는 예/아니오가 둘 있고, 첫 질문은 「いいえ」 여야 합니다. 「しょうばいに おいて いちばん たいせつなこと」 에는 아무것도 고르지 않고 넘기면 「ちんもくは きん なりじゃ！」 로 たからのちず 를 줍니다.

## 3. 블록 이벤트

56 일지에서 「인물이 실리지 않음」 으로 남은 것 중 몇은 장소별 숨김 루틴(`1C:$A010`)이 원인이었습니다. ミントス 여관 `0D/01` 은 `1C:$A6CA` 가 `$6294` bit7(パデキア 싹틈) 이 꺼져 있으면 슬롯 0B 를 숨깁니다. bit7 을 켜고 (12,03) 에서 위를 보자 이벤트 `73`·`74` 가 돌아 `$6294` bit5 가 켜졌습니다.

デスパレス 회의(`03/01`)는 `$6296` 이 0 이 아니고 `$6297` bit7 이 서 있어야 합니다. 출발 전에 `$6296` 을 쓰면 맵에 들어갈 때 `1E:$9E71` 이 줄여 0 이 되므로 도착 뒤(`AFTER`)에 썼습니다. 15차례 기다린 뒤 ピサロ 가 나타나 `$6295` bit0 이 켜졌습니다.

`42/01` 의 「あなたが ちょうど 1000にんめです！」 는 자리에 설 때 한 번 난수 & `1F` 를 봅니다. 1500프레임 기다려도 나오지 않아 `AND #1F` 를 메모리상 `AND #00` 으로 바꿔 돌렸습니다.

## 4. 맵에 들어올 때 서는 비트

모든 실행 기록에서 `08:$B6C3` 이 `$628B` 를 `FF` 로 썼습니다. `$628B` bit5·6·7 은 「이 맵에서 아직 하지 않음」 이고 대화가 끕니다. 2장 필드 걸음 세기에서 `$6288` bit7 이 걸음마다 켜지다가 4걸음째에 꺼지는 것도 보았습니다. 56 일지가 물었던 「`1E:$9863` 의 bit7 이 엔딩의 bit7 과 같은 뜻인가」 는 다른 쓰임이었습니다.

## 틀렸던 것들

- `00/01` 슬롯 06 블록이 기다리는 `$627D` bit0 은 발밑 구역 비트(같은 바이트의 bit4)와 함께 걸음마다 바뀌는 값이라고 보았습니다. 실제로는 かやくつぼ 를 쓰면 켜지는 이 맵만의 표시였습니다.
- おうのてがみ·マスタードラゴン·ヒルタン 은 처음에 A 를 열 번 남짓만 눌러 쓰기가 나오지 않았습니다. 메시지 사이 ▼ 와 레벨 오름 메시지가 많아 A 를 수십~200번 눌러야 했습니다.
- `$6283` bit5 는 `flags --meaning` 이 「スロットマシーン」 대사를 붙여 보였지만(가까운 메시지를 고름), 쓰는 곳 `1D:$A450` 은 1장 탑의 아이들이 부르는 이벤트 `31` 이었습니다. 슬롯머신은 바로 뒤 이벤트 `32` 의 `$628A` bit0 입니다.
