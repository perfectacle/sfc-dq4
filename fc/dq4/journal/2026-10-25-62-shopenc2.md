# 2026-10-25-62: パルプンテ 27가지, 이벤트 전투 비트의 나머지, 대화 13B·0AD 와 맵 이벤트 3E

상점·조우 쪽에 남았던 것을 게임 안에서 닫았습니다. パルプンテ 27칸을 하나씩 일으켜 화면을 보았고, `$6E44` bit7 을 읽는 나머지 곳 가운데 다섯 곳을 실측했습니다. 대화 `13B`·`0AD` 와 `0F/00` 의 밤 이벤트 `3E` 도 끝까지 돌렸습니다. 그러다 `dq4shop.py hidden` 의 아이템 소지 조건이 거꾸로였던 것을 찾아 고쳤습니다. 장 안의 장면 순서로 거르기는 해 보니 틀린 관계라서 넣지 않았습니다. 결과는 [dq4-encounter-format.md](../docs/dq4-encounter-format.md) 와 [dq4-shop-format.md](../docs/dq4-shop-format.md) 에 넣었습니다.

## 1. パルプンテ 를 칸마다 일으키기

앞 일지는 `11:$B86C` 의 비교 값 `34` 를 `43`(공격)으로 바꿔 공격을 パルプンテ 갈래로 보냈습니다. 이번에는 rand 를 부르는 `11:$B8A7` 의 `BRK 17 0F` 를 `LDA #X ; NOP` 으로 덮어 칸 X 를 고정했습니다. 메시지와 PC 를 같이 적으려고 새 프로브 `shopenc2.lua` 를 만들었습니다(메모리상 PRG 바꾸기 + `16:$8656` 기록 + `HOOK="뱅크:주소"`).

처음 27번은 메시지가 모두 나왔는데, `D8`·`DC` 만 아무것도 없었습니다. 1장 첫 전투 세이브스테이트의 명령 창 커서가 どうぐ 에 있어서 ライアン 은 아이템을 썼고, 갈래를 지난 것은 몬스터 둘의 공격이었습니다(`11:$96D1` 의 `BRK 06 1F` 에서 C = 1). 위로 세 번 눌러 こうげき 를 고르게 하고 다시 돌렸습니다.

```
03 A=D8 0188            じかんが とまった
07 A=DC (메시지 없음)    파란 화면 → 필드 バトランド 성 앞
0B A=E0 015D            まもののむれは メタルスライムになった
11 A=E7 019C 0017 001B  まばゆい ひかり → 51 피해 → しんでしまった
```

`DC` 는 ルーラ 와 같은 처리기 `11:$AF9D` 라 전투를 끝내고 날아갔습니다. 30프레임마다 뜬 화면에서 `E0` 뒤 적 그림이 メタルスライム 둘로 바뀌고, `E2` 뒤 スライム 이 사라지는 것도 봤습니다.

## 2. `$6E44` bit7 을 읽는 나머지 곳

여덟 곳을 둘레 코드로 먼저 나눴습니다. `11:$A6AC`·`$A832` 는 `11:$A7C0` 의 장비 무기 비교(`8F` どくばり, `99` どくがのナイフ) 안이고, `11:$AFA5` 는 ルーラ 처리기, `11:$B170` 은 행동 `7B` 의 처리기, `13:$8094` 는 동료 작전, `10:$B0EF` 는 혼란 때 장난 행동을 고르는 곳입니다. `12:$A321`·`$A364` 는 뱅크 `12` 함수 `2E`(`12:$A311`) 안인데, 함수 표가 `12:$8000` 부터 50칸이라는 것을 세고서야 찾았습니다. 부르는 곳은 ルーラ 처리기의 `11:$AFA2` 하나입니다.

ライアン 의 무기 `$60C8` 을 바꿔 공격하고, `$6E44` 는 `seq.lua` 의 `POKE` 로 프레임마다 썼습니다.

```
どくばり   00: 004F 0167(급소)   80: 0016
どくがのナイフ 00: 0016 010B 0011  80: 0016
DC(ルーラ)  00: AFA2 → 12:A353 → AFC6(날아감)
            80: 12:A32B($8A=64) → A372 → AFC1, 005B ふしぎな ちからに ひきもどされた
7B          00: 0148 → 0149(떠남) 또는 014B   80·40: 0148 → 014B
```

행동 `7B` 는 「まあまあ きみたち」 로 몬스터를 달래 보내는 것이고, 이벤트 전투와 도망칠 수 없는 전투(bit6)에서는 늘 실패합니다. `13:$8094`·`10:$B0EF` 는 5장 동료가 필요해 코드 읽기로 두었습니다.

## 3. 대화 13B·0AD

앞 일지에서 `13B` 는 소지품이 바뀌지 않았고 `0AD` 는 「では もんだいじゃ」 에서 멈췄습니다. 루틴을 읽어 보니 `13B`(`15:$AE4E`)는 검사 뒤 `BRK 66 73` → `BRK 30 73` → `BRK 2E 73` 을 조건 없이 이어 부릅니다. 대사가 길 뿐이었습니다. A 를 45번 누르니 `0AA7`~`0AAB` 를 지나 てんくうのつるぎ 가 `14` → `21`, `$629B` = `10` 이 되었습니다.

`0AD`(`15:$AB23`)의 문제는 대답을 받지 않는 독백(「ちんもくは きん なりじゃ」)이었고, 정답이 필요한 것은 그 앞의 예/아니오 둘이었습니다. 첫 물음 「うみに くわしい ろうじんとは わしのことか」 에 「いいえ」 를 해야 이어집니다. 왕좌의 방에서 명령 창(A, A)으로 말을 걸고 아래·A 로 「いいえ」, 다음은 「はい」 로 넘겼습니다.

```
0951 → 0953 → 0955 → 62A1|=02 → 0956 → 0957   소지품 3 = 6E
0951 → 0953 → 0955 → 0958                     소지품이 차 있으면
```

## 4. 맵 이벤트 3E

`0F/00` 밤의 인물 블록을 `dq4npcblock.py 0F 00` 으로 풀어 보니, 이벤트 `3C` 를 부르는 슬롯 16 블록이 「일행이 (03,0B) 에 설 때까지」 기다렸습니다. 앞 일지는 맵에 들어가 기다리기만 했습니다. 2장·밤·`$627B` = `30`·소지품 `76` 으로 (03,0C) 에 워프한 뒤, 상태 창이 뜨는 200프레임을 넘기고 위로 한 걸음 걸었습니다.

```
0362 0363 0365 0366 02A0 0427 0367
끝: 소지품 3 = 71, $627B = 70, $62ED = 1E
```

`76` 없이 같은 걸음을 걸으면 아무 일도 없었습니다.

## 5. 아이템 소지 조건이 거꾸로

`dq4shop.py hidden` 은 `0F/00` 의 밤 인물 셋을 「`[밤 & 아이템 76 있음]` 이면 숨김」 이라고 했습니다. 그런데 4절에서는 `76` 을 가져야 그 인물들이 나왔습니다. `1C:$A097` 의 P 를 보니 찾으면 C = 1 이었고, 도구는 C = 1 을 「없음」 으로 읽고 있었습니다. 고친 뒤 `hidden` 출력에서 바뀐 줄은 이 셋뿐입니다. 이 원자는 덤프로 값을 셀 수 없어 `--compare` 가 보지 못했습니다.

## 6. 장 안의 장면 순서로 거르기

[dq4-story-format.md](../docs/dq4-story-format.md) 의 장면 차례로 「뒤 장면 비트가 켜져 있으면 앞 장면 비트도 켜져 있다」 를 넣어 보았습니다. 짧아지는 줄은 넷이었습니다. 첫 줄 `01/02` 인물 1 의 `[$627E&02 & $627E&04 & $627E&08 & 낮]` 이 `[$627E&02 & 낮]` 이 되었는데, 성문 병사(대화 `021`)는 `$627E` bit1 을 켤 때 ブライ·クリフト 의 비트를 보지 않습니다. 이 관계는 넣지 않았습니다.

## 7. 그룹 FE

`12:$84AA` 의 `BRK 17 5F` 에 닿는 길을 더 찾았습니다. 뱅크 `12` 함수 표 50칸, 바로 앞 `JMP ($0002)` 표 8칸, 롬 전체의 `LDA #$84 ; PHA ; LDA #$A9 ; PHA` 꼴에도 없었습니다. 정상 진행에서는 열리지 않는 조각으로 봅니다(코드 읽기).

## 틀렸던 것들

- パルプンテ 갈래 첫머리 `BRK 05 1F` = 0 을 「행동자가 일행」 으로 읽었습니다. 몬스터 공격도 지나갔으므로 그 뜻이 아닙니다.
- 첫 パルプンテ 실험의 행동자를 ライアン 으로 알았습니다. 명령 창 커서가 どうぐ 에 있어서 실제로는 몬스터의 공격이었습니다.
- `13B`·`0AD`·이벤트 `3E` 가 앞서 안 된 것은 조건이 아니라 입력이었습니다(대사를 다 넘기지 않음, 첫 물음의 답, 밟을 칸).
