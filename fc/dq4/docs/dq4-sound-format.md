# DQ4(FC) 소리 드라이버와 악보 형식

FC 판의 곡·효과음이 롬에 어떻게 들어 있고 드라이버가 어떻게 APU 로 내보내는지 정리한 문서입니다. SFC(DQ5 엔진, SPC700)로 다시 편곡할 원본을 롬만으로 뽑는 것이 목적입니다. 찾아낸 과정은 [2026-10-25-71 일지](../journal/2026-10-25-71-sound.md)·[2026-10-26-24 일지](../journal/2026-10-26-24-sound2.md) 에 있고, SFC 쪽 명령 체계는 [sfc/dq5/docs/dq5-sound-format.md](../../../sfc/dq5/docs/dq5-sound-format.md) 에 있습니다.

- 도구: [fc/dq4/tools/dq4sound.py](../tools/dq4sound.py)(곡·효과음 표, 악보 텍스트, 드라이버를 그대로 돌린 음 사건·APU 쓰기, MIDI, 맵 곡 표, 부르는 곳, NSF·WAV, NDS 곡 대조), APU 합성기 [fc/dq4/tools/dq4apu.py](../tools/dq4apu.py), 프로브 [fc/dq4/tools/lua/soundlog.lua](../tools/lua/soundlog.lua)(APU 쓰기·소리 입구·메시지 기록, 곡 바꿔 끼우기)·[soundscene.lua](../tools/lua/soundscene.lua)(장면마다 고른 곡·맵 곡 고르기의 `x3` 값·`$6BF9` 읽기)·[apustate.lua](../tools/lua/apustate.lua)(MesenCE 의 APU 채널 상태)·[nsflog.lua](../tools/lua/nsflog.lua)(NSF 를 틀어 APU 쓰기 기록).
- 악보 텍스트·MIDI·NSF·소리 파일은 롬에서 뽑은 저작권 데이터라 이 저장소에 두지 않습니다. `dq4sound.py rom export`·`nsf`·`wav` 가 `work/` 아래에 만들고, 비공개 에셋 저장소에는 `fc/dq4/sound/` 아래에 둡니다(「[포팅에 쓰기](#포팅에-쓰기)」).
- 검증: 곡 50개·효과음 55개를 게임 안에서 틀어 MesenCE 로 기록한 APU 쓰기와, `dq4sound.py` 가 롬의 드라이버를 6502 해석기([dq4cpu.py](../tools/dq4cpu.py))로 돌려 낸 APU 쓰기가 프레임마다 모두 같았고, 해독한 음 12212개의 음높이가 모두 실측 쓰기와 맞았습니다(아래 「검증」).

## 뼈대

| 무엇 | 자리 | 비고 |
| --- | --- | --- |
| 드라이버 코드 | 고정 뱅크 `1F` 의 `$E685`~`$F101` | `0F` 에는 없음. NMI(`1F:$C1AD`)가 프레임마다 `$C019` → `$E685` 를 부름 |
| 소리 데이터 | 뱅크 `19` | 곡 표·엔벨로프·비브라토·효과음과 곡 대부분. 드라이버가 `$FF94` 로 잠깐 `19` 를 끼움(`$6E86` = 지금 끼운 뱅크) |

### 입구

고정 뱅크 `1F:$C01C`~`$C02B` 는 `JMP` 표이고, 다른 뱅크는 `BRK n 9F`(뱅크 `19` 함수 n, `19:$8000` 표)로 부릅니다. `BRK b FB` 는 A = b 로 함수 3 을 부르는 짧은 꼴입니다([dq4-bank-format.md](dq4-bank-format.md)).

| 함수(`BRK n 9F`) | 입구 | 하는 일 |
| --- | --- | --- |
| 2 | `$C01C` → `$F088` | 초기화: `$4015` = `0F`, `$4017` = `80`, 스윕 끔, 곡 `00`·효과음 `80` 시작 |
| 3 | `$C01F` → `$EF59` | A 가 `80` 미만이면 곡, 이상이면 효과음 시작. 곡이 지금 곡(`$BF >> 1`)과 같으면 다시 시작하지 않음 |
| 4 | `$C022` → `$F055` | 페이드아웃: `$BB` \|= `45`(곡 5틱마다 주 음량 −1, 0 이 되면 페이드 끝, `$EEE0`) |
| 5 | `$C025` → `$F05C` | 페이드인으로 곡 시작: `$BB` \|= `C5`. 같은 곡이면 다시 시작하지 않고 음량만 올림 |
| 6 | `$C028` → `$EED3` | 주 음량 = A & `0F` |
| 7 | `$C02B` → `$F0B2` | 곡의 끝 표시(`$B0` bit5, 명령 `FC`·채널이 모두 끝남)가 설 때까지 프레임을 기다림 |
| 8 | `19:$803B` | 지금 자리의 맵 곡 번호를 A 로(아래 「맵 곡」) |
| 9 | `19:$8026` | 맵 곡을 고르고 함수 3 으로 틂 |

징글은 거의 모두 `BRK nn FB` → `BRK 07 9F`(끝날 때까지 기다림) → `BRK 09 9F`(맵 곡 되돌리기) 순서입니다. 이야기 명령 `30 n`·인물 블록 명령 `30 n` 은 함수 3([dq4-story-format.md](dq4-story-format.md)), 대사 제어 `EE n` 은 `n < 40` 이면 곡 n 을 틀고 끝날 때까지 기다리며 `n ≥ 40` 이면 효과음 `n + 40` 입니다([dq4-text-format.md](dq4-text-format.md)).

### 틱과 템포

프레임마다 `$E685` 가 효과음 채널을 한 번 돌리고, 곡 채널은 템포 누산기로 돌립니다(`$E6BE`~`$E6F4`): `$BD` += 템포(`$BC`)가 넘치면 `$96` 을 빼며 한 틱을 돌고, 남은 값이 `$6A` 보다 작으면 받아올림 없이(`$97`) 한 번 더 뺍니다. 그래서 템포 t 의 틱 수는 t ≤ 150 이면 프레임마다 t/150, 그 위는 조금 많습니다(155 → 1.0461, 180 → 1.2221). 곡의 템포는 펄스 1 의 첫 바이트이고(`$EFEB`), 명령 `FF` 로 바꿉니다. 음 길이는 틱 단위, 엔벨로프·비브라토는 프레임 단위입니다. 틱 하나 안에서 채널 순서는 펄스 1·2·삼각파(곡 뱅크) → 노이즈(뱅크 `19`)입니다.

## 표

| 표 | 자리 | 형식 |
| --- | --- | --- |
| 곡 표 | `19:$814E` | 곡 `00`~`35`(54개) × 8바이트: 펄스 1·펄스 2·삼각파·노이즈 첫 주소 |
| 곡 뱅크 | `19:$82FE` | 곡마다 1바이트. 0 이면 뱅크 `19` 의 주소, 아니면 곡 표 값의 아래 바이트가 그 뱅크 `$8000` 주소 표의 번호이고(`$C3CE`), 세 채널만 읽어 노이즈는 늘 `19:$8335`(빈 채널) |
| 빈 채널 | `19:$8335` | `94 00`(쉼, 길이 0 = 끝). 곡 `00`·`24` 와 쓰지 않는 채널이 가리킴 |
| 효과음 표 | `19:$A16B` | 효과음 `80`~`B7`(56개) 워드. bit15 = 1 이면 펄스 2, 0 이면 노이즈이고 주소는 워드 \| `8000`. `B2` 는 `0000`(빈 칸) |
| 엔벨로프 | `19:$8337` | 명령 `E1 n` 의 n(짝수)이 바이트 오프셋인 주소 표 |
| 비브라토 | `19:$8842` | 명령 `F0 n` 의 n(짝수)이 바이트 오프셋인 주소 표 |
| 주기 | `1F:$EC83` | 워드 99개. 첫 값 `07F0` 이 A1(55Hz, 펄스) |

곡 `14`·`18` 은 표 값이 `0000` 이라 RAM 을 가리키고 아무도 부르지 않으며, `00`·`24` 는 네 채널이 모두 빈 채널입니다. 그래서 들을 수 있는 곡은 50개입니다.

## 악보 바이트

채널마다 바이트를 차례로 읽습니다(`$E7DA`). `E1` 과 `E8`~`FF` 는 명령, 나머지(`00`~`E0`, `E2`~`E7`)는 음입니다.

### 음

바이트 b 를 75 로 나눈 나머지가 음 번호, 몫이 꼴입니다(`$E9A8`).

| 꼴 | b | 뒤 바이트 | 뜻 |
| --- | --- | --- | --- |
| 0 | `00`~`4A` | 없음 | 앞 음과 같은 길이·게이트 |
| 1 | `4B`~`95` | 길이 d | 길이 = d & `7F`. d bit7 이면 다음 바이트 & `7F` 가 게이트. 길이 0 은 채널 끝 |
| 2·3 | `96`~`E0`, `E2`~`E7` | 게이트 g | 길이는 그대로, 게이트 = g |

- 음 번호 `49` 는 쉼, `4A` 는 잇기(앞 음을 다시 치지 않고 길이만 더함), 나머지 `00`~`48` 이 음높이입니다. 노이즈 채널은 음 번호 & `0F` 를 `$400E` 에 씁니다(노이즈 주기).
- 음높이: 주기 표 번호 = 음 번호 + 3 + 이조(`$6BFE,X`, 효과음은 이조 없음). 삼각파는 이 값이 `39` 이상이면 `39` 를 빼고 `4E` 를 더한 자리의 표를 씁니다(`$ED49`). 펄스는 주파수 = 1789773 / (16 × (주기 + 1)), 삼각파는 32 로 나눕니다. 이조 0 이면 음 번호 `00` 이 펄스 C2, 삼각파 C1 입니다.
- 게이트: 펄스는 게이트 틱이 지나면 엔벨로프의 「떼기」 자리로 넘어갑니다(`$E783`). 0 이면 넘어가지 않습니다. 삼각파는 게이트(0 이면 `0F`)를 주 음량으로 줄이고, 주 음량이 6 미만이거나 줄인 값이 0 이면 그 음을 내지 않습니다(`$EA8D`).
- 리듬 꼴(`F3`)이 켜져 있으면 음을 읽을 때마다 꼴 표에서 (길이, 게이트) 쌍을 차례로 꺼내 씁니다. 꼴 바이트가 `00` 이면 처음으로 돌아가고, 게이트 바이트가 `80` 이상이면 게이트는 그대로 둡니다(`$E9DD`).
- 따라가기(`F7`)가 켜진 펄스 2·삼각파는 음을 읽을 때 바로 앞 채널(펄스 1·펄스 2)의 길이·게이트를 그대로 씁니다(`$E9CA`). 앞 채널이 끝나 길이가 0 이면 이 채널도 끝납니다. 곡 `02`(타이틀)의 펄스 2 는 자기 데이터 끝에서 삼각파 데이터로 이어 읽다가 이렇게 끝납니다.

### 명령

| 바이트 | 인자 | 뜻(처리 주소) |
| --- | --- | --- |
| `FF` | 1 | 템포(`$E966`) |
| `FE` | 2 | 주소로 건너뜀. 효과음이 아니면 돌아올 자리를 `$0634,X` 에 남김(한 단계 부르기, `$E96E`). 곡의 되풀이도 이 명령 |
| `FD` | 0 | `FE` 가 남긴 자리로 돌아감(`$E98D`) |
| `FC` | 0 | 곡의 끝 표시 `$B0` bit5 를 켬(함수 7 이 기다리는 것, `$E88B`). 읽기는 계속함 |
| `FB` | 1 | 이조 = 인자(`$E93F`) |
| `E8` | 1 | 이조 += 인자(`$E948`) |
| `FA` | 2 | 되풀이: 횟수 n, 거리 d. 세던 값이 0 이면 n 을 넣고, 1 을 뺀 값이 0 이 아니면 거리 바이트 뒤 주소 + d − `100` 으로 돌아가고 0 이면 지나감(`$E8FE`, 셈은 `$064B,Y`) |
| `F9` | 1 | 횟수 2 인 `FA`(`$E8F4`) |
| `F7` / `F8` | 0 | 따라가기 켬/끔(`$B0` 의 채널 비트, `$E952`·`$E95C`) |
| `F6` | 1 | 주 음량(`$B0` 아래 4비트) = 인자 & `0F` |
| `F5` / `F4` | 0 | 주 음량 +1 / −1 |
| `F3` | 2 | 리듬 꼴 주소(`$6C03,X`), 꼴을 처음부터 켬(`$E840`) |
| `EC` | 0 | 리듬 꼴 끔 |
| `F2` | 1 | 스윕 레지스터(`$4001`/`$4005`)에 그대로 씀 |
| `F1` | 1 | 미세 음높이(`$B1,Y` 아래 4비트) |
| `F0` | 1 | bit0 이 0 이면 비브라토 번호, 1 이면 끔(`$B5,Y`) |
| `EF` | 0 | 페이드아웃(함수 4 와 같음) |
| `EE` | 1 | 채널 음량(`$B1,Y` 위 4비트). 0 이면 줄이지 않고, 1~F 는 클수록 큼(`$EDEA` → 곱셈 `$EE8A`) |
| `EA` / `E9` | 0 | 채널 음량 +1 / −1(넘치거나 0 이 되면 그대로) |
| `ED` | 1 | 고정 음량·듀티(`$6BFA,Y`). `FF` 면 엔벨로프를 씀, `00` 이면 채널 기본값(`$EE85`) |
| `EB` | 0 | `$6BF9` += 1. 연출이 곡에 맞추려고 읽는 셈(아래 「[맞춤 셈](#맞춤-셈-6bf9)」). 곡을 시작할 때 0(`$F022`) |
| `E1` | 1 | 엔벨로프 번호(`$063D,X`), 처음 자리부터 |

명령 이름은 `dq4sound.py score` 가 찍는 이름입니다(`tempo`, `jump`, `loop` …).

### 엔벨로프

엔벨로프 바이트열은 프레임마다 한 바이트씩 읽습니다(`$EE0C`). 대부분 첫 두 바이트가 `C2 r` 이고 r 은 게이트가 끝났을 때 건너갈 「떼기」 자리입니다(`$E7AD`).

| 바이트 | 뜻 |
| --- | --- |
| `00`~`0F` | 그 수만큼 프레임 동안 앞 값을 둠 |
| `10`~`BF` | `$4000,Y` 값: 위 4비트(듀티·길이 멈춤·고정 음량), 아래 4비트 음량(주 음량·채널 음량을 곱해 줄임, `$EE8A`) |
| `C0`~`FF` | 자리 (b & `3F`) 로 건너뜀 |

곡·효과음이 명령 `E1` 로 쓰는 엔벨로프 전부입니다(`dq4sound.py rom envelopes`). 음량은 값 바이트의 아래 4비트(16진)이고, `×n` 은 머묾 바이트까지 더한 프레임 수, `↺` 는 건너뜀으로 되돌아가 같은 값을 되풀이하는 자리입니다. 듀티는 값 바이트 bit7·6(`00` 12.5%, `01` 25%, `10` 50%, `11` 75%)이고, 한 엔벨로프 안에서 듀티가 바뀌기도 합니다. 값 바이트의 bit5·4(길이 멈춤·고정 음량)는 거의 모두 `30` 입니다. 「떼기」 는 첫 바이트가 건너뜀인 엔벨로프만 있고, `@n` 이 그 자리입니다. 노이즈·효과음용은 펄스 듀티 비트가 노이즈에서는 뜻이 없습니다. 엔벨로프 `74`(효과음 `AE`)처럼 건너뜀 없이 이어지는 것은 다음 자료까지 읽어 가지만, 효과음이 그 전에 되풀이합니다.

| `08` | `19:83F4` | 50% | F E D C B A 9 8×2 7×2 6×2 5×2 4×5 5×3 ↺ | @22: 5×4 4×4 3×6 2×6 1 ↺ | 05 0C |

### 비브라토와 미세 음높이

비브라토 바이트(`$EB53`): bit0·bit1 이 `00` 이면 (b >> 2, bit7 이면 음수)를 이 프레임의 음높이 보정에 더하고 다음 바이트로, `11` 이면 (b >> 2) & `0F` 프레임 기다림, `01` 이면 자리 b >> 2 로 건너뜀, `10` 이면 끝. 보정 값 A(미세 음높이 × 2 + 비브라토)는 주기에 (한 옥타브 위 주기 × (A & `0F`) / 256)을 A bit7 에 따라 빼거나 더합니다(`$EBC0`~`$EC1C`, 한 단계가 약 3.4센트, 코드 읽기). 곡이 쓰는 비브라토(`F0` 의 짝수 인자) 전부:

### 맞춤 셈 `$6BF9`

명령 `EB` 는 `$6BF9` 를 하나 늘리기만 하고(`$E87C`), 곡을 시작할 때 0 으로 돌아갑니다(`$F022`). 드라이버는 이 값을 읽지 않습니다. 롬에서 `$6BF9` 를 읽는 명령은 뱅크 `1A`(타이틀·장 끝·엔딩 연출) 의 두 곳뿐입니다.

| 읽는 곳 | 하는 일 | 쓰는 곡 |
| --- | --- | --- |
| `1A:$8BDA` | 타이틀에서 프레임마다: 패드 `$14` 가 0 이 아니면 건너뛰고, `$6BF9` ≥ 2 이면 기다림을 끝냄 | `02`(타이틀, `EB` 2개) |
| `1A:$806E` | `$6BF9` 가 0 이 아닐 때까지 돌며 기다림(코드 읽기). 장 끝 곡을 `1A:$B905` 에서 튼 뒤 `1A:$8058` 이 부름 | `25`~`28`(장 끝, `EB` 1개씩) |

`EB` 를 쓰는 곡은 `02`·`25`·`26`·`27`·`28` 뿐입니다(표 값이 RAM 을 가리키는 `14`·`18` 을 빼고, `dq4sound.py score` 의 `sync`). 해석기로 돌리면 `02` 의 `EB` 는 곡 시작 뒤 1098·1184프레임, `25`~`28` 의 `EB` 는 곡이 끝나는 바로 앞 프레임(475·511·414·797)에 옵니다. 그러니 장 끝 연출은 징글이 다 울릴 때까지 기다립니다.

실측: 전원을 켜고 [soundscene.lua](../tools/lua/soundscene.lua)(`EVERY_READ=1`)로 `$6BF9` 읽기를 적었습니다. 게임이 프레임 874 에 곡 `02` 를 걸고, 그 뒤 `1A:$8BDA` 가 프레임마다 읽은 값이 892 에 0, 1974 에 1, 2062 에 2 였습니다(874 + 1098·1184 와 같은 자리). 2 를 읽은 뒤 프레임 2075 의 화면에는 「DRAGON QUEST」 글자와 성 그림이 나와 있었고, 2061 까지는 검은 바탕에 「IV」 만 있었습니다. 장 끝 쪽(`1A:$806E`)은 장 끝 장면을 만들지 못해 실측하지 않았습니다.

## 곡 목록

롬에는 곡 이름이 없습니다. 「NDS 이름」은 NDS 판 사운드 테스트 이름표([nds/dq4/docs/sound-format.md](../../../nds/dq4/docs/sound-format.md#곡-목록))의 곡 가운데 선율이 같은 것입니다. `dq4sound.py rom ndsmatch DIR` 이 FC 곡의 펄스 1·2·삼각파에서 이어지는 두 음의 반음 차이 열(조 옮김과 무관)을 만들고, 그 열의 5개 묶음(음이 적은 곡은 3개 묶음) 가운데 NDS 곡 MIDI(비공개 에셋 `nds/dq4/sound/songs/`)의 어느 트랙에 같은 묶음이 있는 비율을 셉니다. 괄호 안이 그 비율이고, 첫째가 0.4 이상이며 둘째보다 뚜렷이 높은 것만 이름으로 적었습니다. 「장면」은 선율 비율은 낮지만 FC·NDS 의 쓰이는 장면이 같아 붙인 것, 「장 번호」는 장 끝 곡을 부르는 코드에서 붙인 것입니다. 빈 칸은 맞는 곡을 정하지 못한 것입니다.

`dq4sound.py rom songs` 의 길이·되풀이는 드라이버를 돌려 채널 상태(읽는 주소·남은 틱·되풀이 셈·이조 등)가 처음 같아지는 틱으로 찾은 것입니다. 「쓰임」의 [확인] 은 아래 실험에서 게임이 그 곡을 부른 것을 기록한 것, [코드] 는 부르는 곳을 코드로만 읽은 것입니다.

### 곡 19

`19` 는 `15`(`04/0E`)와 같은 뱅크 `17`·같은 템포 104 이고 되풀이 길이도 1824틱으로 같으며, 선율도 같습니다(`ndsmatch` 의 코로세움 두 곡 비율이 같음). 롬에서 소리를 거는 길 네 가지를 모두 찾아도 `19` 를 거는 곳이 없습니다.

- 즉치값 `LDA #$19` 바로 뒤의 소리 입구(`JSR`/`JMP $C01F`·`$C025`, `BRK 03 9F`·`05 9F`)와 `BRK 19 FB`, 그리고 `LDA`·`LDX`·`LDY #$19` 뒤 14바이트 안의 소리 입구: 없음.
- 즉치값이 아닌 소리 입구 10곳(`1F:$DDC2` 인물 블록 명령 `30 n`, `1D:$AEE6` 의 표 `1D:$AEFD`, `1A:$B905` 의 `25` + 장, `16:$81A5` 의 대사 제어 등): 인물 블록 `30 n` 은 `09`·`0C`·`0D` 와 효과음뿐이고(`dq4sound.py rom calls` 의 「인물 블록 30」), 표와 계산 값에도 `19` 가 없음.
- 대사 제어 `EE n`: `19` 없음.
- 맵 곡 고르기 `19:$803B` 의 표(`$810B`~`$8131`): `19` 없음.

그래서 `19` 는 표에만 남은 곡으로 봅니다(코드 읽기·정적 검색).

## 맵 곡

`19:$803B`(함수 8)이 고르고 `dq4sound.py rom maps` 가 같은 표를 찍습니다.

1. 맵 안(`$41` bit7): `$6285` bit3 이면 `0E`. 아니면 `19:$8124` 의 3바이트 레코드 14개(그룹, 순번(`FF` 는 아무 순번), 곡)에서 찾고, 레코드 0·5·9·11~13 은 위 표의 조건을 더 봅니다. 없으면 맵 갈래 `$07BA` & `7F`([dq4-block-format.md](dq4-block-format.md#07ba))로 `19:$811C` 표: 0 → `03`, 1 → `0C`, 2 → `01`, 3 → `08`, 4 → `07`, 5 → `06`, 6 → `06`, 7 → `0A`.
2. 탈것(`$0515` ≠ 0): 1(배)이면 `09`, 아니면(2, 열기구) `13`.
3. 필드 1·2·3(`$65`): `19:$8112` 표로 `1D`·`14`·`1D`(필드 2 는 쓰이지 않음).
4. 필드 0: 1~4장(`$615A` 0~3)은 `19:$8116` 표로 `05`·`16`·`17`·`0B`. 5장은 `$6292` ≠ FF 면 `1C`. `$6292` 는 5장 진행 플래그 한 바이트로, 비트마다 동료 합류·마차 같은 일이 켭니다([dq4-story-format.md](dq4-story-format.md)). 모두 켜져 FF 가 되면 `x3 2B 63 41` 이 돌려주는 인물 번호(0~7)로 `19:$810B` 표(クリフト `16`, ミネア `0B`, マーニャ `0B`, ブライ `16`, トルネコ `17`, ライアン `05`, アリーナ `16`)를 봅니다. 번호가 0(勇者)이면 `19:$804C` 에서 `x3 62 63 41` 이 돌려주는 수가 1 일 때 `1C`, 아니면 `$811B` 의 `1D` 입니다(표 `$810B` 의 첫 칸은 읽지 않음).

`x3` 두 호출은 뱅크 `10` 함수 6(`10:$810B`)으로, 첫 바이트가 처리기 번호(`10:$9E67` 표: `2B` → `10:$884C`, `62` → `10:$9862`), 셋째 바이트 `41` 이 일행을 셀 때의 조건(`$6E0A`)입니다. 맵 곡 고르기가 돌아오는 자리(`19:$806F`·`$8050`)의 A 를 [soundscene.lua](../tools/lua/soundscene.lua) 로 적었습니다. 디버그 B 세이브스테이트(8명 모두 일행·마차, 5장)에서 워프 전에 `$6292` = FF 와 일행 자리를 써 두고 필드 0 으로 나간 16번입니다.

워프 실험에서 맵 갈래마다, 그리고 특수 레코드 장소 9곳(`04/01`·`04/07`·`04/0E`·`15/03`·`14/01`·`14/02`·`0A/00`·`2D/00`·`46/03`)에서 게임이 부른 곡이 이 표와 모두 같았습니다(아래 「검증」).

## 포팅에 쓰기

`dq4sound.py rom export [OUT] [--flac]` 한 명령이 곡 50개·효과음 55개마다 아래 파일과 폴더마다 `index.json`(번호, NSF 트랙, NDS 이름, 파일 목록, 채널 주소, 템포, 음 수, 길이·되풀이), 그리고 `OUT/dq4.nsf` 를 만듭니다. 비공개 에셋 `fc/dq4/sound/` 는 이 명령의 출력 그대로입니다(`--flac` 은 `flac` 명령이 있어야 함). 시각·임의 순서가 들어가지 않아 같은 롬·같은 도구면 같은 바이트가 나옵니다.

- `NN.txt`: 채널별 악보 텍스트(주소, 바이트, 명령·음 뜻)와, 드라이버를 돌려 얻은 음 사건(틱, 채널, 음 이름, 길이, 게이트, 음 번호)·템포 바뀜·되풀이 틱.
- `NN.mid`: SMF 형식 1, 트랙 = 지휘(이름·템포·`loopStart`/`loopEnd` 표시) + 펄스 1·펄스 2·삼각파(MIDI 채널 0~2) + 노이즈(채널 10, 노이즈 주기 0~3 → 42, 4~8 → 38, 9~F → 36). 4분음표 = 24틱으로 두고, 템포는 위 틱 비율에서 계산해 실제 길이가 게임과 같습니다. 음높이는 주기에서 가장 가까운 반음, 펄스 음 길이는 게이트(게이트가 0 이거나 길이 이상이면 길이)입니다. 곡은 처음부터 첫 되풀이의 끝까지 한 번 담습니다. 음량·음높이 변화는 아래 컨트롤러로 담습니다.
- `NN.json`: SPC 악보로 옮길 중간 형식(`dq4sound.py rom json N` 과 같은 내용). 아래 「중간 형식」.
- `NN.musicxml`·`NN-score-PP.svg`: 오선 악보(아래 「[오선 악보](#오선-악보)」).
- `NN.flac`: 합성한 소리(아래 「[WAV](#wav)」 를 FLAC 으로).

MIDI 의 컨트롤러(펄스 1·2·노이즈, 삼각파는 음량이 없어 음높이 휨만):

| 컨트롤러 | 값 | 어디서 |
| --- | --- | --- |
| CC7(채널 음량) | 127 × (s + 1) / 16. s 는 엔벨로프에 곱하는 쪽 음량(주 음량 `$B0`, 채널 음량 `EE` 가 있으면 그것을 곱한 값, `$ED67`~`$EDF8`. 고정 음량 `ED` 일 때는 주 음량) | 드라이버가 음량을 내는 자리(`$EE61`·`$EDC7`)에서 `$10`·`$B0` |
| CC11(표현) | 127 × v / 15. v 는 그 프레임의 엔벨로프 값 또는 고정 음량(0~F) | 같은 자리의 A. APU 에 쓰는 음량은 s 와 v 를 곱한 것(`$EE8A`) |
| 음높이 휨(폭 ±2반음, 처음에 RPN 0) | 그 프레임에 APU 에 실제로 쓴 주기의 음높이 − 그 음의 MIDI 음 번호 | 프레임마다 `$4002`/`$4003`·`$4006`/`$4007`·`$400A`/`$400B` 쓰기. 비브라토·미세 음높이·이조와 반음 사이 어긋남이 모두 들어감 |

셋 다 값이 바뀐 프레임에만 냅니다. 엔벨로프가 머무는 프레임(`$6BFD` 위 4비트)은 드라이버가 음량을 다시 쓰지 않으므로 사건도 없습니다. 효과음 MIDI 는 효과음 채널(`$A4` = 4)의 엔벨로프 값만 CC11 로 담습니다. MIDI 에 담지 않은 것: 듀티(엔벨로프 값 바이트의 bit7·6), 하드웨어 스윕(`F2`, 곡 `23` 과 효과음 `92` 등 9개가 씀)이 바꾸는 주기. 이것들은 JSON 의 `envelopes`·악보 명령과 아래 NSF·WAV 에 있습니다.

### 오선 악보

`NN.musicxml` 은 MusicXML 3.1 이고, 파트는 채널마다 하나(pulse1·pulse2·triangle·noise, 효과음은 그 채널 하나)입니다. [dq4score.py](../tools/dq4score.py) 가 쓰고 [verovio](https://www.verovio.org/)(파이썬 패키지)가 쪽마다 SVG 로 그립니다(`xmlIdSeed` 고정).

- 시간: 4분음표 = 24틱(MIDI 와 같음, MusicXML `divisions` 24). 첫 틱(드라이버가 처음 읽는 틱 1)을 0 으로 당깁니다. 드라이버의 틱이 정수라 음 길이는 따로 양자화하지 않고 그대로 담습니다. 마디를 넘는 음은 붙임줄로 나누고, 한 조각은 2진 음표(점 하나까지)와 셋잇단(3:2) 음표의 합으로 가릅니다. 같은 종류의 셋잇단 셋이 이어지면 셋잇단 묶음 표시를 붙입니다.
- 음: 음높이는 MIDI 와 같은 반음(주기에서 가장 가까운 것), 길이는 게이트가 아니라 악보의 음 길이입니다. 노이즈는 타악 보표에 MIDI 와 같은 북 셋(42 닫힌 하이햇 `x` 머리, 38 스네어, 36 베이스 드럼)으로 둡니다. 보표는 가운데 음이 C4 아래면 낮은음자리표입니다.
- 박자: 롬에 없어 되풀이 길이로 정합니다. 96틱(4/4 한 마디)의 배수면 4/4, 아니고 72틱의 배수면 3/4(예: `03` 王宮のメヌエット 3600틱), 되풀이가 없으면 4/4 입니다. 못갖춘마디는 두지 않습니다.
- 템포: 바뀌는 자리마다 4분음표 BPM = 60 × 60.0988 × (프레임마다 틱 수) / 24.
- 되풀이: 시작·끝이 마디 경계면 도돌이표, 아니면 그 자리에 「되풀이 시작」·「되풀이 끝」 글자.

`export` 는 곡마다 MusicXML 을 다시 읽어, 파트마다 음 시작 틱 목록이 같은 곡 MIDI 의 음 켬 틱과 같고 길이가 곡 길이 이상인지 확인하고 다르면 멈춥니다(`dq4sound.py rom scorecheck [N…]` 이 같은 검사). 곡 `02`(序曲)는 pulse1 174·pulse2 244·triangle 468 = 886음, 4578틱으로 MIDI 와 같았고, 105개 모두 같았습니다.

### NSF

`dq4sound.py rom nsf OUT [--start N]` 이 롬의 드라이버를 그대로 쓰는 NSF(버전 1, 뱅크 전환)를 만듭니다. 뱅크 `19`·`10`·`12`·`13`·`17`·`18`·`1F`(16KB × 7)를 이 순서로 4KB 쪽 28개에 싣고, 고정 뱅크 `1F` 의 두 곳만 고칩니다.

- `$FF94`(A = 뱅크, MMC1 직렬 쓰기): 뱅크 표(`$FE8C`, 32바이트)에서 첫 쪽 번호를 찾아 `$5FF8`~`$5FFB` 에 씀. X·A 를 지킴.
- 빈 자리 `$FE8C`~`$FF73`(FF 232바이트)에 뱅크 표, 트랙 → 곡 번호 표(105바이트), INIT. INIT 은 해석기의 `Run` 과 같은 차례로 `$F088`(초기화) → `$E685`(한 틱) → `$0646`~`$064A` = FF → `$EF59`(곡 시작). PLAY 는 NMI 와 같은 `$C019`, 재생 주기 16639µs(60.0988Hz).

트랙은 곡 50개(`01`~`35` 중 빈 곡 `00`·`14`·`18`·`24` 를 뺀 것)와 효과음 55개(`80`~`B7` 중 `B2` 를 뺀 것)를 번호 순으로 둔 105개입니다(`nsf` 가 트랙 → 곡 번호를 찍음).

### WAV

`dq4sound.py rom wav OUT [N…]` 이 해석기로 돌린 프레임마다의 APU 쓰기를 [dq4apu.py](../tools/dq4apu.py) 로 합성해 44100Hz 16비트 모노 WAV 를 씁니다. 곡은 처음부터 첫 되풀이의 끝까지(되풀이가 없으면 끝까지), 효과음은 끝(또는 첫 되풀이)까지이고, 끝에 30프레임을 더 돌립니다. 합성기는 펄스 2·삼각파·노이즈의 엔벨로프·길이·선형 카운터·스윕과 프레임 카운터(5단계), NESdev 위키의 비선형 섞기, FC 본체의 1차 고역(90Hz·440Hz)·저역(14kHz)을 따릅니다. 음량은 곡마다 맞추지 않고 모두 2.8배라 가장 큰 곡(`30`)의 봉우리가 약 0.91 입니다. 105개를 다 합치면 3201초, WAV 로 270MB 라 비공개 에셋 저장소에는 FLAC(무손실, `flac -8`)으로 둡니다.

### 중간 형식(JSON)

| 키 | 내용 |
| --- | --- |
| `id`, `kind` | 번호(16진), `song`/`sfx` |
| `tempo`, `ticks_per_second`, `tempo_changes` | 첫 템포, 실제 틱 속도(누산기 그대로), 바뀐 [틱, 템포] |
| `loop_start`, `loop_len`, `end_tick` | 되풀이 시작 틱과 길이(없으면 `null`), 기록을 멈춘 틱 |
| `channels[]` | 채널마다 `name`·`bank`·`start` 와 `items[]`. 펄스 1 의 `items` 는 템포 바이트 다음부터 |
| `items[]` | 악보를 주소 순으로 푼 것. 모두 `addr`·`bytes`·`op`. 음은 `op` = `note`/`rest`/`tie` 와 `note`(음 번호)·`len`·`gate`(있을 때만, 없으면 앞 값)·`end`(길이 0). `jump`·`loop`(`count`)·`falls-into`·`goes-back` 은 `target` 주소, `rhythm` 은 `pattern`([길이, 게이트 또는 null] 목록), 그 밖의 명령은 `args`(명령 표의 이름과 인자) |
| `timeline[]` | 드라이버를 돌려 음을 읽은 순간마다: `tick`·`frame`·`ch`·`op`(`note`/`rest`/`tie`/`end`)·`note`·`midi`(주기에서 계산한 음높이, 실수)·`noise_period`·`len`·`gate`·`envelope`·`transpose`(부호 있는 수)·`fixed_vol`(`ED` 값, `null` 은 엔벨로프, `0` 은 채널 기본값)·`ch_vol`·`detune`·`vibrato`·`master_vol` |
| `envelopes` | 이 곡의 펄스·효과음이 쓰는 엔벨로프마다 `addr`·`duty`·`attack`/`release`([값 바이트, 프레임 수] 목록)·`attack_loop`/`release_loop`(되돌아가는 자리)·`release_at` |

`items` 는 롬 구조(되풀이·부르기)를 그대로 두어 SPC 쪽에서 같은 구조로 다시 짤 때 쓰고, `timeline` 은 그 구조를 펼친 결과라 둘을 견주어 옮김을 검사할 수 있습니다.

## 검증

- APU 쓰기: [soundlog.lua](../tools/lua/soundlog.lua) 를 1장 왕좌의 방 세이브스테이트에서 왕에게 말을 거는 입력과 함께 돌리고, 첫 소리 입구(효과음 `85`)의 A 를 곡 번호로 바꿨습니다(`SONG`, 뒤의 부르기는 `MUTE`). 1946프레임 동안 게임이 쓴 `$4000`~`$400F` 와, `dq4sound.py compare` 가 같은 곡을 드라이버째 돌려 낸 값이 프레임마다 같았는지 봅니다. 타이틀 곡 `02` 는 전원을 켠 뒤 게임이 스스로 부른 것(624프레임), 효과음 `85` 는 왕좌의 방에서 게임이 스스로 낸 것(5프레임)입니다. 결과는 아래 표.
- 음: 같은 기록에서, 해독한 음마다 그 음이 시작하는 프레임의 실측 쓰기에 주기 표 값(펄스·삼각파의 `$4002`·`$4003` 아래 3비트) 또는 노이즈 주기(`$400E`)가 있는지 봅니다.

## 남은 것

- `x3 62 63 41` 의 조건 `41` 이 죽은 동료를 빼는지(HP 만 0 으로 써서는 수가 줄지 않음).
- 장 끝 연출의 `1A:$806E` 기다림(장 끝 장면을 만들지 못해 코드 읽기)과 [코드] 로 둔 곡·효과음의 실제 장면.
- NDS 이름을 정하지 못한 곡 `11`·`12`·`21`~`23`·`29`·`2A`·`2C`·`32`~`34`. 대부분 음이 열 개 남짓인 징글이라 선율로 가르지 못함.
