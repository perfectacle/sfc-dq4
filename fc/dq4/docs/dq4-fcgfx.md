# DQ4(FC) 원작 그래픽 렌더링

SFC 로 다시 그릴 때 참고하려고 FC 원작의 마을·던전 맵 279개, 필드, 블록·CHR·폰트 시트, 타이틀·창·전투·장 제목·엔딩 화면을 PNG 로 뽑는 도구 [fc/dq4/tools/dq4fcgfx.py](../tools/dq4fcgfx.py) 의 쓰는 법과, 그리면서 새로 확인한 것(MesenCE 색, 필드 물가 블록, 필드·폭포 팔레트 순환)입니다. 블록·타일·팔레트 해석은 [dq4-block-format.md](dq4-block-format.md), 맵·출구·인물은 [dq4-map-format.md](dq4-map-format.md), 필드는 [dq4-field-format.md](dq4-field-format.md) 를 따릅니다. 실험 과정은 [2026-10-25-30 일지](../journal/2026-10-25-30-fcgfx.md) 와 [2026-10-25-41 일지](../journal/2026-10-25-41-fcgfx2.md)·[2026-10-25-58 일지](../journal/2026-10-25-58-fcgfx3.md)·[2026-10-25-63 일지](../journal/2026-10-25-63-fcgfx4.md) 에 있습니다.

뽑은 그림은 롬 그래픽이라 이 저장소에 커밋하지 않습니다. 비공개 저장소 `perfectacle/sfc-dq4-assets` 의 `fc/dq4/` 아래에 그 저장소의 「폴더·파일 규칙」(1배, `<번호>-<이름>-<변형>.png`)대로 두고, 폴더마다 `SOURCE.txt` 세 줄(커밋·명령·롬 SHA-1)을 적습니다. 확대는 갤러리가 `image-rendering: pixelated` 로 합니다.

## 출력

```sh
uv run --locked python fc/dq4/tools/dq4fcgfx.py rom/dq4.nes all OUT          # OUT/{maps,field,gfx,gallery}
uv run --locked python fc/dq4/tools/dq4fcgfx.py rom/dq4.nes scenes OUT SPEC.json   # MesenCE 덤프 장면 → OUT/gfx/screens(있는 목록에 더함)
uv run --locked python fc/dq4/tools/dq4fcgfx.py rom/dq4.nes gallery OUT      # 장면을 넣은 뒤 갤러리만 다시
uv run --locked python fc/dq4/tools/dq4fcgfx.py rom/dq4.nes map 02 01 work/x.png [--night|--annot]
```

맵 목록은 `dq4chest.all_maps`(279개)입니다. `dq4map.maps` 는 마지막 그룹 `48`(맵 10개, 맵 종류 `1B`·`1C`)을 빼므로, 렌더러는 자기 프로세스 안에서만 `dq4map.load` 를 `dq4chest.load` 로 바꿔 씁니다.

이름은 롬에 그룹 → 이름 표가 없어서 `place_table` 이 여덟 단계로 찾습니다. 73개 그룹(`00`~`48`) 모두에 이름이 붙지만(`index.json` 의 `name_src`), 앞 여섯 단계의 49개만 롬 글자에서 나온 이름이고 `near` 와 그것을 이은 `link` 24개는 필드 위 자리 표시입니다. 자리 표시는 파일 이름에 넣지 않으므로(에셋 저장소는 게임 속 이름을 알 때만 붙임) 그 24개는 그대로 `GG-KK.png` 이고, 갤러리·`index.json` 의 `name` 에만 나옵니다. 장소 이름 목록(`0B:$B006` 의 목록 5)을 읽는 곳은 `0B:$AFD0`(`LDA $B006,X`) 하나이고 그 입구 `0B:$AFC1`(함수 `0B[0A]`)를 부르는 BRK·JSR 이 PRG 전체에 없어서, 그룹 → 장소를 잇는 것은 ルーラ 목록(`10:$95EB`/`$95FA` → `$9612`)뿐입니다(코드 읽기). 글자는 롬의 글자표 그대로라 가타카나가 없는 글자는 히라가나입니다(예: `りバーサイド`).

| `name_src` | 그룹 수 | 근거 |
| --- | --- | --- |
| `rula` | 28 | ルーラ 목적지 레코드(`1E:$AF00`)가 장소 이름표(`0B:$B634`)와 같은 순서이고, 필드 자리가 입구 하나와 2칸 안이거나 맵 레코드가 그룹을 적음([dq4-field-format.md](dq4-field-format.md#ルーラ-목적지)) |
| `talk` | 4 | 그 그룹 인물 대사(낮·밤, 조건 갈래 전부)에서 「ここは」「ようこそ」 뒤 30글자 안에 처음 나온 장소 이름표의 이름. 뒤에 「ほこら」「どうくつ」가 이어지면 붙임(`1E` エンドールのほこら, `42` エンドールのどうくつ 등) |
| `talk-phrase` | 5 | 「ここは X」의 X(끝의 だ·です 따위를 뗌)가 장소 이름씨(むら·まち·しろ·ほこら·さと·いえ 등)로 끝나거나 가타카나가 든 8글자 이하인 것 중 가장 짧은 것(`13` サラン, `19` うみべのむら, `1D`, `20` きこりのいえ, `2F` エルフのさと) |
| `talk-kind` | 1 | 「このとう」「このどうくつ」「このとうだい」처럼 그 장소를 가리키는 말만 있을 때 그 말(이름이 아니라 갈래). 처음 여섯(`30`·`31`·`36`·`38`·`40`·`41`) 중 다섯은 아래 `talk-dir` 이 이름을 바꿔 `40` 하나만 남음 |
| `talk-dir` | 9 | 그룹 H 인물 대사의 「きたの　どうくつ」처럼 방위(ひがし·にし·みなみ·きた) + の·に + 장소 이름씨(とうだい·とう·どうくつ·ほこら). H 의 필드 입구에서 그 방위 45도 안(앞으로 간 거리 ≥ 옆 거리)에 입구가 있는 그룹 중 맨해튼 거리가 가장 가까운 것에 「방위の이름씨」를 붙임. 후보는 이름 없는 그룹과 이름씨가 같은 `talk-kind` 그룹뿐(마을·성은 뺌). `index.json` 의 `name_dir` 에 (H, 메시지, dx, dy). 아래 표 |
| `link` | 2 + 3 | 출구 연결 표(`1B:$8223`)와 계단 칸 표(`08:$B22E`, 필드로 나가는 칸 뺌)로 그룹을 잇고, 너비 우선으로 가장 가까운 `rula`·`talk`·`talk-phrase` 그룹의 이름. 거리가 같은데 이름이 다르면 붙이지 않음. `2C` てんくうじょう(`2C/10` (03,05) → `2D/00` 계단), `34` アッテムト(`0A/00` (0A,03) ↔ `34/00` 계단). 이어진 곳의 이름이지 그 그룹 자체의 이름이라는 보장은 없어 `index.json` 에 거쳐 간 출구(`name_via`)를 남김. 아래 `near` 다음에 한 번 더, `near` 그룹에서 이름을 받음(`3A` イムルちかく ← `1C/01`, `3E` エンドールちかく ← `25/00`, `48` りバーサイドちかく ← `2B/00`) |

## 색

NES 색 번호 → RGB 는 MesenCE 기본 팔레트를 화면에서 잰 값(`MESEN_RGB`)입니다. [fc/dq4/tools/lua/fcgfxpal.lua](../tools/lua/fcgfxpal.lua) 가 세이브스테이트를 불러 nametable 을 빈 타일로, OAM 을 화면 밖으로 치운 뒤 BG 팔레트 색 0 을 `00`~`3F` 로 바꿔 가며 화면을 찍습니다. MesenCE 화면 덤프는 메모리를 바꾼 프레임보다 한 프레임 늦게 바뀌어서, 색마다 4프레임을 두고 마지막에 찍었습니다(처음 한 프레임씩 찍었을 때는 색이 하나씩 밀리고, 한 곳에서는 둘이 겹쳤음).

```sh
export LIBDIR=$(uv run krpatch fc lua)
STATE=$PWD/work/state/dq4-ch1-throne.mss SHOT_DIR=$PWD/work/pal \
  "$MESENCE" --testrunner --nes.ramPowerOnState=AllZeros $PWD/rom/dq4.nes $PWD/fc/dq4/tools/lua/fcgfxpal.lua
```

## 필드의 물가 블록

필드 블록 `00`(물)은 화면에 그릴 때 이웃에 따라 블록 `20`~`2F` 로 바뀝니다(`0F:$D478`). 이것을 빼면 물가가 들어간 화면이 덤프와 어긋납니다.

| 단계 | 루틴 | 내용 |
| --- | --- | --- |
| 정의 올리기 | `08:$851E` → `$80B7` | 필드(`$07` = 0)면 블록 `20`~`2F` 의 2바이트 정의를 포인터 `08:$80C2`(`$8ABB`)부터 차례로 올림. 모양 레코드·타일 올리기는 블록 `00`~`1F` 와 같음 |
| 이웃 보기 | `0F:$D4A8`·`$D4CC` | 왼쪽, 아래, 오른쪽, 위 순서로 필드 칸을 찾아(`0F:$D244`) 블록이 `00`·`16`·`0A` 가 아니면 1 을 밀어 넣음(`ROL`). 결과 + `20` 이 그릴 블록: bit3 왼쪽, bit2 아래, bit1 오른쪽, bit0 위가 땅 |
| 필드 3 | `0F:$D483` | 블록 `01` 은 난수(`0F:$C891`)가 `FA` 미만이면 `18`, 아니면 `19`. 그림에는 `18` 을 씀 |

블록 `20` 은 물 그대로, `21` 은 위 두 타일이 물가 타일(`0C:$8030`·`$8010`)입니다. 필드 덤프의 `$7600`+4×블록(`20`~`2F`)과 위 정의로 만든 타일 그림이 같았습니다(필드 0·1·3).

`0F:$D2AA` 는 좌표에서 3 을 뺀 값이 폭·높이를 넘을 때만 0 을 돌려주므로, 가장자리 칸의 이웃은 폭·높이 +2 칸까지 원래 줄 데이터를 읽습니다. `dq4field.decode` 가 이 범위(줄 0 ~ 높이+2, 칸 0 ~ 폭+2)를 게임과 같이 풀어 두므로 렌더러는 따로 풀지 않습니다.

## 팔레트 순환

`1D:$8B1E`(뱅크 1D 함수 0)가 프레임마다 불려 `$3C`(프레임 수)&0F 가 홀수인 프레임에 `$8B4A` 를 부릅니다. 맵 종류(`$28`)가 `00`(필드)·`18`(폭포) 이면 BG 팔레트를 돌리고, 그 밖은 애니메이션 목록(`$8C52`, [dq4-block-format.md](dq4-block-format.md))으로 갑니다. 타일 그림·nametable 은 바뀌지 않습니다(`3B/00` 에서 PPU 쓰기는 `$3F00` 대 팔레트뿐).

| 맵 | 주기 | 바꾸는 것 |
| --- | --- | --- |
| 필드 전부 | 16프레임(`$3C`&0F = 0F) | 팔레트 0 의 색 2·3(`$05FE`·`$05FF`, 물결)을 맞바꿈(`$8B54`) |
| 필드 3 | 16프레임 | 팔레트 3 의 색 1~3(`$0606`~`$0608`, 용암)을 `$0606`←`$0608`, `$0608`←`$0607`, `$0607`←`$0606`(`$8B87`). PPU 에는 `$3F0D`~`$3F0F` 에 `$0606`, `$0608`, `$0607` 순서로 써서 한 번이라도 돈 뒤에는 화면 색 순서가 RAM 과 다름 |
| 맵 종류 `18`(`3B/00` 폭포) | 4프레임(`$3C`&3 = 3) | 팔레트 2 의 색 1~3(`$0603`~`$0605`)을 `$0605`←`$0604`←`$0603`←`$0605` 로 돌림(`$8C18`, 폭포가 흐르는 것). `$3F07` 에 `11` 을 함께 씀 |
| 맵 종류 `18` | 16프레임 | 팔레트 1 의 색 1·2(`$0600`·`$0601`)를 맞바꿈(`$8BF3`) |

`$3E` 가 0 이 아니고 걷기 상태 `$0584` 가 2 이상이면 돌리지 않습니다(`$8B1E`). 그림 파일은 롬의 첫 팔레트(돌리기 전)로 그립니다. `verify` 는 이 순환을 6단계로 돌려 보고 가장 잘 맞는 단계를 씁니다. 필드 3 의 블록 `01` 은 칸을 그릴 때마다 난수로 `18`·`19`(반짝임)가 갈리므로(`0F:$D483`) 둘 중 하나와 같으면 같은 것으로 셉니다.

## 확인

롬만으로 그린 화면과 MesenCE 화면 덤프를 256×240 전체 픽셀로 비교합니다. 렌더러는 RAM 의 장소(`$63`/`$64`/`$65`)·화면 왼쪽 위 칸(`$7C`/`$7B`)·스크롤(`$0505` bit0, `$0508`, `$0509`)·구역(`$7140`)·`$07BA`·시각(`$62ED`)만 읽고 나머지는 롬에서 그립니다. 덤프는 MesenCE 에 `--nes.disableSprites=true --nes.forceBackgroundFirstColumn=true` 를 줘 스프라이트를 끄고 왼쪽 8픽셀도 BG 를 보이게 해서 뜹니다. 프레임마다 블록 → 타일 표가 바뀌는 장면은 [fc/dq4/tools/lua/fcgfxgate.lua](../tools/lua/fcgfxgate.lua) 로 뜹니다. 메모리는 앞 프레임, 화면은 그 프레임에 찍어 `SHOT_DIR/fNNNNN/end.*` 에 두므로 `verify` 에 폴더를 그대로 줍니다.

```sh

WAIT=100 TAIL=10 sh fc/dq4/tools/dq4warp.sh work/w/0E-00 0E/00

  "$MESENCE" --testrunner --nes.ramPowerOnState=AllZeros --nes.disableSprites=true --nes.forceBackgroundFirstColumn=true \
  $PWD/rom/dq4.nes $LIBDIR/seq.lua
uv run --locked python fc/dq4/tools/dq4fcgfx.py rom/dq4.nes verify work/v/*/
```

장 제목 상자의 BG 타일 172장(`$01`~`$AC`)은 `1A:$80C5` → `$8254` 가 만듭니다. 원본은 `1A:$8CB0`(= `$8CA8` + 8, 포인터 `$82B7`)부터 타일마다 1비트 8바이트이고, `$8275` 를 43번 불러 4타일씩 PPU `$1010` 부터 씁니다. 제목의 한자도 여기 있습니다.

폰트 141자(`18:$B840`)는 이름 입력·모험의 서·전투·5장 명령 창의 CHR 덤프(`$1000`+글자×16 앞 8바이트, 뒤 8바이트 0)와 모두 같았습니다. 전투 화면 BG 는 검은 바탕에 창뿐이라 따로 그린 전투 배경은 없습니다.

## 롬만으로 뜬 장면

[dq4scenes.py](../tools/dq4scenes.py) 는 장면 25개를 에뮬레이터·세이브스테이트 없이 뜹니다. [dq4nes.py](../tools/dq4nes.py) 가 [dq4cpu.py](../tools/dq4cpu.py) 위에 MMC1(SUROM), PPU 레지스터(nametable·CHR RAM·팔레트·스크롤 레지스터), OAM DMA, 패드, 진짜 BRK·NMI 를 더한 작은 NES 이고, 전원을 켜서 정해 둔 입력을 줍니다. 덤프는 `fcgfxscene.lua` 와 같은 꼴(`fNNNNN.nt`·`chr`·`pal`·`oam`·`ram`·`ppu`·`png`)이라 `scenes` 가 그대로 읽습니다. `png` 는 MesenCE 화면이 아니라 그 프레임의 nametable·맨 위 스크롤·보이는 줄의 `$2005`·OAM 으로 그린 화면입니다.

- 한 프레임은 NMI 에서 시작하는 29781 CPU 사이클이고, 명령마다 기본 사이클과 분기 성립 1 을 셉니다(페이지를 넘는 1 은 세지 않음). `$2002` bit6 은 OAM 0 의 Y+1 줄에서 켭니다.
- 프레임 기다리기 `1F:$FF74` 는 한 바퀴가 16사이클인 `INC $12` 고리라, 남은 사이클만큼 `$12` 를 올리고 건너뜁니다. `$12` 가 난수에 섞이므로 첫 전투 몬스터는 MesenCE 와 다릅니다(はさみくわがた·おおみみず).
- 실측: 전원 켜고 760·1040·2440프레임의 nametable 그림이 MesenCE 덤프(제작진·IV 로고·타이틀)와 0 픽셀 다릅니다. 이름 입력은 입력을 MesenCE(`boot.lua`) 프레임보다 6프레임 앞당겨 주면 480·740프레임이 0 다릅니다.
- 처리가 밀리는 프레임(lag)이 실기보다 많아 엔딩은 MesenCE 보다 약 1만 프레임 깁니다(스태프 롤 시작 약 31200프레임, 「The End」 약 44000프레임). 그래서 덤프 프레임은 실기와 같지 않고, 장면 시트(`--sheet 단계 --every N --range A-B`)로 보고 골랐습니다.
- 대사를 넘기는 A 의 횟수는 정해 두지 않습니다. 사본에서 B 로 창을 닫고 걸어 보아 좌표가 바뀌면 그 상태를 씁니다. 왕좌의 방에서 필드로 나갈 때는 좌표를 보며 걷습니다(다른 인물이 막으면 기다림).
- 1장은 새로 시작해 이름 「あ」, 2·5장은 이름 확정 직전에서 디버그 장 고르기, 장 끝·엔딩은 [장 끝 표](dq4-save-format.md#장-끝)의 조건을 쓰고 `warp.lua` 와 같은 방법(출구 표 `$05A0`, 장소 쓰기 `1B:$8024`)으로 들어갑니다.
- 바다 장면의 줄 스크롤 루틴 `1F:$FE36` 은 처리가 밀린 프레임에는 돌지 않으므로, 두 줄(scanline 194·210)이 갈라진 프레임(1201·2001)을 고릅니다.

## 엔딩 바다의 줄 스크롤

엔딩의 바다 위 天空城 장면은 화면 아래 두 띠만 가로로 흐릅니다. 고정 뱅크 `1F:$FE36` 이 sprite 0 hit(`BIT $2002` / `BVC`, sprite 0 은 (C0,C1))를 기다렸다가 scanline 194 에 `$2005` ← `$7B`, scanline 210 에 `$2005` ← `$7C` 를 씁니다. `$7B` 는 `$7F` & 3 = 0 인 프레임마다, `$7C` 는 `$7F` & 1 = 0 인 프레임마다 1씩 늘어 아래 띠가 두 배 빠릅니다. 물결 표는 없고 RAM 카운터 둘뿐입니다. 부르는 곳은 `1A:$9D8C`(X 프레임 기다리기)의 `JSR $FE36` 하나이고, 워프 뒤 480프레임부터 불립니다. vblank 에는 `$2000` = `90`, `$2001` = `18`(왼쪽 8픽셀 BG 끔), `$2005` = `00`,`00` 입니다.

이 장면은 가로 mirroring(`$2400` = `$2000`)이라 가로 스크롤이 256픽셀 안에서 돕니다. 전에 화면이 4652·4103픽셀 달랐던 것은 세로 mirroring 으로 그려 오른쪽을 빈 하늘로 채웠기 때문입니다.

[fc/dq4/tools/lua/fcgfxscroll.lua](../tools/lua/fcgfxscroll.lua) 가 `LOG` 프레임의 `$2000`·`$2001`·`$2005`·`$2006` 쓰기를 (프레임, scanline, cycle, 값, pc, PRG 오프셋)으로 `ppulog.txt` 에 적고, `scenes` 는 장면 JSON 항목에 `"ppulog"`, `"mirror": "h"` 가 있으면 줄마다 스크롤을 바꿔 그린 `<장면>-screen.png` 를 더합니다. 줄 가운데 쓰기는 fine X 가 쓴 cycle 의 x 부터, coarse X 는 다음 줄부터 바뀌고, 보이는 줄의 `$2005` 둘째 쓰기(Y)는 그 프레임에 반영되지 않습니다(덤프 6장으로 맞춘 규칙). 로그의 프레임 번호는 그 쓰기가 보이는 화면 덤프 번호입니다.

```sh
DRIVER=$LIBDIR/seq.lua STATE=$PWD/work/end/warp.mss SEQ="wait:1" TAIL=1900 EVERY=0 \
  AT=1000,1001,1002,1003,1800,1801 LOG=1000-1003,1800-1801 SHOT_DIR=$PWD/work/sea \
  "$MESENCE" --testrunner --nes.ramPowerOnState=AllZeros $PWD/rom/dq4.nes $PWD/fc/dq4/tools/lua/fcgfxscroll.lua
# SPEC: [{"name": "ending-dawn1", "title": "…", "prefix": "work/sea/f01000", "ppulog": "work/sea/ppulog.txt", "mirror": "h"}, …]
uv run --locked python fc/dq4/tools/dq4fcgfx.py rom/dq4.nes scenes OUT SPEC.json
```

## 성문 연출

`02/00` 에 들어가면 성문이 열리는 연출 동안 화면 왼쪽 위 칸 `$7C`/`$7B` 를 쓰는 `0F:$D548`·`$D550`($7C = `$6F60` − 8, `$7B` = `$6F80` − 7)이 돌지 않아, RAM 에는 맵을 불러올 때의 (08,0F)가 남고 화면은 일행 자리 기준으로 그려집니다. 스크롤 `$0505`·`$0508`·`$0509` 는 화면과 같습니다.

문짝은 `1B:$870D` 가 그립니다. `$57` 이 단계(0~3, 24프레임 간격)이고, 단계마다 `1B:$8929` + `$100` × 단계 에서 `$40` 바이트 묶음 4개를 `$0300` 큐로 CHR 에 보내고, `1B:$8772` 가 블록 → 타일 표 `$7600` 에서 성문 블록(`$0540`/`$0541` = 10·14 와 각 +1) 넷을 새 타일로 돌립니다. 성문 칸은 `$053E`/`$053F` = (12,09) 입니다.

`rom_screen` 은 다음이 모두 맞으면 연출 중으로 보고 왼쪽 위 칸을 `$6F60` − 8 / `$6F80` − 7 로, 성문 블록 넷은 덤프 WRAM `$7600` 의 값과 보낸 묶음으로 그립니다: `$57` ≤ 3, `$55` = 1~4, `$56` = 8 × `$57`, `$0540` ≠ `FF`, `$53`/`$54` − `$40` × (4 × `$57` + `$55`) 가 `1B:$889C` 표의 시작값(`$8929`·`$8D29`) 중 하나. `$53`/`$54` 는 다른 루틴도 쓰는 임시 변수라 범위만으로는 모호해서 단계 변수까지 봅니다. 단계 사이(다음 단계 첫 조각 전)는 `$55` = 0 이고, 마지막 단계 뒤에는 `$57` = 4, `$55` = 4 로 멈추므로 보낸 조각 수는 min(4 × `$57` + `$55`, 16) 입니다. 시작값은 `1E:$8F42` 가 맵 종류 `32` 면 X = 2 로 골라 `$8D29`, 아니면 `$8929` 입니다.

연출이 시작되기 전에도 화면은 일행 자리로 그려집니다. `02/00` 에 들어오면 `1E:$8F63` 이 발밑 블록(`14`)을 `$0541` 에 두고 `$C5BF` 로 화면을 그린 뒤 15프레임쯤 지나 `$8F38` 에서 `$0540` 을, `1B:$87E0`~ 에서 `$53`~`$57` 을 정합니다. 그 사이(`$0540` = `FF`, `$0541` 이 성문 블록, 성문 블록 넷의 속성이 아직 롬 값)와 첫 조각 전 한 프레임(`$57` = `$55` = 0, `$53`/`$54` = 시작값)은 조각 0개의 연출 중으로 봅니다.

같은 연출은 「とびら」로 여는 성문(속성 `A0`·`A2`, [dq4-block-format.md](dq4-block-format.md))도 씁니다. `1E:$8F00` 이 `$053E`/`$053F` 에 일행 자리, `$0540` 에 블록을 두고 `BRK 03 BF` 로 부릅니다. 성 앞 `02/00` 은 들어오면 저절로 시작합니다.

연출 뒤와 단계가 바뀌는 프레임에는 두 가지를 더 봅니다.

- 마지막 단계는 조각을 성문 블록의 원래 타일 자리(`$7700` 의 뒤 네 칸)에 쓰고 `1B:$8772` 가 `$7600` 을 롬 정의로 되돌립니다. 그 뒤 `$53`~`$57` 은 다른 값으로 덮이고, `02/00` 은 `$0540`/`$0541` 도 `FF` 로 지우지만 그 맵을 나갈 때까지 CHR 에는 열린 그림이 남습니다. 그래서 롬 속성이 `A0`·`A2` 인 블록 넷(성문)의 속성 `$6F40` + 블록이 `1B:$885F` 가 바꾼 `80 80 24 24` 이면 조각 16개를 모두 그립니다. 다섯 맵 모두 성문 블록은 롬 속성 `A0`/`A2` 인 블록 넷(앞 둘이 `$0540`, 뒤 둘이 `$0541`)이었습니다.
- `1B:$8772` 는 `$57` bit0 으로 `$7710` 의 두 벌(앞 16바이트는 타일 `00`~`0F`, 뒤는 성문 블록의 롬 타일) 중 하나를 `$7600` 에 옮깁니다. 단계의 넷째 조각을 보낸 프레임(`$55` = 4)에 `$0300` 큐가 아직 비지 않았으면(`$1F` bit5) 화면은 앞 단계의 벌입니다. 그때는 `$7710` 의 다른 벌로 그립니다.

```sh
WAIT=100 TAIL=10 sh fc/dq4/tools/dq4warp.sh work/g04 04/00 17 0A 0     # 성문 앞, 위를 봄
d=$PWD/work/gv/04; for f in $(seq 112 3 250); do mkdir -p $d/$(printf f%05d $f); done
DRIVER=$LIBDIR/seq.lua STATE=$PWD/work/g04/warp.mss SEQ="wait:30,a:4,wait:30,down:3,wait:8,down:3,wait:8,down:3,wait:8,a:4,wait:400" \
  TAIL=10 EVERY=0 AT=$(seq 112 3 250 | paste -sd, -) SHOT_DIR=$d \
  "$MESENCE" --testrunner --nes.ramPowerOnState=AllZeros --nes.disableSprites=true --nes.forceBackgroundFirstColumn=true \
  $PWD/rom/dq4.nes $PWD/fc/dq4/tools/lua/fcgfxgate.lua               # 「とびら」 = 명령 창 아래로 세 번
uv run --locked python fc/dq4/tools/dq4fcgfx.py rom/dq4.nes verify $d/f*/
```

## ルーラ 목적지 1C~1F 와 배·열기구 자리

`1E:$AE19`(목적지 → 레코드 `1E:$AF00` + 7 × 번호, [dq4-field-format.md](dq4-field-format.md#ルーラ-목적지))로 들어오는 길은 `1E:$AD92`(함수 `1E[24]`/`[25]`, `$AEEE` 로 ルーラ 금지 맵을 거른 뒤)와 `1E:$ADED`(함수 `1E[2C]`) 둘입니다. A 가 `FE`·`FF` 가 아니면 `$AE21`(`BRK 47 73` = `10:$9513`)이 목록 순번을 레코드 번호로 바꿉니다.

| 부르는 곳 | 무엇 | 근거 |
| --- | --- | --- |
| `12:$A6C8` | 필드 주문 ルーラ | 코드 읽기 |
| `12:$AFC6` | キメラのつばさ | 실측: 순번 `00` → 레코드 `03`, 필드 0 (A4,2F), `$6195`~`$6198` = `9D 21 A3 2C` |
| `12:$B15E`/`$B165` | そらとぶくつ: `FF` → `1F`(필드 0 (88,16)), 성공하면 이어서 `FE` → `1E`(맵 `30/00` (09,0C)) | 실측. `$6195`~`$6198` = `FF` |
| `11:$AFD0` | 전투 중 ルーラ(`11:$AF9D`), 가 본 마을 중 난수(`$75`) | 코드 읽기 |

목록 순번 → 레코드 표(`10:$9612`)의 값은 `1B` 까지라 제품판은 `1C`·`1D` 를 넘기지 않습니다. 디버그 목록(`10:$951E`, `$C000` bit4 = 0)에서 순번을 고정하면 `1C` → 필드 3 (19,20), `1D` → 필드 1 (0E,0F) 로 갔습니다([fc/dq4/tools/lua/fcgfxrula.lua](../tools/lua/fcgfxrula.lua), `ROMPATCH="3C000=EF;7C000=EF" PICK=1C`). 그래서 `1E` 와 `1F` 는 そらとぶくつ 전용이고 `1C`·`1D` 는 쓰이지 않는 레코드입니다.

`$6195`/`$6196` 은 배, `$6197`/`$6198` 은 열기구 자리입니다. 도착하면 `1E:$9768` 이 `$628E` bit0(배)·bit1(열기구)이 꺼진 쪽을 `00` 으로 지웁니다. `$628E` = `03` 으로 필드 0 (67,66)에 내리면 (67,67)에 배, (66,64)에 열기구가 보였고, `01`·`02` 면 각각 하나만 보였습니다. 배를 타면(`$0515` = 1) `1E:$92D5` 가 `$42`/`$43` 을 옮겨 써 배 자리가 일행을 따라갑니다.

## 남은 것

- 맵의 밤 팔레트는 4곳만 화면으로 확인.
- 줄 스크롤 렌더링은 보이는 줄의 `$2000`·`$2006` 쓰기를 다루지 않음(로그에 있으면 멈춤). 엔딩 바다 장면에는 없었음.
- `near`·그 `link` 24개 그룹의 진짜 이름. 롬 글자에는 고유 이름도, 그 그룹을 방위로 가리키는 대사도 더 없어(위) 원작 밖 자료(NDS `DEBUG/fieldsymbol.dat` 의 지명과 필드 자리 대조 등)가 필요함. 맵 종류로 `33` 은 탑, `37` 은 동굴과 같은 블록을 씀. `0461` 「てんくうのとう」를 내는 그룹.
- 필드 0↔1 전환 때 배 자리를 `$62E5`/`$62E6` 에 맡기는 것(`1E:$9C13`~`$9C51`)과 필드·전투 ルーラ는 코드 읽기만.
