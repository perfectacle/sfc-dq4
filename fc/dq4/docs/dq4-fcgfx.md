# DQ4(FC) 원작 그래픽 렌더링

SFC 로 다시 그릴 때 참고하려고 FC 원작의 마을·던전 맵 279개, 필드, 블록·CHR·폰트 시트, 타이틀·창·전투·장 제목·엔딩 화면을 PNG 로 뽑는 도구 [fc/dq4/tools/dq4fcgfx.py](../tools/dq4fcgfx.py) 의 쓰는 법과, 그리면서 새로 확인한 것(MesenCE 색, 필드 물가 블록, 필드·폭포 팔레트 순환)입니다. 블록·타일·팔레트 해석은 [dq4-block-format.md](dq4-block-format.md), 맵·출구·인물은 [dq4-map-format.md](dq4-map-format.md), 필드는 [dq4-field-format.md](dq4-field-format.md) 를 따릅니다. 실험 과정은 [2026-10-25-30 일지](../journal/2026-10-25-30-fcgfx.md) 와 [2026-10-25-41 일지](../journal/2026-10-25-41-fcgfx2.md) 에 있습니다.

뽑은 그림은 롬 그래픽이라 이 저장소에 커밋하지 않습니다. 비공개 저장소 `perfectacle/sfc-dq4-assets` 의 `fc/dq4/` 아래에 그 저장소의 「폴더·파일 규칙」(1배, `<번호>-<이름>-<변형>.png`)대로 두고, 폴더마다 `SOURCE.txt` 세 줄(커밋·명령·롬 SHA-1)을 적습니다. 확대는 갤러리가 `image-rendering: pixelated` 로 합니다.

## 출력

```sh
uv run --locked python fc/dq4/tools/dq4fcgfx.py rom/dq4.nes all OUT          # OUT/{maps,field,gfx,gallery}
uv run --locked python fc/dq4/tools/dq4fcgfx.py rom/dq4.nes scenes OUT SPEC.json   # MesenCE 덤프 장면 → OUT/gfx/screens(있는 목록에 더함)
uv run --locked python fc/dq4/tools/dq4fcgfx.py rom/dq4.nes gallery OUT      # 장면을 넣은 뒤 갤러리만 다시
uv run --locked python fc/dq4/tools/dq4fcgfx.py rom/dq4.nes map 02 01 work/x.png [--night|--annot]
```

맵 목록은 `dq4chest.all_maps`(279개)입니다. `dq4map.maps` 는 마지막 그룹 `48`(맵 10개, 맵 종류 `1B`·`1C`)을 빼므로, 렌더러는 자기 프로세스 안에서만 `dq4map.load` 를 `dq4chest.load` 로 바꿔 씁니다.

## 색

NES 색 번호 → RGB 는 MesenCE 기본 팔레트를 화면에서 잰 값(`MESEN_RGB`)입니다. [fc/dq4/tools/lua/fcgfxpal.lua](../tools/lua/fcgfxpal.lua) 가 세이브스테이트를 불러 nametable 을 빈 타일로, OAM 을 화면 밖으로 치운 뒤 BG 팔레트 색 0 을 `00`~`3F` 로 바꿔 가며 화면을 찍습니다. MesenCE 화면 덤프는 메모리를 바꾼 프레임보다 한 프레임 늦게 바뀌어서, 색마다 4프레임을 두고 마지막에 찍었습니다(처음 한 프레임씩 찍었을 때는 색이 하나씩 밀리고, 한 곳에서는 둘이 겹쳤음).

```sh
export LIBDIR=$(uv run krpatch fc lua)
STATE=$PWD/work/state/dq4-ch1-throne.mss SHOT_DIR=$PWD/work/pal \
  "$MESENCE" --testrunner --nes.ramPowerOnState=AllZeros $PWD/rom/dq4.nes $PWD/fc/dq4/tools/lua/fcgfxpal.lua
```

## 필드의 물가 블록

필드 블록 `00`(물)은 화면에 그릴 때 이웃에 따라 블록 `20`~`2F` 로 바뀝니다(`0F:$D478`). 이것을 빼면 물가가 들어간 화면이 덤프와 어긋납니다.

| 단계 | 루틴 | 내용 |
| --- | --- | --- |
| 정의 올리기 | `08:$851E` → `$80B7` | 필드(`$07` = 0)면 블록 `20`~`2F` 의 2바이트 정의를 포인터 `08:$80C2`(`$8ABB`)부터 차례로 올림. 모양 레코드·타일 올리기는 블록 `00`~`1F` 와 같음 |
| 이웃 보기 | `0F:$D4A8`·`$D4CC` | 왼쪽, 아래, 오른쪽, 위 순서로 필드 칸을 찾아(`0F:$D244`) 블록이 `00`·`16`·`0A` 가 아니면 1 을 밀어 넣음(`ROL`). 결과 + `20` 이 그릴 블록: bit3 왼쪽, bit2 아래, bit1 오른쪽, bit0 위가 땅 |
| 필드 3 | `0F:$D483` | 블록 `01` 은 난수(`0F:$C891`)가 `FA` 미만이면 `18`, 아니면 `19`. 그림에는 `18` 을 씀 |

블록 `20` 은 물 그대로, `21` 은 위 두 타일이 물가 타일(`0C:$8030`·`$8010`)입니다. 필드 덤프의 `$7600`+4×블록(`20`~`2F`)과 위 정의로 만든 타일 그림이 같았습니다(필드 0·1·3).

`0F:$D2AA` 는 좌표에서 3 을 뺀 값이 폭·높이를 넘을 때만 0 을 돌려주므로, 가장자리 칸의 이웃은 폭·높이 +2 칸까지 원래 줄 데이터를 읽습니다. `dq4field.decode` 가 이 범위(줄 0 ~ 높이+2, 칸 0 ~ 폭+2)를 게임과 같이 풀어 두므로 렌더러는 따로 풀지 않습니다.

## 팔레트 순환

`1D:$8B1E`(뱅크 1D 함수 0)가 프레임마다 불려 `$3C`(프레임 수)&0F 가 홀수인 프레임에 `$8B4A` 를 부릅니다. 맵 종류(`$28`)가 `00`(필드)·`18`(폭포) 이면 BG 팔레트를 돌리고, 그 밖은 애니메이션 목록(`$8C52`, [dq4-block-format.md](dq4-block-format.md))으로 갑니다. 타일 그림·nametable 은 바뀌지 않습니다(`3B/00` 에서 PPU 쓰기는 `$3F00` 대 팔레트뿐).

| 맵 | 주기 | 바꾸는 것 |
| --- | --- | --- |
| 필드 전부 | 16프레임(`$3C`&0F = 0F) | 팔레트 0 의 색 2·3(`$05FE`·`$05FF`, 물결)을 맞바꿈(`$8B54`) |
| 필드 3 | 16프레임 | 팔레트 3 의 색 1~3(`$0606`~`$0608`, 용암)을 `$0606`←`$0608`, `$0608`←`$0607`, `$0607`←`$0606`(`$8B87`). PPU 에는 `$3F0D`~`$3F0F` 에 `$0606`, `$0608`, `$0607` 순서로 써서 한 번이라도 돈 뒤에는 화면 색 순서가 RAM 과 다름 |
| 맵 종류 `18`(`3B/00` 폭포) | 4프레임(`$3C`&3 = 3) | 팔레트 2 의 색 1~3(`$0603`~`$0605`)을 `$0605`←`$0604`←`$0603`←`$0605` 로 돌림(`$8C18`, 폭포가 흐르는 것). `$3F07` 에 `11` 을 함께 씀 |
| 맵 종류 `18` | 16프레임 | 팔레트 1 의 색 1·2(`$0600`·`$0601`)를 맞바꿈(`$8BF3`) |

`$3E` 가 0 이 아니고 걷기 상태 `$0584` 가 2 이상이면 돌리지 않습니다(`$8B1E`). 그림 파일은 롬의 첫 팔레트(돌리기 전)로 그립니다. `verify` 는 이 순환을 6단계로 돌려 보고 가장 잘 맞는 단계를 씁니다. 필드 3 의 블록 `01` 은 칸을 그릴 때마다 난수로 `18`·`19`(반짝임)가 갈리므로(`0F:$D483`) 둘 중 하나와 같으면 같은 것으로 셉니다.

## 확인

롬만으로 그린 화면과 MesenCE 화면 덤프를 256×240 전체 픽셀로 비교합니다. 렌더러는 RAM 의 장소(`$63`/`$64`/`$65`)·화면 왼쪽 위 칸(`$7C`/`$7B`)·스크롤(`$0505` bit0, `$0508`, `$0509`)·구역(`$7140`)·`$07BA`·시각(`$62ED`)만 읽고 나머지는 롬에서 그립니다. 덤프는 MesenCE 에 `--nes.disableSprites=true --nes.forceBackgroundFirstColumn=true` 를 줘 스프라이트를 끄고 왼쪽 8픽셀도 BG 를 보이게 해서 뜹니다.

```sh
# 워프로 맵에 들어간 상태를 만들고, 그 상태에서 스프라이트를 끈 화면을 덤프
WAIT=100 TAIL=10 sh fc/dq4/tools/dq4warp.sh work/w/0E-00 0E/00
DRIVER=$LIBDIR/seq.lua STATE=$PWD/work/w/0E-00/warp.mss SEQ="wait:2" TAIL=3 EVERY=0 SHOT_DIR=$PWD/work/v/0E-00 \
  "$MESENCE" --testrunner --nes.ramPowerOnState=AllZeros --nes.disableSprites=true --nes.forceBackgroundFirstColumn=true \
  $PWD/rom/dq4.nes $LIBDIR/seq.lua
uv run --locked python fc/dq4/tools/dq4fcgfx.py rom/dq4.nes verify work/v/*/
```

| 덤프 | 결과 |
| --- | --- |
| 맵 종류 50가지마다 맵 하나(워프, 도착 60프레임 뒤) | 50가지 모두 61440 픽셀 같음. `2B` 는 `30/00` 이 들어오자마자 대화 창을 띄워 `33/01` 로 |
| `3B/00`(폭포) 도착 2·6·10·14·22·30프레임 뒤 | 모두 0 다름(팔레트 0~4단계) |
| `04/07`(투기장) (0F,0B) 도착 60·150프레임 뒤 | 0 다름(관중 애니메이션 블록 뺌). 도착하면 주인공이 (0F,09)까지 걸어 올라가 그동안은 화면이 스크롤 중 |
| `02/00` | 워프로 들어가면 성문 연출이 화면을 옮겨 RAM 의 화면 자리와 다름. (0F,20) 에 바로 내리면 0 다름 |
| 밤(`SET="62ED=90"`): `02/00`·`0E/00`·`12/00`·필드 0 | 모두 0 다름 |
| 필드 0 (A4,30)·(06,06)·(F8,F8)·(F9,10), 필드 1 (20,1D)·(05,05)·(3C,3C) | 모두 0 다름. 물결 팔레트가 1단계인 덤프가 넷 |
| 필드 3 (23,2B) 도착 2·18·34·50·66프레임 뒤, (05,05) | 모두 0 다름(용암 팔레트 1~3단계, 반짝임 블록 포함) |
| 필드 3 (3A,32) | 8344 다름. 화면이 줄 데이터 밖(X ≥ 40, Y ≥ 36)을 보여 줌. Y ≥ 36 은 줄 레코드가 RAM 을 가리키고, X = 40 은 화면 줄을 세 칸씩 읽는 `$D27F` 의 이어 읽기 값([dq4-field-format.md](dq4-field-format.md#좌표--타일)) |

화면을 그릴 때 화면 왼쪽 위 칸의 블록은 nametable 의 (`$0508`/16×2, `$0509`/16×2) 에 놓습니다. 스크롤 중(16의 배수가 아닌 스크롤)에도 블록 자리는 16픽셀 격자에 붙어 있습니다.

장면 화면(`scenes`)은 [fc/dq4/tools/lua/fcgfxscene.lua](../tools/lua/fcgfxscene.lua) 로 뜬 nametable·CHR·팔레트 덤프를 그린 것이고 롬에서 직접 푼 것이 아닙니다. 화면과 견주면 제작진 화면·IV 로고·모험의 서 창·이름 입력·전투 두 장면은 스프라이트 자리를 빼고 0 다름, 타이틀은 IV 글자(스프라이트)와 아래 물결이 다르고, 필드의 상태 창·명령 창 장면은 걷는 인물(스프라이트가 OAM 덤프 자리와 달라 다 가려지지 않음)과 게임이 BG 를 가리는 왼쪽 8픽셀만 다릅니다(장면 덤프는 `forceBackgroundFirstColumn` 없이 떴음). 장면 목록은 `[{"name", "title", "prefix"}]` 꼴 JSON 이고 `prefix` 는 덤프 파일 앞부분(`work/scene/boot/f02440`)입니다.

```sh
# 전원을 켜서 2440프레임(타이틀)까지. 세이브스테이트에서는 DRIVER=$LIBDIR/seq.lua 와 STATE, SEQ 를 주고 이 Lua 를 그대로
SHOT_DIR=$PWD/work/scene/boot MAXF=2500 EVERY=0 AT=760,1040,2440 SRAM_DRIVER=$PWD/fc/dq4/tools/lua/fcgfxscene.lua \
  "$MESENCE" --testrunner --nes.ramPowerOnState=AllZeros $PWD/rom/dq4.nes $PWD/fc/dq4/tools/lua/debugsram.lua
```

장 끝·장 제목·엔딩 장면도 같은 방법으로 떴습니다. 장 끝은 [dq4-save-format.md](dq4-save-format.md#장-끝)의 조건 플래그를 `SET` 으로 써 넣고 그 맵으로 워프한 뒤 60프레임마다 A 를 눌러 메시지를 넘기며 60프레임마다 덤프했고, 엔딩은 2장 시작 세이브스테이트에서 `$615A`=`04`, `$6282`=`F0`, `$62A1`=`20` 을 쓰고 `2D/00` (0C,07)로 워프해 1만 프레임씩 네 번 이어 200프레임마다 덤프했습니다.

```sh
STATE=$PWD/work/state/dq4-ch2-start.mss SET="615A=03;6282=E0;628A=10" WAIT=60 TAIL=10 \
  sh fc/dq4/tools/dq4warp.sh work/ce4 04/00 0B 1C          # 4장 끝 조건 + 워프
DRIVER=$LIBDIR/seq.lua STATE=$PWD/work/ce4/warp.mss SEQ="wait:56,a:4,…" TAIL=1300 AT=60,120,… EVERY=0 SHOT_DIR=$PWD/work/ce4s \
  "$MESENCE" --testrunner --nes.ramPowerOnState=AllZeros $PWD/rom/dq4.nes $PWD/fc/dq4/tools/lua/fcgfxscene.lua
```

| 1~4장 끝(제목 상자 + 「完」), 2~5장 제목 | 장 끝 워프 뒤 120~1320프레임 | 모두 0 |

| 엔딩 마지막 「The End」 | 35000프레임 | 0 |

장 제목 상자의 BG 타일은 plane 0 이 `1A:$8CA8` + 8×타일 번호의 1비트 그림과 같았습니다(다섯 장면에서 쓰인 타일 49~57개 모두). 제목의 한자도 여기 있습니다. 엔딩의 들판·마을 장면은 맵 그림과 같은 롬 화면이라 따로 두지 않았습니다.

폰트 141자(`18:$B840`)는 이름 입력·모험의 서·전투·5장 명령 창의 CHR 덤프(`$1000`+글자×16 앞 8바이트, 뒤 8바이트 0)와 모두 같았습니다. 전투 화면 BG 는 검은 바탕에 창뿐이라 따로 그린 전투 배경은 없습니다.

## 남은 것

- 성문 연출(`02/00`)이 화면을 옮기는 변수.
- 맵의 밤 팔레트는 4곳만 화면으로 확인.
- 엔딩 바다 장면의 물결(화면 아래)이 덤프 nametable 과 다른 까닭(줄마다 스크롤을 바꾸는 것으로 보임).
- 장 제목 상자 타일의 plane 1 이 만들어지는 규칙, 1장 제목 화면(새로 시작할 때) 덤프.
- 이름이 안 붙은 그룹 30개. 대사에 장소를 가리키는 말이 없고 ルーラ 목적지도 아님(탑·동굴·성 안쪽 층 등).
