# DQ4(FC) 필드(세계 지도)

필드의 타일 배치와 필드로 가는 목적지 표입니다. 디코더는 [fc/dq4/tools/dq4field.py](../tools/dq4field.py), 실험 과정은 [2026-10-25-05 일지](../journal/2026-10-25-05-field.md) 와 [2026-10-25-41 일지](../journal/2026-10-25-41-fcgfx2.md) 에 있습니다. 필드에 있을 때 맵 종류 `$0028` 은 `00` 입니다([dq4-ram-format.md](dq4-ram-format.md#필드-상태)).

## 필드

RAM `$65` 가 필드 번호입니다. 폭·높이는 `0F:$D2D6`·`$D2D9` 에서 `$65` 로 바로 찾습니다(`$D2BC`·`$D2C3`). `$65` 에 쓰이는 값은 0·1·3 뿐입니다. 쓰는 곳은 도착 레코드(`08:$AF96`, bit6-5)와 ルーラ 레코드(`1E:$AE59`, bit1-0)의 표, 그리고 0·1 을 넣는 상수 쓰기(`12:$B8BD`, `1A:$9DCF`, `1C:$BB82`·`$BCC5`, `1E:$9C3B`·`$9C53`·`$A713`·`$A736`)입니다(코드 읽기). 표에는 2 가 없습니다.

| `$65` | 폭×높이 자리 | 줄 데이터 | 내용 | 입구 |
| --- | --- | --- | --- | --- |
| 0 | 250×250 | 253×253 | 세계 지도 | 59 |
| 1 | 61×61 | 64×64 | ゴットサイド 가 있는 섬(ルーラ 목적지 `18`) | 4 |
| 2 | 42×54 | 없음 | 쓰이지 않음. 줄 레코드 표 포인터 `0B:$8004` = `$BE22` 의 첫 줄이 `$FAA5`(고정 뱅크), 둘째 줄이 `$39DD`(PPU 레지스터 거울)를 가리킴 | 0 |
| 3 | (250×164) | 62×54 | 闇の世界(きぼうのほこら, ルーラ 목적지 `1B`). 폭·높이 자리 `$D2D9`·`$D2DC` 는 필드 0 의 높이와 다음 루틴의 코드 바이트(`FA`·`A4`)라 범위 검사가 거의 없음(아래) | 11 |

폭·높이 표는 `$D2D6`·`$D2D9` 에 3바이트씩(필드 0~2)뿐이고, `$D2BC`·`$D2C3` 은 `$65` 로 그대로 찾으므로 필드 3 은 표 다음 바이트를 읽습니다. 그래서 필드 3 의 범위 검사(250×164)는 데이터(62×54) 가장자리에서 걸리지 않습니다. 표를 세 칸으로 만든 뒤 필드 3 을 더하면서 표를 늘리지 않은 것으로 보이나(코드 읽기), 뜻했는지와 걸어서 데이터 밖으로 나갈 수 있는지는 확인하지 않았습니다.

「줄 데이터」는 줄 포인터가 앞 줄 바로 뒤를 잇는 줄 수와, 그 줄들이 제 바이트로 푸는 칸 수입니다(`fc/dq4/tools/dq4field.py` 의 `extent`). 필드 0·1 은 폭·높이 +3 과 같고, 필드 3 은 줄마다 정확히 62칸, 54줄입니다. 필드 3 의 줄 레코드는 X=80·줄 끝 기준점이 모두 `02` 라 X 가 40 이상인 칸은 의미 있는 값이 아닙니다. 섬이 X `0F`~`2F` 에 있어 화면이 거기까지 가지 않습니다.

## 필드 3 갈래

`$65` 를 3 과 견주는 곳은 롬에 11곳입니다(`A5 65 C9 03`·`A6 65 E0 03`·`A4 65 C0 03` 꼴을 찾음). 그림·팔레트 쪽은 [dq4-block-format.md](dq4-block-format.md#필드-3) 에 실측을 적었습니다.

| 곳 | 하는 일 | 근거 |
| --- | --- | --- |
| `08:$8A34` | 블록 01 속성 `80`, 14 를 `00` 으로 | 실측(덤프의 `$6F40`) |
| `0F:$D487`·`$EBD9`·`$ED5C` | 블록 01 을 난수로 블록 18(대부분)·19 로 그림 | 실측 |
| `1E:$A260`·`$A2AE` | 필드 팔레트를 시각과 상관없이 8번 묶음으로 | 실측 |
| `1D:$8B87` | 팔레트 3 의 색 1~3 을 16프레임마다 돌림 | 실측 |
| `1D:$8D26` | 2프레임마다 스프라이트 타일 4개를 두 그림으로 번갈아 씀 | 실측 |
| `0E:$BB5A` | 필드 3 에서 들어간 맵은 밤 팔레트 | 실측(`26/00`) |
| `1E:$938D` | 필드로 나올 때 인물 슬롯 `0A`~`11` 에 보이지 않는 막이를 둠(아래) | 실측(덤프) |

| `12:$A728` | 낮밤 바꾸기를 막음(C = 1). 같은 루틴이 `$62A1` bit5, `$6288` bit7, `$41` bit7 이고 그룹 `0D`·`09`·`0B`·`46`·`2D`·`08` 일 때도 C = 1. 부르는 곳은 ラナルータ(주문 `38`, `12:$A75C`)와 やみのランプ(아이템 `67`, `12:$B42A`) 둘(아래) | 실측 |

막이: `1E:$9396` 이 슬롯 `0A`~`11` 의 X(`$6F6A`, 같은 값을 `$6FAA` 에도)를 22·25·23·24·23·24·23·24 로 둡니다. Y(`$6F8A`·`$6FCA`)는 [결계](dq4-story-format.md) 수호자를 이긴 수, 곧 `$62A4` 위 4비트 가운데 켜진 수 n 에 따라 `$93CF`~ 가 씁니다. 쓰지 않은 칸은 `FF` 로 남아 화면 밖입니다. 아래 4비트는 보지 않습니다.

| n(`$62A4`) | 슬롯 `0A`·`0B` (22,·)(25,·) | `0C`·`0D` (23,·)(24,·) | `0E`·`0F` | `10`·`11` |
| --- | --- | --- | --- | --- |
| 0(`00`, `0F`) | 20 | 20 | 1F | 1E |
| 1(`10`) | 20 | 20 | 1F | FF |
| 2(`30`) | 20 | 20 | FF | FF |
| 3(`70`) | FF | 20 | FF | FF |
| 4(`F0`) | FF | FF | FF | FF |

1장 왕좌의 방에서 `SET="62A4=…"` 으로 필드 3 (23,2C)에 워프한 덤프의 값입니다. 걸음을 막는 것은 `0F:$CFDE` 가 보는 슬롯 `0A`~`0D` 뿐입니다. (23,22)에서 위로 120프레임 걸으니 `00` 에서는 (23,21)에서 멈췄고 `F0` 에서는 (23,1F)의 `45/00` 입구로 들어갔습니다. (23,1F)·(23,1C)·(24,1C) 는 `45/00`, (23,19)·(24,19) 는 `43/00` 의 입구입니다. (23,21)에 선 화면의 OAM 에서 슬롯 `0A`~`0D` 는 타일 `AE`~`B1`(팔레트 3)의 16×16 스프라이트 넷으로, `0E`~`11` 은 타일 `B2`(팔레트 1)로 그려졌습니다. 화면의 반짝임이 이 스프라이트이고, `$7500` 의 타일 번호 `AE`(`1D:$8D26` 이 2프레임마다 그림을 바꾸는 것, [dq4-block-format.md](dq4-block-format.md#필드-3))가 바로 이 막이의 그림입니다. 막이 칸 앞에서 はなす 를 하면 「そのほうこうには だれもいない。」 입니다.

`12:$A728` 실측: 1장 왕좌의 방에서 워프한 뒤 ライアン 의 첫 소지품을 やみのランプ 로 두고 낮(`$62ED` = `00`)에 썼습니다. やみのランプ 쪽(`12:$B42A`)은 `$A728` 이 C = 0 이면, 맵 안이고 `$07BA` 가 4·5 일 때 「しかし ここでは なにも おこらなかった！」(004B, `$B45D`), `$62ED` ≥ `78`(이미 밤)이거나 C = 1 이면 「しかし なにも おこらなかった。」(02C5, `$B457`), 나머지는 `$A77A` 의 `BRK 04 AF`(`1A:$96A7`)로 밤이 됩니다(두 실행 모두 끝에 `$62ED` = `8C`).

| 자리 | `$41` | `$07BA` | 지난 곳 |
| --- | --- | --- | --- |
| 필드 0 (A4,30) | `00` | | `$B452` → `$A77A` |
| 필드 0, `$62ED` = `80` | `00` | | `$B457` |
| 필드 3 (23,2C) | `00` | | `$B457`(`$65` = 3) |
| `02/00` | `80` | `00` | `$B452` → `$A77A` |
| `0D/00` | `80` | `01` | `$B457`(그룹 `0D`) |

| `35/00` | `80` | `05` | `$B45D` |

`15:$B110` 실측: `45/00` (23,1E)에 워프해 위의 인물에게 말을 거니 `15:$993F` → `$B10E` → `$B110` 을 지났고, 도착 뒤 `$65` 를 `03` 으로 바꾼 실행은 `$B116`(`RTS`), `00` 인 실행은 `$B117` 로 갔습니다. 맵 안에서도 `$65` 는 들어오기 전 필드 번호를 그대로 두므로, 필드 3 에서 들어간 맵(`43`·`45` 등)의 인물이 이 갈래를 탈 것으로 봅니다(코드 읽기).

## 좌표 → 타일

`0F:$D244`(뱅크 0B 를 끼우고 `$D259`)가 X·Y 레지스터의 좌표로 타일 번호(0~31)를 돌려줍니다.

1. X−3 이나 Y−3 이 폭·높이 이상이면 0(`$D2AA`). 아니면 원래 좌표 그대로 찾는다. 그래서 게임이 찾는 칸은 X·Y 가 3 ~ 폭·높이+2 이고 0~2 는 늘 0 이다.
2. 줄 레코드: `0B:$8000 + 필드 × 2` 의 포인터 + Y × 4. 4바이트 = 줄 데이터 포인터, X=80 이 시작되는 바이트 위치, 줄 끝(X=100) 바이트 위치(`$D2DC`). X 가 00~3F 면 바이트 0 부터, 40~BF 는 X=80 기준점, C0~FF 는 줄 끝 기준점부터 읽는다.
3. 줄 데이터는 바이트마다 RLE 입니다(`$D326`). X 의 bit6 이 켜진 40~7F·C0~FF 는 다음 기준점(80, 100)에서 거꾸로 읽습니다(`$D37E`). 칸 위치 셈은 8비트로 돕니다.

| 바이트 | 뜻 |
| --- | --- |
| 위 3비트 0~6 | 그 타일이 (아래 5비트 + 1)칸 |
| 위 3비트 7, 아래 5비트 0~7 | 타일 7 이 (아래 5비트 + 1)칸 |
| 위 3비트 7, 아래 5비트 8~31 | 타일 (아래 5비트) 한 칸 |

`$D516` 은 필드 0 의 (C2, 2E) 를 이벤트 플래그 `$62A1` bit7 이 켜져 있을 때 타일 2 로 바꿉니다(코드 읽기, `$65` 는 보지 않음).

화면에 한 줄을 그릴 때(`0F:$EB9D`)는 `$D27F` 가 X 부터 세 칸을 한 번에 읽습니다. 첫 칸만 `$D2AA` 범위 검사와 기준점 고르기를 하고, 다음 두 칸은 `$D352` 로 그 자리에서 앞으로 이어 읽습니다. 줄 데이터 안에서는 결과가 같지만, 데이터 밖(필드 3 의 X ≥ 40 등)에서는 화면 왼쪽 칸 자리에 따라 값이 달라집니다(필드 3 (3A,32) 화면에서 X=40 칸).

`fc/dq4/tools/dq4field.py` 의 `cell` 이 `$D259` 를 그대로 따르고(롬 밖을 읽으면 None), `decode` 는 줄 0 ~ 높이+2, 칸 0 ~ 폭+2 를 `cell` 로 채운 격자입니다(롬 밖은 0). `lookup` 은 이 격자에 `$D2AA` 범위 검사를 겁니다.

## 필드 → 마을 입구

필드 좌표는 RAM `$42`·`$43` 입니다. 걸음마다 `08:$AEE8` 이 입구 표를 찾습니다.

| 표 | 위치 | 레코드 |
| --- | --- | --- |
| 입구 74개 | `BRK 82 E7`(뱅크 0E 함수 2 의 주소) → `0E:$BE69`, `FF` 끝 | 그룹, 필드 X, 필드 Y |
| 도착 73개 | `08:$B7F7` 의 포인터 → `08:$B7F9`, `FF` 끝 | 그룹, bit6-5 필드 번호(`$65`)·bit4-0 순번(`$64`), X, Y, 방향 |

필드 좌표가 같은 입구가 있으면 그 그룹을 `$63` 에, 같은 그룹의 첫 도착 레코드로 순번·좌표를 정합니다(`$B037`). 그룹 `45`·`18`·`0E` 는 이벤트 플래그로 순번·좌표가 바뀝니다(`$AF15`~`$AF7F`, 코드 읽기).

## ルーラ 목적지

`1E:$AE19` 가 목적지 번호 A 를 받아(`FF`→`1F`, `FE`→`1E`) `1E:$AF00` + 7×번호 의 레코드로 장소를 정합니다(코드 읽기). 번호 `00`~`1B` 는 장소 이름표(`0B:$B634`, ID = 목록 순번 − 1)와 같은 순서입니다. `fc/dq4/tools/dq4field.py places` 가 이 32개를 이름·그룹과 함께 보여 줍니다.

| 바이트 0 | 1 | 2 | 3 | 4 | 5 | 6 |
| --- | --- | --- | --- | --- | --- | --- |
| bit7 꺼짐: bit1-0 → `$65` | `$42` | `$43` | `$6195` | `$6196` | `$6197`(FF 면 그대로) | `$6198` |
| bit7 켜짐: 맵 | `$44` | `$45` | `$63` | `$64` | | |

`$6197`/`$6198` 은 열기구 자리입니다([dq4-save-format.md](dq4-save-format.md#5장-끝과-엔딩)). `$6195`/`$6196` 은 배 자리입니다. 필드로 나올 때 `1E:$932A` 가 이 값을 인물 슬롯 6(`$6F66`/`$6F86`)에 옮겨 배 그림을 놓고, `$628E` bit0(배를 가짐)이 꺼져 있으면 `1E:$9768` 뒤 `$6195`/`$6196` 을 지웁니다. 필드 1 로 갈 때 `1E:$9C51` 이 `$62E5`/`$62E6` 에 맡기고 `80` 으로 두며, 필드 0 으로 돌아올 때 `1E:$9C3D` 가 되돌립니다(코드 읽기). 배를 탄 채 걸으면 `0F:$CCA3` 이 `$42`/`$43` 을 이 자리에 쓰고, 물 칸(`83`)으로 걸으려는 칸이 이 자리면 `0F:$CFD6` 이 `$0527` = 1(타기)로 둡니다(코드 읽기). 실측: 1장 왕좌의 방에서 `SET="628E=01;6195=A631"` 로 필드 0 (A4,30)에 워프하니 슬롯 6 이 (A6,31)이고 그 자리에 배 그림이 보였습니다. `$628E` 를 두지 않으면 같은 워프 뒤 `$6195`/`$6196` 이 `00 00` 이고 배가 없었습니다.

필드 레코드 27개 중 26개는 같은 필드의 입구(위 표) 하나와 1칸, `0C` りバーサイド 는 2칸 떨어져 있어 그룹으로 이을 수 있습니다. 맵 레코드 `01` てんくうじょう 는 `2D/00`, `1E` 는 `30/00` 입니다. 이렇게 이은 이름이 대사(「ここは …」)로 붙인 이름과 둘 다 있는 그룹 20개에서 모두 같았고, 8개 그룹(`05`·`08`·`0C`·`10`·`14`·`16`·`26`·`2D`)은 이 표로만 이름이 붙습니다. `1C`(필드 3 (19,20))·`1D`(필드 1 (0E,0F))는 2칸 안에 입구가 없고 이름도 없습니다.

## 확인

- `fc/dq4/tools/dq4field.py check`: 필드 0·1·3 의 줄 데이터 범위에서, 필드 0 은 앞에서부터 푼 위치가 X=80 기준점·줄 끝 바이트 위치와 표 값이 모두 같음. `cell`(기준점에서 거꾸로 읽기 포함)과 앞에서부터 푼 줄이 필드 0·1·3 의 줄 데이터 안에서 모두 같음.
- 필드 (A3,2E)에서 오른쪽으로 걸어 (A4,2E)에 닿자 `$63`/`$64`/`$44`/`$45` 가 `02`/`00`/`00`/`1D` 가 됨. 입구 표 `02 A4 2E` 와 도착 레코드 `02 00 00 1D 01` 그대로(`fc/dq4/tools/dq4field.py entrances`).
- `fc/dq4/tools/lua/fieldlookup.lua` 로 필드를 걸을 때 게임이 `$D259` 를 부른 147번의 (X, Y, 결과)를 기록해 `fc/dq4/tools/dq4field.py compare` 로 비교: 0 차이. 새 `decode` 로 필드 0 (A4,30)·(F8,F8), 필드 1 (20,1D)·(3C,3C), 필드 3 (23,2B) 에서 걸으며 기록한 269번도 0 차이.
- 필드 가장자리(필드 0 (06,06)·(F8,F8)·(F9,10), 필드 1 (05,05)·(3C,3C), 필드 3 (05,05))로 워프한 화면을 `decode` 로 그린 화면과 견주어 모두 61440 픽셀 같음([dq4-fcgfx.md](dq4-fcgfx.md#확인)). 예전 `decode` 는 줄을 폭에서 잘라 가장자리 +2 칸에서 `IndexError` 가 났다.

## 남은 것

- 타일 번호(0~31) → 통행·조우 지형(블록 속성은 [dq4-block-format.md](dq4-block-format.md)).
- ルーラ 목적지 `1C`·`1D`·`1E`·`1F` 를 쓰는 곳. 배를 타고 내리는 장면(`$0527`)을 실제 물가에서 보기.
- ラナルータ(`12:$A75C`)를 주문으로 써서 やみのランプ 와 같은 갈래인지(코드는 `$62ED` 검사만 없음).
