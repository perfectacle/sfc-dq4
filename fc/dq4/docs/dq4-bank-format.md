# DQ4(FC) 뱅크 호출

FC DQ4 는 다른 PRG 뱅크의 루틴을 `BRK` 명령 뒤에 2바이트를 붙여 부릅니다. 이 문서는 그 형식과 뱅크 배치입니다. 주소 표기와 롬 기본 정보는 [dq4-ram-format.md](dq4-ram-format.md) 를 따릅니다. 디코더는 [fc/dq4/tools/dq4bank.py](../tools/dq4bank.py), 실험 과정은 [2026-10-24-02 일지](../journal/2026-10-24-02-bankcall.md) 와 [2026-10-25-22 일지](../journal/2026-10-25-22-textrest2.md), [2026-10-25-47 일지](../journal/2026-10-25-47-text6.md) 에 있습니다.

## 뱅크 전환과 현재 뱅크

| 주소 | 내용 | 근거 |
| --- | --- | --- |
| `$0507` | 지금 `$8000`~`$BFFF` 에 있는 뱅크(0~`1F`) | `$FF91` 이 씀, 디코더 비교에서 호출 위치의 뱅크로 맞음 |
| `$FF91`(A=뱅크) | `$0507` 에 저장, bit4 를 `$0501` bit4(256KB 절반)에, 아래 4비트를 PRG 뱅크 레지스터에 | 코드 읽기, 쓰기 프로브([dq4-ram-format.md](dq4-ram-format.md#뱅크-전환)) |
| 고정 영역 | `$C000`~`$FFFF` 는 `$0507` 이 `10` 미만이면 뱅크 `0F`, 이상이면 `1F` | `$FF91` 코드 읽기. 디코더가 이 규칙으로 `$C000` 이상 호출 위치를 읽어 기록과 모두 맞음 |
| `$C3EA`(A=뱅크, X=영 페이지 포인터, Y=첨자) | 다른 뱅크의 `(포인터),Y` 한 바이트를 읽고 뱅크를 되돌림 | `probe/reads.lua`: `$C3FD` 가 뱅크 `18` 의 데이터를 읽음 |

## `BRK b1 b2`

IRQ/BRK 벡터가 가리키는 `$C408` 이 처리합니다. 복귀는 `BRK` 다음 셋째 바이트(BRK+3)입니다.

`b2` 의 아래 3비트가 `7` 이면 일반 호출입니다.

| 필드 | 값 |
| --- | --- |
| 대상 뱅크 | `b2 >> 4`, 여기에 `b2` bit3 을 bit4 로(5비트) |
| `b1` bit7 = 0 | 호출. 함수 번호 = `b1` |
| `b1` bit7 = 1 | 호출하지 않고 함수 주소를 꺼냄. 함수 번호 = `b1 & 3F`, 주소는 X 가 가리키는 영 페이지 두 바이트에 |
| 함수 주소 | 대상 뱅크 `$8000 + 함수 번호 × 2` 의 16비트 값 |

예: `0F:$E94B` 의 `00 05 87` 은 뱅크 `08` 함수 `05`, `08:$8000+0A` = `$B6B8` 입니다(맵 번호 `$0550` 을 쓰는 `08:$B708` 은 그 80바이트 뒤).

호출 중에는 A·X·Y 를 `$20`~`$22` 에 두었다가 넘기고, `$0023` 에 `JMP` 명령을 만들어 그리로 `JSR` 합니다. 돌아오면 원래 `$0507` 로 뱅크를 되돌립니다(코드 읽기: `$C38B`).

### 확인

부팅(전원~이름 입력 1500프레임)과 왕좌의 방 → 성 밖 보행(700프레임)에서 `probe/trace.lua` 로 처리기 안 `$C446`·`$C455`(뱅크·함수 번호 확정)와 `$C3CD`(함수 주소 확정)를 기록하고 `fc/dq4/tools/dq4bank.py compare` 로 롬만 읽은 결과와 비교했습니다.

| 장면 | 호출 | 다름 | 호출 위치 |
| --- | --- | --- | --- |
| 부팅 | 371 | 0 | 24 |
| 보행 | 648 | 0 | 43 |

보행 장면의 호출 대상 42곳은 모두 `probe/cover.lua` 에서 실제로 실행됐고, 호출 위치 `1B:$807A` 는 BRK 와 BRK+3 이 실행되고 사이 두 바이트는 실행되지 않았습니다.

## 특수 형식

`b2` 의 아래 4비트가 `3` 이나 `B` 면 일반 호출이 아닙니다(`$C428`). 일반 호출은 아래 3비트를 보지 않지만, 롬의 일반 호출은 모두 아래 3비트가 `7` 입니다.

| `b2` | 하는 일 | 복귀 | 근거 |
| --- | --- | --- | --- |
| `x3` | `b1`·`b2`·셋째 바이트를 `$76`·`$77`·`$78` 에 두고, `n = b2 >> 4` 로 뱅크 `10` 함수 `n`(`0`~`9`), `n + 18`(`A`~`C`), 뱅크 `12` 함수 `n − C`(`D`~`F`) | 불린 함수가 정함(아래) | `$C4F8`. 전투 1000프레임에 779번. 호출 위치 191곳의 복귀 자리 실측 |
| `0B`~`BB` | 메시지 `(b2 >> 4) : b1` 찍기. 뱅크 `16` 함수 `04`(`16:$8028`)를 X=`b2 >> 4`, A=`b1` 로 부름 | BRK+3 | 실측: 전투 끝 `12:$87D1` `09 0B` → `0009`, `12:$8825` `0C 0B` → `000C`, `12:$8886` `C3 1B` → `01C3`, 4장 시작 `1D:$AB7D` `16 3B` → `0316`. 같은 프레임에 `16:$8656` 이 그 번호로 들어감 |
| `CB` | 플래그 켜기: `$627B + b1` 에 셋째 바이트를 OR | BRK+4 | 실측: 장 시작 `1E:$A354` `16 CB 80` → `$6291` `00` → 뒤 검사에서 `80`, `1E:$A399` `0D CB 40` → `$6288` `00` → `40` |
| `DB` | 플래그 끄기: `$627B + b1` 에 셋째 바이트를 AND | BRK+4 | 실측: `1E:$A41B` `0D DB BF`(`$6288` `40` → `00`), `1E:$A3D8` `10 DB 00`, `1E:$A4AC` `07 DB 00`, `08:$B6BD` `1F DB 7F` |
| `EB` | 플래그 검사: `$627B + b1` AND 셋째 바이트의 결과를 Z 로 돌려줌(A·X·Y 는 그대로) | BRK+4 | `$C4B6`. 왕좌의 방 700프레임에 7번 |
| `FB` | 소리 `b1`: 뱅크 `19` 함수 `03` 을 A=`b1` 로 | BRK+3 | `$C46C`. 대사 글자마다 `BRK 96 FB`, 버튼 기다림 뒤 `BRK 85 FB` |

`x3` 형식의 길이는 불린 함수가 복귀 주소를 고쳐 정합니다. 함수는 스택의 BRK 복귀 주소를 `$79/$7A`(뱅크 `10` 함수 `22`~`24` 는 `$84/$85`)에 꺼내고, 읽은 인자 수만큼 Y 를 늘려 다시 씁니다(`10:$809D`·`$80B3`, `10:$AB86`·`$AB99`).

| `b2` | 불리는 함수 | 복귀 | 근거 |
| --- | --- | --- | --- |
| `03` | `10` 함수 `00`(`10:$808A`) | BRK+3 | 실측 1곳 |
| `13` | `10` 함수 `01`(`10:$80C5`, `00` 의 뒤로 이어짐) | BRK+3 | 코드 읽기 |
| `23`, `43`, `63` | `10` 함수 `02`·`04`·`06` | BRK+4(셋째 바이트를 `$6E0A` 에) | 실측 20곳 |
| `33`, `53`, `73` | `10` 함수 `03`·`05`·`07` | BRK+3 | 실측 46곳 |
| `83` | `10` 함수 `08`(`10:$812B`). `93` 과 같은 길로 가되 넷째 바이트를 `$6E0A` 에 더 둠(`10:$8146`) | BRK+5(셋째·넷째 바이트) | 실측 1곳(`10:$BAE1`, 아래). `11:$BC2B` 는 코드 읽기 |
| `93` | `10` 함수 `09`(`10:$812B`) | BRK+4 | 실측 41곳 |
| `A3`, `B3` | `10` 함수 `22`·`23`(`10:$ABAB`, `$ABBF`) | BRK+3 | 실측 29곳 |
| `C3` | `10` 함수 `24`(`10:$ABD3`) | BRK+4(셋째 바이트를 `$7C` 에) | 실측 47곳 |
| `D3` | `12` 함수 `01`(`12:$8157`) | BRK+4 | 실측 6곳 |
| `E3` | `12` 함수 `02`(`12:$8165`) | BRK+3 | 실측 1곳 |
| `F3` | `12` 함수 `03`(`12:$84B3`) | 모름 | 실행 못 봄 |

앞 판에서 「`n` 이 홀수면 BRK+3」 이라 한 규칙은 `93` 에서 틀립니다. 함수 `08`·`09` 는 `$77` 이 `93` 일 때 한 바이트, 아니면 두 바이트를 더 읽습니다. 함수 `22`~`24` 는 `b1` 을 `$6E59` 에 두고 전투 쪽 명령 해석기 `10:$A34D` 로 갑니다. 대사 제어 `F6` 이 부르는 `BRK 29 C3 0C` 가 이 경로로, 명령 `29` 인자 `0C` 가 몬스터 전투 레코드의 비트 하나를 검사합니다([dq4-text-format.md](dq4-text-format.md#제어-바이트)).

`fc/dq4/tools/dq4bank.py rom call 주소` 가 이 형식들도 풉니다(`x3`, `message`, `flag-set`/`flag-clear`/`flag-test`, `sound`). `x3` 는 위 표대로 길이(`len=`)도 찍습니다. `fc/dq4/tools/lua/textbrk.lua` 는 실행 중의 BRK 를 모두 잡아 호출 위치마다 실제 복귀 자리와 메시지·플래그 값을 적습니다.

### `83` 이 도는 장면

`10:$B4D2` 는 몬스터 AI(종류 1~3, [dq4-data-format.md](dq4-data-format.md#ai-종류))가 칸마다 부르는 평가 루틴 표입니다. `10:$B497` 이 행동 ID `$0B` × 2 로 찾으므로 `10:$B52A`·`$B52C` 는 행동 `2C`(べホマラー)·`2D`(べホマズン)이고, 둘 다 `10:$BADB` 입니다. 이 루틴은 `$7300,X`(행동하는 전투원) bit7 이 켜져 있으면(몬스터) `$BAF2` 로, 꺼져 있으면(일행 쪽) `$BAE1` 의 `BRK 6B 83 02 01` 로 전투원마다 조건을 물어 둘 이상이면 SEC 를 돌려줍니다(코드 읽기).

롬의 몬스터 중 이 두 주문을 가진 것은 はしりとかげ(`88`)·スライムべホマズン(`97`)뿐이고 둘 다 AI 종류 0 이라 평가 루틴을 부르지 않습니다. 그래서 1장 첫 전투(`dq4-ch1-battle.mss`)에서 몬스터 행동 칸 `$6D8C`~`$6D97` 을 모두 `28`(→ 행동 `2C`)로 두었습니다. スライム 은 AI 종류 1 이라 `10:$BADB` 가 24번 돌았지만 A = `80` 이라 모두 `$BAF2` 로 갔습니다. `fc/dq4/tools/lua/textx3.lua` 로 `10:$BADB` 에서 A = `00`, P = `06` 으로 바꾸니 `10:$BAE1` 이 26번 실행되고 26번 모두 BRK+5 로 돌아왔습니다(억지로 지나게 한 갈래이고, 일행 쪽에서 이 루틴을 부르는 실제 장면은 남은 것).

## 뱅크 배치

부팅과 보행 두 장면에서 실행된 PRG 오프셋 수(`probe/cover.lua`)입니다.

| 장면 | 실행된 뱅크(오프셋 수) |
| --- | --- |
| 부팅 | `0F` 386, `10` 38, `12` 615, `13` 13, `15` 10, `16` 1632, `18` 31, `19` 3, `1A` 447, `1D` 127, `1E` 48, `1F` 1526 |
| 보행 | `08` 815, `0B` 24, `0E` 79, `0F` 3300, `10` 495, `11` 5, `12` 35, `16` 1335, `18` 94, `19` 31, `1A` 15, `1B` 372, `1C` 455, `1D` 348, `1E` 811, `1F` 1784 |

뱅크 `00`~`07` 은 두 장면에서 한 번도 실행되지 않았습니다. 뱅크 32개가 각각 무엇인지와 빈 자리는 [dq4-rom-map.md](dq4-rom-map.md) 에 있습니다.

바꿔 끼우는 뱅크는 모두 `$BFD8`~`$BFFF` 가 같습니다: `SEI`, `INC $BFDF`(MMC1 리셋), `JMP $FF8E` 와 글자 `" DRAGON QUEST IV"`, 벡터. 전원 직후 어느 뱅크가 `$C000` 쪽에 걸려 있어도 리셋이 고정 뱅크로 이어지게 하는 조각으로 보입니다(코드 읽기).

고정 뱅크 `0F` 와 `1F` 는 `$C03D`~`$E549` 가 같고 `$C002`~`$C03C`, `$E54A`~`$FF09`, `$FFF0`~`$FFF1` 이 다릅니다(6548바이트). 읽기 프로브에서 뱅크 `19`(소리 데이터)를 읽은 코드(`$E771`, `$EE1C`, `$EF81` 등)는 모두 `1F` 의 다른 영역에 있었습니다.

## 남은 것

- `x3` 의 `13`(뱅크 `10` 함수 `01`), `F3`(뱅크 `12` 함수 `03`)을 실행 중에 보지 못함. 롬에서 `00 b1 13` 꼴 64곳·`F3` 22곳은 대부분 데이터 뱅크이고 앞뒤가 코드로 보이는 곳이 없음(코드 읽기).
- `83` 의 둘째 자리 `11:$BC2B`(`BRK 46 83 10 03`): 전투 いれかえ 를 끝내는 `11:$BB91`(`11:$88A2` 가 부름)이 마차에서 들어올 동료 `$7358`(창 `3B` 에서 고름)로 `11:$BBF6` → `$BC02` 를 부르고, 그 동료가 `BRK 46 93 07` 검사에 걸리지 않으면 `$BC21` 로 감(코드 읽기). 5장 필드 전투에서 いれかえ 로 볼 것.

- 뱅크마다 `$8000` 함수 표의 길이와 각 함수의 역할.
- 고정 뱅크 `0F` 만 가진 영역(`$E54A`~`$FF09`)의 역할.
