# DQ4(FC) 상점·여관·보물상자 형식

가게 창에 늘어서는 품목과 장소별 값, 여관 값, 교회·맡기는 곳의 메뉴와 요금, 가게 인물이 고르는 가게 종류, 보물상자와 발밑 숨은 물건(しらべる)의 위치·내용물·열었음 플래그, 그리고 이것들에 タンス·つぼ 와 대화로 받는 물건을 합친 「얻는 물건」 표입니다. 디코더는 [fc/dq4/tools/dq4shop.py](../tools/dq4shop.py)·[fc/dq4/tools/dq4chest.py](../tools/dq4chest.py), 실험 과정은 [2026-10-25-10 일지](../journal/2026-10-25-10-shop.md) 와 [2026-10-25-25 일지](../journal/2026-10-25-25-shop2.md), [2026-10-25-31 일지](../journal/2026-10-25-31-shop3.md) 에 있습니다. 주소 표기는 [dq4-ram-format.md](dq4-ram-format.md), 아이템 ID·이름·가격은 [dq4-data-format.md](dq4-data-format.md), 맵 장소(그룹 `$63`/순번 `$64`)는 [dq4-map-format.md](dq4-map-format.md) 를 따릅니다.

## 대화 값과 가게 종류

인물에게 말을 걸면 `1C:$96C7` 이 인물 레코드에서 대화 번호([dq4-script-format.md](dq4-script-format.md#대화-번호))를 꺼내 `$00:$01` 에 두고, `15:$9962` 가 `$01` = 0 이고 `$00` < 7 이면 메시지 대신 가게 처리 `15:$9CBF` 로 보냅니다. 7 이상은 스크립트(`15:$999E`, 표 `15:$98F6`), `$0161` 이상은 예/아니오 창과 메시지입니다.

| 값 | 처리 | 하는 일 |
| --- | --- | --- |
| 1 | `15:$B84A` | 무기점. `$07C5` = 1 |
| 2 | `15:$B858` | 도구점. `$07C5` = 2 |
| 3 | `15:$B851` | 방어구점. `$07C5` = 3 |
| 4 | `15:$BBF0` | 맡기는 곳(메시지 `0238` 「ここは もちものと おかねの あずかりじょです。」) |
| 0·5 | `15:$B550` | 교회(메시지 `021B`/`021C`, `$62ED` 로 낮·밤) |
| 6 | `15:$BF28` | 여관(메시지 `0231`~`0237`) |

무기·도구·방어구 셋은 가게 창을 열기 전에 `15:$B217` 이 품목을 RAM 에 담습니다.

| RAM | 내용 |
| --- | --- |
| `$07BD`~`$07C4` | 품목 ID(최대 8개, 표에서 bit7 은 지움) |
| `$07C4` | 품목 수(마지막 품목에 bit7 이 있는 줄일 때 씀) |
| `$07C5` | 가게 종류 1~3 |

### 가게 인물

대화 번호는 인물 레코드([dq4-map-format.md](dq4-map-format.md#인물)) 머리 바이트 1 의 bit4-2(위 3비트)와 바이트 4(아래 8비트)입니다([dq4-script-format.md](dq4-script-format.md#대화-번호)). 가게로 가는 길은 셋입니다.

| 길 | 조건 | 줄 수 |
| --- | --- | --- |
| 직접 | 대화 번호 0~6. 바이트 4 가 곧 가게 종류 | 94 |
| 스크립트 | 대화 번호 7 이상의 스크립트([dq4-script-format.md](dq4-script-format.md))에서 문장 `12 n`(서비스 n, `15:$9C63` → `$9CBF`). 앞의 조건(카운터 너머, 낮, 장, 플래그)을 모두 지나야 함 | 21 |
| 호출 | 스크립트의 호출 문장 `00`/`01`(`15:$9C42`)이 아래 루틴을 부름 | 9 |

| 호출 대상 | 하는 일 |
| --- | --- |
| `15:$9D2A` | 주인공 Y(`$45`)가 `16` 이면 인자의 메시지, 아니면 방어구점 `$B851` |
| `15:$ADB7` | 말을 건 인물의 지금 X(`$6F60`+슬롯)가 `1C` 면 교회 `$B550`, `1D` 면 Y(`$6F80`+슬롯)가 `12` 일 때 도구점 `$B858`·아니면 방어구점 `$B851`, 그 밖은 무기점 `$B84A` |
| `15:$B558` | 교회(인사말 다음부터) |
| `15:$B847` | 무기점(`$B84D`, 인사 창 없이) |
| `15:$BF30` | 여관(인사말 다음부터) |
| `15:$A6B0` | 값을 묻지 않고 재움(무료 숙박) |

스크립트의 호출 대상 100곳을 정적으로 따라가(분기 양쪽, `JMP`·`JSR` 따라감) 가게 입구(`$B550`·`$B84A`·`$B851`·`$B858`·`$BBF0`·`$BF28`·`$9CBF`)에 닿는 것은 `$9D2A`·`$ADB7` 둘이었고, 나머지 넷은 가게 루틴 안을 바로 가리킵니다.

`dq4shop.py people` 이 맵 279곳(아래 「보물상자」의 그룹 `48` 포함)의 인물 레코드를 모두 풀어 이 표를 냅니다. 레코드마다 낮 모습(`F` bit4)과 밤 모습(`F` bit3)을 따로 풉니다. 밤에는 대화 번호와 자리가 덧붙은 바이트에서 올 수 있습니다(`dq4talk.talk_id`·`pos` 의 `night`). 두 모습이 같으면 한 줄, 다르면 「낮」·「밤」 표시를 붙이고, 밤 모습인데 스크립트가 낮 갈래로만 가게를 여는 것처럼 어긋나는 길은 뺍니다. 이벤트 플래그로 통째로 바뀌는 인물 목록(`1C:$9D0E`, [dq4-script-format.md](dq4-script-format.md))도 돌아 「목록 플래그 n&m」 을 붙입니다.

기본 목록에서 가게로 가는 길은 124줄(인물 118명)이고, 종류별로 여관 33, 교회 25, 방어구 21, 도구 21, 무기 20, 맡기는 곳 2, 무료 숙박 2 입니다. 바뀌는 목록까지 넣으면 176줄, 맵 41곳입니다. 한 인물이 조건에 따라 두 길을 가지면 줄이 둘입니다.

```sh
uv run python fc/dq4/tools/dq4shop.py rom/dq4.nes people
02/00 (1F,16) 대화 00D 호출 15:9D2A [counter & 주인공 Y($45) ≠ 16] → 방어구: かわのよろい くさりかたびら …
1B/00 (1C,13) 대화 12D 호출 15:ADB7 [인물 자리 (1C,13)] → 교회: 저장·おつげ·되살리기·해독·저주
19/00 (16,0C) 대화 0EE 스크립트 [counter] → 도구: やくそう どくけしそう まんげつそう においぶくろ
```

직접 가는 인물 가운데 아래 10명은 앞 일지에서 말을 걸어 값(`15:$9962` 에서 본 `$00`)이나 열린 가게가 바이트 4 와 같았습니다. 스크립트·호출로 가는 인물의 확인은 아래 「확인」에 있습니다.

| 맵 | 인물 칸 | 바이트 4 | 확인 |
| --- | --- | --- | --- |
| `02/00` | (0D,16) | `01` | `$00`=`01`, 무기점 창 |
| `02/00` | (18,15) | `02` | `$00`=`02`, 도구점 창 |
| `02/00` | (05,14) | `05` | `$00`=`05` |
| `02/00` | (15,21) | `06` | `$00`=`06`, 「ひとばん 4ゴールドですが」 |
| `12/00` | (0F,03) | `01` | 무기점 창 |
| `04/00` | (22,11) | `02` | 도구점 창 |
| `13/00` | (24,04) | `01` | 무기점 창 |
| `0C/00` | (16,05) | `03` | 방어구점 창 |
| `13/00` | (06,17) | `06` | 「ひとばん 2ゴールドですが」 |
| `0C/00` | (1B,0E) | `06` | 「ひとばん 6ゴールドですが」 |

`1B/00` 의 `$ADB7` 인물은 레코드 자리 (1C,13) 에서는 교회입니다. 인물 표에서 이 인물의 자리를 바꾸어 말을 걸면 종류가 바뀌었습니다(아래 「확인」).

### 들어갈 때 숨는 인물

레코드에 있어도 맵에 들어가자마자 숨는 인물이 있습니다. 인물 표를 채운 뒤 `1C:$A010` 이 표 `1C:$ABF5`(그룹, 순번 2바이트 줄, 첫 바이트 bit7 로 끝)에서 지금 장소를 찾고, 같은 자리의 포인터 `1C:$AC8A` 로 뜁니다. 그 장소의 루틴이 장·플래그·시간을 보고 `1C:$A035` 로 슬롯의 `$6F66`·`$6F86`·`$6FA6`·`$6FC6`(+슬롯 − 6)을 `80` 으로 써서 인물을 치웁니다. 1장 세이브스테이트에서 `17/00` 으로 워프하면 프레임 87 에 `1C:$A037` 이 슬롯 8 의 X 를 `80` 으로 썼고, `16/00` 에서는 슬롯 8·9·13·15 가 (80,80) 이었습니다. 장소마다 루틴이 무엇을 보는지는 풀지 않았습니다.

워프한 뒤(`warp.lua` 의 `AFTER`) 숨은 슬롯의 자리 네 바이트를 레코드 자리로 되돌리고 `talk.lua` 의 `SLOT` 으로 말을 걸었습니다.

| 인물 | 조작 | 결과 |
| --- | --- | --- |
| `16/00` (17,03) 대화 `055` | `$615A`=`04`(5장), 자리를 되돌리고 (17,04) 에서 | 조건 둘 참, 서비스 `01`, `$07BD` = `01 02 09` 로 표와 같음 |
| `16/00` (02,1A) 대화 `054` | 자리를 되돌리고 (02,1B) 에서 | `$6285` bit0 꺼짐·카운터 아님 → 메시지 `0326` 「まっていたぜ。 はたらきに　きたんだろう？」, 「はい」 면 `15:$A068`(일하기) |
| `17/00` (07,17) 대화 `0DA` | 자리를 되돌리고 (07,18) 에서 | 메시지 `099D`(「たびの　しょうにんです」) 뒤 무기점, `$07BD` = `06 23 07 2A 33 49` 로 표와 같음 |

## 무기·도구·방어구 목록

`15:$B222` 가 `$07C5` 로 18:`$802C` + 2 × (종류 − 1) 의 포인터를 꺼냅니다.

| 종류 | 포인터 | 목록 시작 |
| --- | --- | --- |
| 1 무기 | `18:$802C` | `18:$B418` |
| 3 방어구 | `18:$8030` | `18:$B49A` |
| 2 도구 | `18:$802E` | `18:$B530` |

세 목록은 무기 → 방어구 → 도구 순으로 이어 붙어 있고, 줄 하나는 이렇습니다.

| 바이트 | 뜻 |
| --- | --- |
| 0 | 그룹 `$63`. `FF` 면 어느 장소에나 맞는 줄이고 순번 바이트가 없음 |
| 1 | 순번 `$64` |
| 2~ | 품목 ID. 마지막 품목은 bit7 이 켜짐 |

`15:$B2CB` 는 줄을 차례로 읽어 (그룹, 순번)이 지금 장소와 같거나 그룹이 `FF` 인 첫 줄을 고릅니다. 맞지 않는 줄은 bit7 이 켜진 바이트까지 건너뜁니다. 목록 끝을 따로 표시하지 않아서, 무기 목록에 없는 장소면 방어구·도구 목록까지 이어서 찾고, 끝의 `FF` 줄(`79` うまのふん 다섯 개)에서 멈춥니다. 무기 20줄, 방어구 20줄, 도구 24줄이 있습니다.

### 그룹 `FE`

도구 목록의 `FE/FE` 줄(やくそう·どくけしそう·せいすい·キメラのつばさ)과 여관의 「그룹 `FE` 이면 10」은 실제 맵이 아니라 뱅크 `15` 함수 `17`(`15:$BEF4`)이 쓰는 가짜 장소입니다. 이 루틴은 `$63`/`$64` 를 스택에 두고 둘 다 `FE` 로 바꾼 뒤, 난수(`1F:$C891`)가 `10` 미만이면 여관 본문 `15:$BF30`, 아니면 도구점 `15:$B85B` 를 열고, 끝나면 `$63`/`$64` 를 되돌립니다. 여관에서 잔 뒤에는 `$64` 가 `FE` 인지 보고 다른 마무리(`15:$A72A`)로 갑니다.

메모리의 PRG 에서 여관 갈래 `15:$9CCA` 의 `JMP $BF28` 을 `JMP $BEF4` 로 바꾸고 `02/00` 여관 주인에게 말을 걸면, 8번(말 걸기 전 1~43프레임 기다림을 바꿈) 모두 도구점이 열려 `$07BD` 가 `53 54 55 56`, `$63`/`$64` 가 `FE`/`FE` 였습니다. `15:$BF0E` 의 `CMP #$10` 을 `CMP #$FF` 로 더 바꾸면 여관이 열려 「ひとばん 10ゴールドですが」가 나왔습니다. 이 함수를 부르는 곳은 찾지 못했습니다(롬 전체에서 `BRK 17/97 58~5F` 꼴은 데이터 3곳뿐).

품목이 종류를 꼭 따르지는 않습니다. `13/00` 무기점은 みかわしのふく·てっかめん 을, `13/00` 방어구점은 やくそう 를 팝니다(화면 확인).

### 덧붙임(`15:$B26B`)

| 장소·종류 | 조건 | 바뀌는 것 |
| --- | --- | --- |
| `16/00` 무기 | `$62E7`·`$62E8`·`$62E9` 가 0 이 아닌 것마다 | `15:$A4A4` 의 `0B` ブーメラン·`04` くさりがま·`23` はじゃのつるぎ 를 차례로 뒤에 붙임 |
| `09/00` 무기 | `$62ED` < `$78`(낮, `15:$9CE5`) | 목록을 `06 23 07 10`(はがねのつるぎ·はじゃのつるぎ·バトルアックス·りりょくのつえ)으로 바꿈. 표의 `09/00` 줄(バトルアックス·まどろみのけん)은 밤 목록 |

`16/00` 은 무기점 인물 둘이 1장 세이브스테이트에서는 인물 표에 나오지 않아, 같은 맵 교회 인물에게 말을 걸 때 `15:$9962` 에서 `$00` 을 `01` 로 바꿔 무기점을 열었습니다. `09/00` 무기점 인물은 낮에는 (04,0B) 에서 `06 23 07 10` 을 팔고, 밤에는 (02,16) 으로 자리를 옮겨 표대로 `07 18` 을 팝니다(`$62ED`=`80` 으로 들어가 네 방향에서 말 걸기). 낮에 들어온 뒤 `$62ED` 를 `80` 으로 바꾸고 (04,0B) 에게 말을 걸어도 `07 18` 이었습니다. `dq4shop.py G K --compare end.ram end.sram` 은 SRAM 덤프의 값으로 덧붙임까지 계산해 비교합니다.

### 가격

가게 창의 가격은 [dq4-data-format.md](dq4-data-format.md) 의 아이템 가격 공식 (`10:$8E19` & 7F) × 10^(`10:$8D1B` & 3) 과 같았습니다. 5개 가게 창 27품목(`02/00` 무기 4, `12/00` 무기 5, `04/00` 도구 6, `13/00` 무기 6, `0C/00` 방어구 6)을 화면에서 읽어 모두 맞았습니다.

### 장소별 값(`15:$B2F7`)

가게 창의 값은 뱅크 `15` 함수 `3`(`15:$B2F7`, 아이템 `$00` → 값 `$00`~`$02`)이 냅니다. 가게 창 그리기(`16:$AD60` 의 `BRK 03 5F`)가 부르고, 뱅크 `15` 안에서는 사기(`15:$BAC6`)·メダル 왕(`$AA28`)·`$9F12`·`$A33B`·`$A5B3` 이 `JSR` 로 부릅니다. 세 장소만 아이템 가격 대신 정한 값을 씁니다.

| 장소 | 아이템 | 값 | 확인 |
| --- | --- | --- | --- |
| 그룹 `18` | `06` はがねのつるぎ | 10 | `18/00` 도구점 창 「はがねのつるぎ 10」 |
| 그룹 `18` | `79` うまのふん | 2 | 코드 읽기 |
| 그룹 `22`(メダル 왕) | `17`·`4E`·`1C`·그 밖 | 메달 1·4·6·20 | `22/00` 창 「てんばつのつえ 1 / しあわせのぼうし 4 / きせきのつるぎ 6 / はぐれメタルへルム 20」 |
| `04/01`(카지노) | 표 `15:$B375`(아이템, 값 2바이트 × 6) | 코인 `5A` 30, `59` 500, `22` 1000, `66` 2500, `50` 4000, `45` 50000 | 경품 창 6줄이 같음 |
| 그 밖 | | 아이템 가격(`BRK 11 0F`) | |

그룹 `18` 에서 `06`·`79` 가 아닌 아이템이면 A 에 아이템이 남은 채로 다음 비교(`CMP #$22`, `CMP #$04`)로 떨어집니다. `18/00` 목록의 やくそう 는 이 비교에 걸리지 않아 8G 였습니다. `fc/dq4/tools/lua/shopprice.lua` 가 함수에 들어갈 때의 아이템과 나올 때의 값을 기록하고, `dq4shop.price` 가 이 규칙을 따릅니다.

## 여관

`15:$BF71` 이 `BRK 87 8F`(뱅크 18 함수 07 의 주소를 `$DA` 에 꺼냄)로 표 `18:$B5CD` 를 얻습니다. 줄은 3바이트(그룹, 순번, 1인 값)이고 `FF` 로 끝나며 31줄입니다.

- 그룹이 `FE` 이면 표를 보지 않고 10(위 「그룹 `FE`」).
- 그룹 `10` 에서 주인공 Y `$45` < `$14` 이면 그 줄 대신 10. `10/00` 밤 여관 인물(15,11)에게 Y `12`·`13` 에서 말을 걸면 `15:$BFB5` 의 A 가 `0A`, 낮 인물(17,1B)에게 Y `1C` 에서 걸면 `05` 였습니다. `dq4shop.py people` 은 인물 Y + 1 이 `14` 미만이면 10 으로 적습니다.
- 요금 = 1인 값 × `BRK 62 23 01`(뱅크 10 함수 2 → 명령 `62`, 인자 `01`) 이 돌려준 A(`0F:$C827` 곱셈).

곱수는 걷는 일행 `$616A`~`$616D`([dq4-save-format.md](dq4-save-format.md)) 가운데 bit7 이 켜진 자리이고, 그 인물 레코드(`10:$9FBA`[번호] 의 주소, 0~9 는 `$6001` + 30 × 번호) `+00` 의 bit7 이 켜진 사람 수입니다. `02/00` 여관에서 RAM 을 바꿔 `15:$BFBB` 의 A 를 봤습니다.

| 바꾼 값 | 곱수 |
| --- | --- |
| 그대로(`86 00 00 00`) | 1 |
| `$616B`=`87`, 레코드 7 `+00`=`80` | 2 |
| 같은 자리, `+00`=`00` 또는 `40` | 1 |
| `$616B`=`87`, `+00`=`80`, HP `0000` | 2 |
| `$616B`=`07`(bit7 없음), `+00`=`80` | 1 |
| `$616B`~`$616D`=`87 87 87` | 4 |
| `$616B`~`$616D`=`87 88 89`, 7·8·9 의 `+00`=`80` | 4 |
| `$616E`=`87`(다섯째 자리), `+00`=`80` | 1 |
| 같은 것에 `$618E`=`80` | 1 |
| `$616B`=`8A`(6바이트 레코드 `$6115`), `+00`=`80` | 2 |
| 마차 자리 `$6172`=`87`, 레코드 7 `+00`=`80`, `$618E`=`00` | 1 |
| 같은 것에 `$618E`=`20` 또는 `21` | 2 |
| `$618E`=`20`, `$6172`~`$6173`=`87 88`, 7·8 의 `+00`=`80` | 3 |
| `$618E`=`A0` | 여관 값 계산(`15:$BFBB`)에 닿지 않음 |

`+00` 이 `00` 인 인물은 교회에서 되살리기 대상이 되므로(아래) bit7 은 살아 있음입니다. HP 값은 보지 않습니다. 마차 자리는 `$618E` bit5(마차 있음)가 켜져 있으면 셉니다. 대화 조건이 마차를 셀지 정하는 `10:$8498`([dq4-script-format.md](dq4-script-format.md))과 같은 규칙으로 보입니다. `$618E` bit7 이 켜졌을 때는 화면이 여관까지 가지 않아 세는지 보지 못했습니다.

## 교회

`15:$B550` 이 인사(`$62ED` 로 낮 `021B`·밤 `021C`) 뒤 메뉴 창을 엽니다. 그룹 `46`·`0E` 와 장소 `04/0E` 는 창 `70`(되살리기·해독·저주만), 나머지는 창 `41` 입니다(`15:$B573`). `04/0E` 교회에서 메뉴가 「いきかえらせる / どくのちりょう / のろいをとく / やめる」인 것을 화면으로 봤습니다.

| 메뉴 | 갈래 | 요금 | 확인 |
| --- | --- | --- | --- |
| 0 おいのりをする | `15:$B6E6` | 없음. 저장 | 「では カミの みまえで…」 |
| 1 おつげをきく | `15:$B728` | 없음. 일행마다 다음 레벨까지 남은 경험치(메시지 `0317`) | 아래 |
| 2 いきかえらせる | `15:$B65E` | 레코드 0~8: (L² + 10) // 10 × 10, 그 밖은 10 | 아래 |
| 3 どくのちりょう | `15:$B5C2` | 5 | 레코드 `+00` bit5(`20`) 일 때 5G |
| 4 のろいをとく | `15:$B60B` | L × 30 | 저주받은 장비를 한 인물 |

L 은 레코드 `+05` 레벨입니다(`BRK 0F 53`). 요금은 `15:$B78E` 에서 `$E2`~`$E4` 로 봤고, 화면의 「…ゴールドの ごきふを」와 같았습니다.

| 실험 | 요금 |
| --- | --- |
| 되살리기: `$616B`=`87`, 레코드 7 `+00`=`00`, L 1·5·10·30 | 10·30·110·910 |
| 되살리기: 레코드 8, L 10 | 110 |
| 되살리기: `$616B`=`8A`·`8B`(6바이트 레코드) | 10·10 |
| 해독: ライアン `+00`=`A0` | 5(`C0`·`90`·`88`·`84`·`82`·`81` 은 「どくには おかされて おりませんぞ」 갈래) |
| 저주 풀기: ライアン 소지품 1 = `9F`(E みなごろしのけん), L 1·10 | 30·300 |
| 저주 풀기: `CC`(E じゃしんのめん), L 7 | 210 |
| 저주 풀기: `1F`(장비 안 함), L 7 | 「べつだん のろわれては おりませんぞ」 |

おつげ 는 일행 수(`BRK 62 23 08`)만큼 돌며 뱅크 `12` 함수 `0F`(`BRK 0F 2F`)로 남은 경험치를 `$00`~`$02` 에 받아 메시지 `0317` 「[이름]よ。 あと [수]の　けいけんちで…」 를 냅니다. 그 함수가 C 를 켜면 메시지 `03AF` 「そなたは　じゅうぶんにつよい！」 입니다(코드 읽기, 레벨 99 로 보임). ライアン(1레벨) 경험치를 5 로 두면 「あと 7」 로 2레벨 경험치 12([dq4-data-format.md](dq4-data-format.md#레벨업)) − 5 와 같았습니다. 경험치를 `9F`(159)로 두면 「あと 10000000」 이 나왔습니다. 남은 값이 음수가 되는 경우인데 게임에서는 전투 뒤 레벨이 오르므로 나오지 않습니다.

저주 검사는 소지품 8칸(`+13`~`+1A`) 가운데 장비(bit7)한 아이템을 `10:$8B90`(아이템 성질 1)으로 봅니다(`10:$979C`, 코드 읽기). 되살리기의 「그 밖은 10」 갈래는 `BRK 2B 53` 이 8 이상일 때입니다. 레코드 번호 9 이상(6바이트 레코드)은 `BRK 2B 53` 이 레코드 `+05` 로 인물 번호를 정하는데(`10:$884C`, 코드 읽기), `$616B`=`8A` 로 두고 레코드 10(`$6115`)의 `+05` 를 `E2`·`C6`·`05` 로 바꿔도 요금은 셋 다 10 이었습니다.

## 맡기는 곳

`15:$BBF0`. 메뉴는 「あずけにきた / ひきとりにきた / やめる」, 다음에 「おかね / どうぐ」입니다. 맡긴 돈은 `$625B`/`$625C` 에 1000G 단위로 둡니다(최대 999, `15:$BC2E`). 수수료는 없습니다.

| 실험(`02/00` 교회 인물에게 말 걸 때 `15:$9962` 에서 `$00`=`04`, 골드 2000) | 결과 |
| --- | --- |
| おかね, 위를 1번 눌러 1 | 골드 1000, `$625B` = 1 |
| おかね, 위 2번(2) | 골드 0, `$625B` = 2 |
| おかね, 위 3번(3) | 골드 2000 그대로, `$625B` = 0 |

물건은 보관함 `$61DB`~`$625A`(128칸, 첫 `FF` 가 끝)에 넣습니다. `15:$B3B2` 가 첫 `FF` 자리를 세고(128 이면 가득), `15:$B3C9` 가 아이템의 bit7(장비)을 지워 그 자리에 쓰고 다음 칸을 `FF` 로 둡니다. `15:$B39C` 는 보관함과 맡긴 돈을 모두 비웁니다(코드 읽기).

| 실험(같은 방법, ライアン 소지품 3 = 아이템) | 결과 |

찾기(`15:$BEB5`~, 수수료를 떼고 `BRK 2E 73` 으로 돌려줌)는 실험하지 않았습니다.

| 블록 종류 | `08:$8055` → `$8464` | 맵 로드 때 블록 32개의 종류 바이트를 `$6F40`~`$6F5F` 에 씀. 값 = `08:$8ADB` + 맵 번호(`$0028`, 6비트) × 64 의 2바이트 기술자 `(b0 & 7) << 8 \| b1` 로 `08:$A80D`(포인터 `08:$8235`) + 3 × 그 값의 셋째 바이트. `b0 & 7` = 7 인 블록은 따로 처리(`08:$847A`) |

### 개수 표와 맵

`dq4chest.py check` 가 맵마다 종류 `04` 칸 수를 개수 표와 비교합니다. 맵 279곳 가운데 276곳이 같습니다.

### 대화로 받는 물건

대화 스크립트 문장에는 물건을 주는 명령이 없고, 호출 문장(`00`·`01`)이 부르는 뱅크 `15` 루틴이 줍니다. 롬 전체에서 「아이템 넣기」 `BRK 2E 73` 은 17곳이고, 대화 루틴은 대개 둘레의 도우미를 거칩니다.

| 루틴 | 하는 일 |
| --- | --- |
| `15:$B0B1` | 아이템 A 를 줌: `BRK 65 33` 으로 빈 자리를 찾아 `BRK 2E 73`. 자리가 없으면 C = 1 |
| `15:$B0C2` | 아이템 A 를 뺌: `BRK 66 73` 으로 찾아 `BRK 30 73` |
| `BRK 4B 73` | 골드 더하기. 금액 = A \| `$70` << 8 \| `$71` << 16 |
| `15:$A988` | 카지노·メダル 왕 경품: `$07C5` = 1 로 그 장소의 무기 목록 줄(`15:$B217`)을 담음. 값은 위 「장소별 값」 |

`dq4chest.gift_scan` 이 호출 대상 루틴을 분기 양쪽·`JMP`·`JSR`(3단)까지 따라가며 위 넷과 플래그 켜기를 모으고, 바로 앞의 `LDA #n` 으로 아이템·금액을 정합니다(가게 입구로 들어가면 멈춤). 루틴 안의 예/아니오(`15:$9AC9`), 아이템 검사(`$A794`), 일행 검사(`$9AF8`), 플래그 검사(`BRK n EB m`)는 「루틴 안」 조건으로 붙입니다. 그다음 맵마다 인물 레코드(보통 목록과 진행 플래그 목록, 낮·밤 모습)의 스크립트를 풀어 이 루틴을 부르는 길과 그 앞의 조건을 적습니다. 보통 목록과 진행 목록에서 같은 줄은 「목록 기본·07&10…」 로 합칩니다.

| 장소 | 대화 | 얻는 것 | 확인 |
| --- | --- | --- | --- |
| `04/01` (1C,08) | `046` | 카지노 경품 6가지(코인 `$62AD`~`$62AF`) | 코인 `FFFF` 에서 まほうのせいすい 를 고르면 `FFE1`, 소지품에 `5A` |
| `22/00` (08,03) | `15A` | メダル 왕 경품 4가지(`$62A2`) | `$62A2` = 30 과 메달 1개를 들고 가면 31 이 되고, てんばつのつえ 를 받은 뒤 30 |
| `09/04` (06,06) | `0FA` | てんくうのかぶと(`4B`) | 왕좌의 방에서 대화 번호를 `0FA` 로 바꿈(`TID`), `$6295` = `08` 로 두면 소지품에 `4B`, `$6295` = `1C` |
| `08/02` (09,05) | `127` | さいごのカギ(`73`) | 같은 방법, `$6298` = `40` 으로 두면 소지품에 `73`, `$6298` = `60` |
| `0D/00` (12,13) | `0AD` | たからのちず(`6E`) | 예/아니오 뒤 문제(메시지 `0955` 「では　もんだいじゃ！」)가 이어져 받기까지 가지 못함 |
| `04/0A` | `04C` | ぎんのめがみぞう 를 25000G 에 삼 | 코드 읽기(메시지 `086B` 「25000ゴールド」) |
| `46/03` | `13B` | てんくうのつるぎ `14` 를 가져가고 `21` 을 줌 | 코드 읽기 |

그 밖(おべんとう, おうじのてがみ, パデキアのねっこ, せかいじゅのしずく, 3장 일삯 골드 등)은 정적 분석만입니다. 금액이 RAM 값인 곳(일삯 `$07C6`~`$07C8`, `$6254`~`$6256`)은 「골드 변수」 로 적습니다.

표에 넣지 않은 `BRK 2E 73` 은 가게 사기(`15:$BADC`), 맡긴 물건 찾기(`15:$BEC3`), 상자·발밑 공통(`1E:$B5D3`), 전투(`11:$B259`, 뱅크 `12` 다섯 곳), 맵 이벤트 `1D:$A748`(おうごんのうでわ 를 빼고 とうぞくのカギ(`71`)를 주는 갈래, 코드 읽기)입니다.

## 남은 것

- 들어갈 때 인물을 숨기는 장소별 루틴(`1C:$ABF5`/`$AC8A`)이 각각 무엇을 보는지. `04/00`·`04/08` 맡기는 곳, `05/01` 방어구, `0E/00`·`46/01` 교회, `17/00` (02,14) 무료 숙박에는 말을 걸어 보지 않았습니다.
- 그룹 `FE`(`15:$BEF4`)를 부르는 곳. `JSR`·`JMP` 피연산자, `BRK 17/97 5x` 꼴, 포인터 바이트 `F4 BE`·`F3 BE` 를 찾아도 코드에서 부르는 곳이 없었습니다.
- 여관 곱수에서 `$618E` bit7 일 때.
- 맡기는 곳에서 물건 찾기(수수료가 아이템마다 같은지), `15:$B39C` 가 보관함을 비우는 때.
- 대화로 받는 물건 가운데 실측하지 않은 줄, たからのちず 문제의 답, 맵 이벤트 `1D:$A748` 이 어느 장소인지.
- 발밑 특수 `EE`(같은 칸의 상자 `EE` 가 먼저 잡힘)의 이벤트 내용.
