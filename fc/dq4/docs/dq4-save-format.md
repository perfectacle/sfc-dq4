# DQ4(FC) 저장 데이터·이벤트 플래그·장 시작

FC 「드래곤 퀘스트 IV」 일본판 Rev A(`rom/dq4.nes`)의 배터리 백업 SRAM(`$6000`~`$7FFF`) 구조, 이벤트 플래그 영역, 장(章)을 시작할 때 롬에서 읽는 표입니다. 주소 표기는 [dq4-handoff.md](../handoff.md#조심할-것) 를 따르고, 필드 RAM 은 [dq4-ram-format.md](dq4-ram-format.md) 에 있습니다. 실험 과정은 [2026-10-25-11 일지](../journal/2026-10-25-11-event.md)·[2026-10-25-23 일지](../journal/2026-10-25-23-event2.md)·[2026-10-25-36 일지](../journal/2026-10-25-36-event3.md) 에 있습니다. 인물 블록 명령은 [dq4-npcblock-format.md](dq4-npcblock-format.md) 에 따로 있습니다.

근거가 실측이 아니라 코드 읽기인 줄에는 「코드 읽기」라고 적었습니다. 덤프를 푸는 도구는 `fc/dq4/tools/dq4event.py` 입니다.

```sh
uv run python fc/dq4/tools/dq4event.py rom/dq4.nes sram work/x/end.sram     # 작업 영역·모험의 서 3칸, CRC 검사
uv run python fc/dq4/tools/dq4event.py rom/dq4.nes chapters                 # 1~5장 시작 표
uv run python fc/dq4/tools/dq4event.py rom/dq4.nes chars --compare work/x/end.sram
uv run python fc/dq4/tools/dq4event.py rom/dq4.nes flags --xref [NN]          # 플래그 바이트·비트마다 쓰는 곳과 검사하는 곳
uv run python fc/dq4/tools/dq4event.py rom/dq4.nes flags --meaning            # 한 비트 플래그마다 뜻([확인]·[추정])
uv run python fc/dq4/tools/dq4event.py rom/dq4.nes ending                   # 5장 끝의 엔딩 장면 목록
uv run python fc/dq4/tools/dq4event.py rom/dq4.nes places                   # 귀환 자리 표, ルーラ 행선지와 마을 레코드
uv run python fc/dq4/tools/dq4event.py rom/dq4.nes events                   # 인물 블록의 이벤트 명령과 맵 이벤트 표
```

## SRAM 배치

게임은 진행 상태를 SRAM 의 작업 영역에 바로 두고, 저장할 때 그 영역을 모험의 서 칸에 통째로 복사합니다.

| 주소 | 크기 | 내용 | 근거 |
| --- | --- | --- | --- |
| `$6001`~`$62EE` | `$2EE` | 작업 영역. 인물 레코드, 골드, 장, 일행, 이벤트 플래그 등 저장되는 모든 값 | 교회에서 저장한 직후 1번 칸의 사본과 바이트가 모두 같음 |
| `$62EF`~`$65DE` | `$2F0` | 모험의 서 1: CRC 아래·위 바이트 + 작업 영역 사본 | 저장할 때 쓰이는 바이트(`probe/writes.lua`) |
| `$65DF`~`$68CE` | `$2F0` | 모험의 서 2(같은 형식) | 빈 칸이 `4B` 로 차 있는 것, 칸 주소 계산 `12:$AD1C`(코드 읽기) |
| `$68CF`~`$6BBE` | `$2F0` | 모험의 서 3 | 같음 |
| `$6BBF`~`$6BD8` | 13 × 2 | `MANABU YAMANA` 두 벌. `12:$AC93` 이 `12:$AD78` 에서 복사 | SRAM 덤프. 초기화 확인용 서명으로 보임(코드 읽기) |
| `$6BD9`~ | | 저장하지 않는 작업 RAM(인물 표 `$6F60`, 맵 버퍼 `$7800` 등) | |

### 체크섬

칸의 첫 두 바이트는 사본 `$2EE` 바이트의 CRC 입니다(아래 바이트 먼저).

- 계산: CRC-16, 다항식 `1021`, 위 비트부터, 시작값 `3A3A`, 마지막 XOR 없음. `12:$ACA2` 가 시작값을 `$12`/`$13` 에 넣고 바이트마다 `1F:$C8AD` 를 부릅니다.
- 검사: `12:$ACC4` 가 다시 계산해 칸의 두 바이트와 뺄셈으로 비교합니다(코드 읽기).
- 빈 칸: 칸 앞 5바이트가 모두 `4B` 이면 빈 칸입니다(`12:$ACF8`). 빈 칸 전체가 `4B` 로 차 있습니다.

| 확인 | 결과 |
| --- | --- |
| 바트랜드 교회에서 저장한 1번 칸 | 적힌 CRC `5AD0`, 다시 계산 `5AD0` |
| 1번 칸의 `$6290` 을 `02`→`0B` 로 바꾸고 CRC 를 `C9C7` 로 맞춰 불러오기 | 정상으로 불러와 귀환 자리 `0B`(`0E/00` (0C,19))에서 시작 |
| 같은 바꾸기에서 CRC 를 그대로 두고 불러오기 | 「おきのどくですが　ぼうけんのしょ　1ばんは　きえてしまいました。」 |

## 작업 영역

### 인물 레코드 `$6001` + 30 × 번호

레코드 번호는 직업 이름 목록([dq4-data-format.md](dq4-data-format.md))의 순번과 같습니다: `0` ゆうしゃ(주인공), `1` しんかん(クリフト), `2` うらないし(ミネア), `3` おどりこ(マーニャ), `4` まほうつかい(ブライ), `5` ぶきや(トルネコ), `6` せんし(ライアン), `7` ひめ(アリーナ). 장 시작 루틴이 0~7 만 초기화합니다(`12:$8EFF`~`$9017`).

| 자리 | 크기 | 내용 | 근거 |
| --- | --- | --- | --- |
| `+00` | 1 | `80` 이면 레코드가 쓰임 | 장 시작 루틴이 `80` 을 씀 |
| `+01` | 2 | HP | 상태 화면: `1B 01` 을 써서 HP 283 |
| `+03` | 2 | MP | 상태 화면: `2A 01` 을 써서 MP 298 |
| `+05` | 1 | 레벨 | 상태 화면 |
| `+06`~`+0A` | 5 | ちから, すばやさ, たいりょく, かしこさ, うんのよさ | 상태 화면(ライアン 7, 4, 13, 1, 2) |
| `+0B` | 1 | 모름. `05` 를 써도 상태 화면에 바뀐 것이 없음 | 상태 화면 |
| `+0C` | 2 | 최대 HP | 상태 화면: `1B 01` 을 써서 283 |
| `+0E` | 2 | 최대 MP | 상태 화면: `21 03` 을 써서 801 |
| `+10` | 3 | 경험치 | 상태 화면: `45 23 01` 을 써서 74565 |
| `+13`~`+1A` | 8 | 소지품. 아래 7비트 = 아이템 ID, bit7 = 장비(화면의 「E」), `FF` = 빈 칸 | 상태 화면(`82` = E どうのつるぎ, `A6` = E かわのよろい) |
| `+1B`~`+1D` | 3 | 주문 비트로 보임. 장 시작 때 `12:$8FC8` 이 `BRK 38 0F` 로 배우게 함 | 코드 읽기. 값은 クリフト·ミネア `02 00 01`, マーニャ·ブライ `01 00 00` |

### 그 밖의 값

| 주소 | 내용 | 근거 |
| --- | --- | --- |
| `$6157`~`$6159` | 골드. `$6157`/`$6158` 에 `39 30` 을 써서 G12345 | 상태 화면. 셋째 바이트는 장 시작 루틴이 0 으로 씀(코드 읽기) |
| `$615A` | 장 − 1(1장 `00` ~ 5장 `04`) | 디버그 장 고르기로 1~5장을 시작해 확인(아래) |
| `$615B` | 장 시작 때 0 | 코드 읽기 |
| `$615D`~`$6160` | 주인공 이름 4바이트(글자 바이트, `00` = 빈 칸) | 세이브스테이트의 이름 `0B 0B 0B 00` 이 모험의 서 목록에 「あああ」로 나옴 |
| `$6165`~`$6169` | ルーラ·キメラのつばさ 로 갈 수 있는 마을 비트(가 본 마을). 장 시작 때 `12:$9179` 의 5바이트로 초기화. [아래](#ルーラ-행선지와-마을-레코드) | 비트 하나만 켜고 キメラのつばさ 를 써서 37곳 모두 도착 자리 확인 |
| `$616A`~`$616D` | 걷는 일행 4자리. bit7 + 레코드 번호 | 장 시작 뒤 선두만 들어 있음(1장 `86` ライアン) |
| `$6172`~`$6177` | 마차 등 나머지 6자리로 보임 | `$615A`=6 모드에서 `84 85 86 87` 이 들어감. 1~5장 시작 세이브스테이트에서는 모두 0 |
| `$618E` | 상태 비트. bit6 = 여자 주인공([dq4-data-format.md](dq4-data-format.md)), bit5 = 마차가 있음, 아래 3비트 = 마차가 어디 있나(0 일행과 함께, 1 마을 밖에 세움). bit7 이면 마차 자리를 세지 않음(`10:$8498`, 코드 읽기). [아래](#마차배열기구) | 마차를 두고 마을에 들어가고 나와 확인 |
| `$618F`, `$6191`/`$6192` | 마차를 세운 맵 그룹과 필드 X·Y | 같음 |
| `$6193`/`$6194` | 아래 3비트를 2 로 할 때(`10:$929B`) 그 맵 그룹·순번 | 코드 읽기 |
| `$6195`/`$6196` | 배의 필드 X·Y. 배를 타면 일행과 함께 움직임 | 배 자리로 걸어 들어가 타고 두 칸 감 |
| `$6197`/`$6198` | 열기구의 필드 X·Y. 그 칸에서 A 를 누르면 탐(`1F:$CBF8` → `$CC16`) | 열기구 자리에서 A, 날아서 9칸 감 |
| `$6282` | 끝낸 장 비트. 장 시작에서 1장 `00`, 2장 `80`, 3장 `C0`, 4장 `E0`, 5장 `F0` | 실측. 장별 시작 루틴(`1E:$A4BE` 등)이 씀. 장이 끝날 때 `1A:$B908` 이 `SEC`·`ROR` 로 한 비트 더함(코드 읽기) |
| `$6290` | 귀환 자리 번호(아래 표). 저장하면 그 교회 자리가 들어감 | 바트랜드 교회 저장 뒤 `02` |
| `$6291` | 플래그 번호 `16`. bit7 = 이 장의 시작 처리를 했음 | bit7 을 0 으로 두고 저장·불러오기 하면 `$615A` 의 장을 처음부터 시작 |

`$627B`~`$62EE` 는 이벤트 플래그 영역입니다(아래). `$6290`·`$6291` 도 이 영역 안에 있어 플래그 명령으로 다룹니다.

## 이벤트 플래그 `$627B`~`$62EE`

플래그는 (번호 n, 마스크 m) 쌍입니다. 주소 = `$627B` + n, 비트 = m. BRK 특수 형식 4바이트 `00 n op m` 으로 다룹니다([dq4-bank-format.md](dq4-bank-format.md#특수-형식)). `1F:$C463` 이 `op` 를 보고 `1F:$C4A1` 로 가서 복귀 주소를 하나 늘린 뒤(BRK+4 로 복귀) 아래를 합니다.

| `op` | 하는 일 | 루틴 | 실측 |
| --- | --- | --- | --- |
| `CB` | `$627B+n` \|= m | `1F:$C4CA` | `1E:$A354` `00 16 CB 80` → `$6291` `00`→`80`, `1E:$A399` `00 0D CB 40` → `$6288` `00`→`40` |
| `DB` | `$627B+n` &= m | `1F:$C4E1` | `1E:$A41B` `00 0D DB BF` → `$6288` `40`→`00`, `1E:$A3D8` `00 10 DB 00` → `$628B` `FF`→`00` |
| `EB` | `$627B+n` & m 을 계산해 Z 플래그로 돌려줌(쓰지 않음) | `1F:$C4B6` | `16:$87F1` `00 16 EB 10` 이 매 프레임 실행됨(`probe/trace.lua`, X=`16`) |

실측은 2장 시작을 `fc/dq4/tools/lua/eventflags.lua` 로 기록한 것입니다. 이 영역을 직접 읽고 쓰는 코드도 있습니다: 불러오기 때 `12:$AC47` 이 칸에서 영역 전체를 복사하고, 대화 스크립트의 명령 `17`·`18`·`19` 와 조건 `1A`~`1C` 도 같은 (n, m) 을 씁니다([dq4-script-format.md](dq4-script-format.md)). `0F:$DC0E` 는 인물 블록 명령 `27`(아래)의 처리기라 맵에 들어갈 때만 쓰는 곳이 아닙니다.

`dq4event.py ops` 는 롬에서 `00 n CB/DB/EB m`(n ≤ `73`) 모양을 모두 찾습니다(435곳). 바이트 모양만 보므로 데이터가 섞일 수 있습니다. 예를 들어 `--flag 16` 은 장 시작(`1E:$A354` 켜기 `80`)과 장 끝(`1A:$B92C` 끄기 `7F`)을 함께 보여 줍니다.

### 플래그를 쓰고 읽는 곳

`dq4event.py flags --xref [NN]` 은 롬 전체에서 플래그를 다루는 곳을 모아 바이트마다, 비트 순서로 찍습니다. 한 줄은 `마스크 종류 어디 [메시지 번호 첫 줄]` 입니다.

| 출처 | 종류 | 모으는 법 | 수 |
| --- | --- | --- | --- |
| BRK 특수 형식 `00 n CB/DB/EB m` | `set`·`clear`·`test` | 바이트 모양. 데이터 뱅크(`00`~`07`, `09`~`0B`)에 있거나, 켜기·검사인데 비트가 하나가 아니거나, 끄기인데 한 비트만 뺀 마스크(또는 `00`)가 아니면 「모양만」으로 거름(`--all` 로 같이 보임) | 394(거른 것 41) |
| 절대 주소 명령(`LDA $62xx` 등 21가지) | `read`·`write` | 바이트 모양. 비트는 모름 | 445(거른 것 19) |
| 대화 스크립트 | `set`·`clear`·`store`, 조건 `talk&`·`talk!=`·`talk\|`(`!` 는 뒤집힌 조건) | 맵의 낮·밤 인물 목록과 [이벤트 목록](dq4-script-format.md#이벤트-목록)의 대화 번호를 `fc/dq4/tools/dq4talk.py` 로 풀어 나무를 따라감. 같은 대화 번호는 처음 인물에만 적고 「외 n명」 | 274 |
| 인물 블록 명령 `27`·`28`·`29` | `set`·`clear`·`store` | 맵 목록·이벤트 목록의 블록1·2 를 `tools/dq4npcblock.py` 로 명령 단위로 풀어 주소가 플래그 영역인 것. 메시지는 같은 블록의 가장 가까운 `26` 명령 | 51 |
| 맵 인물 목록 표 | `test` | [아래](#맵에-들어갈-때-인물-목록을-바꾸는-표) 두 표 | 73 |

BRK 줄의 「맵 GG/KK」 는 명령 앞 `$30` 바이트 안에 `LDA $63`/`CMP #g`, `LDA $64`/`CMP #k` 가 있을 때 붙이고, 메시지는 명령 뒤 `$30` 바이트 안의 첫 메시지 BRK(`00 lo hB`)입니다. 둘 다 짐작용입니다. 끝 줄에 한 비트로 다루는 (바이트, 비트) 수를 셉니다: 184개 중 쓰는 곳과 검사하는 곳이 다 있는 것 141, 쓰기만 27, 검사만 16.

```
== $6286 번호 0B
  01 set     BRK 1C:$9C8C 맵 04/01
  01 talk&   대화 075 04/00 슬롯 12 외 4명  08A0 [F1]ネネ「あなた　おかえりなさい！ いま　しらせがきて
  04 set     대화 055 16/00 슬롯 08 외 2명  084B トルネコさん！ オレだよ　トムのむすこだよ！ あんたのおかげ
  FB clear   BRK 1A:$B934  03BE ここまでの　おはなしを ぼうけんのしょに　きろく　します。
  04 test    BRK 1E:$94C6  0378 スコット「おお！　どうやら やくそくの5にちが　すぎたようだ
```

실측으로 확인한 쓰는 곳 → 읽는 곳:

| 플래그 | 쓰는 곳 | 읽는 곳 | 실측 |
| --- | --- | --- | --- |
| `$627B` bit1 | 대화 `01A`(サントハイム 왕, `01/01` 슬롯 `0A`) `flag\|= 00 02` | 이벤트 `40`(성문 병사, `1D:$A7C2`), 대화 `021`·`022` | 2장 시작에서 `$6281`=`20` 으로 두고 왕에게 말 걸면 메시지 `07A3` 뒤 `$627B`=`02`. 두지 않으면 `07A0` 이고 `$627B`=`00` |
| `$6284` bit6 | 이벤트 `4A`(`1D:$A9D8`, エンドール 무술 대회 뒤 ブライ 「ひめさま　やりましたな！」) 안의 BRK `1D:$A9FE` | 맵 인물 목록 표: `01/00` 인물 목록 비움 | `01/00` 에 들어갈 때 이 비트를 켜면 인물 표 `$6F60` 슬롯 6~ 이 모두 비고, 끄면 11명 |
| `$6282` bit4 | 장 끝 `1A:$B909`(4장 끝에 켜짐) | 맵 인물 목록 표: `01/00` → 목록 `1C:$8D34` | 켜고 `01/00` 에 들어가면 인물 3명이 `1C:$8D34` 목록의 자리 (02,08)·(0E,0E→0F)·(15,05)에 섬 |
| `$6291` bit7 | 장 시작 `1E:$A354` | 장 끝 `1A:$B92C` 가 끔 | [장 끝](#장-끝) |
| `$6287` bit3 | 이벤트 목록 `1C:$8930`(빈 サントハイム 성 `01/01`) 슬롯 6 의 블록 `27 08 87 62` | 2장 끝 검사 `1A:$B855`(`$6287` & `18`) | `$6284` = `40` 으로 `01/01` 에 들어가면 ブライ 「これは　きっかいな！」(`0388`) 뒤 `$6287` `00`→`08` |
| `$627E` bit4 | 바트랜드 왕좌의 방 레코드 20 의 블록(`27 10 7e 62`) | 모름. 켜진 채 `02/01` 에 들어가면 그 인물이 실린 직후 X·Y 가 `80` 이 됨 | 끈 채 `02/01` 에 들어가면 왕의 첫 장면(`0301`·`0302`) 뒤 `10` |

### 플래그 비트의 뜻

`flags --meaning` 은 한 비트로 다루는 184개마다 쓰는 곳·검사하는 곳의 수와 뜻을 찍습니다. 화면·RAM 으로 확인한 13개는 `[확인]`, 나머지는 쓰는 곳(없으면 검사하는 곳) 하나의 맵·장소 이름과 대사 첫 줄을 붙인 `[추정]` 입니다. 장소 이름은 [ルーラ 행선지](#ルーラ-행선지와-마을-레코드)에서 맵 그룹 → 마을 레코드 번호를 찾고, 그 번호를 장소 이름 목록(`0B:$B006` 의 「장소」)의 번호로 씁니다. 1~4장 「どこへ」 목록의 첫 화면 다섯(레코드 `03` `13` `02` `0F` `10` → バトランド イムル サントハイム テンペ フレノール)이 이 규칙과 같았고, 나머지 마을은 같은 규칙을 따른다고 보았습니다(코드 읽기). 대화 스크립트가 부르는 이벤트 표 `1C:$BF74` 의 50개(합류·무술 대회·결계 `$62A4` 등)가 다루는 비트는 [dq4-script-format.md 의 이벤트 표](dq4-script-format.md#이벤트-표)에 있고, `[추정]` 줄을 읽을 때 그 표를 함께 봅니다.

| 플래그 | 뜻 | 근거 |
| --- | --- | --- |
| `$627B` bit1 | サントハイム 왕과 이야기함(2장). 성문 병사 대사가 바뀜 | 위 표 |
| `$6282` bit7~4 | 끝낸 장(1장 끝 `80`, 2장 `C0`, 3장 `E0`, 4장 `F0`) | [장 끝](#장-끝) |
| `$6283` bit7, `$6285` bit2 | 1장 끝 조건 | [장 끝](#장-끝) |
| `$6284` bit6 | エンドール 무술 대회 뒤(2장). サントハイム 성 사람들이 사라지고 이벤트 목록 `1C:$8930`·`$895D` 가 실림 | 위 표 |
| `$6287` bit3 | 빈 サントハイム 성 왕좌의 방에서 ブライ 대사를 봄(2장 끝 조건) | 위 표 |
| `$6288` bit7, `$62A5` bit7 | 엔딩 장면 중. `$62A5` bit7 이면 인물 목록 비움 표를 보지 않음 | [5장 끝과 엔딩](#5장-끝과-엔딩) |
| `$628A` bit4 | 4장 끝 조건 | [장 끝](#장-끝) |
| `$6291` bit7 | 이 장의 시작 처리를 했음 | [장 시작](#장-시작) |
| `$62A1` bit5 | 5장 끝 조건 | [5장 끝과 엔딩](#5장-끝과-엔딩) |

```
00   10   $627B    1    6  [추정] 쓰는 곳 인물 블록 0F/01 슬롯 08 フレノール 「＊「とまれ！[F4] ちかづくと ひめの　いのち」
```

## 장 시작

### 흐름

1. 불러오기 뒤 `1E:$A34C` 가 `$6291` bit7 을 봅니다. 켜져 있으면 저장한 자리로 돌아갑니다(`1E:$A3A1`).
2. 꺼져 있으면 `BRK 16 CB 80` 으로 켜고, `BRK 12` 함수 `17`(`12:$8EAE`)로 장 초기화, `1E:$A480` 장별 처리, `1E:$A578` 이 시작 자리를 `$63`/`$64`/`$44`/`$45` 에 씁니다(`1E:$A595`).
3. 장이 끝나면 `1A:$B8FF`~ 가 `$6282` 에 비트를 더하고 `$615A` 를 1 늘리고 `BRK 16 DB 7F` 로 `$6291` bit7 을 끈 뒤 바로 다음 장 시작으로 갑니다([장 끝](#장-끝)).

### 장 끝

`1A:$B815`(BRK `1A` 함수 `03`)가 `$615A` 로 `1A:$B977` 의 장별 검사 루틴을 골라 부릅니다. 맵에 들어갈 때(`1E:$8ED8`, C=0)와 걸음마다(`1E:$914E`) 등 롬의 39곳에서 불립니다. 조건이 맞으면 장 끝 메시지 번호를 X:A 에 두고 `1A:$B8D2` 로 갑니다.

| 장 | 검사 루틴 | 조건(코드 읽기) | 메시지 |
| --- | --- | --- | --- |
| 1 | `1A:$B829` | `$6283` & `A0` = `80`, 맵 `02/00`, `$6285` & `04`. 맞으면 `$6282` = `80`, `$6281` bit6 끔 | `0346` こうして　ライアンは… |
| 2 | `1A:$B855` | (들어온 C 가 0 이면) `$64` = 0, `$6287` & `18` | `038B` サントハイムおうの　みた　ゆめとは……？ |
| 3 | `1A:$B86E` | 맵 그룹 `42`, `$44` = `1F` | `037C` こうして　トルネコは… |
| 4 | `1A:$B891` | `$628A` & `10`, 맵 그룹 `04`. `$628E` bit0 끔 | `03AC` こうして　マーニャとミネアの　ふたりは… |
| 5 | `1A:$B8C2` | `$62A1` & `20`, 맵 그룹 `2D` 면 `1A:$9BFC`([엔딩](#5장-끝과-엔딩)) | 없음 |

`1A:$B8D2` 는 장 끝 메시지를 내고, `1A:$B8FF` 에서 `$615A + 25` 로 `BRK 19` 함수 `03` 을 부른 뒤 `SEC`·`ROR $6282` 로 끝낸 장 비트를 더하고, `INC $615A`, `BRK 16 DB 7F`(`$6291` bit7 끔)와 `0D`·`0B`·`0A`·`06` 바이트의 비트를 끕니다. 그 뒤 `1A:$B971` 에서 스택을 비우고 `$C974` 로 가 다음 장의 시작 처리를 탑니다. 저장·불러오기 없이 바로 다음 장이 시작됩니다.

네 장 모두 조건 플래그를 써 넣고 그 맵으로 워프해 실측했습니다(`probe/trace.lua`, 3·4장은 2장 세이브스테이트에서 `$615A`·`$6282` 를 그 장 값으로 바꿈).

| 장 | 써 넣은 값 | 워프 | 지난 루틴 | 끝난 뒤 `$615A` `$6282` `$6290` 선두 자리 |
| --- | --- | --- | --- | --- |
| 1 | `$6283`=`80`, `$6285`=`04` | `02/00` (12,0B) | `B829` → `B8D2`(A=`46`) → `B8FF` → `B91E` → `B971` | `01` `80` `10` `87` `01/01` (09,08) |
| 2 | `$6287`=`18` | `01/00` (0E,1A) | `B855` → `B8D2`(A=`8B`) → … | `02` `C0` `12` `85` `16/01` (1B,05) |
| 3 | `$615A`=`02`, `$6282`=`C0` | `42/01` (1F,08) | `B86E` → `B8D2`(A=`7C`) → … | `03` `E0` `11` `83` `15/03` (0E,03) |
| 4 | `$615A`=`03`, `$6282`=`E0`, `$628A`=`10` | `04/00` (0B,1C) | `B891` → `B8D2`(A=`AC`) → … | `04` `F0` `05` `80` `14/00` (05,11) |

`B91E` 직전까지 `$6282` 는 장 끝 루틴이 쓴 값이고(1장은 `80`→`C0`), 다음 장 시작 루틴이 장 시작 값(2장 `80`)으로 다시 씁니다. 끝난 뒤의 값은 모두 [1~5장 시작 표](#15장-시작-표)와 같습니다(3·4장의 시작 자리는 장 머리 장면이 끝난 자리이고, 장 시작 세이브스테이트와 같음).

### 5장 끝과 엔딩

5장 검사 `1A:$B8C2` 는 `BRK 26 EB 20`(`$62A1` & `20`)이 켜져 있고 `$63` 이 `2D`(天空城, ルーラ 레코드 `01`)면 장 끝 메시지 없이 `1A:$9BFC` 로 갑니다. `$9BFC` 는 화면을 끄고 `1A:$9CE0`(화면 연출)과 `1A:$9DC9`(엔딩 준비)를 부른 뒤, 장면 목록을 하나씩 실어 보여 주고 목록이 `FF` 로 끝나면 `1A:$B981`·`$C031` 를 거쳐 `$C0E9` 로 갑니다.

`1A:$9DC9` 는 `$6288` bit7·`$62A5` bit7 을 켜고, `$618E` = `21`(마차 있음, 마차를 밖에 세움), `$65` = 0, 필드 자리와 열기구 자리 `$6197`/`$6198` 을 (`89`,`86`)에, `$0515` = 2(열기구를 탐)로 둡니다. 장면 사이를 열기구로 날아 다니는 장면입니다.

장면 목록은 `1A:$9E74` 의 워드가 가리키는 `1A:$9E76` 입니다(`1A:$9E17` 이 읽음).

| 바이트 0 | 길이 | 내용 |
| --- | --- | --- |
| bit7 꺼짐 | 5 | 맵 그룹, 순번, X, Y, 시간. 시간은 `$62ED` 에 그대로(`78` 이상이면 밤), 아래 7비트는 `$6B`(머무는 길이) |
| bit7 켜짐 | 4 | `$0530` 값, 주소 lo·hi, 길이. 그 주소의 바이트들을 `$7E00` 에 복사해 [일행 움직임 패턴](dq4-npcblock-format.md#일행-움직임-패턴)처럼 패드 입력으로 씀 |

```
맵 2D/00 (0D,05)              $62ED=15(낮)
  일행 움직임 1A:$9EC1: 왼쪽×F 왼쪽×A 위×F 위×F 위×F 위×F 왼쪽×F …
맵 01/00 (0F,15) サントハイム   맵 01/01 (09,0B)   맵 01/02 (0A,05)
맵 02/01 (10,17) バトランド     맵 04/00 (09,15) エンドール   맵 17/00 (0E,05) コーミズ
맵 15/00 (13,15) モンバーバラ   맵 15/03 (0C,0C) $62ED=9B(밤)   맵 14/02 (0D,10)
```

2장 세이브스테이트(B 세 번)에서 `$615A` = `04`, `$6282` = `F0`, `$62A1` = `20` 을 쓰고 `2D/00` (0C,07)로 워프했습니다. 도착하자마자 `1A:$B815` → `$B8C2` → `$9BFC` 를 지났고, `$9E17` 직전에 `$6288` = `80`, `$62A5` = `80`, `$618E` = `21`, `$6197`/`$6198` = `89`/`86`, `$0515` = `02` 였습니다. 그 뒤 맵이 `2D/00` → `01/00`(5672프레임) → `01/01` → `01/02` → `02/01` → `04/00` → `17/00` → `15/00` → `15/03` → `14/02`(20917프레임) 차례로 바뀌어 목록과 같았고, 24000프레임에 스태프 롤(「SCENARIO　YUJI HORII」)이 나왔습니다.

### 1~5장 시작 표

| 장 | 시작 장소 (X,Y) `1E:$A599` | 선두 | 골드 | 처음 귀환 자리 `1E:$A75E` | 초기화 인물 |
| --- | --- | --- | --- | --- | --- |
| 1 | `02/01` (10,15) | ライアン | 50 | `02` | ライアン |
| 2 | `01/01` (09,08) | アリーナ | 100 | `10` | クリフト, ブライ, アリーナ |
| 3 | `16/01` (1B,05) | トルネコ | 0 | `12` | トルネコ |
| 4 | `15/03` (0C,0F) | マーニャ | 100 | `11` | ミネア, マーニャ |
| 5 | `14/00` (05,11) | 주인공 | 0 | `05` | 주인공 |

다섯 장 모두 아래 디버그 장 고르기로 시작해, `1E:$A595` 에서 `$63`/`$64`/`$44`/`$45` 가 표와 같고, 장 시작 뒤 `$615A`·골드·`$616A`·`$6290`·`$6165`~ 가 표와 같고, 그 장에서 초기화되는 인물 8명의 레코드(주문 비트 빼고)가 `chars` 계산과 모두 같았습니다. 2·3장은 시작 뒤 이벤트로 일행이 바뀌므로(예: 2장은 처음에 アリーナ 혼자) `$616A` 는 선두만 확인했습니다.

### 디버그 장 고르기

`1E:$A35B` 가 장을 시작하기 전에 고정 뱅크 `$C000` 의 롬 바이트를 읽어 bit3 이 0 이면 `1F:$F102` 의 「シナリオ」 창(1~5)을 띄웁니다. 제품판은 `FF` 라 나오지 않습니다.

- 좌우(`$14` bit6·bit7)로 `$615A` 를 0~4 사이에서 바꾸고, A 로 그 장을 시작합니다.
- B 는 `$615A` = 6 을 돌려줍니다. 장 초기화가 인물 8명을 모두 초기화하고, 일행 `80 81 82 83`, 나머지 `84 85 86 87`, 골드 90, 주인공 HP·MP `FFFF`, `$615A` 를 4 로 고쳐 5장 자리(`14/00`)에서 시작합니다(`12:$8EC3`, `12:$9066`).

테스트러너에서 PRG ROM 메모리 `3C000`·`7C000`(고정 뱅크 `0F`·`1F` 의 `$C000`)을 `F7` 로 바꿔 창을 보고, 1~5장과 B 를 모두 시작했습니다. 롬 파일은 고치지 않습니다. 성 앞마당 세이브스테이트에서 교회로 걸어가 `$6291` 을 0 으로 둔 채 저장하고, 리셋해 불러온 뒤 3장을 고르는 명령입니다.

```sh
export MESENCE=... LIBDIR=$(uv run krpatch fc lua)
d=$PWD/work/ch3; mkdir -p $d
W="y=12,x=13,y=1C,x=05,y=16,up:2,wait:10,a:6,wait:40,a:6,wait:300"   # 교회 신부 앞
S="a:6,wait:80,a:6,wait:80,a:6,wait:80,wait:60,a:6,wait:200"          # 기도 → 저장
T="reset:1,wait:600,start:4,wait:60,a:4,wait:60,a:4,wait:60,a:4,wait:60,a:4,wait:40"   # 불러오기
A=""; for i in $(seq 45); do A="${A}a:6,wait:44,"; done                # 장 머리말 넘기기
STATE=$PWD/work/state/dq4-ch1-courtyard.mss SEQ="$W,$S,$T,right:2,wait:20,right:2,wait:20,a:4,wait:60,${A}wait:60" \
  TAIL=30 POKEAT="5:6291=00" PRGPOKE="3C000=F7;7C000=F7" SHOT_DIR=$d \
  "$MESENCE" --testrunner --nes.ramPowerOnState=AllZeros $PWD/rom/dq4.nes $PWD/fc/dq4/tools/lua/eventwalk.lua
cat $d/walk.txt    # end ... at 1B,05 map 16/01
```

`$d/end.mss` 가 그 장을 조작할 수 있는 세이브스테이트입니다.

## 인물 블록의 이벤트 명령

맵에 들어가거나 일행이 어느 칸에 서면 저절로 일어나는 장면은 맵마다의 트리거 표가 아니라 인물 블록에서 시작합니다. 블록 명령 전체(길이·뜻·실측)는 [dq4-npcblock-format.md](dq4-npcblock-format.md) 에 있고, 여기에는 플래그·이벤트를 다루는 명령만 둡니다.

| 명령 | 길이 | 하는 일 | 근거 |
| --- | --- | --- | --- |
| `88`·`89`·`8A` `n` | 2 | 이벤트 n. `1F:$DED8` 가 `BRK 1D` 함수 `04`(`1D:$989F`)를 부르고, 그 함수가 `1D:$B639` + 2n 의 주소로 뜀. C 가 서서 돌아오면 다음 명령, 아니면 다음 차례에 다시 | 실측(아래) |
| `26` `lo` `hi` | 3 | 메시지 hi:lo | 실측: `0388`·`0301`·`0302` |
| `27` `m` `lo` `hi` | 4 | `[hi:lo]` \|= m(`1F:$DC09`) | 실측: `$6287` `00`→`08`, `$627E` `00`→`10` |
| `28` `m` `lo` `hi` | 4 | `[hi:lo]` &= m(`1F:$DC16`) | 코드 읽기 |
| `29` `v` `lo` `hi` | 4 | `[hi:lo]` = v(`1F:$DC23`). 롬의 블록에는 없음 | 코드 읽기 |

이벤트 루틴은 보통 일행 자리(`$44`/`$45`)와 플래그를 보고, 메시지를 띄울 때는 `$058A`:`$0589` 에 메시지 번호를 두고 `$0527` 에 `80` 을 씁니다. 예: 이벤트 `40`(`1D:$A7B1`, サントハイム 성문 병사 둘)은 `$44` 가 `0D`~`10`, `$45` 가 `1A` 면 메시지 `0322`(「やや！ よくぞ　もどられました。」)를, `$627B` bit1 이 서 있으면 `0368`/`0369` 를 띄웁니다.

`dq4event.py events` 는 맵 목록과 이벤트 목록의 블록1·2 를 명령 단위로 풀어 이벤트 명령 173곳(이벤트 목록 25곳)을 찍습니다. 이벤트 번호 136가지가 쓰이고, 표의 `00`·`0D` 는 블록에서 쓰이지 않습니다. 실측은 `probe/trace.lua` 로 `1F:$DEDD`(A = 이벤트 번호, `$51` = 슬롯)를, 또는 `fc/dq4/tools/lua/npcblock.lua` 로 슬롯마다 실행한 명령을 기록한 것입니다.

| 장면 | 기록 | `events` |
| --- | --- | --- |
| 2장, `01/00` 성문으로 워프 | 슬롯 `06`·`07` 이벤트 `40` → `1D:$A7B1` 에서 `$0589`=`22`, 메시지 `0322` | `01/00 슬롯 06·07 이벤트 40` |

### 맵에 들어갈 때 인물 목록을 바꾸는 표

맵을 실을 때 `1C:$987F` 가 두 표를 봅니다. 둘째 표는 [dq4-script-format.md 의 이벤트 목록](dq4-script-format.md#이벤트-목록)과 같은 것입니다. 둘 다 그룹·순번이 지금 맵과 같고 `$627B+n` & m 이 0 이 아니면 쓰입니다.

| 표 | 레코드 | 하는 일 | 근거 |
| --- | --- | --- | --- |
| `1C:$9E61` | 4바이트: 그룹, 순번, m, n. 그룹 `FF` 로 끝 | 인물 목록을 싣지 않음(`1C:$9C28` 이 C 를 세움). `$62A5` bit7 이 서 있으면 보지 않음 | 실측: `01/00`, `$6284` bit6 |
| `1C:$9D0E` 가 가리키는 표(`$9D10`) | 6바이트: 그룹, 순번, m, n, 목록 주소(뱅크 `1C`) | 그 주소의 인물 목록을 대신 실음(`1C:$9CC1`) | 실측: `01/00`, `$6282` bit4 → `1C:$8D34` |

`flags --xref` 가 두 표의 항목(73개)을 「맵 표」 줄로 찍습니다.

### 맵 이벤트 표 `1D:$B8CA`

`1D:$B74D`(BRK `1D` 함수 `07`)가 읽는 6바이트 표입니다([dq4-script-format.md](dq4-script-format.md) 의 「맵 이벤트」 호출). 대화 스크립트의 호출 `00 E1 A4`(`15:$A4E1`, 대화 `00F` フレア 등 6곳)와 이벤트 `31`(`1D:$A44D`)이 부릅니다. 그룹·순번이 지금 맵과 같고 넷째 바이트 위 4비트가 `$615A` 와 같은 레코드를 찾아, 셋째 바이트가 `FF` 면 `1D:$B8A2` 에서 따라오는 인물을 놓고, 아니면 `BRK 52 73` 뒤 레코드마다 다른 처리를 합니다. 1장 `30/04`·`3A/04`·`02/00`·`02/03`, 3장 `04/0B`·`04/00`, 4장 `38/03`, 5장 `04/00`·`04/01`·`2F/00` 의 12개입니다. 「なかまに　くわわった」 대사 뒤에 불리므로 손님 동행으로 보지만 화면으로는 확인하지 않았습니다(코드 읽기).

## 마차·배·열기구

| 확인 | 만든 법 | 결과 |
| --- | --- | --- |
| 마차를 두고 마을에 들어감 | 2장 세이브스테이트(B 세 번)에서 `$615A` = `04`, `$618E` = `20`, 필드 0 (67,66) 으로 워프해 위로 걸어 エンドール(그룹 `04`) 입구 (67,65) 로 | `$618E` `20`→`21`, `$618F` = `04`, `$6191`/`$6192` = `67`/`65` |
| 같은 것을 `$618E` = `00` 으로 | | `$618E`·`$618F`~ 그대로 |
| 마을에서 나옴 | 위 상태에서 아래로 걸어 맵 밖으로 | 필드 (67,66), `$618E` `21`→`20` |
| 열기구 | 필드 0 (67,66) 에 도착한 뒤 `$6197`/`$6198` = (68,66), 오른쪽 한 칸, A, 위로 | `$0515` = `02`, 산을 넘어 (68,5D) 까지 날고 `$6197`/`$6198` 이 따라옴 |
| 배 | 도착 뒤 `$6195`/`$6196` = 물 칸 (67,67), 아래로 | `$0515` = `01`, (67,69) 까지 물 위로 가고 `$6195`/`$6196` 이 따라옴 |
| 배를 땅 칸에 | `$6195`/`$6196` = (66,66), 왼쪽으로 | 그냥 걸어 지나감(`$0515` = 0) |

`$0515` 는 저장하지 않는 RAM 으로, 0 걷기, 1 배, 2 열기구입니다. 마을에 들어갈 때(`10:$91C6`) `$0515` 가 1 이면 마차를 세우지 않습니다. 마차를 세운 뒤 필드로 나와 `$63`(그룹 `34`·`3A`·`3E` 는 `10:$9238` 표로 `0A`·`1C`·`25`)과 `$42`/`$43` 이 `$618F`·`$6191`/`$6192` 와 같으면 아래 3비트를 0 으로 되돌립니다(`10:$9200`, 코드 읽기). 아래 3비트 2·3 은 `10:$929B`(그룹 `$6193`/`$6194` 에 둠)·`10:$92E3` 이 쓰고, 그 장면은 확인하지 않았습니다. 불러오기 때는 [귀환 자리](#귀환-자리-표-1ea76d)의 마을 레코드 바이트 3~6 이 배·열기구 자리를 정합니다(필드로 워프하면 진입 루틴이 덮어쓰므로 도착 뒤에 써야 함).

## 귀환 자리 표 `1E:$A76D`

5바이트 레코드 22개: 그룹, 순번, X, Y, 끝 바이트(아래 2비트 방향, 위 6비트는 [마을 레코드](#ルーラ-행선지와-마을-레코드) 번호이고 그 레코드의 3~6바이트를 `$6195`~`$6198` 에 씀). `$6290` 이 번호입니다. 불러오기 때 `1E:$A690` 이 이 표로 자리를 정하고, 교회에서 저장할 때 `1E:$A73F` 가 현재 `$63`/`$64` 와 같은 레코드를 찾아 번호를 `$6290` 에 씁니다(코드 읽기).

바트랜드 교회에서 저장한 세이브스테이트에서, 리셋 직후 1번 칸의 `$6290` 사본(`$6580`)을 `00`~`15` 로 바꾸고 CRC 를 다시 맞춰 불러왔습니다. 22개 모두 도착한 `$63`/`$64`/`$44`/`$45`/`$3D`(방향)가 `dq4event.py places` 와 같았습니다(`09` `0A/00` 과 `15` `1B/00` 만 방향 1).

## ルーラ 행선지와 마을 레코드

ルーラ·キメラのつばさ 의 「どこへ」 목록은 `$6165`~`$6169` 의 비트를 셉니다(`10:$9513`). 비트 순번 i 가 서 있으면 목록에 나오고, 고르면 `10:$9612`[i] (5장은 [`0F` + i])가 마을 레코드 번호가 됩니다. 마을에 들어갈 때는 `10:$95C1` 이 맵 그룹 `$63` 을 그룹 목록에서 찾아 그 비트를 켭니다.

| 표 | 내용 |
| --- | --- |
| `10:$95EB` | 1~4장 그룹 목록 14개: `02 12 01 0E 0F 0C 16 05 04 15 17 00 11 0A`, `FF` 로 끝 |
| `10:$95FA` | 5장(`$615A` ≥ 4) 그룹 목록 23개 |
| `10:$9612` | 비트 순번 → 마을 레코드 번호(1~4장 14개, `FF`, 5장 23개) |
| `1E:$AEFE` | 마을 레코드 표의 주소(`$AF00`). 레코드 7바이트: 필드 번호(bit7 = 맵), X, Y, 바이트 3~6. bit7 이면 바이트 3·4 가 맵 그룹·순번 |

1장 필드 세이브스테이트에서 ライアン 소지품에 キメラのつばさ(`56`)를 넣고, `$6165`~`$6167` 에 비트 하나만 켜 쓰게 했습니다. 1~4장 14개, `$615A`=`04` 로 바꾼 5장 23개, 모두 도착한 `$65`/`$42`/`$43` 이 레코드와 같았습니다. 5장 비트 `15`(그룹 `46`, 레코드 `01`, 필드 바이트 `81`)는 맵 `2D/00` (0C,07)에 섰습니다. 목록 첫 화면은 비트 순서대로 「バトランド イムル サントハイム テンペ フレノール」 였습니다.

## 남은 것

- 인물 레코드 `+0B` 의 뜻, `+1B`~`+1D` 가 주문 비트인지(배운 주문 화면과 비교).
- `$618E` bit7 과 아래 3비트 2·3, `$6172`~`$6177` 이 마차 안 자리인지(마차 안 인물을 바꾸는 화면). 2장에서 クリフト·ブライ 가 일행에 들어오는 이벤트가 쓰는 곳.
- `[추정]` 플래그 171개를 화면 장면과 맞추는 것. 이벤트 루틴 138개 각각의 조건.
- 장 끝 루틴이 끄는 `0D`·`0B`·`0A`·`06` 바이트 비트들의 뜻. 엔딩 장면 목록의 「머무는 길이」 단위.
- `$6000` 바이트와 `$6BBF` 서명이 깨졌을 때의 동작.
