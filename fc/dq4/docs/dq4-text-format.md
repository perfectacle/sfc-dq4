# DQ4(FC) 대사 텍스트

FC DQ4 의 대사·내레이션·전투 문구가 롬에 어떻게 들어 있는지입니다. 디코더는 [fc/dq4/tools/dq4text.py](../tools/dq4text.py), 실험 과정은 [2026-10-25-01 일지](../journal/2026-10-25-01-text.md), [2026-10-25-13 일지](../journal/2026-10-25-13-textrest.md), [2026-10-25-22 일지](../journal/2026-10-25-22-textrest2.md), [2026-10-25-26 일지](../journal/2026-10-25-26-textrest3.md) 에 있습니다. 주소 표기는 [dq4-ram-format.md](dq4-ram-format.md) 를 따릅니다.

## 한눈에

- 메시지는 번호(16비트)로 부르고, 32개씩 묶은 **블록**의 시작 위치만 표에 있습니다. 블록 안에서는 앞 메시지를 끝까지 읽어 건너뜁니다.
- 본문은 **6비트 부호**를 3바이트에 4개씩 채운 비트열입니다. 부호를 표로 바꾸면 **글자 바이트**가 되고, 글자 바이트는 그대로 BG 타일 번호(폰트는 CHR `$1000`)입니다.
- 부호 `3C` 는 히라가나·가타카나 표를 바꾸고, `3D`~`3F` 는 뒤 부호와 함께 **사전 단어**(뱅크 `1B`)를 넣습니다.
- 제어 바이트 `ED`~`FF` 는 줄바꿈·버튼 기다림·쉼·소리·이름/숫자 치환입니다. 치환 인자는 메시지 밖 RAM `$F9`~ 에서 옵니다.
- 이름 목록과 메뉴 문구는 같은 글자 바이트를 압축 없이 씁니다. 메뉴 문구 안의 `80` 이상 바이트는 같은 표의 다른 항목(값을 찍는 루틴이나 다른 문구)을 부릅니다.
- 폰트는 `18:$B840` 의 1비트 타일 141개이고, 전원을 켤 때 `18:$B7A3` 이 BG 타일 `00`~`8C` 로 한 번 올립니다. 글자 바이트 = 타일 번호 = CHR `$1000 + 16 × 글자`.
- `fc/dq4/tools/dq4text.py rom export` 가 메시지·창 문자열·이름 목록을 [기호 텍스트](#포팅용-기호-텍스트)(제어 바이트를 `{LINE}` 같은 기호로 바꾼 글)로 내보냅니다. SFC 쪽 제어 코드로 바꾸는 입력입니다.
- 롬 전체에 메시지 2633개(`0000`~`0AE2`, 빈 번호 있음)가 있습니다. 본문은 뱅크 `00`~`04` 와 `1B:$A500`~`$BB93` 에 있고, 바로 뒤 `1B:$BB94` 부터 사전입니다.

## 메시지 번호에서 시작 위치

`16:$8656`(A=번호 아래 바이트, X=위 바이트)이 합니다.

| 단계 | 내용 |
| --- | --- |
| 블록 | `번호 >> 5`. 시작 포인터 = `16:$88B0 + 블록 × 2`(블록 88개) |
| 뱅크 | `16:$8960` 의 `1C 2C 3A 47 53` 과 비교해 블록이 작아지는 첫 순번(0~4). 5 이면 뱅크 `1B` |
| 블록 안 | `번호 & 1F` 개의 메시지를 끝 부호 `39` 까지 읽어 건너뜀(`0F:$DF6D`) |

블록 `05`~`07` 은 블록 `08` 과 포인터가 같아 비어 있고, 블록 `04`, `0F`, `27` 은 32개를 채우지 않습니다(뒤 번호를 읽으면 다음 블록 글이 나옴).

## 6비트 부호

`0F:$DF99` 가 읽습니다. 포인터 `$49/$4A`, 뱅크 `$51`, 단계 `$5E`(4로 나눈 나머지)입니다.

| 단계 | 부호 | 다음 바이트로 |
| --- | --- | --- |
| 0 | 바이트0 bit7-2 | 넘어가지 않음 |
| 1 | 바이트0 bit1-0, 바이트1 bit7-4 | 넘어감 |
| 2 | 바이트1 bit3-0, 바이트2 bit7-6 | 넘어감 |
| 3 | 바이트2 bit5-0 | 넘어감 |

포인터가 `$BFD8` 이 되면 다음 뱅크 `$8000` 으로, 뱅크 `04` 다음은 뱅크 `1B` `$A500` 으로 갑니다(`0F:$DFD5`).

## 부호 → 글자 바이트

`16:$86BA`. 가나 모드 `$0566`(0=히라가나, 1=가타카나)마다 `16:$8765` 의 64바이트 표를 씁니다.

| 부호 | 하는 일 |
| --- | --- |
| `00`~`3B` | 표의 글자 바이트. 결과가 `F0` 이면 사전 0번 단어 |
| `39` | 메시지 끝(표로는 `F9`) |
| `3C` | 가나 모드 바꾸기 |
| `3D`~`3F` + 부호 c | 사전 단어. 그룹 = `(부호 − 3D) × 2 + c bit5`, 그룹 안 순번 = `c & 1F` |

사전은 `16:$87E5` 의 그룹 포인터 6개(뱅크 `1B`, 단어 192개)에서 시작하고, 단어마다 글자 바이트가 `FE` 로 끝납니다. 0번 단어는 `FB 70 6F`(▼＊「)라 가타카나 모드의 `F0` 이 「넘기고 다음 말」을 한 부호로 씁니다. 그 밖에 「なんと」「せかい」「ございま」 같은 자주 쓰는 말과 숫자 0~9 가 들어 있습니다.

### 제어 바이트

`16:$8091` 이 `8D` 이상을 `16:$80AF` 의 처리기 표(`~바이트 × 2`)로 보냅니다. 메시지에 나오는 것은 `ED`~`FF` 뿐입니다. 표는 `fc/dq4/tools/dq4text.py rom controls` 가 처리기 주소·쓰는 메시지 수와 함께 찍습니다.

| 바이트 | 처리기 | 뜻 | 메시지 수 | 근거 |
| --- | --- | --- | --- | --- |
| `ED` | `16:$81BF` | 몬스터 깜빡임. `$0592` 의 몬스터 칸으로 `1E:$8D0D` 를 부름 | 6 | 실측 |
| `EE n` | `16:$8198` | 소리. `n < 40` 이면 소리 `n` 을 내고 끝날 때까지 기다림(`0E` 는 기다리지 않음), `n ≥ 40` 이면 효과음 `n + 40` | 31 | 실측 |
| `EF` | `16:$82D0` | `$0554` 에 준비된 글자열(`FF` 끝)을 그대로 찍음. 메시지를 부르는 쪽이 채움 | 23 | 실측 |
| `F0` | `16:$80F7` | `FC` 와 같음 | 0 | 실측 |
| `F1` | `16:$8175` | 이어지는 줄의 들여쓰기를 0 으로. 메시지 첫 바이트면 자동 `＊「` 도 붙이지 않음(아래) | 154 | 실측 |
| `F2` | `16:$82C3` | 인자 하나를 건너뛰고 `$00/$01` 이 가리키는 길이 붙은 이름(뱅크 `0B`)을 찍음 | 0 | 실측 |
| `F3` | `16:$82B0` | 주문 이름에서 마지막 글자를 뺀 것 | 0 | 실측 |
| `F4` | `16:$80E9` | 30프레임 쉼 | 174 | 실측 |
| `F5` | `16:$82A0` | 주문 이름(인자 = 주문 ID) | 6 | 실측 |
| `F6` | `16:$820A` | 이름. 인자 `n < 80` 이면 동료 `n & 0F`, 아니면 몬스터 칸 `n & 07` 의 이름 뒤에 `(n >> 3) & 0F` 가 0~7 일 때 `Ａ`~`Ｈ`. 변신한 몬스터는 `동료 이름もどき` | 469 | 실측 |
| `F7` | `16:$81FA` | 아이템 이름(인자 = 아이템 ID) | 71 | 실측 |
| `F8` | `16:$81C8` | 숫자. `$FD`~`$FF`(24비트)를 10진으로, 앞 0 은 뺌 | 70 | 실측 |
| `F9` | `16:$8118` | 메시지 끝. 커서가 줄 시작 칸이 아니면 줄을 바꾸고 끝 | 2633 | 앞 일지 |
| `FA` | `16:$8112` | 줄을 바꾸고 끝 | 0 | 실측 |
| `FB` | `16:$810B` | `FC` 처럼 줄을 바꾸고 ▼ 를 깜빡이며 A·B 를 기다림 | 918 | 화면 |
| `FC` | `16:$80F7` | 줄바꿈. 커서가 줄 시작 칸(`$55`)이면 바꾸지 않음 | 1980 | 코드 읽기, 화면 |
| `FD` | `16:$8104` | 언제나 줄을 바꾸고 ▼ 기다림 | 0 | 실측 |
| `FE` | `16:$80F1` | 언제나 줄바꿈 | 1 | 실측 |
| `FF` | `16:$80D5` | 끝. 줄바꿈도 `。` 도 없음 | 20 | 실측 |

가타카나 모드의 부호 `39` 는 `F9` 가 아니라 `FA` 로 바뀝니다(`16:$8765` 표의 뒤 64바이트). 끝 부호는 모드와 상관없이 `39` 라 메시지 경계는 그대로입니다.

치환 제어(`F2`, `F3`, `F5`, `F6`, `F7`)는 인자를 메시지 안이 아니라 RAM `$F9` 부터의 인자 목록에서 하나씩 꺼냅니다(`16:$82E9`, 순번 `$5B`). 메시지를 부르는 쪽이 `$F9`~ 를 채우고, 숫자는 `$FD`~`$FF` 에 둡니다. 글자는 `$0554` 에 `FF` 끝으로 만든 뒤 한 글자씩 보통 글자처럼 찍습니다. 이름은 [이름 목록](dq4-data-format.md#이름-목록)(뱅크 `0B`, 길이 붙은 글자 바이트)에서 꺼내고(`16:$82F0`), ID 는 목록 순번 − 1 입니다. 동료 이름은 `BRK 2A 53`(뱅크 `10` 함수 `05`)이 `$72`~`$75` 에 4글자로 둡니다.

`F6` 의 몬스터 쪽은 `$6E45 + 칸` 의 몬스터 ID 로 이름을 찾습니다. 그 전에 `BRK 29 C3 0C`(뱅크 `10` 함수 `24`)가 그 몬스터의 전투 레코드 바이트 6(칸 0 은 `$727A`) bit4 를 보고, 켜져 있으면 `BRK 67 73` 이 돌려준 동료의 이름에 `もどき`(`2D 3D 1E 11`)를 붙입니다. 이때는 `Ａ`~`Ｈ` 를 붙이지 않습니다. 전투에서 이 비트를 RAM 에 써 넣으니 대사와 몬스터 목록 창 모두 `ライアンもどき` 로 바뀌었습니다. 이 비트를 켜는 것은 주문 `27`(`モシャス`)입니다. 전투 행동은 `11:$8C78` 이 `BRK 03 1F` 가 돌려준 행동 번호로 표 `11:$A3FA` 의 루틴에 뛰고, 첨자 `27` 의 루틴 `11:$9DA4` 가 `BRK 2A C3 0C`(명령 `2A` = 비트 켜기)로 행동한 몬스터의 바이트 6 bit4 를 켭니다. 첨자 `00`~`3B` 가 주문 ID 와 같은 순서로 보이는 것(공격 주문 `00`~`12` 가 모두 `11:$9AD2`)은 코드 읽기입니다. 끄는 `BRK 2B C3 0C` 는 `11:$B114`(행동 `A6` 등의 루틴이 부름, 코드 읽기)에 있습니다.

메시지 끝 `F9` 앞 글자가 `！ ？ 。` 나 제어 `FB FE F4 FF` 가 아니면, 게임이 `。` 를 붙여 찍습니다(`16:$805A`). 디코더는 화면에 나오는 대로 붙여 보여 줍니다.

## 창에 찍는 흐름

`16:$8028`(뱅크 `16` 함수 `04`)이 메시지 하나를 찍습니다: `16:$8656`(시작 위치) → `16:$85C5`(앞 8글자 미리 읽기) → `16:$8036`(한 글자씩).

| 항목 | 내용 | 근거 |
| --- | --- | --- |
| 자동 `＊「` | `$058B ≥ 5`(왕에게 말을 걸 때 `06`)이고 첫 바이트가 `F1` 이 아니면 `70 6F` 를 앞에 넣고 들여쓰기 3 | `16:$85C5`. 메시지 `060A`(본문은 `そなたの…`)가 화면에 `＊「そなたの…` 로 나옴 |
| 들여쓰기 | 줄이 시작될 때 앞 8글자 안에 `「`(`6F`)가 끝 계열 제어(`F9 FA FB FD FF`)보다 먼저 있으면 그 뒤 줄들을 2칸 들여씀, 없으면 0 | `16:$85FF`, `16:$817A`. `＊「` 뒤 `FC` 가 줄을 바꾸지 않는 까닭도 이것(커서 2 = 들여쓰기 2) |
| 줄 폭 | 커서 `$0551` 이 `$54` 에 닿으면 저절로 다음 줄. 필드 창 `$54 = 16`(22칸), 전투 창 `18`(24칸) | `16:$838B` 코드 읽기, RAM 덤프. 메시지 본문에 22칸을 넘는 줄은 전투 문구(23~24칸) 10개뿐 |
| 줄 수 | 4줄. 줄 번호 `$0552` 는 1·3·5·7(글자 행 순번)로 2씩 늘고 `09` 가 되면 한 줄 올려 `07` 로 | `16:$83B0`, 창 줄 버퍼 덤프(아래) |
| 글자 소리 | 공백·`＊`·`「`·`…` 이 아닌 글자마다 `BRK 96 FB`(효과음 `96`) | `16:$8373`, 실측(글자마다 `1F:$C01F` 에 A=`96`) |

## 창 문자열 표

`16:$A572` 는 그룹 2개의 항목 포인터 표 주소(`$A578`, `$A674`)이고, 바로 뒤 `16:$A576` 의 `70 14` 가 그룹마다 루틴 항목의 끝(항목 번호 × 2)입니다. 항목 하나는 포인터 하나이고 길이는 다음 항목 포인터까지입니다. `fc/dq4/tools/dq4text.py rom windows` 가 모두 찍습니다.

| 그룹 | 항목 | 내용 |
| --- | --- | --- |
| 0(`$A578`) | `00`~`37` 루틴, `38`~`7D` 문자열 | 필드 명령 창·つよさ 창·전투 명령 창·전투 몬스터 목록 등. 루틴은 값(골드, 성별, 레벨, 능력치, 몬스터 이름·마릿수)을 찍음 |
| 1(`$A674`) | `00`~`09` 루틴, `0A`~`30` 문자열 | 타이틀의 모험의 서 메뉴(`ぼうけんをする`, `ぼうけんのしょをうつす` …), 장 5 전투의 `たたかう`·`さくせん`·`いれかえ`, 동료 이름 |

`16:$9783` 이 항목 하나를 찍습니다(A = 항목 번호, 그룹은 `$03D6`). 루틴 항목이면 그 주소로 뛰고, 문자열이면 한 바이트씩 `16:$9810` 으로 찍습니다. 문자열 안의 `80` 이상 바이트 `b` 는 같은 그룹의 항목 `b & 7F` 를 부릅니다(`16:$97B0`).

| `b & 7F` | 하는 일 | 예 |
| --- | --- | --- |
| 루틴 항목 | 그 자리에서 루틴을 부름(값 찍기) | 항목 `44` `18 0C 3D 27 1C 71 84` = `せいべつ：` + 루틴 `04`(`16:$AB29`) → 화면 `せいべつ：おとこ` |
| 문자열 항목 | 그 문자열을 끼워 찍음. 끼운 문자열 안의 `80` 이상은 건너뜀(한 단계만) | 항목 `41` `BB 37 2A 33` = 항목 `3B`(`つよさ`) + `をみる` → `つよさをみる`. 항목 `4F` `D4 71 90` = 항목 `54`(`こうげきカ`) + `：` + 루틴 `10` |

창 틀(테두리)·위치는 이 표에 없고 각 창을 여는 코드가 정합니다(남은 것).

## 폰트

글자 바이트 `00`~`8C` 의 타일(141개)은 PRG `18:$B840` 에 글자마다 8바이트(1비트 평면 하나)로 있습니다. CHR `$1000 + 글자 × 16` 의 앞 8바이트가 이 값이고 뒤 8바이트(둘째 평면)는 0 입니다. 왕좌의 방 대사, 전투, 명령 창, 이름 입력의 CHR 덤프에서 141개가 모두 같았습니다. 뒤 `18:$BCF8`~ 는 라틴 대문자 모양의 다른 글꼴로, 부팅 101~160프레임(타이틀 무렵)에 `$C3EA` 로 읽힙니다.

| 단계 | 값 | 근거 |
| --- | --- | --- |
| 글자 → 타일 번호 | 글자 바이트 그대로 BG 타일 번호(`00`~`8C`) | 화면, 창 줄 버퍼 |
| 타일 번호 → CHR 주소 | `$1000 + 16 × 타일`(BG 패턴 표 `$1000`) | CHR 쓰기 기록 |
| CHR ← PRG | 타일 `00` 은 0 16바이트, 타일 `g`(1~`8C`)는 `18:$B840 + 8g` 의 8바이트 + 0 8바이트 | 아래 루틴, CHR `$10B0`(글자 `0B` あ)에 쓴 8바이트가 `18:$B898` 과 같음 |

폰트를 올리는 루틴은 뱅크 `18` 함수 `08`(`18:$B7A3`)입니다. `$2006` 에 `$1000` 을 쓰고, 타일 `00` 자리에 0 을 16바이트, 이어서 `$B848` 부터 140타일을 `0F:$C888`(`LDA ($00,X)` 로 한 바이트씩)로 읽어 8바이트 + 0 8바이트씩 `$2007` 에 씁니다. 함수 `0C`(`18:$B7A9`)는 같은 코드로 `$BCA8` 부터 36타일(라틴 글꼴)을 올립니다.

| 장면 | `18:$B7A3` 을 부른 곳 | 확인 |
| --- | --- | --- |
| 전원 직후 | `1A:$802E` `BRK 08 8F` | CHR `$10B0` 쓰기, BRK 기록 |
| 타이틀 화면이 BG 를 지운 뒤 | `1A:$8088` `BRK 08 8F`(`1E:$A372` `BRK 02 AF` 에서) | 같음 |
| 왕좌의 방 대화·つよさ 창, 성 앞 → 필드, 필드 보행·전투 들어가기 | 부르지 않음 | CHR `$1000`~`$18CF` 쓰기 0번 |

롬에는 `BRK 08 8F` 가 `1C:$94CD`, `1D:$8E23`, `1E:$A362` 에도 있습니다(실행은 못 봄). 전투에 들어가면 몬스터 그림이 BG 타일 `8D` 부터(`$18D0`~) 올라가므로 대사 창과 몬스터 그림이 같은 BG 패턴 표를 나눠 씁니다. 필드에서 걷다 만난 はさみくわがた 1마리 전투에서는 `$18D0`~`$1B9F`(타일 `8D`~`B9`)를 썼습니다.

CHR 은 RAM(8KB)이라 폰트를 바꾸려면 PRG 의 이 자리를 고치면 됩니다. 글자 바이트 `8D` 이상은 `16:$8091` 이 제어 처리기로 보내므로, 대사 창에 글자로 찍을 수 있는 타일 번호는 `00`~`8C` 141개가 전부입니다.

- 인자 칸 k 는 RAM `$F9 + k` 입니다. 칸 순번 `$5B` 는 메시지를 찍을 때마다 `16:$8596` 이 0 으로 두고 `F2 F3 F5 F6 F7` 이 하나씩 씁니다(코드 읽기, `textforce.lua` 실측과 맞음). 그래서 k 는 메시지 안에서 이 다섯 기호의 순번입니다.
- 글자는 [글자 바이트](#글자-바이트) 표의 유니코드 글자이고, 탁점·반탁점(`3D`·`3E`) + 글자는 합친 글자 하나로 씁니다. 탁점 글자 타일 `65`~`69`(ドじだどぶ)와 겹치므로 한쪽만 맨 글자로 둡니다. 롬은 `ド` 를 대개 타일 `65` 로(메시지 719번, 이름 116번), `じだどぶ` 는 메시지·이름에서 언제나 탁점으로 씁니다. 그래서 `ド` 는 타일 `65`, `3D 4E` 는 `{3D}ト`, 타일 `66`~`69`(창 문자열에 `だ`·`ど` 6번)는 `{66}`~`{69}` 입니다.
- 표에 없는 바이트는 `{XX}`(16진)입니다. 롬의 메시지·창·이름에는 나오지 않습니다.
- 창 문자열의 `80` 이상 바이트는 `{CALL:nn}`(루틴 항목 nn, 값 찍기)과 `{INS:nn}`(문자열 항목 nn 끼워 넣기)입니다.
- `auto_quote` 는 첫 바이트가 `F1` 이 아니라 `$058B ≥ 5` 인 대화에서 `＊「` 가 붙을 수 있다는 뜻입니다. 실제로 붙는지는 부르는 쪽의 `$058B` 가 정합니다. `auto_period` 는 끝 `{END}` 앞에 게임이 `。` 를 넣는다는 뜻입니다. `sym` 에는 둘 다 넣지 않고 `text` 에는 `。` 만 넣습니다.

`export --check` 는 파일을 쓰지 않고 세 가지를 봅니다. 기호 텍스트를 바이트로 되돌린 것이 `bytes` 와 같은지, `codes` 를 풀어 `bytes` 가 되는지, `codes` 를 롬과 같은 순서로 비트에 채운 것이 시작 자리부터의 롬 바이트와 같은지(뱅크를 넘는 메시지 포함)입니다. 메시지 2633개, 창 문자열 109개, 이름 434개가 모두 같았습니다. 기호 하나를 고치거나 부호 한 비트를 바꾸면 그 행을 다르다고 냅니다.

## 대사 창 줄 버퍼

글자는 RAM `$06AA` 부터 4줄짜리 버퍼(`$C0` 바이트, `16:$862B` 가 지움)에 들어갑니다. 줄마다 탁점 행과 글자 행이 창 폭(`$54`) 바이트씩 이어집니다. 글자 칸 = `$0552 × $54 + $0551`(`16:$85B3`), 탁점·반탁점은 그 `$54` 바이트 앞 칸(`16:$831F`)입니다.

| 창 | `$54` | 한 행 | 디코더가 읽는 곳 |
| --- | --- | --- | --- |
| 필드 | `16` | 22바이트 | 창 줄 버퍼. 대사가 끝나 다른 창이 열리면 `$54` 가 그 창 값(`0F` 등)으로 바뀌므로 22칸으로 고정 |
| 전투 | `18` | 24바이트 | nametable. 글자 행 = `$0552 + 13`, 탁점 행은 그 윗행, 열은 `$53`(`16:$8362`, `16:$8335`) |

전투 창은 메시지마다 버퍼를 지우지 않고 첫 줄부터 덮어씁니다. 그래서 버퍼에는 지난 메시지의 탁점과 뒷줄이 남습니다(예: `おおみみずの　こうげき！` 의 `う` 위에 앞 메시지 `ライアンの　こうげき！` 의 `げ` 탁점). 화면은 메시지마다 창을 지우고 글자마다 nametable 에 바로 찍으므로 이것이 보이지 않습니다. `fc/dq4/tools/dq4text.py MSG --compare end.ram` 은 `$54 = 18` 이고 옆에 `end.nt` 가 있으면 nametable 에서 읽고, 명령 창이 그 자리를 덮었으면(틀 타일 `80` 이상) 비교하지 않습니다.

## 확인

- 오프닝 내레이션·왕의 연설을 A 를 한 번씩 눌러 가며 RAM 을 10번 덤프: `fc/dq4/tools/dq4text.py MSG --compare end.ram` 으로 창 줄 버퍼의 모든 줄(28줄)이 메시지 `0300`~`0302` 에 순서대로 있음.

- 제어 바이트: `fc/dq4/tools/lua/textforce.lua` 로 왕좌의 방에서 왕에게 말을 건 순간 `16:$8656` 의 X:A 를 바꾸고 인자(`$F9`~, `$FD`~, `$0554`~)를 써서 띄움. 창 줄 버퍼에 나온 글은 아래와 같음.

- `FE`: `0466`(첫 바이트 `FE`)은 창 둘째 줄부터 찍힘. `FF`: `0007` 이 `。` 없이 끝남.
