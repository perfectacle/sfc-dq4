# DQ4(FC) 필드 인물·탈것 그림과 전투 몬스터 그림

FC 원작의 필드 인물(일행·마을 사람·탈것)과 전투 몬스터 그림을 롬에서 그대로 뽑는 방법입니다. SFC DQ5 규격으로 스프라이트를 새로 그릴 때 원작을 옆에 놓고 보는 참조용입니다. 디코더·열람 도구는 [fc/dq4/tools/dq4fcsprite.py](../tools/dq4fcsprite.py), 전투 덤프용 프로브는 [fc/dq4/tools/lua/spritebattle.lua](../tools/lua/spritebattle.lua) 이고, 찾아낸 과정은 [2026-10-25-29 일지](../journal/2026-10-25-29-fcsprite.md) 에 있습니다.

주소 표기는 `뱅크:$주소` 입니다. 근거 표시가 없는 것은 MesenCE 덤프와 디코더 결과가 같음을 확인한 것이고, 「코드 읽기」 는 리스팅만 읽은 것입니다. 롬에서 뽑은 그림은 저작권 데이터라 `work/` 에만 두고 커밋하지 않습니다.

## 쓰는 법

```sh
uv run --locked python fc/dq4/tools/dq4fcsprite.py rom/dq4.nes sheet          # 전부 만들고 work/dq4-fcsprite/index.html 로 묶음
uv run --locked python fc/dq4/tools/dq4fcsprite.py rom/dq4.nes field 11       # 그림 번호 11(병사)의 PNG·색 번호 행렬
uv run --locked python fc/dq4/tools/dq4fcsprite.py rom/dq4.nes monster 30     # 몬스터 ID 30(キングスライム)
uv run --locked python fc/dq4/tools/dq4fcsprite.py rom/dq4.nes who 11         # 그림 번호 11 을 쓰는 맵·인물(슬롯, 자리, 대화 번호)
```

| 출력(`work/dq4-fcsprite/`) | 내용 |
| --- | --- |
| `field/MM.png`, `field/MM-x8.png` | 필드 그림 표 MM 의 시트 32×64(1배)와 8배. 행은 남·서·동·북, 열은 걸음 0·1(칸마다 16×16). 색 번호 0 은 투명 |
| `field/MMr.*` | 같은 표를 돌려 그리기(그림 번호 bit7)로 쓴 것. 인물 레코드가 쓰는 것만 |
| `field/MM.txt` | 칸마다 색 번호 행렬(`.` 투명, `1`~`3` 은 OBJ 팔레트 안 번호)과 OBJ 팔레트 번호, 시트 PNG 의 색 번호 → NES 색 |
| `monster/II.png`, `II-x8.png`, `II.txt` | 몬스터 ID II 의 그림(그림 크기 그대로), 8배, 색 번호 행렬(색 번호 → NES 색, BG·OBJ 팔레트) |
| `index.html`, `sheet-field.png`, `sheet-monster.png` | 필드 그림 143개와 몬스터 195종을 이름·번호와 한 페이지로. 로컬 파일만 참조 |

PNG 는 팔레트 모드이고 색 번호 0 이 투명입니다. 같은 NES 색은 한 번호로 합칩니다. RGB 는 [fc/dq4/tools/dq4block.py](../tools/dq4block.py) 의 `nes_rgb` 근사라 에뮬레이터 화면과 조금 다릅니다. 정확한 색은 `.txt` 의 NES 색 번호로 봅니다. 8배 PNG 는 [sprites 스킬](../../../.agents/skills/sprites/SKILL.md)의 「같은 배율로 견주기」에 그대로 씁니다.

## 필드 그림

### 흐름

| 단계 | 루틴 | 결과 |
| --- | --- | --- |
| 그림 하나 올리기 | `08:$85D3`(BRK `04 87`) | 그림 번호 A 를 받아 블록 8개를 CHR `$0000` 과 표 `$7200` 에 |
| 번호 → 표 번호 | `08:$859B` | 아래 7비트가 `53` 이상이면 −`0B`, `48`~`4F` 는 일행 `0`~`7`. bit7 은 [돌려 그리기](#돌려-그리기). `0` 이고 `$62A5` bit7 이 켜져 있고 `$615C` bit0 이면 `8`(코드 읽기) |
| 일행 | `1E:$9648`(BRK `0B 87`) | `$7200` 칸 0~3. 그림 번호 = 걷는 일행의 인물 레코드 번호. 빈 칸은 `0E` |
| 맵 인물 | `1C:$9A37` | 그림 표 `$6E5E` 칸 i → `$7200` 칸 i + 4([dq4-script-format.md](dq4-script-format.md#그림과-움직임)) |
| 필드 탈것 | `1E:$9799` | `1E:$97AE` 의 10개(`09 0A 0B 0D 0C 64 65 63 6B 6A`)를 칸 4~D 에 |
| OBJ 팔레트 | `08:$86F2`(BRK `07 87`) | `08:$8703` 의 12바이트(`FF` 끝)를 `$0609` 로. 팔레트 0~3 의 색 1~3 |
| 화면 | `0F:$D7E4`·`$D869` | 인물 슬롯 k 의 블록 = (`$7000`+k 아래 2비트) × 2 + (`$0526` bit7) |

### 그림 표

`08:$8649` 의 워드(`$979B`)부터 표 번호마다 24바이트, 3바이트 레코드 8개입니다. 표는 `08:$A1BB`(블록 모양 표) 앞에서 끝나 108개(`00`~`6B`)입니다. 레코드 j 가 블록 j 이고, 블록 = 방향 × 2 + 걸음입니다. 방향은 `$7000` 과 같은 0 위, 1 오른쪽, 2 아래, 3 왼쪽입니다.

| 바이트 | 비트 | 뜻 |
| --- | --- | --- |
| 0 | 7-0 | CHR 번호 하위 8비트 |
| 1 | 7-4 | 타일 0~3(왼위, 오른위, 왼아래, 오른아래)의 좌우 반전. bit7 이 타일 0 |
| 1 | 2 | 그림 뱅크. 0 이면 `0D`(타일 0 = `$B304`), 1 이면 `0E`(`$8095`). 기준 주소는 `08:$8231` |
| 1 | 1-0 | CHR 번호 상위 2비트 |
| 2 | 7-2 | 모양. 타일 0 = 기준 + CHR 번호 × 16, 타일 1~3 은 `08:$8239` 의 포인터(`$A1D0`) + 모양 × 3 의 부호 있는 바이트 × 16 만큼 앞 타일에서 떨어짐. `3F` 는 다른 경로(`08:$81C6`)지만 표에는 없음 |
| 2 | 1-0 | OBJ 팔레트(블록 4타일 공통) |

그림은 압축 없는 2bpp 16바이트 타일입니다. 올릴 때 같은 그림 주소는 한 그림 안에서 다시 올리지 않고 먼저 붙인 타일 번호를 씁니다(`08:$8254`, 목록 `$7700`, 뱅크는 비교하지 않음). `$7200` + 칸 × 64 에 블록마다 (타일 번호, 속성) 4쌍이 들어갑니다. 속성은 상하 반전 bit7, 좌우 반전 bit6, 팔레트 bit1-0 입니다.

일행 그림 번호와 인물: `0` 勇者, `1` クリフト, `2` ミネア, `3` マーニャ, `4` ブライ, `5` トルネコ, `6` ライアン, `7` アリーナ, `8` 여자 勇者(`0` 과 같은 CHR 번호를 뱅크 `0E` 에서). 덤프로 확인한 것은 `0`·`1`·`2`·`3`·`5`·`6`·`7` 입니다. 표 `09` 말, `0A` 마차, `0B` 배, `0C` 기구, `0E` 관은 그림을 보고 붙인 이름입니다.

### 돌려 그리기

그림 번호 bit7(인물 레코드 바이트 1 bit6, 밤은 bit5)이 켜져 있으면 레코드 4(아래쪽 걸음 0) 하나로 8블록을 모두 만듭니다(`08:$8618`). 방향 k 의 두 블록은 같고, 레코드 4 를 시계 방향으로 k × 90° 돌린 그림입니다.

- 4타일 자리: 새 [0, 1, 2, 3] = 옛 [2, 0, 3, 1](../../../docs/`08:$8981`), 반전 비트도 같이 옮김(`08:$82D2`).
- 타일 그림: 8×8 을 시계 방향으로 돌림(`08:$89C9`).
- k 가 홀수면 옮긴 반전 비트가 상하 반전으로, 짝수면 좌우 반전으로 들어감(`08:$82F6`).
- 방향마다 같은 주소 목록을 비우고 새 타일을 받음(`$79`·`$04` 를 되돌림).

그림으로는 쓰러진 사람처럼 눕힌 모습입니다. 인물 레코드가 쓰는 돌려 그리기는 35가지입니다(보통 목록·진행 목록, 낮·밤).

## 전투 몬스터 그림

### 흐름

`14:$812F` 가 무리 4칸(`$6E45`~`$6E48`)마다 몬스터 ID 를 그림 번호로 바꾸고(`14:$9F0C`: `14:$B2D5` + ID), 팔레트를 맞춘 뒤(`14:$9439`·`$93F2`·`$946E`) 타일을 CHR 에 올리고(`14:$969C`), 마리마다 자리를 정해 nametable·OAM 에 놓습니다(`14:$9822`).

몬스터 195종의 그림 번호는 194가지(`00`~`C1`, キングレオ `BB`·`BE` 가 같음)입니다. 그림 레코드 194개가 가리키는 데이터는 71가지이고, 나머지는 같은 데이터에 팔레트만 다른 것입니다.

### 그림 레코드

`14:$A019` 의 워드가 가리키는 곳 + 그림 번호 × 5(`14:$9FA9`).

| 바이트 | 뜻 |
| --- | --- |
| 0 | 타일 수 |
| 1-2 | 데이터 주소(아래 뱅크의 `$8000`~) |
| 3-4 | 팔레트 주소(뱅크 `14`) |

데이터 뱅크(`14:$9F26`): 그림 `14`·`2E`·`3F`·`B2`·`C0` 은 뱅크 `14`, `B1` 은 `10`, 나머지는 `14:$B398` + 번호 >> 3 바이트의 bit(7 − 번호 & 7)이 1 이면 `07`, 0 이면 `06` 입니다. 그림 수는 `06` 124, `07` 64, `14` 5, `10` 1 입니다.

### 타일 데이터

타일마다 배치 몇 개와 그림 16바이트가 이어집니다(`14:$9712`·`$9783`·`$98F5`·`$9FEB`).

| 머리 바이트 H | 뜻 |
| --- | --- |
| bit7 | 이 타일의 마지막 배치 |
| bit6 | 1 이면 BG(뒤에 자리 1바이트 = 행 << 4 \| 열), 0 이면 OBJ(뒤에 x, y 2바이트) |
| bit5-4 | 팔레트(그 그림의 BG 또는 OBJ 팔레트 순번) |
| bit2, bit1 | 상하 반전, 좌우 반전 |
| bit3 | (마지막 배치에서) 그림 압축 |
| bit0 | (압축일 때) 채움 바이트 있음 |

그림: bit3 이 0 이면 16바이트 그대로. 1 이면 [채움 바이트] + 마스크 2바이트(둘째가 위 8비트) + 마스크가 1 인 자리의 바이트만. 위 비트부터 16자리이고, 0 인 자리는 채움 바이트(없으면 0)입니다.

- BG 배치는 반전한 그림을 따로 만들어 BG 패턴 `$1000` + 번호 × 16 에 `8D` 부터 차례로 올립니다(쓴 반전 종류마다 한 장). 한 마리의 그림은 16×16 타일 칸이고, nametable 에서는 그림 0행이 10행(エスターク·デスピサロ 는 8행)입니다. 가로 자리는 무리 수에 따라 `14:$9C71` 이 정합니다.
- OBJ 배치는 OBJ 패턴 `$0000` 에 한 장 올리고 OAM 반전 비트로 그립니다. OAM x = (x + 그림 왼쪽 열 × 8) & `FF`, y = (y + `4F`) & `FF` 라, 그림 기준으로는 x·y 가 부호 있는 바이트이고 화면에서는 BG 0행보다 y 만큼 아래입니다(`14:$9950`).

### 팔레트

팔레트 주소의 첫 바이트가 위 4비트 = BG 팔레트 수, 아래 4비트 = OBJ 팔레트 수이고, 뒤에 3바이트(색 1~3) 묶음이 OBJ 팔레트, BG 팔레트 순으로 있습니다(`14:$9557`·`$9593`). 배치의 팔레트 순번이 이 목록을 가리킵니다. 게임은 여러 무리의 팔레트를 화면 팔레트 4칸에 나눠 넣고(`$0444`·`$0448` 에 순번 → 칸) 같은 색 묶음은 함께 씁니다. 그래서 화면 팔레트 번호는 전투마다 다르지만 픽셀의 NES 색은 같습니다. 색 0 은 BG 가 `0F`(검정), OBJ 는 투명입니다.

## SFC 쪽에서 참조할 때

| 항목 | FC 원작 | 참고 |
| --- | --- | --- |
| 필드 인물 크기 | 16×16(8×8 OBJ 2×2). DQ5 는 16×24 상자에 실제 14×17 | 비율이 다르므로 복장·색 배치만 옮긴다([dq4-sprite-format.md](../../../sfc/dq4/docs/dq4-sprite-format.md)) |
| 필드 인물 색 | OBJ 팔레트 하나의 3색 + 투명. 팔레트 4개를 모든 인물이 함께 씀(`08:$8703`) | 윤곽 전용 색이 없다. DQ5 는 투명 빼고 8~12색 |
| 걸음 | 방향마다 2프레임, 블록 전체가 바뀜. 모든 인물이 `$0526` bit7 에 맞춰 같이 걷는다 | DQ5 는 머리 고정, 몸만 바뀜 |
| 좌우 | 정면·뒷면은 왼쪽 반을 반전한 타일이 많고, 서쪽은 동쪽을 반전한 그림이 많다(레코드의 반전 비트) | 반전이 아닌 그림도 있으니 표 그대로 본다 |
| 몬스터 | BG 2bpp, 16×16 픽셀마다 BG 팔레트 하나(3색 + 검정), 일부는 OBJ 부품이 위에 겹침 | 그림 영역이 128×64 안팎(エスターク 는 10행). 배경이 검정이라 검정 윤곽이 투명으로 나온다 |
| 팔레트 바꿈 | 그림 194개 중 데이터는 71가지 | 같은 데이터의 팔레트만 바꾼 몬스터는 SFC 에서도 한 그림에 팔레트만 바꿔 쓸 수 있다 |

## 확인

| 실험 | 결과 |
| --- | --- |
| 워프 33곳 + 1장 왕좌의 방 + 2~5장 시작 + 디버그 「シナリオ」 B(8명 일행) + 필드 걷기 4방향, 덤프 43개(`check-field`) | 그림 번호 105가지(표 82개, 돌려 그리기 19가지)의 `$7200` 64바이트가 같음(443칸 중 442칸), CHR 타일 6183장 중 6182장이 같음, 화면 OAM 2×2 묶음 131개 픽셀 33536개 모두 같음, 방향 100번 같음, OBJ 팔레트 43개 모두 같음. 다른 1칸은 아래 |
| 주인공을 필드에서 네 방향으로 걷게 함 | `$7000` = `40`·`41`·`42`·`43` 일 때 블록 0·2·4·6 |
| `check-rom`: 그림 194개를 위 규칙으로 끝까지 읽음 | 데이터 71가지 사이 경계 67곳 중 66곳에서 끝 = 같은 뱅크의 다음 시작. `06:$9D2F`~`$9D34` 6바이트(`88 1C 2D 80 00 7E`)는 어느 그림도 읽지 않음 |
| `spritebattle.lua` 로 고른 무리와 전투 20번(`check-monster`) | 몬스터 26종(그림 26가지, 뱅크 `06`·`07`·`10`·`14` 모두, OBJ 부품·여러 무리·エスターク 포함)의 픽셀 22164개가 NES 색까지 모두 같음 |

4장 시작 세이브스테이트의 칸 5(그림 `3A`)는 `$7200` 이 모두 타일 `78`(빈 타일)로 채워져 있었습니다. 이 칸을 쓰는 인물 넷은 모두 숨은 인물(`$6F60` = `80`)입니다. 같은 맵을 1장에서 새로 읽으면 `3A` 가 없어 비교하지 못했습니다.

방향 비교는 그 칸을 쓰는 보이는 인물이 모두 같은 방향일 때만 합니다. `$7000` bit7 인 인물(`$7040` = `88` 처럼 걷는 인물)이 있으면 OAM 을 만든 뒤 방향이 바뀔 수 있어 뺍니다. 처음에는 이 둘을 빼지 않아 2번 어긋났습니다.

```sh
export MESENCE=/path/to/MesenCE LIBDIR=$(uv run --locked krpatch fc lua)
fc/dq4/tools/dq4warp.sh work/dq4-fcsprite/w-0E-00 0E/00                    # 맵 덤프(end.*)
uv run --locked python fc/dq4/tools/dq4fcsprite.py rom/dq4.nes check-field work/dq4-fcsprite/w-0E-00
d=$PWD/work/dq4-fcsprite/bt-67; mkdir -p $d
STATE=$PWD/work/state/dq4-ch1-field.mss MON="67:1" WAIT=360 SHOT_DIR=$d \
  "$MESENCE" --testrunner --nes.ramPowerOnState=AllZeros "$PWD/rom/dq4.nes" "$PWD/fc/dq4/tools/lua/spritebattle.lua"
uv run --locked python fc/dq4/tools/dq4fcsprite.py rom/dq4.nes check-monster $d
```
