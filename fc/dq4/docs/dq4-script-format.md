# DQ4(FC) 인물 대화 스크립트

마을·성의 인물에게 말을 걸었을 때 어떤 메시지가 나올지 정하는 대화 번호와 대화 스크립트입니다. 디코더는 [fc/dq4/tools/dq4talk.py](../tools/dq4talk.py), 실측 프로브는 [fc/dq4/tools/lua/talk.lua](../tools/lua/talk.lua), 실험 과정은 [2026-10-25-09 일지](../journal/2026-10-25-09-talk.md), [2026-10-25-19 일지](../journal/2026-10-25-19-talk2.md), [2026-10-25-28 일지](../journal/2026-10-25-28-talk3.md) 에 있습니다. 해석기와 스크립트는 모두 뱅크 `15` 에 있고, 주소는 그 뱅크의 CPU 주소입니다. 인물 레코드는 [dq4-map-format.md](dq4-map-format.md#인물), 메시지 번호는 [dq4-text-format.md](dq4-text-format.md) 와 같습니다.

근거를 「실측」과 「코드 읽기」로 나눴습니다. 실측은 게임이 낸 메시지 번호와 디코더 예측을 맞춘 것입니다. 맵 6곳의 낮·밤 인물에게 말을 걸고, 일행·소지품·장·시간을 RAM 으로 만들어 대화 번호를 바꿔 넣은 스크립트를 돌렸습니다([확인](#확인)). 지금 `compare` 는 롬과 RAM 덤프만으로 모든 조건을 풀고, 프로브가 기록한 조건 결과를 빌리지 않습니다.

## 흐름

말 걸기(「はなす」)로 앞 칸에 인물이 있으면 `15:$98F8` 에 A = 인물 슬롯(6~), Y = 말 건 자리 값으로 들어옵니다. 앞에 아무도 없으면 이 루틴을 지나지 않고 메시지 `02F0`(そのほうこうには　だれもいない。)이 나옵니다. 기둥·장식처럼 인물 표에 있지만 말할 수 없는 것은 대화 번호 `008`(스크립트가 메시지 `02F0` 하나)입니다.

1. `$9925`: `$E9` = Y, `$E8` = 슬롯. Y 는 카운터 너머(두 칸 앞)에서 말 걸면 `00`, 바로 앞이면 `22` 였습니다(실측, 12/00 여관 주인).
2. 대화 번호: `1C:$96C7`(BRK 뱅크 1C 함수 01)이 슬롯의 인물 레코드에서 [대화 번호](#대화-번호)를 꺼내 `$00`(아래)·`$01`(위)에 둡니다.
3. `$9962` 가 대화 번호로 갈래를 고릅니다.

| 대화 번호 | 하는 일 | 근거 |
| --- | --- | --- |
| `000`~`006` | [서비스](#서비스): `$9CBF` 에 A = 번호 | 실측: A = 0~6 |
| `007`~`160` | 스크립트 346개. 시작 주소는 `$98F6` 의 워드가 가리키는 `$9642` + 2×(번호 − 7) | 실측 |
| `161`~`178` | 예/아니오: 메시지 m = 번호 − `161` + `500` 을 내고 예/아니오 창, 「はい」 면 m+1, 「いいえ」 면 m+2(`$9C92`) | 실측: `161` → `0500`, `0501`/`0502` |
| `179`~ | 메시지 하나: 번호 − `161` + `500` | 실측 |

메시지는 `$9919` 에서 BRK 뱅크 16 함수 04 로 나가고, 그 안에서 `16:$8656`(X:A = 메시지 번호)을 지납니다.

| 1 | `$B84A` | 무기점 | 실측 |
| 2 | `$B858` | 도구점 | 실측 |
| 3 | `$B851` | 방어구점 | 실측 |
| 4 | `$BBF0` | 맡기는 곳(`0238` 「もちものと　おかねの　あずかりじょです」) | 실측: 대화 번호를 `004` 로 바꿔. 쓰는 인물은 04/00 ネネ(대화 `075`, 5장 카운터 너머) 하나 |
| 6 | `$BF28` | 여관 | 실측 |

## 대화 번호

인물 레코드에서 `1C:$96C7` 이 꺼냅니다. 슬롯 k 는 목록에서 지금 시간에 나오는 레코드만 센 k−6 번째입니다(`1C:$96FC`·`$9798`): 낮(`$62ED` < `78`)은 F bit4, 밤은 F bit3 인 레코드. 레코드의 F·머리·덧붙은 바이트는 [dq4-map-format.md](dq4-map-format.md#인물) 의 「머리」 와 같습니다. 덧붙은 바이트는 F bit4·bit3 이 모두 켜진 레코드에만 있고, F bit0 이 꺼져 있으면 바이트 7, bit1 이 꺼져 있으면 그다음, bit2 가 꺼져 있으면 그다음 두 바이트입니다.

| 값 | 낮 | 밤 | 근거 |
| --- | --- | --- | --- |
| 대화 번호 | (바이트 1 bit4-2) << 8 \| 바이트 4 | F bit1 이 꺼져 있으면 (바이트 1 bit1-0) << 8 \| 덧붙은 바이트(F bit0 이 꺼져 있으면 8, 켜져 있으면 7). 켜져 있으면 낮과 같음 | 실측: 낮 맵 7곳, 밤 맵 2곳 19명 |
| X, Y | 바이트 5, 6 의 bit6-0 | F bit4 가 켜져 있고 bit2 가 꺼져 있으면 덧붙은 두 바이트, 아니면 낮과 같음(`1C:$9907`) | 실측: 밤 19명 중 18명이 RAM `$6F60`/`$6F80` 과 같음(1명은 걸어서 한 칸 옮김) |
| 그림 번호 | ((바이트 0 bit7) << 6 \| 바이트 3 >> 2) + `0F`, 바이트 1 bit6 이면 \| `80` | F bit0 이 꺼져 있으면 (바이트 1 bit7, 바이트 7), 켜져 있으면 낮과 같은 바이트. `80` 은 바이트 1 bit5 | 실측: RAM 그림 표와 93명 같음(아래) |
| 방향 | 바이트 3 bit1-0 → `$7000` | 그림 번호와 같은 바이트 | 코드 읽기(`1C:$99B3`) |
| 움직임 | 바이트 2 bit7-4 → `$7040`([그림과 움직임](#그림과-움직임)) | 바이트 2 bit3-0 | 실측: 8 미만인 73명 중 72명(아래) |

`1C:$96C7` 이 A(`$03`)로 돌려주는 값은 그림 번호에서 `0F` 를 뺀 아래 7비트(bit6 = 바이트 0 bit7, bit5-0 = 바이트 3 >> 2)에 bit7 = 바이트 5(밤은 6) bit7 의 반대를 붙인 것입니다(코드 읽기). `fc/dq4/tools/dq4talk.py G K` 의 「겉모습」 이 이 값입니다.

레코드를 세는 목록은 맵에 들어갈 때 `1C:$9B00` 이 정해 `$3A`/`$3B` 에 둔 것입니다(보통은 뱅크 05 의 목록, 이벤트가 진행되면 [이벤트 목록](#이벤트-목록)). `1C:$96CE` 는 장소 `3A/04` 에서 `$64` 를 잠깐 `03` 으로 바꾸지만, `$96FC` 는 `$64` 를 읽지 않고 `$3A`/`$3B` 만 봅니다. 3A/04 의 인물에게 말을 걸며 바꿔 둔 동안(`1C:$96DE` JSR ~ `$96E1`)의 읽기를 `fc/dq4/tools/lua/talkreads.lua` 로 잡으니 `$3A`(`B4`)·`$3B`(`B9`) 한 번씩뿐이고 `$64` 는 한 번도 읽히지 않았습니다(실측). 대화 번호에는 영향이 없습니다.

맵 레코드 낮 860명·밤 727명과 이벤트 목록 372명의 대화 번호는 861가지이고, 메시지 하나 502, 스크립트 346(스크립트 전부), 서비스 5, 예/아니오 8 입니다.

### 이벤트 목록

맵에 들어갈 때 쓰는 목록은 이야기 진행 플래그로 바뀝니다. 고르는 표 `1C:$9D0E`(56줄)와 되돌리는 조건 `1C:$9C6F`, 실측은 [dq4-map-format.md](dq4-map-format.md#진행-목록) 에 있습니다. 디코더는 `fc/dq4/tools/dq4map.py` 의 `place_records` 를 같이 씁니다. 레코드 형식은 뱅크 05 목록과 같고, 밤 레코드는 목록과 상관없이 F bit3 으로 가릅니다.

### 그림과 움직임

맵에 들어갈 때 `1C:$99B3` 이 그림 번호를 `$9A37` 에 넘깁니다. `$9A37` 은 그 맵에서 쓰는 그림 표 `$6E5E`(16칸, `FF` 는 빈 칸)에서 같은 번호를 찾거나 빈 칸에 넣고, 새로 넣을 때 BRK `04 87`(뱅크 08 함수 04, `08:$85D3`)로 그림을 읽습니다. 인물 표 `$6FE0` 에는 그 칸 번호 + 4(`$07BA` bit7 이면 + 6)가 들어갑니다(코드 읽기). 맵 5곳 덤프 7개(낮 5, 밤 2)에서 인물 93명의 `$6E5E[$6FE0 − 4]` 가 위 식의 그림 번호와 모두 같았습니다. 화면에서는 같은 칸(`$6FE0` = 05, 그림 `11`)을 쓰는 왕좌의 방 병사 둘이 같은 팔레트 3 과 같은 타일 구역(`78`~`85`)으로 그려졌습니다(바라보는 방향에 따라 `78`~`7A` 와 `83`~`85`).

`08:$85D3` 은 먼저 `08:$859B` 에서 번호(아래 7비트)를 고칩니다. `53` 이상은 `0B` 를 빼고, `48`~`4F` 는 `48` 을 뺍니다(일행 그림 `00`~`07` 과 같은 것). 그다음 `08:$979B` + 24 × 번호의 24바이트(3바이트 × 8)를 읽어 CHR 을 짭니다(코드 읽기, 3바이트의 뜻은 남은 것). `fc/dq4/tools/dq4talk.py looks` 는 롬의 모든 인물 레코드(보통 목록 낮·밤, 진행 목록)를 그림 번호로 모아 쓰는 인물 수·장소·첫 대사를 냅니다. 그림 번호는 126가지입니다. 예를 들어 `0F` 는 왕(29명, 「そなたの　かつやくを　きたいしているぞ」), `11` 은 병사(183명), `24`·`25`·`26` 은 개·고양이·말(「わんわん」·「にゃーん」·「ヒヒーン」)입니다. 그래픽은 다시 그리므로 이 목록이 「어느 인물이 어느 겉모습인지」 의 기준입니다.

바이트 2 의 니블 n 은 `1C:$9A74` 가 받습니다(코드 읽기).

- n < 8: `$7040` = n << 4 | n.
- n ≥ 8: 같은 n 을 쓰는 인물끼리 `$DF` + (n − 2) >> 1 의 니블(n 이 짝수면 아래, 홀수면 위)을 차례 번호로 씁니다. `$7040` = n << 4 | (차례 + 1). 왕좌의 방의 n = 8 넷이 RAM 에서 `81`·`82`·`83`·`84` 였습니다(실측).

걸음은 고정 뱅크 `0F:$D63E` 가 정합니다. 인물 차례가 올 때마다 `$7040` 을 하나 줄이고, 아래 니블이 0 이 되면 위 니블을 아래로 다시 채운 뒤 한 걸음 걷습니다. `$7040` 이 0 이면 걷지 않고, `$7000` bit7 이나 자리 (80,80) 도 걷지 않습니다(코드 읽기). 그래서 위 니블은 「걸음 사이 간격」 이고 0 이 제자리입니다. 왕좌의 방 세이브스테이트에서 슬롯 6~17 의 `$7040` 을 `00`·`11`·`22`…`AA`·`FF` 로 바꾸고 1800프레임 동안 자리를 보니, `00` 은 한 번도 움직이지 않았고 `11` 이 10번으로 가장 많이, `22`~`AA` 는 1~5번 움직였습니다(`66`·`FF` 는 0번, 막힌 자리로 보임). 롬에서 왕·병사처럼 서 있는 인물은 n = 0 이고, n = 1 은 숨은 인물(81,81)과 왕좌의 방 슬롯 1A 에 쓰입니다. 한 명 다른 것은 1장 세이브스테이트의 슬롯 6(바이트 2 = `0x`, RAM `31`)으로, 세이브스테이트를 만들기 전에 게임이 바꾼 값으로 보입니다(같은 맵을 워프로 새로 읽은 덤프에서는 `00`).

## 스크립트

문장을 차례로 실행합니다(`$9BA8`). 맨 처음과 `06` 뒤는 블록이고, 블록은 문장마다 다음 바이트가 `3E`·`3F` 면 끝납니다(`$9C2E`).

| 바이트 | 길이 | 뜻 | 근거 |
| --- | --- | --- | --- |
| `40`~`7F` `nn` | 2 | 메시지 (b & `3F`) << 8 \| `nn` 출력(`$9919`) | 실측 |
| `3F` | 1 | 스크립트 끝(갈래 안이면 그 조건만 빠져나옴) | 실측 |
| `07` `c` … | 2+ | [조건](#조건). `c` 의 bit7 = 결과 뒤집기, bit5-0 = 조건 종류. 뒤에 인자, then 갈래, `0B` 가 오면 else 갈래 | 실측 |
| `06` | 1 | 갈래 안에서 블록 시작(조건 뒤가 `06` 이 아니면 문장 하나가 갈래) | 실측 |
| `18` `i` `m` | 3 | 이벤트 플래그 켜기: `$627B+i` \|= m | 실측: 02/00 노인, `$6289` `00` → `10` |
| `17` `i` `m` | 3 | `$627B+i` &= m | 코드 읽기(스크립트 전체 1곳) |
| `19` `i` `v` | 3 | `$627B+i` = v | 코드 읽기(쓰는 스크립트 없음) |
| `12` `n` | 2 | 서비스 n(`$9C63` → `$9CBF`). 돌아와 스크립트를 잇지 않음 | 실측: 12/00 여관 카운터 너머 → 6 |
| `00` `lo` `hi` | 3 | 뱅크 15 루틴 `hi:lo` 호출(`$9C42`). [호출 문장](#호출-문장) | 실측(루틴 6개) |
| `01` `lo` `hi` `a` `b` | 5 | 위와 같고 인자 2바이트는 불린 루틴이 읽음(`$9C25` 에서 Y += 2) | 코드 읽기 |

스크립트 346개 전부를 이 규칙으로 읽으면 못 읽는 바이트가 0개입니다(`fc/dq4/tools/dq4talk.py all`). 쓰인 횟수: 메시지 951, 조건 588, 플래그 켜기 47, 호출 78·48, 서비스 23, `17` 1.

### 조건

`$99CE` 가 종류마다 루틴을 불러 A 를 받고, `$9A4C` 에서 A = 0 이면 then 갈래, 아니면 else 갈래로 갑니다(뒤집힌 조건 `$DC` = `FF` 면 반대). 아래 「참」 은 then 갈래를 탄다는 뜻입니다.

| 종류 | 인자 | 참 | 쓴 횟수 | 근거 |
| --- | --- | --- | --- | --- |
| `02` | 0 | `$E9` = 0(카운터 너머에서 말 걺) | 16 | 실측 |
| `03` | 1 | 걷는 일행에 [인물](#인물-번호) n 이 있고 살아 있음 | 43 | 실측 |
| `05` | 0 | 예/아니오 창(`$B7DD`, A = `48`)에서 「はい」 | 50 | 실측 |
| `11` | 1 | 일행 누군가가 아이템 n 을 가짐(장비 여부 무관, 1~5장 모두 마차 포함) | 12 | 실측 |
| `13` | 1 | 일행의 인물 n 이 죽어 있음. 1~4장은 마차도, 5장(`$615A` ≥ 4)은 걷는 일행만 | 16 | 실측 |
| `14` | 0 | 낮(`$62ED` < `78`) | 76 | 실측(낮·밤) |
| `16` | 1 | 장 `$615A` = n − 1 | 143 | 실측: `$615A` = `04` 로 바꾸면 「5장」 갈래 |
| `1A` | 2 | `$627B+i` ≠ v | — | 코드 읽기 |
| `1B` | 2 | `$627B+i` & m ≠ 0 | 230 | 실측 |
| `1C` | 2 | (`$627B+i` \| m) ≠ 0 | — | 코드 읽기 |
| `1E` | 0 | 일행 선두가 남자 | 2 | 실측 |

일행·인물 조건은 뱅크 10 의 일행 루틴을 BRK 특수 형식(`b2` 아래 4비트 `3`, [dq4-bank-format.md](dq4-bank-format.md#특수-형식))으로 부릅니다. `b2` = `63`·`73` 은 뱅크 10 함수 6·7 인데 둘 다 `10:$810B` 이고, `b1` 이 `$6E0B` 에 들어가 `10:$9E67` 의 처리기 표를 고릅니다. `63` 은 셋째 바이트를 `$6E0A`(일행을 셀 때의 조건 비트)에 두고 BRK+4 로, `73` 은 셋째 바이트 없이 BRK+3 으로 돌아옵니다. A 는 `$6F` 를 거쳐 처리기에 `$76` 으로 갑니다(코드 읽기).

| `b1` | 처리기 | 하는 일 |
| --- | --- | --- |
| `63` | `10:$9880` | 일행에서 인물 번호 A 를 찾음. 찾으면 C = 1, X = 그 자리 |
| `42` | `10:$964A` | 자리 X 의 상태. 레코드 바이트 0 bit7 이 꺼져 있으면 1(죽음), 그 밖의 상태 비트면 2~, 아무것도 아니면 0 |
| `6A` | `10:$9319` | 자리 X 가 마차에 있으면 1 로 보임 |
| `66` | `10:$99A3` | 일행 소지품(레코드 +13~+1A 의 아래 7비트)에서 아이템 A 를 찾음 |
| `29` | `10:$881F` | 자리 X 의 성별(1 = 여자) |
| `2E`·`30` | | 아이템 A 주기, `66` 이 찾은 아이템 빼기(아래 [호출 문장](#호출-문장)) |

조건마다 루틴은 이렇습니다.

- `03`(`$9AF5`): `63 63 40` 으로 찾고, `42 63 40` 이 1 이 아니면 참. 셋째 바이트 `40` 이 `10:$826D` 에서 마차 쪽 찾기를 막습니다. 마차에 있는 인물은 거짓이었습니다(5장, 마차에 アりーナ).
- `13`(`$9AD1`): `63 73` 으로 찾고(걷는 일행, 다음 마차), 5장이면 `6A 73` 이 1(마차)일 때 거짓, 그 뒤 `42 73` 이 1 이면 참.
- `11`(`$A794`): `66 73` 이 찾으면 참. 5장에 마차의 アりーナ가 가진 아이템 `1E` 로 참이 나왔습니다.
- `1E`(`$9AC3`): X = 0 으로 `29 73`. 주인공(레코드 번호 & 7 = 0)은 `$615C` bit0, 손님(레코드 번호 9 이상)은 레코드 바이트 5 = `CB`, 그 밖은 `46` 의 비트(2 ミネア·3 マーニャ·7 アりーナ 가 여자)입니다.

마차 자리를 셀지는 `10:$8498` 이 `$618E` 로 정합니다.

| --- | --- | --- |

### 인물 번호

일행 자리는 `$616A`~`$616D`(걷는 4자리)와 `$6172`~(마차)이고 값은 bit7 + 레코드 번호입니다([dq4-save-format.md](dq4-save-format.md)). 조건의 인물 번호 n 은 레코드 번호 9 미만이면 그 번호 & 7, 9 이상(손님, 레코드 `$610F` + 6 × (번호 − 9))이면 레코드 바이트 5 가 `C5` 이상일 때 바이트 5 − `BD`, 아니면 바이트 5 + `20` 입니다(`10:$884C`, 코드 읽기).

| n | 인물 | 스크립트에서 |
| --- | --- | --- |
| `00` | 주인공 | 5장 「ひつぎに　はいっている　おかたは」 |
| `02` | ミネア | 「ミネアちゃん！」 |
| `03` | マーニャ | 「マーニャちゃん！」 |
| `04` | ブライ | 「あなたも　パデキアを？」(4번 없을 때) |
| `05` | トルネコ | 「あなた！　あなたなのね！」(ネネ) |
| `06` | ライアン | 「ライアンさま」 |
| `07` | アりーナ | 「ひめさまが……！」 |
| `08`·`09` | 손님. `09` = オーりン(「オーりンさん　だよね？」) | 실측(아래) |

손님은 걷는 일행 자리에 레코드 9(`$610F`)를 넣고 바이트 5 를 바꿔 확인했습니다. 대화 `148`(조건 `03 08`)은 바이트 5 = `C5` 에서 참이었고, `C6`·`E8` 과 바이트 0 bit7 을 끈 `C5` 에서 거짓이었습니다. 대화 `0DC`(조건 `83 09`, 뒤집힘)는 `C6` 에서 「있음」, `E9`(인물 번호 `2C`)에서 「없음」 이었습니다. 6번 모두 디코더 예측과 같았습니다.

예: 02/00 성 앞 노인(대화 `00A`, `15:$803D`)

```
07 1B 0E 10      if flag& 0E 10         이미 따라왔으면
47 89              msg 0789
0B 06            else (블록)
47 87              msg 0787
07 05              if yes
06                   (블록)
18 0E 10             flag|= 0E 10
47 88                msg 0788
00 36 9D             call 15:9D36
3E                   (블록 끝)
0B                 else
47 8A                msg 078A
3E               (블록 끝)
3F               스크립트 끝
```

## 이벤트 표

`1C:$AD5F`(BRK `07 CF`)는 A 번째 워드 `1C:$BF74` + 2A 로 점프합니다. 표는 `$BFD8`(바꿔 끼우는 뱅크마다 같은 조각) 앞까지 50개(`00`~`31`)입니다. `fc/dq4/tools/dq4talk.py events` 가 번호마다 루틴을 갈래까지 따라가(뱅크 1C 안의 JSR 은 2단까지) 특수 전투(BRK `01 8F`, A = 번호)·플래그 명령·메시지·장소 쓰기·인물 숨기기(`1C:$BF5C`·`$BF60`, 슬롯 X+6 을 (80,80)·(81,81))를 모으고, 부르는 곳(대화 번호, 다른 뱅크의 `LDA #n` + BRK `07 CF`)을 붙입니다.

실측은 `talk.lua` 의 `EV` 로 했습니다. 1장 왕좌의 방에서 왕에게 대화 `016`(이벤트 `00` 을 부름)을 걸고, 이벤트 입구에서 A 를 `00`~`31` 로 바꿔 50개를 모두 돌렸습니다. 기록에는 특수 전투 번호, 이벤트 플래그·장소·시간·일행 자리 쓰기(첫 말 걸기 덤프와 값이 다른 것만), 메시지가 남습니다. 상수로 정해진 특수 전투 23개는 실행한 전투 번호와 모두 같았습니다. 전투 뒤에 켜는 플래그·메시지는 전투를 이기지 않았으므로 코드 읽기입니다. 이벤트가 세우는 플래그의 뜻은 [dq4-save-format.md](dq4-save-format.md) 의 플래그 표를 따르고, 여기서는 목록만 둡니다. 특수 전투의 몬스터는 [dq4-encounter-format.md](dq4-encounter-format.md) 의 `bosses` 와 같습니다.

「일행」 은 걷는 자리 `$616B`~ 에 들어온 값(bit7 + 레코드 번호, `89` = 손님 레코드 9)입니다. 1장 상태에서 돌렸으므로 일행 루틴이 고른 레코드는 장면에 따라 다를 수 있습니다. 「부르는 곳」 의 세 자리 16진은 대화 번호, `뱅크:주소` 는 BRK `07 CF` 가 있는 곳입니다. 「플래그」 의 `|=` 는 켜기, `&=` 는 끄기(그 값과 AND)입니다.

### 자동 입력 `$0530`

`$0530` bit7 이 켜져 있으면 주인공 걷기 `0F:$CA41` 이 패드 `$14` 대신 `0F:$DB0B` 가 주는 값을 씁니다. 같은 비트가 켜져 있는 동안 `$CB71`·`$CBF8`(A 버튼)·`$D67E` 도 건너뜁니다. `$DB0B` 는 부를 때마다 아래 4비트를 1 줄이고, 0 이 되면 `$0531`(남은 항목 수)을 1 줄입니다. `$0531` 도 0 이 되면 `$0530` = `00` 으로 끝납니다. 항목은 `$0532`/`$0533` 이 가리키는 뱅크 `1C` 의 바이트로, 위 니블이 패드 방향 비트(`$14` bit4-7), 아래 니블이 걸음 수입니다. 포인터가 0 이면 패드는 0 입니다(코드 읽기). `0F:$DAB9` 는 뱅크의 `$8014`·`$8016` 표에서 포인터와 항목 수를 정합니다.

`1C:$BF3B` 는 `$0530` = `8F`, `$0531` = `01`, 포인터 0 으로 「15걸음 동안 입력 없음」 을 겁니다. 이벤트 `08`·`0B`·`2C` 를 `EV` 로 돌리니 `$0530` 이 `8F` 에서 16프레임(한 걸음)마다 1씩 줄어 `80` 다음 `00` 이 됐습니다. 그동안 누른 A 는 무시됐고, `00` 이 된 뒤에야 아래로 걸었습니다(실측). 이벤트 `04` 는 이 값을 건 뒤 전투로 들어가고, 지면 `8F` 그대로 부활 장면으로 갑니다.

## 맵 이벤트

`1D:$B74D`(BRK `07 DF`)는 `1D:$B8CA` 의 6바이트 줄(12개, `FF` 로 끝)에서 그룹 = `$63`, 바이트 3 위 니블 = 장 `$615A`, 순번 = `$64` 인 줄을 찾습니다(코드 읽기). 줄 0 과 줄 2 는 `$6281` bit6 으로 하나만 쓰입니다.

| 바이트 | 내용 |
| --- | --- |
| 0, 1 | 그룹, 순번 |
| 2 | 인물 번호(일행에서 찾음, BRK `52 73`). bit7 이면 찾지 않음 |
| 3 | 위 니블 장, 아래 니블 일행 자리 |
| 4 | 그림 번호(BRK `0D 87`, 뱅크 08 함수 0D) |
| 5 | 인물 슬롯 − 6 |

```
30/04 FF 00 15 08    02/00 FF 00 13 0B    04/00 02 40 02 01
30/04 FF 01 15 06    02/03 FF 00 13 02    04/01 03 41 03 00
30/04 FF 02 15 07    38/03 09 32 19 00    2F/00 0E 40 2F 00
3A/04 08 00 3D 01    04/0B 0A 20 12 00
04/00 0B 20 11 07
```

맵에서 인물로 서 있던 동료가 일행 줄로 옮겨 오는 곳입니다. 5장(`$615A` = 4) 04/01 에 ミネア·マーニャ 를 일행에 넣고 카지노의 マーニャ(슬롯 6, 대화 `08F`)에게 말을 걸었습니다. 대화가 `15:$A4E1` 을 거쳐 `1D:$B74D` 를 지난 뒤 슬롯 6 은 (80,80)으로 숨고, 일행 슬롯 3 의 `$7020` bit7 이 꺼져(보이게 됨) 줄에 섰습니다(실측). 줄마다 갈래(`$B799`~`$B8A2`)가 달라, 다른 줄은 코드 읽기입니다.

## 쓰는 법

```sh
uv run python fc/dq4/tools/dq4talk.py rom/dq4.nes 12 00               # 맵의 인물마다 자리·겉모습·대화 번호·스크립트·대사
uv run python fc/dq4/tools/dq4talk.py rom/dq4.nes 12 00 --ram end.ram # RAM 덤프로 조건을 풀어 나올 메시지만
uv run python fc/dq4/tools/dq4talk.py rom/dq4.nes id 11C              # 대화 번호 하나
uv run python fc/dq4/tools/dq4talk.py rom/dq4.nes all                 # 모든 스크립트를 풀어 못 읽은 명령 수
uv run python fc/dq4/tools/dq4talk.py rom/dq4.nes 02 01 --night       # 밤 목록
uv run python fc/dq4/tools/dq4talk.py rom/dq4.nes calls               # 호출 문장이 부르는 루틴의 갈래
uv run python fc/dq4/tools/dq4talk.py rom/dq4.nes events              # 이벤트 표 50개(--compare DIR… 로 EV 실행 기록과 대조)
uv run python fc/dq4/tools/dq4talk.py rom/dq4.nes looks               # 그림 번호마다 쓰는 인물
```

실측은 `fc/dq4/tools/lua/talk.lua` 를 프로브로 돌립니다. `talk.txt` 에 대화 진입(슬롯·Y), 대화 번호, 조건 결과, 서비스, 이벤트(`1C:$AD5F`·`1D:$B74D`)·특수 전투(`18:$A1AD`), 메시지 번호를 찍고 진입 때 RAM(`talk_N.bin`)을 남깁니다. 환경 변수:

- `SLOT=0C` 또는 `SLOT=06,07,08`: 진입 때 A 를 바꿔 아무 인물에게나 말을 건 것처럼 돌립니다. 여럿이면 N번째 말 걸기에 N번째 슬롯.
- `TID=00B,01A`: N번째 말 걸기의 대화 번호를 바꿉니다(`15:$9942`, 갈래 직전의 `$00`/`$01`). 한 인물 앞에서 아무 스크립트나 돌릴 수 있습니다.
- `SET="616A=8087;60D3=80"`: 첫 말 걸기의 RAM 덤프 전에 한 번 씁니다. 일행·소지품·장·시간을 만들 때 씁니다.
- `EV=14`: N번째 이벤트 입구(`1C:$AD5F`)의 A 를 바꿉니다. 이벤트를 부르는 대화(예: `TID=016`)와 같이 써서 표의 아무 이벤트나 돌립니다. 이벤트 플래그(`$627B`~`$62AF`)·장소(`$63`/`$64`)·일행 자리(`$616A`~`$6179`)·시간(`$62ED`)에 쓰면 `w` 줄(주소, 값, PC)이 남습니다.

맵 이동은 [dq4-warp.md](dq4-warp.md) 의 `warp.lua` 를 드라이버로 씁니다. 왕좌의 방 세이브스테이트라면 `seq.lua` 로 「up:16」 뒤 A 를 거듭 누르면 왕에게 계속 말을 겁니다(명령 창 → はなす → 대사).

```sh
LIBDIR=$(uv run krpatch fc lua) SLOT=0C DRIVER=$PWD/fc/dq4/tools/lua/warp.lua MAP=04/00 X=0B Y=1C DIR=0 \
  SEQ="a:6,wait:40,a:6,wait:150,a:6,wait:80,a:6,wait:80" TAIL=300 MAXF=900 SHOT_DIR=$PWD/work/t \
  "$MESENCE" --testrunner --nes.ramPowerOnState=AllZeros "$PWD/rom/dq4.nes" "$PWD/fc/dq4/tools/lua/talk.lua"
uv run python fc/dq4/tools/dq4talk.py rom/dq4.nes compare work/t      # 「いいえ」 를 골랐으면 --no
```

`compare` 는 덤프의 플래그·장·시간·일행·인물 레코드와 기록한 Y 로 조건을 풀고, 덤프의 플래그로 이벤트 목록을 고르고, 밤이면 밤 레코드를 씁니다. `TID` 로 바꾼 대화 번호는 기록(`tid` 줄)을 따릅니다. 마차 자리를 셀지 정하지 못한 조건만 기록된 결과를 따르고 그 수를 따로 셉니다. 풀 수 있는 조건이 기록과 다르면 「다름」 입니다.

`fc/dq4/tools/lua/talkseek.lua` 는 세이브스테이트에서 인물에게 걸어가 말을 거는 입력 드라이버입니다(인물이 움직여서 닿지 못하는 일이 많아, 맵 4곳의 확인은 `SLOT` 으로 했습니다).

## 남은 것

- 이벤트 표: 전투를 이긴 뒤의 갈래(플래그·메시지)는 코드 읽기. `05`·`06`·`07`·`0B`·`10`·`19`·`21`·`2D`·`2E` 처럼 인물·OAM 만 움직이는 이벤트가 어느 장면인지는 부르는 대화의 맵에서 다시 돌려 봐야 함. 부르는 곳을 못 찾은 `0A`·`10`·`20`. 대화 `13B` 가 `15:$AE4E` 에서 이벤트 `2D` 로 가는 갈래의 실측(1장 왕좌의 방에서는 앞 갈래에서 빠져 `0AA7`·`0AA8` 만 나옴). [자동 입력](#자동-입력-0530) 항목 바이트열(`$0532`/`$0533` 이 0 이 아닌 경우)의 실측.
- 맵 이벤트 `1D:$B8CA` 의 줄 11개(실측은 04/01 하나)와 줄마다 다른 갈래.
- `$618E` 아래 3비트·`$618F`·`$6193` 을 게임이 언제 바꾸는지(마차를 맵에 두고 들어갈 때로 보임, `10:$91C6`~).
- 그림 번호 → CHR: `08:$979B` 의 3바이트 × 8 형식. `looks` 의 대사는 그 그림을 쓰는 첫 인물의 대사일 뿐이라, 겉모습은 그림으로 확인해야 함.
- 걸음 간격의 단위(인물 차례가 몇 프레임마다 오는지, `0F:$D5E1` 의 `$51`)와 걷는 방향을 고르는 곳(`0F:$D884`). 앞 일지의 `$A4B7`(`$7040` = `11`) 실험에서 인물이 900프레임 동안 서 있었던 까닭(막힌 자리인지).
- `1C:$96CE` 가 3A/04 에서 `$64` 를 바꾸는 까닭. 대화 번호에는 영향이 없음을 실측했지만, 바꿔 둘 필요가 있던 곳은 못 찾았습니다.
