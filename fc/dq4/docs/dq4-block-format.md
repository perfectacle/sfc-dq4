# DQ4(FC) 맵 블록·타일·팔레트·통행

마을·던전 맵과 필드는 16×16 픽셀 블록 32개(맵 종류마다 다름)로 그립니다. 이 문서는 블록 번호가 8×8 타일 4개·팔레트·통행 속성으로 바뀌는 과정, 타일 그림을 어디서 CHR-RAM 으로 올리는지, 걸을 때 통행과 지형 효과를 어떻게 정하는지 정리합니다. 디코더는 [fc/dq4/tools/dq4block.py](../tools/dq4block.py), 실험 과정은 [2026-10-25-16 일지](../journal/2026-10-25-16-block.md) 에 있습니다. 맵 해제(`$7800`)는 [dq4-map-format.md](dq4-map-format.md), 필드 타일 번호는 [dq4-field-format.md](dq4-field-format.md) 를 따릅니다.

주소 표기는 `뱅크:$주소` 이고, 근거 표시가 없는 것은 MesenCE 덤프와 디코더 결과가 같음을 확인한 것입니다. 「코드 읽기」 는 리스팅만 읽고 실험으로 확인하지 않은 것입니다.

## 전체 흐름

| 단계 | 루틴 | 결과 |
| --- | --- | --- |
| 맵 종류 정하기 | `08:$B708` | `$0550` = 맵 레코드 첫 바이트, `$0028` = 그 아래 6비트(맵 종류). 필드는 `00` |
| 블록 표 올리기 | `08:$84E9`(필드·맵 공통) | 블록마다 타일 번호 4개 `$7600+4×블록`, 팔레트 `$76C0+블록`, 종류 `$6F20+블록`, 속성 `$6F40+블록`. 타일 그림은 PPU `$1000`+타일×16 |
| 장소별 속성 고치기 | `08:$8A2A` | `$6F40` 몇 칸을 (그룹, 순번)에 따라 바꿈 |
| 맵 해제 | `0F:$E5D4`~ | `$7800` 에 칸마다 블록 번호(아래 5비트)와 구역(위 3비트) |
| 그늘 블록 바꾸기 | `1E:$9F47` | 벽 아래 칸을 그늘이 진 블록으로 바꿈(`$7800` 을 고쳐 씀) |

## 블록 정의 표

`08:$80B3` 의 포인터(`$8ADB`)부터 맵 종류마다 64바이트, 블록 0~1F 마다 2바이트 `a b` 입니다(`08:$8055`).

| 바이트 | 비트 | 뜻 |
| --- | --- | --- |
| `a` | 7-5 | 종류(`$6F20`). 그늘 바꾸기가 씀(아래). 0 이 아니면 맵에 안 쓰여도 올림 |
| `a` | 4-3 | 팔레트(`$76C0`) |
| `a` | 2-0 | 모양 레코드 번호 상위 3비트. `7` 이면 블록 없음(아무것도 올리지 않음) |
| `b` | 7-0 | 모양 레코드 번호 하위 8비트 |

블록 정의 `00 17` 은 `$615A`(장)이 1 이 아니면 `00 12` 로 바뀝니다. 2 일 때는 `$6286` bit4 가 켜져 있어야 바뀝니다(`08:$808E`, 코드 읽기. 1장 세이브스테이트(`$615A`=`00`)에서 필드의 블록 16 이 `00 12` 로 올라간 것은 확인).

블록 20·21 은 지금 주인공이 서 있는 구역과 다른 구역의 칸을 그리는 데 씁니다(아래 「구역」). `08:$853E` 가 맵 종류 t 로 `08:$8AA2` 표에서 2비트(바이트 t>>2, 위 비트부터)를 골라, `08:$8AAF`+선택×4 의 2바이트 정의 두 개를 블록 20·21 로 올립니다. 필드(맵 종류 `00`)는 올리지 않습니다.

### 모양 레코드

`08:$8235` 의 포인터(`$A80D`) + 번호×3 의 3바이트입니다(`08:$80D5`).

| 바이트 | 뜻 |
| --- | --- |
| 0 | CHR 번호 하위 8비트 |
| 1 | bit7-4 모양(0~F), bit2 그림 뱅크(0 이면 `0C`, 1 이면 `0D`), bit1-0 CHR 번호 상위 2비트 |
| 2 | 속성(`$6F40`). 아래 「통행」 |

모양 0~D: 첫 타일 주소 = (`08:$8229`+2×뱅크비트 의 워드) + CHR 번호×16. 뱅크 `0C` 는 `$8000`, `0D` 는 `$7F01` 이 기준입니다. 나머지 세 타일은 `08:$8237` 의 포인터(`$A1BB`)+모양×3 의 부호 있는 바이트 세 개만큼 앞 타일에서 16바이트 단위로 떨어진 주소입니다. 모양 E·F: `08:$8225` 의 포인터(`$A28D`)+CHR 번호×8 에 타일 주소 네 개가 그대로 있습니다(`08:$81C6`).

타일 순서는 왼위, 오른위, 왼아래, 오른아래입니다.

### 타일 그림 올리기

그림은 PRG 뱅크 `0C`·`0D` 에 압축 없이 2bpp 16바이트 타일로 있습니다. `08:$83BD` 가 `0F:$C7E1` 로 그 뱅크를 끼워 16바이트를 PPU 로 복사합니다. 타일 번호는 `8D` 부터 차례로 붙습니다(`08:$84FF`).

- 같은 그림 주소는 다시 올리지 않고 먼저 올린 번호를 씁니다(`08:$823D`, 주소 목록 `$7700`).
- 맵(종류 `00` 이 아님)에서 종류 비트도 속성(아래 7비트)도 없는 블록은 맵(`$7800`)이나 바깥 블록 `$0520` 으로 쓰였을 때만 올립니다(`08:$8487`, 쓰인 블록 표시는 `1E:$A046` 이 `$6E5E` 에).
- 맵 종류 `1E` 가 아니면, 블록 번호가 가장 작은 「안 쓰인 블록」 칸에 정의 `18 11` 을 타일 번호 `FC`~`FF` 로 올립니다(`08:$8710`). 종류 비트가 있는 블록은 쓰인 것으로 칩니다.
- 애니메이션 블록(아래)은 같은 주소를 찾지 않고 늘 새 타일 4개를 받습니다. 그 주소는 목록에 남아 뒤 블록이 다시 쓸 수 있습니다. 맵 종류 `2D`(블록 7개가 같은 그림 주소를 나눠 씀)에서 이렇게 해야 `$7600` 이 맞습니다. 이 동작을 정하는 코드는 아직 못 찾았습니다.

필드(맵 종류 `00`)도 같은 루틴으로 올리고, 블록 32개를 모두 올립니다.

### 타일 애니메이션

`1D:$802A` 가 맵 종류로 `1D:$8096` 목록을 찾습니다. 목록의 bit7 이 켜진 값마다 무리 번호가 하나씩 늘고, 아래 7비트가 맵 종류입니다(`2D` / `2C` / `0E` / `01`·`06`·`08`·`10`). 칸 8개마다 블록 번호(`1D:$8096` 안의 순번 × 8 + 칸, `1D:$80A6`)와 그림 원본 주소(무리 × 16 + 칸 × 2, `1D:$80DE`, 0 이면 빈 칸)가 있습니다. 프레임마다 `1D:$8C52` 가 그 블록의 첫 타일부터 이어진 4타일(64바이트)을 뱅크 `1D` 의 그림으로 덮어씁니다.

| 맵 종류 | 블록 | 그림 |
| --- | --- | --- |
| `2D` | 0E 0F 10 11 12 13 14 1F | `1D:$811E`~`$849E` |
| `2C` | 0D 0E 19 1B | `1D:$851E`·`$859E`·`$861E`·`$869E` |
| `0E` | 14 | `1D:$871E` |
| `01` | 0B | `1D:$891E`~ |
| `06` | 10 | `1D:$891E`~ |
| `08` | 14 | `1D:$891E`~ |
| `10` | 1C | `1D:$891E`~ |

덤프에서 이 블록의 타일은 롬 뱅크 `0C`·`0D` 의 그림과 다르고 뱅크 `1D` 의 위 주소 범위에 있는 그림과 같았습니다(`06`·`0E`). 프레임 순서와 속도(`$0583`, `$3C`)는 코드 읽기입니다.

## 맵 칸 → 화면

### 그늘 바꾸기

`1E:$9F47` 은 맵을 푼 뒤 칸마다, 블록 종류(`$6F20` 아래 3비트)가 1~3 인 칸의 아래 칸이 종류 0 이면 그 칸을 종류 5~7(= 1~3 + 4)인 블록으로 바꿉니다. 아래 칸이 다른 구역이면 맵 종류에 따라 다르게 정합니다(`1E:$A016`·`$A01C` 표). 디코더 `shade()` 가 같은 결과를 냅니다(확인한 모든 맵에서 `$7800` 0 바이트 다름).

### 맵 밖과 구역

- 맵 밖 칸은 바깥 블록 `$0520`(맵 헤더)입니다. `$0550` bit7 이 켜진 맵은 `0F:$D469`(X&7)·`$D471`(Y&7) 무늬로 `$0520` 과 `$0582`(`08:$8A92`+맵 종류, 종류 `0F` 미만만)를 섞습니다(`0F:$D44C`).
- 칸의 위 3비트는 구역입니다. 주인공 칸의 구역(`$46` = `$7140` 위 3비트)과 다른 칸은 블록 20(주인공이 구역 0) 또는 21 로 그립니다. 집 안에 들어가면 밖이 검게 가려지는 것이 이것입니다. `$07BA` 가 4 이면 바깥 블록은 구역과 상관없이 그립니다(`0F:$D4E6`).

### nametable

세로 미러링이라 nametable 두 장이 가로로 붙어 64×30 타일입니다. 화면 왼쪽 위 칸이 맵 좌표 (`$7C`, `$7B`), 스크롤이 X = (`$0505` bit0)×256 + `$0508`, Y = `$0509` 일 때, 화면의 (i, j) 번째 블록(16×15)은 nametable 의 (X/8 + 2i, Y/8 + 2j)(64·30 으로 나눈 나머지)에 2×2 타일로 들어가고 attribute 는 그 블록의 팔레트입니다(`0F:$EB23`). 블록 없음(`a`&7 = 7)인 블록은 타일 `00`(빈 타일)이라 attribute 는 이전 맵의 값이 남아도 보이지 않습니다.

## 팔레트

BG 팔레트 4개의 색 0 은 모두 `0F`(`$05FC`)이고, 색 1~3 의 12바이트를 `$05FD`~ 에 씁니다.

맵(`0E:$802B`):

1. 밤이면 1, 아니면 0. 밤은 `$62ED` ≥ `78`.
2. `0E:$BBB1`(그룹, `FF` 끝)·`$BBD3`(순번, `FF` 는 아무 순번)에 지금 장소가 있으면 그 순번 i 에 따라: i < 0E 이면 맵 종류 대신 `0E:$BBC5`+i 를 씀, i = 0E 이면 `$6293` bit4 일 때 `36`, i = 0F·10 이면 밤으로 침, 11 이상이면 낮으로 침. `$65` 가 3 이면 밤으로 침(`0E:$BB55`).
3. 세트 번호 = `0E:$BBE6`+(맵 종류×2 + 밤).
4. `0E:$BC68`+세트×4 의 4바이트가 팔레트마다 색 묶음 번호, 색 묶음은 `0E:$BD40`+번호×3 의 3바이트.

필드(`1E:$A296`): 시각 `$62ED` 를 `1E:$A2DB` 의 경계 8개(`00 78 7C 80 84 C0 C4 C8`)와 비교한 순번 x 로 `1E:$A2E3`+12x 의 12바이트를 그대로 씁니다. `$65` 가 3 이면 x = 8.

확인한 덤프는 모두 낮(`$62ED` < `78`)입니다. 밤·장소 예외는 코드 읽기입니다.

## 통행

블록 속성 `$6F40` 으로 정합니다. 걸으려는 칸의 블록(아래 5비트)으로 `0F:$D088` 이 `$6F40` 을 `$0594` 에 넣고:

| 속성 | 걸어서 | 배(`$0515` ≠ 0)로 |
| --- | --- | --- |
| bit7 = 0 | 감 | 내려서 걸음(`$0515` = 0, `0F:$D01C`) |
| `83` | 못 감(소리 없음) | 감 |
| `24` | 감 | 감 |
| `B0` | 막힘. 그룹 `3F` 에서 「とびら」로 부술 수 있는 문(메시지 03EC) | 9 | 코드 읽기(`0F:$D0BC`, `1E:$B314`) |
| 그 밖의 bit7 = 1 | 못 감(`BRK A2 FB` = `1F` 함수 22, 부딪히는 소리로 보임) | 못 감 |

`83` 은 물(성의 연못·해자, 필드 바다)입니다. 문(`94`~`A3`)도 걸어서는 막히고 「とびら」로 엽니다(아래 「문과 열쇠」). 인물이 있는 칸은 이 표와 따로 막힙니다.

디버그 기능: `0F:$C000` 바이트의 bit7 이 0 이면 버튼 `$14` bit1 을 누르고 있는 동안 속성을 보지 않고 걷습니다([dq4-debug.md](dq4-debug.md)).

### 장소별 속성 고치기

`08:$8A2A` 가 블록 표를 올린 뒤:

- `$65` = 3 이고 필드면 블록 01 을 `80`, 14 를 `00` 으로(`$8A34`).
- 맵이면 `08:$8A6C`(그룹, `FF` 끝)·`$8A73`(순번)·`$8A79`(블록)·`$8A7F`(값) 표에 맞는 블록을 그 값으로: `1C/00` 블록 12 → `05`, `48/08` 블록 1F → `08`, `00/00` 블록 10·11·14·15 → `A2`.

`00/00` 의 `A2` 는 워프 실험의 덤프(`$6F50`=`A2`, 쓴 곳 `08:$8A66`)로 확인했습니다.

### 성문 연출

성 앞(`02/00`)에 들어오면 블록 표를 올린 지 약 56프레임 뒤 `1B:$8706`(BRK `1B` 함수 3)이 블록 10·11(`$0540`)과 14·15(`$0541`)의 타일 그림을 `$7710` 의 다른 그림으로 바꾸고 속성을 `80`·`24` 로 바꿉니다(`1B:$885A`~`$886D`). 그래서 `02/00` 덤프는 그 네 블록만 롬 정의와 다릅니다. 이 연출은 `1E:$8F00` 이 주인공 좌표의 블록에서 시작합니다(코드 읽기). 열쇠로 여는 문은 아래 「문과 열쇠」.

## 지형 효과

속성 값은 맵 종류마다 블록에 붙은 숫자일 뿐이고, 뜻은 그 값을 읽는 루틴이 정합니다. 걸음을 마치면 `0F:$CE2F` 가 `0F:$CEB1` 로 `$0594`(걸어 들어간 칸의 속성, 아래 7비트)를 `0F:$CEEB` 의 11개 값과 비교해 나눠 보냅니다. 그 밖의 값은 걷는 동안(`0F:$CA77`, `$E9E4`)이나 걸음 수마다(`1E:$99BD`), 명령(「とびら」·「はなす」·「しらべる」)에서 따로 읽습니다. 디코더 `terrain()` 이 값마다 아래 표를 돌려주고, `tables` 명령이 롬의 맵·필드에 쓰인 43가지를 모두 찍습니다.

| 값(아래 7비트) | 읽는 곳 | 하는 일 | 근거 |
| --- | --- | --- | --- |
| `01` | `1E:$99E1`·`$9ACA` | 걸음마다 HP 1 감소. 그때 BG 팔레트를 `16` 으로 채움(코드 읽기) | `16/00` 에서 두 번 밟아 HP 27 → 26 → 25 |
| `02` | 데미지 바닥. 걸음마다 HP 15 | 8 | 실측: `02/01` (3,0F) 에서 HP 27 → 12 → 0(위 「지형 효과」) |
| `04` | `1E:$B415` | 「しらべる」로 보물상자 | [dq4-shop-format.md](dq4-shop-format.md) |
| `05` `0B` | `0F:$CED9` → `1E:$8676` → `12:$B6DD` | 떨어짐. 아래 「떨어지는 칸」 | `3C/01`·`31/02` 에서 3번 |
| `06` `07` `08` `09` `25` `26` `0C` | `0F:$CED4` → `1E:$9100` | 출구 검사. 출구 표 `$05A0` 에 그 칸이 있으면 다른 맵으로 | 왕좌의 방 계단(`08`) → `02/02`. 필드 입구 74곳은 모두 `06` |

### 떨어지는 칸

`1E:$8676` 은 화면을 흔들며 주인공을 떨어뜨린 뒤 `12:$B6DD`(BRK `2C 2F`)로 목적지를 정합니다. 순서는 이렇습니다(코드 읽기, 디코더 `fall()`).

1. 그룹별 코드: `1C` → `3A/00` (17,03). `2D`·`46` → 필드 1 의 방향별 좌표(`12:$B8C5`, `46` 의 (23,1D) 만 필드 1 (13,11)). `30` → 들어온 필드 자리에서 아래로 3칸(1장)·2칸. `2E/01` 은 좌표 구역 셋에 따라 `2E/02` 의 (0A,06)·(05,06)·(06,0A). `3D/01` → `3D/03` (08,0F) 과 `$62AA` bit7.
2. 표 `12:$B971`(포인터 `12:$B96F`): 항목 = 그룹, 순번(bit7 이면 조건이 붙음), [조건, 목적지]. 조건은 `x|80 y 크기`(사각형, 크기 아래 4비트 폭−1·위 4비트 높이−1) 또는 `x y`(한 칸), 첫 바이트 bit6 이면 조건이 이어집니다. 목적지는 `순번|80`(같은 좌표, 순번만 바꿈) 또는 `순번 x y`(x 는 아래 6비트). 같은 그룹 안에서만 옮깁니다. 32항목.
3. 둘 다 아니면 필드로 나갑니다. 들어온 필드 자리(`$42`/`$43`)에서 걷던 방향으로 한 칸(오른쪽은 `$07BA` = 0 이면 두 칸, 위는 `$07BA` 가 0·4·5 면 두 칸).

| 실험 | 예측 | 결과 |
| --- | --- | --- |
| `3C/01` (02,04) 에서 오른쪽으로 (03,04)(`0B`) | 표 `3C 01 83` → `3C/03` 같은 좌표 | `3C/03` (03,04) |
| `31/02` (0C,0F) 에서 아래로 (0C,10)(`0B`) | 표 `31 82 8A 10 BB 03 0F 12` → `31/03` (0F,12) | `31/03` (0F,12) |
| `31/02` (02,0A) 에서 왼쪽으로 (01,0A)(`05`) | 표의 사각형 밖 → 필드, 한 칸 왼쪽 | 맵 종류 `00`, `$42` A4 → A3 |

맵 269개의 떨어지는 칸 18,381개 가운데 5,122개가 표·그룹 코드로 맵에 닿고, 나머지는 필드로 나갑니다.

### 리프트

속성 `0F` 칸을 밟으면 `1E:$8700` 이 `1E:$894A` 로 `1E:$89C8` 표(그룹, 포인터 3바이트, `FF` 끝)를 찾습니다. 그룹마다 8바이트 레코드 = (순번, x, y, 값) 두 개이고, 지금 자리가 한쪽과 같으면 다른 쪽으로 옮깁니다(값은 `$7F`). 표에 없는 칸이면 `1E:$895D` 에서 멈춘 채 돕니다. 그룹 `45` 는 그 전에 `$62AA` 를 뒤집어(순번 4·6 은 bit4, 그 밖은 bit1) `dq4map.special_group` 의 맵 바꾸기와 맞춥니다. 옮긴 뒤 새 맵을 그리고 15칸 아래에서 8프레임에 한 칸씩 목적지까지 올라옵니다.

| 그룹 | 짝 |
| --- | --- |
| `38` | `00`(15,02)↔`01`(17,02), `01`(02,0C)↔`03`(02,04), `01`(0B,1A)↔`02`(05,04), `02`(12,05)↔`03`(16,1D) |
| `47` | `00`(2B,03)↔`00`(1F,03) |
| `45` | `04`(26,17)↔`06`(09,0D), `05`(1D,11)↔`07`(0A,03) |

`38/00` (15,02) → `38/01` (17,02), `45/04` (26,17) → `45/06` (09,0D) 와 `$62AA` = `10` 을 확인했습니다.

### 문과 열쇠

문은 막힌 칸(bit7)이고 아래 7비트가 `14`~`23` 입니다. `1E:$B3C8` 의 16바이트가 4개씩 잠금 단계를 나눕니다(`1E:$B36E`).

| 잠금 | 값 | 여는 것 |
| --- | --- | --- |
| 0 | `14` `18` `1C` `20` | 열쇠 없이 |
| 1 | `15` `19` `1D` `21` | とうぞくのカギ(`71`) 이상 |
| 2 | `16` `1A` `1E` `22` | まほうのカギ(`72`) 이상 |
| 3 | `17` `1B` `1F` `23` | さいごのカギ(`73`) |

같은 줄의 네 값(열)은 문 모양이고 `08:$8796` 이 연 뒤 바꿀 블록을 고릅니다(`14`~`17`, `18`~`1B`, `1C`~`1F`, `20`~`23` 마다 다른 경로, 코드 읽기). 롬에 쓰인 문은 `94`·`95`·`96`·`97`·`9C`·`9D`·`A0`·`A2` 입니다.

- 「とびら」(명령 창 7번째, `1E:$B2A6`): 앞 칸이 문이면 잠금 0 은 바로 엽니다. 아니면 일행이 가진 가장 센 열쇠(`1E:$B3B7` 가 `73`→`71` 순으로 `BRK 66 73`)의 순번이 잠금−1 이상이면 엽니다. 열쇠가 없으면 「かぎを　もっていない。」(0361), 모자라면 「かぎが　あわない。」(0360). 문이 아니면 「ここには　とびらがない。」(035E), 속성 `AC` 는 「この　とびらは　ひらきそうにない。」(03F2), 그룹 `3F` 의 `B0` 은 「がんじょうそうな　とびらだが　3にんで　おせば　こわせそうだ！」(03EC). 3장(`$615A`=3)에서는 잠금 2 문에 다른 경로가 있습니다(`1E:$B381`, 코드 읽기).
- 열쇠를 「どうぐ」로 쓰면 `12:$A78A` → `1E:$8346` 이 같은 일을 합니다(`$6279` = 쓴 열쇠, `1E:$B33B`, 코드 읽기).
- 연 문은 `$6C0C` 의 4바이트 목록(최대 40개, `FF` 끝)에 남습니다: `$7800` 버퍼 주소 상위·하위, 순번(bit7 이면 2×2 문), 바꾼 블록. 맵을 그릴 때 `1E:$A0D6` 이 지금 순번과 같은 항목을 다시 씁니다. 그룹은 적지 않습니다.

왕좌의 방 `02/01` 의 문(03,0C)(`95`)에서 확인했습니다. 열쇠 없이 「とびら」 → 0361. `$60CA` 에 `71` 을 넣고 「とびら」 → `$6C0C` = `79 83 01 07`(주소 `$7983` = (03,0C), 블록 `07`), 그 칸을 지나 (03,0D) 로 들어감. 위층 `02/02` 에 다녀와도 목록이 남고, 돌아오자 `$7983` 이 롬 값 `0C` 로 풀린 뒤 곧 `07` 로 다시 쓰였습니다.

### 앞 칸을 보는 명령

| 값(아래 7비트) | 명령 | 하는 일 | 근거 |
| --- | --- | --- | --- |
| `17` `27` | 「はなす」(`1E:$80D8`) | 앞 칸에 인물이 없고 이 값이면 한 칸 더 앞의 인물과 말함(카운터) | `02/01` (1B,10) 에서 위로: 카운터(`A7`, (1B,0F)) 너머 (1B,0E) 의 인물이 「せんしさま！ ……」 |
| `2B` | 「はなす」·「しらべる」(`1E:$BB10`) | タンス: 「タンスのなかを　しらべた。」(03B5) 뒤 표에 있으면 아이템 | `02/01` (1D,1A): やくそう(`53`)가 `$60CA` 에, `$6274` bit6 이 켜짐 |
| `2A` | 같은 곳 | つぼ: 039E 뒤 같은 표 | 표 항목이 모두 `AA`·`AB` 칸에 떨어짐 |
| `28` | 같은 곳 | 팻말: 아래로 보고 있으면 「たてふだを　みた。」(031B), 아니면 03B8 뒤 좌표로 찾은 메시지 | 필드 0 (A6,30) 에서 위로: 「あやしいものを　みつけたら　おしろまで！　バトランドおう。」(03D9) |
| `30` | 같은 곳 | 그룹 `3F` 에서만 03EC | 코드 읽기 |

タンス·つぼ 표 `1E:$BCED`(`1E:$BC7A`): 7바이트 = 그룹, 순번, x, y, 아이템, 플래그 `$6273`+n, 비트. 27항목이고 좌표가 모두 그 맵의 `AA`·`AB` 칸입니다. 롬의 `AA`·`AB` 칸 226개 가운데 나머지는 「とくに　なにも　みつからなかった。」(0309)·「しかし　なにも　みつからなかった。」(02A6)입니다.

팻말 표: `1E:$BBB6` 의 포인터 두 개(`$41` bit7 이 켜졌을 때 / 꺼졌을 때, 필드는 뒤쪽). 3바이트 = x, y, 메시지 하위 바이트(상위 `03`). 그룹을 보지 않고 좌표만 봅니다. 하위 바이트 `00` 은 장에 따라 `1E:$BBE6` 의 03D0(1·2장)·03D4(3장)·0391(4장부터)입니다. 표의 맵 쪽 9개 좌표는 롬 맵의 `A8` 칸 9개와 하나씩 맞고, 필드 쪽 5개는 필드 0 의 `A8` 칸입니다.

벽 통과 디버그 스위치는 [dq4-debug.md](dq4-debug.md) 에 있습니다.

## 기계가 읽는 지도

`json` 명령이 맵 269개·필드 3개를 JSON 하나로 내보냅니다(기본 `work/dq4block.json`, 약 1.5MB, 커밋하지 않음).

| 키 | 내용 |
| --- | --- |
| `effects` | 속성 값(16진 문자열) → `terrain()` 결과(`walk`, `ship`, `effect`, `hp`, `dir`, `door{lock, shape}`, `talk_over`, `facing`) |
| `keys` | 열쇠 아이템 `71 72 73` |
| `maps[]` | `group`, `index`, `type`(맵 종류), `w`, `h`, `outside`(바깥 블록), `props`(블록 0~1F 의 속성, 없는 블록은 null), `cells`(줄마다 16진 문자열, 그늘 바꾸기 뒤 `$7800` = 위 3비트 구역 + 블록), `falls`(떨어지는 칸마다 `fall()` 결과, 방향은 아래로 침) |
| `fields[]` | `field`, `w`, `h`, `props`, `cells`(블록 번호) |
| `fall_table`, `lifts`, `pots`, `signs` | 위 표들. `signs[].at` 은 그 좌표에 `A8` 칸이 있는 맵 |

장소별 속성 고치기(`08:$8A2A`)는 `props` 에 들어가 있고, 성문 연출·연 문처럼 나중에 바뀌는 칸은 들어 있지 않습니다.

## 디코더

```sh
uv run python fc/dq4/tools/dq4block.py rom/dq4.nes defs 0D          # 맵 종류 0D 의 블록 정의·애니메이션·낮 팔레트
uv run python fc/dq4/tools/dq4block.py rom/dq4.nes 02 01            # 맵 02/01 의 통행 지도(텍스트)
uv run python fc/dq4/tools/dq4block.py rom/dq4.nes 02 01 --nt       # 맵 전체의 nametable 타일 번호
uv run python fc/dq4/tools/dq4block.py rom/dq4.nes 02 01 --png      # work/dq4block-02_01.png (확인용, 커밋 금지)
uv run python fc/dq4/tools/dq4block.py rom/dq4.nes field 0 --png    # 필드 0
uv run python fc/dq4/tools/dq4block.py rom/dq4.nes props            # 속성 값별 뜻·맵 수·칸 수(--maps 는 맵마다)
uv run python fc/dq4/tools/dq4block.py rom/dq4.nes compare work/x   # seq.lua·warp.lua 의 end.* 덤프와 비교
uv run python fc/dq4/tools/dq4block.py rom/dq4.nes effects 3C 01    # 맵의 속성 값마다 뜻·칸 수, 떨어지는 칸의 목적지
uv run python fc/dq4/tools/dq4block.py rom/dq4.nes tables           # 속성 값마다 terrain(), 떨어지기·리프트·タンス/つぼ·팻말 표
uv run python fc/dq4/tools/dq4block.py rom/dq4.nes json             # work/dq4block.json
```

## 남은 것

- 애니메이션 블록이 같은 주소의 타일을 찾지 않게 하는 코드.
- 밤 팔레트, 장소별 팔레트 예외, `$65` = 3 의 뜻.
- 旅の扉(`0A`)의 목적지를 정하는 `08:$B22E`(표 포인터 `08:$B974`)의 형식. 지금은 `1E/00` → `1F/00` 하나만 실측.
- 리프트 레코드의 넷째 바이트(`$7F`, `FF` 가 아니면 `1E:$8A68`·`$8A9A` 를 부름)의 뜻.
- 연 문 목록 `$6C0C` 을 지우는 때. 이벤트(`1D:$AEAE`·`$B379`)에서 지우는 것만 찾았고, 그룹을 옮길 때 지우는지는 확인 못 함.
- 문 모양 네 가지(`08:$8796`)가 바꾸는 블록, 3장의 잠금 2 문 경로(`1E:$B381`), 속성 `33` 의 조건(`BRK 3A 0F`), 떨어질 때 `$07BA` 의 뜻.
- `A9`·`AD`·`AE`·`AF`·`B2`·`85` 처럼 따로 읽는 곳을 못 찾은 막힌 값의 차이(`LDA $6F40,X` 꼴 정적 검색만 함). `1E:$A0B8` 이 `14`~`23` 을 따로 보는 까닭.
- 성 앞 워프 덤프(`02/00`)의 nametable 이 크게 다른 까닭(같은 맵을 걸어서 들어간 덤프는 0 다름).
- 맵 종류 `0F` 의 블록 1F 는 애니메이션 목록에 없는데 덤프의 타일이 `1D:$891E` 의 물 그림이었습니다. 다른 경로로 애니메이션이 붙는 듯합니다.
