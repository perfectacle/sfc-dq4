# DQ4(FC) 롬 뱅크 지도

PRG 512KB(16KB 뱅크 32개)의 뱅크마다 무엇이 들어 있는지와 빈 자리입니다. 주소 표기는 [dq4-ram-format.md](dq4-ram-format.md), 뱅크 호출은 [dq4-bank-format.md](dq4-bank-format.md) 를 따릅니다. 실험 과정은 [2026-10-25-13 일지](../journal/2026-10-25-13-textrest.md), [2026-10-25-22 일지](../journal/2026-10-25-22-textrest2.md), [2026-10-25-26 일지](../journal/2026-10-25-26-textrest3.md) 에 있습니다.

## 한눈에

- 대사 본문 `00`~`04`, 인물 `05`, 전투 몬스터 그림 `06`·`07`, 맵 데이터 `09`~`0B`, 타일 그림 `0C`~`0E`, 맵 그룹 표 `17`, 소리 데이터 `19` 는 데이터 뱅크입니다. 코드는 `08`, `0E`, `10`~`16`, `18`, `1A`~`1E` 와 고정 뱅크 `0F`·`1F` 에 있습니다.
- 바꿔 끼우는 뱅크는 모두 `$BFD8`~`$BFFF`(40바이트)가 리셋 조각이라 쓸 수 있는 자리는 `$8000`~`$BFD7` 입니다.
- 빈 자리(FF 가 이어진 곳)는 롬 전체에 1.9KB 쯤뿐입니다. 가장 큰 곳은 `17:$93E6`(256바이트), `1F:$FE8C`(232바이트), `1B:$BF14`(196바이트)입니다.

## 조사 방법

| 근거 | 내용 |
| --- | --- |
| 실행 | `probe/cover.lua` 를 다섯 장면에서 돌림: 부팅(1500프레임), 성 앞 → 필드 보행(980), 첫 전투(1300), 왕좌의 방 대화·명령 창(1000), 필드 걷다 조우(1100). 뱅크별 실행 오프셋 수는 `fc/dq4/tools/dq4bank.py rom cover cover.txt…` |
| 읽기 | 같은 장면에서 `probe/reads.lua`. 명령 자신을 읽는 것은 빼고 데이터를 읽은 코드 위치를 봄 |
| 디코더 | 다른 형식 문서의 디코더가 읽는 범위(대사, 맵, 필드, 인물, 이름·아이템·몬스터, 조우) |
| 그림 | 위 장면들의 CHR 덤프 타일(16바이트)을 PRG 에서 그대로 찾음: 640개 중 440개가 `0C`(171), `0D`(58), `0E`(199), `06`(11), `1A`(1) 에 있음. 1비트 폰트 129개는 `18` |
| 빈 자리 | `fc/dq4/tools/dq4bank.py rom free`: FF·00 이 16바이트 이상 이어진 곳 |

패드는 고정 뱅크의 `$C8EC` 한 곳에서 읽습니다. 스트로브 뒤 `$C8FF` 의 `LDA $4016,X` 를 X=1 로 8번 돌려 패드 2 를 `$15` 에 둡니다(X=1 이라 실제로 읽는 곳은 `$4017`). 롬에 `$4017` 을 절대 주소로 읽는 명령은 없고, `$15` 를 읽는 닿는 코드는 `$CAD8` 하나인데 `AND #$03` 뒤 `$CAEA` 가 바로 `LDA $0584` 로 덮어 값이 쓰이지 않습니다(코드 읽기). 디버그 스위치와 함께 [dq4-debug.md](dq4-debug.md#패드-2-흔적) 에 자세히 있습니다.

뱅크 끝 `$BFD8` 바로 앞까지 FF 가 이어진 곳을 「끝의 빈 자리」로 셌습니다. 이 밖에 `17:$A9A1`(16), `17:$AC03`(20), `0C:$9090`(24), `0F:$FBBE`(16) 이 FF 로 비어 있습니다. 00 이 이어진 곳(`1A` 의 `$B272`~ 등)은 표 안의 0 일 수 있어 빈 자리로 치지 않았습니다.

## 한글 패치에 주는 뜻

- PRG 는 MMC1(SUROM) 의 최대 512KB 를 다 써서 더 늘릴 수 없고, 빈 자리도 2KB 가 안 됩니다. FC 롬 안에서 대사를 늘리려면 사전을 바꾸거나 기존 자리를 다시 짜야 합니다.
- 이 프로젝트는 SFC 롬으로 옮기므로, FC 쪽은 데이터를 뽑는 곳으로만 씁니다. 옮길 데이터의 자리는 위 표의 데이터 뱅크와 각 형식 문서에 있습니다.

## 남은 것

- 뱅크 `06`, `07` 의 압축 형식과 몬스터마다의 자리(`07:$8000`~ 이 색인으로 보임). 이번에는 몬스터 1종(はさみくわがた, ID `03`)만 봄.
- `0C`~`0E` 타일 그림이 어느 장면의 어느 타일인지, 타일 덤프에서 찾지 못한 200개(압축 그림)의 자리.
- 코드 뱅크마다 `$8000` 함수 표의 길이와 함수 하나하나의 역할.
- 이번 다섯 장면에서 실행되지 않은 코드(상점, 교회, 다른 장의 이벤트 등)가 어느 뱅크에 있는지.
