# DQ4(FC) 적 조우 표

필드·던전에서 걸을 때 전투가 날지, 나면 어떤 무리가 나올지 정하는 표입니다. 디코더는 [fc/dq4/tools/dq4encounter.py](../tools/dq4encounter.py), 실험 과정은 [2026-10-25-07 일지](../journal/2026-10-25-07-encounter.md)(필드), [2026-10-25-21 일지](../journal/2026-10-25-21-encounter2.md)(던전·특수 전투·배·선제), [2026-10-25-32 일지](../journal/2026-10-25-32-encounter3.md)(그룹 3F·정상으로 탄 배·3장 남쪽·특수 전투를 부르는 곳·성수와 トヘロス), [2026-10-25-41 일지](../journal/2026-10-25-41-encounter4.md)(マネマネ·へんげのつえ·`$6E44` bit7 과 값 3·3장 터널을 진행 플래그로·불러오기) 에 있습니다. 코드와 표는 모두 뱅크 `18` 에 있고, 주소는 그 뱅크의 CPU 주소입니다. 몬스터 ID 는 [dq4-data-format.md](dq4-data-format.md#몬스터) 와 같습니다.

근거를 「실측」과 「코드 읽기」로 나눴습니다. 실측은 `fc/dq4/tools/lua/enc.lua` 로 전투를 일으켜 게임 기록과 디코더 예측을 맞춘 것입니다. 필드 7구역 240번, 던전 21층 158번, 3장 지도 아래쪽 24번, 5장 구역 1C 50번·구역 56 113번, 배 위 20번, 특수 전투 34개 전부입니다([확인](#확인)).

## 흐름

걸음마다 `18:$9BE6`(뱅크 18 함수 00)이 돕니다.

1. 조우 없음: `$0584` = 2 이거나 `$6288` bit7 이 켜져 있으면 끝(코드 읽기). `$0515` = 2(열기구)여도 끝([탈것](#배)).
2. 무리 칸 `$6E45`~`$6E48` 을 `FF`, 마릿수 `$6E49`~`$6E4C` 를 0 으로 비움(`$A0F9`).
3. 맵 안(`$41` bit7)이면 [던전](#던전)(`$9F79`)으로 갑니다. 필드면 [구역 지도](#필드-구역-지도)(`$9C19`) → 걸음 배수(`$9CCC`) → 지형 배수(`$9CB2`) → [성수](#성수와-6beb)(`$A0BA`) → 판정(`$9CF6`).
4. [구역 레코드](#구역-레코드) 바이트 0 으로 [조우율](#조우율)을 셈. 난수(`$C891`) < 조우율 이면 전투.
5. [무리 고르기](#무리-고르기)(`$9D0E`) → 전투 시작(`$A11A`). `$A11A` 는 `$6E01` 을 `$7396` 으로 옮기고 [기습·선제](#기습과-선제)(`$A20E`)를 정합니다. 전투 뒤에는 `$6E42` 를 0 으로 되돌림(`$A1A7`).

## 필드 구역 지도

필드를 16×16 칸 묶음으로 나눈 256바이트 지도입니다. 칸 = `($43 & F0) | ($42 >> 4)`, 값의 bit5-0 이 구역 번호입니다(`$9C64`).

| `$615A` | 포인터 | 지도 |
| --- | --- | --- |
| 0, 1, 3(1·2·4장) | `$A241` → `$A4BD` | 256바이트 |
| 2(3장) | `$A243` → `$A6BD` | 128바이트(8줄). Y ≥ 80 이면 그 뒤의 던전 목록 바이트를 그대로 읽음 |
| 4(5장) | `$A245` → `$A5BD` | 256바이트. 필드 0 만. 필드 1 은 Y < 0C 이면 구역 35, 아니면 34. 필드 2 는 36(`$9C3F`) |

3장 지도는 따로 길이를 재지 않습니다. `$615A` = 2 로 바꿔 필드 아래쪽 네 곳에서 싸우니 구역이 07·01·39·0A 로, `$A6BD` + 칸의 바이트(던전 목록 `$A73D`~ 안) & `3F` 와 모두 같았습니다(실측). 3장 일행은 Y ≥ 80 에 가지 못하므로 이 읽기는 실제로는 일어나지 않습니다([3장 남쪽](#3장-남쪽)).

5장 지도 값의 bit7-6 은 0~3 으로, 지도를 네 바다로 나눕니다(북서 2, 북동 3, 남서 1, 남동·가운데 0). 그러나 이 값은 쓰이지 않습니다. 배(`$0515` = 1)일 때 `$9C81` 은 지도 값이 아니라 영 페이지 `$07` 을 읽어 bit7-6 을 구역으로 삼는데, `$07` 은 앞 걸음의 구역(6비트 이하)이라 구역은 늘 `00` 입니다(실측, 아래 [배](#배)).

`fc/dq4/tools/dq4encounter.py maps` 가 지도 셋을 찍고, `--png` 로 필드 위에 구역 번호를 얹은 그림을 만듭니다(롬 화면이므로 `work/` 에만 둡니다).

### 배

`$0515` 는 탈것입니다. 0 걸음, 1 배, 2 열기구(조우 없음, `$9C19`). 배 자리는 `$6195`/`$6196`, 열기구 자리는 `$6197`/`$6198` 이고 세이브 영역에 있습니다.

배에 타는 길(코드 읽기, 아래 실측으로 확인): 걸으려는 칸의 속성이 `83`(물)이고 그 칸이 (`$6195`, `$6196`)이면 `0F:$CFD6` 이 `$0527` = 1 을 두고, 걸음이 끝날 때 `0F:$CE7B` 가 `$0527` 을 `$0515` 로 옮깁니다. 육지(속성 bit7 = 0)로 걸으면 `0F:$D01C` 가 `$0515` = 0 으로 내립니다. 이벤트가 배를 놓는 곳의 예는 `1C:$B2B5`(일행과 배를 (A8,89)에 놓고 플래그 `13` bit0 을 켬)입니다.

`$0515` = 1 이면 구역 = `$07` 의 bit7-6(`$9C81`)입니다. 지형 배수 표는 그대로라 바다(타일 0)는 낮 04, 밤 05 입니다. `$07` 을 마지막으로 쓴 곳을 걸음마다 적으니 둘뿐이었습니다.

| `$07` 을 쓴 곳 | 걸음 | 값 | 뜻 |
| --- | --- | --- | --- |
| `18:$9C88` | 1631 | `00` | 앞 걸음의 구역(이 루틴이 구역을 `$07` 에 둠) |
| `10:$8189` | 118 | `02`·`0C` | 뱅크 10 효과 처리기가 영 페이지 `$00`~`$0F` 를 되돌려 놓음. 값은 배에 타기 직전 육지 걸음의 구역 |

필드 구역은 6비트(최대 `3F`)라 bit7-6 이 늘 0 이고, 따라서 배 위 구역은 늘 `00` 입니다. 실측은 1장 필드 세이브스테이트에서 해안 칸에 서서 바로 옆 바다 칸을 `$6195`/`$6196` 에 쓰고 그 쪽으로 걸어 정상 경로로 탔습니다(`$0515` 는 게임이 씀). 해안 다섯 곳, 배 위 걸음 1749번, 배 위 전투 20번이 모두 구역 `00` 이었고 무리는 디코더와 다름 0 이었습니다. 앞 일지에서 `$0515` 를 직접 써서 네 바다를 돈 1100여 걸음도 같았습니다.

### 3장 남쪽

3장 지도가 128바이트(Y < 80)인 것은 3장 일행이 Y ≥ 80 에 닿지 못하기 때문입니다. 필드 0 의 통행 속성으로 칸을 이으면(마을·동굴 입구 칸은 지나지 않음) 3장 시작 쪽은 Y ≤ 72, ブランカへのトンネル(그룹 `42`) 너머의 エンドール 쪽은 Y ≤ 5D 이고, 남쪽 사막(Y 최대 90, 칸 415개)으로 가는 길은 사막 여관(그룹 `21`, 입구 (B2,4D)) 하나뿐입니다.

- 그룹 `42`: 입구 (84,5A) 로 들어가면 늘 `42/01` (1F,02), (79,5D) 로 들어가면 `$62AA` bit3 일 때 `42/01` (05,0F), 아니면 막힌 `42/00` (`08:$AF99`, 코드 읽기).
- 그룹 `21`: 맵 밖으로 나갈 때 아래쪽을 보고 있으면 (B2,4E), 아니면 (B2,4C) 에 섭니다(`08:$B11A`). 맵 안에서 사막으로 내려가는 길은 `$6292` bit0(마차를 얻음, 대화 `097` 이 켬)이 꺼져 있으면 `1E:$9219` 가 Y = 0F 에서 블록 02 의 속성을 `10` 으로 바꿔 막습니다.

실측: 장을 3장(`$615A` = 2)으로 둔 `21/00` (00,0A)에서 아래로 400프레임 걸으니 `$6292` = 0 이면 (00,0E) 에서 멈췄고, `$6292` = 1 이면 맵을 나가 필드 (B2,59)까지 걸었습니다. 필드 (B2,4E) 에서 위 경로를 따라 걸으니 86걸음 만에 (AD,84) 에 닿았습니다(막힘 없음). 3장 시작 세이브스테이트의 `$6292` 는 `00` 이고, 이 비트를 켜는 대화 `097` 은 5장 사막 여관의 마차 주인입니다.

`$62AA` bit3 은 3장 끝의 「터널이 뚫림」 입니다. 이 비트를 켜는 곳은 롬에 `15:$9D83`(`LDA $62AA ; ORA #08`) 하나이고, 대화 스크립트 두 곳이 부릅니다. 하나는 2장 마을 `0C/00` 의 병사(대화 `035`, `15:$9D68` 이 `$6283` bit2 가 꺼져 있으면 메시지 `034E` 뒤로 이어 감)이고, 다른 하나가 3장의 ネネ(대화 `075`, `04/00` 낮·`04/08` 밤)입니다. 3장 진행은 아래와 같습니다(코드 읽기, 아래 실측으로 확인).

| 차례 | 하는 곳 | 플래그 |
| --- | --- | --- |
| 1 | `42/00` 의 굴 파는 노인(대화 `06C`)에게 공사비를 냄 | `$6287` bit7(플래그 `0C` `80`) |
| 2 | エンドール 에 가게를 삼(`15:$A03D`) | `$6286` bit5. `04/00` 에 들어갈 때 `1C:$A3B9` 가 이 비트가 꺼져 있으면 ネネ(슬롯 `12`)를 (80,80)으로 치움 |
| 3 | `04/01` 에 들어감. `1C:$9C6F` 가 `$6287` bit7 이면 `BRK 0B CB 01` | `$6286` bit0 |
| 4 | ネネ 에게 말 걸기. `$6286` bit0 이면 메시지 `08A0`(「いま　しらせがきて どうくつが　かいつうしたって！」)·`08A2`·`08A3` 뒤 `15:$9D83` | `$62AA` bit3 |
| 5 | 필드 (79,5D) 로 들어가면 `08:$AFBA` 가 bit3 을 보고 `42/01` (05,0F) | |
| 6 | `42/01` 의 X = `1F` 에 닿으면 장 끝 검사 `1A:$B86E` | 메시지 `037C` |

실측: 3장 시작 세이브스테이트의 처음 장면(ネネ 의 대사)을 넘긴 뒤 `$6286` = `20`, `$6287` = `80` 만 써 넣고(1·2 차례), 나머지는 게임이 하게 했습니다. `04/01` 로 워프하자 `$6286` 이 `21` 이 됐고, `04/00` (06,1D) 에서 위의 ネネ 에게 말을 거니 `08A0` → `08A2` → `08A3` 뒤 `$62AA` = `08` 이었습니다. 그 상태로 필드 (79,5D) 에 아래·왼쪽 칸에서 들어간 네 번이 모두 `42/01` (05,0F) 였고, `$62AA` = `00` 인 상태(`04/01` 까지만 간 것)로 아래·왼쪽·위 칸에서 들어간 세 번은 `42/00` (05,0B) 였습니다. `42/01` 에서는 서쪽으로 빠져나가는 이주민 둘(레코드 00·01, 블록 `05:$BC90`)이 일행과 같은 통로를 반대로 걸어, 마주 서면 둘 다 멈춥니다. 옆 칸 (03,0D) 에서 4300프레임 기다려 둘이 (05,0F) 에서 사라진 뒤 걸으니 (1F,02) 에 닿았고 메시지 `037C`(「こうして　トルネコは…」)가 나왔습니다. 같은 3장 상태(`$6292` = `00`)로 필드 (B2,4E) 에서 위로 걸어 `21/00` 에 들어가 아래로 400프레임 걸으니 (00,0E) 에서 멈췄습니다. 3장 진행 플래그로도 사막 여관 남쪽은 막혀 있습니다.

## 던전

맵 안에서는 그룹 `$63` 으로 목록을 찾아 순번 `$64` 번째 바이트가 구역입니다(`$A069`). 레코드는 `[그룹, 순번마다 구역…]`, 길이 1 + `$A474[그룹]`(그룹마다 맵 수), `FF` 로 끝납니다. 목록에 없는 그룹(마을)과 구역 `FF` 인 순번은 조우가 없습니다. 장 1~4 와 5장은 다른 목록을 씁니다(`$615A` = 4 이면 5장).

| 표 | 위치 | 레코드 |
| --- | --- | --- |
| 1~4장 | `$A23B` → `$A73D`~`$A778` | 9개 |
| 5장 | `$A23D` → `$A779`~`$A810` | 25개 |
| 그룹 크기 | `$A474`, 73바이트 | [맵 표](dq4-map-format.md) 의 그룹별 맵 수와 73그룹 모두 같음 |

맵 안의 흐름(`$9F79`~`$9FB7`)은 필드와 다릅니다.

1. 그룹 `3F` 면 걷는 일행이 한 명이고 그 사람이 주인공일 때만 이어감([그룹 3F](#그룹-3f)).
2. 그룹 `3A` 면 [조우 켬/끔 칸](#그룹-3a) 을 봄.
3. 던전 목록으로 구역, 레코드, 걸음 배수(`$9CCC`). 지형 배수는 타일과 상관없이 `0F`(`$9F9B`). 성수 검사(`$A0BA`)는 하지 않습니다.

### 그룹 3A

그룹 `3A`(맵 7개, 모두 구역 41)는 `$6E05` bit7 이 켜져 있을 때만 조우합니다(`$9FC8`, 모든 순번). 순번 0·3 에서는 걸을 때마다 `$A247` 의 2바이트 자리 표(`FF` 끝)를 봅니다. 순번 0 은 `$A247`, 순번 3 은 `$A24E` 부터입니다. 바이트 0 bit5-0 = X, 바이트 1 bit5-0 = Y 이고 (X,Y)·(X+1,Y)·(X,Y+1)·(X+1,Y+1) 네 칸을 바이트 0 bit7·bit6, 바이트 1 bit7·bit6 이 「켬/끔」으로 정합니다. 그 칸을 밟으면 `$6E05` bit7 이 그 값이 됩니다.

`1E:$A5AD` 가 `$0515`·`$6E42`·`$6E41`·`$6BEB`·`$6E05` 를 한꺼번에 0 으로 지웁니다. 부르는 곳은 `1E:$A3C6` 하나이고, 그 함수(`1E` 함수 22, `1E:$A3BA`)는 리셋 뒤 시작 루틴 `0F:$C968` 이 `1E` 함수 0C·34 다음, 본 루프(`$C9ED`) 직전에 부릅니다(`0F:$C97A`, 코드 읽기). 전멸해 교회에서 되살아날 때와 타이틀에서 「ぼうけんのしょ」 를 불러올 때 돌았고, 맵 진입·필드로 나가기·전투 끝에서는 돌지 않았습니다(실측). 불러오기는 전원을 켜고 A 를 눌러 「ぼうけんをする」 → 「ぼうけんのしょ　1」 을 고른 것으로, 163프레임에 `12:$AC47` 이 칸을 작업 영역으로 옮기고 493프레임에 `1E:$A3BA` → `$A5AD` 가 돌았습니다. 300프레임에 `$0515`·`$6E42`·`$6E41`·`$6BEB`·`$6E05` 를 `01 03 7F 32 80` 으로 써 두니 `$A5AD` 에 들어갈 때 그 값이었고 돌아온 `1E:$A3C9` 에서 모두 `00` 이었습니다. 불러온 칸은 MesenCE 가 테스트러너에 넣는 SRAM 의 칸 1(1장 처음, 메시지 `0300`·`0301` 로 이어짐)입니다. 그러니 성수·トヘロス·においぶくろ·배는 전멸하거나 다시 불러오면 풀립니다. 워프로 3A/01 에 들어가 160걸음을 걸었을 때 `$6E05` 는 내내 `00` 이었고 판정은 한 번도 없었습니다. 3A/00 에서는 (02,18) 을 밟은 뒤부터 판정이 났고, 그 상태로 계단을 지나 3A/05 에서도 판정과 전투가 났습니다(실측).

## 기습과 선제

`$A20E`: k = 구역 레코드 바이트 0 bit1-0, r = rand(33)(`BRK 17 0F` 에 A = 21). 문턱 T0 = `$A45C[2k]`, T1 = `$A45C[2k+1]` 로 r ≤ T0 이면 `$6E44` = 0, r ≤ T1 이면 1, 그 위는 2 입니다.

| k | T0, T1 | 보통 | 기습(1) | 선제(2) |
| --- | --- | --- | --- | --- |
| 0 | 1E, 1F | 241/256 | 8/256 | 7/256 |
| 1 | 1B, 1F | 194/256 | 31/256 | 7/256 |
| 2 | 1B, 1C | 217/256 | 8/256 | 31/256 |
| 3 | 18, 1C | 194/256 | 31/256 | 31/256 |

`$A123` 에서 `$6E44` 를 바꿔 전투 첫 메시지를 보니 1 은 `01DC`(「…は　こちらが　みがまえるまえに　おそいかかってきた！」), 2 는 `01E0`(「しかし　…は　まだこちらに　きづいていない！」), 0 은 그 메시지 없이 바로 싸움이었습니다(실측). bit7·bit6 만 켠 `80`·`C0` 은 0 과 같이 시작했습니다. 특수 전투는 늘 `C0` 입니다(`$A1F3`, 실측 34개). 특수 전투 바이트 7 의 bit7-6 이 bit1-0 으로 가고(`$A1E4`~`$A1EA`), 그 뒤 `$A1F8` 은 디버그 스위치 `$C000` bit5 가 켜져 있으면(제품판 `FF`) bit6 을 한 번 더 켜고, 꺼져 있으면 건너뜁니다(코드 읽기). 앞의 `ORA #$C0` 이 이미 켰으므로 어느 쪽이든 값은 같습니다.

bit1-0 은 시작 메시지만이 아니라 차례마다 「누가 움직이나」 입니다. 전투 루틴의 `11:$8D9B` 가 값 0 이면 C = 1, 3 이면 C = 0 을 돌려주고, `11:$80FF`·`$AD21` 이 1 을, `11:$8656`(도망) 이 2 를 따로 봅니다. 차례가 끝나면 `11:$AA7C` 가 bit1-0 을 지웁니다. 전투 중에는 `11:$8A20`(메시지 `01E1` 「しかし　まもののむれは おどろき　とまどっている！」 뒤)·`$9247`·`$A2BF`·`$BCD8` 이 3, `11:$9250`·`$B782` 가 2, `11:$842C`·`$AF80` 이 1 을 넣습니다(코드 읽기). 실측: 1장 필드에서 걸어 난 전투의 `$A123` 에서 `$6E44` 를 `03` 으로 바꾸니, 「あらわれた」 뒤 첫 차례에 공격 메시지 없이 `11:$AA81` 이 `00` 을 쓰고 둘째 차례부터 보통으로 싸웠습니다(`00` 은 첫 차례부터 `004C` 「…の　こうげき！」). 앞 일지가 「메시지가 더 나오지 않았다」 고 본 것은 이 빈 차례입니다.

bit7 은 「이벤트가 부른 전투」 입니다. 전투 끝 `18:$A19F` 가 bit7 이 꺼져 있을 때만 `BRK 15 EF`(`1E` 함수 15 = `1E:$A1C9`, 맵·필드 화면과 음악을 되살림)를 부릅니다. 특수 전투는 부른 이벤트 스크립트가 그 뒤 화면을 스스로 그립니다. 실측: 1장 첫 전투 세이브스테이트에서 `$6E44` 를 `00`·`80` 으로 두고 이기니 메시지(`0009`·`000C`·`01C8`·`01C9`·`0298`·`02A0`·`01C3`)는 같았고, `00` 은 `1E:$A1C9` 를 지나 필드로 돌아왔으나 `80` 은 지나지 않아 검은 화면에 명령 창만 떴습니다. 나머지 읽는 곳(`10:$A4E3`·`$B0EF`, `11:$A6AC`·`$A832`·`$AFA5`·`$B170`·`$B8A0`·`$B8AB`, `12:$A321`·`$A364`, `13:$8094`)이 무엇을 바꾸는지는 남은 것입니다.

bit6 은 도망칠 수 없음입니다. 1장 첫 전투 세이브스테이트에서 `$6E44` 를 프레임마다 쓰고 기다림을 넷으로 바꿔 にげる 를 골랐더니, `00`·`80` 은 같은 두 번(「にげだした！」 `001D` 만)에 도망쳤고 `40` 은 네 번 모두 「しかし　まわりこまれてしまった！」(`0004`)였습니다(`11:$8627` 의 `BIT $6E44 ; BVS`).

보통 전투에서 나온 값의 수(실측): k = 0 전투 268번 중 0 이 256, 1 이 5, 2 가 7번(기대 252·8.4·7.3). k = 3 인 구역 1C(5장 필드) 전투 50번 중 37·5·8번(기대 37.9·6.1·6.1). k = 2 인 구역 56(5장 サントハイム 성 `01/01`) 전투 107번 중 91·2·14번(기대 90.7·3.3·13.0).

## 특수 전투

`$A1AD`(뱅크 18 함수 01): A = 번호, `$A23F` → `$A34C` 부터 8바이트씩 34개(끝 `$A45C`). 바이트 0~3 = 몬스터 ID, 4~7 bit3-0 = 마릿수, 바이트 7 bit7-6·bit6 은 `$6E44` 로 가지만 `ORA #$C0` 이 늘 켭니다. 그 뒤 `$A123`(음악 고르기)부터는 보통 전투와 같습니다. 몬스터 ID `AD`·`AE`·`BC` 는 `$A123` 에서 따로 음악을 고릅니다(코드 읽기).

부르는 곳:

- `LDA #번호 ; BRK 01 8F`: 뱅크 1C·1D·1E 21군데(예: 05 = ピサロのてさき + おおめだま `1C:$AD6E`, 03 = キングレオ `1D:$ABC2`, 19 = デスピサロ `1C:$BB71`). 06 = どぐうせんし `1D:$9C83` 은 5장 `45/01` 의 석상이 일행 옆에 오면 부릅니다(실측: 판정을 끈 채 무작위로 걸어 8번 중 3번, 스택의 복귀 주소 `1D:$9C87`).
- 상자: 내용 `FE`(`1E:$B868`, 메시지 `0299` 뒤 `LDA #00`) → 00 ミミック, `FD`(`1E:$B86F`) → 1B ひとくいばこ([dq4-shop-format.md](dq4-shop-format.md)). 실측: `03/02` 상자 (0F,07)에서 しらべる 하니 `$A1AD` 에 A = 00.
- `1C:$AF04`: `LDA $B024,X`(X = `$6287` & 7) 로 07~0B(ミスター ハン, ラゴス, ビビアン, サイモン, ベロリンマン) 중 하나. 투기장 상대로 보입니다. 표는 다섯 바이트이고 바로 뒤는 코드입니다.
- デスパレス(그룹 `03`): 말을 걸면 `15:$B10E` 가 대화 전에 `08:$B725` 를 불러 인물 겉모습(`$DA`)을 `08:$B756` 표 `2A 36 37 0D 35 34` 에서 찾고, Y = `1C` + 순번(없으면 `1C`)으로 이벤트 20(`1C:$B968`: `TYA ; BRK 01 8F`)을 부릅니다. 겉모습 `19`·`05`·`0C`·`08` 은 빼고, へんげのつえ 로 몬스터 모습일 때(`$6296` ≠ 0 이고 `$6297` bit7)는 부르지 않습니다([아래](#デスパレス-와-へんげのつえ)).

| 겉모습 | 2A | 36 | 37 | 0D | 35 | 34 |
| --- | --- | --- | --- | --- | --- | --- |
| 특수 전투 | 1C ライノソルジャー | 1D マネマネ | 1E アームライオン | 1F しにがみ | 20 ミニデーモン | 21 ベンガル |
| 실측(말 걸기) | `03/00` (19,0A) | `03/01` (05,14) | `03/00` (09,0F) | `03/00` (17,05) | `03/00` (20,04) | `03/00` (09,1A) |

01 どぐうせんし(06 과 같은 무리)는 부르는 곳이 없습니다. 롬의 `BRK 01 8F` 30곳(그 밖에 `b1` = `01`·`81`, `b2` = `88`~`8F` 꼴 7곳은 데이터·피연산자)에서 A 는 모두 `LDA #번호` 이거나 투기장 표(`$6287` & 7 이 5~7 이면 표 뒤의 `20 0B D2` 를 읽음)·デスパレス(`1C`~`21`)입니다. `$A1AD` 로 뛰는 `JSR`·`JMP` 는 없고(뱅크 18 함수 표 하나뿐), `BRK` 자리로 뛰어 다른 A 를 넘기는 분기·점프도 상자의 `1E:$B868`(`LDA #00 ; BEQ`) 말고는 없습니다. 인물 블록 명령 `21 NN`(`1F:$DA8A`, [dq4-npcblock-format.md](dq4-npcblock-format.md#명령))도 특수 전투를 부를 수 있지만, `fc/dq4/tools/dq4encounter.py scripts` 가 맵 목록·이벤트 목록(뱅크 `1C`)의 블록 2117개를 [fc/dq4/tools/dq4npcblock.py](../tools/dq4npcblock.py) 로 풀어 보니 명령 5010개 가운데 `21` 은 0번이었습니다(정적 검색).

### デスパレス 와 へんげのつえ

へんげのつえ(아이템 `68`)를 쓰면 `1E:$B02F` 가 `$6296` = `78`(120걸음)을 두고 모습을 `1E:$B079` 표에서 고릅니다. デスパレス(그룹 `03`)에서는 난수 < `C0` 이면 표의 `25`~`33` 칸(몬스터), 아니면 `00`~`24` 칸(사람)이고, 표 값에 bit7 = (칸 ≥ `25`) 를 붙여 `$6297` 에 씁니다. 다른 곳에서는 순번 01 맵의 X 01~0D, Y 0F~17 안이면 늘 몬스터, 아니면 デスパレス 와 같은 난수입니다(코드 읽기). 걸음마다 `1E:$9E6B` 가 `$6296` 을 1 줄이고, 0 이 되면 `1E:$97B8` 로 겉모습을 되돌립니다. `1E:$9817` 도 `$6296` 을 0 으로 지웁니다(부르는 때는 남은 것).

대화 앞 `15:$B132` 의 검사는 `$6296` = 0 이면 전투, 아니면 `$6297` bit7 이 꺼져 있을 때만 전투입니다.

실측(1장 왕좌의 방 세이브스테이트에서 워프):

- `03/01` (06,14) 에서 왼쪽의 マネマネ(겉모습 `36`)에게 말 걸기: 메시지 `0446`(「くふふ！ うまそうな　にんげんだわい！」) 뒤 `08:$B752` 에서 Y = `1D`, `$A1AD` 에 A = `1D`, 화면에 マネマネ 1마리.
- 같은 자리에서 `$6296`/`$6297` 을 써 넣고 말 걸기: `78 80`·`01 A5` 는 `0758`(보통 대사)만 나오고 전투 없음, `78 05`(사람 모습)는 `0448`(「おのれ！　くせものめ！」) 뒤 전투 `1D`, `00 80` 은 `0446` 뒤 전투 `1D`.
- ライアン 소지품 첫 칸에 へんげのつえ 를 넣고 どうぐ → つかう: 메시지 `019E` 뒤 `1E:$B031` 이 `$6296` = `78`, `1E:$B071` 이 `$6297` 을 씀. `03/01` 에서 쓰고 바로 マネマネ 에게 말 건 12번 가운데 `$6297` 이 `A4`·`A5`·`BD`·`BE`·`C3`·`C4`(bit7) 인 10번은 전투 없음, `4C` 인 2번은 `0447`·`0448` 뒤 전투 `1D`.
- `$6296` = `02` 로 두고 두 걸음: `1E:$9E71` 이 `01`, `00` 을 씀.

`fc/dq4/tools/dq4encounter.py bosses` 가 34개와 부르는 곳을 찍습니다.

실측: `BOSS=NN` 으로 34개를 모두 일으키니 `$6E45`~`$6E4C` 가 표와 같았고, 「…が　あらわれた。」(`0005`)가 무리 수만큼 나왔습니다(34개 모두). 화면도 표의 몬스터였습니다(0C 의 きゅうけつこうもり 2 + うらぎりこぞう 2, 16 의 アンドレアル 3, 18 의 エビルプリースト + スモールグール 3, 14 의 エスターク). 따로 5장 45/01 을 걷다가 이벤트가 스스로 특수 전투를 불렀고, 번호는 06 이었습니다(위).
