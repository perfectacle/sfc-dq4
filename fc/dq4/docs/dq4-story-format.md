# DQ4(FC) 이야기 진행: 플래그를 켜는 장면, 장마다 진행 순서, 블록 이벤트 루틴 표

FC 「드래곤 퀘스트 IV」 일본판 Rev A(`rom/dq4.nes`)의 이벤트 플래그(`$627B`~`$62EE`, [dq4-save-format.md](dq4-save-format.md#이벤트-플래그-627b62ee))마다 그 비트를 켜는 장면을 에뮬레이터로 일으켜 확인한 결과와, 그것을 장마다 이야기 순서로 늘어놓은 표입니다. 포팅할 때 이 표가 「어느 장면 뒤에 어느 플래그가 서 있어야 하나」의 근거가 됩니다. 인물 표·블록 명령에서 새로 확인한 것과 블록 이벤트 루틴의 정적 표도 여기에 둡니다. 실험 과정은 [2026-10-25-46 일지](../journal/2026-10-25-46-event4.md)·[2026-10-25-56 일지](../journal/2026-10-25-56-event6.md)·[2026-10-25-60 일지](../journal/2026-10-25-60-flags2.md)·[2026-10-26-21 일지](../journal/2026-10-26-21-flags3.md)·[2026-10-26-31 일지](../journal/2026-10-26-31-flags4.md) 에 있습니다.

근거가 실측이 아니라 코드 읽기인 줄에는 「코드 읽기」라고 적었습니다. 도구는 [fc/dq4/tools/dq4story.py](../tools/dq4story.py), 뜻 표는 [fc/dq4/tools/dq4flags.py](../tools/dq4flags.py), 프로브는 [fc/dq4/tools/lua/flagsweep.lua](../tools/lua/flagsweep.lua)·[npcbits.lua](../tools/lua/npcbits.lua) 입니다.

```sh
uv run python fc/dq4/tools/dq4story.py rom/dq4.nes story [N]     # 장마다 진행 순서 → 플래그
uv run python fc/dq4/tools/dq4event.py rom/dq4.nes flags --meaning # 비트마다 뜻([확인] 184)
uv run python fc/dq4/tools/dq4story.py rom/dq4.nes events         # 블록 이벤트 루틴 138개가 보는 것·하는 것
uv run python fc/dq4/tools/dq4story.py rom/dq4.nes jobs READY work/ev5/jobs.tsv   # 남은 [추정] 비트마다 실험 시나리오
MESENCE=... LIBDIR=$(uv run krpatch fc lua) \
  uv run python fc/dq4/tools/dq4story.py rom/dq4.nes run work/ev5/jobs.tsv work/ev5/runs -j 4
uv run python fc/dq4/tools/dq4story.py rom/dq4.nes confirm work/ev5/runs   # 비트마다 켜고 끈 장면
```

## 확인하는 법

한 비트를 「확인」 했다는 것은 그 비트를 켜는 롬의 자리(BRK 플래그 명령, 대화 스크립트의 `flag|=`, 인물 블록 명령 `27`)가 실제로 돌아 `$627B+n` 에 그 비트를 쓰는 것을 프로브로 보고, 그때 화면에 나온 메시지로 장면을 정했다는 뜻입니다.

### 시나리오

`dq4story.py jobs` 가 `[추정]` 비트의 쓰는 곳마다 시나리오를 만듭니다. 출발은 장마다 조작할 수 있는 세이브스테이트(`READY/chN.mss`)와 그 SRAM 덤프(`chN.sram`)입니다.

| 쓰는 곳 | 시나리오 | 입력 |
| --- | --- | --- |
| 대화 스크립트 `flag|=` | 그 대화를 쓰는 맵으로 워프하고, 첫 인물을 주인공 앞에 붙여(`PIN=auto`) 대화 번호를 바꿔 말 건다(`TID`). 대화 나무에서 그 문장까지 지나는 조건(플래그·장·시간·예/아니오·아이템)을 `SET` 과 입력으로 맞춤 | A 로 말 걸기·넘기기(예/아니오는 「はい」, 조건이 「いいえ」 면 B) |
| 뱅크 `15` 호출 루틴·뱅크 `1C` 이벤트 안의 BRK | 그 루틴에 닿는 대화(호출 문장, [이벤트 표](dq4-script-format.md#이벤트-표)를 부르는 대화)로 위와 같이 | 같음 |
| 뱅크 `1D` 블록 이벤트 안의 BRK | 그 이벤트 명령이 있는 블록의 맵으로 워프. 도착 자리는 맵 입구와, 루틴이 `$44`/`$45` 와 견주는 값의 조합. 루틴이 검사하는 플래그를 모두 켠 변형도 | B 로 대사 넘기기 |
| 인물 블록 `27` | 그 블록의 맵(이벤트 목록이면 그 목록의 플래그를 켜서)으로 워프. 블록의 `2E x y` 자리에 도착하는 변형도 | 같음 |

모든 시나리오에서 대상 비트를 먼저 끄고(끄는 곳이면 켜고) 들어가, 그 비트가 바뀌는지를 봅니다. 값을 치르는 대화가 막히지 않게 골드를 `FFFF` 로 두고, 뱅크 `1C`·`1D` 의 특수 전투 `BRK 01 8F`(22곳)를 메모리상 `EA` 로 바꿔 보스 전투를 건너뜁니다(롬 파일은 그대로). 장은 그 맵 그룹의 이야기가 있는 장을 먼저 고르고, 맵에 들어갈 때 그 블록의 인물 목록이 실리는 장만 씁니다([인물 목록 표](dq4-save-format.md#맵에-들어갈-때-인물-목록을-바꾸는-표)를 장 시작 플래그로 계산).

| READY | 만든 법 | 워프 때 걷는 쪽 |
| --- | --- | --- |
| `ch1` `ch2` `ch5` | `work/state/dq4-chN-start.mss` 그대로 | 아래 |
| `ch3` | 3장 시작에서 아래를 한 번 누르고(이벤트 `2F` 가 패드 입력을 기다림) B 로 머리 장면을 넘김 | 아래 |
| `ch4` | 4장 시작에서 B 로 머리 장면을 넘겨 `15/00` (1A,02) | 오른쪽 |

### 프로브 `flagsweep.lua`

워프 드라이버(`warp.lua`) 위에서 플래그 영역·일행 자리 `$616A`~`$6177`·`$618E` 쓰기를 쓴 곳과 함께 남기고, 메시지(`16:$8656`), 대화 진입·번호, 블록 이벤트 명령(`1F:$DEDD`), 대화 이벤트(`1C:$AD5F`)·맵 이벤트(`1D:$B74D`)·특수 전투(`18:$A1AD`), 맵 바뀜을 프레임과 함께 씁니다. BRK 플래그 처리기(`1F:$C4BC`~`$C4EF`)에서 쓰면 BRK 자리를, 블록 명령 `27`~`29` 처리기(`1F:$DC09`~`$DC2F`)에서 쓰면 인물 슬롯(`$51`)을 붙입니다. 맵에 들어갈 때마다 `08:$B6BA`·`$B6C3` 이 `$6289`·`$628B` 에 쓰는 것은 `confirm` 에서 뺍니다.

### 맵을 나가면 지워지는 바이트

워프로 필드에 나가는 순간 `1E:$9316`·`$9319` 가 `$6285`·`$6289` 를 0 으로 쓰고, `1E:$931C` 가 `BRK 1F DB 7F` 로 `$629A` bit7 을 끕니다(2장·4장 READY 에서 필드로 워프해 확인). 맵에 들어갈 때마다 `08:$B6BD` 도 `$629A` bit7 을 끄고, `08:$B6C3` 이 `$628B` 를 `FF` 로 씁니다. 그래서 `$6285`·`$6289`·`$628B` 와 `$629A` bit7 의 비트는 「이 마을·던전에 있는 동안」의 표시입니다. 맵 → 맵 워프에서도 `$6289` 는 지워지고 `$6285` 는 남습니다([2026-10-25-53 일지](../journal/2026-10-25-53-shopenc.md)). `$6285` 는 필드로 나갈 때만 지워집니다. 1장 끝 조건 `$6285` bit2 도 바트랜드 성 앞(`02/00`)에 있는 동안만 서 있으면 됩니다.

### `02/01` 레코드 20 이 빠지는 곳

`02/01` 레코드 20 이 실린 직후 `80` 자리로 빠지는 것은 장소별 손질 루틴(`1C:$A010`, [dq4-shop-format.md](dq4-shop-format.md#들어갈-때-숨는-인물)·[dq4-map-format.md](dq4-map-format.md#장소별-인물-손질))의 `02/01` 처리기 `1C:$A171` 입니다. 1장 성 앞마당에서 `02/01` 로 워프하며 `$6F7A`(슬롯 `1A` X)의 쓰기를 잡으니 `1C:$99E9` 가 `10` 을 쓴 다음 프레임에 `1C:$A037` 이 `80` 을 썼고, 그 직전 실행 주소가 `$A17B`·`$A035`(고리 `LDY #9`·`LDX #0C`)였습니다.

### 블록 이벤트 루틴 138개

`dq4story.py events` 가 `1D:$B639` 표의 루틴마다 쓰는 블록과, 루틴을 갈래·JSR(뱅크 `1D`, 3단)까지 따라가며 본 것을 찍습니다(코드 읽기). 「자리」 는 `$44`/`$45` 와 견주는 값, 「봄」 은 BRK 플래그 검사, 「플래그 읽음」 은 `LDA $62xx` 뒤 `AND`·`ASL` 로 본 비트, 「읽음」 은 인물 표 열·일행 패턴·맵 번호처럼 조건이 될 RAM, 「패드」 는 `$14` 를 읽음, 「켬·끔」 은 BRK 플래그 쓰기, 메시지는 BRK 메시지와 `$0589`/`$058A` 에 넣는 번호입니다. 138개 중 아무것도 찾지 못한 것은 24개이고, 대개 다른 인물의 블록 주소나 `1F` 의 공통 루틴으로 판단합니다.

```
21   1D:$A1F5 02/01:06 02/01:12 02/01:17 외 2 | 플래그 읽음 $627E&10
2F   1D:$A416 16/01:0A | 패드
4A   1D:$A9D8 04/07:14 | 읽음 인물 방향; 켬 $6284&40 $6288&80; 메시지 0386 0387
```

예: 이벤트 `2F`(3장 시작 `16/01` 슬롯 `0A`)는 패드 `$14` 의 방향 비트가 서면 C 를 세웁니다. 3장 시작 세이브스테이트가 2500프레임 동안 그대로였다가 아래를 한 번 누르자 바로 메시지 `031F` 로 넘어갔습니다.
