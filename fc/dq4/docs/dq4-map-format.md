# DQ4(FC) 마을·던전 맵

필드(세계 지도)가 아닌 맵 279개의 블록 배치와 출구 표입니다. 디코더는 [fc/dq4/tools/dq4map.py](../tools/dq4map.py), 실험 과정은 [2026-10-25-02 일지](../journal/2026-10-25-02-map.md) 에 있습니다. 주소 표기는 [dq4-ram-format.md](dq4-ram-format.md) 를 따릅니다.

## 장소 번호

맵은 **(그룹, 순번)** 두 바이트로 가리킵니다. 지금 있는 곳은 RAM `$63`(그룹)·`$64`(순번)입니다. 예: 바트랜드 성 앞마당은 `02/00`, 왕좌의 방은 `02/01` 입니다.

| 표 | 위치 | 내용 |
| --- | --- | --- |
| 그룹 표 | `17:$B181`(`BRK 81 7F` = 뱅크 17 함수 1 의 주소) | 그룹마다 레코드 목록의 16비트 포인터. `FFFF` 로 끝남(그룹 `00`~`48`, 73개) |
| 레코드 | 그룹 포인터 + 순번 × 3 | 맵 번호 1바이트, 맵 데이터 포인터 2바이트 |

그룹의 맵 수는 다음 그룹 포인터까지의 레코드 수입니다. 마지막 그룹 `48` 은 다음 포인터 자리가 `FFFF` 라 이 방법으로 셀 수 없고, 레코드가 맵 번호 `FF` 에서 끝납니다(`48/00`~`48/09`, 10개).

맵 번호는 레코드 첫 바이트이고 RAM `$0550`·`$0028` 에 들어갑니다(`08:$B708`, `0F:$E94E`). `$0550` 에는 바이트 그대로, `$0028` 에는 아래 6비트만 들어갑니다. 아래 6비트는 279개 맵에 74가지 값뿐이라 장소가 아니라 맵 종류(지형 세트)로 보입니다(예: `03` 을 쓰는 맵이 29개). 위 2비트는 맵의 성질입니다.

| 비트 | 맵 수 | 뜻 | 근거 |
| --- | --- | --- | --- |
| 7 | 13(`03/03` `0E/00` `14/00` `1A/00` `1B/00` 등) | 맵 밖 칸을 무늬로 채움. 아래 [맵 밖 칸](#맵-밖-칸) | 실측 |
| 6 | 124(그룹 `2C`~`42`·`48` 의 거의 모두 등) | 이동 주문·아이템이 듣지 않는 맵으로 보임. `$41` bit7 일 때 `1E[2B]`(`1E:$AEEE`)가 `08[0F]`(`08:$B71C`, `BIT $0550`)로 이 비트를 보고 C = 0 을 돌려줌. 이동 주문·아이템 루틴 `1E[24]`(`1E:$AD83`, `12:$A6C8`·`$AFC6`·`$B15E` 가 부름)은 C = 0 이면 소리 `92` 를 내고 아무 데도 가지 않음 | 코드 읽기 |

`18/00`(`C5`)·`29/00`(`CB`)·`38/00`(`D6`)은 둘 다 켜져 있습니다. 맵마다의 값은 `fc/dq4/tools/dq4map.py list` 의 「맵번호」 입니다.

맵 데이터는 (그룹, 순번) 순서로 뱅크 `09` → `0A` → `0B` 에 이어 붙어 있습니다. 뱅크는 `0F:$E9AB` 가 정합니다: `(2C,08)` 미만이면 `09`, `(45,04)` 미만이면 `0A`, 나머지 `0B`.

## 맵 데이터

머리 3바이트 뒤에 비트열이 옵니다(`0F:$E957`).

| 바이트 | 내용 |
| --- | --- |
| 0 | 폭(블록 수) |
| 1 | 높이 |
| 2 | bit7-6 + 2 = 블록 값의 비트 수, bit4-0 → RAM `$0520`(맵 밖 칸의 블록 번호, 아래) |

비트열은 바이트마다 bit7 부터 읽습니다(`0F:$E618`). 위치는 `폭 × 높이 − 1` 을 나타내는 데 필요한 비트 수(왕좌의 방 32×36 이면 11비트)로, 왼쪽 위부터 가로로 센 칸 번호입니다. 포인터가 `$BFD8` 에 닿으면 다음 뱅크로 넘어갑니다(뱅크 `0B` 는 `$801A` 부터).

해제 결과는 RAM `$7800` 부터 폭 × 높이 바이트입니다. 한 바이트에 아래 5비트 블록 번호, 위 3비트 속성이 들어갑니다.

### 첫 패스: 블록 번호

1. 블록 비트 수만큼 읽은 값으로 맵 전체를 채운다(`$E5BF`).
2. 2비트 명령을 되풀이한다(`$E588`).

| 명령 | 하는 일 |
| --- | --- |
| `0` | 쓸 값을 정한다(`$E672`). 값 하나를 읽고, 이어지는 2비트가 `0` 이 아니면 그 명령으로. `0` 이면 1비트를 더 읽어 1 이면 **패스 끝**, 0 이면 값 셋을 더 읽어 **2×2 무늬**(왼쪽 위·오른쪽 위·왼쪽 아래·오른쪽 아래) |
| `1` | 사각형(`$E6A1`). 위치 둘(왼쪽 위, 오른쪽 아래)을 읽어 채운다. 2×2 무늬면 2칸 간격으로 |
| `2` | 길(`$E793`). 위치와 방향 2비트(0 위, 1 오른쪽, 2 아래, 3 왼쪽)를 읽고 점을 찍은 뒤, 1비트씩 읽어 0 이면 그 방향으로 한 칸(2×2 무늬면 두 칸) 가며 찍는다. 1 이면 2비트 부명령: `0` 오른쪽으로 돌고 한 칸, `1` 왼쪽으로 돌고 한 칸, `2` 갈림길(1비트로 방향을 정하고 지금 자리를 쌓아 둔 뒤 돌고 한 칸), `3` 1비트가 0 이면 새 길(위치·방향부터), 1 이면 쌓아 둔 자리로 돌아감(쌓인 것이 없으면 길 끝) |
| `3` | 점 하나(`$E78A`). 위치를 읽어 찍는다 |

### 둘째 패스: 위 3비트

첫 패스가 끝나면 2비트를 읽어(`$E5A3`) 0 이 아니면 그 수를 값의 비트 수로 삼아 같은 명령을 한 번 더 돌립니다. 이때는 칸의 위 3비트만 바꿉니다(`값 << 5`). 사각형 명령은 2×2 무늬여도 한 칸 간격으로 씁니다(`$E6F7`).

해제가 끝나면 `$E562` 부터 BRK 로 뱅크 `1E`·`1D`·`1B` 의 뒤처리를 부릅니다. 아래 확인은 그 전(`$E560`) 시점입니다.

### 맵 밖 칸

맵 폭·높이 밖의 칸을 물으면 `0F:$D403` → `$D44C` 가 블록 번호를 돌려줍니다. 맵 번호 bit7 이 꺼져 있으면 늘 `$0520`(머리 바이트 2 의 아래 5비트)입니다. 켜져 있으면 (X & 7, Y & 7) 로 무늬 표 `$D469`(열 비트 `01 02 04 … 80`)와 `$D471`(줄 마스크 `44 EE EE 44 11 BB BB 11`)을 AND 해 0 이 아니면 `$0520`, 0 이면 `$0582` 를 돌려줍니다. `$0582` 는 맵 종류 `$28` 이 `0F` 미만일 때 `08:$8A92` 의 `$28` 번째 바이트입니다(`08:$8A85`). 8×8 칸마다 반씩 섞인 무늬로, 마을·성 둘레를 두 블록으로 채웁니다.

실측: 5장 시작 세이브스테이트(`14/00`, 맵 번호 `85`, `$0520` = `03`, `$0582` = `04`)에서 걸으며 `$D451`·`$D461`·`$D465` 를 trace 하니 맵 밖 칸 50번 중 `$0520` 25번, `$0582` 25번이었고, 50번 모두 (X, Y) 로 고른 쪽이 위 무늬와 같았습니다.

## 출구 표 `$05A0`

맵에 들어갈 때 `1B:$8101` 이 채웁니다. 7바이트씩, 첫 바이트 `FF` 로 끝납니다.

| 오프셋 | 내용 |
| --- | --- |
| +0, +1 | 출구 칸 X, Y |
| +2, +3 | 목적지 그룹·순번(→ `$63`, `$64`) |
| +4, +5 | 도착 X, Y |
| +6 | 플래그(아래 연결 표의 끝점 플래그 `& C3`) |

### 연결 표

출구는 맵마다 따로 있지 않고, 두 장소를 잇는 **연결** 125개가 한 표에 있습니다(`1B:$8221` 의 포인터 → `1B:$8223`). 연결 하나는 10바이트, 끝점 둘이 5바이트씩입니다.

| 끝점 바이트 | 내용 |
| --- | --- |
| 0, 1 | 그룹, 순번 |
| 2, 3 | 칸 X, Y |
| 4 | 플래그. bit2 가 켜져 있으면 도착 좌표를 bit1-0 방향(0 위, 1 오른쪽, 2 아래, 3 왼쪽, 방향 표 `0F:$D22C`)으로 한 칸 옮김 |

현재 장소와 같은 끝점이 있으면 그 칸이 출구, 반대쪽 끝점이 목적지·도착 자리가 됩니다. 목적지 그룹이 `45`(순번 4·5)·`40` 이면 이벤트 플래그 `$62AA` 에 따라 순번이 바뀝니다(`1B:$81BF`, 코드 읽기). `32` 는 BRK 플래그 검사를 거칩니다(남은 것).

## 인물

맵에 들어갈 때 `1C:$9878` 이 RAM 인물 표(슬롯 32개, 열마다 `$20` 바이트: `$6F60` X, `$6F80` Y, `$7000` 방향 …)의 슬롯 6부터 채웁니다. 슬롯 0~5 는 주인공과 일행입니다. 레코드에서 꺼내는 대화 번호·그림 번호·움직임과 대화 스크립트는 [dq4-script-format.md](dq4-script-format.md#대화-번호) 에 있습니다.

| 표 | 위치 | 내용 |
| --- | --- | --- |
| 그룹 포인터 | `05:$8000 + 그룹 × 2` | 그 그룹의 첫 목록 |
| 목록 | 그룹 포인터부터 순번 수만큼 | 레코드들, 첫 바이트 `00` 으로 끝남 |
| 진행 목록 표 | `1C:$9D0E` 의 워드 → `1C:$9D10` | 6바이트 56줄, `FF` 로 끝남([진행 목록](#진행-목록)) |

레코드는 머리 뒤에 블록 둘이 붙을 수 있습니다(`1C:$9B71`).

| 부분 | 내용 |
| --- | --- |
| 바이트 0 `F` | bit4: 낮(`$62ED` < `78`)에 인물 표에 넣고 블록1 이 있음. bit3: 밤에 넣고 블록2 가 있음. bit2-0: 밤에 낮과 다른 바이트를 쓸지 |
| 머리 | 7바이트. `F` 의 bit4·bit3 이 모두 켜져 있으면 bit0·bit1 이 꺼진 만큼 1바이트씩, bit2 가 꺼지면 2바이트 더 |
| 블록 | 길이 바이트 + 그만큼의 본문. 인물 표 `$7060/$7080` 이 블록1 본문 주소 |

| 머리 바이트 | 낮에 쓰는 것 | 근거 |
| --- | --- | --- |
| 0 bit7, 3 bit7-2 | 그림 번호(겉모습) | 실측(RAM 그림 표와 93명) |
| 1 bit4-2, 4 | 대화 번호 | 실측 |
| 1 bit6 | 그림 번호 bit7 | 실측 |
| 2 bit7-4 | 움직임(걸음 사이 간격, 0 = 제자리. 밤은 bit3-0) | 실측(`$7040`) |
| 3 bit1-0 | 방향 | 실측(`1C:$98ED`) |
| 5, 6 bit6-0 | X, Y | 실측 |

밤 레코드의 덧붙은 바이트와 뜻은 [dq4-script-format.md](dq4-script-format.md#대화-번호) 의 표와 같습니다.

### 진행 목록

`1C:$9D0E` 를 밤·이벤트용 대체 목록으로 짐작했지만, 이야기 진행 플래그로 고르는 목록 표였습니다. 밤은 목록을 바꾸지 않고 레코드의 F bit3 으로 가릅니다. 맵에 들어갈 때 `1C:$9CC1` 이 줄을 차례로 보고, (그룹, 순번)이 같고 플래그 `$627B` + 바이트 3 & 바이트 2 가 켜진 첫 줄의 목록(뱅크 1C, 주소 = 바이트 4·5)을 씁니다. 레코드 형식은 뱅크 05 목록과 같습니다.

| 바이트 | 내용 |
| --- | --- |
| 0, 1 | 그룹, 순번 |
| 2 | 플래그 마스크 |
| 3 | 플래그 번호(`$627B` + n) |
| 4, 5 | 목록 주소(뱅크 1C) |

56줄이 쓰는 플래그는 `$6282`(끝낸 장: `10` 20줄, `40` 7줄), `$62A1` bit5 10줄, `$6295` bit0 4줄, `$6283` bit7 6줄, `$6284` bit6 4줄, `$627B` 3줄, `$627F`·`$628A` 1줄씩입니다. 플래그의 뜻은 [dq4-save-format.md](dq4-save-format.md) 를 따릅니다.

줄을 고른 뒤 `1C:$9C6F` 가 보통 목록으로 되돌리는 경우가 있습니다. `$62A5` bit7 이 켜져 있으면 늘 그대로 둡니다. 그렇지 않고 `$6282` bit4 나 `$6287` bit7 이 켜져 있으면, 장소 04/01, 12/02, 02/xx(02/03 빼고), `$6295` bit1 이 켜진 15/02 를 되돌립니다(04/01 은 `$6286` bit0 을 켬). 플래그 시험 BRK `n EB m` 은 비트가 꺼져 있으면 Z = 1 입니다([dq4-save-format.md](dq4-save-format.md)).

| 조작(워프, `SET`) | 장소 | 고른 목록 | 인물 표(FF 아닌 슬롯, 그중 숨은 80) |
| --- | --- | --- | --- |
| `$6283` = `80` | 02/01 | `1C:$8184` 12명 | 21(9). 앞 12명 자리 중 11명 같음 |
| `$6283` = `80`, `$6287` = `80` | 02/01 | 되돌림: 보통 목록 21명 | 21(9) |
| `$6283` = `80`, `$6282` = `10` | 02/01 | 되돌림: 보통 목록 21명 | 21 |
| `$6282` = `10` | 15/02 | `1C:$8F14` 2명 | 2 |
| `$6282` = `10`, `$6295` = `02` | 15/02 | 되돌림: 보통 목록 1명 | 1 |
| `$6282` = `40` | 04/01 | `1C:$868E` 1명 | 1 |
| `$6282` = `50` | 04/01 | 되돌림: 보통 목록 13명, `$6286` = `01` | 13 |
| `$6282` = `10` | 02/03 | `1C:$9331` 낮 2명(되돌리지 않는 곳) | 2 |
| 없음 | 02/03 | 보통 목록 1명 | 1 |
| `$6283` = `80` | 02/00 | `1C:$841E` 12명 | 12 |
| `$6282` = `10` | 04/00 | `1C:$8ACE` 16명 | 16 |
| `$6282` = `10` | 12/00 | `1C:$9142` 18명 | 18 |

자리는 덤프가 도착 300프레임 뒤라 걷는 인물을 빼고 맞췄습니다. 02/01 에서 앞 장소(같은 02/01, 21명)를 떠나 12명 목록으로 들어오면 나머지 9칸은 (80,80)으로 남습니다. `$6287` bit7 로 되돌린 02/01 에서도 21명 중 뒤 9명이 (80,80)인데, 이것은 아래 [장소별 인물 손질](#장소별-인물-손질)이 숨긴 것입니다.

### 장소별 인물 손질

인물 표를 채운 뒤 `1C[08]`(`1C:$9EA6`)이 장소별 루틴 `1C:$A010`(74곳)과 `1C:$AD32` 로 인물을 숨기거나 옮깁니다. 루틴 표와 장소마다의 조건은 [dq4-shop-format.md](dq4-shop-format.md#들어갈-때-숨는-인물) 와 `fc/dq4/tools/dq4shop.py hidden` 에 있습니다. 02/01 은 `$627E` bit4(1장 첫 장면의 왕 블록이 켬, [dq4-npcblock-format.md](dq4-npcblock-format.md#예-바트랜드-왕좌의-방-첫-장면))가 켜져 있으면 인물 12~20(슬롯 `12`~`1A`) 9칸을 숨깁니다. 첫 장면에 서 있던 사람들입니다.

실측: 성 앞마당 세이브스테이트(`$627E` = `10`)에서 `$6287` = `80` 으로 02/01 에 워프하며 `$6F66`~`$6F9F` 에 `80` 을 쓰는 곳을 잡으니 9칸 × 2(X·Y) 18번이 모두 숨기는 루틴 `1C:$A035` 의 `STA`(PC `$A03A`·`$A03D`)였고, 끝난 인물 표의 (80,80)도 그 9칸이었습니다. 같은 워프에서 `1C:$9EA6` 에 들어올 때만 `$62A5` 를 `80` 으로 두고 `$9EB4`(RTS)에서 되돌리니 이 쓰기가 없어지고 21명이 모두 섰습니다. `$62A5` bit7 은 「진행 목록을 되돌리지 않고 장소별 손질도 하지 않음」 입니다. 엔딩 장면([dq4-save-format.md](dq4-save-format.md#5장-끝과-엔딩))이 켭니다.

`fc/dq4/tools/dq4map.py npcs G K` 는 이 규칙으로 목록을 고릅니다. `--ram` 이나 `--compare` 로 덤프를 주면 그 플래그·시간으로, `--set 6282=10,6283=80` 으로 플래그를 직접 줄 수도 있습니다. 덤프는 파일(CPU `$0000`~`$7FFF`)이나 `seq.lua`·`warp.lua` 의 `end.*` 폴더입니다. `lists [G K]` 는 표의 줄을 냅니다. `fc/dq4/tools/dq4talk.py` 도 같은 함수(`place_records`)를 씁니다.

## 확인

- `fc/dq4/tools/lua/atpc.lua` 로 해제 직후(`0F:$E560`) RAM 을 덤프해 비교: 앞마당 `02/00`(38×41) 1558바이트 0 차이, 왕좌의 방 `02/01`(32×36) 1152바이트 0 차이.
- `fc/dq4/tools/dq4map.py check`: 맵 279개를 모두 풀었을 때 278곳 모두 해제가 끝난 자리가 다음 맵의 시작 포인터와 같음.
- 그룹 `48`: `warp.lua` 로 `48/00`·`01`·`04`·`05`·`07` 에 들어가 `fc/dq4/tools/dq4block.py compare` 로 그늘 바꾸기 뒤 `$7800` 이 모두 0 차이. `48/09` 는 들어가자마자 필드로 나가서(아래), 해제 직후(`0F:$E560`) 덤프와 비교해 432바이트 0 차이.
- `48/09` 가 곧바로 필드로 나가는 까닭: 이 맵의 인물은 레코드 하나(슬롯 6, (00,00), 그림 `80`)이고 블록이 `8A 28`(블록 이벤트 `28`, `1D:$A321`) 하나뿐입니다. 이 이벤트가 소리 `93`, 일행 슬롯을 차례로 다루는 연출(`1E[30]`, `1E:$8C84`, `$55`~`$58` = `F3 04 02 1E`), 맵 나가기(`1E[2F]`, `1E:$86AD`)를 부릅니다. 나가는 곳은 `12[2C]`(`12:$B6DD`)가 그룹으로 정합니다. 그룹 `48` 은 그 표(`12:$B971`)에 없어서 C = 0 으로 돌아오고, `1E:$92E3` 이 지금 필드 자리 `$42`/`$43` 으로 내보냅니다. `$6285` bit2 가 켜져 있으면 먼저 `$42`/`$43` = (90,D9) 로 바꿉니다(`12:$B741`). 1장 왕좌의 방에서 워프하니 도착 뒤 `1D:$A321`·`1E:$8C84`·`1E:$86AD`·`$86D7` 을 차례로 지나 필드 (A4,2C)(워프 전 필드 자리)로 나갔습니다. `$6285` = `04` 를 두고 다시 하니 필드 (90,D7)이었습니다(방향에 따라 `$43` 을 2 줄임, `12:$B770`). `1E:$86BB` 에 `48/09` 를 따로 보는 갈래가 있지만 C = 1 일 때만 지나므로 실측하지 못했습니다.
- `fc/dq4/tools/dq4map.py exits G K --compare end.ram`: 왕좌의 방·앞마당의 출구 표가 RAM `$05A0` 과 같음.
- `fc/dq4/tools/dq4map.py npcs G K --compare at.bin`: 로드 직후(`1C:$9890`) 인물 표와 비교해 왕좌의 방 21명, 앞마당 13명의 X·Y·방향이 모두 같음. 인물 목록을 그룹마다 끝까지 읽으면 71곳 모두 다음 그룹 포인터에서 끝남(레코드 944개).
- `fc/dq4/tools/dq4map.py npcs G K --compare DIR`: 워프로 진행 플래그를 켜고 들어간 덤프 8개에서 고른 목록의 인물 수가 인물 표와 같음([진행 목록](#진행-목록)).

## 남은 것

- 블록 번호(5비트)와 위 3비트가 어떤 그래픽·통행·이벤트가 되는지(맵 번호별 블록 정의).
- 해제 뒤 BRK 뒤처리(뱅크 `1E` 함수 `11`·`20`·`29`, `1D` 함수 `03`, `1B` 함수 `01`)가 버퍼를 바꾸는지.
- 연결 끝점 플래그 bit7-6 의 뜻, 그룹 `32` 의 BRK 검사. 필드와 맵 사이(가장자리로 나가기)의 출구.
- 인물 레코드의 블록 본문(`$7060/$7080`) 형식.
- 필드(세계 지도)의 형식.
- 맵 번호 bit6 갈래를 화면으로 확인하기(이 비트가 켜진 맵에서 ルーラ·キメラのつばさ 쓰기). `$41` bit7 의 뜻.
- `1C:$9EA6` 이 손질 앞에 부르는 `1C:$9EB5`(`$62ED` ≥ `78` 일 때 표 `1C:$9F8A`)가 하는 일.
- 그룹 `48` 이 어느 장면의 맵인지(필드 입구가 없고 이벤트 `30` 이 `48/04` 로 보냄). `1E:$86BB` 의 `48/09` 갈래.
