# NDS DQ4 대사·폰트·한글 팬패치

DS 일본판의 대사 파일, 폰트, 그리고 한글 팬패치가 한글을 넣은 방식입니다. 도구는 `nds/dq4/tools/ndstext.py`(대사), 툴킷의 `krpatch nds font`(폰트), `ndskr.py`(한글 대응표)입니다.

## 대사 파일 MPT0

`data/data/MESS/<언어>/bNNNN000.mpt`. 언어 폴더는 `ja`(207개), `en`·`fr`·`de`·`es`·`it`(147개씩)입니다. 메시지 번호는 머리 `+08` 의 첫 번호에 색인 번호를 더한 값입니다(예: `b0506000.mpt` 는 `+08` 이 506102 라 색인 5번이 506107). 첫 번호는 대개 파일 이름의 `NNNN` × 1000 에 0~7 을 더한 값이지만, 38·102·503 을 더한 파일도 있어 파일 이름만으로는 번호를 낼 수 없습니다.

머리는 32바이트, 리틀 엔디언 u32 8개입니다.

| 위치 | 값 | 뜻 |
| --- | --- | --- |
| `+00` | `MPT0` | 표지 |
| `+04` | 파일 크기 | 실제 크기와 같음(952개 전부) |
| `+08` | 예: 2, 1001, 506102 | 첫 항목(색인 번호 0)의 메시지 번호 |
| `+0C` | 예: 999, 1534 | 마지막 항목의 메시지 번호(= `+08` + 마지막 색인 번호) |
| `+10` | 항목 수 | |
| `+14` | `0x20` | 색인 위치 |
| `+18` | 항목 수 × 6 + 2 | 색인 크기(끝에 `FE FE` 2바이트) |
| `+1C` | 본문 크기 | 본문은 파일 크기 − 본문 크기 위치부터 |

색인은 항목마다 6바이트(u16 번호, u16 바이트 길이, u16 위치 ÷ 4)이고 번호 순으로 정렬돼 있습니다. 색인 번호는 0 부터 띄엄띄엄합니다(쓰지 않는 번호는 항목이 없음). 문자열은 UTF-8 이고, 문자열 사이는 `FE FE` 와 4바이트 맞춤 채움입니다.

확인: 파일 952개 전부 머리 크기가 파일 크기와 같고, 문자열 91,398개(+ 한글판 `ja` 207개)가 모두 UTF-8 로 풀렸습니다. 952개 전부 `+0C` − `+08` 이 마지막 색인 번호와 같고, 첫 색인 번호는 모두 0 입니다.

`+08` 이 메시지 번호라는 근거는 메시지를 부르는 쪽 두 곳입니다. 이벤트 스크립트의 메시지 명령 2,932개는 이 규칙으로 2,931개가 대사에 있고(「파일 이름 × 1000 + 색인」으로 읽으면 1,493개), 동료 대화 표 레코드 7,209개는 전부 있습니다(전 규칙으로는 3,831개). 게임 화면에서도 1장 첫 대사들이 `b0000000.mpt` 색인 0·1·2(메시지 2·3·4)부터 차례로 나왔습니다.

### 끝 표지 `@cN@`

숫자는 문장이 아니라 말하는 인물에 딸린 값이고, 메시지 창이 글자를 찍을 때 내는 효과음을 고릅니다. `@a<인물 번호>` 가 붙은 인물 785명 중 773명이 모든 문장에서 같은 숫자를 씁니다.

| 값 | 일본어 문자열 | 쓰는 화자 |
| --- | --- | --- |
| 0 | 1,704 | 화자 없는 지문·시스템 문장(`@a@b` 뒤 「이름「」 꼴이 아닌 것 1,556개 중 1,555개), 일부 뱃사람 |
| 1 | 5,751 | 여자·아이: アリーナ, マーニャ, ミネア, 女, シスター, 姫, 踊り子, ホイミン, 男子供 |
| 2 | 9,927 | 보통 남자: トルネコ, クリフト, ブライ, 王, 兵士, 老人, 商人, おばさん, 「＊「」 로 시작하는 이름 없는 인물 |
| 3 | 1,452 | 굵은 목소리: ライアン, あらくれ, 戦士, マスタードラゴン, チキーラ, エッグラ |

영어 대사는 147개 파일 8,811개가 모두 `@c0@` 이고, 프랑스어 등 나머지 언어에는 `@c` 가 없습니다. 일본어판에만 의미 있는 값입니다.

대사 표지를 나누는 함수 `0x02053D6C`(Thumb)가 `@0`~`@9`·`@a`·`@b`·`@c` 뒤 글자를 칸마다 따로 담고, `0x02053710` 이 `@c` 칸의 첫 글자를 꺼내 `0x02106400` 에 둡니다. 창에 글을 넘기는 `0x02054820` 은 글 앞에 `ESC`(0x1B) + 숫자 한 글자를 붙입니다. 이 숫자는 보통 「목소리 줄」(`0x02107888` 의 글자열, 읽을 자리 `0x02107830`)에서 꺼내고, 줄에서 꺼낸 글자가 `9` 일 때만 `@c` 숫자를 씁니다. 창 쪽 `0x0204CE1C` 는 `ESC` 뒤 숫자를 창의 효과음 번호(창 `+0x9E0`)로 바꿉니다.

| 숫자 | 효과음 번호 | `DEBUG/soundlist.dat` 의 이름 |
| --- | --- | --- |
| 0 | 0(없음) | |
| 1 | 301 | `メッセージ（高）` |
| 2 | 302 | `メッセージ（中）` |
| 3 | 303 | `メッセージ（低）` |

여자·아이가 높은 소리, 굵은 목소리 인물이 낮은 소리를 쓰는 것과 맞습니다. 위 내용은 코드 읽기이고, 효과음 번호 상수 301~303 은 `0x0204CFBC`~`0x0204CFC4` 에서 읽었습니다.

SDAT 를 읽은 사운드 분석 결과로는 셋 다 SE 시퀀스 안의 짧은 블립입니다. 음 하나를 2~3틱 치고 끝나며(뱅크 110, 음량 120, 플레이어 4 = PCM SE 채널 12~15), 301·302 는 같은 PCM 샘플(악기 88)을 음 84·76 으로, 303 은 다른 샘플(악기 97)을 음 64 로 냅니다. 같은 분석에서 전투 메시지를 찍을 때 글자마다 효과음 함수 `0x02084268` 에 302 가 들어오는 것을 훅으로 기록해, 글자 효과음이 실제로 울리는 것을 확인했습니다.

아래 소리 샘플 비교로는 차이를 잡지 못했습니다. 1장 왕의 연설(`b0000000.mpt` 메시지 12)과 이어서 왕에게 말을 건 대사(메시지 28)에서 `@c` 숫자를 0·1·3·9 로 바꾸거나 목소리 줄을 그 숫자로 고정해도, 소리 샘플이 바이트 하나까지 같았습니다. 두 장면 모두 목소리 줄이 `2222…` 로 채워져 있어 `@c` 를 읽지 않는 경로였고, 줄을 바꿔도 소리가 같은 까닭은 찾지 못했습니다. 지난 대화를 다시 보는 화면은 없는 것으로 봅니다. 필드 메뉴(대화·주문·도구·조사하다·강한 정도·작전)와 실행 파일 문자열, 메뉴 이름 표(`b1004000`·`b1010000`·`b1020000`)에 그런 항목이나 「会話」·「履歴」·「ログ」 같은 낱말이 없습니다.

### 인물 번호 `@a`

`@a` 뒤 네 자리는 맵 스크립트의 인물 오브젝트([script-format.md](script-format.md#오브젝트))와 짝입니다. 스크립트의 메시지 명령(`0x03`~`0x06`)이 부르는 대사를 오브젝트마다 모으면, 대사를 부르는 오브젝트 2,471개 중 2,420개가 한 인물 번호만 씁니다. 같은 인물 번호가 여러 맵 파일(같은 장소의 시기별 맵 등)에 나올 수는 있습니다(774개 번호 중 616개는 한 파일에만). 오브젝트 머리 `+04` 의 인물 모습 번호와 `@a` 뒤 이름도 맞습니다(모습 `0x0F` 는 兵士 174번, `0x11` 은 衛兵 75번, `0x03` 은 おばさん 135번).

### 변수 `%a`

`%a` 뒤 다섯 자리는 「꼴 2자리 + 변수 번호 2자리 + 끝자리 1자리」입니다. 대사를 펼치는 함수 `0x02052F8C`(Thumb)는 `%a` 다음 셋째·넷째 숫자를 변수 번호로, 다섯째 숫자를 끝자리로 읽고 앞 두 자리는 읽지 않습니다(코드 읽기). 끝자리는 같은 변수의 몇째 값인지를 고릅니다(`%a00821`~`%a00825` 는 레벨업 능력치 다섯 칸, `%a00101`·`%a00102` 는 교환하는 두 아이템).

변수 번호의 이름표가 `arm9.bin` `0x020C0840`(파일 오프셋 `0C0840`)에 (번호 s32, 이름 문자열 주소) 8바이트 짝으로 92개 있고 번호 −1 로 끝납니다. 값은 세 단계로 찾습니다.

1. 메시지 객체에 등록된 값(객체 `+0x600` 이 개수, 0x18바이트 칸). 전투·가게처럼 그 장면의 코드가 메시지를 띄우기 전에 넣습니다.
2. 전역 공급자(`0x02053078` 이 부르는 콜백). 주인공 이름, 일행 선두, 지금 돈, 이민 마을 이름 등.
3. 둘 다 없으면 이름표에 있는 번호는 `{이름}`, 없는 번호는 `<NDEF MACRO 번호>` 로 찍습니다(서식 문자열 `{%s}`·`{%s%d}`·`<NDEF MACRO %d>` 가 `0x020C0B28` 에 있음).

한글판 롬으로 1장 왕좌의 방에서 왕에게 말을 걸기 직전에 대사 본문을 RAM 에서 바꿔 띄워 확인했습니다.

### 이름 표

이름 표(`b1000000`~`b1007000`)는 일본어가 `@1이름@` 꼴이고 `;` 가 두 줄 표시의 줄바꿈 자리입니다. 영어는 `@0<성 N·M·F>@2정관사@3부정관사@4이름@5…` 처럼 관사·복수형을 함께 둡니다.

게임의 아이템·몬스터 등 번호는 「메시지 번호 − 파일 기준 번호」입니다. 이름을 찾는 함수 `0x0205378C`(Thumb, 종류는 인자의 위 4비트)가 종류별 기준 번호(`0x02053928` 의 표: 1000000, 1001000, 1002000, 1003000, 1004000, 1005000, 1006000, 1006200, 1007000, 1010000)에 번호를 더해 메시지를 찾습니다(코드 읽기). 종류 값과 기준은 아래와 같습니다. 번호 × 2 를 더하는 것은 아이템 설명(`b0831000`)이고, 아이템 1 의 설명이 메시지 831002 「とくしゅこうかは ないようだ」입니다(가게 화면에 같은 문장이 나옴). 그래서 `ndstext.py names`·`glossary` 의 「번호」 열(색인 번호)과 게임 번호는 머리 `+08` 만큼 어긋납니다.

| 파일 | `+08` | 게임 번호 | 예 |
| --- | --- | --- | --- |
| `b1000000`(아이템) | 1000001 | 색인 + 1 | 색인 0 `ひのきのぼう` = 아이템 1 |
| `b1001000`(인물) | 1001001 | 색인 + 1 | 색인 0 `ソロ` = 인물 1(주인공), 색인 2 `ライアン` = 3 |
| `b1002000`(몬스터) | 1002000 | 색인 그대로 | 색인 0 `スライム` = 몬스터 0 |
| `b1003000`(주문·특기) | 1003001 | 색인 + 1 | |
| `b1004000`(메뉴) | 1004000 | 색인 그대로 | |

| 종류(위 4비트) | 메시지 번호 |
| --- | --- |
| `0x1`·`0x3` | 번호 그대로 |
| `0x2` | 831000 + 번호 × 2(아이템 설명) |
| `0x4`~`0xC` | 1000000(아이템), 1001000(인물), 1002000(몬스터), 1003000(주문·특기), 1004000(메뉴), 1005000(작전), 1006000·1006200(능력치·직업), 1007000(지명) + 번호 |
| `0xE` | 1010000 + 번호 |
| `0xD`·`0xF` | 다른 함수(`0x02053A40`·`0x02053A70`) |

인물 번호 1(주인공)·3(ライアン)·4(アリーナ)·23(ドラン)은 [debug.md](debug.md) 의 일행 순서 칸 실측과 맞습니다.

## 한글 팬패치

[한글 팬패치 v1.1](../references.md)은 대사의 문자 코드를 바꾸지 않습니다. `zen10`·`zen12` 의 글리프 1400개를 한글 음절로 다시 그리고, 대사를 그 코드로 다시 썼습니다. 그래서 한글판 대사 파일을 그대로 읽으면 엉뚱한 한자가 나옵니다(예: `ライアン` → `居章牢`).

- 바뀐 코드는 두 폰트에서 같은 1400개입니다. 반각 폰트는 그대로입니다.
- U+3300 이상 1342개(한자와 `㌃` 같은 묶음 기호)는 **코드 순서대로 KS X 1001 음절 순서의 부분열**입니다. 「가각간갇갈감…」이 한자 코드가 커지는 순서로 깔려 있습니다.
- 그 앞 58개(키릴 `ЁАБ`, 히라가나, 일부 기호 자리)는 순서가 없는 자주 쓰는 음절입니다(「이무르귀엘연레비…」).
- 실행 파일 쪽 메뉴 문자열(`overlay_0016.bin`, `arm9.bin`)은 Shift_JIS 이고 같은 방식으로 제자리에서 바뀌었습니다([rom-map.md](rom-map.md#한글-팬패치가-바꾼-파일)).

대응표 [kr-font.tsv](../tables/kr-font.tsv) 는 코드, 일본어 글자, 한글, 판정 방식(`auto`·`eye`) 네 열입니다. 이렇게 만들었습니다.

1. 기준 폰트(macOS AppleSDGothicNeo)로 2350음절을 그리고, 글리프와 글자 상자를 가로·세로 따로 늘려 맞춰 흐린 코사인 유사도를 냅니다(설정 4개 합).
2. 순서 구간 1342자는 「KS 순서로 늘어나기만 한다」는 조건의 동적 계획법으로 고릅니다.
3. 고른 라벨로 초성·중성·종성 조각 비트맵을 배우고(다수결), 후보를 합성해 해밍 거리로 다시 정렬합니다. 바뀌지 않을 때까지 되풀이합니다. 드문 음절이 이웃을 가로채지 않도록 음절 빈도([hangul-freq.json](../tables/hangul-freq.json), 같은 저자의 다른 한글 패치 대본에서 셈)를 사전 확률로 더합니다.
4. 두 방법이 갈린 글자와 앞쪽 58자는 글리프를 크게 그려 사람이 읽었고(`eye`, 114자), 그 값은 다시 정렬할 때 고정점입니다.

확인(`ndskr.py check`):

- 표의 코드가 두 폰트의 바뀐 코드 1400개와 같습니다.
- 순서 구간 1342자가 KS 순서를 한 번도 거스르지 않습니다.
- 판독이 잘 틀리던 글자(ㅡ·ㅢ·ㅚ, 받침 ㅁ/ㅂ/ㅇ)가 든 이름 18개가 기대한 한글로 읽힙니다(크리프트, 브라이, 톨네코, 사막의 바자, 괴물 버섯, 은의 타롯 등).
- 1400자 전부를 글리프와 나란히 그린 그림 12장을 사람이 읽어 대조했습니다.
- `ndskr.py draft … --freq nds/dq4/tables/hangul-freq.json` 이 표를 바이트 단위로 다시 만듭니다.
- 한글판 일본어 대사 전체(음절 442,520자)를 이 표로 읽으면, 빈도표에 없는 음절은 146번(0.03%)뿐이고 많이 나온 것부터 「지저귐의 꿀」(`さえずりの蜜`), 「뗏목」, 「데스팰리스」, 「짭짤」처럼 모두 제대로 된 낱말입니다.
- `98A8` 은 「훔」입니다. 글리프 아래쪽이 「흠」(`9A13`)과 같은 네모(ㅁ)이고, 쓰인 47곳이 모두 「훔쳐보는」·「훔친」·「훔치겠」 같은 「훔치다」 꼴입니다. 전에는 「훑」으로 읽었습니다.
- 에뮬레이터(desmume libretro)로 한글판 롬을 1장 시작부터 띄워, 대사 창 13장(지문 3, 대신 1, 왕 7, 여자 2)이 이 표로 읽은 `b0000000.mpt` 메시지 2~24 와 글자 하나까지 같았습니다. 메뉴의 「도구 일람」(`overlay_0016` 문자열)도 표대로 보였습니다.

### 실행 파일 문자열의 오타

실행 파일 메뉴 문자열(`ndstext.py sjis`, [rom-map.md](rom-map.md#실행-파일의-shift_jis-문자열))을 이 표로 읽으면 팬패치가 바꾼 120개 중 몇 개가 낱말이 되지 않습니다. 대사에서 같은 코드를 1,600번 가까이 쓰는 글자라 표는 맞고, 팬패치 쪽 실수로 보입니다.

| 자리 | 일본어 | 표로 읽은 한글 | 뜻했을 말 |
| --- | --- | --- | --- |
| `arm9.bin` `0BF228` | `@まちのなまえをきめてください` | 마을 일름을 결정해 주세요 | 이름 |
| `overlay_0016` `016040` | `@メッセージ` | 부시지 | 메시지 |
| `overlay_0016` `015F70` | `@バルザック＋` | 발撒크＋ | 撒(`U+6492`)은 폰트에 없는 코드 |
| `overlay_0016` `015FA8` | `@町を出る住民をさがす` | 떠난 주민 찾燕 | 燕(`U+71D5`)도 폰트에 없음 |

폰트에 없는 코드는 ※·× 와 다른 X 모양 대체 글자 하나로 찍힙니다. 한글판 롬에서 왕의 대사 본문을 RAM 에서 `[撒][燕]`, `[捧撒豪＋]` 로 바꿔 띄우니 `[X][X]`, `[발X크＋]` 꼴로 나왔습니다. 메뉴 문자열도 같은 폰트·대응으로 찍히므로(「도구 일람」 확인) 메뉴에서도 이 모양일 것으로 봅니다. 그 메뉴(이민 마을·`overlay_0016` 의 몬스터 표) 자체를 띄워 보지는 않았습니다.

## 동료 대화 표

`data/data/PARAM/param_player_talk1.dat`~`talk6.dat` 은 장마다 하나인 동료 대화 표입니다. 레코드가 가리키는 메시지가 그 장의 동료 대화 파일에만 있습니다.

| 파일 | 크기 | 레코드 | 메시지 | 장 |
| --- | --- | --- | --- | --- |
| `talk1` | 9,464 | 215 | `b0500`~`b0502` | 1장 |
| `talk2` | 42,244 | 960 | `b0503`~`b0509` | 2장 |
| `talk3` | 5,064 | 115 | `b0512`~`b0513` | 3장 |
| `talk4` | 7,220 | 164 | `b0516`~`b0517` | 4장 |
| `talk5` | 215,516 | 4,898 | `b0520`~`b0545` | 5장 |
| `talk6` | 37,712 | 857 | `b0547`~`b0552` | 6장 |

머리 4바이트(`60 7C 0E 00`, 여섯 파일 모두 같음) 뒤에 44바이트 레코드가 이어집니다. 여섯 파일 모두 (크기 − 4) 가 44 로 나누어떨어집니다. 처음에는 메시지 번호가 있는 `+16` 을 레코드 시작으로 잡았는데, 그러면 파일 끝에 28바이트가 남습니다.

| 위치 | 값 | 뜻 |
| --- | --- | --- |
| `+00`~`+0E` | 대부분 0, 가끔 장소 같은 값(`017A`, `01AB`) | 모름 |
| `+10` | u32 | 메시지 번호(`b0500000.mpt` 의 2번 = 500002) |
| `+14`, `+16` | 1장은 `0037`·`003C`, 5장은 `013D`·`FFFF` 등 29~30가지 | 모름. 장소·일행 조건 후보 |
| `+18` | 309가지 | 모름. 같은 장소 안 세부 위치 후보(1장 왕좌의 방 문장이 `0001`, 동굴 문장이 `0106`) |
| `+1A` | 1·2·3 | 모름 |
| `+1C` | `FFFF`, `FF00`~`FF0x` | 모름. 진행 단계 조건 후보 |
| `+21` | 3~25 | 모름. 화자 이름과 한 대 일로 맞지 않음 |
| `+22` | 0·2·4·8 … | 모름. 시간대 비트 후보(밤 낱말이 든 문장이 4 에 조금 더 많지만 결정적이지 않음) |
| `+28` | `0160`·`0130`·`0168` 등 | 모름. 비트 묶음 |
| `+2A` | `0101` | 모든 레코드 같음 |

레코드 7,209개의 메시지 번호가 모두 대사 파일에 있습니다(메시지 번호를 MPT0 머리 `+08` 기준으로 읽을 때).

```sh
uv run --locked python nds/dq4/tools/ndstext.py talk work/nds/jp 1 --kr work/nds/kr
```

## 남은 것

- 마을 대화에서 `@c` 숫자·목소리 줄을 바꿔도 소리 샘플이 같았던 까닭(전투 메시지에서는 글자마다 302 가 울림). 창 `+0x9E0` 의 효과음 번호에서 `0x02084268` 까지의 경로.
- 유럽어 `%a` 꼴 번호 `01`~`05` 의 뜻(이 롬에는 해석 코드가 없음). 메시지 객체에 값을 등록하는 코드와 전역 공급자 목록.
- 폰트에 없는 코드가 실제 메뉴(이민 마을 「떠난 주민 찾기」 머리 등)에서 찍히는 모습. 대사로 넣어 본 모양만 확인.
- 동료 대화 표 필드의 나머지 뜻은 [param-format.md](param-format.md#남은-것).
