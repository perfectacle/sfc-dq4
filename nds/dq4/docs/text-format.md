# NDS DQ4 대사·폰트·한글 팬패치

DS 일본판의 대사 파일, 폰트, 그리고 한글 팬패치가 한글을 넣은 방식입니다. 도구는 `nds/dq4/tools/ndstext.py`(대사), `ndsfont.py`(폰트), `ndskr.py`(한글 대응표)입니다.

## 대사 파일 MPT0

`data/data/MESS/<언어>/bNNNN000.mpt`. 언어 폴더는 `ja`(207개), `en`·`fr`·`de`·`es`·`it`(147개씩)입니다. 파일 이름의 `NNNN` × 1000 이 그 파일의 메시지 번호 시작입니다(예: `b0102000.mpt` 의 7번 = 102007).

머리는 32바이트, 리틀 엔디언 u32 8개입니다.

| 위치 | 값 | 뜻 |
| --- | --- | --- |
| `+00` | `MPT0` | 표지 |
| `+04` | 파일 크기 | 실제 크기와 같음(952개 전부) |
| `+08`, `+0C` | 예: 2·999, 1001·1534 | 모름. 번호 범위와 비슷하지만 맞지 않음 |
| `+10` | 항목 수 | |
| `+14` | `0x20` | 색인 위치 |
| `+18` | 항목 수 × 6 + 2 | 색인 크기(끝에 `FE FE` 2바이트) |
| `+1C` | 본문 크기 | 본문은 파일 크기 − 본문 크기 위치부터 |

색인은 항목마다 6바이트(u16 번호, u16 바이트 길이, u16 위치 ÷ 4)이고 번호 순으로 정렬돼 있습니다. 번호는 띄엄띄엄합니다(쓰지 않는 번호는 항목이 없음). 문자열은 UTF-8 이고, 문자열 사이는 `FE FE` 와 4바이트 맞춤 채움입니다.

확인: 파일 952개 전부 머리 크기가 파일 크기와 같고, 문자열 91,398개(+ 한글판 `ja` 207개)가 모두 UTF-8 로 풀렸습니다.

## 표지

| 표지 | 수(일본어) | 뜻 |
| --- | --- | --- |
| `@a<인물 4자리>␣␣<이름>@b` | 6,725 | 말하는 인물. 인물 번호와 이름표(편집용으로 보임). 예: `@a0002  大臣@b` |
| `@a@b` | 12,109 | 화자 없이 본문 시작(지문, 동료 대화 `이름「…` 꼴) |
| `@c<숫자>@` | 18,834 | 문자열 끝. 숫자 0~3(뜻은 남은 것) |
| `%a<5자리>` | 2,513 | 변수. `%a00090` 주인공 이름, `%a00120` 고른 인물, `%a00100` 아이템, `%a00130` 몬스터 등(대사 문맥에서 추정) |
| 줄바꿈 + 탭 | | 다음 줄. 탭은 `「` 뒤 들여쓰기 |

이름 표(`b1000000`~`b1007000`)는 일본어가 `@1이름@` 꼴이고 `;` 가 두 줄 표시의 줄바꿈 자리입니다. 영어는 `@0<성 N·M·F>@2정관사@3부정관사@4이름@5…` 처럼 관사·복수형을 함께 둡니다.

## 폰트 NFTR

`data/data/G2D/FONT/`. NDS 표준 비트맵 폰트 형식입니다. `ndsfont.py info` 로 읽었습니다.

| 파일 | 칸 | bpp | 글자 | 코드 |
| --- | --- | --- | --- | --- |
| `zen12.nftr` | 12×14 | 1 | 2075 | 한자 약 1700, 히라가나·가타카나, 기호, 전각 영숫자 |
| `zen10.nftr` | 10×12 | 1 | 2075 | `zen12` 와 같은 코드 |
| `han12.nftr`, `han10.nftr` | 12×14, 10×12 | 1 | 422 | 반각 라틴·키릴·기호(유럽판 대사용) |

블록은 FINF·CGLP(글리프)·CWDH(폭)·CMAP(코드 → 글리프 번호)입니다. 비트맵은 위 줄부터, 바이트 안에서는 높은 비트부터입니다. CMAP 은 종류 0(연속)·1(표)·2(짝 목록)를 모두 씁니다.

## 한글 팬패치

[한글 팬패치 v1.1](../references.md)은 대사의 문자 코드를 바꾸지 않습니다. `zen10`·`zen12` 의 글리프 1400개를 한글 음절로 다시 그리고, 대사를 그 코드로 다시 썼습니다. 그래서 한글판 대사 파일을 그대로 읽으면 엉뚱한 한자가 나옵니다(예: `ライアン` → `居章牢`).

- 바뀐 코드는 두 폰트에서 같은 1400개입니다. 반각 폰트는 그대로입니다.
- U+3300 이상 1342개(한자와 `㌃` 같은 묶음 기호)는 **코드 순서대로 KS X 1001 음절 순서의 부분열**입니다. 「가각간갇갈감…」이 한자 코드가 커지는 순서로 깔려 있습니다.
- 그 앞 58개(키릴 `ЁАБ`, 히라가나, 일부 기호 자리)는 순서가 없는 자주 쓰는 음절입니다(「이무르귀엘연레비…」).
- 실행 파일 쪽 메뉴 문자열(`overlay_0016.bin`, `arm9.bin`)은 Shift_JIS 이고 같은 방식으로 제자리에서 바뀌었습니다([rom-map.md](rom-map.md#한글-팬패치가-바꾼-파일)).

대응표 [kr-font.tsv](../tables/kr-font.tsv) 는 코드, 일본어 글자, 한글, 판정 방식(`auto`·`eye`) 네 열입니다. 이렇게 만들었습니다.

1. 기준 폰트(macOS AppleSDGothicNeo)로 2350음절을 그리고, 글리프와 글자 상자를 가로·세로 따로 늘려 맞춰 흐린 코사인 유사도를 냅니다(설정 4개 합).
2. 순서 구간 1342자는 「KS 순서로 늘어나기만 한다」는 조건의 동적 계획법으로 고릅니다.
3. 고른 라벨로 초성·중성·종성 조각 비트맵을 배우고(다수결), 후보를 합성해 해밍 거리로 다시 정렬합니다. 바뀌지 않을 때까지 되풀이합니다. 드문 음절이 이웃을 가로채지 않도록 음절 빈도([hangul-freq.json](../tables/hangul-freq.json), 같은 저자의 다른 한글 패치 대본에서 셈)를 사전 확률로 더합니다.
4. 두 방법이 갈린 글자와 앞쪽 58자는 글리프를 크게 그려 사람이 읽었고(`eye`, 114자), 그 값은 다시 정렬할 때 고정점입니다.

확인(`ndskr.py check`):

- 표의 코드가 두 폰트의 바뀐 코드 1400개와 같습니다.
- 순서 구간 1342자가 KS 순서를 한 번도 거스르지 않습니다.
- 판독이 잘 틀리던 글자(ㅡ·ㅢ·ㅚ, 받침 ㅁ/ㅂ/ㅇ)가 든 이름 18개가 기대한 한글로 읽힙니다(크리프트, 브라이, 톨네코, 사막의 바자, 괴물 버섯, 은의 타롯 등).
- 1400자 전부를 글리프와 나란히 그린 그림 12장을 사람이 읽어 대조했습니다.
- `ndskr.py draft … --freq nds/dq4/tables/hangul-freq.json` 이 표를 바이트 단위로 다시 만듭니다.
- 한글판 일본어 대사 전체(음절 442,520자)를 이 표로 읽으면, 빈도표에 없는 음절은 146번(0.03%)뿐이고 많이 나온 것부터 「지저귐의 꿀」(`さえずりの蜜`), 「뗏목」, 「데스팰리스」, 「짭짤」처럼 모두 제대로 된 낱말입니다.

## 동료 대화 표

`data/data/PARAM/param_player_talk1.dat`~`talk6.dat` 은 장마다 하나인 동료 대화 표입니다. 레코드가 가리키는 메시지가 그 장의 동료 대화 파일에만 있습니다.

| 파일 | 크기 | 레코드 | 메시지 | 장 |
| --- | --- | --- | --- | --- |
| `talk1` | 9,464 | 215 | `b0500`~`b0502` | 1장 |
| `talk2` | 42,244 | 960 | `b0503`~`b0509` | 2장 |
| `talk3` | 5,064 | 115 | `b0512`~`b0513` | 3장 |
| `talk4` | 7,220 | 164 | `b0516`~`b0517` | 4장 |
| `talk5` | 215,516 | 4,898 | `b0520`~`b0545` | 5장 |
| `talk6` | 37,712 | 857 | `b0547`~`b0552` | 6장 |

머리 4바이트(`60 7C 0E 00`, 여섯 파일 모두 같음) 뒤에 44바이트 레코드가 이어집니다. 여섯 파일 모두 (크기 − 4) 가 44 로 나누어떨어집니다. 처음에는 메시지 번호가 있는 `+16` 을 레코드 시작으로 잡았는데, 그러면 파일 끝에 28바이트가 남습니다.

| 위치 | 값 | 뜻 |
| --- | --- | --- |
| `+00`~`+0E` | 대부분 0, 가끔 장소 같은 값(`017A`, `01AB`) | 모름 |
| `+10` | u32 | 메시지 번호(`b0500000.mpt` 의 2번 = 500002) |
| `+14`, `+16` | 1장은 `0037`·`003C`, 5장은 `013D`·`FFFF` 등 29~30가지 | 모름. 장소·일행 조건 후보 |
| `+18` | 309가지 | 모름. 같은 장소 안 세부 위치 후보(1장 왕좌의 방 문장이 `0001`, 동굴 문장이 `0106`) |
| `+1A` | 1·2·3 | 모름. 2 이상이면 메시지 번호가 대사 파일에 없는 일이 많음(여러 문장 묶음 후보) |
| `+1C` | `FFFF`, `FF00`~`FF0x` | 모름. 진행 단계 조건 후보 |
| `+21` | 3~25 | 모름. 화자 이름과 한 대 일로 맞지 않음 |
| `+22` | 0·2·4·8 … | 모름. 시간대 비트 후보(밤 낱말이 든 문장이 4 에 조금 더 많지만 결정적이지 않음) |
| `+28` | `0160`·`0130`·`0168` 등 | 모름. 비트 묶음 |
| `+2A` | `0101` | 모든 레코드 같음 |

레코드 7,209개 중 메시지 번호가 대사 파일에 있는 것은 3,831개입니다. 나머지의 쓰임(여러 문장 묶음의 번호 규칙 등)은 남은 것입니다.

```sh
uv run --locked python nds/dq4/tools/ndstext.py talk work/nds/jp 1 --kr work/nds/kr
```

## 남은 것

- `@cN@` 숫자의 뜻(창 닫기·대기·입력 대기 등), `@a` 인물 번호와 맵 인물의 대응.
- MPT0 머리 `+08`·`+0C`.
- `%aNNNNN` 변수 번호 전체 목록(지금은 문맥 추정).
- 대응표 판독이 애매했던 글자: `98A8`(훑/훔). 글리프로는 「훑」 쪽이지만 쓰인 대사로 확인하지 못함.
- 게임 화면에서 한글판 대사를 띄워 대응표와 비교하기(에뮬레이터 실측).
- 동료 대화 표의 필드 뜻(장소·일행·진행·시간대 조건, 여러 문장 묶음). 에뮬레이터로 대화를 걸며 레코드 번호를 잡아야 함.
