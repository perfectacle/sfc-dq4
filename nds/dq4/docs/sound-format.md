# NDS DQ4 소리 형식과 곡 목록

NDS 「ドラゴンクエストIV 導かれし者たち」(일본판)의 소리 자료(`data/data/SOUND/sound_data.sdat`)와 게임이 곡·효과음을 고르는 방식을 정리한 문서입니다. SFC DQ5 엔진의 소리를 해킹할 때 곡 대응·편곡 참고로 씁니다. 찾은 과정은 [2026-10-25-16 일지](../journal/2026-10-25-16-sound.md) 에, 악보 json·txt 는 [2026-10-26-01 일지](../journal/2026-10-26-01-score.md) 에 있습니다.

- 도구: [ndssound.py](../tools/ndssound.py). `info`(SDAT 목록), `export`(곡·효과음 합성, MIDI, 악보 json·txt, 샘플·뱅크), `scorecheck`(악보로 MIDI 를 다시 만들어 견줌), `maps`(맵 곡 표), `scenes`(에뮬레이터 실측), `summary`(곡별 장면), `gallery`. 앞부분은 게임과 무관한 SDAT 코드(SDAT·SSEQ·SSAR·SBNK·SWAR·STRM 읽기, 합성, MIDI)이고 뒷부분만 이 게임에 묶여 있습니다.
- 추출물(원본 SSEQ·합성 WAV·MIDI·샘플)은 롬에서 뽑은 소리라 비공개 에셋 저장소 `nds/dq4/sound/` 에만 둡니다([아래](#추출물)).
- 기준 롬: `rom/dq4ds.nds`(SHA-1 은 [README](../../../README.md#원본-롬)). 주소는 ARM9 주소(메인 RAM `0x02000000`~)입니다.

## SDAT

NitroSDK 의 소리 묶음 파일입니다. 머리 `0x40` 바이트 뒤에 블록 넷이 있습니다.

| 블록 | 위치 | 크기 | 내용 |
| --- | --- | --- | --- |
| `SYMB` | `0x40` | `0x5033` | 종류별 이름 표(`SND_BGM_M02_MENUET` 등) |
| `INFO` | `0x5074` | `0x8B8` | 종류별 레코드 |
| `FAT` | `0x592C` | `0x6EC` | 파일 110개의 (위치, 크기) |
| `FILE` | `0x6018` | 11,009,288 | SSEQ 50 + SSAR 1 + SBNK 54 + SWAR 4 + STRM 1 = 110 |

`SYMB`·`INFO` 는 종류 8가지마다 표 위치(u32)를 차례로 둡니다. 표는 u32 칸 수와 칸마다 레코드 위치(0 이면 빈 칸)입니다. `SYMB` 의 SEQARC 칸만 (묶음 이름, 안쪽 시퀀스 이름 표) 두 위치입니다.

| 종류 | 칸 | 레코드 | INFO 레코드 | 이 게임 |
| --- | --- | --- | --- | --- |
| SEQ | 52 | 50 | u16 파일, u16, u16 뱅크, u8 음량, u8 채널 우선, u8 플레이어 우선, u8 플레이어 | 곡 2~51. 0·1 은 빈 칸 |
| SEQARC | 1 | 1 | u16 파일, u16 | `SEQ_SE`(효과음). 안쪽 칸 1171개 중 시퀀스 634개, 모두 이름 있음 |
| BANK | 112 | 54 | u16 파일, u16, u16 파형 묶음 ×4(`FFFF` 없음) | 곡마다 하나(2~51), `BANK_BGMT`(1), `BANK_ME`(100), `BANK_SE`(110), `BANK_NOISE`(111) |
| WAVEARC | 4 | 4 | u32 파일(아래 24비트) | `WAVE_SE`·`WAVE_ME`·`WAVE_BGM`·`WAVE_BGMT` |
| PLAYER | 9 | 9 | u8 동시 곡 수, u8, u16 채널 마스크, u32 힙 | 아래 표 |
| GROUP | 1 | 1 | u32 수, 칸마다 u8 종류(0 SEQ, 1 BANK, 2 WAVEARC, 3 SEQARC)·u8 싣기 비트·u16·u32 번호 | `GROUP_STATIC`: 뱅크 100·110·111(파형까지)과 `SEQ_SE` |
| PLAYER2 | 1 | 1 | u8 채널 수, 채널 번호 | `PLAYER_STRM`: 채널 6·7 |
| STRM | 1 | 1 | u16 파일, u16, u8 음량, u8 우선, u8 플레이어 | `STRM_OVERTURE32_8`: PCM8 스테레오 32728Hz, 3,834,883표본(117.2초), 루프 없음 |

| 플레이어 | 채널 | 쓰는 것 |
| --- | --- | --- |
| 0 `PLAYER_BGM` | 0~11, 힙 `0x32000` | 곡 50개 전부(ME 포함) |
| 1 `PLAYER_ME` | 0~11, 힙 `0x400` | SEQ 레코드가 가리키지 않음 |
| 2·3 `PLAYER_SE_NOISE` | 14·15 | 효과음(뱅크 111, PSG·잡음) 24개 |
| 4~8 `PLAYER_SE_PCM` | 12~15 / 8~15 | 효과음(뱅크 110) 610개 |

곡 뱅크 50개는 모두 `WAVE_BGM`(샘플 109개)만 씁니다. `BANK_BGMT`(`WAVE_BGMT` 163개)와 `BANK_ME` 는 어느 SEQ 레코드도 가리키지 않습니다.

### sound_data.sadl

SoundMaker 가 내는 C 머리 파일(`#define 이름 번호`) 755줄입니다. 이름과 번호가 `SYMB` 의 755개와 모두 같습니다(`WAVE_*`, `PLAYER_*`, `BANK_*`, `SND_BGM_*`, `SEQ_SE`, `STRM_*`, `GROUP_*`, `SND_SE_*`). 게임 코드는 읽지 않고 개발 때 쓴 것으로 보입니다.

### 사운드 테스트 이름표

`DEBUG/soundlist.dat` 는 `BGM, 번호, 이름` / `SE, 번호, 이름` 줄로 된 Shift_JIS 텍스트입니다. BGM 1~49(34 「終曲・導かれし者たち」 는 `#` 으로 막힘)와 SE 300~327·400~409 의 일본어 이름이 있습니다. 번호는 SEQ 번호·SSAR 안쪽 번호와 같고, BGM 1(序曲)이 STRM 입니다. 이 표를 여는 코드는 찾지 못했습니다([debug.md](debug.md)).

## SSEQ·SSAR

SSEQ 는 머리 `0x18` 에 자료 시작(u32)이 있고, SSAR 는 `0x18` 자료 시작, `0x1C` 칸 수, `0x20` 부터 12바이트 칸(u32 시퀀스 위치(`FFFFFFFF` 빈 칸), u16 뱅크, u8 음량, u8 채널 우선, u8 플레이어 우선, u8 플레이어)입니다. 명령은 NitroSDK 시퀀스 명령 그대로이고, 이 게임에 나오는 것은 아래뿐입니다(곡 50개를 끝까지 따라 셈, 효과음 634개).

| 명령 | 뜻 | 곡 | 효과음 |
| --- | --- | --- | --- |
| `00`~`7F` | 음(음 번호, 세기 u8, 길이 가변) | 42,970 | 3,340 |
| `80` / `81` | 쉼(가변) / 악기(가변) | 117,419 / 513 | 16,574 / 1,084 |
| `93` / `94` / `95` / `FD` | 트랙 열기 / 건너뛰기 / 부르기 / 돌아오기 | 383 / 302 / 2,052 / 813 | 424 / 25 / 7 / 2 |
| `C0` / `C1` / `D5` | 팬 / 음량 / 표현(음량 2) | 460 / 77,342 / 441 | 459 / 4,674 / 1,057 |
| `C4` / `C5` | 음높이 휨 / 휨 폭(반음) | 921 / 438 | 11,652 / 1,026 |
| `C6` / `C7` | 우선순위 / 모노(1)·폴리(0). 곡은 433개 모두 0 | 287 / 433 | 0 / 1,058 |
| `CA`~`CD`, `E0` | 모듈레이션 깊이·속도·종류·폭, 지연 | 467·90·16·50, 90 | 726·280·5·234, 3 |
| `D0`~`D3` | 어택·디케이·서스테인·릴리스 덮어쓰기 | 35·18·6·79 | 482·182·258·755 |
| `C8`, `CE`·`CF`, `E3` | 이음(tie), 포르타멘토 켬·시간, 휩쓸기 음높이 | | 17, 1·38, 40 |
| `D4` / `FC` | 되풀이 시작(횟수) / 끝 | | 1 / 1 |
| `E1` | 템포 | 11,068 | 1,273 |
| `FE` / `FF` | 트랙 할당 / 끝 | 50 / 116 | 343 / 1,033 |

변수·조건 명령(`A0`~`A2`, `B0`~`BD`)은 쓰지 않습니다.

### 시퀀서와 합성

`export` 는 DS 사운드 드라이버를 흉내 내 곡을 합성합니다. 참고 구현은 같은 저장소 주인의 ghost-trick `sseq_render.py`(MIT)이고, 이 게임이 쓰는 명령을 더했습니다.

- 갱신 주기는 ARM7 64 × 2728 클록(약 191.96Hz)입니다. 프레임마다 템포 누산기에 템포를 더해 240 이 넘을 때마다 한 틱(4분음표 48틱)을 돌고, 엔벨로프·LFO·휩쓸기는 프레임마다 갱신합니다.
- 감쇠는 0.1dB 단위이고 세기·트랙 음량·표현·곡 음량을 모두 `round(400·log10(v/127))`(NitroSDK 의 제곱 데시벨 표와 같은 값, 진폭 ∝ v²)로 더합니다. 엔벨로프는 어택 곱셈·디케이/릴리스 뺄셈(NitroSDK 의 `Cnv_Attack`·`Cnv_Fall`), 진폭은 `10^(감쇠/200)` 입니다.
- 음높이는 1/64 반음 단위: (음 − 기준 음) × 64 + 휨 × 폭 × 64 / 128 + 휩쓸기 + LFO.
- 악기 종류: PCM(1)·PSG(2, 듀티 (n+1)/8 의 네모파, 기준 음에서 약 261.6Hz)·잡음(3, 15비트 LFSR)·드럼 세트(0x10)·키 분할(0x11).
- 동시 발음은 플레이어 채널 수(곡 12)로 막고, 넘치면 우선순위가 낮은 것·놓는 중인 것·오래된 것 순으로 뺏습니다.

곡의 루프는 트랙이 처음으로 앞자리로 건너뛰는(`94`) 틱으로 찾고, 모든 트랙이 루프하거나 끝난 뒤 가장 긴 루프를 곡의 루프로 씁니다. 사건(음) 단위로 루프 1회차와 2회차가 같은지 7곡(2·5·14·21·30·32·51)을 견줬더니 음 862~2,044개 중 일치가 0.999~1.000 이었습니다. 루프가 없는 곡은 21개(장 끝 곡 6·8·10·13, 엔딩 34, ME 35~50)입니다.

합성 결과는 근사입니다. 에뮬레이터(desmume libretro)의 소리를 녹음해 견주려 했으나, 이 코어를 화면 없이 돌려 받은 소리는 장면을 바꿔도 스펙트럼이 거의 같고 리듬이 보이지 않아(동기 모드 출력으로 보임) 대조하지 못했습니다(「남은 것」).

### 악보(JSON·TXT)

SFC DQ5 의 SPC 악보로 옮길 때 FC 곡과 같은 변환기를 쓰려고, FC 의 `NN.json`·`NN.txt`([FC 「중간 형식」](../../../fc/dq4/docs/dq4-sound-format.md#중간-형식json))와 같은 꼴로 냅니다. `export` 가 곡·효과음마다 MIDI·WAV 를 만드는 같은 시퀀서 실행에서 씁니다.

| 키 | 내용 | FC 와 다른 점 |
| --- | --- | --- |
| `id`, `kind` | 번호(16진, 곡 2자리·효과음 3자리), `song`/`sfx` | 같음 |
| `tempo`, `ticks_per_second`, `tempo_changes` | 틱 0 의 템포(`E1` 이 없으면 120), 그 템포의 실제 틱 속도(템포 ÷ 240 × 191.96), 값이 바뀐 [틱, 템포](같은 틱에 여럿이면 마지막) | 템포 값의 단위가 다름(SSEQ 는 4분음표/분) |
| `ticks_per_quarter` | 48 | NDS 만 |
| `loop_start`, `loop_len`, `end_tick` | 곡 루프의 시작 틱·길이(없으면 `null`), 기록을 멈춘 틱(루프 곡은 루프 2회 끝, MIDI 와 같음) | 같음 |
| `name`, `title` | `SYMB` 이름, 사운드 테스트 이름 | NDS 만 |
| `bank`, `instruments` | SBNK 번호·이름·파형 묶음, 이 악보가 쓰는 프로그램마다 SBNK 정의(종류, 구간마다 음 범위·파형·기준 음·ADSR·팬, PCM 은 `samples/` 파일 이름) | FC 의 `channels[].bank` 는 롬 뱅크라 뜻이 다름 |
| `volume`, `channel_priority`, `player_priority`, `player` | SEQ 레코드(효과음은 SSAR 칸) | NDS 만 |
| `channels[]` | 트랙마다 `name`(`trackN`)·`track`(트랙 번호)·`start`·`midi_track`·`midi_channel`·`programs` 와 `items[]` | FC 는 기종 채널(`pulse1` 등) 4개 |
| `items[]` | 그 트랙이 시퀀서 실행에서 지난 명령을 주소 순으로 푼 것. 모두 `addr`·`bytes`·`op`. `note` 는 `note`(전치 전 MIDI 음 번호)·`velocity`·`gate`(울리는 틱), `rest` 는 `len`, `jump`·`call`·`open-track` 은 `target`(`open-track` 은 `track` 도), `loop-start` 는 `count`(0 은 끝없이), `loop-end` 는 `target`(되풀이 첫 명령), 그 밖은 `args` | 아래 |
| `timeline[]` | 음마다 `tick`·`frame`·`ch`·`addr`·`note`(전치 뒤)·`velocity`·`len`·`gate`·`program`·`volume`·`expression`·`pan`·`transpose`·`bend`·`bend_range`·`priority`·`tie`·`mod`(깊이가 0 이 아닐 때 깊이·속도·종류·폭·지연)·`adsr`(트랙이 덮어쓴 값, 없으면 `null`)·`sweep`·`portamento` | FC 는 쉼·이음도 있음. NDS 는 쉼이 따로 없어 음만 |

- `addr`·`target` 은 SSEQ 파일(효과음은 SSAR 파일) 안 위치입니다. FC 와 같이 `addr` 는 16진 글자, `target` 은 정수입니다.
- 음 길이: FC 의 음은 `len`(다음 음까지)과 `gate`(울리는 길이)를 함께 가집니다. SSEQ 는 `note-wait`(`C7`)가 0 이면 음이 기다리지 않고 쉼(`rest`)이 시간을 넘깁니다. 곡은 433트랙 모두 0 입니다. 그래서 `items` 의 음에는 `gate` 만 두고, `timeline` 의 `len` 은 그때 기다린 틱(`note-wait` 0 이면 0)입니다.
- `op` 이름: 뜻이 같은 것은 FC 와 같게 씁니다(`note`·`rest`·`tempo`·`jump`·`call`·`return`·`transpose`·`end`). 나머지는 SSEQ 명령 그대로입니다: `program`(`81`), `pan`·`volume`·`master-vol`·`expression`(`C0`·`C1`·`C2`·`D5`), `bend`·`bend-range`(`C4`·`C5`), `priority`·`note-wait`·`tie-mode`(`C6`~`C8`), `porta-key`·`porta`·`porta-time`(`C9`·`CE`·`CF`), `mod-depth`·`mod-speed`·`mod-type`·`mod-range`·`mod-delay`(`CA`~`CD`·`E0`), `attack`·`decay`·`sustain`·`release`(`D0`~`D3`, 엔벨로프 덮어쓰기), `loop-start`·`loop-end`(`D4`·`FC`), `sweep-pitch`(`E3`), `open-track`·`track-alloc`(`93`·`FE`). FC 의 `tie`(앞 음 잇기 음표)는 SSEQ 에서 `tie-mode` 를 켠 뒤의 음이라 이름을 나눴습니다. FC 의 `loop` 는 끝에 횟수가 있고 SSEQ 는 처음(`loop-start`)에 있습니다.
- `items` 는 정적 디스어셈블이 아니라 시퀀서가 실제로 지난 명령입니다(트랙 번호마다 `Track.visited`). 곡은 끝까지 따라가므로 위 명령 표의 수와 모두 같습니다(음 42,970, 쉼 117,419, 음량 77,342 등). 부르기(`call`)로 들어간 서브루틴은 그것을 부른 트랙마다 들어갑니다.
- txt 는 FC 처럼 `곡 NN: 이름 (SYMB), SSEQ 파일, 뱅크, 음량, 플레이어, 트랙 번호:시작` 머리, 트랙마다 `[trackN] $시작` 과 `주소  바이트  명령`, 끝에 음 사건(틱, 트랙, 음 이름, 음 번호, 세기, len, gate, 프로그램)·템포 바뀜·되풀이·끝 틱입니다.

검증(`scorecheck`): `items` 만으로 트랙을 돌리는 해석기(시퀀서와 따로 짠 것)로 사건을 다시 만들어, 곡은 같은 MIDI 쓰기로 SMF 를 써 `export` 의 `.mid` 와 견주고, 효과음은 json 의 `timeline` 과 음을 견줍니다. 곡 50개 모두 MIDI 바이트가 같았고(음 98,675개, 템포 사건 포함), 효과음 634개도 모두 음(3,460개)이 같았습니다. 이번 `export` 의 `.mid`·`.sseq`·`.wav`(곡 폴더 151개, 효과음 634개)는 PR #328 때 에셋 저장소에 올린 것과 바이트가 같습니다.

## SBNK·SWAR·STRM

- SBNK: `0x38` 악기 칸 수, `0x3C` 부터 칸마다 4바이트(u8 종류, u16 위치). 종류 1·2·3 은 위치에 10바이트(u16 파형, u16 파형 묶음 칸, u8 기준 음, u8 어택·디케이·서스테인·릴리스, u8 팬), 0x10 은 (낮은 음, 높은 음) 뒤 음마다 12바이트(u16 종류 + 10바이트), 0x11 은 8바이트 위쪽 음 경계 뒤 구간마다 12바이트입니다. 54개 뱅크의 악기 칸은 빈 칸 4,087, PCM 194, PSG 7, 잡음 27, 드럼 세트 21(구간 236), 키 분할 195(구간 556)입니다.
- SWAR: `0x38` 샘플 수, `0x3C` 부터 u32 위치. SWAV 는 머리 12바이트(u8 형식, u8 루프, u16 표본율, u16 타이머, u16 루프 시작(워드), u32 루프 길이(워드)) 뒤 자료입니다. IMA-ADPCM 은 자료 첫 워드가 (예측값 s16, 색인 u16)이고 루프 시작은 그 워드를 뺀 니블 수입니다. 샘플 362개: IMA-ADPCM 278, PCM16 77, PCM8 7, 루프 있는 것 303. 표본율은 22050Hz(55)·32000Hz(40)·18000Hz(28) 순으로 많습니다.
- STRM: `HEAD` 의 `0x18` 형식·루프·채널 수, `0x1C` 표본율, `0x20` 루프 위치·총 표본·자료 위치·블록 수·블록 크기·블록 표본·마지막 블록 크기·표본. 자료는 블록마다 채널 순서로 놓입니다.

### 필드 곡

`0x02025BF8` 이 고릅니다(`0x020BAE20` 이 0 이면 고르지 않음). 장 번호 `0x020BAE24` 가 1~4 면 5·7·9·12, 0 이면 곡 없음, 5·6 이면 이야기 플래그 `0x14A` 가 꺼져 있을 때 19, 켜져 있을 때 일행 첫 인물 번호로 고릅니다: 3(ライアン) → 5, 4~6(アリーナ·クリフト·ブライ) → 7, 7(トルネコ) → 9, 8·9(ミネア·マーニャ) → 12, 25(ピサロ) → 27, 1·2(ソロ·ソフィア) → 일행이 혼자면 19, 아니면 `0x0200F528` 에 따라 19 또는 20, 그 밖 → 20. 이어서 `[0x020C4EAC+4]` 가 1·2 이면 20, 탈것 `0x020ECE40` 이 1 이면 28(기구), 2 이면 25(배)입니다(코드 읽기). 인물 번호는 이름 표 `MESS/ja/b1001000.mpt` 의 색인 + 1 입니다(23 ドラン, 24 ロザリー, 25 ピサロ).

실측: 장 시작 세이브스테이트 6개에서 필드로 나가니 5·7·9·12·19·20, 6장에서 탈것 칸을 1·2 로 쓰니 28·25 였습니다. 6장 일행의 첫 자리를 7명(ソロ·ライアン·アリーナ·トルネコ·ミネア·マーニャ·ピサロ)으로 바꿔도 모두 20 이었습니다. 마차가 있으면 20 으로 덮이는 것으로 보이며, `0x020C4EB0` 을 0 으로 묶어도 바뀌지 않아 선두별 곡은 실측하지 못했습니다.

### 전투 곡

`0x02025D68` 이 고릅니다. 기본 30, 장(`0x020EB9A8`)이 4 이거나 `0x02010330`(5장 이상에서 일행을 보는 조건, FC 의 「첫 둘이 ミネア·マーニャ」 와 같은 것으로 보임)이 참이면 11. 조우 객체 `0x020C4CD8` 의 `+0x120`(조우 레코드의 `+0`)이 0 이 아니면 그 곡, `[0x020EAA70]` 이 0 이 아니면 33 입니다. 조우 레코드는 ARM9 `0x0209B774` 의 `0x28` 바이트 표이고, 곡이 있는 것은 고정 전투(`+0x1A` 고정 무리 번호) 19개입니다: 31 이 13개(157·158·169·172~174·176·177·180~184), 32 가 3개(179·185·241), 11 이 2개(170·175), 16 이 1개(243).

실측: 전투 테스트에서 1·6장 30, 4장 11. 던전 `dab1` 에서 조우 레코드 번호(`0x020C4CE0`)를 고정하고 걸어 일으킨 전투 19건(보통 + 고정 18)이 모두 표대로였습니다(고정 무리는 실리지 않아 상대는 비어 있음). 1장 던전에서 조우해 A 만 누른 기록은 30 → 23 → 2(バトランド城)였고, 23 은 오버레이 3 의 `0x02120C5C` 가 부릅니다(전멸로 보임). 6장 일행으로 이긴 기록은 30 → 21(맵 곡)이었고, 승리 팡파르로 보이는 곡 요청은 없었습니다.

### 스크립트의 소리 명령

이벤트 스크립트 명령(`0x0201FDA8` 의 분기 표)을 처리기까지 따라갔습니다. 명령 전체는 [script-format.md](script-format.md) 에 있습니다.

| 명령 | 처리기 | 하는 일 | 쓰인 수 |
| --- | --- | --- | --- |
| `0x86 n` | `0x020240DC` | 곡 n(`0x02025B28`) | 31 |
| `0x87 n` | `0x020240EC` | n 이 1 이면 곡을 15프레임에 줄여 멈춤(`0x020540B4`) | |
| `0x147 n` | `0x02024C2C` | n 이 0 이면 곡을 멈추고(`0x020540B4`), 아니면 곡 n. 어느 쪽이든 필드 곡 자동 고르기를 끔(`0x020BAE20` = 0, 필드 곡 함수가 이 값이 0 이면 아무것도 하지 않음) | 48 |
| `0x13A n 길이 x` | `0x0202250C`(`0x02023290` 을 부름) | 인자 n 이 모두 ME 번호(여관 41, 레벨업 47 등)라 ME 로 보임 | 20 |
| `0x62 n` / `0x63 n` | `0x02025304` / `0x02025314` | 효과음 n(`0x02025E58` → `0x02054118` / `0x02025E60` → `0x02054134`) | 586 / 85 |

대사 창은 글자를 찍을 때 `0x0204CE1C` 에서 효과음 301~303(メッセージ 高·中·低)을 고르고, 대사의 끝 표지 `@cN@` 이 그 값을 줍니다([text-format.md](text-format.md), 코드 읽기). 301·302 는 같은 PCM 샘플(`WAVE_SE` 76, 악기 88)을 음 84·76 으로, 303 은 다른 샘플(3, 악기 97)을 음 64 로 2~3틱 치는 짧은 소리입니다.

## 추출물

`ndssound.py export OUT` 의 결과를 비공개 에셋 저장소 `nds/dq4/sound/` 에 둡니다. 에셋 저장소 규칙대로 파일 이름은 16진 번호와 이름(사운드 테스트 이름, 없으면 `SYMB` 이름에서 `SND_BGM_`·`SND_SE_M_` 를 뗀 것)입니다.

| 경로 | 내용 | 수 |
| --- | --- | --- |
| `songs/NN-이름.sseq` | SDAT 의 원본 SSEQ | 50 |
| `songs/NN-이름.mid` | MIDI(SMF 1, 4분음표 48틱, 트랙마다 채널, `loopStart`/`loopEnd` 표시, 루프 2회 펼침) | 50 |
| `songs/NN-이름.json`·`.txt` | 악보(아래 「악보」). 서곡 `01` 은 스트림이라 없음 | 50 |
| `songs/NN-이름.wav` | 합성(32768Hz 스테레오, 도입 + 루프 1회 + 4초 페이드). `01-序曲.wav` 는 스트림을 그대로 | 50 + 1 |
| `sfx/NNN-이름.wav` | 효과음 합성(루프는 2회 + 0.5초, 30초까지) | 634 |
| `sfx/NNN-이름.json`·`.txt` | 효과음 악보 | 634 |
| `samples/SS-NN.wav` | SWAR 샘플(16비트, 루프는 `smpl` 청크). SS 는 파형 묶음 번호 | 362 |
| `songs/`·`sfx/`·`samples/index.json` | 번호·이름·길이·루프 지점(초·표본·틱)·SDAT 위치(FAT 파일 번호·위치·크기, 효과음은 SSAR 안 시퀀스 위치)·쓰는 장면·악보 파일(`score`·`scoreText`). `01` 은 `score: null` 과 까닭(`scoreNote`), FC 서곡 악보 자리(`fcScore`: `fc/dq4/sound/songs/02.json`). `samples/index.json` 에 SBNK 악기 정의(종류·구간·파형·기준 음·ADSR·팬) 54개 | |
| `gallery/index.html` | 갤러리(`audio` 태그, `preload="none"`) | |

곡 WAV 를 루프 2회로 두면 726MB 라 1회로 줄였고(약 400MB), 루프 2회는 MIDI 와 `index.json` 의 루프 지점으로 씁니다. `.mini2sf` 는 DS 쪽 재생 드라이버 롬이 있어야 만들 수 있어 두지 않았습니다(「남은 것」).

```sh
uv run --locked python nds/dq4/tools/ndssound.py info
uv run --locked python nds/dq4/tools/ndssound.py export OUT
uv run --locked python nds/dq4/tools/ndssound.py scorecheck OUT     # 악보 json → MIDI 가 .mid 와 같은지
DESMUME_CORE=… uv run --locked python nds/dq4/tools/ndssound.py scenes work/sc0.json --maps all --shard 0/4   # 1/4·2/4·3/4 도
uv run --locked python nds/dq4/tools/ndssound.py summary work/summary.json work/sc0.json work/sc1.json work/sc2.json work/sc3.json
uv run --locked python nds/dq4/tools/ndssound.py gallery OUT --scenes work/summary.json
```

## 남은 것

- `.mini2sf`(DS 재생 드라이버를 담은 2SF) 만들기.
- 악보 json 을 SPC 악보로 옮기는 변환기와, DS 에만 있는 곡(ピサロ 26·27·51, 밤 3·15, 17·33)의 옮김. 악기(SBNK 프로그램)를 DQ5 악기에 대응시키는 표.
- 합성과 실기(에뮬레이터) 소리의 대조. desmume libretro 코어를 화면 없이 돌려 받은 소리가 장면과 무관하게 뭉개져 있어 견주지 못했습니다. 코어의 소리 동기 방식을 바꾸거나 다른 에뮬레이터로 녹음해야 합니다.
- 쓰는 곳을 못 찾은 곡: 4, 장 끝 6·8·10·13, ME 39·40·42·44·48·49·50. 승리 팡파르(FC `11`, DQ5 `1F`)가 DS 에 있는지(6장 승리에서 곡 요청 없음).
- 5·6장 선두 인물별 필드 곡의 실측(마차가 있으면 늘 20). 마차 칸으로 본 `0x020C4EB0` 이 맞는지.
- 고정 전투 레코드(`+0x1A` 고정 무리 번호)와 보스 이름의 대응. 33 을 켜는 `[0x020EAA70]` 의 장면.
- 효과음 대부분의 실제 장면(문·계단·주문·회심 등은 이름표 이름만, 실측은 전투 몇 가지).
- `BANK_BGMT`·`WAVE_BGMT`·`BANK_ME`·`PLAYER_ME` 를 쓰는 곳.
- 23 이 전멸 곡인지 화면으로 확인.
