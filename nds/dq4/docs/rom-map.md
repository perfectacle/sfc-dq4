# NDS DQ4 롬 지도

DS 일본판 `rom/dq4ds.nds`(헤더 `DRAGONQUEST4` / `YIVJ`)의 파일 시스템입니다. `krpatch nds unpack` 으로 풀고 `nds/dq4/tools/ndsfs.py` 로 셌습니다.

```sh
uv run --locked krpatch nds unpack rom/dq4ds.nds work/nds/jp
uv run --locked krpatch nds unpack rom/dq4ds-kr.nds work/nds/kr
uv run --locked python nds/dq4/tools/ndsfs.py summary work/nds/jp
uv run --locked python nds/dq4/tools/ndsfs.py diff work/nds/jp work/nds/kr
```

## 머리

| 카드 크기 | 128MB, 그중 `0x6209278` 바이트 사용 |

일본판과 내용이 다른 파일은 216개입니다. 대사 파일 `MESS/ja/*.mpt` 207개 전부와 아래 9개입니다. 다른 언어 대사와 그래픽 폴더는 그대로입니다.

### `TRANS/m278_03.dssa` 의 1바이트

바뀐 곳은 파일의 마지막 바이트(`0x3AD7`)입니다. 이 파일은 DSSA([graphics-format.md](graphics-format.md#dssa--아틀라스를-오려-붙이는-애니메이션))이고, 마지막 바이트는 마지막 프레임(`FRAM` 71번, 기록 48개)의 마지막 기록의 u8 순서 칸입니다. 일본판은 앞 기록들과 이어지는 `2C`·`2D`·`2E` 인데 한글판만 `00` 입니다.

두 롬의 FAT 를 비교하면 까닭이 보입니다. 일본판은 파일 번호 순서와 다르게 놓여 있고 마지막 자리는 파일 43번입니다. 한글판은 파일을 번호 순서대로 다시 묶었고, 이 파일(파일 번호 4826, 가장 큰 번호)이 롬의 맨 끝에 옵니다. 그 끝(`0x607D510`)이 헤더의 사용 크기이자 한글판 롬 파일 크기(101,176,592바이트, 128MB 가 아님)입니다. 롬을 다시 묶고 잘라 내는 과정에서 맨 끝 한 바이트가 0 이 된 것으로 보입니다. 번역과는 상관없는 바뀜입니다. 이 기록이 화면에 주는 차이(그리는 순서)는 확인하지 않았습니다.

## 실행 파일의 Shift_JIS 문자열

대사 파일(UTF-8)과 달리 `arm9.bin`·오버레이 안의 메뉴 문자열은 Shift_JIS 입니다. 롬의 `arm9.bin` 은 압축되지 않았고(`0x02000000` 에 그대로 실림), 오버레이 적재 주소는 `y9.bin`(32바이트 레코드, `+04` 가 주소)에 있습니다. `ndstext.py sjis` 가 문자열과 그것을 가리키는 포인터를 찾습니다.

```sh
uv run --locked python nds/dq4/tools/ndstext.py sjis work/nds/jp work/nds/kr
```

꼴은 하나입니다. 4바이트 맞춘 자리에서 시작해 0 으로 끝나고, 다음 문자열도 4바이트 맞춘 자리에서 시작합니다. 메뉴 문자열 대부분은 앞에 `@` 를 붙입니다(`@だいじなもの`). 문자열은 주소(u32)로만 불립니다. 코드의 리터럴 풀에 주소 하나가 있거나, 주소를 늘어놓은 표가 있습니다.

| 모듈 | 문자열 | 한글패치가 바꾼 것 | 주로 있는 곳 |
| --- | --- | --- | --- |
| `arm9.bin` | 201 | 92 | `0B30A0`~`0BF6D8`. 이름 입력 글자판 표 4개(`0BEFE4` 32개, `0BF0E8` 33개, `0BF068`·`0BF170` 27개씩, 가리키는 문자열은 `0BEB60`~`0BEE18`), 인물 이름 표(`0B2DBC` 20개: `@エド`·`@カーラ`…), 메뉴 낱말 |
| `overlay_0000` | 2 | 0 | `タウン`·`ランド` |
| `overlay_0015` | 1 | 0 | `@テストです` |
| `overlay_0016` | 28 | 28 | 필드 메뉴(도구·주문·작전·상점 일람, 이민 마을) |

찾은 232개 모두 가리키는 포인터가 있습니다(158개는 2개 이상 이어진 주소 표 안).

가나가 없는 한자·기호만의 문자열은 잡음이 많아 따로 찾습니다(`--kanji`). 포인터가 있는 것만 남기면 14개입니다.

| 모듈 | 오프셋 | 문자열 | 한글패치 |
| --- | --- | --- | --- |
| `arm9.bin` | `0BAA3C`, `0BED1C`~`0BED9C` | `@？`, `@！`, `@．`, `@　`(전각 공백), `@－` | 그대로. 이름 입력 글자판의 기호 칸 |
| `overlay_0000` | `022E00` | `横丁` | 「거」 + 표에 없는 `那` |
| `overlay_0000` | `0276C4` | `囮卆` | 그대로. 뜻 모름(문자열이 아닐 수 있음) |
| `overlay_0015` | `00C4A4`, `00C874` | `@？` | 그대로 |
| `overlay_0016` | `015FA4`, `0189B4`, `0189B8`, `0199FC` | `@完`, `@倍`, `@＿`, `@？` | `@완`, `@배`, 그대로, 그대로 |

```sh
uv run --locked python nds/dq4/tools/ndstext.py sjis work/nds/jp work/nds/kr --kanji
``` 팬패치는 포인터를 고치지 않고 같은 자리에 같은 길이 이하로 덮어썼습니다. 카타카나 글자판 자리는 `@Ａ`~`@ｚ` 영문자로 바꿨습니다. 바꾼 문자열을 대응표로 읽은 결과와 오타는 [text-format.md](text-format.md#실행-파일-문자열의-오타)에 있습니다.

## `DEBUG/*.dat`

`data/data/DEBUG/` 의 네 파일은 Shift_JIS(cp932) 쉼표 구분 글(줄 끝 CRLF)입니다. 개발용 메뉴가 쓰던 목록으로 보이고, `flagshop.dat` 말고는 여는 코드를 찾지 못했습니다([debug.md](debug.md)).

| 파일 | 줄 | 꼴 | 내용 |
| --- | --- | --- | --- |
| `flagshop.dat` | 347 | `번호, 묶음, 이름` | 진행도 프리셋 이름(「序章」~「天空城（裏エンディング）」). 적용 코드는 [debug.md](debug.md) |
| `action.dat` | 565 | `번호,이름` | 행동 번호 0~564 의 이름. 0 `なし`, 1 `メラ` 부터 주문·특기, 몬스터 전용 행동(`あやしいめ`, `かみつき攻撃`), 보스 단계별 행동(`エビルプリースト２６`). 빈 번호는 `なし` |
| `fieldsymbol.dat` | 90 | `번호,맵 머리글자 + 장소 이름` | 필드 기호(마을·동굴 표시) 번호와 장소. 예: `10,HA(CA)バトランド城下町＆城`, `120,DPお楽しみダンジョン（DPOUT）`. 머리글자는 맵 이름 앞 두 글자(`MAP/_list.txt` 의 둘째 칸)와 같은 꼴 |
| `soundlist.dat` | 87 | `종류, 번호,이름`(종류는 `BGM`·`SE`) | 사운드 테스트 목록. BGM 48곡(1 `序曲`~), SE 38개(300 `決定音`, 301~303 `メッセージ（高·中·低）`, 400번대 전투음) |

세 목록의 번호는 게임 안 번호와 같습니다.

- `action.dat`: 주문·특기 이름 표(`b1003000`, 게임 번호 = 메시지 번호 − 1003000)와 번호가 맞습니다. 두 쪽에 이름이 있는 120개 중 88개는 이름 표의 이름이 그대로 들어 있고(`51,自ホイミ` ↔ 51 `ホイミ`), 나머지 32개도 같은 행동의 개발용 이름입니다(`110,ほのお小` ↔ `ひのいき`, `226,力ため１` ↔ `ちからため`).
- `fieldsymbol.dat`: 스크립트 명령 `0xBE`(필드로 나가기)의 첫 인자로 쓰이는 15가지가 모두 이 목록에 있고, 그 스크립트의 맵이 있는 장소입니다(`caf1` 10 バトランド, `cbf3` 32 サントハイムの城, `mqout` 59 ロザリーヒル). [script-format.md](script-format.md)
- `soundlist.dat` 의 SE: 스크립트 명령 `0x62`(효과음)의 인자 305·309·311 이 `階段`·`扉（大）`·`扉（岩・石など）` 와 번호가 같습니다. 글자 효과음 301~303 은 메시지 창 코드의 상수와 같습니다([text-format.md](text-format.md#끝-표지-cn)). BGM 번호는 확인하지 않았습니다.

## 남은 것

- `PARAM/*.dat` 는 동료 대화·몬스터·가게·メダル·얻는 물건 표까지([param-format.md](param-format.md)), 나머지 파일은 남음. `SCRIPT/*.bin` 은 [script-format.md](script-format.md).
- `DEBUG/soundlist.dat` 의 BGM 번호와 게임 BGM 번호.
