# NDS DQ4 PARAM 표 형식

`data/data/PARAM/*.dat` 가운데 늘어난 내용([extras.md](extras.md))을 가르는 데 쓴 표입니다. 몬스터·가게·メダル·얻는 물건·동료 대화 표와, 이벤트 스크립트(`SCRIPT/<맵>.bin`)가 부르는 대사 파일을 다룹니다. 도구는 [ndsparam.py](../tools/ndsparam.py), 찾은 과정은 [2026-10-25-07 일지](../journal/2026-10-25-07-param.md) 에 있습니다. 진행도 프리셋(`param_player_event*`·`param_player_flag`)은 [debug.md](debug.md), 메시지 번호 규칙은 [text-format.md](text-format.md) 를 봅니다.

모든 PARAM 파일은 머리 4바이트 뒤에 고정 길이 레코드가 이어집니다. 머리 값은 파일 종류마다 다르고(`param_map_shop_*`·`param_map_medal` 은 `1A 00 00 00`, `param_item_*` 은 `32 BC 00 00`) 레코드 수와는 맞지 않습니다.

```sh
uv run --locked python nds/dq4/tools/ndsparam.py monsters work/nds/jp rom/dq4.nes   # DS 몬스터 표와 FC 대조
uv run --locked python nds/dq4/tools/ndsparam.py items work/nds/jp rom/dq4.nes      # 아이템 번호 대조
uv run --locked python nds/dq4/tools/ndsparam.py casino work/nds/jp rom/dq4.nes     # 카지노·メダル 경품
uv run --locked python nds/dq4/tools/ndsparam.py talk work/nds/jp 1                 # 동료 대화 조건
```

| `+02` | u16 | 레벨(보스 99, 엔딩 뒤 300~450) | 값 분포 |

## 아이템 번호

가게·メダル·얻는 물건 표의 아이템 값 n 은 이름 표 `b1000000` 의 n−1 번입니다. 1장 バトランド 가게 줄이 `(2, 30) (3, 100) (10, 200) (5, 550)` 이고, FC 같은 가게가 こんぼう 30G·どうのつるぎ 100G·いばらのむち 200G·くさりがま 550G 입니다. n−1 번 이름이 こんぼう·どうのつるぎ·せいなるナイフ·くさりがま 이므로 값이 맞습니다.

DS 와 FC 의 아이템 순서는 무기 앞쪽(FC `00`~`13`, DS 번호 = FC ID + 1)만 같고, 그 뒤는 DS 가 새 아이템을 사이사이에 끼워 넣고 도구 순서도 바꿨습니다. 옮길 때는 번호를 더해서 맞추지 말고 `items` 가 내는 대응표를 씁니다. 아이템의 강도·장비 가능 인물 표는 PARAM 에 없습니다(`arm9.bin`·오버레이에서 가격 열을 찾지 못함, 남은 것).

## 동료 대화 표

머리 4바이트 + 44바이트 레코드(7,209개). 게임은 맵에 들어갈 때 그 맵의 레코드 묶음(같은 `+18` 이 이어진 줄)을 힙에 옮기고, 「はなす」로 일행과 말하면 조건을 통과한 레코드 목록을 만들어 그중 하나를 띄웁니다.

| RAM | 뜻 |
| --- | --- |
| `0x020ED18C` | 지금 맵의 레코드 묶음 주소 |
| `0x020ED190` | 그 묶음의 레코드 수 |
| `0x020ED194` | 조건을 통과한 레코드 목록. 항목 `0x1C` 바이트(+0 줄 수, +4 메시지 번호) |
| `0x020ED2AC` | 통과한 레코드 수 |
| `0x020ED2B0`·`0x020ED2B4` | 고른 항목 번호, 그 메시지 번호(화면에 뜬 문장과 같음) |
| `0x020ED338` | 지금 맵 번호(`MAP/_list.txt` 순서) |

| 위치 | 크기 | 뜻 | 근거 |
| --- | --- | --- | --- |
| `+00` | u16 | 조건 값 0(이야기 플래그 번호로 보임). 0 이 아니면 이번 실측에서 한 번도 통과하지 않음(425줄) | 모름 |
| `+04` | u16 | 조건 플래그 1. `+1E` 가 1 이면 켜져 있어야, 2 면 꺼져 있어야 통과 | 아래 실측 |
| `+08` | u16 | 조건 플래그 2. `+1F` 가 1 이면 켜짐, 2 면 꺼짐 | 아래 실측 |
| `+0C` | u16 | 조건 값 3(한 번만 나옴) | 모름 |
| `+10` | u32 | 첫 메시지 번호 | 화면 대조 |
| `+14` | u16 | 켜져 있어야 하는 이야기 플래그 | 아래 실측 |

| `+18` | u16 | 맵 번호(`MAP/_list.txt` 순서. 544·545 는 목록 밖, 필드로 보임) | `0x020ED338` 과 같은 맵의 묶음만 실림 |
| `+1A` | u16 | 줄 수: 첫 메시지부터 이어서 띄울 메시지 수. 10 이상(111, 211, 8221 …)은 다른 뜻 | 7,209개 모두 번호~번호+줄 수−1 이 대사에 있음 |
| `+1C` | u8 | `FF` 면 조건 없음. 0~27 이면 이번 실측에서 거의 통과하지 않음(1,875개 중 3개) | 모름 |
| `+1E`·`+1F` | u8 ×2 | 조건 플래그 1·2 의 뜻(1 켜짐, 2 꺼짐, 4·7·8 은 모름) | |
| `+21` | u8 | 말하는 인물 = 인물 이름 표 `b1001000` 번호 + 1 | 대사의 화자 이름과 7,208/7,209 일치 |
| `+22` | u8 | 시간: 0 언제나, 2 낮, 4 밤, 8·10 은 모름 | 낮 실측 514번에 4 는 한 번도 없음 |
| `+28` | u16 | 비트 묶음. `0x40` 이 없으면 거의 통과하지 않음 | 통과 514번 중 509번이 `0x40` 있음 |
| `+2A` | u16 | 늘 `0101` | |

이야기 플래그는 RAM `0x020CE7DC` 의 비트 배열입니다([debug.md](debug.md#ram-지도)).

### 실측

진행도 프리셋 1~346 을 하나씩 적용해 그 시작 맵에서 「はなす」를 고르고, 통과 목록(`0x020ED194`)과 그때의 이야기 플래그를 모았습니다. 일행과 말할 수 있었던 280곳에서 묶음 레코드 7,907줄(통과 514줄)을 얻었습니다.

- `+14` 켜짐·`+16` 꺼짐: 통과 514줄 모두 성립(프리셋 표만으로 계산하면 1줄 어긋남, RAM 플래그로는 0줄).
- `+04`·`+1E`: 통과 줄 가운데 `+1E` 가 1 인 68줄은 모두 플래그가 켜져 있고, 2 인 93줄 중 88줄은 꺼져 있음. `+08`·`+1F` 도 1 인 19줄은 켜짐, 2 인 21줄은 꺼짐.
- 위 조건·`+1C = FF`·`+00 = 0`·`+28` 의 `0x40` 를 모두 따지면 통과 514줄 중 504줄을 맞히고, 통과하지 않은 줄 가운데 1,027줄을 통과로 잘못 냅니다. 잘못 낸 줄의 대부분(741줄)은 그 맵에서 통과한 줄에 없는 인물이 말하는 줄이고(그 인물이 일행에 없다고 보임), 68줄은 밤 문장입니다.
- 1장 프리셋 7·8·12·13·16 에서 화면에 뜬 문장이 `0x020ED2B4` 의 메시지 번호와 같았습니다(프리셋 13 은 레코드 1 「ホイミン「ぼく お城に入るのなんて…」」).
- `+1C` 가 맵 안 구역인지 보려고 프리셋 13(caf1)에서 주인공 자리를 13곳으로 옮겨 말했지만 목록이 늘 같았습니다.

## 이벤트 스크립트가 부르는 대사

`SCRIPT/<맵>.bin` 의 4바이트 정렬 u32 가운데 대사 파일 번호 범위(MPT0 머리 `+08`~`+0C`)에 드는 값을 파일별로 세면, 맵과 대사 파일이 이어집니다(`scripts`). 명령 형식을 풀지 않은 근사치이지만, 6장·이민 마을처럼 대사 파일이 장소별로 나뉜 곳은 장소를 바로 알려 줍니다. 결과는 [extras.md](extras.md#6장-맵과-이벤트) 에 있습니다.

## FC 와 대조

`items`·`monsters` 는 이름(히라가나·가타카나, 작은 가나 차이 무시)으로 먼저 짝을 찾고, 이름이 없으면 가게 값(아이템)이나 경험치·HP·공격·수비(몬스터)가 같은 것을 찾습니다. FC 폰트에 작은 가나가 없어 FC 이름은 `イエテイ` 처럼 적혀 있으므로, [glossary-table.md](glossary-table.md) 의 「FC 에 같은 이름 없음」 가운데 몬스터 5개(イエティ·アークバッファロー·フェイスボール·フェアリードラゴン·ガーディアン)는 표기 차이일 뿐입니다.

| 종류 | 같음 | 표기만 다름 | 이름만 바뀜(값 같음) | 값 바뀜 | 새로 생김 | DS 에 없음 |
| --- | --- | --- | --- | --- | --- | --- |
| 아이템 | 121 | 1(いかづち→いかずちのつえ) | 3(いばらのむち→せいなるナイフ, モーニングスター→ホーリーランス, ブーメラン→クロスボウ) | | 36 + 같은 이름 둘째 칸 2(てんくうのつるぎ, てつのきんこ) | 1(ラックのたね) |
| 몬스터 | 156 | 5(작은 가나) | 1(マリンリバイアサン→マリンワーム) | 52 | 67(그중 もどき 40) | |

아이템의 「이름만 바뀜」은 같은 가게 칸에 같은 값으로 섰다는 뜻이고 강도는 비교하지 못했습니다. 몬스터 「값 바뀜」 52줄은 대부분 5장 끝 몬스터의 경험치 하향(ライノスキング 855→655 등)과 보스 HP 상향(エスターク 900→2700, デスピサロ 800→1600~2100 여섯 형태)입니다. 새 몬스터는 6장·お楽しみダンジョン 의 22종(パンドラボックス~ギャオース), もどき 10종 × 4벌, エッグラ·チキーラ 각 2, まもの 1 입니다.

## 남은 것

- 동료 대화 `+00`·`+0C`·`+1C` 와 `+1E`·`+1F` 의 1·2 밖 값, `+22` 의 8, `+1A` 의 10 이상 값. 일행 조건이 레코드 어디에 있는지(말하는 인물 `+21` 이 일행에 있어야 하는 것으로 보임). 통과 목록에서 하나를 고르는 규칙(무작위인지, 들은 문장을 빼는지).
- 밤에 말해 `+22` = 4 확인. 지금 실측은 모두 낮 프리셋.
- 가게 레코드 → 마을 대응과 `+06` 교회 종류, 칸 24~25.
- 얻는 물건 종류 바이트 `07` 밖 값의 화면 확인, `+12` 가 열었음 플래그인지.
- 몬스터 `+10`~`+1D`·`+1F`~`+3B`(행동·내성·드롭), 아이템 강도·장비 표의 위치.
