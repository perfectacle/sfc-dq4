# NDS DQ4 PARAM 표 형식

`data/data/PARAM/*.dat` 가운데 늘어난 내용([extras.md](extras.md))을 가르는 데 쓴 표입니다. 몬스터·가게·メダル·얻는 물건·동료 대화 표와, 이벤트 스크립트(`SCRIPT/<맵>.bin`)가 부르는 대사 파일을 다룹니다. 도구는 [ndsparam.py](../tools/ndsparam.py), 찾은 과정은 [2026-10-25-07 일지](../journal/2026-10-25-07-param.md)·[2026-10-25-10 일지](../journal/2026-10-25-10-param2.md)·[2026-10-25-15 일지](../journal/2026-10-25-15-param3.md)·[2026-10-25-17 일지](../journal/2026-10-25-17-param4.md) 에 있습니다. 진행도 프리셋(`param_player_event*`·`param_player_flag`)은 [debug.md](debug.md), 메시지 번호 규칙은 [text-format.md](text-format.md) 를 봅니다.

모든 PARAM 파일은 머리 4바이트 뒤에 고정 길이 레코드가 이어집니다. 머리 값은 파일 종류마다 다르고(`param_map_shop_*`·`param_map_medal` 은 `1A 00 00 00`, `param_item_*` 은 `32 BC 00 00`) 레코드 수와는 맞지 않습니다.

```sh
uv run --locked python nds/dq4/tools/ndsparam.py monsters work/nds/jp rom/dq4.nes   # DS 몬스터 표와 FC 대조
uv run --locked python nds/dq4/tools/ndsparam.py items work/nds/jp rom/dq4.nes      # 아이템 번호 대조
uv run --locked python nds/dq4/tools/ndsparam.py casino work/nds/jp rom/dq4.nes     # 카지노·メダル 경품
uv run --locked python nds/dq4/tools/ndsparam.py talk work/nds/jp 1                 # 동료 대화 조건
```

| `+2F` 값 | 결과 |
| --- | --- |
| `00`·`01`·`02`·`03`·`0C`·`C0` | 「スライムに 12の ダメージ!!」 |

## 아이템 번호

가게·メダル·얻는 물건 표의 아이템 값 n 은 이름 표 `b1000000` 의 n−1 번입니다. 1장 バトランド 가게 줄이 `(2, 30) (3, 100) (10, 200) (5, 550)` 이고, FC 같은 가게가 こんぼう 30G·どうのつるぎ 100G·いばらのむち 200G·くさりがま 550G 입니다. n−1 번 이름이 こんぼう·どうのつるぎ·せいなるナイフ·くさりがま 이므로 값이 맞습니다.

DS 와 FC 의 아이템 순서는 무기 앞쪽(FC `00`~`13`, DS 번호 = FC ID + 1)만 같고, 그 뒤는 DS 가 새 아이템을 사이사이에 끼워 넣고 도구 순서도 바꿨습니다. 옮길 때는 번호를 더해서 맞추지 말고 `items` 가 내는 대응표를 씁니다.

### 아이템 표(ARM9)

아이템 능력치는 PARAM 이 아니라 ARM9 `0x02095594` 부터 32바이트 레코드에 있습니다(아이템 n 은 `0x02095594 + 32 × (n−1)`, n = 1~161). 가게 값 58개 가운데 56개가 이 표의 값과 같은 자리를 찾아서 알았습니다. 앞 판은 레코드 시작을 16바이트 앞(`0x02095584`)으로 잡아 앞 아이템의 뒷부분을 섞어 읽었습니다.

| 위치 | 뜻 | 근거 |
| --- | --- | --- |
| `+00` | u16 값(G). 0 은 가게에서 안 팖 | 가게 표와 56/58 같음 |
| `+02` | u16 팔 값. 77개 중 68개가 값 × 3/4 | |
| `+06` | u8 강도(공격력·수비력) | FC 와 이름이 같은 장비 82개 중 74개 같음 |
| `+10` | u8 아이템 번호 n(아이템 158 만 137) | |
| `+12` | u8 종류: 0 도구, 1 무기(1~42), 2 방어구(43~106), 3~6 장신구 | 번호 구간 |
| `+14` | u16 장비할 수 있는 인물. 비트 n 이 인물 번호 n+1: 0 ソロ, 1 ソフィア, 2 ライアン, 3 アリーナ, 4 クリフト, 5 ブライ, 6 トルネコ, 7 ミネア, 8 マーニャ, 9 ピサロ | 비트 0~8 이 FC 장비 표(인물 8명, 주인공은 ソロ·ソフィア 둘)와 82개 중 78~82개 같음. 비트 9 는 まかいの 장비 4종이 이 비트만 가져 ピサロ 로 봄 |
| `+04`·`+08`~`+0E`·`+13`·`+16`~`+1E` | 모름. `+1C` 는 `0x020CAExx` 꼴 주소 | |

장비 비트를 찾은 방법: ARM9·오버레이의 모든 자리·간격(1~32바이트)·비트에 대해, DS 번호 순으로 그 비트를 모아 FC 인물별 장비 가능 여부와 맞는 수를 셌습니다. 간격 32, 위 자리에서만 9개 비트가 각각 FC 인물 하나와 78개 이상 맞았습니다. 새 장비 수치와 장비 인물은 [extras.md](extras.md#새-장비-수치) 에 있습니다.

## 가게 표

머리 4바이트 + 208바이트 레코드(first 19개, second 30개). 레코드 하나가 마을 하나의 가게 모두입니다.

| 위치 | 뜻 | 근거 |
| --- | --- | --- |
| `+00` | u16, 늘 0 | |
| `+02` | u16 여관 1인 값 | first 0 이 4G(FC バトランド 4G) |
| `+04` | u16, 늘 0 | |
| `+06` | u16 교회 종류: 0 없음, 1 보통, 2 저장 없는 교회 | 2 인 레코드 셋이 FC `0E/00`·`04/0E` 와 같은 가게이고, FC 도 그 두 곳만 교회 메뉴 2~4(저장 없음) |
| `+08` | (아이템 u16, 값 u16) 50칸 | |

| 칸 | 뜻 | 근거 |
| --- | --- | --- |
| 0~5 | 무기점 | FC 무기점 줄과 같은 차례 |
| 6~11 | 방어구점 | FC 방어구점 줄과 같은 차례 |
| 12~17 | 도구점 | FC 도구점 줄. 도구점이 장비를 함께 팔면 여기 들어감 |
| 18~23 | 카지노 경품(값은 코인) | エンドール 레코드 둘에만 있음 |
| 24~25 | 다른 여관 값(second 6 의 `(0, 10)` 하나) | 같은 가게인 FC `10/00` 은 「주인공 Y < 14 이면 여관 10G」 |
| 26~31 | 밤 무기점 | second 14 의 0~3 은 FC `09/00` 낮 목록, 26~27 은 밤 목록(バトルアックス 5500·まどろみのけん 8000)과 같음 |
| 32~34 | 특별 가게 | second 1 에 みかわしのふく 3000·やいばのよろい 9800·はぐれメタルよろい 35000(FC `04/09` 은 15000) |

같은 마을이 first·second 에 모두 있습니다(second 20 = first 0). second 에만 5장 마을(FC `1B/00`·`19/00`·`1A/00`·`2F/05` 등)이 있어 first 는 1~4장, second 는 5장 이후 표로 보입니다.

레코드와 마을의 대응은 품목으로 맞췄습니다(`shops JPROOT FCROM`). DS 레코드의 무기·방어구·도구 품목을 DS 번호로 바꾼 FC 장소별 품목과 견주면, 가게가 있는 레코드 39개 가운데 29개가 어느 FC 장소와 품목이 완전히 같고 여관 값도 같습니다(예: first 0 = `02/00` バトランド, first 7 = `04/00` エンドール, second 21 = `1B/00`). 나머지는 DS 가 한 레코드에 FC 의 두 장소를 합친 것(first 2 ≈ `13/00`·`13/03`)이나 FC 에 없는 가게입니다. 가게 레코드 번호를 고르는 코드·파일 이름 문자열은 ARM9·오버레이에서 찾지 못해(`param_map_shop` 문자열이 없음, 파일 번호로 여는 것으로 보임) 품목 대조로만 맞췄습니다.

## 동료 대화 표

머리 4바이트 + 44바이트 레코드(7,209개). 게임은 맵에 들어갈 때 그 장의 표를 읽어 지금 맵(`+18`)의 레코드만 힙에 남기고, 「はなす」로 일행과 말하면 ARM9 `0x02036530` 이 조건을 통과한 레코드 목록을 만들어 그중 하나를 띄웁니다. 대화 관리자는 `0x020ED18C` 입니다.

| --- | --- | --- |

| `0x020ED194` | `+8` | 통과 목록(최대 10). 항목 `0x1C` 바이트(+0 줄 수, +4 메시지 번호, +8 세 자리 표시, +C·+10 십·일 자리) |
| `0x020ED2AC`·`0x020ED2B0` | `+120`·`+124` | 통과 수, 고른 항목 번호 |
| `0x020ED2B4` | `+128` | 들은 문장 목록(20개, 수는 `+178` = `0x020ED304`). 말할 때마다 고른 메시지를 넣고, 여기 있는 메시지는 통과 목록에 넣지 않음 |
| `0x020ED334` | `+1A8` | 말한 횟수. 3 이 되면 통과 목록에 더 넣지 않음. 마을 사람과 말하거나 아이템을 받으면 `0x02036320` 이 최근 이벤트 값·이 횟수를 0 으로 되돌림(들은 문장 목록은 그대로) |

| 위치 | 크기 | 뜻 |
| --- | --- | --- |
| `+00` | u32 | 0 이 아니면 이 값이 최근 이벤트 값 목록에 있어야 통과 |
| `+04`·`+08`·`+0C` | u32 ×3 | 조건 1~3 의 값 |
| `+10` | u32 | 첫 메시지 번호 |
| `+14` | u16 | 켜져 있어야 하는 이야기 플래그 |
| `+16` | u16 | 꺼져 있어야 하는 이야기 플래그(`FFFF` 는 조건 없음) |
| `+18` | u16 | 맵 번호(544·545 는 목록 밖, 필드) |
| `+1A` | u16 | 줄 수. 1~9 는 첫 메시지부터 그 수만큼. 세 자리 `abc`(111, 211)는 질문 a 줄 뒤에 はい/いいえ 를 묻고, はい 면 다음 b 줄, いいえ 면 그 뒤 c 줄. 네·다섯 자리(8221, 14203, 18203 …)는 천 자리(10 이상이면 −10)가 함께 말하는 인물 번호이고, 일 자리 수만큼 이어서 띄움(`0x02036CF0`). 0 이면 목록에 넣지 않음 |
| `+1C`·`+1D` | u8 ×2 | `FF` 가 아니면 직전 대화 값이 둘 중 하나와 같아야 통과 |
| `+1E`·`+1F`·`+20` | u8 ×3 | 조건 1~3 의 종류(아래 표). 0 이면 거기서 끝 |
| `+21` | u8 | 말하는 인물(인물 번호 = 이름 표 `b1001000` 번호 + 1). 걷는 줄에 있고 쓰러지지 않아야 통과(인물 `+5D` 가 0 이 아니면 쓰러져도 됨). 24(ロザリー)는 일행 맨 끝에 있어도 됨 |
| `+22` | bit2-0 | 시간: 0 언제나, 2 낮, 4 밤 |
| `+22` bit5-3 ~ `+28` bit2-0 | 3비트 ×12 | 일행 칸 조건(아래 표) |
| `+28` | bit6-3 | 우선순위 0~13. 작은 수부터 보며, 통과한 레코드가 나온 순위에서 멈춤 |
| `+29`~`+2B` | | 늘 `01 01 01` |

| --- | --- | --- | --- |

일행 칸 조건(`0x02036B54`). 3비트 자리마다 인물 하나를 봅니다: `+22` bit5-3 주인공(ソロ·ソフィア 둘 중 하나), `+23` ソロ·ソフィア, `+24` ライアン·アリーナ, `+25` クリフト·ブライ, `+26` トルネコ·ミネア, `+27` マーニャ·ピサロ, `+28` bit2-0 パノン. 값은 1 걷는 줄에 있고 살아 있음, 2 걷는 줄 밖이거나 쓰러짐, 3 2 와 같고 일행에 없어도 됨, 4 살아 있음, 5 걷는 줄에 있고 쓰러짐입니다. 걷는 줄은 `0x020C52D4[인물] & 0x1000`, 쓰러짐은 HP(인물 레코드 `+6E`) 0 으로 읽었습니다.

고르기: 통과 목록에서 ARM9 `0x0207EAA8`(선형 합동 난수, 상태 `0x02116C20`)로 하나를 고릅니다. 목록이 비면 일행에 따라 정해진 문장(`512102` トーマス「ワンワンワン」, `524434` パトリシア「ヒヒーン！」, `802267` 주인공「……」)을 씁니다. 6장은 6장 표에서 하나도 통과하지 않으면 5장 표로 한 번 더 거릅니다.

### 실측

진행도 프리셋 1~346 을 하나씩 적용하고 시작 맵에서 「はなす」를 골라, 통과 목록과 그 직전 RAM 4MB 를 모았습니다. 일행과 말할 수 있었던 곳은 280곳입니다. 위 규칙을 RAM 덤프에 그대로 적용한 흉내(우선순위, 플래그 세 벌, 아이템, 변장, 일행 칸, 들은 목록, 6장 → 5장)는 280곳 모두에서 통과 목록이 같았습니다. 이전 판의 「통과하지 않은 줄 1,027줄을 통과로 잘못 냄」은 우선순위와 일행 조건을 몰랐기 때문입니다.

RAM 을 바꿔 직접 확인한 것:

- 프리셋 12(古井戸): 최근 이벤트 값 목록에 `0x3EF` 를 넣자(`0x020ED308`, 수 1) `+00` = 1007 인 레코드 64·65 만 남음(우선순위 7 이 13 보다 앞섬).
- 프리셋 13(caf1, 낮): 시간대 `0x020CE1B4` 를 1(아침)로 두자 밤 문장(500031·500033)만 남음. 古井戸(시간 0 레코드뿐)는 그대로.
- 프리셋 13: 직전 대화 값 `0x020ED33C` 를 0·1·2·6·7·9 로 두자 `+1C` 가 그 값인 레코드(우선순위 6)가 뽑힘.
- 프리셋 12 에서 「はなす」를 되풀이하자 들은 문장 목록이 501027 → 501025 → 501033 으로 늘고, 그때마다 그 문장이 통과 목록에서 빠졌습니다. 말한 횟수(`+1A8`)가 3 이 된 뒤에는 통과 목록이 비었습니다. 고르는 순서는 난수라 같은 세이브스테이트에서도 실행마다 같다는 보장은 없습니다(이번 실행은 501027 부터).
- 프리셋 16(湖の塔 지하)에 최근 이벤트 값 1101 을 넣고 말하자 레코드 160(`+1A` = 211)이 나왔습니다. 「えぐえぐっ…」「でも もう助かったんだよね…」 두 줄 뒤 はい/いいえ 를 물었고, はい 면 501406, いいえ 면 501407 이 떴습니다.
- 프리셋 94(4장)에서 `mhout` 으로 옮기고 직전 대화 값을 4 로 두자 레코드 104(`+1A` = 18203, マーニャ)만 통과했습니다. 통과 항목의 `+14` 가 8(ミネア)이었고, 화면에는 マーニャ 두 줄과 ミネア 한 줄, 모두 세 줄이 떴습니다.
- 앞 일지에서 「고른 메시지 번호」로 읽은 `0x020ED2B4` 는 들은 문장 목록의 첫 칸이었습니다. 처음 말한 직후에는 두 값이 같아 화면 대조가 맞았습니다.

## 이벤트 스크립트가 부르는 대사

`SCRIPT/<맵>.bin` 의 4바이트 정렬 u32 가운데 대사 파일 번호 범위(MPT0 머리 `+08`~`+0C`)에 드는 값을 파일별로 세면, 맵과 대사 파일이 이어집니다(`scripts`). 명령 형식을 풀지 않은 근사치이지만, 6장·이민 마을처럼 대사 파일이 장소별로 나뉜 곳은 장소를 바로 알려 줍니다. 결과는 [extras.md](extras.md#6장-맵과-이벤트) 에 있습니다.

## FC 와 대조

`items`·`monsters` 는 이름(히라가나·가타카나, 작은 가나 차이 무시)으로 먼저 짝을 찾고, 이름이 없으면 가게 값(아이템)이나 경험치·HP·공격·수비(몬스터)가 같은 것을 찾습니다. FC 폰트에 작은 가나가 없어 FC 이름은 `イエテイ` 처럼 적혀 있으므로, [glossary-table.md](glossary-table.md) 의 「FC 에 같은 이름 없음」 가운데 몬스터 5개(イエティ·アークバッファロー·フェイスボール·フェアリードラゴン·ガーディアン)는 표기 차이일 뿐입니다.

| 종류 | 같음 | 표기만 다름 | 이름만 바뀜(값 같음) | 값 바뀜 | 새로 생김 | DS 에 없음 |
| --- | --- | --- | --- | --- | --- | --- |
| 아이템 | 121 | 1(いかづち→いかずちのつえ) | 3(いばらのむち→せいなるナイフ, モーニングスター→ホーリーランス, ブーメラン→クロスボウ) | | 36 + 같은 이름 둘째 칸 2(てんくうのつるぎ, てつのきんこ) | 1(ラックのたね) |
| 몬스터 | 156 | 5(작은 가나) | 1(マリンリバイアサン→マリンワーム) | 52 | 67(그중 もどき 40) | |

아이템의 「이름만 바뀜」은 같은 가게 칸에 같은 값으로 섰다는 뜻이고 강도는 비교하지 못했습니다. 몬스터 「값 바뀜」 52줄은 대부분 5장 끝 몬스터의 경험치 하향(ライノスキング 855→655 등)과 보스 HP 상향(エスターク 900→2700, デスピサロ 800→1600~2100 여섯 형태)입니다. 새 몬스터는 6장·お楽しみダンジョン 의 22종(パンドラボックス~ギャオース), もどき 10종 × 4벌, エッグラ·チキーラ 각 2, まもの 1 입니다.

## 남은 것

- 동료 대화: 직전 대화 값·최근 이벤트 값·`0x020B91C8` 를 쓰는 쪽의 뜻, 플래그 B·C 가 무엇을 기록하는지(대화에서는 B 1·4·10·150, C 2·4·9·14·60·61·90·200 을 봄).
- 얻는 물건: `FMAP` 에 짝이 없는 종류(`2C` 등)와 `+10` 플래그.
- 몬스터 내성 값 1·2 의 뜻, `+28`~`+2E`·`+36`~`+3B`, 행동 번호 체계.
- 가게 레코드 번호를 고르는 코드. `param_map_shop` 문자열은 없고, 파일 번호 4217·4218 은 ARM9 `0x020BE978` 의 (파일 번호, 값) 표에만 나옴. haout 스크립트에는 가게를 여는 것으로 보이는 명령이 없어(대부분 `0x4A`·`0x07`·`0x18`), 가게 인물은 맵 인물 표 쪽에서 정해지는 것으로 보임.
