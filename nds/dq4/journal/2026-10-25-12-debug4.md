# 2026-10-25-12: 시간대·인물 레코드·필드 좌표 범위·메시지 디버그 키·fk01

디버그 도구의 남은 것을 이어서 풀었습니다. 시간대 RAM 과 인물 레코드의 칸을 찾았고, 필드 좌표가 돌아가는 범위와 위 화면 지도의 대응을 쟀습니다. 메시지 디버그 키는 화면으로 확인했고, `fk01` 이 다른 맵으로 넘어가는 조건을 좁혔습니다. 결과는 [debug.md](../docs/debug.md) 에 있습니다.

## 1. 시간대

조우 판정이 전투 준비 객체에 넘기는 값 하나가 `0x0201C56C`(게임 상태 `+0xB4`)였습니다. 이 함수는 그 칸을 읽기만 하고, 쓰는 함수 `0x0201C524` 는 값 0~4 에 따라 `+0xB8` 에 밝기 값을 함께 씁니다. 장 시작 상태 넷 모두 `0x020CE1B4` 가 2 였습니다.

イムルの村(프리셋 4)에서 이 칸에 0~4 를 쓰고 맵을 다시 실었습니다. 0 은 색 보정 없음, 1 은 푸른 아침, 2 는 낮, 3 은 주황 저녁, 4 는 어두운 밤이었고, 가게 창구 사람은 2·3 에서만 나왔습니다. `ndswarp.py map … --time 4` 로 묶었습니다.

## 2. 메시지 디버그 키

500002 에서 오른쪽을 한 번씩, 함께 누르는 키를 바꿔 가며 눌렀습니다.

```
오른쪽 500003, B+오른쪽 500013, R+오른쪽 500113, R+B+오른쪽 501113, L+오른쪽 511113, L+B+오른쪽 611113
```

[앞 일지](2026-10-25-08-debug2.md)에서 코드로 읽은 단위와 같았습니다. X 는 `+8` 을 1 → 2 → 3 → 4 로 바꿨고, 3 에서 글자가 작은 창, 4 에서 창이 뜨지 않았습니다.

## 3. 인물 레코드

6장 상태에서 「つよさ」 화면을 네 명 찍고 레코드의 값과 맞췄습니다. 처음에는 ソロ 와 ドラン 둘만으로 찾다가 みのまもり·うんのよさ 가 엇갈려 헤맸습니다. ライアン·アリーナ 를 더하니 `+0x6A` 가 みのまもり, `+0x76` 이 うんのよさ 로 셋이 맞았고, ドラン(みのまもり)·ソロ(うんのよさ) 만 화면 값과 달랐습니다. ちから·すばやさ 는 장비를 뺀 값이었습니다. ライアン 의 ちから 176 에 ちからのゆびわ 를 더하면 화면의 184 입니다.

가진 물건은 `+0x84` 부터 4바이트씩입니다. 물건 번호를 그대로 이름 파일 번호로 보면 ソロ 의 장비가 「ほほえみのつえ」 같은 엉뚱한 이름이 됐습니다. 화면의 장비 이름으로 이름 파일을 거꾸로 찾으니 번호가 늘 `0x101` 씩 컸습니다.

## 4. 필드 좌표 범위

필드 워프에 1500 칸을 주니 134.67 칸에 섰습니다. x 1700·2000, z 1600·1900 에서도 같은 양만큼 줄었고, 그 양이 1365⅓ 칸 = `0x1000000` 이었습니다. 좌표가 24비트에서 돌아가는 것입니다.

위 화면 지도의 칼 모양 표시는 흰 픽셀의 중심을 재서 11곳의 좌표와 맞췄습니다. 대략 `(58 + x/10, 11 + z/10)` 픽셀입니다.

## 5. fk01

[앞 일지](2026-10-25-09-debug3.md)에서 `fk01` 은 6장(프리셋 331) 상태에서만 곧 `ckout` 으로 넘어갔습니다. 원인을 찾으려 부팅 상태에 6장 상태의 RAM 을 덮어쓰며 좁혔습니다.

- 이야기 플래그 156개 전부와 장 번호 6 을 덮어써도 `fk01` 에 머물렀습니다.
- 바로 앞 맵 이름(`srout`·`ckout`·`caf1`)을 바꿔도 머물렀습니다.
- 게임 상태 블록·일행 블록·그 밖의 고정 영역을 영역별로 덮어써도 머물렀습니다.
- `0x020B0000`~`0x02110000` 전체(다른 낱말 1,178개)를 덮어쓰면 넘어갔습니다.

1,178개를 ddmin 으로 덜어 내니(시험 247번) 일곱 낱말이 남았습니다.

```
0x020C6104~0x020C6110  주인공 레코드 +0x84~+0x90  물건 0x122·0x13E·0x150·0x159(てんくうの つるぎ·よろい·たて·かぶと), 끝 바이트 01
0x020CE810             이야기 플래그 13번째 낱말  0 → 0x9D10
0x020EB9A8             장 번호                   0 → 6
```

이 일곱 칸에서 하나씩 빼 보니 조건이 드러났습니다.

| 시험 | 결과 |
| --- | --- |
| 플래그 낱말에서 비트 하나만(420·424·426·427·428) | `fk01` 그대로 |
| 플래그 431 만 | `ckout` |
| 플래그 431 만 빼기 | `fk01` 그대로 |
| 네 물건 중 하나 빼기 | `fk01` 그대로 |
| 네 물건의 장비 바이트를 `00` 으로(가지고만 있음) | `fk01` 그대로 |
| 장 번호 4 / 5 / 6 | `fk01` / `ckout` / `ckout` |

`fk01` 은 **5장 이후, 이야기 플래그 431 이 켜져 있고, 주인공이 てんくうの つるぎ·よろい·たて·かぶと 넷을 장비하고 있으면** 곧 `ckout` 으로 넘어갑니다. 天空 장비를 모두 갖춘 뒤라 天空城이 나는 연출을 건너뛰는 분기로 보입니다.

## 틀렸던 것들

- 「한 낱말 이분 탐색으로 원인 칸을 찾을 수 있다」: `0x0210FF2C` 가 나왔지만 그 칸만 써서는 재현되지 않았습니다. 여러 칸이 함께 맞아야 하는 조건이라 ddmin(차례로 덜어 내며 최소 집합을 찾는 방법)으로 바꿨습니다.

## 남은 것

- 인물 레코드의 상태 이상 칸(`+0x5B`~`+0x5F` 를 써도 메뉴가 그대로), 주문 번호와 이름의 대응.
- ドラン 의 みのまもり·ソロ 의 うんのよさ 가 화면과 다른 이유.
