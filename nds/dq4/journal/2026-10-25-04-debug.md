# 2026-10-25-04: 디버그 메뉴·진행도 프리셋으로 장 시작 세이브스테이트 만들기

늘어난 내용(6장, 동료 대화, 이민 마을)을 게임 화면에서 확인하려면 아무 장·아무 맵에서 바로 시작할 수 있어야 합니다. 롬에 남은 개발용 기능을 찾아 부팅 디버그 메뉴, 전투 테스트, 진행도 프리셋을 되살렸고, 서장·1~6장 시작 세이브스테이트를 전원부터 만드는 도구를 만들었습니다. 결과는 [debug.md](../docs/debug.md) 에 있습니다.

## 1. 드라이버

에뮬레이터는 desmume libretro 코어입니다. 그래픽 작업에서 쓰던 [ndsplay.py](../tools/ndsplay.py)에 RAM 읽기·쓰기(`retro_get_memory_data` 가 메인 RAM 4MB 를 그대로 줌), 값 고정, 조건 대기, 길게 누르기를 더했습니다. 코어에는 중단점이 없어서 코드는 정적으로 읽고(Capstone 으로 ARM·Thumb 역어셈블), 확인은 RAM 을 쓰고 화면을 보는 식으로 했습니다.

## 2. DEBUG 폴더와 빈 오버레이

`data/data/DEBUG` 의 네 파일은 모두 Shift_JIS 문자표였습니다.

```
flagshop.dat     "  1, 0,１章スタート" … 347줄
fieldsymbol.dat  "14,MAイムルの村" …
soundlist.dat    "BGM, 1,序曲" …
action.dat       "1,メラ" …
```

이 파일 이름을 가진 문자열은 실행 파일 어디에도 없었습니다. 오버레이 38개 중 20개가 32바이트짜리 0 이라, 디버그 메뉴 코드는 그쪽에 있다가 비워진 것으로 봤습니다. 그래도 ARM9 에 `Debug Menu`, `Battle Menu Part`, `Town Part`, `SSA Viewer Part`, `Message Debug Part` 문자열이 남아 있었습니다.

## 3. 장면 관리자

`Battle Menu Part` 를 찍는 함수의 객체를 따라가니 정적 초기화에서 전역 객체로 만들어지고, `0x020084AC` 가 이런 객체 14개를 관리자 `0x02108048` 에 번호로 등록했습니다. 관리자의 다음 장면 요청 칸(`+0x6C` = `0x021080B4`)에 번호를 쓰니 그 장면으로 바로 넘어갔습니다.

- `0x11`: 위 화면에 `Battle Menu Part` 와 다섯 항목. A 로 1장 일행이 슬라임과 싸우는 전투가 시작됨.
- `0x01`: `1:Town Part / 2:SSA Viewer Part / 3:Message Debug Part` 와 빌드 날짜 `07/10/20 23:45`. 메뉴 표 `0x020B8C08` 이 고른 항목을 장면 `0x0C`·`0x08`·`0x16` 으로 보냄.
- `0x16`: バトランド城 위에 「ERROR:MID <8>」. 메시지 번호를 찍는 메시지 디버그.

메뉴에서 아래를 6프레임 누르면 커서가 끝까지 내려갔습니다. 메뉴는 누르고 있는 동안 매 프레임 움직이므로 1프레임만 눌러야 했습니다.

## 4. 맵 이름과 워프

서장 지하실에서 계단을 올라가기 전후의 RAM 을 비교하니 `0x020C4F44` 의 문자열이 `mlb1a` → `mlout1` 로 바뀌었습니다. 여기에 다른 맵 이름을 쓰고 장면 `0x0C` 를 요청하니 그 맵이 실렸습니다. 주인공 자리는 걸음마다 같은 폭으로 바뀌는 값을 찾아 `0x020EC524`(x·y·z, 한 칸 `0x1333`)로 잡았고, 써 보니 주인공과 카메라가 옮겨지고 그 자리에서 다시 걸을 수 있었습니다.

돈은 메뉴를 연 채 「0 인 칸에 값을 쓰고 돈 창이 바뀌는지」를 반씩 나눠 찾았습니다(`0x020C55F0`). 같은 방식이 메뉴를 막는 칸과 이벤트를 시작하는 칸(`0x020D2874`)도 함께 찾아 주었습니다.

## 5. 진행도 프리셋

장 번호 칸을 찾으려 서장을 실제로 진행해 봤습니다. 그런데 워프로 들어간 집에서는 어머니 대화가 멈췄고, 바깥 맵을 격자로 찍어 문 자리를 찾은 뒤 걸어 들어가도 다음 단계가 이어지지 않았습니다.

방향을 바꿔 `param_player_flag.dat` 을 읽는 코드를 찾았습니다. 레코드 수가 `flagshop.dat` 줄 수와 같은 347개였기 때문입니다. 이 파일을 여는 함수 `0x0200D9D4` 는 이야기 플래그를 모두 지우고 레코드 0~N 의 플래그를 켜는 「프리셋 N 적용」이었습니다. 이 함수를 부르는 `0x0200D774` 는 `param_player_event1`~`4.dat` 에서 프리셋 레코드를 번호로 찾아 일행을 꾸리고, 다시 `0x0200DD5C` 가 「대기 번호 `0x020B970C` 가 -1 이 아니면 적용」하고 있었습니다. 대기 번호를 쓰는 함수 `0x0200DD50` 만 부르는 곳이 없었습니다. 빠진 디버그 메뉴의 몫입니다.

```
poke 20b970c 01000000; (맵 이름 caf1); poke 21080b4 0c000000
→ 「第一章 王宮の戦士たち」「これは バトランドという 小さな国の 王宮戦士の物語。」
```

레코드 `+0x93` 에 시작 맵 이름이 있어서, 「프리셋 번호 → 시작 맵」을 롬에서 읽어 그대로 들어가게 했습니다(`ndswarp.py preset`). 1~5장 시작 프리셋(1·24·59·93·109)에서 모두 장 시작 해설이 나왔습니다. 6장은 엔딩 뒤 프리셋 311(세계수)과 331(피사로가 동료)을 씁니다.

## 6. 전원부터 만들기

출발 세이브스테이트 없이 「전원 → 장면 `0x01` → 1:Town Part」로 맵 장면에 들어간 뒤 프리셋을 적용하니, 롬만 있으면 누구나 같은 세이브스테이트를 만들 수 있었습니다(`ndswarp.py chapters`).

## 틀렸던 것들

- 「`0x020CE100` 이 맵 번호」: 지하실 `0x149`, 바깥 `0x159` 로 바뀌어 그렇게 봤지만, 다른 맵으로 워프하면 늘 `0x149` 로 돌아갔습니다. 맵 번호는 RAM 에 정수로 남지 않습니다.
- 「장면 `0x0E` 가 디버그 메뉴」: 메뉴 문자열을 쓰는 표가 `0x0E` 장면 근처에 있어 그렇게 봤지만 `0x0E` 는 필드였고, 메뉴는 `0x01` 이었습니다.
- 「`0x020D2874` 가 돈」: 돈 창을 바꾼 첫 후보였지만, 메뉴 대신 대화 이벤트가 떠서 창이 바뀐 것이었습니다.
- 「출발 세이브스테이트 없이 작업마다 부팅」: 한 코어에서 이어 돌리면 앞 작업의 장면이 남아 다음 맵이 검게 실렸습니다. 부팅 상태를 한 번 저장해 작업마다 다시 읽습니다.
