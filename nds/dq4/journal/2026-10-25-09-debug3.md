# 2026-10-25-09: 전투 테스트 Select 모드와 fk01

디버그 도구의 남은 것 두 가지를 풀었습니다. 전투 테스트에서 몬스터와 마릿수를 골라 바로 싸우는 방법을 확인해 `ndswarp.py battle` 로 만들었습니다. 맵 화면 모음에서 유일하게 실패한 `fk01` 의 원인도 찾았습니다. 결과는 [debug.md](../docs/debug.md) 에 있습니다.

## 1. 전투 테스트 Select 모드

[첫 디버그 일지](2026-10-25-04-debug.md)에서는 `Encount` 모드만 실측했습니다. `Select` 모드의 갱신 함수 `0x02008D78` 은 커서 줄(`+0x10`)마다 갈라졌습니다.

```
줄 1: 오른쪽·왼쪽 → +0x1C(무리 0~3)
줄 2: 오른쪽·왼쪽 → +0x20[무리] ±1, R 을 누른 채면 ±10, 0~0x140
줄 3: 오른쪽·왼쪽 → +0x30[무리] ±1, 0~8
줄 4·5: 무리 목록·전투 배경 목록 앞뒤
```

키 비트는 DS 패드 그대로(오른쪽 `0x10`, 왼쪽 `0x20`, R `0x100`)였습니다. 키를 하나씩 누르는 대신 1장 상태에서 장면 `0x11` 을 열고, 첫 줄에서 오른쪽을 한 번 눌러 `Select` 로 바꾼 뒤 `+0x20` 에 50, `+0x30` 에 3 을 썼습니다. 위 화면 표가 `3.MONSTER : m050`, `4.COUNT : 3`, 오른쪽 열 `m050(3)` 으로 바뀌었고, A 를 누르니 장면이 `0x0D` 로 넘어가 「とらおとこAは みのけもよだつ おたけびを あげた!」로 전투가 시작됐습니다.

이 순서를 `ndswarp.py battle OUT 50x3 1x2 --state …` 로 묶었습니다. 그래픽 트랙에서 몬스터 조립 결과를 게임 화면과 견줄 때 씁니다.

## 2. fk01

맵 544개의 화면 모음(비공개 에셋 저장소 `nds/dq4/screens/`)을 만들 때 6장(프리셋 331) 상태에서 `fk01` 로 옮기면 맵 이름이 곧 `ckout` 으로 바뀌었습니다. 맵 목록에서 그룹 `f` 는 `fk01` 하나뿐입니다.

같은 워프를 다른 상태에서 해 봤습니다.

| 출발 | 240프레임 동안 맵 이름 | 화면 |
| --- | --- | --- |
| 부팅 디버그 메뉴(진행 없음) | `fk01` 그대로 | 구름 위 天空城 |
| 5장 시작 | `fk01` 그대로 | 「どこからともなく こえが きこえる……」 |
| 6장(프리셋 331) | 곧 `ckout` | 天空城 바깥 |

맵은 실렸고, 진행도가 앞서면 그 맵의 스크립트가 바로 `ckout` 으로 넘겼습니다. 실행 파일에서 `fk01` 을 쓰는 곳은 `0x02027F98` 하나로, 목적지 번호(`0x0201CFEC` 의 값)가 `0x17` 이면 `fk01`, `0x19` 면 `dpb8b` 로 맵 이동을 요청합니다. 天空城이 하늘을 나는 연출에 들어가는 길로 보입니다.

## 틀렸던 것들

- 「`fk01` 은 맵을 싣지 못함」: 실렸고 스크립트가 다른 맵으로 넘긴 것입니다.

## 남은 것

- `fk01` 을 `ckout` 으로 넘기는 플래그.
- 몬스터 번호와 이름의 대조표. `m050` 이 とらおとこ 인 것만 확인했습니다.
