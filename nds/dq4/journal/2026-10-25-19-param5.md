# 2026-10-25-19: 이민자 수, 가게 표 자리, 맵 안 임시 플래그

[17 일지](2026-10-25-17-param4.md)의 남은 것을 마무리했습니다. 이민자 수와 단계 전환은 실측으로 확정했고, 플래그 B·C 는 맵 안 임시 플래그로 확인했습니다. 가게 레코드를 고르는 코드는 이번에도 찾지 못했습니다. 결과는 [param-format.md](../docs/param-format.md) 와 [extras.md](../docs/extras.md) 에 있습니다.

## 1. 이민자 수

nds-text2 가 `ndsscript.py ops` 로 명령마다 처리 주소를 뽑아 두었습니다. `0x102` 는 ARM9 `0x0202121C`(ARM 코드)에서 `0x02024448` 을 부르고, 이 함수는 `0x02037534` 가 돌려주는 주소 `0x020ED358` 의 u32 를 인자 둘과 견줍니다. 앞에서 처리 루틴을 못 찾은 것은 명령 표를 Thumb 함수 포인터 표로만 찾았기 때문입니다.

실측은 5장 상태에서 했습니다. 단계 k 의 플래그만 켜고 `0x020ED358` 에 a−1, a, b−1, b 를 쓴 뒤 필드로 들어갔습니다. a−1 이면 아무 플래그도 바뀌지 않았고, a 부터 다음 단계 플래그가 켜졌습니다. 단계는 이민자 1·5·9·13·17명에서 오릅니다. b 를 쓰면 그 단계 조건은 거짓이었고, 한 단계 위의 조건이 맞아 그 플래그가 켜졌습니다.

## 2. 가게 레코드

가게를 여는 명령은 nds-text2 가 찾은 `0x98`(인자는 가게 종류)입니다. 레코드 번호는 인자에 없습니다.

haout·maout 스크립트에서 `0x98` 이 든 물체의 자리(물체 머리 `+0x0C`·`+0x14`)를 읽었습니다. 주인공을 그 1.2 남쪽에 두고 말을 걸자 무기점이 열렸습니다. haout 은 first 0 의 품목, maout 은 first 1 의 품목이었습니다. 앞 일지의 품목 대조가 화면으로도 맞았습니다.

가게를 연 RAM 에서 표를 가리키는 값을 찾으니, 두 가게 표가 PARAM 파일과 같은 내용으로 ARM9 정적 자료에 들어 있었습니다(first `0x020945F8`, second `0x02099A30`). 두 표를 가리키는 곳은 둘이었습니다.

- 표 묶음 객체 `0x020C51D8` 의 `+0x84`·`+0x88`(초기화 `0x0200D0CC`)
- 게임 상태 `0x020CE3F0`·`0x020CE3F4`

레코드를 고르는 코드를 찾으려고 세 가지를 해 봤지만 닿지 못했습니다.

- `+0x84`·`+0x88` 을 읽는 ARM·Thumb 명령을 모두 훑었습니다.
- `+0x2F0`·`+0x2F4` 를 읽는 곳을 훑었습니다. 나온 것은 다른 객체였습니다.
- haout·maout 두 가게를 연 RAM 에서 0 과 1 로 갈리는 칸을 찾았습니다. 30곳이 나와 하나로 좁히지 못했습니다.

## 3. 얻는 물건 `+10`

값이 있는 847줄이 모두 종류 `00` 이었습니다. 짝 `FMAP` 모델은 문(door·wdoor)과 감옥 쇠창살뿐이었습니다. 확인 함수 `0x0201CEB4` 가 보는 배열은 게임 상태 `+0x248`(`0x020CE348`)이라, 열쇠로 연 문의 플래그로 봤습니다. `+15` 는 `+0x258` 배열입니다. `2C` 처럼 `FMAP` 에 짝이 없는 종류가 놓이는 자리는 찾지 못했습니다.

## 4. 몬스터 내성 값 1·2

15 일지와 같은 전투(マーニャ 의 メラ, スライム)에서 `+2F` bit5-4 를 1·2 로 두었습니다. 피해는 0 일 때와 같은 12 였습니다. 피해 주문에서는 3(듣지 않음)만 효과가 있었고, 1·2 의 효과는 다른 주문(상태 이상 등)으로 봐야 합니다.

## 5. 플래그 B·C

SCRIPT 전체에서 `0x17`·`0x18` 의 첫 인자(플래그 종류)가 1·2 인 명령을 모았습니다. 종류 1 이 플래그 B, 2 가 C 입니다(`0x020235A0` 이 종류 0·1·2 를 `0x020CE7DC`·`0x020CE75C`·`0x020CE6DC` 로 나눔). 같은 번호가 여러 맵에서 따로 쓰이고 켜는 맵과 보는 맵이 거의 같아, 맵 안 임시 플래그로 보였습니다.

실측: caf1 에서 두 배열의 첫 낱말을 `0x20` 으로 쓰고 haout 으로 옮기자 둘 다 0 이 되었고, caf1 로 돌아와도 0 이었습니다.

## 틀렸던 것들

- 「`0x102` 처리 루틴이 없다」: 명령 표 항목은 ARM 코드였습니다.
- 「얻는 물건 `+10` 은 뜻 모를 플래그」: 문 플래그입니다.
