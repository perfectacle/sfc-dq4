# 2026-10-26-03: 스크립트 명령 처리 함수 분류, 칸·상태 비트·깃발 종류

[2026-10-25-18 일지](2026-10-25-18-script2.md)의 남은 것을 이어 풀었습니다. 분기표 칸마다 처리 함수를 읽어 명령 347가지를 부르는 대상으로 나눴고, 이름 없던 명령 73가지에 이름을 붙였습니다(실측 30, 코드·스크립트 읽기 43). `script` 열 칸이 장 번호라는 것, 상태 비트 `0x02` 가 되풀이라는 것, 깃발 종류 1 이 맵 머리글자가 바뀔 때만 지워진다는 것을 코드와 실측으로 확인했습니다. 전투 중에는 맵 스크립트가 돌지 않습니다. 결과는 [script-format.md](../docs/script-format.md)에 있습니다.

## 1. 처리 함수를 싱글턴으로 묶기

분기표 칸은 「인자 주소를 넘겨 함수 호출」 아니면 「객체를 `0x02023290` 에 넘김」 꼴입니다. 함수 쪽은 capstone 으로 끝까지 따라가 부르는 함수와 리터럴을 모았습니다. 가장 많이 불리는 것들을 열어 보니 모두 같은 꼴이었습니다.

```
0213433C push {r3, lr}; ldr r0,=…; ldr r0,[r0]; tst r0,#1; bne …   ; 처음이면 생성자를 부르고 비트를 켬
         ldr r0,=0x0214D5D0; pop {r3, pc}                           ; 싱글턴 주소를 돌려줌
```

정적 지역 변수로 만든 싱글턴의 getter 입니다. getter 를 싱글턴 주소로 바꿔 놓으니 명령들이 갈라졌습니다: 인물 관리자 `0x0214D5D0`, 주인공 `0x0214B728`, 카메라 `0x0214CEE4`, 창 관리자 `0x0214D188`, 맵 관리자 `0x0215B428`. 일행 구조체 `0x020C533C`, 깃발 배열, 맵 비트 `0x020CE100` 처럼 리터럴로 바로 읽는 것도 같이 셌습니다.

객체 명령의 객체는 BSS 에 있는 C++ 객체라 `arm9.bin` 에는 vtable 포인터가 없습니다. 1장 상태의 RAM 덤프에서 읽으니 vtable 칸이 [0] 시작, [1] 갱신, [2] 끝, [3] 끝났나 였습니다. `0xBD`·`0xC0`·`0xC8`·`0x15D` 넷만 마을 RAM 에서 0 이었는데, 필드 오버레이 쪽 객체입니다.

## 2. 소품 명령의 번호는 FMAP 물체 번호

`0x1C`·`0x1D`·`0x1E` 의 첫 인자 `0x1F5`(501) 등은 [graphics-format.md](../docs/graphics-format.md) 의 `FMAP` 배치 `+0x2C` 와 같은 범위였습니다. 스크립트마다 같은 이름의 맵 팩 `FMAP` 에서 그 번호를 찾으니 `0x1C` 164/166, `0x1D` 214/215, `0x69` 185/185, `0xF6`·`0xFD`·`0x123` 전부가 있었습니다. 모델 이름으로 보면 `0x1C` 는 `door01`·금고(`kinko1`), `0x69`·`0x68`·`0xA2` 는 승강기(`dgel`·`teelv1a`), `0x11C` 는 보물상자(`tbox02`)·항아리, `0x2A` 는 상자·책장·게시판입니다. 世界樹の花 를 얻는 `tdf5` 의 `2A 184C` → `1C 184C 0` 은 「꽃을 조사하면 그 물체를 움직인다」로 읽힙니다.

## 3. 주입하고 RAM 전체를 비교

1장 시작 세이브스테이트에서 A 를 눌러 왕의 연설을 넘기고 조작할 수 있는 상태를 만들었습니다. 제어 오브젝트 `execute` 의 맨 위 명령을 빈 RAM 으로 돌리는 앞 회차 방법으로 306가지를 넣고, 240프레임 뒤 4MB 를 기준 실행과 비교했습니다. 명령 하나에 2초쯤 걸렸습니다. 15% 넘는 명령에서 함께 바뀐 곳은 잡음으로 뺐습니다.

```
028 | 시간대+0:6          0FA | 진행+4:1 맵이름+1:3     014 | 0x020C55F8:2
03F | 맵비트+1:1          169 | 맵비트+2:1              16D | 0x020CE1F4:12
```

이렇게 걸린 것은 값을 바꿔 다시 쟀습니다. `28 4` 는 시간대를 4 로, `FA 2`·`FA 3` 은 장 번호를 2·3 으로 하고 맵 이름을 `cbf2`·`mfm1f1`(그 장 시작 맵)로, `3F 0` 은 조우 비트 `0x200` 을 켰습니다. 앞 회차가 「맵 이름」 이라 부른 `0xFA` 는 장 바꾸기입니다.

## 4. 조건 명령은 자식 깃발로

조건 명령은 RAM 에 흔적을 남기지 않습니다. 맨 위 명령 자리에 조건을, 그 자식 자리(깊이 1)에 맵 깃발 `0x50` 쓰기를 넣어 깃발이 켜지는지로 참·거짓을 읽었습니다. 처음에는 모든 조건이 참으로 나왔습니다. 조건을 상태 1 로 넣었기 때문입니다(아래 6절). 상태 0 으로 바꾸니 `18 2 50 1` 거짓, `18 2 50 0` 참으로 갈렸습니다.

```
0A 주인공 둘레 상자 1   0A 먼 상자 0
80 3 0  1 → ライアン HP 0 으로 만들면 0      80 3 1  0 → HP 0 이면 1
71 0 1 0 3 …  1(일행 [3])   71 … 4 …  0    72 는 그 반대
41 4 0  0   41 4 1  1   41 2 0  1   ([0x020EA39C]=3)
D9 3  1 ([0x020CE210]=1, 4 − 1 = 3)
```

`0x16` 은 「인물이 일행에 있으면」 으로 짐작했지만 일행 [3] 에서 0~9 모두 거짓이었습니다. 처리 함수는 인물 표 `0x020C52D4[n]` 의 비트 `0x10000` 을 봤고, 이 비트를 켜니 참이 됐습니다.

## 5. 인물 명령은 인물 오브젝트에

인물 쪽 명령은 「지금 실행 중인 오브젝트」의 인물에게 듣습니다. `caf1` 의 병사(오브젝트 6)의 `execute` 에 넣고 아래 화면을 기준과 비교했습니다. `B1 7F` 로 병사가 ピサロ 모습이 됐고, `113 50` 으로 자세가, `58 0` 으로 사라졌습니다. 처음에는 위 화면을 잘라 비교해 아무 변화도 못 봤습니다. 마을 화면은 아래 화면입니다.

일행 명령은 일행 칸 `0x020C5614` 로 쟀습니다. `66 9` 는 일행을 [3, 9] 로, `67 3` 은 빈 일행으로, `12 83 1 0` 은 ライアン 소지품에 도구 `0x83` 을 넣었습니다. `6A 0` 은 HP 3 인 ライアン 을 27 로 채우고 HP 0 은 그대로 두며, `6A 1` 은 HP 0 도 27 로 채웠습니다.

## 6. 상태 비트 0x02 는 되풀이

`0x0205A368` 을 부르는 곳을 찾으니 콜백 표 `0x021081C0` 을 거쳐 나무 걷기 `0x02059A58` 이었습니다. 형제 목록의 마지막 명령이 끝나면 그 명령의 `0x02` 를 보고, 켜져 있으면 목록 처음으로 돌아가 형제 모두의 `0x10`·`0x40` 을 지웁니다. 파일에서 `0x02` 1,664개 중 1,662개가 형제 목록의 마지막 명령이었습니다.

형제 목록 마지막 자리에 `13 1 0`(돈 1)을 넣으니 상태 1 은 60프레임에 한 번, 상태 3 은 56번 더했습니다. 같은 걷기 코드에서 상태 1 의 조건이 늘 참이 된 까닭도 나왔습니다. 끝난(`0x40`) 명령은 처리 함수를 부르지 않고 처리 칸의 기본값 참으로 끝납니다.

## 7. script 열 칸은 장 번호

`0x07` 의 배열을 읽는 콜백(`0x02023410`)을 따라 스크립트를 싣는 곳(`0x0201EFF4`)에 닿았습니다. 마을 장면 준비가 넘기는 칸 번호는 `[0x020EB9A4 + 4]`, 곧 장 번호였고 6 이면 5 로 바뀝니다. 장 시작 세이브스테이트 8개에서 함수 문맥이 가리키는 그룹은 서장·1장 1, 2~5장 2~5, 6장 둘 다 5 였습니다. `0x07` 이 켜는 것은 지금 장 칸의 오브젝트입니다. 칸 6~9 에도 명령이 있지만 이 코드로는 실리지 않습니다.

## 8. 깃발 종류 1·2

두 배열의 리터럴을 찾으니 마을 장면 준비(`0x0212E8D0`)가 종류 2 는 늘 지우고, 종류 1 은 `0x0200B8E0` 이 0 이 아닐 때만 지웠습니다. 이 함수는 앞 맵 이름과 지금 맵 이름의 첫 두 글자를 견줍니다. 두 배열을 `0xF0F0` 으로 채우고 `0x1F` 로 옮기니 `caf2b`·`caout`·`ca1f1` 에서는 종류 1 이 남고, `cbout`·`ccout` 에서는 지워졌습니다. 종류 2 는 다섯 곳 모두 지워졌습니다. 종류 1 은 같은 성·마을의 층 사이를 오가는 동안 이어지는 깃발입니다.

## 9. 전투 안

`78 1 0` 으로 전투를 연 뒤와 `ndswarp.py battle` 의 전투 테스트에서 주입 칸을 `0x13` 으로 바꿨지만 120~180프레임 동안 실행되지 않았습니다. 전투 중 `0x0211D540` 에는 오버레이 3 이 실려 마을 쪽 처리 함수도 없습니다. 전투 안에서만 뜻이 있는 스크립트 명령은 없습니다.

## 10. 가게 인자와 en 키

`0x98` 인자를 5장 상태 `hcy1b1`(돈 50000G)에서 다시 넣었습니다. `0x10` 은행, `0x12` 약초 사고팔기, `0x17` 인질 동료 고르기, `0x1A` 모험의 서 기록, `0x1C` 무기를 사러 온 손님 등이 나왔고, `0xD`·`0xE`·`0x14`·`0x15` 는 여전히 반응이 없었습니다. 스크립트에 쓰인 인자를 세어 보니 이 넷은 어디에도 없습니다.

`0x0201D2BC` 는 `[0x020CE214]` 가 1 이면 `en` 을 키로 씁니다. unicorn 으로 두 함수에 `en` 을 넣으니 first 18, second 0 이었습니다. first 레코드 18 은 여관 10G 와 도구 4가지뿐입니다.

## 틀렸던 것들

- `0x64`·`0x66` 을 「모습 바꾸기」로 불렀습니다. 일행 칸을 읽으니 `0x66` 은 일행에 넣기, `0x64` 는 맵 인물을 숨기고 일행에 넣기입니다. 앞 회차에서 주인공 그림이 바뀐 까닭은 다시 보지 않았습니다.
- `0xFA` 를 「맵 이름」 으로 불렀습니다. 장 번호를 바꾸고 맵 이름을 그 장의 시작 맵으로 둡니다.
- `0x16` 을 「인물이 일행에 있으면」 으로 봤습니다. 인물 표 비트 `0x10000` 검사입니다.
- 조건을 상태 1 로 넣고 재서 모두 참이 나왔습니다. 끝난 명령은 참을 돌려줍니다.
- 깃발 종류를 `ndswarp.py map` 으로 옮겨 시험했더니 둘 다 지워졌습니다. 맵 이름을 직접 써서 앞 맵 이름이 바뀌지 않기 때문입니다. 스크립트 맵 이동으로 다시 쟀습니다.

## 남은 것

- 「분류」만 한 명령 173가지의 뜻. 특히 6장 연출의 인물 이동 객체(`0x2C`~`0x33`·`0x4B`·`0x4C`·`0x5B`), 카메라 객체(`0x24`·`0x29`·`0xB4`·`0xB6`), 주인공 줄(`0xA6`·`0xB0`), `0x142`.
- 인물 그림 객체 `+0xC8`·인물 객체 `+0x38` 비트가 화면에서 바꾸는 것.
- 인물 표 비트 `0x10000`, `0x020C55F8`, `0x020EA39C` 의 뜻.
- 칸 0 이 실리는 때와 칸 6~9 의 자료.
- `0x98` 인자 `0xD`·`0xE`·`0x14`·`0x15`.
- `0x020CE214` 를 1 로 쓰는 곳(가게 키 `en` 을 쓰는 장면).
