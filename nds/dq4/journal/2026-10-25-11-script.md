# 2026-10-25-11: 스크립트 명령표와 대사 표지·변수의 코드

대사·롬 구조의 남은 칸을 코드에서 찾고 에뮬레이터로 확인했습니다. 이벤트 스크립트 해석기의 분기표를 찾아 명령을 RAM 에 넣어 하나씩 돌렸고, `@cN@` 은 글자 효과음, `%a` 는 ARM9 의 변수 이름표, `@a` 는 맵 스크립트의 인물 오브젝트라는 것을 확인했습니다. 결과는 [script-format.md](../docs/script-format.md), [text-format.md](../docs/text-format.md), [rom-map.md](../docs/rom-map.md)에 있습니다.

## 1. 해석기 분기표

스크립트 명령 번호는 `0x177` 까지 있습니다. 함수 포인터가 300개 넘게 이어진 표를 찾았지만 없었습니다. 대신 ARM `b` 명령이 이어진 곳을 찾으니 `0x0201FDC4` 부터 377개가 한 덩어리였습니다.

```
0201FDB0 ldrh  r2, [r5]          ; 명령 번호
0201FDB8 rsb   r1, r4, #0x178
0201FDBC cmp   r2, r1
0201FDC0 addls pc, pc, r2, lsl #2
0201FDC4 b     #0x20225EC        ; 범위 밖
0201FDC8 b     ...               ; 명령 0
```

칸마다 「상태 비트 검사 → 인자 주소(명령 + 4)를 넘겨 함수 호출」 꼴이었습니다. `0x18` 의 함수를 읽으니 첫 인자로 배열 셋(`0x020CE7DC`·`0x020CE75C`·`0x020CE6DC`) 중 하나를 고르고 둘째 인자 번호의 비트를 셋째 인자와 비교했습니다. 깃발 검사입니다. 등록 함수를 거슬러 올라가니 해석기 본체는 `0x0205Axxx` 의 범용 코드이고, 깊이 바이트로 노드 나무(깊이·부모·첫 자식·다음 형제)를 만들어 참을 돌려준 명령의 자식만 실행했습니다.

## 2. 명령을 넣어 보기

1장 왕좌의 방에서 왕에게 말을 걸면 `06 1C 1D 1E 0 0 0 0 0`(대사 28~30)이 실행됩니다. 이 9낱말을 RAM 에서 찾아 다른 명령으로 덮어쓰고 말을 걸면, 그 명령을 원하는 때에 한 번 실행할 수 있습니다. `06 10` 으로 바꾸니 메시지 16 이 떴습니다.

명령 304가지를 스크립트에서 가장 많이 쓰인 인자로 하나씩 넣고, 20·80·200 프레임 뒤 화면과 깃발 배열·맵 이름·장면 번호·주인공 자리·돈을 비교했습니다.

```
11   10011 0 0        map caf1 → casino, scene 0C → 0F
13   10013 61A8 0     gold 150 → 25150
17   17 2 1 1         맵 깃발 1 = 1
20   10020 snf1 … 1001 1   map caf1 → snf1, 맵 깃발 6·7·8 = 0
78   10078 0 EF       scene 0C → 0D(전투)
BE   100BE 20 0 0 0   map → field, scene 0E
12E  1012E            map → surechigai, scene 13
```

화면으로는 장 제목 띠(`0xB3`), 「!」 말풍선(`0x51`), 세피아(`0xC9`), 이민 마을 메뉴(`0x12D`), 마을 이름 입력(`0x130`)이 보였습니다. 맵 깃발이 맵을 옮기면 지워지는 것도 이 실험에서 나왔습니다.

조건 명령은 왕 대사의 부모 조건 `18 2 7 1` 자리를 바꿔 시험했습니다. `0x19` 의 함수는 `0x020CE1B4` 값이 인자 1 이면 2·3 일 때, 3 이면 1·4 일 때 참이었습니다. 이 칸을 1~4 로 고정하고 `19 1`·`19 3` 을 넣은 8번이 모두 이 규칙대로 대사 가지를 골랐습니다.

`0x07` 은 배열 `0x020EA69C` 에 1 을 씁니다. 1장 낮 상태 RAM 에서 이 배열의 켜진 칸 0~11·19~27 이, 그 맵 `initialize` 의 낮 가지가 켠 번호와 같았습니다.

## 3. `@cN@` 은 글자 효과음

`DEBUG/soundlist.dat` 에 `SE,301,メッセージ（高）`·`302 （中）`·`303 （低）` 이 있었습니다. 대사 표지를 나누는 함수(`@`, `0`~`9`·`a`·`b`·`c` 를 비교하는 Thumb 코드 `0x02053D6C`)에서 `@c` 칸을 꺼내는 곳을 따라가니, 창에 글을 넘길 때 `ESC` + 숫자를 붙이고 창 쪽 `0x0204CE1C` 가 그 숫자 1·2·3 을 효과음 301·302·303 으로 바꿨습니다. 여자·아이가 1, 굵은 목소리가 3 인 것과 맞습니다.

다만 이 숫자는 「목소리 줄」(`0x02107888`)이 `9` 일 때만 쓰입니다. 명령 `0x11A` 가 이 줄을 채웁니다(ev03 에서 ロザリー 대사 앞에 1, ピサロ 앞에 2). 왕의 대사 두 곳 모두 줄이 `2222…` 였고, 줄이나 `@c` 를 바꿔도 소리 샘플은 바이트 하나까지 같았습니다. 효과음 번호까지는 코드로 확인했지만 소리로는 잡지 못했습니다.

## 4. `%a` 변수 이름표

`%a` 를 펼치는 함수(`%`·`a` 를 비교하는 `0x02052F8C`)는 `%a` 다음 다섯 숫자 중 셋째·넷째를 변수 번호로, 다섯째를 끝자리로 읽었습니다. 앞 두 자리는 읽지 않았습니다. 값을 못 찾으면 쓰는 서식 `{%s}`·`<NDEF MACRO %d>` 옆에서 (번호, 이름) 표 92칸을 찾았습니다(`0x020C0840`, `HERO`·`LEADER`·`TOWN_NAME`·`G_INN_BILL` 등).

왕의 대사 본문을 RAM 에서 `%a00090` 등으로 바꿔 띄웠습니다.

```
09[솔로]  11[라이안]  12[라이안]  05[라이안]  26[ソロタウン]  41[150]
24[{PLAY_TIME}]  86[{PARTY}]  06[{CURRENT_PC}]  99[<NDEF MACRO 99>]  09f[솔로](%a01090)
```

세 줄짜리 시험은 창이 비어 나와, 두 줄로 나눠 다시 했습니다.

## 5. `@a` 는 인물 오브젝트

메시지 명령(`0x03`~`0x06`)이 부르는 대사의 `@a` 번호를 오브젝트마다 모으니, 대사를 부르는 오브젝트 2,471개 중 2,420개가 번호 하나만 썼습니다. 오브젝트 머리 `+04` 를 세어 보니 화자 이름과도 맞았습니다(`0x0F` 兵士, `0x11` 衛兵).

## 6. 이름 표 번호

`1000000`, `1001000`, `1002000` 이 들어 있는 상수표(`0x02053928`)를 찾았습니다. 이름을 찾는 함수가 종류별 기준 번호에 게임 번호를 더해 메시지를 찾았습니다. 인물 표는 `+08` 이 1001001 이라 색인 + 1 이 게임 번호이고, 이것은 [debug.md](../docs/debug.md) 의 일행 칸 실측(3 ライアン, 4 アリーナ, 23 ドラン)과 맞습니다.

## 7. 실행 파일 문자열과 폰트에 없는 코드

`ndstext.py sjis --kanji` 로 가나 없는 문자열을 찾았습니다. 포인터가 있는 것은 14개였고 대부분 이름 입력 글자판의 `@？`·`@！` 같은 한 글자였습니다.

폰트에 없는 撒·燕 은 왕의 대사에 넣어 띄웠습니다. ※·× 와 다른 X 모양 대체 글자로 찍혔습니다. 이민 마을 메뉴(`0x12D` 주입)에서 「마을을 떠난 주민 찾기」를 골라 봤지만, 주민이 없어 撒·燕 이 든 머리 문자열까지는 가지 않았습니다. 마을 이름 입력(`0x130`)에서는 오타 「마을 일름을 결정해 주세요」가 실제 화면에 그대로 나왔습니다.

## 8. 6장 이벤트

이름을 붙인 명령으로 `srout`·`ev03`·`dpout` 을 덤프해 단계를 읽었습니다. `ev03` 은 5장 イムル 꿈과 6장 회상을 함께 담고, 오브젝트 사이에서 맵 깃발을 하나씩 넘기며 연출을 이어 갑니다. 6장 단계 깃발 `0x1A4`·`0x1AA`·`0x1AB`·`0x1AF` 는 장 시작 세이브스테이트(프리셋 310·331)의 깃발 배열에서 값을 읽어 맞췄습니다. エッグラ·チキーラ 재대결은 이야기 깃발 `0x1B1`~`0x1B7` 로 전투 인자 2~8 을 고릅니다.

## 틀렸던 것들

- `@cN@` 을 소리 샘플만 비교해 「바꿔도 아무것도 안 바뀐다」고 적었습니다. 코드로는 효과음 번호를 고르고, 그 장면은 목소리 줄이 먼저 정해져 `@c` 를 읽지 않는 경로였습니다.
- `%a` 다섯 자리를 「꼴 2자리 + 변수 3자리」로 읽었습니다. 실제로는 변수 번호가 2자리이고 마지막 1자리가 끝자리입니다(`%a00821` 은 변수 82 의 첫째 값).
- 스크립트의 깊이 바이트를 들여쓰기 정보로만 봤습니다. 실제로는 실행 나무를 만드는 데 쓰입니다.
- 분기표를 함수 포인터 표로 찾으려 했습니다. `addls pc, pc, r2, lsl #2` 뒤의 `b` 명령 줄이었습니다.

## 남은 것

- 이름 없는 스크립트 명령 250여 가지, `0x07` 칸 번호와 오브젝트의 짝, 상태 비트 `0x02`, 깃발 종류 1.
- `@cN@` 효과음이 소리로 잡히지 않는 까닭.
- 유럽어 `%a` 꼴 번호의 뜻.
- 폰트에 없는 코드가 실제 메뉴에서 찍히는 모습.
- `DEBUG/action.dat`·`fieldsymbol.dat`·`soundlist.dat` 번호가 게임 번호와 같은지.
