# 2026-10-25-14: 주문 배우는 표, ドラン 의 고정 능력치, 상태 이상 칸

[앞 일지](2026-10-25-12-debug4.md)의 인물 레코드에서 남긴 세 가지를 풀었습니다. 주문 배우는 표의 번호를 이름과 맞췄고, ドラン 의 화면 값이 어디서 오는지 찾았습니다. ソロ 의 うんのよさ 가 다르다던 것은 틀린 관찰이었습니다. 결과는 [debug.md](../docs/debug.md#인물-레코드) 에 있습니다.

## 1. 주문 배우는 표

레코드 `+0xB4` 부터 6바이트씩 읽으면 (번호, 번호, 레벨, `04`) 꼴이 됩니다. 번호를 이름 파일 `b1003000` 의 번호로 그대로 읽으면 ブライ 의 첫 주문이 ヒャダルコ 가 되어 어색했습니다. 필드 화면의 ブライ 주문 이름(リレミト·ルーラ·インパス·ラナルータ·レミラーマ)으로 이름 파일을 거꾸로 찾으니, 레코드의 번호가 늘 이름 번호보다 1 컸습니다.

```
ソロ   0x32/0xC4 Lv2 ホイミ, 0x35/0xC5 Lv5 ベホイミ, 0xCB Lv7 ルーラ, 0xCF Lv11 トヘロス, 0xCC Lv13 リレミト, 0x38/0xC6 Lv27 ベホマ, 0x3D/0xC8 Lv28 ザオラル …
ブライ 0x0D Lv1 ヒャド, 0x25 Lv3 ルカニ, 0x1C Lv5 ラリホー, 0xCC Lv7 リレミト, 0xCB Lv9 ルーラ …
```

첫 번호는 전투에서, 둘째 번호는 필드에서 쓰는 번호입니다. 회복 주문은 필드용 번호(`0xC4`~`0xC8`)가 따로 있고 그 번호의 이름은 이름 파일에 없습니다. ソロ 의 「じゅもん」 화면은 ホイミ·ベホイミ·ルーラ·トヘロス·リレミト·ベホマ·ザオラル 순서였고, 표에서 필드용 번호가 있는 것만 레벨 순으로 뽑은 것과 같았습니다.

## 2. ソロ 의 うんのよさ

ソロ 의 `+0x76` 에 100·10·89·80·75 를 차례로 쓰니 화면이 모두 그 값을 그대로 보였습니다. 쓰지 않은 지금의 6장 상태도 88 로 레코드와 같았습니다. 앞 일지에서 본 75 는 그 전에 만든 6장 상태(프리셋 311)의 화면이었습니다. 같은 인물을 서로 다른 세이브스테이트에서 견준 실수였습니다.

## 3. ドラン 의 고정 능력치

ドラン 레코드의 ちから(`+0x68`)·みのまもり(`+0x6A`)·すばやさ(`+0x6C`)·かしこさ(`+0x6D`)·うんのよさ(`+0x76`)를 하나씩 10 으로 바꿔도 「つよさ」 화면은 그대로였습니다. `+0x4F` 를 바꾸니 얼굴만 ライアン·ソロ 로 바뀌었습니다.

몬스터 표(`PARAM/param_monster_monster.dat`)에서 HP 258·195·160 이 나란한 항목(번호 204)을 찾아 RAM 사본(`0x020A0F44`)을 바꿔 봤지만 화면은 그대로였습니다. 화면 값 일곱 개를 차례로 실행 파일 전체에서 찾으니 ARM9 데이터 한 곳이 나왔습니다.

```
0208cf78: cc 00 c3 00 23 00 11 00 06 00 14 00 02 01 00 00 c3 00 a0 00
```

번호 204 뒤에 ちから 195, すばやさ 35, みのまもり 17, かしこさ 6, うんのよさ 20, HP 258, MP 0, こうげき力 195, しゅび力 160 이 화면 차례대로 있습니다. しゅび 칸을 99 로 쓰니 화면도 99 가 되었습니다. ドラン 은 성장하지 않는 동료라 능력치를 이 고정 블록에서 가져오는 것으로 봅니다. すばやさ 칸은 바꿔도 화면이 그대로여서, 블록 전체를 화면이 바로 읽는지는 확인하지 못했습니다.

## 4. 상태 이상 칸

처음에는 메뉴로 찾으려 했습니다. ソロ 레코드의 `+0x5B`~`+0x5F` 를 `0xFF` 로 써도 메뉴가 그대로였습니다. 다음에는 「독이면 걸을 때 HP 가 준다」를 신호로 삼아, ライアン 레코드의 0 인 바이트를 하나씩 `0xFF` 로, `+0x40`~`+0x80` 은 비트 하나씩 바꾸며 마을과 동굴에서 걸어 봤습니다. 모두 HP 가 그대로였습니다.

막혀서 메시지 쪽으로 갔습니다. 전투 문장 801403 이 「%a00180は　どくにおかされた！」였고, 이 번호를 상수로 쓰는 코드 `0x02017466` 바로 앞에서 `0x0201E888(대상 + 0x188, 0x16, 0)` 을 불렀습니다. `0x0201E888` 은 `대상 + 0x188 + 12 × 상태 번호` 칸을 다루는 함수였습니다.

여기서 처음 전투 실험의 출력을 다시 보니, 첫 판에서 ライアン 레코드의 `+0x290`·`+0x294`·`+0x299` 가 0 → 1·22·1 로 바뀌어 있었습니다. `0x188 + 12 × 0x16 = 0x290` 이니 그 판에서 이미 독에 걸렸던 것입니다. 그 실험은 전투 뒤에 걷지 않았고, 레코드 차이를 끝까지 보지 않아 지나쳤습니다.

동굴 상태에서 이 세 바이트만 직접 쓰고 메뉴를 여니 ライアン 의 Lv 자리에 「どく」가 떴습니다. 이렇게 독을 건 상태로 네 걸음 걸어도 HP 는 그대로였습니다. 앞의 바이트 훑기가 아무것도 못 찾은 것은 「걸으면 HP 가 준다」는 신호가 네 걸음 안에 나오지 않았기 때문입니다. 상태 번호 0~31 을 하나씩 같은 식으로 써 보니 메뉴에 이름이 뜬 것은 `0x16` 하나였습니다.

## 틀렸던 것들

- 「독이면 네 걸음 안에 HP 가 준다」: 독을 직접 써도 네 걸음에는 줄지 않았습니다. 이 신호로 한 바이트·비트 훑기는 처음부터 찾을 수 없는 실험이었습니다.

- 「ソロ 의 うんのよさ 는 레코드 88, 화면 75」: 서로 다른 세이브스테이트를 견준 것이었습니다.
- 「주문 번호 = 이름 번호」: 주문 번호 − 1 이 이름 번호입니다(물건은 − `0x101`, 인물은 − 1).

## 남은 것

- 독 말고 다른 상태 번호의 뜻(메뉴에 뜨지 않음).
- ドラン 고정 블록의 すばやさ 칸을 바꿔도 화면이 그대로인 이유.
