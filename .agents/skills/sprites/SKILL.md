# 스프라이트

이 스킬이 SPRITE-01, SPRITE-02 의 정본이다. 규격 수치의 정본은 [docs/dq4-sprite-format.md](../../../docs/dq4-sprite-format.md), 도구 사용법은 [tools/README.md](../../../tools/README.md) 다.

## 절차

1. **원작을 먼저 잰다** — 바꾸려는 자리에 DQ5 가 무엇을 그리는지 VRAM·OAM·CGRAM 덤프로 꺼내 색 번호 행렬로 본다(`tools/lua/dq4objdump.lua` → `tools/dq4spritelab.py hero`). 크기·색 수·윤곽 색·눈 위치·프레임 수를 표로 적는다. 외부 사이트의 시트는 보조 참고일 뿐 치수의 근거가 아니다.
   완료: 실측 표가 형식 문서에 있다.
2. **정면 한 장을 격자에서 그린다** — `tools/dq4sprites.py` 의 문자 행렬에 직접 그린다. 실측 규칙(폭·높이·윤곽 1색·눈 1×2·바닥 윤곽 없음) 안에서 복장만 바꾼다.
   완료: `uv run --locked python tools/dq4sprites.py` 가 색 수를 찍고 행 폭 검사를 통과한다.
3. **같은 배경·같은 배율로 견준다** — `tools/dq4spritelab.py compare <이름>` 으로 원작 인물 옆에 놓고 8배 그림을 본다. 머리·몸 비율, 눈·콧수염이 분리되는지, 발이 땅에 붙는지를 본다.
4. **MesenCE 에 띄운다** — `tools/dq4spritelab.py data <이름>` 뒤 `tools/lua/dq4sprite.lua` 로 실제 필드에서 걷게 한다. `TEST=1` 자동 보행 결과(`walk-test.txt`)와 화면을 확인하고, GUI 로 열어 사용자가 직접 보게 한다.
5. **사용자 확인 뒤에 넓힌다** — 정면이 확인되기 전에는 측면·후면·보행·다른 인물로 넓히지 않는다. 확인된 뒤 같은 규칙으로 나머지를 그리고 일지에 「채택 확인」 과 「1차 시안」 을 나눠 적는다.

## 규칙

### SPRITE-01 — 원작 실측 격자 안에서 그린다

스프라이트는 원작(SFC DQ5) 인물을 덤프해 잰 규칙 안에서 그린다. 2026-10-25 실측: 폭 14, 높이 17(모자·투구가 있으면 19까지), 투명 빼고 8~12색, 윤곽·머리카락·눈이 한 색, 눈은 1×2 픽셀을 6·9열에, 맨 아랫줄 윤곽 없음, 방향당 2프레임에 머리 고정.

- 이유: 필드에서 원작 인물과 나란히 서므로 크기·색 수·윤곽 처리가 다르면 바로 어긋나 보인다. 반려된 첫 시안은 16×24 를 꽉 채워 원작보다 7줄 컸고 15색에 윤곽이 여러 색이었다. 눈을 고치기 전에 크기와 색 수부터 어긋나 있었다.
- 생성 이미지를 축소하거나 부분 수정해 만들지 않는다. 생성 이미지는 복장·색 시안으로만 쓴다.
- 다른 팬 작업·외부 시트의 픽셀을 가져오지 않는다([ORIG-01](../analysis/SKILL.md#orig-01--남의-데이터-금지)).

### SPRITE-02 — 정면 한 장을 원작 옆에서 확인한 뒤 넓힌다

새 인물은 정면 정지 자세 한 장을 먼저 그려 원작 인물과 같은 배경·같은 배율로 견주고 MesenCE 에 띄워 사용자 확인을 받는다. 그 뒤에 측면·후면·보행·다른 인물로 넓힌다.

- 이유: 작은 격자에서는 얼굴 몇 픽셀이 인상을 정한다. 보행 시트까지 만든 뒤 반려되면 전부 버린다.
- 확인 기록은 일지에 「사용자 확인」 으로 적고, 확인 안 된 것은 「1차 시안」 으로 구분한다.

## 함정

- OAM 은 **낮은 슬롯이 위**다. 덤프를 되돌릴 때 슬롯 역순으로 겹쳐야 한다.
- `startFrame` 에서 OAM 을 바꾸고 같은 프레임의 `endFrame` 에서 찍으면 한 프레임 늦다.
- OBJ 팔레트 4~7 은 DQ5 색 연산에 들어간다. 실험에서는 팔레트 3 을 쓴다.
- `dq4sprite.lua` 는 필드 `01/00` 과 주인공 머리 타일 쌍이 확인될 때만 그린다. 마을·전투에서는 바뀌지 않는다.
