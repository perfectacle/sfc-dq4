# 트랙

이 스킬이 TRACK-01, TRACK-02 의 정본이다.

## 절차 — 세션 시작

1. **트랙을 정한다** — 사용자가 말한 일이 어느 트랙인지 [TRACK-01](#track-01--트랙과-소유-파일) 표로 정한다. 두 트랙에 걸치면 사용자에게 묻는다.
   완료: 트랙 이름(`dq5` 또는 `dq4`)을 한 단어로 말할 수 있다.
2. **남은 항목을 고른다** — [docs/todo.md](../../../docs/todo.md) 의 자기 트랙 절을 읽고, 사용자가 따로 정하지 않았으면 위에서부터 고른다. 사용자가 "묻지 말고 쭉 진행" 하라고 했으면 항목마다 묻지 않고 이어서 한다.
   완료: 이번 작업의 항목 하나와, 그 항목을 「끝났다」고 할 조건(무엇을 실측으로 확인하면 되는지)을 말할 수 있다.
3. **워크트리를 판다** — [git-workflow 절차 1](../git-workflow/SKILL.md#절차).
   완료: 새 워크트리 안에서 `rom/` 이 보인다.
4. **분석하고 문서를 쓴다** — [analysis](../analysis/SKILL.md), [journal](../journal/SKILL.md).
5. **todo 를 고친다** — 끝낸 항목은 지우고, 새로 생긴 의문은 자기 트랙 절에 더한다. 같은 PR 에 넣는다.
   완료: `git diff origin/main -- docs/todo.md` 가 자기 트랙 절 안에만 있다.

## 규칙

### TRACK-01 — 트랙과 소유 파일

| 트랙  | 하는 일                                                 | 소유 파일                                                                                     |
| ----- | ------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| `dq5` | SFC DQ5 엔진 분석: 실내 맵, 필드, 인물, 출구, 스크립트 | `docs/dq5-*.md`, `tools/dq5*.py`, `docs/journal/*-dq5-*.md`, `docs/images/dq5-*`              |
| `dq4` | FC DQ4 원작 데이터 분석: 맵, 대사, 몬스터, 이벤트       | `docs/dq4-*.md`, `tools/dq4*.py`, `docs/journal/*-dq4-*.md`, `docs/images/dq4-*`, `tools/lua/nes/` |

세션은 자기 트랙의 소유 파일만 만들고 고친다. 다른 트랙의 파일을 바꿔야 하면 고치지 않고 [docs/todo.md](../../../docs/todo.md) 의 그 트랙 절에 항목으로 남기거나 사용자에게 알린다.

- 이유: 두 세션이 동시에 PR 을 올린다. 같은 파일을 고치면 나중에 머지되는 쪽이 충돌을 풀어야 하고, 그 과정에서 상대 세션의 분석 결과가 지워질 수 있다.
- 새 트랙(예: 빌드·패치 단계의 `build`)이 필요하면 이 표와 [AGENTS.md](../../../AGENTS.md) 의 트랙 표에 한 줄을 더하는 PR 을 먼저 머지한다.

### TRACK-02 — 공유 파일

아래 파일은 여러 트랙이 함께 쓴다. 자기 트랙 몫의 줄·절만 더하거나 고치고, 다른 트랙의 줄은 손대지 않는다.

| 파일                  | 트랙 몫                                                                    |
| --------------------- | -------------------------------------------------------------------------- |
| `README.md`           | 「문서」 목록의 자기 트랙 줄, 「해킹 일지」 목록의 자기 일지 줄            |
| `docs/todo.md`        | `## dq5`·`## dq4` 절                                                       |
| `docs/references.md`  | 표의 자기 트랙 줄. 두 트랙이 함께 쓰는 자료는 「공통」 절                  |
| `tools/figures.py`    | 자기 트랙 그림을 만드는 함수와 `main` 의 그 호출 한 줄                     |
| `tools/lua/*.lua`     | 기존 프로브는 출력·환경 변수를 바꾸지 않는다. 바꿔야 하면 새 파일로        |
| `tools/listing.py`    | 기존 옵션의 출력을 바꾸지 않는다                                           |
| `pyproject.toml`·`uv.lock` | [dependencies](../dependencies/SKILL.md) 절차로만                    |

- 이유: 공유 파일도 줄 단위로 나뉘어 있으면 git 이 자동으로 합친다. 같은 줄을 둘이 고칠 때만 충돌한다.
- 다른 트랙이 쓰는 프로브의 동작을 바꾸면 그 트랙의 실험이 조용히 다른 결과를 낸다. 그래서 공유 도구는 새 파일이나 새 옵션으로 넓힌다.
