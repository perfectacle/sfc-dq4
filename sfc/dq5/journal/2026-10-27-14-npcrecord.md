# 2026-10-27-14: 인물 레코드와 등장 조건 쓰기

인물 목록을 고치는 도구는 지금까지 인라인 스크립트만 다뤘습니다(`dq5npcwrite.py`·`dq5npcrelocate.py`). 이번에는 기존 인물 엔트리의 좌표·방향·그림·대화 번호·층·이동·애니메이션 간격과 한 벌 엔트리의 낮/밤, 그리고 등장 조건 표 두 개의 기존 항목을 제자리에서 고치는 `dq5npcrecord.py`를 만들고 게임에서 확인했습니다. 입력 형식은 [쓰기 형식](../docs/dq5-build-format.md#인물-레코드등장-조건-dq5npcrecord1), 읽기 형식은 [맵 형식의 인물 절](../docs/dq5-map-format.md#인물-128000)에 있습니다.

## 1. 필드 자리를 로더 순서대로

한 벌 엔트리(`80`·`40`)는 필드 자리가 고정이지만, 두 벌 엔트리(`C0`)는 마스크에 따라 필드마다 한 바이트 또는 낮·밤 두 바이트가 됩니다. 낮 로더 `12:8161` 과 밤 로더 `12:8227` 이 `Y` 를 늘리는 순서를 그대로 옮겨, 엔트리 바이트에서 시간대마다 필드 바이트의 오프셋을 내는 함수를 만들었습니다. 같은 바이트를 낮·밤이 함께 가리키면 그 필드는 공유입니다.

`check` 는 모든 목록 639개·엔트리 2,483개에서 이 오프셋으로 읽은 값이 `dq5npc.py` 의 `parse`(로더를 옮긴 것)와 같은지 먼저 봅니다.

```
목록 639개, 인물 2483개, 대체 표 296개, 빈 맵 표 43개 검사 통과; 바뀐 레코드 0개
```

## 2. 무엇을 쓰고 무엇을 두나

쓰는 값은 인물 표 23칸 비교(낮밤 692개 덤프, 1,562슬롯)로 엔트리→인물 표 대응이 맞은 필드만 골랐습니다. X·Y 아래 7비트, X·Y bit7 의 방향, 대화 번호 12비트, 그림, 이동의 층·간격·속도, 기타의 걸음, 추가 값의 두 애니메이션 간격입니다.

나머지는 원본 비트를 그대로 둡니다. `b0` bit4-5 와 두 벌 마스크는 바꾸면 엔트리 길이가 달라지고, 기타 bit3-7 은 뜻을 다 모릅니다(bit3 은 읽는 곳이 없고, bit4-6 은 `32A0`·`33A0` 으로, bit7 은 `31C0` 을 켬). 기타 bit7 이 켜진 엔트리는 Y 를 하나 줄여 놓으므로, 입력의 `y` 는 인물 표에 들어갈 칸으로 받고 저장할 때 1 을 더합니다. 원본에는 bit7 이 켜진 채 저장 Y 가 0 인 엔트리가 없었습니다.

한 벌 엔트리는 `b0` bit7-6 만 바꾸면 낮 인물을 밤 인물로 바꿀 수 있습니다. 길이가 같기 때문입니다. 다만 한 시간대 인물 수가 늘어납니다. 인물을 놓는 슬롯 번호에 상한 검사가 없으므로(남은 것 참고), 그 목록을 쓰는 맵이 원본의 같은 시간대에 놓던 최대 수를 넘는 전환은 받지 않게 했습니다. 02/06 은 대체 목록 `10:9B57` 이 낮에 5명이라 기본 목록 낮 2명을 3명으로 늘릴 수 있었습니다.

Y 를 낮·밤이 공유하면서 기타 bit7 만 다른 두 벌 엔트리가 4개(`05:C3EF`·`05:CF8E`·`10:BBCC`·`10:CE00`) 있습니다. 같은 저장 바이트가 낮·밤에 한 칸 다른 칸으로 풀리므로, 이 엔트리에서는 bit7 이 켜진 쪽 `y` 를 하나 작게 적어야 충돌하지 않습니다. 두 벌 엔트리에서 공유 필드의 한쪽만 바꾸면 거부합니다. 입력에 없는 시간대도 원본 값으로 인코딩해 보므로, 낮 `x` 만 바꾼 공유 엔트리는 충돌로 잡힙니다.

## 3. 등장 조건 표

`12:82FB` 는 `PHK`·`PLB` 로 데이터 뱅크를 12 로 두고 16비트 `Y` 로 `$8449,Y` 를 읽습니다. `12:8357` 은 8비트 `Y` 로 `$839C,Y` 를 읽고 `INY` 넷 뒤 `BNE` 로 되돌아가므로 항목은 64개까지입니다. 두 표는 `12:839C` 부터 빈틈없이 이어지고(43×4+1 = `$AD`, `839C + AD = 8449`), 뱅크 12 끝의 빈 자리는 336바이트뿐이라 1,777바이트인 대체 표를 같은 뱅크 안에서 옮길 수 없습니다. 그래서 이번에는 기존 항목의 맵·플래그·켜짐/꺼짐·마스크와 대체 목록 포인터만 고칩니다. 원본 마스크는 모두 한 비트였으므로 한 비트만 받습니다. 포인터는 `10:8000`~`DDB1` 의 목록 시작점만 받습니다.

## 4. 재배치 도구와 함께

`dq5npcrelocate.py` 는 목록 전체를 원본 롬에서 읽어 `32:8000`·`33:8000` 으로 복사합니다. 원본 자리를 고치는 레코드 패치를 함께 빌드하면 주소가 겹치지 않아 빌더가 통과시키지만, 게임은 옮긴 사본을 읽으므로 수정이 사라집니다. 그래서 재배치 도구에 `--records` 를 더해 같은 문서를 넘기면 고친 엔트리 바이트를 사본에 넣고, 고친 대체 표 항목은 조건 4바이트와 옮긴 목록 주소 2바이트를 함께 쓰게 했습니다. 원본 그대로인 문서를 `--records` 로 넘겼을 때 패치 목록은 넘기지 않았을 때와 바이트까지 같았습니다.

## 5. 게임에서

`dq5npcrecordcheck.py` 가 원본과 변경 롬 세 벌을 만들고, 선실 세이브스테이트에서 `dq5warp.lua` 로 02/06 (24,14) 에 들어갑니다. 새 Lua 프로브 `dq5npcrecordcheck.lua` 는 인물 목록 로더가 끝나는 `12:803C` 에서 WRAM 을 저장하고, 들어간 뒤 메시지 루틴 `24:8BAF` 가 받은 번호를 모읍니다.

처음에는 선실 17/00 에서 하려 했습니다. 그런데 `dq5warp.lua` 는 배 사다리 출구를 목적지로 덮고 맵 번호가 17/00 이 아니게 되는 것으로 도착을 보므로, 17/00 으로 다시 들어가는 이동은 도착을 알아채지 못하고 시간을 넘겼습니다. 01/01 (13,8) 은 주변 인물이 모두 벽의 불(그림 `46`)이라 맞지 않았습니다. 02/06 의 기본 목록(`05:8CD4`)에는 낮 인물 둘과 밤 인물 둘이 있어 낮밤 전환까지 한 맵에서 볼 수 있었습니다.

```
day-original: 목록 058CD4 인물 2 표 불일치 0 메시지 1D1,129
day-edited: 목록 058CD4 인물 3 표 불일치 0 메시지 1D1,6C6
day-relocated: 목록 058CD4 인물 3 표 불일치 0 메시지 1D1,6C6
night-original: 목록 058CD4 인물 2 표 불일치 0 메시지 -
night-edited: 목록 058CD4 인물 1 표 불일치 0 메시지 -
condition-original: 목록 058CD4 인물 2 표 불일치 0 메시지 1D1
condition-edited: 목록 109B57 인물 5 표 불일치 0 메시지 -
7개 장면, 검사 7개 통과
```

- 밤 인물 `05:8D34`(원래 (7,32), 대화 `0DE`)를 낮으로 바꾸고 (24,12)·대화 `300` 으로 두자, 낮 목록 셋째 슬롯에 그 값으로 놓였습니다. 위를 누르고 A 를 두 번 누르자 메시지 `6C6`(대화 번호 `26D` 이상은 `T + 3C6`)이 떴습니다. 원본 롬에서는 같은 입력에 주인공이 (24,12) 까지 걸어가 「その方向には　誰もいない。」(`129`)였습니다.
- 낮 인물 `05:8D0B` 의 그림을 `29` 에서 `18` 로 바꾸자 `3220` 이 `18` 이었습니다.
- 밤에는 남은 밤 인물 `05:8D2C` 하나만 놓였고, 원본은 둘이었습니다.
- 같은 문서를 `--records` 로 재배치한 롬은 스크립트 포인터 두 칸(`3480`·`34A0`)을 빼고 인물 표가 레코드만 고친 롬의 예측과 같았고 메시지도 `6C6` 이었습니다.
- 02/06 의 `7E:21AD` bit4 대체 조건(표 80번)을 「꺼졌을 때」로 뒤집자, 그 비트가 꺼진 선실 상태에서 `10:9B57` 목록 5명이 놓였습니다. 원본은 기본 목록이었습니다.

`1D1`(「パパスさま　パパスさま！」)은 입력 없이 들어가기만 해도 잡혔습니다. 무엇이 그 번호로 메시지 루틴을 부르는지는 보지 않았습니다.

## 남은 것

- 인물 수·순서 바꾸기와 새 목록 추가. 목록 자체는 `dq5npcrelocate.py` 의 재배치로 늘릴 수 있지만, 인물을 놓는 `$81`(`12:8030` 이 받고 `1E:DD19` 가 하나씩 늘림)에는 상한 검사가 없고, 인물을 놓은 뒤 `00:E1BA`~`E1C9` 가 `1F:D4A7`(VRAM 전송 뒤 `03:F195`)과 `16:F607` 을 부르고 그때마다 `$81` 을 `7E:1982`·`1983` 에 남깁니다. 그 사이 `$81` 을 늘려 다른 물체를 이어 놓는지, 맵마다 몇 개인지, 인물 표 32칸 가운데 마지막으로 쓸 수 있는 슬롯이 어디인지는 확인하지 않았습니다. 원본에서 한 시간대에 가장 많이 놓는 목록은 23명(19/02 낮·밤, 03/05 낮)입니다.
- 대체 표·빈 맵 표 항목 늘리기. 대체 표는 뱅크 12 안의 16비트 주소로만 읽혀(`$8449,Y`), 뱅크 12 빈 자리 336바이트로는 옮길 수 없습니다. `12:82FB` 를 긴 주소로 읽게 고치는 코드 수정이 필요합니다.
- 기타 bit4-7 의 뜻, `1D1` 을 부르는 곳.
