# 2026-10-25-24: 조우의 남은 것 3

[2026-10-25-17](2026-10-25-17-encounter3.md) 에서 남긴 것을 이어서 풀었습니다. 몬스터 칸 비트 `2A`, にげる 의 실패 갈래와 성공 확률, 맵 항목 `+4`(`$194D`)의 나머지 비트, 낮밤을 바꾼 뒤 맵을 다시 부르는 경로입니다. 결과는 [dq5-data-format.md 「전투 조우」](../../dq5-data-format.md#전투-조우-23e7c2) 와 「이벤트 전투 무리」 표에 있습니다.

## 1. 몬스터 칸 비트 `2A` 는 마비

기습을 막는 검사(`26:835B`)가 보는 비트 `2A` 는 전투 중 몬스터 칸 `+A` bit5 입니다. 이 비트를 켜는 곳(`BRK 88 7A`, `$43` = `2A`)이 `20:D15F` 에 있었지만, 어느 행동에서 오는지는 표로 따라가기 어려웠습니다.
그래서 몬스터에게 그 행동을 자기 편에 쓰게 했습니다. 행동 속성 `26:8765[행동]` 의 bit7(적 쪽)을 끄고, スライム 의 행동 6개를 모두 그 행동으로 바꿔 몬스터 칸 `7E:07CA`·`07CB` 에 쓰는 값을 보았습니다. 행동 `10`~`AA` 를 모두 돌렸습니다.

```
78 まひこうげき   07CA ← E0   (+A bit5)
97 やけつくいき   07CA ← E0
77 どくこうげき   07CA ← D0   (+A bit4)
96 どくのいき     07CA ← D0
59 アストロン     07CA ← C4   (+A bit2)
A1 なめまわし     07CA ← C1   (+A bit0)
1A マヌーサ       07CB ← 08   (+B bit3)
1B メダパニ       07CB ← 20   (+B bit5)
```

`97` 에서는 `20:D0C9` → `20:D145` → `20:D15F` 가 차례로 불렸습니다. `2A` 는 마비이고, 기습은 잠들지도 마비되지도 않은 몬스터가 있어야 남습니다.

## 2. にげる

`20:966E` 는 다른 조건을 더 보는 갈래가 아니었습니다. 실패 메시지를 띄우고 `$1000` 의 아래 두 비트를 기습(1)으로 바꿔 몬스터가 먼저 움직이게 하는 실패 처리입니다.
그 앞을 다시 읽으니 `20:961E` 에 `BIT $1015 / BVS 20:966E` 가 있었습니다. 무리 플래그 bit6 이 켜져 있으면 난수 없이 실패합니다. 무리 `3E` 의 플래그를 덮어 확인했습니다.

```
플래그 00   20961E 209621 20962C 20966E    ← 난수 판정에서 실패
플래그 40   20961E 209621 20966E           ← 바로 실패
플래그 80   20961E 209621 20962C 20965F    ← 난수 판정에서 성공
```

`dq5warp.lua` 의 `BATTLE` 이 쓰는 무리 1번은 플래그가 `D0` 이라, 처음에는 그 전투에서 にげる 를 아무리 눌러도 실패만 나왔습니다.

난수 쪽은 시도 횟수(`$1016`, 3 에서 멈춤)로 `27:8008` = `02 02 04 08` 에서 n 을 고르고, 난수(0~n-1)가 0 이면 실패입니다. 시도마다 1/2, 1/2, 3/4, 7/8 이고 민첩은 읽지 않습니다.
조우 계수를 `FF` 로 덮어 걷자마자 무작위 전투가 붙게 하고, 걷기 전에 기다리는 프레임을 바꿔 가며 32번 싸웠습니다.

| 주인공 레벨(구역 레벨 9) | 첫 시도 | 둘째 | 셋째 |
| --- | --- | --- | --- |
| 1 | 18/30 | 4/12 | 4/8 |
| 13 | 같음 | 같음 | 같음 |
| 14 | 13/13 바로 성공 | | |

레벨 1 과 13 은 기다린 프레임이 같으면 난수도 같아 결과가 같았습니다. 레벨 차이가 5 보다 작으면 레벨은 확률에 들어가지 않습니다.

## 3. 맵 항목 `+4` 의 나머지 비트

`1F:F8F2`(bit1)를 부르는 곳은 `11:809C` 하나였습니다. `11:8056`(ルーラ)과 `11:82B6`(リレミト)이 같은 루틴을 쓰고, リレミト 가 `$0F18` bit7 을 켜면 `1F:F8F2`, 아니면 `1F:F8D3` 으로 갈립니다.
주인공의 배운 주문 비트(`+23` = `FF`)를 켜고 21/02 에서 외웠습니다.

| 주문 | `+4` | 결과 값 | 화면 |
| --- | --- | --- | --- |
| ルーラ | `01` | 1 | 「天井に頭を ぶつけた！」 |
| ルーラ | `08` | 2 | 「しかし 不思議な力によって かき消された！」 |
| ルーラ | `00` | 0 | 날아감 |
| リレミト | `01`·`04` | 0 | 밖으로 나감 |
| リレミト | `03` | 1 | 「しかし 何も おこらなかった。」 |

bit2 를 읽는 `1F:F906` 은 부르는 곳을 찾지 못했고, 롬의 맵 항목 `+4` 값에도 bit2 가 켜진 것이 없습니다. 실제로 쓰는 것은 bit0(천장)·bit1(リレミト 막음)·bit3(마력이 지워짐)뿐입니다.

## 4. 낮밤을 바꾼 뒤

낮밤을 바꾸면 `06:D905` 가 화면을 닫았다 엽니다. 실내면 `2A:F363` 을 부르는데, 이 루틴은 맵 그룹 표 `0F:EA97 + BC*5` 의 `[BD][X][Y]`, 곧 그 그룹에 들어갈 때 서는 곳으로 옮깁니다. 필드면 `01:A04B` 로 필드만 다시 그립니다.
[2026-10-25-17](2026-10-25-17-encounter3.md) 에서 21/02 의 `+4` 를 `00` 으로 바꾸고 やみのランプ 를 썼을 때 숲이 나온 까닭이 이것입니다. 그룹 `21` 의 들어가는 곳이 21/00 (0,82) 였습니다.

같은 `+4` = `02` 인 01/04 에서 やみのランプ 를 쓰자 「何も おこらなかった」였습니다. `1F:F921` 이 그룹마다 이야기 플래그를 따로 보기 때문입니다(코드 읽기).
