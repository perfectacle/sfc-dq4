## 1. 그림자 기록과 지우기

`22:B08A` 가 그림자를 칠할 때 쓰는 `$62` 는 `22:B215[칸]` 이고, 이 표는 `0001 0002 0004 … 8000` 입니다. 칠한 타일마다 `7E:8000 + 타일*2` 에 이 비트를 OR 하고, 칠한 타일 번호의 최소·최대를 `0CE8`·`0CF9` 에 남깁니다.

```
スライム 3 + マッドプラント 1: 0CE8 = 170 172 174 177, 0CF9 = 203 205 207 213
7E:8000: 170·171 → 1, 172·173 → 2, 174·175 → 4, 177~181 → 8, 202·203 → 1, …
```

쓰러질 때 지우는지 보려고 スライム 3마리 전투에서 공격을 거듭했습니다. 가운데 スライム(칸 1, `0C60+1` bit6 이 꺼짐)이 쓰러진 뒤 `7E:8000` 의 값 종류가 `1 2 3 4 6` 에서 `1 4` 로 줄었고, 배경 아래 띠 타일의 비트평면 3 비트가 168 → 112 로 줄었습니다. 이웃 スライム 과 겹친 타일의 그림자는 남았습니다.
`0CE8` 을 읽는 `22:B347` 은 그 범위를 원래대로 돌리고 남은 그림자를 다시 칠하고, `22:B38C` 는 `7E:8000` 에서 칸 비트를 지웁니다(코드 읽기).

## 2. E9 를 그리는 때

이벤트 무리를 `E7` 1마리로 덮고(`RP=11D764=D0E7FFFFFF0100000000000000`), `E7` 의 HP(`7E:07C2`)를 1, 주인공 HP(`7E:204E`)를 999 로 고정해 싸웠습니다.

```sh
mkdir -p work/p/e7rw
RP=11D764=D0E7FFFFFF0100000000000000 battle tools/lua/rwatch.lua SHOT_DIR=$PWD/work/p/e7rw AFTER=6000 MAXF=1700 \
  WAYPOINTS="3,11;3,24;7,24;7,22;37,66;37,72;down:90;wait:300;a:6;wait:40;a:6;wait:40;a:6;wait:40;a:6;wait:300;a:6;wait:100;a:6;wait:100;a:6" \
  POKE="7E07C2=01;7E07C3=00;7E204E=E7;7E204F=03" WATCH=7E584C-7E5877,7E5800-7E584B FROM=880
```

`E7` 은 1600프레임쯤 쓰러졌지만, 그동안 OAM 을 만드는 `22:A277` 은 조각 목록의 앞 19개(`E7`+`E8`)만 읽었고 `E9` 의 항목 `7E:584C`~`5877` 은 그림을 풀 때(`22:9DEB` 등)만 읽혔습니다. 1551프레임부터는 이 버퍼를 다른 용도(`00:8ECB`)로 씁니다.
`dq5warp.lua` 의 `GROUP=2B` 로 실제 이벤트 무리를 붙여도 무리 구성은 같았습니다. `E9` 가 나오는 장면은 찾지 못했습니다.

## 3. 같은 머리 번호

전투 시작 때 실행 기록에서 `$0D1A`(그림 번호)를 쓰는 곳은 `22:9014`(머리 포인터 표 고르기)와 `22:9201`(이미 올린 그림인지 비교)뿐이었고, `22:90D6` 이 풀기 직전에 `$0D1A` 를 올린 자리 번호로 바꿉니다. 번호를 나눈 효과는 타일을 따로 올리는 것뿐이라는 결론을 코드로 내리고 남은 일에서 뺐습니다.

## 4. 걸을 수 없는 지형

지형 0·5·8·D 의 칸 중 이웃이 땅인 곳을 골라, 땅 쪽 두 블록 떨어진 곳에 서서 그 칸 쪽으로 다섯 걸음 걸었습니다.

```
u4 … (435, 102, 7, 7), (436, 102, 5, 5), (437, 102, 5, 5), (438, 102, 7, 7) …   # (x, y, $1AA0, 예상)
u0 (276, 82, 2, 2), (276, 83, 2, 2)                                                # 지형 0 앞에서 멈춤
```

지형 5 는 지나가며 `$1AA0` = 5 가 되었습니다. 0·8 은 경계에서 멈췄고, D(9칸)는 둘레가 0·3·9 라 다가갈 수 없었습니다.
`POKE="7F3CB2=01"`(필드 (354,120) 오른쪽 블록을 지형 8 의 블록 `001` 로)처럼 주인공 옆 칸을 0·8·D 의 블록으로 바꾸고 걸어도, 세 가지 모두 그 칸으로 가지 못했습니다.

## 5. 세계 1·2 의 지형

`03:CB1B` 는 `$1949` 를 보지 않습니다. `POKE="7E1949=01"`(또는 `02`)로 고정하고 세계마다 다섯 곳에서 오른쪽으로 걸었습니다.

```
w0 (1, 39, 12, 6, 6, True), … (1, 42, 12, 7, 7, True), … (1, 50, 12, 6, 6, True)   # (세계, x, y, $1AA0, 예상, 지도 같음)
w9 (2, 49, 52, 2, 2, True), … (2, 52, 52, 7, 7, True), … (2, 56, 52, 4, 4, True)
```

열 곳 모두 WRAM 의 세계 지도가 `dq5field.py --world` 의 지도와 같았고, 걸음마다 `$1AA0` 이 같은 `03:CC48` 표로 찾은 지형과 같았습니다.

## 6. 물결 색 HDMA

`$0DF2` = 3 인 25번 배경(`$1AA0` = `97`)의 채널 3 은 모드 `43`(레지스터 둘에 두 번씩) → `$2121`, 간접 뱅크 `27` 이었습니다. 간접 표 `7E:0DB9` 가 가리키는 `27:FF9E` 를 보니 `31 31 00 04 39 39 00 04 31 31 00 08 …` 로, 줄마다 CGRAM 주소 `31`·`39`(팔레트 3 의 1번·9번 색)에 `0000`~`1800` 의 파란색을 쓰는 항목이었습니다. 950→1000프레임 사이 간접 주소가 `FFD2` → `FFAA` 로 옮겨 가 무늬가 흐르고, 채널 4 는 BG1 가로 스크롤을 `0042` → `0074` 로 움직였습니다.

## 틀렸던 것들

- 처음 지형 실측은 땅에서 두 블록 떨어진 곳에서 두 걸음만 걸어, 목표 칸에 닿기 전에 끝났습니다. 한 걸음은 좌표 1(블록 반)입니다.
- 지형 3 위에 바로 세운 시험은 대부분 움직이지 못했습니다. 장면 이동은 걸을 수 없는 칸에도 주인공을 세우기 때문에, 출발 칸은 걸을 수 있는 지형(2·6·7)으로 골라야 했습니다.
