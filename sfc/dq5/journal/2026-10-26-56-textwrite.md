# 2026-10-26-56: 보행 대사 3,200개 일괄 쓰기

보행 메시지의 코드 목록을 편집해 허프만 트리와 함께 다시 넣는 `dq5textwrite.py`를 만들었습니다. 원래 글꼴과 메시지 번호를 유지하며, 적지 않은 메시지는 그대로 둡니다. 입력과 배치는 [쓰기 형식](../docs/dq5-build-format.md#보행-대사-일괄-쓰기-dq5text1)에 있습니다.

## 1. 글꼴 실험에서 메시지 쓰기를 분리하기

기존 `dq5hangul.py retree`는 한글 시제품을 위해 새 글꼴을 더하고 메시지 `129`를 샘플로 바꾸었습니다. 메시지 편집용 도구에는 그 부수 효과가 없어야 하므로 트리 생성·비트스트림 인코딩을 재사용하되, 원래 글꼴 표와 그림은 건드리지 않게 했습니다. `retree`의 기존 동작은 그대로 유지합니다.

입력은 `messages` 안의 `{id, codes}` 목록입니다. 일부 항목만 적으면 그 메시지만 바꾼 뒤 전체를 다시 압축합니다. 빈 목록이면 원본 전체를 다시 만듭니다. 글자 코드는 `000`~`3DA`, 제어 코드는 `1000`~`101D`·`1100`~`1118`입니다. 끝 코드 `1001`·`1010`·`1018`은 마지막에 한 번만 둡니다. 변수 인자를 준비하는 호출 코드는 그대로 두므로, 새 메시지의 변수 요구도 그 호출에 맞아야 합니다.

## 2. 디코더와 색인도 함께 옮기기

기본 배치는 `38:8000`입니다. 디코더 사본·마스크·트리는 한 뱅크 안에 놓고, 메시지 비트스트림은 LoROM 뱅크 경계를 넘으며 이어 씁니다. 색인에는 뱅크 `20`을 뺀 주소와 시작 비트를 적고 보행 호출의 색인 훅에서 다시 OR합니다. 자료는 지원 범위 `30`~`3F` 안에 모두 들어가야 합니다.

원본의 보행 디코더 호출과 색인 호출만 바꾸고, 전투 디코더·창·이름·글꼴은 유지합니다. 필드 지도 기본 `34:8000`과 분리하려고 기본값을 `38:8000`으로 골랐지만, 입력 크기와 다른 도구의 배치를 바꾸면 빌더에서 겹침을 다시 확인해야 합니다.

## 3. 다시 풀어 비교하기

```text
원본 메시지 3,200개, 코드 163,649개: 왕복 일치
메시지 두 개 수정: 두 개 일치, 나머지 3,198개 보존
합성 검사 7개: 통과
```

새 롬의 디코더 피연산자에서 트리 주소와 뿌리를 읽고 새 색인을 따라 전체 메시지를 풀었습니다. 원본은 기존 `dq5text.message`로 읽은 코드와도 전부 비교했습니다. 수정 롬의 원래 영역은 패치에 적은 네 영역과 빌더가 고치는 머리 밖에서 바뀐 바이트가 없었습니다. 기존 `retree`도 원래 메시지 3,199개와 한글 샘플 `129`가 종전대로 나왔습니다.

## 4. 게임 디코더로 앞·뒤 메시지 읽기

선실의 파파스에게 말 걸어 메시지 `129`를 띄웠습니다. 원본 스트림 `07:F1B5`, 원문을 재압축한 2MB 롬의 `38:A9FE`, 같은 메시지를 바꾼 4MB 롬의 `38:A9FE`에서 실제 디코더 반환을 기록했습니다. 각 실행에서 읽은 64개 코드는 해당 메시지부터 이어지는 예상 코드와 모두 같았습니다.

뒤쪽 메시지 `C70`도 바꾸어 불렀습니다. 시작 주소는 `3C:B1BE`로 첫 배치 뱅크와 달랐고, 여기서도 64개 코드가 일치했습니다. 화면에는 바꾼 글자 `あいうえお`가 나왔습니다.

`MESENCE`를 설정한 뒤 다음 명령으로 게임 검사 4건을 재현합니다. 실행마다 새 출력 폴더에 `results.json`과 디코더 기록·화면을 남깁니다.

```sh
uv run --locked python sfc/dq5/tools/dq5textcheck.py rom/dq5.sfc \
  --state work/state/ship.mss --out work/textcheck
```

## 남은 것

이 도구는 코드 목록을 받습니다. 문자열 번역 편집과 새 한글 글꼴 대량 삽입은 아직이며, 전투 메시지·창·이름 표는 별도입니다. 이름·숫자 같은 변수와 문맥이 필요한 제어 코드는 메시지를 부르는 게임 코드의 대기열 준비에 맞추어 써야 합니다.
