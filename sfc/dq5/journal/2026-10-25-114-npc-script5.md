# 2026-10-25-114: 인물 그림 고르기와 문 명령 넷째 바이트

[첫 장면 재현과 남은 스크립트 명령](2026-10-25-95-npc-script4.md)에서 남긴 셋을 닫았습니다. 인물 그림을 고르는 코드를 읽고 값마다 OAM 타일 번호로 확인했고,
문 명령의 넷째 바이트는 데이터에 나오는 값과 읽는 곳을 모두 따라갔습니다. 결과는 [dq5-map-format.md 「인물 표」·「인라인 스크립트」](../docs/dq5-map-format.md#인물-표-1edb44)에 있습니다.

## 1. 그림을 그리는 세 갈래

인물 표를 읽는 곳을 찾다 `00:EC82` 에서 `32A0` 의 bit6-7 로 그리는 루틴을 고르는 갈래를 만났습니다.

```
00:EC82  LDA $32A0,Y / AND #$C0
         00 → JMP $F071,  40 → JMP $F7AA,  80 → JMP $FBEB
```

파파스(`32A0` = `61`)가 타는 `00:F7AA` 는 그림 한 장 안에서 위쪽은 `3260`, 아래쪽은 `3240` 으로 자세를 고르고, 둘 다 `00:EE8C` 표를 거칩니다.

```
3260(또는 3240) bit7 이 켜졌으면 그 아래 니블, 아니면 31E0 위 니블, 그것도 0 이면 3240 아래 니블
00:EE8C = 00 04 0C 0C 08 04 0C 08 00 04 0C 00 00 00 00 00
```

## 2. 자세 n 과 네 그림

`23 n` 으로 고정한 자세는 `00:EE8C[n]` 으로 그림을 고르니, 0·8·B 는 `00`, 1·5·9 는 `04`, 4·7 은 `08`, 2·3·6·A 는 `0C` 입니다.
앞 일지에서 애니메이션을 끄고 찍은 그림의 묶음과 같습니다. 방향 `31E0` 의 위 니블 8·1·4·2 도 같은 표를 지나 위·오른쪽·아래·왼쪽이 됩니다.

애니메이션을 끄고(`1A`) `23 n` 을 준 파파스의 OAM 을 `tools/lua/hookdiff.lua` 로 덤프했습니다. 파파스 자리 (88~103, 119~135) 의 타일 번호입니다.

| n | 윗부분 | 아랫부분 |
| --- | --- | --- |
| 0(`00`, 위) | `90 91 92 93` | `9E 9F A0 A1` |
| 1(`04`, 오른쪽) | `94 95 96 97` | `A6 A7 A8 A9` |
| 4(`08`, 아래) | `98 99 9A 9A`(오른쪽은 뒤집음) | `AE AF B0 B1` |
| 2(`0C`, 왼쪽) | `9B 9C 97 9D`(하나는 뒤집음) | `B6 B7 B8 B9` |

표 값이 4씩 늘 때 윗부분은 타일 4개, 아랫부분은 8개씩 뒤로 갑니다.

## 3. `32A0` 아래 니블은 애니메이션 장 수

`00:EDD0` 은 걷기(`32C0`)·서기(`32E0`) 간격이 찰 때마다 `3280` 을 1씩 올리고, `32A0` 아래 니블과 같으면 0 으로 되돌립니다. 그림을 올릴 때 이 니블은 늘 `01` 입니다.
서 있는 파파스의 OAM 을 10프레임마다 찍었습니다.

```
32A0=61: f460 3280=00 아래 B6 B7 B8 B9 | f470 01 BA BB BC BD | f480 01 BA… | f490 00 B6…
32A0=60: 네 번 모두 3280=00, B6 B7 B8 B9
```

`01` 이면 아랫부분 두 장(B6~ 와 BA~)을 번갈아 쓰고, bit0 을 끄면 0번만 남습니다. 앞 일지에서 「걷는 동안 다리 그림만 달라짐」이라 적은 것이 이것입니다.

## 4. `33A0` bit1-3

- bit3: `00:E8AE` 가 bit3 이 켜진 인물을 건너뜁니다. 주인공 바로 왼쪽에 세운 파파스에게 말을 거니, 그대로면 「父さんは　ここにいるから」, `44` 로 bit3 을 켜면 「その方向には　誰もいない。」 였습니다.
  그림이 `46`~`48`·`78`·`7F`·`84`·`A2` 이상인 인물에게 `1E:DC67` 이 `09` 를 주는 것은 말을 걸 수 없고 지나갈 수 있는 물건으로 만드는 것입니다.
- bit2·bit1: `00:EADB` 가 bit2 가 켜지면 층 마스크 대신 bit1 로 앞뒤를 정합니다. 탁자 (6,8) 위에 세운 파파스를 `POKE` 로 `33A0` = `30`·`34`·`36` 으로 두니,
  `34` 일 때만 탁자 위 그릇보다 앞에 그려졌고(24픽셀 차이), `30`·`36` 은 그릇이 파파스 아랫부분을 덮었습니다. 바닥 (5,13) 과 침대 옆 (11,10) 에서는 셋이 같았습니다.

## 5. 문 명령의 넷째 바이트

데이터의 문 명령 33개 중 넷째 바이트가 `01` 이 아닌 것은 21/00 의 `41 39 22 02` 와 2B/00 의 `43 10 0D 28` 둘입니다.

- 21/00: 이 인물(`05:C4B3`)은 이동 간격이 0 이라 맵에 들어가도 스크립트가 돌지 않았습니다. 엔트리 이동 바이트를 `45`(간격 1)로 덮자 걸어가 문을 열었고,
  넷째 바이트를 `01`·`02`·`04` 로 바꿔도 문 셀 `+1` 은 모두 `32` 가 되었습니다.
- 23/00: 문 셀(`+7` = `C5`)이 Y < `20` 인 (41,21) 에 있어 `01:DAEF` 의 조건에 맞는 자리입니다. 인물 스크립트를 `2B 28 17 41 28 13 n` 으로 덮어 (40,19) 를 열게 하니, n = `00`·`01`·`02`·`28` 모두 같은 셀이 바뀌어 문이 열렸습니다.

실행 감시로 보면 세 맵 모두 `01:D915` 만 돌고, n 을 읽는 `01:DAEF`·`01:ED05` 는 한 번도 돌지 않았습니다. `01:DAEF` 는 문 칸 속성(`BB`·`BC`·`BD`·`BE`·`C3`·`C5`·`C6`·`CD`)을 보는 `01:DA96` 에서만 불리고,
그 경로는 주인공의 とびら 명령(`01:D92E`) 쪽입니다(코드 읽기). 인물 스크립트의 넷째 바이트가 결과를 바꾸는 맵은 데이터에 없습니다.

## 틀렸던 것들

- 23/00 의 문을 정적 맵 데이터에서 찾았지만 문 속성 칸이 없었습니다. 닫힌 문은 게임이 맵을 푼 뒤에 덮어 쓰므로, 맵에 들어간 뒤 WRAM 을 덤프해 찾았습니다.
- 처음 문 명령의 목표를 문 속성 칸 바로 옆으로 줬다가 열리지 않았습니다. 01/05 처럼 속성 칸에서 (-1,-2) 인 칸을 줘야 열렸습니다.

## 남은 것

- 주인공의 とびら 명령으로 23/00·18/00 문을 열 때 `7E:1E8E` 가 하는 일(`01:DAEF`)과 `01:ED05` 가 쓰이는 문 — 해결됨: n 은 문을 연 뒤 칸의 층, `C4` 문에서 `01:ED05`([dq5-map-format.md](../docs/dq5-map-format.md) 「인라인 스크립트」 의 `41`·`43`)
