# 2026-10-25-162: 긴 시퀀스·새 샘플 넣기와 남은 명령

[시퀀스 인코더와 곡 바꿔 넣기](2026-10-25-150-sound6.md) 에서 남긴 두 한계를 풀었습니다. 하나는 원래보다 긴 시퀀스이고, 다른 하나는 새 악기입니다. 둘 다 실제 롬에서 울려 DSP 기록으로 확인했습니다. 남은 명령 `E2`·`E7`·`E8`·`FB` 는 만든 시퀀스로 직접 울려 뜻을 정했고, `$0F1B` bit6 장면도 걸었습니다. 결과는 [dq5-sound-format.md](../docs/dq5-sound-format.md) 「긴 시퀀스와 새 샘플」「악기 만들기」에 있습니다. 소리 자료와 만든 롬은 커밋하지 않았습니다.

## 1. 포인터 표 고리

시퀀스와 샘플은 `[길이 2]` 를 따라 n 번 건너뛰어 찾습니다(`2B:C3AB`). 이 루틴의 첫 5바이트(`48 DA 29 FF 00`)를 `JSL 70:8010 / RTS` 로 바꿨습니다. 고리는 `$FB`·`$FD` 가 시퀀스 묶음의 시작(`2E:E2E4`)이나 샘플 묶음의 시작(`2B:EB00`)이면 표에서 포인터를 찾고, 없으면 원래 루틴을 그대로 옮겨 놓은 걷기를 합니다. 짧은 분기는 `dq5song.py` 안의 작은 어셈블러로 채웠습니다. 처음에 손으로 센 오프셋 넷이 모두 두 바이트씩 모자라서였습니다.

```
70:8038  a3 05        LDA $05,S      ; 들어온 번호
70:803D  48           PHA
70:803E  0a           ASL A
70:8040  63 01        ADC $01,S      ; x 3
70:8044  98           TYA            ; 시퀀스 표 0, 샘플 표 +200
70:8046  63 01        ADC $01,S
70:8048  aa           TAX
70:804A  bf 00 81 70  LDA $708100,X
70:804E  f0 10        BEQ walk
```

곡 `03` 자리에 2101바이트짜리 음계(원래 1703바이트)를 넣고 롬을 4MB 로 만들어 융단을 폈습니다. SPC 시퀀스 칸에 길이 `0835` 가 올랐고, 두 트랙이 음표 40·20개까지 시각 차 1.2프레임 이하, 음 틀림 0 이었습니다.

## 2. BRR 인코더와 새 악기

[dq5brrenc.py](../tools/dq5brrenc.py) 를 새로 썼습니다. 블록마다 필터 4개 x 범위 13개를 모두 시험하는 단순한 방식입니다. 롬 샘플 0x26개를 풀었다 다시 싸면 SNR 25.6~108.9 dB 였습니다.

32샘플 주기 사각파 4주기를 BRR 72바이트로 싸서 샘플 `26` 으로 더했습니다. 곡 `03` 의 곡 묶음 레코드 첫 샘플을 `00` → `26` 으로 바꿔 `instrument 00` 이 그 샘플을 고르게 했습니다. 첫 시험에서는 SPC RAM 에 사각파가 바이트까지 같게 올라갔는데도 SRCN 이 `00` 이었습니다. `F0` 은 SPC `28EC` 의 곡 묶음 표를 보는데, 그 표는 전원을 켤 때 드라이버 이미지와 함께 올라가므로 세이브스테이트에는 원래 값이 남아 있었습니다. 고친 롬을 켜서 읽은 SPC `28FA` 는 `26` 이었습니다. 시험에서는 세이브스테이트를 불러온 뒤 SPC `28FA` 를 Lua 로 `26` 으로 써 넣었고, SRCN 이 `06`(샘플 `26` 이 든 칸)으로 쓰이며 음표가 모두 맞았습니다.

기존 샘플 중 FC 소리에 가까운 것도 찾았습니다. 반복 부분 전체를 한 창으로 DFT 해 배음을 보니 고정 샘플 `1F`(반복 32샘플)가 홀수 배음만 0.37·0.27·0.17 인 사각파였습니다. 삼각파에 가까운 것은 `09`·`05`, 사인에 가까운 것은 `17`·`18` 이었습니다.

## 3. 남은 명령을 직접 울리기

`FB` 를 쓰는 곡 `0A`(맵 03/02)를 기록했지만, 그 트랙은 `E2` 도 켜 있어 둘이 섞였습니다. 그래서 곡 `03` 자리에 명령 하나씩만 쓰는 40바이트짜리 시퀀스를 넣었습니다.

```
  note 31 len 30
  pitch_slide 0C 18
  tie len 30
  rest len 30
  note 31 len 10
  pan_slide 40 30
  tie len 40
  rest len 30
  fade 40
  note 31 len 40
```

- `FB 0C 18`: 피치가 0x18틱(992~1006 프레임) 동안 고르게 올라 12반음 위에서 멈췄습니다. 비브라토가 아니라 음높이 미끄럼이었습니다. 디코더 이름을 `pitch_slide` 로 바꾸고, `E2`·`E6`·`E7`·`E9` 도 `pitch_env`·`volume2_slide`·`fade`·`fine_tune` 으로 바꿨습니다.
- `E8 40 30`: 왼쪽 음량이 35 → 0 으로 줄고 오른쪽은 36 그대로였습니다.
- `E7 40`: 다음 음의 음량이 0 에서 천천히 커졌습니다. `1DBA` 는 v 가 양수면 음량 곱 `0254` 를 0 에서, 음수면 `FF` 에서 시작해 움직입니다.

`E2` 는 곡 `0D` 트랙 1(`e2 04`)에서 쟀습니다. 피치 하위 바이트가 3틱마다 `0 1 0 -1 0 3 0 -6 0 12 0 -18 0 18` 로 움직였습니다. 표 4(`08D4` 의 다섯째 포인터 `0903`)의 `0 1 0 -1 0 2 0 -4 0 8 0 -12 0 12` 에 1.5를 곱한 값입니다. 표 끝에 이르면 `-12 0 12` 가 되풀이되었습니다.

스크립트 연산 `03` 은 `22AF` 가 그 곡 자리의 트랙마다 `1635`(트랙 끝 처리)를 부르는 것이었습니다.

## 4. $0F1B 장면

dq5-npc2 가 `06:C297` 을 실제로 돌린 방법(`TO=22/01,4,15`, `SET=2194|80`, `LATESET=31E0=88`, 위를 보고 A 연타)으로 다시 걸었습니다.

```
596 exec 06C297
886 exec 06E413
886 cmd=04 arg=05 from=06:E419
887 cmd=1A arg=1D from=25:FD03
887 cmd=01 arg=1D from=25:FD07
1097 cmd=1A arg=05 from=00:CEB1
```

여관 처리기의 bit6 갈래가 맵 곡 `05` 를 X `10` 으로 줄이고, 장면이 이어서 여관 곡 `1D` 를 틀었습니다. `1A` 가 앞 곡을 X `7E` 로 다시 줄이므로 채널 0 음량은 912 프레임에 0 이 되었습니다.

## 남은 것

- `02`·`03` 과 나머지 `04` 를 부르는 장면, SPC 명령 `06`~`08`·`11`·`12`·`14`.
- 붙임(`4F`)이 다시 KON 하는 조건(`1593`)의 실측. 만든 시퀀스에서 `tie` 가 KON 을 냈습니다.
- 곡 이름(dq5-warp 의 SPC·WAV 와 함께).
