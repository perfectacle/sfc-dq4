# 2026-10-24-12: 맵별 루틴과 출구 번호

출구 셀 수와 목적지 항목 수가 맞지 않던 5개 맵(01/05, 03/02, 04/05, 06/05, 18/00)을 풀었습니다. 맵을 다 푼 뒤 맵마다 따로 도는
루틴이 셀 버퍼에 출구 셀을 더하거나 지우고 있었습니다. 이것까지 반영하니 346개 맵 모두 게임의 출구 셀과 같습니다.
결과는 [dq5-map-format.md 의 「맵별 루틴」](../../dq5-map-format.md#맵별-루틴-15f907) 에 있습니다.

## 1. 계단을 밟았는데 맵이 안 바뀐다

01/04 와 01/05 는 같은 성의 1층과 2층입니다. 01/04 의 출구 1 은 「01/05 의 출구 2」를 가리키는데, 맵 데이터로 센 01/05 의 출구 셀은 2개(0, 1)뿐입니다.

배 선실 세이브스테이트에서 사다리 항목(파일 오프셋 `156FF5`)을 종류 `60` 항목 `E40C2C0101`(01/04, x=12, y=44)로 덮어 01/04 로 갔습니다.

```sh
export LIBDIR=$(uv run --locked krpatch sfc lua)
STATE=$PWD/work/state/ship.mss PRE="b:4,wait:40" WAYPOINTS="3,11;3,24;7,24;up:10;13,44;down:20" \
  ROMPATCH="156FF5=E40C2C0101" CHANGES=2 AFTER=200 MAXF=2000 \
  SHOT_DIR=$PWD/work/w4 "$MESENCE" --testrunner "$PWD/rom/dq5.sfc" "$PWD/tools/lua/walk.lua"
```

처음엔 (12,46) 으로 걸어 계단을 밟으려 했는데 위에서 내려와도, 아래에서 올라가도 맵이 바뀌지 않았습니다.
`dq5exit.py` 가 01/04 의 둘째 출구 셀을 찍기 전에 죽어서, 01/05 의 출구 셀 (13,47) 을 01/04 것으로 잘못 읽고 있었습니다.
01/04 의 출구 셀은 (14,47) 이고, 플레이어는 출구 셀 한 칸 왼쪽(x=13)에 서야 합니다. (13,44) 에서 아래로 걸으니 바로 넘어갔습니다.

```
f00314 map 17/00 -> 01/04 at x=7 y=23
f00415 reached 13,44
f00467 map 01/04 -> 01/05 at x=13 y=46
f00667 end map 01/05 x=12 y=47
```

종류 `60` 항목으로는 적힌 좌표 (12,44) 에 그대로 섰습니다. 뒤에서 03/02 (10,10), 04/05 (3,12), 06/05 (30,31), 01/05 (13,47) 로 덮었을 때도 모두 그 좌표에 섰으니 좌표 변환은 없습니다.

## 2. 없는 출구 2 에 도착했다

01/05 의 (12,47) 은 출구 셀 (13,47) 의 왼쪽입니다. 맵 데이터로는 (13,47) 이 출구 1 인데, 항목은 「출구 2」였습니다.
도착 루틴 `2A:FC93` 을 `cover.lua` 로 보니 출구 셀을 만날 때마다 줄이는 `DEC $08` 이 3번 실행됐습니다. 게임의 셀 버퍼에는 출구 셀이 3개 있었습니다.

같은 시점(`2A:FCF0`)에 `atpc.lua` 로 WRAM 을 덤프해 디코더 결과와 비교하니, (51,20) 의 `+4` 가 게임에서만 `$85`(출구 속성)였습니다.
그 칸에 쓰는 코드를 `wwatch.lua` 로 잡으니 `1E:F1D0` 이었습니다.

```
1E:F1C7  LDA #$7E
1E:F1C9  PHA
1E:F1CA  PLB
1E:F1CB  LDA #$85
1E:F1CD  STA $EC1C        ; 7E:EC1C = (51,20) 의 +4
1E:F1D0  LDA #$10
1E:F1D2  TSB $EC79        ; 1E:F1D5~F1DB 도 TSB 로 다른 세 칸의 +1 에 bit4
1E:F1DE  RTL
```

(51,20) 은 벽 바깥 빈 곳이라 걸어서는 갈 수 없는 칸입니다.

## 3. 맵마다 부르는 루틴 표

`1E:F1C7` 은 `02:94E0` 에서 `JSL` 로 불렸고, `02:94E0` 은 `calls.lua` 로 보니 `15:F7EA JSL 15:F7F1` 에서 들어왔습니다.
`15:F7F1` 은 `JML [$A5]` 하나이고, 그 앞의 `15:F7F4` 가 `15:F907` 표를 훑어 `$A5` 를 채웁니다.

```
15:F907: [BC][BD|FF][플래그|FF][마스크][루틴 24비트][다른 루틴 24비트] × 162, FF
22: 01 05 ff 00 02:94E0 15:F906
14: 04 05 ff 00 02:AB25 15:F906
114: 06 05 ff 00 1E:F1F1 03:D4B5
23: 03 02 ff 00 1E:F1DF 02:CE16
```

맞지 않던 4개 맵이 모두 이 표에 있었습니다. 4개 맵으로 순간이동해 루틴이 끝난 직후(`15:F7EE`)를 덤프하니, 모두 출구 셀이 하나씩 늘어 항목 수와 같아졌습니다.

```
01/05 decoder [(5, 7), (13, 47)]  game [(5, 7), (51, 20), (13, 47)]
04/05 decoder 5개                 game + (4, 66)
06/05 decoder [(31, 31)]          game [(18, 24), (31, 31)]
03/02 decoder []                  game [(55, 6)]
```

## 4. 조건이 있는 루틴

03/02·06/05 의 루틴은 `BRK #$0B` 로 시작합니다. BRK 처리기(`00:8F80`)는 BRK 뒤 바이트를 번호로 표 `00:921B` 에서 갈래를 고르고,
`0B` 갈래(`00:93BA`)는 인자 2바이트(마스크, 번호)로 `7E:2190+번호` 를 검사해 결과를 Z 플래그로 돌려줍니다.

```
1E:F1F1  JSL $03F0F6
1E:F1F5  BRK #$0B / 40 10   ; 7E:21A0 & $40
1E:F1F9  BNE $F202
1E:F1FB  LDA #$85 / STA $7EEA94 / RTL   ; 꺼짐: (18,24) 를 출구 셀로
1E:F202  JSL $1FFB75 / RTL              ; 켜짐
```

플래그를 `POKE` 로 켜 봤지만 덤프 시점엔 0 이었습니다. 쓰기 감시를 거니 맵을 옮길 때 `00:A8CC` 가 `7E:219F`·`7E:21A0` 을 0 으로 지우고 있었습니다.
그 `STA` 를 `ROMPATCH="28D2=EAEAEAEA"` 로 막고 다시 켜니, 켜짐 쪽 `1F:FB75` 가 원래 칸을 `$80` 으로 돌려놓고 `25:FA4C` 로 블록을 놓아 출구 셀이 (31,16) 으로 옮겨 갔습니다.
03/02 도 같아서 (32,13) 에 생겼습니다.

```
06/05 켜짐 game [(31, 16), (31, 31)]
03/02 켜짐 game [(32, 13)]
```

켜졌을 때는 갈 수 있는 자리에 계단이, 꺼졌을 때는 들어설 수 없는 칸에 같은 번호의 출구 셀만 생깁니다.
계단이 있든 없든 뒤의 출구 번호가 밀리지 않게 자리를 지키는 것으로 보입니다.

## 5. 표 전체를 훑고 346개 맵을 모두 확인

표 항목 162개(서로 다른 루틴 63개)에서 `LDA #즉값` 뒤 셀 버퍼(`7E:C000-`)에 쓰는 곳을 훑으니, 출구 여부를 바꾸는 곳이 두 개 더 나왔습니다.

- 18/00 `02:9517`: (57,37) `+4` 를 `$A1` → `$F2` 로 덮어 출구 셀을 지웁니다. 남는 셀은 (38,49) 가 아니라 (57,37) 이었습니다.
- 04/07 `03:C56B`: (15,20) `+4` 를 `$94` 로 덮어 지웁니다. 맵 데이터로 세도 수는 맞았지만 번호가 하나씩 밀려 있었습니다.

`tools/dq5exit.py` 에 이 훑기(`map_hook`, `hook_writes`, `apply_hook`)를 넣고, 346개 맵을 모두 순간이동해 `15:F7EE` 덤프의 출구 셀과 비교했습니다.
사다리 항목을 종류 `60` 항목 `[E0|BD] 02 02 01 [BC]` 로 덮어 맵마다 한 번씩, 8개씩 병렬로 돌려 1분 반쯤 걸렸습니다. 맵 하나는 이렇게 돌립니다(01/05).

```sh
export LIBDIR=$(tools/lua/seqlib.sh "$(uv run --locked krpatch sfc lua)" work/walklib walk.lua)
STATE=$PWD/work/state/ship.mss PRE="b:4,wait:40" WAYPOINTS="3,11;3,24;7,24;up:10" \
  ROMPATCH="156FF5=E502020101" CHANGES=1 AFTER=150 MAXF=700 \
  SHOT_DIR=$PWD/work/all/0105 FROM=300 AT=15F7EE \
  "$MESENCE" --testrunner "$PWD/rom/dq5.sfc" "$PWD/tools/lua/atpc.lua"
```

```
pred == game      346 / 346
decoder == game   340 / 346
```

## 틀렸던 것들

- 01/04 의 출구 셀이 (13,47): 01/05 의 것이었다. `dq5exit.py` 가 01/04 에서 죽어 둘째 셀이 찍히지 않았다(없는 출구 번호로 도착 자리를 구하다 죽음).
- 종류 `60` 으로 (12,44) 를 줬는데 (7,42) 에 섰다: 같은 명령을 다시 돌리니 (12,44) 에 그대로 섰다. 이전 기록이 왜 달랐는지는 확인하지 못했다.
- 남는 항목은 이벤트로 생기는 출구: 이벤트 스크립트가 아니라 맵을 푼 직후의 맵별 루틴이 늘 만든다.
- 18/00 의 (38,49) 는 쓰이지 않는 셀: 18/02 에서 오는 출구였다. 지워지는 셀은 (57,37) 이다.
- 맵 데이터만으로 센 출구 번호: 6개 맵(01/05, 03/02, 04/05, 04/07, 06/05, 18/00)에서 틀린다.

## 남은 것

- 01/05 (51,20)·04/05 (4,66) 처럼 조건 없이 빈 곳에 둔 출구와 짝이 되는 계단을 무엇이 만드는지(이벤트 스크립트로 보임)
- `21A0` 이 켜진 채 맵별 루틴이 도는 경우. 맵을 옮길 때마다 지워지므로 맵을 다시 그리는 다른 경로가 있을 것으로 보입니다
