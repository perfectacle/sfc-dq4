# 2026-10-25-06: 전투 조우 표

DQ4 몬스터를 넣을 자리인 DQ5 의 조우 표를 풀었습니다. 어느 맵·필드 칸이 어느 구역 번호를 쓰는지, 구역마다 어떤 무리가 얼마의 확률로 나오는지, 한 걸음마다 조우를 정하는 계산입니다. 결과는 [dq5-data-format.md 「전투 조우」](../docs/dq5-data-format.md#전투-조우-23e7c2) 와 [sfc/dq5/tools/dq5encounter.py](../tools/dq5encounter.py) 에 있습니다.

## 1. 조우 계수 표에서 거꾸로

출발점은 조우 계수 표 `23:EA44` 를 읽는 `23:E898` 이었습니다. 이 루틴의 시작(`23:E7C2`, `PHP / PHB / PHK / PLB`)부터 끝까지 디스어셈블하니 두 가지를 받습니다.

- A: 구역 번호. `× 22` 해서 `23:96F3` 레코드를 찾습니다.
- Y: 조우율. 계수(`23:EA44`)와 곱해 `>> 6` 한 값이 256 분의 확률입니다.

ROM 에서 `JSL $23E7C2` 를 찾으니 `00:82B4` 한 곳이었고, 그 앞의 `01:84CF` 가 A·Y 를 정합니다. 실내 맵이면 맵에 들어갈 때 정한 `$1A98`, 필드면 좌표로 찾는 17칸 너비 격자입니다.
`$1A98` 을 쓰는 곳(`STA $1A98` 검색)에서 맵 그룹 포인터 `23:FD6A` 와 맵마다 6바이트 항목을 찾았습니다. 항목 수는 그룹마다 맵 수와 같았습니다.

## 2. 레코드 22바이트

`23:E8FE` 이후를 읽으니 `+1`~`+B` 11바이트의 하위 3비트를 더해 난수로 칸을 고르고, 칸 번호에 따라 세 갈래로 나뉩니다.

```
칸 10   → 23:B04B 고정 무리(3종)
칸 5~9  → +C+칸 의 몬스터 한 종, 마릿수 = 23:EA63/EA73[bit3-5]
칸 0~4  → 여러 종: 종 수를 칸 0~2 의 bit6-7 무게로 2·3·4 중에서, 나머지 종은 칸 0~4 에서 다시 뽑음, 마릿수 부호 + 7
```

`dq5encounter.py` 로 구역 85개(`00`~`54`, 실내 표·필드 격자·배 표가 쓰는 가장 큰 번호가 `54`)를 풀었습니다. 구역 `01` 은 スライム·とげぼうず·せみもぐら·ドラキー·おおきづち·いっかくウサギ, 구역 `46` 의 고정 무리는 ブルーイーター·エビルマスター·レッドイーター 입니다.

## 3. 던전에서 무작위 전투 잡기

선실 세이브스테이트에서 배 사다리 출구를 덮어 실내 맵 5개(`21/02`·`21/03`·`04/00`·`09/02`·`07/00`)로 순간이동하고, 긴 통로를 왕복했습니다.
툴킷의 `probe/trace.lua` 로 `23:E7C2` 진입과, 무리를 정하고 나가는 세 곳(`23:E9B0` 한 종, `23:EA40` 여러 종, `23:E98F` 고정)의 레지스터와 `7E:1001`~`1008` 을 기록했습니다.
`PRE` 의 기다리는 프레임을 바꾸면 난수가 달라져 다른 무리가 나옵니다.

```sh
export LIBDIR=$(tools/lua/seqlib.sh "$(uv run --locked krpatch sfc lua)" work/walklib walk.lua)
STATE=$PWD/work/state/ship.mss PRE="b:4,wait:40" \
  WAYPOINTS="3,11;3,24;7,24;up:10;70,43;46,43;70,43;46,43" ROMPATCH="156FF5=E2322B0121" \
  CHANGES=99 MAXF=4000 TRACE=23E7C2,23E9B0,23EA40,23E98F LOG=7E1001,7E1003,7E1005,7E1007,7E1A98,7E1948 \
  SHOT_DIR=$PWD/work/e1 "$MESENCE" --testrunner "$PWD/rom/dq5.sfc" "$LIBDIR/probe/trace.lua"
uv run --locked python sfc/dq5/tools/dq5encounter.py rom/dq5.sfc --trace work/e1/trace.txt
```

`21/02` 에서는 걸을 때마다 `A=0001 Y=0007` 로 들어왔고(`$1948` = 0, 맵 표의 첫 값 `01`), 29걸음째에 `23:EA40` 으로 나가며 `$1001` = スライム, `$1002` = ドラキー, 마릿수 1·1 이 되었습니다. 전투 화면도 「スライム − 1ひき」「ドラキー − 1ひき」였습니다.
`21/02` 의 1번과 나머지 맵 4개 × 기다림 4가지, 모두 17번의 첫 전투가 맵 표의 구역 번호로 들어왔고, `--trace` 검사에서 17개 무리 모두 그 구역에서 나올 수 있는 칸·마릿수였습니다.

```
OK  구역 04 mixed  칸 -: ナイトウイプス 1, ナイトウイプス 1
OK  구역 04 single 칸 7: おおねずみ 3
OK  구역 0F single 칸 8: わらいぶくろ 1
OK  구역 09 mixed  칸 -: メラリザード 2, ガップリン 2
…
17개 중 0개 어긋남
```

`04/00` 의 ナイトウイプス 두 줄은 여러 종 무리에서 같은 칸이 두 번 뽑힌 경우로, 화면에도 「ナイトウイプス − 1ひき」가 두 줄 나왔습니다.

## 4. 표를 고쳐 갈래마다 확인

구역 `01` 레코드(파일 오프셋 `119709`)를 `ROMPATCH` 로 고쳐 `21/02` 에서 걸었습니다.

| 고친 것 | 나온 무리 |
| --- | --- |
| 칸 5 만 무게 1, 마릿수 부호 7, 몬스터 ドラキー | ドラキー 8마리(`$1005` = 8) |
| 같은데 몬스터 キングスライム | `$1005` = 8 인데 화면에는 3마리 |
| 칸 10 만 무게 1, 고정 무리 5 | ブルーイーター 2·エビルマスター 1·レッドイーター 2 |
| 칸 0~4 만 무게 1(부호 1), 종 수 무게는 4종에만 | 네 종 무리, 마릿수 모두 1 |
| `23:EA44` 8바이트를 0 | 3번 × 320걸음 동안 조우 없음 |

キングスライム 는 표의 마릿수가 그대로 나오지 않아, 화면 크기에 맞춰 줄이는 처리가 뒤에 있는 것으로 보입니다.

## 틀렸던 것들

- 처음에는 확률 계산 뒤의 `LDA $01 / BNE` 를 「계수 번호가 0 이 아니면 반드시 조우」로 읽었습니다. 바로 앞의 16비트 `STA $00` 이 `$01` 에 곱의 위 바이트를 쓰므로, 「확률이 256 이상이면 반드시 조우」입니다.
- 필드에서 확인하려고 `04:FE83` 복귀 좌표를 해안 숲 (22, 94) 로 바꿔 나가 보았지만, 거기서도 강제 전투가 붙었고 전투를 끝낸 뒤에는 움직일 수 없어 `23:E7C2` 가 한 번도 불리지 않았습니다.

## 남은 것

- 필드 구역 격자와 지형별 조우율의 실측(조작 가능한 필드 세이브스테이트가 필요), `$1948`·`$1949` 가 무엇을 고르는지(시대·세계로 보임)
- 실내 조우율 20(`01:8526`)이 쓰이는 때, `$7E21C9` 처리(せいすい·トヘロス 류로 보임)
- 고정 무리의 하위 4비트(`$1009`~), 레코드 `+0`·`$1000`·`$1010`, 맵 항목 `+3`~`+5` 의 쓰임
- 마릿수를 화면 크기에 맞춰 줄이는 곳
