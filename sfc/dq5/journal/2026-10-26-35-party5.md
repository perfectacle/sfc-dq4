# 2026-10-26-35: 결혼식·グランバニア 의 신부 칸과 8년 동안 비워 두는 칸 0

[일지 2026-10-26-19](2026-10-26-19-party4.md)의 남은 것 셋을 실측했습니다. 결혼식 뒤 신부는 ビアンカ 면 칸 0 에서, フローラ 면 인물 레코드 표에서 일행에 들어오고, グランバニア 에 처음 오면 オジロン 장면 끝에 칸 0 으로 옮겨집니다. 석상 뒤 8년 동안 칸 번호에 1 을 더하는 갈래는 그 칸 0 의 아내를 비켜 가는 것이었습니다. 결과는 [dq5-data-format.md 「사람 동료 칸」](../docs/dq5-data-format.md#사람-동료-칸-7e294a)의 실측 3~5 에 있습니다.

## 1. 신부를 칸으로 옮기는 곳은 2F:8F7A 가 아니었다

앞 일지는 `05:FB7D` 를 `2F:8F7A` 가 부른다고 적었는데, 그 자리는 그림 자료(`22 22 2E FB 05 …`)였습니다. `05:FB7D` 는 `05:FB51` 에서 시작하는 루틴의 가운데이고(`05:FB50` 이 `RTL`), 롬에서 `51 FB 05` 를 찾으니 `10:96F6` 하나였습니다. `dq5npc.py rom/dq5.sfc 02 06 --flags 2190=40` 으로 보면 02/06 대체 목록 `10:9674`(`2190.6`)의 サンチョ(`10:96BE`, 그림 `29`) 스크립트 끝 `37 51 FB 05` 입니다.

```text
+00 09 8f 80  219F.7 기다림     +08 37 f5 fa 05  05:FAF5   +0E 21 aa 03  메시지 3AA
+1E 10 0f 20  219F.5 켬         +21 09 8f 10     219F.4 기다림
+2E 37 51 fb 05  05:FB51
```

같은 목록의 オジロン(`10:9674`)이 `219F.5` 를 기다려 `3AB`·`3B0` 을 말하고 `219F.4` 를 켭니다. グランバニア 에 처음 와 オジロン 을 만나는 장면입니다.

## 2. 결혼식까지 가기

신부 고르기 세이브스테이트 `dq5-bride-1f08.mss` 첫 프레임에 칸 0 의 ビアンカ 를 써 두었습니다. 실제 게임에서는 물의 반지 뒤 `05:F504` 가 넣어 두는 칸이고, 인물 레코드 표 칸 `03` 을 ルイーダ 에서 본 칸 꼴(`+0` 에 bit7, 장비 넷, 레코드 `+22`~`+29`)로 바꿔 만들었습니다. 도착 인사를 A 로 넘긴 뒤 오른쪽·위로 두 칸씩 걸어 ビアンカ 에게, 왼쪽·위로 フローラ 에게 말을 걸었습니다.

```text
ビアンカ  1763 06:F792   2050 21:AA63 / 21:9FD8 / 21:A85C   칸 0 에 같은 32바이트
フローラ  1652 06:F792   1930 21:AA63 / 21:9F9F             칸 0 빔
```

고른 뒤에는 5,000프레임 넘게 기다려도 조작이 풀리지 않았습니다. 인물 표 `7E:3020`·`3080`·`3480` 을 덤프하니 슬롯 9·11·12(신부 둘·하인)가 (29,18)·(29,20)·(29,22) 에서 모두 「(29,23) 도착 대기」 에 서 있었습니다. 하인 스크립트 끝의 `05:F555` 와 조작 풀기(`40`)까지 가지 못한 것입니다.

결혼식장 1F/01 은 덮어쓰기 목록이 없는 맵(기본 목록이 식 장면)이라 그리로 옮기려 했지만, `dq5warp.lua TO=1F/01,13,35` 는 필드로 나가 파파스와 슬라임 전투가 되었습니다. 식이 끝나면 `05:F60B` → `05:F648` 이 1F/0A (7,17) 로 옮기므로, 1F/0A 로 바로 갔습니다.

```sh
STATE=…/postB.mss SET="19AE=00" TO=1F/0A,7,17 SETTLE=1 SAVE=w0AB.mss \
  SHOT_DIR=… "$MESENCE" --testrunner "$PWD/rom/dq5.sfc" "$PWD/sfc/dq5/tools/lua/dq5warp.lua"
```

`postB.mss`·`postF.mss` 는 고른 뒤 3,700프레임에 저장한 세이브스테이트입니다(`dq5msg.lua` 를 감싸 그 프레임에 `emu.createSavestate` 를 쓰는 작은 스크립트). 1F/0A 에 저장한 둘은 `work/state/dq5-wed-1f0a-bianca.mss`·`dq5-wed-1f0a-flora.mss` 입니다.

## 3. 결혼식 뒤 장면 (05:F6FF·05:F6D8)

1F/0A 에 서자 기본 목록의 인물 `05:C01D` 가 `05:F661` 을 돌고 `21A1.7` 을 켜, 신부 인물이 `05:F68F` 뒤 갈래 네이티브를 불렀습니다. A 를 60프레임마다 누르며 `CALLS` 를 걸었습니다(`05:F661` 은 기다리는 동안 매 프레임 돌아 기록에서 뺌).

```text
ビアンカ  561 05:F6F4   1303 05:F6FF → 21:AA63 (201D 1→2) → 21:8A07 A=030B   1485 조작 풀림
フローラ  378 05:F6AF   1910 05:F6D8 → 21:8042 A=0047 (201D 1→2)             2033 조작 풀림
```

ビアンカ 는 칸 0 이 모두 0 이 되고 레코드 1 에 칸의 내용이 돌아왔으며, `+22` 가 `01` → `0B` 로 바뀌었습니다. フローラ 는 인물 레코드 표에서 `47 80 48 …` 로 들어왔습니다. 두 갈래 모두 주인공에게 ほのおのリング(`9E`), 신부에게 みずのリング(`9F`)·シルクのヴェール(`99`)가 붙었습니다.

`+22` 는 이름 표 `01`(`dq5text.py` 의 `string(rom, 1, n)`)에서 `01` = やどやのむすめ, `0B` = 「！のつま」, `0D` = グランバニアへいし 이고, ピピン 의 `+22` 가 `0D` 입니다. 5절의 ルイーダ 목록 창에 ビアンカ 가 「ああああのつま」, 아들(`05`)이 「ああああのむすこ」 로 떴습니다.

## 4. グランバニア 의 オジロン 장면 (05:FB7D)

결혼식 뒤 세이브스테이트에서 02/06 으로 옮기고, 그룹이 바뀌며 지워지는 `219F` 를 `LATESET="219F|80"` 로 켰습니다. 처음에는 (38,20) 에 내려 サンチョ 가 (38,23) 에서 멈췄습니다(스크립트 자리 `96CD` = (38,18) 도착 대기). 주인공이 길을 막은 것이라 (36,19) 로 바꾸었습니다.

```text
134  05:FAF5         647  219F = A0
841  05:FB05   1335  05:FB2C   1616  219F = B0   (フローラ 1556)
1745 05:FB51   1839 05:FB7D A=0301 → 21:A85C  201D 2→1   (フローラ 1685 / 1779, A=4701)
1926 조작 막힘 → 02/07, 「フローラさん 気が ついたようですよ。」·「シスター「おめでたです。」·「サンチョ「こいつは めでたい！」
```

칸 0 의 장비 칸은 무기·갑옷·방패·투구 넷뿐이라 みずのリング 와 シルクのヴェール 는 맡긴 물건 `7E:2250 + 99`·`+ 9F` 로 갔습니다(둘 다 0 → 1). フローラ 는 칸 `+18`·`+1F` 가 `03`·`01` 로, ルイーダ 에서 뺄 때와 같았습니다. 02/06 세이브스테이트는 `work/state/dq5-granbania-0206-bianca.mss`·`dq5-granbania-0206-flora.mss` 입니다.

## 5. 8년 동안 칸 번호에 1 을 더하는 갈래

`21:8923` 은 `BRK 88 BA`(`21:A76C` → `21:AA8E`, 찬 칸 세기)의 결과에 `2190.5` 켜짐·`21B7.5` 꺼짐이면 1 을 더합니다(`21:893A`~`8946`). 선실 파파스의 대화 번호를 `0F0`(ピピン, 대화 스크립트 끝 `call FD21`)으로 바꾸고 플래그만 바꿔 말을 걸었습니다.

```sh
P="b:4,wait:40,up:3,wait:20,a:4$(printf ',wait:60,a:4%.0s' $(seq 8)),wait:100"
STATE=$PWD/work/state/ship.mss SET="36EB=F0;370B=00;2190|20" PRE="$P" CALLS=21AA8E,218947,218955 LOG=7E003A,7E004A \
  DUMP="800:7E294A:96" MAXF=810 SHOT_DIR=… "$MESENCE" --testrunner "$PWD/rom/dq5.sfc" "$PWD/sfc/dq5/tools/lua/dq5msg.lua"
```

```text
플래그 없음            칸 0 빔   $3A=294A  → 칸 0
2190.5                칸 0 빔   $3A=296A  → 칸 1
2190.5 + 21B7.5       칸 0 빔   $3A=294A  → 칸 0
없음, 칸 0 = サンチョ             $3A=294A  → 칸 1
2190.5, 칸 0 = サンチョ           $3A=296A  → 칸 1
```

칸 0 이 차 있어도 칸 2 가 되지 않은 것을 보고 `$3A` 를 찍었습니다. 찬 칸 세기는 `$3A` 부터 세는데, 그 값이 플래그에 따라 `294A`·`296A` 였습니다. `WRAMWATCH=003A-003B` 로 쓰는 곳을 보니 `21:8BF6`·`21:8C24` 였고, 그 앞 `21:8BE1` 이 필드 번호 `40` 을 같은 조건에서 `50` 으로 바꿉니다. 필드 `50` 은 칸 1 에서 시작하는 사람 동료 칸입니다. 그래서 루틴은 칸 1 부터의 순번을 얻고, 1 을 더해 실제 칸 번호로 돌립니다.

ルイーダ(`dq5-luida-0202.mss`)의 칸 0~4 에 ビアンカ·아들·딸·サンチョ·ピピン 을 두고 なかまをくわえる 의 첫 사람을 골랐습니다(`06:EE26` → `21:AA63`, `$42` = 0).

```text
플래그 없음        목록 ビアンカ·クーパー·アニー·サンチョ·ピピン  → ビアンカ(칸 0)
2190.5            목록 クーパー·アニー·サンチョ·ピピン          → 아들(칸 1), 칸 0 ビアンカ 그대로
2190.5 + 21B7.5   목록 ビアンカ·…                              → ビアンカ(칸 0)
```

칸 0 에 있는 것은 グランバニア 에서 옮겨진 아내입니다. 석상 장면(`dq5-statue-0302.mss`)을 칸 0 에 4절의 ビアンカ 칸을 둔 채 돌리자 아이들·サンチョ·ピピン 이 칸 1~4 에 들어가고 칸 0 은 그대로였습니다. 8년 동안 아내는 목록에서 빠지고, 그 칸은 비켜 갑니다.

## 틀렸던 것들
