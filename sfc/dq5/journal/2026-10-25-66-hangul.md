# 2026-10-25-66: 롬 확장, 트리 다시 만들기, 한글 메시지

[2026-10-25-45](2026-10-25-45-text2.md) 에서 글자 코드 `3DB` 하나를 늘려 「한」 을 띄웠습니다. 이번에는 실제 한글 해킹롬에 필요한 큰 작업 셋, 곧 롬 확장, 보행 모드 메시지를 새 허프만 트리로 다시 부호화해 늘린 뱅크로 옮기기,
그리고 이름·창·전투 문자열의 1바이트 부호를 넓히는 길이 되는지 실험했습니다. 결과는 [dq5-hangul-format.md](../docs/dq5-hangul-format.md) 에 있습니다.

## 1. 실험용 롬 만들기

`sfc/dq5/tools/dq5hangul.py` 를 새로 만들었습니다. 원본 롬은 그대로 두고 `work/` 에 실험용 롬을 씁니다.

```sh
for s in 2 3 4; do uv run --locked python sfc/dq5/tools/dq5hangul.py rom/dq5.sfc expand --size $s -o work/hangul/dq5-${s}m.sfc; done
```

늘린 자리는 0 으로 채우고, 뱅크마다 첫 8바이트에 `DQ5X` 와 파일 뱅크 번호를 써서 어느 CPU 주소가 어디로 가는지 알아볼 수 있게 했습니다. 머리 체크섬도 고칩니다.

## 2. 늘린 롬이 도는지

`dq5msg.lua` 가 `STATE` 없이 전원을 켜 시작하도록 고치고, 5프레임째에 CPU 주소 몇 곳을 읽었습니다.

```sh
DUMP="5:308000:8;5:408000:8;5:608000:8;5:7D8000:8" MAXF=900 SHOTS=600,899 SHOT_DIR=$PWD/work/hangul/boot-2m \
  "$MESENCE" --testrunner "$PWD/work/hangul/dq5-2m.sfc" "$PWD/sfc/dq5/tools/lua/dq5msg.lua"
```

```
2MB: 308000 44 51 35 58 30 …   408000 00 …            7D8000 44 51 35 58 3D …
3MB: 308000 … 30   408000 … 40   608000 … 40   7D8000 … 40
4MB: 308000 … 30   408000 … 40   608000 … 60   7D8000 … 7D
```

2MB 는 뱅크 `30`~`3F`, 4MB 는 `40`~`7D` 까지 새 자료가 보였고, 3MB 는 `60` 부터 `40` 이 되풀이됐습니다.
그다음 전원을 켜 START·A 를 눌러 이름 입력 창(3,000프레임)까지 가며 두 번 찍었습니다. 처음에는 2·3MB 만 원래 롬과 달라 보였는데, MesenCE 가 롬 파일 이름마다 SRAM 을 두어 먼저 돌린 실험의 저장이 남아 있었기 때문입니다.
새 이름으로 복사한 롬끼리 비교하자 원래 롬(복사본)과 2·3·4MB 가 모두 같은 화면이었습니다. 원래 롬의 선실 세이브스테이트를 늘린 롬에 불러 파파스에게 말을 걸어도 메시지 `742` 와 화면이 같았습니다.

## 3. 메시지를 뱅크 30 으로

`retree` 는 2MB 롬에서 메시지 3,200개를 원래 트리로 풀고, 129 를 `{1006}` `3DB` `3DC` `{1001}`(「한글」)로 바꾼 뒤 새 트리로 다시 부호화합니다.
새 트리 표는 뱅크 24 에 들어가지 않습니다. 뱅크 24 에는 48바이트 넘는 빈 곳이 없고 원래 표 1,980바이트 둘 뒤에 전투 메시지 트리(`24:9C2E`)가 붙어 있습니다.
그래서 디코더(`24:9E02`~`9E46`, 69바이트)를 뱅크 30 에 통째로 옮겼습니다. 원래 디코더는 `PHK`/`PLB` 로 데이터 뱅크를 제 뱅크로 두고 표를 `LDA abs,X` 로 읽으므로, 옮긴 사본은 표만 같은 뱅크 30 에 두면 됩니다.

```sh
uv run --locked python sfc/dq5/tools/dq5hangul.py rom/dq5.sfc retree -o work/hangul/dq5-retree.sfc
STATE=$PWD/work/state/ship.mss PRE="b:4,wait:40,up:3,wait:20,a:4,wait:30,a:4,wait:200" MAXF=280 ROMPATCH="30139=6129" \
  SHOT_DIR=$PWD/work/hangul/retree "$MESENCE" --testrunner "$PWD/work/hangul/dq5-retree.sfc" "$PWD/sfc/dq5/tools/lua/dq5msg.lua"
```

```
잎 993, 노드 992, 뿌리 X 0000, 최장 부호 17비트
디코더 308000, 트리 1·0 30804D·30880D, 폰트 표 308FCD, 메시지 141244바이트 ~1A8000(파일)
롬만으로 다시 풀기: 메시지 3199개 중 3199개 같음, 129 = 1006 03DB 03DC 1001
```

## 4. 색인이 가리키는 뱅크

색인 값은 24비트를 3 오른쪽으로 미는 21비트 주소라 뱅크 `1F` 까지만 가리킵니다. [앞 일지](2026-10-25-45-text2.md)에서 `3F` 까지라고 적은 것은 틀렸습니다.
색인에는 `주소 - 200000` 을 넣고, 색인을 푸는 `24:8C8D` 끝의 `LDA $02` / `STA $F2` 를 `JSL` 로 바꿔 뱅크에 `20` 을 OR 했습니다. 보행 모드 메시지는 맞게 나왔는데, 전투를 돌려 보니 메시지 프레임이 달라졌습니다.

```
원래:   161 248C39 5E  202 6A  246 5E  287 6A  330 5E  395 69
고친 것: 161 248C39 5E  231 6A  271 5E  342 6A  381 5E
```

고친 곳을 하나씩 되돌리며 돌리자 이 `JSL` 하나가 원인이었습니다. `24:8C8D` 는 전투 메시지(`24:8C39` → `24:8C60`)도 부릅니다. 보행 모드 쪽 호출(`24:8BD6`)만 비운 디코더 자리 `24:9E07` 의 작은 루틴(`JSR 8C8D` 뒤 `$F2 |= 20`)으로 돌리자 전투 메시지 번호·프레임이 원래와 같아졌습니다.

## 5. 다시 만든 롬 비교

메시지 9개(`1DB`·`3CE`·`0B6`·`16B`·`2D2`·`1F9`·`058`·`742`·`061`)를 원래 롬과 새 롬에서 띄우고 A 를 눌러 345·549·753프레임에 찍었습니다. 다른 곳은 파파스·주인공 자리와 `1F9` 의 ▼ 자리뿐이었고,
원래 롬을 두 번 돌린 것끼리도 같은 자리가 달랐습니다. 전원을 켜 이름 입력 창까지도 같았습니다.

## 6. 1바이트 부호는 어디서 그리나

이름 표·창·전투 메시지의 1바이트 부호가 어디서 글자가 되는지 보았습니다. 이름 부호 표(`24:B270`)와 탁점 표(`24:AE9A`·`24:B36E`)를 읽는 명령을 롬 전체에서 찾으니 뱅크 24 의 `24:A7B6` 계열뿐이었고, 이것은 메시지 안 이름(`1008` 등)이 씁니다.
명령 창을 열면서 `24:A609`·`A631`·`A756`(보행 모드 글자 그리기)과 `24:A7B6` 을 기록하자 한 번도 불리지 않았습니다. 창 문자열을 읽는 `04:B0F0` 을 따라가니 바이트를 BG3 타일맵에 그대로 썼습니다(`04:B235`).

```
명령 창을 연 뒤 VRAM 워드 1CA4: 208E 207C 2029 2024 201C 2001 2001 201B
```

「はなす」 의 바이트 `29 24 1C` 가 그대로 타일 번호였습니다. 전투 메시지가 뜰 때도 보행 모드 글자 그리기는 불리지 않아, 전투 글자를 그리는 곳은 남겼습니다.

## 틀렸던 것들

- 색인이 뱅크 `3F` 까지 가리킨다고 적었다: 21비트 주소라 `1F` 까지다.
- 색인 뱅크 보정을 `24:8C8D` 안에 넣었다: 전투 메시지도 같은 루틴을 써서 전투 메시지가 깨졌다. 보행 모드 호출만 돌렸다.
- 늘린 롬의 부팅 화면이 달라 롬 확장이 뭔가를 바꾼다고 의심했다: 롬 파일 이름마다 남은 SRAM 차이였다.
- 창 글자도 보행 모드 폰트로 그때그때 그린다고 보았다: 명령 창은 바이트를 BG3 타일 번호로 바로 쓴다.

## 남은 것

- 전투 메시지 글자를 그리는 루틴, 창 글자 타일(BG3)을 미리 올리는 곳과 남는 타일 수
- 2바이트 부호를 넣었을 때 창 너비·이름 길이가 견디는지
- 늘린 롬에서 SRAM 저장·불러오기 실측
