# 2026-10-25-100: SRAM 세이브 형식

모험의 서 3칸이 SRAM 에 어떻게 놓이고, 무엇을 저장하며, 체크섬을 어떻게 계산하는지 확인했습니다. 결과는 [dq5-data-format.md 「SRAM 세이브」](../docs/dq5-data-format.md#sram-세이브-258000) 에 있고,
SRAM 파일을 읽는 도구는 [dq5sram.py](../tools/dq5sram.py) 입니다.

실험은 세이브스테이트(또는 전원 켜기)에서 입력을 재생하는 작은 MesenCE 프로브로 했습니다. 끝 프레임에 `emu.memType.snesSaveRam` 8KB 와 WRAM 을 덤프하고,
둘째 프레임에 SRAM 을 고치는 기능(`SRAMW`, `SRAMCOPY`)을 붙였습니다. 이 프로브는 스크래치라 저장소에 넣지 않았습니다.

## 1. SRAM 을 만지는 코드

롬에서 뱅크 `70` 롱 주소와 `MVN $70,$7E`·`MVN $7E,$70` 을 찾자 거의 다 뱅크 25 였습니다. `25:8000` 은 `DRAGON QUEST V` 글자이고, 바로 뒤 `25:800E` 가 워드 셋 `0012`·`0AB2`·`1552` 입니다.

```
25:83CE  JSR $8450 / STA $7E2A9E          체크섬을 7E:2A9E 에
         LDA $25800E,X / TAY / LDX #$2000 / LDA #$0A9F / MVN $7E,$70   7E:2000 부터 AA0 바이트를 칸으로
25:8258  ... MVN $70,$7E                   칸에서 7E:2000 으로
25:8450  CLC / ADC $7E2000,X / INX INX / CPX #$0A9E   워드 합
```

칸 셋이 `0012` 부터 `AA0` 씩 이어져 `1FF2` 에서 끝나고, 그 뒤 14바이트에 머리가 한 벌 더 들어갑니다.

## 2. 저장한 것과 WRAM

선실 세이브스테이트에서 파파스 대화 번호를 `05`(교회)로 바꾸고 おいのり → はい → 칸 1 로 기록했습니다. 기록 칸 목록은 메시지 8A 뒤 400프레임쯤 지나 떠서, 그 전에 누른 아래 입력은 먹지 않았습니다.

```
칸 1  stored FE2A  calc FE2A  WRAM 7E:2000~2A9F 와 차이 0
```

## 3. 켤 때의 검사

세이브스테이트 없이 전원을 켜고, 둘째 프레임에 SRAM 을 고친 뒤 START 를 눌러 모험의 서 화면으로 갔습니다.

- 칸 1 을 칸 2 로 복사하고 칸 2 의 `+1`(이름) 두 바이트를 바꾼 뒤 `000E` = `03` 으로 켰습니다. `25:81E7` 의 비교에서 칸 2 는 계산 `2E00`·저장 `2BFD` 로 달랐고, 1D0「まことに　ざんねんですが　ぼうけんのしょ…は　消えてしまいました。」가 떴습니다.
- 머리 `0000` 첫 바이트만 지우면 `1FF2` 쪽을 보고 되살려, 칸 1 이 그대로 남았습니다. 두 곳을 다 지우면 SRAM 전체가 0 이 되고 머리만 다시 써졌습니다.

## 4. 기록 칸 목록

`000E` 를 `07` 로 하고 칸 2 의 `+1` 을 `12 13`(うえ), 칸 3 의 `+1` 을 `13`(え)으로 쓰자, 교회의 칸 목록 2·3 에 「うえ」「え」 이름이 나왔습니다. 목록은 칸의 `+1`, 곧 저장된 `7E:2001` 주인공 이름을 읽습니다.
`000E` 의 비트가 칸이 쓰이는지를 정하고, 쓰지 않는 칸은 「しようしていません」 입니다.

## 5. 도구

`dq5sram.py rom 파일` 은 머리 두 곳, 쓰는 칸 비트, 칸마다 상태·체크섬(저장값과 계산값)·이름·레벨·금화를 찍습니다. `--fix` 는 세 칸의 체크섬을 다시 계산해 새 파일로 씁니다.
위 실험의 SRAM 덤프로 칸 2·3 의 체크섬이 「다름」으로 나오고, `--fix` 뒤에는 「맞음」이 되는 것을 확인했습니다.

## 남은 것

- 칸 상태 바이트 `000F`~`0011` 의 비트 뜻. 쓰는 칸은 `C0` 이고, `25:818B` 가 `40` 을 쓰며, 체크섬이 틀린 쓰지 않는 칸은 `& 30` 만 남깁니다(코드 읽기).
