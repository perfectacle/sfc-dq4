# 2026-10-26-37: 게임 데이터 표 쓰기 도구

포팅에 쓸 쓰기 도구의 첫 번째로, 몬스터·물건·주문 표를 고쳐 롬에 넣는 `sfc/dq5/tools/dq5tables.py` 를 만들었습니다. FC DQ4 의 몬스터 능력치를 DQ5 레코드에 옮기려면 이 길이 필요합니다. 형식은 [dq5-build-format.md 「게임 데이터 표」](../docs/dq5-build-format.md#게임-데이터-표-dq5tables1) 에 있습니다.

## 1. 읽기 도구는 있는데 쓰는 길이 없었다

[dq5-data-format.md](../docs/dq5-data-format.md) 에는 몬스터 레코드 25바이트, 물건 표 9개, 주문 표의 필드가 비트 단위까지 풀려 있습니다. 도구(`dq5monster.py`·`dq5item.py`·`dq5spell.py`)는 그 값을 찍기만 했습니다. 몬스터 HP 는 바이트3 과 바이트10 의 아래 3비트, 금화는 바이트7 과 바이트8 bit2-3 처럼 한 값이 여러 바이트에 흩어져 있습니다. 손으로 `ROMPATCH` 를 짜면 같은 바이트의 다른 필드를 지우기 쉽습니다.

## 2. 필드를 비트 조각으로 적는다

필드마다 (바이트, 시작 비트, 비트 수) 조각을 낮은 비트부터 적었습니다. 읽을 때와 쓸 때 같은 조각 목록을 씁니다. 쓸 때는 조각이 차지하는 비트만 바꾸므로, 어느 필드도 차지하지 않는 비트(몬스터 바이트11 bit0-5 처럼 읽는 곳을 못 찾은 비트)는 롬 값 그대로 남습니다.

```
HP   = 바이트3[0:8] + 바이트10[0:3]   → 11비트
금화 = 바이트7[0:8] + 바이트8[2:4]    → 10비트
내성 = 바이트12~16 의 2비트 18칸       → "000000000103300000"
```

물건은 표 9개가 따로 놓여 있어서, 물건 하나의 바이트를 `23:B081 + k*D8 + n`(k = 0~6)과 `23:B669 + n*2` 의 두 바이트로 모아 가상 레코드 하나처럼 다뤘습니다. 주문도 MP·범위 바이트(`26:8765`)와 실행 루틴 주소(`26:8865`)를 묶었습니다.

## 3. 내보내고, 고치고, 다시 넣기

`export` 는 다섯 표(몬스터 236, 물건 216, 주문 171, 피해량 64, 동료 몬스터 42)를 JSON 으로 냅니다. 고칠 항목·필드만 남긴 JSON 을 `patch` 에 주면 롬과 다른 바이트만 `dq5patch/1` 쓰기로 내고 `orig` 를 채웁니다. 빌더가 다른 쓰기 도구와 겹치는지 검사할 수 있습니다.

```
$ dq5tables.py rom/dq5.sfc export -o work/tables/all.json
$ dq5tables.py rom/dq5.sfc patch work/tables/all.json -o none.dq5patch.json
바뀐 바이트 0개, 쓰기 0개
```

내보낸 값은 읽기 도구 셋의 값과 몬스터 236종(필드·내성·행동), 물건 216개, 주문 171개 모두에서 같았습니다. 다섯 표의 첫·둘째·마지막 항목에서 필드마다 0 과 최댓값을 넣고 다시 읽는 시험 354번도 그 필드만 바뀌었습니다.

## 4. 게임에서 확인

スライム 를 고친 롬 세 벌을 빌더로 만들고, 배 선실에서 슬라임 셋 이벤트 전투로 들어갔습니다(`dq5battle.lua`).

```json
{"format": "dq5tables/1", "monsters": [{"id": "00", "HP": 1, "경험치": 777, "금화": 600}]}
```

```
"at": "23:8003", "hex": "01",          "orig": "07"
"at": "23:8005", "hex": "09 03 58 09", "orig": "01 00 01 01"
```

| 고친 값 | 본 것 |
| --- | --- |
| `HP` 300 | 전투 슬롯 `7E:07C0 + 슬롯*16 + 2` 가 셋 모두 `2C 01`. 바이트10 의 위 비트까지 읽힘 |
| `HP` 1·`경험치` 777 | 「それぞれ 2331ポイントの けいけんちを かくとく！」 (777 × 3) |
| `HP` 1·`경험치` 0·`금화` 600 | 소지금 `7E:2019` 가 20 → 1,820 (600 × 3). 바이트8 bit2-3 의 위 비트까지 읽힘 |

## 남은 것

- 물건·주문·피해량·동료 몬스터 표는 읽기 도구와 값을 대조했을 뿐, 고친 롬을 게임에서 돌려 보지는 않았습니다.
- 성장 표(`23:EB50`), 조우 구역 레코드(`23:96F3`), 상점 목록은 아직 이 도구에 없습니다.
- 표의 항목 수를 늘리는 길(몬스터 237번째 등)은 이름 표·그림 표가 함께 늘어야 해서 다루지 않았습니다.
