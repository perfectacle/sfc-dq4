# 2026-10-25-13: 인물 표와 인라인 스크립트

인물 엔트리의 남은 바이트(기타·이동·추가 값)가 인물 표 어디에 들어가는지 풀고, 엔트리 끝에 붙는 인라인 스크립트를 명령으로 읽었습니다.
그 스크립트에서 01/05 빈 곳 출구의 짝인 계단을 놓는 곳이 나왔고, 맵별 루틴이 지워질 플래그를 보는 이유와 표의 둘째 루틴의 쓰임도 함께 확인했습니다.
결과는 [dq5-map-format.md 「인물」](../../dq5-map-format.md#인물-128000)과 [「맵별 루틴」](../../dq5-map-format.md#맵별-루틴-15f907)에 있습니다.

## 1. 엔트리 값을 인물 표로 옮기는 `1E:DB44`

`12:8161`(낮)·`12:8227`(밤)은 엔트리에서 그 시간대 값을 `$04`~`$0E` 에 모으고, `1E:DB44` 가 그 값을 인물 표 `7E:xxxx + 슬롯` 에 나눠 넣습니다.
이 루틴을 그대로 옮겨 `dq5npc.py` 의 `table_values` 로 만들었습니다. 눈에 띄는 것은 이렇습니다.

- 방향은 따로 바이트가 없고 X·Y 의 bit7 두 개로 정합니다(`1E:DD9C`, `88` 위·`11` 오른쪽·`44` 아래·`22` 왼쪽).
- 이동 바이트는 층(bit0-1) · 이동 간격(bit2-5) · 속도(bit6-7). 간격이 8 이상인 인물에게는 `1E:DD1E` 가 차례 번호를 붙여 같은 간격 인물끼리 걸음이 엇갈리게 합니다.
  이 번호는 맵마다 `12:800E` 가 지우는 `$85`~`$8C` 를 세어 가며 붙으므로, 놓는 순서까지 따라 해야 값이 맞습니다.
- 추가 값은 위 니블이 걷기, 아래 니블이 서기 애니메이션 간격입니다.

확인은 이미 있던 덤프로 했습니다. 346개 맵을 하나씩 순간이동해 인물을 다 놓은 직후(`AT=12803C`) 낮·밤으로 덤프한 692개입니다.

```
# 맵마다: uv run --locked python tools/dq5npc.py rom/dq5.sfc BC BD --compare <덤프>/at_12803C.bin
all_day ok=346 bad=0 missing=0 slotsOK=932 no-npc=4
all_night ok=346 bad=0 missing=0 slotsOK=630 no-npc=4
```

처음에 `32A0`·`33A0` 까지 통째로 견주자 165개 맵이 어긋났습니다. 게임 값에는 `1E:DB44` 가 쓰지 않는 bit0·bit3·bit6 이 더 켜져 있었습니다.
다른 루틴이 같은 바이트의 나머지 비트를 쓰는 것이라, `1E:DB44` 가 넣는 비트만 비교하게 하자 22칸 모두 같았습니다.

## 2. 인라인 스크립트 해석기 `01:C800`

`b0` bit5 엔트리 끝의 `[길이][바이트…]` 는 인물 표 `3480`·`34A0`·`34C0` 에 첫 바이트 주소가 들어가고, 매 프레임 `01:C800` 이 명령 하나씩 실행합니다.
명령 표는 `01:C827`(00~56), bit7 이 켜진 바이트는 두 바이트짜리 「(X,Y) 로 걸어가 도착할 때까지」입니다.

각 처리 루틴이 `$AE` 를 얼마나 늘리는지(`01:C8D9` 는 1, `01:C8EA` 는 A 만큼, `01:C937` 은 상대 점프)를 읽어 명령 길이 표를 만들고,
모든 목록(기본 346개 + 대체 293개)의 스크립트를 이 길이로 읽어 끝이 길이 바이트와 맞는지 봤습니다.

```
$ uv run --locked python tools/dq5npc.py rom/dq5.sfc --check-scripts
scripts 1034, mismatch 0
```

`$AE` 를 늘리지 않고 끝나는 명령은 다음 프레임에 같은 명령을 다시 실행합니다. `14`(도착 대기), `09`(플래그 대기), `08`(주인공 자리 대기)이 이렇게 기다리고,
아무 일도 하지 않는 `00` 같은 명령은 스크립트의 끝이 됩니다.

메시지 명령은 `21`·`30`·`31`·`32` 넷이고, 모두 `01:CEA9` 에서 텍스트 트랙이 찾은 `24:8157` 을 부릅니다. 넷은 창을 열고 닫는 `BRK 95` 를 붙이느냐만 다릅니다.

## 3. 순찰 병사로 걷기 명령 확인

01/05 의 병사(`05:89B8`, 슬롯 `0B`)는 이런 스크립트를 가졌습니다.

```
+00 13 25 2f     걸어가기 X Y (37,47)
+03 14           도착 대기
+04 1d 20        이동 간격 20
+06 13 2c 2f     걸어가기 X Y (44,47)
...
+16 13 1d 2f     걸어가기 X Y (29,47)
+19 14           도착 대기
+1A 03 e5        상대 점프 → +00
```

배 선실 사다리의 목적지를 01/05 로 바꿔 서 있기만 하면서, 슬롯 `0B` 의 좌표가 바뀔 때마다 적는 프로브(`tools/lua/slottrack.lua`, `SLOT=0B`)를 4,000프레임 돌렸습니다. 꺾인 자리만 추리면 이렇습니다.

```
f00349 (29,47)  f01024 (44,47)  f01096 (44,55)  f01545 (29,55)  f01977 (29,47)
f02624 (44,47)  f02696 (44,55)  f03145 (29,55)  f03577 (29,47)
```

스크립트대로 네모를 1,600프레임마다 돕니다. (37,47) 은 같은 줄 위라 꺾이지 않습니다.

## 4. 파파스가 01/05 의 계단을 놓는다

[출구 일지](2026-10-24-12-exit-hook.md)에서 남긴 01/05 (51,20) 의 빈 곳 출구 셀을 다시 봤습니다. 스크립트의 네이티브 호출(`37`)을 모두 뽑아 보니,
플래그 `7E:21A7 & 40` 일 때 쓰는 대체 목록(`10:8994`)의 인물이 `06:CCEB` → `1F:FA9B` 를 부르고 있었습니다.

```
+00 08 aa 04 2e 09 주인공 자리 대기 후 이벤트 시작 (42,4)-(46,9) 안이 될 때까지
+06 21 91 02     메시지(창 열고 닫음) 0291
+0D 13 30 05     걸어가기 X Y (48,5)
...
+44 13 3f 13     걸어가기 X Y (63,19)
+47 14           도착 대기
+48 37 eb cc 06  네이티브 호출 06:CCEB
+4D 28           숨기기
```

메시지 `291` 은 「パパス「なに…っ！！ 王子が　さらわれただと！？」」입니다. 파파스가 왕자를 찾아 방 구석으로 달려가 계단을 내는 장면입니다.
`1F:FA9B` 는 (63,18)~(64,19) 네 셀을 계단 타일로 바꾸고 (51,20) `+4` 를 0 으로 지웁니다(코드 읽기).

실측은 사다리 목적지를 01/05 (44,8)(사각형 안)로 덮고 플래그를 고정해, A 를 눌러 가며 기다렸습니다.

```
WP="3,11;3,24;7,24;up:10$(for i in $(seq 1 45); do printf ';a:4;wait:40'; done);wait:10"
LIBDIR=$(uv run --locked krpatch sfc lua) STATE=$PWD/work/state/ship.mss PRE="b:4,wait:40" POKE="7E21A7=40" ROMPATCH="156FF5=E52C080101" \
  WAYPOINTS="$WP" CHANGES=9 MAXF=2800 WATCH="c51_20=7EEC1C;c64_19=7EEA64" \
  SHOT_DIR=$PWD/work/npcstair "$MESENCE" --testrunner rom/dq5.sfc tools/lua/walk.lua
```

| | (51,20) `+4` | (64,19) `+4` |
| --- | --- | --- |
| 플래그 `21A7 & 40` 고정 | `00` | `85` |
| 플래그 없이(파파스 없음) | `85` | `80` |

빈 곳의 출구 셀이 사라지고 계단에 출구 셀이 생겼습니다. 셀 순서로 두 자리 사이에 다른 출구 셀이 없으니 출구 번호는 바뀌지 않습니다.
맵별 루틴이 빈 곳에 출구 셀을 미리 두는 것은, 이벤트 뒤에 생길 계단과 번호를 맞춰 두는 자리 지킴이라는 앞 일지의 짐작과 맞습니다.

![01/05. 초록 선이 파파스 스크립트의 걷기 목표, 노란 틀이 지워지는 빈 곳 출구 셀, 빨간 틀이 새 계단. 오른쪽은 스크립트가 끝난 뒤 MesenCE 화면(주인공 왼쪽에 계단)](../../images/dq5-npc-script-0105.webp)

04/05 (4,66) 은 같은 방법으로 찾지 못했습니다. 04/05 목록에는 네이티브 호출이 없고, 셀 버퍼에 `$85` 를 즉값으로 쓰는 곳 7개와
블록을 놓는 `25:FA4C` 호출 6개를 모두 따라가도 04/05 를 다루는 것은 맵별 루틴 `02:AB25` 하나였습니다.

## 5. 숨은 인물 목록 9개

대체 목록 사이에 표가 가리키지 않는 목록 9개가 있습니다. 이 중 둘(`10:8BBD`, `10:A731`)은 끝 표시 `00` 하나뿐인 빈 목록입니다.
인물을 놓는 `12:8000` 을 부르는 곳은 롬 전체에서 `00:E1B2` 하나이고, 그 안에서 목록 주소를 `$A5` 에 두는 곳은 기본 목록(`12:803F`)과 대체 표(`12:82FB`) 둘입니다.
9개 주소를 16비트 값으로 롬에서 찾으면 몇 곳씩 나오지만 모두 이 경로 밖의 데이터라, 지금 롬에서는 쓰이지 않는 목록으로 봅니다(코드 읽기).
내용은 `dq5npc.py --list 10AC3B` 처럼 볼 수 있습니다.

## 6. `7E:21A0` 은 맵 그룹이 바뀔 때만 지워진다

앞 일지는 「맵을 옮길 때 `00:A8CC` 가 `219F`·`21A0` 을 지운다」고 적었는데, 03/02·06/05 루틴이 왜 늘 꺼진 비트를 보는지가 남아 있었습니다.
맵을 푸는 `01:8F26` 을 읽어 보니 지우는 것이 둘로 나뉘어 있었습니다.

```
01:8F26  LDA $7E21C7 / CMP $BC / BEQ +   ; 그룹이 다르면
01:8F2E  JSL $00A8C5                       ; 21A1~21A4 와 219F·21A0 을 지움
01:8F34  LDA $7E21C8 / CMP $BD / BEQ +   ; 맵만 다르면
01:8F3C  JSL $00A957                       ; 21A1~21A4 만 지움
```

`POKE` 를 매 프레임이 아니라 200프레임째 한 번만 쓰도록 고친 `walk.lua` 사본으로, 배 선실(17/00)에서 200프레임째에 `219F`~`21A2` 를 `11 22 33 44` 로 쓰고 사다리를 탔습니다.

| 가는 곳 | `219F` `21A0` `21A1` `21A2` |
| --- | --- |
| 17/02(같은 그룹) | `11 22 00 00` |
| 03/02(목적지를 바꿔 그룹을 옮김) | `00 00 00 00` |

`21A0` 은 같은 그룹 안의 맵을 오가는 동안 살아 있는 플래그입니다. `12:F62E`·`12:F69E` 가 `21A0` bit7·bit6 을 켜고 루틴과 같은 계단 루틴(`1F:FB35`·`1F:FB75`)을
부르므로(코드 읽기), 이벤트로 낸 계단은 그룹 안 다른 맵에 다녀와도 맵별 루틴이 다시 놓습니다. 그룹을 떠나면 사라집니다.

## 7. 표의 둘째 루틴은 매 프레임 훅

맵별 루틴 표의 `+7~+9` 는 `$1AA6` 에 쓰이기만 하고 읽는 명령이 없었습니다. 읽기 감시(`rwatch.lua`)에도 걸리지 않았습니다.
`15:F7D0` 을 다시 보니 `$1AA5` 에 `22`, `$1AA9` 에 `60` 을 써서 `JSL [루틴] / RTS` 라는 코드를 RAM 에 만들고 있었고, 필드 주 루프 `00:8099` 가
`JSR $80B1` → `JMP $1AA5` 로 그 코드를 실행합니다. 실행이라 읽기 감시에 안 걸린 것입니다.

실행 횟수를 세는 프로브(`tools/lua/execcount.lua`, `EXEC=02AE55,15F906,001AA5,0080B1`)로 배 선실에서 17/02 로 걸어 갔습니다.

```
0080B1 map 17/00 n=252   001AA5 map 17/00 n=252   02AE55 map 17/00 n=252
15F906 map 17/02 n=339   0080B1 map 17/02 n=338   001AA5 map 17/02 n=338
```

17/00 의 둘째 루틴 `02:AE55` 가 주 루프와 똑같이 252번, 항목이 없는 17/02 에서는 기본값 `15:F906` 이 주 루프 횟수에 맵을 푼 직후 첫 루틴 몫 한 번을 더해 돌았습니다.
표 항목 136개가 이 자리에 루틴을 두고, 가장 흔한 `03:D4B5` 는 `7E:1ECE` 를 `C0` 마다 되감는 카운터입니다.

## 틀렸던 것들

- 「맵을 옮길 때 `219F`·`21A0` 이 지워진다」: 같은 그룹 안에서는 지워지지 않습니다(6절). 앞 일지가 쓰기 감시로 잡은 `00:A8CC` 는 그룹이 바뀔 때만 타는 `00:A8C5` 안에 있습니다.
- 스크립트 명령 `06` 의 조건을 처음에 `09` 와 같은 방향으로 읽었습니다. `09` 는 f bit7 이 0 이면 「꺼질 때까지」 기다리지만, `06` 은 bit7 이 0 이면 「켜져 있을 때」 뜁니다.
  처리 루틴(`01:C998`)을 다시 읽어 고쳤습니다. 이렇게 읽어야 01/05 의 병사(`05:89E3`)가 `06 91 80 FF` 로 제자리를 맴돌다 `21A1 & 80` 이 켜지면 걸어 나가는 흐름이 됩니다.
- `08` 을 「사각형에 들어올 때까지」로 적었다가, x0 bit7 이 켜진 파파스 스크립트가 주인공이 사각형 안에 서자 움직인 것을 보고 「bit7 이면 안, 아니면 밖이 될 때까지」로 고쳤습니다.
