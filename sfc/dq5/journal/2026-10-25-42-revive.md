# 2026-10-25-42: 동료를 되살리고 마비를 풀기

[2026-10-25-33](2026-10-25-33-exec3.md) 에서 「なにも おこらなかった」로 끝난 되살리기·상태 풀기 주문을, 쓰러지거나 마비된 동료가 있는 장면에서 다시 보았습니다. 결과는 [dq5-data-format.md 「주문과 행동」](../docs/dq5-data-format.md#주문과-행동-268765) 에 있습니다.

## 1. 동료가 있는 전투

dq5-warp 세션이 `dq5warp.lua` 에 넣은 `PARTY=02`(슬라임 동료)로 전투 세이브스테이트를 만들었습니다. 주인공이 주문을 쓰도록 `SET` 도 함께 줍니다.

```sh
STATE=$PWD/work/state/ship.mss FIELD=341,56 BATTLE="00:3" PARTY=02 \
  ROMPATCH="118001=00;118003=C8" SET="2064=01;2050=63;2044=63" SETTLE=300 SAVE=party.mss \
  SHOT_DIR=$PWD/work/b "$MESENCE" --testrunner "$PWD/rom/dq5.sfc" "$PWD/sfc/dq5/tools/lua/dq5warp.lua"
```

`SET` 은 `PARTY` 보다 먼저 들어가 동료 칸에 준 값은 덮였습니다. 그래서 동료 상태는 전투가 시작된 뒤 한 번만 쓰도록(매 프레임 고정하지 않도록) 실험용 Lua 에 프레임 번호를 붙인 쓰기를 더했습니다.

## 2. 일행 레코드 +1

동료 레코드(`7E:206A`)의 HP 칸(`+E`)을 0 으로 해도 동료는 계속 싸웠습니다. 슬라임의 공격력을 올려 동료가 실제로 쓰러지게 하자 「しんでしまった！」와 함께 `+1` 이 `80` → `00` 이 되었습니다.
`+1` 에 값을 하나씩 넣어 보니 bit6(`C0`)이면 동료 차례마다 「からだがしびれて うごけない！」, bit4(`90`)면 「もうどくに おかされている！」가 나왔습니다. bit5 등은 900프레임 안에 메시지가 없었습니다.

## 3. 주문

주인공 주문 칸 8 의 주문(`23:BE31`)을 바꿔 가며 たたかう → じゅもん → 첫 주문 → 우리 편 창에서 대상을 골랐습니다.

```
+1=00, ザオラル → 주인공   070 07B  しかし なにも おこらなかった！
+1=00, ザオラル → 동료     070 097  いきかえらなかった！
+1=00, ザオリク → 동료     070 096  いきかえった！        (+1 = 80)
+1=C0, キアリク → 동료     070 095  しびれが きえた！     (+1 = 80)
```

ザオラル 는 확률로 실패하는 주문이고(이 한 번은 실패), ザオリク 는 되살렸습니다. 동료가 쓰러진 뒤 파파스의 ザオラル 는 여전히 「なにも おこらなかった」였습니다. 파파스가 살아 있는 쪽을 대상으로 고른 것으로 보입니다.

## 틀렸던 것들

- 처음에는 HP 를 0 으로 하면 쓰러진 것으로 칠 줄 알았지만, 쓰러짐은 `+1` bit7 이었습니다.

## 남은 것

- 보통 독의 비트와 キアリー(주인공 주문 칸 8 에 넣으면 주문 목록 창에서 멈춤)
- 파파스 같은 AI 가 되살리기 대상을 고르는 방식
- 몬스터 필드 `68`·`6D`, 시작 상태 `39`, 저주 장비 화면 캡처
