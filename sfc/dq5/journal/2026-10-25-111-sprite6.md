# 2026-10-25-111: 07/02 물체를 놓는 곳과 04/0A 물체

맵 OBJ 물체의 마지막 남은 둘을 닫았습니다. 결과는 [dq5-graphics-format.md 「맵 OBJ 물체」](../docs/dq5-graphics-format.md#맵-obj-물체-16f862) 에 있습니다.

## 1. 04/0A 의 0E 는 지워지지 않았다

물체 슬롯의 가로 칸 수(`7E:34E8`)를 쓰기 감시하자, 맵을 만들 때 `16:F75E` 가 `06` 을 쓴 뒤 `00:E91B` 가 0 을 썼습니다. 둘레를 읽어 보니 `00:E8C2` 는 슬롯 32개를 통째로 지우는 루틴이었습니다.
`warp.txt` 를 다시 보니 도착 자리가 필드였습니다. 순간이동한 (7,27) 이 16x26 맵 밖이라 곧바로 필드로 나간 것입니다. 맵 안 (7,22) 로 들어가자 `0E` 의 칸 목록과 OAM 묶음 7개가 맞았습니다.

```
f00412 arrived map 04/0A cell 7,22
맵 OBJ 물체 1개: 칸 목록이 16:F862 항목과 같은 덤프 7개, OAM 묶음 7개가 칸 배치·반전·팔레트까지 같음 0E
```

## 2. 07/02 의 물체는 ゲマ 장면이 놓는다

07/02 의 인물 대체 목록에는 パパス·어린 주인공·ゲマ 일행이 나오는 목록이 있고, 인라인 스크립트가 `06:CC62` 등의 네이티브 루틴을 부릅니다. `SET=219C|04` 로 그 목록을 켜고 들어가 3,400프레임을 그대로 두자 장면이 돌았습니다.
물체 슬롯의 좌표를 쓰기 감시하자 `12:8D11`·`12:8D1A` 가 한 슬롯을 (10,18) 로 썼고, 그 루틴 `12:8CFD` 를 부르는 곳이 `02:9D84`~`9E1F` 에 모여 있었습니다. 장면 덤프에서 물체 `02`(ゲマ, 4x4)가 그 자리에 놓여 OAM 이 그림과 같았습니다.

```
slot 13 4x4 x 10 y 18
맵 OBJ 물체 8개: 칸 목록이 16:F862 항목과 같은 덤프 96개, OAM 묶음 12개가 칸 배치·반전·팔레트까지 같음
```

## 틀렸던 것들

- 04/0A 의 `0E` 를 「맵을 푼 뒤 칸 수가 0 으로 지워진다」 고 적었습니다. 순간이동 자리가 맵 밖이라 필드로 나가며 슬롯이 모두 지워진 것이었습니다.
