# 2026-10-25-16: 내성·상태 주문·동료가 되는 몬스터

[2026-10-25-10](2026-10-25-10-spell.md) 에서 남긴 것을 이어 풀었습니다. 내성 종류 11개와 상태 주문의 성공 확률, 동료가 되는 몬스터의 필드 `76`·`77` 과 동료 레코드 `23:AED1` 을 확인했습니다.
범위 비트로 대상 수가 정해지지 않는다는 것은 두 그룹 전투에서 다시 확인했습니다. 결과는 [dq5-data-format.md 「주문과 행동」](../docs/dq5-data-format.md#주문과-행동-268765)·[「동료가 되는 몬스터」](../docs/dq5-data-format.md#동료가-되는-몬스터) 에 있습니다.

## 1. 두 그룹 전투 장면

`sfc/dq5/tools/lua/dq5warp.lua` 로 필드 이벤트 전투의 무리를 スライム 셋·ドラキー 둘로 바꿔 세이브스테이트를 만들었습니다. 몬스터를 오래 살려 두려고 두 레코드의 HP 를 200, 공격력을 0 으로 덮었습니다.
전투가 시작된 뒤에 롬을 덮으면 이미 슬롯에 옮겨진 HP·MP 는 바뀌지 않으므로, 이 값은 세이브스테이트를 만들 때 넣어야 합니다. 내성·행동·떨어뜨리는 물건처럼 쓸 때마다 레코드를 읽는 필드는 나중에 덮어도 됩니다.

```sh
export LIBDIR=$(uv run --locked krpatch sfc lua)
STATE=$PWD/work/state/ship.mss FIELD=341,56 BATTLE="00:3,03:2" \
  ROMPATCH="118001=00;118003=C8;11804C=00;11804B=C8" SETTLE=300 SAVE=battle2.mss \
  SHOT_DIR=$PWD/work/b "$MESENCE" --testrunner "$PWD/rom/dq5.sfc" "$PWD/sfc/dq5/tools/lua/dq5warp.lua"
```

이 전투에서도 몇 턴 뒤 파파스가 합류해(`002`), 파파스의 행동(파일 오프셋 `11958D`)을 바꿔 주문을 걸게 했습니다. 기록은 `sfc/dq5/tools/lua/dq5battle.lua` 로 했습니다.

## 2. 대상 수는 범위 비트가 아니다

파파스의 メラ·ギラ·イオ 는 한 마리, スライム 그룹 셋, 다섯 마리 모두에게 들어갔습니다. 이번에는 대상이 두 그룹이라 「그룹」과 「전체」가 갈리는데도 범위 비트를 바꾼 효과는 없었습니다.

```
メラ 26:8766 = E2(전체)  → 070 069            (한 마리)
ギラ 26:8769 = E4(전체)  → 070 069 069 069    (한 그룹)
イオ 26:876C = A5(하나)  → 070 069 069 069 069 (모두)
```

몬스터 행동 고르기에서는 범위 값이 0(자신)인지만 쓰이고, 대상 수를 정하는 곳은 찾지 못했습니다. 롬에서 メラ·ギラ·イオ 순서로 값이 「하나·하나·하나 / 그룹·그룹·그룹 / 전체·전체·전체」인 표를 비트 마스크별로 찾아도 `26:8765` 밖에 나오지 않았습니다.

## 3. 내성 11종

파파스가 주문 하나만 쓰게 하고 スライム·ドラキー 레코드의 바이트12~16 을 둘 다 그 종류만 3 인 값과 0 인 값으로 바꿔, 22번 돌렸습니다(`ROMPATCH="11958D=<주문 x6>;11800C=<5바이트>;118057=<5바이트>"`).

```
52 イオ      3: 079 079 079 079 079   0: 069 069 069 069 06C …
56 ザキ      3: 079                   0: 07C (いきのねを とめた)
58 マヌーサ  3: 079 079 079           0: 085 085 085 (まぼろしに つつまれた)
59 ニフラム  3: 079 079 079           0: 081 081 081 (ひかりのなかへ けしさった)
5A ルカニ    3: 079                   0: 08C (しゅびりょくを さげた)
5D メダパニ  3: 079 079 079           0: 087 087 087 (こんらんした)
```

53 ヒャド, 54 バギ, 55 ライデイン, 5B マホトラ, 5C マホトーン 도 같았습니다. ニフラム 은 처리 루틴에 `LDX #59` 가 있어 처음 파싱에서 빠졌고, ルカニ 는 `LDA #5A` 로 다른 루틴에 넘깁니다.

## 4. 상태 주문의 값

상태 주문 루틴 `20:AE41` 은 처리 루틴이 넣은 A 값을 대상이 우리 쪽일 때 쓰고(`20:AE1D`), 몬스터 쪽일 때는 내성으로 `27:8065` = 128, 89, 38, 0 을 봅니다.
슬라임 행동을 몬스터용 ラリホー(`4B`, 처리 루틴 `20:B410`: `LDA #03 / LDX #57 / JMP AE41`)로 하고 MP 를 `POKE` 로 채워 주인공에게 걸게 한 뒤, `LDA` 의 값(파일 오프셋 `103413`)만 바꿨습니다.

```
0: 070 079 070 079 070 079 … (6번 모두 きかなかった)
1: 070 079 070 079 070 079 …
2: 070 03E (ねむってしまった)
3: 070 03E
8: 070 03E
```

난수가 같아 첫 시도의 난수(0~7)가 1 이었고, 값이 그보다 커야 걸립니다. 난수(0~7) < 값, 곧 값/8 의 확률로 정리했습니다.

## 5. 동료가 되는 몬스터

필드 `76`·`77` 을 읽는 `20:C1ED`·`20:C241` 을 따라가니 전투 뒤 동료 처리였습니다. `$1117`(마지막에 쓰러뜨린 몬스터)의 `76` 이 확률 등급, `77` 이 동료 종류이고, `7E:29EA[종류]` 의 하위 4비트(이미 들인 수를 비트로)에 따라 `27:8162`·`8172`·`8182` 중 하나에서 1/N 을 뽑습니다.

처음에는 확률 칸(`27:8162[7]`, 파일 오프셋 `138170`)을 1 로 바꾸고 이겨도 동료가 되지 않았습니다. 그 앞에서 플래그(`BRK #0B` 의 `2140`)·`$1010`·레벨을 검사하는데, `20:8000` bit0 이 켜져 있으면 그 검사를 건너뜁니다.
이 비트(파일 오프셋 `100000`)를 함께 켜자 「なんと スライムが おきあがり なかまに なりたそうに こちらをみている！」 뒤에 「スライムが なかまに くわわった！」가 나왔습니다.

같은 조건에서 필드 `76` = 0 이면 안 되고, `76` = 1 과 `27:8162[1]` = 1 이면 됐습니다. `7E:29EC`(スライム 의 종류 2) = `07` 이면 안 되고, `01` 과 `27:8172[7]` = 1 이면 됐습니다.

## 6. 동료 레코드

동료로 들어온 슬라임은 파티 레코드 셋째(`7E:2094`)에 `82 80 08 00 00 00 03 08 05 01 03 …` 로 들어갔습니다. `23:AED1 + 종류*9` 의 슬라임 칸 `01 63 08 05 01 03 08 00 01` 과 겹치는 값이 많아, 칸을 `02 10 11 22 33 44 55 66` 으로 덮고 다시 들였습니다.

```
82 80 55 00 66 00 03 11 22 33 44 4B 00 00 55 00 66 00 02 10 …
```

+0 이 처음 레벨(`+12`), +1 이 최대 레벨(`+13`), +2~+5 가 파티 레코드 `+7`~`+A`, +6 이 HP(`+2`·`+E`), +7 이 MP(`+4`·`+10`)였습니다. +8 하위 4비트는 앞 일지의 장비 갈래입니다.

## 틀렸던 것들

- 몬스터 필드 `6E`(바이트8 bit4-5)는 `27:8051` 로 「ひらりと みをかわした」 갈래를 고르는 코드라 몬스터가 피하는 확률로 보고 スライム·ドラキー 를 3 으로 바꿨지만, 6,000프레임 동안 피한 수가 3 → 3 으로 그대로였습니다. 그 갈래가 실행될 때 읽힌 값은 0 이었습니다(누구의 값을 읽는지 아직 모름).
- 범위 비트가 플레이어 쪽에서만 쓰일 수 있어 주인공이 주문을 쓰게 하려 했지만, 이 시점의 어린 주인공은 명령 창에 じゅもん 이 없어 해 보지 못했습니다.
- `wwatch` 식으로 `$112B`·`$10F6` 쓰기를 잡으려 했으나 `00:1100`~`1130`·`7E:` 미러 어느 쪽으로도 쓰기 콜백이 잡히지 않았습니다(같은 방법으로 `00:07D2` 는 잡힘). 이유는 아직 모릅니다.

## 남은 것

- 주문 대상 수를 정하는 곳, 플레이어 명령 입력(`20:8700`)의 범위 비트
- 내성 5E·5F·60·61, `20:AEC6`·`AEFF` 에 넘기는 값
- 동료 조건(플래그 `2140`·`$1010`·레벨)을 디버그 비트 없이 실측, `23:AED1 +8` bit4-7, 파티 레코드 `+6`
- 몬스터 필드 `68`·`69`·`6D`·`6E`, 시작 상태 `39`
- 물건 표 k1~k4 플래그: 조회 표 `21:A3FF` 를 부르는 BRK 를 찾아 쓰는 곳 확인
