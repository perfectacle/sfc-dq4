# 2026-10-25-41: 여관·교회 값, 격투장·슬라임 레이스 倍率, 계단을 만드는 내용물

[앞 일지](2026-10-25-11-shop2.md)에서 남긴 가게 값과 상자 내용물을 이어서 확인했습니다. 결과는 [dq5-data-format.md](../docs/dq5-data-format.md) 의 「여관」「교회·코인 판매·맡기는 곳·카지노」「격투장」「슬라임 레이스」,
[dq5-map-format.md](../docs/dq5-map-format.md) 의 「두 칸 앞」「내용물 값」에 있습니다.

가게는 앞 일지처럼 선실 파파스의 대화 번호를 `POKE="7E36EB=<번호>;7E370B=00"` 으로 바꿔 열고, 메시지 번호와 값은 툴킷 `probe/trace.lua` 로 `24:8BAF` 의 A 와 RAM 을 찍었습니다.
실제 맵의 계단은 `sfc/dq5/tools/lua/dq5warp.lua` 로 내려서서 `tools/lua/wsnap.lua` 로 WRAM 을 떠 비교했습니다.

## 1. 여관 값은 일행 수를 곱한다

여관 값의 곱셈 횟수는 필드 45(일행 수)입니다. 필드 표를 풀어 보니 묶음 4(`7E:2000`)의 `+1D`, 곧 `7E:201D` 를 읽고 후처리 `21:99FD` 가 그 수만큼 일행 레코드를 `21:92FF` 로 검사해 셉니다.
그래서 `7E:201D` 만 2 로 하거나 둘째 레코드 첫 바이트(`7E:206A`)만 `80` 으로 하면 그대로 혼자였고, 둘 다 바꿔야 했습니다.

```
일행 1                          0F28 = 1A   ひと晩 26ゴールド
7E201D=02;7E206A=80             0F28 = 34   52
7E201D=03;7E206A=80;7E2094=80   0F28 = 4E   78
```

둘이서 첫 항목을 `17 07` 로 덮고 실제로 묵자 금화(`7E:2019`)가 20 에서 6 이 되었습니다.

값 bit7 은 `06:E44F` 에서 잘 때의 `$198E` bit7 로 갑니다. 같은 항목을 `17 87`·`17 07` 로 하고 묵은 뒤 `$198E` 는 `80`·`00` 이었습니다.
`$198E` 를 읽는 곳은 `00:E209`(하위 2비트로 깬 뒤 방향)와 `00:E360`(bit7)이고, `00:E360` 은 따라오는 동료를 주인공 칸에 겹쳐 둘지(`00:E59F`) 줄을 세울지(`00:E5B0`) 고릅니다.
선실에는 따라오는 동료가 없어 이 갈래까지는 실행되지 않았습니다.

## 2. 교회·코인 판매·맡기는 곳

교회 메뉴는 `$E8` 0~4 가 おいのり·おつげ·いきかえらせる·どくのちりょう·のろいをとく 입니다. 되살리기를 고르면 인물 창이 뜨는데, 주인공 HP(`7E:204E`)를 0 으로 해도 레코드 `+1` bit7 을 켜도
「なんと　…どのは　死んでおりませんぞ！」(97)였습니다. 죽음 검사(필드 3E, 후처리 `21:99AA`)가 단순한 비트가 아니었습니다.

값을 보는 것이 목적이라 검사 갈림을 `BRA` 로 덮었습니다(파일 `3614F`·`3625B`·`362D9`).

```
되살리기  레벨(7E2052) 0C → 0F28 = 78(120)   21 → 14A(330)    메시지 B0「…ゴールドの　ご寄付を」
저주      레벨 21 → 14A(330)
독        5
```

필드 27 은 묶음 0(일행 레코드)의 `+12` 이고 다른 일지에서 주인공 레벨로 확인된 자리입니다. 되살리기는 `06:F625`, 저주는 `06:E279` 가 10 을 곱합니다.

코인 판매는 다섯 자리 입력 창에서 위를 눌러 한 장·석 장을 고르자 `$0F28` 이 `14`·`3C`(20·60)였습니다.
맡기는 곳은 금화를 5000 으로 두고 금화를 골라 2 를 넣자 「2000ゴールドですね」(BE)였고, `BRK 88 98` 에 단위 수 2 가 넘어갔습니다.

## 3. 격투장

`26:8E5A` 는 롬 `01:8000` 이 0 이 아니면 주인공 레벨(`BRK 8A 27`)로 `23:DC27` 문턱 50개를 훑어, 넘지 않는 마지막 시합까지에서 난수로 고릅니다.
시합은 `23:DA97 + 시합*8` 의 `[몬스터][倍率]` 넷이고, 倍率 정수는 `$115A`, 소수는 `$115E` 로 갑니다.

선실(레벨 1)에서 말을 걸자 시합 9 가 나왔습니다.

```
표   いっかくウサギ 2  ドラキー 5  グリーンワーム 3
RAM  $115A = 01 04 02, $115E = 07 07 07
창   1.7  4.7  2.7
```

소수 난수가 4 이상이면 3 을 더하고 정수에서 1 을 빼므로, 倍率은 표 값의 ±0.3 안에서 움직입니다(코드 읽기, 이번 실측은 한 번).

## 4. 슬라임 레이스

코인 검사(`06:F210`, 파일 `37210`)를 `BRA` 로 덮고 설명을 거절하자 레이스 화면에 倍率 10개가 떴습니다. 이 값은 롬에 없었고, WRAM 에서 `7E:1299` 에 그대로 있었습니다.
쓰기 감시로 쓰는 곳을 찾으니 `11:E06C` 였고, 바로 앞 `11:E043` 이 쌍 표 `11:E02F`(1-2, 1-3 … 4-5)를 따라 `7E:12AD + 슬라임` 두 값을 `11:DF49` 에 넘기고 있었습니다.

```
7E:12AD = 1A 07 4B 84 10   (합 256)
倍率    = 1-2 91, 1-3 9, 1-4 5, 1-5 39, 2-3 27, 2-4 14, 2-5 151, 3-4 2, 3-5 15, 4-5 7
```

다섯 값의 합이 256 이라 이기는 확률의 무게로 보입니다. 순서 무관 두 마리가 1·2착 할 확률로 계산해 보면 3-4 는 맞지만 2-5 는 280 이 나와 화면의 151 과 달랐습니다. `11:DF49` 는 아직 읽지 않았습니다.

## 5. 계단을 만드는 내용물

`D003`(01/05 (64,18), 발밑)은 `dq5warp.lua TO=01/05,64,19` 로 내려서서 바로 しらべる 했습니다. 28C·150 이 나오고, 하지 않은 것과 셀 버퍼를 비교하자 30바이트가 달랐습니다.

```
(63,18)~(64,19) 블록 C7 → A0 A1 A2 A3, +4 → 05 (오른쪽 아래만 85)
의자(+6·+7)는 (63,20)~(64,21) 로 옮겨짐
(51,20) +4 85 → 00, (3,20) +4 80 → 00
```

`1F:FA9B` 가 고정 주소에 블록을 쓰고 `LDX #$3F / LDY #$12` 로 자리를 잡는 코드와 같았습니다. 지워진 (51,20) 은 맵에 처음부터 있던 빈 곳 출구 셀입니다.
출구는 셀 순서로 번호가 매겨지니, 빈 곳에 출구 하나를 미리 두었다가 계단이 생길 때 그 자리를 옮기는 방식입니다.

`D008`(06/05 (30,16))도 같았습니다(계단 (30,15)~(31,16), 출구 (31,16), 지우는 칸 (18,24)).
`D006`(03/02 (31,13))은 처음에 찾아지지 않았습니다. 발밑 표의 `+4` 가 이 항목만 2 였고, 앞 일지에서 방향으로 적었던 `$C3` 이 실은 주인공 층이었습니다.
`TO=03/02,31,13,2`(층 2)로 내려서자 찾아져 계단 (31,12)~(32,13), 출구 (32,13), 지우는 칸 (55,6) 이 나왔고, 층 1 이면 찾지 못했습니다.

## 6. `D005` 와 두 칸 앞 표

`D005` 는 앞 일지의 세 표 어디에도 없었습니다. `$1E73` 에 쓰는 곳 10군데를 보니 `12:FD02` 가 `1E:F435` 표에서 읽고 있었고, 그 표의 2F/01 (8,7) 이 `D005` 였습니다.
이 표를 부르는 `12:ED48` 은 방향에 따라 두 칸 앞 줄의 세 칸을 찾습니다. 항목 0 을 선실 (7,11) 로 덮자 시작 자리에서 しらべる 로 やくそう 가 나왔고, 내용물을 `D005` 로 하면 155·152 였습니다.

## 7. `D001`·`D002`·`D009` 와 `01:868B`

- `D001` 은 `POKE="7E1948=01"` 이면 12C 만 나오고 맵이 바뀌지 않았습니다. `D002` 는 같은 `$1948` 검사로 갈라집니다.
- `D009` 는 `POKE="7E21A8=04"` 로 열자 12B 뒤 `7E:21A1` 이 `71` → `F1` 이 되고 다른 메시지 없이 끝났습니다(`12:F6D9 BRK 0C 80 11`).
- `01:868B` 는 `26:8DF1` → `26:8E0A` 로 [이벤트 전투 무리](../docs/dq5-data-format.md#이벤트-전투-무리-23d757) `23:D757 + 번호*13` 을 씁니다. `0C`~`0F` 는 ミミック·ひとくいばこ·ツボック·あくまのツボ 한 마리씩이었습니다.

## 틀렸던 것들

- 발밑 표 `+4` 는 주인공 방향이다: 주인공 층(`$C3`)이었다. 선실에서 `+4` = 2 가 안 찾아진 것은 방향이 아니라 층이 1 이어서였다.
- `7E:201D` 나 레코드 첫 바이트 하나만 바꾸면 일행이 는다: 둘 다 있어야 필드 45 가 센다.
- 두 칸 앞 표는 번호와 마스크가 뒤바뀌어 있다: 실험에서 내가 두 바이트를 거꾸로 덮은 것이었다. 실제 항목대로면 `7E:223C`~ 이다.

## 남은 것

- 교회의 죽음·독·저주 상태 비트(필드 3E 등), 맡기는 곳 한도, 여관 bit7 의 화면 차이(따라오는 동료가 있는 장면).
- 격투장 상금, 슬라임 레이스 倍率 식(`11:DF49`)과 다섯 값(`7E:12AD`)을 정하는 곳.
- `D005` 의 빨간 빛 갈래 플래그, 두 칸 앞 표를 실제 맵에서 열기.
