# 2026-10-25-153: 옮긴 레코드 자리 다시 재기, VRAM 배치, 창 머리 +0 bit5·6

[2026-10-25-140](2026-10-25-140-hangul4.md) 에서 고른 `7E:1C33`~ 를 읽기 감시와 실행 감시로 다시 쟀고, BG3 칸을 넓히는 길의 근거로 장면별 VRAM 배치를 덤프했고, 창 머리 `+0` bit5·6 의 갈래를 읽었습니다.
결과는 [dq5-hangul-format.md 「시제품」](../docs/dq5-hangul-format.md#시제품) 과 [dq5-text-format.md 「창 레코드 머리」](../docs/dq5-text-format.md#창-레코드-머리) 에 있습니다.

## 1. 7E:1C33~ 도 비어 있지 않았다

선실·필드·전투 세이브스테이트의 `7E:1C30`~ 을 덤프하자 `1C38`~`1C52` 에 `7E 3C C3 66 99 66 …` 같은 자료가 있었습니다. 필드 실행의 첫 쓰기 기록에서 `02:ACB2`~`ACEC` 가 `7E:1C0D`~`1C31` 을 썼습니다.
무기점 실행에서는 `06:F534` 의 목록 훑기가 `7E:1C33`·`1C4B` 를 읽었습니다(파파스 대화 번호를 가게로 바꾼 실험이라 목록 주소가 낮은 WRAM 을 가리킨 것으로 보임).

## 2. 7E:1ABC~ 로 다시

`dq5msg.lua` 에 읽기 감시(`WRAMWATCHREAD`)와 감시 시작 프레임(`WWFROM`)을 더하고, 일곱 실행에서 `7E:1ABC`~`1BB1` 을 봤습니다.

```sh
STATE=$PWD/work/state/sp2-battle.mss PRE="$B" MAXF=2500 WRAMWATCH=1ABC-1BB1 WRAMWATCHREAD=1 \
  SHOT_DIR=$PWD/work/proof/battle "$MESENCE" --testrunner "$PWD/rom/dq5.sfc" "$PWD/sfc/dq5/tools/lua/dq5msg.lua"
```

```
새 게임(1,600~) w 0 r 0   전투 w 0 r 0   필드 w 0 r 0   무기점 w 0 r 1(06:F53D)
교회 w 0 r 0   이벤트 전투 w 0 r 0   일행 메뉴 w 0 r 0
```

이 범위를 가리키는 명령 모양 1,373곳(자료 바이트 포함)에 실행 감시를 걸었을 때 실행된 곳도 없었습니다. 다만 실행 커버리지를 통째로 모으는 방법(`COVER`)은 1,000프레임만 돌려도 MesenCE 테스트 실행이 끝나지 못해 쓰지 못했고, 간접·DP 접근은 감시로만 잡히므로 증명은 아닙니다. `proto --long` 의 복사 자리를 `7E:1AC0` 으로 옮겼습니다.

## 3. VRAM 배치

다섯 장면의 PPU 상태가 모두 BG2 타일맵 `0000`, BG1 타일맵 `0800`, BG3 글자 `1000`, BG3 타일맵 `1C00`, BG1·BG2 글자 `2000`, OBJ `6000` 이었습니다. BG3 글자는 384칸에서 타일맵에 막힙니다.
타일맵이 가리키는 칸만 세면 장면마다 비는 BG1·BG2 글자 자리가 있었지만(선실 `2010`~`2B3F`, 필드 `3780`~`5FFF`), 맵 전체의 타일이라 걸으면 바뀝니다.

## 4. 창 머리 +0 bit5·6

`+0` bit6 이 켜진 창은 `04:9FD3` 에서 높이를 일행에 맞추는 갈래로 갑니다. bit5 가 켜져 있으면 `BRK 88 45`(일행 수)로 높이를 정하고, 꺼져 있으면 지금 메뉴 번호(`$09FF`)마다 다른 규칙으로 셉니다.
앞서 일행 창 `0E` 에서 bit6 을 끄면 한 줄, bit5 를 끄면 셋 중 둘이 나온 것과 맞습니다.

## 틀렸던 것들

- 다섯 실행에서 안 쓰인 자리를 빈 자리로 보았다(`7E:1C33`~): 세이브스테이트에 자료가 남아 있었고 필드 루틴이 바로 앞을 썼다.

## 남은 것

- `7E:1ABC`~ 의 간접·DP 접근까지 증명, BG3 칸을 넓히는 두 길(타일맵 옮기기, BG1·BG2 글자 빌리기)
