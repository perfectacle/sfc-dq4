# 2026-10-26-19: 사람 동료 칸과 ルイーダ, 신부 고르기의 일행, 주인공 이름의 넷째 A

[일지 2026-10-26-12](2026-10-26-12-party3.md)와 [일지 2026-10-26-07](2026-10-26-07-native-ev.md)의 남은 것 넷을 실측했습니다. 주인공 이름 입력은 넷째 A 뒤 커서만 おわり 로 가고, 사람 동료 칸 `7E:294A` 는 ルイーダ·석상 장면·신부 고르기가 씁니다. 결과는 [dq5-data-format.md 「사람 동료 칸」](../docs/dq5-data-format.md#사람-동료-칸-7e294a)·「맡길 수 없는 동료」·「이름 입력 창」과 [dq5-text-format.md 「네이티브 호출」](../docs/dq5-text-format.md#네이티브-호출)의 `F792` 에 있습니다.

## 1. 주인공 이름의 넷째 A

롬을 처음 쓰는 이름으로 복사해 빈 SRAM 으로 켜고(MesenCE 가 롬 이름마다 SRAM 을 남기므로 한 번 돌릴 때마다 새 이름을 씀), A 를 60프레임마다 누르면서 이름 판에서 4프레임마다 화면을 찍었습니다.

```sh
PRE="wait:56,a:4,…(13번)…,wait:200" SHOTS="652,656,…,736" CALLS=038B72,038BE0,038C04,038D09 LOG=7E00CA,7E00CC,7E00E8 \
  MAXF=780 SHOT_DIR=$PWD/work/name "$MESENCE" --testrunner "$PWD/work/<새 이름>.sfc" "$PWD/sfc/dq5/tools/lua/dq5msg.lua"
```

```text
419 038B72                       이름 판
479·539·599 038BE0  $CA=0·1·2    あ 셋
659 038BE0 / 038C04 $CA=4        넷째 あ, 668프레임부터 커서가 おわり
719 038D09  $CC=$E8=3B           다섯째 A(おわり)
728                              말 빠르기 창
```

넷째 A 는 글자를 넣고 커서를 おわり 로 옮길 뿐이고, 말 빠르기 창은 다섯째 A 뒤에 떴습니다. 아기 이름 실측과 같습니다.

## 2. 사람 동료 칸에 쓰는 곳

`21:A85C` 를 직접 부르는 `JSR`·`JSL` 은 없었습니다. `BRK 80`~`93` 처리기(`00:8FC9` → `00:9197`)를 읽으니 홀수 명령은 바이트 하나를 `$3F` 에 먼저 읽고, `00:920A` 표의 비트로 다음 바이트를 일행 루틴 번호 `$38` 에, A 를 `$42`(레코드 번호)·`$43` 에 둡니다. `BRK 88 n` 은 루틴 n 만, `BRK 8A n` 은 `$42` = A, `BRK 8C n` 은 `$42`·`$43` = A 의 아래·위 바이트입니다. 루틴 번호 표는 `21:8E8C`(n < `80`)·`21:8F8C`(n ≥ `80`)이고, `21:A85C` 는 `BC`, 칸에서 데려오는 `21:AA63` 은 `BD` 였습니다.

롬에서 `BRK 8C BC`·`BRK 89 80 BC` 를 찾으니 일곱 곳이었습니다. `06:EDA2` 는 메시지 `479`~`481`(ルイーダ) 사이, `05:F504` 는 ルドマン 의 `357` 뒤, `02:F8FC` 의 넷은 `21AE` 의 비트마다 인물 `01`·`02`·`05`·`06` 을, `05:FB7D` 는 신부를, `06:F7C8` 은 `F792` 의 ビアンカ 갈래였습니다.
ルイーダ 의 대화 번호는 대화 처리기 표 `06:DBDB` 에서 `ED01` 이 열한째(`00A`)인 것으로 찾았고, 모든 맵의 인물 목록을 훑자 02/02 (4,56) 의 대체 목록(`21AD.4`) 하나에만 있었습니다.

## 3. ルイーダ 에서 빼고 넣기

인물 레코드 표 `23:C014 + 번호 × 42` 의 칸을 그대로 일행 레코드 1(`7E:206A`)에 쓰고, 선실 파파스를 대화 번호 `00A` 로 바꿔 なかまをはずす 를 골랐습니다. 처음 세 번은 사람 목록이 뜨기 전에 아래를 눌러 주인공이 골라졌습니다. 「誰を はずすの？」(`477`)가 A 를 기다리는 창이라, A 로 넘긴 뒤 100프레임 기다려 아래를 누르니 ピピン 이 골라졌습니다.

```text
1069 21:A85C   201D 2 → 1
칸 0  86 80 50 00 00 00 23 28 1D 14 0F 00 00 00 50 00 00 00 01 63 | 0C 50 78 8A | 0D 00 00 00 F4 00 00 01
```

칸은 레코드 `+0`~`+13`(`+0` 에 bit7), 장비 넷, 레코드 `+22`~`+29` 입니다. やくそう 를 하나 더 쥐여 주면 맡긴 물건 `7E:22F1` 이 1 늘었고, なかまをくわえる 로 데려오자 레코드가 원래대로(やくそう 만 빠짐), 칸은 모두 0 이 되었습니다.
02/02 (4,58) 에 `dq5warp.lua` 로 내려 진짜 ルイーダ 에게 말을 걸어도 같은 바이트였습니다(세이브스테이트 `work/state/dq5-luida-0202.mss`).

인물마다 바꿔 보니 주인공·ヘンリー·パパス·ベラ 는 「まだ やらなくては いけないことが…」(`47C`), キラーパンサー 는 「モンスターさんは うちでは ちょっとね」(`47D`)였습니다. サンチョ 의 `+29` 만 `02`·`03` 으로 바꾸면 `47C`, `08`·`09` 면 빠졌으니, `47C` 를 가르는 것은 `+29` bit1 입니다. フローラ 는 칸 `+0` 이 `87`, 칸 `+18`·`+1F` 가 `03`·`01` 로 바뀌었습니다(`21:A802` 가 레코드 `+22` = `DF` 를 따로 다룸).

## 4. 석상이 돌아오는 장면

`02:F8FC` 를 부르는 `05:F3EC` 는 03/02 대체 목록 `10:A392` 의 (31,7) 인물 스크립트 끝에서 불립니다. 이 목록은 `21BA.4` 일 때 놓이므로 `TO=03/02,31,9 SET="2190|60;1948=02;21BE|20;21BA|10;21AE|74"` 에 일행 다섯을 함께 써서 내렸습니다(세이브스테이트 `work/state/dq5-statue-0302.mss`). 도착하자마자 「なんと 石像のまわりを やさしい光が つつんでいる！」가 떴고, A 를 넘기자 이렇게 되었습니다.

```text
447 05:F3EC
723 02:F8FC → 21:A85C ×4   201D 5 → 4 → 3 → 2 → 1
칸 0~3  81 …(아들)  82 …(딸)  85 …(サンチョ)  86 …(ピピン)
21AE 74 → 02, 21B7 = 20, 02/07 (38,27) 로 옮겨 57C~57E
```

## 5. 신부 고르기의 BRK 8A 48·8A E9

`06:F7B4` 의 `BRK 88 BD` 는 칸 0 을 일행에 넣고, `BRK 8A 48`(루틴 `48` = `21:9F9F`)은 인물 번호 A(`03`) 레코드를 지우며, `BRK 8A E9`(`21:9FD8`)는 그 레코드를 찾아 `$47` 에 둡니다. 앞 세션에서 본 「일행 수 1 → 2」는 `dq5warp.lua` 로 만든 세이브스테이트의 칸 0 이 비어 있어서였습니다. 0 바이트 칸이 인물 `00` 레코드로 들어오고, 인물 `03` 을 찾지 못해 그대로 남았습니다.
실제 게임에서는 물의 반지 뒤 `05:F504` 가 ビアンカ 를 칸에 넣어 두므로, ルイーダ 로 만든 ビアンカ 칸을 `dq5-bride-1f08.mss` 첫 프레임에 써 두고 두 신부를 다시 골랐습니다.

```text
フローラ  2305 21:AA63/A89F 201D 1→2, 21:9F9F 2→1, 칸 0 빔
ビアンカ  2425 21:AA63/A89F 201D 1→2, 21:9FD8($42=03), 21:A85C 2→1, 칸 0 에 같은 32바이트
```

フローラ 를 고르면 ビアンカ 는 장비까지 사라지고, ビアンカ 를 고르면 칸 0 으로 돌아갑니다. 결혼식 뒤 フローラ 는 인물 레코드 표에서(`05:F6D8`), ビアンカ 는 칸 0 에서(`05:F6FF`) 일행에 들어오는 것으로 읽힙니다.

## 6. `0EE` 가 나오는 레코드

`+0` bit7 이 켜진 레코드는 몬스터 동료와 キラーパンサー 뿐입니다. 몬스터의 `+29` 는 `21:8204`·`21:A9A0` 이 `02` 로 쓰고, キラーパンサー 는 인물 레코드 표 칸 `0B` 의 `8A` 를 그대로 받습니다. 칸 `0B` 를 그대로 일행에 두고 モンスターじいさん 에게 맡기자 `0F2` 로 맡겨졌습니다(칸 0 = `80 80 2C …`). 필드 `E5`(`+29` 쓰기)를 `BRK` 로 부르는 코드도 주인공을 고치는 `02:9BEE` 뿐이라, 보통 게임에서 `0EE` 가 나오는 레코드는 없습니다.

## 틀렸던 것들

- 주인공 이름은 넷째 A 에서 바로 말 빠르기 창으로 넘어간다고 적었습니다. 100프레임 간격 화면 사이에 다섯째 A 가 끼어 있었던 것입니다.
- `F792` 뒤 일행 수가 1 → 2 가 된다고 적었습니다. 사람 동료 칸이 빈 세이브스테이트에서만 그렇고, 실제 게임에서는 두 갈래 모두 1 로 돌아옵니다.
- ルイーダ 의 `06:ED64`(`BRK 89 80 E4` 뒤 `$46` 시프트)를 보고 `+29` bit3 으로 가른다고 짐작했습니다. サンチョ 의 `+29` 만 바꾼 실측으로 bit1 임을 확인했습니다.

## 남은 것

- `21:8923`·루틴 `BD` 가 `2190.5` 이고 `21B7.5` 가 꺼져 있으면 칸 번호에 1 을 더하는 갈래.
