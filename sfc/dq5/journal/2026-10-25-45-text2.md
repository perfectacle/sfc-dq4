# 2026-10-25-45: 끝 코드, 이름 변수, 몸짓, 일행 조회와 대화 조건

[2026-10-25-07](2026-10-25-07-textctl.md) 에서 남긴 텍스트 쪽 빈칸을 메웠습니다. 대화 조건이 부르는 `BRK 88`·`89`·`8B` 는 일행 레코드를 읽는 필드 조회였고, 일행을 `SET` 으로 만들어 조건 `03`·`11`·`13`·`20`·`14` 의 뜻을 갈랐습니다.
메시지에 한 번도 쓰이지 않은 이름 변수는 허프만 트리의 잎을 바꿔 띄웠고, 끝 코드 셋의 차이, `1100` 번대 몸짓의 화면, 창 레코드 머리 일부를 확인했습니다. 한글을 넣을 때의 제약을 정리하고, 새 글자 코드 `3DB` 를 실제로 늘려 「한」 을 띄웠습니다.
결과는 [dq5-text-format.md](../docs/dq5-text-format.md) 의 「끝 코드」·「몸짓 코드」·「일행 조회」·「창 레코드 머리」·「한글 넣기 준비」 에 있습니다.

## 1. 실험 드라이버

실험마다 같은 일을 했습니다. 선실 세이브스테이트를 불러 롬을 덮고, WRAM 을 고친 뒤 파파스에게 말을 걸어, 그동안 지나는 PC 와 쓰기를 적고 화면을 찍습니다.
이것을 프로브 하나 `sfc/dq5/tools/lua/dq5msg.lua` 로 묶었습니다. `SET` 은 첫 프레임에 한 번, `POKE` 는 매 프레임 고칩니다. 결과는 `msg.txt` 와 `end.png` 입니다.

```sh
export LIBDIR=$(uv run --locked krpatch sfc lua)
TALK="b:4,wait:40,up:3,wait:20,a:4,wait:30,a:4,wait:150"
STATE=$PWD/work/state/ship.mss PRE=$TALK MAXF=300 CALLS=248BAF \
  ROMPATCH="3012D=070305616B0B61293F" SET="206A=05;206B=80;201D=02;201E=02;2021=01" \
  SHOT_DIR=$PWD/work/cond/03-05 "$MESENCE" --testrunner "$PWD/rom/dq5.sfc" "$PWD/sfc/dq5/tools/lua/dq5msg.lua"
```

`ROMPATCH` 는 파파스 스크립트를 `07 03 05 61 6B 0B 61 29 3F`(조건 `03 05` 가 참이면 메시지 `16B`, 거짓이면 `129`)로 덮고, `SET` 은 일행 레코드 둘째(`7E:206A`)에 サンチョ(`05`)를 넣어 일행을 둘로 만듭니다.

## 2. BRK 80~93 은 필드 조회

`BRK` 처리기(`00:8F80`)에서 `80`~`93` 은 한 곳(`00:9197`)으로 모였습니다. 번호 bit0 이 켜져 있으면 한 바이트를 `$3F` 로 더 읽고, `00:920A` 표의 비트에 따라 다음 바이트나 부른 쪽 레지스터를 `$38`·`$42`·`$43`·`$44` 에 넣은 뒤 `21:8AF8` 을 부릅니다.
`21:8AF8` 은 몬스터 레코드를 읽던 필드 읽기 루틴이었고, `$38` 이 필드 번호입니다. 설명자를 풀어 보니 조건이 쓰는 필드는 묶음 0(일행 레코드 `7E:2040`, 42바이트)과 묶음 4(`7E:2000`)였습니다. 이것을 `dq5talk.py --field` 로 찍게 했습니다.

```
field 3E: 묶음 0 (7E2040, 42바이트) +1 길이 1 후처리 21:99AA
field 90: 묶음 4 (7E2000, 24바이트) +28 길이 1 간접 후처리 21:975E
field DB: 묶음 4 (7E2000, 24바이트) +29 길이 1 간접 후처리 21:9A40
field 45: 묶음 4 (7E2000, 24바이트) +29 길이 1 간접 후처리 21:99FD
```

후처리를 읽자 `$3F` 는 일행 거르개였습니다. `21:92FF` 가 일행 순서(`7E:2020`~)의 레코드마다 bit6 이면 `+1` bit7, bit2 면 `+0` bit7 을 보고, bit4·3 이 마차 밖(`7E:201E` 명)·안 범위를 고릅니다.
그러면 조건 `03` 은 「인물 번호 인자가 마차 밖에 살아 있음」(`BRK 8B 48 DB`), `20` 은 「인물 번호 02 가 마차 밖에 살아 있지 않음」(`BRK 89 4C 45`), `11` 은 「누군가 물건 인자를 가짐」(필드 `90` 이 필드 `33` 으로 일행을 훑음), `13` 은 「레코드 인자 번째의 `+1` bit7」 이 됩니다.
`14` 는 `21:8000` 이 시간대 `7E:075E` 를 `F0` 과 견주는 것이라 낮인지입니다.

## 3. 조건을 일행으로 가르기

예측대로 나오는지 일행을 바꿔 가며 보았습니다(`msg.txt` 의 `248BAF` A 값).

```
c03_00 016B   c03_k5 016B   c03_k5dead 0129   c03_k5wagon 0129   c03_k5none 0129
c20_none 016B   c20_k2 0129   c20_k3 016B
c13_00dead 0129   c13_01 016B   c13_01b 0129
c11_42 016B   c11_01 0129   c11_01have 016B
c14_day 016B   c14_night 0129
```

`k5dead` 는 `206B` = `00`, `k5wagon` 은 `201E` = 1, `c13_01b` 는 `206B` = `40`, `c11_01have` 는 주인공 첫 칸(`7E:2058`)에 たけのやり(`01`), `c14_night` 는 `7E:075E` = `0100` 입니다. 16개가 모두 예측과 같았습니다.
`+1` bit7 이 살아 있음인지는 전투에서 확인했습니다. 슬라임·ドラキー 전투 세이브스테이트에서 A 만 눌러 주인공이 쓰러지게 두자 `7E:2040` 이 `00 80 18` → `00 80 07` → `00 00 00` 이 되었습니다(`+2` 가 HP).

## 4. 인물 번호

조건 `03` 의 인자는 일행 레코드 `+0` 의 인물 번호입니다. 둘째 레코드에 번호를 넣고 `1008`(`$F5` = 1, 메시지 `00C`)로 이름을 띄웠습니다.

```
01 クーパー(아들 7E:2009)  02 アニー(딸 7E:2011)  03 ビアンカ  04 ビアンカ  05 サンチョ  06 ピピン
07 フローラ  08 パパス  09 ヘンリー  0A ベラ  0B パパスのむすこ  0C やどやのむすめ  81 ボロンゴ  82 スラリン  83 ドラきち
```

스크립트에서 `03 03`·`03 07` 이 조건 `1F`(신부가 ビアンカ) 갈래 안에 들어 있어, `03` 이 어른 ビアンカ, `07` 이 フローラ 인 것과 맞습니다. `03 09` 뒤에는 「ヘンリー「…………」 가 나옵니다.

## 5. 메시지에 없는 이름 변수

`1009`·`100C`·`100E`·`1014`·`101B` 는 메시지 3,200개에 한 번도 쓰이지 않았습니다. 허프만 트리를 훑어 보니 잎이 991개이고 이 코드들은 잎이 아예 없었습니다.
그래서 메시지 `008`(「{100A}ですね」)의 잎 `100A`(파일 오프셋 `1211F4`, `0A 90`)를 다른 코드로 바꾸고 `$F5` = `05` 로 띄웠습니다.

| 잎 | 화면 |
| --- | --- |
| `1009` | いっかくウサギ(몬스터 5) |
| `100C` | (빈칸) |
| `1014` | めいれいさせろ(이름 표 6 의 5번째) |
| `100E` | (빈칸) |
| `101B` | 주인공이 살아 있으면 ああああ, `7E:2041` = 0 이고 サンチョ 가 일행 첫째면 サンチョ |

`100C` 의 이름 표 7 은 `21:959B` 에서 `30:8000` 이었고, 롬이 1.5MB(뱅크 `2F` 까지)라 롬 밖입니다.
쓰이는 것 중 `1013` 은 메시지 `248`(「今日から あなたは {1013}よ！」)로, 둘째 레코드 `+0` = `80` 이면 ボロンゴ, 없으면 빈칸이었습니다(마차 안이어도 나옴). `100F` 는 메시지 `116` 에서 `$F5` = 0, `7E:0F23` = 0 으로 두고 `7E:1005` 를 `00`·`01`·`FF` 로 하자 スライムＡ·スライムＢ·スライム 였습니다.

`$F5` 를 채우는 쪽은 쓰기 감시로 보았습니다. 여관(대화 번호 `06`)에서는 `06:E3B9` 근처가 `1A 00 00` 을 넣은 뒤 메시지 `072` 를 띄웠고, 전투에서는 `20:843F`·`20:8A51`·`20:C6CA` 가 몬스터 칸을 넣은 뒤 전투 메시지(`24:8C39`)를 띄웠습니다. 전투 메시지도 같은 대기열을 씁니다.

## 6. 끝 코드 셋

파파스 스크립트를 메시지 `129` 셋(`61 29 61 29 61 29 3F`)으로 덮고, 잎 `1001`(파일 오프셋 `121420`)을 `1010`·`1018` 로 바꿔 차례로 띄웠습니다.

```
1001: 116 248BAF  132 1001  132 248BAF  148 1001  157 248BAF  173 1001
1010: 116 248BAF  132 1010  132 24841F  314 248BAF  330 1010  339 24841F ...
1018: 116 248BAF  132 1018  132 248BAF  148 1018  148 248BAF  164 1018
```

`1001` 은 버튼을 기다리지 않고, 다음 메시지가 찍히는 동안 앞 메시지 줄이 위로 밀려났습니다(마지막엔 한 줄). `1010` 은 메시지마다 ▼(`24:841F`)에서 멈췄고, `1018` 은 세 줄이 밀리지 않고 쌓였습니다.
처리기를 읽으면 `1001` 은 「창 줄 수 − 이 메시지 줄 수」 만큼 밀어 올리고, `1018` 은 커서만 18점 내립니다. 스크립트가 서술문 뒤에 붙이는 빈 메시지 `013` 은 `{1006}{1010}`, 곧 버튼 대기만 하는 메시지입니다.

## 7. 몸짓 코드

`1100` 번대가 든 메시지를 하나씩 파파스에게 띄우고(`ROMPATCH="30139=6xxx"`), 처리기 호출과 인물 표 쓰기를 적었습니다.

```sh
TALK_A="b:4,wait:40,up:3,wait:20,a:4,wait:30,a:4$(printf ',wait:56,a:4%.0s' $(seq 14))"
STATE=$PWD/work/state/ship.mss PRE="$TALK_A" MAXF=1000 CALLS=2481A4 ROMPATCH="30139=6638" \

  "$MESENCE" --testrunner "$PWD/rom/dq5.sfc" "$PWD/sfc/dq5/tools/lua/dq5msg.lua"
```

`7E:31E0` 은 방향이고, `7E:3260` 은 처음 보는 값이었습니다. 파파스 슬롯의 `7E:326B` 를 값마다 고정해 찍자 `84` 는 `7E:31EB` = `44`(아래) 화면과 픽셀이 같았고, `81`·`82`·`88` 은 오른쪽·왼쪽·위 모양에 가까웠습니다. bit7 이 켜지면 방향과 따로 모양을 고정하는 값입니다.
그 밖에 `1104` 는 두 번 뛰어오르고, `1110` 은 한 바퀴 돌고, `1100` 은 메시지 창이 한 번 커졌다 돌아오고(「わっ！」), `1105` 는 창이 흔들리고(「キリキリキリ」), `1116`·`1117` 은 맵 화면을 어둡게 했다 되돌렸습니다(메시지 `774`).
`1112`·`1114`·`1118` 은 파파스 그림이 3~6프레임 바뀌는 것만 보였습니다(「さぶい」·「ごほん」·「ヒック」).

## 8. 한글 넣기 준비

한글을 넣으려면 글자 코드·폰트·트리·메시지 자리가 모두 늘어나야 합니다. 롬에서 잰 것은 이렇습니다.

```
글자 코드  001~3DA, 24:81B0 이 1000 미만을 글자로 봄 → 3DB~FFF 가 빔
폰트 표    24:B176 50묶음(250바이트), 바로 뒤 24:B270 이름 부호 표
그림       07:980E~07:D77B, 뱅크는 07~0A 만(+4 bit0-1)
트리       잎 991, 노드 990, 최장 17비트, 표 뒤에 전투 트리 24:9C2E
메시지     07:D77C~0C:8020, 색인 값>>3 = 21비트 → 뱅크 3F 까지
빈 곳      0B:FB99 1,127바이트(00). 롬 1.5MB
```

글자 하나를 실제로 늘려 보았습니다. 폰트 표를 `0B:FB99` 로 복사해 51번째 묶음(1자, 11×13)을 붙이고, 그림은 메시지에 쓰이지 않는 글자 `2E0`~`2E2` 자리(`07:CA9F`)에 「한」 을 그려 넣었습니다. 트리 잎 の(`399`)를 `3DB` 로 바꿔 메시지 `129` 를 띄웠습니다.

```sh
P=$(uv run --locked python sfc/dq5/tools/dq5text.py rom/dq5.sfc --hangul-test)
STATE=$PWD/work/state/ship.mss PRE=$TALK MAXF=280 ROMPATCH="30139=6129;$P" \
  SHOT_DIR=$PWD/work/hangul/patched "$MESENCE" --testrunner "$PWD/rom/dq5.sfc" "$PWD/sfc/dq5/tools/lua/dq5msg.lua"
```

## 9. 창 레코드 머리

명령 창 레코드(`04:ED0C`, 파일 오프셋 `26D0C`) 머리 `02 04 0C A9 00 04` 의 바이트를 하나씩 바꿔 명령 창을 열었습니다(`PRE="b:4,wait:40,down:3,wait:20,a:4,wait:80"`).
`+0`·`+1`·`+2` 는 X·Y·너비(타일), `+3` 아래 4비트는 높이, `+3` bit7 은 항목 줄 간격(끄면 8점으로 겹침), bit5 를 끄면 창이 뜨지 않았습니다. `+4`·`+5` 는 바꾸면 화면이 깨졌습니다.
상태 창(창 `02`)에서는 `B0`·`B1`·`C6` 을 서로 바꿔 넣어 HP·MP·레벨 자리임을 확인했습니다.

## 틀렸던 것들

- 조건 `03`·`11`·`13`·`20` 은 일행이 있어야 갈린다고만 보고 동료 장면 세이브스테이트를 찾으려 했다: 일행 레코드와 순서 몇 바이트를 `SET` 하는 것으로 충분했다.
- `13` 의 `+1` bit7 을 처음엔 「일행에 있음」 으로 보았다: 주인공이 쓰러지자 꺼져 살아 있음이었다.
- 폰트 표를 옮길 때 `24:B176` 을 읽는 피연산자 둘만 고쳤다: 같은 표를 `24:B178`·`24:B17A` 로 읽는 곳이 더 있어 글자가 옛 표 바깥 값으로 찍혔다. 넷 다 고치자 맞았다.
- `1009`·`101B` 등을 메시지에서 찾아 띄우려 했다: 쓰이지 않는 코드는 트리에 잎이 없어 넣을 수도 없었다. 다른 잎을 바꿔 시험했다.

## 남은 것

- 대화 번호 `000` 인물의 실제 대사, 네이티브 호출 142곳의 나머지
- 창 레코드 머리 `+4`·`+5`, 상태 창의 나머지 자리 바이트
- 조건 `03` 인자 `47` 의 인물, 일행 레코드 `+1` bit6, `BRK 8C`
- `1112`·`1114`·`1118` 이 바꾸는 모양 값
- 한글: 트리 표·그림·메시지를 둘 자리를 정하는 것, 1바이트 부호(이름·창·전투)를 넓히는 방법
