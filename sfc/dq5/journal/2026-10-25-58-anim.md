# 2026-10-25-58: 실내 맵의 움직이는 타일

[창 타일과 움직이는 타일](2026-10-25-36-gfx2.md) 일지에서 「맵 CHR 슬롯 `BE`~ 가 바뀌고 `03:D751` 이 고친다」까지 본 실내 맵의 움직이는 타일을 끝까지 풀었습니다. 맵마다 고르는 표, 종류마다의 원본 타일과 간격을 찾고 맵 9곳에서 프레임마다 견줬습니다. 결과는 [dq5-graphics-format.md 「실내 맵의 움직이는 타일」](../docs/dq5-graphics-format.md#실내-맵의-움직이는-타일) 에 있습니다.

## 1. 맵에 들어갈 때와 매 프레임

`dq5warp.lua` 로 01/01 에 들어가 03 뱅크의 실행 명령을 모았습니다. `dq5warp.lua` 와 `cover.lua` 가 둘 다 `TO` 를 읽어서, `cover.lua` 의 `FROM`·`TO` 를 `CFROM`·`CTO` 로 바꾼 사본으로 돌렸습니다.

```sh
LIBDIR=$(tools/lua/seqlib.sh "$(uv run --locked krpatch sfc lua)" work/warplib ../../sfc/dq5/tools/lua/dq5warp.lua)
sed 's/getenv("FROM")/getenv("CFROM")/; s/getenv("TO")/getenv("CTO")/' tools/lua/cover.lua > work/cover2.lua
mkdir -p work/an/c0101
env LIBDIR=$LIBDIR STATE=$PWD/work/state/ship.mss TO=01/01,20,20 SETTLE=400 CFROM=250 CTO=800 LO=030000 HI=03FFFF \
  MAXF=900 SHOT_DIR=$PWD/work/an/c0101 "$MESENCE" --testrunner "$PWD/rom/dq5.sfc" "$PWD/work/cover2.lua"
uv run --locked python tools/listing.py rom/dq5.sfc work/an/c0101/cover.txt > work/an/c0101/list.txt
```

맵을 불러올 때 `03:D3E9` 가 `03:D82E` 를 3바이트씩 넘기며 `$BC`·`$BD` 와 같은 항목을 찾고, 셋째 바이트 k 로 `03:D806[k]` 를 읽어 종류 비트마스크로 둡니다. 켜진 종류마다 `03:D786` 의 블록 번호를 `01:8B98`(맵 블록을 풀어 CHR 슬롯을 주는 루틴)에 넘깁니다.
매 프레임 도는 `03:D4B5` 는 `7E:1ECE` 를 0~`BF` 로 올리고, 종류마다 `03:D964` 의 주기로 `00:A025`(하드웨어 나눗셈)를 불러 나머지가 0 일 때만 움직입니다. 종류 0~5 는 `(1ECE / 주기) % 벌 수` 로 벌을 골라 롬 `03` 뱅크에서 바로 보내고, 6 이상은 `03:D751` 로 WRAM 사본을 한 줄 돌립니다.

## 2. 프레임마다 견주기

`dq5gfxdump.lua` 를 장면 이동 뒤에 붙여 프레임마다 WRAM·VRAM 을 덤프하고, 새 도구 `sfc/dq5/tools/dq5anim.py --check` 로 견줬습니다.

```sh
mkdir -p work/an/0200
env LIBDIR=$LIBDIR STATE=$PWD/work/state/ship.mss TO=02/00,20,20 SETTLE=300 DUMPF=$(seq -s, 500 1 560) MAXF=600 \
  SHOT_DIR=$PWD/work/an/0200 "$MESENCE" --testrunner "$PWD/rom/dq5.sfc" "$PWD/sfc/dq5/tools/lua/dq5gfxdump.lua"
uv run --locked python sfc/dq5/tools/dq5anim.py rom/dq5.sfc --check work/an/0200 500 560
```

```
7E:1ED0 = 0007, 종류 [0, 1, 2]
종류 0: 주기 24, 수 4, 타일 6, VRAM 2BE0 → 60/60 맞음
종류 1: 주기 24, 수 2, 타일 4, VRAM 2C40 → 60/60 맞음
종류 2: 주기 8, 수 4, 타일 6, VRAM 2C80 → 60/60 맞음
```

01/01 의 종류 8 은 `1ECE` 가 120·144·168 인 다음 프레임에만 바뀌었고, 바뀐 10타일은 앞 프레임을 한 줄 아래로 돌린 것이었습니다. 그 10타일은 블록 `0FD`·`23D`·`27B` 의 CHR 10개를 모두 7줄 돌린 꼴이라, 원본이 이 블록들의 CHR 이라는 것도 확인했습니다. 맵 9곳에서 종류 0~6·8·9·10·13·14 가 같은 식으로 맞았습니다.

## 3. 걷는 방향으로 미는 종류 14

04/00 의 종류 14 는 서 있을 때 60프레임 동안 그대로였습니다. 코드에서 `7E:$C4`(걷는 방향) bit0·bit1 을 보길래 출구 옆 (17,50) 에서 위·아래·왼쪽·오른쪽으로 걸었더니, 위·아래로 걷는 동안은 그대로, 왼쪽·오른쪽으로 걷는 동안(`$C4` = 2·1) 89 프레임에서 바뀌었습니다.

## 틀렸던 것들

- 처음 04/00 은 (20,20) 에 세워 걷지 못해 종류 14 가 늘 그대로인 줄 알았습니다.

## 남은 것

- 종류 7·11·12 의 실측. 쓰는 맵이 BC `50` 이상(50/50·51/57·53/51·54/50 등)뿐인데 장면 이동 도구로 들어가지 못했습니다.
- 종류 7 의 `03:D5EC` 갈래와 종류 14 의 가로 밀기를 바이트 단위로.
