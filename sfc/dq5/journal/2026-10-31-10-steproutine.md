# 2026-10-31-10: 걸음 루틴을 뱅크 00 밖에 두기, 걸음 루틴이 하는 일

[걸음 루틴 표 일지](2026-10-30-04-maprest.md)가 남긴 둘을 풀었습니다. 하나는 걸음 루틴 표에 뱅크 00 밖의 새 루틴을 두는 것이고, 다른 하나는 걸음 루틴이 무엇을 하는지입니다. 출구 표를 옮길 때 남겨 둔 필드행 갈래(`2A:F52A`)의 DB 감사도 장면으로 쟀습니다. 결과는 [쓰기 형식 「걸음 루틴 표」](../docs/dq5-build-format.md#걸음-루틴-표-dq5step1)와 [「표 옮기기」의 DB 감사](../docs/dq5-build-format.md#실내-출구영역-이동-표-옮기기-dq5exittables1)에 넣었습니다.

## 1. 걸음 루틴은 언제 불리나

지난번에는 찾기(`00:C652`)가 `$1AAD` 를 채운다는 것만 보았습니다. 이번에는 `$1AAD` 를 부르는 쪽을 풀었습니다. `00:C342` 를 부르는 곳은 `00:BEA0` 의 `JSR` 하나입니다.

```
00:BE9F  PHA / JSR $C342 / PLA / BCS $BE74       ; 캐리면 이번 걸음을 하지 않음
00:C342  LDX $BE / BPL CLC·RTS                    ; 필드면 부르지 않음
00:C346  STA $00 / PHA / JSL $00B107 / JSR $C4C6 / PLA
00:C351  LDA $24 / AND #$0F / STA $00 / JMP ($1AAD)
```

그러니 걸음 루틴은 실내에서 걸으려 할 때마다 불리고, `$00` 에 누른 방향을 받고, 캐리로 「이 걸음을 하지 말라」를 돌려줍니다. 원본 15그룹의 루틴을 모두 풀어 보니 하나같이 맵 `$BD`·방향·칸 `$C1`·`$C2`·이벤트 플래그를 보고, 맞으면 메시지나 장면을 돌린 뒤 캐리를 켭니다. 그룹 `51` 은 이벤트 없이 캐리만 켜서 한 줄을 막습니다. 그룹 `20`·`04`·`18`·`32` 가 같이 쓰는 `00:C5DE` 만 늘 캐리를 끄고, 물체 칸 `7E:3780,X` 가 `F2` 인 슬롯의 `7E:31A0,X` 를 바꿉니다. 그룹마다의 표는 형식 문서에 두었습니다.

`00:C4C6` 은 걸음 루틴 앞에서 늘 돕니다. 왼쪽이면 `7E:3740`, 오른쪽이면 `7E:3780` 이 `61`·`62` 인지 보고, 대각선 칸도 `61`·`62` 면 스택 6바이트를 버리고 `00:BEA6` 으로 가서 방향을 대각선으로 바꿉니다. 비스듬한 계단으로 보이지만 장면은 재지 않았습니다.

## 2. 받침

`JMP ($1AAD)` 는 뱅크 00 안에서만 뜁니다. 지난번 도구는 찾기를 다른 뱅크로 옮기면서 `00:C652` 에 `JML` 4바이트만 남겼으니, 그 뒤 `00:C656`~`C686` 49바이트가 빕니다. 여기에 `JSL 몸통 / RTS` 5바이트 받침을 두고 표에는 받침 주소를 적었습니다. 받침은 9개까지 들어갑니다.

비는지는 둘로 보았습니다.

- 정적 검색: 롬 전체에서 그 자리로 가는 `JSR`·`JMP`·`JSL`·`JML`, 뱅크 00 안의 상대 가지(찾기 안의 것 빼고)가 없습니다. `LDA` 꼴로 그 주소를 담은 바이트가 8곳 있었으나 풀어 보면 명령 흐름이 이어지지 않는 자료 자리였습니다.
- 훑기: 찾기만 옮긴 롬으로 `dq5freesweep.py --ranges 00C656-00C686 --kinds maps,field` 를 돌렸습니다. 실내 맵 346곳과 필드 세계 셋에서 그 자리(뱅크 80 거울 포함)의 읽기·실행이 0 이었습니다.

`dq5stepwrite.py` 는 이제 루틴을 `BB:AAAA`(BB ≠ `00`)로 받습니다. 그런 루틴이 있으면 `--table-at` 이 있어야 하고, 받침은 원래 찾기 바이트를 `orig` 로 담습니다. 같은 루틴을 여러 그룹에 적으면 받침 하나를 같이 씁니다. 몸통은 도구가 쓰지 않습니다. `dump` 는 받침을 거친 루틴을 받침이 부르는 주소로 내보냅니다.

단위 테스트는 3C:B000 에 `LDA #$5A / STA $7E0100 / SEC / RTL` 을 둔 합성 롬에서 받침을 `JSR` 처럼 돌려, 쓰기·캐리·스택이 제자리로 돌아오는 것을 봅니다.

## 3. 밟아서 확인

새 도구 `dq5stepcheck.py` 는 그룹 01 의 루틴을 `3C:B000` 으로 바꾼 롬 `f` 를 만듭니다. 몸통은 「왼쪽이면 캐리」인 시험 코드 `LDA $00 / AND #$02 / BEQ +2 / SEC / RTL / CLC / RTL` 입니다. 찾기만 옮긴 롬 `h` 도 만듭니다. 새 프로브 `lua/dq5stepprobe.lua` 는 `00:C656`~`C686` 의 실행 PC 와 읽기를 세고, 몸통에 들어올 때의 레지스터와 스택을 적습니다.

```
left: 01/00 (40, 84) $1AAD=C656 읽기 0 실행 {'00C656': 5, '00C65A': 5}
  entry f=538 P=34 DB=00 D=0000 S=02F1 A=0002 00=02 C1=28 C2=54 ret=00C659 outer=BEA2
right: 01/00 (44, 84) $1AAD=C656 읽기 0 실행 {'00C656': 4, '00C65A': 4}
  entry f=556 P=34 DB=00 D=0000 S=02F1 A=0001 00=01 C1=29 C2=54 ret=00C659 outer=BEA2
left-orig: 01/00 (36, 84) $1AAD=C385 읽기 0 실행 {'00C656': 1, … '00C686': 1}
left-h: 01/00 (36, 84) $1AAD=C385 읽기 0 실행 {}
other: 03/00 (39, 60) $1AAD=C565 읽기 0 실행 {}
5개 장면, 걸음 루틴 받침 검사 통과
```

- `f` 롬 01/00 (40,84) 에서 왼쪽을 40프레임 눌러도 움직이지 않았습니다. 받침 둘(`JSL`·`RTS`)만 5번씩 돌았습니다. 오른쪽은 (44,84) 까지 걸었습니다.
- 몸통에 들어올 때 P = `34`(M·X 8비트), DB = `00`, D = `0000` 이었습니다. 스택에는 받침의 `JSL` 이 쌓은 `00:C659` 위에 `00:BEA0` 의 `JSR` 이 쌓은 `BEA2` 가 있었습니다. `$00` 은 왼쪽 `02`·오른쪽 `01`, `$C1`·`$C2` 는 주인공 칸이었습니다.
- 원본에서는 찾기(`00:C656`~`C686`)가 맵을 놓을 때 1번 돌고 걸음마다 다시 돌지 않았습니다. `h` 롬에서는 그 자리를 아무도 실행하거나 읽지 않았습니다.
- 03/00 의 `$1AAD` 는 원래 그룹 03 항목 `C565` 그대로였습니다.

## 4. 필드행 갈래의 DB

[출구 표 옮기기](2026-10-27-24-exitreloc.md)의 DB 감사는 필드로 나가는 갈래(`2A:F52A`·`2A:F425`)를 장면으로 지나지 않아 코드 읽기로만 남겼습니다. `dq5exitcheck.py` 에 원본 장면 둘을 더했습니다.

- `field-original`: 03/00 (38,70) 에서 아래로 걸어 필드 (251,216) 로.
- `redirect-original`: 15/0A (21,51) 에서 아래로 걸어 왼쪽 출구를 밟고, `2A:F52A` 가 54/50 (31,25) 으로 돌림.

기본 창으로 돌리면 실행 명령 수가 417개 그대로였습니다. 15/0A 장면은 `2A:F4C2` 창을 열지만, `2A:F4DA` 의 `JSL $00CE49`·`$00CD44` 가 DB 를 바꾼 채 명령 5,000개 넘게 돌아 창이 닫힌 뒤에 `2A:F4ED` 의 `JSR $F52A` 에 닿았습니다. 창을 닫는 한도를 400,000 으로 늘리자 MesenCE 가 종료 코드 255 로 끝나서, 대신 갈래를 부르는 자리에서 창을 다시 열었습니다(`AUDITOPEN=2AF4ED,2AF4F0,2AF234,2AF7B5`).

```
field-original: field (251, 216) 층 01
redirect-original: 54/50 (31, 25) 층 01
  2A:F547 STA $198E             1회 롬 읽기 0곳
```

`2A:F52A`~`F704` 에서 실행한 DB 기준 접근은 `2A:F547` 의 `STA $198E` 하나였습니다. 03/00 장면이 지난 `2A:F425`~`F4B8` 에서는 0곳이었습니다. 레코드 뱅크(`$183C`)를 낮은 WRAM 거울이 있는 `00`~`3F` 로 묶은 지금 조건으로 충분합니다. 그룹 `11`(`05:E87C`)·12·0F·22·05 갈래는 장면을 지나지 않았습니다.

## 틀렸던 것들

- 프로브 범위를 `00:C688` 까지 잡았더니 모든 롬에서 `00:C687`·`C688` 이 24번씩 잡혀 받침 검사가 실패했습니다. 그 둘은 기본 루틴 `CLC / RTS` 이고, 찾기를 옮겨도 그대로 쓰입니다. 받침 자리는 `C686` 까지입니다.
- 정적 검색에서 뱅크 00 안의 상대 가지 둘(`00:C6D5`·`C6EC`)이 받침 자리를 가리키는 것으로 나왔습니다. 풀어 보니 둘 다 명령 중간의 바이트였습니다.

## 남은 것

- 그룹 51·54 의 새 맵. `01:94B4` 가 `$BD` 마다 영역 이동 목록을 고르고, 맞는 것이 없으면 앞 맵의 개수가 남습니다. 51·54 갈래를 표로 바꾸는 훅과 `dq5exitreloc.py` 의 고층 목록 늘리기가 함께 필요합니다.
- `00:C4C6` 의 대각선 갈래가 도는 장면과 `7E:3740`·`3780` 의 뜻, `00:C5DE` 가 바꾸는 `7E:31A0,X` 의 뜻과 `F2` 물체.
- 받침을 거친 몸통이 이벤트를 부르는 경우(`BRK` 메시지, 원래 루틴처럼 `JSL` 로 장면 돌리기)의 실측. 이번 몸통은 캐리만 돌려줍니다.
