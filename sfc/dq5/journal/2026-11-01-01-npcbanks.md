# 2026-11-01-01: 인물 목록을 여러 뱅크에 나누기

`dq5npcrelocate.py` 는 기본 목록을 한 뱅크(`--base`), 대체 목록을 한 뱅크(`--alt`)에 몰아 둡니다. 원본 목록만 옮겨도 기본 20,173바이트·대체 23,986바이트라 한 뱅크(32,768바이트)에 남는 자리가 크지 않습니다. DQ4 포팅 쪽에서 5장 인물을 더하려면 이 한도를 넘어야 해서, 목록을 그룹(기본)이나 목록(대체)마다 다른 뱅크에 둘 수 있게 했습니다. 결과는 쓰기 형식의 [목록을 여러 뱅크에 나누기](../docs/dq5-build-format.md#목록을-여러-뱅크에-나누기)에 있습니다.

## 1. 로더가 뱅크를 고르는 곳

`12:8000` 의 기본 목록 갈래를 읽었습니다(코드 읽기).

```text
12:801A  LDA $BC / CMP #$50 / BCS …        ; 그룹 50 이상은 기본 목록 없음
12:8020  LDA #$05 / STA $A7                ; 목록 뱅크
12:8024  JSR $803F
12:803F  PHB / PHP / SEP #$20 / LDA $A7 / PHA / PLB
12:8047  LDA $BC / REP #$30 / AND #$00FF / ASL / TAY
12:8050  LDA $D4B2,Y / STA $A5             ; 그룹 첫 목록(데이터 뱅크 = $A7)
12:8059  LDA $BD / BEQ … / JSR $8067        ; 00 끝 목록을 $BD 개 건너뜀
12:802C  LDA $A7 / PHA / PLB / LDA ($A5) …  ; 엔트리를 읽음
```

뱅크는 `12:8020` 의 즉값 하나이고, 그룹 표도 그 뱅크에서 읽습니다. 그래서 그룹마다 뱅크를 다르게 하려면 두 가지가 필요합니다. 첫째, `$A7` 을 그룹 번호로 고르는 것. 둘째, 뱅크마다 같은 자리(`12:8051` 즉값)에 그룹 표를 두는 것. 대체 목록은 `12:833B` 의 `LDA #$10; STA $A7` 이 뱅크를 정하고, 표를 옮기면 `dq5npclists.assemble_find` 의 새 루틴이 즉값으로 넣습니다.

## 2. 고친 것

- `12:8020` 의 네 바이트를 `JSL` 로 덮고, 첫 기본 뱅크의 목록 뒤에 `[그룹 수][그룹마다 뱅크]` 표와 11바이트 루틴을 둡니다. 이 자리에서 X 는 8비트(`12:800B SEP #$30`)이므로 `LDX $BC` 한 바이트로 표를 고릅니다. 그룹 수 바이트는 게임이 읽지 않고, `dq5npc.group_pointers` 가 표 길이를 알려고 읽습니다.

  ```text
  DA          PHX
  A6 BC       LDX $BC
  BF xx xx xx LDA 뱅크표,X
  85 A7       STA $A7
  FA          PLX
  6B          RTL
  ```

- 기본 뱅크는 모두 같은 하위 주소에서 시작하고, 앞에 그룹 수 × 2바이트 표를 둡니다. 표에는 그 뱅크에 든 그룹 칸만 채웁니다. 그룹은 `--group-bank GG=BB` 로 고정한 것부터 놓고, 나머지는 번호 차례로 앞 뱅크부터 채웁니다.
- 대체 목록은 목록 차례로 앞 뱅크부터 채웁니다. 뱅크가 여럿이면 대체 표 항목 끝에 목록 뱅크 바이트를 더해 7바이트로 하고, 새 루틴이 그 바이트를 `$A7` 에 넣습니다(104바이트, 6바이트 항목은 102바이트). 그래서 `overrides` 가 없어도 표를 옮깁니다.
- 뱅크를 하나씩 주면 나누기 전과 같은 출력을 냅니다. `origin/main` 의 도구와 원본 목록 문서, 빈 맵 표를 44항목으로 늘린 문서(표를 옮기는 갈래) 두 가지로 패치 JSON 을 견주어 바이트까지 같았습니다.
- `dq5npc.all_lists` 는 다음 목록을 같은 뱅크 안에서만 찾습니다. 나눈 롬에서도 639목록의 이름·순서가 원래 롬과 같고, 기본 346목록의 자리가 `--report` 의 대응표와 같았습니다.

## 3. 게임에서 재기

원본 목록을 다음처럼 나눠 `dq5npcrelocatecheck.py --all` 로 돌렸습니다.

```text
--base 32:8000,34:8000 --group-bank 17=34 --group-bank 02=34 --alt 33:C000,35:8000 --case 21/00:7E2190=80
기본 32:8000 18,935바이트(그룹 00·01·03~16·18~35, 뱅크 표·루틴 포함), 34:8000 1,412바이트(그룹 02·17)
대체 33:C000 16,378바이트, 35:8000 9,785바이트(대체 표 35:9DB8 296항목·루틴 35:A5D1)
```

검사 장면은 기본 346맵 낮·밤과 02/06·21/00 의 대체 목록 낮·밤입니다. 장면마다 인물을 다 놓은 직후(`12:803C`) 인물 표 23칸과 스크립트 포인터 세 바이트(뱅크 포함)를 원래 롬과 재배치 대응표에 견줍니다.

```text
696/696 통과, 인물 1590슬롯, 포인터 652개
읽은 목록의 새 뱅크: 32 648장면, 34 32장면, 33 4장면, 35 4장면(인물 없는 06/01·02·03·06 의 8장면은 목록 없음)
```

02/06 의 대체 목록 `10:9B57` 은 `33:DB57`, 21/00 의 `10:D12C` 는 `35:9132` 로 옮겨졌습니다. 그래서 두 기본 뱅크와 두 대체 뱅크가 모두 낮·밤으로 읽혔습니다.

## 4. DQ4 쪽에서 쓰는 법

DQ4 빌드(`sfc/dq4/tools/dq4chapter1.py`)는 지금 `--base` 에 뱅크 `35` 의 환경 맵 레코드 뒤 자리(`npc_base`, `35:8000` 이 아닐 수 있음), `--alt 38:8000` 처럼 뱅크를 하나씩 줍니다(`dq4groupbuild.py` 는 `33:8000`·`38:8000`). 그대로 두면 출력이 바뀌지 않습니다. 5장 인물이 넘치면 비어 있는 뱅크를 쉼표로 더합니다. 예: `--base 35:8000,3B:8000 --alt 38:8000,3C:8000`. 기본 뱅크는 하위 주소가 같아야 하므로, `npc_base` 가 `35:A300` 이면 더할 뱅크도 `3B:A300` 처럼 같은 하위 주소로 주고 그 앞 바이트는 다른 도구가 씁니다. 특정 그룹을 다른 뱅크로 보내려면 `--group-bank 3A=3B` 를 더합니다. 더한 뱅크가 다른 도구의 영역과 겹치는지는 지금처럼 빌더(`apply_writes`)가 봅니다.

## 남은 것

- 기본·대체 목록을 나눈 롬에서 `lists`·`new_lists`·`--new-map`(새 그룹 36~)·`--records` 를 함께 쓴 경우는 단위 시험과 정적 대조만 했고 게임에서 재지 않았습니다.
- 스크립트 길이를 바꾼 `--mutations` 다섯 장면은 한 뱅크 배치로만 돌립니다.
