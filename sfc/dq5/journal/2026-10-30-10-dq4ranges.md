# 2026-10-30-10: dq4 트랙이 쓰는 구간과 dq5 도구 기본 자리

dq4 트랙이 dq5 의 요청 둘에 답을 보냈습니다. 메뉴 빌드의 `BASE_SHA1` 은 없어졌고, 타이틀·서곡·메뉴·사운드 포팅이 쓰는 롬·WRAM 구간 목록이 왔습니다. 목록을 통합 빌드에 쓴 고정 롬과 바이트로 견주고, dq5 도구의 기본 자리가 그 구간과 겹치는지 봤습니다. 결과는 [통합 포팅 빌드](../docs/dq5-build-format.md#dq4-트랙이-쓰는-롬wram-구간)의 표 둘에 있습니다.

## 1. `BASE_SHA1`

`git show 320056e6 -- sfc/dq4/tools/dq4menupatch.py` 에서 `BASE_SHA1 = 'ed46db6d…'` 줄과 `hashlib.sha1(rom).hexdigest() != BASE_SHA1` 검사가 함께 지워진 것을 봤습니다. 지금 메뉴 빌드는 서곡이 부르는 스텁(`JSL 70:FF00`)과 비어 있는 메시지 자리로 바탕 롬을 고릅니다. 통합 빌드가 값을 바꿔 부르던 우회도 필요 없어졌습니다. 요청 ①은 끝냈습니다.

## 2. 목록을 고정 롬과 견주기

[통합 포팅 빌드 일지](2026-10-27-26-portbuild.md)에서 쓴 고정 롬 세 단계가 작업 폴더에 남아 있었습니다. 타이틀 `dq4-title-baseline`, 서곡 `ccfebeb…`, 메뉴 `e102f29…` 입니다. 단계마다 바로 앞 단계와 바이트로 견줬습니다(16바이트 안쪽 틈은 이음).

- 타이틀: 원래 롬 뒤에 `20`~`2F` 를 붙인 2MB(타이틀 빌드가 늘리는 방식)와 견줌
- 서곡: 타이틀을 `dq5build.expand` 로 4MB 로 늘린 것과 견줌. 늘린 뱅크 첫머리 5바이트는 서곡 빌드가 표지를 쓰지 않아 모두 다르게 나오므로 뺌
- 메뉴: 서곡과 견줌

대부분 목록과 맞았습니다. `07:D77C`~`08:F276`, `65:8000`~`69:B941`, `70:FF00`~`FF37` 은 끝 바이트까지 같았습니다. 다른 것은 이렇습니다.

```
목록에 없음  서곡  30:FF00~30:FF14   21  (dq4overture.py FADE_STUB)
목록에 없음  메뉴  04:D1DE~D1E0 04:D222~D224 04:D584~D587 04:D68C~D68F 04:D794~D797 04:D82E~D831
목록에 없음  메뉴  24:A7D6~24:A7D7    2  (JSR $A81E → JSR $9E11)
목록에 없음  메뉴  30:829B~30:829D    3  (타이틀 FadeOut 의 JML $03FE5C → JML $608100)
더 넓음      메뉴  04:F43D~F4BA(목록 ~F4B2), 04:F4DC~F5D3(목록 ~F5CF), 24:AF1E~B175(목록 AF1E 한 점)
바뀌지 않음  타이틀 03:FE5C
```

`04:D1DE` 등 여섯 곳은 `sfc/dq4/tools/dq4nameentry.asm` 의 `org` 이고 지금 main 에도 있습니다. `30:829B` 는 타이틀 코드 `30:8000`~`8FFF` 안이라 통합 빌드는 이미 예약합니다. `30:FF00` 은 거울 안이라 [거울 추정](../docs/dq5-build-format.md#고정-롬이-차지하는-자리)이 잡던 자리입니다.

이 롬은 2026-10-27 에 만든 것입니다. 그 뒤 dq4 에 더해진 뱅크 `58`(창 글자 그림)은 들어 있지 않습니다. 사운드 포팅 자리도 서곡이 쓴 `70` 말고는 없습니다. 이 둘과 WRAM 은 표에 「알려 준 것」으로 적었습니다.

## 3. dq5 도구 기본 자리

`sfc/dq5/tools/*.py` 에서 `'BB:AAAA'` 문자열과 `0xBBAAAA` 상수를 모두 뽑아 목록 구간 안에 드는 것을 골랐습니다. 뱅크 `30`~`3F` 는 타이틀이 실제로 쓰는 자리(위 비교의 `30:8000`~`39:821F`)와 따로 견줬습니다. 겹친 것은 세 갈래입니다.

- 쓰기 도구의 기본 자리 다섯: `dq5mapwrite.py --at 30:8000`, `dq5npcrelocate.py --base 32:8000 --alt 33:8000`, `dq5fieldwrite.py --at 34:8000`, `dq5textwrite.py --at 38:8000`, `dq5eventwrite.py` 의 `60:8000`. 모두 타이틀 에셋이나 메뉴 자료 위입니다.
- 시험 도구가 원래 롬을 늘린 시험 롬에만 쓰는 자리: `68:8000`, `6E:8000`·`6F:8000`, `7C:8000`, `60:8000`.
- 같은 도구·상수를 dq4 빌드가 빌려 쓴 자리: `dq5song.py --reloc` 의 `70:8010`~, `dq5hangul.py`·`dq5text.py` 의 `24:9E02`·`AF1E` 등.

쓰기 도구 다섯의 기본값은 옮기지 않았습니다. `dq5portbuild.py` 는 다섯 도구를 모두 `--at`(인물은 `--base`·`--alt`)을 주고 부릅니다(`run_tool` 호출 다섯 곳). 크기를 재는 시험 쓰기(`probe`)도 원래 롬 위에서 합니다. 그래서 기본 자리는 통합 롬에 들어가지 않습니다. 옮길 곳도 마땅치 않습니다. 타이틀이 쓰지 않는 `30`~`3F` 뱅크는 `3A`~`3F` 뿐이고, 시험 도구 여럿이 이미 그 자리를 씁니다. 게다가 dq4 의 `dq4groupbuild.py` 가 `dq5npcrelocate.py patch` 를 `--base`·`--alt` 없이 부르고 있어, 기본값을 바꾸면 dq4 빌드 결과가 바뀝니다.

시험 도구가 쓰는 `3A`~`3E` 와 원래 롬 끝의 `1F:FE30`·`10:FFE0`·`10:FFE8`·`22:FF30` 은 겹치지 않았습니다.

## 4. 거울 추정을 목록으로 바꿀 수 있나

바꾸지 않았습니다. 목록에는 `30:A000`~·`60:8000`~·`70:8600`~ 처럼 끝이 없는 자리가 있습니다. 게다가 바이트 비교로 목록에 없는 `30:FF00`~`FF14` 가 나왔습니다. 거울 추정은 고정 롬 자체를 보므로 이 자리를 잡습니다. 목록은 dq4 빌드가 바뀌면 낡습니다. 끝 주소까지 적힌 목록이 dq4 문서에 생기면 `keep` 으로 넘길 수 있을지 다시 봅니다.

## 틀렸던 것들

- `03:FE5C` 를 타이틀이 고치는 훅으로 읽었습니다. 바이트 비교에서 타이틀 단계는 이 자리를 바꾸지 않았습니다. 타이틀 코드 `30:829A` 의 `JML $03FE5C` 가 돌아가는 곳입니다. 메뉴는 이 JML 의 대상을 `60:8100` 으로 바꿉니다(`dq4menupatch.py` 의 `FADEOUT_EXIT`).
