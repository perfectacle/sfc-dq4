# 2026-10-25-11: 메달·코인 교환·여관 값과 상자 내용물의 남은 것

[상점](2026-10-25-03-shop.md)과 [보물상자](2026-10-25-02-treasure.md)에서 남겨 둔 것을 풀었습니다. 작은 메달·코인 교환의 상품과 값, 여관 값 표,
상자·タンス 내용물 `D000`~`D009`, 속성 `$D3`·`$D4`, ツボ·タル 안의 `FFFD`·`FFFE`, 그리고 처음 보는 발밑 표(`1E:F08B`)입니다.
결과는 [dq5-data-format.md](../../dq5-data-format.md#작은-메달과-코인-교환-04fd55) 와 [dq5-map-format.md](../../dq5-map-format.md#보물상자와-タンスツボタル-12e4c9) 에 있습니다.

실험은 모두 선실 세이브스테이트(`work/state/ship.mss`)에서 했습니다. 가게는 파파스 슬롯의 대화 번호를 `POKE="7E36EB=<번호>;7E370B=00"` 으로 바꿔 열고,
상자류는 선실 タンス 항목(파일 오프셋 `FF6E2`)을 `ROMPATCH` 로 덮어 열었습니다. 메시지 번호는 툴킷의 `probe/trace.lua` 로 `24:8BAF` 의 A 를 모았습니다.

```sh
LIBDIR=$PWD/work/walklib STATE=$PWD/work/state/ship.mss PRE="b:4,wait:40" ROMPATCH="FF6E7=00D0" \
  WAYPOINTS="3,5;up:8;wait:20;a:8;wait:60;down:6;wait:25;down:6;wait:25;down:6;wait:25;right:6;wait:25;a:8;wait:200;a:4;wait:150" \
  TRACE=248BAF,12E534 MAXF=1300 SHOT_DIR=$PWD/work/v00D0 "$MESENCE" --testrunner "$PWD/rom/dq5.sfc" "$PWD/work/walklib/probe/trace.lua"
```

`work/walklib` 는 `tools/lua/seqlib.sh "$LIBDIR" work/walklib walk.lua` 로 만든 드라이버 폴더입니다.

## 1. 목록 종류 4·5 는 목록이 아니었다

형식 문서의 「목록 종류 4(`04:A11A`)·5(`04:A3A2`)」는 `04:FBD5` 표를 종류 번호로 이어 읽은 값이었습니다. 그런데 `04:FBD5` 의 포인터는 4개뿐이고,
다섯째·여섯째 자리(`04:FBDD`)는 이미 도구점 첫 목록 `1A A1 A2 A3 …` 입니다. 두 주소는 코드 한가운데였습니다.

작은 메달 처리기(`06:EBF7`)를 읽으니 `$0F20` 에 4 를 쓴 뒤, 목록을 띄우기 직전에 3 과 키 `16` 으로 바꿉니다. 코인 교환(`06:EF70`)도 3 과 키 `15` 입니다.
よろず屋 목록 `16`·`15` 는 지난번에 「메탈킹의 검 0G」처럼 값이 이상하게 나왔던 두 목록입니다. 값은 따로 있었습니다.

```
06:EC8A  LDX $0F23 / LDA $04FD55,X / DEC A / CMP $46     ; 고른 순번의 메달 수
06:F06A  LDA $04FD5B,X (X = 순번*3), FD5C, FD5D → $0F28~  ; 코인 24비트
```

`04:FD55` 는 `dq5shop.py` 가 「종류 3 의 끝, 뒤는 다른 데이터」로 적어 둔 바로 그 자리였습니다.
메달·코인이 없으면 처리기가 바로 끝나서, 그 갈림(`06:EC0B`·`06:EF84`, 파일 `36C0B`·`36F84`)을 `80`(BRA)으로 덮고 A 를 몇 번 눌렀습니다.

```
작은 메달: せんしのパジャマ 5  ふしぎなボレロ 10  きせきのつるぎ 16  しんぴのよろい 21  はやぶさのけん 30  メタルキングのたて 43
코인 교환: エルフののみぐすり 300  せかいじゅのは 1000  メガンテのうでわ 5000  キラーピアス 10000  メタルキングのけん 50000  グリンガムのムチ 250000
```

화면 두 장의 값 12개가 모두 표와 같았습니다.

## 2. 여관 값

여관 처리기(`06:E384`)가 메시지 072「ひと晩　{1004}ゴールドですが」 앞에 부르는 `06:F563` 이 값을 정합니다. `04:FD6D` 를 2바이트씩 넘기며 첫 바이트가 `$BC` 인 항목을 찾고,
둘째 바이트 하위 7비트에 `BRK 89 40 45` 의 값을 그 횟수만큼 더합니다. 끝 표시가 없습니다.

선실은 그룹 17 이라 표에 없을 텐데 「26ゴールド」가 나왔습니다. 앞에서부터 훑으면 32번째 항목(`04:FDAB`)이 우연히 `17 1A` 였습니다.
첫 항목을 `17 07` 로 덮자(파일 `27D6D`) 「7ゴールド」가 나와 표에서 고른다는 것을 확인했습니다. 혼자라 곱셈은 확인하지 못했습니다.

앞 21개 항목 중 그룹 `22`·`01`·`21` 은 두 번씩 나옵니다. 코드에서 `7E:2190 & 40` 이 켜지면 둘째 항목을 고르므로, 이야기 진행에 따라 값이 바뀌는 마을로 보입니다.
`02` 가 22번째에 다시 나오는데 첫 항목이 먼저 잡혀 쓰일 수 없으니, 표는 21개로 보았습니다.

교회·코인 판매·맡기는 곳은 ROM 표 없이 처리기 안에 상수가 있었습니다(되살리기 레벨 × 10, 독 5G, 코인 20G, 맡기기 1000G 단위). 상태 이상이나 돈이 있는 세이브스테이트가 없어 코드 읽기로 남겼습니다.

## 3. `$D3`·`$D4` 는 위층의 タル·ツボ

`12:E4C9` 가 부르는 검사 루틴을 하나씩 보니, `$D4`(`12:E7F2`)와 `$D3`(`12:E827`)은 셀 `+7` 을 보고 종류 번호 2·0A 를 돌려줍니다.
점프 표 `12:E4A7` 에서 2 는 `12:EFD7`(메시지 135 ツボ), 0A 는 `12:F013`(149 タル)입니다.

346개 맵을 풀어 세어 보니 `$D3` 은 배(17/00) 창고의 タル 더미 맨 아래 줄 등 10칸이었습니다. 그 앞에서 しらべる 하자

```
537 12E534 A=FF0A X=0008 Y=0001     ; 종류 0A, 항목 없음(Y=1)
538 248BAF A=0149                   ; タルの中を　のぞきこんだ
742 248BAF A=012C                   ; しかし　何も　見つからなかった
```

선실 タンス 항목의 좌표를 이 칸(8,27)으로 바꾸자 「なんと！　やくそうを　見つけた！」가 나왔고, 셀 `+7` 을 `POKE="7ECDC7=D4"` 로 바꾸면 135 가 나왔습니다.

## 4. タンス 표 `+4` 는 읽지 않는다

`1F:F5CB` 를 가리키는 명령은 롬 전체에 4개이고 모두 `12:FB9D` 안입니다. 이 루틴은 `[BC BD]`, `[X Y]` 를 16비트로 비교한 뒤 Y 를 3 늘려 `+5` 로 건너뜁니다.
표 전체(`1F:F5CB`~`F8D3`, 미러 `9F:` 포함)에 읽기 감시를 걸고 항목을 열어도, 그룹 18 로 순간이동해 맵에 들어가도 `+4`(`1FF6E6`)를 읽는 곳은 없었습니다.

## 5. 발밑 표

검사 루틴 두 번째(`12:E6BE`)는 속성을 보지 않고 `1E:F08B` 표를 선 칸·위·오른쪽 위·오른쪽 순으로 찾습니다. 항목 모양은 タンス 표와 같은데 `+4` 를 `$C3`(주인공 방향)과 비교합니다.
여기서는 `+4` 가 쓰이니, タンス 표의 `+4` 도 원래 방향 칸이었던 것으로 보입니다.

항목 0 을 `17 00 03 05 01 A1 00 00 80`(선실 (3,5), 방향 1, やくそう)으로 덮고 같은 자리에서 しらべる 했습니다.

```
방향 1: 12E534 A=0001 → 12B 足もとを　調べた！ → 12E やくそうを　見つけた！ → 132
방향 2: 12E534 A=0003 → 12F タンスを開けて …   (발밑 항목을 지나쳐 タンス 를 염)
```

18개 중 10개가 ちいさなメダル 이고, 이것이 마을 바닥의 숨은 메달이었습니다. 열림 플래그는 `7E:2240` 부터입니다.

## 6. `D000`~`D009` 와 `FFFD`·`FFFE`

내용물 처리 `12:F43B` 는 `0100` 미만을 물건, `D000` 미만을 금화로 보고, 그 위는 `12:F493`(FFFD)·`F4B5`(FFFE)·`F4CF`(FFFF)·`F51F`(D000~)로 갑니다.
`D000`~`D009` 는 하나씩 비교하며 장소마다 정해진 일을 합니다. 선실 タンス 내용물을 하나씩 바꿔 열었습니다.

```
D000  264 カギの技法を見つけた！ → 165 覚えた！        D001  맵이 17/00 → 17/04 로 바뀜
D002  17/00 → 17/02                                    D003  28C イスをどかせて → 150 おりる階段を見つけた！
D004  2B3 すごい　ニオイがする …トイレのようだ          D005  155 ツボを見た → 152 青い光
D006·D008  12B → 150                                   D007  2F1 でっぱった石がある。押してみますか？
D009  12B → 12C
```

`D001`·`D002` 는 `$BD`·`$C1`·`$C2` 를 바꾸고 `00:D267` 로 장면을 다시 그립니다. 놓인 곳(04/02 와 04/04 의 ツボ)끼리 서로를 가리켜, 두 맵을 잇는 숨은 통로로 보입니다.

`FFFD`·`FFFE` 는 종류 번호를 보고 갈립니다. 상자면 人くい箱·ミミック 이고, 그 밖이면 메시지와 `01:868B` 에 넘기는 값이 다릅니다.

```
FFFD  상자 139 人くい箱   A=0D  | タンス 류 13B あくまのツボ  A=0F
FFFE  상자 13A ミミック   A=0C  | タンス 류 159 ツボック      A=0E
```

선실 タンス 를 `FFFD`·`FFFE` 로 바꾸자 あくまのツボ·ツボック 한 마리와 전투가 붙었습니다.

## 틀렸던 것들

- 목록 종류 4·5 의 목록이 `04:A11A`·`04:A3A2` 에 있다: `04:FBD5` 를 4개 넘게 읽은 값이었다. 두 가게는 よろず屋 목록과 따로 둔 값 표를 쓴다.
- `D000`~`D004` 는 다섯 개뿐이다: 처리기는 `D009` 까지 있고, 나머지는 새로 찾은 발밑 표에 있었다.
- `$D3`·`$D4` 는 놓인 칸이 없다: 항목이 놓인 칸이 없을 뿐, 맵에는 15칸 있다.
- 배 창고의 タル 에 はなす 를 쓰면 열린다: 「その方向には　誰もいない」였고, しらべる 여야 했다.

## 남은 것

- 여관 값에 일행 수를 곱하는 것과 값 bit7(`$0F36` → `$198E`)의 뜻. 표가 21개에서 끝나는지.
- 교회 되살리기·저주·독 값, 코인 판매 20G, 맡기는 곳 한도의 실측(돈·상태 이상이 있는 세이브스테이트 필요).
- 슬라임 레이스(`03:A1EE`)·격투장(`26:8E38`, `04:E391`)의 배당과 상품 표.
- `D001`·`D002` 의 `$1948` 조건, `D003`·`D006`·`D008` 의 계단, `D005` 가 쓰이는 곳(세 표에 없음), `D009` 의 플래그.
- `01:868B` 에 넘기는 값(`0C`~`0F`)이 몬스터를 고르는 표. 조우 고정 무리 표(`23:B04B`)와는 맞지 않는다.
