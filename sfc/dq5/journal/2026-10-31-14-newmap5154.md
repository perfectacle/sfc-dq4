# 2026-10-31-14: 그룹 51·54 의 새 맵, 걸음 루틴 몸통에서 이벤트 부르기

[새 그룹 일지](2026-10-27-55-newgroup.md)부터 남아 있던 그룹 51·54 의 새 맵을 풀었습니다. `01:94B4` 가 51·54 의 영역 이동 목록을 맵마다 즉값으로 고르기 때문에 그동안 맵을 더하지 않았습니다. [걸음 루틴 일지](2026-10-31-10-steproutine.md)가 남긴 「받침을 거친 몸통이 이벤트를 부르는 경우」도 쟀습니다. 앞 PR 리뷰의 LOW(받침 몸통 주소가 롬 밖이어도 받던 것)도 고쳤습니다. 결과는 [쓰기 형식 「그룹 51·54 새 맵」](../docs/dq5-build-format.md#그룹-5154-새-맵)과 [「뱅크 00 밖 루틴의 받침」](../docs/dq5-build-format.md#뱅크-00-밖-루틴의-받침)에 넣었습니다.

## 1. 51·54 를 고르는 자리

`01:94B4` 를 X 16비트로 다시 풀었습니다. 50·53·52 를 차례로 보고, `01:9510` 의 `CMP #$51 / BNE $9540` 에서 51 을 가릅니다. 51 은 `$BD` 를 50·51·55·52·56·57·53·54 차례로, 54 는 `01:95C9` 에서 50~53 을 견줍니다. 맞으면 목록마다 `LDA long 개수 / STA $183D / LDX #레코드 / STX $183A / LDA #뱅크` 뒤 `01:94C9`(`STA $183C / PLP / PLB / RTS`)로 갑니다.

그래서 `01:9510` 4바이트를 `JML` 로 바꾸면 51·54 를 한꺼번에 넘겨받을 수 있습니다. 50·52·53 은 그 앞에서 끝나니 건드리지 않습니다. 스텁은 A(`$BC`)가 51·54 가 아니면 원래 가던 `01:9540` 으로 돌려보냅니다. 51·54 면 `[BC][BD][개수][레코드 16비트][뱅크]` 표에서 맵을 찾아 세 값을 두고, A = 뱅크로 `01:94C9` 에 갑니다. 표에 없으면 개수를 0 으로 둡니다. 다른 그룹이 가는 `01:962D` 가 `STZ $183D` 하는 것과 같습니다.

표에는 원래 12맵도 다 넣었습니다. 원래 맵만 즉값으로 두고 새 맵만 표로 가르려면 51·54 갈래 끝(`01:95C6`·`962A`) 둘을 고쳐야 합니다. 그런데 `01:95C6` 은 51/54 맵이 맞은 갈래(`01:95C4` 의 `LDA #$01`)도 이어서 지나는 `BRL` 이라 바꿀 수 없었습니다.

## 2. 도구

`dq5exitreloc.py` 의 `--new-map` 이 51·54 를 받습니다. 새 맵마다 고층 목록을 하나씩 `high_triggers` 16개 뒤에 붙이고, `--high-hook-at` 에 스텁과 표를 둡니다. 새 맵이 있는데 `--high-hook-at` 이 없거나, 새 맵이 없는데 있으면 거부합니다. `dump --new-map 51/58` 은 그 맵의 목록을 빈 채로 내보냅니다.

`check` 는 고층 맵마다 `01:9430` 을 65816 해석기로 돌려 `$183A`·`$183C`·`$183D` 를 봅니다. 원래 롬 그대로도 고층 맵 25개를 이 해석기로 돌려 통과했으니, 스텁뿐 아니라 원래 즉값 갈래도 코드대로 따라간 것입니다.

`dq5newmap.py` 가 막던 51·54 를 풀었습니다. 고층 속성은 전처럼 `dq5encounterwrite.py` 가 씁니다.

단위 테스트는 합성 롬의 `01:94C9` 에 `STA $183C / RTS`, `01:9540` 에 `$183D = EE` 를 두고 스텁만 돌립니다. 새 맵·원래 맵이 제 목록을 고르고, 표에 없는 51 맵은 개수 0, 그룹 55 는 원래 갈래(`EE`)로 가는지 봅니다.

## 3. 밟아서 확인

새 도구 `dq5highhookcheck.py` 의 롬 `k` 는 51/58(51/55 의 레코드)·54/54(54/53 의 레코드)를 더합니다. 속성은 복사한 맵과 같게 두고, 영역 이동도 복사한 맵 것을 그대로 둡니다(고층 목록 `3F:E000`, 스텁 `3F:F000`). 롬 `n` 은 출구 패치만 뺐습니다.

```
new51: 51/51 (42, 6) 층 02
old51: 51/51 (42, 6) 층 02
orig51: 51/51 (42, 6) 층 02
new54: 54/52 (27, 18) 층 04
old54: 54/52 (27, 18) 층 04
orig54: 54/52 (27, 18) 층 04
other50: 05/01 (33, 47) 층 01
orig50: 05/01 (33, 47) 층 01
stay51: 51/58 (12, 71) 층 01
nohook51: field (196, 233) 층 01
10개 장면 통과
```

- 51/58 (12,71) 에서 아래로 걸어 (12,72) 의 영역 이동을 밟자 51/51 (42,6) 층 2 에 섰습니다. 원본 51/55 와 같은 자리입니다. 54/54 도 원본 54/53 과 같은 54/52 (27,18) 층 4 였습니다.
- 같은 롬의 원래 맵 51/55·54/53 도 원본과 같았습니다. 표로 고른 원래 목록이 맞습니다.
- 50/51 은 원본과 같은 05/01 (33,47) 이었습니다. 스텁 앞에서 끝나는 그룹은 그대로입니다.
- 스텁이 없는 `n` 롬의 51/58 에서 같은 걸음을 하자 필드 (196,233) 으로 나갔습니다. 앞 맵의 개수와 `$183C` = `$BD` 가 남은 탓으로 봅니다(까닭은 코드 읽기).

## 4. 받침 몸통에서 이벤트 부르기

`dq5stepcheck.py` 에 롬 `e` 를 더했습니다. 그룹 01 의 몸통(`3C:B000`)이 왼쪽에서 원래 루틴(`00:C409`)과 같은 꼴로 이벤트를 부릅니다.

```
LDA $00 / AND #$02 / BEQ 끝
BRK 95 00 / BRK 99 ED / BRK 0E / BRK 95 FF / SEC / RTL     ; 대화 창, 메시지 2ED, 창 닫기
끝: CLC / RTL
```

01/00 (40,84) 에서 왼쪽 12프레임, 200프레임 뒤 A, 120프레임 뒤 오른쪽 24프레임을 누르자 메시지 `2ED`「ガルルー！」가 한 번 나오고 (43,84) 까지 걸었습니다. BRK 처리기는 스택에 쌓인 K 로 인자를 읽으므로 뱅크 `3C` 의 `BRK` 도 그대로 돌았습니다.

## 5. 리뷰 LOW: 롬 밖 몸통

`dq5stepwrite.py` 는 뱅크 `01`~`7D` 의 몸통 주소를 롬 크기와 견주지 않았습니다. 몸통은 다른 패치가 쓰므로 원래 롬(1.5MB) 밖이어도 될 수 있습니다. 그래서 「이 패치를 넣은 롬」, 곧 원래 크기와 `--table-at` 뱅크까지 늘린 크기 가운데 큰 쪽을 넘으면 거부하게 했습니다. 테스트는 2MB 합성 롬의 `40:8000`(거부, `--table-at 50:8000` 이면 받음)과 1.5MB 롬의 `30:8000`(거부)·`3F:8000`(`--table-at 30:8000` 이면 받음)을 봅니다.

## 틀렸던 것들

- 처음 이벤트 몸통에는 `BRK 0E` 가 없었습니다. A 한 번으로 창은 닫혔으나 오른쪽을 눌러도 걷지 못했고 몸통도 불리지 않았습니다. A 를 한 번 더 누르면 대화 `129`「その方向には　誰もいない。」가 나온 뒤에야 걸었습니다. 원래 루틴처럼 `BRK 0E` 를 넣자 A 한 번 뒤 바로 걸었습니다.
- 왼쪽을 4프레임만 누르면 걸음으로 받지 않아 몸통이 불리지 않았습니다. 12프레임으로 늘렸습니다.

## 남은 것

- `BRK 0E` 가 무엇을 기다리는지, 빼면 왜 걷지 못하는지.
- 51·54 새 맵의 인물·문·상자·필드 출구 갈래(`2A:F52A`) 등 다른 표와의 연결은 이번에 재지 않았습니다. 이번에는 영역 이동만 쟀습니다.
- 고층 목록 나누기(`01:94B4` 의 50·52·53 그룹 공유), 통합 빌드의 새 뱅크 자리 정하기.
