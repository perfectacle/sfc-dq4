# 2026-10-25-35: 이야기 플래그 목록

DQ4 의 장(章)과 사건 진행을 DQ5 엔진에 옮기려면, DQ5 가 이야기 진행을 어디에 적고 누가 그것을 보는지부터 알아야 합니다. 그래서 이야기 플래그(`7E:2190 + 번호` 의 비트)를 켜고 끄고 보는 곳을 롬 전체에서 모으는 [tools/dq5flags.py](../tools/dq5flags.py) 를 만들었습니다. 결과는 [dq5-flags.md](../docs/dq5-flags.md) 에 있습니다.

## 1. 이미 알던 형식 모으기

플래그를 다루는 형식은 앞선 일지들에서 하나씩 나와 있었습니다.

- 네이티브 코드의 `BRK 0B`·`0C`·`0D mask idx`(시험·켜기·끄기, [2026-10-24-12](2026-10-24-12-exit-hook.md))
- 대화 스크립트의 조건 `1B`·`1A`·`1C` 와 명령 `17`·`18`·`19`([2026-10-25-01](2026-10-25-01-text.md))
- 인물 인라인 스크립트의 `06`·`09`·`10`·`11`·`55`
- 인물 목록 표 `12:839C`·`12:8449`([2026-10-24-08](2026-10-24-08-npc-flags.md))
- 맵별 루틴 표 `15:F907`

대화 스크립트와 인물 쪽은 `dq5talk.py`·`dq5npc.py` 의 파서를 그대로 씁니다. 대화 번호마다 그 번호를 쓰는 인물이 어느 맵에 있는지도 인물 목록에서 거꾸로 찾아 붙였습니다.

## 2. 네이티브 코드 훑기

`BRK 0B`·`0C`·`0D` 는 코드를 따라가며 찾지 않고 롬 바이트에서 `00 0B`·`00 0C`·`00 0D` 를 찾았습니다. 처음 세어 보니 `00 0C` 가 1,003번이었고, 그중 뱅크 `0C`·`0D`·`0E` 에 240번 넘게 몰려 있었습니다. 앞뒤 바이트를 보니 그림 데이터였습니다.

```
0C:8742  ... 49 06 20 08 02 82 00 0c 66 0c 0c 3c f8 e0 ...
```

그래서 기준을 둘 세웠습니다. 하나는 시험(`0B`) 바로 뒤가 BEQ·BNE 인 경우로, 이것이 다섯 번 이상 나오는 뱅크만 코드 뱅크로 봅니다(뒤에 게임에서 `BRK 0B` 실행을 본 `29` 를 더함). 다른 하나로, `0B` 는 뒤가 BEQ·BNE 일 때, `0C`·`0D` 는 뒤가 흔한 명령일 때만 셉니다.
게임에서 실제로 쓰는 쓰기를 보니 `STA $7E21C7` 처럼 롱 주소로 바이트를 다루는 곳도 많았습니다. 그래서 `7E:2190`~`220F` 롱 주소 명령도 함께 찾았습니다.

## 3. 게임에서 잡은 것과 맞추기

놓치는 것이 얼마나 되는지 보려고 `sfc/dq5/tools/lua/dq5flagtrace.lua` 를 만들었습니다. BRK 벡터 처리기(`00:8F80`)에 들어올 때 스택의 돌아갈 주소에서 BRK 자리와 서명 바이트를 읽고, `7E:2190`~`220F` 쓰기를 적습니다.
`dq5warp.lua` 로 장면을 옮기거나(`TO`·`FIELD`) `seqlib.sh` 의 드라이버로 돌 수 있습니다.

```sh
export LIBDIR=$(uv run --locked krpatch sfc lua)
STATE=$PWD/work/state/ship.mss FIELD=341,56 BATTLE="00:1" TEST="a:4,wait:30,…" MAXF=8000 \
  SHOT_DIR=$PWD/work/t1 "$MESENCE" --testrunner "$PWD/rom/dq5.sfc" "$PWD/sfc/dq5/tools/lua/dq5flagtrace.lua"
uv run --locked python sfc/dq5/tools/dq5flags.py rom/dq5.sfc --check work/t1/flagtrace.txt …
```

```
1588 brk 02:A7AB 0C 08 02        ← 첫 필드 이벤트 끝, 2192.3 켬
1860 brk 06:CFC8 0C 80 15        ← 21A5.7 켬
BRK 자리 49개, 롱 쓰기 26개 중 75개가 목록에 있음
```

첫 필드 이벤트, 필드 걷기, 01/04, 선실과 아래 대화 실험에서 잡은 BRK 자리 49곳과 롱 쓰기 26곳이 모두 목록에 있었습니다. 다만 정적 훑기는 시험·켜기의 바로 뒤를 보는 규칙이라, 놓치지 않았다고 장담하지는 못합니다.

## 4. 대화로 확인

[2026-10-25-01](2026-10-25-01-text.md) 의 요령대로 선실 파파스의 대화 번호를 `POKE` 로 바꿔 말을 걸었습니다.

목록에서 `2191.7` 은 대화 `01F`(21/0B) 가 보고 대화 `020`(21/04) 이 켭니다.

| 대화 | 넣은 플래그 | 결과 |
| --- | --- | --- |
| `01F` | 없음 | 「たぶん　この村の洞くつに 入っていったと思うけど…」(`768`) |
| `01F` | `2191` = `80` | 「さっそく　薬を　調合してるから 明日の朝には…」(`76E`) |
| `020` | 없음 | 「坊や　わるいが　この岩を…」 뒤 `219D=20` 쓰기 |
| `020` | `219D`·`2194` = `20` | 「やれやれ　たすかった！」 갈래, `2191=B0` 쓰기 |

목록의 「봄 대화 01F」, 「켬 대화 020 0681FA(`219D.5`)」, 「켬 대화 020 0681EC(`2191.7`)」 와 같았습니다.

필드에서 `21A5` bit7 을 켜 두면 주인공이 움직이지 않았고, 조우 판정도 한 번도 불리지 않았습니다. 이 비트는 첫 필드 이벤트 뒤 `06:CFC8` 이 켭니다.
