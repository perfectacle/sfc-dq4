# 2026-10-25-82: 전투 메시지의 남은 코드와 바다 배경

전투 모드 메시지 디코더(`sfc/dq5/tools/dq5battletext.py`)에서 화면으로 확인하지 못했던 제어 코드 `F2`·`F9`·`EA`·`FA`·`E2`·`E4` 와, 글자표로는 「ダ·ズ·ゾ」로 찍히던 바이트를 전투 화면에 띄워 확인했습니다. 바다를 배로 지날 때의 배경 번호도 다시 봤습니다. 결과는 [dq5-data-format.md 「전투 모드 메시지」](../docs/dq5-data-format.md) 와 [dq5-graphics-format.md 「번호를 정하는 곳」](../docs/dq5-graphics-format.md#번호를-정하는-곳) 에 있습니다.

## 1. 아무 메시지나 전투 창에 띄우기

장면 이동 도구로 슬라임 하나와 싸우게 하고(`BATTLE=00:1`), 메시지 루틴 `24:8C39` 에 들어올 때 A 를 바꾸는 `sfc/dq5/tools/lua/dq5msgswap.lua` 를 썼습니다. 「スライムの　こうげき！」(`05E`)가 불릴 때마다 차례로 다른 메시지 번호로 바꿉니다. MesenCE 의 `emu.setState` 로 `cpu.a` 를 고치면 그대로 먹었습니다.

```lua
emu.addMemoryCallback(function()
  local s = emu.getState()
  if (s["cpu.a"] & 0xFFFF) == 0x05E and k <= #tos then
    s["cpu.a"] = (s["cpu.a"] & 0xFF0000) | tos[k]; emu.setState(s); k = k + 1
  end
end, emu.callbackType.exec, 0x248C39, 0x248C39)
```

```sh
LIBDIR=$(tools/lua/seqlib.sh "$(uv run --locked krpatch sfc lua)" work/warplib ../../sfc/dq5/tools/lua/dq5warp.lua)
env LIBDIR=$LIBDIR STATE=$PWD/work/state/ship.mss FIELD=341,56 BATTLE="00:1" POKE="7E204E=E7;7E204F=03" SETTLE=300 \
  TEST="wait:200,a:4,wait:30,a:4,wait:30,…" FROMMSG=05E TOMSG=118 SHOTS=… MAXF=1600 SHOT_DIR=$PWD/work/m/t1 \

```

## 2. 글자

`118` 은 바이트로 `89 9C 83 5B 6A …` 로 시작해 디코더가 「だゾパルプンテ」로 찍던 메시지입니다. 화면에는 「＊「パルプンテ　パルプンテ　パルプンテ……。」로 떴습니다. `89` 는 「＊」, `9C` 는 「「」, `9D` 는 「…」, `9A` 는 「。」였고, `136` 「＊「おや　おきゃくさん　おかえりですね。」도 같았습니다. 같은 메시지 안의 「フジミだ」「キズ」는 `83` 을 앞에 붙인 탁점 글자라 겹치지 않습니다. 디코더에 `BATTLE_GLYPHS` 로 넣었습니다.

## 3. 제어 코드

- `EA`: `192` 「なんと　{EA}が　せんとうに　おどりでた！」가 「なんと　フローラが　せんとうに　おどりでた！」로 떴습니다.
- `FA`: `0A0`「{ED}{FA}は　ぜんめつした！」는 주인공 혼자면 「あああああは」, `PARTY=02` 로 동료를 하나 넣으면 「あああああたちは」였습니다. `0BE` 의 `{EE}{FA}` 도 「あああああたちは」.
- `F2`: 처리기 `24:886C` 는 메시지 속도 `7E:2035` 로 `24:8891` → `27:8000` 표를 찾아 그만큼 기다립니다. 속도를 `00`·`03`·`07` 로 고정하고 처리기에 들어오고 나가는 프레임을 재니 23·27·1 프레임이었습니다(표 값 22·26 + 1, 속도 7 은 표를 건너뜀).
- `F9`: `BRK 19 32` 는 기다림이 아니었습니다. 들어오고 나가는 프레임이 같았고, 그 3프레임 뒤 APU 포트에 `$2141` = `0C`, `$2142` = `32` 가 쓰였습니다. `05E` 를 띄울 때는 `05 32` 였습니다.
- `FD`: ▼ 를 띄워 누르기를 기다린 뒤 다음 글을 셋째 줄에 이어 썼습니다.
- `E2`·`E4`: 432개 메시지를 모두 풀어도 쓰는 메시지가 없었습니다.

## 4. 배로 바다 건너기

`$1954` 에 쓰는 곳을 롬에서 찾으니 `01:82F5`·`01:832A` 가 `03` 을 썼습니다(배에 오르는 쪽). 앞 일지에서 쓴 `80` 은 배가 아니었습니다. 주인공 그림은 `7E:21BE` bit0 이 배(`98`)로 바꿉니다.

바다 위 (328,27)에서 `LATESET="1954=03;21BE|01"` 로 배를 띄워 위아래로 저었더니 걸음마다 `$1AA0` = `00` 이 되었고, `probe/trace.lua` 로 보면 걸음마다 `00:82AB`·`01:84CF`·조우 검사 `23:E7C2`(구역 `52`)가 돌았습니다.

```sh
env LIBDIR=$LIBDIR STATE=$PWD/work/state/ship.mss FIELD=328,27 LATESET="1954=03;21BE|01" ROMPATCH="11EA44=FFFFFFFFFFFFFFFF" \
  SETTLE=30 TEST="up:30,wait:10,up:30,wait:10,down:30,wait:300" TRACE=0082AB,0184CF,23E7C2,23E898 LOG=7E1A98,7E1954 \
  MAXF=1100 LIMIT=600 SHOT_DIR=$PWD/work/sea/t1 "$MESENCE" --testrunner "$PWD/rom/dq5.sfc" "$PWD/work/warplib/probe/trace.lua"
```

조우 계수 표 `23:EA44` 를 모두 `FF` 로 덮어도 바다에서는 전투가 붙지 않았습니다(땅에 닿은 뒤에는 곧바로 숲 배경 전투가 붙음). 그래서 바다 그림 배경 00 은 이벤트 전투에 `$1AA0` = `00` 을 고정해 `dq5battlebg.py 00 --compare` 로 견줬고, 타일맵 셋 256칸·팔레트 38색·펴진 110줄이 모두 맞았습니다.

## 틀렸던 것들

- 앞 일지는 `$1954` = `80` 을 배로 보고 「배로 가는 동안 걸음 처리가 돌지 않는다」고 적었습니다. 배는 `03` 이고, 배로 가는 동안에도 걸음 처리와 조우 검사가 돕니다.
- `F9` 를 이름 그대로 「기다림」으로 읽었습니다. 처리기에서 시간을 쓰지 않고 소리 명령을 보냅니다.

## 남은 것

- 바다에서 전투가 붙지 않는 까닭(`23:E7C2` 의 나머지 조건, 구역 `52` 의 내용).
- `F9` 의 소리 `0C 32` 가 무슨 소리인지, `E2`·`E4` 를 쓰는 다른 텍스트가 있는지.
