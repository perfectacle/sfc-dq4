# 2026-10-26-25: ラインハット 의 パパス 를 움직이는 21A1.7 은 이벤트 28 이 맵을 넘어가며 켬

[2026-10-26-09](2026-10-26-09-papas0100.md) 에서 원래 이야기 순서(`21A7.5` 뒤)의 01/04·01/00 パパス 가 기다리는 `21A1.7` 을 켜는 곳을 못 찾았습니다. 01/05 에서 パパス 에게 납치를 알린 뒤 도는 이벤트 번호 `28` 이 주인공을 01/04·01/00 으로 걸어 옮기면서, 맵마다 들어선 뒤 `21A1.7` 을 다시 켭니다. 같은 그룹 안에서 맵을 옮기면 `21A1` 이 지워지지만 이벤트 스크립트는 맵을 넘어 이어 돌기 때문입니다. 결과는 [이야기 진행 지도](../docs/dq5-story.md) 의 28~30 줄에 적었습니다.

실험에는 `sfc/dq5/tools/lua/dq5seqtrace.lua` 에 `ROMPATCH`(첫 프레임에 파일 오프셋의 롬 바이트를 덮음)를 더해 썼습니다.

## 1. 원래 순서로 납치 장면부터 걷기

`dq5warp.lua` 로 `TO=01/04,62,14 SET="219E|02;219A|10"`(ヘンリー 의 방, 목록 `10:8728`)에 들어가 위로 걸었습니다. 46 프레임에 (59,4)-(67,9) 에 들어서자 `21A7` = `40`(`21A7.6`), 메시지 `028D`, 355 프레임 `21A1` = `80` 뒤 산적이 ヘンリー 를 데려가 861 프레임에 조작이 풀렸습니다. 문 (67,10) 을 지나 (67,12)~(67,15) 의 영역 이동으로 01/00 (51,30) 에 서자, 162 프레임에 `21A7` = `60`·`219B` = `02`, 메시지 `0290`「おい！　はやく王子を舟へ！」였습니다.

이 상태로 01/04 에 돌아가 보니 パパス(목록 `10:87ED` 의 다섯째, 슬롯 `0C`)가 (64,15) 에 놓였다가 다음 프레임에 (128,128) 로 숨겨졌습니다. 01/04 의 목록 루틴 `12:998F`(표 `12:AFC1` 의 01/04 항목)가 `2190` 단계 비트가 꺼진 갈래에서 이렇게 봅니다.

```
12:99EE  BRK 0B 01 16   ; 21A6.0
         BNE 99FF
         BRK 0B 40 17   ; 21A7.6
         BEQ 99FF
         LDX #$0C / BRL 8CCC      ; 21A6.0 꺼짐·21A7.6 켜짐이면 パパス 숨김
99FF     BRK 0B 80 17   ; 21A7.7
         BEQ (RTS)
         LDX #$0C / BRL 8CCC      ; 이미 나갔으면 숨김
```

2026-10-26-09 의 01/04 실험은 `21A7|60` 이라 パパス 가 숨은 채였고, `21A7|20` 으로 들어가 말을 걸었을 때는 대화 번호 `000` 이라 메시지 `1CC` 뿐이었습니다. 원래 순서에서는 `21A6.0` 이 먼저 켜져 있어야 합니다.

## 2. 21A6.0 은 01/05 의 パパス

`21A6.0` 을 켜는 곳은 01/05 대체 목록 `10:896D`(`21A7.6`) 의 パパス 하나입니다. 그 인라인 스크립트는 주인공이 (42,4)-(46,9) 에 들어서면 메시지 `0291` 뒤 `21A6.0` 을 켜고, 네이티브 `06:CC01`·`06:CBA4`·`06:CC08` 로 이벤트 번호 `27`, `07`~`0C`(주인공 Y 로 고름), `28` 을 겁니다. 번호 `28`(`15:F3CD`)은 이렇습니다.

```
15F3CD 01 0e   걷기 오른쪽 14칸
15F3CF 04 0c   걷기 아래 12칸
15F3D1 10 12 80  21A2.7 켜기
15F3D4 b0 13 80  21A3.7 기다림        ; パパス 의 메시지 0292·0293 뒤
15F3D7 04 02 / 01 03 / c2            ; 아래 2, 오른쪽 3 → 01/04 로
15F3DC 10 11 80  21A1.7 켜기
15F3DF b0 11 40  21A1.6 기다림
15F3E2 08 04 / 01 03 / c2            ; 위 4, 오른쪽 3 → 01/00 으로
15F3E7 10 11 80  21A1.7 켜기
15F3EA b0 11 40  21A1.6 기다림
```

`dq5flags.py` 의 `21A1.7` 켜는 곳 목록에도 `15F3DC`·`15F3E7`(번호 28)이 있었지만, 01/05 의 이벤트라 앞 세션은 후보에서 뺐습니다.

## 3. 실측

선실 세이브스테이트에서 `TO=01/05,42,8 SET="219A|10;219B|02;219E|02;21A7|60"`(1절의 두 장면 뒤와 같은 비트)으로 들어가 A 를 40 프레임마다 눌렀습니다.

```sh
T="wait:10"; for k in $(seq 1 40); do T="$T,a:4,wait:40"; done
STATE=<01/05 세이브스테이트> SEQ="$T" HOOK=23E2F4 \
  WLOG="bc=7E00BC;bd=7E00BD;a1=7E21A1;a7=7E21A7;9b=7E219B" MAXF=1900 SHOT_DIR=$PWD/work/papas \
  "$MESENCE" --testrunner "$PWD/rom/dq5.sfc" "$PWD/sfc/dq5/tools/lua/dq5seqtrace.lua"
```

| 프레임 | 일 |
| --- | --- |
| 63·104·137 | `23:E2F4` A = `27`·`0C`·`28` |
| 673 | 마지막 오른쪽 걸음에서 01/04 (64,17) 로 옮김, `21A1` 지워짐 |
| 743 | `21A1` = `C0`, `21A7` = `E0`: パパス(슬롯 `0C`)가 `21A1.7` 을 보고 `21A7.7`·`21A1.6` 을 켬 |
| 825 | 01/00 으로 옮김, `21A1` 지워짐 |
| 920 | `21A1` = `80`, `219B` = `03`: 01/00 의 パパス 가 `219B.0` 을 켬 |
| 952 | `21A1` = `C0` |

같은 실행에서 `ROMPATCH="AF3DE=00"`(15:F3DC 의 마스크 `80` → `00`)이면 01/04 에서 パパス 가 (64,15) 에 선 채 `21A1`·`21A7` 이 바뀌지 않았고, `ROMPATCH="AF3E9=00"`(15:F3E7)이면 01/04 까지는 같고 01/00 에서 `219B` 가 `02` 로 남았습니다. 두 パパス 의 `21A1.7` 은 이 두 명령이 켭니다.

들어선 X 가 44·45 면 번호 28 의 걸음이 01/05 (65,19)·(66,19) 에서 끝나 맵을 옮기지 않았고, 01/05 에서 `21A1.7` 을 켜도 받는 사람이 없어 멈췄습니다. 42·43 은 둘 다 위 표와 같았습니다. 걸음이 들어선 자리에서 상대적으로 옮겨 가는 것이라, (42,4)-(46,9) 의 왼쪽에서 걸어 들어오는 원래 길에서 맞습니다.

## 틀렸던 것들

- 「01/04·01/00 모두 들어설 때 `21A1.7` 을 켜는 곳이 없다」(2026-10-26-09): 맵을 들어설 때 켜는 코드는 정말 없고, 이어 돌던 이벤트 스크립트가 들어선 뒤 켭니다.
- 「원래 순서의 01/04 에서 パパス 가 기다린다」: `21A7.6` 이 켜진 채 `21A6.0` 이 꺼져 있으면 `12:998F` 가 パパス 를 숨깁니다. 01/05 장면 전에는 01/04 에 パパス 가 없습니다.
