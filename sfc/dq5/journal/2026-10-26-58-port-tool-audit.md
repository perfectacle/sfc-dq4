# 2026-10-26-58: DQ4 포팅 도구 누락과 통합 충돌 점검

완성한 개별 쓰기 도구만으로 DQ4를 포팅할 수 있는지 확인했습니다. 출구·인물 배치·대화 분기·주문 습득·범용 그림·게임 전체 한글 경로가 남아 있었고, DQ4 타이틀·메뉴와의 기본 배치 충돌도 재현했습니다. 분야별 목록과 재현 근거는 [포팅 도구 점검](../docs/dq5-port-tool-audit.md)에 있습니다.

## 1. 읽기 도구와 쓰기 도구를 나누기

`b38afd1`에서 DQ5·SFC DQ4 도구의 CLI와 패치 함수·입력 스키마를 대조하고, FC DQ4의 장별 진행·저장 형식에서 필요한 연결을 찾았습니다. 단순히 이름에 `write`가 있는지 세지 않았습니다. 음악과 효과음은 `dq5song.py`의 공용 인코더가 있고, 타이틀·서곡·한글 메뉴·조합형 이름 입력도 실제 포팅 도구가 있었습니다.

반면 인물 재배치는 스크립트 길이를 바꿀 뿐 인물 레코드를 새로 만드는 기능은 아니었습니다. 보행 대사 본문과 대화 조건 VM도 별개였습니다. 지원하지 않는 입력을 실제로 주어 거부되는 범위를 확인했습니다.

## 2. 포팅 타이틀까지 합쳐 보기

현재 코드를 사용해 타이틀·서곡·메뉴 롬을 다시 만들었습니다. `dq5build.py fromrom`으로 패치 목록으로 바꾸고 기본 쓰기 도구와 합치자 맵 `30:8000`, 인물 `32:8000`, 필드 `34:8000`, 대사 `38:8000`, 이벤트와 메뉴 `60:8000`에서 모두 겹침 오류가 났습니다.

타이틀의 실제 그래픽 자료는 203,456바이트였습니다. 저뱅크에 원본 규모의 맵·인물·필드·대사까지 모두 재배치하면, 배치 목록에서 다시 컴파일한 맵 기준 681,634바이트로 524,288바이트의 공간을 넘습니다. 미러 복제와 순수 자료량을 구분했고, 아직 게임에서 돌리지 않은 상위 뱅크 이동 후보는 설계 근거로만 적었습니다.

## 3. 없는 맵 번호가 가리키는 곳

`17/00`에서 뽑은 JSON의 맵 번호만 `17/05`로 바꿨습니다. 원본에 없는 번호인데 패치 생성은 성공했습니다. 빌더로 만든 롬에서는 `18/00`의 포인터가 실제로 바뀌었습니다.

```text
포인터 자리 0F:8CD3
원본 f0 cf 1b → 생성 롬 00 80 30
1B:CFF0 → 30:8000
```

또 `exits`를 입력에 덧붙여도 원래와 같은 패치를 내며 성공으로 끝났습니다. 이는 출구 지원이 아니라 미지원 필드를 무시하는 동작입니다. 입력 보호와 새 맵 증설 기능을 구분해 후속 수정으로 남겼습니다.

## 4. 기존 표 쓰기를 게임에서 확인하기

`dq5tables.py`로 물건 `00`의 힘을 2에서 77로 바꾸었습니다. 실제 처리기 `21:A495`의 읽기 값이 `02`에서 `4D`로 바뀌었고 상점 장비 비교창 공격력은 13에서 88로 올랐습니다. 읽기 값은 로그로, 화면 수치는 두 캡처를 직접 비교했습니다.

메라 `01`의 소비 MP를 7로 바꾼 롬에서는 파파스가 주문을 쓸 때 MP가 `65→58→51→44→37`로 줄었습니다. 이 값은 전투용 표이며 AI와 필드 주문의 별도 값까지 함께 바뀐 것은 아닙니다.

기존 DQ4 메뉴·이름 입력 롬도 다시 만들고 MesenCE 검사 15건을 통과했습니다. 이름 칸 VRAM은 256바이트 중 차이가 0이었습니다. 음악·효과음 71시퀀스, 보행 대사 3,200개 왕복과 라이안 정면 삽입도 확인했습니다. 이들 빌드·왕복 결과를 이번 게임 실행 결과와 구분했습니다.

## 틀렸던 것들

개별 도구들이 원본 DQ5 위에서 함께 빌드된다는 사실만으로 DQ4 포팅 통합까지 확인했다고 볼 수 없었습니다. 실제 포팅 타이틀·메뉴를 포함하자 기본 배치가 충돌했습니다. ‘쓰기 도구 완료’ 역시 기존 슬롯 편집, 새 항목 증설, 다른 표와의 연결을 따로 보아야 했습니다.
