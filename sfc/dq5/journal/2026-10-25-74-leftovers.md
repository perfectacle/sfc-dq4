# 2026-10-25-74: 실내 맵 슬롯 처리, 세계 1·2 조우 대조, 전투 메시지

주인 없이 남은 todo 항목 셋을 정리했습니다. 그룹 `$50` 이상 맵에서 찾은 「맵보다 먼저 슬롯을 받는 처리」가 실내 맵에서도 돌아 343개 맵 셀 버퍼를 모두 맞췄고, 세계 1·2 의 조우를 지형까지 대조했고, 전투 모드 메시지 디코더를 만들었습니다.
결과는 [dq5-map-format.md](../docs/dq5-map-format.md) 의 「그룹 `$50` 이상」, [dq5-data-format.md](../docs/dq5-data-format.md) 의 「전투 조우」·「전투 모드 메시지」에 있습니다.

## 1. 실내 맵도 슬롯을 먼저 받는다

`03:D3E9` 는 `$BC` < `$50` 이면 실내 블록 표로 블록을 올리고, `04:822D` 에는 실내 맵 항목도 있습니다. 22/00·02/00 을 `01:BA4C` 에서 덤프해 `dq5map.py` 와 비교하니 VRAM 슬롯 번호가 `12`·`18` 만큼 어긋났고, 그 처리를 넣자 0바이트 차이였습니다.
그래서 실내 맵 343개를 모두 순간이동해 덤프했습니다. 패스 3 이 없는 맵은 `01:BA4C` 를 지나지 않아 `01:8F23` 에서 덤프했습니다.

```
처리를 거치면 343개 중 343개 0바이트 차이
거치지 않으면 101개 어긋남(= 표에 든 맵 수)
```

처음에는 06/00 등 배 맵 넷이 어긋났는데, `03:D806` 마스크 `8103` 의 bit15 를 잘라 냈기 때문이었습니다. `03:D460` 은 16비트를 모두 밀어 보며, 7FFF 로 자른 값은 따로 `$1ED0` 에 둡니다.
그룹 `$50` 이상 18개도 다시 덤프해 모두 0바이트 차이인 것을 확인했습니다.

## 2. 세계 1·2 의 조우

세계 1·2 는 지형 표(`03:CB1B`)가 같고 지도만 바뀌므로, `dq5encounter.py --steps` 가 `$1949` 에 맞는 지도(`dq5field.WORLDS`)로 지형을 구하게 했습니다. 각 세계 세 곳에서 조우를 끄고 걸으며 `00:82AF` 를 추적했습니다.

```
세계 1: 150·181·192걸음, 세계 2: 245·65·93걸음 — 모두 0번 어긋남
```

926걸음, 격자 칸 44곳, 지형 1·2·4·5·6·7 이 표대로 구역·조우율을 냈습니다.

## 3. 전투 모드 메시지

`24:8C39` 는 보행 모드와 같은 방식이지만 트리가 `24:9C2E`·`24:9D18`, 처음 X 가 `E8`, 잎이 1바이트입니다. 432개를 풀어 보니 이름 문자열 부호로 그대로 읽혔습니다. 풀린 바이트는 `7E:0E4B` 에 쌓이고 `24:86A5` 가 하나씩 꺼내며 `E2` 이상을 `24:86F2` 처리기로 보냅니다.
이벤트 전투에서 메시지 번호를 추적하고 화면을 찍어 대조했습니다.

```
899 05E  「あああああの　こうげき！」     963 069  「スライムに　4の　ダメージ！！」
1006 05E 「スライムの　こうげき！」       1046 06A 「あああああは　1の　ダメージを　うけた！」
```

## 4. 셀 `+1` bit6 만 켜진 칸

18/00 의 (10,22)~(10,29) 는 `+1` = `43`(bit6, 층 1·2)입니다. 그 길을 걸어 오르며 bit6 을 지웠더니 걸음은 프레임까지 같았지만, 지운 쪽에서만 578프레임에 상태 창이 뜨고 그 뒤 화면 색이 넓게 달랐습니다. 아직 뜻을 정하지 못했습니다.

## 틀렸던 것들
