# 2026-10-25-61: 대화 번호 000, 네이티브 호출 갈래, 창 머리, 몸짓 위치

조건 `03` 인자 `47` 의 인물과 `BRK 8C`, `1112`·`1114`·`1118` 몸짓이 바꾸는 값을 확인했습니다. 결과는 [dq5-text-format.md](../docs/dq5-text-format.md) 의 「특수 기능」·「네이티브 호출」·「창 레코드 머리」·「일행 조회」·「몸짓 코드」 에 있습니다.

## 1. 대화 번호 000 인물

대화 번호 `000` 인 인물 엔트리는 대체 목록까지 875개입니다. 먼저 선실의 `000` 인물(17/00 (6,9), 그림 `A6`, 슬롯 `0C`) 앞에 서서 말을 걸었습니다.

```sh
WL=$(tools/lua/seqlib.sh "$(uv run --locked krpatch sfc lua)" work/walklib walk.lua)
LIBDIR=$WL STATE=$PWD/work/state/ship.mss PRE="b:4,wait:40" WAYPOINTS="6,11;6,10;up:6;a:4;wait:40;a:4;wait:200" \
  CHANGES=9 MAXF=700 CALLS=248BAF,06AF62,0582C0 SHOT_DIR=$PWD/work/talk0/a6 "$MESENCE" --testrunner "$PWD/rom/dq5.sfc" "$WL/probe/calls.lua"
```

```
133 0582C0 A=0000 …
134 248BAF A=0129
```

대화 처리기 `06:AF62` 는 불리지도 않고 「誰もいない」(`129`)가 나왔습니다. 말을 걸 상대를 고르는 `05:82C0` 을 따라가니, 앞 칸에 인물이 있어도 그림 번호를 `05:862F` 목록과 견주어 목록에 있으면 건너뛰었습니다(`05:85F8`).
목록은 `46 47 48 49 4B 4C 4D 4F 78`~`7F 80 81 83 84 63 4A 99 12 24 35 98 A4`~`A8 FE` 이고, 875개 중 443개가 이 그림입니다.

나머지 432개는 상대가 됩니다. 선실에서 숨어 있는 뱃사람(그림 `2E`, 슬롯 `0A`, 대화 번호 `000`)을 `POKE="7E302A=09;7E308A=09"` 로 주인공 앞에 두고 말을 걸었습니다.

```
115 06AF62 A=00FF
115 06DBD2 A=0000
116 248BAF A=01CC
```

특수 기능 `00` 으로 가서 「その方向には ダレモイナイ。」(`1CC`)가 나왔습니다. 대화 번호를 실행 중에 쓰는 코드(`STA $36E0,Y`)는 슬롯끼리 값을 옮기는 세 곳뿐이라, `000` 인물이 따로 대사를 갖는 길은 없었습니다.

## 2. 네이티브 호출 142곳

`dq5talk.py --calls` 가 대상마다 첫 `RTS`·`RTL`·`JMP` 까지 곧게 읽어, 띄우는 창·메시지, `BRK 0C`·`0D` 로 켜고 끄는 플래그, 부르는 루틴을 찍게 했습니다.
`BRK` 는 번호마다 뒤에 붙는 바이트 수가 달라서, 처리기(`00:921B` 표)가 `00:8FAC` 로 바이트를 꺼내는 횟수와 `00:920A` 표 비트로 길이를 정했습니다.

```
06:C254 8 가게 JSL 04:D977, JSR E384
06:B604 1 메시지 win 00, flag? 1F&02, query 88 33, msg 43A
06:F83B 11 값 쓰기 STA $19AE
06:FB8F 1 장면 JSL 01:86C3, flag 2B|10
```

갈래는 가게 8곳(40번), 메시지 52곳(56번), 장면 24곳(28번), 값 쓰기 12곳(49번), 호출 45곳(55번), 빈 루틴 1곳입니다. 갈래 붙이기는 코드 읽기이고, 가게 갈래는 앞서 대화 번호로 가게를 열어 본 실험과 같은 처리기입니다.

## 3. 창 레코드 머리 +4·+5

명령 창 머리의 `+4`(`00`)·`+5`(`04`) 를 한 비트씩 뒤집어 명령 창을 열었습니다(파일 오프셋 `26D10`·`26D11`).

| 바꾼 값 | 화면 |
| --- | --- |
| `+4` = `01`·`02`·`04`·`08` | 창이 뜨지 않고 어두운 맵에서 멈춤 |
| `+4` = `10`·`20`·`40`·`80` | 그대로 |
| `+5` = `05`·`06`·`00`·`0C` | 물건 목록 같은 다른 창이 겹쳐 뜸 |
| `+5` = `24` | 항목 글자가 한 칸 오른쪽 |
| `+5` = `14`·`44`·`84` | 그대로 |

창 레코드 222개를 훑으니 `+4` 아래 4비트가 0 인 39개는 첫 `FE` 가 모두 `+6`, 0 이 아닌 것은 `+7`·`+8` 이었습니다. `+4` 가 머리 길이를 정하는 것으로 보입니다.

상태 창은 자리 바이트를 하나씩 바꿨습니다. `83` 을 `82` 로 하면 「Lv:」 줄이 사라지고 `84` 면 엉뚱한 줄이 하나 더 생겨, 아래 비트가 그 뒤 줄 수였습니다. `87`·`85` 는 바꾸자 「Ex:」·「―:」·「5:」·「LvEx」 처럼 찍혀, 이 창에서 `85`~`88` 은 「:」·「Ex」·「Lv」·「―」 를 찍는 바이트입니다.

## 4. 인물 번호 47 과 BRK 8C

일행 레코드 둘째에 번호를 넣고 `1008` 로 이름을 띄우는 방법(앞 일지 4절)을 이어 썼습니다.

```
47 フローラ  0D ラインハットおうじ  0E ああああのつま  10 ああああのむすこ  46 ピピン  48 パパス
```

조건 `03 47` 은 「フローラさんの だんなさん」 같은 대사 앞에 있어, 결혼한 フローラ 와 함께일 때입니다. 거르개 bit5 가 보는 `+1` bit6 은 마비라는 것이 [dq5-data-format.md 「주문과 행동」](../docs/dq5-data-format.md#주문과-행동-268765) 에 실측되어 있습니다.
`BRK 8C` 는 `00:920A` 표 값 `A8` 로 `$38` 을 읽고 A 의 아래·위를 `$42`·`$43` 에 넣습니다. `1013` 이 이것으로 일행 레코드의 이름을 읽어 ボロンゴ 를 찍은 것이 앞 일지의 실험입니다.

## 5. 1112·1114·1118 이 바꾸는 값

인물 표 전체(`7E:3000`~`37FF`) 가운데 파파스 슬롯(`& 1F = 0B`) 쓰기만 기록하도록 프로브에 `WWRANGE` 를 더했습니다.

```sh
TALK_A="b:4,wait:40,up:3,wait:20,a:4,wait:30,a:4$(printf ',wait:56,a:4%.0s' $(seq 14))"
STATE=$PWD/work/state/ship.mss PRE="$TALK_A" MAXF=240 CALLS=2481A4 ROMPATCH="30139=6758" WWRANGE="7E3000-7E37FF:1F=0B" \
  SHOT_DIR=$PWD/work/gesture2/758 "$MESENCE" --testrunner "$PWD/rom/dq5.sfc" "$PWD/sfc/dq5/tools/lua/dq5msg.lua"
```

```
758(1112): 136 7E300B=20  138 7E300B=00  140 7E300B=20  142 7E300B=00 …
8FA(1114): 209 7E318B=FF  212 7E318B=00  219 7E318B=FF  222 7E318B=00
589(1118): 187 7E318B=01  190 7E318B=00
```

`7E:3180` 을 `FC` 로 고정하자 파파스 그림이 4점 내려가, 세로 어긋남입니다. 기침은 한 점씩 두 번, 딸꾹질은 한 번 움직입니다. `1112` 는 `7E:3000` 을 2프레임마다 바꾸는 떨림입니다.

## 틀렸던 것들

- 대화 번호 `000` 인물은 인라인 스크립트로 대사가 정해진다고 보았다: 절반은 말을 걸 상대가 아니고, 나머지는 모두 `1CC` 였다.
- 처음엔 주인공을 `000` 인물 바로 아래 칸에 세우고 말을 걸었다: 상대를 찾는 범위가 두 셀 앞이라 칸이 맞지 않았고, 그 뒤에도 그림 번호 목록 때문에 상대가 되지 않았다.
