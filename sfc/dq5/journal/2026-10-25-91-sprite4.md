# 2026-10-25-91: 맵 OBJ 물체 배치와 마지막 인물 세트

맵 OBJ 타일을 어디에 어떻게 그리는지 찾았고, 확인하지 못했던 인물 세트를 마저 확인했습니다. 결과는 [dq5-graphics-format.md](../docs/dq5-graphics-format.md) 의 「맵 OBJ 물체」「검증」 에 있습니다.

## 1. 맵 OBJ 물체는 탈것 슬롯이었다

07/00 덤프에서 맵 OBJ 타일 `13D` 를 쓰는 OAM 이 2x3 칸 두 묶음으로 나왔습니다. OAM 버퍼에 이 타일 번호를 쓰는 곳을 잡자 탈것을 그리는 `00:FC9E` 였습니다.
그 슬롯은 `7E:3220` 이 `FE` 인 탈것 슬롯이었고, 가로·세로 칸 수와 칸 목록도 탈것과 같은 자리에 있었습니다.
칸 목록을 만드는 `16:F7DD` 를 부르는 곳 셋 중 `16:F6E6`·`16:F789` 가 `16:F862` 의 9바이트 항목을 읽었습니다. 항목은 [맵][자리][가로·세로][팔레트][칸 바이트 주소]이고 모두 74개입니다.

```
07 00 x 19 y 34 c02 r3 f4C ptr 16FB81 00 00 00 00 00 00
04 06 x 39 y  9 c02 r4 f4C ptr 16FB87 00 01 02 03 04 05 06 07
```

물체가 놓이는 맵 16곳에 순간이동해(그룹 `$50` 이상은 필드 입구를 `ROMPATCH` 로 바꿔) 덤프하자, 74개 중 65개의 칸 목록이 슬롯과 같았고 화면에 나온 OAM 묶음 271개가 배치·반전·팔레트까지 같았습니다.

## 2. 17/01·17/02 와 숨은 인물

17/01·17/02 는 배(17/00)와 같은 그룹이라 `dq5warp.lua` 가 「배를 떠났다」 를 알아채지 못해 순간이동이 실패했습니다. 필드 입구의 목적지를 17/01 로 바꿔 걸어 들어가자 세트 `33`·`50`·`93` 이 맞았습니다.
15/0B 의 세트 `36` 인물은 숨은 상태(`7E:31C0` bit7)로 놓여 칸 목록 번호가 0 이었습니다. 타일은 VRAM `090` 에 다 있었고, 칸 목록 표의 6번이 세트 `36` 의 칸과 같았습니다.
06/01 의 세트 `9E` 는 「인물을 놓지 않음」 표의 `C4 04` 에 걸려 있었습니다. `7E:21D4` bit2 를 켜자 놓였습니다.

## 3. 아이들

`dq5warp.lua` 의 `PARTY` 로 일행 레코드를 만든 뒤 `SET` 으로 `+0`(인물 번호)을 1·2 로 고치자 그림 `90`·`91` 이 따라 걸었습니다. `7E:21B3` bit3 을 켜고 끄면 두 아이의 머리 색이 금발과 다른 색으로 바뀌었습니다. 결혼 상대에 따라 색이 바뀌는 `1F:D051` 의 동작 그대로라, 「추정」 을 떼고 `むすこ`·`むすめ` 로 둡니다.

```
kids  ['0x2d', '0x90', '0x91', '0xff'] 21B3 00   VRAM 확인 세트: 63 6C 80   (팔레트 0 으로 그린 묶음 24)
kidsB ['0x2d', '0x90', '0x91', '0xff'] 21B3 08   VRAM 확인 세트: 63 6C 80
```

## 남은 것

- 07/02 에서 스크립트가 놓는 맵 OBJ 물체(`16:F862` 의 `00`~`07`·`0E`).
- 세트 `5C`(마차에 탄 동료 자리 그림)와 `A2`(아무 그림 번호도 가리키지 않음)가 쓰이는 장면.
