# 2026-10-26-08: ラインハット 01/00 의 パパス 와 대화 234·22A 의 이벤트

[이야기 진행 지도](../docs/dq5-story.md) 의 「남은 것」 두 줄, 01/00 의 パパス(`219B.0`)가 어떻게 놓이는지와 대화 `234`·`22A` 가 이벤트 번호 `3D`·`40` 을 거는 갈래를 쟀습니다. 앞 세션은 목록 `10:8414` 의 17항목 가운데 앞 8항목만 놓인다고 보았는데, 그것은 슬롯 8~15 만 읽어서였습니다. 17항목은 모두 놓이고, パパス 는 맵 루틴이 숨기거나 옮깁니다.

## 1. 17항목이 모두 놓임

`dq5warp.lua` 로 `TO=01/00,45,30 SET=21A7|40`(목록 `10:8414` 를 고르는 `21A7.6`)에 들어가 세이브스테이트를 만들고, 10 프레임 뒤 WRAM 을 덤프해 슬롯 8~`1F` 의 X(`7E:3020`)·Y(`7E:3080`)·그림(`7E:3220`)을 읽었습니다.

```sh
export LIBDIR=$(uv run --locked krpatch sfc lua)
STATE=$PWD/work/state/ship.mss TO=01/00,45,30 SET="21A7|40" SAVE=a0100.mss SHOT_DIR=$PWD/work/p0100 \
  "$MESENCE" --testrunner "$PWD/rom/dq5.sfc" "$PWD/sfc/dq5/tools/lua/dq5warp.lua"
LIBDIR=$(tools/lua/seqlib.sh "$LIBDIR" work/seqlib) STATE=$PWD/work/p0100/a0100.mss SEQ=wait:5 MAXF=12 FROM=10 \
  SHOT_DIR=$PWD/work/p0100/d "$MESENCE" --testrunner "$PWD/rom/dq5.sfc" "$PWD/tools/lua/wsnap.lua"
```

슬롯 8~`18` 의 그림이 `19 03 02 49 0C 17 01 33 39 39 39 39 02 33 2C 49 36` 으로, 목록 17항목의 그림 번호와 차례대로 같았습니다. `19`~`1F` 는 비었습니다. パパス(그림 `2C`)는 15번째 항목이라 슬롯 `16` 이고, 자리가 (128,128)(숨김)이었습니다.

## 2. 숨기는 곳은 01/00 맵 루틴

슬롯 `16` 의 X·Y 에 쓰기 감시를 걸자(`tools/lua/wwatch.lua`, `WATCH=7E3036-7E3036,7E3096-7E3096`) 383 프레임에 인물을 놓는 `1E:DB44` 가 (92,21) 을 쓰고, 384 프레임에 `12:8CCC`(슬롯 숨기기)가 `80` 을 썼습니다. `12:8CCC` 에 실행 감시를 걸어 스택을 읽으니 돌아갈 곳이 `12:998D` 였습니다. 그 둘레를 읽으면 이렇습니다(`BRK 0B m i` 는 `7E:2190+i` 의 마스크 `m` 검사).

```
12:9976  LDX #$16
         BRK 0B 01 0B      ; 219B.0
         BNE 998B          ; 켜져 있으면 숨김
         BRK 0B 80 17      ; 21A7.7
         BEQ 998B          ; 꺼져 있으면 숨김
         LDA #$36 / LDY #$1F / BRL 8D11   ; (54,31) 에 놓음
998B     JSR 8CCC
```

`SET=21A7|C0` 으로 다시 들어가자 385 프레임에 슬롯 `16` 이 (54,31) 로 옮겨졌습니다.

## 3. パパス 가 걸어 나감

`21A7|C0` 상태로 (51,33) 에 들어서면 납치 장면(목록 첫 인물의 스크립트, 메시지 `0290`「おい！　はやく王子を舟へ！」)이 돕니다. A 로 창을 닫으며 `tools/lua/wlog.lua` 로 슬롯 `16` 과 플래그를 적었습니다.

| 프레임 | 일 |
| --- | --- |
| 410 | `21A7` = `E0`(납치 인물이 `21A7.5` 를 켬) |
| 583 | 창을 닫자 `21A1` = `80`, 곧바로 `219B` = `03`(パパス 스크립트가 `219B.0` 을 켬) |
| 590~614 | (54,31) → (54,35), 615 프레임에 `21A1` = `C0` |
| 622~870 | (54,55) 까지 내려간 뒤 왼쪽으로 |

パパス 의 인라인 스크립트(`10:852A`)대로 `21A1.7` 을 기다렸다가 `219B.0` 을 켜고 `21A1.6` 을 켜며 걸어 나갔습니다.

## 4. 원래 순서에서는

원래 이야기 순서는 납치 장면이 먼저 `21A7.5`·`219B.1` 을 켜고, 01/04 에서 パパス 가 문을 열며 `21A7.7` 을 켭니다. 그래서 `21A7|E0`·`219B|02` 로 (51,33) 에 들어가 보았습니다. パパス 는 (54,31) 에 섰지만 납치 인물(슬롯 `0A`)이 385 프레임에 숨겨져, 900 프레임 동안 `21A1` 은 0 이었고 パパス 는 움직이지 않았습니다.

01/04 의 パパス(목록 `10:87ED`, 문을 열고 나감)도 `21A1.7` 을 기다립니다. `21A7|60` 으로 01/04 (64,20) 에 들어가 600 프레임 동안 `21A1` 쓰기를 감시했지만 없었습니다. `dq5flags.py` 로 찾은 `21A1.7` 을 켜는 곳 가운데 01/0x 인물 스크립트는 01/00(납치 인물)·01/04(`10:8728` 목록)·01/05·01/09 뿐이고 01/04 의 `10:87ED` 목록에는 없습니다. 원래 순서에서 이 두 장면의 `21A1.7` 을 켜는 곳은 「남은 것」으로 남깁니다.

## 5. 대화 234·22A 의 이벤트 번호

선실 파파스(슬롯 `0B`)의 대화 번호(`7E:36EB`·`370B`)를 바꿔 말을 걸고, 네이티브와 `23:E2F4`(이벤트 번호를 받는 곳)에 실행 감시를 걸었습니다. 쓴 드라이버는 세이브스테이트를 불러 처음 3 프레임 동안 WRAM 을 쓰고 입력을 재생하며 실행 주소의 A 를 적는 것입니다.

대화 `234`(ヘンリー)는 `21D2.5`·`21D1.3` 이 꺼져 있으면 `06:B83C` 를 부릅니다. `06:B83C` 는 일행을 돌며 레코드 `+0` 이 1 이면 `21D2.2`, 2 면 `21D2.1` 을 켜고, 그런 사람이 하나라도 있으면 이벤트 번호 `3D` 를 겁니다. 없으면 메시지만 띄웁니다(코드 읽기). 앞 세션에서 걸리지 않은 것은 일행이 주인공 하나라서였습니다. 일행 둘째 칸(`7E:206A`~)에 `dq5warp.lua` 의 `PARTY` 와 같은 레코드를 쓰되 `+0` 을 `01` 로 두자, 1213 프레임에 `06:B83C`, 이어 `21D2` = `04`, 1570 프레임에 `23:E2F4` A = `3D` 였습니다. 번호 `3D`(`15:F588`)는 첫 명령에서 `219F.1` 을 기다리므로 선실에서는 그대로 멈춥니다.

대화 `22A`(プサン)는 `21B5.5`·`21B5.2` 가 꺼져 있으면 메시지 `A71`「これで　この城が　天より 落ちてしまった理由が わかりました。…」 뒤 `06:B737` 을 부릅니다. 462 프레임에 `06:B737`, 621 프레임에 `21DF` = `80`, 3198 프레임에 맵이 04/00 (25,8) 로 바뀌고 화면이 빛바랜 색이 되었습니다. 4598 프레임에 `23:E2F4` A = `40` 이고, 번호 `40` 대로 주인공이 왼쪽 7칸·아래 20칸 걸은 뒤 4819 프레임에 `21A1` = `80` 이 되었습니다. 6000 프레임 화면은 ビアンカ「よかったわね。　これからは　2人　幸せに　眠りつづけるはずよ。」였습니다. `06:B737` 은 지금 자리(`$B6`~`$C3`·`$BC`·`$BD`)를 `7E:0F47`~`0F53` 에 적어 두고 맵을 옮깁니다. 빛바랜 색과 유년기 ビアンカ 의 대사로 보아 과거로 가는 장면입니다.
