# 2026-10-25-164: 몬스터·동료·물건 표의 읽히지 않는 비트

[dq5-data-format.md](../docs/dq5-data-format.md) 「남은 것」의 세 줄을 닫았습니다. 몬스터 레코드 바이트11 bit0-5·바이트16 bit0-1·바이트24 bit7, 동료 레코드 `+8` bit4·6, 물건 표 k1 bit2 입니다.
셋 다 「읽는 곳 없음」으로 남아 있던 것이라, 다른 길로 다시 찾아 근거를 굳혔습니다. 같은 줄에 있던 몬스터 필드 `69` 는 같은 문서의 「몬스터 행동 칸 고르기」 절이 이미 루틴마다 정리해 두어 줄만 지웠습니다.

## 1. 필드 설명자 전부 풀기

이 게임의 표는 대부분 필드 번호로 읽힙니다. 필드 f 는 `21:8D96[f]` → `21:8C86` 의 설명자(묶음·레코드 안 오프셋·길이)와 후처리 `21:8E8C[f]` 로 정해집니다. 256개를 모두 풀어 세 표를 읽는 필드만 골랐습니다.

```
몬스터(묶음 2·9, 23:8000)  68~77, DC, DD, DF, F1, F2
  바이트11  6B·F1   후처리 21:A25C = >> 6 & 3  (bit6-7)
  바이트16  6F      내성 칸 표 21:91F9: 바이트16 에 C0·30·0C 만(종류 5F·60·61)
  바이트24  77      bit0-6
동료(묶음 5, 23:AED1)  +8: 8B(21:9EC0, bit0-3)·8C(21:9EC5, bit6 → $49 bit7)
```

내성 칸 표는 종류 `61` 에서 끝나고 그 뒤는 코드 바이트라, 바이트16 bit0-1 을 가리키는 칸은 없습니다.
필드 `8C` 를 `BRK #88`~`8D` 로 읽는 것처럼 보이는 바이트는 넷(`23:9BFA`·`1E:87E0`·`2B:BFBB`·`2B:C10A`)이었습니다. 디스어셈블해 보니 모두 `STY $1D8B` 같은 다른 명령의 피연산자이거나 표 데이터였습니다. `22:BC47` 의 `00 8C 8C` 도 16비트 X 의 `LDY #$0001 / STY $0D8C` 였습니다.

## 2. 필드를 거치지 않는 읽기

롬에서 이 표들을 긴 주소(`LDA long` 등)로 읽는 바이트를 모두 찾았습니다.

- 몬스터 표: 41곳. 앞뒤를 디스어셈블하면 코드 흐름 안에 있는 것은 구역 레코드(`23:96F3`)를 읽는 `01:84C9` 뿐이었습니다. 나머지는 그래픽·표 데이터 속입니다.
- 동료 표: `21:A57D` 하나. `23:AED1 + 종류*9 + 8` 을 `& 0F` 해 장비 갈래 표 `21:A63E` 로 갑니다.
- 물건 k1(`23:B159`): 7곳. 모두 `21:A458`(가격)과 비트 루틴 `21:A49D`~`A514` 이고, bit2 를 보는 것은 `21:A4E6`(루틴 `21:A4DD`) 뿐입니다. 이 루틴은 `BRK #94` 조회 표의 7번 칸(`21:A40D`)에서만 가리키고, `00 94 07` 은 코드가 아닌 `11:D137` 한 곳입니다.

## 3. 실행하며 읽기 감시

새 프로브 `lua/dq5romread.lua` 는 `dq5warp.lua` 로 장면을 옮기면서 롬의 정한 자리를 읽는 PC 를 모읍니다. 표의 바이트11·16·24, 동료 레코드 전부, k1 표 전부를 걸고 전투를 A 로 치렀습니다.

```sh
ROMREAD="23:8000-970B/25/11,16,24;23:AED1-AFFA/9;23:B159-B230"
FIELD=341,56 BATTLE="00:3,0C:2" PARTY=02,03          → 21:8C31 이 바이트11
FIELD=341,56 BATTLE="27:1,28:1,2D:2" PARTY=27,28 ADULT=1 → 21:8C31 이 바이트11
FIELD=341,56 BATTLE="00:1" POKE="7E21B1=40;7E1010=80" → 21:8C31 이 바이트11·24(동료 판정 77)
TO=21/02,50,43 + 좌우 왕복 + A                         → 21:8C31 이 바이트11
```

읽는 곳은 필드 읽기 공용 루틴 `21:8C31` 하나였고, 위 필드 표대로 바이트11 은 `6B`, 바이트24 는 `77` 입니다. 동료 레코드와 k1 표는 이 장면들에서 한 번도 읽히지 않았습니다.
동료 판정까지 간 슬라임 전투는 첫 필드 이벤트라 パパス 가 끝내 버려 동료가 되지 않았고, 21/02 에서도 동료가 들어오는 데까지는 가지 못했습니다. 그래서 동료가 들어올 때의 읽기는 이번 감시에 없습니다. 그래도 1·2절에서 bit4·6 을 꺼내는 길이 없음을 보았습니다.

값으로는 바이트11 bit0-5 가 173종에서 0 이 아니고, 바이트16 bit0-1 은 ミルドラース(`EB`)만 3, 바이트24 bit7 은 236종 모두 0 입니다.
