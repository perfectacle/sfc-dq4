# 2026-10-30-34: 블록을 늘린 롬의 세계 지도 화면 15프레임 없애기

[블록 훅 일지](2026-10-30-25-mblock.md)와 [타일 늘리기 일지](2026-10-30-28-tilefast.md)가 남긴 것 하나를 했습니다. 블록 번호를 10·11비트로 늘린 롬에서 たびびとのちず(`B6`) 세계 지도 화면의 점을 다 만드는 프레임이 원본보다 15프레임 늦었습니다. `00:BDC5` 의 빠른 훅을 더 줄이지 않고, 점 하나를 만드는 `03:CB07` 을 훅으로 바꿔 지형까지 한 번에 내게 했습니다. 이제 늘린 롬이 원본보다 15프레임 일찍 점을 다 만들고, 다 만든 뒤의 화면은 원본 게임과 같습니다. 형식은 [쓰기 형식의 「필드 세계 지도」](../docs/dq5-build-format.md#필드-세계-지도)와 [블록 훅 속도·빛 칸·세계 지도 실측](../docs/dq5-build-format.md#블록-훅-속도빛-칸세계-지도-실측)에 있습니다.

## 1. 다시 재기

앞 일지와 같이 배 선실 세이브스테이트에서 `dq5warp.lua` 로 세계 0 (341,56)·세계 1 (50,28)(`$1949` 를 `01` 로 고정)에 내리고, 가진 물건 첫 칸(`7E:2056`)에 `B6` 을 넣어 どうぐ → つかう 했습니다. 입력은 `dq5gfxlimitcheck.py` 의 `ITEM_MENU` 그대로입니다. 새 프로브 `lua/dq5mapdots.lua` 는 점 루프 `03:CAC2` 의 점 하나(`03:CAC5` 의 `JSR $CB07` 에서 `03:CAC8` 로 돌아오기까지)와 `00:BDC5`(`00:BE16` 의 `RTS` 까지)를 부를 때마다 마스터 클록(`emu.getState()` 의 `masterClock`)을 더하고, 처음·마지막 프레임과 횟수를 적습니다. 프레임은 프로브를 켠 때부터 셉니다. 시험 롬은 `dq5blockgrowcheck.py` 와 같이 만든 same 롬(모든 칸 512 이상)입니다.

```
                    점 하나    00:BDC5 한 번   점 15,360개    점 하나    00:BDC5 한 번   점 15,360개
                    세계 0     세계 0          세계 0         세계 1     세계 1          세계 1
원본                2,038      972             950~1,099      2,048      981             942~1,091
10·11비트(고치기 전) 2,212      1,137           950~1,114      2,304      1,230           942~1,106
```

앞 일지와 프레임 수의 기준은 다르지만(앞 일지는 원본 1,239·1,231), 15프레임 늦는 것은 같았습니다. 세계 1 은 빠른 훅이 세계 0 말고는 `DEC / BEQ` 로 갈래를 고르고 `JMP` 로 합치므로 `00:BDC5` 한 번이 세계 0 보다 93 더 듭니다. 점마다 늘어난 174·256마스터 클록이 15,360번 쌓여 15프레임이 됩니다.

## 2. 어디를 줄일까

점 하나는 `03:CB07` → `JSL $03CB1B` → `JSL $00BDC1` → `JSR $00BDC5` 로 네 겹을 들어갑니다.

```
03:CB07  PHX / LDX $CE / STX $90 / LDX $D0 / STX $92 / PLX / JSL $03CB1B / CLC / ADC #$20 / STA $CD / RTS
03:CB1B  PHP / REP #$30 / PHX / PHY / JSL $00BDC1 / LSR / TAX / BCS / SEP #$20 / LDA $03CC48,X / (LSR × 4 | AND #$0F)
         / PLY / PLX / PLP / RTL
00:BDC1  JSR $BDC5 / RTL
00:BDC5  PHP / PHB / REP #$30 / (빠른 훅: JML … JML $00BE14) / PLB / PLP / RTS
```

원본의 점 하나 2,038 가운데 `00:BDC5` 몸통이 972 이고 나머지 1,066 의 큰 몫이 들고 나기(`JSL`·`JSR`·`RTL`·`RTS` 와 레지스터 쌓기)입니다. 빠른 훅 몸통을 174 넘게 줄이려면 [일지 25](2026-10-30-25-mblock.md) 3절에서 이미 짧게 짠 반 바이트 평면 읽기와 세계 고르기를 다시 짜야 하는데, 들고 나기를 덜면 몸통을 그대로 써도 됩니다. `03:CB07` 은 점 루프 `03:CAC5` 에서만 불리고(롬에서 `JSR $CB07` 은 이 한 곳), `03:CB1B` 는 `01:81D6`·`01:84E0`·`01:BE8E`(조우·전투 배경·天空城 착륙)에서도 불립니다. 그래서 `03:CB07` 만 바꿔 세계 지도 화면만 새 길로 가고, 다른 곳은 지금처럼 `00:BDC5` 의 빠른 훅으로 가게 했습니다. 빠른 훅 몸통을 다시 짠 판은 만들지 않았습니다.

## 3. 03:CB07 을 훅으로

`03:CB07` 의 `PHX / LDX $CE / STX`(`DA A6 CE 86`)를 `JML` 로 바꿉니다. 훅은 빠른 훅 셋째 몸통으로, `00:BDC9` 몸통과 같은 번호 셈(`dq5fieldwrite.fast_hook` 의 `number`)에 머리와 꼬리를 붙인 것입니다.

- 머리(M 8비트·X 16비트로 들어옴): `PHX / PHY` 로 점 자리 X 와 점 수 Y 를 지키고, 원래처럼 `$CE`·`$D0` 을 `$90`·`$92` 에 둔 뒤 `REP #$20` 하고 번호 셈으로 갑니다.
- 꼬리: `REP #$30 / LSR / TAX / SEP #$20 / LDA 지형표,X` 뒤 홀수 번호면 `AND #$0F`, 짝수면 `LSR` 넷을 하고 `PLY / PLX` 뒤 `03:CB15`(`CLC / ADC #$20 / STA $CD / RTS`)로 `JML` 합니다. 지형 표는 블록 표 패치가 `03:CB2A` 에 넣은 옮긴 표(`dq5field.terrain_table`)를 읽습니다.
- 좌표가 `0200` 이상이면 번호 셈이 A = 0 으로 꼬리에 옵니다. `03:CAC2` 는 `$CE`·`$D0` 을 `03:CB40` 에서 `AND #$01FF` 로 자르고 `03:C8D2`~`C941` 에서도 `0010`·`0000` 이나 `AND #$01FF` 로 두므로 이 갈래는 돌지 않습니다(코드 읽기).
- DB 는 바꾸지 않습니다. 세계(`$7E1949`)·평면·지형 표를 모두 긴 주소로 읽습니다.

셋째 몸통이 붙어 `--planes-at` 자리의 빠른 훅이 10번째 비트만이면 148, 11번째 비트까지면 168바이트 늘었습니다. 블록 표를 늘리지 않은 롬은 빠른 훅을 넣지 않으므로 이 훅도 넣지 않습니다. 작은 해석기(`w65816`)로 돌리는 `test_dq5blockgrow` 에서 세계 0·1·넷째 세계와 좌표 아홉 곳의 `$CD`(지형 + 20)·X·Y·스택·`$90`~`$93` 이 원래 루틴과 같고, 좌표 `0200` 이면 블록 0 의 지형인지 봅니다.

```
                    점 하나    00:BDC5 한 번   점 15,360개    점 하나    00:BDC5 한 번   점 15,360개
                    세계 0     세계 0          세계 0         세계 1     세계 1          세계 1
원본                2,038      972             950~1,099      2,048      981             942~1,091
10·11비트(지금)      1,637      -               950~1,084      1,734      -               942~1,076
```

점 하나가 원본보다 401·314 짧아 두 세계 모두 원본보다 15프레임 일찍 점을 다 만듭니다. 세계 지도 화면에서 `00:BDC5` 는 한 번도 불리지 않았습니다.

## 4. 화면과 검사

- 1,300프레임 VRAM `0000`~`7FFF`(모드 7 타일맵과 점) 16,384워드가 세계 0·1 모두 10·11비트 same 롬과 원본 게임에서 같았습니다. swap 롬(새 블록 지형 `0D`)은 점 15,360개가 모두 `2D` 였고, 세계 0 에서 하나만 `23`(블록 512 미만으로 둔 `00:CF50` 칸)이었습니다. 앞 일지와 같습니다.
- 지도는 점을 만드는 동안 차례로 그려지므로 그 사이 화면은 원본과 다릅니다. 다 만든 뒤 1,260~1,340프레임을 프레임마다 찍으니, 늘린 롬의 프레임 f 화면이 원본 게임의 f + 15 화면과 모두 같았습니다. 깜박이는 표시(32프레임 주기)도 15프레임 앞당겨질 뿐입니다.
- 필드 불러오기의 멈춘 구간은 세계 0 461~492(원본 462~492), 세계 1 453~483, 세계 2 (62,64) 451~481, 세계 2 첫걸음 822 로 일지 25·28 의 값과 같았습니다(10·11비트 same 롬, 고치기 전 롬도 같음).
- 블록 표를 늘리지 않은 롬(`w12pal`, 블록 표 패치만 넣은 롬)은 고치기 전 도구로 만든 것과 바이트마다 같았습니다. 원본 롬 SHA-1 은 그대로입니다.
- `dq5blockgrowcheck.py` 10비트 13건·11비트 21건, `dq5gfxlimitcheck.py` 23건, `dq5fieldgrowcheck.py` 44건, `sfc/dq5/tools/tests` 500건: 통과.

## 틀렸던 것들

- 처음 훅은 X 만 지켰습니다. 원래 `03:CB1B` 가 `PHY / PLY` 로 지키던 Y(점 수, `03:CB40` 이 걸음 표를 고르는 데 씀)를 번호 셈의 `TAY` 가 덮어, 점 루프가 15,360번에서 끝나지 않고 1,300프레임까지 39,859번 돌았습니다. 해석기 시험도 Y 를 보지 않아 지나쳤습니다. `PHY / PLY` 를 더하고 시험에 Y 를 넣었습니다.

## 남은 것

- `00:BDC5` 의 빠른 훅 한 번은 그대로 1,137(세계 0)·1,230(세계 1)마스터 클록입니다(원본 972·981). 조우·전투 배경·天空城 착륙은 걸음마다 한 번이라 재지 않았습니다.
- 늘린 롬은 세계 지도 화면의 점을 원본보다 15프레임 일찍 다 만듭니다. 원본과 같은 프레임에 맞추지는 않았습니다.
