# 2026-10-25-07: 메시지 제어 코드, 대화 조건, 메뉴 문자열

DQ4 대사를 DQ5 메시지로 옮기려면 메시지 안의 제어 코드(줄바꿈, 쪽 넘김, 이름·숫자 자리)가 무엇을 하는지 알아야 합니다.
이번에 제어 코드 처리기를 찾아 뜻을 화면과 프레임으로 확인하고, 대화 스크립트의 조건 코드, 대화 번호 `000`~`010`·`24F`~`26C` 갈래, 명령 창 같은 메뉴 문자열이 어디 있는지 정리했습니다.
결과는 [dq5-text-format.md](../docs/dq5-text-format.md) 의 「제어 코드」·「대화」·「메뉴 창 문자열」 에 있습니다.

## 1. 아무 메시지나 띄우는 방법

제어 코드마다 그 코드가 든 메시지를 띄워 봐야 합니다. 메시지 번호 `633` 미만은 대화 번호로 바로 띄울 수 없어서, 선실 파파스의 스크립트를 덮었습니다.
파파스 스크립트의 거짓 분기 메시지 `41 2D`(`06:8139`, 파일 오프셋 `30139`)를 bit5 가 켜진 `6x yy` 로 바꾸면 메시지 `xyy` 가 그대로 나옵니다.

화면을 여러 장 찍는 프로브 `tools/lua/shots.lua`(`SHOTS` 프레임마다 `sNNNNN.png`)를 새로 만들어 `walk.lua` 드라이버에 끼웠습니다.
아래는 메시지 `1DB` 를 띄우고 200프레임마다 A 를 누르며 찍는 명령입니다.

```sh
export LIBDIR=$(tools/lua/seqlib.sh "$(uv run --locked krpatch sfc lua)" work/walklib walk.lua)
STATE=$PWD/work/state/ship.mss \
  PRE="b:4,wait:40,up:3,wait:20,a:4,wait:30,a:4,wait:240,a:4,wait:200,a:4,wait:200" \
  WAYPOINTS="" CHANGES=9 MAXF=770 SHOTS=345,549,753 ROMPATCH="30139=61DB" \
  SHOT_DIR=$PWD/work/textctl/1DB "$MESENCE" --testrunner "$PWD/rom/dq5.sfc" "$PWD/tools/lua/shots.lua"
```

## 2. 제어 코드 처리기

코드를 꺼내는 쪽에서 거꾸로 찾았습니다. 메시지 첫머리를 푸는 `24:8157` 뒤의 `24:8178` 이 코드를 하나씩 꺼내 `24:819D` 로 넘기고,
`24:819D` 는 `1000` 미만이면 글자, `1000`~`10FF` 면 `24:8204`, `1100` 이상이면 `24:8240` 점프 표로 갑니다.
`dq5text.py --controls` 가 두 표의 처리기 주소와 뜻을 찍습니다.

처리기를 읽어 보니 이름·숫자 처리기는 모두 `24:889F` 로 인자를 꺼내는데, 이것은 메시지가 아니라 `$F5`~`$F8` 을 한 칸씩 당기는 대기열이었습니다.
메시지 `058`「{1004}ゴールドで」 를 띄울 때 `24:84BB`(`1004`)에서 `$F5` 를 기록하니 `03 00 00` 이었고 화면은 「3ゴールド」 였습니다.

```sh
TRACE=2484BB,2484C0,2484DA,24889F LOG=00F5,00F7 ROMPATCH="30139=6058" … "$LIBDIR/probe/trace.lua"
```

```
131 2484BB A=0008 … 00F5=0003 00F7=0000
```

그래서 `POKE` 로 대기열을 고정해 보았습니다.

| 메시지(코드) | `POKE` | 화면 |
| --- | --- | --- |
| `058`(`1004`) | `$F5`~`$F7` = `39 30 00` | 12345ゴールド |
| `008`(`100A`) | `$F5` = `05` | ブロンズナイフ(물건 5) |
| `18D`(`1008`, `100B`) | `$F5` = `$F6` = `05` | ああああ は ベギラマ(주문 표 5번째) |
| `00C`(`1008`) | `$F5` = `00`~`05` / `40`·`41` / `80`·`81` | 주인공 / ああああたち / スライム + 글자 하나 |

주인공·아들·딸 이름은 `7E:2001`·`2009`·`2011` 에서 바로 읽습니다(`24:8A0F`). 첫 바이트를 바꾸자 이름 첫 글자가 바뀌었습니다.
신부 이름 `1015` 는 `BRK 0B 08 23` 이 참이면 롬의 「ビアンカ」, 아니면 「フローラ」 였고, `7E:21B3` 에 `08` 을 넣자 ビアンカ 가 나왔습니다.

## 3. 프레임으로 본 제어 코드

눈에 보이지 않는 코드는 처리기가 코드를 받는 `24:81A4` 를 `calls.lua` 로 기록해 프레임을 보았습니다.

```
메시지 16B: … 135:035A 136:1000 136:1019 136:0000 136:0000 136:0000 136:101A 137:032C …
메시지 1F9: … 327:100D 358:02EB … 499:101C 499:0327 502:0304 505:02E5 …
```

- `1019`~`101A` 사이 공백 셋은 같은 프레임에 찍혔습니다. `1019` 가 켜는 `7E:0F11` bit7 은 글자마다 기다리는 `04:9D7E` 를 건너뜁니다.
- `100D` 뒤 31프레임을 쉬고, `101C` 뒤로는 3프레임에 한 글자씩 찍혔습니다(`7E:0F11` bit0).
- `1002` 는 A 를 누를 때까지 기다린 뒤, 지난 쪽의 줄을 밀어 올렸습니다.
- `1003`·`1006` 은 기록에 한 번도 나오지 않았습니다. 줄 첫머리에서 `24:8AF9` 가 미리 보고 먹고, 둘 다 아니면 「＊「」 를 붙입니다.
  위 그림의 「＊「よくぞもどられた！」(메시지 `0B6`)가 그 경우이고, `1007` 은 들여쓰기를 끄고 다음 사람의 대사를 줄만 바꿔 잇습니다(메시지 `233`).

`1100` 번대는 말하는 인물(`7E:0F1E` 슬롯)의 값을 바꾸는 처리기들이었습니다. `1107` 은 파파스 슬롯 `0B` 의 `7E:31EB` 에 `44` 를 썼지만, 선실 화면에서는 파파스 모습이 달라지지 않아 뜻은 남겼습니다.

## 4. 대화 조건 코드

조건 처리기(`06:B15B`)는 A = 0 을 돌려주면 참입니다. 파파스 스크립트를 `07 <조건> 61 6B 0B 61 29 3F`(참이면 `16B`, 거짓이면 `129`)로 덮어 조건마다 말을 걸었습니다.

| 조건 | 실험 | 나온 메시지 |
| --- | --- | --- |
| `05` | はい / いいえ | 16B / 129 |
| `1E`·`1F` | `7E:21B3` = `08` / `00` | 16B / 129 |
| `02` | `7E:0F1D` = 0 / 1 | 129 / 16B |
| `1A 01 01` | `7E:2191` = 1 / 3 | 129 / 16B |
| `03 nn` | `00` / `01`·`02`·`04` | 16B / 129 |
| `13 nn`, `11 nn` | `00` / `01` | 16B / 129 |
| `20`, `14` | | 16B |
| `9B 01 01`(`1B` 뒤집기) | | 16B |

`05` 는 はい/いいえ 창을 열고 はい 면 참, `1E`·`1F` 는 신부가 ビアンカ 이면 참입니다. `03`·`11`·`13`·`20` 은 인물 정보를 조회하는 `BRK 88`·`89`·`8B` 를 거치는데, 선실에서는 일행이 주인공 혼자라 뜻을 가르지 못했습니다.

## 5. 대화 번호 `000`·`24F` 갈래

`06:B34F`(대화 번호 `24F`~`26C`)는 메시지를 띄운 뒤 `BRK 95 32` 로 はい/いいえ 창을 열고, 답에 따라 다음 메시지를 고릅니다. 파파스 슬롯에 `24F` 를 넣고 답을 바꿔 보았습니다.

```
はい:   116 248BAF A=0615 / 355 248BAF A=0616
いいえ: 116 248BAF A=0615 / 379 248BAF A=0617
```

「旅は　楽しいかい？」 다음에 はい 면 「好きでやってるなら」, いいえ 면 「つらい旅か」 입니다.

`06:DBD2` 점프 표는 17개이고 `01`~`10` 은 가게 처리기입니다(가게 종류는 [dq5-data-format.md](../docs/dq5-data-format.md#가게-종류-06dbd2)).
남은 `000` 을 넣고 말을 걸자 메시지 `1CC`「その方向には　ダレモイナイ。」 가 나왔습니다. 「誰もいない」(`129`)를 가타카나로 쓴 따로 된 메시지입니다.
스크립트 명령 `12`(특수 기능)와 `01`(인자 있는 네이티브 호출)은 스크립트 574개에 한 번도 쓰이지 않았고, `00` 네이티브 호출은 142곳이었습니다(`dq5talk.py --calls`).

## 6. 메뉴 문자열

명령 창의 「はなす」를 이름 문자열 부호로 바꿔 롬에서 찾으니 `04:ED13` 한 곳에 있었습니다. 명령 창을 여는 동안 그 근처를 읽는 곳을 `rwatch.lua` 로 잡자
`04:9C40` 이 `04:EB48` 표에서 창 번호로 레코드(`04:ED0C`)를 찾고, `04:B0F0` 이 항목 문자열을 읽었습니다.
레코드는 머리 6바이트 뒤에 `FE <항목> … FF` 가 줄마다 이어집니다. `ROMPATCH="26D13=1C2429"` 로 はなす 를 すなは 로 바꾸자 명령 창 첫 항목이 그대로 바뀌었습니다.

## 틀렸던 것들

- 이름·숫자 변수의 인자가 메시지 안 다음 코드에 있다고 보았다: 메시지 `058` 의 `1004` 뒤 코드는 바로 「ゴールド」 였고, 처리기는 `$F5` 대기열에서 꺼냈다.
- `7E:0E4B` 버퍼를 읽는 곳을 `7E0E4B` 읽기 감시로 찾으려 했다: 코드는 데이터 뱅크 24 로 `24:0E4B` 를 읽어 감시에 걸리지 않았다. 처리기를 직접 기록하는 쪽으로 바꿨다.
- 조건 처리기가 A = 1 이면 참이라고 보았다: `1B` 플래그가 꺼진 파파스가 거짓 분기를 타는 것과 맞추면 A = 0 이 참이다.
- `1019` 를 들여쓰기 끄기로 보았다: 화면에서 `1019` 줄도 들여 써 있었고, 프레임 기록에서 기다림을 없애는 코드로 확인했다.

## 남은 것

- 끝 코드 `1001`·`1010`·`1018` 의 차이, `1100` 번대 몸짓의 화면 모양
- `1013`·`100F`·`101B`·`1009`·`100C` 실측, `$F5` 를 채우는 쪽
- `BRK 88`·`89`·`8B` 조회와 조건 `03`·`11`·`13`·`20`·`14` 의 뜻(동료가 있는 세이브스테이트 필요)
- 대화 번호 `000` 인물의 실제 대사, 네이티브 호출 나머지, 창 레코드 머리와 숫자 자리가 있는 창
