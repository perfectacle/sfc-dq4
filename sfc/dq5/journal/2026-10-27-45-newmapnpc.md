# 2026-10-27-45: 새 맵 번호의 인물 기본 목록

[새 맵 번호 일지](2026-10-27-39-newmap.md)는 맵 포인터·맵 속성·출구를 늘렸지만, 인물 기본 목록은 늘리지 못했습니다. 그래서 새 맵은 다음 그룹 첫 맵의 목록을 읽었습니다. 이번에는 `dq5npcrelocate.py` 가 `--new-map GG/MM` 을 받아 새 맵의 기본 목록을 넣게 했습니다. 형식은 [쓰기 형식의 「인물 수·순서와 조건 표」](../docs/dq5-build-format.md#인물-수순서와-조건-표-listsnew_listsoverridesno_npc)에 있습니다.

## 1. 어디에 끼워 넣나

기본 목록 로더 `12:803F` 는 그룹 포인터(`05:D4B2 + BC*2`)가 가리키는 그룹 첫 목록에서 `00` 으로 끝나는 목록을 `$BD` 개 건너뜁니다. 그룹마다 목록 수를 따로 적어 두지 않으므로, 새 맵 `BD` 의 목록은 그룹 마지막 목록 바로 뒤에 있으면 됩니다. 재배치는 이미 기본 목록 전체를 다시 쓰고 그룹 포인터 54개를 새 자리로 고치므로, 그룹마다 마지막 목록 뒤에 새 맵 목록을 번호 차례로 끼우기만 하면 뒤 그룹의 포인터는 저절로 밀립니다.

새 맵은 `dq5newmap.py`·`dq5exitreloc.py` 와 같은 `--new-map GG/MM`(대문자, 되풀이) 으로 받고, 그룹 끝 번호부터 빈틈없이 이어지는지 봅니다. 인물은 `lists` 에 `{"map": "0D/05", "entries": [...]}` 로 적습니다. 원본에 없는 맵이라 엔트리는 다른 목록의 엔트리를 `{"list", "index"}` 로 복사해 만듭니다. 적지 않은 새 맵은 빈 목록이 됩니다.

슬롯 한도는 원본에 잰 값이 없으므로 원본 전체 최댓값 `1F` 까지 받고, 인물이 있는 새 맵은 늘어난 맵으로 출력합니다. 그룹 전체(`BD` = `7F`)에 걸린 맵 OBJ 물체는 새 맵에도 놓이므로 함께 셉니다.

## 2. 새 그룹과 짝 맞추기

새 그룹 번호(`36` 부터)도 받게 했습니다. `12:8050` 은 `LDA $D4B2,Y` 로 그룹 포인터 표를 `$BC`×2 로 읽고, 원래 표는 54개(108바이트) 뒤가 코드(`20 42 D5 6B`)입니다. 그래서 옮기지 않은 롬에서 그룹 `36` 은 `4220`(MMIO 자리)을 포인터로 읽습니다. 재배치는 그룹 표를 `--base` 첫머리로 옮기고 `12:8051` 피연산자를 고치므로, 표 끝에 새 그룹의 포인터를 이어 두고 그 그룹 목록을 기본 목록 맨 뒤에 두면 됩니다. 새 그룹은 `36` 부터 빈틈없이, 맵은 0 부터 이어져야 받습니다. 그룹 `50` 이상은 `12:801C` 가 기본 목록을 읽지 않으므로 받지 않습니다. 새 그룹을 만드는 도구가 아직 없어 이 부분은 게임에서 보지 못했고, 옮긴 표의 `36` 칸이 새 목록을 가리키는 것만 패치 바이트로 확인했습니다.

`--new-map` 과 `dq5newmap.py` 문서의 짝이 어긋나면, 빠진 새 맵은 다음 그룹 첫 목록을 읽습니다(독립 검토에서 짚음). 그래서 `--newmap-doc` 으로 그 문서를 주면, 원래 롬에 없는 맵을 새 맵으로 쓰고 `--new-map` 과 다르면 거부하게 했습니다.

## 3. 게임에서

`dq5npclistcheck.py` 에 새 맵 롬을 더했습니다. `dq5newmap.py` 로 0D/05 를 0D/02 의 레코드·속성으로 만들고, `--new-map 0D/05` 로 인물 둘을 넣은 롬입니다. 인물 둘은 02/06 의 밤 인물을 낮으로 바꿔 (12,2)·(16,2) 에 세우고 대화 `300` 을 준 사본입니다. 0D/05 (12,4) 로 들어가 위를 누르고 말을 걸었습니다.

```
original-0D02: 목록 05A255 인물 1 슬롯 09/09(예측 09) 끝 05A277/05A277 표 불일치 0 메시지 -
original-0E00: 목록 05A282 인물 0 슬롯 08/08(예측 08) 끝 05A282/05A282 표 불일치 0 메시지 -
newmap-day: 목록 329C9D 인물 2 슬롯 0A/0A(예측 0A) 끝 329CAB/329CAB 표 불일치 0 메시지 6C6
newmap-night: 목록 329C9D 인물 0 슬롯 08/08(예측 08) 끝 329CAB/329CAB 표 불일치 0 메시지 -
newmap-0D02: 목록 329C70 인물 1 슬롯 09/09(예측 09) 끝 329C92/329C92 표 불일치 0 메시지 -
newmap-0E00: 목록 329CAC 인물 0 슬롯 08/08(예측 08) 끝 329CAC/329CAC 표 불일치 0 메시지 -
16개 장면, 검사 9개 통과
```

새 맵 0D/05 에는 낮에 두 인물이 섰고, 말을 걸자 메시지 `6C6` 이 나왔습니다. 같은 그룹 0D/02 는 옮긴 원래 목록 한 명이 그대로였습니다. 다음 그룹 0E/00 은 인물이 없지만, 로더가 멈춘 목록 끝(`$A5`)이 옮긴 0E/00 목록(`32:9CAC`)이라 새 목록 하나만큼 밀린 자리를 바르게 읽었습니다. 앞서 있던 10장면도 그대로 통과했습니다.

## 남은 것

- 새 그룹(`36`~)의 게임 실측. 새 그룹 번호를 만드는 맵 쪽 도구가 나오면 그 장면에 인물 확인을 더합니다.

- 새 맵의 슬롯 한도를 원본 전체 최댓값보다 좁게 정하는 것. 맵을 놓은 뒤 슬롯을 더 쓰는 장면 코드(`04:FB1C` 등)가 새 맵에서 돌지는 장면을 만들 때 정해집니다.
