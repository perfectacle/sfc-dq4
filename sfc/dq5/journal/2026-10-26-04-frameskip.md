# 2026-10-26-04: Lua 화면이 늦게 찍히던 것은 프레임 건너뛰기

타이틀 GIF(`dq5titlegif.py`)는 같은 입력으로 돌려도 장 수가 달랐습니다. WRAM 이 280프레임 무렵 갈리던 것은 SRAM 을 함께 쓰던 탓으로 이미 고쳤지만([2026-10-25-165](2026-10-25-165-title2.md)), WRAM 해시가 같아진 뒤에도 Lua 가 프레임 끝에 읽는 화면은 1~3프레임 늦을 때가 있었습니다. 그 원인을 찾아 고쳤습니다. 결과는 [dq5-graphics-format.md 「오프닝 타이틀 로고」](../docs/dq5-graphics-format.md#오프닝-타이틀-로고-02e840)에 있습니다.

## 1. 두 도구의 차이

부팅 시험 `dq5boottest.py` 는 6,500프레임 동안 네 번 돌려 메모리 해시가 모두 같았고, `dq5titlegif.py` 는 GIF 장 수가 302·325장으로 달랐습니다. 두 도구는 이제 같은 방법(시험용 롬 이름, 그 이름의 SRAM 지우기, 롬·스크립트 뒤의 `--Snes.RamPowerOnState=AllZeros`)으로 켭니다. 다른 것은 부팅 시험이 VRAM·CGRAM·OAM·WRAM 해시를 보고, 타이틀 GIF 는 화면 버퍼(`emu.getScreenBuffer`)를 본다는 것뿐이었습니다. 에뮬레이션은 같고 화면을 읽는 쪽만 흔들린다는 뜻입니다.

## 2. 프레임 건너뛰기

MesenCE 실행 파일에는 SNES 설정 `DisableFrameSkipping`(설정 창의 「Disable frame skipping when fast forwarding」)이 있습니다. 테스트 실행은 최대 속도로 돌므로 PPU 가 일부 프레임을 그리지 않고, 그때 화면 버퍼에는 앞에 그린 그림이 남는다고 보았습니다.

전원부터 타이틀 GIF 와 같은 입력으로 100~600프레임을 매 프레임 찍는 실행을 넷 돌렸습니다(`dq5shots.lua`).

```
인자 없음                         두 실행에서 501장 중 43장 다름
--Snes.DisableFrameSkipping=true  두 실행에서 501장 중 0장 다름
```

## 3. 도구 고치기

`dq5titlegif.py`·`dq5effectgif.py`·`dq5boottest.py` 의 MesenCE 인자에 `--Snes.DisableFrameSkipping=true` 를 더했습니다. RAM 0 켜기와 같이 롬·스크립트 뒤에 둡니다. `dq5titlegif.py` 를 두 번 돌리자 GIF 두 개가 바이트째 같았습니다(5,570~6,788프레임, 342장).

## 남은 것

- 전투 연출 그림을 화면과 견줄 때 「화면을 찍는 프레임이 1~3프레임 흔들림」 을 피하려 4프레임 동안 그대로인 덤프만 골랐던 비교는 이 인자로 다시 할 수 있습니다.
