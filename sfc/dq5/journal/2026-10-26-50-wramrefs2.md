# 2026-10-26-50: CDL 로 직접 피연산자 후보 907곳 거르기

[2026-10-26-39](2026-10-26-39-wramrefs.md)의 정적 전수에서 `7E:1ABC`~`1BB1` 을 직접 가리키는 피연산자 가운데 코드 뱅크에서 실행되지 않은 907곳이 남았습니다. 이것을 하나씩 코드·자료로 나눴습니다. 결과는 [dq5-hangul-format.md 「옮긴 레코드를 둘 자리」](../docs/dq5-hangul-format.md#옮긴-레코드를-둘-자리)에 있습니다.

## 1. MesenCE 의 CDL

MesenCE Lua 의 `emu` 함수 목록을 뽑아 보니 `getCdlData` 가 있었습니다. 필드 세이브스테이트에서 5프레임만 돌리고 꺼내도 코드 약 14만, 자료 약 55만 바이트가 표시돼 있었습니다. 이 롬으로 돌린 모든 실행이 쌓은 기록입니다. 앞에서 모은 실행 바이트(85,676개)보다 훨씬 넓습니다. `lua/dq5execcov.lua` 에 `CDL=1` 을 더해 `cdl.bin` 으로 남기게 했습니다.

## 2. 나누기

`dq5wramrefs.py --cdl` 로 907곳을 나눴습니다.

```
직접 코드 뱅크 자료: 327
직접 코드 뱅크 코드: 11
직접 코드 뱅크 없음: 569
```

자료로 읽힌 327곳은 명령이 아닙니다. CDL 이 코드라 한 11곳과 실행 코드가 없던 뱅크 `11` 의 2곳은 정렬된 디스어셈블로 하나씩 봤습니다. 모두 앞 명령의 피연산자 안이었습니다. 예를 들어 `11:BB44` 는 `11:BB43 LDA #$04FF` 의 `FF 04` 안이고, `22:9064` 는 `STA $0DFC`·`STA $0D1B` 의 이음매입니다. CDL 의 코드 표시는 피연산자 바이트에도 붙으므로, 명령 시작인지는 디스어셈블로 가려야 했습니다.
