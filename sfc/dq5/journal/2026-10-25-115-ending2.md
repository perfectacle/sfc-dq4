# 2026-10-25-115: 「THE END」 타일맵과 스태프 롤의 밑줄·올리기

[2026-10-25-108 일지](2026-10-25-108-ending.md) 에서 남긴 엔딩의 남은 것 둘을 풀었습니다. 결과는 [dq5-graphics-format.md](../docs/dq5-graphics-format.md) 의 스태프 롤과 「엔딩 「THE END」」 에 있습니다.

## 1. 「THE END」 타일맵

엔딩 장면 세이브스테이트(`dq5warp.lua` 의 `TO=02/06,39,9 SET=2190|80 ROMPATCH=81B89=3774F902`)에서 `7E:21EA` 를 한 번 `84` 로 두고 `7E:9FF0`~`A3FF` 쓰기를 감시했습니다. 한 번만 쓰는 드라이버는 `sfc/dq5/tools/lua/dq5pokeonce.lua` 로 넣었습니다.

```
7E9FF0-7EA3FF pc=03A436 first=3710 n=256 addr=7EA007 val=00
```

`03:A40A` 가 `03:A478` 의 바이트 128개로 32칸 × 4줄을 만들고, 속성 위 바이트는 `03:A4F8` 의 [타일 한계][속성] 쌍에서 고릅니다. 이대로 만든 타일맵이 지금까지 덤프에서 옮겨 쓰던 104칸과 모두 같아, `dq5gfx.py` 가 롬에서 만들게 바꿨습니다. 그린 `the-end.png` 는 바꾸기 전과 바이트째 같습니다.

## 2. 85점줄의 무늬는 밑줄이었다

덤프의 BG3 를 그려 보니 남던 85점줄은 「PRODUCTION STAFF」 같은 섹션 제목 밑의 줄 무늬였습니다. 문자열은 제목 뒤에 `FE FC 02 FB 10 F9 F9 FE` 처럼 새 줄에서 `FB n` 을 둡니다. `02:FC66` 은 `1E:F5A8` 의 2bpp 타일 하나를 칸 위 8점에 놓고 아래 8점을 비우기를 n 번 되풀이합니다.
이 칸을 그리게 하자 스태프 롤이 도는 덤프 12장의 글자 점줄 970줄이 모두 롬 그림과 같았습니다(남은 192줄은 「THE END」 화면 6장).

```
970 / 1162
[('f03750', 32), ('f03900', 32), ('f04050', 32), ('f04200', 32), ('f04350', 32), ('f04500', 32)]
```

## 3. 줄을 올리는 방식

덤프마다 BG3 `vscroll` 은 0 이었습니다. `02:FE5D` 는 16프레임마다 타일맵 두 줄(`$40` 워드)을 VRAM `$1F18` 부터 다시 써서 타일 번호를 한 글자 줄씩 밀어 올립니다(코드 읽기). 글자는 BG3 타일 그림 쪽(`7E:6000` 버퍼)에 그려집니다.

## 틀렸던 것들

- 85점줄을 「지운 줄 자리의 띠」로 보았습니다. 섹션 제목 밑줄(`FB`)이었습니다.
- `FB`·`F7`·`F6` 을 화면 넘기기·기다리기로 보았습니다. `FB` 는 밑줄이고, `F7`·`F6` 은 스태프 롤 문자열에 쓰이지 않습니다.
