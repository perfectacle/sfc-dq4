# 2026-10-27-03: 실내 출구와 영역 이동 쓰기

DQ4 의 마을·성을 DQ5 맵 위에 올리려면 계단과 가장자리가 어디로 이어지는지도 바꿔야 합니다. 기존 출구 목적지와 영역 이동 레코드를 고치는 `dq5exitwrite.py`를 만들었습니다. 입력은 [쓰기 형식](../docs/dq5-build-format.md#실내-출구영역-이동-dq5connections1)에 있습니다.

## 고정 표 6,990바이트

출구 목적지 표는 그룹마다 `[그룹][맵 0 항목들]…[FF]`이고, 맵 목록은 bit7 이 켜진 항목에서 끝납니다. 54개 그룹을 다 읽으면 `2A:F224` 에서 끝나고 그 뒤는 코드입니다. 표 전체를 닫는 `FF` 가 따로 있다고 보고 읽으면 코드를 표로 읽게 되므로, 그룹 수와 끝 주소를 함께 검사합니다.

일반 영역 이동 405개와 색인, 그룹 `$50` 이상이 쓰는 뱅크 `01` 의 목록 16개까지 합쳐 6,990바이트입니다. 원본을 내보냈다 다시 넣으면 쓰기가 0개입니다. 출구는 종류(같은 그룹·다른 그룹·좌표·특수)와 길이, 끝 표시를 그대로 두고 목적지 필드만 바꿉니다.

## 방향이 아니라 층

reader 는 영역 이동 `+4` 를 「바라보는 방향」, `+B` 를 「방향」 으로 적고 있었습니다. 형식 문서는 이미 둘 다 주인공 층(`$C3`)으로 고쳐 두었고, `00:CE26` 의 `LDA $C3 / CMP $0004,Y` 도 층 비교입니다. 쓰기 입력은 `source_layer`·`destination_layer` 로 이름을 붙였고, `dq5trigger.py`·`dq5exit.py` 의 표시도 층으로 바꾸었습니다.

이번 실측에서도 확인했습니다. 01/00 영역 6 은 원래 층 1 로만 발동해서, 층 2 인 주인공이 같은 자리를 지나가면 그대로 01/00 에 남습니다. `source_layer` 만 2 로 바꾼 롬에서는 같은 걸음이 01/04 로 이어졌습니다.

## 그대로 두어야 하는 원본 값

가장자리 출구 8개는 사각형이 x0 = `FF`, x1 = `00` 입니다. 시작<끝 검사를 하면 원본부터 거부됩니다. 엔진은 주인공 X 가 음수(bit7)이면 상한 대신 x0 과 같은지만 보므로(`00:CDFE`→`CE0C`, Y 도 같음), 시작 좌표 bit7 이 켜진 쪽은 끝 좌표를 검사하지 않습니다. `span_raw` 의 `FA`~`FE` 도 그대로 둡니다.

고층 목록은 50/50·50/51 처럼 여러 맵이 한 레코드를 씁니다. 한 맵만 생각하고 고치면 다른 맵의 연결도 같이 바뀌므로, 공유 레코드는 `shared_maps` 에 영향받는 맵을 모두 적어야 받습니다.

## 밟아서 확인

변경 롬 두 벌과 원본에서 같은 자리를 20번 밟았습니다.

| 장면 | 변경 롬 | 원본 롬 |
| --- | --- | --- |
| 같은 그룹 출구 01/00 → 01/09 출구 1 | 01/09 (24,5) | 01/03 (19,5) |
| 다른 그룹 출구 21/02 → 01/03 출구 0 | 01/03 (19,5) | 0E/03 (38,67) |
| 좌표 출구 01/01 → 01/04 (16,6) 층 1 | 01/04 (16,6) 층 1 | 01/00 (21,28) 층 2 |
| 출발층 1 → 2 | 01/04 (16,7) | 01/00 (32,60) 에 남음 |
| 고층 공유 레코드 → 01/04 | 50/50·50/51 모두 01/04 (17,7) | 두 맵 모두 05/01 (33,47) |
| 가장자리 y 6~11 → 6~8 | y=8 은 01/04 (16,9), y=10 은 필드로 | y=8 은 (16,6), y=10 은 (16,8) |
| 사각형을 (32,58) 한 칸으로 | 01/04 (16,7), 옛 자리 (32,60) 은 그대로 | (32,58) 에 남고 (32,60) 은 01/01 |

출구 도착 칸은 reader 가 계산한 「목적지 출구 셀의 한 칸 왼쪽」 과 같았습니다. 영역 이동은 걸어 들어온 방향으로 한 칸 더 간 자리에 섰습니다. 가장자리 사각형의 세로 범위를 줄이면 같은 y 에서 들어서도 도착 y 가 6 에서 9 로 바뀌었습니다. 넓은 사각형은 들어선 자리로 도착 칸을 정하므로(`2A:F650`, 코드 읽기) 이 장면은 맵과 층만 비교합니다.

처음에는 다른 그룹 출구 01/0A (9,10) 를 골랐는데, 원본 롬에서도 네 방향 어느 쪽으로 밟아도 출구 처리 `2A:F6FD` 가 불리지 않았습니다. 2A/00 (19,11) 도 같았습니다. 21/02 (112,7) 은 주인공 x 를 111 로 두어야 발동했습니다. 01/00 (60,80) 은 x 60 그대로 발동했으므로, 밟는 자리의 규칙은 아직 모릅니다. 배의 17/01 은 장면 이동 도구가 `2A:EFF5` 부터 5바이트를 덮어 17/01 출구 항목까지 바뀌어 버리므로 쓰지 않았습니다.

원본 출구 569개에는 `FF` 바이트가 없습니다. 엔진이 다른 그룹을 `FF` 까지 한 바이트씩 건너뛰며 찾으므로(`2A:F711`), 좌표 출구의 x 를 `FF` 로 쓰면 그 뒤 바이트가 다음 그룹 머리로 읽힙니다. 표 구조만 읽는 검사로는 이를 알 수 없어서, 입력에서 `FF` 를 거부하고 `check` 가 빌드한 롬에서 엔진처럼 그룹 머리를 찾아 보게 했습니다.

`dq5exitcheck.py` 가 입력 생성부터 빌드·보행·비교까지 재현합니다.

## 남은 것

- 출구·레코드 증설과 재배치, 출구 종류 변경, 새 맵 번호 연결.
- 조건 검사(`flags` bit6 꺼짐, `2A:F4CA`)가 맞지 않아 막히는 레코드를 바꾼 실측. 조건을 거치는 01/06 영역 0 은 사각형만 바꿔 확인함.
- 01/0A·2A/00 출구가 발동하지 않는 조건과, 출구 셀을 밟는 x 위치의 규칙.
