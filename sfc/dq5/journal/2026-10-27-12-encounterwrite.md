# 2026-10-27-12: 조우 격자·구역 연결·고정 무리·이벤트 무리 쓰기

DQ4 의 들판과 동굴에 DQ4 몬스터를 내려면 구역 레코드만으로는 모자랍니다. 어느 자리가 어느 구역을 쓰는지, 칸 10 의 고정 무리와 이벤트 전투 무리에 누가 나오는지도 바꿔야 합니다. 이 넷을 고치는 `dq5encounterwrite.py` 를 만들고 게임에서 확인했습니다. 입력은 [쓰기 형식](../docs/dq5-build-format.md#조우-표-dq5encounter1)에 있습니다.

## 1. 문서에서 실측된 것만 고르기

[전투 조우](../docs/dq5-data-format.md#전투-조우-23e7c2) 절에서 쓰기로 옮길 수 있는 표를 골랐습니다.

| 표 | 자리 | 실측 근거 |
| --- | --- | --- |
| 필드 구역 격자 5개 | `23:F1FC`~`23:F54D` | 격자 칸 24개·1,182걸음과 세계 1·2 의 926걸음이 계산과 같음 |
| 실내 맵 항목의 구역 셋 | `23:FD6A` 포인터, 맵마다 6바이트 | 무작위 전투 17번의 구역이 표의 `$1948` = 0 칸과 같음. 1·2 칸은 코드 읽기라 이번에 실측 |
| 고정 무리 9개 | `23:B04B` + n×6 | 고정 무리 5 로 ブルーイーター 2·エビルマスター 1·レッドイーター 2 |
| 이벤트 전투 무리 64개 | `23:D757` + n×13 | 무리 번호를 바꾸자 ゲマ·エスターク 등과 싸움 |

넷 모두 고정 길이 표입니다. 격자 다섯 개는 `23:F54E` 에서 끝나고, 바로 거기서 맵 항목이 시작해 `23:FD69` 에서 포인터 표 앞까지 이어집니다. 고정 무리는 물건 표 `23:B081` 앞에서, 이벤트 무리는 격투장 표 `23:DA97` 앞에서 끝납니다. 그래서 항목 수와 크기를 늘리지 않고 값만 바꿉니다.

빼 둔 것도 있습니다. 그룹 `50` 이상 맵의 구역 연결(`23:FDD6`)은 코드 읽기뿐이라 받지 않습니다. 고정 무리의 하위 4비트와 이벤트 무리 `+9`~`+C` 는 `$1009`~`$100C` 로 가는 줄 번호입니다. `$100A` 에 0·1·`80` 을 넣어 본 것 말고는 값의 범위를 모르므로 원래 값을 둡니다. 배의 바다 구역 직사각형도 경계를 확인하지 않아 넣지 않았습니다.

## 2. 내보내고 다시 넣기

`dump` 는 격자 5개, 맵 346개, 고정 무리 9개, 이벤트 무리 64개를 JSON 으로 냅니다. 다시 넣으면 3,812바이트에서 쓰기가 0개입니다. 원래 이벤트 무리의 빈 자리는 172칸 모두 마릿수 0 이었고, 고정 무리 빈 자리의 마릿수·줄 바이트도 다섯 곳 모두 `00` 이었습니다. 무리를 줄이면 이벤트 무리는 빈 자리 마릿수를 0 으로, 고정 무리는 마릿수 부호를 0 으로 쓰고 줄 번호는 남깁니다.

이벤트 무리에서 원래 가장 큰 마릿수는 8 이고, 형식 문서에는 몬스터 `00` 9마리가 나온 실측이 있습니다. 마릿수는 1~9 만 받습니다.

이벤트 무리의 첫 바이트는 그대로 쓰되, 곡 번호(bit0-1) 3 은 받지 않습니다. 곡 표 `26:8F96` 은 셋뿐이라 3 이면 표 밖을 읽습니다. 원래 64개에서 늘 꺼져 있는 bit2·3 도 뜻을 보지 못했으므로 받지 않습니다.

## 3. 원본과 같은 장면에서 견주기

같은 장면을 대조 롬과 고친 롬으로 돌렸습니다. 조우가 드물면 짧은 실행에서 전투가 붙지 않으므로, 장면 준비로 조우 계수 표 `23:EA44` 를 모두 `FF` 로 덮었습니다. 걸음마다 `23:E7C2` 에 들어올 때의 A(구역)와, 무리를 정하고 나가는 `23:E9B0`·`23:EA40`·`23:E98F` 에서 `$1001`~`$1008` 을 기록했습니다.

```text
필드 341,56   격자 0 의 (9~11, 0~2) 0D → 01   12걸음 구역 0D → 01   몬스터 20·22 → 01·00
실내 21/02    areas 01·14·14 → 0D·01·0D
  $1948 = 0                                    26걸음 구역 01 → 0D   몬스터 01 → 22·26
  $1948 = 1                                    26걸음 구역 14 → 01   몬스터 28·00 → 01
  $1948 = 2                                    26걸음 구역 14 → 0D   몬스터 28·00 → 22·26
고정 무리 5   B2·B0·B1 (2·1·2) → 00·03 (3·1)  고친 표의 무리가 그대로 나옴
이벤트 무리 1 スライム 3 → ドラキー 2         첫 전투 메시지 때 $1001~$1008
```

고정 무리 장면의 대조 롬은 원래 롬이 아니라, `dq5progresswrite.py` 로 21/02 의 구역 `01` 을 칸 10(고정 무리 5)만 나오게 한 롬입니다. 원래 롬의 구역 `01` 은 고정 무리 칸의 무게가 0 이라서 고정 무리가 나오지 않습니다. 대조 롬과 고친 롬은 고정 무리 표만 다릅니다.

이벤트 무리는 장면 이동 도구의 `BATTLE` 이 바로 그 표를 덮으므로 쓰지 않았습니다. 대신 `GROUP=01` 로 원래와 같은 무리 번호를 주어, 첫 필드 이벤트를 켠 채 원래 표를 읽게 했습니다.

실내는 장면 이동 도구의 `SET` 으로 시작할 때 `$1948` 을 1·2 로 두었습니다. 맵에 들어설 때 `01:83E6` 이 그 값으로 칸을 고르므로, 문서에 코드 읽기로만 있던 1·2 칸도 이렇게 확인했습니다.

`dq5encountercheck.py` 가 이 12회 실행과 단언을 다시 돌립니다.

```sh
MESENCE=… uv run --locked python sfc/dq5/tools/dq5encountercheck.py rom/dq5.sfc \
  --state work/state/ship.mss --out work/encountercheck
```

## 틀렸던 것들

처음에는 이벤트 장면을 도착하고 60프레임 뒤에 끝냈습니다. 그래서 전투 메시지가 하나도 기록되지 않았습니다. 장면 이동 도구는 `TEST` 입력이 끝나면 멈추므로, A 를 눌러 전투를 진행하는 입력을 주었습니다.

## 남은 것

그룹 `50` 이상 맵의 구역 연결 표 `23:FDD6` 을 그 맵에서 실제로 읽는지 실측해야 합니다. 배의 바다 구역 직사각형 `01:85D8` 은 경계 칸에서 구역이 바뀌는지 봐야 합니다. 고정 무리 하위 4비트와 이벤트 무리 `+9`~`+C` 는 값의 범위와 `$100C` 의 쓰임을 확인해야 합니다. 셋 다 확인한 뒤에 쓰기 도구에 넣습니다.
