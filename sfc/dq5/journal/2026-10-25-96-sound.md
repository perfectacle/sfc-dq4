# 2026-10-25-96: 소리 명령과 맵 곡

전투 메시지 코드 `F9` 가 APU 에 `0C 32` 를 보낸다는 것에서 출발해, 게임이 소리를 내는 명령 체계를 따라갔습니다. 명령 입구와 대기열, `BRK 0F`~`19`, 몇 가지 효과음, 맵마다의 곡 번호를 찾았습니다. 결과는 [dq5-sound-format.md](../docs/dq5-sound-format.md) 에 있습니다. 바다 전투 배경에서 다르게 나온 타일 12개의 원인도 함께 적었습니다.

## 1. 포트를 쓰는 곳에서 명령 입구로

`$2141`·`$2142` 를 쓰는 곳은 `2B:C317`·`2B:C31F` 같은 한 줄짜리 루틴이었고, 그 위에 대기열 `7E:1D95` 를 넣고 빼는 `24:FF83` 이 있었습니다. `24:FF83` 으로 뛰어오는 곳을 보니 `24:FE91` 부터 9바이트짜리 입구 14개가 `LDA #명령 / JMP 24:FF83` 꼴로 늘어서 있었습니다.

`F9` 의 `BRK 19 32` 는 BRK 표 `00:921B` 의 `19` 번 → `00:9256` → 표 `00:928C` → `00:92E8` 의 `JSL 24:FEAC`(명령 `0C`)였습니다. `BRK 0F`~`19` 가 모두 이 꼴로 입구를 부릅니다.

## 2. 게임이 보낸 명령 모으기

`24:FF83` 에 들어올 때 A(명령), 스택의 인자, 부른 곳을 적는 `sfc/dq5/tools/lua/dq5sndlog.lua` 를 만들었습니다.

```sh
LIBDIR=$(tools/lua/seqlib.sh "$(uv run --locked krpatch sfc lua)" work/walklib walk.lua)
mkdir -p work/s/talk
env LIBDIR=$LIBDIR STATE=$PWD/work/state/ship.mss PRE="b:4,wait:40,up:3,wait:20,a:4,wait:30,a:4,wait:150,a:4,wait:60" \
  WAYPOINTS="" CHANGES=99 AFTER=99999 MAXF=400 SHOTS=50,56,70,72,100,104,116,118,140,150 SHOT_DIR=$PWD/work/s/talk \
  "$MESENCE" --testrunner "$PWD/rom/dq5.sfc" "$PWD/sfc/dq5/tools/lua/dq5sndlog.lua"
```

```
55 cmd=0C arg=34 from=00:92E9     # B: 창이 닫힘
71 cmd=0C arg=33 from=00:92E9     # A: 명령 창이 열림
102 cmd=0C arg=33 from=00:92DF    # はなす 를 고름
117 cmd=0C arg=32 from=00:92E9    # 파파스의 대화 창이 뜸
148 cmd=05 arg=32 from=24:85C9
```

화면과 맞춰 보니 `0C 32` 는 대화 창이 뜨는 소리였습니다. 전투 메시지에서 `F9` 가 「＊「…」「ジャミ「…」처럼 말하는 사람 앞에만 붙는 것과도 맞습니다. 롬에서 `BRK 19 32` 꼴은 창 루틴 `04:9DA2` 와 `F9` 처리기 둘뿐이었습니다.
전투(슬라임 하나)에서는 시작에 `1A 01`·`0C 17`, 명령을 고를 때 `0C 33`, 맞을 때 `0C 37`, 승리에 `1A A0`·`01 1F` 가 나갔습니다.

## 3. 맵 곡

맵을 불러올 때 `00:CEB1` 이 명령 `1A` 를, `00:CEA2` 가 같은 인자로 명령 `01` 을 보냈습니다. 인자는 맵 레코드(`23:FD6A`)의 `+5` 였고, 장면 이동 도구로 들어간 12곳 모두 표와 같았습니다.

```sh
LIBDIR=$(tools/lua/seqlib.sh "$(uv run --locked krpatch sfc lua)" work/warplib ../../sfc/dq5/tools/lua/dq5warp.lua)
mkdir -p work/s/m0400
env LIBDIR=$LIBDIR STATE=$PWD/work/state/ship.mss TO=04/00,20,20 SETTLE=300 MAXF=650 SHOT_DIR=$PWD/work/s/m0400 \
  "$MESENCE" --testrunner "$PWD/rom/dq5.sfc" "$PWD/sfc/dq5/tools/lua/dq5sndlog.lua"
uv run --locked python sfc/dq5/tools/dq5sound.py rom/dq5.sfc --check work/s/m0400/snd.txt --map 04/00
```

```
04/00 표 0A, 게임 0A
```

곡 번호는 사다리를 내려가 맵이 바뀌는 프레임(321)에 나갔고, 도착(412)보다 앞섰습니다. 처음에는 도착 뒤만 보다가 빈 결과를 얻었습니다.

## 4. 바다 배경의 타일 12개

[바다 전투](2026-10-25-87-seabattle.md) 에서 배경 00 의 아래 띠 타일 12개가 디코더와 달랐습니다. 같은 전투를 다시 붙여 1100프레임에 덤프하고 견주니, 다른 12개는 `7E:8000`(그림자를 칠한 타일마다 몬스터 칸 비트를 남기는 표)에 기록이 있는 12개와 같았고, 바뀐 바이트는 모두 비트평면 3 에서 비트가 켜지기만 한 것이었습니다. 몬스터 그림자 자국입니다.

## 틀렸던 것들

- `F9` 를 처리기 이름대로 「기다림」으로 보았다가, 지난 일지에서 소리 명령임을 확인했고 이번에 대화 창 소리로 정했습니다.
- 맵 곡을 도착한 뒤의 기록에서만 찾아 처음에 하나도 못 찾았습니다. 곡은 맵을 불러오는 순간(도착 표시보다 90프레임쯤 앞)에 나갑니다.
