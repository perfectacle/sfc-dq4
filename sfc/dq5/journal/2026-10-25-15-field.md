# 2026-10-25-15: 마을 입장 실측과 세계 지도 셋

장면 이동 도구(`sfc/dq5/tools/lua/dq5warp.lua`)로 조작 가능한 필드에 설 수 있게 되어, 코드만 읽고 적었던 마을 입장을 입구 47개에 걸쳐 실제로 밟아 보았습니다.
그러다 「시대」로 알던 `$1949` 가 사실은 세계 지도 셋 중 하나를 고르는 값이라는 것, 바다 위의 입구가 다른 세계의 입구라는 것, `$BC` `$50` 이상이 필드가 아니라 따로 둔 실내형 맵이라는 것을 확인했습니다.
결과는 [dq5-field-format.md](../docs/dq5-field-format.md) 의 「세계 셋」「팔레트」「마을 입장」과 [dq5-map-format.md](../docs/dq5-map-format.md) 의 「그룹 `$50` 이상」에 있습니다.

## 1. 입구 46개를 밟기

`dq5warp.lua` 의 `FIELD` 는 그룹 01 입구 좌표를 바꿔 그 자리에 세워 줍니다. 입구 좌표 바로 아래 칸(Y+2)에 서서 위로 한 칸 걸으면 입구를 밟습니다.
`sfc/dq5/tools/dq5field.py --entrances` 로 입구와 `0F:EA97` 의 도착 자리를 뽑고, 입구마다 아래·위·오른쪽·왼쪽 순서로 들어갈 때까지 시도했습니다.

```sh
export LIBDIR=$(uv run --locked krpatch sfc lua)
STATE=$PWD/work/state/ship.mss FIELD=399,381 POKE="7E1949=00" TEST="up:30,wait:250" MAXF=3000 \
  SHOT_DIR=$PWD/work/ent/0-s "$MESENCE" --testrunner "$PWD/rom/dq5.sfc" "$PWD/sfc/dq5/tools/lua/dq5warp.lua"
```

```
f00871 end map 02/00 cell 29,83 BE=80 1949=00
```

8개씩 나란히 돌려 35초에 끝났습니다. 그룹 01 항목은 도구가 덮어쓰므로 빼고 46개를 돌렸고, 40개가 들어갔습니다.
들어가지 못한 6개는 모두 세계 값이 1·2 인 그룹이었습니다. 처음에는 `SET="1949=01"` 로 시작할 때 한 번 바꿨는데 결과 줄에는 늘 `1949=00` 이 찍혔습니다.
`$1949` 에 쓰는 곳을 찾으니 `2A:FEE4` 가 맵에 들어갈 때마다 그 그룹의 세계를 다시 쓰고 있었습니다. 01/00 을 지나 나가는 도구의 길에서 0 으로 돌아간 것입니다.
`POKE="7E1949=01"` 로 매 프레임 고정하자 6개도 모두 들어갔습니다.

예측과 비교하니 46개 중 42개가 `0F:EA97` 의 `$BD`·도착 좌표와 같았습니다. 다른 넷 중 셋은 `2A:F28D` 와 `2A:F384` 의 예외 코드 그대로였습니다.

| 입구 | 예측 | 실제 | 코드 |
| --- | --- | --- | --- |
| (320,109) | 28/00 (0,23) | 28/02 (40,27) | `$B6` 하위 바이트가 `$40` 이면 28/02 |
| (85,269) | 13/00 (32,85) | 13/00 (16,7) | `$B8` = `$010D` 이면 (16,7) |
| (452,233) | 표 밖(그룹 `51`) | 51/50 (22,8) | 그룹 `51` 은 51/50 (22,8) 로 고정 |
| (65,301) | 1F/00 (100,29) | 1F/00 (95,29) | 못 찾음 |

1F/00 은 도착하자 「わん わん!」 대화가 떴습니다. 이 맵의 둘째 루틴(`$1AA6` = `03:D4B5`)을 `ROMPATCH` 로 빼도 (95,29) 여서 원인은 남겨 둡니다.

## 2. 바다 위의 입구

입구 그림에서 바다 위에 찍혔던 입구는 그룹 `09`·`08`·`15` 였고, 셋 다 세계 값이 1·2 였습니다. 그 자리에 `$1949` 를 바꿔 서 보았습니다.

```sh
STATE=$PWD/work/state/ship.mss FIELD=49,29 POKE="7E1949=01" SAVE=f.mss MAXF=900 \
  SHOT_DIR=$PWD/work/sea/e2b "$MESENCE" --testrunner "$PWD/rom/dq5.sfc" "$PWD/sfc/dq5/tools/lua/dq5warp.lua"
```

`$1949` = 0 이면 바다 한가운데였던 자리가, 1 이면 눈 덮인 땅의 동굴 앞, 2 면 보라색 바다로 둘러싸인 땅의 동굴 앞이었습니다. 지도 자체가 바뀐 것입니다.
산·숲 위에 찍혔던 그룹 `22`·`1C`·`30` 입구도 같은 식으로 다른 세계의 마을 앞이었습니다.

## 3. 세계 지도 셋

`01:A5C2` 를 부르는 곳(`01:9F6E`)을 읽으니 `LDA $1949` 뒤에 세 갈래가 있었습니다. 1 이면 `01:A5F1`, 2 면 `01:A620` 이 다른 RLE 덩어리를 풉니다.
세 세계에서 필드에 선 뒤 WRAM 을 덤프해, 각 덩어리를 `sfc/dq5/tools/dq5field.py` 의 RLE 로 푼 결과와 비교했습니다. 장면 이동 도구를 드라이버로 둔 Lua 폴더를 만들어 `atpc.lua` 를 얹었습니다.

```sh
export LIBDIR=$(tools/lua/seqlib.sh "$(uv run --locked krpatch sfc lua)" work/warplib dq5warp.lua)
STATE=$PWD/work/state/ship.mss FIELD=49,29 POKE="7E1949=01" TEST="wait:300" AT=008090 FROM=560 MAXF=900 \
  SHOT_DIR=$PWD/work/fd/f1 "$MESENCE" --testrunner "$PWD/rom/dq5.sfc" "$PWD/tools/lua/atpc.lua"
uv run --locked python sfc/dq5/tools/dq5field.py rom/dq5.sfc --world 1 --compare work/fd/f1/at_008090.bin
```

```
world == 7F:0000: True / e000 == 7E:E000: True
```

세 세계 모두 같았습니다(세계 0 은 `(341,56)`, 2 는 `(63,29)` 에서 덤프). 블록 정의와 타일 그래픽도 같은 표를 써서, 롬의 블록 표로 덤프 VRAM·CGRAM 을 칠한 화면이 게임 화면과
3,584 표본 중 3,572·3,477·3,572 픽셀 같았습니다(다른 픽셀은 주인공·창). 세계 1·2 는 256x256 지도의 왼쪽 위 구석만 땅입니다.

![세계 지도 셋과 각 세계의 입구(노란 틀). 세계 1·2 는 왼쪽 위 128x128 블록만 2배로](../images/dq5-field-worlds.webp)

같은 루틴이 `$194B` 에 `02`·`05`·`0E` 를 넣고, 세계 1·2 는 `01:A6A3` 으로 2·3번 줄 팔레트를 `01:A199`·`01:A3B5` 에서 옮깁니다.

## 4. 팔레트 4번 줄과 시간대

세 세계의 CGRAM 을 줄마다 롬에서 찾았습니다. 4번 줄은 세계 1·2 에서 `10:EC48`(실내 팔레트 표 `$34` 번)과 같았고, 세계 0 에서는 색 1~3 만 달랐습니다.
WRAM 팔레트 버퍼(`7E:3914-`)의 2~4번 줄 쓰기를 감시했습니다.

```
7E3954-7E39B3 pc=01A0C4 first=456 n=1560 addr=7E3956 val=E0
7E3954-7E39B3 pc=01A0F5 first=456 n=312 addr=7E3996 val=80
7E3954-7E39B3 pc=02ABEF first=502 n=52 addr=7E3972 val=E0
```

세계 0 에서는 `01:A090` 이 매 프레임 2·3번 줄과 4번 줄 색 1~3 을 DMA 로 다시 씁니다. 4번 줄 색 1~3 은 `01:A0F6 + $1961*6` 의 10단계 표(물결)이고,
2·3번 줄은 `01:A132` 가 시간대 `$075E` 로 8벌 중 하나를 고릅니다. `$075E` 를 11가지 값으로 고정해 CGRAM 을 덤프했더니 모두 표대로 고른 벌과 같았습니다
(색 30개 중 26개. 나머지 4개는 `02:ABEF` 가 따로 깜박이는 2·3번 줄 색 14·15).

```
0000 -> A2C5   0001 -> A289   0002 -> A24D   0050 -> A24D   00EE -> A289   00EF -> A2C5
00F0 -> A301   00F1 -> A33D   00F2 -> A379   01FD -> A33D   01FE -> A301
```

1·5~7번 줄은 실내 맵과 같은 팔레트 세트였습니다. 필드에서도 `$BC`/`$BD` 에 마지막으로 나온 맵 번호가 남아 있어 그 세트가 쓰입니다.
01/00 에서 나오면 세트 `2E`, 02/00 에서 나오면 세트 `06` 이었습니다. 필드 타일은 2·3·4번 줄만 쓰므로 화면에는 드러나지 않습니다.

## 5. 그룹 `$50` 이상은 필드가 아니다

(452,233) 입구로 들어간 51/50 은 `$BE` bit7 이 켜진 실내 맵(동굴)이었습니다. 맵 포인터 루틴의 `$BC ≥ $50` 갈래(`01:933D`)를 실행 커버리지로 뽑아 보니,
뱅크 `1F` 의 `CEB6` 표에서 그룹 목록을 찾고 24비트 포인터로 뱅크 `0F` 의 레코드를 가리켰습니다. 블록은 `17:8369`, CHR 은 `1F:8000`, CHR 팔레트 표는 `0F:CF83` 으로 바뀝니다.

`sfc/dq5/tools/dq5map.py` 에 이 경로를 더하고 51/50 을 풀어 게임 셀 버퍼(`15:F7EE`)와 비교하니, VRAM 슬롯 시작을 `DC` 로 주었을 때 17,408바이트 중 2바이트만 달랐습니다.
나머지 17개도 보려 했지만 사다리 출구 항목의 `$BD` 는 5비트라 `51`·`50` 같은 값을 못 씁니다. 대신 입구 `04:FD97` 의 51 항목과 `2A:F3E5` 의 즉값을 덮었습니다.

```sh
ROMPATCH="1573E6=54;1573EC=51;27E7D=54;157F2A=FF"   # 그룹 54, $BD 51. 157F2A 는 54 를 막는 세계 검사
```

18개 중 5개(50/51, 51/56, 54/51, 54/53, 51/50)는 0~2바이트 차이였고, 13개는 VRAM 슬롯 번호만 어긋났습니다. 맞는 슬롯 시작이 맵마다 달라 그 규칙은 남겨 둡니다.

이 맵들의 영역 이동은 `01:94B4` 가 고르는 뱅크 `01` 목록이었고, 레코드는 실내 영역 이동과 같은 12바이트였습니다. 51/50 에서 위로 걸어 필드 (452,233) 으로 나왔고,
51/51 에 (42,7) 로 들어가 위로 걸어 51/55 로 갔습니다(방향 값 2 = 위). 54/51·52/50 등에서는 들어간 뒤 주인공이 움직이지 않아 더 밟지 못했습니다.
이 실험에서 세이브스테이트를 중간에 남기려고 `sfc/dq5/tools/lua/dq5savestate.lua`(드라이버 입력을 재생하다 `SAVEAT` 프레임에 저장)를 썼습니다.

## 6. 머리 `+0` bit3-5 와 셀 `+0` bit3

`$1A33` 은 지난번에 뱅크 `7E` 로만 감시했습니다. 이번에는 뱅크 `00` 미러까지 읽기 감시를 걸고 21/02 던전에 들어가 걷다가 무작위 전투를 붙이고,
명령 창의 여섯 항목을 차례로 열었지만 한 번도 읽히지 않았습니다.

셀 `+0` bit3 은 선실의 문 양옆 등 8칸에 있습니다. 매 프레임 모든 셀의 bit3 을 지우는 Lua 를 얹어 문 (3,14)~(3,16) 에 서 보았는데, 주인공 둘레 화면은 지우지 않은 쪽과 같았습니다.
파파스 쪽 16x14 픽셀만 달랐고 원인은 모릅니다.

## 틀렸던 것들

- `$1949` 를 「어린 시절·어른 시절 시대 값」으로 보았습니다. 실제로는 세계 지도 셋 중 하나를 고르는 값이고, 맵에 들어갈 때마다 그 그룹의 세계로 다시 써집니다.
- 바다 위의 입구를 정체 모를 항목으로 남겼습니다. 다른 세계 지도의 입구였습니다.
- `$BC` `$50`~`$54` 를 「필드」로 적었습니다. 실내 맵과 같은 꼴의 맵 18개였습니다.
- 필드 팔레트 5~7번 줄을 `10:F028-` 로 적었습니다. 마지막으로 나온 맵의 팔레트 세트를 따릅니다.
- `SET` 으로 한 번 바꾼 `$1949` 가 남아 있으리라 보았습니다. 맵을 지나며 다시 써져서 `POKE` 로 고정해야 했습니다.

## 남은 것

- 1F/00 도착 X 가 표와 다른 까닭
- `$1949` 가 1·2 로 바뀌는 이야기 흐름, `$194A`·`$198E` 의 뜻
- 세계 1·2 에서 필드 VRAM 타일 `454`~`459` 가 롬 타일과 다른 까닭
- 그룹 `$50` 이상: VRAM 슬롯 시작 규칙, 50/50 띄우기, 영역 이동 레코드 나머지 실측
- 머리 `+0` bit3-5 를 읽는 곳(주문·저장·탈것 쪽), 셀 `+0` bit3·`+1` bit4-6 의 쓰임
