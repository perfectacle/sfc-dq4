# 2026-10-25-10: 주문 표와 몬스터 필드

DQ4 주문과 몬스터를 넣을 자리인 DQ5 의 행동 표(MP·처리 루틴·피해량)와 몬스터 레코드의 나머지 필드, 물건 표의 장비 비트를 풀었습니다.
결과는 [dq5-data-format.md 「주문과 행동」](../docs/dq5-data-format.md#주문과-행동-268765), [「몬스터」](../docs/dq5-data-format.md#몬스터-238000), [「물건 표」](../docs/dq5-data-format.md#물건-표-23b081) 에 있습니다.

## 1. 실험 틀: 슬라임 셋 이벤트 전투

[핸드오프](../handoff.md) 의 「전투 재현」 장면(선실 세이브스테이트 → 03/00 → 슬라임 셋)을 그대로 쓰고, 경유점이 끝나면 A 를 계속 눌러 싸우게 했습니다.
전투 메시지 루틴 `24:8C39` 가 불릴 때마다 메시지 번호와 RAM 몇 군데를 적는 `sfc/dq5/tools/lua/dq5battle.lua` 를 새로 만들었습니다.

```sh
STATE=$PWD/work/state/ship.mss PRE="b:4,wait:40,b:4,wait:40" \
  WAYPOINTS="3,11;3,24;7,24;7,22;37,66;37,72;down:90" MAXF=3000 \
  PEEK="7E07C0:64,7E204E:2,7E206C:4" \
  ROMPATCH="156FF5=E0253C0103;11958D=010101010101;118003=C8" \
  SHOT_DIR=$PWD/work/b0 "$MESENCE" --testrunner "$PWD/rom/dq5.sfc" "$PWD/sfc/dq5/tools/lua/dq5battle.lua"
```

- 전투 중 몬스터는 `7E:07C0 + 슬롯*16`(필드 읽기 묶음 3)에 있고 `+2` 가 HP 입니다. 주인공 HP 는 `7E:204E`, 파파스 HP·MP 는 `7E:206C`·`7E:206E` 였습니다.
- 두 번째 턴쯤 파파스가 손님으로 합류합니다(메시지 `002`). 파파스는 몬스터 `DC`(ちちおや) 레코드로 움직여, 그 행동 6개(파일 오프셋 `11958D`)를 바꾸면 파파스가 원하는 주문을 겁니다.
- 슬라임 레코드는 파일 오프셋 `118000` 입니다. `118003=C8` 은 슬라임 HP 를 200 으로 늘려 전투를 오래 끌기 위한 것입니다.

메시지 번호는 `069`(몬스터가 받은 피해), `06A`(우리 쪽이 받은 피해), `070`(となえた), `079`(きかなかった), `0A3`(ひらりと みをかわした), `0B4`(なんと ～を みつけた) 등을 봤습니다.

## 2. 행동 번호와 표 셋

몬스터 레코드의 바이트17~22 는 이름 표 3번의 번호였습니다(スライム `73 73 98 73 73 98` = たたかう·たたかう·ー…, ガップリン 의 `4B` = ラリホー).
이름 표 3번은 171개이고 앞쪽이 주인공 주문, 가운데 `39`~`65` 가 이름은 같은 몬스터용 주문, 뒤가 몬스터 행동입니다.

이 번호로 읽는 표를 셋 찾았습니다.

- `26:839A`·`26:83D0` 이 `26:8765[행동]` 을 읽습니다. 하위 5비트가 MP(1F 이면 MP 없음), bit5-6 과 bit7 은 따로 꺼냅니다.
- 처리 루틴 표 `20:B7F9`. メラ 는 `20:B0E5` 의 `LDX #50 / LDA #01 / JMP B307` 처럼 내성 종류와 양 번호를 넣고 공통 루틴으로 뜁니다.
- `20:AB70` 이 `27:8071 + 양 번호*2` 의 [바탕][폭] 으로 양 = 바탕 + 난수(0~폭-1) 을 만듭니다. 바탕이 FE 면 300 입니다.

## 3. MP 와 피해량

파파스의 행동을 모두 メラ(`01`)로 바꾸자 슬라임이 받은 피해가 12·13·15·15, 파파스 MP 가 65 → 63 → 61 → 59 → 57 이었습니다(표: MP 2, 양 12~15).
표를 직접 바꿔 두 번 더 봤습니다.

```
26:8766 = A5 (MP 5)        → MP 65 → 60 → 55 → 50 → 45
27:8073 = 64 01 (100, 폭 1) → 피해 100, 100, 95(남은 HP)
```

ギラ(`04`) MP 4, ラリホー(`17`) MP 3 도 표와 같았습니다.

## 4. 내성

파파스가 ラリホー 를 걸자 슬라임 둘이 「ねむらせた」 였고, 슬라임 바이트14 를 `C0` 으로 바꾸자 「きかなかった」 였습니다.
メラ 는 바이트12 bit4-5, ギラ 는 바이트12 bit2-3 이었습니다. 이 세 자리가 `21:91F9 + 종류*2` 표(종류 50 → [0][30], 51 → [0][0C], 57 → [2][C0])와 맞아서, 내성은 필드 `6F` 를 내성 종류로 읽는 2비트 칸 18개로 정리했습니다.

값에 따른 피해는 `20:AB9E` 가 `27:8055` = 255, 205, 84, 0 을 곱해 256 으로 나눕니다. メラ 로 확인했습니다.

```
내성 0: 12 13 15 15      내성 1: 9 10 12 12      내성 2: 3 4 4 4      내성 3: きかなかった
```

## 5. 몬스터 필드

필드 읽기 `21:8B00` 은 `BRK #88` 뒤 바이트 하나로 필드 번호를 받습니다. 롬에서 `00 88 <필드>` 를 찾아 몬스터 필드마다 읽는 곳을 모았습니다.
전투 시작 루틴 `26:81BE` 는 `5F`·`5B`·`55`·`63`·`67` 을 읽어 전투 슬롯(묶음 3)의 `5D`·`F5`·`51`·`61`·`65` 로 옮기고, `71`·`70` 으로 처음 상태를 겁니다.
행동 고르기 `21:AF9E` 는 `68`·`69`·`6A`(6번)·`6B` 를 읽습니다.

각 필드를 슬라임 레코드에서 바꿔 전투를 봤습니다.

| 바꾼 것 | 결과 |
| --- | --- |
| 바이트0(`5F`) = FF | 첫 메시지가 `05E 06A`: 슬라임이 주인공보다 먼저 공격(원래 `05E 069`) |
| 바이트1(`63`) = 60 | 첫 턴에 주인공 쓰러짐(`003`) |
| 바이트2 = FF, 바이트8 = 41(`67` = 7FF) | 주인공 공격이 「ミス」 또는 1 |
| 바이트4(`5B`) = 20, 행동 = メラ | 슬라임이 メラ 를 검. 바이트4 = 0 이면 그냥 공격 |
| 바이트11(`6B`) = 80 / C0 | 첫 턴에 슬라임 셋이 6번 / 9번 공격 |
| 바이트10(`6C`) = 08 / 18 | 턴마다 HP +16·+22 / +92(최대 HP 까지) |
| 바이트9(`71`) = D7 | 처음부터 셋 다 잠듦(「しかし スライムは ねむっている」) |
| 바이트9(`74`) = 07 | 쓰러뜨리면 반드시 상자, 「やくそうを みつけた」. 0F·3F 이면 안 떨어뜨림 |
| 바이트9 = 07, 바이트23(`75`) = 06 | 「どうのつるぎを みつけた」 |

`6B` 는 `21:B029` 에서 0 이면 행동 1번, 1 이면 난수로 1~2번, 2 면 2번, 3 이면 3번을 넣고, `6C` 는 `20:8D26` 에서 `27:804B`·`27:804E` 로 회복량을 만듭니다.
`74` 는 `25:898C` 에서 `27:8218` 의 1·8·16·32·64·128·256·4096 중 하나로 1/N 을 뽑습니다. 원래 슬라임은 2(1/16)입니다.

## 6. 물건 표의 장비 비트

물건 표 9개의 기준 주소를 롬에서 찾으니 k8(`23:B741`)을 읽는 곳이 없고, `21:A53B` 가 `23:B669 + 물건*2` 를 16비트로 읽었습니다.
동료가 몬스터면 `23:AED1 + 몬스터*9 + 8` 의 하위 4비트(갈래)로 `8000 >> 갈래` 를 만들어 이 16비트와 AND 합니다. 사람이면 `23:B591[물건] & 21:A632[인물]` 입니다.
그래서 k7·k8 은 따로 된 표 둘이 아니라 동료 몬스터용 16비트 표 하나로 정리했습니다. 도구 50개는 모두 0 이었습니다(코드 읽기).

## 틀렸던 것들

- 행동 표의 bit5-6 을 대상 범위(자신·하나·그룹·전체)로 보고 바꿔 봤지만, メラ 를 「전체」·「그룹」으로 바꿔도 한 명에게만 들어갔고(파파스가 걸 때와 슬라임이 걸 때 모두), 슬라임의 ギラ 는 「하나」로 바꿔도 주인공·파파스 둘에게 들어갔습니다.
  행동 고르기 `21:B053` 은 이 값이 0(자신)인지만 보고, 바로 뒤 `BRK #89` 가 X 를 덮어써 대상 마스크는 다른 값(필드 `45`)으로 정합니다. 값의 분포(メラ 하나, ギラ 그룹, イオ 전체)는 이름과 맞지만 뜻은 확인하지 못했습니다.
- 바이트12 bit7(`70`) = 1 로 시작 상태 `39` 를 걸어 봤지만 화면에 달라진 것이 없었습니다.

## 남은 것

- 실행할 때 주문 대상 수를 정하는 곳, 범위 비트를 쓰는 곳(플레이어 명령 입력 `20:8700` 쪽)
- 상태 주문 루틴(`20:AE41`·`AEC6`·`AEFF`)에 넘기는 값, 내성 50·51·57 밖의 종류 실측
- 몬스터 필드 `68`·`69`·`6D`·`6E`·`76`·`77`(`76`·`77` 은 동료가 되는 것으로 보임), 시작 상태 `39`
- 물건 표 k1~k4 플래그의 뜻, 장비 비트의 인물 번호와 동료 이름 대응, `23:AED1` 레코드
