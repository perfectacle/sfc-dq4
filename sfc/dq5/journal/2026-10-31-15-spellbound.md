# 2026-10-31-15: やまびこのぼうし 경계, マホカンタ, 남은 처리 루틴 첫머리

[새 주문을 주문으로 다루기](2026-10-27-60-spellclass.md)와 [처리 루틴 연결](2026-10-27-27-spellfx.md)에서 남긴 것이 셋 있었습니다. `20:8EE8`(`$1016` bit4) 경계를 게임에서 보지 않았고, マホカンタ 처럼 세 경계 밖에서 주문을 가르는 처리가 새 번호 `C6`~`D4` 에 먹는지도 몰랐습니다. 처리 루틴 첫머리 가운데 `STX $43` 이 끼거나 `AEC6`·`AEFF`·`B657` 을 부르는 16개는 값의 쓰임을 재지 않아 도구가 받지 않았습니다. 셋 다 게임에서 재고, 첫머리 16개를 `dq5spellfx.py` 가 받게 했습니다. 결과는 [행동 번호 늘리기](../docs/dq5-build-format.md#주문으로-다루기class)와 [처리 루틴 연결](../docs/dq5-build-format.md#처리-루틴-연결필드-주문-dq5spellfx1)에 있습니다.

## 1. 20:8EE8 은 やまびこのぼうし

`20:8EE8` 을 품은 루틴(`20:8EA9`)은 행동마다 `20:84D5` 에서 불리고, carry 가 켜져 돌아오면 `20:84F1` 에서 같은 행동을 다시 돕니다.

```
20:8EA9  $1016 bit4 면 bit3·4 를 끄고 CLC(두 번째 차례)
         $1016 bit3·$1012 = 0·$10F5 bit7 이면 끄고 CLC
         $42 = $10F5(행동한 쪽) / BRK 89 80 3D → $49
20:8EC9  $49 = 93 이 아니면 CLC
         $1037,X & 3 = 1 이 아니면 CLC
         $1073,X(그 행동) < 31 → $1016 bit4, SEC      = 31 → $118E 도 지움
20:8EE8  CMP #$65 / BCC → bit4, SEC   = 65 → $118E 도 지움   > 65 → CLC
```

`93` 을 물건 이름 표 5 에서 찾으니 やまびこのぼうし 였습니다. 주문을 두 번 울리는 모자입니다. `31`·`65` 는 パルプンテ 입니다. 그래서 주인공 물건 셋째 칸(`7E:2058`)에 `93` 을 두고 장비 비트(`7E:2054`)를 `03` → `07` 로 켠 채 전투에서 ホイミ 를 외우게 했습니다.

```
원본 롬 ホイミ:  070 → 094 → 1A1 → 094, HP 5 → 44 → 84, MP 97    20:8EF1 A=0027
spell 롬 C6:     070 → 094 → 1A1 → 094, HP 5 → 37 → 70, MP 97    20:8EF1 A=00C6
skill 롬 C6:     070 → 094,               HP 5 → 44,        MP 97    20:8EFB 로 감
```

`1A1` 은 「じゅもんが やまびことなって こだまする！」 입니다. 두 번째 차례에는 MP 가 줄지 않았습니다. `spell` 롬은 스텁이 C6 을 경계 안으로 보내 울렸고, `skill` 롬은 경계 밖이라 울리지 않았습니다. `$1016` bit4 일 때 실행 루틴을 `26:8565` 에서 대신 읽는 것(`20:84A6`)도 이 두 번째 차례입니다(코드 읽기).

## 2. マホカンタ 는 MP 칸으로 가른다

몬스터 상태 `39`(マホカンタ)가 어디 있는지는 상태 비트 시험 루틴 `21:917F` 에 프로브를 걸어 찾았습니다. 몬스터 슬롯 0 의 상태 바이트는 `7E:07C0` 부터이고, `39` 는 `7E:07CC` bit6 입니다. 이 바이트를 `40` 으로 붙잡은 슬라임에게 C7 을 외우게 했습니다.

```
메라 대조 롬 メラ: 070 → 078 → 06A(주인공이 맞음), MP 98
spell 롬 C7:       070 → 078 → 06A, MP 98
skill 롬 C7:       070 → 078 → 06A, MP 98
```

`078` 은 「ひかりのかべが じゅもんを はねかえした！」 입니다. 원본 롬의 주인공 전투 목록 둘째 칸은 キアリー(`2C`)라, 대조 롬은 원본 롬에 목록 첫 두 칸만 ホイミ·メラ 로 둔 것입니다.

`class` 와 관계없이 되튀어서 갈림을 찾아보았습니다. 되튀기 검사 `20:F3F9`(맞는 쪽 상태 일행 `11`·몬스터 `39`)를 부르는 세 곳 가운데 `20:F46B` 가 `LDA $10F7 / JSL $26838C / BCC` 로 행동의 MP 칸(`26:8765` 아래 5비트가 `1F` 가 아니면 MP 를 씀)을 먼저 봅니다. マホトーン(`20:85A8`)과 같은 갈래입니다. C7 은 メラ 의 MP 칸을 베꼈으니 `skill` 이어도 되튑니다.

## 3. 남은 첫머리 16개

16개를 디스어셈블해 보니 `STX $43` 꼴 둘은 따로 다룰 것이 아니었습니다. `B301`(몬스터 メラ)은 `SEP / LDX #50 / LDA #16` 바로 뒤가 `B307` 이고, `B651`(ひのいき)은 바로 뒤가 `B657` 입니다. `86 43` 은 공통 루틴의 첫 명령이었습니다. 그래서 `stub` 이 `JMP`·`JSR` 없이 바로 공통 루틴 자리로 이어지는 첫머리도 받게 했습니다.

```
B657  STX $43 / JSR $AB70 / …              숨 피해(양 번호 A, 내성 칸 X)
AEC6  우리 쪽: AEA4(난수 0~7 < A)  몬스터: AECC(AE41 과 같은 내성 단계, 레벨 검사)
AEFF  우리 쪽: AEA4                 몬스터: AF06(레벨 검사 없이 27:8059·8061)
```

몬스터만 쓰는 행동이라, 파파스 장면에서 슬라임 행동 여섯이나 파파스 행동 여섯을 그 행동으로 두었습니다. 슬라임이 쓰면 우리 쪽이 맞는 값, 파파스가 쓰면 몬스터가 맞는 값을 봅니다. 처음에는 롬 바이트를 손으로 바꿔 재고, 확인한 뒤 `dq5spellfxcheck.py` 의 장면으로 옮겨 `dq5spellfx.py` 패치로 다시 쟀습니다.

```
あまいいき  B718 chance 3 → 0     원본: 주인공 첫 숨에 잠(03E)   변경: 잠 0, 03F 9번
            B718 resist 57 → 5B    원본: 슬라임 잠 3번           변경: 잠 0, 03F 6번
ラリホーマ  B419 chance 6 → 0     원본: 주인공 잠 1번           변경: 잠 0, 079 8번
            B419 resist 57 → 5B    원본: 슬라임 잠(082) 3번      변경: 잠 0, 079 6번
かえんのいき B6E2 amount 2A → 29  원본: HP 24 가 첫 숨에 0     변경: 6·6·10
            B6E2 resist 51 → 5B    원본: 31~37                  변경: 1 또는 079
몬스터 メラ  B301 amount 16 → 02  원본: 8·9                    변경: 76·78
            B301 resist 50 → 5B    원본: 8·9                    변경: 079 두 번
```

양 번호 `2A` 는 30~40, `29` 는 6~10, `16` 은 7~12, `02` 는 70~90 입니다(`27:8071`). 첫머리는 54개에서 70개(`B307` 33·`AE41` 14·`AB70` 8·`B657` 7·`AEC6` 6·`AEFF` 2)가 되었습니다.

```sh
MESENCE=… uv run --locked python sfc/dq5/tools/dq5spellgrowcheck.py rom/dq5.sfc \
  --state work/state/ship.mss --out work/spellgrowcheck      # 21회 실행 통과
MESENCE=… uv run --locked python sfc/dq5/tools/dq5spellfxcheck.py rom/dq5.sfc \
  --state work/state/ship.mss --out work/spellfxcheck        # 30회 실행, 수정 17건 통과
```

## 틀렸던 것들

- 몬스터 メラ 첫머리 `B301` 을 손으로 바꿀 때 `LDA`·`LDX` 피연산자를 한 바이트 앞(`B305`·`B303`, 명령 바이트)에 썼습니다. 양을 바꾼 롬은 피해가 2 로 나왔고, 내성 칸을 바꾼 롬은 「パパスは メラを となえた！」 에서 멈췄습니다. `B301` 은 `E2 30 A2 50 A9 16` 이라 피연산자가 `B304`·`B306` 입니다. 도구는 피연산자 주소를 첫머리에서 읽으므로 이 실수가 없습니다.
- 처음 `20:8EC9` 에 들어오는 길을 찾을 때 `BRK #$89` 를 두 바이트 명령으로 읽어 `20:8EC7` 의 `BRA` 로 빠지는 줄 알았습니다. `BRK 89` 는 인자 두 바이트(`80 3D`)를 더 가진 네 바이트라, `20:8EC9` 는 그 바로 뒤입니다.

## 남은 것

- `65`~`67` 이 아닌 즉값으로 행동 번호를 범위로 견주는 곳(갑옷 원소 `20:ABF4` 의 `13`·`39`·`48`·`8E`·`95` 같은 것)은 롬 전체를 훑지 않았습니다.
- `AEC6` 을 `JSR` 로 부르는 マホトラ(`B1F8`, 값 8) 첫머리는 도구가 받지만 게임에서 바꿔 보지 않았습니다.
- 필드 `3D` 를 읽는 `BRK 89 80 3D` 가 어떤 장비 칸을 보는지(머리 칸만인지)는 재지 않았습니다. 셋째 칸을 장비로 켜서 잰 것뿐입니다.
- 첫머리가 네 명령 꼴이 아닌 행동 전용 처리 루틴의 값.
