# 2026-10-25-14: 조우의 남은 것

[2026-10-25-06](2026-10-25-06-encounter.md) 에서 코드만 읽고 남겨 둔 조우의 나머지를 실제로 돌려 확인했습니다. 필드 구역 격자와 지형별 조우율, `$1948`·`$1949`, 실내 조우율 20, `$7E21C9`, 선제·기습, 구역 레벨, 맵 항목의 전투 배경·소리, 큰 몬스터의 마릿수 줄이기입니다. 결과는 [dq5-data-format.md 「전투 조우」](../docs/dq5-data-format.md#전투-조우-23e7c2) 와 [sfc/dq5/tools/dq5encounter.py](../tools/dq5encounter.py) 에 있습니다.

## 1. 장면 이동 도구에 기록을 붙이기

필드 실험이 막혀 있던 이유(강제 전투 뒤 조작 불가)는 [2026-10-25-08](2026-10-25-08-warp.md) 의 `dq5warp.lua` 가 풀어 주었습니다. 다만 이 도구는 도착한 뒤 `TEST` 입력을 누르고 끝나므로, 걷는 동안의 레지스터를 보려면 따로 기록을 붙여야 했습니다.
그래서 `dq5warp.lua` 를 그대로 부르면서 `TRACE`·`RWATCH`·`WWATCH`·`LATE`·`SHOTS` 를 더하는 `sfc/dq5/tools/lua/dq5warptrace.lua` 를 만들었습니다. 기록은 `dq5warp.lua` 가 끝날 때 함께 씁니다.

`01:84CF` 는 구역(A)과 조우율(Y)을 정하고 `00:82AF` 로 돌아옵니다. 여기를 걸음마다 기록하고, 같은 값을 표로 계산하는 `dq5encounter.py --steps` 를 더했습니다.
지형은 `03:CB1B` 를 따라 세계 지도 블록의 니블(`03:CC48`)로 계산합니다. 조우하면 걷기가 끊기므로 조우 계수 표를 0 으로 덮고 걸었습니다.

```sh
export LIBDIR=$(uv run --locked krpatch sfc lua)
STATE=$PWD/work/state/ship.mss FIELD=174,110 ROMPATCH="11EA44=0000000000000000" \
  TEST="left:120,right:240,left:120,up:120,down:240,up:120" \
  TRACE=0082AF LOG=7E00BC,7E00BE,7E00B6,7E00B8,7E1948,7E075E,7E21C9 \
  SHOT_DIR=$PWD/work/g1 "$MESENCE" --testrunner "$PWD/rom/dq5.sfc" "$PWD/sfc/dq5/tools/lua/dq5warptrace.lua"
uv run --locked python sfc/dq5/tools/dq5encounter.py rom/dq5.sfc --steps work/g1/trace.txt
```


밤 표 `23:F1EE` 는 낮 표와 바이트가 같아 따로 확인할 것이 없었습니다.

## 3. `$1948`·`$1949`

`$1948` 을 쓰는 곳은 이벤트 두 곳(`02:9C47` → 1, `1E:DE8E` → 2)과 `00:A72A` 입니다. `00:A72A` 는 플래그 `7E:2190` bit6·5·4 로 0·1·2 를 다시 정합니다.
`dq5warp.lua` 의 `SET` 으로 플래그만 켜고 필드로 나가 보니 `$1948` 은 바뀌지 않았습니다. `00:A72A` 는 맵 불러오기에서 불리지 않고, 부르는 쪽은 긴 초기화 루틴(`00:A6E9` 근처)입니다.
`$1948` 자체를 1·2 로 바꾸고 나가자 같은 자리 (341,56) 에서 구역이 `0D` → `16` 으로, (174,110) 에서는 `02` → `13` 으로 바뀌었습니다. 각각 `23:F273`·`23:F394` 격자의 값입니다.

`$1949` 는 맵에 들어갈 때 `2A:FEF5` 가 맵 그룹 표(`0F:EA97 + BC*5`) 첫 바이트 bit5-6 에서 1 을 빼 넣습니다. `SET` 으로 바꿔도 필드에 나가면 0 으로 돌아가서, `POKE` 로 매 프레임 고정했습니다.
1 이면 눈 덮인 세계, 2 이면 어두운 숲 세계가 그려졌고 구역은 `23:F4B5`(`07`)·`23:F50A`(`49`) 격자 값이었습니다. 이 두 세계의 지도는 아직 풀지 않아 지형까지는 맞춰 보지 못했습니다.

## 4. 실내 조우율 20

`01:851F` 의 `TXY / BMI` 가 보는 X 는 바로 앞 `00:CAFD` 의 결과입니다. 이 루틴은 주인공이 선 셀과 오른쪽 셀(인물은 가로 2칸)의 구역 니블을 지금 구역 마스크 `7E:3720` 과 비교합니다. 둘 다 다르면 마스크를 바꾸는 `0F:D0BD` 를 부르고 X = 80 으로 돌아옵니다.
다른 방의 지붕을 숨기는 구역([dq5-map-format.md 「셀 버퍼」](../docs/dq5-map-format.md#셀-버퍼-7ec000-))이 바뀌는 걸음입니다.

조우가 있는 맵 중 구역이 둘 이상인 09/00(구역 `08`)을 골랐습니다. 안쪽 방이 구역 2 이고 경계가 X = 12 입니다. (5,60) 에서 좌우로 오가며 `01:851F`·`00:82AF` 를 기록했습니다.

```
01851F A=0008 X=0000 Y=0008 7E3720=0010 7E3020=800B   ← (11,60)
0082AF A=0008 X=0000 Y=0007
01851F A=D608 X=0080 Y=000C 7E3720=0020 7E3020=800C   ← (12,60) 에서 구역 2 로
0082AF A=D608 X=0080 Y=0020
```

돌아 나올 때 (10,60) 에서도 같았고, 넘는 걸음 4번 모두 20, 나머지 59번은 7 이었습니다.

## 5. `$7E21C9`

쓰는 곳은 `00:8332`(지우기)와 뱅크 11 의 세 곳입니다. `11:801A` 는 주문 번호(`$46`) − `27` 로 `11:8024` 표를 골라 뜁니다. 이름 문자열 3번 표에서 `27` 이 ホイミ 이므로 13번째인 `11:8797` 이 `34` トヘロス 입니다. 이 루틴이 1 을 넣습니다.
2·3·4 를 넣는 곳 옆의 메시지는 `1AC`「{1008}は {100A}を ふりまいた！」, `1B6`「においぶくろを あけた！」, `1C0`「まもののエサを ふりまいた。」였습니다.

물건을 실제로 쓰지는 않고, 필드에 도착한 뒤 `LATE` 로 값만 넣었습니다.

| 넣은 값 | 조우율(구역 `0D`, 지형 2) |
| --- | --- |
| `21C9=01`, 레벨 1 | `0C` |
| `21C9=01`, `2052=09` | `00` |
| `21C9=02`, 레벨 1 | `0C` |
| `21C9=03`·`04` | `60` |
| `21C9=01`, `1A9C=05` | 5걸음 뒤 `21C9` = 0 |

`7E:2052` 를 `30` 으로 바꾸자 전투의 상태 창에 「ﾚ:48」이 나와 주인공 레벨임을 확인했습니다. 시작할 때 `SET` 으로 넣은 값은 필드에 나가는 동안 지워졌습니다(맵을 옮기면 지움).

## 6. 전투 시작 때 쓰는 값

구역 `0D` 에서 전투를 붙이고 `RWATCH` 로 `$1000`·`$1009`~`$100B`·`$100F`·`$1010`·`$1AA0`·`$194B`·`$194D` 를 읽는 곳을 모았습니다.

- `$1000` 은 `26:8329` 가 읽습니다. 레코드 `+4` bit6-7 을 번호로 `27:8043` 의 두 값과 난수(0~31)를 비교해 bit1·bit0 을 켭니다. 표를 `20 00` 으로 덮자 「しかし まもののむれは おどろき とまどっている！」, `00 20` 으로 덮자 「ダンスニードルたちは いきなり おそいかかってきた！」로 시작했습니다. bit1 이 선제, bit0 이 기습입니다.
- `$100F` 는 `21:B9A1` 이 읽습니다. 몬스터 행동 표 `21:BC33` 의 17번이고, 주인공 레벨이 `$100F + 4` 보다 크면 도망칩니다. 구역 `0D`(레벨 9)를 スライム 3마리만 나오게 고치고 방어만 했습니다. 레벨 13 에서는 끝까지 셋이 남았고, 14 에서는 「スライムBは にげだした！」가 나왔습니다.
- `$1009` 는 `22:86D5` 가 무리마다 `$0D1B` 로 옮기고, `$1010` 은 읽는 곳이 나오지 않았습니다. 전투를 이기고 끝까지 진행해도 같았습니다.

## 7. 맵 항목 `+3`·`+5`

21/02 의 항목(파일 오프셋 `11FAE2`, `01 14 14 07 01 09`)을 고쳐 들어갔습니다.

- `+3` 을 `07` → `02`·`0B` 로 바꾸자 같은 전투(おおきづち·スライム)의 배경이 동굴 → 초록 바닥·붉은 벽돌로 바뀌었습니다.
- `+5` 는 `00:8405` 가 읽어 `24:FE91` 로 넘깁니다. `24:FE91` 은 소리 명령 `1A` 를 보내는 입구입니다. `+5` 를 `0C` 로 바꾸자 맵에 들어갈 때 `24:FE91` 의 A 가 `09` → `0C` 가 되었습니다.

## 8. 큰 몬스터의 마릿수

구역 `0D` 를 キングスライム 8마리(마릿수 부호 7)만 나오게 고치고 `WWATCH=0D16-0D16` 으로 마릿수를 쓰는 곳을 보았습니다.

```
808 0D16 pc=22:86D5 v=08     ← $1005 에서
808 0D16 pc=22:92A4 v=03     ← 줄인 값
```

`22:9284` 는 몬스터 너비 `$0D13` 을 더해 가며 28 미만에 들어가는 마릿수만 남깁니다. `$0D13` 은 `22:9071` 이 몬스터 그림 레코드 `+5` 의 위 니블 + 1 로 넣습니다. キングスライム 은 `66` 이라 7 이고, 7 × 3 = 21 은 들어가지만 7 × 4 = 28 은 넘칩니다. スライム(`11` → 2)으로 같은 실험을 하면 8마리 그대로였습니다.
줄 번호(`7E:2FCD + 줄`)를 고르는 `22:92AE` 가 `$0D1B` 를 보므로, 고정 무리의 하위 4비트는 줄을 고르는 값으로 보입니다. 실제 고정 무리 9개는 모두 0 입니다.

## 틀렸던 것들

- `$1948` 을 바꾸려고 플래그 `7E:2190` bit6·5 를 켜고 필드에 나갔지만 `$1948` 은 그대로였습니다. `00:A72A` 가 맵 불러오기에서 불린다고 보았는데, 불러오기 경로에는 없었습니다.
- `$7E21C9` 를 `SET` 으로 시작할 때 넣었더니 필드에서 이미 0 이었습니다. 맵을 옮길 때 지워지므로 도착한 뒤(`LATE`)에 넣어야 했습니다.
- 처음에는 레코드 `+0` 이 せいすい 류 비교에만 쓰인다고 보았습니다. 전투 안에서도 몬스터가 도망칠지를 정하는 데 씁니다.
