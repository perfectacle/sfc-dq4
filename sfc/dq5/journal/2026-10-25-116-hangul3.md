# 2026-10-25-116: 한글 시제품을 전원부터, 긴 창 레코드 옮기기

[2026-10-25-103](2026-10-25-103-hangul2.md) 의 시제품은 세이브스테이트에 창 글자를 다시 써 넣고 찍었습니다. 이번에는 세이브스테이트 없이 전원부터 켜 새 게임으로 한글 이름을 넣고 메시지·명령 창까지 갔고,
원래 자리에 들어가지 않는 긴 명령 창 레코드를 뱅크 04 밖으로 옮겼습니다. 결과는 [dq5-hangul-format.md 「시제품」](../docs/dq5-hangul-format.md#시제품) 에 있습니다.

## 1. 전원부터 켜 새 게임

```sh
uv run --locked python sfc/dq5/tools/dq5hangul.py rom/dq5.sfc proto --long -o work/fresh-pl2.sfc
P="wait:1500,start:4,wait:200,down:4,wait:30,down:4,wait:30,a:4,wait:600,a:4,wait:300,down:4,wait:20,down:4,wait:20,left:4,wait:20,a:4,wait:100"
P="$P,up:4,wait:20,up:4,wait:20,left:4,wait:20,left:4,wait:20,left:4,wait:30,a:4,wait:40,left:4,wait:30,a:4,wait:60"
P="$P,down:4,wait:20,down:4,wait:20,down:4,wait:20,down:4,wait:20,right:4,wait:30,a:4,wait:100$(printf ',a:4,wait:56%.0s' $(seq 110))"
P="$P,wait:300,left:3,wait:30,a:4,wait:90,a:4,wait:250"
PRE="$P" MAXF=10700 SHOTS=3200,6850,10390,10600 SHOT_DIR=$PWD/work/hangul/poweron-long \
  "$MESENCE" --testrunner "$PWD/work/fresh-pl2.sfc" "$PWD/sfc/dq5/tools/lua/dq5msg.lua"
```

MesenCE 는 롬 파일 이름마다 SRAM 을 두므로 새 이름의 롬은 모험의 서가 없이 시작합니다. ぼうけんのしょをつくる → 1번에서 이름 입력 창이 뜨고, かな/カナ 칸으로 가타카나 쪽으로 바꾸면 ハヒフヘ 자리에 전·조·사·용 이 나옵니다.
ヘ(용)·フ(사)를 고르고 おわり 를 누르자 이름이 `5E 5D 70 70` 으로 저장됐습니다. 같은 입력을 원래 롬에 하면 「ヘフッッ」 이라, 남은 칸이 `70` 으로 채워지는 것은 게임의 동작입니다.
그 뒤 A 를 눌러 오프닝을 넘기자 메시지 `1DB` 에 「용사ッッ」, 배 선실에서 연 명령 창과 상태 창, 빈 쪽 메시지 `129` 가 모두 한글로 나왔습니다.

## 2. 긴 창 레코드

창 레코드는 데이터 뱅크 04 에서 16비트 주소로 읽으므로 다른 뱅크로 그냥 옮길 수는 없습니다. 같은 16비트 주소가 뱅크 00~3F 에서는 `$0000`~`$1FFF` 가 낮은 WRAM 이라는 점을 써서, 레코드를 창을 열 때 낮은 WRAM 으로 복사하게 했습니다.
빈 자리를 고르려고 선실·필드·전투 세이브스테이트에서 명령 창·대화·전투를 돌리며 낮은 WRAM 8KB 를 27번 덤프했고, `7E:119F`~ 610바이트가 모두 0 이었습니다.

`04:9C46` 의 `LDA $EB48,X` / `STA $DA` 를 `JSL 36:8100` / `NOP` 로 바꾸고, 훅이 원래 두 명령 뒤 주소가 `$11A0` 이면 `MVN 7E,36` 으로 뱅크 36 의 레코드를 복사합니다. 창 표의 창 01 칸은 `$11A0` 입니다.
명령 창을 열자 `7E:11A0` 에 새 레코드가 있었고, BG3 타일맵 테두리가 2~16열로 너비 15 였습니다.

## 3. 2바이트 이름 부호

이름 문자열을 글자 코드로 바꾸는 `24:A7B6` 은 `84`·`83`(탁점)과 `01`(공백)을 빼면 바이트를 `24:B270` 으로 바꿉니다(`24:A7D5` 의 `JSR $A81E`). 이 호출을 `retree` 가 비운 `24:9E11` 의 작은 루틴으로 돌려, 접두 `85` 뒤 바이트를 새 글자 번호로 읽게 했습니다(`proto --twobyte`).

```sh
uv run --locked python sfc/dq5/tools/dq5hangul.py rom/dq5.sfc proto --twobyte -o work/proto2b.sfc
STATE=$PWD/work/state/ship.mss POKE="7E2001=85;7E2002=18;7E2003=85;7E2004=19;7E2005=85;7E2006=10;7E2007=85;7E2008=11" \
  PRE="b:4,wait:40,down:3,wait:20,a:4,wait:40,a:4,wait:150" MAXF=260 SHOT_DIR=$PWD/work/hangul/twobyte \
  "$MESENCE" --testrunner "$PWD/work/proto2b.sfc" "$PWD/sfc/dq5/tools/lua/dq5msg.lua"
```

처음에는 접두 뒤 바이트를 `00` 부터 매겼는데, 「름」 이 `85 01` 이 되어 이름을 복사하는 `24:8A0F` 가 `01` 을 이름 끝으로 보고 멈췄습니다. 남은 바이트 수(`$00`)가 홀수가 되어 접두 루틴이 하나 더 줄이자 0 을 지나쳐 메시지가 이름 앞에서 멈췄습니다.
`10` 부터 매기자 메시지 `129` 가 「이름은 한글이름입니다。」, 메시지 `1DB` 가 「한글이름！ 今日から おまえは 한글이름だ！」 였습니다.
