# 2026-10-27-NN: 새 맵 번호 더하기

DQ4 의 마을은 DQ5 의 같은 자리 마을보다 방이 많을 수 있습니다. 원본에 없는 맵 번호를 하나 더하면 그 번호로 찾는 표가 모두 따라 늘어야 합니다. 맵 번호로 찾는 표를 실측으로 모으고, 맵 포인터·맵 속성을 늘리는 `dq5newmap.py` 를 만들었습니다. 출구는 `dq5exitreloc.py --new-map` 으로 잇습니다. 새 맵 0D/05 에 게임의 계단으로 들어가 걸어 다녔습니다. 결과는 [쓰기 형식](../docs/dq5-build-format.md#새-맵-번호-dq5newmap1)에 있습니다.

## 1. 맵 번호를 읽는 코드

문서에서 `$BC`·`$BD` 로 표를 찾는다고 적힌 곳을 모으면 스무 곳쯤입니다. 빠진 것이 없는지 보려고 `$BC`·`$BD`(직접 페이지 `00:00BC`·`7E:00BC`) 읽기에 감시를 걸고 원본 롬 세 장면(01/03 에서 걷기, 21/02 와 01/00 에서 출구 밟기)을 돌렸습니다. 읽은 PC 는 95곳이었습니다.

명령 꼴로 나누면 대부분 `CMP #$xx`(특정 맵에서만 도는 갈래)나 `CMP $BD` 로 표를 훑는 찾기 목록입니다. 찾기 목록은 새 번호를 주면 항목이 없어 기본 동작을 합니다. 번호로 곧장 색인하는 곳은 넷이었습니다.

| 곳 | 표 | 새 번호를 주면 |
| --- | --- | --- |
| `01:9316` `LDY $8ED7,X` | 맵 포인터, 그룹 표 + `$BD`×3 | 뒤 그룹 포인터 |
| `01:83FB` `LDA $FD6A,X` | 맵 속성, 그룹 표 + `$BD`×6 | 뒤 그룹 속성 |
| `12:8050` `LDA $D4B2,Y` | 인물 기본 목록, `00` 끝 목록 `$BD` 개를 건너뜀 | 다음 그룹 첫 맵의 목록 |
| `2A:F732` | 출구 목적지, 목록 `$BD` 개를 건너뜀 | 다음 맵이나 그룹 머리 |

`2A:F40D` 는 `$BC`×5 를 곱셈 레지스터로 셉니다. 그룹마다 들어가는 곳 표(`0F:EA97`)라 기존 그룹에 맵을 더할 때는 상관없습니다.

## 2. 그룹 표를 옮겨 빈틈 만들기

맵 포인터와 맵 속성은 꼴이 같습니다. 그룹 목록이 이어지고 바로 뒤에 그룹 표가 붙어 있습니다(`0F:8AC9`~`8ED6` 뒤 `0F:8ED7`, `23:F54E`~`FD69` 뒤 `23:FD6A`). 그룹마다 맵 수는 다음 그룹 포인터와의 차입니다. 맵 하나를 끼우면 뒤가 모두 밀리는데 뒤에는 그룹 표가 있고, 그 뒤는 다른 자료입니다.

그룹 표 108바이트를 같은 뱅크의 빈 자리(`0F:FF50` 176바이트, `23:FF20` 224바이트)로 옮겼습니다. 그러면 옛 표 자리 108바이트만큼 목록을 밀 수 있습니다(맵 포인터 36개, 맵 속성 18개). 코드는 표 주소 피연산자 셋(`01:9317`, `01:83FC`·`8401`)만 바꿉니다. DB 는 그대로 `0F`·`23` 이라 같은 창의 다른 abs 접근(`STA $1823` 등)은 바뀌지 않습니다.

맵 수를 세는 쪽이 문제였습니다. 도구들은 「다음 그룹 포인터와의 차, 마지막 그룹은 표 자리까지」로 맵 수를 셉니다. 표를 옮기면 마지막 그룹의 끝을 알 수 없으므로, 옮긴 표 뒤에 목록 끝 주소 16비트를 하나 더 붙였습니다. `dq5map.group_spans` 가 코드의 피연산자로 표를 찾고 이 끝 표시를 읽습니다. `all_maps`·`map_pointer`·`pointer_addr`, 조우 도구의 맵 항목 읽기를 이것으로 바꾸었고, 원본에서 맵 364개 재포장·조우 표 검사는 차이 0 그대로였습니다.

원본 롬 네 장면(01/03, 21/02, 0D/01, 50/50)에서 옛 그룹 표 두 곳을 읽는 명령은 `01:9316`·`83FB`·`8400` 셋뿐이었습니다.

## 3. 출구와 인물

출구는 `dq5exitreloc.py` 에 `--new-map` 을 더했습니다. 원본 롬의 맵 목록에 새 맵을 더한 것으로 문서를 검사하고, `dump` 는 새 맵에 「출구 없음」(`special` 0) 하나를 넣어 냅니다. 0D/05 를 더하면 출구 표가 2바이트 늘어 원래 자리에 맞지 않으므로 출구를 `2A:D812`, 레코드를 `3F:8000` 으로 옮겼습니다.

인물 기본 목록은 늘리지 못했습니다. 인물 도구는 원본 목록·대체 목록·빈 맵 표를 고치지만 새 맵의 기본 목록은 받지 않습니다(인물 도구 담당에게 요청함). 새 맵은 다음 그룹 첫 맵의 목록을 읽으므로, 그 목록이 빈 그룹을 롬에서 찾으니 `0A`·`0D`·`14`·`25`·`31`·`32` 여섯이었습니다. 실험은 0D 에 했습니다.

## 4. 0D/05 에 들어가기

0D/05 를 0D/02(계단 하나뿐인 작은 방)의 레코드·속성으로 만들고, 0D/01 의 출구 1(원래 0D/02 로 감)을 0D/05 로 돌렸습니다. 0D/05 의 출구는 0D/02 와 같은 0D/01 출구 1 입니다. `dq5newmapcheck.py` 가 이 롬과 원본에서 12장면을 밟습니다.

```
enter: 0D/05 (14, 11) 층 01 1A98=FF 1AA0=80 194D=01 194B=09 1983=08
enter-original: 0D/02 (14, 11) 층 01 1A98=FF 1AA0=80 194D=01 194B=09 1983=09
walk: 0D/05 (10, 8) …
walk-original: 0D/02 (10, 6) …
leave: 0D/01 (14, 11) …
```

0D/01 의 계단을 내려가자 0D/05 의 계단 옆 (14,11) 에 섰고, 맵 속성 WRAM 네 바이트는 0D/02 와 같았습니다. 인물 뒤 슬롯은 `08`(인물 없음)로 0E/00 의 빈 목록을 읽은 것과 맞습니다. 같은 길을 걸으면 원본 0D/02 는 (10,6) 에서 멈췄고 0D/05 는 (10,8) 까지 갔습니다. 0D/02 의 인물 한 명이 (10,8) 에 서 있기 때문입니다. 0D/05 의 계단을 밟자 0D/01 (14,11) 로 나왔습니다.

목록이 밀린 뒤 그룹의 21/02 출구는 원본처럼 0E/03 (38,67) 로 갔고, 21/02 에 섰을 때의 속성(구역 `01`)도 같았습니다. 앞 그룹 01/00 의 출구도 같았습니다. 출구 표 쪽 기존 44장면도 다시 돌려 모두 맞았습니다.

## 틀렸던 것들

- 처음에는 계단 (15,11) 바로 위 (15,10) 에서, 다음에는 (14,10) 에서 내려가게 했는데 둘 다 출구가 불리지 않았습니다(원본도 같음). 계단 블록이 (14~15, 10~11) 네 칸이라 둘 다 이미 계단 위였습니다. 블록 밖 (14,9) 에서 내려가자 발동했습니다.
- 새 맵에서 걷는 장면을 원본 0D/02 와 같은 칸으로 기대했으나, 원본은 인물에 막혀 두 칸 덜 갔습니다. 인물이 없는 새 맵과 견주는 장면이라 기대 칸을 따로 두었습니다.
- 표가 옮겨지지 않은 롬에서도 빈 입력이 그룹 표를 옮겼습니다. 맵 수가 그대로면 표를 옮기지 않게 고쳤습니다.

## 남은 것

- 새 맵의 인물 기본 목록. 인물 도구가 새 맵 목록을 받아야 합니다.
- 그룹 `$50` 이상의 새 맵(표가 따로 있음), 새 그룹 번호.
- 그룹 표 자리만큼만 늘어남(맵 포인터 36개, 맵 속성 18개). 더 늘리려면 표 덩어리를 다른 뱅크로 옮기고 DB 즉값(`01:92F1`·`01:83ED`)도 바꿔야 합니다.
- `$BC`·`$BD` 를 읽는 코드 조사는 세 장면 안에서만 했습니다. 전투·메뉴·이벤트에서만 도는 코드는 들지 않았습니다.
