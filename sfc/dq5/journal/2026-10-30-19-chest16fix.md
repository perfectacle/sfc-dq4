# 2026-10-30-19: 상자 번호 16비트 훅의 남은 마스크와 물건 보상

[상자 번호 16비트 일지](2026-10-30-16-chest16.md)의 켜기 훅(`12:F839`)은 `$1E81` 이 `00` 이고 넘길 마스크 칸 `7E:291B` 가 `00` 이 아니면 상자 256 이상의 비트를 켭니다. 상자를 열어 놓고 `12:F839` 까지 가지 않으면 `291B` 가 남고, 다음에 다른 보상이 `$1E81` = `00` 으로 `12:F839` 를 부르면 그 마스크를 `7E:28F3 + $1E80` 에 OR 합니다. `$1E80` 이 `FF` 까지 될 수 있으므로 사람 동료 칸(`294A`~)까지 닿습니다. 리뷰에서 나온 이 지적을 고치고, 게임에서 금화로만 보던 상자 300 을 물건 보상으로도 열어 봤습니다. 결과는 [쓰기 형식 「상자 257개 이상」](../docs/dq5-build-format.md#상자-257개-이상---wide-at)에 넣었습니다.

## 1. 훅 고치기

256 미만의 길은 원래 루틴 그대로 두고, 훅 두 곳에 몇 바이트를 더했습니다.

- 열기 훅 첫머리: `SEP #$20 / LDA #$00 / STA $7E291B`. 앞 상자가 남긴 마스크를 지우고 시작합니다.
- 켜기 훅: `$1E81` = `00`·`291B` ≠ `00` 다음에 `LDA $7E1E80 / CMP #$28 / BCS 원래 길` 을 넣었습니다. `28` 은 `28F3`~`291A` 의 바이트 수입니다. 원래 길은 `$1E81` = `00` 을 OR 하므로 아무것도 바꾸지 않습니다.

`dq5chestreloc.py` 는 `--wide-at` 이 있으면 서랍·발밑·두 칸 앞·아래층 상자 표의 `mask` 가 `00` 인 항목을 거부합니다. 원래 롬에는 그런 항목이 없었습니다. 상자 비트를 `28F3`~ 에 두는 것은 이름(`'일반'`)으로 가리지 않고 `claim(..., allow_wide=n >= 256)` 으로 받게 했고, 상자가 576개를 넘으면 「576개까지」라고 알립니다. `check` 는 만든 롬의 `12:E66F` 가 `--wide-at` 자리를 그대로 가리키는지 봅니다. `locate` 는 훅을 같은 표 자리로 다시 만들어 견주므로 새 바이트도 그대로 봅니다.

해석기 테스트에는 이것을 더했습니다.

- `2A:F224` 를 부를 때 DP `$00`·`$01` 이 `$1E71`·`$1E72` 와 같은지(그동안은 `LDA #순서 / RTL` 로 바꿔 놓아 이 준비를 보지 않았음).
- `291B` 에 `04` 를 남기고 이미 열린 상자 300·256 미만 상자를 열면 `291B` 가 `00`.
- `291B` = `08`·`$1E81` = `00` 으로 `$1E80` 을 `28`·`80`·`FF` 로 두고 켜기 훅을 부르면 `28F3`~`291A`·`294A`~`29FF` 가 그대로이고 `291B` 도 남음.

훅에서 새 두 줄을 빼면 열기·켜기 테스트가 하나씩 실패하는 것도 봤습니다.

## 2. 보상마다 `12:F839` 에 가는 길

`lua/dq5chestcheck.lua` 에 `12:F839` 실행 기록(`$1E80`·`$1E81`·`291B`·스택 맨 위)을 더하고, 상자 301개 롬에서 상자 300 의 보상만 바꿔 열었습니다. 잠김·가득 찬 경우는 같은 빌드를 작업 폴더의 일회용 스크립트로 만들어 돌렸습니다.

```
wide_open      reward 022C  set index=05 mask=00 pend=08 ret=F51C   28F8=08 291B=00
wideitem_open  reward 0033  set index=05 mask=00 pend=08 ret=EE25   28F8=08 291B=00
FFFC(잠김)     메시지 14E, reward·set 없음                          28F8=00 291B=08 $1E80=05 $1E81=00
물건 33, 주인공 물건 12칸 가득(7E:2056~2061 = A1)
               reward 0033, 메시지 12E·14A·13D → いいえ → 14B, set 없음  28F8=00 291B=08
```

금화는 `12:F518` 의 `JSR $F839` 로 들어갔습니다(`ret` 가 `F51C`). 물건은 보상 루틴(`12:F43B`)이 `12:F467` 에서 `JMP $F6E4` 로 가고 `12:F70C` 의 `BRL $F839` 로 들어갔습니다. 스택 맨 위는 보상 루틴을 부른 `12:EE23` 의 돌아갈 주소였습니다. 상자 몬스터(`01:868B`)를 지나는 `12:F4A8` 은 물건 보상의 길이 아닙니다. 뱅크 12 를 바이트로 찾으니 `12:F839` 로 가는 명령은 `JSR` 셋(`12:F1CF`·`F4A8`·`F51A`) 말고도 `12:F70C` 의 `BRL`, `12:F821` 의 `BRA` 가 있었습니다.

잠긴 상자와, 물건이 가득해 버리기를 거절한 상자는 `12:F839` 를 지나지 않았습니다. 둘 다 `291B` = `08`, `$1E80` = `05`, `$1E81` = `00` 을 남겼습니다. 리뷰가 걱정한 바로 그 상태입니다. 그대로면 다음 상자를 열 때까지 남지만, 1절의 두 줄로 다음 상자를 열 때 지우고, 그 사이 `$1E80` 이 `28` 이상인 보상은 원래 길로 갑니다.

그 사이에 `12:F839` 를 부르는 다른 보상도 봤습니다(코드 읽기). 뱅크 12 에서 `$1E80` 에 쓰는 곳은 `12:E628`·`E699`·`E74C`·`EAC1`·`FC27`·`FD21`·`FD75` 일곱입니다. 모두 `$1E81` 에 마스크를 함께 둡니다. `12:E628`(`$1E80` = `23`, 마스크 `10`)과 `12:EAC1`(`01`, `14`)은 마스크가 상수이고, 나머지는 `ORA #$80`·`TSB` 로 `$1E80` 이 `80` 이상입니다. 상자 몬스터(`FFFD`·`FFFE`)는 전투(`12:F4A4` `JSL $01868B`) 뒤 `12:F4A8` 에서 켜고, 01/05 의 빈 상자(`FFFF`) 특례(`12:F4D7`~`F517`)는 `12:F839` 없이 끝납니다.

## 3. 게임에서 다시 확인

```
dq5chestcheck.py rom/dq5.sfc --state work/state/ship.mss --case wide_open --case wide_alias --case wide_entry --case wide_save --case wideitem_open
4쌍/8실행 통과: 보상·금화·새 열림 비트·기존 비트 보존·들어갈 때 열린 상자, 기록·불러오기 1실행 통과
```

`wideitem_open` 은 상자 300 의 보상을 물건 `33` 으로 바꾼 롬입니다. 원본은 19/00 이 표에 없어 12B·12C, 패치는 메시지 131 과 물건 `33` 을 얻고 `28F8 & 08` 만 켜졌습니다. 상자 1·44 의 바이트는 그대로였고 `291B` 는 `00` 으로 돌아왔습니다. `wide_open`·`wide_alias`·`wideitem_open` 은 이제 `12:F839` 에 상자 300 의 바이트 번호 `05`·`$1E81` = `00`·`291B` = `08` 로 꼭 한 번 들어갔는지도 봅니다.

## 남은 것

- 상자 몬스터를 연 뒤 전투에서 전멸하면 `12:F4A8` 로 돌아오는지. 돌아오지 않으면 `291B` 가 남지만, 1절의 두 줄로 다음 상자를 열 때 지워집니다.
- 상자 300 밖의 번호(256~575)는 여전히 해석기 테스트와 코드 읽기입니다.
