# 2026-10-25-89: 전투 글자 타일과 창 머리 +0 위 비트

[2026-10-25-86](2026-10-25-86-text5.md) 에 이어, 전투 메시지에 쓰는 BG3 타일 `96` 이후가 어디서 오는지와 창 머리 `+0`·`+2` 의 위 비트를 보았습니다.
결과는 [dq5-hangul-format.md 「1바이트 부호」](../docs/dq5-hangul-format.md#1바이트-부호) 와 [dq5-text-format.md 「창 레코드 머리」](../docs/dq5-text-format.md#창-레코드-머리) 에 있습니다.

## 1. 전투의 BG3 타일 96 이후

보행 모드에서는 BG3 타일 `96`~`17F` 가 메시지 글자를 그려 넣는 칸인데, 전투 메시지 바이트에는 「。」(`9A`)·「「」(`9C`)·「…」(`9D`) 처럼 `96` 이후 번호가 섞여 있습니다(전투 메시지 코드 뜻은 다른 세션이 실측).
슬라임·ドラキー 전투 세이브스테이트의 VRAM 을 덤프해 타일 `80`~`BF` 를 그려 보니 `9A` 부터 문장 부호와 「Ａ」~「Ｐ」 가 들어 있었습니다. 타일마다 평면 하나를 롬에서 찾았습니다.

```
9A 평면0 = 04:EA68   9C = 04:EA78   9D = 04:EA80   A0 = 04:EA98   A1 = 04:EAA0
```

`04:EA28` 을 읽는 곳은 `04:E2D9`·`E2FC` 둘이고, 그 루틴 `04:E2A1` 은 `26:8030`(전투 시작)에서 부릅니다. VRAM 워드 `14B0`(타일 `96`)부터 2bpp 4개, 이어서 1bpp 22개(`Y` 가 `F0` 이 될 때까지)를 전송 목록 `7E:4000` 에 넣습니다.
곧 `04:E528` 의 1bpp 138자(타일 `01`~`8A`) 뒤 창 테두리 2bpp 11개 다음이 이 전투 글자입니다. 전투 동안은 타일 `96`~`AF` 를 이 글자가 차지합니다.

## 2. 창 머리 +0·+2 의 위 비트

일행 셋 どうぐ 창 `0E`(`+0` = `66`, `+2` = `C9`)에서 바꿔 열었습니다. `+0` 을 `26`(bit6 끔)으로 하자 일행 가운데 한 줄만, `A6`·`E6`(bit7 켬)이면 창이 뜨지 않았고, `67` 이면 한 칸 오른쪽이었습니다. `+2` 의 위 두 비트는 `09`·`49`·`89` 로 바꿔도 같았습니다.
`dq5text.window_header` 가 `+0` 의 아래 5비트를 X 로, 위 3비트를 `x_flags` 로 나눠 돌려주게 했습니다.

## 남은 것

- 창 머리 `+0` bit5, `+2` 위 두 비트, `+4` 위 4비트, 상태 창 제목 뒤 `12 12 12`
- 전투에서 BG3 타일 `B0` 이후(막대 모양)를 올리는 곳
