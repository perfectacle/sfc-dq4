# 2026-10-25-01: 메시지, 폰트, 대화 스크립트

DQ4 대사를 넣으려면 DQ5 가 대사를 어떻게 저장하고 고르는지부터 알아야 합니다. 이번에 메시지(허프만 부호), 폰트, 그리고
인물의 대화 번호에서 메시지까지 가는 길(대화 스크립트)을 풀었습니다. 결과는 [dq5-text-format.md](../docs/dq5-text-format.md) 에 있습니다.

## 1. 말을 걸면 부르는 곳

「ドラクエ命」의 텍스트 해석에 보행 모드 메시지를 찾는 루틴이 `24:8BAF` 라고 나와 있어서, 롬에서 그 자리를 디스어셈블하니
`LSR ×4`, `×3`, `LDA $AF1E,X` 로 정말 16개 단위 색인을 읽고 있었습니다.

배 선실 세이브스테이트에서 오른쪽을 보고 A 를 두 번(명령 창 → 「はなす」) 누르며 `24:8BAF` 호출을 기록했습니다.

```sh
export LIBDIR=$(tools/lua/seqlib.sh "$(uv run --locked krpatch sfc lua)" work/walklib walk.lua)
STATE=$PWD/work/state/ship.mss PRE="b:4,wait:40,right:3,wait:20,a:4,wait:30,a:4,wait:200" WAYPOINTS="" \
  CHANGES=9 MAXF=400 EVERY=0 SHOT_DIR=$PWD/work/text1 CALLS=248BAF,248B98 \
  "$MESENCE" --testrunner "$PWD/rom/dq5.sfc" "$(uv run --locked krpatch sfc lua)/probe/calls.lua"
```

```
115 248BAF A=0129 X=02DA Y=0000 ret=00:8167
117 248B98 A=1001 X=076A Y=0008 ret=00:816D
```

오른쪽엔 아무도 없어서 「その方向には　誰もいない。」가 나왔고, 이것이 메시지 0x129 입니다.

## 2. 허프만 디코더를 옮기다

`24:9E02` 는 비트를 LSB 부터 읽어 1 이면 `24:8CB6`, 0 이면 `24:9472` 쪽 노드를 따라가고, bit15 가 켜진 노드에서 13비트 코드를 돌려줍니다.
`sfc/dq5/tools/dq5text.py` 로 옮겨, 게임이 `24:8BAD`(64개를 다 푼 직후)에서 `7E:0E4B` 에 둔 값과 비교했습니다.

```
1006 02E6 0399 0090 0133 03C6 02E8 0000 025F 02EA 0398 0330 0398 0356 1001 ...
python == game: True (64개)
```

화면의 글자 수(13자)와 `1006` 뒤 코드 수가 같아서, そ=`02E6`, の=`0399` … 。=`0356` 처럼 바로 맞출 수 있었습니다.
코드가 가나 순서가 아니어서 글자표는 폰트를 봐야 했습니다. 메시지 3,200개를 모두 풀어 보니 끝 코드까지 막힘없이 풀렸습니다.

## 3. 폰트

글자를 그리는 동안 ROM 읽기를 집계(`rprof.lua`)하니 `24:A75C` 가 `07:A1B5-07:D690` 을, `24:A63F` 가 `24:B176-` 표를 읽었습니다.
`24:A609` 리스팅을 보니 `24:B176` 은 5바이트마다 「같은 크기 글자 묶음」(개수, 폭, 높이, 시작 주소)이었고,
글자는 폭×높이 비트씩 이어 붙은 1bpp 그림이었습니다. 「。」는 9×3, 한자는 11×13 처럼 묶음마다 크기가 다릅니다.

이렇게 그린 글자가 화면과 같았습니다.

![MesenCE 화면(위)과 dq5text.py 로 메시지 129 를 풀어 롬 폰트로 그린 것(아래)](../images/dq5-text-0129.webp)

글자 986자를 128자씩 그려 읽고, 이름 입력용 글자 목록인 메시지 `061` 을 찾아 가나의 순서를 맞췄습니다.
모양이 같은 쌍은 문맥으로 갈랐습니다. 예를 들어 「どれいの日ゥ」「代ゥ　王」으로 나오던 글자는 々였고, 「ゴ～ルド」의 글자는 장음 ー였습니다.

## 4. 대화 번호에서 메시지까지

다음은 선실의 파파스(대화 번호 `012`)에게 말을 걸었습니다. 메시지는 0x742「パパス「父さんは　ここにいるから…」였는데 `012` 와 숫자가 이어지지 않습니다.
인물 표의 대화 번호(`7E:36E0`·`7E:3700`)를 읽는 곳을 `rwatch.lua` 로 잡으니 `06:AF6D` 였고, 리스팅을 따라가니 대화 번호로 갈래를 나누고
`011`~`24E` 는 `06:AEF8` 표의 32개 묶음에서 스크립트를 건너뛰어 찾고 있었습니다. 스크립트 바이트 `41 2D` 가 메시지 `0x12D + 0x615 = 0x742` 였습니다.

스크립트는 작은 바이트코드입니다. 파파스의 스크립트는 「`7E:2191` 플래그가 켜져 있으면 『港に着いたか！』 와 함께 `7E:2192` 를 켜고, 아니면 『父さんは　ここにいるから』」 입니다.
`7E:2192 & 80` 은 17/00 에 인물을 놓지 않는 플래그라, 배가 항구에 닿은 뒤 말을 걸면 파파스가 선실에서 사라지게 됩니다.

## 5. 스크립트 경계와 실측

스크립트 574개를 실행기(`06:B065`) 길이로 읽은 끝이, 게임이 번호로 스크립트를 찾을 때 쓰는 건너뛰기 규칙(`06:AFA9`)의 다음 시작과 같은지 검사했습니다.

```
scripts 574, mismatch 0
```

갈래마다 실제로 확인하려고, 파파스 슬롯의 대화 번호를 `POKE` 로 바꿔 말을 걸었습니다.

| 대화 번호 | 예측 | 게임의 첫 메시지 |
| --- | --- | --- |
| `012`(원래 값) | 스크립트 → 742 | 742 |
| `02A` | 스크립트 → 77D「おうおう　小さいのに教会に…」 | 77D |
| `0F3` | 스크립트 → 9F4(조건 셋을 거친 마지막 갈래) | 9F4 |
| `199` | 스크립트 → 9BF「ようこそ…女王　アイシスです」 | 9BF |
| `26D` | 직접 메시지 26D + 3C6 = 633 | 633 |
| `4BE` | 직접 메시지 884「返事がない……」 | 884 |

01/02 에 순간이동해 진짜 시체 인물(`4BE`)에게 말을 걸어 보려 했지만, 이 시점에는 그 맵에 인물이 놓이지 않아 「誰もいない」만 나왔습니다. 그래서 슬롯 값을 바꾸는 방법을 썼습니다.

## 틀렸던 것들

- 대화 스크립트의 `07`(조건)은 늘 `06` 블록이 따라온다: 분기는 `06` 이 없으면 명령 하나다. 그렇게 읽자 444개 실패가 16개로 줄었다.
- 건너뛰기 규칙에서 `00` 은 1바이트: `06:AFD8` 이 0 이면 2바이트를 더 건너뛴다. 이것을 빼먹어 16개가 어긋났고, 대화 번호 `02A` 가 엉뚱한 메시지(638)를 가리켰다.
- 남은 16개는 네이티브 호출 뒤의 숨은 바이트로 보았다: 위 `00` 규칙을 고치니 모두 맞았다.
- `CHARS` 를 16자 문자열의 튜플로 썼는데 파이썬이 이어 붙여 문자열 하나가 되었다. 색인을 바로 쓰게 고쳤다.
