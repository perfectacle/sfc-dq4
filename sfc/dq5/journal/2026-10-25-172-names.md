# 2026-10-25-172: 동료 몬스터 이름 후보와 고르는 규칙

일행 관리 체계의 첫 조각으로 동료 몬스터 이름이 어디서 오고 어떻게 정해지는지 풀었습니다. 결과는 [dq5-data-format.md 「일행 관리」](../docs/dq5-data-format.md#일행-관리)에 있습니다.

## 1. 이름 표 0A

`dq5text.py` 의 문자열 표를 0번부터 훑으니 표 `0A` 가 ボロンゴ·プックル·チロル·ゲレゲレ 로 시작해, 넷씩 スラリン·スラぼう·アキーラ·サスケ, ドラきち·ラッキー·まなぶ·ミワリン … 으로 이어졌습니다.
`dq5monster.py --companions` 의 종류 순서(01 キラーパンサー, 02 スライム, 03 ドラキー …)와 맞춰 보면 종류 × 4 칸부터 넷이 그 종류의 이름이고, 41종 × 4 = 164칸 뒤로는 사람 이름(ビアンカ…)과 몬스터 이름 표가 이어집니다.

## 2. 레코드의 이름 번호

동료 조건 검사를 끄고(`ROMPATCH=100000=01`, `20:8000` bit0) 동료 확률 표 `27:8162`~`8191` 을 모두 `0001` 로 덮은 뒤, 필드에서 スライム 한 마리와 싸워 이기고 A 를 눌러 들였습니다.
`7E:29EC`(スライム 의 들인 비트)를 `SET` 으로 바꿔 가며 새 레코드(`7E:2094`)를 보니 `+0` = `82`(종류 2) 는 그대로이고 `+1` 만 `80`·`81`·`82` 로 달라졌습니다.

| `29EC` 전 → 후 | `+1` |
| --- | --- |
| `00` → `01` | `80` |
| `01` → `03` | `81` |
| `02` → `03` | `80` |
| `03` → `07` | `82` |
| `05` → `07` | `81` |
| `06` → `07` | `80` |
| `07` | 들지 않음 |

이름 번호는 켜진 비트 수가 아니라 처음 꺼진 비트입니다(`02` 면 0, `05` 면 1). `dq5warp.lua` 의 `PARTY=02` 로 スライム 동료를 두고 `+1` 을 `80`~`83` 으로 고정해 전투에 들어가자 전투 창 이름이 スラリン·スラぼう·アキーラ·サスケ 였습니다.

## 3. 셋까지

`20:C25A` 가 `27:8153[비트 4개]`(= 켜진 비트 수, `00 01 01 02 …`)로 확률 표를 고르고 3 이상이면 들이지 않습니다. 그래서 같은 종류는 셋까지이고, 넷째 이름은 보통 들이기로는 붙지 않습니다(코드 읽기).
