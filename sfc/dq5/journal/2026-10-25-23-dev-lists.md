# 2026-10-25-23: 01:8001 목적지 목록, 전투 곡, 무리 플래그 bit4·6, 미니게임 감시

[앞 일지](2026-10-25-18-debug-switch.md)에서 남긴 것을 이어 보았습니다. `01:8001` 을 읽는 나머지 11곳, `7E:2CD0` 이 전투 곡인지, 무리 플래그 bit4·6·7, 격투장 숫자 입력의 범위입니다. 롬 밖 뱅크 감시도 슬라임 레이스·격투장·탈것 장면으로 넓혔습니다.

## 1. `01:8001` 은 목적지 목록을 고른다

11곳을 하나씩 디스어셈블했습니다. 셋을 보면 성격이 드러납니다.

```
04:B8A4  LDA $018001 / BEQ / LDA #$0B / BRA / LDA #$07 / STA $43   ; 이름 표 번호
25:82AA  LDA $018001 / BEQ / LDA $2585D5,X / BRA / LDA $2585EB,X
23:E453  ... CMP $2585D5,X ... CPX #$11      /    ... CMP $2585EB,X ... CPX #$36
```

이름 문자열 루틴 `21:955D` 의 표 주소 목록(`21:959B`)을 덤프하니 표 `0B` 는 `23:D5F3`(ラインハット·オラクルベリー·しゅうどういん … 마을 이름)이고, 표 7 은 `30:8000` 이었습니다. 디버그 입구 `2B:848A` 처럼 롬 밖 뱅크 `30` 입니다.
`25:85D5` 는 22개, `25:85EB` 는 54개 목록인데 앞 22개가 같고 뒤로 맵 그룹 `17`·`03`·`04`·`25` … 가 이어집니다. 맵 그룹 수가 54개입니다.
`04:B88A` 는 `BRK 88 4D` 로 고른 번호를 이 이름 표로 바꿔 창에 쓰는 곳이고, `BRK 88` 점프 표에서 `4C`·`4D` 는 `21:9DEB`·`21:9E2C` 였습니다. 팔리는 롬은 목적지 24개 중 플래그가 켜진 것만 세고, `00` 이면 플래그 없이 고정 비트 표 `21:9E82` 를 씁니다.

ルーラ·キメラのつばさ 의 목적지 목록으로 보입니다. 개발용 롬에서는 맵 그룹 54개가 모두 목적지였고 이름은 확장 롬에 있었던 것으로 보입니다.

실측도 해 보았습니다. 일행 레코드 첫 칸(`7E:2056`)에 キメラのつばさ(`A4`)를 넣고 필드에서 どうぐ → つかう 했습니다. `probe/trace.lua` 로 11곳을 감시하니 `01:8001` 이 `FF` 든 `00` 이든 `23:E453`(A = `01`)과 `1E:E553`(A = `00`)이 돌았고, 화면은 둘 다 「キメラのつばさを ほうり投げた！」 뒤 날아올랐다가 제자리에 내렸습니다.
마을을 하나도 들르지 않은 세이브스테이트라 목록 차이는 드러나지 않았습니다.

## 2. `7E:2CD0` 은 전투 곡

`7E:2CD0` 을 넘기는 `24:FEAC` 를 감시하니 전투 시작 때 `17`·`16`·`18` 이 한 번, 전투 중에는 `32`~`37` 이 여러 번 불렸습니다. 같은 함수가 효과음에도 쓰입니다.
곡인지 가리려고 SPC RAM 을 비교했습니다. 무리 `20` 을 부르면서 `26:8F96` 의 값만 바꾸고, 700프레임(전투 중)에 SPC RAM 64KB 를 덤프했습니다.

| 비교 | 다른 바이트 |
| --- | --- |
| `16` 과 `16`(같은 실행 두 번) | 0 |
| `16` 과 `17` | 25,336 |
| `16` 과 `18` | 27,883 |
| `17` 과 `18` | 27,865 |

몬스터와 화면이 같고 이 바이트 하나만 다른데 SPC RAM 의 40% 가까이가 달라집니다. 효과음 하나로는 이렇게 바뀌지 않으니 곡 데이터를 바꿔 올린 것입니다.

## 3. 무리 플래그 bit4·6·7

**bit4** — 무리 `01`(첫 필드 이벤트, 플래그 `D0`)의 사건 루틴 `20:E1BD` 는 `$101A` 가 1 일 때 `20:E1C4` 부터 돕니다. 플래그를 `C0` 으로 바꿔 비교했습니다.

| 플래그 | `20:E1C4` | 화면 |
| --- | --- | --- |
| `D0` | 1647프레임에 실행 | 「なんと パパスが たすけにきた！」, 그 뒤 상태 창에 パパス H410 |
| `C0` | 실행 안 됨 | 혼자 계속 싸움 |

`$101A` 는 판 수로 보입니다(첫 판 0, 둘째 판 1).

**bit6** — 도망치기 코드 `20:961E` 가 `BIT $1015 / BVS 20:966E` 로 시작합니다. 무리 `00`(スライム 1)에서 `SETTLE` 을 300~355 로 바꿔 난수를 달리하며 にげる 를 여섯 번씩 골랐습니다.

| 플래그 | 도망침 / 실패 |
| --- | --- |
| `00` | 3 / 3 |
| `80` | 3 / 3 |
| `40` | 0 / 6(모두 「しかし まわりこまれてしまった！」) |

도망친 판은 필드로 돌아와 파파스가 「大丈夫か？」 하고 말을 거는 것까지 보았습니다. 보스 무리 대부분이 `C0` 이라 앞 일지에서 メタルスライム 무리(`3D`, `C0`)로 해 본 도망치기가 여섯 번 모두 실패했던 것도 이것 때문입니다.

**bit7** — 도망치기에서는 `00` 과 차이가 없었습니다. 코드로는 선제·기습 판정을 건너뜁니다.

## 4. 무리를 부르는 곳의 나머지

상자 몬스터 `0C`·`0E`·`0F` 는 `12:F4A4` 의 `JSL $01868B` 로 `BRA` 해 오는 `LDA #imm` 이었습니다. 「호출 바로 앞 즉값」만 보던 검색이 놓친 것입니다([dq5-map-format.md](../docs/dq5-map-format.md)에 이미 실측이 있음).
무리 번호 `$100D` 를 쓰는 명령은 롬 전체에서 `26:8E0C` 하나뿐이고, 그 앞 입구 넷을 부르는 곳은 모두 즉값이었습니다. `00`·`29`·`30`~`3F` 는 끝내 찾지 못했습니다.
격투장(`06:F2CA`)은 A = 0 으로 `26:8F43` 만 불러, 곡을 무리 `00` 의 bit0-1 로 고릅니다.

## 5. 격투장 숫자 입력의 범위

`26:8E8E` 이후를 읽으면 입력 값 `$0F28` 이 `#$33` 이상이면 다시 묻고, 번호 - 1 로 8바이트 레코드를 찾습니다. 숫자 창은 위·아래로 자리 값을, 왼쪽·오른쪽으로 자리를 옮깁니다.

| 입력 | 결과 |
| --- | --- |
| 50 | 「バルーン ＊2.7 / ドラゴンマッド ＊2.7 / メッサーラ ＊17.2 / ダークマンモス ＊4.1」 |
| 51 | 입력 창이 다시 뜸 |
| 0 | A 를 눌러도 넘어가지 않음 |

## 6. 미니게임·탈것 장면의 롬 밖 뱅크 감시

슬라임 레이스는 코인이 없으면 바로 끝나서, 코인 검사(`06:F210` 의 `BNE`)를 `BRA` 로 바꿨습니다(`ROMPATCH=37210=80`). 그러자 규칙 설명 뒤 레이스 화면이 떴고, 입력을 넣자 슬라임들이 달렸습니다.
탈것은 `$1954` 를 `walk.lua` 의 `POKE` 로 고정했습니다. `03` 이면 물 위를, `82` 면 바다 위를 걸었습니다(주인공 그림은 그대로).

| 장면 | 프레임 | 뱅크 `30` 이상 실행 |
| --- | --- | --- |
| 슬라임 레이스(설명, 배당 창, 달리기) | 2,950 | 0 |
| 격투장(배당 창, 코인 없음) | 1,190 | 0 |
| `$1954` = `03` 필드 걷기 | 2,590 | 0 |
| `$1954` = `82` 필드 걷기 | 2,590 | 0 |

## 틀렸던 것들

- 앞 일지에서 bit5 를 「도망칠 수 없음」으로 적었습니다. 실제로는 「たたかう·にげる」 창을 건너뛰는 것이고, 도망치기가 늘 실패하게 하는 것은 bit6 입니다.
- `26:8F96` 의 파일 오프셋을 처음에 `134F97` 로 잘못 셈해 롬의 엉뚱한 곳을 덮었습니다. 뱅크 `26` 의 `8F97` 은 `130F97` 입니다.
