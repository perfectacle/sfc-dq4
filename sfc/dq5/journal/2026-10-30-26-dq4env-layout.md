# 2026-10-30-26: dq4 환경 맵의 새 배치에서 문 표 패치와 함께 쓰기를 다시 재기

dq4 트랙이 바꾼 맵의 문 물체 항목을 뱅크 01 끝에서 뱅크 `3D` 로 옮겼습니다([dq4 형식 문서 「물체 항목 뱅크」](../../dq4/docs/dq4-environment-format.md#물체-항목-뱅크)). 뱅크 01 끝에는 중계 코드 24바이트만 남고, `01:F42D` 훅이 바꾼 맵에서 DB 를 `3D` 로 바꿉니다. [앞 일지](2026-10-29-02-lowfix.md)는 항목이 뱅크 01 끝에 있을 때 쟀으므로, 문 표 패치(`--door-bank`)를 만드는 순서가 아직 필요한지와 어느 뱅크가 비는지를 다시 보았습니다. 결과는 [쓰기 형식 「dq4 환경 맵과 함께 쓰기」](../docs/dq5-build-format.md#dq4-환경-맵과-함께-쓰기)에 넣었습니다.

## 1. 코드에서 본 것

`dq4environmentrom.py` 의 `obj` 루틴은 바꾼 맵을 찾으면 스택에 둔 Y 를 항목 주소 − `D2FC` 로 덮고 `SEP #$20 / LDA #$3D / PHA / PLB` 를 합니다. 그래서 바꾼 맵의 항목과 표(`3D:FD97`~`FEB6` 복사)는 문 표 복사본이 아니라 `3D` 에서 읽힐 것입니다. 뱅크 01 끝에 남은 것은 `JSL` 중계 코드뿐이라 DB 로 읽힐 자료가 없습니다. 그렇다면 문 표 패치를 원래 롬에서 만들어도 게임은 같아야 합니다. 다만 `dq5newmap.py check` 는 복사본의 `F037`~`FFFF` 를 뱅크 01 과 견주므로, 훅 `01:F42D` 와 중계 코드가 다른 것으로 여전히 거부할 것입니다.

## 2. 롬 만들기

원래 롬에서 dq4 패치를 새로 만들고(`bank01_bytes` 24), 그 위에 1A/05(1A/00 복사)를 더하는 문 표 패치를 만들었습니다.

```sh
uv run --locked python sfc/dq4/tools/dq4environmentrom.py --out work/dq4env/env
uv run --locked python sfc/dq5/tools/dq5build.py rom/dq5.sfc build work/dq4env/env/dq4-environment.dq5patch.json --size 4 -o work/dq4env/env.sfc
uv run --locked python sfc/dq5/tools/dq5newmap.py work/dq4env/env.sfc patch work/dq4env/doors.json -o work/dq4env/doors-env.dq5patch.json --door-bank 3C
uv run --locked python sfc/dq5/tools/dq5newmap.py rom/dq5.sfc patch work/dq4env/doors.json -o work/dq4env/doors-orig.dq5patch.json --door-bank 3C
```

`both` 는 원래 롬에 dq4 패치와 `doors-env` 를, `wrong` 은 dq4 패치와 `doors-orig` 를 함께 빌드한 것입니다. 그룹 빌드(`dq4groupbuild.py`, `--door-bank 3B`)도 새로 만들었습니다.

```
check both:  … 쓰기 0개 검사 통과
check wrong: 오류: 뱅크 3C 복사본의 F42D 가 뱅크 01 과 다름(…)
--door-bank 3D:            오류: --door-bank 3D: 뱅크 01 을 복사할 뱅크가 비어 있지 않음
--door-stub-at 01:FED0:    오류: --door-stub-at 01:FED0: 문 표 뱅크 밖의 빈 자리 68바이트가 필요함
```

dq4 패치가 쓰는 뱅크는 `3D`·`3E`·`3F`·`40`·`41` 이라 문 표 뱅크로 고를 수 있는 것은 그대로 `30`~`3C` 입니다.

## 3. MesenCE 로 돌려 보기

`--testrunner` 로만 돌렸습니다. 장면은 `dq5exitcheck.lua` 에 `dq5newmapcheck.py` 의 문 장면 입력을 넣었고, 읽기 감시는 장면마다 한 구간씩 걸었습니다.

- `dq4environmentromcheck.py --rom groups.sfc`: 통과했습니다. 바꾼 맵 68곳 픽셀 차이 0, 걷는 층 불일치 0, 문 물체 56/56, 성문을 열린 채로 지나 성 안으로 들어갔고, 대조 맵과 바꾸지 않은 다섯 맵의 셀 버퍼가 원본과 같았습니다.
- 바꾼 맵 0A/01 의 문 (42,33) 아래 (42,36) 에서 위로 걸으면 `env`·`both`·`wrong` 모두 셀 `01 91 E0 04 00 10 38 3B` 에 막혔습니다. 순서를 거꾸로 한 `wrong` 도 문이 있습니다. 옛 배치의 `wrong` 은 문 물체가 없어 걸어 들어갔습니다.
- 같은 문에 이벤트 `C4 2A 21 02` 를 걸자 세 롬 모두 `7E:21C2` 가 `04` 가 되고 셀이 `00 31 E0 04 00 00 00 00` 으로 바뀌어 (42,34) 까지 걸어 들어갔습니다. dq4 문서가 바꾼 맵에서 재지 않은 길로 남긴 문 이벤트 입구(`01:D915`)입니다.
- `both` 의 이 장면에서 `3D:FD97`~`FEB6` 은 72번(처음 `01:F499`) 읽혔고, `3C:FD97`~`FEB6`·`01:FD97`~`FEB6`·`01:FED0`~`FFFF`·`3C:E000`~`FFFF` 는 0번이었습니다. `3C:D2FC`~`D8C1` 은 509번으로, 훅 앞에서 맵 번호까지 건너뛰는 읽기(처음 `01:F416`)입니다. `wrong` 도 `3C:E000`~`FFFF` 0번입니다. 옛 배치에서는 336번이었습니다.
- 그룹 빌드 37/00 의 문 (42,37) 도 막혔고(`01 91 E8 18 00 10 38 3B`), 표는 `3D` 에서 39번, `3B`·`01` 에서 0번 읽혔습니다.
- 바꾸지 않은 맵의 문 장면 여덟(01/04 잠긴 문·열쇠, 01/00 성문 그대로·열기·닫기, 1A/00 종류 3F·19/00 종류 40 열기, 01/03 방 문)은 `both`·`wrong`·`group` 모두 원본과 셀·메시지가 같았고 옛 문 표 읽기는 0번이었습니다. `both` 에서 표는 `3C` 에서만 읽혔습니다(26~117번, `3D` 0번).

## 틀렸던 것들

- `dq4environmentromcheck.py` 를 dq4 패치만 넣은 롬에 돌리려 했습니다. 이 검사는 지금 새 그룹 맵(36/00 등)까지 보므로 그룹 빌드 롬이어야 합니다. `LIBDIR` 이 없으면 MesenCE 가 조용히 끝나 `warp.txt` 가 없다는 오류만 납니다.
- 바꾼 맵에서 とびら 로 문을 열려고 `dq5newmapcheck.py` 의 명령 창 입력을 그대로 썼습니다. 0A/01·37/00 에서는 A 를 누르자 명령 창 대신 「めいれいさせろ」 창이 떠 とびら 를 고르지 못했습니다. 그래서 문 이벤트로 열었습니다.

## 남은 것

- 바꾼 맵에서 とびら·どうぐ 열쇠로 여는 장면(입구 `01:D8C2`·`01:D97B`)은 이번에 재지 못했습니다. dq4 트랙의 とびら 실측([일지](../../dq4/journal/2026-10-30-28-door-bank.md))이 있습니다.
- `check` 가 거꾸로 만든 순서를 거부하는 것은 복사본에서 실행되지 않는 바이트 때문입니다. 실행되지 않는 구간을 견주기에서 뺄지는 정하지 않았습니다.
