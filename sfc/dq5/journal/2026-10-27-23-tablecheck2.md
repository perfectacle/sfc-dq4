# 2026-10-27-23: 표 쓰기의 남은 물건 플래그·주문·동료 필드 실측

[앞 일지](2026-10-27-06-tablecheck.md)에서 남긴 `dq5tables.py` 의 필드를 고친 롬으로 게임에서 확인했습니다. 대상은 물건 플래그, 주문 `범위`·`적쪽`, 동료 `최대레벨`·`장비갈래` 입니다. 물건 필드 셋은 게임에서 볼 수 없었고, 그 까닭을 함께 적었습니다. 결과는 [쓰기 형식](../docs/dq5-build-format.md#게임-데이터-표-dq5tables1)에 있습니다.

## 1. 무엇을 보면 갈리는가

물건 플래그의 뜻은 [물건 표](../docs/dq5-data-format.md#물건-표-23b081)에서 롬 바이트를 직접 고쳐 확인해 두었습니다. 이번에는 같은 장면을 원래 롬과 고친 롬으로 돌려, 로그로 남길 수 있는 값이 갈리는지를 봅니다. 화면 차이만으로는 도구가 단언할 수 없으므로 메시지 번호와 창 번호를 기록했습니다.

- 메시지: 보행 모드는 `24:8BAF`, 전투 모드는 `24:8C39` 의 A
- 창: 창을 여는 `04:9C52` 의 A. 창 레코드 주소라서 `04:EB48[창]` 으로 번호를 되찾습니다(`38` = `F197`, `4A` = `F2F6`, `4C` = `F314`, `4F` = `F337`, `6F` = `F99D`)
- 전투 대상: 주인공의 대상 바이트 `7E:1037`(bit7 이 켜지면 적 쪽. 이번 실행에서 우리 편 주인공은 `01`·`03`, 적 슬라임은 `81`·`83` 이었고 아래 비트의 뜻은 보지 않음)

## 2. 장면 만들기

선실 세이브스테이트의 명령 창은 はなす·じゅもん / つよさ·どうぐ / そうび·さくせん / とびら·しらべる 순서입니다. 아래 장면들은 이 창에서 시작합니다.

| 장면 | 준비 | 고친 필드 |
| --- | --- | --- |
| 필드 どうぐ → やくそう → つかう | 가진 물건 셋째 칸에 やくそう, HP 5 | `쓰면없어짐`·`사용메시지없음` |
| 같은 장면, 일행 둘 | 일행 레코드 1 에 들인 슬라임 레코드를 그대로 씀 | `필드대상창` |
| 무기점 うりにきた → やくそう | 상점 검사와 같은 선실 장면 | `팔수없음` |
| 무기점 かいにきた → どうのつるぎ | 소지금을 넉넉히 | `상점전투설명` |
| 일행 둘인 무기점 비교 창 | 위 슬라임 레코드 | 동료 `장비갈래`, 물건 `장비몬스터` |
| 필드 そうび | 없음 | `저주` |
| 필드 じゅもん → インパス → やくそう | 주인공 필드 주문 칸 0~7 을 모두 켬 | インパス 다섯 필드 |
| 전투 どうぐ → やくそう | 첫 필드 이벤트 전투(슬라임 하나) | 물건 `적쪽`·`전투대상창` |
| 전투 じゅもん → メラ | 주인공 전투 주문 칸 8 을 メラ 로 | 주문 `범위`·`적쪽` |
| 전투 뒤 떨어뜨리기 | 가진 물건 12칸을 채우고 `20:8000` bit5 로 확률을 건너뜀 | `가득창` |
| 슬라임을 들이고 다음 전투 | 들인 슬라임의 다음 레벨 경험치를 1 로 붙잡음 | 동료 `최대레벨` |

## 3. 결과

```text
쓰면없어짐 1 → 0       1A2·18F 뒤 가진 물건에서 빠짐 → 남음
사용메시지없음 0 → 1   1A2·18F → 18F 만
필드대상창 1 → 0       일행 둘: 창 38 → 창 없이 1A2
팔수없음 0 → 1         052「やくそうかい。」 → 056「…そいつは 引き取れないな。」
가득창 0 → 1           사람 고르기 창 4F → 6F
상점전투설명 0 → 1     036「これは 戦いのときに 道具として 使っても 効力が あるぜ！」 이 더 나옴
저주 0 → 1             25:FD00 을 부르지 않음 → A = 23 으로 부름
물건 적쪽 0 → 1        창 4A·대상 03 → 창 4C·대상 83
전투대상창 1 → 0       창 4A → 창 없음
インパス              451·49A·457·45F 에서 설명 49B, 종류 456 더함, 가격줄 45F 빠짐, 횟수줄 457 빠짐, 장비줄 45E 더함
주문 범위 1 → 3        창 4C → 창 없이 슬라임이 맞음
주문 적쪽 1 → 0        창 4C·대상 81·069 → 창 4A·대상 01·06A(주인공이 맞음)
최대레벨 99 → 1        다음 전투 뒤 슬라임 레벨 2 → 1, 레벨업 메시지 0BF 두 번 → 한 번
장비갈래 1 → 5         スラリン AND 0000 → 0400, 「そうびできない」 → 「8▶ 21」
장비몬스터 0529 → 4529 スラリン AND 0000 → 4000, 같은 화면 변화
```

무기점의 설명은 형식 문서에 적힌 `034`「…効力のある 品物ですよ！」 가 아니라 `036`「…効力が あるぜ！」 였습니다. 글은 같고 끝맺음만 무기점 주인의 말투입니다.

`dq5tablecheck.py` 가 앞 일지의 장면을 포함해 39회 실행하고 위의 메시지·창·대상·읽기 값·레벨과 레벨업 메시지 수를 단언합니다. 화면 문구와 そうび 에서 무기 칸에 머무는 것은 화면을 눈으로 견줬습니다.

```sh
MESENCE=… uv run --locked python sfc/dq5/tools/dq5tablecheck.py rom/dq5.sfc \
  --state work/state/ship.mss --out work/tablecheck
```

```text
39회 실행, 수정 24건(표 4종) 게임 검사 통과
```

## 4. 볼 수 없었던 필드

- `k1b2`: 읽는 루틴 `21:A4DD` 는 `BRK #94 07` 로만 갑니다. 롬에서 그 바이트가 있는 곳은 코드가 아닌 `11:D137` 하나이고, 직접 부르는 곳도 없습니다(정적 검색). 게임에서 이 비트를 읽는 길을 찾지 못했으므로 무엇을 볼지 없습니다.
- `k4하위`: `BRK #94 15` 로 읽히지만 부르는 곳의 뜻을 모릅니다. 무엇을 봐야 갈리는지 정하지 못했습니다.
- `그룹무작위`: 적 그룹을 고른 뒤 살아 있는 한 마리를 난수로 고르는 갈래(`20:A917`)입니다. 한 마리 무리에서는 원래 롬도 같은 대상이고, 여러 마리 무리에서는 원래 롬도 난수로 대상이 바뀌어 이번처럼 한 번씩 돌려서는 견줄 수 없습니다. 이 비트를 가진 물건을 슬라임 셋 무리에 기다리는 프레임을 바꿔 여러 번 쓰거나 난수를 고정하면, 대상이 늘 같은지와 바뀌는지로 견줄 수 있습니다. 아직 하지 않았습니다.

## 틀렸던 것들

물건 목록의 커서는 선실 세이브스테이트에서 셋째 칸에 있었습니다. 처음에는 아래를 두 번 눌러 셋째 칸으로 가려 했는데, 커서가 한 바퀴 돌아 ひのきのぼう 를 「道具として 使ってみた」 로 썼습니다. 아래 입력을 빼고 바로 고르게 했습니다.

장비몬스터 실측에서 `23:B676` 위 바이트를 읽는 것을 단언하려 했습니다. 그런데 `21:A594` 는 16비트로 읽어서 MesenCE 읽기 콜백에는 낮은 바이트 주소 `23:B675` 만 잡혔습니다. 그래서 읽은 곳과 AND 결과를 단언했습니다.

## 남은 것

`k4하위` 의 뜻, 그리고 `그룹무작위` 를 난수를 고정한 장면에서 견주는 일이 남았습니다. 상점 설명 메시지가 `034`·`036` 중 어느 것인지 가게 종류로 갈리는지도 보지 않았습니다.
