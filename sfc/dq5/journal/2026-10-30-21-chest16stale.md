# 2026-10-30-21: 잠긴 상자·가득 찬 가방 뒤 남은 마스크를 게임 검사로

[상자 번호 16비트 훅의 남은 마스크 일지](2026-10-30-19-chest16fix.md)에서 잠긴 상자와, 물건이 가득해 버리기를 거절한 상자가 `12:F839` 를 지나지 않고 넘길 마스크 칸 `7E:291B` 를 남기는 것을 일회용 스크립트로 쟀습니다. 이번에는 그 둘을 `dq5chestcheck.py` 의 사례 `widelock_open`·`widefull_open` 으로 옮겨 누구나 다시 돌릴 수 있게 하고, 다음 열기가 그 마스크를 지우는 것까지 게임에서 봤습니다. 결과는 [쓰기 형식 「상자 257개 이상」](../docs/dq5-build-format.md#상자-257개-이상---wide-at)의 표에 넣었습니다.

## 1. 다음 상자로 걸어가기

처음에는 상자 300 을 열고 왼쪽의 상자 299(19/00 의 (6,45))로 걸어가 열 생각이었습니다. 299 의 비트 `28F8 & 10` 을 미리 켜 두면 열기 훅이 「이미 열림」 갈래로 가므로, 끝에 `291B` 가 `00` 이면 훅 첫머리가 지운 것입니다.

그런데 `left`·`down`·`right` 를 몇 번 눌러도 `7E:3020`·`3080` 은 `11,46` 그대로였습니다. 장면 그림을 보니 (11,46) 은 가게 계산대 안의 한 칸이라, 왼쪽은 가게 주인, 아래는 계산대, 오른쪽은 벽입니다. 위의 상자 300 말고는 닿는 상자가 없습니다.

## 2. 같은 상자를 두 번 열기

그래서 상자 300 을 두 번 엽니다. 두 번째 열기도 상자 300 이라 훅이 다시 `291B` 에 `08` 을 두므로, 끝의 WRAM 만으로는 지웠는지 알 수 없습니다. `lua/dq5chestcheck.lua` 에 실행 기록 둘을 더했습니다.

- `open`: `12:E66F`(훅이면 그 `JML`)에 들어올 때의 `291B`.
- `count`: 맵 안 순서를 세는 `2A:F224` 를 부를 때의 `291B`. 훅은 `291B` 를 지운 뒤에 이것을 부릅니다.

가방이 가득한 경우는 장면을 만들 때 `7E:2056`~`2061` 을 `A1` 로 채웁니다. 버리기 물음(메시지 13D)에서 A 를 누르면 버릴 물건을 고르는 13F 로 가고, B 를 누르면 いいえ 로 14B 가 나왔습니다. 그래서 한 번 열 때의 입력은 기존 입력 뒤에 `wait:60,b:4,wait:300,b:4,wait:200` 을 붙였습니다.

```
widelock_open  open pend=00 → count pend=00 → 142·14E
               open pend=08 → count pend=00 → 142·14E                     set 없음, 끝 28F8=00 291B=08
widefull_open  open pend=00 → count pend=00 → 131 reward 0033 12E·14A·13D·14B
               open pend=08 → count pend=00 → 131 reward 0033 12E·14A·13D·14B  set 없음, 끝 28F8=00 291B=08
```

두 사례 모두 `12:F839` 에 한 번도 들어가지 않았고, 첫째가 남긴 `08` 을 둘째 열기가 `2A:F224` 앞에서 `00` 으로 지웠습니다. 열기 훅 첫머리의 `SEP #$20 / LDA #$00 / STA $7E291B` 를 빼고 다시 돌리면 `widelock_open` 이 `2A:F224 를 부를 때의 291B ['00', '08']` 로 실패했습니다.

```
dq5chestcheck.py rom/dq5.sfc --state work/state/ship.mss --case wide_open --case wide_alias --case wide_entry \
  --case wide_save --case wideitem_open --case widelock_open --case widefull_open --case chest
5쌍/10실행 통과: …, 기록·불러오기 1실행 통과, 넘길 마스크 지우기 2실행 통과
```

`open`·`count` 줄은 `value=` 를 담지 않아, 보상·메시지만 보는 기존 사례는 그대로 통과했습니다.

## 3. 해석기 테스트

`test_dq5chestwide.py` 에 셋을 더했습니다.

- 켜기 훅: `$1E80` = `27`(`28F3`~`291A` 의 마지막 바이트)·`291B` = `08` 이면 `291A` 에 `08` 을 켜고 `291B` 를 지웁니다.
- 열기 훅: 표에 없는 맵(05/00)으로 `12:E669` 에 돌아갈 때도 `291B` 를 지웁니다.
- `check`: 패치가 훅을 `--wide-at` 보다 `800` 뒤에 두게 바꾸면(그 자리에도 훅이 온전히 있어 `locate` 는 지남) 「`--wide-at` 자리를 가리키지 않음」 으로 거부합니다. 바꾸지 않으면 통과합니다.
