# 2026-10-29-01: 필드 그림 늘리기(세계마다 타일 벌·움직이는 타일 16벌·낮밤 인물 팔레트)와 그룹 50 이상 맵 18개 실측

[필드 그림 쓰기](2026-10-27-57-fieldgfx.md)가 남긴 것 셋을 했습니다. `dq5fieldgfxwrite.py` 로 세계 1·2 에 따로 타일 512개와 니블 표를 줄 수 있고, 움직이는 타일을 1·2·4·8·16벌로 바꿀 수 있고, 세계 0 의 낮밤 인물 팔레트(`01:A45E`·`A422`)를 쓸 수 있습니다. 그룹 50 이상 맵은 50/50 하나만 보던 것을 18개 모두로 넓혔습니다. 형식은 [필드 그림 쓰기](../docs/dq5-build-format.md#필드-그림-dq5fieldgfx1)와 [필드 형식](../docs/dq5-field-format.md#타일-그래픽과-팔레트)에 있습니다.

## 1. 움직이는 타일 벌을 어디에 둘 수 있나

벌을 넘기는 `02:AC98` 을 읽으면, `$1C31` 로 `02:AD89` 의 WRAM 주소 표(`C800`, `C8C0`, … `CD40`)를 골라 `$1C13` 에 두고 `AND #$07` 로 돕니다. 벌을 늘리려면 표와 `AND` 를 바꾸고, `7E:C800` 뒤에 벌을 더 풀 자리가 있어야 합니다.

`7E:C000`~`FFFF` 는 필드에 들어갈 때 타일 평면을 푸는 자리라 쓰는 곳이 많아 보였습니다. 그래서 `7E:C000`~`DFFF` 에 읽기·쓰기 콜백을 걸고, (341,56) 에서 이리저리 걷고 메뉴를 여닫았습니다.

```
w pc=01A6A0 / 01A681   first=439   타일 RLE 풀기(C000~DFFF)
r pc=01A4D3 … 01A53C   first=441   평면을 VRAM 에 올림(C000~DFFF)
w pc=01C7AC·01C7B5     first=457   돌린 타일(C000~C7FF)
w pc=2B8063·2B8082     first=459   움직이는 타일 벌(C800~CDFF, 1,536바이트)
r pc=008F75            first=493   DMA(C000~CDFF)
```

올린 뒤로 `7E:CE00`~`DFFF` 를 건드린 코드는 없었습니다. 벌 하나가 192바이트라 16벌이면 `D3FF` 까지입니다. 벌 수는 `AND` 로 돌므로 2의 거듭제곱만 받고, 벌 주소 표는 옮긴 RLE 바로 뒤에 둡니다. `02:ACD5`·`02:ACDC` 의 `LDA $02AD89,X`·`LDA $02AD8A,X` 는 긴 주소라 표를 늘린 뱅크에 두어도 됩니다. 1·2·4벌로 줄일 때는 원래 표의 앞 칸이 그대로 맞아 `AND` 만 바꾸고, RLE 가 원래 자리에 들어가면 옮기지 않습니다.

## 2. 세계마다 타일 벌

타일은 `01:A4A7` 의 `LDA #$12 … LDX #$B1A8` 하나로 정해져 세 세계가 같은 512개를 씁니다. 니블 표(`2A:D712`)도 하나이고, 타일맵 워드를 만드는 `00:BBAC` 의 네 곳이 긴 주소로 읽습니다. 둘 다 `JSL` 훅으로 바꾸었습니다.

- 불러오기 훅은 `$1949 & 3` 으로 `[주소][뱅크]` 표를 고르고, 원래 코드처럼 `$4374`·DB·X 를 둡니다. 풀기 루틴(`01:A64F`)이 DB 를 자료 뱅크로 두고 DMA 레지스터를 절대 주소로 쓰므로 세계 RLE 도 `30`~`3F` 에 둡니다.
- 니블 훅은 X 를 지키고 `표 + 세계 × 256 + X` 를 읽습니다.

디코더 `dq5field.tile_word` 도 훅이 있으면 세계별 니블 표를 읽게 했습니다. 훅을 쓴 롬은 `2A:D712` 를 읽지 않기 때문입니다.

돌린 타일(4·5·20·21)은 WRAM 에 푼 평면을 다시 읽어 만들므로 따로 손대지 않았습니다.

## 3. 세계 0 의 낮밤 인물 팔레트

`01:A422`·`01:A45E` 를 쓰는 곳은 `01:A14C`·`01:A159` 둘뿐이고, 둘 다 `01:A132` 안입니다. 고른 시간대 색인이 `0C` 이상(`$075E` `00F1`~`01FD`)이면 `A422`, 아니면 `A45E` 를 `01:A3F1` 이 `7E:3A76`·`3A96`(11·12번 줄 색 1~15)에 옮깁니다. 그래서 `A422` 가 밤, `A45E` 가 낮입니다.

처음에는 `$075E` 를 `00F0` 으로 두고 한 걸음 걸으면 밤이 될 줄 알았는데, 걸어도 `$075E` 가 그대로였습니다. 선실 상태의 `7E:2190` 이 `0A` 라 bit1(시간 멈춤)이 켜져 있었습니다([낮밤](../docs/dq5-field-format.md#낮밤-0082d3)). bit1 을 끄자 한 걸음에 `00F1` 이 되었고, 11·12번 줄 30색이 낮 벌에서 밤 벌로 바뀌었습니다.

```
f01050  075E=00F0  day=30 night=6  1AA1=0
f01075  075E=00F1  day=6  night=30 1AA1=1
```

## 4. 전투 뒤와 배

리뷰에서 1절의 근거가 장면 하나뿐이라는 지적을 받았습니다. 접근 감시를 `lua/dq5rangewatch.lua` 로 옮겨 16벌 롬에 두 장면을 더 돌렸습니다.

- 이벤트 전투: スライム 하나를 A 로 이겨 1,790프레임쯤 필드로 돌아왔습니다. 돌아온 직후에는 벌이 `1` 에서 185프레임 멈췄는데, 그동안 `$7F` 도 서 있었습니다(이벤트 대사). 1975프레임부터 다시 8프레임마다 돌았습니다.
- 배: 세워 둔 배에 올라(`$1954` = `03`) 바다를 돌고 내렸습니다. 내린 뒤 1,400프레임쯤 무작위 전투가 붙었습니다.

두 장면 모두 전투 중에도 `7E:C000`~`DFFF` 를 건드린 코드가 없었습니다. 돌아온 뒤에도 필드 타일과 벌을 다시 풀지 않았고, 벌을 푼 460프레임 뒤로 `CE00`~`D3FF` 에 닿은 것은 `00:8F75` 의 DMA 읽기뿐이었습니다.

## 5. 게임에서 확인

`dq5fieldgrowcheck.py` 의 시험 롬은 둘입니다.

- grow: 세계 1 의 타일 2 를 줄무늬로·니블을 2↔3번 줄로, 세계 2 의 타일 2 를 점무늬로·타일 63 의 니블을 2↔3번 줄로 바꿉니다. 움직이는 타일 8~15벌은 0~7벌의 첫 타일을 벌 번호로 칠하고, 인물 팔레트 낮·밤을 새 색으로 둡니다.
- high-all: 그룹 50 이상 CHR 628개를 모두 반전하고, 블록 295개의 모든 칸을 좌우 반전해 옮깁니다.

| 시험 | 결과 |
| --- | --- |
| 원본·grow 세계 0 (341,56), 800~1040 매 프레임 | VRAM 타일 502개가 세계 0 벌과 같음. 241프레임 동안 원본은 8벌, grow 는 16벌을 하나씩 차례로 돎(grow `5, 6, …, 15, 0, 1, …`) |
| 원본·grow 한 걸음(1000 → 1100) | `$075E` `00F0`→`00F1`, 11·12번 줄 30색이 낮 벌에서 밤 벌로. 원본은 `01:A45E`→`01:A422`, grow 는 새 색 |
| 원본·grow 세계 1·2 (50,28) | 타일 502개가 그 세계 벌과 같음. grow 의 타일 2 가 세계 1 은 줄무늬·세계 2 는 점무늬, 니블을 바꾼 세계 1 의 타일 2 칸 436개·세계 2 의 타일 63 칸 279개가 원본 게임에서는 모두 원래 니블, grow 에서는 모두 새 니블 워드. 11·12번 줄 30색은 `04:96D6` 의 OBJ 팔레트 3·4 |

## 틀렸던 것들

- 니블 훅의 첫 판은 X 만 지켰습니다. 세계 0 은 통과했지만 세계 1 에서 타일 2 를 쓰는 타일맵 칸이 하나도 없었습니다. `00:BBC9` 가 `XBA` 로 A 의 윗바이트를 타일맵 워드의 아랫바이트에 넣는데, 훅이 그 자리에 `세계 + X 윗바이트` 를 남겨 타일 번호가 1 씩 밀린 것입니다. 윗바이트를 스택에 두었다가 되돌리게 고쳤습니다.
- 전투 뒤 시험 창을 처음에 돌아온 직후(1790~1990)로 잡았더니 벌이 0·1·2 만 보였습니다. 이벤트 대사 동안 벌이 멈추기 때문이라, 다시 돌기 시작한 1975 부터로 옮겼습니다.
- 그룹 50 이상 맵을 처음에 `01:BA4C` 에서 덤프했더니 18개 중 8개가 `+4` 에서 2~8바이트 달랐습니다. `+4` 를 `32` 로 찍는 `01:8F93` 이 그 뒤에 돌기 때문입니다. 맵별 루틴 직후(`15:F7EE`)로 옮기자 모두 같았습니다.

## 남은 것

- 필드 타일 수 512 넘기기. 타일이 VRAM 워드 `2000`~`3FFF` 를 다 쓰고, 블록 정의의 타일 번호가 9비트입니다.
- 2·3번 줄 팔레트 벌 수 늘리기(세계 0 시간대 8벌, 세계 1·2 한 벌)와 세계마다 움직이는 타일 벌.
- ルーラ·세계를 오가는 이벤트 뒤에 세계 타일 벌과 16벌이 다시 맞게 올라가는지. 세계 1·2 는 `$1949` 고정으로만 보았습니다.
- `7E:CE00`~`D3FF` 가 비어 있다는 것은 걷기·메뉴, 이벤트 전투 뒤, 배를 타고 내린 뒤의 세 장면으로 확인했습니다. 세계를 오가는 이벤트·ルーラ·융단 같은 다른 탈것은 보지 않았습니다.
- ラナルータ·여관처럼 `$075E` 를 직접 바꾸는 장면에서 인물 팔레트가 바뀌는지.
