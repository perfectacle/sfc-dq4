# 2026-10-26-17: 시퀀스 0x47개 전부의 악보

들어 보기 페이지에는 .spc·.wav 만 있고 악보가 없었습니다. 롬의 시퀀스 0x47개 전부(쓰는 곳이 없는 `00` 포함)를 롬만으로 다시 쌀 수 있는 글(.txt)·MIDI(.mid)·MusicXML(.musicxml)로 내는 [sfc/dq5/tools/dq5score.py](../tools/dq5score.py) 를 썼고, KON 기록과 견줘 박자·음 차이를 확인했습니다. 결과는 [dq5-sound-format.md](../docs/dq5-sound-format.md) 의 「악보 내보내기」 에 있습니다. 파일은 비공개 에셋 저장소에만 올렸습니다.

## 1. 틱과 4분음표

시퀀스 71개의 음 길이를 세니 `18`·`30`·`60`·`0C`·`C0` 순으로 많았습니다. 48틱을 4분음표로 두면 8분·4분·2분·16분·온음표이고, `10`·`20` 은 셋잇단입니다.
틱이 나는 곳(SPC `146C`)을 읽으니 템포를 더해 넘치거나 `FB` 이상이면 `FA` 를 빼고 한 틱입니다. 타이머 0 목표는 .spc 의 `$FA` = `28`(8000Hz / 40 = 200Hz)이라 1초 = 200 x 템포 / 250 = 0.8 x 템포 틱이고, 4분음표 48틱이면 BPM 이 템포 바이트와 같습니다. 앞서 실측한 「틱당 프레임 x 템포 ≈ 75」(60.1 / 0.8)와도 맞습니다.

## 2. 음높이

처음에는 악기 샘플 머리의 음높이 h 를 반음(12 log2(h / 1000h))으로 바꿔 더했습니다. 그러자 곡 `02` 에서 동시에 울리는 음끼리 불협 음정(단2·장2·증4·단7·장7)이 되는 비율이 0.13 에서 0.33 으로 뛰었습니다. 악기가 둘 이상인 30곡 평균도 0.21 → 0.28 이라, h 는 샘플마다 음 번호의 뜻을 맞추는 값으로 보고 더하지 않았습니다. MIDI 음은 음 번호 + 조옮김 + 23 입니다.

## 3. KON 과 견주기

배 선실 세이브스테이트에 `lua/dq5spcdump.lua` 를 드라이버로 두고 대기열에 곡을 넣어 `lua/dq5dspw.lua` 로 KON 을 적었습니다.

```sh
LIBDIR=<lib.lua·probe 와 boot.lua = dq5spcdump.lua 를 둔 폴더> STATE=$PWD/work/state/ship.mss \
  CMDS="10:1A:00:00;14:01:02:00" FULLSET=02 MAXF=2400 SHOT_DIR=$PWD/work/kon/02 \
  "$MESENCE" --testrunner "$PWD/rom/dq5.sfc" "$PWD/sfc/dq5/tools/lua/dq5dspw.lua"
uv run --locked python sfc/dq5/tools/dq5score.py rom/dq5.sfc --kon work/kon/02/dspw.txt --seq 02 --start 14 --count 60
```

처음에는 음 시작만 견줘서 붙임으로 이은 음과 비율 `00` 의 레가토가 어긋났습니다. 드라이버대로 음표·붙임마다 KON 을 내되 앞 음을 비율 `00` 으로 읽었으면 내지 않게 하자 승리 곡 `1F` 의 레가토 오름(KON 1번)이 맞았습니다. 다음으로 `0A` 트랙 6 이 2,256틱에서 하나 모자랐습니다. 쉼 뒤의 음도 비율 `00` 을 따라 빼고 있었는데, 게임은 쉼 뒤에서 늘 다시 쳤습니다.

```
02  5트랙 189 KON  최대 4.81 프레임  음 차이 틀림 0
03  7트랙 320      5.20             0
04  7트랙 267      6.12             0
0A  7트랙 225      4.75             0
0D  7트랙 324      5.10             0
10  6트랙 360      5.57             0
38-00(メラ) 18     1.42             0
```

트랙 0 의 KON 을 직선으로 맞추면 틱당 프레임이 예측의 0.9984배(`02`)·0.9987배(`10`)이고 직선에서 남는 차는 1.2 프레임 안쪽이라, 최대 차의 대부분은 작은 빠르기 차이가 쌓인 것입니다.

## 4. 곡 17 의 빠진 샘플

전투 곡 `17` 은 트랙 2~4 가 수백 프레임씩 어긋났습니다. 300프레임 뒤의 SPC RAM 에서 샘플 색인(`03FF`)을 보니 곡 묶음 샘플 여덟 가운데 `00`·`05` 만 올라와 있었고, 그 밖의 샘플을 쓰는 음은 KON 이 나지 않았습니다. 그 음을 빼자 6트랙 343개가 3.96 프레임 안에서 맞았습니다.
에셋의 .spc 55개를 같은 식으로 보니 `17.spc`·`17-01.spc` 만 샘플 여섯(`16`·`0E`·`09`·`17`·`0B`·`08`)이 빠져 있었습니다. 들어 보기 파일의 결함이라 「남은 것」 에 둡니다.

## 5. 내보낸 것

곡 50개(`00`~`31`)와 갈래 6개, 효과음 137갈래, 모두 193벌을 냈습니다. 시퀀스 번호 71개 가운데 빠진 것은 없습니다. 끝없는 되풀이(뒤로 가는 `EA`)는 트랙마다 두 번째로 되돌아가는 틱 중 가장 늦은 틱까지 연주했고, 되풀이가 없는 곡은 27개였습니다.

- `.txt` 193개를 다시 싸서 롬 시퀀스와 바이트까지 같았습니다.
- `.mid` 193개는 트랙마다 켜기·끄기 수가 같았습니다(음 56,171개).
- `.musicxml` 193개는 모든 마디가 192틱이었습니다.

`index.json` 의 항목마다 `score`(파일 이름·틱 수·되풀이 여부·음 수)를 넣었고, .spc 가 없는 `00` 은 새 항목으로 더했습니다. `dq5soundpage.py` 는 「파일·악보」 칸에 링크를 겁니다.
