# 2026-10-27-46: 옮긴 레코드 자리 7E:1ABC~1BB0 을 접근 카운터로 닫기

옮긴 창 레코드를 둘 `7E:1ABC`~`1BB0`(245바이트)이 정말 비어 있는지를 정적 후보 대신 실측으로 닫았습니다. 장면 841개를 돌리며 이 범위의 주소마다 읽기·쓰기 횟수를 셌고, 원래 게임 코드의 접근은 0 이었습니다. 결과는 [dq5-hangul-format.md 「실측으로 닫기: 접근 카운터」](../docs/dq5-hangul-format.md#실측으로-닫기-접근-카운터)에 있습니다.

## 1. 카운터와 대조

`lua/dq5cdldump.lua` 에 `ACCRANGE` 를 더했습니다. 3프레임째의 MesenCE 접근 카운터(`emu.getAccessCounters`, WRAM 읽기·쓰기)를 0 으로 치고, 20프레임마다 범위 안 주소별 차이를 `acc.txt` 에 씁니다. 처음에는 CDL 과 함께 300프레임마다 썼는데, 장면 도구가 `TEST` 가 끝나면 스스로 멈춰 마지막 수백 프레임을 놓칠 수 있어 20프레임으로 줄이고 다시 돌렸습니다.

대조는 `1BB1` 을 쓰는 17/01 항구 장면입니다([2026-10-27-25](2026-10-27-25-wramrefs3.md)).

```
TO=17/01,40,56 SET="2192|80" LATESET="21A1|80;21A4|80" ACCRANGE=1ABC-1BB1
1BB1 545 1        (1ABC~1BB0 은 한 줄도 없음)
```

## 2. 장면 841개

`dq5cdlsweep.py --acc 1ABC-1BB1` 에 `extra` 장면을 더했습니다. 여관(대화 `06`), 교회(대화 `05`)에서 기록한 뒤 2,700 프레임에 리셋해 START·A 로 칸 1 을 불러오기(`RESETAT`), 세워 둔 배에 걸어 오르기, 융단·天空城·드래곤(`LATESET=1954=80`·`81`·`82`), 슬롯 셋과 맞음 판정 덮기, 슬라임 레이스, 격투장입니다. 불러오기 장면은 끝 화면에서 상태 창이 뜬 채 조작할 수 있어 실제로 불러온 것을 확인했습니다.

```
maps 346, battles 236, field 3, sound 71, effects 171, extra 14 → 841번, acc.txt 없는 실행 0
1ABC-1BB1 접근: 주소 246곳
  246곳 모두  extra/church-save-load 읽기 4 쓰기 1
  1BB1        maps/17_01·17_02·27_00 쓰기 1
  1AF9~1B67   maps/17_03 쓰기 208(56곳)
```

교회 장면의 「읽기 4·쓰기 1」 은 리셋할 때 낮은 WRAM 을 0 으로 채우는 `00:864A` 와 `MVN` 의 수로, 앞서 전원을 켤 때 잰 것과 같습니다.

## 3. 17/03 의 쓰기

17/03 에서는 8바이트마다 `+1`·`+5`·`+6`·`+7` 자리에 쓰기가 있었습니다. 범위 전체 읽기·쓰기 감시(뱅크 거울 모두)를 걸어 다시 들어가자 `01:AA26`·`01:AA63`… 이 데이터 뱅크 `80`, Y = `1B58` 로 쓰고 있었습니다. Y 를 모아 보니 이 셀 버퍼 쓰기는 보통 데이터 뱅크 `7E`·`7F` 로 `C000`·`0000` 부터 8바이트씩 가는데, 17/03 에서는 뱅크 `80` 의 `00D8`~`BFF8` 까지 갔습니다. 낮은 WRAM 거울 전체를 덮는 쓰기입니다. 17/03 은 26 × 56 칸(11,648바이트)의 작은 맵이고, 실행은 없는 맵 43/1F 로 끝나 있었습니다.

장면 도구는 배의 사다리 출구를 롬에서 덮어 들어갑니다. 서 있기만 하면 접근이 0 이었고, 들어선 직후 세이브스테이트로 남겨 덮지 않은 롬에서 같은 입력(왼쪽·오른쪽·위·아래 30프레임씩)을 걸자 접근 0 에 17/04 로 걸어 나갔습니다. 덮은 출구를 다시 밟아 엉뚱한 맵을 불러온 도구의 부산물이었습니다.

## 4. 결론

이 841개 장면에서 원래 게임 코드가 `7E:1ABC`~`1BB0` 을 읽거나 쓴 적은 없습니다. [2026-10-27-36](2026-10-27-36-wramrefs4.md)에 남은 정적 미정 179곳·명령 시작 29곳은 이 실행들에서 한 번도 실행되지 않은 바이트입니다.
