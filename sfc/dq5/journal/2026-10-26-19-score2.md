# 2026-10-26-19: 악보의 피치 벤드·박자 추정·SVG

[2026-10-26-16](2026-10-26-16-score.md) 의 악보에 빠졌던 음높이 미끄럼(`FB`)·엔벨로프(`E2`)·미세 조정(`E9`)·메아리를 MIDI 에 넣고, MusicXML 에 추정한 박자를 넣고, 사람이 읽는 SVG 악보를 더했습니다. 결과는 [dq5-sound-format.md](../docs/dq5-sound-format.md) 의 「악보 내보내기」 에 있습니다.

## 1. 엔벨로프 표를 롬에서

SPC RAM 의 포인터 표 `08D4` 가 가리키는 표 일곱(`08E2`·`0945`·`0992`·`09CC`·`0903`·`09A7`·`0924`)을 롬에서 찾으니 `08D4`~`09DF` 268바이트가 통째로 `2B:C663`(파일 오프셋 `15C663`)에 있었습니다. 표 `00` 은 `1E 16` 머리 뒤 `[미세 음높이][틱]` 쌍이고, 읽는 자리가 `1E` 에 닿으면 `16` 으로 돌아가 끝의 `00 F4 00 0C`(0, -12, 0, 12)를 되풀이합니다.

## 2. 미세 음높이의 단위

`1B8F` 가 반음 사이를 v/256 으로 나누는 것으로 읽어 처음에는 1/256 반음으로 두었습니다. KON 기록의 곡 `0D` 트랙 1(`E2 04`)에서 첫 음의 DSP 피치를 보니 3375 를 가운데로 3틱마다 이렇게 바뀌었습니다.

```
표 값   0  1  0 -1  0  2  0 -4  0  8  0 -12  0  12
피치  3375 3376 3375 3374 3375 3378 3375 3369 3375 3387 3375 3357 3375 3393
```

바뀐 양이 표 값의 1.5배이고, 12 → +18 은 0.092 반음입니다. 1/256 반음이면 그 절반이라, 단위는 1/128 반음입니다. 디코더 벤드를 피치 3375 로 되돌리면 표 값 ±1 의 두 칸(±2, 실제 ±1)만 다르고 나머지는 같았습니다(1.5 의 버림).

## 3. 박자 추정

롬에는 박자 정보가 없습니다. 길이 24틱 이상인 음의 길이 가운데 마디 첫 박에 놓인 비율에 박 수를 곱해 3/4·4/4 를 견줬습니다. 못갖춘마디를 12틱씩 옮겨 가며 고르면 음이 적은 곡에서 엉뚱한 자리가 뽑혀, 3/4 은 값이 1.3 이상이면서 4/4 의 1.2배를 넘을 때만, 못갖춘마디는 0 보다 1.2배 넘게 나을 때만 고르게 했습니다. 곡 56개 가운데 3/4 이 `05`·`0A`·`0F`·`0F-01`·`2A` 의 5개, 못갖춘마디가 17개였습니다. 들어서 정한 것이 아니어서 `index.json` 에 「(추정)」 을 붙였습니다.

## 4. SVG 와 PDF

LilyPond·MuseScore 는 이 기계에 없고, MusicXML 을 SVG 로 그리는 verovio 는 Python 3.15 휠이 없었습니다(6.2.1 까지 cp314). 그래서 의존성 없이 시간 비례 오선 악보(1틱 = 1px, 음표 머리·올림표·기둥·꼬리·덧줄, 음 길이를 가는 가로줄)를 직접 그렸습니다. 193개 모두 XML 로 읽혔고, rsvg-convert 로 191개를 그림으로 바꿨습니다. 남은 둘(`0F`·`0F-01`)은 높이가 45,410px 이라 rsvg 의 한도(32,767px)를 넘은 것입니다.

## 5. 다시 낸 것

```
.mid 193개  음 56,171  피치 벤드 39,321  켜기·끄기 짝 틀림 0
.musicxml 193개  첫 못갖춘마디를 뺀 모든 마디가 박자 길이
KON 대조(02·0A·0D)  앞 일지와 같음(최대 4.81·4.75·5.10 프레임, 음 차이 틀림 0)
```

같은 롬으로 빈 폴더에 두 번 낸 결과는 바이트까지 같았습니다.
