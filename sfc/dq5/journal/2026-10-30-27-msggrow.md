# 2026-10-30-27: 보행 메시지 3200 이상 덧붙이기와 부르는 길마다의 번호 한도

dq4 트랙이 2장(サントハイム·テンペ·フレノール) 대사를 넣을 새 보행 메시지 번호를 요청했습니다. 지금까지는 DQ5 메시지 3,200개 가운데 한 맵의 인물만 쓰는 것을 덮어 썼는데, 그 자리가 모자라기 시작했습니다. 번호가 디코더까지 가는 길을 읽고, `dq5textwrite.py` 가 3200 이상을 덧붙이게 한 뒤, 덧붙인 메시지를 대화 번호·대화 스크립트·이벤트 명령 `60`·인물 인라인 `21` 로 띄워 확인했습니다. 결과는 [메시지 번호의 한도](../docs/dq5-text-format.md#메시지-번호의-한도)와 [3200 이상 덧붙이기](../docs/dq5-build-format.md#3200-이상-덧붙이기)에 있습니다.

## 1. 번호가 디코더까지 가는 길

메시지를 띄우는 입구는 `JSL $248157` 입니다. `24:8157` 은 `24:815B` 에서 `REP #$30` 으로 A 를 16비트로 쌓고 `24:8BAF` 를 부릅니다.

```
24:8BAF  PHP / PHB / REP #$30 / PHA
24:8BB4  LSR ×4 / STA $0E09 / ASL / ADC $0E09 / TAX      X = (번호 >> 4) * 3
24:8BC1  SEP #$20
24:8BC3  LDA #$24 / PHA / PLB                           데이터 뱅크 24
24:8BC7  LDA $AF1E,X / STA $00 / LDA $AF1F,X / STA $01 / LDA $AF20,X / STA $02
24:8BD6  JSR $8C8D                                       ($00 >> 3 → $F0~F2, 아래 3비트 → $F3)
24:8BD9  PLA / AND #$000F / … 그만큼 끝 코드까지 풀어 버림
```

번호를 어떤 수와 견주는 명령은 없었습니다. `C9 80 0C`(`CMP #$0C80`)와 `C9 7F 0C` 는 롬 어디에도 없습니다. `CPX`·`CPY #$0C80` 꼴 바이트(`E0 80 0C`·`C0 80 0C`)는 네 곳(`07:A56A`·`04:A5AC`·`0E:EACF`·`2F:8367`) 있지만 메시지 루틴과 아래 부르는 길 안이 아닙니다. 색인 표를 읽는 피연산자(`1E AF`·`1F AF`·`20 AF` 앞이 `BD`)는 `24:8BC7`·`8BCC`·`8BD1` 셋뿐이고, `24:8BAF` 를 부르는 곳(`20 AF 8B`)도 `24:8164` 하나입니다. `24:8C8D` 는 데이터 뱅크를 쓰지 않아, 표를 다른 뱅크에 두어도 `24:8BC3` 의 뱅크만 바꾸면 됩니다.

걸리는 것은 표의 크기입니다. `24:AF1E` 에서 200개 × 3 = 600바이트가 끝나는 `24:B176` 이 바로 글자 묶음 표입니다. 그래서 표를 제자리에서 늘릴 수 없고 옮겨야 합니다.

## 2. 부르는 길마다의 끝

`JSL $248157` 22곳 가운데 번호를 롬 자료에서 바로 받는 길을 다시 읽었습니다. 나머지(즉값·작은 계산값)는 [dq4 문서 「인물」](../../dq4/docs/dq4-environment-format.md#인물)에서 원래 메시지 안으로 닫혀 있습니다.

```
00:BF85  LDY #$02 / LDA [$80],Y / XBA / DEY / LDA [$80],Y / JSL $248157    이벤트 명령 60: 16비트
01:D01F  LDY #$02 / LDA [$AE],Y / XBA / DEY / LDA [$AE],Y / JSR $CEA9         인라인 21 등: 16비트
06:AFFB  LDA $0F19 / SEC / SBC #$024F / CLC / ADC #$0615 / JSL $248157       대화 번호 T + 3C6
06:B070  AND #$3F / XBA / LDA ($F9),Y / … AND #$2000 → AND #$1FFF 또는 ADC #$0615   대화 스크립트 메시지
```

이벤트와 인라인은 16비트를 그대로 넘기고, 대화 스크립트는 bit5 갈래로 `1FFF`, 더하기 갈래로 `2614` 까지 닿습니다. 대화 번호는 인물 레코드가 12비트라 `FFF + 3C6 = 13C5` 까지입니다. `BRK 97+n` 은 n = 0~6 만 받아 `6FF` 까지입니다. 그래서 쓰기 도구의 끝을 대화 스크립트 bit5 갈래와 같은 `1FFF` 로 두었습니다.

## 3. 색인을 머리로 옮기기

`dq5textwrite.py` 는 이미 디코더 사본·마스크·트리를 머리에 두고 메시지를 그 뒤에 잇습니다. 덧붙이는 경우만 색인 표를 트리 뒤(글자 묶음 표가 있으면 그 앞)에 두고, `24:8BC3` 의 17바이트를 뱅크와 세 주소만 바꿔 씁니다. 3,200개만이면 원래대로 `24:AF1E` 를 덮습니다. 빈 `messages` 로 만든 패치 목록이 바뀌기 전 도구의 출력과 바이트까지 같았습니다.

```
dq5textwrite.py rom/dq5.sfc check                  보행 메시지 3200개, 코드 163649개, 다른 메시지 0개
dq5textwrite.py rom/dq5.sfc check grow.json        보행 메시지 8192개, 코드 168665개, 다른 메시지 0개
patch grow.json:  38:8000~3C:CA64 (5뱅크 반), 24:8BC3 17바이트, 24:9E02, 24:9E07, 24:8BD7
```

16개 묶음의 끝은 `{1001}` 하나짜리 메시지로 채웠습니다. 다시 읽을 때 메시지 수를 따로 적어 둘 자리가 없어서, 표 끝(옮긴 글자 묶음 표, 없으면 메시지 0 의 첫 바이트)까지를 세 바이트씩 세어 알아냅니다. 그러려면 마지막 묶음도 16개가 다 있어야 합니다.

## 4. 게임에서 띄우기

3200~`1FFF`(4,992개)를 덧붙이고 `C80`·`CC5`·`13C5`·`1FFF` 에만 「あいうえお」 같은 다섯 글자를 넣었습니다. 새 프로브 `dq5textgrowcheck.lua` 는 `24:8BAF` 가 받은 번호와 `24:8B98` 이 푼 64코드를 남기고, 안쪽에서는 기존 프로브(파파스 대화는 `dq5msg.lua`, 17/00 인물은 `dq5scriptcheck.lua`)를 그대로 돌립니다.

```
대화 번호 8BA: 3CBE1F 1006 327 398 2FD 328 329 1001
대화 번호 8FF: 3CBE50 1006 32A 2E5 2FE 32B 34C 1001
대화 번호 FFF: 3CC2B5 1006 2FF 300 32C 32D 2E6 1001
대화 스크립트 012 (C80): 3CBE1F 1006 327 398 2FD 328 329 1001
대화 스크립트 012 (1FFF): 3CCA5F 1006 32E 2E7 354 3C3 302 1001
이벤트 명령 60 C80: 3CBE1F 1006 327 398 2FD 328 329 1001
이벤트 명령 60 1FFF: 3CCA5F 1006 32E 2E7 354 3C3 302 1001
인물 인라인 21 1FFF: 3CCA5F 1006 32E 2E7 354 3C3 302 1001
원래 메시지 633 원본 롬과 같은 앞 64코드
원래 메시지 742 원본 롬과 같은 앞 64코드
원래 메시지 C7F 원본 롬과 같은 앞 12코드
17개 검사 통과
```

이벤트 갈래는 기록에 `f362 pc=00BED2 event=608000 op=60` 이 남아, `60:8000` 에 쓴 명령 `60` 이 띄운 것입니다. 대화 스크립트의 `msg C80`·`msg 1FFF` 는 `dq5talkwrite.py` 가 `615` 이상이라 더하기 꼴(`46 6B`·`59 EA`)로 씁니다. 그래서 `dq5talkwrite.py` 의 메시지 한도도 `1FFF` 로 올리고, `1000` 이상은 4자리로 받게 했습니다.

## 틀렸던 것들

- 원래 메시지 `C7F` 를 원본 롬과 64코드 그대로 견주었더니 달랐습니다. 디코더는 메시지 하나가 아니라 이어지는 64코드를 미리 푸는데, 원본 롬에서는 `C7F` 뒤가 메시지가 아니고 덧붙인 롬에서는 `C80` 이 이어집니다. 원래 메시지 3,200개 안의 코드(`C7F` 는 12코드)만 견주도록 고쳤습니다.
- 처음에는 색인 끝을 「글자 묶음 표 피연산자가 원래 값 `24:B176` 이 아니면 그 표」 로 찾았습니다. 피연산자를 비워 둔 시험 고정 롬에서 0 을 표로 읽어 끝을 잘못 찾았습니다. 표가 색인과 메시지 0 사이에 있을 때만 끝으로 보게 고쳤습니다.

## 남은 것

- 대화 번호 `900` 이상을 덧붙인 스크립트(`dq5talkwrite.py --extra-at`)와 함께 쓴 롬에서 스크립트 끝 뒤 번호가 메시지 `T + 3C6` 으로 가는지는 재지 않았습니다. 이번 대화 번호 실측은 덧붙인 스크립트가 없는 롬입니다.
- 인물 인라인 `30`·`31`·`32` 는 `21` 과 같은 `01:CEA9` 를 지나지만 게임에서는 `21` 만 띄웠습니다.
