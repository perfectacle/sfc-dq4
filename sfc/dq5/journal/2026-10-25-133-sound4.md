# 2026-10-25-133: SPC 드라이버 명령표와 곡 자료

[곡 줄이기·키우기 명령과 탈것 곡](2026-10-25-118-sound3.md) 에서 DSP 로는 뜻이 안 보였던 명령을, SPC RAM 의 드라이버를 풀어 읽고 APU 포트에 쓰이는 바이트를 기록해 정했습니다. 곡 자료가 롬 어디에서 어떻게 SPC 로 가는지도 찾았습니다. 결과는 [dq5-sound-format.md](../docs/dq5-sound-format.md) 에 있습니다. SPC RAM 덤프는 `work/` 에만 두었습니다.

## 1. SPC700 디스어셈블러

`dq5sndlog.lua` 의 `SPCDUMP` 로 필드에서 SPC RAM 64KB 와 DSP 레지스터를 떴습니다. 툴킷에 SPC700 디스어셈블러가 없어 [spc700.py](../tools/spc700.py) 를 새로 썼습니다. ALU 여섯 줄(`OR`·`AND`·`EOR`·`CMP`·`ADC`·`SBC`)과 `TCALL`·`SET1`·`BBS` 처럼 규칙이 있는 칸은 만들어 채우고, 나머지는 하나씩 적었습니다.

명령을 받는 곳은 포트 `$F4` 를 읽는 `0F6D` 였습니다.

```
0F6D  40        SETP
0F6E  e5 f4 00  MOV A,$00F4
0F71  65 f4 00  CMP A,$00F4
0F74  d0 f7     BNE $0F6D
...
0F86  e5 f5 00  MOV A,$00F5
...
0A1A  68 17     CMP A,#$17
0A1C  b0 07     BCS $0A25
0A1F  1c        ASL A
0A20  5d        MOV X,A
0A22  1f eb 09  JMP [$09EB+X]
```

`SETP` 로 직접 페이지를 1 로 두고 쓰는 드라이버라, `$8A` 는 `$018A` 입니다. 명령은 `00`~`16` 의 23개뿐입니다. 그런데 게임은 `8B`·`93` 같은 명령도 보냅니다.

## 2. 2B 뱅크가 명령을 바꾼다

APU 포트 `$2140`~`$2143` 에 쓰기 콜백을 걸고, 앞 일지처럼 메뉴 효과음을 다른 명령으로 바꿔 보냈습니다.

```
8B 00  2141=0B 2142=00 / 0B 05 / 0B 1F / 0B 22 / 0B 20 / 0B 21
93 00  2141=13 2142=00 / 13 17 / 13 1D / 13 21 / 13 32 … 13 3D / 13 46
94 00  2141=10 2142=00
0D 02  (없음)
```

대기열 처리기 `2B:BF0D` 가 `명령 & 3F` 로 표 `2B:C43B` 를 골랐습니다. `8B` 와 `93` 은 롬의 목록(`2B:C422`·`2B:C429`)을 하나씩 `0B`·`13` 으로 보내고, `0D` 의 처리 루틴은 `RTS` 하나였습니다.

`1A` 는 인자를 `05`·`00`·`FF` 로 바꿔도 APU 로 간 바이트가 같았습니다.

```
2141=04 2143=7E 2142=02   지금 곡 02 를 X 7E 로 줄이기
2141=15
2141=09 2142=02  …(대답이 7F 가 될 때까지)
2141=16
2141=0A
```

인자는 어디에도 나가지 않습니다. 맵 곡에서 `1A` 의 인자가 곡 번호와 같았던 것은 `00:CEB1` 이 그렇게 넣었을 뿐입니다.

## 3. 두 칸 표와 참조 수

SPC 의 `00`·`0B` 처리기는 샘플 n 의 칸을 `03FF+n` 에서 찾아 플래그에 `20` 을 더하고, `0B` 는 `10` 도 켭니다. `10`·`13` 은 시퀀스로 같은 일을 하고(`04C7+n`), `16` 은 두 표의 플래그를 모두 `& 1F` 합니다. 앞 일지에서 `8B 00` 이 `053C`·`0544`… 를 `10` → `30` 으로 바꾼 것은 고정된 샘플 여섯에 참조 수 1 이 더해진 것이었습니다.

`09` 는 8개 곡 자리에서 곡 n 을 찾아 포트 `$F5` 로 상태를 돌려주고, 없으면 `7F` 를 줍니다. `1A` 가 `09` 를 되풀이한 것은 앞 곡이 다 줄어 멈출 때까지 기다린 것입니다.

## 4. 곡 자료의 자리

`2B:C25F` 를 지날 때 전송 포인터 `$FB` 와 첫 두 바이트(길이)를 적었습니다.

```
502 exec 2BC1C8 A=0002
502 xfer ptr=2EE7A6 len=01F7     시퀀스 02
505 xfer ptr=2CA81A len=0316     샘플 03
512 exec 2BC21E A=0000           샘플 00 (이미 있음)
513 xfer ptr=2CAB32 len=07DE     샘플 04
```

`2B:C391`·`2B:C39E` 가 `$FB` 를 `2B:EB00`·`2E:E2E4` 로 두고, `2B:C3AB` 가 `[길이 2][자료]` 를 n 번 건너뜁니다. 길이를 따라 걸으면 샘플 0x26개 뒤에 바로 시퀀스 묶음이 이어지고, 시퀀스는 `46` 뒤부터 길이 0 이었습니다. `93` 목록의 끝이 `46` 인 것과 맞습니다. 곡 n 이 쓰는 샘플은 `2B:E67F` 의 n 번째 레코드 `[L][한 바이트][샘플 L개]` 에 있었습니다.

이 표로 [dq5spc.py](../tools/dq5spc.py) 를 썼습니다. `--check` 는 SPC RAM 의 칸 표에 오른 것을 롬과 견줍니다.

```
$ uv run --locked python sfc/dq5/tools/dq5spc.py rom/dq5.sfc --check work/spc/spc00550.bin
seq    02 slot 11 ok
...
sample 03 slot 06 ok
26 loaded, 0 differ
```

마법 융단을 편 뒤의 덤프도 30개가 모두 같았습니다(전송 중인 1090 프레임에는 샘플 `0A` 하나가 덜 와서 달랐음). 샘플 머리 7바이트는 DIR(`$0700`, DSP `5D` = `07`)의 반복 주소 - 시작 주소와 같은 반복 위치 2바이트에 ADSR1·ADSR2·GAIN(`FF E0 B8`)과 음높이 2바이트가 붙은 꼴이었습니다.

탈것과 여관에서도 전송을 기록하니, 전송은 늘 `01`·`0C` 뒤에 있었고 `1A` 가 나간 프레임에는 없었습니다. 배는 `0C 04` 로 시퀀스 `04` 를, 융단은 `01 03` 으로 시퀀스 `03` 을, 天空城은 `01 0D` 로 시퀀스 `0D` 를 받았습니다.

## 5. 여관과 天空城

선실 파파스의 대화 번호를 여관(`06`)으로 바꿔 묵었습니다(`walk.lua` 의 `PRE` 로 대화).

```
573 cmd=1A arg=1D from=25:FD03
573 cmd=01 arg=1D from=25:FD07
```

여관은 곡 `1D` 를 틀었고 `02`·`03`·`04` 는 없었습니다. 여관 처리기는 `06:E409` 에서 `$0F1B` bit6 을 보고, 켜져 있으면 `06:E413` 으로 맵 곡을 줄입니다. `POKE="7E0F1B=40"` 으로 켜자 `573 cmd=04 arg=04 from=06:E419` 가 나왔습니다. 교회(`05`)의 おいのり·되살리기에서는 곡 명령이 없었습니다.

天空城이 내리지 못한 것은 땅이 맞지 않아서였습니다. `01:C375` 가 4x3칸의 지형을 `01:BE7D` 로 보고, 지형이 목록 `01:BE7A`(`01`·`06`)에 없는 칸이 하나라도 있으면 실패합니다. 지형은 `03:CB1B` 가 블록 번호의 니블 `03:CC48` 에서 꺼냈고, `01:BE92` 에서 찍은 7칸이 `dq5field.py` 의 블록으로 계산한 값과 모두 같았습니다. 그래서 열두 칸이 모두 `01`·`06` 인 자리를 계산으로 찾아 `FIELD=335,61` 에서 내렸습니다. `333,60` 에서는 A 를 누를 때 자리가 (333,68) 로 옮겨 가 있어 지형 `0C` 를 만나 실패했습니다.

```
559 exec 01C319
656 cmd=01 arg=0D from=00:CEA2
f01150 end map 06/08 cell 24,11
```

내리자 天空城 안(맵 06/08)으로 들어가고, 맵 곡도 `0D` 라 `1A` 없이 `01 0D` 만 나갔습니다.

## 남은 것

- `$0F1B` bit6 을 켜는 장면(`06:BDC8`·`06:C29C`)과 `02`·`03`·`04` 의 나머지 부르는 곳.
- SPC 쪽 `01`·`05`~`08`·`0C`·`11`·`12`·`14` 처리기, 시퀀스 형식, 곡 묶음 둘째 바이트.
- 곡 이름. 소리를 들어 볼 수 없어, 쓰인 장면이 정해진 곡에만 장면 이름을 붙였습니다.
