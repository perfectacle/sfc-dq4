# 2026-10-26-40: 실내 맵 레코드 쓰기 도구

포팅용 쓰기 도구의 두 번째로, 실내 맵 레코드를 풀고 다시 싸는 `sfc/dq5/tools/dq5mapwrite.py` 를 만들었습니다. 고친 맵은 늘린 롬의 새 뱅크에 놓고 맵 포인터를 바꿉니다. 형식은 [dq5-build-format.md 「실내 맵 레코드」](../docs/dq5-build-format.md#실내-맵-레코드-dq5map1) 에 있습니다.

## 1. 다시 싸서 원래 바이트가 나와야 한다

맵 레코드는 머리 9바이트, 배치 비트스트림(put·block·fill·end), 속성 패스 셋입니다([dq5-map-format.md](../docs/dq5-map-format.md#맵-레코드)). 디코더 `dq5map.py` 는 셀 버퍼를 만들 뿐 명령을 다시 쓸 수 있는 꼴로 남기지 않습니다. 그래서 레코드를 명령 단위 JSON 으로 푸는 쪽과 그 JSON 을 바이트로 싸는 쪽을 따로 짰습니다. 기준은 고치지 않은 JSON 을 다시 쌌을 때 원래 레코드와 바이트까지 같은지입니다.

## 2. 첫 시도: 마지막 바이트가 다르다

처음에는 364개 맵 중 46개가 다르게 나왔습니다. 길이는 같고 마지막 바이트의 아래 니블만 달랐습니다.

```
02/04: 원래 0E, 다시 싼 것 00
1E/01: 원래 84, 다시 싼 것 80
```

패스 3 끝 바이트 다음의 남은 니블입니다. 게임은 읽지 않지만 레코드에 들어 있으므로 JSON 에 담았습니다.

## 3. 둘째 시도: 레코드가 다음 맵과 겹친다

바이트는 모두 같아졌는데, 레코드 끝을 다음 맵 시작과 견주자 90여 곳에서 끝이 몇 바이트씩 넘쳤습니다. 00/02 는 디코더가 패스 3 을 `18:9290`(파일 `C1290`)에서 시작해 엔트리 없이 끝내는데, 이 도구는 엔트리 하나를 더 읽었습니다.

패스 사이의 정렬을 잘못 본 것이었습니다. 니블 리더(`01:B8A8`·`01:B8DD`)의 상태 (주소, 반 바이트)를 니블 위치 q 로 놓고 다시 따져 보면 이렇습니다.

```
nib()   N[q]·N[q+1] 을 한 바이트로 돌려주고 q += 1   (패스 머리는 이 값의 bit7 = N[q] 의 bit3)
byte()  N[q+1]·N[q+2] 를 돌려주고 q += 2
값 니블  nib() & 0F = N[q+1], q += 1
```

패스 머리는 「다음 바이트」가 아니라 지금 위치의 니블 `N[q]` 입니다. 앞 패스의 끝 바이트가 반 바이트에서 끝나면 그 끝 바이트의 아래 니블이 곧 다음 패스의 머리가 되고, 머리 다음 니블 하나는 아무도 읽지 않습니다. 패스 1·2 가 끝날 때의 맞춤 니블도 「반 바이트면 하나 더」가 아니라 위치를 짝수로 맞출 뿐입니다. 이 위치 계산을 그대로 옮기자 364개 맵이 모두 바이트까지 같고, 레코드 끝이 디코더가 패스를 끝낸 자리와 같았습니다.

```
$ dq5mapwrite.py rom/dq5.sfc check
맵 364개 233794바이트, 다른 맵 0개
```

남은 겹침은 세 곳(20/03 → 20/04, 31/04 → 31/05, 31/05 → 31/06)입니다. 패스 3 이 반 바이트에서 끝나 마지막으로 읽는 니블이 다음 맵 머리 첫 바이트의 위 니블입니다. 게임은 패스 3 끝에서 위 2비트만 보므로 문제가 없습니다. `--in-place` 로 이 세 맵을 덮을 때 그 바이트가 바뀌면 거부합니다.

## 4. 옮겨 놓고 게임에서 보기

01/05 로 두 롬을 만들었습니다. 하나는 고치지 않고 `30:8000` 으로 옮기기만 했고, 다른 하나는 명령 끝에 블록 둘을 더했습니다.

```json
["block", 774], ["put", 4, 2], ["block", 356], ["fill", 8, 2, 13, 5], ["end"]
```

패치 목록은 레코드(파일 `0x180000`)와 포인터(`0F:8AFF` 의 `73 B5 18` → `00 80 30`) 두 쓰기입니다. 배 사다리 출구를 `E502020101` 로 덮어 01/05 로 들어가고 `atpc.lua` 로 `01:BA4C`(속성 패스 끝)에서 WRAM 을 덤프했습니다.

| 롬 | 셀 버퍼 | `dq5map.py --compare` |
| --- | --- | --- |
| 원래 | — | 0바이트 차이 |
| 옮기기만 | 원래 롬과 같음 | 0바이트 차이(`30:8000` 에서 읽음) |
| 블록 더함 | 셀 28칸이 다름 | 0바이트 차이 |

화면에도 사다리 옆에 붉은 바닥 직사각형과 벽 조각이 새로 보였습니다.

## 틀렸던 것들

- 패스 머리를 늘 새 바이트의 첫 니블로 보았습니다. 패스 3 뒤 남은 니블도 처음에는 레코드 밖으로 보았습니다. 실제로는 리더의 지금 위치 니블이라 앞 패스 끝 바이트와 겹칠 수 있습니다.

## 남은 것

- 속성 패스 엔트리를 고친 맵은 게임에서 돌려 보지 않았습니다.
- 칸마다 블록을 적은 격자에서 put·fill 명령을 만드는 길이 없습니다. 지금은 명령을 손으로 적습니다.
