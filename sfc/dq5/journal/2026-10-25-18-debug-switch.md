# 2026-10-25-18: 개발용 스위치 01:8000, 이벤트 무리 플래그, 작전 창

[앞 일지](2026-10-25-12-event-battle.md)에서 남긴 것을 이어 보았습니다. 이벤트 전투 무리 플래그의 비트, 무리 `30`~`3F` 를 부르는 곳, 장면 이동 도구로 01/04 에 가면 화면이 검다는 기록, 필드에 늘 떠 있던 「めいれいさせろ」 창입니다.
무리 번호를 찾다가 디버그 입구 `2B:848A` 가 보던 롬 `01:8000` 을 다른 곳도 읽는다는 것을 알았고, 거기서 디버그 기능 둘이 나왔습니다.

## 1. 무리 플래그 bit0-1: 전투 곡

`26:8E0A` 는 레코드 첫 바이트를 `& FC` 해서 `$1000` 에 둡니다. 그럼 bit0-1 은 어디로 가는지 찾으려고 `23:D757` 을 읽는 명령을 롬에서 찾았더니 셋째가 있었습니다.

```
26:8F5B  STZ $1014
         CMP #$40 / BCS (표를 읽지 않음)       ; 무리 번호 40 이상
         LDA $23D757,X / AND #$03 / STA $1014
         LDA $268F96,X / ... / STA $7E2CD0      ; 26:8F96 = 17 16 18 F3
         JSL $24FEAC
```

`01:86A7` 이 무리를 옮기기 전에 부르는 루틴입니다. `wwatch.lua` 로 `7E:2CD0` 쓰기를 보니 무리 `01`·`3E`(bit0-1 = 0)는 `17`, `20`(1)은 `16`, `2C`(2)는 `18` 이었습니다.
bit0-1 이 1 인 무리는 おやぶんゴースト·ゆきのじょおう·ゲマ(`20`)·イブール 같은 보스이고, 2 는 エスターク 와 마지막 ミルドラース 입니다. 그래서 전투 곡 번호로 보는데, 소리를 듣고 확인한 것은 아닙니다.
`CMP #$40` 은 앞 일지에서 모양으로 추측한 「표는 64개」를 코드로 뒷받침합니다.

## 2. bit4~7: `$1015`

전투를 시작할 때 `26:82CE` 가 `$1000 & F8` 을 `$1015` 에 둡니다. `$1015` 를 읽는 명령 68곳을 마스크별로 모았습니다.

- bit4(`AND #$10`, `20:E197`): 무리 번호가 `20:E1B6` 의 목록 `01`·`1E` 에 있으면 무리별 루틴을 부릅니다. 첫 필드 이벤트(파파스와 슬라임)와 ジャミ 전투입니다.
- bit5(`AND #$20`, `20:901D` 등): 실측했습니다. 무리 `3E` 의 플래그를 바꿔 전투 첫 창을 비교했습니다.

| 플래그 | 첫 창 |
| --- | --- |
| `00`·`80`·`40`·`10` | 「たたかう / にげる」 |
| `20` | 「こうげき / ぼうぎょ / どうぐ」(명령 창으로 바로) |

bit5 가 켜진 무리는 `07`·`09`·`0A`(ジャミ·ゴンズ) 셋으로, 도망칠 수 없는 전투입니다.
- bit6·7: `BIT $1015` 로 갈리는 곳이 여럿이고, bit7 은 선제·기습 판정(`26:8329`)을 건너뜁니다. 무리 `3D` 로 도망치기를 여섯 번(기다리는 프레임을 바꿔 난수를 바꿈), 끝까지 싸우기를 한 번씩 해 보았지만 플래그에 따른 차이는 보이지 않았습니다.

## 3. 무리 `30`~`3F` 를 부르는 곳

`26:8F43`(곡 고르기)을 부르는 곳을 따라가니 무리를 옮기는 입구가 둘 더 있었습니다. `01:85EC`(19곳)과 `01:868B`(1곳)이고, 모두 `LDA #무리 / JSL` 꼴입니다. 넷을 모으면 부르는 무리는 이렇습니다.

```
01:86A7  01 02 0B
01:86C3  11~2F 중 20개
01:85EC  03~0A 10 14 16~1E
01:868B  0D
```

`00`·`0C`·`0E`·`0F`·`29`·`30`~`3F` 를 즉값으로 부르는 곳은 없고, 이 입구들로 뛰는 `JML` 이나 주소 표도 없었습니다. `0C`~`0F` 는 상자 몬스터(ミミック·ひとくいばこ·ツボック·あくまのツボ)인데 `0D` 만 즉값입니다. 나머지는 번호를 계산해서 부르는 것으로 보이며, 찾지 못했습니다.

## 4. 롬 `01:8000`·`01:8001`

`26:8E5A` 는 격투장(가게 종류 `0E`, `06:F226`)이 시합을 고르는 곳입니다. 첫머리가 이렇습니다.

```
26:8E5C  LDA $018000 / ORA $018001 / BEQ 숫자 입력
         ...23:DC27 표와 난수로 시합 고르기
```

롬에서 `LDA $018000` 은 `00:A981`·`00:A99F`·`26:8E5C`·`2B:8494` 네 곳입니다. 팔리는 롬의 `01:8000`·`01:8001` 은 `FF FF` 이고, 개발 중에는 `00` 으로 두어 디버그 기능을 켰던 것으로 보입니다.

### 벽 통과

`00:A97D`(필드)와 `00:A99C`(실내)는 이동 판정 앞에서 `01:8000` 이 `00` 이고 `$24` bit6 이 켜져 있으면 판정을 건너뜁니다. `$24` 는 `00:8C03` 이 1P 패드 상위 바이트로 만드는데, bit6 은 B 버튼입니다(A·X 는 bit7).
처음에 X 로 해 보았다가 메뉴만 열려서 `00:8C03` 을 읽고 B 로 바꿨습니다.

| 장면 | 입력 | `8000=FF` | `8000=00` |
| --- | --- | --- | --- |
| 04/00 (27,75) | B + 왼쪽 150프레임 | (24,75) 에서 막힘 | (12,75), 나무 그림 위 |
| 필드 (341,56) | B + 위 200프레임 | (340,52) 에서 막힘 | (341,32), 바다 위 |
| 필드 (341,56) | 위 200프레임 | (340,52) | (340,52) |

### 격투장 시합 고르기

선실의 파파스를 대화 번호 `0E`(격투장)로 바꾸고 말을 건 뒤 A 로 대사를 넘겼습니다.

```sh
STATE=$PWD/work/state/ship.mss PRE="b:4,wait:40,up:3,wait:20,a:4,wait:30,a:4,wait:250,a:4,wait:80,a:4,wait:80" \
  POKE="7E36EB=0E;7E370B=00" ROMPATCH="8000=0000" MAXF=760 SHOT_DIR=$PWD/work/arena \
  "$MESENCE" --testrunner "$PWD/rom/dq5.sfc" "$PWD/tools/lua/walk.lua"
```

원래 롬은 「ダンスニードル ＊1.9 / ドラキーマ ＊1.9」 배당 창이 뜨고, `8000=0000` 이면 그 자리에 「00000」 숫자 입력 창이 뜹니다. 위를 세 번 눌러 3 을 넣고 A 를 누르자 「スライムA ＊3.0 / スライムB ＊2.7 / スライムC ＊3.3」 시합이 나왔습니다.

## 5. 01/04 의 검은 화면

`TO` 로 01/04 의 (12,44)·(64,17)·(4,7)에 가고, `SETTLE` 을 150·400 으로 바꿔 세이브 때 그림과 끝 그림을 모두 보았습니다. 모두 방과 인물이 정상으로 그려졌습니다. 검은 화면은 다시 나오지 않아서 도구는 고치지 않고 [dq5-handoff.md](../handoff.md) 의 그 줄을 지웠습니다.

## 6. 「めいれいさせろ」 창

걸음을 멈추고 조금 있으면 상태 창과 함께 뜨고, 움직이면 사라집니다. 04/00 에 서서 이름 문자열 루틴 `21:955D` 를 감시하자 516프레임에 한 번 불렸고, 그때 `$42`·`$43` 이 `05`·`06` 이었습니다.
이름 표 6 의 5번이 「めいれいさせろ」(0 ガンガンいこうぜ … 5 めいれいさせろ)이고, `$42` 를 쓴 곳은 `04:B919` 였습니다. 그 앞 `04:B912` 의 `BRK 88 4F` 가 작전 값을 조회합니다.
선실 세이브스테이트에서 이어진 찌꺼기가 아니라, 지금 작전을 보여 주는 게임 본래의 창입니다.

## 7. 롬 밖 뱅크 실행 감시, 장면을 더해

앞 일지와 같이 `cover.lua LO=300000 HI=FFFFFF` 로 뱅크 `30` 이상의 실행을 모았습니다. 테스트 러너가 약 100초에 끝나므로 한 번에 2,400~2,700프레임으로 끊었습니다.

| 장면 | 만든 법 | 뱅크 `30` 이상 실행 |
| --- | --- | --- |
| 세계 1(눈 덮인 땅) 필드 걷기 | `FIELD=341,56 POKE=7E1949=01` | 0 |
| 세계 2(보라색 바다) 필드 걷기 | `FIELD=341,56 POKE=7E1949=02` | 0 |
| エスターク 전투, 이어서 무작위 전투 | `FIELD=341,56 GROUP=2C` | 0 |
| 04/00 성 앞, 명령 창 | `TO=04/00,27,75 SAVE=castle.mss` 뒤 `seqboot.lua` | 0 |

## 틀렸던 것들

- 벽 통과 버튼을 X 로 보았습니다. `$24` bit6 은 `00:8C03` 이 B 를 옮겨 둔 자리입니다.
- 세계를 바꾼 감시를 처음에 `SET=1949=01` 로 돌렸는데, 끝난 뒤 `$1949` 가 `00` 이었습니다. `2A:FEE4` 가 맵을 지날 때 다시 씁니다. `POKE` 로 고정해야 합니다.
- 실내 맵 장면에 `dq5warp.lua` 를 드라이버로 두고 `cover.lua` 를 붙였더니 도구의 `TO`(맵)와 프로브의 `TO`(프레임)가 겹쳐 둘 다 엉뚱하게 돌았습니다. 세이브스테이트를 먼저 만들고 따로 붙였습니다.
