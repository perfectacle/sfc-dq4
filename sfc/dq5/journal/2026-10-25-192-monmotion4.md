# 2026-10-25-192: 보스가 쓰러질 때의 색, 무리 번호를 두는 곳, 그림 9A

형식 문서의 몬스터·스프라이트 쪽 「남은 것」 을 비웠습니다. 결과는 [dq5-graphics-format.md](../docs/dq5-graphics-format.md) 의 「몬스터 움직임」 과 「그림 번호와 세트」 에 있습니다.

## 1. `22:CC16` 의 색

`22:CC16` 의 바이트를 다시 풀었습니다. 효과음 명령 `BRK 16 44` 가 3바이트라 처음에는 그 뒤가 어긋나 읽혔습니다.
바로 풀자 꼴이 단순했습니다. `$8587`(처음 처리)·`$8585`(끝 처리)·`$858A` = 30 을 두고 `22:A650` 을 부르는 단계가 이어집니다. 첫 무리가 `E7` 이면 넷, `EA` 면 아홉입니다.

```
E7: 00 → 20 → 1E → 02 → 24
EA: 00 → 20 → 0A → 10 → 04 → 06 → 08 → 1E → 02 → 24
```

[2026-10-25-185](2026-10-25-185-monmotion3.md) 의 `2B` 덤프에서 30프레임마다 색을 보니 원래 색, 푸르스름한 흰색, 주황, 붉은색, 검정 차례였습니다.

## 2. `$100D` 를 두는 곳

`GROUP=2B` 로 싸움을 걸며 `$100D` 를 모든 미러에서 감시했습니다. 쓰는 곳은 `26:8E0C` 하나였고, 값은 `2B` 였습니다.
`01:86C3` 을 `LDA #nn` 으로 부르는 곳을 롬에서 찾으니 `26` 은 `02:F8A6`, `2B` 는 `02:F868`, `2F` 는 `02:F88E`, `2C` 는 `06:B595` 였습니다.

## 3. 그림 `9A` 와 `7E:21D1` bit6

`1F:CF29`~`CF44` 를 읽으면 `7E:21D1` bit6 이 켜져 있을 때 아무것도 풀지 않습니다. 그림 `9A` 는 `7E:21B3` bit3 이 켜져 있으면 `2F`, 아니면 `97` 칸을 읽습니다.
처음에는 주인공 슬롯의 그림(`7E:196F`)을 `9A` 로 두었지만, 주인공 그림은 다른 플래그로 정해져 바뀌지 않았습니다. 그래서 02/06 인물 목록의 첫 인물 그림 칸을 롬에서 `9A` 로 덮었습니다.
처음 넣은 `58CD9` 는 `dq5npc.py` 가 찍은 `058CD4` 를 파일 오프셋으로 잘못 읽은 것이었습니다. CPU 주소 `05:8CD4` 이므로 파일 오프셋은 `28CD9` 입니다.
bit3 이 꺼져 있으면 세트 `60`(フローラ), 켜져 있으면 세트 `1C`(ビアンカ)의 타일이 VRAM 에 모두 있었습니다. `dq5sprite.py --compare` 는 표의 `9A` 칸(`1C`)만 보고 있어, bit3 이 꺼진 덤프에서 이 인물을 놓쳤습니다. 덤프의 `7E:21B3` 을 보게 고쳤습니다.

## 4. 화면 찍기

`lua/dq5monlog.lua` 의 `SHOTS=1` 을 `lua/dq5shots.lua` 처럼 화면 버퍼(`emu.getScreenBuffer`)로 바꿨습니다. 맞음 깜빡임에서 프레임 f 끝의 OAM 은 늘 f+1 의 화면에 나왔고, 흔들림은 없었습니다. 장면 GIF 14개를 다시 찍었습니다.
