# 2026-10-27-47: 전투 배경·실내 맵 그림 쓰기

전투 배경의 그림·목록·팔레트와 실내 맵의 CHR·팔레트·블록 정의를 고쳐 넣는 쓰기 도구 둘을 만들었습니다. 그림 압축 인코더를 붙였고, 내보낸 그대로 넣으면 쓰기가 0개입니다. 넘치는 자료는 늘린 뱅크로 옮깁니다. 고친 그림이 MesenCE 화면 메모리에 나오는 것까지 확인했습니다. 입력 형식은 [전투 배경 쓰기](../docs/dq5-build-format.md#전투-배경-dq5battlebg1)와 [실내 맵 그림 쓰기](../docs/dq5-build-format.md#실내-맵-그림-dq5mapgfx1)에 있습니다.

## 1. 전투 배경의 자리

배경 자료는 모두 뱅크 28 에 있고 세 표가 16비트 포인터입니다. `dq5battlebg.py` 의 디코더로 자료마다 끝을 재어 늘어놓았습니다.

| 자리 | 내용 | 바이트 |
| --- | --- | ---: |
| `28:82F9`~`8394` | 그림 표(종류 39 × 2) | 156 |
| `28:8395`~`BDFB` | 그림 23개 | 14,951 |
| `28:BDFC`~`BECF` | 팔레트 표(106) | 212 |
| `28:BED0`~`C9C1` | 팔레트 레코드 54개 | 2,737 |
| `28:C9C2`~`CAAB` | 목록 표(117) | 234 |
| `28:CAAC`~`FFED` | 목록 52개(빈틈 포함) | 12,923 |

목록 끝 `FFED` 뒤 18바이트만 0 이라 뱅크가 사실상 찼습니다. 그림 하나라도 커지면 자리가 모자랍니다.

## 2. 누가 뱅크 28 을 정하나

`22:CB24`(그림 B)와 `22:CB43`(그림 A)은 표에서 16비트를 읽어 `$53` 에 두고 `LDA #$28 / STA $55` 로 뱅크를 채웁니다. 그 뒤 디코더 `22:CB62` 는 `LDA [$53]` 으로 읽고 DB 는 `7E` 입니다. 그래서 두 즉값만 바꾸면 그림 전체를 어느 뱅크로든 옮길 수 있습니다. 목록은 `22:887F`, 팔레트는 `22:8808` 이 각각 `$52`·`$55` 에 28 을 넣습니다. 표가 16비트라 이 둘은 뱅크 28 에 남기고, 그림을 옮기면 비는 14,951바이트를 넘침 자리로 씁니다. 세계 2 의 목록 `28:FD64` 는 `22:88D3` 의 `LDA #$FD64` 즉값입니다.

## 3. 타일 인코더

디코더(`22:992A`)의 마스크는 반 타일(평면 0·1, 2·3)마다 줄 순서로 두 평면을 번갈아 읽고, 마스크 비트를 이어서 씁니다. 인코더는 모두 0 인 평면을 빼고, 그대로 쓰기와 채움 값(0 이나 그 타일에 나오는 바이트)별 마스크 압축을 모두 만들어 가장 짧은 것을 고릅니다. 그림 23개를 다시 싸서 풀면 모두 같았고, 크기는 14,951바이트에서 14,920바이트로 조금 줄었습니다.

바뀌지 않은 자료는 원래 바이트를 그대로 둡니다. 처음에는 제자리 다시 놓기에서도 원래 바이트를 지켰더니, 칸 하나를 바꾼 그림이 5바이트 커져 그림 자리를 5바이트 넘쳤습니다. 넘칠 때는 다시 싼 바이트가 더 짧은 자료를 바꿔 한 번 더 놓게 했더니 원래 자리에 들어갔습니다.

## 4. 실내 맵 그림의 자리

블록 정의는 `16:8000` 부터 1,936개(`16:E7BA` 까지)입니다. 블록 표를 만드는 `01:8CD8` 은 다음 블록의 `+2` 가 `FF` 이면 멈추고 최대 2,048개 포인터를 `7E:B000` 에 둡니다. 맵 블록이 쓰는 CHR 은 `000`~`B79`(2,938개)입니다. 블록 뒤 `16:E7BA`~ 와 CHR 뒤 `15:EF40`~ 는 다른 자료라 늘릴 자리가 없습니다. 니블 표 `2A:8781` 의 2,938번째 뒤도 다른 자료입니다.

맵을 불러올 때 `01:92F4` 가 즉값으로 블록 뱅크(`$1823` = 16), CHR 뱅크(`$1824` = 13), 니블 표 롱 주소(`$B1`~`$B3` = `2A:8781`)를 둡니다. `01:8C15` 는 CHR 을 DMA 채널 7 로 보내고(`$4374` 에 `$1824` + 번호 bit10~11), 니블은 `LDA [$B1],Y` 로 읽습니다. 둘 다 어느 뱅크든 됩니다. 블록 표를 만드는 `01:8CD8` 은 DB 를 블록 뱅크로 두고 곱셈기 `$4202` 를 절대 주소로 쓰므로, 블록은 I/O 거울이 있는 `30`~`3F` 로만 옮깁니다. `01:8CD8` 의 뱅크(`01:8CDF`)와 시작 주소(`01:8CE7`)도 즉값입니다.

## 5. 게임에서 확인

`dq5gfxwritecheck.py` 로 원본과 시험 롬 다섯을 돌렸습니다. 8건 모두 통과했습니다.

| 시험 | 결과 |
| --- | --- |
| 원본 배경 06 | 위 띠 타일 33개·타일맵 512칸·색 35개가 기대와 같음 |
| 배경 제자리 | 칸 하나를 같은 그림의 다른 타일로 바꿔 그림이 원래 크기 안에 들게 함. 표 쓰기 없이 같음, 타일 `30A` 와 팔레트 5 의 1번(`001F`)이 원본 게임과 다름 |
| 배경 다시 놓기 | 그 칸을 줄무늬로 바꿔 그림이 커짐. 같음. VRAM 타일 `30A` 가 넣은 줄무늬(`AA FF 55 FF …`), 원본 게임은 `FF 00 …`·색 `0DC0` |
| 배경 옮김 `--at 40:8000` | 위와 같음 |
| 원본 맵 01/05 | 셀 버퍼 32,640바이트, CHR 슬롯 105개의 VRAM 타일, BG 1~7번 줄 105색이 기대와 같음 |
| 맵 제자리 | 같음. CHR `080` 의 슬롯 `0CD` 가 줄무늬, CGRAM 2번 줄 1번이 `001F`, 블록 654 를 좌우 반전해 셀 12칸이 원본과 다름 |
| 맵 옮김 | 새 CHR `B7A` 로 만든 2×2 블록 1936 을 01/05 의 (4,2) 에 놓음. 셀 버퍼·CHR 슬롯 106개가 같고 새 CHR 이 슬롯 `127` 에 들어감 |
| 맵 옮김, 전투 뒤 | 21/02 통로를 왕복해 무작위 전투(몬스터 `04`)를 붙이고 にげる 로 나옴. 전투 전 700프레임, 나온 뒤 2,100프레임, 명령 창을 연 2,900프레임 모두 CHR 슬롯 143개 가운데 133개가 옮긴 CHR 과 같음 |

21/02 의 나머지 10개는 원본 롬으로 같은 장면을 돌려도 디코더와 다른 같은 번호들입니다. 움직이는 타일로 보이며, 원본과 같은 집합인지를 통과 조건으로 둡니다. 전투가 BG 타일 자리(VRAM `4000`~)를 배경 그림으로 덮었다가 맵으로 돌아올 때 옮긴 뱅크에서 다시 보낸 것입니다. `dq5battleflee.lua` 가 정한 프레임 동안 아래·A 를 눌러 にげる 를 고릅니다.

배경의 아래 띠 타일(`$200`~)은 원본에서도 4개가 디코더와 달랐습니다. 몬스터 그림자가 칠해진 타일이라([전투 배경](../docs/dq5-graphics-format.md#전투-배경)) 바이트 비교에서 빼고 개수만 남깁니다.

## 틀렸던 것들

- 블록을 옮긴 롬을 원본 롬으로 만든 선실 세이브스테이트에서 돌리자, 새 블록 자리의 셀 19바이트가 기대와 달랐습니다. 블록 포인터 표 `7E:B000` 은 맵마다가 아니라 게임을 시작할 때(`00:A6BD` → `01:8CD8`) 만들므로, 세이브스테이트에는 원본 롬의 표가 남아 있었습니다. 그 롬으로 전원부터 선실 상태를 만들자 맞았습니다.
- 맵 CHR 의 VRAM 자리를 슬롯 × 32 로 셌다가 105개 모두 어긋났습니다. 실내 맵 BG 글자 기준이 타일 `200`(VRAM `4000`)이라 슬롯 + `200` 이었습니다.
- 처음 「배경 제자리」 시험은 칸을 줄무늬로 바꿨는데, 그 그림이 5바이트 커져 실제로는 다시 놓기였습니다. 독립 리뷰가 짚어 같은 그림의 다른 타일로 바꾸는 진짜 제자리 시험을 더했습니다.
- 다시 놓기의 자리 순서를 집합 순서에 맡겨 실행마다 패치 목록이 달랐습니다(리뷰). id 순으로 고정했습니다. 다시 놓을 때 표가 가리키지 않는 틈까지 쓰던 것도 원래 자료가 차지하던 바이트만 쓰게 고쳤습니다.
- 배경 비교 도구 `dq5battlebg.py` 는 그림 뱅크를 28 로 두므로 옮긴 롬에서는 엉뚱한 자리를 풀었습니다. 확인 도구에서 `22:CB35` 의 즉값을 따라 풀게 했습니다.

## 남은 것

- 목록·팔레트가 그림이 비운 자리로도 모자랄 때의 옮기기. 표가 16비트라 뱅크 28 안에서만 놓습니다.
- BG 팔레트 줄 늘리기(`10:E5C8` 줄 뒤 56바이트), 그룹 `50` 이상 맵의 블록·CHR, 필드 그림.
- 블록을 옮긴 롬을 이어하기로 켰을 때 블록 표가 다시 만들어지는지. 실측은 새 게임 경로만입니다.
- 옮긴 블록·CHR 로 01/05·21/02 말고 다른 맵, 밤 팔레트, 문을 열거나 상자를 연 뒤는 돌려 보지 않았습니다. `01:9FDF` 가 `$1948` 이 0 이 아닐 때 `7F:4C9D` 에 `16` 을 쓰는데, 이 자리는 필드 세계 지도 버퍼(`7F:0000`~) 안이라 블록 뱅크와는 다른 것으로 보입니다(읽는 곳은 찾지 못함).
