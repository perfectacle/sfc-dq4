# 2026-10-25-49: 필드 68 실측, AI 의 되살리기 대상, 피하기의 앞 조건

주문·몬스터 영역의 남은 것 넷을 마무리하려 했습니다. 몬스터 필드 `68` 을 전투로 확인했고, 파파스가 되살리기 주문의 대상을 고르는 방식과 피하기(필드 `6E`) 갈래의 앞 조건을 읽었습니다. 보통 독은 찾지 못했습니다.
결과는 [dq5-data-format.md 「몬스터」](../docs/dq5-data-format.md#몬스터-238000)·[「주문과 행동」](../docs/dq5-data-format.md#주문과-행동-268765) 에 있습니다.

## 1. 필드 68

[2026-10-25-46](2026-10-25-46-monster3.md) 에서는 슬라임이 メラ 를 고르지 않아 비교하지 못했습니다. 이번에는 슬라임 행동 6개를 모두 メラ 로 하고, 슬롯 MP(`7E:07C4` 등)와 주인공 HP 를 고정하고, パパス 의 행동을 マホトーン 으로 했습니다. 슬라임의 マホトーン 내성(바이트15)은 0 으로 했습니다.
메시지마다 `$10F5`(행동하는 쪽)·`$10F7`(행동)을 적었습니다.

```
68 = 0 : 070 084 ×3 (파파스 マホトーン) → 슬라임 80·81·82 가 매 턴 070 076 「しかし じゅもんは ふうじこめられている！」
68 = 1 : 070 084 ×3 → 슬라임이 행동 73(たたかう)으로 바꿔 05E
```

`68` 이 0 이 아니면 `21:B2D6` 이 주문을 못 쓰는 상태(자신의 상태 `33`)에서 MP 를 쓰는 행동을 후보에서 뺀다는 코드 읽기와 맞습니다.

## 2. 파파스의 되살리기 대상

슬라임 동료가 실제로 쓰러지는 전투(슬라임 공격력을 올림)에서 파파스의 행동을 ザオラル 로 하고 메시지마다 `$10F6` 을 적었습니다. 동료가 쓰러지기 전에는 `02`(동료)를 고른 적이 있지만, 쓰러진 뒤로는 `01`·`00`·`00`·`01` 이었습니다.
AI 의 대상 고르기 `20:A964` 는 슬롯 16개를 돌며 상태 `29` 가 켜진 슬롯만 마스크에 넣고 `00:9546` 으로 하나를 고릅니다. 쓰러진 동료는 이 비트가 꺼져 후보에 들지 않으므로, AI 동료는 되살리기 주문을 써도 쓰러진 쪽을 고르지 못합니다.

## 3. 피하기의 앞 조건

`20:C763` 앞을 거슬러 읽었습니다. 보통 공격 처리(`20:C6C8`~)에서 `$10F6` bit7 로 갈래가 나뉩니다.

- 대상이 몬스터: 대상의 상태 `45`·`2A`·`30`(잠)·`2E` 중 하나라도 켜져 있으면 피하지 않고, 아니면 필드 `6E` 로 1/64·1/16·1/4.
- 대상이 일행: 상태 `02`·`1D`·`08` 을 보고, 필드 `3D` 가 100 이면 1/6, 아니면 1/64.

[2026-10-25-39](2026-10-25-39-shop-sell.md) 에서 피하기 표를 「늘」로 바꾸었는데도 파파스의 공격 일부가 맞은 것은 이 상태 조건 때문으로 보이지만, 그때 상태를 적지 않아 확인하지는 못했습니다.

## 4. 보통 독

맹독은 일행 레코드 `+1` bit4 였습니다. 보통 독을 찾으려고 전투에서 동료 `+1` 에 bit5·3·2·1·0 을 하나씩 켜고 2,500프레임 싸웠지만 메시지도 HP 변화도 없었습니다. 필드에서 주인공 `+1` 에 같은 비트(와 bit4)를 켜고 좌우로 걸어도 HP 가 줄지 않아, 이 시험으로는 독을 가리지 못했습니다.
