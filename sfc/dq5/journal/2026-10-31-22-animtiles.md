# 2026-10-31-22: 세계마다 움직이는 타일 벌, 세계를 오갈 때 바다·타일 벌, ラナルータ 뒤 인물 팔레트, `00:BDC9` 몸통 덜기

[그림 쓰기 일지](2026-10-27-47-gfxwrite.md)부터 이어 온 필드 그림의 남은 것 가운데 다섯을 풀었습니다. 세계마다 다른 움직이는 타일 벌(타일 454~459)을 쓰게 했고, 세계를 오가는 장면에서 그 벌과 움직이는 바다가 다시 만들어지는지 쟀습니다. `01:C62B` 가 도는 장면을 찾았고, ラナルータ 뒤 인물 팔레트를 쟀습니다. 블록 훅에서 부르는 곳이 없어진 `00:BDC9` 몸통도 덜었습니다. 결과는 [쓰기 형식 「필드 그림」](../docs/dq5-build-format.md#필드-그림-dq5fieldgfx1)과 그 실측 절, [필드 형식 「움직이는 바다」](../docs/dq5-field-format.md#움직이는-바다-01c5c8)에 넣었습니다.

## 1. 타일 454~459 를 푸는 곳

`2B:8000` 을 X 16비트로 풀었습니다. 필드를 불러올 때 `01:C5F2` 뒤 `JSL $2B8000` 으로 들어옵니다.

```
2B:8006  LDA #$1E / PHA / PLB / STA $4374     ; RLE 뱅크를 DB 와 DMA 원본 뱅크로
2B:800D  LDX #$C800 / STX $2181 / STZ $2183    ; WRAM 포트 7E:C800
2B:8016  LDX #$D0FF / JSR $8039                ; RLE 를 DMA 로 풂
2B:801C  … DMA 목록 $1C13·$1C20·$1C2A, $1C31 = 0 / PLB / PLP / RTL
```

`2B:8039` 는 `LDA ($09)` 로 RLE 를 DB 에서 읽고 `$4370`~`$4375`·`$420B` 를 절대 주소로 씁니다. 그래서 세계마다 뱅크만 바꾸려면 DB 와 `$4374` 를, 주소까지 바꾸려면 X 를 함께 둬야 합니다. `2B:8016` 의 `LDX #$D0FF / JSR` 첫 4바이트를 `JML` 로 바꾸고, 훅이 셋을 둔 뒤 원래 `JSR` 처럼 `PEA $801B` 로 돌아올 자리를 쌓아 `2B:8039` 로 `JML` 하게 했습니다. `2B:8039` 의 `RTS` 가 `2B:801C` 로 돌아옵니다.

## 2. 도구

`dq5fieldgfxwrite.py` 에 `anim_files` 를 더했습니다. `world1`·`world2` 마다 `anim_file` 과 같은 꼴의 파일이고, 세계 0 과 빠진 세계는 `anim_file` 을 씁니다. 세계 0 과 다른 세계가 있으면 `--anim-worlds-at`(`30`~`3F`)에 훅·고르기 표(`[뱅크 4][주소 4]`)·RLE 를 둡니다. 벌 주소 표와 `AND` 는 세 세계가 같이 쓰므로 벌 수가 다르면 거부합니다. `--anim-at` 으로 16벌로 늘린 것과 함께 쓸 수 있습니다. 이때 세계 0 의 자리는 표가 가리키고, 훅이 덮는 `2B:8017` 에는 쓰지 않습니다. `current()` 는 세계마다 벌(`anim_worlds`)을 읽습니다.

단위 테스트는 합성 롬에서 훅을 해석기로 돌려 세계 0·1·2·3 마다 DB·X·`$4374` 쓰기를 보고, 16벌 롬과 같은 RLE 를 하나만 두는 것, 벌 수가 다를 때의 거부를 봅니다.

## 3. 밟아서 확인

새 도구 `dq5animworldcheck.py` 의 롬 `aw` 는 움직이는 타일을 세계 1 비트 반전·세계 2 XOR `F0` 으로, 바다 원본을 세계 0 비트 반전·세계 1 XOR `0F`·세계 2 XOR `F0` 으로 둡니다.

```
{"case": "stand-w0", "anim_sets_seen": 8, "frames": 136}
{"case": "stand-w1", "anim_sets_seen": 8, "frames": 136}
{"case": "stand-w2", "anim_sets_seen": 8, "frames": 136}
{"case": "rula-world1", "frames": ["1600:1"]}
…
{"case": "chimera-cross", "frames": ["1000:2", "2200:0", "3300:2"]}
{"case": "castle-0608", "frames": ["700:0"]}
{"case": "statue-5250", "frames": ["3900:2"]}
{"case": "ship27-ff", "frames": ["2000:1"]}
14/14 통과
```

- 세 세계에 서서 136프레임 동안 움직이는 타일이 매 프레임 그 세계 벌이었고 8벌이 차례로 다 보였습니다. 바다 타일도 그 세계 16벌이었습니다. 그 두 자리 말고 VRAM `0000`~`7FFF` 는 원본 게임과 같았습니다.
- [세계 이동 일지](2026-10-31-03-worldmeasure.md)의 세계를 오가는 열한 장면(`WORLD_SCENES`)을 `aw` 롬으로 돌렸습니다. ルーラ 넷, 걸어 나가기 둘, キメラのつばさ, 天空城 이륙, 52/50 석상, `$1949` = `FF` 뒤의 둘입니다. 덤프 프레임 15곳 모두 움직이는 타일과 바다 타일이 내린 세계의 벌이었습니다. 두 원본 모두 필드를 불러올 때마다 다시 고릅니다.

## 4. `01:C62B` 가 도는 곳

`02:A2F9` 는 `02:A2D5` 안에 있고, `02:A2D5` 는 맵별 루틴 표에서 17/01(배 갑판)의 맵을 놓은 뒤 루틴이었습니다. `dq5freesweep.py --ranges 01C62B-01C62B --access exec` 로 실내 맵 346곳·필드 셋을 훑자 17/01 과 27/00 에서 들어갈 때 한 번씩 돌았습니다.

```
maps 17_01 frames=600 01C62B-01C62B n=1 first=f376
maps 27_00 frames=600 01C62B-01C62B n=1 first=f590
```

배 위 바다는 실내 타일(`$1C33` 의 포인터로 모은 `7E:3D14`)을 미는 것이라 필드 바다 원본과는 상관없습니다(코드 읽기). 27/00 이 `02:A2D5` 에 닿는 길은 표 밖이고, 롬에서 `02:A2D5` 를 담은 다른 자리 `12:8963` 이 그 길인지는 재지 않았습니다.

## 5. ラナルータ 뒤 인물 팔레트

새 도구 `dq5personpalcheck.py` 는 낮 인물 팔레트를 모두 `001F`, 밤을 모두 `7C00` 으로 둔 롬으로, 세계 0 에서 낮에 ラナルータ 를 두 번 외웁니다.

```
[{"frame": 600, "075E": "0020", "person": "day"}, {"frame": 1750, "075E": "0190", "person": "night"},
 {"frame": 2850, "075E": "0050", "person": "day"}]
```

ラナルータ 로 밤이 되자 CGRAM 11·12번 줄이 밤 팔레트로, 다시 외우자 낮 팔레트로 바뀌었습니다. 원본 게임도 같은 프레임에 `$075E` 가 같았습니다.

## 6. `00:BDC9` 몸통 덜기

`00:BDC5` 는 롬에서 `00:BDC1` 의 `JSR $BDC5` 로만 들어오고, `00:BDC1` 은 `03:CB20` 의 `JSL` 하나뿐입니다(정적 검색). 지형 루틴 `03:CB1B` 의 `PHP` 뒤를 빠른 훅으로 바꾼 롬에서는 그 `JSL` 에 닿지 않습니다. 그래서 `dq5fieldwrite.py` 의 빠른 훅에서 `00:BDC5` 몸통과 `00:BDC9` 의 `JML` 을 뺐습니다. 그래도 불린다면 원래 루틴이 9번째 비트 읽기(`00:BE06`)의 10·11번째 비트 훅을 거쳐 맞는 번호를 냅니다.

`dq5blockgrowcheck.py` 를 10비트(14건)·11비트(`--bits 11`, 22건)로 다시 돌려 모두 통과했습니다. 세 세계 서기·걷기·벽·융단과 세계 1·2 시간대 벌입니다.

## 틀렸던 것들

- 처음 ラナルータ 장면은 `$075E` 가 끝까지 `0020` 이었습니다. 화면을 찍어 보니 「移動中の 呪文を 覚えていない。」였습니다. 시계 장면처럼 `7E:2063` = `FF` 로 주문을 배운 것으로 둬야 했습니다. 시간 멈춤 `7E:2190` bit1 도 꺼 둡니다.
- 덤프를 400프레임에 잡았는데 필드에 내리는 것이 440프레임이었습니다. 덤프를 600·1750·2850 으로 옮겼습니다.

## 남은 것

- 여관에서 묵은 뒤의 인물 팔레트. 필드로 나올 때 불러오기가 `$075E` 로 고르는 것은 시간대 실측과 같은 길로 보이나 장면은 재지 않았습니다.
- 늘린 타일(VRAM `4000`~`5FFF`)을 큰 그림 장면(ベネット 의 지도, ブオーン 이 나타나는 장면)에서 덮지 않는지.
- 엔딩 비행의 스태프 롤이 BG3 글자 자리로 VRAM `4000`~`5FFF` 를 지우는 것과 늘린 필드 타일이 같은 자리를 쓰는 것. 고치려면 스태프 롤 글자 기준을 옮기거나 늘린 타일을 다른 자리에 둬야 해서, 어느 쪽인지 정해야 합니다.
- 27/00 이 `02:A2D5` 에 닿는 길.
