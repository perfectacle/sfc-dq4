# 2026-10-31-25: 작전 AI 의 남은 칸 — 작전 3 거름의 MP, 회복 무게 둘, 범위 A0, 종류 비트

[AI 쓰기 일지](2026-10-27-43-aiwrite.md)에서 받지 않고 남긴 칸을 쟀습니다. 작전 3 이 MP 드는 주문을 빼는 거름(`21:DA58`)은 AI 레코드도 전투 MP 도 아닌 주문 목록 창의 MP 표를 보았습니다. 작전 `+3`·`+4` 와 범위 `A0` 은 게임에서 결정이 바뀌어 `dq5aiwrite.py` 가 받게 했습니다. 행동 `+0` 종류 비트와 범위 `A0`·`C0`·`E0` 은 코드를 읽었습니다. 결과는 [쓰기 형식 「작전 AI」](../docs/dq5-build-format.md#작전-ai학습-배율내성-배율갑옷-원소-dq5ai1)와 [데이터 형식 「작전 AI」](../docs/dq5-data-format.md#작전-ai-21bc6d)에 넣었습니다.

## 1. 작전 3 거름이 보는 MP

`21:DA3A` 부터는 행동자의 주문 칸 여덟을 돕니다. 칸마다 `$42` = 행동자, `$43` = 칸으로 두고 `BRK 88 85` 를 부른 뒤 `$49`·`$47` 을 봅니다.

```
21:DA4F  BRK 88 85                ; $46 = 행동, $47 = MP
21:DA52  LDA $49 / BIT #$FF / BNE 다음
21:DA59  LDA $1211 / CMP #$03 / BNE + / LDA $47 / AND #$FF / BNE 다음   ; 작전 3 이면 MP 가 드는 주문을 뺌
21:DA65  LDA $47 … / CMP $7E412F,X / BEQ 넣기 / BPL 다음                ; 남은 MP 보다 크면 뺌
21:DA77  $1216 = $46 / JSR $DA8B                                          ; 후보 넣기
```

`lua/dq5aicheck.lua` 에 PC 마다 직접 페이지 `$42`~`$4A` 를 적는 `AIPROBE` 를 더해 `21:DA52` 의 값을 보았습니다. マーリン(`$42` = `02`)의 メラ 칸(`$43` = `01`)에서 `$46` = `01`, `$47` = `02` 였습니다. 그런데 전투 MP(`26:8766`)를 0 으로 둔 롬으로 전투를 시작해도 `$47` 은 2 그대로였습니다.

그래서 `AIREADS` 로 `21:DA4F`~`DA52` 사이에 읽은 자리를 모았습니다. 마지막 읽기가 칸마다 `21:9BB5`(メラ)·`21:9BBA`(ベギラゴン) 처럼 행동 번호를 더한 자리였습니다. `21:9BAD` 의 `LDA $219BB4,X` 이고, 주문 목록 창의 MP 숫자 표입니다([`dq5spellgrow.py` 의 `menu_mp`](../docs/dq5-build-format.md#행동-번호-늘리기-dq5spellgrow1)). メラ 칸을 0 으로 둔 롬으로 전투를 시작하자 `$47` = 0 이 되었습니다.

```
menu_mp: 통과 원본 0 변경 6     ; 21:DA77 에 メラ 가 닿은 횟수(작전 3)
```

거름을 지난 뒤에도 점수에서 たたかう 가 앞서, 고른 행동은 그대로 たたかう 였습니다. AI 레코드 `+3` 을 0 으로 둔 롬은 원본과 같이 0번이었습니다. 처음 이 장면은 원본 롬으로 저장한 전투 상태에 고친 롬을 얹어 돌렸는데, 그때도 `$47` 은 2 였습니다. 롬을 바꾼 채로 전투를 다시 시작한 뒤에 0 이 되었으므로 검사는 그렇게 합니다.

## 2. 작전 `+3`·`+4`

[데이터 형식](../docs/dq5-data-format.md#작전-ai-21bc6d)의 회복 점수는 `min(회복량, 최대HP − HP) × +3 + 받을피해 × +5 + (999 − HP) × 256 − MP × +4 × 12` 입니다. 주인공 HP 2 에 최대 HP 250(`7E:204E`)으로 두자 ホイミン 이 ベホマ(`29`)를 골랐습니다.

| 롬(작전 0) | ホイミン |
| --- | --- |
| 원본(`+3` = `FF`, `+4` = `64`) | ベホマ 2 |
| `+3` = 0 | ホイミ 2 |
| `+3` = 8 | ホイミ 2 |
| `+3` = 8, `+4` = 0 | ベホマ 2 |
| `+4` = `FF` | ベホマ 2 |
| `+5` = 0 | ベホマ 2 |

`+3` 을 낮추면 회복량보다 MP 가 앞서 싼 ホイミ 로, 거기서 `+4` 를 0 으로 하면 MP 를 따지지 않아 다시 ベホマ 로 갔습니다. `dq5aiwrite.py` 가 `heal_value`(`+3`)·`heal_mp`(`+4`)를 받게 하고, `dq5aicheck.py` 에 `heal_value`·`heal_mp` 를 더했습니다. `heal_mp` 는 원본이 아니라 `+3` 만 8 로 둔 롬과 견줍니다.

`+5` 는 회복 후보마다 같은 값(받을 피해 × `+5`)을 더해 순위를 바꾸지 못합니다. `+12`(예상 피해 무게)를 `7FFF` 로 둔 롬은 HP 4 에서 원본처럼 회복하지 않았습니다. 이 장면의 예상 피해(`7E:4138` + `413A`)가 0 인 것으로 보입니다(코드 읽기). `+A` 는 メタル 계열 적이 있어야 도는 ドラゴラム 처리기라 재지 않았습니다. 셋은 받지 않습니다.

## 3. 범위 `A0`·`C0`·`E0`

`+4` 의 bit5-7 을 고르는 곳은 둘입니다. 공격 평가 `21:DD47` 은 `00`·`20`·`40`, 회복 평가 `21:EF05` 는 `60`·`80` 만 갈래가 있습니다. 나머지는 `$1213` = `0A` 로 넘깁니다(코드 읽기). 원본 `00`~`AA` 에서 `E0` 31개는 모두 `+0` `11`·갈래 `30`, `A0` 9개는 갈래 `30` 7개·`3B`(ドラゴラム) 1개·`13` 1개, `C0` 1개는 갈래 `06` 입니다.

ギラ 의 범위를 `20` → `A0` 으로 바꾸자 マーリン 은 ギラ 를 한 번도 고르지 않았습니다(원본 1번). `A0` 은 쓰기를 받게 했고, 바꿔 보지 않은 `C0`·`E0` 은 원래 값 그대로만 받습니다.

## 4. 행동 `+0` 종류 비트(코드 읽기)

`21:BC86`(`+0`)을 읽는 곳은 넷입니다.

- `21:D406`(위협 셈 `21:D3FD`): `& 7F` 가 `10` 이상이면 빠집니다. bit3 이 켜지면 `$1227` = 1, 꺼지면 0 인 차례에만 셉니다. 하위 니블로 `21:D58F` 표의 처리기를 고릅니다.
- `21:D74C`: bit7 은 숨 공격입니다(フバーハ 문턱, 원래 알던 것).
- `21:D9E8`: bit7 이면 たたかう(`73`)로 셈하고, 아니면 하위 니블로 `21:DAEE` 표의 처리기를 부릅니다.
- `21:D9FE`: 위와 같은 루틴의 둘째 읽기입니다.

원본 값은 `00`·`01`~`06`·`08`~`0B`·`10`·`11`·`83` 입니다. 바꿔서 결정이 달라지는 장면을 만들지 못해 받지 않습니다.

## 5. 검사

`dq5aicheck.py` 는 변경 롬 스물한 벌과 `menu_mp` 롬으로 22건이 모두 통과했습니다. 원래 있던 결정도 모두 그대로였고, 대조 롬도 원본과 같았습니다.

## 틀렸던 것들

- 작전 3 거름이 전투 MP(`26:8765`)를 보리라 여기고 그 칸을 0 으로 두었습니다. 위 1절대로 `$47` 은 2 그대로였습니다.
- 그다음 원본으로 저장한 전투 상태에 고친 롬을 얹었습니다. 전투 MP 쪽은 전투를 다시 시작해도 같아서 저장 시점 탓이 아니었습니다. `21:9BB4` 를 찾은 뒤에는 롬을 바꾼 채 전투를 다시 시작해 쟀습니다.
- `21:9BDC` 를 0 으로 두고 マーリン 이 바뀌길 기다렸습니다. 그 자리는 ホイミン 칸의 읽기였습니다.
