# 2026-10-26-57: 인물 스크립트 길이를 늘려 목록째 재배치하기

인물 스크립트를 원래 슬롯보다 길게 쓰는 `dq5npcrelocate.py`를 만들었습니다. 기본·대체 인물 목록을 각각 확장 뱅크로 옮기고, 목록을 고르는 포인터와 읽는 뱅크를 함께 바꿉니다. 입력은 [쓰기 형식](../docs/dq5-build-format.md#인물-목록-재배치-dq5npcrelocate1)에 있습니다.

## 1. 명령만 늘리면 다음 인물이 밀린다

기존 `dq5npcwrite.py`는 슬롯 길이를 유지하며 짧아진 명령 뒤를 채웠습니다. 인물 레코드 안에는 길이 바이트와 스크립트가 들어 있으므로, 더 긴 명령을 넣으려면 뒤따르는 인물과 목록도 함께 옮겨야 합니다.

기본 목록 346개와 플래그 대체 목록 293개를 읽었습니다. 합계 639목록·2,483인물 레코드 안에 서로 다른 스크립트 1,034개가 있습니다. 낮·밤이 같은 스크립트를 쓰는 경우는 한 번만 옮기고 공유 관계를 유지합니다. 인물 수·순서와 스크립트 밖의 바이트도 그대로 둡니다.

## 2. 기본·대체 목록의 읽는 뱅크를 나누기

기본 배치는 `32:8000`에 그룹 포인터 54개와 기본 목록을, `33:8000`에 대체 목록을 둡니다. 원본을 그대로 옮겼을 때 각각 20,173바이트·23,986바이트입니다. 각 덩어리는 한 뱅크 안에 들어가야 합니다.

로더의 `12:8021`은 기본 목록 뱅크, `12:8051`은 그룹 포인터 표 주소, `12:833C`는 대체 목록 뱅크입니다. 대체 목록 선택 표 `12:8449`의 296항목도 새 목록 주소로 바꿉니다. 조건·맵 번호는 보존합니다.

`--report`는 목록·인물·스크립트 각각의 옛 주소와 새 주소를 남깁니다. 코드 안의 임의 직접 참조까지 자동으로 고치지는 않습니다. 인물 명령 `04`의 절대 점프도 재배치 대상과 연결할 정보가 없어 거부합니다.

## 3. 원본 보존과 길이 변경 확인하기

원본 목록을 옮긴 뒤 인물 레코드·낮밤 표·스크립트를 다시 읽어 비교했습니다. 스크립트 포인터는 원래 주소와 같아야 하는 값이 아니므로, 주소 대응표로 변환한 예상값과 견줍니다.

게임에서는 기본 맵 346개를 낮밤 각각 불러 원본·재배치 롬을 비교하고, `02/06`의 플래그 대체 목록 낮밤 2건을 더했습니다. 합계 694쌍 모두 통과했습니다. 인물 배치 직후 `12:803C`에서 실제 인물 1,581슬롯의 표 23칸과 활성 스크립트 포인터 649개의 하위·상위·뱅크를 대조했습니다.

## 4. 길어진 스크립트를 실제로 실행하기

선실 파파스 `05:A84F`와 기본 목록의 공유 스크립트 `05:8B2D`, 대체 목록의 공유 스크립트 `10:914F`를 모두 39바이트로 바꿨습니다. 기존 길이는 각각 23·10·3바이트입니다. 앞에 명령을 늘어놓고 마지막에 좌표 `(5,13)`으로 옮긴 뒤 멈추도록 했습니다.

파파스 한 번, 기본 공유·대체 공유를 낮밤 각각 한 번씩 실행한 5건에서 좌표 `(5,13)`·이동 상태 `00`을 확인했습니다. 시간대 값과 마지막 명령의 3바이트 포인터도 새 배치에서 계산한 값과 같았습니다. 대체 목록은 이동 간격 때문에 6,000프레임을 주어 끝까지 기다렸습니다.

`MESENCE`를 설정하고 다음 명령으로 기본 맵의 낮밤 전수 비교와 긴 스크립트 실행을 재현합니다. `--all`을 빼면 대표 장면 8쌍만 비교합니다. 결과·덤프·시험 롬은 출력 폴더의 새 하위 폴더에 남습니다.

```sh
uv run --locked python sfc/dq5/tools/dq5npcrelocatecheck.py rom/dq5.sfc \
  --state work/state/ship.mss --out work/npc-relocate-check --all --mutations --jobs 6
```

## 5. 다른 쓰기 도구와 한 롬에 합치기

필드 세 세계를 기본 `34:8000`, 인물 목록을 `32:8000`·`33:8000`, 보행 대사를 `38:8000`에 놓고, 주인공 성장값 한 항목도 바꾸어 네 패치 목록을 한 4MB 롬으로 만들었습니다. 쓰기 329개·230,018바이트가 겹치지 않았고, 원본에 IPS를 붙인 결과와 생성 롬의 차이는 0바이트였습니다.

합성 롬의 메시지 3,200개를 다시 읽어 원본과 같음을 확인했습니다. 선실 세이브스테이트에서 파파스에게 말 걸었을 때 게임 디코더가 돌려준 64코드도 같았습니다. 이 대화 검사는 세이브스테이트의 기존 인물 상태를 쓰므로 인물 목록 재로드 검사는 아닙니다. 재로드는 앞의 694쌍에서 따로 확인했습니다.

## 남은 것

인물 수·순서·등장 조건을 편집하거나 새 목록을 추가하는 기능은 없습니다. 각 영역이 한 뱅크를 넘는 배치와 `04` 절대 점프를 포함한 스크립트도 지원하지 않습니다.
