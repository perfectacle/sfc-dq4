# 2026-10-25-85: 인물 스크립트 명령 실측 2

[인물 스크립트 명령 실측](2026-10-25-75-npc-script2.md)에서 처리 루틴만 읽고 남긴 명령을 같은 실험대로 하나씩 돌렸습니다. 인물 표 `32A0`·`33A0` 비트를 바꿔 화면도 봤고,
첫 장면 재현과 나머지 둘째 루틴은 어디까지 갔는지 적습니다. 결과는 [dq5-map-format.md 「인라인 스크립트」](../docs/dq5-map-format.md#인라인-스크립트-01c800)에 있습니다.

## 1. 실험대를 넓게 보기

배 선실 파파스(`05:A848`, 슬롯 08) 스크립트를 `2B 05 0D <명령> 16` 으로 덮고, 인물 표 64칸(`7E:3000`~`37E0` 의 슬롯 08)과 `19AE` 를 `tools/lua/wlog.lua` 로 적었습니다.
도착 직후 표가 채워지는 프레임(f326)과 순간이동(f354) 뒤에 바뀐 칸만 추리면 명령마다 이렇게 나옵니다.

```
1C   c33A0:30>31          22   (33A0 bit0 이 이미 0)        1F   c31C0:00>02
23 03 c3240:02>83 c3260:02>83   2E 03 c3260:02>83            27   c3380:00>80
35 30 c32C0:F0>30          39 05 c3180:00>05   3A 05 c3180:00>FB   1E 04 c3360:01>04
3F   f19AE:00>01           0B   f19AE:00>80 (8프레임 뒤 00)   47   c33A0:30>36
2A   f385 c3380:00>80, f386 X·Y 80        2C·2D  X·Y 를 0,0(나타날 자리를 안 정함)
34   스크립트 주소가 34 에서 멈춤
```

표 값만으로는 뜻을 모르는 것은 실험을 따로 짰습니다.

## 2. 부딪힘과 비켜 주기

주인공(9,11) 왼쪽 (5,11) 에 파파스를 세우고 주인공이 왼쪽으로 걸었습니다.

| 파파스 스크립트 | 주인공이 멈춘 곳 |
| --- | --- |
| `2B 05 0B` | (1,11) — 파파스를 지나감 |
| `2B 05 0B 12` | (7,11) |
| `2B 03 0B 13 05 0B 14` | (7,11) |
| `2B 05 0B 1F 1B` | (1,11), 파파스는 앞으로 밀려 가다 (1,9) 로 비킴 |

`2B` 순간이동은 셀에 자리를 남기지 않고, `12` 가 두 셀 `+0` 에 층 마스크를 OR 해(`00:DF53`) 막습니다. 걷기(`13`·`14`)는 스스로 자리를 옮겨 적습니다.
`1B` 는 애니메이션을 끄고 그 자리에 머무는 명령인데, `31C0` bit1(`1F`)이 켜져 있으면 매 프레임 `01:CDE4` 를 돌아 주인공에게 비켜 줍니다.

거꾸로 파파스가 주인공 쪽으로 걸으면 `1C` 가 없을 때는 주인공 앞 (7,11) 에서 서고, `1C`(`33A0` bit0)가 있으면 주인공을 지나 (13,11) 까지 갔습니다.

## 3. 조작 막기, 창, 문

- `3F` 뒤 `16` 으로 머물면 주인공이 왼쪽을 눌러도 (9,11) 그대로였고, `3F 40` 이면 (1,11) 까지 걸었습니다. `19AE` bit0 이 주인공 조작을 막습니다.
- `0B` 를 255번 되풀이해 `19AE` bit7 을 켠 채 두어도 주인공은 걸었습니다. bit7 의 뜻은 남깁니다.
- `34` 는 A 를 누를 때까지 다음으로 넘어가지 않았고, 누르자 뒤의 순간이동을 했습니다. `33` 은 바로 넘어갑니다. 처리 루틴은 `BRK 95 00`(창 열기)과 `BRK 0E`·`BRK 95 FF` 입니다.
- 문 명령의 넷째 바이트는 `7E:1E8E` 로 갑니다. 01/05 문에서 `00`·`01`·`02`·`28`·`80` 을 줘도 문 셀 `+1` 은 모두 `31` 이 되어 결과가 같았습니다. 읽는 곳은 `01:DAEF`($BD = 0 일 때)와 `01:ED05`(셀 `+1` 에 OR)라, 다른 맵에서 쓰일 것으로 보입니다.

## 4. 자세, 높이, 속도

`23 n` 을 0~7 로 바꿔 서 있는 파파스를 찍으니 여덟 그림이 모두 달랐습니다. `3240`·`3260` 이 n | `80` 이 되고 걷지 않는 동안 그 자세로 섭니다.
`23 03` 뒤에 `0D` 를 두면 둘 다 `03` 으로, `0E` 면 `3240` 만, `0F` 면(파파스는 `32A0` bit6 이 켜짐) `3260` 만 위 니블이 지워졌습니다.

`39 05`·`3A 05` 는 서 있는 파파스와 안 보이게 한 화면의 차이를 보면 그림 윗변이 112 → 107·117 로 5픽셀씩 움직였습니다. `3180` 은 그림을 그리는 높이입니다.

`1E 04` 는 한 칸에 2프레임, 기본 `01` 은 8프레임 걸렸습니다.

## 5. 사라지기·나타나기 효과

`2A` 는 `03:AE3F` 를 부른 뒤 31프레임째에 X·Y 를 `80` 으로 치웠고, 그동안 화면에는 불꽃 같은 그림이 줄어들었습니다. `2C`·`2D` 는 `50` 으로 정한 자리로 옮긴 뒤 `03:AE8D` 를 부릅니다.
`50` 없이 쓰면 (0,0) 으로 갑니다.

## 6. 인물 표 비트를 화면으로

`POKE` 로 매 프레임 값을 고정하고 서 있는 화면, 걷는 중의 화면을 바탕과 견줬습니다(다른 픽셀 수).

| 고정한 값 | 서 있을 때 | 걷는 중 |
| --- | --- | --- |
| `32A0` = `21`(bit6 끔) | 270 — 타일이 엇갈린 그림 | |
| `32A0` = `60`(bit0 끔) | 0 | 84~88 — 다리 그림만 다름 |
| `33A0` = `38`(bit3) | 0 | |
| `33A0` = `34` / `36` | 115 / 0 | 0 / 48 |

bit6 은 그림 표 `25:86D0` 를 따르는 타일 배치의 종류로 보이고, bit0 과 `33A0` bit1-2 는 걷기·서기 그림 고르기에 끼어드는 것으로 보이지만 규칙은 아직 모릅니다.

## 7. 첫 장면과 나머지 둘째 루틴

배 선실 세이브스테이트의 `21A1` 은 이미 `71`(깨어난 뒤)이었습니다. `21A1` 을 0 으로 쓰고 사다리로 17/00 에 다시 들어가니 침대의 인물(슬롯 09)이 버튼 없이 3프레임 만에 사라졌고,
`05:A874` 는 놓이지 않았습니다. 다른 이야기 플래그가 이미 진행된 상태라, 첫 장면을 다시 보려면 새로 시작한 세이브스테이트가 필요합니다.

둘째 루틴은 `03:D4B5`·`02:AE55` 밖에 39개가 있습니다. 형식 문서에 쓰는 맵과 함께 목록만 두었습니다.

## 틀렸던 것들

- 처음 몽타주에서 `27` 뒤에도 파파스가 보이는 줄 알았는데, 자른 칸이 주인공이었습니다. 같은 자리를 다시 자르자 `27` 도 `51` 처럼 보이지 않았습니다.
- `1D 40` 뒤 `3300` 이 0 이라 `1D` 가 듣지 않는 줄 알았는데, 실험 스크립트 끝의 `16`(이동 간격을 0 으로 쓰는 명령)이 덮은 것으로 보여 `1D` 는 남은 것에 둡니다.
