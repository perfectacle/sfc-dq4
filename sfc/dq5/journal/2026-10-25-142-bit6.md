# 2026-10-25-142: 셀 +1 bit6 은 층 2 인물의 우선순위를 묶어 둔다, $194C 의 나머지 값

맵 형식 문서 「남은 것」의 마지막 줄(셀 `+1` bit6)과, 코드 읽기로만 두었던 `$194C` 의 나머지 값을 실측으로 닫았습니다. 결과는 [dq5-map-format.md](../docs/dq5-map-format.md) 의 셀 `+1` 표와 「매 프레임 루틴 39개」의 `$194C` 줄에 있습니다.

## 1. bit6 이 결과를 바꾸는 조건

앞서 18/00 계단에서 bit6 을 지워도 화면이 같았던 것은 주인공이 층 1 이었기 때문입니다. 인물 우선순위를 정하는 `2B:B8F3`~`B934` 를 다시 읽었습니다. 칸마다 셀 `+1` 을 `$A1` 에 두고, 인물 층 `$97`(`01`·`02`·`04`)을 색인으로 두 표를 씁니다.

```
+1 & B80C[$97] >= $97          → bit3 을 켜고 끝            B80C = (층1) 06, (층2) 04, (층4) 00
+0 bit3                        → $03 = 10 (우선순위 3 으로)
+1 & 78 (bit3~6) != 0          → 건너뜀, $03 = +1 & 30
+1 & B810[$97] 이 0 이 아니고 $97 보다 작고 +5|+6 != 0
                               → $03 = 10                    B810 = (층1) 00, (층2) 01, (층4) 03
```

뒤의 `2B:BB0B` 는 `$03` 이 `10` 이면 그 줄 OBJ 에 `30`(우선순위 3)을 씁니다. 0 이면 이웃 칸 `$02` 를 보고 `20` 으로 둘 수 있습니다.
bit6 은 셋째 줄의 `AND #$78` 에만 들어가므로, bit6 만 켜진 칸은 넷째 줄로 가지 못해 우선순위를 3 으로 올리지 않습니다. 넷째 줄은 층 1 이면 `B810` 이 0 이라 늘 실패합니다. 그래서 bit6 이 갈림을 바꾸는 것은 층 2·4 의 인물뿐입니다.

롬 맵을 풀어 층 2 에서 조건에 맞는 칸을 세니 21개 맵에 191개였습니다. `+0` bit3 꺼짐, `+1` 이 bit0 켜짐·bit2 꺼짐·bit3~5 꺼짐·bit6 켜짐, `+5`·`+6` 이 0 이 아닌 칸입니다. 18/00 의 (24,62)·(25,62)(`+1` = `43`)가 그런 칸입니다.

## 2. 실측

18/00 (27,62) 에 층 2 로 섰습니다(`TO=18/00,27,62,2`). 왼쪽으로 그 칸들을 지나갔다가 돌아오는 같은 입력을 두 번 넣었습니다. 한 번은 그대로, 한 번은 191칸의 `+1` 에서 bit6 만 지운 값을 `POKE` 로 매 프레임 고정했습니다.

```
덤프 25  주인공 (25,62)  OAM 5B: 20 / 30   7E:1AB9: 20 / 30
덤프 30  주인공 (24,61)  OAM 7B: 20 / 30
덤프 47  주인공 (24,62)  OAM 3B·3F: 20 / 30
VRAM·CGRAM 차이 없음
```

bit6 이 있으면 주인공 OBJ 몇 줄이 우선순위 2 로 남고, 지우면 3 으로 올라갔습니다. 그 자리의 화면은 눈으로 같았습니다.

## 3. `$194C` 의 나머지 값

18/00 루틴을 막고 `POKE="7E194C=…"` 로 고정한 채, 병사를 주인공 칸에 겹친 앞 일지의 실험을 다른 값으로 되풀이했습니다.

```
00 과 03·80·FF        OAM 같음(1·2 가 아니면 0 의 갈래)
00 과 02, 일행 둘     PARTY=02,05 로 걸으면 OAM 30~CF 의 순서가 다름
```

`00:EB60` 은 1·2 와만 견주므로 다른 값은 모두 0 처럼 갑니다. 0 과 2 는 일행 슬롯끼리 겹칠 때 갈립니다. 0 이면 Y 로만, 2 면 층 값 `38A0` 을 먼저 봅니다. 병사(일행이 아닌 슬롯)와 겹친 앞 실험에서는 0 과 2 가 같았습니다.
