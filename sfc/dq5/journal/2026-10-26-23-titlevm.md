# 2026-10-26-23: 오프닝 타이틀을 롬 코드로 돌려 그리기

[2026-10-26-11](2026-10-26-11-titlehdma.md)에서 물결·BG4 HDMA 표와 링 반짝이를 롬만으로 계산했지만, 로고 밝히기·성·V·링을 한 타임라인에 겹쳐 연출 전체를 그리는 일이 남았습니다. 층마다 흉내 내는 대신, 전투 연출에서 쓴 65C816 해석기(`w65816.py`)로 타이틀 고리를 롬 코드 그대로 돌리고 그 결과를 작은 PPU 렌더러로 그렸습니다. 결과는 [dq5-graphics-format.md 「롬 코드로 그린 타이틀」](../docs/dq5-graphics-format.md#롬-코드로-그린-타이틀-dq5titlevmpy)에 있습니다.

## 1. 렌더러부터

작은 PPU 렌더러(모드 0·1, 창 둘, 색 더하기, 밝기, OBJ, HDMA 표로 줄마다 스크롤·창)를 먼저 만들어 확인했습니다. 타이틀 세이브스테이트에서 프레임마다 남긴 VRAM·CGRAM·OAM·WRAM·PPU 상태로 그린 그림이 같은 프레임 화면과 50프레임 간격 26장 모두 화소째 같았습니다. 이것을 `sfc/dq5/tools/dq5ppu.py` 로 옮겼습니다.

## 2. 상태 한 벌에서 돌리기

`lua/dq5titlesnap.lua` 로 타이틀 고리가 처음 `00:969A` 에 닿은 때의 상태를 한 벌 남기고, 해석기가 거기서부터 돕니다. `00:969A` 마다 NMI 처리기를 롬 코드로 돌리고, 해석기가 쓴 PPU 레지스터를 MesenCE 상태 키로 옮겨 그립니다.

처음 40프레임은 바로 맞았습니다. 1,240프레임으로 늘리자 172프레임부터 어긋났습니다. 98프레임에 화면을 바꾸며 BG 모드·타일맵·창·색 더하기 레지스터를 새로 쓰는데 그것을 옮기지 않았고, `$2180` WRAM 포트도 해석기에 없었습니다. 둘을 더하자 431프레임까지 맞았습니다.

## 3. 지연 프레임

432프레임부터는 VRAM·CGRAM·OAM·PPU 상태가 모두 같은데 WRAM 의 `$075B`(프레임 수)와 `$71`(물결 각도)이 달랐습니다. 게임에서 `00:969A` 가 불린 프레임 번호를 적어 보니, 1,250번 동안 기다림 없이 지나간 프레임이 22곳에 있었습니다.

```
(3, 4, 7, 3), (6, 9, 12, 3), (9, 14, 16, 2), … (204, 227, 229, 2), (336, 360, 380, 20)
```

처리가 한 프레임을 넘기면 NMI 가 처리 도중에 들어와 `$075B` 를 올립니다. 해석기는 기다림에서만 NMI 를 돌려 이 수가 모자랐습니다. 마지막 20은 물결 준비 고리(`MVP` 로 478바이트씩 240번)입니다.

처음에는 걸음 수로 프레임 길이를 어림했습니다. 일반 명령만 도는 프레임에서 13,790걸음은 넘기고 11,864걸음은 안 넘겼고, 준비 고리 프레임은 `MVP` 114,720걸음이 섞였습니다. 일반 8, `MVP` 바이트 15, 한 프레임 99,200 으로 두자 지연 수가 맞아 431프레임까지 같았습니다. 그래도 물결 각도는 몇 도 어긋났습니다. 준비 고리는 반복마다 `$075B` 를 더하는데, 반복 몇 째에 NMI 가 끼는지가 달랐습니다.

```
362 L vm 209  game 209
366 L vm 184  game 161
```

그래서 어림을 버리고 메모리 접근마다 마스터 주기를 셌습니다. ROM·WRAM 8, I/O 6, 명령마다 메모리에 닿지 않는 내부 주기를 65C816 주기 표대로 6씩 더했습니다. 내부 주기를 빼면 지연이 모자랐고, 명령마다 1씩 넣으면 넘쳤습니다. 표대로 넣자 기다림·지연 순서가 게임과 같아졌고, 세이브스테이트에서 돌린 1,285프레임이 모두 화소째 같았습니다.

## 4. 에셋 GIF 와 견주기

`dq5titlegif.py` 와 같은 입력으로 전원부터 돌려 5,562프레임 뒤 스냅숏을 떴습니다(`BOOT=1`). 에셋의 GIF 342장 가운데 328장(5,570~6,760)이 같았습니다.

남은 14장은 이 실행이 40프레임마다 누르는 A 로 타이틀이 끝나 어두워지는 부분입니다. 해석기에 같은 A 입력을 넣자 어두워지기 시작했습니다. 다만 입력 프레임을 몇 프레임 옮겨야 덤프와 가까웠고, 그래도 단계가 맞지 않았습니다.

## 틀렸던 것들

- 세이브스테이트 실행과 전원부터 실행의 WRAM 이 `7E:08D6`~`0970` 에서 계속 달라, 처음에는 스냅숏 앞 이력이 달라서 끝 14장이 갈린다고 봤습니다. 전원부터 실행에서 스냅숏을 떠도 같았습니다. 이 자리는 덤프 시점(프레임 끝)과 해석기 시점(`00:969A`)의 차이로 보입니다.
- 걸음 수 어림으로 지연 수를 맞추면 된다고 봤지만, 준비 고리 반복 안의 NMI 자리까지 맞아야 했습니다.

## 남은 것

- A 로 타이틀이 끝나는 14장(입력 시점과 어두워지는 단계).
- 스냅숏 없이 전원부터 롬 코드로: 소리 칩과 주고받는 부분과 SRAM 이 남습니다.
