# 2026-10-27-19: 인물 수를 바꾸고 등장 조건 표를 옮기기

[지난 일지](2026-10-27-14-npcrecord.md)에서는 기존 인물 엔트리만 제자리에서 고쳤습니다. 이번에는 인물 슬롯 번호(`$81`)가 어디까지 쓰이는지 코드와 게임으로 확인했습니다. 그 결과로 `dq5npcrelocate.py` 가 목록의 인물 수·순서를 바꾸고, 새 대체 목록을 더하고, 등장 조건 표 두 개를 통째로 다시 쓰게 했습니다. 대체 표는 뱅크 12 밖으로 옮겼습니다. 형식은 [맵 형식의 인물 슬롯](../docs/dq5-map-format.md#인물-슬롯-81)과 [쓰기 형식](../docs/dq5-build-format.md#인물-수순서와-조건-표-listsnew_listsoverridesno_npc)에 있습니다.

## 1. 인물 뒤에 누가 슬롯을 쓰나

지난번에는 `1F:D4A7`·`16:F607` 이 인물 뒤에 같은 슬롯 번호로 물체를 놓는지 모른다고 적었습니다. 읽어 보니 `1F:D4A7` 은 맵 OBJ 타일을 VRAM 에 올리기만 합니다. 이어 부르는 `03:F195` 는 맵이 1E/00 일 때만 VRAM 을 더 쓰고, 읽은 범위에서 `$81` 은 건드리지 않았습니다(1E/00 의 물체 수도 아래 셈과 같았음). `$81` 을 늘리는 것은 `16:F607` 입니다. 맵 OBJ 물체 표 `16:F862` 에서 맵에 맞는 항목마다 `INC $81`(`16:F6E9`·`16:F7D1`)을 하고, 끝난 값을 `00:E1C9` 가 `7E:1983` 에 남깁니다. 물체 항목 `+4` bit7 이면 `21:8000` 의 낮밤(`7E:075E` ≥ `F0`)으로 놓을지 정합니다.

그래서 맵을 다 놓은 뒤의 슬롯은 「8 + 인물 수 + 물체 수」로 셀 수 있습니다. 물체가 있는 33개 맵에 원본 롬으로 낮·밤 한 번씩 들어가, 맵을 다 놓은 직후(`00:E1CC`)의 `7E:1983` 에서 인물 뒤 `$81` 을 뺀 수가 66장면 모두 셈과 같은 것을 확인했습니다. 낮밤으로 고르는 실내 항목은 00/00 의 낮 전용·밤 전용 하나씩뿐이라, 수는 맞지만 어느 쪽이 놓였는지는 보지 않았습니다.

```
objects-0702: 인물 끝 0C 다음 빈 슬롯 14 물체 8(예측 8)
objects-5453: 인물 끝 08 다음 빈 슬롯 16 물체 14(예측 14)
```

원본의 모든 맵·목록·낮밤을 이 셈으로 보면 최댓값은 `1F` 입니다(19/02 낮·밤과 03/05 낮, 인물 23명). 인물 표 한 칸은 `$20` 슬롯이라 `$81` 이 `20` 을 넘으면 다음 칸을 덮습니다.

맵을 놓은 뒤에도 `$1983` 부터 슬롯을 더 쓰는 코드가 있습니다. `04:FB1C` 는 `$1983` 슬롯에 인물을 하나 만들고 `$1983` 을 늘립니다(부르는 곳 7개, 이벤트 뱅크 02·05·대화 06). `01:BA95` 는 `$1983` 부터 네 슬롯을 씁니다. 이것들이 어느 맵에서 도는지는 정리하지 않았습니다. 그래서 쓰기 도구는 기본으로 맵마다 원본이 같은 시간대에 쓰던 최댓값까지만 받습니다. `--allow-growth` 를 주면 원본 전체 최댓값 `1F` 까지 받고, 늘어난 맵을 출력합니다.

## 2. 대체 표를 뱅크 12 밖으로

대체 표 `12:8449` 를 읽는 곳은 `12:82FB` 하나입니다. 롬에서 `$8449`~`$844E` 피연산자를 찾아도 이 루틴의 여섯 명령뿐이었고, 부르는 곳도 `12:8015` 하나였습니다. 루틴은 `PHK`·`PLB` 로 데이터 뱅크를 12 로 두고 `$8449,Y` 로 읽으며, 뱅크 12 끝 빈 자리는 336바이트라 1,777바이트 표가 들어가지 않습니다.

`12:82FB` 다섯 바이트를 `JSL 새 루틴; RTS` 로 덮었습니다. 새 루틴은 `--alt` 뱅크의 대체 목록과 표 뒤에 102바이트로 놓입니다. 데이터 뱅크는 `7E` 로 두어 플래그를 `$2190,Y` 로 읽고, 표는 긴 주소 `LDA long,X`·`AND long,X` 로 읽습니다. 그래서 확장 뱅크의 `0000`~`7FFF` 가 WRAM·MMIO 거울이라는 점에 걸리지 않습니다. 결과는 원래처럼 `$A5`~`$A7` 과 캐리로 돌려줍니다. 원래 루틴도 `TDC`·`TAY` 로 `Y` 를 0 으로 만들므로 직접 페이지가 0 이라고 보고 있었고, 새 루틴도 `$00`·`$A5`·`$BC`·`$BD` 를 같은 직접 페이지로 씁니다.

빈 맵 표 `12:839C` 는 `12:8357` 이 8비트 `Y` 로 4바이트씩 읽다 `BNE` 로 돌아가므로 64항목에서 끝납니다. 대체 표를 옮기면 바로 뒤가 비므로 63항목과 종료자까지 제자리에서 늘립니다.

## 3. 목록 구조

`lists` 는 원본 목록 하나를 「어느 엔트리를 어떤 차례로」로 다시 적습니다. 빠진 엔트리는 지워지고, 같은 엔트리를 두 번 쓰면 복사됩니다. 사본에는 `dq5npcrecord/1` 의 필드 수정을 붙일 수 있습니다. 새 엔트리를 처음부터 만들지 않고 원본을 복사하게 한 것은, 기타 bit3-7 처럼 뜻을 다 모르는 비트를 원본에 있던 값으로 두기 위해서입니다. `new_lists` 는 같은 방식으로 새 대체 목록을 만들고, `overrides` 에서 `new:이름` 으로 가리킵니다.

아무 키도 주지 않았을 때 새 도구의 패치 목록은 고치기 전 도구의 것과 바이트까지 같았고, `check` 도 그대로 통과했습니다.

## 4. 게임에서

`dq5npclistcheck.py` 가 롬 세 벌을 원본과 함께 10장면 돌립니다. 인물 목록 로더 직후의 인물 표 23칸, 목록 끝 주소(`$A5`~`$A7`, 로더가 끝 `00` 을 가리킨 채 멈춤), 맵을 다 놓은 직후의 `7E:1983` 을 롬에서 예측한 값과 견줍니다.

```
count-day: 목록 3286EF 인물 3 슬롯 0B/0B(예측 0B) 끝 32874E/32874E 표 불일치 0 메시지 1D1,6C6
count-night: 목록 3286EF 인물 0 슬롯 08/08(예측 08) 끝 32874E/32874E 표 불일치 0 메시지 -
table-day: 목록 33DDB2 인물 2 슬롯 0A/0A(예측 0A) 끝 33DDDA/33DDDA 표 불일치 0 메시지 1D1,6C6
table-0101: 목록 None 인물 0 슬롯 08/08(예측 08) 끝 3282C8/None 표 불일치 0 메시지 -
table-2100: 목록 33CB92 인물 10 슬롯 12/12(예측 12) 끝 33CD02/33CD02 표 불일치 0 메시지 -
growth-day: 목록 3286EF 인물 23 슬롯 1F/1F(예측 1F) 끝 3287DA/3287DA 표 불일치 0 메시지 1D1,6C6
```

- 02/06 기본 목록을 [둘째, 첫째, 밤 인물을 낮·(24,12)·대화 `300` 으로 바꾼 사본] 으로 쓰자, 낮에 3명이 그 차례로 섰습니다. 두 칸 아래에서 말을 걸자 메시지 `6C6` 이 나왔습니다. 밤에는 아무도 없었습니다(원본은 낮 2명·밤 2명).
- 대체 표를 옮기고 맨 앞에 「02/06, `7E:21AD` bit4 꺼짐 → 새 목록」을 더하자, 선실 상태에서 새 목록 2명이 놓이고 더한 인물이 메시지 `6C6` 을 띄웠습니다. 빈 맵 표 44번째 항목으로 더한 01/01 은 인물을 놓지 않았습니다(원본 5명). 옮긴 표의 원래 항목인 21/00 → `10:CB92` 도 옮긴 사본의 10명으로 그대로 골라졌습니다.
- `--allow-growth` 로 02/06 낮을 23명으로 채우자 `7E:1983` 이 `1F` 였고, 원본에서 가장 많이 쓰던 슬롯까지 인물이 다 놓이고 말도 걸렸습니다.

## 틀렸던 것들

- 지난 일지에서는 `1F:D4A7`·`16:F607` 둘 다 같은 `$81` 로 물체를 놓을 수 있다고 보았습니다. 실제로 슬롯을 쓰는 것은 `16:F607` 뿐이고, `1F:D4A7` 은 VRAM 만 씁니다.

## 남은 것

- 맵을 놓은 뒤 `$1983` 부터 슬롯을 더 쓰는 `04:FB1C`(부르는 곳 7개)·`01:BA95` 가 어느 맵·장면에서 도는지, 그리고 슬롯 번호를 직접 쓰는 이벤트 코드(`02:AE7F`·`02:AFBC` 등)가 어느 맵의 어느 인물을 가리키는지. 정리되면 맵마다 슬롯 한도를 원본 최댓값 대신 실제 여유로 정할 수 있습니다.
- 슬롯 `1F` 를 넘기는 배치(`20` 이상)가 실제로 다음 칸을 덮는지는 시험하지 않았습니다. 도구가 받지 않습니다.
- `01:BA95` 는 `$1983` 부터 네 슬롯을 씁니다. 원본에서도 19/02·03/05 는 `1F` 까지 차므로, 그 맵에서 `01:BA95` 가 도는 장면이 있는지와 `--allow-growth` 의 한도를 `1F` − 4 로 둘지가 남았습니다.
