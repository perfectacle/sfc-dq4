# 2026-10-25-12: 이벤트 전투 무리 표와 롬 밖 뱅크 실행 감시

[장면 이동 도구](2026-10-25-08-warp.md)의 `BATTLE` 은 첫 필드 이벤트의 무리 1번을 덮어 쓰는 방식이라, 게임에 이미 있는 보스 전투를 그대로 부를 수 없었습니다.
그 무리 표(`23:D757`)를 풀어 번호만 주면 그 무리와 싸우게 했고, 남겨 둔 질문인 「디버그 입구 말고도 롬 밖 뱅크 `30`~`3F` 로 뛰는 코드가 있는가」를 실행 감시로 확인했습니다.

## 1. 무리 번호를 넣는 곳

필드 이벤트 루틴 `02:A775` 는 이렇게 시작합니다.

```
02:A77B  LDA #$06 / STA $1AA0
02:A780  LDA #$01            ; 무리 번호
02:A782  JSL $0186A7
```

`01:86A7` → `01:8608` → `26:8DF1` → `26:8E0A` 를 따라가면 A 를 `$100D` 에 두고 `A × 13` 으로 `23:D757` 의 레코드 13바이트를 `$1000`~`$100C` 로 옮깁니다. 첫 바이트만 `& FC` 합니다.
그러니 `02:A781`(파일 오프셋 `12781`)의 즉값 한 바이트를 바꾸면 그 번호의 무리와 싸웁니다. `dq5warp.lua` 에 `GROUP=번호` 로 넣었습니다.

## 2. 무리 표 `23:D757`

레코드는 `[+0 플래그][+1~+4 몬스터, 빈 자리 FF][+5~+8 마릿수][+9~+C]` 입니다. `00`~`3F` 의 64개가 이 꼴에 맞고, `40` 부터는 마릿수 자리에 `FF` 가 나와 다른 데이터로 보입니다.
`+9`~`+C` 는 64개 모두 `00` 입니다. `dq5encounter.py --events` 가 표를 풉니다.

```
01 플래그 D0  スライム(00) 3                     ; 첫 필드 이벤트
08 플래그 C0  ゲマ(2C) 1
2C 플래그 C2  エスターク(E5) 1
30~3A 플래그 C0  スライム(00) 1                   ; 같은 레코드 11개
3D 플래그 C0  メタルスライム(2D) 3, メラリザード(0D) 1
3E 플래그 00  スライム(6A) 8
```

롬에서 `LDA #imm / JSL $0186A7` 은 3곳(무리 `01`·`02`·`0B`), 거의 같은 입구 `01:86C3` 을 부르는 곳은 21곳(무리 `11`~`2F`)입니다(정적 검색). 무리 `30`~`3F` 를 즉값으로 부르는 곳은 이 검색에 없었습니다.

`GROUP` 으로 네 무리를 불러 보았습니다. 명령은 `FIELD=341,56 GROUP=<번호> SETTLE=300` 입니다.

| 무리 | 전투 화면 |
| --- | --- |
| `08` | 「ゲマ − 1ひき」 |
| `2C` | 「エスタークが あらわれた！」 |
| `3D` | 「メタルスライム − 3ひき」「メラリザード − 1ひき」 |
| `3E` | 「スライム − 7ひき」, 그림도 7마리 |

`3E` 는 표에 8마리인데 7마리가 나왔습니다. 플래그 탓인지 몬스터 탓인지 가르려고 둘을 바꿔 보았습니다.

| 명령 | 결과 |
| --- | --- |
| `BATTLE="6A:8"`(무리 1번, 플래그 `D0`) | 7마리 |
| `GROUP=3E BATTLE="00:8"`(무리 `3E`, 플래그 `00`) | 8마리 |
| `BATTLE="00:9"` | 9마리 |

몬스터 `6A` 에 따른 것입니다. 이름이 같은 スライム `00` 은 9마리까지 나왔습니다. [「전투 조우」](../../dq5-data-format.md#전투-조우-23e7c2)의 「큰 몬스터는 화면에 그만큼 나오지 않는다」와 같은 줄일 수 있는데, `6A` 는 그림이 `00` 과 같아 보이는데도 줄었습니다.

## 3. 롬 밖 뱅크로 뛰는 코드

디버그 입구 `2B:848A` 는 `JSL $309495` 로 롬에 없는 뱅크 `30` 으로 뜁니다. 같은 꼴의 바이트(`22 xx xx 3x`)는 롬 전체에 수백 개라 정적으로는 거를 수 없어서, 실행 감시로 보았습니다.
`cover.lua` 의 범위를 `LO=300000 HI=FFFFFF` 로 주면 뱅크 `30` 이상(롬 밖 `30`~`3F`, WRAM `7E`·`7F`, 미러 `80` 이상)에서 실행된 명령이 모두 남습니다.

먼저 감시가 제대로 걸리는지 보았습니다. `dq5warp.lua` 를 드라이버로 두고, 필드에 도착해 SELECT 를 30프레임 눌렀습니다.

```sh
export LIBDIR=$(tools/lua/seqlib.sh "$(uv run --locked krpatch sfc lua)" work/warplib dq5warp.lua)
STATE=$PWD/work/state/ship.mss FIELD=341,56 ROMPATCH=8000=00 TEST="wait:60,select:30,wait:120" \
  FROM=2 TO=800 LO=300000 HI=FFFFFF SHOT_DIR=$PWD/work/cov/dbg00 \
  "$MESENCE" --testrunner "$PWD/rom/dq5.sfc" "$PWD/tools/lua/cover.lua"
```

`ROMPATCH=8000=00` 이면 뱅크 `30` 에서 PC 64개가 실행됐고(`30:00BA` 등, 없는 뱅크를 비춘 엉뚱한 코드), `8000=FF`(원래 값)이면 0개였습니다.

그 다음 원래 롬으로 세 장면을 돌렸습니다. `seqboot.lua` 드라이버로 같은 입력열(좌우 걷기, A·B·X·Y·SELECT·START)을 반복했습니다.

| 출발 | 프레임 | 지나간 장면(300프레임마다 찍은 그림) | 뱅크 `30` 이상 실행 |
| --- | --- | --- | --- |
| `field-free.mss` | 6,000 | 필드 걷기, 무작위 전투(주문 포함), 전멸, 교회에서 되살아남, 마을 대화·예/아니오 | 0 |
| 무리 `3D` 전투 | 3,600 | 전투 승리, 필드 걷기, 무작위 전투 한 번 더, 파파스의 ホイミ | 0 |
| `ship.mss` | 6,000 | 명령 창, しらべる, 대화, 상태 창 | 0 |

이 장면들에서는 디버그 입구 말고 롬 밖 뱅크로 가는 코드가 돌지 않았습니다. WRAM 에서 도는 코드도 없었습니다.

## 틀렸던 것들

- 처음엔 롬 전체(`LO=000000`)를 감시해 정적 검사까지 한 번에 하려 했습니다. 뱅크 `2B` 를 범위에 넣으면 실행 콜백이 너무 많아 MesenCE 테스트 러너가 약 100초 만에 결과 없이 끝납니다. 감시 범위는 드물게 실행되는 곳으로만 좁힙니다.
- 전투 마릿수가 줄어든 것을 처음엔 무리 플래그(`3E` 의 `00`) 탓으로 보았습니다. 플래그와 몬스터를 바꿔 보니 몬스터 `6A` 탓이었습니다.

## 남은 것

- 무리 플래그 `+0`(`$1000`)의 비트 뜻. 64개 중 `C0` 41개, `C1` 10개, `00` 3개, `80`·`C2`·`E1` 2개씩, `90`·`D0`·`D1`·`E0` 1개씩입니다
- 무리 `30`~`3F` 를 부르는 곳(즉값 검색에는 없음, 스크립트 바이트코드나 레지스터로 부를 수 있음)
- 몬스터 `6A` 가 8마리 중 7마리만 나오는 까닭
- `$1AA0` = 6(이벤트 전투 배경으로 보임)을 바꾼 전투
- 롬 밖 뱅크 감시를 아직 돌리지 않은 장면: 어른 시절, 배·마차·동료가 있는 장면, 카지노 같은 미니게임
