# 2026-10-26-49: 필드 세계 지도 쓰기 도구

실내 맵에 이어 필드 세계 지도를 고쳐 롬에 넣는 `sfc/dq5/tools/dq5fieldwrite.py` 를 만들었습니다. 형식은 [dq5-build-format.md 「필드 세계 지도」](../docs/dq5-build-format.md#필드-세계-지도) 에 있습니다.

## 1. 덩어리 둘과 그것을 가리키는 곳

필드 지도는 세계마다 RLE 두 덩어리입니다. 지도의 하위 8비트(64KB)와 블록 번호 9번째 비트(8KB)입니다([dq5-field-format.md](../docs/dq5-field-format.md#불러오기-01a5c2)). 덩어리 주소는 표가 아니라 불러오기 루틴 안의 즉값이었습니다. 세 루틴 모두 덩어리마다 같은 꼴입니다.

```
01:A5E3  A9 17        LDA #$17
01:A5E5  8D 74 43     STA $4374     ; DMA 원본 뱅크
01:A5E8  48 AB        PHA / PLB
01:A5EA  A2 59 9A     LDX #$9A59
01:A5ED  20 4F A6     JSR $A64F     ; RLE 풀기
```

`01:A64F` 는 덩어리를 DMA 원본으로 읽고 주소는 16비트만 늘리므로, 덩어리 하나는 한 뱅크 안에 있어야 합니다. 도구는 덩어리를 늘린 뱅크(기본 `34:8000`)에 차례로 놓되 뱅크를 넘으면 다음 뱅크 첫머리로 옮기고, 이 꼴을 찾아 뱅크·주소 즉값을 바꿉니다.

## 2. 다시 싸기

RLE 는 제어 바이트 bit7 이 0 이면 글자 그대로 c+1 개, 1 이면 다음 바이트를 (c & 7F)+1 번이고 `80` 이 끝입니다. 같은 값 3개 이상을 반복으로 싸는 인코더로 세 세계 여섯 덩어리를 다시 싸서 풀자 모두 원래와 같았습니다. 크기는 세계 0 지도가 25,868 → 25,958바이트로 조금 컸고, 9번째 비트 덩어리 셋은 같았습니다.

## 3. 게임에서 보기

세계 0 을 고치지 않고 옮긴 롬과, 주인공이 서는 (341,56)(블록 좌표 (170,28)) 오른쪽의 블록 (172~176, 25~28) 을 블록 307 로 칠한 롬을 만들었습니다. 307 은 9번째 비트가 켜진 언덕 블록이라 두 덩어리를 모두 시험합니다. `dq5warp.lua` `FIELD=341,56` 으로 필드에 서서 `atpc.lua` 로 `00:8090` 에서 WRAM 을 덤프했습니다.

```
w0      7F:0000 같음 True 7E:E000 같음 True
w0-edit 7F:0000 같음 True 7E:E000 같음 True
```

고친 롬은 주인공 오른쪽의 바위산 자리가 언덕으로 바뀌어 보였습니다.

`tools/lua/seqlib.sh … dq5warp.lua` 로 Lua 폴더를 만들려다 `cp: tools/lua/dq5warp.lua: No such file or directory` 가 났습니다. `seqlib.sh` 는 드라이버를 `tools/lua/` 에서 찾는데 `dq5warp.lua` 는 `sfc/dq5/tools/lua/` 로 옮겨져 있습니다. 폴더를 손으로 만드는 방법을 [handoff](../handoff.md) 에 적었습니다.

## 남은 것

- 필드 블록 정의(`2A:A32C`·`2A:AD27`)와 입구 표(`04:FD97`)를 쓰는 길.
- 세계 1·2 는 다시 싸기만 확인했고 게임에서 돌려 보지 않았습니다.
