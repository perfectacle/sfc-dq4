# 2026-10-25-181: 전투 연출 번호와 프레임마다 그린 연출 층

[2026-10-25-160](2026-10-25-160-effects.md) 의 연출 조각·움직임 스크립트를 이어, 행동에서 연출 번호로 가는 길을 찾고 연출이 도는 동안 프레임마다 덤프해 연출 층만 그렸습니다. 1~3절은 dq5-sprite 세션이 한 것을 넘겨받아 정리했습니다. 결과는 [dq5-graphics-format.md](../docs/dq5-graphics-format.md) 의 「연출 번호와 프레임 덤프」 에 있습니다.

## 1. 연출을 부르는 곳

주인공이 メラ 를 걸 때와 たたかう 로 칠 때 실행된 PC(뱅크 20~2F)를 견주었습니다. メラ 에만 있는 뱅크 22 행 JSL 은 `26:8B7D` 의 `JSL 22:D73C` 하나였습니다.

```
26:8B61  LDX $10F7          ; 행동
26:8B68  JSL 20:FF02        ; carry = 행동하는 쪽
26:8B6E  LDA 26:8BE0,X  /  26:8B74  LDA 26:8C75,X
26:8B78  BIT $100E → 26:8B7D JSL 22:D73C  또는  26:8B83 JSL 28:8000
```

`22:D73C` 는 A 를 `$0D14` 에 두고 `22:D7AA` 의 첨자로 씁니다. 160 에서 행동 번호로 본 `29:8296`·`29:FACF` 의 첨자도 이 연출 번호입니다. 우리 편 주문·몬스터용 주문·숨·たたかう 는 행동과 같은 번호라 그림 이름은 그대로 맞습니다.

## 2. 프레임마다 덤프

연출이 시작하고 끝나는 프레임이 주문마다 달라, `22:D73C` 에 들어온 프레임부터 `22:D796`(끝) 뒤 4프레임까지 덤프하는 `lua/dq5fxdump.lua` 를 만들었습니다. メラ 는 447~499 프레임이었습니다.

```sh
# 주인공에게 주문 칸 8 을 주고 슬라임 HP 200 인 전투 상태
STATE=$PWD/work/state/ship.mss FIELD=341,56 BATTLE="00:3,03:2" \
  ROMPATCH="118001=00;118003=C8;11804C=00;11804B=C8" SET="2064=01;2050=63;2044=63" SAVE=cast.mss … dq5warp.lua
# 주문 nn 을 걸며 연출 덤프(boot.lua = dq5battle.lua)
STATE=cast.mss ROMPATCH="11BE31=nn" PRE="a:4,wait:60,down:8,wait:30,a:8,wait:60" LOOP="a:3,wait:40" SHOTS=1 \
  MAXF=800 … sfc/dq5/tools/lua/dq5fxdump.lua
# 몬스터 쪽: 슬라임 MP 255(118004=FF·11804D=FF)로 만든 castm.mss 에서 ROMPATCH="118011=<행동 x6>"
```

처음 몬스터 쪽은 たたかう 연출 `73` 만 찍혔습니다. 슬라임 MP 가 0 이라 주문을 고르지 않았던 것이고, MP 255 상태를 만들자 걸었습니다.

## 3. 연출 층 그리기와 대조

연출 층(BG3 7~20줄과 OBJ 팔레트 4~7)만 그린 그림을 같은 실행의 화면과 견주니 처음에는 반도 맞지 않았습니다. 세 가지 까닭이 있었습니다.
- MesenCE 화면은 위 8줄을 자른 그림이고, 덤프 k 의 모습은 화면 k+1 에 찍힙니다.
- 화면을 찍는 프레임이 1~3프레임 흔들립니다. 그래서 덤프가 4프레임 동안 그대로인 것만 골라 셋 중 가장 맞는 화면을 썼습니다.
- 메라 불덩이가 화면 위쪽에서는 OAM 에 있는데 화면에 없었습니다. 56~159줄 밖은 창이 OBJ 를 가리는 줄이었습니다.
이것을 맞춘 뒤 イオナズン 57,285점, ライデイン 29,812점을 비롯해 견줄 수 있었던 벌 대부분이 모두 맞았습니다.

## 4. 고르지 않던 몬스터 행동

몬스터 쪽 회복(`5A`~`64`)·メガンテ·マホキテ·モシャス·がったいだ 는 행동 여섯 칸을 채워도 슬라임이 고르지 않았습니다. 행동 칸 고르기([dq5-data-format.md](../docs/dq5-data-format.md) 「몬스터 행동 칸 고르기」)는 먼저 행동 평가 조건(필드 `68`)으로 칸을 거릅니다. 슬라임 레코드의 필드 `68`(바이트8, `118008` = `01`)을 0 으로 하자 열다섯 행동이 모두 900프레임 안에 걸렸습니다. 회복은 건 몬스터 위에 반짝이 OBJ 를 냈습니다. メガンテ(2,502점)·がったいだ(712점)는 화면과 모두 맞았고, 회복은 4프레임 그대로인 덤프가 없어 견주지 못했습니다.

## 틀렸던 것들

- 연출 덤프를 그대로 화면과 견주어 맞지 않는 것을 그리기 잘못으로 보았습니다. 화면 쪽의 자르기·늦음·흔들림·OBJ 창 때문이었습니다.
- `29:8296`·`22:D7AA` 의 첨자를 행동 번호로 보았습니다. 연출 번호입니다.

- 몬스터가 우리 편을 칠 때 화면 쪽 변화.
