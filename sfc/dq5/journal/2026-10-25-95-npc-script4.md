# 2026-10-25-95: 첫 장면 재현과 남은 스크립트 명령

[인물 스크립트 명령 실측 2](2026-10-25-85-npc-script3.md)에서 막혔던 첫 장면(깨어나기)을 새 게임 세이브스테이트로 재현했습니다.
남은 스크립트 명령도 같은 실험대로 모두 돌렸습니다. 결과는 [dq5-map-format.md 「인라인 스크립트」·「맵별 루틴」](../docs/dq5-map-format.md#인라인-스크립트-01c800)에 있습니다.

## 1. 새 게임 세이브스테이트

전원을 켜고 A 를 40프레임마다 누르며 6,500프레임을 돌렸습니다. 맵 번호와 `7E:21A1`, 침대 쪽 인물을 `tools/lua/wlog.lua` 로 적었습니다.

```
f05744 bc=17 bd=00 f=00 x9=0B y9=0A   ; 배 선실이 풀리고 침대에 슬롯 09
f05801 f=01 x9=80 xA=0B               ; A 한 번에 깨어남
f06164 f=71                           ; ship.mss 와 같은 상태
```

5,760프레임의 A 는 아직 먹지 않았고 5,800프레임의 A 에 깨어났습니다. 그래서 5,770프레임에 누르기를 멈추고 5,790프레임에 저장했습니다(`work/state/ship-wake.mss`, 만드는 법은 [handoff](../handoff.md)).
화면에는 침대에 누운 주인공과 선 파파스가 보입니다.

## 2. 깨어나기

`ship-wake.mss` 에서 아무것도 누르지 않으면 900프레임 동안 아무 값도 바뀌지 않았습니다. 30프레임에 B 를 누르고 A 로 메시지를 넘긴 기록입니다.

```
f00001 x0=09 y0=0B v0=80  x9=0B y9=0A  xA=22 yA=02  f=00 e=80
f00032 x9=80  xA=0B yA=0B  f=01        ; 자는 그림이 사라지고 대역이 침대 옆에
f00040 f=21                            ; 00:BFB3 가 bit5 → 파파스 메시지 1DD
f00379 f=31                            ; 메시지를 넘기자 bit4
f00387 xA=0A  f00395 xA=09             ; 대역이 (9,11) 로 걸음
f00403 f=71  f00404 v0=00 xA=80        ; bit6, 06:CC95: 대역을 치우고 주인공을 보이게
f00412 e=00                            ; 19AE 가 0
```

쓰기 감시로 bit0 은 `02:AE55`(둘째 루틴)와 `00:93F3`, bit5 는 `00:BFB3` 가 쓰는 것을 확인했습니다. 주인공은 장면 내내 `3380` = `80` 으로 숨어 있고, 인물 둘(자는 그림 `05:A867`, 일어나는 대역 `05:A874`)이 연기를 맡습니다.

## 3. 남은 스크립트 명령

파파스 실험대(스크립트 덮어 쓰기, 17/00 다시 들어가기)에서 `7E:219F` 를 `POKE` 로 고정해 플래그 명령을 봤습니다.

| 스크립트 | 조건 | 결과 |
| --- | --- | --- |
| `06 0F 01 08` `2B 05 0D 16` `2B 08 0D 16` | `219F` = 0 / 1 | (5,13) / (8,13) |
| `06 8F 01 08` … | `219F` = 1 | (5,13) |
| `07 08 0A 0B 0C 0A` … / `07 88 …` | 주인공 (9,11) | (8,13) / (5,13) |
| `09 0F 01` `2B 05 0D` | `219F` = 1 / 0 | 그대로 / (5,13) |
| `09 8F 01` `2B 05 0D` | `219F` = 0 | 그대로 |
| `10 0F FF` `11 0F F0` | | `219F` = `F0` |
| `55 0F 5A` | | `219F` = `5A` |

- `15` 를 10번 되풀이하는 데 88프레임이 걸렸습니다. `16` 은 `3300` 을 0 으로 두고 그 자리에 머뭅니다. `1D 40` 은 `3300` 을 `42`(아래 니블은 바뀜)로 둡니다.
- `18` 은 2,000프레임 동안 (1~8, 7~15) 를 돌아다녔고, `19 03 02` 는 처음 자리 (5,13) 둘레 (2~6, 11~13) 안에서만 걸었습니다.
- `2F n` 은 `31E0` = n 으로 두고, 위 니블 `8`·`1`·`4`·`2` 가 위·오른쪽·아래·왼쪽 그림이었습니다.
- `36 30` 은 `32E0` 을 `33`, `39 05` 뒤 `38` 은 `3180` 을 0, `1C` 뒤 `22` 는 `33A0` bit0 을 끕니다.

메시지 명령은 한 쪽짜리 메시지 `034` 로 봤습니다.

| 명령 | A 를 누르지 않으면 | 화면 |
| --- | --- | --- |
| `21` | 다음으로 안 넘어감 | 창에 메시지 |
| `30` | 바로 넘어감 | 창이 열린 채 남음 |
| `31` | 바로 넘어감 | 창이 없어 안 보임 |
| `32` | 다음으로 안 넘어감 | 창이 없어 안 보임 |

`20` 은 APU 포트 쓰기를 감시했습니다. 명령 없이는 `2BC31D`~ 가 `$2141`=`00`·`$2142`=`05` 를 쓰는데, `20 34 02` 면 `$2140`~`$2143` 에 `01 0C 34 02`, `20 37 03` 이면 `01 0C 37 03` 이 갔습니다. 효과음 명령 `0C` 에 번호와 둘째 값을 그대로 넘깁니다.

## 4. 인물 표 비트

- `19AE` bit7: `0B` 로 켜 둔 채 A 를 누르면 명령 창이, X 를 누르면 「足もとを 調べた」 가 뜨지 않았습니다(켜지 않으면 둘 다 뜸). `00:80E7` 이 `19AE & 81` 을 보고 명령 입력을 건너뜁니다. 걷기는 막지 않습니다. 첫 장면 내내 켜져 있다가 끝에 꺼집니다.
- `32A0` bit6: 애니메이션을 끄고(`1A`) `24 00` 으로 `3240` 만 바꾸면 그림 아랫부분(화면 120~133행), `2E 00` 으로 `3260` 만 바꾸면 윗부분(112~125행)이 바뀌었습니다. 위·아래 반쪽을 따로 고르는 그림이고, 이 비트를 끄면 타일이 엇갈립니다. `0F` 가 bit6 에 따라 `3260`·`3240` 중 하나를 지우는 것과 맞습니다.

## 틀렸던 것들

- 앞 일지는 `23 n` 의 n = 0~7 이 모두 다른 그림이라 했습니다. 서 있는 애니메이션이 돌고 있어 찍은 프레임마다 다리 그림이 달랐던 탓입니다. `1A` 로 애니메이션을 끄고 0~B 를 찍으니 그림은 네 가지(0·8·B, 1·5·9, 2·3·6·A, 4·7)였습니다.
- 처음에 `24 06`·`2E 06` 으로 반쪽을 보려다 차이가 안 나거나 엉뚱하게 났습니다. `06` 은 기본 자세와 같은 그림이었고, 애니메이션이 켜져 있었기 때문입니다.
