# 2026-10-25-31: 그림자 칠하기와 전투 배경의 남은 것

[배치·그림자](2026-10-25-21-mongfx-layout.md)와 [전투 배경](2026-10-25-22-battlebg.md) 일지에서 남긴 것을 이어서 풀었습니다. 그림자를 배경 타일에 칠하는 방식, 배경의 세계(`$1949`)·밤 팔레트, 필드 지형과 배경 번호, 띠를 펴고 움직이는 HDMA, `E7` 전투의 무리 합치기, 같은 머리를 나눠 쓰는 번호를 확인했습니다. 결과는 [dq5-graphics-format.md](../docs/dq5-graphics-format.md) 의 「그림자」「무리를 더하는 몬스터」「같은 머리를 가리키는 번호」「전투 배경」에 있습니다.

실험 명령의 `battle` 함수는 [배치·그림자 일지 1절](2026-10-25-21-mongfx-layout.md#1-머리-값이-가는-곳)과 같습니다.

## 1. 그림자는 비트평면 3

그림자가 있을 때(マッドプラント 1마리)와 머리 +0 의 모양 번호를 0 으로 덮었을 때(`RP=128C99=20`)의 1000프레임 VRAM 을 비교했습니다.

```
46 바이트 다름, 타일 내 위치 17·19·…·31(비트평면 3), 타일 $2AE~$2B1·$2CE~$2D1, 비트는 켜지기만 함, 타일맵 차이 0
```

`22:B08A` 를 읽으니 구간마다 `7E:6000`(BG 타일 `$200`~ 의 WRAM 사본)에서 그 줄의 비트평면 3 바이트에 `22:B203` 마스크를 OR 하고, 고친 타일을 `7E:5A20` 에 표시합니다. 색 번호가 8 커지니 팔레트 9~15번이 어두운 색인 셈입니다.
배경 아래 띠가 같은 그림 타일을 칸마다 따로 복사해 256개를 쓰는 까닭도 여기서 풀렸습니다. 칸마다 그림자를 따로 칠하려면 타일을 나눠 쓸 수 없습니다.

## 2. 세계와 밤

`$1949` 를 `POKE` 로 처음부터 고정하면 배 선실에서 다른 세계로 나가 이벤트 전투가 열리지 않습니다. 그래서 전투 셋업이 `$1949` 를 읽는 두 곳 `22:881D`·`22:88AD`(파일 오프셋 `11081D`·`1108AD`)의 `AD 49 19` 를 `A9 01 00`·`A9 02 00` 으로 덮었습니다.

```sh
mkdir -p work/bg/e2
RP="11081D=A90200;1108AD=A90200" battle sfc/dq5/tools/lua/dq5battledump.lua SHOT_DIR=$PWD/work/bg/e2 MAXF=1020 \
  POKE="7E1001=00;7E1005=1" DUMPF=890,1000 FROM=850 TO=1000 AT=22CA91
uv run --locked python sfc/dq5/tools/dq5battlebg.py rom/dq5.sfc 06 --era 2 --compare work/bg/e2 890
```

06·01(필드)과 1C·15(실내, `$1AA0` 에 `8E`·`87`)의 세계 1·2 가 모두 타일·타일맵·팔레트까지 같았고, 필드 세계 2 의 BG2 는 `28:FD64` 목록과 256/256 같았습니다. `$1AA0` = `07` 은 세계 2 에서도 원래 목록이었습니다.
처음에 실내를 비교했을 때는 0/256 이 나왔는데, `8E` 의 번호를 `0E` 로 착각했기 때문입니다(번호는 `8E - 72 = 1C`). 실내 배경이 `28:FD64` 로 바뀌지 않게 도구에 `--indoor` 를 더했습니다.

밤은 `$075E` = `0190`(`POKE="…;7E075E=90;7E075F=01"`)으로 고정하자 `$1AA1` = 1 이 되었습니다. `21:8000` 은 [맵 형식](../docs/dq5-map-format.md)에 적힌 대로 `$075E >= F0` 이면 밤이라는 루틴입니다.

## 3. 필드 지형

`01:84CF` → `03:CB1B` 를 읽으면 필드 블록 번호로 `03:CC48` 의 니블을 찾습니다. 세계 0 지도에서 지형별 칸 하나를 골라, `dq5warp.lua` 로 그 자리에 선 뒤 좌우로 한 걸음씩 걸었습니다. `wsnap.lua` 를 끼워 10프레임마다 WRAM 을 덤프하고, 걸음이 끝난 칸의 예상 지형과 `$1AA0` 을 견줬습니다.

```sh
LIBDIR=$(tools/lua/seqlib.sh "$(uv run --locked krpatch sfc lua)" work/warplib ../../sfc/dq5/tools/lua/dq5warp.lua)
mkdir -p work/tr/t1
env LIBDIR=$LIBDIR STATE=$PWD/work/state/ship.mss FIELD=86,328 SETTLE=30 TEST="left:20,wait:50,right:20,wait:50" \
  FROM=100 STEP=10 SHOT_DIR=$PWD/work/tr/t1 "$MESENCE" --testrunner "$PWD/rom/dq5.sfc" "$PWD/tools/lua/wsnap.lua"
```

```
1 [(86, 328, 161, 1), (87, 328, 1, 1), (88, 328, 7, 7)]      # (x, y, $1AA0, 예상)
2 [(354, 120, 161, 2), (355, 120, 2, 2), (356, 120, 2, 2)]
...
12 [(312, 164, 161, 12), (313, 164, 12, 12), (314, 164, 6, 6)]
```

도착한 칸에서는 `$1AA0` 이 실내 값(`A1`)으로 남아 있고, 걸음을 마쳐야 바뀝니다. 걸은 지형 1·2·3·4·6·7·9·A·B·C 는 모두 예상과 같았고, 0·5·8·D 는 걸어 들어가지 못했습니다.

## 4. 띠를 펴는 HDMA

`$420C` 와 DMA 레지스터(`4300`~`437F`)를 정한 프레임에 읽는 `sfc/dq5/tools/lua/dq5hdma.lua` 로 HDMA 를 봤습니다.

```sh
mkdir -p work/p/hd2
battle sfc/dq5/tools/lua/dq5hdma.lua SHOT_DIR=$PWD/work/p/hd2 MAXF=1020 POKE="7E1001=00;7E1005=1" DUMPF=860,872,884,896,1000
```
 펴는 동안 채널 1·2 가 모드 `42` 로 BG1·BG2 세로 스크롤에 걸려 `7E:5C00` 간접 표를 쓰고, 다 펴진 뒤에는 모드 `02` 로 `7E:0DAD` 직접 표를 씁니다.

배경 종류에 따라 채널 3 이 다르게 켜졌습니다.

```
06 (0DF2=2)  ch3 02 0F …  BG2 가로 스크롤, 세 구간이 다른 속도로 움직임
1A (0DF2=1)  ch3 42 0D …  BG1 가로 스크롤
25 (0DF2=3)  ch3 43 21 …  CGRAM, $420C=1E
15 (0DF2=0)  ch3 꺼짐
```

`$0DF2` 는 `22:8983` 의 하위 2비트를 뒤집어 넣은 값이라(`22:860B`), 표 값 1 인 필드 배경이 `$0DF2` = 2 가 됩니다.

## 5. E7 전투와 같은 머리 번호

`E7` 전투의 WRAM 에서 `0C10` 은 `E7 FF FF`, 첫 무리 조각 수는 19(`E7` 10 + `E8` 9)였습니다. 그림을 다 푼 뒤 `22:8A57` 이 `E8`·`E9` 무리를 지우고 `E8` 의 조각을 `E7` 에 붙이는 것입니다. `E9` 의 조각 11개는 조각 목록 뒤에 있지만, 첫 턴 동안 OAM 을 만드는 `22:A277` 이 읽지 않았습니다(`rwatch.lua`).

그림 번호 `11`·`29`·`5E` 를 쓰는 몬스터 다섯(`C0`·`D3`·`DA`·`CB`·`D2`)은 `dq5encounter.py` 의 조우 구역과 이벤트 무리 표 어디에도 없었습니다. 그림 번호는 이미 올린 타일을 다시 쓰는 열쇠일 뿐이고(`22:91F7`), 그 뒤로는 올린 자리 번호가 쓰입니다.

## 틀렸던 것들

- 실내 배경을 세계 2 로 비교할 때 `$1AA0` = `8E` 를 번호 `0E` 로 읽어 다 틀린 줄 알았습니다. 번호는 `1C` 였습니다.
- 지형 실측에서 처음에는 `$BC` 가 0 인 덤프만 골랐다가 하나도 남지 않았습니다. 필드에서도 `$BC` 는 01 로 남고, 필드인지는 `$BE` bit7 로 봐야 했습니다.
- 그림 번호가 `0C47` 에 그대로 남는 줄 알았는데, 풀기 직전에 올린 자리 번호로 바뀝니다(`22:90D6`).

## 남은 것

- `E9` 를 그리는 때(`E7` 이 `EA` 로 바뀌는 장면 필요).
- 같은 머리를 다른 번호로 나눈 이유.
- 걷지 못한 지형 0·5·8·D, 세계 1·2 의 지형 표, `$0DF2` = 3 의 CGRAM 표 내용.
