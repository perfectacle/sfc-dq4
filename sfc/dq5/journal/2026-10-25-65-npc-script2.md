# 2026-10-25-65: 인물 스크립트 명령 실측, 04/05 반쪽 계단, 매 프레임 루틴

[인물 표와 인라인 스크립트](2026-10-25-13-npc-script.md)에서 남긴 것을 풀었습니다. 처리 루틴만 읽었던 스크립트 명령을 스크립트를 덮어 써서 확인했고,
인물 표 `32A0`·`33A0` 의 나머지 비트를 넣는 곳을 찾아 692개 덤프와 바이트째 맞췄습니다. 04/05 (4,66) 의 짝 계단은 없다는 것, 맵별 루틴 표 둘째 루틴 두 개가 하는 일도 확인했습니다.
결과는 [dq5-map-format.md 「인물」](../docs/dq5-map-format.md#인물-128000)과 [「맵별 루틴」](../docs/dq5-map-format.md#맵별-루틴-15f907)에 있습니다.

## 1. 인물 표의 나머지 비트

앞 일지에서는 `32A0`·`33A0` 을 비교할 때 `1E:DB44` 앞부분이 넣는 비트만 봤습니다. 쓰기 감시(`wwatch.lua`)를 걸고 배 선실에 다시 들어가니 같은 루틴의 뒷부분이 더 쓰고 있었습니다.

```
7E33A0-7E33BF pc=1EDC89 addr=7E33AC val=B9    ; 1E:DC86 STA $33A0,Y (ORA #$09)
7E32A0-7E32BF pc=1EDC9C addr=7E32A8 val=61    ; 1E:DC99 STA $32A0,Y (ORA $00)
```

- `1E:DC67`: 그림 번호가 `46`~`48`·`78`·`7F`·`84`·`A2` 이상이면 `33A0` 에 `09` 를 더합니다.
- `1E:DC89`: 그림을 VRAM 에 올리는 `1F:CF1E` 가 `$00` 에 `01` 또는 `41` 을 남기고(그림 표 `25:86D0` 의 bit7), `1E:DC94` 가 그 값을 `32A0` 에 더합니다.
  `7E:21D1 & 40` 이면 늘 `01` 이고, 그림 `9A` 는 `7E:21B3 & 08` 에 따라 `2F`·`97` 로 바꿔 봅니다.
- `1E:DC5C`: 그림이 0 이면 `3380` 을 `80` 으로 둡니다.

이 셋을 `table_values` 에 더하고 비교할 때 쓰던 비트 마스크를 없앴습니다. 덤프의 `21D1`·`21B3` 은 `--compare` 가 덤프에서 읽습니다.

```
ok 692 bad 0 slotsOK 1562     # 맵마다 dq5npc.py BC BD --compare <덤프>/at_12803C.bin, 23칸
```

## 2. 스크립트를 덮어 쓰는 실험대

명령 하나씩 보려면 결과가 눈에 띄는 자리에서 원하는 바이트를 돌려야 합니다. 배 선실 세이브스테이트는 17/00 의 기본 목록을 쓰고, 파파스(`05:A848`, 슬롯 08)가
23바이트짜리 스크립트를 가졌습니다. 이 스크립트를 `ROMPATCH` 로 덮고, 사다리 목적지를 17/00 자신(`E0090B0117`, (9,11))으로 바꿔 인물 목록을 다시 읽게 했습니다.
값은 새로 만든 `tools/lua/wlog.lua` 로 바뀔 때마다 적었습니다.

```sh
LIBDIR=<walk.lua 를 boot.lua 로 둔 폴더> STATE=$PWD/work/state/ship.mss PRE="b:4,wait:40" \
  ROMPATCH="156FF5=E0090B0117;2A850=<스크립트 23바이트>" WAYPOINTS="3,11;3,24;7,24;up:10;wait:2000" \
  CHANGES=9 MAXF=1500 WLOG="x=7E3028;y=7E3088;v=7E3388;c=7E3548" SHOT_DIR=… "$MESENCE" --testrunner rom/dq5.sfc tools/lua/wlog.lua
```

되풀이(`02 n` … `01`)는 `2B 03 0D 02 03 13 08 0D 14 13 03 0D 14 01 16` 으로 봤습니다. (3,13) 과 (8,13) 사이를 세 번 오간 뒤 (3,13) 에 섰습니다.

```
f00354 x08=03 y08=0D   f00393 x08=08   f00426 x08=03   f00473 x08=08
f00509 x08=03          f00556 x08=08   f00589 x08=03   (그 뒤 변화 없음)
```

`05` 는 네이티브 루틴이 A 에 0 을 돌려줄 때까지 다음 명령으로 넘어가지 않습니다(`01:C987`). 롬에서 `LDA #$00`·`RTL` 로 된 `05:F196` 과 `LDA #$01`·`RTL` 인 `05:F199` 를
골라 뒤에 순간이동을 두니, 앞의 것은 (5,13) 으로 옮겼고 뒤의 것은 끝까지 (8,9) 그대로였습니다.

## 3. 깜빡이며 나타나고 사라지기(`50`~`53`)

`50 x y` 는 `3560`·`35A0` 에 자리만 적고, `53` 이 그 자리로 옮긴 뒤 `3540` 카운터를 올리며 `3380` bit7 을 켰다 껐다 합니다.
`51`·`52` 는 거꾸로 카운터를 내립니다.

```
50 05 0D 53 : f362 (5,13) c=89 → v=80 이 363·365·368·372 프레임 → f377 c=00 끝
2B 05 0D 52 : v=80 이 354·360·365·369·372 프레임 → f374 X·Y = 80 80
2B 05 0D 51 : 같은 깜빡임 → f374 v=80 인 채 끝
```

`3380` bit7 이 무엇인지는 화면으로 봤습니다. `51` 로 끝난 뒤의 화면에는 (5,13) 의 파파스가 보이지 않았고, 순간이동만 한 대조 화면에는 보였습니다.
`3380` bit7 은 그 프레임에 인물을 그리지 않는 비트이고, `51` 은 깜빡이며 사라지기, `52` 는 사라진 뒤 표에서 치우기, `53` 은 나타나기입니다. `4F`(카운터가 0 이 될 때까지 대기)는 데이터에 나오지 않습니다.

## 4. 문 열고 닫기(`41`·`43`)

파파스 스크립트의 `41 3C 0F 01` 은 (60,16) 에 서서 바로 위 (60,15) 를 가리킵니다. 01/05 의 다른 인물(`05:89E3`, 14바이트) 스크립트를 덮어
이 명령만 돌리고 (60,15) 셀을 봤습니다.

| 스크립트 | (60,15) `+2 +3 +5 +6` |
| --- | --- |
| 덮기 전 | `DB 10 0C 38` |
| `41 3C 0F 01` | `BE 18 DB 10`(f376) |
| `41 3C 0F 01` · `02 3C 15 01` · `43 3C 0F 01` | `BE 18 DB 10` 이었다가 f876 에 `DB 10 0C 38` |
| `43 3C 0F 01` 만 | 그대로 |

`41` 은 문 열기(`01:D915`), `43` 은 문 닫기(`00:E066` 뒤 `01:F117`)입니다. 넷째 바이트(`01`, 다른 곳에서는 `28`)의 뜻은 아직 모릅니다.
`20`(`24:FEAC`)은 전투에서 효과음에 쓰는 루틴을 부르지만 소리를 따로 재지는 못했습니다.

## 5. 04/05 (4,66) 은 반쪽 계단

04/05 의 밤 인물 목록을 보니 비앙카의 대사 「まっ暗だわ　…。足もとに　気をつけてね……。」(메시지 `210`)를 띄우는 숨은 인물의 사각형이 (7,65)-(8,71), (2,65)-(5,67) 처럼
바로 이 빈 곳에 있었습니다. 맵 그림에서 검게 보이던 곳은 캄캄한 바닥입니다. 장면 이동 도구로 (3,66) 에 서서 걸어 보니 아래로 4칸, 오른쪽으로 25칸이 걸어졌고 화면은 주인공만 보였습니다.

그런데 (4,66) 을 밟아도 04/06 으로 가지 않았습니다. 왼쪽에서 (1,66) → (10,66), 아래에서 (3,69) → (3,65), 오른쪽에서 (6,66) → (2,66) 모두 맵이 그대로였고,
맵별 루틴 `02:AB25` 를 `+4` 에 쓰도록 고쳐도(`ROMPATCH=12B28=A4`) 같았습니다. 읽기 감시로 그 셀을 읽는 곳을 따라가니 계단 판정 `00:E2C5` 가 나왔습니다.

```
00:E2C9  LDA $3740 / AND #$7F / CMP #$05 (또는 33·4C) ; 왼쪽 셀 +4
00:E2DA  LDA $3760 ...                               ; 왼쪽 셀 +7
00:E2E7  LDA $3780 ... / 00:E2F8 LDA $37A0 ...       ; 오른쪽 셀
```

`2B:8209` 가 주인공이 선 두 셀의 `+4`·`+7` 을 `3740`~`37A0` 에 모으고, 왼쪽과 오른쪽이 둘 다 계단 속성이어야 옮겨 갑니다. (3,66) `+7` 을 `05` 로 고정하고 다시 걷자
(3,66) 에서 04/06 (3,5) 로 옮겨 갔습니다.

```
POKE=7F339F=00 : f00085 at 5,66 → 맵 그대로
POKE=7F339F=05 : f00097 map 04/05 -> 04/06, 끝 (3,5)
```

(4,66) 은 출구 번호만 맞추는 반쪽 계단이고, 04/06 (4,5) 계단은 이 어둠 속으로 내려가는 한쪽 길입니다. 짝이 되는 계단을 만드는 곳은 없습니다.

## 6. 매 프레임 루틴 둘

`03:D4B5` 는 79개 항목이 쓰는 가장 흔한 둘째 루틴이고, 실내 맵의 움직이는 타일을 돌립니다. 표와 종류별 움직임은
[실내 맵의 움직이는 타일](2026-10-25-58-anim.md) 일지가 풀었습니다. 여기서는 둘째 루틴 자리(`$1AA6`)를 비우면 타일이 멈추는 것을 VRAM 을 10프레임마다 견주는 프로브(`tools/lua/vramdiff.lua`)로 확인했습니다.

```
00/00 그대로        : 38번 중 16번 바뀜, 매번 57C1-58FF 140바이트
00/00 $1AA6=15:F906 : 38번 중 0번
0D/00, 1C/00        : 16번씩, 57C0-5A3F 부근
```

`02:AE55` 는 17/00·1A/04 에서 돕니다. `02:B329` 가 `$24 & CF` 를 보고 켜져 있으면 `7E:21A1` bit0 을 켭니다. 선실에서 `21A1` 을 0 으로 두고 버튼을 하나씩 눌렀습니다.

| 누른 것 | 없음 | A | B | X | Y | 십자 키 넷 | Start | L | R |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| `21A1` | 0 | 1 | 1 | 1 | 1 | 1 | 0 | 0 | 0 |

17/00 기본 목록의 `05:A867`·`05:A874` 가 `09 91 01` 로 이 비트를 기다리고, 같은 목록의 파파스가 「目が　さめたようだな」(메시지 `1DD`)를 말합니다.
첫 장면에서 버튼을 누르면 주인공이 깨어나는 계기로 보이지만, 그 장면 자체는 아직 재현하지 못했습니다.

## 틀렸던 것들

- 04/05 (4,66) 을 「빈 곳에 둔 출구 셀」로 보고 짝 계단을 만드는 이벤트를 찾았습니다. 빈 곳은 캄캄한 바닥이었고, 셀 하나만 계단 속성이라 처음부터 밟히지 않는 자리였습니다.
- `3380` bit7 이 켜진 프레임만 세면 「깜빡임」 같았지만, `51` 은 bit7 을 켠 채 끝나 인물이 계속 보이지 않습니다.
- 처음 버튼 실험에서 A·십자 키가 `21A1` 을 켜지 않는 것처럼 나왔습니다. `POKE` 로 0 을 쓴 바로 다음 프레임부터 누른 탓이었고, 20프레임 쉬고 누르자 켜졌습니다.
