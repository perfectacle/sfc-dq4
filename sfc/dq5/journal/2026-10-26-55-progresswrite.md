# 2026-10-26-55: 성장·조우 구역·상점 목록 쓰기

성장 레코드, 조우 구역 레코드, 상점 품목과 교환 값을 JSON으로 편집하는 `dq5progresswrite.py`를 만들었습니다. 항목 수와 배치 자리는 유지하고 적은 필드만 고칩니다. 입력은 [쓰기 형식](../docs/dq5-build-format.md#성장조우상점-dq5progress1)에 있습니다.

## 1. 세 종류의 고정 슬롯

성장은 사람 11종·동료 몬스터 42종, 각각 80바이트입니다. 원래 문서의 길이 `50`은 16진수였습니다. 꺾이는 레벨, 경험치 배수, 능력치별 구간 값을 내보내고 활성 구간 밖의 바이트는 보존했습니다. HP·MP의 레벨 1 이후 값은 게임이 두 배로 읽으므로, 새 곡선이 줄어드는지 검사할 때도 실제 값으로 바꾸어 견줍니다.

조우는 85개 레코드에 22바이트씩입니다. 일반 몬스터 칸 10개와 고정 무리 칸 하나를 구분했습니다. 무게·마릿수 부호와 같은 바이트의 다른 비트에 종 수 무게·확률 계수·플래그가 들어 있어, 부분 수정이 나머지 비트를 바꾸지 않게 합니다.

상점은 종류별 11·15·17·5목록, 합계 48목록입니다. 이야기 플래그나 주인공 위치에 따라 같은 키의 다른 목록을 고르므로 키·순서·품목 수는 유지했습니다. 메달 교환 값 6바이트와 코인 교환 값 6개×3바이트도 고칠 수 있습니다. 일반 물건 가격은 기존 `dq5tables.py`로 고칩니다.

## 2. 원본 예외를 새 입력의 규칙과 구분하기

모든 성장 레코드가 엄격한 오름차순 꺾임과 비감소 곡선이라고 가정할 수 없었습니다. 동료 몬스터 종류 `27`에는 마지막 꺾임이 중복된 `[2,3,4,5,6,7,7]`이 있었고, 사람 종류 5의 HP에는 줄어드는 구간이 있었습니다.

원본과 같은 값은 그대로 보존합니다. 새 꺾임을 쓰면 2~99 사이 엄격한 오름차순인지 확인하고, 새 능력치 값이나 꺾임을 쓰면 곡선이 줄어들지 않는지 검사합니다. 꺾임 수를 바꿀 때는 경험치 배수와 능력치 일곱 배열을 모두 받습니다. 기존 값을 다시 넣는 일과 새 값을 잘못 쓰는 일을 구분했습니다.

## 3. 바이트와 기존 디코더로 대조하기

```text
성장 53개·조우 85개·상점 48개·교환 값 12개
6,510바이트: 다른 항목 0개
원본 JSON 그대로 패치: 쓰기 0개
합성 검사 9개: 통과
```

성장값은 `dq5growth.py`의 누적 경험치·능력치 계산으로, 조우는 `dq5encounter.py`의 구역 풀이로, 상점은 `dq5shop.py`의 품목·교환 값으로 다시 읽었습니다. 실제 롬 수정 입력도 빌더로 만들고 IPS를 원본에 다시 붙인 결과가 만든 롬과 같은지 확인했습니다.

## 4. 게임에서 레벨업·조우·상점 확인하기

주인공 성장의 HP·힘 구간과 경험치 값을 바꾼 뒤 슬라임 한 마리와 싸워 이겼습니다. 레벨 1에서 2로 올랐을 때 최대 HP·MP·힘·민첩·지혜·운·수비 순서로 `[33,3,16,6,7,4,3]`, 다음 누적 경험치 70이 나왔습니다. 수정 롬을 읽기 도구로 계산한 값과 같습니다.

조우는 맵 `21/02`의 구역 1에서 칸 5만 무게 7, 몬스터 3(드라키), 마릿수 부호 0으로 두었습니다. 실제로 걸어서 붙은 전투에서 몬스터 종류 `03`·마릿수 1을 확인했습니다.

무기점의 키 1 목록을 `[00,01,08,1D,32,2F]`로 고치고, 기존 `dq5tables.py`로 물건 `00`의 가격을 77, `01`의 가격을 88×10으로 바꿨습니다. 상점 창에 바뀐 품목과 `77G`·`880G`가 보였습니다. 가격 계산 루틴 `21:A475`에서 읽은 결과도 여섯 품목 순서대로 `[77,880,850,1200,240,550]`과 같았습니다.

`MESENCE`를 설정한 뒤 다음 명령으로 레벨업·조우·상점 검사를 다시 돌립니다. 결과와 실행별 로그는 출력 폴더 아래 새 하위 폴더에 남습니다.

```sh
uv run --locked python sfc/dq5/tools/dq5progresscheck.py rom/dq5.sfc \
  --state work/state/ship.mss --out work/progresscheck
```

## 틀렸던 것들

원본 성장 표에도 중복 꺾임과 감소 곡선이 있었습니다. 새 입력에 적용할 규칙을 원본 전체에도 적용하면 정상적인 왕복을 막으므로, 수정하지 않은 원본 값은 보존하도록 고쳤습니다.
