# 2026-10-31-23: 일반 입구가 불리는 칸, 바다 구역 경계, 물건 k2 bit4·k4 하위

쓰기 도구(포팅용) 항목에 남은 질문 몇 가지를 풀었습니다.

- 일반 입구 `2A:F247` 이 어떤 칸에서 불리는지 찾고, 옮긴 일반 표로 들어가는 것을 게임에서 확인했습니다.
- 배의 바다 구역 직사각형 경계가 어느 쪽에 들어가는지 쟀습니다.
- `$100A`·`$100C` 를 읽는 곳을 정리했습니다.
- 물건 k2 bit4(`그룹무작위`)와 k4 하위 6비트의 뜻을 게임에서 쟀습니다.

결과는 쓰기 형식의 [입구 표 옮기기·늘리기](../docs/dq5-build-format.md#입구-표-옮기기늘리기)와 [물건 표](../docs/dq5-build-format.md#게임-데이터-표-dq5tables1), 데이터 형식의 [전투 조우](../docs/dq5-data-format.md#전투-조우-23e7c2)·[물건 표](../docs/dq5-data-format.md#물건-표-23b081), 필드 형식의 [마을 입장](../docs/dq5-field-format.md#마을-입장-2af247)에 있습니다.

## 1. 일반 입구는 마을 그림 칸의 아래 끝에서

`00:C7DD` 는 `$198F` 가 0 도 음수도 아닐 때만 `JSL 2A:F230` 으로 갑니다. `$198F` 를 켜는 것은 바로 앞에서 부른 계단 판정 `00:E2C5` 입니다. 실내(`$BE` bit7)에서는 계단 속성 `05`·`33`·`4C` 를 보고, 필드에서는 다른 갈래로 갑니다.

```text
00:E30B  LDA $3740 / CMP #$45 / …  LDA $3780 / CMP #$45 / …   ; 선 두 칸의 +4 가 모두 45
00:E321  $90 = $B6, $92 = $B8 + 1 / JSL $00BCA8 / CMP #$45 / BNE → $198F |= 7F
```

선 두 칸이 모두 `45` 이고 바로 아래 칸이 `45` 가 아니면 일반 입구를 봅니다. 이것을 확인하려고 `lua/dq5entrylog.lua` 를 썼습니다. 01/00 입구 아래 (331,71) 에서 위로 걸었습니다.

```text
f525 fdcb B6=331 B8=68 cells=4A,93,4A,93
f533 fdcb B6=331 B8=67 cells=4A,93,4A,93
f539 stair/normal/f247 B6=331 B8=67 198F=7F cells=45,93,45,93
```

보조 표(`2A:FDCB`)는 걸음마다 읽었고, `00:C7DD`·`2A:F247` 은 칸이 `45` 인 (331,67) 에서 한 번만 돌았습니다.

옮긴 표로 들어가는 것도 보았습니다. 일반 표를 `68:8000` 으로 옮기면서 맨 앞에 (331,67) → 그룹 `02` 를 하나 더 두었고, 그룹 01 항목은 그 뒤에 그대로 두었습니다. 장면 이동 도구로 01/00 에서 나오면 그룹 01 항목 자리 (331,67) 에 섭니다. 거기서 아래로 갔다가 다시 입구로 올라오면 02/00 (29,83) 에 들어갔습니다. 원래 롬은 같은 걸음으로 01/00 (32,92) 에 들어갔습니다. 들어갈 때는 좌표가 같은 첫 항목을, 나올 때는 그룹이 같은 첫 항목을 고릅니다. 이 장면은 `dq5entrancecheck.py` 에 둘을 더해 여섯 실행이 되었습니다.

## 2. 바다 구역 경계

`01:85A9` 는 `$B6`·`$B8` 을 `LSR` 로 반으로 나눈 블록 좌표를 직사각형과 견줍니다. X0·Y0 와는 `BCC`, X1·Y1 과는 `BCS` 로 비교하므로 [X0, X1)·[Y0, Y1) 일 것으로 보였습니다. 배는 걸음마다 이 루틴을 지나므로, 경계 양쪽이 모두 바다(지형 0)인 칸을 세계 0 지도에서 찾았습니다. 거기서 `LATESET="1954=03;21BE|01"` 로 배를 띄워 경계를 건너 저었습니다(`dq5searectcheck.py`, `lua/dq5searect.lua`). 둘째 직사각형은 `1948=02` 를 더했습니다.

```text
x0:  01:52 02:52 03:52 04:51            y0:  40:52 41:52 42:51 43:51
y1:  97:51 98:51 99:52 9A:52            x0b: 58:53 59:54 5A:54
x1b: A0:54 A1:53 A2:53                  y0b: 7A:53 7B:54 7C:54
y1b: C4:54 C5:53 C6:53
```

일곱 경계 모두 시작 값은 안, 끝 값은 밖이었습니다. 첫째 직사각형의 X1(33)은 양쪽이 바다인 칸이 없어 재지 못했습니다.

## 3. `$100A`·`$100C`

`$1009`~`$100C` 를 읽는 명령은 `22:86D5` 의 `LDA $1009,Y`(Y = 0~3) 하나였습니다. 다른 뱅크에서 걸린 것은 자료 바이트였습니다. 그러니 `$100C` 는 넷째 무리의 값이고, 다른 무리와 같은 길로 갑니다. 값은 `$0D1B` 를 거쳐 무리 표 `7E:0C24` 에 남습니다.

줄을 고르는 `22:92AE` 는 bit7 이면 2, `01` 이면 1, 그 밖이면 0 입니다. 그런데 `0C24` 를 읽는 다른 곳은 0 인지·음수인지만 봅니다. 부르기의 `22:D1C0` 은 값이 `01`~`7F` 인 무리에 몬스터를 더하지 않습니다. 효과 기준 칸 Y 를 정하는 `22:EB60`·`EBB2` 는 0 이 아닌 무리가 있으면 `03`, 0 인 무리가 있으면 `0A` 로 둡니다. 그래서 `02`~`7F` 는 앞줄에 서면서도 이 두 곳에서는 뒷줄처럼 셀 것으로 보입니다. 이 갈래는 재지 않았습니다.

## 4. 물건 k2 bit4 는 「그룹을 그대로」

`20:9531` 은 대상 그룹을 고른 뒤 `BRK #94 0E` 로 k2 bit4 를 읽습니다.

```text
20:9531  BRK #94 0E / PLA / BCS $953C / JSR $95EE / BRA / 953C: JSR $95F1
20:95EE  JSR $A917            ; 그룹에서 살아 있는 한 마리를 난수로
20:95F1  ASL ×3 / AND #$78 / ORA #$81 / STA $1037,X
```

조회 루틴은 비트가 켜져 있으면 carry 를 켭니다. 그러면 켜진 쪽이 난수를 건너뛰고 그룹 번호를 그대로 대상 바이트에 넣습니다. 앞서 문서에 적은 「켜져 있으면 난수」는 반대였습니다.

`dq5grouptargetcheck.py` 로 확인했습니다. やくそう(A1)를 적쪽으로 바꾸고 이 비트만 1·0 으로 둔 롬 둘을 만들었습니다. 첫 필드 이벤트 전투를 スライム 3 으로 붙이고, 명령 앞 기다림을 0·5·11·17·23·31프레임으로 바꿔 여섯 번씩 썼습니다.

```text
k2 bit4 = 1: $1037 83 83 83 83 83 83 (대상 0 0 0 0 0 0)
k2 bit4 = 0: $1037 83 83 93 93 83 8B (대상 0 0 2 2 0 1)
```

원래 이 비트가 켜진 17개는 그룹을 치는 いかずちのつえ 등입니다. `dq5tables.py` 의 키 이름은 바꾸지 않고, 문서에 뜻을 적었습니다.

## 5. 물건 k4 하위 6비트

k4 bit0-5 를 읽는 루틴은 `21:A5BA`(`LDA $23B3E1,X / AND #$3F`) 하나입니다. 이 루틴은 `BRK #94 n` 조회 표(`21:A3FF`)의 15번째 칸으로 갑니다. n 은 바이트이므로 `00 94 0F` 를 찾아야 합니다. 롬에서 `20:BA0F` 한 곳이 나왔고, 전투에서 물건을 쓰는 `20:B9F9` 안이었습니다.

```text
20:BA0A  STA $F6 / STA $10F7 / BRK #94 0F / LDA $46 / CMP #$06 / BNE …
         … ASL / TAX / LDA $2781D0,X / JSL $2485D4 / LDA $2781D1,X / JSL $2485D8
```

값이 `06` 이 아니면 `27:81D0` + 값 × 2 의 두 바이트를 전투 메시지로 띄웁니다. 표는 `01` → `0CC`「…を どうぐとして つかってみた！」, `07` → `0D3`「…を つかった！」 등이고, `08` 이상은 「けんから ほのおが まきおこる！」 같은 둘째 줄이 붙습니다. やくそう(A1)는 `07` 입니다. `dq5grouptargetcheck.py` 에서 이것을 `01` 로 바꾼 롬으로 써 보았습니다.

```text
k4하위 원래(07): 전투 메시지 0D3 094 05E 06A
k4하위 01:       전투 메시지 0CC 094 05E
```

값 `06`(`9A`~`9D`·`A0`)은 다른 갈래(`20:BA18`, `LDA $F5 / BRK #8B …`)로 가는데, 무엇을 하는지는 재지 않았습니다. 값은 216개 가운데 `01` 이 146개, `07` 이 24개입니다.

## 틀렸던 것들

- k2 bit4 를 「켜져 있으면 난수로 한 마리」로 적었습니다. `BCS` 의 방향을 거꾸로 읽은 것이고, 실측으로 반대임을 확인했습니다.
- k4 하위를 읽는 `BRK` 를 `00 94 15` 로 찾아 「읽는 길이 없다」고 적었습니다. n 15 는 16진 `0F` 입니다.
- 처음 대조 실행은 (331,68) 에서 아래·위 24프레임씩 걸어 입구 칸까지 되돌아오지 못했습니다. 고친 롬과 같은 자리 (331,67) 에서 시작하게 했습니다.
