# 2026-10-27-63: 맵을 놓은 뒤 더 쓰는 인물 슬롯

[인물 목록 재배치](2026-10-27-19-npclists.md)의 `--allow-growth` 는 맵의 인물을 슬롯 `1F` 까지 늘립니다. 그런데 맵을 다 놓은 뒤에도 장면 코드가 `7E:1983` 부터 슬롯을 더 씁니다. 그런 맵에서 인물을 끝까지 늘리면 장면이 다음 칸으로 넘쳐 쓸 수 있습니다. 슬롯을 더 쓰는 두 루틴(`04:FB1C`, `01:BA95`)이 어느 맵·장면에서 몇 슬롯을 쓰는지 찾아, `dq5npcrelocate.py` 의 한도에 넣었습니다. 결과는 [맵 형식의 「인물 슬롯」](../docs/dq5-map-format.md#인물-슬롯-81)에 있습니다.

## 부르는 곳을 장면까지

`04:FB1C` 를 부르는 일곱 곳은 대부분 이벤트·번호 스크립트의 네이티브 호출 안이었습니다. 부르는 루틴의 첫머리를 이벤트 표·번호 표·대화 스크립트의 `00`·인물 스크립트의 `37` 에서 찾아 맵까지 이었습니다.

- 1A/02 アルカパ 여관: 대화 `029` → 번호 `01` → `02:AE69`.
- 06/08 天空城 조종 방: 이벤트 3 → `06:D704`.
- 1A/00: 대체 목록 `10:B4E3` 의 パパス 스크립트 → 번호 `05` → `02:AF9B`.
- 22/00: ポワン 대화 `04D` → `06:C00A`.
- 01/05: 번호 `3D` 의 `1E:DDB3`.
- 11/00: 기본 목록 `05:A3D2` 인물의 스크립트 → `05:E72A` → `05:E838`·`05:E7EC`.

`01:BA95` 는 06/00 의 マスタードラゴン 대화 `23A` 와, 06/05 대체 목록 `10:AB3A` 의 인물 `10:ABB5` 스크립트(`05:E931`)에서 불립니다.

처음에는 `JSL` 만 찾았습니다. 그래서 같은 뱅크의 `JSR`·`JMP` 로 들어오는 `05:E7EC`·`05:E838`, 인물 스크립트 `37` 로 들어오는 `05:E72A`·`05:E931` 을 놓쳤습니다. 1F/00·23/00 의 번호 `4E`·`4F` 가 부르는 `05:E8AC` 도 `05:E931` 로 이어진다고 잘못 읽었습니다. 실제로는 `JSL 05:E8EC; RTL` 이고, `05:E8EC` 도 `05:E914` 의 `RTL` 에서 끝납니다. 지금은 긴 호출(`JSL`·`JML`, 인물 스크립트 `05`·`37`, 이벤트 스크립트 `A0`)을 롬 전체에서, 같은 뱅크 호출(`JSR`·`JMP`·`JSR (a,X)`·`JMP (a,X)`, 뱅크 06 이면 대화 스크립트 `00`)을 그 뱅크에서 바이트 꼴로 찾습니다. 결과가 정해 둔 목록과 같은지도 `dq5slotusecheck.py` 가 봅니다(`callers`). `04:FB1C` 는 일곱 곳의 `JSL` 뿐입니다. `01:BA95` 는 두 곳의 `JSL`, `05:E931`·`05:E72A` 는 스크립트 `37` 하나씩입니다.

처음 세운 장면 셋은 아무것도 걸리지 않았습니다. 배 선실의 매 프레임 루틴(17/00)과 31/02·1B/07 의 맵 뒤 루틴은 첫머리가 가까웠을 뿐, 부르는 곳은 따로 있었습니다. 1A/02 는 パパス 와 같은 줄에 서면 말이 걸리지 않았습니다. 두 칸 아래 (12,14) 에서 위로 걸어 올라가 말을 걸자 메시지 `77F` 뒤에 `02:AE7B` 가 불렸습니다.

## 몇 슬롯을 쓰나

| 장면 | `$1983` | 쓴 슬롯 |
| --- | --- | --- |
| 1A/02 여관 | `0D` → `0E` | `0D` |
| 06/08 이벤트 3 | `0D` → `0E` | `0D` |
| 대화 `23A`(선실 パパス 에 넣음) | `0D` 그대로 | `0D`·`0E`·`0F`·`10` |
| 06/05 `10:ABB5` 스크립트 | `12` 그대로 | `12`·`13`·`14`·`15` |
| 11/00 `05:A3D2` 스크립트 | `12` → `14` | `12`·`13` |

`04:FB1C` 는 하나를 만들고 `$1983` 을 늘립니다. `01:BA95` 는 넷을 쓰면서 `$1983` 은 늘리지 않습니다. 둘 다 `02:B3B4` 로 슬롯 X 의 인물 표 값을 슬롯 Y 에 복사해 만듭니다. 슬롯을 비우는 루틴이 아닙니다.

06/05 는 `7E:2190` bit7 로 대체 목록을 고르고, 스크립트가 기다리는 `21A1` bit6 을 미리 켜고 들어갔습니다. 메시지 `50E`·`50F` 뒤 `05:E931` 이 불렸습니다. 11/00 은 처음 두 번 슬롯을 만들지 않았습니다. `219F` 쓰기를 지켜보니 `05:E72A` 가 bit3·4 를 먼저 끄고, 인물 `02`·`01` 이 마차 밖 일행에 살아 있을 때만(`BRK 8B`) 다시 켰습니다. 선실 상태의 일행에는 두 인물이 없습니다. 그래서 일행 레코드 1·2 에 인물 레코드 표(`23:C014`)의 `01`·`02` 를 베끼고 `219F` bit7 을 켜자, `05:E852`·`05:E806` 이 차례로 `04:FB1C` 를 불렀습니다. 1A/02 의 이벤트는 이어서 `LDX #$0C` 로 슬롯 `0C` 를 움직이는데, 이것은 목록 다섯째 인물(그림 `30`, 맵 밖 (46,3) 에 있던 ビアンカ)이었습니다. 이 맵에서 인물을 지우거나 앞에 끼우면 이벤트가 다른 인물을 옮깁니다.

## 슬롯 20 은 다음 칸

인물 표는 칸마다 `$20` 슬롯이라, 슬롯 `20` 은 다음 칸의 슬롯 0 입니다. 대화 `23A` 장면을 `$1983` = `1E` 로 시작하자 `01:BA95` 가 슬롯 `1E`~`21` 을 썼고, 인물 표 곳곳의 슬롯 0·1(주인공과 일행 첫째) 자리 42바이트가 바뀌었습니다. 같은 장면을 `0D` 로 돌리면 0바이트입니다.

그래서 `--allow-growth` 한도를 맵마다 min(`1F`, `20` − 장면이 더 쓰는 수)로 바꾸었습니다. 06/00·06/05 는 `1C`, 11/00·1A/00·01/05 는 `1E` 입니다. 늘어난 맵을 알릴 때는 남은 슬롯도 함께 냅니다. 1A/02 를 23명으로 늘린 롬에서는 여관 장면이 슬롯 `1F` 를 쓰고 끝까지 갔습니다. 24명은 거부되었습니다.

코드로만 읽은 1A/00·22/00·01/05 도 같은 한도에 넣었습니다. 1A/00 은 들어서면 아침 장면(메시지 `23C`~`241`)이 이어졌지만 번호 `05` 가 기다리는 `21A2` bit7 이 켜지기 전에 끝났습니다. 06/00 은 대화 `23A` 를 쓰는 인물이 그 맵 대체 목록 `10:AA73` 에만 있어 붙였습니다. 잰 곳은 배 선실(18/03)입니다.

## OBJ VRAM

같은 장면에서 맵을 다 놓은 뒤 OBJ 다음 타일 `$1995` 는 1A/02 가 `013C`, 06/08 이 `00F4` 였습니다. [맵 OBJ·탈것 타일 쓰기](2026-10-27-56-objtiles.md)에서는 탈것 타일이 `180` 부터 올라가므로, 그 자리까지라면 1A/02 는 68타일, 06/08 은 140타일이 남습니다. OBJ 이름 표 자리(`$2101`)는 이 장면들에서 쓰이지 않아 재지 못했고, `180` 앞을 다른 것이 쓰는지도 보지 않았습니다.

## 남은 것

- 1A/00·22/00·01/05 장면과, 06/00 맵 안에서 대화 `23A` 를 거는 장면의 실측.
- 같은 방문에서 대화 `029`·`04D` 를 두 번 걸 때 `04:FB1C` 가 다시 도는지. 다시 돈다면 `$1983` 이 더 늘어납니다.
- 함수 포인터 표나 `JSL [$xx]` 처럼 주소가 바이트 꼴로 드러나지 않는 호출.
- 맵마다 OBJ VRAM 의 끝(`$2101` 이름 표와 `180` 앞의 다른 쓰임)과, 그로부터 새 그림 번호·세트가 쓸 수 있는 타일 수.
- 슬롯 번호를 직접 쓰는 다른 이벤트 코드(`02:AFBC` 의 `LDX #$12` 등)가 가리키는 인물. 1A/02 의 `0C` 만 확인했습니다.
