# 2026-10-25-150: 시퀀스 인코더와 곡 바꿔 넣기

[곡 시퀀스 형식과 효과음](2026-10-25-143-sound5.md) 에서 만든 디코더를 다시 싸는 쪽까지 늘렸습니다. 곡 하나를 다른 악보로 바꿔 넣어 실제로 울리는지 DSP 기록으로 봤고, FC DQ4 곡을 옮겨 넣을 때 걸리는 한계를 적었습니다. 결과는 [dq5-sound-format.md](../docs/dq5-sound-format.md) 「인코더와 바꿔 넣기」「한계와 둘 자리」에 있습니다. 소리 자료와 만든 롬은 커밋하지 않았습니다.

## 1. 다시 쌀 수 있는 글

앞의 디코더는 흐름으로 닿는 바이트만 트랙별로 보여 주어, 그대로는 다시 쌀 수 없었습니다. 그래서 본문을 처음부터 끝까지 차례로 풀고, 닿지 않는 바이트는 `db` 로 남기는 `listing` 을 더했습니다. 점프 오프셋은 숫자 대신 이름(`LXXXX`)으로 적어, 글을 고쳐 길이가 바뀌어도 싸는 쪽이 다시 셉니다.

이름이 겹치는 것이 둘 있었습니다.

- 명령 `F1`·`F2` 가 둘 다 `follow` 였습니다. `F1` 을 `follow1` 로 나눴습니다.
- 시퀀스 머리의 템포와 명령 `EB` 가 둘 다 `tempo` 였습니다. 처음 싸 보니 `KeyError: '60'` 이 났고, 머리 줄은 들여 쓰지 않고 본문은 들여 쓰는 것으로 가렸습니다.

```
$ uv run --locked python sfc/dq5/tools/dq5song.py rom/dq5.sfc --check
...
46: tempo 78 tracks 1 bytes  383 unread   0
71 sequences (decoded and re-encoded), 0 problems
```

0x47개 모두 풀었다 다시 싼 바이트가 원래와 같았습니다.

## 2. 마법 융단 곡을 음계로

곡 `03` 을 두 트랙짜리 음계(트랙 0 은 도레미파솔라시도, 트랙 1 은 도파솔도)로 바꿨습니다. 시퀀스 묶음은 포인터 없이 길이로 이어 걷기 때문에, 길이 바이트는 그대로 두고 42바이트 뒤를 `FF` 로 채워 1703바이트를 덮었습니다.

`work/snd/scale.txt`:

```
tempo 73
track L0
track L1
L0:
  instrument 00
  volume 60
  volume2 C0
  gate_preset CC
L0LOOP:
  note 31 len 18
  note 33
  note 35
  note 36
  note 38
  note 3A
  note 3C
  note 3D len 30
  rest
  jump -> L0LOOP
L1:
  instrument 00
  volume 40
  volume2 C0
L1LOOP:
  note 25 len 30
  note 2A
  note 2C
  note 31 len 60
  jump -> L1LOOP
```

```sh
uv run --locked python sfc/dq5/tools/dq5song.py rom/dq5.sfc 03 --encode work/snd/scale.txt -o work/b03/song03.dq5patch.json
uv run --locked python sfc/dq5/tools/dq5build.py rom/dq5.sfc build work/b03/song03.dq5patch.json \
    -o work/b03/dq5s.sfc --ips work/b03/dq5s.ips
```

만든 롬으로 융단을 펴고 `lua/dq5dspw.lua` 로 기록했습니다. 목소리 0 의 첫 KON(911 프레임)은 앞 곡이 남긴 것이라 950 부터 견줬습니다.

```
$ uv run --locked python sfc/dq5/tools/dq5song.py rom/dq5.sfc 03 --seqfile work/snd/scale.txt \
    --kon work/snd/k03s/dspw.txt --start 950 --count 16
track 0: 16 notes, 0.6551 frame/tick, max frame error 1.1, pitch mismatches 0
track 1: 16 notes, 0.6528 frame/tick, max frame error 1.7, pitch mismatches 0
```

목소리 0 은 반음 0·2·4·5·7·9·11·12, 목소리 1 은 0·5·7·12 로 울렸습니다.

## 3. 한계

SPC 쪽 자리를 세는 초기화 `22F4` 는 샘플·시퀀스를 `$28E7`(= `2A5D`)부터 `D6F6` 앞까지 둡니다. 고정 샘플·시퀀스를 빼면 27,609바이트가 남습니다. 원래 곡 가운데 가장 큰 `15` 가 26,402바이트를 써서, 남는 것은 1KB 남짓입니다. 시퀀스 칸은 0x14개 중 17개를 고정 효과음이 차지해 곡 몫은 셋입니다.

곡 묶음 표 `2B:E67F` 는 드라이버 이미지 안에 있었습니다. 롬 `2B:C58F`~ 를 SPC `0800`~ 과 견주니 `15DF` 앞까지 같았습니다. `15DF` 는 명령 처리 루틴의 `CALL` 대상을 고쳐 쓰는 자리입니다. `F0`(악기)이 SPC `28EC` 에 올라간 이 표를 보므로, 악기 구성을 바꾸면 SNES 쪽 전송과 SPC 쪽 악기 고르기가 함께 바뀝니다.

## 4. 남은 명령

- `E2`: 읽는 곳이 없어 보였던 `78`·`8C` 는 틱마다 도는 `1F04` 가 읽었습니다. 표 `08D4` 의 n 번째를 따라 미세 음높이 `8D` 를 틱 단위로 바꾸는 음높이 엔벨로프이고, KON 마다 처음(`79` = 2)부터 다시 돕니다.
- `E6`: `1E0B` 가 음량 2(`29`)를 목표까지 남은 틱으로 나눠 다가가게 합니다. 필드 곡 트랙 1(`volume2 40`, `e6 80 C0`)에서 목소리 1 의 왼쪽 음량이 `09` → `12` 로 두 배가 되었습니다.
- 스크립트 연산 `11`~`18` 은 모노·스테레오, 주 음량, 메아리 음량·되먹임·지연, FLG 였습니다.

`$0F1B` bit6 의 장면 `06:C297` 은 대화 `055`(22/01 (4,13))였습니다. 장면 이동 도구로 네 방향에서 말을 걸었지만, 그 자리에 인물이 없어 はなす 만 열렸습니다. 선실 파파스의 대화 번호를 `055` 로 바꿔도 `06:C297` 은 돌지 않았습니다.
