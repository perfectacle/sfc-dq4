# 2026-10-24-04: 출구

DQ4 맵을 넣으려면 맵과 맵을 잇는 출구(문·계단·사다리)를 알아야 합니다. 이번 일지는 그것을 찾은 과정입니다.
결과는 [dq5-map-format.md 의 「출구」](../../dq5-map-format.md#출구-2af6b8) 에 있습니다.

## 1. 맵 전환인데 출구가 아니었다

오프닝의 맵 전환(왕좌의 방 → 출산 방)에서 `$BC`/`$BD` 에 쓰는 코드를 잡으니 `00:C013` 이었습니다.
`[$80]` 포인터로 바이트를 읽어 `$BC $BD $C1 $C2 $C3 $198E` 에 차례로 넣는, **이벤트 스크립트의 「맵 이동」 명령**이었습니다.
컷신이 맵을 옮긴 것이라 출구 데이터는 지나지 않았습니다.

ROM 에서 `STA $BC` 꼴 바이트를 모두 찾아(120곳) 뱅크 `$01` 의 후보를 읽어 보니 `25:8621` 표를 쓰는 곳이 있었는데,
키가 맵 번호라 루라(순간이동 주문) 목적지 표에 가까웠습니다. 결국 플레이어가 직접 문을 밟게 하는 수밖에 없었습니다.

## 2. 조작할 수 있는 장면까지

A 연타로 12,000프레임을 돌리니 6,000프레임쯤 몇 년 뒤 배 선실 장면이 나오고 주인공을 움직일 수 있었습니다.
그 직전에 연타를 멈추고 세이브스테이트를 만들었습니다(`mkstate.lua`).

```sh
SHOT_DIR=$PWD/work/state MAXF=6460 EVERY=0 PERIOD=40 TAP=a TAPUNTIL=6150 SAVEAT=6450 STATE=ship.mss \
  "$MESENCE" --testrunner "$PWD/rom/dq5.sfc" "$PWD/tools/lua/mkstate.lua"
```

## 3. 어디가 출구인가

처음엔 프레임 수로 방향키를 눌렀는데, 걷는 속도가 일정하지 않아 원하는 칸에 서지 못했습니다.
방향을 바꿔 가며 네 번 걸어 봤지만 맵이 바뀌지 않았고, 걸을 때마다 읽히는 ROM 표(`0F:D635-`)는 출구가 아니라 화면 스크롤 때 새 줄을 그리는 코드였습니다.

실마리는 맵 디코더에서 왔습니다. 왕좌의 방에 작은 계단 그림이 있는 칸을 보니 위층 속성 `+7` 이 `$05`/`$85` 였고,
배 맵(17/00)에서도 같은 값이 짐칸 가운데 칸막이 안 (7~8, 22~23) 에 있었습니다. 맵 그림을 보니 사다리였습니다.

![17/00 과 17/02. 빨간 틀이 출구 셀, 초록 칸이 밟은 자리와 도착 자리](../../images/dq5-exits-ship.webp)

## 4. 자동 보행

목표 셀까지 정확히 가려고, 매 프레임 주인공 좌표(`7E:3020`/`7E:3080`)를 읽어 그쪽으로 방향키를 누르는 `walk.lua` 를 만들었습니다.

```sh
STATE=$PWD/work/state/ship.mss PRE="b:4,wait:40,b:4,wait:40" WAYPOINTS="3,11;3,24;7,24;7,22" SHOT_DIR=$PWD/work/walk3 \
  "$MESENCE" --testrunner "$PWD/rom/dq5.sfc" "$PWD/tools/lua/walk.lua"
```

```
f00144 reached 3,11
f00288 reached 3,24
f00328 reached 7,24
f00362 map 17/00 -> 17/02 at x=7 y=23
f00482 end map 17/02 x=10 y=41
```

사다리 칸에 올라서자 17/02 로 넘어가 (10, 41) 에 섰습니다. 이 드라이버를 `boot.lua` 자리에 끼우면(`seqlib.sh`)
지금까지의 감시·집계 스크립트를 세이브스테이트에서 걸어가는 상황에 그대로 쓸 수 있습니다.

## 5. 출구 번호는 「앞에 있는 출구 셀의 수」

그 순간 `$BD` 에 쓰는 곳은 `2A:F7AD`, 도착 좌표는 `2A:FCF8`~`FD07` 이었고, 리스팅을 읽으니 구조가 독특했습니다.

- `2A:FC16`: 셀 버퍼를 0번 셀부터 **플레이어 셀 바로 앞까지** 훑으며 `+4`/`+7` 이 `2A:FF37` 목록(`$85 $A1 $B3 $CC`)인 셀을 센다. 그 수가 출구 번호.
- `2A:F6FD`: `2A:ED61` 표에서 `$BC` 그룹 → `$BD` 번째 맵의 항목들 → 출구 번호 번째 항목.
- `2A:FC93`: 새 맵을 푼 뒤 그 맵에서 N 번째 출구 셀을 찾아 한 칸 왼쪽에 세운다.

출구 데이터에 좌표가 없고, 맵에 출구 블록을 놓은 순서가 곧 연결 번호입니다. 블록 오른쪽 아래 셀에만 속성 bit7 이 붙어
(앞 일지의 블록 전개) 2x2 계단도 한 번만 세어집니다.

Python 으로 옮기니 실제로 걸어 본 결과와 같았습니다.

```
map 17/00: exit cells 1, table entries 1
  0: cell (8, 23) [c2 00] at 2AEFF5: 17/02 의 출구 0 → 도착 (10, 41)
```

## 6. 전부 검사

출구 번호를 셀 순서로 매기므로, 맵마다 출구 셀 수와 목적지 항목 수가 같아야 합니다.

```
entries-cells Counter({0: 258, 1: 87, -1: 1})
```

87개 맵은 항목이 정확히 하나 더 많았고, 그 마지막 항목은 83개가 특수 종류(`00`)였습니다.
플레이어가 맵 가장자리 밖에 서면 모든 출구 셀이 「앞」에 있으니 출구 번호가 셀 수가 되어 바로 그 여분 항목을 고릅니다.
가장자리로 걸어 나가 필드로 나가는 출구로 보이지만, 아직 직접 걸어 보지 않은 가설입니다. 항목이 하나 적은 1개 맵도 남았습니다.

## 틀렸던 것들

- 오프닝의 맵 전환 = 출구: 이벤트 스크립트 명령이었다.
- `25:8621` 표 = 출구 표: 키가 맵 번호라 루라 목적지 쪽으로 보인다.
- 걸을 때마다 읽는 `0F:D635-` = 출구 검사: 스크롤 때 새 줄을 그리는 코드였다.
- 프레임 수로 걷기: 속도가 일정하지 않아 칸을 놓쳤다. 좌표를 읽어 걷는 드라이버로 해결.
