# 2026-10-25-40: 세계 2 를 오가는 순간이동 칸, 54/52 의 문, $194A 의 나머지

[2026-10-25-34 일지](2026-10-25-34-field3.md) 에서 못 찾은 세계 2 의 길을 찾았습니다. 표가 아니라 칸 속성 `$33` 에 반응하는 순간이동이었고, 세계 2 쪽 30/00 과 세계 0 쪽 52/50 을 잇습니다.
54/52 의 막힌 영역 이동을 여는 플래그도 찾아 그룹 `$50` 이상 영역 이동 25개를 모두 밟았습니다. 결과는 [dq5-field-format.md](../docs/dq5-field-format.md) 의 「순간이동 칸」과 [dq5-map-format.md](../docs/dq5-map-format.md) 의 「영역 이동」에 있습니다.

## 1. 표에서 꺼낸 값을 `$BC` 에 쓰는 곳

즉값이 아닌 값을 `$BC` 에 쓰는 명령(`STA`·`STX`·`STY $BC`)을 롬 전체에서 모으자 97곳 중 코드로 보이는 것이 열 남짓이었고, 대부분 아는 표(`0F:EA97`, 영역 이동, 세이브 복원 `06:B7CB`)였습니다.
새로 나온 것이 `03:9BAE` 였습니다. `03:9BEB` 의 네 바이트 `01 2A 52 30` 에서 지금 `$BC` 를 찾아, 짝이 되는 `03:9BEF` 의 `[$BC][$BD][X][Y]` 로 보냅니다. 01 ↔ 2A, 52 ↔ 30 이 짝이고, 30 은 세계 2 그룹입니다.

거슬러 올라가니 `00:C99E` 가 맵을 옮길 때 출구 속성 `$00` 이 `$33` 이면 `02:BB37` → `03:9B0F`(화면 일렁임) → `03:9B9C` 로 갔습니다. 디코더로 칸 `+4` 가 `$33` 인 곳을 찾으니 30/00 의 (13~14,11~12), 2A/00 의 (18~19,10~11) 이었고 52/50·01/00 에는 없었습니다.

## 2. 실제로 밟기

30/00 (13,15) 에 서서 위로 걷게 하고 맵 번호 쓰기를 지켜보았습니다.

```
600 039B0F A=0033 ... 0000=CA33
1246 039B9C
1246 00BC pc=03:9BB0 v=52
f02103 end map 52/50 cell 26,25
```

순간이동 칸을 밟은 600프레임에서 일렁임이 시작되고 650프레임쯤 뒤 52/50 (26,25) 에 섰습니다. 2A/00 (18,11) 의 칸도 같은 식으로 01/0A (8,10) 에 보냈습니다. 52/50 은 0F/00 으로 이어지니 세계 2 → 세계 0 의 길입니다.

반대쪽 52/50 에는 그 칸이 없어서, 52/50 셀 버퍼에 칸을 직접 써 넣었습니다(셀 버퍼가 `7F` 뱅크로 넘어가는 자리라 `7F:16E4`·`16EC`·`1894`·`189C`).

```sh
STATE=$PWD/work/state/ship.mss FIELD=452,231 \
  ROMPATCH="1573E6=52;1573EC=50;27E7D=52;157F2A=FF;1573F0=1A;1573F4=35;1573F8=01" \
  LATE="700:7F1894=33;7F189C=B3;7F16E4=33;7F16EC=B3" TEST="down:30,wait:300,up:40,wait:1500" ...
```

위로 걸어 그 칸을 밟자 30/00 (13,12) 로 갔습니다. 30/00 에서 아래로 걸어 나가면 `$1949` = 2 인 필드 (38,114) 에 섭니다. 세계 2 로 들어가는 길은 「52/50 에 순간이동 칸이 생기는 것」이고, 그 칸을 놓는 이벤트는 찾지 못했습니다.

## 3. 54/52 의 문

54/52 의 맵별 루틴 `03:BA55` 는 `BRK #$0B 02 2F`(`7E:21BF` bit1)가 켜져 있으면 셀 `7E:DE91`·`DE99`·`DEA1`·`DEA9` 에 `04` 를 씁니다. 폭 56 으로 풀면 (26~29,17) 의 `+1`, 곧 막혀 있던 레코드 칸입니다.
`SET="21BF|02"` 로 들어가 (27,18) 에서 위로 걷자 54/53 (17,41) 에 섰고, 플래그 없이는 (27,18) 에서 멈췄습니다. 이로써 그룹 `$50` 이상 영역 이동 25개를 모두 밟았습니다.

## 4. `$194A` 를 읽는 곳 전부

던전 걷기·주문, 필드 걷기·ルーラ, 필드 전투 세 장면에서 `$194A` 읽기 감시를 걸었습니다. 읽는 곳은 `00:830C`·`00:834A`·`02:C792`·`2A:FDA3` 이고, `22:8820`·`22:88B0` 은 `$1949` 를 16비트로 읽으며 따라 걸린 것이었습니다.
하위 비트를 3·4 와 비교하는 곳과 `21:8763`(`& 1F` < 3, 코드 읽기)뿐이라 `01`·`02` 는 `00` 과 다르지 않습니다. bit7 은 `02:C792` 가 실내에서 켜져 있으면 일행 필드 `91` 을 보고 `$1954` 를 정해, 마차를 데려갈 수 있는 맵 표시로 보입니다.

## 5. `$198E` bit7

장면 이동 도구에 일행을 만드는 `PARTY` 가 들어와, 그룹 `1A` 입구 항목의 `+4`(파일 오프셋 `7EB1D`)를 `04`·`84`·`06`·`86` 으로 바꿔 `PARTY=02,05` 로 들어갔습니다.
bit7 이 꺼진 `04`·`06` 은 동료 둘이 주인공 뒤(위를 보면 아래, 아래를 보면 위)에 줄지어 섰고, 켜진 `84`·`86` 은 동료가 주인공 자리에 겹쳐 보이지 않았습니다. `00:E360` 이 고르는 `00:E59F` 갈래가 동료를 주인공 자리에 두는 쪽입니다.

## 6. `$1A33`

앞 일지까지 맵 불러오기·던전 보행·전투·도망·명령 창·교회 저장·탈것 값·リレミト·ルーラ 에서 한 번도 읽히지 않았습니다. 실측 범위에서는 쓰지 않는 값으로 적고 todo 에서 뺐습니다.
