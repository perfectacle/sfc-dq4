# 2026-10-27-53: 대화 스크립트 574개 넘게 늘리기

[대화 스크립트 쓰기](2026-10-27-20-talkwrite.md)는 원래 스크립트 574개를 고치고 뱅크 06 안에서 옮기는 데까지였습니다. DQ4 의 마을 사람 수만큼 대사를 두려면 스크립트 수 자체를 늘려야 합니다. 이번에는 원본에서 쓰이지 않는 대화 번호 `900`~`FFF` 를 새 스크립트에 주고, 늘린 뱅크에 두게 했습니다. 형식과 확인 결과는 [쓰기 형식의 「대화 번호 900~ 에 스크립트 덧붙이기」](../docs/dq5-build-format.md#대화-번호-900-에-스크립트-덧붙이기)에 있습니다.

## 1. 번호를 어디서 가져오나

대화 번호 갈래는 `011`~`24E` 스크립트, `24F`~`26C` 묻기, `26D` 이상 메시지 `T + 3C6` 입니다. 메시지는 3,200개라 `8B9` 를 넘는 번호는 원본에서 쓰이지 않습니다. 인물 레코드의 대화 번호는 12비트입니다. `06:AF62` 는 인물 표 `7E:36E0`·`7E:3700` 두 바이트를 16비트로 읽어 `$0F19` 에 둡니다. 롬 전체에서 `CMP #$024F`·`SBC #$024F`·`CMP #$026D`·`$0F19` 를 찾아보니 모두 `06:AF62`~`B35x` 의 갈래 고르기 안이었습니다. 다른 곳(`02:B52E`·`12:9277`)은 인물 슬롯끼리 값을 옮기기만 합니다. 그래서 새 번호를 `900` 부터 쓰기로 했습니다. 위 바이트가 `09` 이상인지만 보면 되어 루틴이 짧아집니다.

## 2. 뱅크 06 에 묶여 있던 것 풀기

[앞 일지](2026-10-27-20-talkwrite.md)에서 스크립트는 데이터 뱅크 06 에 묶여 있다고 적었습니다. 데이터 뱅크를 정하는 곳을 하나씩 보니 셋이었습니다.

- `06:AF93`: 묶음 표를 읽고 건너뛰기 전에 `06` 으로 둠.
- `06:B05D`: 실행 직전에 `06` 으로 둠.
- 네이티브 호출: `06:B135` 가 `PHB` 만 하고 바꾸지 않아, 원래는 실행기의 `06` 을 이어받음.

실행기는 `$0F1C`·`$0F2F`·`$0A01` 같은 WRAM 과 롱 주소 `7E:2190` 만 쓰므로, 데이터 뱅크가 낮은 WRAM 거울이 있는 `30`~`3F` 면 그대로 돌 것으로 보았습니다(코드 읽기, 아래 3절에서 쓴 명령·조건만 게임에서 확인). 그래서 네 자리를 바꿨습니다.

1. `06:AF7B` 의 `CMP #$024F` → 조회 루틴. `900` 이상이면 `06:AF89` 처럼 `n` 을 쌓고 `JSR` 복귀 주소를 버립니다. 그다음 새 묶음 표에서 시작을 읽고 데이터 뱅크를 스크립트 뱅크로 두어, 원래 건너뛰기 `06:AF9C` 로 들어갑니다. 끝의 `06:AFF1` `PLB` 가 원래 뱅크로 되돌립니다.
2. `06:B04F` 의 `CMP #$024F` → 덧붙인 번호도 스크립트로 실행하게.
3. `06:B05D` 의 `LDA #$06` → 대화 번호에 따라 `06` 이나 스크립트 뱅크.
4. `06:B136` 의 `JSR $B13C` → 인자를 읽은 뒤 데이터 뱅크를 `06` 으로 두고 네이티브 루틴으로. 원래 루틴들은 `06` 을 전제로 쓰였을 것이라 맞췄습니다.

네 루틴은 84바이트로, 뱅크 06 빈 자리 `06:FE10` 에 두었습니다. 덧붙인 스크립트 쪽은 32개 묶음마다 16비트 시작 주소를 앞에 두는 원래 꼴 그대로입니다. 그래서 건너뛰기 규칙 검사와 부호화를 원래 스크립트와 같이 씁니다. `dq5talk.py` 도 `900` 이상을 읽게 했습니다.

## 3. 원래 뱅크의 같은 스크립트와 견주기

대화 `900`~`921`(34개, 묶음 둘)을 `3F:8000` 에 넣은 롬과, 같은 몸통 셋을 원래 스크립트 `012`·`013`·`014` 에 넣은 대조 롬을 만들었습니다. 선실 파파스의 대화 번호를 `POKE` 로 바꿔 말을 걸었습니다.

```
900 vs 012: 74F | 74F
901 vs 013: 616 616 616 616 618 1CC 74F | 616 616 616 616 618 1CC 74F
921 vs 014: 129 742 | 129 742
012 덧붙인 롬 vs 원본: 742 | 742
02/06 인물 대화 번호 921: 1D1 129 742 | 129 742
```

플래그(`7E:2190`~`219F`·`21F0`~`21F3`)도 쌍마다 바이트까지 같았습니다. `901` 은 BRK 로 일행을 조회하는 조건 넷(`03`·`13`·`11`·`20`), はい/いいえ, 네이티브 호출(`06:B3A0` → 메시지 `1CC`), 플래그 쓰기를 한데 모은 스크립트입니다. 데이터 뱅크가 `3F` 인 채로 BRK 서비스가 돌아도 같은 결과였습니다. `921` 은 둘째 묶음의 둘째 스크립트라 새 묶음 표와 건너뛰기를 함께 거칩니다.

마지막 줄은 [인물 레코드 쓰기](2026-10-27-14-npcrecord.md)로 02/06 인물 하나의 대화 번호를 `921` 로 바꾸고, 그 인물에게 걸어가 말을 건 것입니다. `1D1` 은 그 맵에 들어설 때의 장면 메시지로 원본에서도 나옵니다.

`dq5talkgrowcheck.py` 가 이 다섯 비교를 재현합니다. 롬 없이 도는 단위 검사도 넷 더해 21개입니다(옮길 곳·순서·뱅크 검사, 왕복과 늘리기, 루틴 옮기기·원래 스크립트와 함께 쓰기·뱅크 끝·다른 자료와 겹침·네 자리 일부만 바뀐 롬 거부, 빈 자리 밖 거부).

## 틀렸던 것들

- 앞 일지는 스크립트 수 574 를 늘리지 않는다고 적었습니다. 갈래를 정하는 비교가 `06:AF7B`·`B04F` 두 곳뿐이라 루틴으로 돌릴 수 있었습니다.
- 앞 일지는 스크립트를 뱅크 06 밖에 두려면 실행기와 네이티브 루틴을 바꿔야 한다고 보았습니다. 실행기는 데이터 뱅크만 `30`~`3F` 로 두어도 3절의 명령·조건이 같은 결과였고, 네이티브 루틴은 부르는 순간만 `06` 으로 돌리면 됐습니다.

## 남은 것

- 덧붙인 뱅크에서 BRK 일행 조회 조건의 거짓 갈래와, 돌리지 않은 조건 `02`·`14`·`1A`·`1E`·`1F`.
- 이미 넣은 덧붙인 스크립트를 줄이거나 지우는 쓰기.
- 번호 `FFF` 근처처럼 위 바이트가 큰 번호를 인물 레코드로 거는 실측(이번에는 `921` 까지).
- 원래 스크립트를 덧붙인 뱅크로 옮기기(지금은 원래 574개는 뱅크 06 에 그대로).
