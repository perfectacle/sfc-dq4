# 2026-10-27-01: SPC 스크립트 연산 실측

사운드 드라이버의 스크립트 연산 `03`·`04`·`11`~`17` 은 그동안 코드만 읽고 적어 두었습니다. 이번에 스크립트 자리에 시험할 바이트를 써 넣고 게임에서 돌려, 연산 전부와 그동안 표에 없던 트랙 연산 `20`~`BF` 를 DSP 값으로 확인했습니다. 결과는 [dq5-sound-format.md 「효과음과 스크립트」](../docs/dq5-sound-format.md#효과음과-스크립트) 에 넣었습니다.

## 1. 스크립트를 곡 자리에 돌리는 길

처음에는 메뉴 효과음 `0C 33` 을 `0C 02 00`(지금 흐르는 필드 곡 `02` 와 스크립트 `00`)으로 바꿔 보냈습니다. 아무것도 바뀌지 않았습니다. `0C31` 은 이미 오른 곡이면 `1450` 에서 빠져 스크립트까지 가지 않습니다. `0C 33 00` 그대로면 스크립트가 돌기는 하지만, 자리 번호(Y)가 효과음 자리 `01` 이라 곡 음량 같은 자리 연산은 효과음에 걸립니다.

SPC 명령 `05` 의 처리기 `0BBB` 를 읽으니 `$F6` 이 시퀀스 번호, `$F7` 이 스크립트 번호였습니다. `1FC0` 이 그 시퀀스가 오른 자리를 찾아 자리마다 스크립트를 돌리고, 못 찾으면 Y = `FF` 로 돌립니다. 대기열 명령 `05` 도 인자와 X 를 그대로 넘기는지 보려고 `0C 33` 을 `05 02` X `00` 으로 바꾸고 스크립트 `00` 을 `00 30 FF` 로 덮었습니다. 608 프레임에 자리 0 음량이 `80` → `30` 이 되었습니다.

새 프로브 `sfc/dq5/tools/lua/dq5sscript.lua` 는 `SSAT` 프레임에 SPC RAM `SSADDR`(기본 `0843`, 스크립트 `00` 자리)를 `SSCRIPT` 로 덮고, 프레임마다 DSP(주 음량·메아리·FLG·지연·EON·NON·필터·목소리 음량)와 드라이버 변수(`03A7`~`03F9`, `$A9`~`$B0`), 그 프레임의 KON 을 `sscript.txt` 로 남깁니다. 끝에서 `dq5sndlog.lua` 를 이어 불러 바꿔 보내기를 그대로 씁니다.

```sh
K=$(uv run --locked krpatch sfc lua); mkdir -p work/warplib
ln -sf "$K/lib.lua" work/warplib/; ln -sfn "$K/probe" work/warplib/probe
cp sfc/dq5/tools/lua/dq5warp.lua work/warplib/boot.lua
env LIBDIR=$PWD/work/warplib STATE=$PWD/work/state/ship.mss FIELD=341,56 SETTLE=60 TEST="wait:100,a:4,wait:1000" \
  HFROM_CMD=0C HFROM_ARG=33 HCMD=05 HARG=02 HX=00 SSCRIPT=03FF DSP=1 MAXF=1500 SHOT_DIR=$PWD/work/ss/o03 \
  "$MESENCE" --testrunner "$PWD/rom/dq5.sfc" "$PWD/sfc/dq5/tools/lua/dq5sscript.lua" --Snes.DisableFrameSkipping=true
```

명령은 604 프레임에 나가고 608 프레임에 반영됩니다. 같은 틀로 스크립트 바이트만 바꿔 서른두 번 돌렸습니다(8개씩 병렬, 한 번에 16초).

## 2. 곡 음량 연산은 「목표」 가 아니라 속도

`01`·`04` 를 「곡 음량 목표」 로 적어 두었는데, 음량을 매 틱 바꾸는 `1E7B` 를 읽으면 `03C7` 은 부호 있는 속도입니다. 틱마다 r/32 를 더해 0 에 닿거나 `80` 을 넘으면 멈추고 속도를 0 으로 둡니다. `04` 는 여기에 `03D7` bit0 을 켜는데, 이 bit 가 켜진 채 0 에 닿으면 `22AF` 로 곡을 끝냅니다.

```
01 F0  776 프레임 음량 0, KON 은 610~1500 프레임 49번(보내지 않았을 때와 같음)
04 F0  777 프레임 음량 0, 마지막 KON 767, EON 1F → 00
18 F0  04 F0 과 같음(자리 03F9 = 0)
03     608 프레임 목소리 음량 모두 0, 그 뒤 KON 없음, 03F9 = FF
```

`01` 은 곡을 소리 없이 계속 흘리고, `04`·`18` 은 줄인 뒤 끝내고, `03` 은 바로 끝냅니다. SPC 명령 `04`(곡 줄이기)가 r = -X 로 같은 자리를 쓰는 것도 이 때문입니다. 시퀀스 명령 `E5` 도 같은 속도 칸을 씁니다.

## 3. 메아리와 모노

`13 40 20` 은 주 음량을 `40,20` 으로, `14 30 10` 은 메아리 음량을 `30,10` 으로, `15 0A` 는 FLG 를 `15` → `0A`, `16 40` 은 되먹임을 `40` 으로 바꿨습니다. `10` 뒤 8바이트는 필터 계수 `FF 08 17 24 24 17 08 FF` 를 그대로 덮었습니다.

`17 03` 은 지연을 `03` 으로 바꾸면서 메아리 쓰기를 끄고(FLG `35`) 메아리 음량을 `00,00` 으로 내렸습니다. 611 프레임에 FLG 가 `15` 로 돌아오고, 615 프레임에 메아리 음량이 `14,EC` 로 돌아왔습니다. 메아리 버퍼가 바뀌는 동안 낡은 메아리를 내지 않으려는 기다림입니다. `17 08` 은 지연이 `05` 그대로라 5 로 잘리는 것도 맞았습니다. 기다림 중에 `14`·`16` 을 보내면 DSP 에 쓰지 않고 저장만 했다가 기다림 끝(612 프레임)에 씁니다.

`11` 은 메아리 음량 `14,EC` 를 `14,14` 로 바꾸고, 다음 음량 계산부터 팬을 쓰지 않아 목소리 음량이 `12,17` → `17,17` 처럼 양쪽이 같아졌습니다. 필드의 오른쪽 메아리 음량은 음수(`EC`)인데, 모노에서는 이것도 왼쪽 값으로 바뀝니다. `13 40 20 11 12` 는 주 음량이 `40,20` 으로 남아, `12` 가 저장해 둔 오른쪽 값을 되돌리는 것을 확인했습니다.

롬에서 SPC 명령 `05` 를 부르는 입구 `24:FED0` 의 네 곳 가운데 `23:FEA1` 은 A bit0 을 뒤집어 `1F` 를 더한 값으로 스크립트 `1F`(`11`)·`20`(`12`)을 고릅니다. 이것을 부르는 `25:80D4` 는 `7E:2035` bit6 을 넘깁니다. 처음에는 저장이 없는 세이브스테이트라 타이틀에서 바로 새 게임이 시작되어 메뉴를 볼 수 없었고, 같은 명령 `05 1F` X `1F` 를 바꿔 보내 위와 같은 결과를 얻었습니다.

그 뒤 메뉴까지 가 보았습니다. 선실 세이브스테이트를 불러 WRAM `7E:2000`~`2A9F` 와 체크섬(`25:8450` 과 같은 워드 합)을 SRAM 칸 1 에, 롬 `25:8000` 의 머리를 `0000`·`1FF2` 에 쓰고 리셋했습니다. 모험의 서 메뉴가 「ぼうけんをする / せっていをかえる / …」 로 떴고, せっていをかえる → 칸 1 → 말 빠르기 → 「ステレオ　モノラル」 창에서 오른쪽을 눌러 モノラル 를 골랐습니다. 고르는 순간에는 아무 명령도 나가지 않았습니다. 이어 ぼうけんをする 로 칸 1 을 불러오자 2571 프레임에 `23:FEB1` 의 `05 1F` 가 나가고, 메아리 음량 `14,14`, 목소리 음량 `0E,0E`·`0B,0B`·`14,14`, `03EF` = `00` 이 되었습니다. ステレオ 그대로 불러온 쪽은 `05 20` 이었고 `14,EC` 와 `13,0C` 처럼 좌우가 달랐습니다. `25:80D4` 는 설정 화면이 아니라 불러오기 쪽 루틴입니다.

## 4. 트랙 연산 `20`~`BF`

스크립트 `16` 의 `22 32 42 52 62 72 82 92` 는 표에 없는 바이트였습니다. `224B` 는 바이트를 `XCN` 한 뒤 2 를 빼서, 위 4비트 - 2 를 트랙 번호, 아래 4비트를 연산으로 씁니다. `22`~`92` 는 트랙 0~7 의 메아리 켜기입니다.

```
20 F0  트랙 음량 곱 속도: 목소리 0 음량이 2프레임마다 줄어 0
21 20  트랙 음량: 목소리 0 12,17 → 06,08
23     메아리 끄기: EON 1F → 1E (23 22 는 1F 로 돌아옴)
24     잡음 켜기: NON 01, FLG 아래 5비트가 음마다 0E·13·11·10
26     트랙 끝: 목소리 0 음량 0, KON 49 → 44
28     12,17 → 12,E9 (오른쪽 부호)
29     EE,17 (왼쪽 부호)
2A     EE,E9
```

`1F3C`·`1F5C` 가 쓰는 DSP `3D` 는 처음에 피치 변조로 잘못 읽었는데, `3D` 는 NON(잡음)이고 실측에서도 NON 이 켜졌습니다. 위상 연산 `27`~`2A` 는 `0380` 에 0~3 을 두고, 음량을 DSP 에 쓰기 직전(`1AF2`)에 bit0 이면 오른쪽, bit1 이면 왼쪽 값을 부호 반전합니다.

`06`·`19` 같은 빈 번호는 인자 없이 건너뛰었습니다. `06 40 FF` 는 `06` 을 넘긴 뒤 `40 FF`(트랙 2 음량 곱 속도 -1)로 읽혀 목소리 2 가 줄었고, 그 뒤에 남아 있던 원래 바이트 `05 01` 까지 돌아 곡 변수가 1 이 되었습니다.

## 5. 되풀이 효과음을 끝내는 `05`

나머지 세 곳은 모두 `05 n` X `01` 입니다. 효과음 `32`·`3C`·`44`(갈래 `0D`)는 `if_flag 01` 로만 빠져나오는 고리를 돌고, 게임이 변수를 1 로 두어 끝냅니다.

```
32  0C 32 00 → 목소리 7 이 2~3프레임마다 KON → 2719 05 32 → 2722 꺼짐 (불러온 뒤 「よくぞもどられた！」)
3C  937 0C 3C 00 → 938 05 3C → 939 KON 한 번 → 940 꺼짐 (슬롯, 맞음 판정 8B39D=EAEA)
44  550 0C 44 0D → 695 05 44 → 697 변수 1 → 724 꺼짐 (15/01 미닫이 방, 도착 뒤 21F0=07·21F6=01)
```

`3C`·`44` 는 `JSL 24:FED0` 네 바이트를 `EA` 로 덮어 다시 돌렸습니다. `3C` 는 목소리 7 이 2프레임마다 KON 을 계속했고, `44` 는 1,700 프레임 끝까지 울렸습니다.

## 틀렸던 것들

- `01`·`04`·`18`·`E5` 를 「곡 음량 목표」 로 적었습니다. 목표 값이 아니라 틱마다 더하는 부호 있는 속도입니다.
- 트랙 연산의 `L` = `4`·`5` 가 쓰는 DSP `3D` 를 피치 변조로 읽었습니다. `3D` 는 NON(잡음)입니다.
- `0C 02 X` 로 지금 곡에 스크립트를 돌릴 수 있다고 보았습니다. 이미 오른 곡에는 스크립트까지 가지 않습니다. 대기열 명령 `05` 를 씁니다.
- `24:85C9` 의 `05 32` 를 「전투 메시지를 찍을 때」 로만 적었습니다. 필드 대화에서도 나가고, 창이 열릴 때 시작한 `32` 의 되풀이를 끝내는 명령입니다.
- `25:80D4` 를 소리 설정 화면의 루틴으로 보았습니다. 설정 화면에서 고를 때는 아무것도 보내지 않고, 모험의 서를 불러올 때 보냅니다.
