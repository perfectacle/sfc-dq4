# 2026-10-25-118: 곡 줄이기·키우기 명령과 탈것 곡

[곡 명령의 반응과 세계별 필드 곡](2026-10-25-110-sound2.md) 에서 뜻을 모르고 남긴 명령 열한 개를 DSP 기록으로 가르고, 배·마법 융단·天空城·マスタードラゴン 을 타고 내릴 때 보내는 명령을 기록했습니다. 결과는 [dq5-sound-format.md](../docs/dq5-sound-format.md) 에 있습니다.

## 1. 명령을 바꿔 보내기

`02`·`03`·`04` 를 부르는 곳은 여관·교회·이벤트 등 여러 장면에 흩어져 있습니다. 장면을 하나씩 만드는 대신, 필드에서 A 로 메뉴를 열 때 나가는 `0C 33` 을 바꿔치기했습니다. `dq5sndlog.lua` 가 `24:FF83` 에 들어오는 순간 A·X 레지스터와 스택의 인자를 고쳐 쓰는 방식입니다(`HFROM_CMD`·`HFROM_ARG` 로 고를 명령, `HCMD`·`HARG`·`HX` 로 보낼 명령).

```sh
LIBDIR=$(tools/lua/seqlib.sh "$(uv run --locked krpatch sfc lua)" work/warplib ../../sfc/dq5/tools/lua/dq5warp.lua)
mkdir -p work/h/c04
env LIBDIR=$LIBDIR STATE=$PWD/work/state/ship.mss FIELD=341,56 SETTLE=60 TEST="wait:100,a:4,wait:420" \
  HFROM_CMD=0C HFROM_ARG=33 HCMD=04 HARG=02 HX=0020 DSP=1 MAXF=1000 SHOT_DIR=$PWD/work/h/c04 \
  "$MESENCE" --testrunner "$PWD/rom/dq5.sfc" "$PWD/sfc/dq5/tools/lua/dq5sndlog.lua"
```

필드 곡은 `02` 입니다. 채널 0 음량을 8프레임마다 적으면 이렇습니다.

```
04 02 X=20  11,16 11,16 0F,14 0E,12 0C,10 0B,0E 09,0C 07,09 05,07 04,05 02,03 01,01 00,00
03 02 X=20  11,16 00,00 02,02 03,04 05,07 07,09 08,0B 0A,0D 0B,0F 0D,11 0E,13 10,15 12,17
04 05 X=20  11,16 12,17 12,17 12,17 12,17 …
```

`04` 는 곡을 줄이고 `03` 은 0 에서 키웁니다. X 를 `10`·`20`·`40` 으로 바꾸면 끝나는 프레임이 774·691·649(줄이기), 776·696·656(키우기)이라, 걸리는 시간은 X 에 반비례합니다. 인자가 지금 곡(`02`)이 아니면 `04`·`02` 는 아무것도 하지 않았습니다. 그래서 인자는 곡 번호이고, 롬에서 `04` 를 부르는 곳 대부분이 `LDA $194B`(맵 곡) 다음에 있는 것과도 맞습니다. `02 02` 는 4프레임 뒤 모든 채널의 ENVX 를 0 으로 만들어 곡을 바로 멈췄습니다.

`0D`·`0E`·`94`·`95`·`96` 은 인자를 `00`·`01`·`02`·`80` 으로 바꿔 보내도, `8B 00`·`93 00`·`09 1F` 도 DSP 기록이 바꾸지 않은 것과 같았습니다. 전원을 켜서 기록하니 `8B 00`·`93 00` 은 54프레임에 `00:A6E1`·`A6E5` 가 한 번씩 보내는 초기화 명령이었습니다.

## 2. SPC RAM 으로 본 흔적

DSP 에 안 보여도 드라이버 상태는 바뀔 수 있어, `SPCDUMP` 로 640 프레임의 SPC RAM 64KB 를 떠서 `0D` 를 보낸 것과 견줬습니다. 덤프 파일은 `work/` 에만 두었습니다.

```
c8b  018B:00/0B 053C:12/32 0544:10/30 054C:10/30 0554:10/30 055C:10/30 0564:10/30
c93  0185:02/46 018B:00/13 05DA:10/30 05E0:10/30 05E6:10/30 … 063A:10/30
c94  0185:02/00 018B:00/10 05DA:10/30
c95  00F4:40/C0 018E:40/C1 01C2:11/1D 01C4:A2/A5
```

`8B` 와 `93` 은 같은 간격으로 늘어선 표를 한꺼번에 `30` 으로 고칩니다. 무슨 표인지는 SPC 프로그램을 읽어야 알 수 있어 뜻은 정하지 않았습니다. `0D` 와 `0E` 는 SPC RAM 까지 같았습니다.

## 3. 탈것

배는 handoff 의 걸어서 오르는 방법으로, 마법 융단은 アイテム 창 입력을 다시 맞춰 실제로 폈습니다(이번 입력은 handoff 에 적음). 天空城·드래곤은 `LATESET=1954=81`·`82` 로 탄 상태를 만들고, 타고 내리는 루틴 입구를 `WATCH` 로 함께 기록했습니다.

```
배         565 cmd=1A arg=04 from=01:82DD / cmd=0C arg=04 from=00:92E9
융단 펴기   898 cmd=1A arg=00 from=01:BC87 / cmd=01 arg=03 from=00:92AB
융단 내리기 1111 exec 01BDEA / cmd=1A arg=FF from=01:BE38 / cmd=01 arg=02 from=01:BE3F
天空城     462 exec 01C2EF / cmd=01 arg=0D from=00:92AB
드래곤     462 exec 01BFD1 (명령 없음)
드래곤 내리기 583 exec 01C213 / cmd=1A arg=01 / cmd=01 arg=02 from=01:C21A
```

`$1954` 가 `80` 이상이면 `00:810C` 가 A 를 메뉴 대신 `01:BC3F` 로 보내 내리기를 합니다. 융단을 산 위에서 내리려 하면 「ここでは 降りられない。」만 나오고 명령은 없었습니다. 天空城은 잔디 위에서도 메시지만 나와 내리는 곡은 보지 못했습니다.

곡 번호로는 마법 융단 `03`, 天空城 `0D` 이고, 배는 `0C 04` 로 틀었습니다. 드래곤은 필드 곡을 그대로 둡니다. 함께 보낸 `1A` 의 인자는 `04`·`00`·`FF`·`01` 로 곡 번호와 달라, 맵 곡에서 「`1A` 인자 = 곡 번호」로 본 것은 맵을 불러올 때에만 맞는 말입니다.

## 남은 것

- `02`·`03`·`04` 를 부르는 실제 장면(여관·교회·문·이벤트 `C6` 등)에서의 기록.
- `0D`·`0E`·`94`·`95`·`96`·`8B`·`93`·`09` 의 뜻, 명령 `1A` 인자의 뜻, 天空城에서 내릴 때의 곡.
- 곡·효과음 이름. 이번에도 소리를 들어 보지 않아 이름을 붙이지 않았습니다.
