# 2026-10-25-129: 문 명령 넷째 바이트는 층

[주인공 とびら 명령과 위쪽 문](2026-10-25-119-door.md)에서 남긴 둘(판정 때 `7E:1E8E` 가 `01` 인 까닭, `01:ED05` 가 쓰이는 문)을 닫았습니다. 결과는 [dq5-map-format.md](../docs/dq5-map-format.md#인라인-스크립트-01c800)의 `41`·`43` 줄에 있습니다.

## 1. 주인공 쪽의 `1E8E` 는 층

23/00 (40,22) 에서 とびら 를 고르는 순간을 `tools/lua/pcseq.lua` 로 뱅크 01 에서 따라가니 `01:D8C2` → `01:D9CE` 였습니다.

```
01:D9CE  LDA $C1 / STA $1E8C     ; 주인공 X
01:D9D3  LDA $C2 / STA $1E8D     ; 주인공 Y
01:D9D8  LDA $C3 / STA $1E8E     ; 주인공 층
```

이때 DB 가 `01` 이라 실제로는 `01:1E8C`(WRAM 하위 8KB 미러)에 씁니다. 앞 일지에서 `7E:`·`00:` 주소로만 쓰기 감시를 걸어 아무것도 안 걸린 까닭입니다. 덤프의 `1E8C`·`1E8D` 도 주인공 자리((40,25) 면 `28 19`, (40,22) 면 `28 16`)였습니다.

`POKE=7E00C3=04` 로 주인공 층을 고정하고 같은 길을 걸어 とびら 를 고르자 `01:DAF5`(거절)를 지나지 않고 `01:DA99` 로 가 문이 열렸습니다(셀 (40,19) `+2` `5D` → `57`). `02` 로 고정하면 (40,26) 에서 한 칸도 못 걸었습니다.

## 2. `C4` 문은 칸의 층을 n 으로

문 열기(`01:D915`)는 문 표 `01:D2FC`(맵마다 `[X][Y][종류 & 7F][..][..]`)에서 찾은 종류로 `01:DFC7` 에서 갈립니다. `BB`~`BD`·`BE`·`C3`·`C5`·`C6`·`CD`·`BF`·`C0`·`C1`·`C2`·`C7`~`C9`·`D7` 밖의 종류는 `01:ECE2` 로 가고, 여기서 `01:ED05` 가 칸 `+1` 에 n 을 OR 합니다.
표에서 그런 종류는 `C4` 하나(7곳: 01/04 (67,10), 02/02 (33,52), 02/07 (31,18) 등)였습니다.

01/04 의 대체 목록(`7E:219E & 02`)에는 `41 43 0A 01` 로 바로 그 문을 여는 인물이 있습니다. (62,8) 에 서서 메시지를 넘기고, 넷째 바이트만 `01`·`02`·`04` 로 바꿔 덤프를 견줬습니다.

```
         (67,12)+1 (67,13)+1 (67,14)+1 (67,15)+1
n=01        01        01        09        19
n=02        02        02        0A        1A
n=04        04        04        0C        1C
```

세 경우 모두 `01:ED05` 가 한 번 돌았습니다. 문 아래 네 칸의 걸을 수 있는 층(`+1` bit0-2)이 n 이 됩니다.

## 틀렸던 것들

- 「쓰기 감시에 걸리지 않으니 블록 복사일 것」이라 보았지만, 실제로는 보통 `STA` 가 뱅크 01 미러 주소로 쓴 것이었습니다. 감시는 `01:1E8C` 처럼 실행 뱅크의 미러까지 걸어야 합니다.
