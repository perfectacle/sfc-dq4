# 2026-10-27-06: 표 쓰기의 물건·주문·피해량·동료 실측

`dq5tables.py`로 고친 물건 플래그·주문 필드·피해량·동료 몬스터 표가 게임에서 쓰이는지 확인했습니다. 표마다 대표 필드를 고친 롬과 원래 롬으로 같은 장면을 돌려, 결과가 갈리는 것을 봤습니다. 결과는 [쓰기 형식](../docs/dq5-build-format.md#게임-데이터-표-dq5tables1)에 있습니다.

## 1. 이미 확인한 것과 남은 것

몬스터 표는 표 쓰기 도구를 만들 때 HP·경험치·금화를 전투에서 봤습니다. 물건 가격은 상점 검사에서, 물건 `00` 의 힘과 メラ 의 전투 MP 는 포팅 도구 점검에서 봤습니다. 남은 것은 물건 플래그, 주문의 범위·적쪽·대상루틴, 피해량 표, 동료 표였습니다.

이 가운데 물건 플래그와 주문 대상루틴의 뜻은 형식 문서를 쓸 때 롬 바이트를 직접 고쳐 확인했습니다. 이번에는 뜻이 아니라 `dq5tables.py patch` → `dq5build.py build` 로 만든 롬을 게임이 읽는지를 봅니다.

## 2. 장면 셋

새 장면을 만들지 않고 이미 쓰던 장면 셋을 골랐습니다.

| 장면 | 시작 | 고친 표 |
| --- | --- | --- |
| 무기점 장비 비교 창 | 선실 세이브스테이트. 상점 검사와 같은 입력 | 물건 `06` どうのつるぎ 의 `장비사람`, `칸` |
| 파파스가 슬라임 셋에게 メラ | 선실 → 첫 필드 이벤트. 슬라임 HP 200, 파파스 행동 여섯을 모두 メラ | 주문 `01` 의 `대상루틴`, 피해량 `01` |
| 슬라임을 동료로 들임 | 필드 341,56 의 이벤트 전투(슬라임 하나) | 동료 `02`(スライム) 의 `레벨`·`HP`·`MP` |

장면을 준비하는 롬 덮기와 매 프레임 쓰기는 Lua 가 합니다. 동료 장면에서는 동료 조건(`7E:21B1` bit6, `$1010` bit7)을 주고 `27:8162` 의 등급 7 칸을 1 로 바꿨습니다. 이 칸은 16비트 8개라 등급 7 은 `27:8170` 입니다. 처음에 한 바이트짜리 표로 보고 `27:8169` 를 고쳤더니 슬라임이 일어나지 않았습니다. 어느 덮기도 확인하는 표의 바이트를 건드리지 않습니다.

물건은 처음에 `00` ひのきのぼう 의 장비 비트를 고쳤습니다. 그런데 장비 검사 `21:A561` 의 AND 값이 그대로 `80` 이었습니다. 읽는 자리를 `23:B591`~`23:B668` 전체로 넓히자 비교 창이 읽는 것은 진열 첫 품목 `06` 의 `23:B597` 이었습니다. ひのきのぼう 는 주인공이 든 무기라 이 창에서 힘(`23:B4B9`, 포팅 도구 점검)은 읽히지만 장비 비트 `23:B591` 은 읽히지 않았습니다.

## 3. 결과

```text
물건 06 장비사람 A6 → 26   21:A561 AND 80 → 00   「13▶ 24」 → 「そうびできない」
물건 06 칸 0 → 1            23:B237 00 → 01        「こうげきりょく 13▶ 24」 → 「しゅびりょく 7▶ 16」
メラ 대상루틴 975F → 97BC    한 번에 1마리 → 3마리   원래 12·13·15, 고친 롬 (12·15·14)·(13·14·14)
피해량 01 바탕 12 폭 4 → 40 1  피해 12·13·15 → 40·40·40
동료 02 레벨·HP·MP 1·8·0 → 7·99·42  일행 레코드 +12·+2·+4 가 그대로 바뀜
```

칸을 1(갑옷)로 바꾸자 どうのつるぎ 를 갑옷으로 견줬습니다. 지금 수비력 7 에서 입은 ぬののふく 의 4 를 빼고 힘 13 을 더해 16 입니다. メラ 는 대상루틴만 바꿔도 한 번에 셋을 쳤고, 피해는 원래 범위 12~15 그대로였습니다. 피해량은 폭을 1 로 두어 난수가 0 만 나오게 했더니 세 번 모두 40 이었습니다.

동료 장면에서는 「なかまに くわわった！」(`0A5`) 뒤 `21:814B` 가 `23:AEE3` 의 `07` 을 읽었습니다. 일행 셋째 레코드는 원래 롬에서 레벨 1·HP 8·MP 0, 고친 롬에서 레벨 7·HP 99(최대도 99)·MP 42(최대도 42)였습니다.

## 4. 다시 돌리기

`dq5tablecheck.py` 가 다섯 롬을 만들고 원래 롬과 함께 8회(장면 준비까지 9회) 실행한 뒤 위 값을 단언합니다. 표 읽기 값은 `lua/dq5tablecheck.lua` 가 남깁니다. 읽기 PC 는 MesenCE 읽기 콜백의 값이라 읽은 명령 다음 주소입니다. 칸은 비교 창이 계산해 `7E:0046` 에 남긴 새 능력치(24 → 16)도 봅니다. 상점 화면 문구는 두 롬의 `end.png` 를 눈으로 견줬습니다.

```sh
MESENCE=… uv run --locked python sfc/dq5/tools/dq5tablecheck.py rom/dq5.sfc \
  --state work/state/ship.mss --out work/tablecheck
```

```text
9회 실행, 수정 5건(표 4종) 게임 검사 통과
```

## 틀렸던 것들

동료 확률 표 `27:8162` 를 한 바이트짜리로 보고 고쳤습니다. 표에 256·1024 같은 값이 있으니 16비트일 수밖에 없었습니다.

장비 비교 창이 주인공이 든 무기의 장비 비트를 읽는다고 보았습니다. 실제로는 진열 품목의 장비 비트와 든 무기의 힘을 읽습니다.

## 남은 것

물건의 나머지 플래그(`팔수없음`·`쓰면없어짐`·`저주` 등), 주문 `범위`·`적쪽`, 동료 `최대레벨`·`장비갈래` 는 고친 롬으로 게임에서 보지 않았습니다. `장비갈래` 는 동료 몬스터의 장비 검사(`21:A57D`)가 읽으므로, 동료 몬스터가 있는 상점이나 장비 장면이 필요합니다.
