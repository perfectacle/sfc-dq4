# 2026-10-25-08: 디버그 모드 찾기와 장면 이동 도구

다른 실험들이 막혀 있던 이유는 하나였습니다. 실험 출발점이 배 선실 세이브스테이트뿐이고, 필드로 나가면 강제 전투 뒤 조작이 막힙니다. 그래서 숨은 디버그 모드가 남아 있는지 찾아보고, 없으면 선실에서 어느 장면으로든 갈 수 있는 도구를 만들기로 했습니다. 디버그 메뉴로 들어가는 입구는 남아 있었지만 메뉴 코드는 롬에 없었고, 대신 만든 도구 `sfc/dq5/tools/lua/dq5warp.lua` 의 사용법은 [dq5-handoff.md 「장면 이동 도구」](../handoff.md#장면-이동-도구) 에 있습니다.

## 1. 2P 패드를 읽는 곳

디버그 기능은 흔히 2P 패드나 평소 안 쓰는 버튼으로 켭니다. 패드 레지스터를 읽는 명령을 롬에서 찾으니 `00:8BE5` 한 곳이 1P~4P(`$4218`~`$421E`)를 `$0748`~`$074F` 에 옮겨 두고 있었습니다.
2P 값 `$074A`/`$074B` 를 읽는 명령은 롬 전체에서 `2B:849F` 하나였습니다.

```
2B:848A  LDA $7F / AND #$07 / BNE 끝      ; 이 프레임에 다른 일이 없을 때
         LDA $7E / BNE 끝
         LDA $018000 / CMP #$FF / BEQ 끝  ; 01:8000 이 FF 가 아닐 때만
         LDA $0749 / ORA $074B / AND #$20 ; 1P 나 2P 의 SELECT
         BEQ 끝
         JSL $309495
```

보행 중 매 프레임 `00:8090` 이 부르는 곳입니다. 조건은 둘입니다. 파일 오프셋 `8000`(`01:8000`)이 `FF` 가 아니어야 하고, SELECT 를 눌러야 합니다. 팔리는 롬의 `01:8000` 은 `FF` 라서 이 길은 늘 닫혀 있습니다.

## 2. 뛰어갈 곳이 롬에 없다

`30:9495` 는 이 롬 밖입니다. 롬은 1.5MB(뱅크 `00`~`2F`)인데, 롬 머리의 크기 바이트(`7FD7`)는 `0B`, 곧 2MB 입니다.
개발용 기판에는 뱅크 `30`~`3F` 에 512KB 가 더 꽂혀 있었고, 디버그 메뉴는 거기 들어 있었던 것으로 보입니다.

실제로 열어 보았습니다. 조작 가능한 필드 세이브스테이트(아래 3절에서 만든 것)에서 `ROMPATCH="8000=00"` 을 주고 SELECT 를 누르자 `2B:84A6` → `30:9495` 로 들어갔습니다.
MesenCE 는 없는 뱅크 `30` 을 파일 오프셋 `101495`(`20:9495`)로 비추는데, 그곳은 명령 중간이라 엉뚱한 코드가 돌고 이름이 빈 「は を となえた!」 창이 떴습니다. 패치하지 않으면 같은 입력에도 `2B:84A6` 에 닿지 않습니다.

```
8000=FF: (호출 없음)
8000=00: 22 2B84A6 ... / 22 309495 ... ret=2B:84AA
```

메뉴 코드가 없으니 이 입구는 쓸 수 없습니다. 공개 자료(일본어 공략·소문 모음)에서도 SFC 판 DQ5 의 디버그 모드나 순간이동 코드는 찾지 못했습니다.

## 3. 필드에서 조작이 막히는 까닭

도구를 만들려면 먼저 필드 조작이 막히는 까닭을 알아야 했습니다. 배 사다리 출구 항목을 덮어 01/00 (32,92) 로 간 뒤 아래로 걸어 나가니, 필드 (331,67) 에 서자마자 슬라임 셋과 전투가 붙었습니다.
조우 계수 표 `23:EA44` 를 0 으로 해도 같았으니 무작위 조우가 아닙니다.

무리를 쓰는 곳부터 거슬러 올라갔습니다.

1. `wwatch.lua` 로 `$1001`~`$1008` 을 감시했습니다. `7E:1001` 로는 안 걸리고, 뱅크 `00` 미러 `00:1001` 로 걸었더니 `26:8E2D` 가 `23:D757 + 무리*13` 에서 13바이트를 옮기고 있었습니다.
2. `calls.lua` 로 호출자를 따라가니 `26:8DF1`(A = 무리 1) ← `01:8608` ← `01:86A7`, 그리고 `01:86A7` 을 부른 곳은 `02:A782` 였습니다.
3. `02:A775` 는 `$1AA0` 에 6 을 넣고 무리 1번 전투를 거는 이벤트 루틴입니다.

맵을 푼 뒤 도는 맵별 루틴 표 `15:F907` 에는 `$BC` 가 `FE` 인 필드용 항목이 넷 있습니다.

```
fe 00 04 80  15:F906 (없음)  02:AB33   ; 7E:2194 bit7 켜짐
fe 00 84 80  02:A94C         02:AC98   ; 7E:2194 bit7 꺼짐
fe 01 ff 00  15:F906         02:AC98
fe 02 ff 00  15:F906         02:AC98
```

선실 세이브스테이트의 `7E:2194` 는 `00` 입니다. 그래서 필드에 나가면 `02:A94C` 가 골라져 파파스와의 첫 전투 이벤트가 돌고, 이벤트가 끝날 때까지 조작이 막힙니다.
`7E:2194` bit7 만 켜고 같은 길로 나가자 전투 없이 바로 걸을 수 있었습니다.

## 4. 도구: `dq5warp.lua`

`walk.lua` 의 사다리 순간이동을 장면마다 쓰기 좋게 묶었습니다.

- `TO=BC/BD,X,Y[,방향]` 으로 사다리 항목을 종류 `60` 항목으로 덮습니다.
- `FIELD=X,Y` 는 01/00 으로 간 뒤 아래로 걸어 나갑니다. 필드로 나갈 때 쓰는 입구 표 `04:FD97` 의 그룹 01 항목을 주어진 좌표로 덮고, `7E:2194` bit7 을 켭니다.
- `BATTLE=몬스터:마릿수,…` 는 반대로 bit7 을 끈 채 나가, 이벤트 전투 무리 1번(`23:D757 + 13`)을 고른 몬스터로 바꿉니다.
- `SET` 은 시작할 때 한 번만 WRAM 을 고칩니다. `walk.lua` 의 `POKE` 는 매 프레임 같은 값을 써서 다른 비트까지 덮기 때문에 따로 두었습니다.

도착하고 기다렸다가 세이브스테이트를 남기고, `TEST` 입력으로 좌표가 바뀌는지 봅니다. 장면마다 이렇게 확인했습니다.

| 장면 | 명령 | 결과 |
| --- | --- | --- |
| 필드 | `FIELD=341,56 TEST="left:40,up:40"` | 322프레임에 배를 떠나 440프레임에 필드 (341,56). (341,56) → (336,52) 로 움직임 |
| 필드에서 걷기·조우 | 만든 세이브스테이트를 원래 롬으로 불러 좌우로 1,200프레임 | `23:E7C2`(조우 판정) 42번, 381프레임에 구역 `0D` 에서 トンネラー 4마리 전투 |
| 필드에서 마을로 | 같은 세이브스테이트에서 `left:80,down:100` | 그룹 01 입구 (331,67) 를 밟아 01/00 (32,92) 로 들어감(`$BE` = `80`) |
| 실내 맵 | `TO=04/00,27,75 TEST="up:40"` | 04/00 (27,75) 성문 앞, (27,71) 로 움직임 |
| 전투 | `FIELD=341,56 BATTLE="0C:2,00:1"` | 「つちわらし − 2ひき」「スライム − 1ひき」 전투 명령 창 |

필드에서 마을로 들어간 실험은 [dq5-field-format.md 「마을 입장」](../docs/dq5-field-format.md#마을-입장-2af247) 이 코드만 읽고 적은 `04:FD97` 입구 판정을 실제로 걸어 확인한 첫 결과이기도 합니다.

## 틀렸던 것들

- 첫 필드 전투를 「무작위 조우를 꺼도 붙는 강제 전투」로만 보고 조우 쪽을 찾았습니다. 실제로는 필드에 나갈 때 도는 맵별 루틴(`15:F907` 의 `FE` 항목)이 플래그 `7E:2194` bit7 을 보고 거는 이벤트였습니다.
- `$1001` 쓰기를 `7E:1001` 로 감시하면 아무것도 걸리지 않습니다. 게임은 뱅크 `00` 의 WRAM 미러(`00:1001`)로 씁니다.

## 남은 것

- 시대(`$1949`)를 바꾼 장면, 동료·탈것 상태를 바꾼 장면 — 해결됨: `dq5warp.lua` 의 `ADULT`·`PARTY`·`WAGON`·`POKE 7E1949`([handoff.md](../handoff.md) 「장면 이동 도구」)
