# 2026-10-25-93: 맡기는 곳에서 찾는 한도, 슬라임 레이스 倍率 코드, D005 의 기다림

[앞 일지](2026-10-25-78-shop4.md)에 남긴 가게 자투리 셋을 마저 확인했습니다. 결과는 [dq5-data-format.md](../docs/dq5-data-format.md) 의 「교회·코인 판매·맡기는 곳·카지노」「슬라임 레이스」,
[dq5-map-format.md](../docs/dq5-map-format.md) 의 「내용물 값」에 있습니다. 실험은 선실 세이브스테이트에서 파파스의 대화 번호를 바꾸는 방법 그대로입니다.

## 1. 찾기 메뉴가 숫자 창까지 가지 않던 이유

앞에서는 맡기는 곳의 찾기에서 늘 E3「おやめに　なるのですね」로 끝났습니다. 100프레임마다 화면을 찍어 보니 CB「何を　おかえししましょう？」가 ▼ 를 띄운 채 A 를 기다리고 있었고,
그동안 누른 아래·A 는 메시지를 넘기는 데 쓰였습니다. 목록(どうぐ·ぼうぐ·ぶき·おかね)은 그 뒤에 떴고, 위를 누르면 おかね 로 돌아 올라갑니다.

```
아래, A(찾기) → CB → A → 목록 → 위, A(おかね) → CD「今　5000ゴールド」 → 숫자 창 → 위, A → CE → A
```

맡긴 금화를 5 로 두고 1 을 찾았습니다.

```
가진 돈 98999  → CE → D1 はい　どうぞ
가진 돈 99500  → CE → CF そんなに　たくさん　お持ちになれない
```

찾은 뒤 가진 돈이 100000 이 되는 쪽만 거절되었습니다.

## 2. 倍率 나눗셈 코드

앞 일지에서는 측정값에 맞춰 식을 세웠습니다. 이번에 `11:DF49` 뒤쪽을 X 16비트로 다시 풀었습니다.

- `11:E073` 은 시프트와 덧셈으로 하는 32비트 곱셈입니다. `11:DFCE` 가 a'b' × ((256-a')+(256-b')) 를 나누는 수로 만듭니다.
- `11:DFD4`~`DFE9` 가 (256-a')(256-b') 를 8비트 올려(× 256) 나눠지는 수로 둡니다.
- `11:DFF4` 부터 나누는 수를 더해 가며 나눠지는 수를 넘지 않는 횟수 q 를 셉니다. q 가 2 미만이면 2 로 두고, 아니면 1 을 더합니다(`11:E009`~`E02A`).

곧 倍率은 q + 1 입니다. 「올림」은 나누어떨어지지 않을 때만 같고, 나누어떨어지면 하나 큽니다. 도구의 식을 이대로 고치고 줄을 덮은 레이스를 하나 더 만들었습니다.
줄을 엉뚱한 값으로 덮은 다섯째 레이스는 값이 `4 1 7 243 1` 이고 倍率이 `123 162 80 123 128 147 90 128 128 147` 이었습니다. 넘침이 여러 번 일어났는데도 다섯 레이스의 50개가 모두 맞았습니다.

## 3. `D005` 빨간 빛 뒤의 `BRK 09 78`

`BRK` 처리 표(`00:921B`)에서 `08`·`09` 는 `00:93A5` 입니다. `08` 은 `00:969A`(한 프레임 기다림)를 한 번, `09 n` 은 n 번 부릅니다. `BRK 09 78` 은 120프레임 기다림입니다.
앞 일지의 기록에서 빨간 빛 갈래는 15F 부터 처리 끝(`12:F5BE`)까지 155프레임, 파란 빛 갈래는 152 부터 29프레임이었습니다. 차이 126프레임이 기다림과 맞습니다. 그 앞의 `BRK 19 44` 는 소리 명령입니다.

## 틀렸던 것들

- 슬라임 倍率은 256/S 를 올린 값이다: 나눈 몫에 1 을 더한 값이었다. 나누어떨어질 때만 다르다.
- 찾기 메뉴는 숫자 창 입력이 안 먹는다: 메시지가 A 를 기다리는 동안 누른 입력이 그쪽으로 갔다.
