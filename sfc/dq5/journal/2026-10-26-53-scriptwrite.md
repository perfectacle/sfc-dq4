# 2026-10-26-53: 이벤트·인물 스크립트 쓰기 도구

이벤트·인물 명령을 JSON으로 편집해 롬에 넣는 `dq5eventwrite.py`·`dq5npcwrite.py`를 만들었습니다. 원본을 다시 만들었을 때 바이트가 같고, 새 명령을 넣은 롬에서도 표 조회·보행·인물 분기를 확인했습니다. 입력과 제약은 [쓰기 형식](../docs/dq5-build-format.md#이벤트-스크립트-dq5event1)에 있습니다.

## 1. 같은 명령 목록, 다른 배치 방식

이벤트는 `23:E2C2`의 이벤트 표와 `23:E325`의 번호 표에 24비트 주소가 있습니다. 새 명령을 확장 뱅크에 놓고 지정한 항목만 바꾸었습니다. 번호 `20`~`25`처럼 스크립트 중간을 가리키는 항목도 있어, 원래 주소를 공유한다고 다른 항목까지 따라 바꾸지는 않습니다. 코드에 직접 적힌 주소도 그대로 둡니다.

인물은 목록 엔트리 안에 길이 바이트와 명령이 들어 있습니다. 기본 목록은 뱅크 `05`, 대체 목록은 뱅크 `10`에 묶여 있어 스크립트만 확장 뱅크로 옮길 수 없습니다. 이번에는 원래 길이를 유지하고 짧아진 부분을 `00`(그 자리)으로 채웠습니다. 원래 슬롯보다 긴 명령은 거부합니다.

둘 다 명령의 `op`와 바이트 인자 `args`를 쓰지만 라벨 기준은 다릅니다. 이벤트 `C3`는 배치된 CPU 주소로, 인물 `03`은 명령 주소+1에서의 변위로, `06`·`07`은 명령 주소에서의 변위로 바꿉니다. 인물 변위는 −128~127이어야 하고 명령 첫 바이트를 가리켜야 합니다.

## 2. 원본 왕복과 잘못된 입력

```text
이벤트 시작점 106개, 2,420바이트: 일치
이벤트 연속 영역 86개, 1,664바이트: 일치
인물 고유 슬롯 1,034개, 21,559바이트: 일치
인물 시간대 참조 1,274개
합성 검사 13개: 통과
```

이벤트 두 집합은 일부 겹치므로 합쳐 고유 스크립트 수로 세지 않습니다. 인물은 공유 슬롯을 한 번만 인코딩하고 참조하는 인물·시간대를 따로 보여 줍니다.

합성 검사는 분기 기준과 변위 양 끝, 라벨, 명령 길이, 값 범위, 슬롯 초과, 뱅크 경계, 지정한 표 항목만 바뀌는지를 봅니다. JSON이 객체가 아닌 경우와 `+1` 같은 잘못된 명령 문자열도 거부합니다. 원본에는 마지막 명령이 네이티브 호출인 스크립트가 있으므로, 원본 그대로인 패치에 새 종료 규칙을 강제하지 않았습니다. 바뀐 슬롯에는 도달 가능한 흐름이 끝을 넘어가는지 검사합니다.

## 3. 확장 뱅크를 게임에서 읽기

번호 표 `07`과 이벤트 표 `8`을 각각 `60:8000`으로 바꿨습니다. 넣은 명령은 플래그 `7E:220F`에 `40`을 OR하고 오른쪽 두 칸 걷고 끝내는 6바이트입니다. 파파스의 인물 명령 `37`로 시험용 네이티브 루틴을 불러 실제 표 조회 루틴 `23:E2F4` 또는 `23:E29A`를 거쳤습니다. 시작 주소를 WRAM에 직접 넣는 대신 표가 바뀐 것까지 확인한 것입니다.

```text
번호 표: f354 23:E2F4 → f362 60:8000(10) → 60:8003(01)
이벤트 표: f354 23:E29A → f362 00:1A0D(C3) → 60:8000(10) → 60:8003(01)
둘 다: f378 60:8005(FF), 주인공 (9,11) → (11,11), 7E:220F = 40
```

## 4. 인물 라벨 분기

선실을 다시 읽게 하고 파파스의 23바이트 슬롯을 고쳤습니다. 길이 바이트는 `05:A84F`, 첫 명령은 `05:A850`입니다. 슬롯 `08`의 좌표와 스크립트 포인터를 기록했습니다.

| 명령과 조건 | 예상·실제 좌표 |
| --- | --- |
| `03` 라벨로 건너뛰기 | (8,13) |
| `06`, `7E:219F` bit0 꺼짐 | (5,13) |
| `06`, 같은 비트 켜짐 | (8,13) |
| `07`, 주인공이 사각형 안 | (8,13) |
| `07`, 주인공이 사각형 밖 | (5,13) |

각 갈래는 `2B`로 순간이동한 뒤 `16`으로 멈춥니다. 이벤트 두 경우와 합쳐 7건 모두 예상대로 끝났고, 빌더가 만든 IPS를 원본에 적용한 결과도 만든 롬과 같았습니다.

## 5. 다시 확인하기

원본 롬과 선실 세이브스테이트를 준비하고 `$MESENCE`를 MesenCE 실행 파일로 지정합니다. 실험 도구는 입력 JSON·패치 목록·롬·IPS와 실행 기록을 출력 폴더에 만듭니다. 결과물은 커밋하지 않습니다.

```sh
uv run --locked python sfc/dq5/tools/dq5eventwrite.py rom/dq5.sfc check
uv run --locked python sfc/dq5/tools/dq5npcwrite.py rom/dq5.sfc check
uv run --locked python -m unittest discover -s sfc/dq5/tools/tests -p 'test_dq5*write.py'
uv run --locked python sfc/dq5/tools/dq5scriptcheck.py rom/dq5.sfc --state work/state/ship.mss --out work/scriptcheck
```

## 틀렸던 것들

실험 프로브에서 `dofile`에 저장소 상대 경로를 주었더니 MesenCE의 작업 폴더가 달라 드라이버를 찾지 못했습니다. Python에서 드라이버의 절대 경로를 계산해 환경 변수로 넘겼습니다. 도구와 문서에는 개인 환경 경로를 넣지 않습니다.

## 남은 것

인물 목록의 가변 길이 재배치, 필드 블록·입구 표, 대사 대량 삽입은 아직입니다. 이벤트 쓰기는 지정한 표 항목만 교체하며 직접 참조·계산된 참조를 한꺼번에 옮기지 않습니다. 게임 검증은 위 시험 명령 7건이며, 전체 이야기 장면의 회귀 검사는 하지 않았습니다.
