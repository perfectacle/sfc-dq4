# DQ5(SFC) 필드(세계 지도) 형식

필드 지도가 ROM 에 어떻게 들어 있는지 정리한 문서입니다. 찾아낸 과정은
[2026-10-24-09 일지](../journal/2026-10-24-09-field.md) 와 [2026-10-25-15 일지](../journal/2026-10-25-15-field.md), [2026-10-25-26 일지](../journal/2026-10-25-26-field2.md), [2026-10-25-104 일지](../journal/2026-10-25-104-daynight.md), [2026-10-25-135 일지](../journal/2026-10-25-135-daynight2.md), [2026-10-25-147 일지](../journal/2026-10-25-147-tactics2.md), [2026-10-25-157 일지](../journal/2026-10-25-157-tactics3.md), [2026-10-25-167 일지](../journal/2026-10-25-167-tactics4.md) 에 있습니다. 구현은 [sfc/dq5/tools/dq5field.py](../tools/dq5field.py).

## 불러오기 (`01:A5C2`)

필드에 나가면 RLE 두 덩어리를 DMA 로 WRAM 포트에 풉니다(`01:A64F`).

| 원본 | 풀린 곳 | 크기 | 내용 |
| --- | --- | --- | --- |
| `17:9A59` | `7F:0000` | 64KB | 세계 지도. 256x256 블록, 한 바이트가 블록 번호 하위 8비트 |
| `2A:8D3E` | `7E:E000` | 8KB | 블록 번호 9번째 비트(칸마다 1비트, `0x80 >> (i & 7)`) |

### 세계 셋 (`01:9F40`)

세계 지도는 셋이고, `01:9F40` 이 `$1949` 로 불러올 덩어리를 고릅니다. 블록 정의·타일 그래픽은 셋이 같고, 지도와 팔레트 2·3번 줄만 다릅니다.

| `$1949` | 지도(`7F:0000`) | 9번째 비트(`7E:E000`) | 불러오기 | `$194B` | 팔레트 2·3번 줄 |
| --- | --- | --- | --- | --- | --- |
| 0 | `17:9A59` | `2A:8D3E` | `01:A5C2` | `02` | 시간대마다(아래) |
| 1 | `2A:B722` | `2A:C310` | `01:A5F1` | `05` | `01:A199` |
| 2 | `2A:C51A` | `2A:D299` | `01:A620` | `0E` | `01:A3B5` |

세계 1 은 눈 덮인 땅, 세계 2 는 보라색 바다의 땅이고 둘 다 지도 왼쪽 위 구석만 씁니다. `$1949` 를 `POKE` 로 고정하고 필드에 서서 WRAM·VRAM 을 덤프하니,
세 세계 모두 지도·9번째 비트가 풀린 덩어리와 바이트까지 같았고, 롬의 블록 표로 그린 화면이 게임 화면과 같았습니다(3,584 표본 중 3,572·3,477·3,572 픽셀, 나머지는 인물·창).

`$1949` 는 실내 맵에서 필드로 나갈 때 `2A:F425` 안의 `2A:F475` → `2A:FEE4` 가 나온 그룹의 세계(아래 `0F:EA97` +0 bit5-6 에서 1을 뺀 값)로 다시 씁니다. 한 번만 바꾼 값은 필드로 나가며 사라졌습니다.
세계 2 인 1C/00 에서 걸어 나가자 `$1949` = 2 인 필드 (96,99) 에 섰습니다.

세계를 건너는 길은 출구 목적지 표와 영역 이동 표를 모두 훑어 하나만 나왔습니다. 11/00 의 영역 이동 `(86,13)` → 22/00 (35,102) 입니다(22 는 세계 1).
실제로 11/00 에서 그 자리를 밟아 22/00 에 들어가고, 22/00 에서 걸어 나가자 `$1949` = 1 인 필드 (107,100) 에 섰습니다.
돌아오는 길은 아래 「필드로 나가는 길 바꾸기」의 22 항목입니다. `7E:2190` bit5 를 켠 뒤 22/00 에서 걸어 나가자 `2A:F601` 이 `$BC` 를 `11` 로 바꿔 11/00 에 섰습니다.
세계 2 를 오가는 길은 표에서 찾아지는 값으로 `$BC` 를 쓰는 코드를 롬에서 훑어 찾았습니다. 아래 「순간이동 칸」입니다.

### 순간이동 칸 (`00:C99E`, `03:9B9C`)

맵을 옮긴 뒤 `00:C99E` 가 선 칸의 출구 속성 `$00` 을 보고, `$33`(블록 오른쪽 아래 칸은 bit7 이 붙은 `$B3`)이면 `02:BB37` → `03:9B0F` 로 화면을 일렁이게 한 뒤 `03:9B9C` 가 `03:9BEB` 표로 다른 맵에 보냅니다.

```
03:9BEB  열쇠 $BC: 01 2A 52 30
03:9BEF  4바이트씩 [$BC][$BD][X][Y]: 2A/00 (18,11), 01/0A (8,10), 30/00 (13,12), 52/50 (26,25)
         가는 곳이 그룹 30 이면 시간대 $075E 를 0 으로
```

30/00 (13,12) 의 순간이동 칸에 올라서자 650프레임쯤 뒤 52/50 (26,25) 에, 2A/00 (18,11) 의 칸에서는 01/0A (8,10) 에 섰습니다. 52/50 은 0F/00 으로 나가는 영역 이동이 있어(그룹 `$50` 이상 실측), 세계 2 에서 세계 0 으로 돌아오는 길입니다.
01/0A 에는 맵을 푼 뒤 (8~9,9~10) 에 칸이 있어, 층 1 로 서서 밟자 2A/00 (18,11) 로 갔습니다. 52/50 에는 칸이 없고, 세계 2 로 들어가는 길은 칸이 아니라 석상 이벤트입니다.

어른 시절(`7E:2190` bit6)의 52/50 대체 인물 목록(`10:82C5`)에는 석상 셋 (26,17)·(30,23)·(22,23) 과 숨은 인물 하나가 있습니다.
석상 앞 칸 (22,26)·(26,20)·(30,26) 에서 물건 `9E`~`A0`(ほのおのリング·みずのリング·いのちのリング)을 쓰면 물건 처리기 `11:8E7D` 가 `23:DD3F` 를 불러 그 물건 번호(`$0F22`)를 `7E:21D8`·`21D9`·`21DA` 에 넣습니다. (26,20) 에서 ほのおのリング 를 쓰자 `21D9` = `9E` 가 되었습니다.
석상 앞에 서면 석상의 인라인 스크립트(`06:DAC3`·`DB28`·`DB40`)가, 그 바이트가 0 이면 「女神像の指が 白く光っている。」를 띄웁니다.
반지가 놓여 있으면 `06:DADB` 가 메시지 4D2(「女神像の指に ほのおのリングが はめられている。ほのおのリングを はずしますか?」)와 はい/いいえ 창을 띄우고, はい 면 반지를 가진 물건 칸에 돌려주고 메시지 132(「…を 手に入れた。」)를 띄웁니다.
그 뒤 `24:A981`(X = 석상의 인물 슬롯 `0B`·`09`·`0A`)이 `24:AC8C` 로 그 인물의 방향 `7E:31E0+X` 를 `88`(위)로 바꾸고 그 바이트를 0 으로 합니다. 석상은 방향마다 다른 그림이라, 반지가 있는 그림이 반지 없는 그림으로 바뀝니다(1260프레임 `7E:31E9` ← `88`). 반지를 놓을 때는 `23:DD3F` 뒤 `24:A98F` → `24:AC9F` 가 방향을 `44`(아래)로 바꿔 반지 있는 그림이 됩니다(ほのおのリング 를 쓴 뒤 1457프레임 `7E:31E9` ← `44`). 맵을 불러올 때는 `1E:DB91` 이 `88` 로 둡니다. `21D9` = `9E` 로 (26,20) 에 서서 はい 를 고르자 `7E:2058` 에 `9E` 가 들어가고, 1260프레임에 `24:A981` 과 `21D9` = 0 이 차례로 일어났으며 석상 손가락의 붉은 점이 사라졌습니다. 숨은 인물의 인라인 스크립트는 주인공이 (24~29,13~15) 에 들어서면 `06:DB60` 을 부릅니다.
`06:DB60` 은 세 바이트가 모두 0 이 아니면 시간대 `$075E` 를 `50` 으로 두고 이벤트 8(`23:E29A`)을 겁니다. `SET="2190|40;21D8=01;21D9=01;21DA=01"` 로 52/50 (24,17) 에 들어가 위로 걷자 이벤트가 돌고 30/00 (13,12) 에 섰습니다. 세 바이트 없이는 같은 자리에서 아무 일도 없었습니다.
30/00 에서 아래로 걸어 나가면 `$1949` = 2 인 필드 (38,114) 에 섭니다. 52/50 셀 `+4` 에 `33`·`B3` 을 써 넣어도 30/00 으로 갔지만, 게임은 이 칸을 쓰지 않습니다.

### 필드로 나가는 길 바꾸기 (`2A:F52A`)

영역 이동의 `$BC` bit7(필드로)을 밟으면 `2A:F52A` 가 맵에 따라 필드 대신 다른 맵으로 보냅니다. 그룹 `$50` 이상 맵으로 가는 길은 모두 여기서 나옵니다.

| 나가는 맵 | 조건 | 가는 곳 |
| --- | --- | --- |
| 12/02·03·04 | | 53/51 (10,15)·(40,15)·(14,23) |
| 12/06 | | 53/52 (58,15), 층 2 |
| 0F/* | `$C2` = 20 | 52/50 (X 를 보정) |
| 15/0A | `$C1` < 30 / 아니면 | 54/50 (31,24) / (53,23) |
| 15/0D·15/06 | | 54/50 (42,47)·(114,47) |
| 15/01 | | 54/51 (25,63) |
| 22/* | `7E:2190` bit5 켜짐 | 11/00 (86,13) |
| 11/* | | `05:E87C` 를 부름 |
| 05/* | | 50/50 (`$C1`-2, 18) |

15/0A 의 왼쪽 출구 (21,52) 와 오른쪽 출구 (77,52) 를 밟자 54/50 의 (31,25)·(53,24) 에, 22/00 은 위 조건대로 11/00 에 섰습니다. 나머지는 그룹 `$50` 이상 맵의 영역 이동을 거꾸로 밟은 결과와 짝이 맞습니다([dq5-map-format.md](dq5-map-format.md#영역-이동-00cdec)).

![$1949 로 고르는 세계 지도 셋과 각 세계의 입구(노란 틀). 세계 1·2 는 왼쪽 위 128x128 블록만 2배로](../images/dq5-field-worlds.webp)

```
RLE 제어 바이트 c
  bit7 = 0: 다음 c+1 바이트를 그대로
  bit7 = 1: n = c & 7F. 0 이면 끝, 아니면 다음 한 바이트를 n+1 번
```

두 덩어리 모두 필드에 선 순간의 WRAM 과 같습니다.

## 블록 (`00:BBF7`, `00:BC4E`)

블록은 16x16 픽셀(8x8 타일 2x2)이고 아래층·위층이 있습니다. 블록 번호는 9비트로 읽지만, 원본 정의 표는 층마다 511개(`m` = 0~510)이며 항목은 5바이트입니다. 아래층은 `2A:A32C`~`AD26`, 위층은 `2A:AD27`~`B721`입니다. 아래층의 511번 자리는 위층 0번과 겹치고, 위층의 511번 자리는 세계 1 압축 지도(`2A:B722`)입니다. 세 세계의 65,536칸씩을 검사했을 때 최대 블록 번호는 510·497·508이며 511은 쓰이지 않았습니다. 타일 번호 자체의 범위는 0~511입니다. `00:BBF7` 경로에서는 번호를 `7F:0000` 의 칸 바이트(하위 8비트)와 `7E:E000` 의 비트 하나(9번째 비트)로 모아 `00:BC4E` 에 넘기므로 512개를 넘을 수 없습니다(코드 읽기). `00:BC4E` 를 부르는 다른 길 `00:D009` 의 `JSL $00BC48` 은 `00:D2B1` 이 `$04` 에 둔 값을 넘기며, 그 범위는 확인하지 않았습니다. 두 표를 읽는 명령은 `00:BC72`·`BC78`·`BC80`·`BC8D` 넷뿐입니다.

```
아래층 2A:A32C + m*5, 위층 2A:AD27 + m*5
  +0..+3  네 칸(왼위, 오위, 왼아래, 오아래) 타일 번호 하위 8비트
  +4      타일 번호 9번째 비트. 칸 q 는 0x80 >> q (00:BC9C)
```

타일 팔레트는 `2A:D712 + 타일/2` 의 니블입니다(짝수 타일은 위 니블). 위층은 4비트, 아래층은 3비트를 쓰고 `(값 + 8) << 8` 을 타일맵 워드에 더합니다(`00:BBAC`).
타일 512개가 쓰는 팔레트 줄은 2번(323개)·3번(185개)·4번(4개)뿐입니다.

## 타일 그래픽과 팔레트

- 타일: `12:B1A8` 의 RLE 를 `7E:C000-FFFF` 에 풀면 비트플레인 0·1·2·3 이 4KB 씩(`C000`/`D000`/`E000`/`F000`) 들어 있고,
  `01:A4CE` 가 타일마다 섞어 VRAM 워드 `2000-`(바이트 `0x4000-`)에 512개를 올립니다. 재조립한 16KB 가 필드의 VRAM 과 바이트까지 같습니다.
  그 뒤 `7E:E000-` 는 블록 9번째 비트로 덮어씁니다.
- 움직이는 타일: 세 세계 모두 몇 프레임마다 DMA 로 타일 `454`~`459`(VRAM 워드 `3C60`, 192바이트)를 `7E:C800`~`CDFF` 의 8벌 중 하나로, 타일 `4`·`5`·`20`·`21`(워드 `2040`·`2140`, 64바이트씩)을 `7E:C400-` 의 벌로 바꿉니다. 덤프 시점에 따라 이 타일들만 롬 타일과 다릅니다.
  8벌은 필드에 들어갈 때 `2B:8000` 이 `1E:D0FF` 의 RLE(위와 같은 꼴, DMA 로 WRAM 포트에)를 `7E:C800` 에 푼 것입니다(1,536바이트 = 6타일 × 8벌, `1E:D703` 에서 끝). 푼 결과가 (341,56) 덤프의 `7E:C800-CDFF` 와 같았습니다.
  `7E:C400-` 는 롬 타일 `4`·`5` 와 `20`·`21` 을 두 개씩 이어 줄마다(평면마다) 16비트로 보고 한 픽셀씩 돌린 것입니다(`01:C790`, 세계 0 은 오른쪽 `01:C7B7`, 세계 1·2 는 왼쪽 `01:C7C5`). 같은 덤프의 `C400-C47F` 가 두 쌍 모두 오른쪽으로 9픽셀 돌린 값과 같았습니다.
  바꾸는 간격은 `02:AC98` 이 정합니다. `$7F` 는 본 루프(`00:809C`)가 매 프레임 `$19C3` 만큼 더하는 값이고(`$19C3` 은 걸음 빠르기, 보통 1, 탈것이면 `00:BE25` 가 `$1957` 로 둠), `$7F & 02:AD44[$19C3]`(`07`·`0F`·`0F`·`1F`)가 0 인 프레임에 다음 벌로 넘어갑니다. 필드 (341,56) 에서 매 프레임 VRAM 을 덤프하자 `3C60` 의 6타일과 `2040` 의 타일이 같은 프레임에 8프레임마다(가끔 처리가 밀린 11프레임) 바뀌었고, `3C60` 은 8벌을 0→7 차례로 돌았습니다. 들어선 뒤 `$19C3` 과 `$7F` 를 고쳐 재니 `$19C3` = 2·3·4 에서 8·16·8프레임마다였습니다.
  벌은 `02:ACD5` 가 `$1C31` 로 `02:AD89` 의 WRAM 주소 표(8개, `C800`~`CD40`)를 골라 `$1C13` 에 두고, `02:ACE7` 의 `AND #$07` 로 0~7 을 돕니다. 필드에 들어갈 때 `2B:8033` 이 `$1C31` 을 0 으로 둡니다.
  필드 (341,56) 에서 걷고 메뉴를 여닫는 동안 `7E:C000`~`DFFF` 의 CPU 읽기·쓰기를 모두 모으니, 타일을 VRAM 에 올린 뒤(`01:A4D3`~`A53C`) `7E:CE00`~`DFFF` 를 읽거나 쓴 코드는 없었습니다. `C000`~`C7FF` 는 돌린 타일(`01:C78E`~`C7B5`), `C800`~`CDFF` 는 벌(`2B:8063`)이 썼고, `C000`~`CDFF` 를 DMA(`00:8F75`)가 읽었습니다. 16벌(`--anim-at`)을 넣은 롬으로 두 장면을 더 보았습니다. 이벤트 전투(スライム 하나)를 이기고 필드로 돌아온 뒤, 그리고 세워 둔 배에 올라 바다를 돌고 내린 뒤입니다. 두 장면 모두 전투 중과 그 뒤에 `7E:CE00`~`D3FF` 를 건드린 것은 `00:8F75` 의 DMA 읽기뿐이었고, 필드 타일·벌을 다시 풀지도 않았습니다. 돌아온 뒤 서 있는 동안(전투 뒤 166프레임, 배 뒤 281프레임) 16벌이 모두 차례로 돌았습니다. 확인한 장면은 이 셋(걷기·메뉴, 전투 뒤, 배를 타고 내린 뒤)뿐이고, 세계를 오가는 이벤트·ルーラ·다른 탈것은 보지 않았습니다. 그래서 벌을 `D3FF` 까지 16벌로 늘려 쓸 수 있습니다([필드 그림 쓰기](dq5-build-format.md#필드-그림-dq5fieldgfx1)).
- 팔레트: [아래 절](#팔레트-01a04b).

`1F:D28E`·`1F:D2DE` 도 같은 꼴의 RLE 지만 VRAM 데이터 포트(`$2118`/`$2119`)로 바로 풀며, 필드에서는 VRAM 워드 `6000-` 근처(스프라이트로 보임)를 채웁니다.
`1F:D2DE` 쪽은 제어 바이트 `$7F` 를 「다음 뱅크 `$8000` 으로 넘어감」으로 씁니다.

## 마을 입장 (`2A:F247`)

고정 표 쓰기는 `dq5fieldtables.py`로 합니다([쓰기 형식](dq5-build-format.md#필드-블록입구-표-dq5fieldtables1)). 일반 입구는 47개, 보조 입구는 14개이며 끝의 `FF`는 유지합니다. 일반 그룹 도착 표는 `0F:EA97`~`EBA4`의 54항목(그룹 `00`~`35`)입니다. 그 뒤 `0F:EBA5`는 실행 코드이므로 항목을 늘려 쓰지 않습니다. 입구 표 둘은 읽는 곳 21곳(긴 주소 20곳, 세계 지도 `03:C880` 의 포인터)을 함께 바꿔 다른 자리로 옮기고 늘릴 수 있습니다([입구 표 옮기기·늘리기](dq5-build-format.md#입구-표-옮기기늘리기)).

필드 좌표(`$B6`, `$B8`)가 `04:FD97` 표의 `[그룹][X 16비트][Y 16비트]` 와 정확히 같으면 그 그룹(`$BC`)으로 들어갑니다(47항목, 두 칸짜리 입구는 항목 둘).
들어가기 전에 `2A:FEF5` 가 그 그룹의 세계(`0F:EA97 + 그룹*5` 의 bit5-6 에서 1을 뺀 값, 그룹 `05`·`$50` 이상은 0)가 `$1949` 와 같은지 봅니다. 세계가 다르면 입구를 밟아도 들어가지 않습니다(그룹 `$54` 는 늘 못 들어감).
그 뒤 `2A:F384` 가 `0F:EA97` 항목으로 `$BD`·도착 X·Y·층(`$C3`)·`$198E` 를 정하고, `2A:FD7E` 가 `$194A` 를, `2A:F28D` 가 맵마다 예외를 덮어씁니다.

```
0F:EA97 + 그룹*5
  +0  bit0-4 $BD, bit5-6 세계+1, bit7 → $194A bit7
  +1  도착 X, +2 도착 Y, +3 도착 층($C3 → 7E:31A0)
  +4  bit0·1·7 → $198E, bit2-6 → $194A bit0-4
$198E bit0-1  도착 때 바라보는 방향. 0 위, 1 오른쪽, 2 아래, 3 왼쪽(00:E209 가 00:E873 의 08·01·04·02 로 7E:31E0 등을 채움)
```

입구 47개 중 46개를 실제로 밟았습니다(나머지 하나인 그룹 01 은 장면 이동 도구가 그 항목을 쓰므로 [2026-10-25-08 일지](../journal/2026-10-25-08-warp.md) 의 실험으로 대신함).
입구 바로 아래(막히면 위·오른쪽·왼쪽)에 서서 입구 쪽으로 한 칸 걸었고, 세계 1·2 의 입구는 `$1949` 를 `POKE` 로 고정했습니다. 46개 모두 들어갔고, 42개는 `0F:EA97` 의 `$BD`·도착 좌표 그대로였습니다.
나머지 넷은 이렇습니다.

`$1949` 를 0 으로 둔 채 세계 1·2 의 입구 6개를 밟으면 네 방향 모두 들어가지 않았습니다.

1F/00 은 표의 X 를 `0F:EB33` 에서 바꿔 보면 (99,29)·(101,29)·(100,27)·(100,31) 등에는 그대로 서고 (100,29) 에서만 (95,29) 로 걸어갔습니다.
`+3` 을 방향으로 보았으나 층입니다. 그룹 `02`(값 `01`)로 들어가면 `7E:31A0` = `01`, `1B`(값 `02`)는 `02` 이고, `02` 의 값을 `02` 로 바꾸자 02/00 에서 주인공이 움직이지 못했습니다.
`$198E` 는 그룹 `1A` 항목의 `+4` 를 `04`~`07` 로 바꿔 들어가 서 있는 모습으로 확인했습니다. bit7 은 `00:E360` 이 동료를 세우는 갈래를 고릅니다. 장면 이동 도구 `PARTY=02,05`(スラリン·ホイミン)로 같은 입구에 들어가자, bit7 이 꺼져 있으면 동료가 주인공 뒤(바라보는 반대쪽)에 줄지어 섰고, 켜져 있으면(`84`·`86`) 동료가 주인공과 같은 자리에 겹쳐 서서 보이지 않았습니다(`00:E59F`).
`$194A` 하위 비트는 실내 맵에서 무작위 조우를 셀지 정합니다. `00:8309` 가 `& 7F` 이 3 이면 바로, 아니면 `00:8340` 이 실내이고 4 일 때(또는 21/01~04)만 조우 걸음 루틴(`21:82E2`·`21:83CF`)으로 갑니다.

`$194A` 를 읽는 곳은 던전·필드·전투에서 읽기 감시로 모두 모았습니다: `00:830C`·`00:834A`(위 조우), `02:C792`, `2A:FDA3`(쓰는 루틴 안). 하위 비트를 3·4 와 비교하는 곳과 `21:8763` 의 `& 1F` < 3 뿐이라, `01`·`02` 는 `00` 과 같게, `07` 은 조우는 꺼지고 `21:8763` 에서는 3 이상으로 다뤄집니다.
bit7 은 마차를 데려갈 수 있는 맵입니다. `02:C792` 가 실내에서 bit7 이 켜져 있으면 필드처럼 일행 필드 `91`(`BRK #88`, 마차)을 보고 `$1954` 를 정하고, `21:8763` 도 같은 필드를 봅니다.
장면 이동 도구 `PARTY=02 WAGON=1` 로 마차를 데리고 들어가자, bit7 이 켜진 0A/00·13/00 에서는 `02:C7AD` 가 `$1954` = 1 을 쓰고 0A/00 에서 마차가 주인공을 따라왔고, bit7 이 꺼진 02/00 에서는 `$1954` = 0 이고 동료 スラリン 만 따라왔습니다. 0D/00(`$194A` = `84`)도 필드 (385,401) 에서 위로 80 프레임 걸어 들어가자 `02:C7AD` 가 `$1954` = 1 을 쓰고 마차가 따라왔습니다(마차 없이는 0). 앞서 0D 입구가 마차로는 들어가지지 않는다고 본 것은 위로 20 프레임만 눌러 입구까지 닿지 않은 것이었습니다.

두 표를 나눈 까닭은 서는 자리와 들어가는 판정에 있습니다. `04:FD97` 47항목은 마을·성 그림 위의 입구로, 나올 때 그 칸에 그대로 섭니다. `04:FE83` 14항목은 `04:FD97` 에 없는 그룹(성 앞뜰 03, 배 06, 그룹 `$50` 이상의 세계 2 입구, ルーラ 로만 가는 1E 등)이고, 나올 때 한 칸 아래(Y+1)에 섭니다. 걸어 들어가는 판정도 `04:FE83` 쪽은 따로 된 `2A:FDCB` 가 맡아, マスタードラゴン 착륙(그룹 03)과 표가 끝난 뒤 내려 둔 天空城(`7E:21D4` bit2, 세계 0)의 자리 `7E:21DB`·`21DD` 둘레 3x3 에 들어서면 06/00 (37,61) 로 들이는 갈래를 함께 둡니다(코드 읽기).

`04:FE83` 은 다른 두 곳에서도 읽힙니다.
- 걸어서 들어가는 입구: `00:8409` 가 부르는 `2A:FDCB` 는 필드에서 걸어 다닐 때(`$1954` bit7 이 꺼짐) 주인공 자리가 표의 (X, Y) 와 같으면 그 그룹으로 들입니다(`2A:FE0A`. 항목마다 부르는 `2A:FEE2` 는 C 만 켜고 돌아오는 빈 검사이고, 세계 검사는 `2A:FEF5` 가 그룹의 세계(`0F:EA97` bit5-6)와 `$1949` 를 견줌). マスタードラゴン(`$1954` = `82`)이면 (249~253, 213~215) 를 (251,215) 로 맞춰 그룹 03 에 내립니다. 필드 (234,439) 에서 위로 걸어 (234,437) 을 밟자 2E/00 (18,31) 에 들어갔습니다.
- ルーラ 행선지: `25:85D5` 의 행선지 그룹 22개(1E 는 열아홉째) 중 고른 그룹을 `1E:E545` 가 `04:FD97` 에서, 없으면 `04:FE83` 에서 찾아 `$0B50`·`$0B52` 에 (X, Y+1) 을 둡니다. 행선지 첫 칸을 `1E` 로 덮고 ルーラ 를 외우자 (396,400) 에 내렸습니다. 1E 항목 (396,399) 은 걸어서는 산에 막혀 닿지 않는 자리라, 1E 의 항목을 쓰는 것은 ルーラ 뿐입니다.

リレミト 는 이 표를 쓰지 않습니다. `11:80FC` 가 들어갈 때 남긴 필드 자리 `$0B50`·`$0B52` 로 `$B6`·`$B8` 을 두고 그룹마다 Y+1 따위를 더합니다(16 은 `11:81D3`). 장면 이동 도구로 바로 들어간 16/00 에서 リレミト 를 외우면 그 자리가 비어 있어 (0,1) 에 섰습니다.
그룹 `06` 은 배입니다. `00:CD62` 가 `7E:21B6` bit0 이 꺼져 있으면 표 대신 배의 자리 `7E:21DB`·`21DD`(`$1954` 가 `81` 이 아니면 Y+1)로 덮습니다.
06/00 에서 걸어 나가면 선실 세이브스테이트의 값 그대로 (0,1) 바다에 섰고, `SET="21DB=55;21DC=01;21DD=40;21DE=01"` 이면 (341,321), `SET="21B6|01"` 이면 표대로 (441,232) 에 섰습니다.

그 세계로 바꾸어 같은 자리에 서면 동굴·마을 그림 위에 있습니다(위 세계 셋 그림의 노란 틀).

## 디버그 벽 통과 (`00:A97D`)

이동 판정 앞에서 `00:A97D`(필드)와 `00:A99C`(실내)가 롬 `01:8000` 을 봅니다. `00` 이고 B 버튼(`$24` bit6, `00:8C03` 이 1P 패드 상위 바이트에서 만듦)을 누르고 있으면 판정을 건너뜁니다.
팔리는 롬의 `01:8000` 은 `FF` 라 이 길은 닫혀 있습니다.

`ROMPATCH=8000=00` 을 주고 B 를 누른 채 걸어 확인했습니다(`dq5warp.lua`).

| 장면 | 입력 | `8000=FF` | `8000=00` |
| --- | --- | --- | --- |
| 04/00 (27,75) | 왼쪽 150프레임 | (24,75) 에서 막힘 | (12,75), 나무 그림 위 |
| 04/00 (27,75) | 위 150프레임 | (27,62) | (27,61) |
| 필드 (341,56) | 위 200프레임 | (340,52) 에서 막힘 | (341,32), 바다 위 |

B 를 누르지 않으면 `8000=00` 이어도 (340,52) 에서 막혔습니다.

## 개발용 스위치 `01:8001`

롬 `01:8001` 을 `LDA $018001` 로 읽는 곳은 11곳입니다(팔리는 롬은 `FF`). `00` 일 때 고르는 쪽은 대부분 개발용 확장 롬(뱅크 `30`~)이 있어야 맞는 값입니다. 모두 코드 읽기입니다.

| 곳 | `FF`(팔리는 롬) | `00` |
| --- | --- | --- |
| `04:B8A4` | 이름 표 `0B`(`23:D5F3`, ラインハット·オラクルベリー … 마을 이름) | 이름 표 7(`30:8000`, 롬 밖) |
| `25:8295`·`25:82AA`·`25:836A`·`1E:E553`·`23:E453` | 목록 `25:85D5`(22개. `23:E453` 은 앞 17개만 찾음) | 목록 `25:85EB`(54개, 앞 22개는 `25:85D5` 와 같고 뒤는 맵 그룹 `17`·`03`·`04` …) |
| `25:848C` | `7E:2033` = `16` | `7E:2033` = `36` |
| `21:9DEB`·`21:9E2C`(`BRK 88 4C`·`4D`) | 목적지 24개 중 플래그가 켜진 것만 셈 | 플래그를 보지 않고 `21:9E82` 비트 표를 씀 |
| `05:D5D7` | 창 `0B` | 창 `93` |
| `11:805D` | ルーラ 를 쓰기 전에 `BRK 89`(인자 `08`) 검사 | 검사하지 않음 |

`04:B88A` 는 `BRK 88 4D` 로 고른 번호를 이름으로 바꿔 창에 쓰는 곳이라, 이 묶음은 ルーラ·キメラのつばさ 의 목적지 목록으로 보입니다. 개발용 롬에서는 맵 그룹 54개 모두가 목적지였던 것으로 보입니다.
선실에서 キメラのつばさ(`A4`)를 일행 레코드 첫 칸(`7E:2056`)에 넣고 필드에서 써 보았습니다. `01:8001` 이 `FF`·`00` 어느 쪽이든 `23:E453`(A = `01`)과 `1E:E553`(A = `00`)이 돌았고, 목록 창 없이 날아올랐다가 제자리(도구가 그룹 `01` 입구로 덮어 둔 자리)에 내렸습니다. キメラのつばさ 는 목록을 쓰지 않습니다.

목록은 ルーラ 가 띄웁니다. 목적지 플래그는 `BRK 88 4C`·`4D` 가 필드 읽기(`21:8B00`)로 읽는 `7E:2030`~`7E:2032`(24비트, 비트 n = `25:85D5` 의 n 번째)입니다. 주인공 레코드 `+23`(`7E:2063`)을 `FF` 로 해 이동 주문을 모두 배우게 하고 MP(`7E:2044`·`7E:2050`)를 채운 뒤 じゅもん → ルーラ 를 골랐습니다.

| 조건 | `BRK 88 4C`(개수) | 이름 표 | 화면 |
| --- | --- | --- | --- |
| `01:8001` = `FF`, 선실 그대로(`7E:2030`~ = `FF FF 00`) | `10` | `0B` | 「どこへ？」 ラインハット·オラクルベリー·しゅうどういん·ポートセルミ·ルラフェン … |
| `FF`, `7E:2030` = `05` | | `0B` | ラインハット·しゅうどういん·グランバニア·きたのきょうかい·エルヘブン … |
| `00` | `36`(54) | 7(`30:8000`) | 목록 창이 뜨지 않음 |

`7E:2030` 하나만 바꿔 목록이 바뀌므로 플래그 자리는 실측입니다. `01:8001` = `00` 이면 개수 54 로 롬 밖 이름 표를 읽다가 창을 그리지 못합니다(`probe/trace.lua` 로 `21:9E0E`·`21:9E55` 갈래와 `$43` = 7 을 확인).
`11:805D` 는 ルーラ 처리(`11:8056`) 안에 있습니다.

### 롬 밖 뱅크 실행 감시

개발용 확장 롬(뱅크 `30`~)을 부르는 코드가 실제 장면에서 도는지, 장면마다 뱅크 `30` 이상의 실행을 모았습니다. 앞 일지들은 `cover.lua LO=300000 HI=FFFFFF`, 이번에는 `sfc/dq5/tools/lua/dq5seqtrace.lua` 로 `30:0000`~`7D:FFFF` 와 `B0:0000`~`FF:FFFF` 를 따로 감시했습니다(`80`~`AF` 는 롬 거울, `7E`·`7F` 는 WRAM 이라 뺌).

| 장면 | 만든 법 | 프레임 | 뱅크 `30` 이상 실행 |
| --- | --- | --- | --- |
| 세계 1·2 필드 걷기 | `FIELD=341,56 POKE=7E1949=01`·`02` | 2,400~2,700 | 0 |
| エスターク 전투, 이어서 무작위 전투 | `FIELD=341,56 GROUP=2C` | 2,400~2,700 | 0 |
| 04/00 성 앞, 명령 창 | `TO=04/00,27,75` | 2,400~2,700 | 0 |
| 슬라임 레이스·격투장 | 선실 파파스 대화 `0D`·`0E`, 코인 검사 `ROMPATCH=37210=80` | 2,950·1,190 | 0 |
| `$1954` = `03`·`82` 필드 걷기 | `POKE` | 2,590 | 0 |
| 카지노 슬롯(1 ドル, 코인을 넣고 돌림) | `TO=19/02,42,27 SET=203C=64` 뒤 しらべる | 3,690 | 0 |
| 어른 주인공·마차·동료 셋의 필드 걷기와 전투(마차에서 ボロンゴ 가 나와 명령을 받음) | `FIELD=341,56 PARTY=02,05,01 WAGON=1 ADULT=2` | 3,590 | 0 |

어느 장면에서도 롬 밖 뱅크를 실행하지 않았습니다. `01:8001` = `FF`(팔리는 롬)이면 위 표의 갈래가 모두 롬 안쪽을 고르기 때문으로 보입니다.

## 탈것 (`01:BC10`)

필드(`$BE` bit7 꺼짐)를 불러올 때 `01:BC10` 이 탈것을 다시 세웁니다. `$1954` 를 쓰는 명령은 15곳이고 값은 `00`·`03`·`04`·`80`·`81`·`82` 입니다.

```
7E:2190 bit7 켜짐      → 01:BFD1
$1954 = 80             → 01:BC7B
$1954 = 81             → 01:C2EF
$1954 = 82             → 01:BFD1   ($1954 = 82, $1957 = 2 를 쓰고 7E:33A0·7E:3380 비트를 켬)
```

- 걷는 속도는 `$19C3`(한 프레임에 나아가는 양)입니다. `$19F3` 에 프레임마다 더해 8 이 되면 한 칸을 마칩니다(`00:821C`). 맵을 세울 때 `$1957` 에 둔 값이 `00:BE25` 에서 `$19C3` 로 옮겨집니다. 걷기·마차(`01:BE73`)는 1, 마법 융단(`01:BD1F`)·マスタードラゴン(`01:C000`)은 2 입니다.
  필드 좌표 `$B6` 이 바뀌는 간격을 재자 걷기·마차(`PARTY=02 WAGON=1`)·`$1954` = `81` 은 8프레임, `80`·`82` 는 4프레임에 한 칸이었습니다. 배 선실(17/00)에서도 걷기는 8프레임이었고, `$1957` 을 2 로 두면 4프레임이었습니다. 배는 해안 앞 바다에 둔 배로 걸어 들어가 타고(`$1954` = `03`, 위 「실제 게임에서 배에 타는 길」), 그대로 위로 저었을 때 8프레임에 한 칸, `$19C3` = 1 이었습니다.
- まほうのじゅうたん(`CC`)을 풀밭에서 쓰자 융단에 탄 그림으로 물 위를 걸었고, 그 뒤 `$1954` 는 `80` 이었습니다. `11:81CE` 의 `03` 은 융단이 아닙니다.
- 필드에 도착한 뒤(`dq5warp.lua` 의 `LATESET`) `$1954` 를 바꾸고 바다 (328,27) 에서 걸었습니다. `80` 은 붉은 마법 융단, `81` 은 그림자를 드리운 성(天空城으로 보임), `82` 는 금빛 용(マスタードラゴン)으로 날았습니다. 배는 `03` 이고 주인공 그림이 배 그림(`98`, `7E:21BE` bit0)이어야 합니다. `7E:21BE` bit0 과 `03` 을 함께 주자 흰 돛단배가 바다를 지나갔고, `03` 만 주면 주인공 그림 그대로 물 위를 걸었습니다. `7E:21BE` bit0 에 `00`·`01`·`02`·`04` 를 주면 작은 배 그림으로 서서 움직이지 못했습니다.
- 실제 게임에서 배에 타는 길: 필드를 불러올 때 `00:E4AB` 가 `$1954` = `03`(배에 탄 채)이거나 `7E:21BF` bit4 면 주인공을 배로 그리고(`$1955` = 1, `7E:33A0` = `B8`), 아니면 `7E:21B5` bit7(`06:F702` 가 켬. 바로 앞 `06:F6DA` 가 ルドマン 의 배 플래그 `21B4` 를 읽음) 등일 때 `2B:8367` 이 세워 둔 배를 일행 칸 5(`7E:3025`·`3045` X, `3085`·`30A5` Y)에 `7E:21CD`~`21D0`(필드 X·Y, 배에서 내릴 때 `2B:8346` 이 씀) 자리로 놓습니다. 주인공이 그 칸으로 걸어 들어가면 `01:82C7` 이 칸 5 의 종류(`7E:3385 & 0F` = 4)를 `$1955` 에 두고, 이어 `00:C20D` 가 필드면 `7E:33A0` = `B8`(배 그림)로 바꾼 뒤 `00:C25F` 에서 `$1954` = `03` 을 씁니다(`$1955` 가 `08` 이면 `2B:841C` 갈래, 실내면 `02`). `FIELD=328,39 SET="21B5|80;21CD=48;21CE=01;21CF=25;21D0=00"` 로 해안 바로 위 바다 (328,37)에 배를 두고 위로 걷자 690프레임에 `01:82DD` 가 `$1955` = `04` 를, 698프레임에 `00:C25F` 가 `$1954` = `03` 을 썼고(쓰기 감시), 흰 돛단배로 바다를 지나 (323,34)까지 갔습니다. 배를 땅 (310,56)에 두면 주인공이 그 앞에서 막혔습니다. `01:82F5`·`01:832A` 는 배에서 내릴 때 돕니다. 배에 탄 채(`$1954` = `03`) 땅 쪽으로 가면 `01:830F` 가 `$1954` 를 잠깐 0 으로 두고 그 칸을 걸을 수 있는지 봅니다(`01:8387`). 걸을 수 있으면 `01:832A` 를 지나 내리고(배는 그 자리에 남음), 못 걷는 칸이면 `01:82F5` 가 `03` 을 되돌려 배에 남습니다. 위 장면에서 배에 오른 뒤 아래 해안으로 가자 746프레임에 `01:830F`→`01:832A` 가 돌아 (328,41) 에 내렸고, `SET=21BF|10`(배에 탄 채 시작)으로 산 쪽(위)을 누르자 `01:82F5` 가 돌아 배에 남았습니다.
- `7E:2190` bit7 을 켜고 필드로 나가도 금빛 용을 탄 그림이 됩니다(위 분기의 첫 줄).

### 주인공 그림 (`05:D98F`)

일행 레코드 `+0` 으로 걷는 그림 번호를 고르는 곳입니다. 주인공(`+0` = 0)은 플래그로 갈립니다.

```
7E:21BE bit0 켜짐   → 98   (배 그림)
7E:2190 bit6 꺼짐   → 2E   (어린 시절)
7E:21BE bit5 꺼짐   → 3A   (노예 시절 차림)
그 밖              → 2D   (망토 차림 어른)
```

- `7E:2190` bit6·5 와 `7E:21BE` bit5 를 켜자(`ADULT=2`) 필드·실내 모두 망토 차림 어른이 걸었습니다. `7E:21BE` bit5 를 빼면(`ADULT=1`) 노예 시절 차림입니다.
- `7E:21BE` bit0 만 켜면 필드의 주인공이 배 그림이 됩니다. 땅 위에서는 화면이 하얗게 되고, 바다에서는 `$1954` 를 함께 바꿔야 움직입니다.
- 실내에서 `7E:2190` bit7 로 보였던 망토 차림은 주인공이 아니라 뒤따르는 일행(`7E:1967` = 4, 그림 `9A`·`90`·`91`)이었습니다. 이야기 끝 무렵의 일행으로 보입니다.

### 마차 (`02:C788`)

일행 그림을 세울 때 `02:C788` 이 `BRK 88 91`(필드 `91`, `7E:201C`)을 묻고, 마차가 있으면 `$1954` 를 1 로 둡니다. `7E:201C` 를 `80` 으로 두자(`WAGON=1`) 말이 끄는 마차가 주인공 뒤에 나왔습니다(`01`·`02` 는 나오지 않음).

| 일행(`PARTY`) | `7E:201E` = 일행 수(고치기 전) | `7E:201E` = 3 |
| --- | --- | --- |
| `02`·`02,05`, 마차 없음 | 동료가 뒤따름 | (같음) |
| `02,05,01`, 마차 없음 | 따르는 셋 모두 빈 그림 | 주인공·スライム·ホイミスライム 만 걸음 |
| `02,05,01`, 마차 있음 | 마차와 빈 그림 둘 | 마차와 그 옆을 걷는 スライム·ホイミスライム |

빈 그림은 `05:D920` 이 걷는 일행마다 `$0B33` 의 2비트를 `^ 80` 해 `7E:1978` 에 두고, `02:C6F0` 이 bit7 인 일행을 그림 `35`(관으로 보임) 칸으로 보내서 생깁니다. `7E:201E`(마차 밖을 걷는 수)를 일행 수 그대로 4 로 두면 넷 모두가 그렇게 되었고, 3 으로 두자 제 그림이 나왔습니다. `PARTY` 는 이제 `7E:201E` 를 최대 3 으로 둡니다.

## 낮밤 (`00:82D3`)

시간대는 16비트 `$075E` 하나입니다. 걸음마다 도는 `00:8290`(조우 판정 `23:E7C2` 바로 뒤)이 `00:82D3` 에서 1 을 더하고 `01FF` 로 자릅니다.

```
$BE bit7 = 0 (필드)  그리고  $1949 = 0 (세계 0)  그리고  7E:2190 bit1 = 0   이면   $075E = ($075E + 1) & 01FF
밤 = $075E >= 00F0   (21:8000, carry)
```

한 바퀴는 512걸음이고 낮(`0000`~`00EF`)이 240걸음, 밤(`00F0`~`01FF`)이 272걸음입니다. 해 질 녘·새벽 색은 필드 색 벌([팔레트](#팔레트-01a04b))이 `00EE`~`00F1`, `01FD`~`0001` 의 몇 걸음 동안 바뀌는 것입니다. `$075E` 를 직접 읽는 곳은 `21:8000`·`01:A134`(색) 말고도 셋 있습니다(코드 읽기).

- `06:B74A`: 장면을 바꾸는 이벤트 앞에서 지금 상태를 `7E:0F47`~`0F53` 에 남깁니다. `$075E`·`$075F`, 필드 좌표 `$B6`~`$B9`, 칸 `$C1`~`$C3`, 맵 `$BC`·`$BD`, 방향 `7E:31E0`, `7E:2190` 입니다. 그 뒤 `$075E` 를 0(낮)으로 두고 `02:D356` 과 이벤트 `40`(`23:E2F4`)을 부릅니다. `06:B7AE` 가 남긴 값을 되돌립니다.
- `02:D399`: `02:D356` 안에서 `7E:21EA` bit7(엔딩)이 꺼져 있으면 `$075E` 를 잠시 0 으로 두고 `02:D76A`·`02:D7C6` 을 부른 뒤 원래 값으로 되돌립니다. 그 두 루틴이 낮 기준으로 무언가를 그리게 하는 자리입니다.
- `06:CE9D`: `LDA $075E / STA $075E / STZ $075F` 로 윗바이트만 지워, 밤(`0100` 이상)이면 `00xx` 의 낮으로 돌립니다. 이어서 `25:FD00`(A = `1D`)·`04:FB0F`(A = `07`)를 부르고 `7E:21AC` bit3 을 켜는 이벤트 루틴의 일부입니다.
실내 맵의 낮밤 인물·팔레트도 같은 `21:8000` 을 봅니다([dq5-map-format.md](dq5-map-format.md)). `sfc/dq5/tools/dq5daynight.py` 가 롬에서 이 값들과 `$075E` 에 상수를 쓰는 곳을 뽑습니다.

확인한 것(`field-free.mss`, 조우 계수표 `11EA44` 를 0 으로):

- 필드에서 6000프레임을 걸어도 `$075E` 는 `0050` 그대로였고, 이 세이브스테이트의 `7E:2190` 은 `0A`(bit1 켜짐)였습니다. `7E:2190` 을 `08` 로 고정하자 98걸음에 `0050` → `00B2` 로 걸음마다 1 씩 올랐습니다.
- 마을(01/00, `$BE` = `80`)에서는 `7E:2190` 을 `08` 로 해도 `00:82C2` 를 170번 지나는 동안 오르지 않았습니다.
- ラナルータ(`11:829B`)는 밤이면 `0050`, 아니면 `0190` 을 쓰고 `06:D905` 로 맵을 다시 불러옵니다. 주인공 필드 주문 목록(`23:BE2C`, 8칸)의 첫 칸을 `37` 로 바꿔 외우자 `0050` 에서는 `0190`(밤), `0190` 에서는 `0050`(낮)이 되었고 필드가 다시 그려졌습니다.
- やみのランプ(`11:8C18`)는 낮일 때만 같은 `11:82A1` 로 `0190` 을 씁니다. 필드 낮에서 쓰자 `0190` 이 되었고, 밤(`0190`)에서 쓰면 「火を ともした！」 다음 「しかし 何も おこらなかった。」였습니다. 둘 다 `$1949` ≠ 0 이거나 `1F:F8D3` 이 0 이 아니면 바꾸지 않습니다([dq5-data-format.md](dq5-data-format.md) 의 맵 항목 `+4`).

- 여관: 선실의 파파스 슬롯 대화 번호(`7E:36E8`·`36EB`)를 `006`(여관, `06:E384`)으로 바꾸고 금화(`7E:2019`)를 채워 묵었습니다. 들어갈 때 `$075E` 가 `0190`·`0050`·`00F0` 어느 것이든 자고 나면 `06:E43A` 가 `0050` 으로 두었습니다.

`$075E` 에 상수를 쓰는 곳은 도구가 `LDA #` 로 알아본 것만 25곳입니다. 여관 말고는 대부분 이벤트가 `0050`(낮)·`0190`·`00FF`(밤)·`0080` 으로 둡니다(코드 읽기).

`7E:2190` bit1(시간 멈춤)을 켜고 끄는 곳:

```
00:A72A  저장을 불러온 뒤(25:801C 다음):
           2190 bit6 꺼짐            → bit1 켬, $1948 = 0
           bit6 켜짐·bit5 꺼짐       → bit1 끔, bit0 켬, $1948 = 1
           bit6·bit5 켜짐·bit4 꺼짐  → $1948 = 2
06:D5E3  처음 배(17/01 대체 인물 목록 10:B26F) 船長 장면의 인물 스크립트가 부름:
           bit1 켬, $075E = 0050, 이벤트 37(15:F48E)을 23:E2F4 로 곧바로 시작함. 끝의 06:D63B 는 실제 진행에서 닿지 않음
02:9B90  06:CD62($075E = 0050, bit1 끔, 21A5 bit7 끔) → 02:9C23(03/05 (34,43) 로 옮기고 bit6·bit0 켬, $1948 = 1)
```

03/05 는 노예 채석장(「さっさと 岩をはこばんかっ！」)이라, 청년기 노예 시절이 시작될 때 아침이 되고 시간이 흐르기 시작합니다. 유년기에는 bit1 이 켜진 채입니다.

확인한 것:

- 저장 불러오기: 선실에서 파파스를 교회(대화 번호 `05`)로 바꿔 `7E:2190` 을 고친 채 칸 1 에 기록하고, 같은 실행에서 리셋해 ぼうけんをする → 칸 1 로 불러왔습니다. `00:A72A` 를 지난 뒤 `2190`·`$1948` 은 `08` → `0A`·0, `0A` → `0A`·0, `4A` → `49`·1, `6A` → `6A`·2, `7A` → `7A`·0 으로 위 갈래와 같았습니다.
- 이벤트 37: 船長 장면 뒤 해석기(`00:BEC3`)를 지날 때의 `$19B3` 은 `15:F48E` 부터 `F4A2`(왼쪽 52칸 걷기)까지 나아가다가 2881프레임에 `15:EF40`(`02:A94C` 가 거는 다음 장면, 「パパス「この女の子は？」」)으로 바뀌었습니다. `15:F4A4`(`06:D63B`)는 지나지 않았습니다.
- 노예 시절 시작: `TO=07/02,12,8,1 SET="219C|01;075E=10;075F=00" LATESET="21A3|01"` 로 파파스가 ゲマ 에게 쓰러지는 장면을 돌렸습니다. 3126프레임에 `06:CD7D` 가 `$075E` 를 `0010` → `0050` 으로, 3142프레임에 `06:CD8D` 가 `2190` 을 `0A` → `08`(bit1 끔)로, 3143프레임에 `06:CD9E` 가 `49`(bit6·bit0)로 바꾸고, 3418프레임에 `02:9C23` 으로 03/05 (34,43) 에 섰습니다. `$075E` 를 `0190`(밤)으로 두면 장면 인물이 서지 않았습니다.
- 처음 배: `TO=17/01,51,55`·`SET=21BF|01` 로 갑판에 내려 위로 걷자 船長 장면이 돌아 `06:D5E3` 을 지났습니다. A 를 눌러 항구를 지나 필드(276,142)로 나가 첫 슬라임 전투를 치르는 5900프레임 동안 `06:D63B` 는 불리지 않았고 `2190` 은 `0E`(bit1 켜짐)였습니다.

## 좌표

- `$B6`/`$B8`: 주인공의 필드 좌표, 8픽셀 단위. 블록 좌표는 반으로 나눈 값입니다. 실내 맵에서 나올 때 `04:FD97`/`04:FE83` 표로 정해집니다.
- `$90`/`$92`: 칸을 검사할 때 쓰는 8픽셀 타일 좌표. 블록 색인은 `(y >> 1) * 256 + (x >> 1)`.

## 필드의 인물

필드에서는 인물 목록을 풀지 않습니다. 슬롯 0 이 주인공이고 `$1967`(그릴 슬롯 수)만큼 뒤에 일행·마차가 붙습니다. 필드 (341,56) 에서 혼자면 `$1967` = 1, `PARTY=02,05 WAGON=1` 이면 `$1967` = 5 로 슬롯 1~4 에 그림 번호 `06`·`08`·`02`·`04` 가 들어갔고, 화면에는 주인공과 スライム 둘이 보였습니다(OAM 에 그린 항목 8개 → 32개). 슬롯 8~`0F` 에는 배 선실에서 남은 자리 값이 그대로 있었지만 그림 번호가 0 이고 그려지지 않았습니다.
