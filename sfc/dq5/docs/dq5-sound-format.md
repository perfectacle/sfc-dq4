## 명령과 대기열

소리는 [명령][인자] 두 바이트입니다. `24:FE91` 부터 9바이트짜리 입구가 14개 있고(`PHP / SEP #$20 / PHA / LDA #명령 / JMP 24:FF83`), A 에 인자를 넣고 `JSL` 합니다.
`24:FF83` 이 명령과 인자를 `7E:1D95`~(16칸) 대기열에 넣고, `2B:C30F`~`C32F` 가 APU 포트 `$2141`(명령)·`$2142`(인자)·`$2143`·`$2140` 에 써서 보냅니다(대화 중 기록에서 `$2141` = `0C`, `$2142` = `32` 처럼).

| 입구 | 명령 | 롬에서 직접 부르는 곳(`JSL`) | 실측한 쓰임 |
| --- | --- | --- | --- |
| `24:FE91` | `1A` | 20 | 앞 곡 정리. 인자는 쓰지 않음(아래 「SPC 로 가는 명령」). 맵을 불러올 때는 곡 번호가 `$1D8B`(지금 곡)와 다를 때만 보냄(`00:CEAB`). 전투 시작(`26:8F49`, 인자 `01`), 전투 승리(`20:80DF`, 인자 `A0`) |
| `24:FE9A` | `01` | 16 | 곡 틀기. 곡 자료가 SPC 에 없으면 먼저 보냄(아래 「곡 자료」). 맵을 불러올 때 늘 맵 곡으로(`00:CEA2`), 승리 때 `1F`(`BRK 0F`). 앞 곡을 줄여 끝낸 뒤 새 곡이 시작됨(아래 「DSP 로 본 반응」) |
| `24:FEA3` | `03` | 4 | 곡 키우기. 인자가 지금 곡이면 음량을 0 에서 X 속도로 올림(곡을 다시 시작하지 않음) |
| `24:FEAC` | `0C` | 7 | 곡·효과음 n 을 틀고 X 번 스크립트를 돌림(아래 「효과음과 스크립트」). 효과음(아래 표), 전투 시작 때 `17`(`26:8F91`, 전투 곡 번호 `7E:2CD0`) |
| `24:FEB5` | `0E` | 0 | 아무것도 안 함. 2B 처리 루틴 `2B:BFA7` 은 대기열 칸만 비우고 APU 로 보내지 않음 |
| `24:FEBE` | `02` | 3 | 곡 멈추기. 인자가 지금 곡이면 4프레임 뒤 모든 채널이 꺼짐, 다르면 그대로 |
| `24:FEC7` | `04` | 12 | 곡 줄이기. 인자가 지금 곡이면 X 속도로 음량을 0 까지 줄임, 다르면 그대로 |
| `24:FED0` | `05` | 4 | 전투 메시지를 찍을 때 인자 `32`(`24:85C9`) |
| `24:FED9` | `0D` | 0 | 아무것도 안 함. 처리 루틴 `2B:BFC8` 은 `RTS` 하나이고 APU 로 보내지 않음 |
| `24:FEE2`~`24:FF06` | `94`·`8B`·`93`·`95`·`96` | 1·1·1·0·0 | 곡 자료 관리(아래 「SPC 로 가는 명령」). `94 n` = 곡 n 자료 미리 올리기, `8B`·`93` = 늘 둘 샘플·시퀀스 고정(전원을 켠 54프레임에 `00:A6E1`·`A6E5` 가 한 번), `95`·`96` = SPC 명령 `15`·`16` |

승리 뒤에는 대기열 안에서 `24:FF12` 가 `09 1F` 도 보냈습니다. `09 n` 은 곡 n 이 아직 울리는지 SPC 에 묻는 명령입니다(아래 「SPC 로 가는 명령」). `02`·`03`·`04`·`0D`·`0E`·`94`·`8B`·`93`·`95`·`96`·`09` 의 쓰임은 실제 장면이 아니라 명령을 바꿔 보내 본 것입니다(아래 「명령을 바꿔 보내 보기」). 부르는 곳: `03` 은 `02:9C18`·`03:9964`, `02` 는 `0F:FC49`, `04` 는 `02:9BAF`·`02:AAE8`·`03:9833`·`03:EC2F`·`06:CD6E`·`06:E0EC`·`06:E419`·`23:DE18`·`23:FE71`(이벤트 명령 `C6`)·`29:80D1`, `8B`·`93` 은 `00:A6E1`·`00:A6E5`.

## BRK 0F~19

`BRK nn a b` 는 공용 서비스 호출이고(`00:8F80`, 표 `00:921B`), `0F`~`19` 는 모두 `00:9256` 에서 표 `00:928C` 로 갈라 위 입구를 부릅니다. A 는 `BRK` 다음 첫 바이트, X 는 둘째 바이트입니다(`03`·`04`·`0C` 만 X 를 넘김).
「기다림」은 입구를 부른 뒤 `24:FE44` 를 부르는 것입니다. `24:FE44` 는 대기열의 읽기 칸 `$1D93` 부터 쓰기 칸 `$1D91` 까지가 모두 `FF`(보냄)가 될 때까지 한 프레임씩 쉽니다(bit6 이 켜진 명령은 보낸 것으로 침). 곧 소리가 끝날 때까지가 아니라 명령이 APU 로 넘어갈 때까지입니다. 실측: 효과음 `BRK 16 33`·`16 37` 은 들어간 다음 프레임에 나왔고, 승리 때 `BRK 0F 1F`(명령 `01`)는 33프레임(1564→1597) 걸렸습니다. 그 사이 앞 곡의 음량이 줄었으므로, 대기열이 곡을 줄이는 동안 다음 명령을 넘기지 않는 것으로 보입니다.

| BRK | 명령 | 기다림 | BRK | 명령 | 기다림 |
| --- | --- | --- | --- | --- | --- |
| `0F` | `01` | 예 | `15` | `04` | 예 |
| `10` | `02` | 예 | `16` | `0C` | 예 |
| `11` | `01` | | `17` | `03` | |
| `12` | `02` | | `18` | `04` | |
| `13` | `94` | | `19` | `0C` | |
| `14` | `03` | 예 | | | |

곧 `BRK 19 nn` 과 `BRK 16 nn` 이 효과음 nn 입니다. 롬에서 `00 19 nn`·`00 16 nn` 꼴을 찾으면 효과음 번호마다 부르는 자리를 대강 모을 수 있습니다(데이터 속 우연한 바이트도 섞임).

## 효과음

| 명령 `0C` 인자 | 장면(실측) |
| --- | --- |
| `32` | 대화 창이 열릴 때. 배 선실에서 파파스에게 말을 걸자 메시지 창이 뜨는 프레임에 보냄. 전투 메시지 코드 `F9`(`BRK 19 32`)도 같은 소리이고, 「＊「…」·「ジャミ「…」 처럼 말하는 사람 이름 앞에 붙음. 롬에서 `BRK 19 32` 는 `04:9DA2`(창 루틴)와 `24:8898`(`F9` 처리기) 둘 |
| `33` | 명령 창 열기·고르기(A) |
| `34` | 창 닫기(B) |
| `37` | 공격이 맞을 때 |
| `17` | 전투 시작(전투 곡) |

## DSP 로 본 반응

MesenCE Lua 에는 오디오 녹음 함수가 없어(`emu.memType` 에 `spcDspRegisters`·`spcRam` 만 있음), 프레임마다 DSP 레지스터(주 음량 `$0C`·`$1C`, 메아리 `$2C`·`$3C`, 8채널 ENVX 합, KON `$4C`·KOF `$5C`, FLG `$6C`, 채널 0 음량 `$00`·`$01`)를 적어 명령과 견줬습니다(`dq5sndlog.lua` 의 `DSP=1`).

- 전투 승리(1564 `1A A0`·`01 1F`): 채널 0 음량이 `10` → `00` 으로 30프레임에 걸쳐 줄고(1564~1594), ENVX 가 0 이 된 뒤 1602 에 다른 음량으로 새 곡이 울렸습니다.
- 전투 시작(500 `1A 01`, 501 `0C 17`): 필드 곡이 줄어 502 에 끊기고, 508 에 KON 과 함께 전투 곡이 시작했습니다.
- 선실 → 필드(444 `1A 02`·`01 02`): 452 에 KON, 메아리 음량이 `00` → `14` 로 바뀌었습니다.
주 음량은 내내 `5C` 였습니다. 곡 이름·효과음 이름은 소리를 들어 보지 못해 정하지 않았습니다.

## 명령을 바꿔 보내 보기

장면마다 부르는 곳을 찾아가는 대신, 필드(세계 0, 곡 `02`)에서 A 로 메뉴를 열 때 나가는 `0C 33` 을 `24:FF83` 에 들어오는 순간 다른 명령·인자·X 로 바꿔 보냈습니다(`dq5sndlog.lua` 의 `HCMD`·`HARG`·`HX`). 604 프레임에 보내고 DSP 를 기록했습니다.

| 명령 인자 X | 채널 0 음량(604 → ) |
| --- | --- |
| `04 02 10` | `11,16` 에서 줄기 시작해 774 에 `00` |
| `04 02 20` | 691 에 `00` |
| `04 02 40` | 649 에 `00` |
| `04 05 20` | 그대로(`12,17`) |
| `03 02 10` | 608 에 `00` 으로 떨어진 뒤 776 에 `12,17` |
| `03 02 20` | 696 에 `12,17` |
| `03 02 40` | 656 에 `12,17` |
| `03 05 20` | 곡이 끊기고 메아리 음량 `00`·FLG `35`(메아리 쓰기 끔), 채널 0 이 `0D,06` 까지 올라 다른 소리가 남. `01 05` 를 보냈을 때와 KON 이 같은 프레임(664)에 남 |
| `02 02` | 608 에 모든 채널 ENVX 합 `0`, 음량 `00` |
| `02 05` | 그대로 |
| `0D`·`0E`·`94`·`95`·`96`(인자 `00`·`01`·`02`·`80`), `8B 00`·`93 00`·`09 1F` | 주 음량·메아리·FLG·채널 0 음량·ENVX 가 바꾸지 않은 기록과 같음 |

X 가 두 배면 걸리는 시간이 반쯤으로 줄어, 줄이기·키우기 모두 약 2800/X(십진) 프레임입니다. `03 02`·`04 02` 사이 KON 이 난 프레임은 서로 같아 곡은 이어서 흐릅니다.
DSP 로 안 보이는 명령도 SPC RAM 은 바꿉니다(`SPCDUMP` 로 640 프레임을 `0D` 와 견줌, 메아리 버퍼 `D700`~ 은 뺌): `8B 00` 은 `053C`·`0544`… 8바이트 간격 6칸을 `10` → `30`, `93 00` 과 `94 00` 은 `05DA`·`05E0`… 6바이트 간격을 `10` → `30` 으로 바꿨고, `95`·`96`·`09` 는 `00F4`·`018E`·`0196`~ 몇 바이트만 바뀌었습니다. 그 칸은 아래 「SPC 드라이버」의 샘플 칸 표(`0535`~, 8바이트)와 시퀀스 칸 표(`05D5`~, 6바이트)의 플래그 바이트이고, `30` 은 고정 비트 `10` 에 참조 수 1(`20`)이 더해진 값입니다. `0D` 와 `0E` 의 SPC RAM 은 같았습니다.

## SPC 로 가는 명령

대기열의 명령은 2B 뱅크가 `명령 & 3F` 로 표 `2B:C43B` 의 처리 루틴을 골라 SPC 명령으로 바꿉니다(`2B:BF0D`). 명령을 바꿔 보내며 APU 포트 `$2140`~`$2143` 에 쓰인 값을 모두 기록했습니다(work 의 쓰기 콜백).

| 대기열 명령 | APU 로 간 것 | 뜻 |
| --- | --- | --- |
| `1A 05`·`1A 00`·`1A FF` | `04 02 7E`, `15`, `09 02` 을 대답이 `7F` 일 때까지 되풀이, `16`, `0A` | 세 인자 모두 같은 바이트가 나감. 지금 곡(`$1D8B` = `02`)을 X `7E` 로 빨리 줄이고, 대기열의 `01`·`03`·`0C` 를 지우고(`2B:C118`), 곡이 멈출 때까지 기다린 뒤 참조 수를 비우고 쓰지 않는 자료를 버림. `$1D8B` 는 `FF` |
| `8B 00` | `0B 00`·`0B 05`·`0B 1F`·`0B 22`·`0B 20`·`0B 21` | 목록 `2B:C422` 의 샘플을 고정 |
| `93 00` | `13 00`·`13 17`·`13 1D`·`13 21`·`13 32`~`13 3D`·`13 46` | 목록 `2B:C429` 의 시퀀스를 고정 |
| `94 00` | `10 00` | 곡 n 자료 올리기(`2B:C1C8`: 시퀀스 n 을 `10` 으로, 곡 묶음 n 의 샘플을 `00` 으로). 곡 묶음 0 은 샘플이 없음 |
| `95 00`·`96 00` | `15 00`·`16 00` | |
| `09 1F` | `09 1F` | |
| `0D 02`·`0E 02` | 없음 | |

SPC 쪽은 `$F4`(`$2140`) bit0 이 바뀌면 `$F5` 를 명령으로 읽고(`0F6D`), `17` 보다 작으면 표 `09EB` 로 갑니다(`0A19`). 드라이버는 직접 페이지 1 을 씁니다(`SETP`, `$8A` = `$018A`). 처리 루틴은 SPC RAM 덤프를 [spc700.py](../tools/spc700.py) 로 풀어 읽었습니다(코드 읽기).

| SPC 명령 | 처리 | 하는 일 |
| --- | --- | --- |
| `00`·`0B` | `0A26`·`0C2E`(= `0A26`) | 샘플 n(인자) 의 칸을 `03FF+n` 에서 찾아, 있으면 플래그 bit7~5(참조 수)에 `20` 을 더함(`E0` 이 끝). `0B` 는 bit4(고정)도 켬. 없으면 2B 가 이어서 자료를 보냄 |
| `10`·`13` | `0CA7`·`0D43` | 시퀀스 n 으로 같은 일(`04C7+n`, 칸 표 `05D5`). `13` 은 고정 |
| `09` | `0C08` | 8개 곡 자리(`03B7` 켜짐, `03AF` 곡 번호)에서 곡 n 을 찾아 `$F5`(`$2141`)로 `03DF+자리` 를, 없으면 `7F` 를 돌려줌. 2B 는 `2B:C0F8` 에서 이 값을 읽음 |
| `0A` | `0C24` | 참조 수가 0 인 샘플(`255D`)과 시퀀스(`27BA`)를 버리고 자리를 모음 |
| `15` | `0D8E` | `052B`~`0534` 를 `FF` 로 채우고 받던 전송 상태(`$8A`)를 정리 |
| `16` | `0E01` | 샘플 칸 표와 시퀀스 칸 표의 플래그를 모두 `& 1F`(참조 수만 지움, 고정은 남김) |
| `02`·`03`·`04` | `0B25`·`0B34`·`0B95` | 곡 멈추기·키우기·줄이기(위 「명령을 바꿔 보내 보기」의 실측) |
| `01`·`0C` | `0AD9`·`0C31` | 곡 틀기(`11CA`). `0C` 는 이어서 스크립트 X(아래 「효과음과 스크립트」) |
| `05` | `0BBB` | 스크립트 n 돌리기 |

## 곡 자료

곡 번호 n 은 시퀀스 번호입니다. `01 n`·`03 n`·`0C n` 을 보내면 2B 뱅크가 시퀀스 n 과 곡 묶음 n 의 샘플이 SPC 에 있는지 보고, 없는 것을 보냅니다(`2B:BF98` → `2B:C1C8`). 시퀀스는 SPC 명령 `90`(`10` 에 bit7 = 자료가 따라옴), 샘플은 `80` 으로 보내고, 자료는 `2B:C25F` 가 `[$FB]` 에서 3바이트씩 `$2141`~`$2143` 으로 넘깁니다.

| 표 | 롬 | 형식 |
| --- | --- | --- |
| 샘플 0x26개 | `2B:EB00`~(`2B:C391`) | `[길이 2][반복 위치 2][ADSR1][ADSR2][GAIN][음높이 2][BRR]` 을 이어 붙임. 뱅크를 넘어도 파일 오프셋으로 이어짐 |
| 시퀀스 0x47개 | `2E:E2E4`~(`2B:C39E`) | `[길이 2][자료]` 를 이어 붙임 |
| 곡 묶음 | `2B:E67F`(`2B:C3CB`) | 곡마다 `[샘플 수 L][한 바이트][샘플 번호 L개]`. 곡 `02` = `03 02 03 00 04`(샘플 `03`·`00`·`04`) |

SPC RAM 쪽은 이렇습니다.

| 주소 | 내용 |
| --- | --- |
| `0535`~ | 샘플 칸 0x14개 x 8바이트: `[BRR 길이 2][ADSR1][ADSR2][GAIN][음높이 2][플래그]`. 플래그 bit7~5 참조 수, bit4 고정 |
| `05D5`~ | 시퀀스 칸 0x14개 x 6바이트: `[FF][주소 2][길이 2][플래그]` |
| `03FF+n`·`04C7+n` | 샘플 n·시퀀스 n 이 든 칸(`FF` 면 없음) |
| `0700`~ | DSP 샘플 목록(DIR = `07`). 칸마다 `[시작 2][반복 2]` |
| `D700`~ | 메아리 버퍼(ESA = `D7`) |

실측: 필드(550 프레임)와 마법 융단을 편 뒤(1180 프레임)의 SPC RAM 덤프에서, 칸 표에 오른 시퀀스·샘플 26개·30개가 롬 자료와 바이트까지 같았습니다(`dq5spc.py --check`). 샘플은 DIR 의 시작 주소에 BRR 이 있고, 반복 주소 - 시작 주소가 머리 2바이트(반복 위치)와 같았습니다. 연주 중인 채널의 ADSR·GAIN 은 `FF E0`·`B8` 로 머리 값과 같았습니다(곡이 바꾼 `FA` 도 있음).
곡 묶음의 둘째 바이트 k 는 곡을 틀기 전에 보내는 샘플 수입니다. `2B:C1C8` 이 앞 k 개를, 곡이 시작한 뒤 `2B:C1DB` 가 나머지 L - k 개를 보냅니다(`2B:C3F2`). 곡 `02`(`03 02 03 00 04`)는 `03`·`00` 뒤에 `04` 를, 곡 `03`(L 8, k 4)은 `00`·`03`·`05`·`06` 뒤에 `07`~`0A` 를 보낸 것이 전송 기록과 같았습니다.

장면에서 본 전송(`2B:C25F` 를 지날 때의 `$FB` 와 길이):

| 장면 | 명령 | 보낸 것 |
| --- | --- | --- |
| 선실 → 필드 | `1A 02`·`01 02` | 시퀀스 `02`(`2E:E7A6`, `01F7`), 샘플 `03`·`04`(`00` 은 이미 있음) |
| 마법 융단 펴기 | `1A 00`·`01 03` | 시퀀스 `03`, 샘플 `03`·`06`~`0A`(`00`·`05` 는 고정) |
| 배에 오르기 | `1A 04`·`0C 04` | 시퀀스 `04`, 샘플 `08`·`07`·`0A`·`09`·`0B` |
| 天空城 | `01 0D` | 시퀀스 `0D`, 샘플 `03`(다음 `02` 는 기록이 끝남) |
| 드래곤에서 내리기 | `1A 01`·`01 02` | 시퀀스 `02`, 샘플 `03`·`04` |

`1A` 를 보낸 프레임에는 아무것도 전송되지 않고, 전송은 늘 `01`·`0C` 뒤에 있었습니다. 곧 `1A` 의 인자(`04`·`00`·`FF`·`01`)가 곡 번호와 달랐던 것은 쓰이지 않는 값이기 때문입니다.

## 시퀀스 형식

시퀀스(곡과 효과음 모두)는 `[템포][트랙 수 N][트랙 오프셋 2바이트 x N]` 머리 뒤에 트랙 바이트가 옵니다. 오프셋은 시퀀스 첫 바이트 기준입니다(`11CA`). 트랙 하나가 DSP 목소리 하나를 씁니다. 곡을 틀면 트랙마다 길이 `CC` 비율·음량 `60`·`80`·가운데 팬으로 시작합니다(`1273`~`12AE`).

트랙 바이트는 틱마다 기다림이 0 이 된 트랙에서 `154E` 가 읽습니다. 명령은 시간을 쓰지 않고, 음표 하나를 읽으면 그 길이만큼 쉽니다.

| 바이트 | 뜻 |
| --- | --- |
| `00`~`4F` | 음표, 앞 길이 그대로. `00` = 쉼, `4F` = 붙임(음을 바꾸지 않음), 나머지 n 은 음 n + 조옮김 |
| `50`~`9F` | 음표 n = 바이트 - `50` 에 새 길이(다음 바이트, 틱) |
| `A0`~`B5` | 소리 길이 비율(게이트)을 표 `17CD` 의 값으로: `0D 1A 26 33 40 4D 5A 66 73 80 8C 99 A6 B3 BF CC D9 E6 F2 FE FF 00` |
| `B6`~`DA` | 아무것도 안 함(`15CC`). 실제로 쓰인 것은 `D0` 뿐 |
| `DB`~`FE` | 명령(아래 표, 처리 루틴 표 `0795`) |
| `FF` | 트랙 끝 |

음 n 은 n - 1 = 옥타브 x 12 + 반음으로 나눠 표 `07E5` 의 피치에 옥타브를 곱합니다(`1B73`). 잡음을 켠 트랙(`E3`)은 음 번호 하위 5비트를 FLG 의 잡음 주파수로 씁니다(`1B46`).

| 명령 | 인자 | 뜻(처리 루틴) |
| --- | --- | --- |
| `DB` | 오프셋 2 | 되풀이 카운터 1(`022B`)이 0 이 아니면 점프 = 첫 바퀴에만 건너뜀(`18F3`) |
| `DC` | 오프셋 2 | 카운터 1 로 두 바퀴 되풀이: 0 이면 2 로 두고 1 을 빼 0 이 아니면 점프(`18F8`) |
| `DD` | r | 릴리스(ADSR2 하위 5비트, `181A`) |
| `DE` | a1 a2 r | `EF` + `DD`(`1817`) |
| `DF` | m | 좌·우 위상 뒤집기 비트(bit0 왼쪽, bit1 오른쪽, `16F3`·`1AF2`) |
| `E0` | 오프셋 2, v | 곡 변수(`03E7`)가 v 면 점프. 읽은 틱이 끝나면 변수는 0(`16C0`·`14BC`) |
| `E1` | | 곡 진행 표시(`03DF`)를 1 올림. 명령 `09` 의 대답이 이 값(`16B2`) |
| `E2` | v | `78`·`79`·`8C`·`8D` 를 둠(`16FF`). 뜻 모름 |
| `E3`·`E4` | | 잡음 켜기·끄기(DSP NON, `1F3C`·`1F5C`) |
| `E5` | v | 곡 음량 목표(`03C7`, `171C`). 쓰는 곡 없음 |
| `E6` | a b | `0343`·`0344`(`172C`). 뜻 모름 |
| `E7` | v | `0253`(`173E`). 쓰는 곡 없음 |
| `E8` | 목표 시간 | 팬 미끄럼(`1757`) |
| `E9` | v | 음높이 미세 조정(`8D`, `1B8F`) |
| `EA` | 오프셋 2 | 점프(`179B`) |
| `EB` | t | 템포(곡 자리 `03B7`, `17B1`) |
| `EC` | v | 소리 길이 비율(`0204`, `17BC`) |
| `ED` | v | 음량(`28`, `17E3`) |
| `EE` | p | 팬(부호 있음, `3C`, `17EE`) |
| `EF` | a1 a2 | ADSR1·ADSR2(`17F9`) |
| `F0` | i | 악기. 곡 묶음 레코드의 i 번째 샘플을 고르고 그 머리의 ADSR·GAIN·음높이를 씀(`182E`) |
| `F1`·`F2` | | 앞 트랙 따르기: 음표마다 바로 앞 트랙의 길이·비율을 가져옴(`18DF`·`1C64`) |
| `F3` | | 따르기 끄기(`18EA`) |
| `F4` | 오프셋 2 | 카운터 2(`0217`)로 두 바퀴 되풀이(`1905`) |
| `F5` | 횟수, 오프셋 2 | 카운터 2 로 「횟수」 바퀴 되풀이(`191C`) |
| `F6` | v | 음량 2(`29`, `1922`) |
| `F7` | | 아무것도 안 함 |
| `F8` | 오프셋 2 | 부르기(돌아올 자리를 `0267` 에 3단까지, `192E`) |
| `F9` | | 돌아가기. 쌓인 것이 없으면 아무것도 안 함(`1970`) |
| `FA` | t | 조옮김(부호 있음, `1989`) |
| `FB` | 깊이 속도 | 비브라토(`1990`) |
| `FC`·`FD` | | 메아리 켜기·끄기(DSP EON, `1F7E`·`1F9E`) |
| `FE` | n | 스크립트 n 을 돌림(`204B`, 아래) |

오프셋은 모두 인자 바로 뒤를 기준으로 더하는 16비트 값입니다. 목소리 음량은 `ED` x `F6` x 곡 음량(`03A7`)이고, `EE` 가 한쪽을 줄입니다(`1A9E`). 뜻을 「모름」으로 둔 명령과 `E5`·`E6`·`E8` 의 세부는 코드 읽기만 했습니다.

틱: 곡 자리마다 `03BF` 에 템포를 더해 넘치면(또는 `FB` 이상이면) 한 틱입니다(`146C`). 실측한 다섯 곡에서 틱당 프레임 x 템포가 모두 약 75 였습니다(`02` 0.6635 x `71`, `03` 0.653 x `73`, `04` 0.833 x `5A`, `0D` 1.070 x `46`). 곧 1초에 약 0.8 x 템포 틱입니다.

`dq5song.py --check` 는 시퀀스 0x47개의 모든 트랙을 흐름(점프·되풀이 두 갈래·부르기)대로 끝까지 풉니다. 모르는 바이트와 범위 밖 점프가 0 이고, 닿지 않는 바이트는 시퀀스 `37`·`39`·`41`·`45` 의 끝 1~2바이트(점프 뒤의 `FF` 등)뿐입니다.

### 실측: 디코더 음표와 KON

`lua/dq5dspw.lua` 로 SPC 가 DSP 에 쓴 KON·피치·FLG 를 프레임마다 적고, `dq5song.py N --kon dspw.txt --start F` 로 트랙 i 를 목소리 i 로 보고 음표 12개씩 견줬습니다. 시각은 첫 음과 틱당 프레임으로, 음은 악기가 같은 이웃 음끼리 반음 차이(피치 비의 log2 x 12)로 봤습니다.

| 곡 | 장면 | 트랙 | 최대 시각 차(프레임) | 음 차이 틀림 |
| --- | --- | --- | --- | --- |
| `02` | 필드 | 5 | 1.9 | 0 |
| `03` | 마법 융단 | 7 | 2.6 | 0 |
| `04` | 배(`0C 04 01`, `--flag 1`) | 7 | 1.9 | 0 |
| `0D` | 天空城 | 7 | 1.7 | 0 |
| `17` | 전투 | 6 | 3.5 | 0 |

배 곡은 곡 변수 0 으로 풀면 트랙 0·1·3~6 의 음이 틀렸고, 0C 의 X(`01`)가 고른 스크립트 `01`(`05 01`)대로 변수를 1 로 두자 모두 맞았습니다. 선실의 맵 곡도 같은 시퀀스 `04` 를 `01 04`(변수 0)로 틉니다.

## 효과음과 스크립트

효과음도 같은 형식의 시퀀스입니다(`32`~`46` 대부분 트랙 1개, 고정 목록 `2B:C429`). 목소리 7 에서 울렸습니다(KON `80`). 명령 `0C n X` 는 시퀀스 n 을 튼 뒤 X 가 `21` 보다 작으면 스크립트 X 를 돌립니다(`0C82` → `204B`). 효과음은 첫머리의 `E0` 들로 X 에 따라 다른 소리로 갈라집니다(`37` 은 21갈래, `34` 는 6갈래).

스크립트는 SPC RAM 표 `0801`(2바이트 x 0x21)이 가리키는 바이트열이고, 명령 `05 n` 도 같은 것을 돌립니다(`0BBB`). 확인한 연산:

| 바이트 | 인자 | 뜻 |
| --- | --- | --- |
| `00` | v | 곡 음량(`03A7`) |
| `01` | v | 곡 음량 목표(`03C7`, `03CF` = `80`) |
| `02` | t | 템포 |
| `05` | v | 곡 변수(`03E7`) = v |
| `10` | 8바이트 | DSP `0F`·`1F`…`7F`(메아리 필터 계수) |
| `FE` | r v | DSP 레지스터 r 에 v |

스크립트 `00`~`14` 는 모두 `05 n` 하나(변수 = 번호)이고, `15`·`16`·`19` 는 연산 `10`·`13`·`14`·`16`·`17` 을 쓰는 메아리 설정(뜻은 `10` 만 읽음), `1A`~`1E` 는 곡 음량 `0A`·`13`·`24`·`44`·`80` 입니다.

전투에서 공격이 맞을 때의 `0C 37` 을 APU 포트 기록으로 X 를 얻어 견줬습니다.

| X | KON | 시각 차 | 음 틀림 |
| --- | --- | --- | --- |
| `07` | 4 | 0.7 | 0 |
| `04` | 8(잡음) | 0.7 | 0 |
| `02` | 6 | 0.6 | 0 |
| `03` | 8(잡음) | 0.6 | 0 |

메뉴의 `0C 33 00` 은 음표 하나(`44` + 조옮김 `0C`)이고 KON 도 하나였습니다.

## 맵 곡 (`23:FD6A`)

실내 맵 레코드 `23:FD6A[BC] + BD*6`(6바이트, [dq5-data-format.md 「전투 조우」](dq5-data-format.md))의 `+5` 가 곡 번호입니다. 맵을 불러올 때 `00:CEB1` 이 이 값을 `$194B` 에 두고 명령 `1A` 로 보내고(지금 올린 곡과 다를 때만), 이어서 `00:CEA2` 가 같은 인자로 명령 `01` 을 보냅니다. 필드는 세계 0 이 `02`, 세계 1 이 `05`, 세계 2 가 `0E` 였습니다(`$1949` 를 매 프레임 고정하고 필드에 나가 기록). 탈것의 곡은 아래 「탈것」에 있습니다.
`dq5sound.py` 가 346개 맵의 곡을 뽑습니다. 가장 많은 것은 `09`(106개), `0A`(80), `06`(60), `01`(38), `0C`(20) 입니다. 곡 이름은 소리를 듣지 않아 정하지 않았습니다.

## 탈것

필드 세계 0(곡 `02`)에서 기록했습니다. `$1954` 가 `80`~`82` 면 `00:810C` 가 A 를 누를 때 메뉴 대신 `01:BC3F` 로 내리기를 하고(`80` → `01:BDEA`, `81` → `01:C30A`, `82` → `01:C179`), 타는 쪽은 `01:BC0E` 가 `80` → `01:BC7B`, `81` → `01:C2EF`, `82` → `01:BFD1` 로 가릅니다.

| 탈것 | 탈 때 | 내릴 때 |
| --- | --- | --- |
| 배 | `1A 04`(`01:82DD`)·`0C 04`(`BRK 19`). 세워 둔 배로 걸어 올라탐 | |
| 마법 융단 | `1A 00`(`01:BC87`)·`01 03`(`BRK 11`). アイテム 창에서 실제로 폄 | `1A FF`(`01:BE38`)·`01 02`(`01:BE3F`, 맵 곡 `$194B`). 산 위에서는 「ここでは 降りられない。」만 나오고 명령 없음 |
| 天空城 | `01 0D`(`BRK 11`, `01:C2EF` 안) | 명령 없음. 맵 06/08 로 들어가 맵 곡 `01 0D`(`00:CEA2`) |
| マスタードラゴン | 명령 없음(필드 곡 `02` 그대로) | `1A 01`(`01:C213`)·`01 02`(`01:C21A`) |

天空城·드래곤은 `LATESET=1954=81`·`82` 로 탄 상태를 만든 것이고, 이야기 속에서 처음 탈 때의 장면은 보지 않았습니다.
天空城은 `01:C375` 가 주인공 둘레 4x3칸(x-1~x+2, y-1~y+1)의 지형이 모두 `01`·`06`(목록 `01:BE7A`)일 때만 내립니다. 지형은 필드 블록 번호(좌표 / 2)의 니블 `03:CC48`(`03:CB1B`)이고, `01:BE92` 에서 찍은 7칸의 값이 계산과 모두 맞았습니다. `FIELD=335,61` 에서 열두 칸이 모두 `06` 이라 내렸고, 바다(328,27, 지형 `09`)나 `02` 가 섞인 곳에서는 메시지만 나왔습니다.
