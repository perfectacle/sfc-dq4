## 명령과 대기열

소리는 [명령][인자] 두 바이트입니다. `24:FE91` 부터 9바이트짜리 입구가 14개 있고(`PHP / SEP #$20 / PHA / LDA #명령 / JMP 24:FF83`), A 에 인자를 넣고 `JSL` 합니다.
`24:FF83` 이 명령과 인자를 `7E:1D95`~(16칸) 대기열에 넣고, `2B:C30F`~`C32F` 가 APU 포트 `$2141`(명령)·`$2142`(인자)·`$2143`·`$2140` 에 써서 보냅니다(대화 중 기록에서 `$2141` = `0C`, `$2142` = `32` 처럼).

| 입구 | 명령 | 롬에서 직접 부르는 곳(`JSL`) | 실측한 쓰임 |
| --- | --- | --- | --- |
| `24:FE91` | `1A` | 20 | 앞 곡 정리. 인자는 쓰지 않음(아래 「SPC 로 가는 명령」). 맵을 불러올 때는 곡 번호가 `$1D8B`(지금 곡)와 다를 때만 보냄(`00:CEAB`). 전투 시작(`26:8F49`, 인자 `01`), 전투 승리(`20:80DF`, 인자 `A0`) |
| `24:FE9A` | `01` | 16 | 곡 틀기. 곡 자료가 SPC 에 없으면 먼저 보냄(아래 「곡 자료」). 맵을 불러올 때 늘 맵 곡으로(`00:CEA2`), 승리 때 `1F`(`BRK 0F`). 앞 곡을 줄여 끝낸 뒤 새 곡이 시작됨(아래 「DSP 로 본 반응」) |
| `24:FEA3` | `03` | 4 | 곡 키우기. 인자가 지금 곡이면 음량을 0 에서 X 속도로 올림(곡을 다시 시작하지 않음) |
| `24:FEAC` | `0C` | 7 | 곡·효과음 n 을 틀고 X 번 스크립트를 돌림(아래 「효과음과 스크립트」). 효과음(아래 표), 전투 시작 때 `17`(`26:8F91`, 전투 곡 번호 `7E:2CD0`) |
| `24:FEB5` | `0E` | 0 | 아무것도 안 함. 2B 처리 루틴 `2B:BFA7` 은 대기열 칸만 비우고 APU 로 보내지 않음 |
| `24:FEBE` | `02` | 3 | 곡 멈추기. 인자가 지금 곡이면 4프레임 뒤 모든 채널이 꺼짐, 다르면 그대로 |
| `24:FEC7` | `04` | 12 | 곡 줄이기. 인자가 지금 곡이면 X 속도로 음량을 0 까지 줄임, 다르면 그대로 |
| `24:FED0` | `05` | 4 | 시퀀스 인자·스크립트 X 를 SPC 명령 `05` 로(아래 「효과음과 스크립트」). 메시지·슬롯 코인·미닫이 방의 되풀이 효과음 끝내기, 모노·스테레오(`23:FEA1`) |
| `24:FED9` | `0D` | 0 | 아무것도 안 함. 처리 루틴 `2B:BFC8` 은 `RTS` 하나이고 APU 로 보내지 않음 |
| `24:FEE2`~`24:FF06` | `94`·`8B`·`93`·`95`·`96` | 1·1·1·0·0 | 곡 자료 관리(아래 「SPC 로 가는 명령」). `94 n` = 곡 n 자료 미리 올리기, `8B`·`93` = 늘 둘 샘플·시퀀스 고정(전원을 켠 54프레임에 `00:A6E1`·`A6E5` 가 한 번), `95`·`96` = SPC 명령 `15`·`16` |

승리 뒤에는 대기열 안에서 `24:FF12` 가 `09 1F` 도 보냈습니다. `09 n` 은 곡 n 이 아직 울리는지 SPC 에 묻는 명령입니다(아래 「SPC 로 가는 명령」). `02`·`03`·`04`·`0D`·`0E`·`94`·`8B`·`93`·`95`·`96`·`09` 의 쓰임은 실제 장면이 아니라 명령을 바꿔 보내 본 것입니다(아래 「명령을 바꿔 보내 보기」). 부르는 곳: `03` 은 `02:9C18`·`03:9964`, `02` 는 `0F:FC49`, `04` 는 `02:9BAF`·`02:AAE8`·`03:9833`·`03:EC2F`·`06:CD6E`·`06:E0EC`·`06:E419`·`23:DE18`·`23:FE71`(이벤트 명령 `C6`)·`29:80D1`, `8B`·`93` 은 `00:A6E1`·`00:A6E5`.

## BRK 0F~19

`BRK nn a b` 는 공용 서비스 호출이고(`00:8F80`, 표 `00:921B`), `0F`~`19` 는 모두 `00:9256` 에서 표 `00:928C` 로 갈라 위 입구를 부릅니다. A 는 `BRK` 다음 첫 바이트, X 는 둘째 바이트입니다(`03`·`04`·`0C` 만 X 를 넘김).
「기다림」은 입구를 부른 뒤 `24:FE44` 를 부르는 것입니다. `24:FE44` 는 대기열의 읽기 칸 `$1D93` 부터 쓰기 칸 `$1D91` 까지가 모두 `FF`(보냄)가 될 때까지 한 프레임씩 쉽니다(bit6 이 켜진 명령은 보낸 것으로 침). 곧 소리가 끝날 때까지가 아니라 명령이 APU 로 넘어갈 때까지입니다. 실측: 효과음 `BRK 16 33`·`16 37` 은 들어간 다음 프레임에 나왔고, 승리 때 `BRK 0F 1F`(명령 `01`)는 33프레임(1564→1597) 걸렸습니다. 그 사이 앞 곡의 음량이 줄었으므로, 대기열이 곡을 줄이는 동안 다음 명령을 넘기지 않는 것으로 보입니다.

| BRK | 명령 | 기다림 | BRK | 명령 | 기다림 |
| --- | --- | --- | --- | --- | --- |
| `0F` | `01` | 예 | `15` | `04` | 예 |
| `10` | `02` | 예 | `16` | `0C` | 예 |
| `11` | `01` | | `17` | `03` | |
| `12` | `02` | | `18` | `04` | |
| `13` | `94` | | `19` | `0C` | |
| `14` | `03` | 예 | | | |

곧 `BRK 19 nn` 과 `BRK 16 nn` 이 효과음 nn 입니다. 롬에서 `00 19 nn`·`00 16 nn` 꼴을 찾으면 효과음 번호마다 부르는 자리를 대강 모을 수 있습니다(데이터 속 우연한 바이트도 섞임).

| 명령 `0C` 인자 | 장면(실측) |
| --- | --- |
| `32` | 대화 창이 열릴 때. 배 선실에서 파파스에게 말을 걸자 메시지 창이 뜨는 프레임에 보냄. 전투 메시지 코드 `F9`(`BRK 19 32`)도 같은 소리이고, 「＊「…」·「ジャミ「…」 처럼 말하는 사람 이름 앞에 붙음. 롬에서 `BRK 19 32` 는 `04:9DA2`(창 루틴)와 `24:8898`(`F9` 처리기) 둘 |
| `33` | 명령 창 열기·고르기(A) |
| `34` | 창 닫기(B) |
| `37` | 공격이 맞을 때 |
| `17` | 전투 시작(전투 곡) |

## DSP 로 본 반응

MesenCE Lua 에는 오디오 녹음 함수가 없어(`emu.memType` 에 `spcDspRegisters`·`spcRam` 만 있음), 프레임마다 DSP 레지스터(주 음량 `$0C`·`$1C`, 메아리 `$2C`·`$3C`, 8채널 ENVX 합, KON `$4C`·KOF `$5C`, FLG `$6C`, 채널 0 음량 `$00`·`$01`)를 적어 명령과 견줬습니다(`dq5sndlog.lua` 의 `DSP=1`).

- 전투 승리(1564 `1A A0`·`01 1F`): 채널 0 음량이 `10` → `00` 으로 30프레임에 걸쳐 줄고(1564~1594), ENVX 가 0 이 된 뒤 1602 에 다른 음량으로 새 곡이 울렸습니다.
- 전투 시작(500 `1A 01`, 501 `0C 17`): 필드 곡이 줄어 502 에 끊기고, 508 에 KON 과 함께 전투 곡이 시작했습니다.
- 선실 → 필드(444 `1A 02`·`01 02`): 452 에 KON, 메아리 음량이 `00` → `14` 로 바뀌었습니다.
주 음량은 내내 `5C` 였습니다. 곡 이름은 아래 「곡 이름」 에서 공식 음반 곡명과 장면으로 짝지었고, 효과음 이름은 정하지 않았습니다.

## 명령을 바꿔 보내 보기

장면마다 부르는 곳을 찾아가는 대신, 필드(세계 0, 곡 `02`)에서 A 로 메뉴를 열 때 나가는 `0C 33` 을 `24:FF83` 에 들어오는 순간 다른 명령·인자·X 로 바꿔 보냈습니다(`dq5sndlog.lua` 의 `HCMD`·`HARG`·`HX`). 604 프레임에 보내고 DSP 를 기록했습니다.

| 명령 인자 X | 채널 0 음량(604 → ) |
| --- | --- |
| `04 02 10` | `11,16` 에서 줄기 시작해 774 에 `00` |
| `04 02 20` | 691 에 `00` |
| `04 02 40` | 649 에 `00` |
| `04 05 20` | 그대로(`12,17`) |
| `03 02 10` | 608 에 `00` 으로 떨어진 뒤 776 에 `12,17` |
| `03 02 20` | 696 에 `12,17` |
| `03 02 40` | 656 에 `12,17` |
| `03 05 20` | 곡이 끊기고 메아리 음량 `00`·FLG `35`(메아리 쓰기 끔), 채널 0 이 `0D,06` 까지 올라 다른 소리가 남. `01 05` 를 보냈을 때와 KON 이 같은 프레임(664)에 남 |
| `02 02` | 608 에 모든 채널 ENVX 합 `0`, 음량 `00` |
| `02 05` | 그대로 |
| `0D`·`0E`·`94`·`95`·`96`(인자 `00`·`01`·`02`·`80`), `8B 00`·`93 00`·`09 1F` | 주 음량·메아리·FLG·채널 0 음량·ENVX 가 바꾸지 않은 기록과 같음 |

X 가 두 배면 걸리는 시간이 반쯤으로 줄어, 줄이기·키우기 모두 약 2800/X(십진) 프레임입니다. `03 02`·`04 02` 사이 KON 이 난 프레임은 서로 같아 곡은 이어서 흐릅니다.
DSP 로 안 보이는 명령도 SPC RAM 은 바꿉니다(`SPCDUMP` 로 640 프레임을 `0D` 와 견줌, 메아리 버퍼 `D700`~ 은 뺌): `8B 00` 은 `053C`·`0544`… 8바이트 간격 6칸을 `10` → `30`, `93 00` 과 `94 00` 은 `05DA`·`05E0`… 6바이트 간격을 `10` → `30` 으로 바꿨고, `95`·`96`·`09` 는 `00F4`·`018E`·`0196`~ 몇 바이트만 바뀌었습니다. 그 칸은 아래 「SPC 드라이버」의 샘플 칸 표(`0535`~, 8바이트)와 시퀀스 칸 표(`05D5`~, 6바이트)의 플래그 바이트이고, `30` 은 고정 비트 `10` 에 참조 수 1(`20`)이 더해진 값입니다. `0D` 와 `0E` 의 SPC RAM 은 같았습니다.

## SPC 로 가는 명령

대기열의 명령은 2B 뱅크가 `명령 & 3F` 로 표 `2B:C43B` 의 처리 루틴을 골라 SPC 명령으로 바꿉니다(`2B:BF0D`). 명령을 바꿔 보내며 APU 포트 `$2140`~`$2143` 에 쓰인 값을 모두 기록했습니다(work 의 쓰기 콜백).

| 대기열 명령 | APU 로 간 것 | 뜻 |
| --- | --- | --- |
| `1A 05`·`1A 00`·`1A FF` | `04 02 7E`, `15`, `09 02` 을 대답이 `7F` 일 때까지 되풀이, `16`, `0A` | 세 인자 모두 같은 바이트가 나감. 지금 곡(`$1D8B` = `02`)을 X `7E` 로 빨리 줄이고, 대기열의 `01`·`03`·`0C` 를 지우고(`2B:C118`), 곡이 멈출 때까지 기다린 뒤 참조 수를 비우고 쓰지 않는 자료를 버림. `$1D8B` 는 `FF` |
| `8B 00` | `0B 00`·`0B 05`·`0B 1F`·`0B 22`·`0B 20`·`0B 21` | 목록 `2B:C422` 의 샘플을 고정 |
| `93 00` | `13 00`·`13 17`·`13 1D`·`13 21`·`13 32`~`13 3D`·`13 46` | 목록 `2B:C429` 의 시퀀스를 고정 |
| `94 00` | `10 00` | 곡 n 자료 올리기(`2B:C1C8`: 시퀀스 n 을 `10` 으로, 곡 묶음 n 의 샘플을 `00` 으로). 곡 묶음 0 은 샘플이 없음 |
| `95 00`·`96 00` | `15 00`·`16 00` | |
| `09 1F` | `09 1F` | |
| `0D 02`·`0E 02` | 없음 | |

SPC 쪽은 `$F4`(`$2140`) bit0 이 바뀌면 `$F5` 를 명령으로 읽고(`0F6D`), `17` 보다 작으면 표 `09EB` 로 갑니다(`0A19`). 드라이버는 직접 페이지 1 을 씁니다(`SETP`, `$8A` = `$018A`). 처리 루틴은 SPC RAM 덤프를 [spc700.py](../tools/spc700.py) 로 풀어 읽었습니다(코드 읽기).

| SPC 명령 | 처리 | 하는 일 |
| --- | --- | --- |
| `00`·`0B` | `0A26`·`0C2E`(= `0A26`) | 샘플 n(인자) 의 칸을 `03FF+n` 에서 찾아, 있으면 플래그 bit7~5(참조 수)에 `20` 을 더함(`E0` 이 끝). `0B` 는 bit4(고정)도 켬. 없으면 2B 가 이어서 자료를 보냄 |
| `10`·`13` | `0CA7`·`0D43` | 시퀀스 n 으로 같은 일(`04C7+n`, 칸 표 `05D5`). `13` 은 고정 |
| `09` | `0C08` | 8개 곡 자리(`03B7` 켜짐, `03AF` 곡 번호)에서 곡 n 을 찾아 `$F5`(`$2141`)로 `03DF+자리` 를, 없으면 `7F` 를 돌려줌. 2B 는 `2B:C0F8` 에서 이 값을 읽음 |
| `0A` | `0C24` | 참조 수가 0 인 샘플(`255D`)과 시퀀스(`27BA`)를 버리고 자리를 모음 |
| `15` | `0D8E` | `052B`~`0534` 를 `FF` 로 채우고 받던 전송 상태(`$8A`)를 정리 |

| `02`·`03`·`04` | `0B25`·`0B34`·`0B95` | 곡 멈추기·키우기·줄이기(위 「명령을 바꿔 보내 보기」의 실측) |

## 곡 자료

곡 번호 n 은 시퀀스 번호입니다. `01 n`·`03 n`·`0C n` 을 보내면 2B 뱅크가 시퀀스 n 과 곡 묶음 n 의 샘플이 SPC 에 있는지 보고, 없는 것을 보냅니다(`2B:BF98` → `2B:C1C8`). 시퀀스는 SPC 명령 `90`(`10` 에 bit7 = 자료가 따라옴), 샘플은 `80` 으로 보내고, 자료는 `2B:C25F` 가 `[$FB]` 에서 3바이트씩 `$2141`~`$2143` 으로 넘깁니다.

| 표 | 롬 | 형식 |
| --- | --- | --- |
| 샘플 0x26개 | `2B:EB00`~(`2B:C391`) | `[길이 2][반복 위치 2][ADSR1][ADSR2][GAIN][음높이 2][BRR]` 을 이어 붙임. 뱅크를 넘어도 파일 오프셋으로 이어짐 |
| 시퀀스 0x47개 | `2E:E2E4`~(`2B:C39E`) | `[길이 2][자료]` 를 이어 붙임 |
| 곡 묶음 | `2B:E67F`(`2B:C3CB`) | 곡마다 `[샘플 수 L][한 바이트][샘플 번호 L개]`. 곡 `02` = `03 02 03 00 04`(샘플 `03`·`00`·`04`) |

곡 묶음의 둘째 바이트 k 는 샘플을 「곡 앞」 k개와 「곡 뒤」 L - k 개로 나눕니다. 명령 `01 n` 의 처리기 `2B:BF2B` 는 SPC 에 명령을 보내고 `$2140` 의 대답을 `$08D8` 에 받습니다(`2B:C373`).

- 대답 bit6 이 꺼져 있으면(시퀀스가 SPC 에 없음) 대기열 칸에 bit7 을 켜고, 다음 차례에 `2B:BF9D` → `2B:C1AE` 가 시퀀스와 「곡 앞」 샘플을 보낸 뒤 곡을 틉니다. 대답 bit6 이 켜지면 칸에 bit6 도 켜고 `2B:BFA3` → `2B:C1BA` 가 「곡 뒤」 샘플을 하나씩 보냅니다(곡이 울리는 동안).
- 대답 bit6 이 처음부터 켜져 있으면(시퀀스가 이미 SPC 에 있음) `2B:C1AE` 를 건너뛰고 바로 `2B:C1BA` 로 갑니다. 「곡 앞」 샘플은 보내지 않습니다.
- `2B:C20F` 는 샘플을 하나 보낼 때마다 지금 대기열 칸(스택의 칸 번호로 `$1D95+X`)이 `FF`(명령이 끝나거나 지워짐)인지 보고 그렇다면 보내기를 그만두는 검사입니다.

실측(`EXEC` 기록, 대기열에 `1A 00` 뒤 `01 n`): 곡 `15` 는 대답이 `80` 이라 `2B:BF6F`·`BF84` → `2B:C1AE`(샘플을 30~106 프레임에 보냄) → 대답 `40` 에 `2B:BF57`~`BF6B` → `2B:C1BA` 였습니다. 고정 시퀀스(`2B:C429`, 켤 때 `93` 으로 올림)인 곡 `17` 은 처음 대답이 이미 `C0` 이라 `2B:BF57`~`BF6B` → `2B:C1BA` 로만 갔고, 곡 묶음 그대로(k = 2)면 「곡 뒤」 여섯을 14·103·210·228·278·292 프레임에 보내 300 프레임 뒤 SPC 색인 `03FF` 에 여덟 샘플이 모두 있었습니다.
`dq5spcfile.py` 의 `FULLSET` 은 둘째 바이트를 샘플 수로 바꿔 모든 샘플을 「곡 앞」 에 넣습니다. 고정 시퀀스 곡은 그 묶음을 보내는 `2B:C1AE` 를 지나지 않으므로, `FULLSET` 아래에서 `01 17` 은 「곡 뒤」 0개만 보내 상주 샘플 `00`·`05` 만 남았습니다. 「`2B:C20F` 가 대기열 칸을 `FF` 로 보아 건너뜀」 이 아니라 `2B:C1AE` 를 아예 타지 않는 것입니다. `94 17` 을 먼저 보내면 곡 자료 올리기가 모든 샘플을 보내므로 같은 결과를 냅니다.

SPC RAM 쪽은 이렇습니다.

| 주소 | 내용 |
| --- | --- |
| `0535`~ | 샘플 칸 0x14개 x 8바이트: `[BRR 길이 2][ADSR1][ADSR2][GAIN][음높이 2][플래그]`. 플래그 bit7~5 참조 수, bit4 고정 |
| `05D5`~ | 시퀀스 칸 0x14개 x 6바이트: `[FF][주소 2][길이 2][플래그]` |
| `03FF+n`·`04C7+n` | 샘플 n·시퀀스 n 이 든 칸(`FF` 면 없음) |
| `0700`~ | DSP 샘플 목록(DIR = `07`). 칸마다 `[시작 2][반복 2]` |
| `D700`~ | 메아리 버퍼(ESA = `D7`) |

실측: 필드(550 프레임)와 마법 융단을 편 뒤(1180 프레임)의 SPC RAM 덤프에서, 칸 표에 오른 시퀀스·샘플 26개·30개가 롬 자료와 바이트까지 같았습니다(`dq5spc.py --check`). 샘플은 DIR 의 시작 주소에 BRR 이 있고, 반복 주소 - 시작 주소가 머리 2바이트(반복 위치)와 같았습니다. 연주 중인 채널의 ADSR·GAIN 은 `FF E0`·`B8` 로 머리 값과 같았습니다(곡이 바꾼 `FA` 도 있음).
곡 묶음의 둘째 바이트 k 는 곡을 틀기 전에 보내는 샘플 수입니다. `2B:C1C8` 이 앞 k 개를, 곡이 시작한 뒤 `2B:C1DB` 가 나머지 L - k 개를 보냅니다(`2B:C3F2`). 곡 `02`(`03 02 03 00 04`)는 `03`·`00` 뒤에 `04` 를, 곡 `03`(L 8, k 4)은 `00`·`03`·`05`·`06` 뒤에 `07`~`0A` 를 보낸 것이 전송 기록과 같았습니다.

장면에서 본 전송(`2B:C25F` 를 지날 때의 `$FB` 와 길이):

| 장면 | 명령 | 보낸 것 |
| --- | --- | --- |
| 선실 → 필드 | `1A 02`·`01 02` | 시퀀스 `02`(`2E:E7A6`, `01F7`), 샘플 `03`·`04`(`00` 은 이미 있음) |
| 마법 융단 펴기 | `1A 00`·`01 03` | 시퀀스 `03`, 샘플 `03`·`06`~`0A`(`00`·`05` 는 고정) |
| 배에 오르기 | `1A 04`·`0C 04` | 시퀀스 `04`, 샘플 `08`·`07`·`0A`·`09`·`0B` |
| 天空城 | `01 0D` | 시퀀스 `0D`, 샘플 `03`(다음 `02` 는 기록이 끝남) |
| 드래곤에서 내리기 | `1A 01`·`01 02` | 시퀀스 `02`, 샘플 `03`·`04` |

`1A` 를 보낸 프레임에는 아무것도 전송되지 않고, 전송은 늘 `01`·`0C` 뒤에 있었습니다. 곧 `1A` 의 인자(`04`·`00`·`FF`·`01`)가 곡 번호와 달랐던 것은 쓰이지 않는 값이기 때문입니다.

## 시퀀스 형식

시퀀스(곡과 효과음 모두)는 `[템포][트랙 수 N][트랙 오프셋 2바이트 x N]` 머리 뒤에 트랙 바이트가 옵니다. 오프셋은 시퀀스 첫 바이트 기준입니다(`11CA`). 트랙 하나가 DSP 목소리 하나를 씁니다. 곡을 틀면 트랙마다 길이 `CC` 비율·음량 `60`·`80`·가운데 팬으로 시작합니다(`1273`~`12AE`).

트랙 바이트는 틱마다 기다림이 0 이 된 트랙에서 `154E` 가 읽습니다. 명령은 시간을 쓰지 않고, 음표 하나를 읽으면 그 길이만큼 쉽니다.

| 바이트 | 뜻 |
| --- | --- |
| `00`~`4F` | 음표, 앞 길이 그대로. `00` = 쉼, `4F` = 붙임(음을 바꾸지 않음), 나머지 n 은 음 n + 조옮김. 음표와 붙임 모두 KON 을 내되, 앞 음의 소리 길이 비율이 `00`(끝까지 끌기)이면 KON 없이 이어짐(아래) |
| `50`~`9F` | 음표 n = 바이트 - `50` 에 새 길이(다음 바이트, 틱) |
| `A0`~`B5` | 소리 길이 비율(게이트)을 표 `17CD` 의 값으로: `0D 1A 26 33 40 4D 5A 66 73 80 8C 99 A6 B3 BF CC D9 E6 F2 FE FF 00` |
| `B6`~`DA` | 아무것도 안 함(`15CC`). 실제로 쓰인 것은 `D0` 뿐 |
| `DB`~`FE` | 명령(아래 표, 처리 루틴 표 `0795`) |
| `FF` | 트랙 끝 |

KON: 음표를 읽으면 `1593` 이 기다림 `15`(소리 끄기까지 남은 틱)가 `FF` 가 아닐 때만 `1A58`(KON)을 부릅니다. `15` 는 앞 음을 읽을 때 비율 `0204` 가 `00` 이면 `FF`(끄지 않음), `FE` 면 길이 - 1, 나머지는 길이 x 비율 / 256 이 됩니다(`15A1`). 그래서 비율 `00`(`B5` 또는 `EC 00`) 뒤의 음표·붙임은 KON 없이 음높이만 바꾸는 레가토가 되고, 그 밖에는 붙임도 다시 칩니다. 실측: 곡 `0A` 트랙 0 은 비율 `00` 의 음 `35` 뒤 붙임에서 KON 이 없었고(643 → 723), 만든 시퀀스의 비율 `FF` 음 뒤 붙임은 990 프레임에 KON 을 냈습니다.

음 n 은 n - 1 = 옥타브 x 12 + 반음으로 나눠 표 `07E5` 의 피치에 옥타브를 곱합니다(`1B73`). 잡음을 켠 트랙(`E3`)은 음 번호 하위 5비트를 FLG 의 잡음 주파수로 씁니다(`1B46`).

| --- | --- | --- |
| `DB` | 오프셋 2 | 되풀이 카운터 1(`022B`)이 0 이 아니면 점프 = 첫 바퀴에만 건너뜀(`18F3`) |
| `DC` | 오프셋 2 | 카운터 1 로 두 바퀴 되풀이: 0 이면 2 로 두고 1 을 빼 0 이 아니면 점프(`18F8`) |

틱: 곡 자리마다 `03BF` 에 템포를 더해 넘치면(또는 `FB` 이상이면) 한 틱입니다(`146C`). 실측한 다섯 곡에서 틱당 프레임 x 템포가 모두 약 75 였습니다(`02` 0.6635 x `71`, `03` 0.653 x `73`, `04` 0.833 x `5A`, `0D` 1.070 x `46`). 곧 1초에 약 0.8 x 템포 틱입니다.

`dq5song.py --check` 는 시퀀스 0x47개의 모든 트랙을 흐름(점프·되풀이 두 갈래·부르기)대로 끝까지 풉니다. 모르는 바이트와 범위 밖 점프가 0 이고, 닿지 않는 바이트는 시퀀스 `37`·`39`·`41`·`45` 의 끝 1~2바이트(점프 뒤의 `FF` 등)뿐입니다.

### 실측: 디코더 음표와 KON

`lua/dq5dspw.lua` 로 SPC 가 DSP 에 쓴 KON·피치·FLG 를 프레임마다 적고, `dq5song.py N --kon dspw.txt --start F` 로 트랙 i 를 목소리 i 로 보고 음표 12개씩 견줬습니다. 시각은 첫 음과 틱당 프레임으로, 음은 악기가 같은 이웃 음끼리 반음 차이(피치 비의 log2 x 12)로 봤습니다.

| 곡 | 장면 | 트랙 | 최대 시각 차(프레임) | 음 차이 틀림 |
| --- | --- | --- | --- | --- |
| `02` | 필드 | 5 | 1.9 | 0 |
| `03` | 마법 융단 | 7 | 2.6 | 0 |
| `04` | 배(`0C 04 01`, `--flag 1`) | 7 | 1.9 | 0 |
| `0D` | 天空城 | 7 | 1.7 | 0 |
| `17` | 전투 | 6 | 3.5 | 0 |

배 곡은 곡 변수 0 으로 풀면 트랙 0·1·3~6 의 음이 틀렸고, 0C 의 X(`01`)가 고른 스크립트 `01`(`05 01`)대로 변수를 1 로 두자 모두 맞았습니다. 선실의 맵 곡도 같은 시퀀스 `04` 를 `01 04`(변수 0)로 틉니다.

## 효과음과 스크립트

효과음도 같은 형식의 시퀀스입니다(`32`~`46` 대부분 트랙 1개, 고정 목록 `2B:C429`). 목소리 7 에서 울렸습니다(KON `80`). 명령 `0C n X` 는 시퀀스 n 을 튼 뒤 X 가 `21` 보다 작으면 스크립트 X 를 돌립니다(`0C82` → `204B`). 효과음은 첫머리의 `E0` 들로 X 에 따라 다른 소리로 갈라집니다(`37` 은 21갈래, `34` 는 6갈래).

스크립트는 SPC RAM 표 `0801`(2바이트 x 0x21)이 가리키는 바이트열이고, 명령 `05 s n` 도 같은 것을 돌립니다(`0BBB`, `$F6` = 시퀀스 s, `$F7` = 스크립트 n). `05` 는 시퀀스 s 가 오른 곡 자리마다 한 번씩 돌리고(`1FC0`·`1FD9`), s 가 어느 자리에도 없으면 자리 번호 `FF` 로 돌려 자리를 쓰는 연산(`00`~`0F`, `20`~`BF`)은 건너뜁니다. `0C n X` 는 방금 튼 자리(`03F8`)에서 돌립니다. 대기열 명령 `05` 도 인자를 s, X 레지스터를 n 으로 보냅니다. 필드 곡 `02` 를 트는 중에 메뉴 효과음 `0C 33` 을 `05 02` X `00` 으로 바꿔 보내고, 그 앞 프레임에 스크립트 `00` 자리(`0843`)를 시험할 바이트로 덮어(`dq5sscript.lua`) DSP 와 드라이버 변수를 프레임마다 읽었습니다(604 프레임에 보내 608 프레임에 반영).

## 인코더와 바꿔 넣기

`dq5song.py rom N` 은 시퀀스를 다시 쌀 수 있는 글로 냅니다. 머리 줄(`tempo XX`, `track L…`)은 들여 쓰지 않고, 본문은 처음부터 끝까지 차례로 들여 써서 풉니다. 점프 대상과 트랙 시작에는 이름(`LXXXX:`)을 붙이고 점프는 `-> 이름` 으로 적습니다. 흐름으로 닿지 않는 바이트는 `db XX` 입니다. 이름은 아무 글자나 써도 되고(`L` 로 시작), 싸는 쪽(`assemble`)이 두 번 훑어 오프셋을 다시 셉니다.

```
tempo 73
track L0
L0:
  instrument 00
  gate_preset CC
L0LOOP:
  note 31 len 18
  note 33
  ...
  jump -> L0LOOP
```

`--check` 는 0x47개를 모두 글로 풀었다가 다시 싸서 원래 바이트와 같은지도 봅니다(모두 같음). `--encode 글 -o 패치.json` 은 시퀀스 N 자리에 넣는 `dq5patch/1` 을 냅니다([dq5-build-format.md](dq5-build-format.md)).

실측: 마법 융단 곡 `03`(1703바이트)을 두 트랙짜리 음계(42바이트)로 바꿔 `dq5build.py build` 로 롬을 만들었습니다. 융단을 펴자 `01 03` 뒤 목소리 0 이 반음 0·2·4·5·7·9·11·12, 목소리 1 이 0·5·7·12 로 울렸습니다. `dq5song.py 03 --seqfile 글 --kon` 으로 견주니 두 트랙 모두 음표 16개의 시각 차 1.7프레임 이하, 음 틀림 0 이었습니다.

| `70:8010` | 고리. `$FB`·`$FD` 가 시퀀스 묶음(`2E:E2E4`)이면 시퀀스 표, 샘플 묶음(`2B:EB00`)이면 샘플 표에서 번호 x 3 의 포인터를 읽어 `$FB`·`$FD` 에 두고 돌아감. 포인터가 0 이거나 다른 묶음이면 원래처럼 길이로 걸음 |

`--sample ID=파일` 은 샘플을 번호 ID 로 더하고, `--set N=바이트` 는 곡 묶음 레코드 N 을 같은 길이로 덮습니다. 원래 번호(`00`~`25`)를 주면 그 샘플을 바꾸고, `26` 부터는 새 번호입니다.

실측:

- 긴 시퀀스: 곡 `03` 자리에 2101바이트(원래 1703)짜리 음계를 `--reloc` 으로 넣었습니다. 융단을 펴자 SPC 시퀀스 칸의 길이가 `0835`(2101)였고, 두 트랙 음표 40·20개의 시각 차 1.2프레임 이하, 음 틀림 0 이었습니다.
- 새 샘플: `dq5brrenc.py --wave square --period 32 --cycles 4` 로 만든 사각파(BRR 8블록)를 샘플 `26` 으로 더했습니다. 곡 `03` 의 레코드를 `08 04 26 03 05 06 07 08 09 0A`(첫 샘플 `00` → `26`)로 바꾸고 `instrument 00` 으로 음계를 울렸습니다. SPC RAM 의 DIR 칸 6 이 그 BRR 과 바이트까지 같았고, 반복 주소 - 시작 주소가 머리의 반복 위치와 같았습니다. 목소리 0·1 의 SRCN 이 `06` 으로 쓰였고, 음표의 시각 차 2.3프레임 이하, 음 틀림 0 이었습니다.
- 곡 묶음 표는 전원을 켤 때 드라이버 이미지와 함께 SPC `28EC` 에 올라갑니다. 고친 롬을 켜서 400프레임에 읽은 SPC `28FA` 가 `26` 이었고, 원래 롬은 `00` 이었습니다. 그래서 세이브스테이트(SPC RAM 이 이미 올라간 상태)로 시험할 때는 SPC `28FA` 도 `26` 으로 써 넣어야 SRCN 이 바뀌었습니다(넣지 않으면 샘플은 올라가도 SRCN `00`).

## 악기 만들기

[sfc/dq5/tools/dq5brrenc.py](../tools/dq5brrenc.py) 는 파형(사각·삼각·톱니·사인)이나 16비트 모노 WAV 를 BRR 로 싸서 샘플 자료를 냅니다. 블록마다 필터 0~3 과 범위 0~12 를 모두 시험해 복호 오차가 가장 작은 것을 고르고, 첫 블록과 반복 시작 블록은 필터 0 으로 둡니다. `--check` 로 롬 샘플 0x26개를 풀었다 다시 싸면 SNR 이 25.6~108.9 dB 였습니다(짧은 반복 샘플 `1E`~`22` 가 낮음). 복호기는 가우스 보간을 하지 않고 15비트로 자르는 단순한 꼴이라, 진폭을 그 안에 두어야 DSP 와 같아집니다.

FC 소리에 가까운 롬 샘플(`--nearest`: 반복 부분 전체를 한 창으로 DFT 해 기본음과 배음 8개를 이상적인 파형과 견줌):

| 파형 | 가까운 샘플 | 배음 2~8(기본음 = 1) |
| --- | --- | --- |
| 사각파(FC 펄스 50%) | `1F`(반복 32샘플, 고정 목록) | 0.00 0.37 0.00 0.27 0.00 0.17 0.00 |
| 사각에 가까움 | `0E`, `06` | `0E` 0.16 0.35 0.09 0.02 … |
| 삼각파 | `09`, `05`, `21`, `0F` | `09` 0.03 0.09 0.04 0.03 … |
| 사인 | `17`, `18`, `1E` | 거의 0 |
| 잡음 | 샘플이 아니라 DSP 잡음(`E3`, FLG 주파수) | |

FC 의 펄스 12.5%·25% 와 FC 삼각파의 계단 꼴은 롬에 같은 것이 없습니다. 필요하면 `dq5brrenc.py` 로 한 주기 32샘플짜리를 만들어 넣으면 됩니다(사각파 32샘플 4주기가 BRR 72바이트).

## 전투 곡

`26:8F5B` 가 무리 번호 A 로 곡을 고릅니다. 무리가 `40` 보다 작으면(이벤트 전투) `23:D757 + 무리*13` 의 첫 바이트 하위 2비트를 `$1014` 에 두고, 아니면(마주침 전투) 0 으로 둡니다. 곡은 표 `26:8F96[$1014]` = `17`·`16`·`18` 입니다([dq5-data-format.md 「이벤트 전투 무리」](dq5-data-format.md)). 이어 `00:833C` 가 참(실내 `$BE` bit7 이고 `$194A & 7F` = 4(마주치는 동굴), 또는 맵 21/01~04)이면 X 를 1 로 두고 `0C 곡 X` 를 보냅니다.

| 장면 | 명령 | 실측 |
| --- | --- | --- |
| 마주침·보통 이벤트 전투 | `1A 무리`·`0C 17 00` | 필드 スライム(무리 `00`) |
| 보스(등급 1) | `0C 16` | 무리 `20` |
| 마지막 보스(등급 2) | `0C 18` | 무리 `2C`(エスターク)·`2F`(ミルドラース) |
| 승리 | `1A A0`·`01 1F`(`20:80DF`) | 위 「DSP 로 본 반응」 |
| 전멸 | `1A`(`20:8149`)·`01 0B`(`BRK 11 0B`) | エスターク 에게 기절하자 1170 프레임 |
| 도망 | 곡 명령 없음. 필드로 돌아가며 맵 곡 `1A 02`·`01 02` | 「ああああは にげだした！」 뒤 1785 프레임 |

`1A` 의 인자 자리에는 무리 번호가 들어가지만 쓰이지 않습니다(위 「SPC 로 가는 명령」).

동굴 갈래: 세 전투 곡 모두 첫 트랙 머리가 `fe 19 / if_flag 01 / fe 16` 이라, 곡 변수가 1 이면 스크립트 `16` 을 건너뛰고 `19` 의 소리 설정이 남습니다. 메뉴 효과음을 `0C 17 X` 로 바꿔 보내 400프레임 뒤 DSP 를 읽었습니다.

| X | 주 음량 | 메아리 음량 왼·오 | 메아리 되먹임 |
| --- | --- | --- | --- |
| `00` | `5C` | `14`·`EC`(오른쪽 위상 뒤집힘) | `0C` |
| `01` | `4D` | `40`·`40` | `00` |

동굴 안에서 실제로 마주친 전투: `00:833C` 가 따로 보는 맵 21/02 (50,43) 에서 좌우로 걸어 마주친 전투(998 프레임)가 `1A FF`·`0C 17 01` 이었습니다. 맵 곡 `09` 가 이미 주 음량 `4D`·메아리 `40`/`40` 이라 전투 곡이 시작된 뒤에도 DSP 값이 그대로였습니다(`DSP=1`, 990·1400·1800 프레임). 앞서 03/02 에서 마주치지 않은 것은 그 맵의 구역에 조우가 없어서로 보입니다.

이벤트 무리 64개 가운데 등급이 0 이 아닌 것은 15개입니다(`dq5sound.py --battle`). 나머지 49개와 마주침 무리는 모두 곡 `17` 입니다.

| 등급 | 곡 | 무리(몬스터) |
| --- | --- | --- |
| 1 | `16` | `04` おやぶんゴースト, `06` ゆきのじょおう, `09`·`0A` ジャミ·ゴンズ, `12` ニセたいこう, `15` ようがんげんじん 셋, `1E` ジャミ, `1F` ゴンズ, `20` ゲマ, `22` ラマダ, `25` イブール, `26` ブオーン, `2B` ミルドラース(첫 모습) |
| 2 | `18` | `2C` エスターク, `2F` ミルドラース(둘째 모습) |

`08` ゲマ(어린 시절 지는 싸움)는 등급 0 이라 보통 전투 곡입니다(코드 읽기, 표 값).

## 효과음 쓰임

효과음은 다섯 길로 나옵니다. 코드의 `BRK 16 n X`·`BRK 19 n X`(`00:9256`), `24:FEAC` 를 바로 부르는 `JSL`, 인물 인라인 명령 `20 n X`([dq5-map-format.md](dq5-map-format.md)), 전투 메시지 코드 `F9`(`0C 32`), 전투 연출의 효과음 표(아래)입니다. [sfc/dq5/tools/dq5sfx.py](../tools/dq5sfx.py) 가 다섯 길을 모두 모아 효과음·갈래마다 부르는 곳을 찍습니다. 코드 쪽은 롬 전체에서 `00 16 n X`·`00 19 n X`(n = `32`~`46`, X ≤ `20`)와 `LDA #n [LDX #x] JSL 24:FEAC` 를 바이트 꼴로 찾으므로 데이터 속 우연한 바이트도 섞입니다(274곳). 뱅크로는 `20`(전투), `03`, `02`, `22`, `05`, `01`, `06`, `00` 순입니다. `dq5sndlog.lua` 는 소리 서비스 `BRK` 로 온 명령에 `brk=BRK 자리 X=둘째 인자` 를, `24:FEAC` 를 바로 부른 명령 `0C` 에는 그때의 X 레지스터(갈래)를 붙입니다.

137갈래 가운데 122갈래는 다섯 길 중 하나 이상에서 부르는 곳이 있고, 15갈래(`32-01` `36-04` `37-06` `37-0F` `37-12` `39-08` `39-11` `3C-01` `41-01` `41-03` `41-06` `44-00` `44-05` `44-08` `45-00`)는 롬에서 부르는 곳을 찾지 못했습니다. `24:FEAC` 를 바로 부르는 곳 7곳 가운데 X 를 레지스터로 넘기는 것은 `00:9451`(`LDA #01 / TAX` 로 `33-01`), `01:CE7C`(인물 명령 `20`), `20:8FCC`·`26:8F91`(전투 곡 갈래 0·1), `28:804E`(연출 표)뿐이라, 이 15갈래는 지금 롬에서 쓰이지 않습니다. 간접 호출까지 이렇게 전수로 보았습니다.

1. 명령 `0C` 를 대기열에 넣는 입구는 `24:FEAC` 하나입니다. `JMP 24:FF83` 으로 끝나는 입구는 19개이고(`24:FE7F` = `19`, `24:FE88` = `1B`, `24:FF71` = `08` 등 다른 명령), `24:FF83` 을 `JSL`·`JML` 이나 3바이트 포인터로 부르는 곳은 롬에 없습니다. 대기열의 X 칸(`7E:1DB5`)에 쓰는 코드도 `24:FF83` 안의 `24:FFD6` 하나입니다.
2. `24:FEAC` 를 가리키는 3바이트(`AC FE 24`)는 롬 전체에 7곳이고, 모두 위의 `JSL` 자리입니다. 포인터 표에 들어 있는 것은 없습니다.
3. `BRK 16 n X`·`BRK 19 n X` 꼴의 바이트(`00 16 n X`·`00 19 n X`)는 15갈래 모두 롬 어디에도 없습니다(데이터 속 우연한 바이트도 0).
4. 레지스터 X 자리의 값: `00:9451` 은 `01` 고정, `01:CE7C` 는 인물 인라인 명령 `20` 의 인자(목록 1,077명·스크립트 전부를 `dq5sfx.py` 가 훑음), `20:8FCC`·`26:8F91` 은 곡 `16`~`18`, `28:804E` 는 효과음 표 `28:811E`·`28:816E` 의 칸 전부(`dq5sfx.py --fx`).
5. `[n][X]` 두 바이트가 나란히 놓인 자리는 갈래마다 11~20곳 있지만, 위 1~4 의 어느 길로도 읽히지 않는 데이터입니다. `42-19` 는 갈래가 아닌 값이라 `03:AD9A` 의 바이트는 데이터입니다.

### 전투 연출의 효과음 (`28:8000`)

## 맵 곡 (`23:FD6A`)

실내 맵 레코드 `23:FD6A[BC] + BD*6`(6바이트, [dq5-data-format.md 「전투 조우」](dq5-data-format.md))의 `+5` 가 곡 번호입니다. 맵을 불러올 때 `00:CEB1` 이 이 값을 `$194B` 에 두고 명령 `1A` 로 보내고(지금 올린 곡과 다를 때만), 이어서 `00:CEA2` 가 같은 인자로 명령 `01` 을 보냅니다. 필드는 세계 0 이 `02`, 세계 1 이 `05`, 세계 2 가 `0E` 였습니다(`$1949` 를 매 프레임 고정하고 필드에 나가 기록). 탈것의 곡은 아래 「탈것」에 있습니다.
`dq5sound.py` 가 346개 맵의 곡을 뽑습니다. 가장 많은 것은 `09`(106개), `0A`(80), `06`(60), `01`(38), `0C`(20) 입니다. 곡 이름은 소리를 듣지 않아 정하지 않았습니다.

실측: 346곳 모두에 장면 이동 도구(`TO`)로 들어가 `00:CEA2` 의 `01` 인자를 기록했고, 모두 표와 같았습니다(`dq5mapmusic.py`). 들어갈 칸은 모든 맵의 출구 도착 칸(`dq5exit.py`, 250곳)에서, 없는 맵은 통행 격자(`attrgrid.py`)의 가운데에 가장 가까운 `o` 칸에서 골랐습니다. `o` 칸이 없는 `03/09`·`06/07`·`2B/02`·`32/04` 는 `.` 칸에 층 2 로 섰습니다. `17/00`(배)은 시작 세이브스테이트(17/01)와 같은 그룹이라 장면 이동 도구가 사다리 단계로 가서 「arrived」 없이 「end map 17/00」 만 찍지만, 맵은 불러와져 곡 `04` 가 나갔습니다. 시간을 밤(`$075E` = `0190`, 화면이 어둡고 여관 주인이 없음)으로 두고 250곳을 다시 들어가도 곡은 모두 낮과 같았습니다. 밤에 따로 바뀌는 맵 곡은 없습니다.

맵을 불러올 때 곡을 고르는 `00:CE6B` 는 표의 곡보다 먼저 다음을 봅니다.

| 조건 | 결과 | 실측 |
| --- | --- | --- |
| `7E:21A5` bit6(`BRK 0B 40 15`) | 곡 명령을 보내지 않아 앞 곡이 그대로 | `SET 21A5\|40` 으로 21/00 에 들어가자 `1A`·`01` 이 없음 |
| `7E:21DF` bit7(이벤트 명령 `C8 v` 가 v \| 80 을 둠) | 표 대신 `21DF & 7F` 의 곡 | `SET 21DF=8C` 로 21/00 에 들어가자 맵 곡 `06` 대신 `1A 0C`·`01 0C` |
| `7E:2190` bit7(`BRK 0B 80 00`, `$BE` bit7 이 꺼진 필드에서) | 곡 `03`(마법 융단 곡) | 코드 읽기(`00:CE84`) |
| `$1954` = `03`(배) | `0C 04 01`(배 곡, 곡 변수 1) | 코드 읽기(`00:CE8F`) |

이벤트 명령 `C9` 가 `21DF` 를 0 으로 돌리고 맵 곡으로 되돌립니다(`23:FE8F`). 그래서 이벤트 곡은 `C8` 로 켠 뒤 `C9` 까지 맵을 옮겨도 이어집니다.

## 추출: 샘플 WAV 와 SPC 파일

롬에서 나온 결과(WAV·SPC)는 커밋하지 않고 비공개 에셋 저장소의 `sfc/dq5/sound/` 에 둡니다.

### 악기 샘플(`dq5brr.py`)

샘플 0x26개의 BRR 을 S-DSP 와 같은 정수 계산(필터 1~3, 16비트로 자른 뒤 1비트 왼쪽 밀기)으로 풀어 16비트 모노 WAV 로 씁니다. 빠르기는 DSP 음높이 `$1000` 일 때의 32000Hz 이고, 끝 블록 머리의 반복 비트가 켜진 샘플은 머리의 반복 위치(바이트)를 표본 수(9바이트 = 16표본)로 바꿔 `smpl` 청크에 넣습니다. 반복이 없는 것은 `0A`·`0D`·`11`~`15`·`23` 의 8개입니다. 샘플마다 ADSR·GAIN·음높이는 `index.json` 에 적습니다.

확인: 곡 `02` 를 튼 직후의 SPC 상태에서 MesenCE 가 목소리마다 풀어 둔 BRR 표본 12개(`spc.dsp.voices[n].sampleBuffer`)와 견줬습니다. 목소리 7 은 같은 표본 12개가 디코더 결과에 그대로 있었습니다. 목소리 0~2 는 값이 100 안쪽으로 조금씩 달랐습니다(예: `-20906` 과 `-21002`). 키를 다시 누를 때 앞 소리의 이전 표본 둘이 남아 필터에 들어가기 때문으로 보입니다.

### SPC 파일(`dq5spcfile.py`, `lua/dq5spcdump.lua`)

곡·효과음마다 다음 순서로 .spc 를 만듭니다.

1. 배 선실 세이브스테이트를 불러, 10프레임에 소리 대기열(`7E:1D95`~)에 `1A 00` 을 넣습니다. 14프레임에는 곡이면 `01 n`, 효과음(`32`~)이면 `0C n 00` 을 넣습니다. 넣는 칸은 `24:FF83` 과 같은 셈으로 고릅니다.
2. 이 실행에서만 곡 묶음 n 의 둘째 바이트(곡 전에 보낼 샘플 수)를 샘플 수로 바꿉니다. 그러면 곡이 시작하기 전에 샘플이 모두 SPC 로 갑니다.
3. SPC 의 곡 자리(`03AF`·`03B7`)에 n 이 오르고 대기열이 빈 프레임을 기다립니다. 그 뒤 처음 시작되는 SPC700 명령의 실행 콜백에서 spcRam 64KB·DSP 레지스터 128바이트·SPC700 레지스터·입출력 포트·타이머를 잡습니다.
4. 표준 v0.30 형식(ID666 글자 꼴)으로 묶습니다. `$F0`~`$FF` 에는 잡은 레지스터 값을 넣습니다(`F1` = 타이머 켜짐·IPL, `F2`·`F3` = DSP 주소·값, `F4`~`F7` = CPU 가 쓴 포트, `FA`~`FC` = 타이머 목표).

곡 변수 갈래도 따로 만듭니다. 시퀀스 명령 `E0 [오프셋][값]` 은 곡 변수(명령 `0C n X` 의 스크립트 X 가 둠)가 값과 같으면 뜁니다. 흐름을 따라 닿는 `E0` 의 값은 늘 `01` 부터 이어지므로 갈래 수 = 가장 큰 값 + 1 입니다. 이렇게 센 효과음 21개의 갈래 수는 dq5-mongfx2 가 따로 센 표와 모두 같았습니다(`32`:2, `33`:3, `34`:6, `35`:3, `36`:5, `37`:21, `38`:19, `39`:18, `3A`:1, `3B`:3, `3C`:2, `3D`:6, `3E`:6, `3F`·`40`:1, `41`:8, `42`·`43`:1, `44`:15, `45`:2, `46`:13, 모두 137개).
곡은 `04`·`0F`·`15`·`16`·`17`·`18` 에 갈래 `01` 이 하나씩 있습니다(`04` 는 배에 탈 때 `0C 04 01`). 효과음은 갈래마다 `<번호>-<갈래>.spc`(갈래 `00` 부터)로 만듭니다. 곡은 `01 n` 으로 튼 `<번호>.spc` 와 `0C n 01` 로 튼 `<번호>-01.spc` 를 둡니다. 192개 모두 곡 자리에 올라 소리가 났고, 같은 번호의 갈래끼리 WAV 가 모두 달랐습니다.
`dq5soundpage.py` 는 에셋 갤러리에 들어 보기 페이지(`gallery/sound.html`)를 씁니다. 곡·효과음·샘플마다 재생기, 쓰이는 장면(게임에서 확인한 것과 맵 곡 표에서 나온 것), 길이, 악기(곡 묶음의 샘플), 그 곡을 쓰는 실내 맵(맵 레코드 `+5`)을 보이고, 들은 사람이 이름을 적어 JSON 으로 모을 수 있습니다.

`--wav` 를 주면 game-music-emu(libgme)로 WAV 도 굽습니다(32000Hz 스테레오, S-DSP 의 빠르기). 들어 보기용이라 곡은 30초(끝 4초 줄이기), 효과음은 4초입니다. 120초·44100Hz 로 구우면 곡 49개만 1GB 가 넘어 짧게 두었고, 끝까지 들을 때는 .spc 를 틉니다. `--wav-only` 는 이미 만든 .spc 로 WAV 만 다시 굽습니다.

- **명령 경계**: 처음에는 프레임 끝에서 바로 잡았습니다. 그러자 70개 가운데 12개(곡 `05`·`1C`·`1D`·`1E`·`23`·`28`·`2C`·`2D`, 효과음 `37`·`3B`·`3D`·`40`)가 libgme 에서 첫 1초에 최대값으로 튀고 끊기거나, 소리가 나지 않았습니다. `05` 는 MesenCE 로 열자 프레임 기록이 하나도 남지 않았습니다. 프레임 끝의 SPC700 이 명령을 반쯤 실행한 상태여서, 다음 명령의 시작에서 잡도록 바꿨습니다. 그 뒤 70개 모두 소리가 나고 최대값에 닿는 것이 없었습니다.
- **이어서 흐르는지**: 곡 `02` 를 게임에서 잡은 뒤 600프레임 동안의 DSP 목소리별 샘플 번호·음높이와 견줬습니다. 비교 대상은 그 .spc 를 MesenCE 로 따로 틀어 같은 600프레임 동안 적은 값입니다. 샘플 번호가 바뀐 10번과 음높이 윗바이트가 바뀐 62번이 차례·값 모두 같았고, 시각은 0~1프레임 차이였습니다.
- 곡 자리에 n 이 오른 프레임은 스테이트를 불러온 뒤 16~107프레임이었습니다. 곡이 시작한 바로 그 상태라 곡 첫머리부터 흐릅니다.

## 악보 내보내기 (`dq5score.py`)

[sfc/dq5/tools/dq5score.py](../tools/dq5score.py) 가 롬만으로 시퀀스 0x47개 전부를 악보로 냅니다(에뮬레이터·세이브스테이트 없음). 곡(`00`~`31`)은 `<번호>`(곡 변수 0)와 갈래가 있으면 `<번호>-<갈래>`, 효과음(`32`~)은 갈래마다 `<번호>-<갈래>` 로 모두 193개(곡 56, 효과음 137)입니다. 파일은 비공개 에셋 저장소의 `sfc/dq5/sound/songs/`·`sfx/` 에만 둡니다.

| 파일 | 내용 |
| --- | --- |
| `.txt` | `dq5song.py` 의 listing 꼴. `#` 머리(시퀀스·갈래·악기 → 샘플)를 빼고 그대로 `dq5song.py --encode` 로 다시 쌀 수 있음 |
| `.mid` | 형식 1. 트랙 = 시퀀스 트랙 = 채널, 4분음표 = 48틱 = 드라이버 1틱, 템포(BPM) = 템포 바이트 |
| `.musicxml` | MusicXML 4.0. 트랙마다 한 파트, 추정한 박자(아래)로 마디를 자름, 음 길이는 온음표~128분 셋잇단을 붙임줄로 이음. 마디 안에서 같은 종류의 셋잇단 셋이 이어지면 셋잇단 묶음(`<tuplet>`)을 닮(fc/dq4 와 같은 규칙) |
| `-score-NN.svg` | MusicXML 을 [verovio](https://www.verovio.org/)(파이썬 패키지, 저장소 의존성에 이미 있음)로 쪽마다 그린 판각 악보. 설정은 `fc/dq4/tools/dq4score.py` 와 같고 `xmlIdSeed` 를 고정해 같은 입력이면 같은 바이트. 가운데 음이 60 아래인 트랙은 낮은음자리표 |

연주 규칙은 드라이버를 따릅니다.

- 템포: 200Hz 타이머(`$FA` = `28`, 8000Hz / 40)마다 템포를 더해 250 을 넘으면 1틱입니다(`146C`: 넘치거나 `FB` 이상이면 `FA` 를 뺌). 1초 = 0.8 x 템포 틱이고 4분음표가 48틱이므로 BPM 이 곧 템포 바이트입니다. 시퀀스의 음 길이는 `18`(925번)·`30`(874)·`60`(428)·`0C`(385)·`C0`(280) 순으로 많아 48틱 = 4분음표가 맞습니다.
- 음높이: MIDI 음 = 음 번호 + 조옮김 + 23(음 `25` → 가운데 C, 약속값). 샘플 머리의 음높이는 더하지 않습니다. 더하면 동시에 울리는 음끼리 단2·장2·증4·단7·장7 이 되는 비율이 악기가 둘 이상인 30곡 평균 0.21 → 0.28 로 늘어, 머리 음높이는 샘플마다 음 번호의 뜻을 맞추는 값으로 보입니다. 잡음 트랙(`E3`)은 36 + 잡음 주파수입니다.
- 길이: 붙임(`4F`)은 앞 음에 이은 한 음입니다. 소리 길이(MIDI 끄기)는 길이 비율로 줄입니다(위 「시퀀스 형식」의 `15A1`). 따르기(`F1`·`F2`)는 앞 트랙의 길이와 비율을 가져옵니다.
- 박자: 롬에 박자 정보가 없어 추정합니다(`guess_meter`). 길이 24틱 이상인 음(잡음 빼고)의 길이 가운데 마디 첫 박에 놓인 비율 x 박 수를 3/4(144틱)·4/4(192틱)로 견주고, 3/4 은 그 값이 1.3 이상이면서 4/4 의 1.2배를 넘을 때만, 못갖춘마디는 0 보다 1.2배 넘게 나을 때만 고릅니다. 곡 56개 가운데 3/4 이 5개(`05`·`0A`·`0F`·`0F-01`·`2A`), 못갖춘마디가 있는 것이 17개입니다. 들어서 정한 박자가 아니므로 `index.json` 의 `meter` 에 「(추정)」을 붙입니다.
- 되풀이: `DB`·`DC`·`F4`·`F5`·`F8`·`F9` 는 펼칩니다. 뒤로 가는 `EA` 는 끝없는 되풀이라, 트랙마다 두 번째로 되돌아가는 틱 가운데 가장 늦은 틱에서 곡을 끝내고 모든 트랙을 그 틱까지 연주합니다(곡 `02` 는 6,144틱). 되풀이가 없는 곡(승리 `1F`·`19` 등 27개)은 마지막 음까지입니다.
- MIDI 에는 악기(`F0`)를 프로그램 바꿈(샘플 번호), 음량(`ED`)을 CC7, 팬(`EE`)을 CC10, 메아리 켜기·끄기(`FC`·`FD`)를 CC91(100·0)로 넣습니다. 음높이 미끄럼(`FB`)·엔벨로프(`E2`)·미세 조정(`E9`)은 피치 벤드(RPN 0 으로 범위 ±12 반음)로 넣습니다.
  - 엔벨로프 표는 SPC `08D4`~`09DF` 가 롬 `2B:C663` 에 그대로 있습니다(포인터 7개, 표 `00`~`06`). 읽는 자리가 머리 첫 바이트(되돌 자리)에 닿으면 둘째 바이트(돌아갈 자리)로 가고, `[미세 음높이][틱]` 을 따릅니다.
  - 미세 음높이(`8D`) 1 은 1/128 반음입니다. 곡 `0D` 트랙 1(`E2 04`, 피치 3375)의 DSP 피치가 3틱마다 표 값 v 의 1.5배(1 → +1, 2 → +3, -4 → -6, 8 → +12, -12 → -18, 12 → +18)씩 바뀌었고, 디코더가 낸 벤드를 그 피치로 되돌리면 ±1 두 값(1.5 의 버림)만 빼고 같았습니다. `E9` 도 같은 `8D` 를 쓰므로 같은 단위로 둡니다(`E9` 를 쓰는 곡의 KON 기록은 견주지 않음).
  - `FB 반음 틱` 은 지금 울리는 음(쉼 뒤가 아니면)에 그 틱부터 걸려, 틱 수에 걸쳐 고르게 옮긴 뒤 그 음이 붙임으로 이어지는 동안 머물고, 다음 새 음에서 풀립니다. 실측: 곡 `0A` 트랙 2 의 `note 27 len 60 / FB 07 30 / tie …` 에서 DSP 피치가 틱 96 부터 144 까지 2291 → 3432(7.00 반음)로 고르게 올랐고(피치 쓰기 48번, 디코더 벤드와의 차 최대 0.154 반음), 다음 새 음(틱 432, 음 `44`)은 제 음높이였습니다. 울리는 음이 없을 때(쉼 뒤·첫 음 앞)의 `FB` 는 다음 음의 시작부터 걸립니다. 실측: 곡 `1A` 트랙 0 의 첫 음 앞 `FB 01 06` 뒤 음 `30` 이 KON 의 피치 3857 에서 6틱 동안 4087(1.00 반음 위)까지 오르고, 다음 음 `2C`(틱 24)는 3062(제 음높이, 4반음 아래)였습니다. 시퀀스 71개에서 앞의 경우가 317번, 뒤의 경우가 95번입니다.

KON 과 견주기: 배 선실 세이브스테이트에서 소리 대기열에 `1A 00`·`01 n`(효과음은 `0C n X`)을 넣고(`lua/dq5spcdump.lua` 를 드라이버로) `lua/dq5dspw.lua` 로 2,400프레임 동안 KON 을 적은 뒤 `dq5score.py --kon` 으로 견줬습니다. 연주의 KON 은 음표와 붙임마다이고, 앞 음을 비율 `00` 으로 읽었으면 내지 않으며, 쉼 뒤의 음은 늘 다시 칩니다(`0A` 트랙 6 에서 쉼 뒤 음의 KON 을 보고 고침). 첫 KON 에 맞추고 틱 → 프레임은 템포로 셉니다.

최대 프레임 차는 대부분 빠르기의 작은 차이가 쌓인 것입니다. 트랙 0 의 KON 을 직선으로 맞추면 틱당 프레임이 `02` 는 예측(프레임 속도 / (0.8 x 템포))의 0.9984배, `10` 은 0.9987배였고, 직선에서 남는 차는 1.21·1.09 프레임이었습니다.
