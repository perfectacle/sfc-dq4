# DQ5(SFC) 이야기 플래그

DQ4 의 장(章)·사건 진행을 옮길 자리인 DQ5 의 이야기 플래그를 정리한 문서입니다. 플래그를 켜고 끄고 보는 곳을 모두 모아 [tools/dq5flags.py](../tools/dq5flags.py) 로 찍습니다. 찾아낸 과정은 일지에 있습니다.

- [2026-10-25-35: 이야기 플래그 목록](../journal/2026-10-25-35-flags.md)
- [2026-10-25-44: 이야기 플래그 2](../journal/2026-10-25-44-flags2.md)
- [2026-10-25-55: 이벤트 스크립트 번호 표와 청년기 순서](../journal/2026-10-25-55-event2.md)

기준 롬과 주소 표기는 [dq5-map-format.md](dq5-map-format.md) 와 같습니다.

## 자리

이야기 플래그는 `7E:2190 + 번호` 의 비트입니다. 이 목록은 번호 `00`~`7F`(`7E:2190`~`220F`)만 봅니다.

| 범위 | 쓰임 |
| --- | --- |
| `7E:2190`~`21C1` | 비트 플래그. 50바이트 거의 모든 비트가 어딘가에서 켜지고 시험됨 |
| `7E:21C2`~`2206` | 바이트 변수와 일부 비트(`21C9` 조우 효과, `21A1`·`21CA`~`21CC` 맵 임시 값 등) |
| `7E:2210`~ | 보물상자·タンス·발밑 열림 비트([dq5-map-format.md](dq5-map-format.md)). 이 목록에서는 뺌 |

맵을 옮기면 `00:A8CC`·`00:A940` 근처가 `219F`·`21A0`·`21A2`~`21A4`·`21C2`~`21C5`·`21EE` 를 지웁니다(게임에서 쓰기 기록으로 확인). 이 칸들은 맵 안에서만 쓰는 임시 값입니다.

## 다루는 곳

| 출처 | 형식 | 다루는 것 |
| --- | --- | --- |
| 네이티브 코드 | `BRK 0B mask idx`(시험, `00:93BA`), `BRK 0C mask idx`(켜기), `BRK 0D mask idx`(끄기). 시험은 켜져 있으면 Z 를 지움 | 비트 |
| 네이티브 코드 | `LDA`·`STA`·`CMP` 등 롱 주소 `7E:21xx` | 바이트 |
| 대화 스크립트(`06:B065`) | 조건 `07 1B idx mask`(켜짐)·`1A idx 값`(바이트가 다름)·`1C`, 명령 `17 idx mask`(AND, 끄기)·`18 idx mask`(OR, 켜기)·`19 idx 값`(바이트 쓰기) | 비트·바이트 |
| 인물 인라인 스크립트(`01:C800`) | `06 f m`(뛰기)·`09 f m`(기다림)·`10 f m`(켜기)·`11 f m`(AND)·`55 f m`(바이트 쓰기). `f` bit7 은 「꺼졌을 때」 | 비트·바이트 |
| 인물 목록 표 | `12:839C` `[BC][BD][f][m]`(인물을 놓지 않음), `12:8449` `[BC][BD][f][m][목록]`(목록 바꿈) | 비트 |
| 맵별 루틴 표(`15:F907`) | `+2` `f`, `+3` `m` | 비트 |
| 맵 조건 표 `01:9A12`·`02:CAF6` | `[BC][BD][f][m]` + 35바이트·루틴 포인터 2바이트. `BC` `FE` 필드, `FD` 어디서나(`02:CA6D`·`01:997D`) | 비트 |
| 이벤트 스크립트(`00:BEC3`) | `10 idx mask` 켜기, `20 idx mask` AND, `B0 idx mask` 켜질 때까지 기다림. 형식과 시작 주소는 [dq5-event-format.md](dq5-event-format.md) | 비트 |

`f` 의 bit7 은 「꺼졌을 때 참」이고 번호는 아래 7비트입니다.

## 도구

```sh
uv run --locked python sfc/dq5/tools/dq5flags.py rom/dq5.sfc            # 비트마다 켬·끔·봄 개수와 첫 문맥
uv run --locked python sfc/dq5/tools/dq5flags.py rom/dq5.sfc 2191.7     # 그 비트를 다루는 모든 곳
uv run --locked python sfc/dq5/tools/dq5flags.py rom/dq5.sfc 2191       # 그 바이트
```

```
2191.7
  봄          대화 01F (21/0B) 0681B7  「親方が　やっと 薬草をとって　帰ってきたんだ！…」
  켬          대화 020 (21/04) 0681CD  「やれやれ　たすかった！ 坊や　ありがとう！…」
  켬          대화 020 (21/04) 0681EC  「やれやれ　たすかった！ 坊や　ありがとう！…」
  봄          맵별 루틴 21/04 → 15F906 (꺼짐일 때)
  봄          코드 06:C4C2 BRK 0B
  봄          코드 12:9DBC BRK 0B
```

대화 스크립트는 그 대화 번호를 쓰는 인물의 맵(낮·밤, 대체 목록 포함)을 괄호에 적습니다. 문맥은 시험이면 참 갈래의 첫 메시지, 켜기·끄기면 바로 앞 메시지입니다.

지금 롬에서 비트 525개와 바이트 65개, 참조 5,050개가 나옵니다. 켜는 곳(비트 단위)이 없는 비트가 30개(그중 24개는 그 바이트를 통째로 쓰는 곳이 있고, 6개는 아래 「쓰지 않는 비트」), 시험하는 곳이 없는 비트가 37개입니다.

| 대화 스크립트 | 197 | 915 |

| 맵별 루틴 표·맵 조건 표 | 29 | 38 |

끄기 명령은 출처마다 AND 마스크(`BRK 0D`, 대화 `17`, 인물 `11`, 이벤트 `20`)를 받으므로, 뒤집어서 「끄는 비트」로 셉니다.

번호를 X 로 받아 `7E:2190,X` 를 다루는 공용 자리는 `BRK` 처리기(`00:93C4`~`9406`), 대화(`06:B0C2`~`B341`), 인물(`01:C9A4`~`CB31`·`01:D2EE`), 인물 목록 표(`12:8324`~`8385`), 맵별 루틴 표(`15:F824`·`F8B7`), 맵 조건 표(`01:99AC`·`02:CAA9`·`04:8160`), 이벤트 스크립트(`00:BFA9`~`BFFC`), 상자 사건(`12:F83C`), 두 칸 앞·발밑 표(`12:FD2E`·`FD82`)입니다. 마지막 셋은 번호에 `80` 을 더해(`7E:2210`~) 상자 쪽 비트를 다루므로 이 목록의 범위 밖입니다([dq5-map-format.md 「두 칸 앞」](dq5-map-format.md#두-칸-앞-1ef435)). `BRK 0B`~`0D` 의 피연산자는 언제나 명령 뒤 즉값이고(`00:93BA`), 계산한 번호를 쓰는 BRK 는 없습니다.

네이티브 코드는 롬 전체를 훑습니다. 그림 데이터에 같은 바이트가 많아, 시험이 BEQ·BNE 로 이어지는 일이 다섯 번 이상인 뱅크(`00`~`06`, `0F`, `11`, `12`, `1E`, `1F`, `20`, `21`, `23`~`25`, `2A`)와 게임에서 `BRK 0B` 실행을 본 `29` 만 봅니다. 또 `BRK 0B` 는 바로 뒤가 BEQ·BNE 인 것, `0C`·`0D` 는 바로 뒤가 흔한 명령인 것만 셉니다. 「흔한 명령」에는 `LDX abs`·`STX dp,Y` 같은 레지스터·색인 명령도 넣었습니다(`06:C363 BRK 0C 04 05` 뒤의 `LDX $0F1E`, `06:B872 BRK 0C 04 42` 뒤의 `STX $01,Y`). `0D` 는 끄는 비트(마스크를 뒤집은 것)가 셋 이상이면 데이터로 보고 뺍니다(`0F:8903`·`12:E08C`·`23:9059` 처럼 `21F0`·`2206`·`21F6` 여러 비트를 한 번에 끄던 것).
뱅크 `17`·`22`·`2B` 는 코드 뱅크에서 `JSL` 로 들어가는 곳(12·67·30곳)이 있지만 그림 데이터도 섞여 있습니다. 그래서 뱅크를 통째로 넣지 않고, 디스어셈블해 코드로 확인한 `BRK` 네 자리(`17:9375`·`17:9397`·`2B:BCCA`·`2B:BEBC`)만 더합니다. 롱 주소는 `2B` 도 봅니다(`2B:84B8`~`84E9` 의 `21D7` 읽기·쓰기). `2B:8895`·`9008`·`9A8B`·`AE48`, `17:89AA` 의 `00 0C` 는 앞뒤가 그림 데이터였습니다.
데이터 뱅크가 `7E` 인 코드는 짧은 주소로도 씁니다. `LDA #m` 뒤의 `TSB`·`TRB $2190`~`$220F`(사이에 다른 `TSB`·`TRB` 가 이어져도 같은 `LDA #`)를 켜기·끄기로 셉니다. 02 뱅크에 9곳 있습니다.

켜는 곳이 없던 비트 30개를 하나씩 보았습니다.

- `2195.2`(アルカパ 아이들 「レヌール城の　お化けを 退治したら…」)·`21D2.2` 는 위 두 `BRK 0C` 가 켭니다. 뒤 명령 규칙이 좁아 빠졌던 것입니다.
- `21F0.0`~`.5`·`2206`·`21F6` 의 끄기만 있던 비트는 데이터 바이트였습니다.
- `21A9.2`·`21BA.6`·`21BA.7`·`21BB.6`·`21C2.2`·`21C2.7`·`21C3.0` 은 비트 명령은 없지만 그 바이트를 롱 주소로 쓰는 곳이 있습니다.
- 남은 8개 중 둘은 켜는 곳을 찾았습니다.
  - `21BF.7`: `17:9375 BRK 0C 80 2F` 가 켭니다. 맵별 루틴 표의 첫 항목 「29/00, `21BF.7` 이 꺼져 있을 때 `02:9B12`」가 `17:9295` 를 부르고 이벤트 스크립트 `15:F47F` 를 겁니다. 그 스크립트의 네이티브 `17:9340` 안에 있습니다. 29/00 에 들어서자 원 모양으로 화면이 열리며 「よかった！ 気がつかれましたのね！」가 나왔고, 389 프레임에 `17:9340` 이 불린 뒤 `7E:21BF` 가 `00` → `80` 이 되었습니다. 수도원에서 깨어나는 장면을 본 표시입니다.
  - `21D7.7`: `02:8B22 LDA #$80 / TSB $21A2 / TSB $21D7` 이 켭니다. `02:89E6` 이 `$BD` = `53` 이고 `21D7.7` 이 꺼져 있으면 `02:8AEB` 를 부르고, 그 안에서 `21E2.7` 이 켜져 있으면 인물 슬롯 `0B` 를 (23,71) 쪽으로 옮긴 뒤 켭니다. 이 루틴은 그룹 `51`(51/51~57)의 매 프레임 루틴 `02:88B6`·`88BC` 안에 있습니다. 51/53(레일과 광차가 놓인 맵)에 `SET 21E2|80` 으로 들어가자 823 프레임에 `02:8B27` 이 실행되었습니다(그 직전 `21D7` = `00`).
- 끝까지 남은 6개(`21B3.4`·`21B7.6`·`21B7.7`·`21B8.6`·`21BE.0`·`21C0.0`)는 `BRK 0C`·롱 주소·짧은 주소 쓰기(`STA`·`TSB`·`INC`, 16비트로 앞 바이트를 쓰는 것 포함) 어디에도 없습니다. 보는 곳은 `21B3.4` 가 ベネット 대화 `1C9`, `21B7.6`·`.7` 이 19/00 대화 `0B3`·`0B7`(「めずらしい物が 手にはいったら…」), `21C0.0` 이 ルドマン 쪽 대화 `1FC`, `21B8.6` 이 `1F:F9D1`, `21BE.0` 이 맵 조건 표 `02:CAF6` 입니다. 롬 전체에서 이 여섯 비트를 켜는 꼴을 찾아도 없습니다. `BRK 0C mask idx` 는 뱅크 구분 없이 롬 전체에 없고(`21B8` 의 `22:9481 BRK 0C 7A 28` 은 비트가 다섯인 그림 데이터), 그 바이트나 앞 바이트를 롱·짧은 주소로 쓰는 명령(`STA`·`TSB`·`INC`·`DEC`·`STZ`)은 `19:DBD2 DEC $21B3`·`0B:D6CA INC $21B8`(둘 다 코드 뱅크로 보지 않은 곳), 앞 바이트만 8비트로 쓰는 `02:A3BF STA $7E21B6`(`21B6.4`)·`25:8320 INC $21BF`·`2D:8A22 TSB $21BF` 뿐이라, 여섯 비트를 켜는 것은 없습니다. 번호를 상수로 받는 다른 길(대화 `18`, 인물 `10`, 이벤트 스크립트 `10`, 인물 목록·맵 조건 표)에도 없습니다. 그래서 이 여섯은 보는 곳만 남은 「쓰지 않는 비트」로 둡니다.

확인한 것:

- `sfc/dq5/tools/lua/dq5flagtrace.lua` 로 게임에서 `BRK 0B`·`0C`·`0D` 를 부른 자리와 `7E:2190`~`220F` 쓰기를 잡았습니다. 첫 필드 이벤트, 필드 걷기, 01/04, 선실과 대화 4번에 더해 21/00·1A/00·04/00·09/00·08/00·01/00 에서 상하좌우로 걸으며 A 를 누른 8장면(그중 둘은 `2194`·`2195` 를 켜 둠)까지 16장면입니다.
  BRK 자리 100곳과 직접 롱 쓰기 26곳이 모두 목록에 있었고(위 규칙을 고친 뒤 9장면을 다시 돌려 BRK 116곳·롱 쓰기 25곳도 모두 있음), 공용 자리로 쓴 것은 `BRK 0C` 4·`0D` 1·대화 `18` 3·인물 `10` 2·이벤트 스크립트 켜기 1 이었습니다(`dq5flags.py --check`). 이벤트 스크립트가 켠 하나(09/00 에서 `219F.7`)는 처음에 정적 목록에 없었습니다. 스크립트 번호 표를 더한 뒤로는 번호 `10`·`4D`·`4F` 가 `219F.7` 을 켜는 곳으로 나옵니다(그때 어느 스크립트였는지는 기록하지 않음).
- 첫 필드 이벤트 뒤에 `02:A7AB BRK 0C 08 02`(`2192.3` 켬)와 `06:CFC8 BRK 0C 80 15`(`21A5.7` 켬)가 실행되었습니다. 둘 다 목록에 켜는 곳으로 있습니다.
- 선실 파파스의 대화 번호를 `01F` 로 바꿔 말을 걸자, `2191.7` 이 꺼져 있으면 메시지 `768`「…この村の洞くつに 入っていったと思うけど…」, 켜 두면 `76E`「…明日の朝には できるかもしれないな。」였습니다(목록의 「봄 대화 01F」).
- 대화 번호 `020` 으로 말을 걸자 `219D=20`(`0681FA` 의 켜기)이 쓰였고, `219D`·`2194` bit5 를 켜 두면 「やれやれ　たすかった！」 갈래로 가서 `2191` bit7 이 켜졌습니다(`0681EC`).
- `21A5.7` 을 필드에서 켜 두면 걷지 못하고 조우 판정(`00:82A5`)도 없었습니다.

## 청년기 사건 순서

청년기는 켜는 곳이 대화인 비트를 대사 흐름으로 늘어놓은 것입니다. 장소 이름은 ルーラ 목적지 목록 `25:85D5` 와 이름 표 `0B` 의 짝(`dq5gfx.py` 의 `group_names`, [dq5-graphics-format.md](dq5-graphics-format.md))으로 맞췄습니다. 이 짝으로 보면 그룹 `20` 은 ポートセルミ 이고(전에는 オラクルベリー 로 적었음, オラクルベリー 는 `19`), 그룹 `03` 만 이름 표에 없어 대사(ヨシュア·노예 생활)로 신전이라 붙였습니다.
각 단계에서 켜는 대화나 스크립트를 하나 이상 걸어, 그 메시지 뒤에 그 비트가 켜지는 것을 보았습니다. 아래 갈래 표의 여덟 대화에 더해, 대화 `13B` 는 메시지 `882`「うーん　うーん……。 は！　ユメだったかっ！？」 뒤에 `21BC` = `02`, `1E8` 은 「あなたも　フローラお嬢さまとの ご結婚を　お望みですか？」에서 はい 를 고르자 `21B4` = `80`, `1F6` 은 ビアンカ 의 「こんな私で　いいの？」에서 はい 를 고르자 `21AC` = `80`·`21B3` = `08` 이었습니다(쓰기 PC 는 모두 대화 `18` 의 `06:B0CA`). 마리아 장면 번호 `2C`(`15:F426`)를 29/00 에서 걸자 `00:BFB3` 이 `21B0` 에 `04` 를 쓰고 메시지 `2F9` 가 떴고, 천공의 번호 `41` 은 [dq5-event-format.md 「실측」](dq5-event-format.md#실측) 에서 `21B5=10` 을 썼습니다. アルカパ 의 `0D7` 은 일행에 ビアンカ(인물 `03`)가 마차 밖에 살아 있어야 켜는 갈래로 갑니다. `PARTY="02"` 로 동료 레코드를 만들고 도착 뒤 `+0` 을 `03` 으로 고친 채(`LATESET 206A=03`), `2190.6`·`21AC.4` 를 켜고 1A/03 (22,14) 의 노인에게 두 칸 아래 (22,16) 에서 말을 걸었습니다. 메시지 `873`·`874` 뒤 `9E7`「ビアンカ「おじいさん！ 私よ　ビアンカよ。」, `9E8`「ビアンカちゃんに会えて 本当に　よかったわい。」가 이어지고 1509 프레임에 `21AF` = `20`(`06:B0CA`)이 쓰였습니다. 다시 말을 걸면 첫 갈래의 `9E8` 만 나왔습니다.

## DQ4 장 진행을 넣는다면(설계 메모)

위는 실측과 문맥이고, 이 절은 옮길 때의 생각입니다. 사실로 확인한 것이 아닙니다.

- 비트 플래그 자리는 `7E:2190`~`21C1`(50바이트, 400비트)이고 거의 다 쓰입니다. DQ5 사건을 지우고 DQ4 사건을 넣는다면 이 400비트를 다시 나눠 쓰게 됩니다.
- DQ5 는 장소(맵 그룹)마다 플래그 바이트가 대체로 몰려 있습니다(배 `2191`·`2192`, サンタローズ `2194`·`2199`, アルカパ `2195`, レヌール城 `2196`·`2197`, ラインハット `219A`·`219B`). DQ4 의 다섯 장과 장마다의 마을·탑을 같은 식으로 바이트 몇 개씩에 묶으면 다루기 쉬워 보입니다.
- 장 번호처럼 여러 값을 갖는 것은 `$1948`(어린 시절·청년 전반·후반)처럼 바이트 하나에 두고, 그 값을 맵 항목·조우 격자·인물 목록이 고르게 하는 길이 있습니다. 지금 `$1948` 은 0~2 만 씁니다.
- 맵을 옮길 때 지워지는 칸(`219F`·`21A0`·`21A2`~`21A4`·`21C2`~`21C5`·`21EE`)은 맵 안의 임시 값이라, 장 진행에는 쓰지 않아야 합니다.
