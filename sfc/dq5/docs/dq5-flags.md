# DQ5(SFC) 이야기 플래그

DQ4 의 장(章)·사건 진행을 옮길 자리인 DQ5 의 이야기 플래그를 정리한 문서입니다. 플래그를 켜고 끄고 보는 곳을 모두 모아 [tools/dq5flags.py](../tools/dq5flags.py) 로 찍습니다. 찾아낸 과정은 일지에 있습니다.

- [2026-10-25-35: 이야기 플래그 목록](../journal/2026-10-25-35-flags.md)
- [2026-10-25-44: 이야기 플래그 2](../journal/2026-10-25-44-flags2.md)
- [2026-10-25-55: 이벤트 스크립트 번호 표와 청년기 순서](../journal/2026-10-25-55-event2.md)

기준 롬과 주소 표기는 [dq5-map-format.md](dq5-map-format.md) 와 같습니다.

## 자리

이야기 플래그는 `7E:2190 + 번호` 의 비트입니다. 이 목록은 번호 `00`~`7F`(`7E:2190`~`220F`)만 봅니다.

| 범위 | 쓰임 |
| --- | --- |
| `7E:2190`~`21C1` | 비트 플래그. 50바이트 거의 모든 비트가 어딘가에서 켜지고 시험됨 |
| `7E:21C2`~`2206` | 바이트 변수와 일부 비트(`21C9` 조우 효과, `21A1`·`21CA`~`21CC` 맵 임시 값 등) |
| `7E:2210`~ | 보물상자·タンス·발밑 열림 비트([dq5-map-format.md](dq5-map-format.md)). 이 목록에서는 뺌 |

맵을 옮기면 `00:A8CC`·`00:A940` 근처가 `219F`·`21A0`·`21A2`~`21A4`·`21C2`~`21C5`·`21EE` 를 지웁니다(게임에서 쓰기 기록으로 확인). 이 칸들은 맵 안에서만 쓰는 임시 값입니다.

## 다루는 곳

| 출처 | 형식 | 다루는 것 |
| --- | --- | --- |
| 네이티브 코드 | `BRK 0B mask idx`(시험, `00:93BA`), `BRK 0C mask idx`(켜기), `BRK 0D mask idx`(끄기). 시험은 켜져 있으면 Z 를 지움 | 비트 |
| 네이티브 코드 | `LDA`·`STA`·`CMP` 등 롱 주소 `7E:21xx` | 바이트 |
| 대화 스크립트(`06:B065`) | 조건 `07 1B idx mask`(켜짐)·`1A idx 값`(바이트가 다름)·`1C`, 명령 `17 idx mask`(AND, 끄기)·`18 idx mask`(OR, 켜기)·`19 idx 값`(바이트 쓰기) | 비트·바이트 |
| 인물 인라인 스크립트(`01:C800`) | `06 f m`(뛰기)·`09 f m`(기다림)·`10 f m`(켜기)·`11 f m`(AND)·`55 f m`(바이트 쓰기). `f` bit7 은 「꺼졌을 때」 | 비트·바이트 |
| 인물 목록 표 | `12:839C` `[BC][BD][f][m]`(인물을 놓지 않음), `12:8449` `[BC][BD][f][m][목록]`(목록 바꿈) | 비트 |
| 맵별 루틴 표(`15:F907`) | `+2` `f`, `+3` `m` | 비트 |
| 맵 조건 표 `01:9A12`·`02:CAF6` | `[BC][BD][f][m]` + 35바이트·루틴 포인터 2바이트. `BC` `FE` 필드, `FD` 어디서나(`02:CA6D`·`01:997D`) | 비트 |
| 이벤트 스크립트(`00:BEC3`) | `10 idx mask` 켜기, `20 idx mask` AND, `B0 idx mask` 켜질 때까지 기다림. 형식과 시작 주소는 [dq5-event-format.md](dq5-event-format.md) | 비트 |

`f` 의 bit7 은 「꺼졌을 때 참」이고 번호는 아래 7비트입니다.

## 도구

```sh
uv run --locked python sfc/dq5/tools/dq5flags.py rom/dq5.sfc            # 비트마다 켬·끔·봄 개수와 첫 문맥
uv run --locked python sfc/dq5/tools/dq5flags.py rom/dq5.sfc 2191.7     # 그 비트를 다루는 모든 곳
uv run --locked python sfc/dq5/tools/dq5flags.py rom/dq5.sfc 2191       # 그 바이트
```

```
2191.7
  봄          대화 01F (21/0B) 0681B7  「親方が　やっと 薬草をとって　帰ってきたんだ！…」
  켬          대화 020 (21/04) 0681CD  「やれやれ　たすかった！ 坊や　ありがとう！…」
  켬          대화 020 (21/04) 0681EC  「やれやれ　たすかった！ 坊や　ありがとう！…」
  봄          맵별 루틴 21/04 → 15F906 (꺼짐일 때)
  봄          코드 06:C4C2 BRK 0B
  봄          코드 12:9DBC BRK 0B
```

대화 스크립트는 그 대화 번호를 쓰는 인물의 맵(낮·밤, 대체 목록 포함)을 괄호에 적습니다. 문맥은 시험이면 참 갈래의 첫 메시지, 켜기·끄기면 바로 앞 메시지입니다.

지금 롬에서 비트 510개와 바이트 65개, 참조 4,962개가 나옵니다. 켜는 곳(비트 단위)이 없는 비트가 30개, 시험하는 곳이 없는 비트가 59개입니다.

| 출처 | 플래그 | 참조 |
| --- | --- | --- |
| 네이티브 `BRK 0B`·`0C`·`0D` | 436 | 1,584 |
| 인물 인라인 스크립트 | 218 | 1,516 |
| 대화 스크립트 | 197 | 915 |
| 인물 목록 표 | 98 | 339 |
| 롱 주소 | 65 | 310 |
| 이벤트 스크립트 | 70 | 260 |
| 맵별 루틴 표·맵 조건 표 | 29 | 38 |

끄기 명령은 출처마다 AND 마스크(`BRK 0D`, 대화 `17`, 인물 `11`, 이벤트 `20`)를 받으므로, 뒤집어서 「끄는 비트」로 셉니다.

번호를 X 로 받아 `7E:2190,X` 를 다루는 공용 자리는 `BRK` 처리기(`00:93C4`~`9406`), 대화(`06:B0C2`~`B341`), 인물(`01:C9A4`~`CB31`·`01:D2EE`), 인물 목록 표(`12:8324`~`8385`), 맵별 루틴 표(`15:F824`·`F8B7`), 맵 조건 표(`01:99AC`·`02:CAA9`·`04:8160`), 이벤트 스크립트(`00:BFA9`~`BFFC`), 상자 사건(`12:F83C`), 두 칸 앞·발밑 표(`12:FD2E`·`FD82`)입니다. 마지막 셋은 번호에 `80` 을 더해(`7E:2210`~) 상자 쪽 비트를 다루므로 이 목록의 범위 밖입니다([dq5-map-format.md 「두 칸 앞」](dq5-map-format.md#두-칸-앞-1ef435)). `BRK 0B`~`0D` 의 피연산자는 언제나 명령 뒤 즉값이고(`00:93BA`), 계산한 번호를 쓰는 BRK 는 없습니다.

네이티브 코드는 롬 전체를 훑습니다. 그림 데이터에 같은 바이트가 많아, 시험이 BEQ·BNE 로 이어지는 일이 다섯 번 이상인 뱅크(`00`~`06`, `0F`, `11`, `12`, `1E`, `1F`, `20`, `21`, `23`~`25`, `2A`)와 게임에서 `BRK 0B` 실행을 본 `29` 만 봅니다. 또 `BRK 0B` 는 바로 뒤가 BEQ·BNE 인 것, `0C`·`0D` 는 바로 뒤가 흔한 명령인 것만 셉니다.

확인한 것:

- `sfc/dq5/tools/lua/dq5flagtrace.lua` 로 게임에서 `BRK 0B`·`0C`·`0D` 를 부른 자리와 `7E:2190`~`220F` 쓰기를 잡았습니다. 첫 필드 이벤트, 필드 걷기, 01/04, 선실과 대화 4번에 더해 21/00·1A/00·04/00·09/00·08/00·01/00 에서 상하좌우로 걸으며 A 를 누른 8장면(그중 둘은 `2194`·`2195` 를 켜 둠)까지 16장면입니다.
  BRK 자리 100곳과 직접 롱 쓰기 26곳이 모두 목록에 있었고, 공용 자리로 쓴 것은 `BRK 0C` 4·`0D` 1·대화 `18` 3·인물 `10` 2·이벤트 스크립트 켜기 1 이었습니다(`dq5flags.py --check`). 이벤트 스크립트가 켠 하나(09/00 에서 `219F.7`)는 처음에 정적 목록에 없었습니다. 스크립트 번호 표를 더한 뒤로는 번호 `10`·`4D`·`4F` 가 `219F.7` 을 켜는 곳으로 나옵니다(그때 어느 스크립트였는지는 기록하지 않음).
- 첫 필드 이벤트 뒤에 `02:A7AB BRK 0C 08 02`(`2192.3` 켬)와 `06:CFC8 BRK 0C 80 15`(`21A5.7` 켬)가 실행되었습니다. 둘 다 목록에 켜는 곳으로 있습니다.
- 선실 파파스의 대화 번호를 `01F` 로 바꿔 말을 걸자, `2191.7` 이 꺼져 있으면 메시지 `768`「…この村の洞くつに 入っていったと思うけど…」, 켜 두면 `76E`「…明日の朝には できるかもしれないな。」였습니다(목록의 「봄 대화 01F」).
- 대화 번호 `020` 으로 말을 걸자 `219D=20`(`0681FA` 의 켜기)이 쓰였고, `219D`·`2194` bit5 를 켜 두면 「やれやれ　たすかった！」 갈래로 가서 `2191` bit7 이 켜졌습니다(`0681EC`).
- `21A5.7` 을 필드에서 켜 두면 걷지 못하고 조우 판정(`00:82A5`)도 없었습니다.

## 어린 시절 사건 순서

이야기 앞부분(어린 시절)의 플래그를 사건 순서대로 놓은 것입니다. 맵 그룹 이름은 그 그룹 대사에 나오는 인물·장소로 붙였습니다.
`실측` 은 이 문서나 다른 문서에서 게임으로 확인한 것이고, `문맥` 은 켜는 곳의 대사·맵으로 짐작한 것입니다. 순서는 대사 흐름으로 정했습니다.

## 청년기 사건 순서

청년기는 켜는 곳이 대화인 비트를 대사 흐름으로 늘어놓은 것입니다. 맵 그룹 이름은 대사로 붙였고, 모두 `문맥` 입니다(`21B3.3` 만 [dq5-text-format.md](dq5-text-format.md) 에서 실측).

| 순서 | 장소(그룹) | 사건 | 켜는 비트 | 켜는 곳 |
| --- | --- | --- | --- | --- |
| 1 | 신전(03) | 노예 생활, ヨシュア 가 도망을 도움 「さあ　誰か来ないうちに 早く」 | `21B0.3`~`.7`, `21BB.5` | 대화 `07B`·`07C`·`080`·`08E`·`090` |
