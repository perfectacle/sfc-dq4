# 2026-10-29-01: 필드에서 가나 칸을 슬롯으로

필드에서 가나 칸 `010`~`073` 을 한글 슬롯으로 돌려 쓰고, 전투에 들어가면 가나 그림을 되돌렸습니다. 슬롯이 24개로 늘어 강함 보기의 직함 줄도 한글이 됐습니다. 결과는 [가나 칸 슬롯](../docs/dq4-window-text-format.md#가나-칸-슬롯)에 있습니다.

## 1. 가나 칸을 되돌릴 그림

전투 메시지와 몬스터 목록은 가나 1바이트 타일을 쓰고, 게임은 전투에 들어갈 때 가나 칸을 다시 올리지 않습니다. 그래서 필드에서 가나 칸을 쓰면 전투에 들어갈 때 우리가 되돌려야 합니다. 게임이 올린 가나 칸을 VRAM 덤프에서 꺼내 롬의 1bpp 창 글자(`04:E528`~, 칸 `01` 부터 8바이트씩)와 견줬습니다.

```
칸 010  VRAM 20 ff fc ff 20 ff 3c ff 66 ff aa ff 92 ff 64 ff
        롬   20    fc    20    3c    66    aa    92    64
105칸 중 105칸 일치(평면 0 = 1bpp, 평면 1 = FF)
```

따로 그림을 둘 필요 없이 롬 `04:E5A0`(칸 `10`)에서 평면 0 으로 보내고 평면 1 은 `FF` 로 채우면 됩니다. 메시지 캔버스 청소(`WqClean`)가 평면 1 을 `FF` 로 채우는 것과 같은 DMA 입니다.

## 2. 슬롯 배치

가나 칸 100칸을 작은 슬롯 4개, 중간 2개, 큰 2개로 나눠 기존 16개 뒤가 아니라 같은 크기의 맨 앞에 뒀습니다. 빈 슬롯은 표 순서대로 고르므로, 필드에서는 가나 칸 슬롯을 먼저 씁니다. 가나 칸은 메시지 캔버스(`096`~`17F`) 밖이라 메시지가 떠도 지워지지 않습니다. 슬롯 등급에 `$10` 을 더하면 필드 전용으로 하고, 전투(`$1944` = `00:8952`)에서는 건너뜁니다.

가나 칸 슬롯에 그리면 `7E:3D5A` 의 아래 두 비트에 덩이 수 3 을 넣습니다. 이 바이트는 대기열과 겹친 게임의 창 타일맵 요청(`$0BEC`, bit7·6)을 미뤄 두는 자리이고, 0 이 아니면 NMI 받침이 게이트를 부릅니다. 게이트는 전투 NMI 작업일 때만 35칸씩 세 번에 나눠 되돌립니다.

## 3. 전투에서 가나가 그대로 깨짐

처음 빌드에서는 강함 보기를 닫고 싸우자 「メラリザード」 가 깨졌고, VRAM 의 가나 칸은 전투 내내 29칸만 롬과 같았습니다. `3D5A` 를 덤프하니 필드에서 이미 0 이었습니다. 게이트가 대기열과 `$0BEC` 가 겹칠 때 `$0BEC` 를 `3D5A` 에 그대로 써(`STA`) 덩이 수를 지웠습니다. OR 로 넣게 고치자 전투 화면이 뜬 뒤 덤프에서 105칸이 모두 롬과 같았습니다.

## 4. 직함 줄과 예/아니요

슬롯이 24개가 되자, 지난번에 슬롯이 모자라 되돌렸던 직함 줄(`D2`, 이름 표 1)을 다시 켰습니다. 09/00(일행 셋)에서 「크리프트 / 파파스의 아들 / 성별 : 남자」 와 라벨·장비 이름이 모두 나왔습니다.

09/00 무작위 입력에서 도구 → 버리기의 「예 / 아니요」 가, 뒤에 떠 있는 명령 창의 「대화 / 주문」 자리에 비쳤습니다. 예/아니요 `32` 와 명령 창 `01` 이 둘 다 전용 칸 `1D0`~ 에서 시작했기 때문입니다. 전용 칸은 메시지 캔버스를 피하려고 둔 것이라, 캔버스 밖 가나 칸 슬롯이 생긴 지금은 `32`·교회 `3C`·맡기는 곳 `51`·`52`·`54` 를 일반 슬롯으로 옮겼습니다. 교회·맡기는 곳·여관 장면에서 모두 한글로 나왔고, 버리기 장면의 명령 창도 그대로였습니다. 예/아니요 창 `62`(いいえ / はい)도 고정 문구로 바꿨습니다.

| 장면 | 결과 |
| --- | --- |
| 09/00 강함 보기 | 직함·라벨·장비 한글 |
| 강함 보기 뒤 전투 | 가나 칸 105칸 롬과 일치, 몬스터 목록·전투 메시지 정상 |
| 교회 · 맡기는 곳 · 여관 | 한글 창, 메시지와 함께 |
| 무작위 입력 6벌(전투 둘 포함) · 이름 검사 셋 · 단위 시험 | 모두 정상 |

## 틀렸던 것들

- 처음에는 버리기 장면의 깨진 작은 창을 아직 바꾸지 않은 `62` 로 봤습니다. `62` 를 바꿔도 그대로여서 보니, 09/00 세이브스테이트의 낮은 WRAM `7E:1AC0` 에 맵을 불러올 때 복사된 옛 `32` 레코드가 남아 있었습니다. 새 `60:B400` 사본을 `SET` 으로 넣자 「예 / 아니요」 였습니다.

## 남은 것

- 창 레코드를 훑으면 본문에 가나가 남은 창이 더 있습니다(`4B` つかう/そうび, `75` 동료 넣고 빼기, `77` 기록 등). 필드에서 뜨면 가나 칸 슬롯과 겹쳐 깨집니다.
- 한글 표에 없는 이름은 원래 가나로 찍혀 필드에서 깨짐. Galmuri9 의 가나로 슬롯에 그릴 것
- 전투 밖에서 가나 칸이 필요한 장면(이름 입력 등)에서도 되돌려야 하는지
