# 2026-10-25-50: 라이안 정면을 DQ5 롬 데이터로 연결

라이안 정면 정지 자세를 DQ5 어린 주인공 세트에 넣는 변환기와 IPS, 비교 갤러리를 만들었습니다. 형식과 재현 방법은 [롬 에셋 문서](../docs/dq4-rom-assets-format.md)에 있습니다. 기존 Lua 표시 실험과 달리, 이번 결과는 롬에 기록한 인물 데이터를 원래 게임 로더가 읽습니다.

## 1. 기존 추출기를 역변환 기준으로

`dq5sprite.py`에 이미 해독된 세트 레코드와 저·고 바이트 줄기 압축을 사용했습니다. 세트 `82`의 방향별 머리와 몸을 분리하고, 정면 정지 그림을 넣은 뒤 중복 타일과 좌우 반전 타일을 합쳤습니다. 새 타일과 레코드를 기존 추출기로 다시 읽어 정면의 색 번호가 같은지 비교했습니다.

팔레트 0은 다른 인물과 공유합니다. 이를 바꾸지 않고 라이안 색을 기존 팔레트로 대응시켰기 때문에 분홍 갑옷이 갈색 계열로 바뀝니다. 원래 라이안 정면의 확인과 이 색 변경본의 확인을 구분해 갤러리에 표시했습니다.

## 2. 원래 공간을 넘는 압축 자료

기존 압축 공간은 758바이트이고 새 자료는 37타일, 804바이트였습니다. 처음에는 제자리 교체를 시도했지만 용량 검사에서 거부됐습니다. 롬을 1.5MiB에서 2MiB로 확장하고 `30:8000`에 새 자료를 기록했습니다. 확장 영역은 기존 마지막 512KiB 미러로 채운 뒤 새 자료만 덮었습니다. 헤더의 크기 값은 이미 2MiB였으며 체크섬은 다시 계산했습니다.

원본 롬은 수정하지 않습니다. 확장 IPS에는 미러 영역의 원작 데이터가 포함되므로 롬·패치 모두 로컬 `work/`에만 둡니다.

## 3. 독립 추출과 화면 비교

기존 디코더로 새 롬을 추출해 정면 일치, 다른 방향 6프레임과 다른 인물 146세트 및 공용 팔레트 보존을 검사했습니다. IPS를 원본에 적용한 결과도 별도 출력 롬과 같습니다.

갤러리는 제작물과 롬 적용 결과를 나란히 보여 줍니다. 배율·방향·두 프레임·전체 시트·보행 재생을 선택할 수 있습니다. 원래 라이안 정면만 확인된 상태이며 다른 인물과 색 변경본은 시안입니다.

## 4. 실제 롬 로더와 비교

MesenCE 2.2.1에서 콜드 부팅 2,400프레임 후 새 게임 메뉴를 확인했습니다. 별도의 필드 상태에서 입력만으로 마을·필드를 오가며 그래픽 로더 9회 실행을 확인했습니다. 이후 덤프 181개의 VRAM 타일 32,281건과 OAM 그림 215건이 모두 디코더와 일치했습니다. 세트 `82`는 4방향·2프레임을 관찰했습니다. 관찰 프로브는 그래픽 메모리를 덮어쓰지 않습니다. 전체 게임 진행을 검증한 것은 아닙니다.

## 틀렸던 것들

- 4bpp로 만들 수 있다고 바로 DQ5 롬에 들어가는 것은 아닙니다. 세트 레코드·머리와 몸의 배치·공유 팔레트·압축 공간을 함께 맞춰야 했습니다.
- 정면 정지 한 장만 바꿔도 머리가 두 프레임에서 공유됩니다. 두 번째 정면 프레임에는 원래 몸이 남아 혼합된 그림이 됩니다.

## 남은 것

- 다른 인물에 영향을 주지 않으면서 라이안의 고유색을 유지하는 팔레트 배정.
- 라이안의 측면·후면·보행과 다른 인물의 시각 확인 및 롬 연결.
- 타이틀·맵·몬스터와 통행·출구·이벤트의 단계별 연결.
