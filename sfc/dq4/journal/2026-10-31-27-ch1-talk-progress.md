# 2026-10-31-27: 1장 진행 대사, 예·아니요 갈래, 합류 팡파르, 창살 너머 말 걸기

1장 인물 가운데 진행에 따라 대사가 바뀌는 사람을 모두 찾아 남은 둘(성 앞 노인, 보스 뒤 성 앞 사내)을 옮겼고, 노인·사내·호이민의 예·아니요를 진짜 갈래로 만들었습니다. 호이민이 동료가 될 때 팡파르를 울리고, 이무르 감옥의 창살 너머로 알렉스에게 말이 닿게 했습니다. 명세는 [1장 첫머리의 「진행에 따라 바뀌는 대사」](../docs/dq4-chapter1-format.md#진행에-따라-바뀌는-대사)와 [환경의 「문과 성문」](../docs/dq4-environment-format.md#문과-성문)에 있습니다.

## 1. 조건이 남는 대화 모두 찾기

`dq4npcport` 는 1장 시작 상태(장 0, 깃발·일행 없음)로 FC 대화를 돌려 처음 나오는 메시지만 옮깁니다. 그래서 깃발·물건·일행·예·아니요로 갈리는 대화는 따로 옮겨야 합니다. 1장 그룹 맵(FC `02`·`12`·`1C`·`30`·`41`·`3A`)의 낮·밤 목록과 보스 뒤 목록마다 `dq4talk` 의 스크립트 나무를 풀고, 장(`16`)·낮밤(`14`)·카운터(`02`) 조건을 그 맵·시간대로 풀어 없앴습니다. 그 뒤에도 조건이나 깃발 쓰기가 남는 대화는 12개였습니다.

```
00A 노인        if flag& 0E 10 → 0789 / 0787, if yes → flag|= 0E 10, 0788, call 15:9D36 / 078A
00B 왕          if item 6C
00D 방어구점    if counter → 가게
00F·010 프레아  if flag& 06 80
012·013         flag|= 06 80
014 동굴 병사   if flag& 08 80, call+2 15:9D3E
015 호이민      if yes
016 보스        call 15:9D57(이벤트 00)
019 사내        079D, if yes → 079E / 079E
148 탑의 병사   if flag& 08 80, if party 08
15F 죽은 병사   if flag& 08 80
```

`00A` 와 `019` 말고는 이미 덧붙인 대화나 보스 뒤 목록이 맡고 있었습니다. 둘은 「물음과 예 쪽 대답을 이은」 메시지 하나로 옮겨져, 예·아니요 창 없이 늘 같은 말을 했습니다.

## 2. 노인과 사내

노인의 깃발 `$6289`&`10` 에 맞는 DQ5 자리가 없어 새로 골랐습니다. [플래그 목록](../../dq5/docs/dq5-flags.md)의 `dq5flags.py` 출력에 한 번도 나오지 않는 비트 가운데, 앞서 1장 연출 깃발이 고른 `2199.0` 을 빼고 `2196.7` 을 썼습니다. 처음에는 「켜기만 하고 보지 않는」 `2208.4` 를 골랐다가, 그 비트는 DQ5 코드가 켜는 자리가 있어 바꿨습니다.

덧붙인 대화 `old_man` 은 깃발이 있으면 `0789`(「헉헉…… 역시 늙은이에게는 무리인 모양일세」), 없으면 `0787` 뒤 조건 `05`(예·아니요)로 갑니다. 「예」면 깃발을 켜고 `0788`, 「아니요」면 `078A` 입니다. 사내 `braggart` 는 `079D` 뒤 예·아니요 창을 띄우고 두 갈래 모두 `079E` 입니다.

FC 는 노인에게 「예」 하면 `15:9D36` 이 노인 슬롯 `0E` 의 걸음 간격 `$704E` 를 `33` 으로 둡니다. 노인의 블록은 `24 80 00`(목표 = 일행) 뒤 `03`(목표로 한 걸음)이라 노인이 느리게 따라오다 지칩니다. DQ5 쪽 노인은 옮긴 서 있는 인물이라 스크립트가 없고, 빌릴 수 있는 한 벌 인물도 다 써서 이 걸음은 옮기지 못했습니다.

1장 롬을 배 선실에서 감옥으로 워프해 세이브스테이트를 만들고, 거기서 성 앞으로 워프해 쟀습니다(같은 맵으로는 워프가 맵 번호 바뀜을 기다리다 끝나지 않음).

```
노인 아래 (44,27) 위로, 예      DAB → DAC, 2196 = 80, 다시 말 걸면 DAE
                  아니요        DAB → DAD, 2196 = 00, 다시 말 걸면 DAB
사내(보스 깃발, 걸음 간격 0) 예  DAF → 창 → DB0
                        아니요  DAF → 창 → DB0
```

사내는 걸어 다니는 인물이라, 걸음 간격 `7E:3301`~`3317` 을 매 프레임 0 으로 묶어야 처음 자리에서 말이 닿았습니다.

## 3. 호이민의 합류 팡파르

FC `0794` 는 `{SOUND:1A}{STOP}` 으로 끝나 「ホイミンが なかまに くわわった！」 를 띄운 채 소리 `1A` 를 울리고 끝날 때까지 기다립니다. 사운드 포팅의 곡 자리 `26` 이 NDS 「仲間が加わった」 입니다. DQ5 의 ベラ 합류(`06:C184`)에는 곡 호출이 없었고, 곡을 틀고 기다리는 길은 `06:F79A` 의 `BRK 0F 24` / `LDA #$24` / `JSL 24:FF0F` 였습니다. 그 길을 뱅크 06 의 작은 루틴(`FANFARE_AT`)으로 만들어 대화 스크립트가 「동료가 되었다!」 뒤에 부르게 했습니다.

처음 판은 레벨업 루틴처럼 `24:FF0F` 와 `20:8218` 만 불렀습니다. 곡 요청이 `24:FF0F` 로만 기록되고 다음 프레임에 맵 곡 요청이 왔습니다. `24:FF0F` 는 그 곡이 끝나기를 기다릴 뿐 틀지 않으므로 소리가 나지 않았습니다. `BRK 0F 26` 을 앞에 넣자 이번에는 팡파르 뒤 `20:8218` 에서 돌아오지 않았습니다. 대화가 끝나지 않고 합류 깃발도 켜지지 않았습니다. `20:8218` 이 부르는 `00:CE61` 은 지금 곡 `$1D8B` 가 맵 곡과 다르면 사운드 포팅 훅(`71:8560`)으로 앞 곡을 줄이는데, 팡파르가 끝나 `$1D8B` 가 `FF` 였습니다. 맵 곡을 `$194B` 에서 읽어 `24:FE9A` 로 바로 틀게 바꿨습니다.

```
D8C → D8D, 1032 곡 26 요청, KON 1078~1591, 1767 24:FF0F 돌아옴·맵 곡 09 요청, 1791 맵 곡 KON
21B8 = 01, 201D = 02
아니요: D8C → D8E, 21B8 = 00, 201D = 01
```

SPC 의 KON 은 `$F2` = `4C` 뒤 `$F3` 쓰기로 잡았습니다. 팡파르 음은 513프레임(FC 소리 `1A` 의 길이 409프레임보다 김) 울리고, 끝 뒤 176프레임에 돌아왔습니다.

## 4. 창살 너머의 알렉스

밤 감옥에서 알렉스에게 창살 바깥에서 말을 걸면 `129`(아무도 없음)였습니다. FC 감옥 `12/02` 의 창살 (3,3)은 블록 속성 `97`(さいごのカギ 문)이고, FC 「はなす」(`1E:$80D8`)는 속성 아래 7비트가 `17`·`27` 이면 한 칸 더 앞의 인물과 말합니다. 그래서 FC 에서는 창살 너머로 말이 닿습니다. 환경 빌드는 `97` 을 문 목록에 넣지 않아 벽으로 두었습니다.

DQ5 의 카운터는 여관 카운터처럼 바닥 칸에 `+1` bit7(못 감)과 블록 속성 `15` 를 둔 칸입니다(テンペ 여관에서 맞춘 것). `97` 도 `A7` 과 같은 카운터로 두었습니다.

```
밤, (8,7)에서 왼쪽: 129 → D83, 2197 = 02
낮, 같은 자리: CC3
왼쪽으로 20프레임: (8,7) 그대로
```

`97` 은 5장 맵(`16/00`·`16/02`·`05/00`·`04/01`·`04/05`)에도 있습니다. 모두 카운터가 되어 さいごのカギ 로는 열리지 않습니다. 전에도 벽이었으므로 막히는 곳은 늘지 않았습니다.

## 틀렸던 것들

- 「`24:FF0F` 에 곡 번호를 주면 틀고 기다린다」: 기다리기만 합니다. 레벨업 루틴(`level_up`)도 같은 꼴이라 팡파르가 울리지 않을 것으로 보입니다(재지 않음).
- 「맵 곡은 `20:8218` 로 돌리면 된다」: 팡파르가 끝난 뒤에는 `00:CE61` 이 돌아오지 않았습니다.

## 남은 것

- 필드 레벨업 팡파르가 실제로 울리는지(코드 읽기로는 `BRK 0F` 가 없음).
