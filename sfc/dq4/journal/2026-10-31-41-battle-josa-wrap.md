# 2026-10-31-41: 전투 메시지 418개와 이름 뒤 조사, 넘치는 줄 나누기

전투 메시지 432개 가운데 검사가 끝까지 찍는다고 적은 것은 417개였습니다. 남은 15개가 왜 빠졌는지 보고, 전투 메시지의 조사와 1장에 장면이 없는 필드 시스템 메시지(`188`·`054`~`057`)도 화면에 띄워 봤습니다. 결과는 [전투 메시지 검사](../docs/dq4-battle-text-format.md#전투-메시지-검사)와 [조사 코드 검증](../docs/dq4-josa-format.md#검증)에 있습니다.

## 1. 빠진 15개

`dq4battletexts.SOURCE` 에는 418개가 있고, 검사는 그중 `004` 하나를 뺐습니다. 번역하지 않은 14개(`000`, `1A3`~`1AF`)를 `dq5battletext.message` 로 원래 롬에서 풀어 봤습니다.

```
000  {EF}
1A2  {F7}は　ボーッとしている。{FE}        ← 마지막 메시지
1A3  {FF}{FF}{FF}{FF}っ{F2}な　ト　イ{FE}
1A4  ャ　　　くくる{FE}
1A9  ほ　しつおか奇
1AA  たこ　しつくかしを攻かり{FE}
```

`000` 은 빈 메시지이고 `1A3` 부터는 원래 롬에서도 뜻 없는 바이트입니다. 옮길 메시지가 아니므로 남은 것은 `004` 하나입니다.

## 2. `004` 는 이제 멈추지 않는다

`004`「이럴 수가, {EC}{이}/전투에 끼어들었다!」를 다시 넣어 돌리니 멈추지 않고 다음 메시지로 넘어갔습니다. 화면은 「이럴 수가, 가 / 전투에 끼어들었다!」였습니다. `{EC}` 처리기 `24:8ABB` 를 읽어 보니 일행 레코드 여덟 개(`7E:2040` + 42 × n)에서 `+0` 이 `80` 인 사람을 찾고, 없으면 `$00` 을 0 으로 두고 그냥 돌아갑니다.

```
24:8AC6  LDX $8AE9,Y        ; 0, 2A, 54, …
24:8AC9  LDA $7E2040,X
24:8ACD  CMP #$80           ; 인물 번호 80 = 킬러팬서
24:8ACF  BEQ $8ADD          ; 찾으면 BRK 8C 로 이름
24:8AD8  STZ $00            ; 없으면 이름 없이 돌아감
```

주인공 `+0` 을 `80` 으로 둔 판에서는 「이럴 수가, ボロン가」가 찍혔고, 그 뒤 주인공이 킬러팬서로 다뤄져 전투가 이어지지 않았습니다. DQ4 에는 킬러팬서가 없어 이 메시지는 나오지 않습니다. 그래서 검사에서 빼지 않고 이름 없는 화면 그대로 봅니다.

화면의 주인공 이름이 「라이언ㅂ」이었던 것도 함께 고쳤습니다. 이름을 옮기는 `24:8A0F` 는 `01` 앞까지 읽는데, 검사가 넣는 이름에 끝 바이트 `01` 이 없어 세이브스테이트의 다음 바이트가 붙었습니다.

## 3. 이름 뒤 조사

이름 코드 뒤에 조사가 오는 메시지를 코드별로 셌습니다.

```
F7 249  F5 34  EE 3  F4 2  EC 1  EA 1
```

`F7` 은 이미 검증 표에 있습니다. 나머지 39개를 바꿔 띄우니, 「노송나무 막대가」·「큰 눈알을」·「플로라가」·「메시지8을」처럼 모두 앞 글자의 받침대로 골라졌습니다. 가나 이름 뒤는 「はめつのたて를」처럼 받침 없는 쪽입니다. 1장 조우 몬스터는 DQ4 몬스터를 옮기기 전까지 빌려 쓰는 DQ5 몬스터라, 236종 가운데 한글 이름이 있는 것은 31종뿐입니다.

## 4. 조사가 이름과 떨어진 줄

같은 화면에서 `0D1` 은 「피사로의 부하는 노송나무 막대 / 를 몸에 걸쳤다!」였습니다. 빌더는 이름을 7칸(56점)으로 세는데, 한글 일곱 자 이름은 70점이 넘어 줄이 넘쳤습니다. 이름 뒤에 이어 그린 구간이 넘치면 `BmCarryWrap` 은 이름 끝 열만 앞 줄에 찍고 구간째 다음 줄로 옮깁니다. 그 구간 맨 앞이 조사였습니다.

구간을 그리면서 첫 띄움(`10 05`)의 토큰 자리와 그 앞 점 자리를 `7E:A921`·`A922` 에 남기게 했습니다. 넘쳤을 때 첫 띄움 앞까지가 지금 줄에 들면, 버퍼의 띄움 두 바이트 자리를 `FF`(줄 바꿈)과 `E3 길이`(남은 구간 머리)로 바꾸고 앞부분만 다시 그립니다. 바이트가 하나 늘지만 구간 앞의 `E3` 는 이미 꺼냈으므로 버퍼 끝에서 메시지 바이트가 버려지지는 않습니다.

```
고치기 전  0D1  피사로의 부하는 노송나무 막대 / 를 몸에 걸쳤다!
고친 뒤    0D1  피사로의 부하는 노송나무 막대를 / 몸에 걸쳤다!
```

다른 38개 화면은 그대로였습니다. 418개 전수 검사는 모두 끝까지 찍혔고(멈춤 0), 한 화면에 가장 많이 쓴 풀 칸은 111 → 112칸입니다. 1장 걷기 검사 26구간, 창 글자 깨짐 검사의 전투 두 장면, dq4 단위 시험도 통과했습니다. 창 글자 검사가 거는 `talk02`·`talk03`(가게 목록의 가나)은 고치기 전 롬(`origin/main`)에서도 같이 걸렸습니다.

## 5. 1장에 장면이 없는 필드 메시지

`lua/dq4battlemsgswap.lua` 에 입구 주소 `ENTRY` 를 두고, `dq4battlemsgcheck.py --field` 로 성 앞(`36/00`)에서 빈 곳에 「はなす」를 고를 때 뜨는 보행 메시지(`24:8BAF`)를 바꿔 끼웠습니다.

```
188  열쇠가 맞지 않는다!
189  녹슬어서 열리지 않는다!
18A  밖에서 잠겨 있는 것 / 같다.
054  ＊「かしのつえ 말이죠? / 그건 팔지 않는 편이 좋지 / 않을까요?
055  ＊「대단히 죄송합니다만 그렇게 / 귀한 물건은 받을 수 / 없습니다.
```

`056`·`057` 까지 일곱 개 모두 창 안에서 끝까지 찍혔습니다. `054` 의 물건 이름은 그때 `$F5` 에 든 값이라 가나 이름이 들어갔습니다.

## 틀렸던 것들

- `004` 가 「끼어드는 동료가 없으면 `{EC}` 처리가 끝나지 않는다」는 설명은 지금 롬과 맞지 않았습니다. 지금은 이름 없이 돌아가 끝까지 찍힙니다. 그때 무엇이 멈추게 했는지는 다시 재지 않았습니다.
- `{EC}` 뒤 「ボロン가」를 처음에는 한글 「보론」 뒤에 잘못 고른 조사로 봤습니다. 화면을 키워 보니 가나 「ボロン」이었고, 가나 뒤 받침 없는 쪽이 맞았습니다.

## 남은 것

- 빌려 쓰는 DQ5 몬스터와 adopt 표에 없는 물건·주문은 이름이 가나로 찍힙니다. 몬스터 이름은 DQ4 몬스터를 옮길 때 바뀝니다.
- 줄을 나누는 곳은 구간의 첫 띄움뿐입니다. 첫 띄움 앞까지도 줄에 들지 않으면 전처럼 구간째 다음 줄로 갑니다.
- `188`·`189`·`18A`·`054`~`057` 은 바꿔 끼워서만 띄웠습니다. 1장에는 이 메시지가 나오는 장면이 없습니다.
