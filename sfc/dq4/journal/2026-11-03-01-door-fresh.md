# 2026-11-03-01: 문 검사 둘의 출발 상태도 검사 롬으로

[08번 일지](2026-11-02-08-fresh-states.md) 에서 장면 검사 열셋의 출발 상태를 검사 롬으로 만들게 옮겼지만, 문 검사 둘은 남아 있었다. `dq4doorcheck` 는 `--state` 를 꼭 받아 손으로 고른 1장 세이브스테이트를 그대로 불러왔고, `dq4doorstandcheck` 는 `--state` 를 주면 같은 빌드인지 보지 않고 썼다. 두 검사도 `dq4freshstate.resolve` 를 거치게 했다. 결과는 [저장 기록 검사](../docs/dq4-savefixture-format.md#검사-롬으로-만든-출발-상태) 에 반영했다.

## 1. 출발 상태

| 검사 | 출발 상태 |
| --- | --- |
| `dq4doorcheck` | 1장 롬의 서장 끝(`dq4freshstate.make`, 롬 SHA-1 별 캐시) |
| `dq4doorstandcheck` | `dq4heroblockcheck.make_base` 의 성 마을 `36/00`(그대로) |

문 칸에 서는 검사는 원래 성 마을 출발 상태를 썼다. 서장 끝·배 선실이 아닌 상태도 같은 곁 파일을 적도록 `resolve` 에 `build` 를 더했다. `build` 가 만든 상태에 롬과 상태 파일의 SHA-1 을 적어, 두 검사 모두 `--state` 에는 같은 롬으로 적은 상태만 받는다. 옛 `work/state/dq4-ch1-field.mss` 를 주면 두 검사 모두 곁 파일이 없다며 불러오기 전에 멈춘다.

도장을 찍으려면 만든 상태가 맞아야 한다. 그런데 `make_base` 는 순간이동 기록에 `arrived map 36/00` 이 없어도 남은 세이브스테이트를 돌려주었다. 캐시에만 넣지 않았을 뿐이다. 그대로 두면 성 마을에 닿지 못한 상태도, 같은 `--out` 에 앞 실행이 남긴 `hub/end.mss` 도 지금 롬의 SHA-1 을 받는다. 그래서 순간이동 전에 `hub/end.mss`·`warp.txt` 를 지우고, `36/00` 도착이 기록됐을 때만 돌려주게 했다. 롬 SHA-1 은 `build` 를 돌리기 전에 읽은 롬 바이트로 적는다. 곁 파일이 막는 것은 실수로 다른 빌드의 상태를 쓰는 일뿐이다. 일부러 다시 적은 곁 파일은 막지 못한다.

`dq4doorcheck` 는 사례가 0개여도(문을 못 찾거나 맵 배치가 바뀌면) 통과로 쳤다. `dq4doorstandcheck` 처럼 사례가 있어야 통과하게 했다. 병렬 기본값도 6 에서 2 로 내려 `dq4doorstandcheck` 와 맞췄다.

## 2. 1장 롬에서 돌린 결과

`dq4build.py --out work/ch1` 의 `dq4-ch1-full.sfc` 로 헤드리스(MesenCE testrunner, 병렬 2) 돌렸다.

| 검사 | 결과 |
| --- | --- |
| `dq4doorcheck` | 통과 22/22(잠금 0 은 열림, 잠긴 문은 열쇠 없이 닫힘·메시지 한 번, 다시 밀면 다시 한 번, 열쇠로 열림) |
| `dq4doorstandcheck` | 통과 20/20(문 칸 우선순위 모두 `30`) |

서장 끝에서 떠나도 순간이동으로 같은 문 옆 칸에 섰고, 실패는 없었다.

## 3. 재발 방지

`test_dq4freshstate.py` 의 expectedFailure 둘을 지우고 두 검사를 옮긴 목록에 넣었다. 옮기기 전 도구에 돌리면 네 항목(두 검사 × 「출발 상태를 `resolve`·`make` 로 만들어야 함」·「`--state` 를 받으면 같은 빌드인지 봐야 함」)이 실패한다. 같은 파일이 `build` 로 만든 상태에 SHA-1 이 적히는지, 문 칸 검사의 `resolve` 에만 `build` 가 있는지도 본다. `test_dq4heroblockbase.py` 는 `make_base` 가 성 마을에 닿지 않은 상태와 앞 실행이 남긴 상태를 거절하는지 본다. 고치기 전 코드에서는 넷 중 셋이 실패했다. `test_dq4door.py` 는 사례가 0개일 때 실패로 치는지 본다. 문 열기 검사는 `guards.toml` 에 `dq4-door-open` 으로 새로 등록했다.
