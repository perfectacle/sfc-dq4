# 2026-10-28-08: 게임 안 예/아니요 창

여관·교회 등에서 뜨는 예/아니요 창 `32` 를 한글로 바꿨습니다. 결과는 [교회·맡기는 곳·예/아니요](../docs/dq4-window-text-format.md#교회맡기는-곳예아니요)에 있습니다.

## 1. 레코드가 두 벌

`32` 는 타이틀 메뉴의 지우기 확인에도 쓰여, [메뉴 패치](../docs/dq4-menu-format.md)가 창 표 칸을 `04:1AC0`(낮은 WRAM)으로 돌려 두었습니다. 메뉴에서는 `60:B000` 의 한글 레코드를, 맵을 불러올 때(`2B:82BD`)부터는 `60:B400` 의 원래 레코드를 `7E:1AC0` 으로 복사합니다. 창 글자 빌드가 창 표로 레코드를 읽으면 WRAM 자리가 나오므로, 그때는 `60:B400 + (자리 − 1AC0)` 의 사본을 읽고 고칩니다. 끝은 `FF 80` 입니다.

```
60:B400  16 05 07 a5 00 02 fe 9e 1a ff fe 9e 1b ff 80 ff 00 | 10 04 06 ... (62)
```

「아니요」 가 네 열이라 너비를 6 에서 7 로 넓혔습니다(x 22 + 7 = 29).

## 2. 시험

선실 세이브스테이트에서 파파스를 여관(대화 번호 `06`)으로 바꾸자, 앞 빌드에서도 예/아니요 창 대신 메시지 창 안에 글자 조각이 보였습니다. 원래 롬과 메뉴 패치 전 롬은 「はい / いいえ」 가 정상이었습니다. 이 세이브스테이트는 맵을 불러오기 전에 저장된 것이라 `7E:1AC0` 에 사본이 없었던 것입니다. `60:B400` 의 48바이트를 `SET` 으로 `7E:1AC0` 에 넣자 앞 빌드는 「はい / いいえ」, 이번 빌드는 「예 / 아니요」 였습니다.

| 시험 | 결과 |
| --- | --- |
| 여관 + `7E:1AC0` 사본 | 「예 / 아니요」, 커서는 「예」 |
| 무작위 입력 6벌 · 이름 검사 셋 · 단위 시험 | 모두 정상 |

## 틀렸던 것들

- 여관의 깨진 화면을 메뉴 패치의 버그로 봤지만, 맵을 불러오기 전 세이브스테이트라 WRAM 사본이 없었던 것이었습니다.

## 남은 것

- 맵을 실제로 불러온 뒤(계단·순간이동)의 예/아니요를 세이브스테이트 없이 확인
- `62`(いいえ/はい)가 게임 안에서 쓰이는지
