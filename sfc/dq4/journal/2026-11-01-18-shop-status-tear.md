# 2026-11-01-18: 가게 동료 창의 「소지 중 ↔ 없음」 이 바뀔 때 깨지던 글자

가게 사기 목록에서 커서를 옮기면 아래 동료 창의 상태가 「소지 중」 과 「없음」 으로 바뀝니다. 바뀌는 순간 「엑소버드 소시[」 처럼 글자가 깨진다는 보고를 받았습니다. 보이는 슬롯에 다른 문구를 덮지 않게 해 고쳤습니다. 명세는 [보이는 슬롯에 다른 문구](../docs/dq4-window-text-format.md#보이는-슬롯에-다른-문구)에 있습니다.

## 1. 재현

옛 이무르 방어구점 세이브스테이트(`dq4-ch1-imuru-armor-party2.mss`)는 지금 롬에 불러오면 화면이 멈췄습니다. `dq4ch1walkcheck.py --until throne_out` 으로 지금 롬의 시작 상태를 만들고, `dq5warp.lua` 에 `TO=37/00,34,8`·`PARTY=05` 를 줘 카운터 앞(셀 34,9)에 세웠습니다.

방어구점 주인을 도구점으로 바꾸려고 대화 번호 표 `06:DBDB` 의 방어구점 칸(`03`, 파일 `35BE1`)을 도구점 처리기 `E01F` 로 덮었습니다. 주인공 소지품에 약초(`A1`)만 넣고 사기 목록에서 약초 ↔ 해독초로 커서를 오르내리니, 전환마다 2프레임이 깨졌습니다.

```
904  ㅂㅂㅂㅂ 소지 중   호이민 없음
905  ㅂㅂㅂㅂ'없음 ㅡ   호이민 없음     ← 깨짐
906  ㅂㅂㅂㅂ'없음 ㅡ   호이민 없음     ← 깨짐
907  ㅂㅂㅂㅂ 없음      호이민 없음
939  ㅂㅂㅂㅂ'소시[    호이민 없음     ← 깨짐(보고와 같은 꼴)
```

## 2. 그림이 타일맵보다 먼저 간다

깨진 프레임은 새 문구의 그림에 옛 문구의 자리 배치가 겹친 모양이었습니다. 「소지 중」 은 「중」 의 받침이 위 줄까지 올라와 다섯 칸을 쓰고, 「없음」 은 그보다 짧습니다. 상태 문구는 같은 버퍼 자리(키)에 다시 그리므로 `WtAlloc` 이 같은 슬롯을 돌려주고, 새 그림은 우리 대기열로 바로 다음 NMI 에 VRAM 에 갑니다. 게임의 창 타일맵 전송(`$0BEC`)은 2프레임 뒤에 갑니다. 그 사이에는 옛 타일맵이 새 그림을 가리킵니다.

## 3. 보이는 동안은 새 슬롯에

슬롯마다 1바이트인 보임 표시 `!wt_vis` 는 bit0 만 쓰고 있었습니다. bit1~7 에 그린 문구의 표식(그림 자리 `!wt_ptr` 의 7비트 해시)을 넣었습니다. `WtAlloc` 은 같은 키의 슬롯이 보이는 중이고 표식이 다르면 그 슬롯을 건너뛰고 새 슬롯을 받습니다. 옛 슬롯은 같은 키로 남깁니다. 게임이 새 타일맵을 보내면 `WtVis` 가 그 키 자리가 새 슬롯의 첫 칸을 가리키는 것을 보고 옛 슬롯을 안 보인다고 표시하고, 옛 슬롯은 다른 그림에 쓰입니다.

내용이 같으면 원래처럼 같은 슬롯에 그립니다. 목록을 다시 그릴 때마다 슬롯을 두 배로 쓰면 가나 칸이 모자라 캔버스 슬롯으로 넘치기 때문입니다.

새 WRAM 이 필요 없게 해시는 보임 바이트의 남은 비트에 두고, 해시를 셀 때만 쓰는 워드는 이름 그리기의 임시값 `!wn_s` 와 함께 씁니다. `7E:3D14`~`3FFF` 는 이미 다 쓰고 있고, `3B60`~`3D13` 은 롬에서 그 주소를 피연산자로 쓰는 바이트를 세어 봐도 「비어 있다」 고 쓰는 `3D14`~ 와 수가 비슷해 가를 수 없었습니다.

## 4. 검사에 규칙을 더함

`dq4windowcheck.py` 의 규칙(가나·비침·덮임)은 이 깨짐을 잡지 못했습니다. 30프레임마다 덤프해서 2프레임짜리 깨짐을 지나치고, 「덮임」 은 캔버스 밖 빌린 슬롯만 봅니다. 규칙 「바뀜」 을 더했습니다. 바로 앞 프레임과 이 프레임 모두 슬롯이 보이고 키 자리의 타일맵 두 줄이 그대로인데 슬롯 그림이 바뀌면 걸립니다. 장면 `shopflip` 은 `--shop` 세이브스테이트로 위 재현을 매 프레임 덤프합니다.

```
고치기 전  shopflip  FAIL 6/230 프레임  904:5칸(바뀜 042), 938:5칸(바뀜 042), 972:5칸 …
고친 뒤    shopflip  PASS 230 프레임
           shopwho   PASS 60 프레임
```

## 틀렸던 것들

- 처음 짠 코드는 고른 슬롯에 표식을 쓰기 전에 `TXA` 로 A 를 덮어, 보임 바이트에 슬롯 번호가 들어갔습니다. bit0 이 틀어지자 보이는 물건 목록 슬롯을 동료 창 문구가 가져가 `shopwho` 의 목록 줄이 「장비 불가」 로 바뀌었습니다. 표식을 슬롯 번호를 센 뒤에 읽게 고쳤습니다.
