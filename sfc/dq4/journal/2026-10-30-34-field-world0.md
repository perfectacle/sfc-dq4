# 2026-10-30-34: FC 필드 0 을 DQ5 세계 0 에

지금까지 새 그룹의 필드 입구는 DQ5 세계 지도의 빈 들판 (341,56) 둘레에 임시로 두었습니다. 이번에는 FC 필드 0 의 지형을 DQ5 세계 0 에 넣고, 입구를 FC 의 입구 자리로 옮겼습니다. 결과는 [dq4-field-format.md](../docs/dq4-field-format.md)에 있습니다.

## 1. 블록 고르기

FC 필드 0 은 블록 22종입니다. DQ5 세계 0 의 블록 511개를 지형 니블(`03:CC48`)과 타일 속성(`2A:D512`)으로 나누고, 세계 0 에서 쓰인 칸 수로 줄을 세웠습니다. 지형 0 은 바다(속성 `80`), 1 은 메마른 땅(`4C`), 2 는 언덕(`43`), 3 은 산(`82`), 6 은 풀밭(`4A`), 7 은 숲(`4B`), C 는 마을·성·동굴(`45`)이었습니다. 후보 블록을 롬의 필드 타일과 낮 팔레트로 그려 보고 그림이 맞는 것을 골랐습니다. 덤불은 작은 나무 블록 366, 암초는 바다 위 바위 블록 1(지형 8, `81`), 팻말은 블록 21(`96`~`98`), 다리는 블록 22(`4E`)가 있었습니다.

DQ5 의 마을 그림 블록은 입구 뜻이 없습니다. 입구는 좌표 표로만 정하므로(`2A:F247`), FC 입구 블록은 그림이 비슷한 지형 C 블록에 두고 입구는 표로 겁니다.

## 2. 지도 넣기

FC 블록 (x, y) 를 DQ5 블록 (x, y) 에 두었습니다. FC 디코더의 격자는 253×253(0~2 줄·칸은 바다)이고 DQ5 세계는 256×256 이라 남는 곳은 바다입니다. 블록 번호가 모두 512 아래라 `dq5fieldwrite.py` 가 10번째 비트 평면을 만들지 않고, 그 경우에는 상자 패치가 옮기는 밤에 빛나는 풀 칸을 읽지 않습니다. 그래서 원래 롬에서 만든 패치를 그대로 씁니다. 압축한 두 덩어리(4,094·10,445바이트)는 이 빌드에서 빈 뱅크 `3A` 에 들어갔습니다.

## 3. 입구

FC 에서 입구 블록에 들어서면 들어갑니다. DQ5 는 8픽셀씩 걸어서, 원래 롬의 필드 (341,56)에서 오른쪽으로 10·14·18·26·34프레임 누르자 342·343·343·344·345 에 섰습니다. 입구 하나를 한 칸에만 두면 옆 칸으로 지나칠 수 있으므로 블록의 네 칸을 모두 입구로 넣었습니다.

FC 의 두 칸짜리 성·동굴 오른쪽 반(속성 `07`)이 입구인지는 FC 에서 쟀습니다. バトランド 성 오른쪽 반 (A5,2E) 아래에서 위로 걸으니 `02/00` 에 들어가며 `$42` 가 `A4` 였고, 동굴 오른쪽 반 (8E,1B)도 `41/00` 에 들어가 `$42` = `8D` 였습니다. 오른쪽 반도 입구로 넣었습니다.

古井戸の底(`1C`)의 입구 (A2,1A)는 그림 없는 숲 블록이었습니다. 처음에는 입구 블록이 속성 `06` 이어야 한다고 막았다가 빌드가 멈췄습니다. FC 입구는 좌표 표로 정해지므로 그 검사를 뺐습니다.

나오는 자리는 입구 옆 블록입니다. 탑 `30` 은 작은 섬에 있어 아래가 바다라 왼쪽 풀밭에 세웁니다.

## 4. DQ5 원래 입구

DQ5 마을 입구가 FC 땅 위에 남으면 그 칸에서 DQ5 마을로 들어갑니다. 세계 0 에서 들어가는 항목 53개(일반 41, 보조 12)를 FC 지도 밖에 만든 3×3 산섬 가운데로 옮겼습니다. 항목을 지우지 않은 것은 ルーラ 행선지 그룹이 표에 꼭 있어야 하기 때문입니다.

## 5. 검사 고치기

`dq4groupcheck.py` 의 들어가기 장면은 필드 (341,56) 세이브스테이트에서 그룹마다 정한 길로 걸었습니다. 이제 입구가 FC 자리라 `FIELD` 워프로 입구 옆에 섭니다. `FIELD` 는 원래 입구 표의 그룹 `01` 항목을 덮는데 이 빌드는 그 표를 `3C:8000` 으로 옮기므로, 옮긴 표의 같은 항목을 덮는 `ROMPATCH` 를 함께 줍니다. 입구 블록마다 걸을 수 있는 이웃의 두 줄(열)에서 한 칸씩 걸어, 66장면이 모두 그룹 도착에 섰습니다.

새 검사 `dq4fieldcheck.py` 는 필드에 서서 WRAM `7F:0000`·`7E:E000` 이 넣은 지도와 같은지 보고(같음), 블록 종류 열한 가지에 걸어 들어갑니다. 바다·산·암초·팻말은 막혔고 풀·언덕·덤불·숲·사막·독늪·다리는 들어갔습니다.

## 6. 1장 통합 롬

검토에서 1장 빌드(`dq4chapter1.py build`)가 깨진다는 지적을 받았습니다. 1장 빌드는 새 맵 레코드를 `3A:8000` 으로 돌린 채 그룹 빌드를 부르는데, 필드 지도도 `3A:8000` 이라 그 안의 `dq5build` 가 겹침으로 멈췄습니다. `3A` 에는 레코드(약 24KB) 뒤 서장 대화(`3A:F000`)까지 남은 자리가 약 3.9KB 라 지도가 들어가지 않습니다. 메뉴 롬을 문서의 차례대로 만들어 `30`~`3F` 에서 0 이거나 원래 롬 `20`~`2F` 의 거울인 구간을 찾으니, 타이틀 자료가 끝난 `34:BFD2`~`34:FFFF` 가 16,430바이트였습니다. 1장 빌드는 지도를 `34:C000` 에 둡니다. 1장 빌드가 얹는 패치 목록에 입구별 도착 훅이 없었던 것도 더했습니다. 훅이 없으면 엔진이 보조 입구 (X, Y+1) 에 세우는데, 그 칸이 입구 블록의 다른 칸입니다.

서장을 켠 빌드(`--prologue`)와 켜지 않은 빌드 모두 롬이 나왔습니다. 1장 롬에서 `dq4fieldcheck.py` 12장면이 모두 지났습니다(WRAM 지도도 같음). `dq4groupcheck.py --groups 36` 은 들어가기 12장면·나가기·머무르기·영역 이동이 모두 지났고, 나가면 (328,95)에 섰습니다. 왕좌의 방 `36/01` 의 계단 하나는 1장 인물이 막아 40번의 시작 모두 오르지 못했습니다. 이 검사는 원래 인물을 뺀 롬에서 돌리는 것이라 필드와는 상관없습니다.
