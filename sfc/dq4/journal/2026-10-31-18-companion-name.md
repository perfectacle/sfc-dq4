# 2026-10-31-18: 동료 이름 「호이민」

1장에서 합류하는 호이민의 이름이 상태 창·전투 메시지에 가나 「ホイミン」 으로 나왔습니다. 이름 표 `0A` 의 그 칸을 이름 입력과 같은 한글 표시 바이트로 바꿔, 창·전투·필드 메시지 모두에서 「호이민」 으로 찍게 했습니다. 명세는 [1장 첫머리의 「우물 아래와 호이민」](../docs/dq4-chapter1-format.md#우물-아래와-호이민)에 있습니다.

## 1. 어디를 고칠까

이름이 찍히는 길은 셋입니다. 창(상태 창·「누구」 목록·전투 상태 창)은 `WnName`·`WnList` 가, 전투 메시지는 `WnBattle` 이, 필드 메시지는 `24:A7B6` 이 이름 바이트를 받습니다. 셋 모두 첫 바이트가 한글 표시 바이트(`85`~)면 한글로, 아니면 가나로 찍습니다. 주인공 이름이 한글로 나오는 것도 이 덕분입니다.

가나 이름마다 한글 짝을 셋에 따로 넣는 방법도 있었습니다. 하지만 `21:955D` 가 이름 표에서 읽어 오는 바이트 자체를 한글 표시 바이트로 두면, 세 길이 모두 주인공 이름처럼 찍습니다. 조사도 받침을 보고 고릅니다. 호이민은 종류 `05` × 4 + 이름 번호 0 = 칸 `14` 입니다. 「호이민」 은 `99 69 93 3C 8D 46` 으로, 가나 넉 자(`5F 43 61 6F`)보다 2바이트 깁니다.

## 2. 표에 자리가 없다

그룹 빌드의 이름 문서에 표 `0A` 를 더하자 `dq5namewrite` 가 거부했습니다.

```
오류: 23:C242 자리에 2바이트가 넘침; --at 으로 옮겨야 함
```

`23:C242`~`D6A0` 은 표 여덟이 빈틈 없이 이어진 곳입니다. 표를 통째로 옮기면 다른 도구(`dq4battlemsg`·`dq4windowtext`)가 표를 원래 자리에서 읽는 전제가 깨집니다. 그래서 같은 표 안에서 2바이트를 덜었습니다. 칸 `0`~`3` 은 종류 `00` 자리이고, 동료 종류는 `01` 부터라 쓰이지 않습니다. 칸 `0` 「ボロンゴ」(`84 5F 6C 6F 84 4B`)의 끝 2바이트를 뺐습니다.

다시 빌드하자 이번에는 겹침이 났습니다.

```
겹침 23:CE17~23:CE1B:
  names writes[0] 23:C242 이름 문자열 표
  dq4-inns-shop-keys writes[6] 23:CE17 물건 01 이름 てつのやり
```

`dq5namewrite` 는 한 문서의 바뀐 바이트를 첫 자리부터 마지막 자리까지 한 덩어리로 씁니다. 같은 문서에 표 `0B`(ルーラ 목록, 맨 끝 표)가 있으니, 덩어리가 표 `0A` 에서 `0B` 까지 이어져 그 사이에서 가게 열쇠 패치가 고친 물건 이름을 덮었습니다. 표 `0A` 는 따로 문서(`companion-names`)로 만들었습니다. 그 덩어리는 표 `0A` 칸 `0`~`14` 안에서 끝납니다. 1장 롬은 그룹 빌드의 패치를 이름 목록으로 골라 얹으므로(`dq4chapter1.GROUP_PATCHES`) 거기에도 더했습니다. 처음에는 이 목록을 빠뜨려 롬의 칸 `14` 가 그대로 가나였습니다.

## 3. 실측

1장 롬에서 탑 위 `39/04` (46,22)로 순간이동해 호이민을 넣고(`PARTY=05`, 기록 `+0` = `C5`) 헤드리스 MesenCE 로 쟀습니다.

```
LIBDIR=$LIBDIR SHOT_DIR=... STATE=... TO="39/04,46,22" LATESET="31E0=88;206A=C5" PARTY="05" SAVE=top.mss \
  $MESENCE --testrunner 롬 sfc/dq5/tools/lua/dq5warp.lua
```

| 장면 | 결과 |
| --- | --- |
| 롬의 표 `0A` | 칸 `0` = `84 5F 6C 6F`, 칸 `14` = `99 69 93 3C 8D 46` |
| 필드 명령 창 | 상태 창 「ああああ 호이민」 |
| 「주문」 → 「누구」 목록에서 호이민 | 목록 「호이민」, 필드 메시지 「호이민은 이동 중에 쓰는 주문을 익히지 않았다.」 |
| 보스에게 말을 걸어 전투 | 전투 상태 창 「호이민」, 「호이민의 공격!」·「큰 눈알에게 2의 데미지!!」 |

받침이 있는 「민」 뒤에서 필드 메시지는 「은」, 전투 메시지는 「의」 를 골랐습니다.

## 틀렸던 것들

- 이름 문서 하나에 표 `0A`·`0B` 를 함께 넣으면 된다고 봤습니다. 한 문서가 한 덩어리로 써서 그 사이 물건 이름과 겹쳤습니다.

## 남은 것

- 「호이민이」 처럼 받침 「이/가」 를 고르는 필드 메시지는 따로 띄워 보지 않았습니다(같은 조사 코드라 「은」 과 같은 길).
- 호이민의 다른 이름 번호(スラッポ 등 칸 `15`~`17`)는 가나 그대로입니다. 1장 합류는 이름 번호 0 만 씁니다.
