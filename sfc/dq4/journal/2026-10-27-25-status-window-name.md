# 2026-10-27-25: 상태 창에 한글 이름 찍기

필드·전투 상태 창의 주인공 이름이 「크리프트」 → 「やrり」로 깨지던 것을 Galmuri9 한글로 찍었습니다. 이름 칸은 사용자 결정대로 4칸에서 5칸으로 넓혔습니다. 결과는 [상태 창 이름](../docs/dq4-window-text-format.md#상태-창-이름)에 있습니다.

## 1. 깨지는 까닭과 넓히는 자리

이름은 8바이트(한글 넉 자, `7E:2001`~)인데 `04:ABCF` 는 앞 4바이트를 그대로 BG3 타일 번호로 찍습니다. Galmuri9 한글은 한 자 10점이라 넉 자에 40점, 5칸이 필요합니다.

창 `02` 의 머리 너비만 6 → 7 로 바꾸면 아무 일도 없었습니다. 일행 열 창은 사람이 하나 늘 때마다 `04:A394` 가 너비 +5, `04:A3A4` 가 x −5 를 하고, 내용 열은 `04:B18E` 가 10바이트씩 옮깁니다. 세 상수를 6·6·`0C` 로 바꾸자 일행 3명 창이 사람마다 6칸으로 섰습니다. 너비 6 일 때만 이름 출력으로 가던 지름길 `04:AB58 CMP #$06` 도 7 로 바꿨습니다.

## 2. 렌더러

`04:ABCF` 를 뱅크 `60` 의 `WnName` 으로 돌렸습니다. 한글 표시 바이트면 이름 입력이 넣은 글리프(뱅크 `62`~`64`) 넉 자를 10점 간격 띠에 겹치고, 이름 줄 5칸과 위 테두리 줄 5칸을 BG3 칸 `180`~`1CF` 에 그려 NMI 전송 목록으로 올립니다. 글자 높이 9점 가운데 맨 윗줄은 위 테두리 타일(`8D`)의 7줄째에 합성합니다. 테두리 그림은 롬 `04:E978`~ 에서 읽습니다.

## 3. 처음 돌렸을 때 멈춤

어셈블은 됐지만 B 를 누르자 게임이 멈췄습니다. 역어셈블해 보니 `REP #$30` 구간의 `SBC #!wn_hi_base` 가 `e9 85`(8비트 즉치)로 들어가 그 뒤 명령이 한 바이트씩 어긋나 있었습니다. asar 는 즉치의 너비를 값 크기로 정합니다. 16비트 구간의 작은 즉치 셋에 `.w` 를 붙였습니다.

```text
60:C032  e9 85 c9     SBC #$C985   ← 16비트 CPU 가 읽는 모양
60:C032  e9 85 00     SBC #$0085   ← .w 를 붙인 뒤
```

## 4. 세이브스테이트의 BG3 자리

멈춤은 없어졌지만 이름 칸이 줄무늬였습니다. VRAM 덤프에서 BG3 타일맵이 아직 바이트 `3800`(워드 `1C00`), 곧 타일 `180`~`1FF` 자리에 있었습니다. 세이브스테이트가 BG3SC 를 옮기기 전 값을 갖고 있어서입니다. `dq5warp.lua` 로 09/00 에 순간이동해 맵을 다시 불러온 상태를 저장하고, 그 상태에서 시험했습니다.

## 5. 처음 연 창의 이름 칸

다시 불러온 상태에서도 처음 연 창은 이름 칸이 옛 VRAM 내용이었고, 닫았다 다시 열면 바르게 나왔습니다. 목록 항목 수 `7E:0758` 과 `$1A` 쓰기를 감시했습니다.

```text
f39 WnUpload cnt=0 off=0000
f39 w7E0758=01 pc 60:C2EF
f39 w00001A=80 pc 60:C2F3
f40 w00001A=20 pc 04:9D4B
f41 w00001A=00 pc 00:8DED
```

항목 수는 1 에서 내려오지 않았고, 붙인 바로 다음 프레임에 `04:9D41`~`9D49` 가 `$19` 워드를 `AND #$7FFF` 로 다시 써서 `$1A` bit7 을 지웠습니다. 이 게임에서는 목록을 붙인 쪽이 곧바로 NMI 를 기다려야 합니다. 이름 입력이 `JSL 00:958A` 를 부르는 까닭이 이것이었습니다. 같은 호출을 넣자 첫 프레임부터 이름이 바르게 나왔습니다.

## 틀렸던 것들

- 이름을 `POKE=2001=…` 로 넣었다가 화면이 바뀌지 않았습니다. 뱅크 없는 `2001` 은 00:2001 이라 WRAM 미러 밖입니다. `7E2001` 로 써야 합니다.
- `dq5warp.lua` 의 `SAVE` 에 절대 경로를 주면 `SHOT_DIR` 뒤에 붙어 열기에 실패하고 스크립트가 멈춥니다. 파일 이름만 줍니다.
- 처음 본 줄무늬를 업로드 코드의 오류로 의심했지만, 하나는 세이브스테이트의 옛 BG3 자리, 하나는 NMI 를 기다리지 않은 탓이었습니다.
