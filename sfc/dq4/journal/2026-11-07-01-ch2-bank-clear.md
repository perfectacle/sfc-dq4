# 2026-11-07-01: 2장으로 넘어갈 때 맡긴 것 비우기

1장에서 맡기는 곳에 맡긴 물건과 금화가 2장 아리나에게 그대로 남아 있었다. FC 는 장이 바뀌면 가방과 맡긴 돈을 비운다. 2장 넘김 코드가 같은 일을 하게 했다. 결과는 [2장 「1장 끝에서 옮기기」](../docs/dq4-chapter2-format.md#1장-끝에서-옮기기)에 있다.

## 1. FC 는 무엇을 비우나

FC 장 초기화 `12:$8EAE` 는 끝에서 `BRK 05 5F`(`15:$B39C`)를 부른다. 이 함수는 가방 `$61DB`~ 128칸과 맡긴 돈 `$625B`/`$625C` 를 비운다. FC 의 맡기는 곳은 물건을 이 가방 칸에 넣으므로, 맡긴 물건도 함께 사라진다. 1장 끝 조건을 켜고 가방 `53 06 FF`, 맡긴 돈 5 를 써 둔 뒤 넘기면 2장 시작에 `$61DB` = `FF`, 맡긴 돈 `00 00` 이었다([FC 가게 문서](../../../fc/dq4/docs/dq4-shop-format.md)). 손에 든 금화는 장마다 표(`12:$91D9`, 2장 100)로 다시 둔다. 이 롬은 이미 100 으로 두고 있었다.

## 2. 이 롬에서의 자리

이 롬은 DQ5 맡기는 곳을 그대로 쓴다. 맡긴 물건은 `7E:2250 + 물건 번호` 에 개수 한 바이트씩이고, 찾기 목록은 번호 `00`~`DF` 를 훑는다. 맡긴 금화는 `7E:203A`(1000G 단위)다. 넘김 코드 `_transfer` 에 둘을 비우는 줄을 넣었다.

```
A9 00 00     LDA #$0000
8F 50 22 7E  STA $7E2250        ; 첫 두 칸 0
A2 50 22     LDX #$2250
A0 51 22     LDY #$2251
A9 DE 00     LDA #$00DE
54 7E 7E     MVN $7E,$7E        ; 한 칸 뒤로 베껴 2251~232F 까지 0 을 민다
A9 00 00     LDA #$0000
8F 3A 20 7E  STA $7E203A        ; 맡긴 금화
```

`2332` 부터는 DQ5 맡긴 동료 칸이고, 이 롬은 그 자리에 전투 글자 사본을 둔다. 비우는 범위는 `232F` 에서 끝난다.

## 3. 확인

- 단위 테스트(`test_dq4ch2event.TransferTest`): 넘김 코드에서 위 바이트를 찾아 A 16비트에서 도는지 보고, 흉내 낸 WRAM 에서 `2250`~`232F` 와 `203A`~`203B` 만 0 이 되는지 본다.
- 2장 걷기 검사의 머리: 1장 `castle` 첫머리에 やくそう 3 개(`22F1` = 3)와 금화 2000(`203A` = 2)을 맡겨 두고 1장 끝을 걸었다. `castle` 끝에는 두 바이트가 0 이 아니었고(`BANK_HERB`·`BANK_GOLD` 켜짐), 넘김을 지난 `king` 끝과 `opening` 끝에는 둘 다 0, 아리나 물건 칸은 `62 FF …`(비단 로브)이었다. 뒤 사건 묶음 여섯도 두 번 걸어 기록이 같았다.

## 남은 것

- 고치기 전 롬으로 같은 머리를 걸어 맡긴 것이 남는지 대조하지는 않았다(넘김 앞 `castle` 끝과 뒤 `king` 끝의 값으로 보았다).
- 1장 도중 저장한 기록을 2장 롬에서 불러올 때는 넘김을 타지 않는다. FC 도 장 중간 기록을 불러올 때 장 초기화를 타지 않는다.
