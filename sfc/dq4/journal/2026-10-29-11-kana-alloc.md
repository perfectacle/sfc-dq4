# 2026-10-29-11: 가나 칸을 이름 길이만큼

가나 칸 슬롯을 고정 크기로 나눠 두면, 메시지와 함께 뜨는 가게 목록에 9열 이름이 여럿일 때 큰 슬롯이 모자라 캔버스로 넘쳐 메시지 창에 비쳤습니다(깨짐 검사의 무기점 `01`). 가나 칸 104칸을 이름 길이만큼 잘라 쓰게 바꿨습니다. 결과는 [가나 칸을 길이만큼](../docs/dq4-window-text-format.md#가나-칸을-길이만큼)에 있습니다.

## 1. 설계

캔버스 안 고정 슬롯 18개는 그대로 두고, 가나 칸만 항목 12개로 나눴습니다. 항목마다 첫 칸과 칸 수를 RAM 에 두고, 그릴 때마다 살아 있는 항목으로 104칸 점유 비트맵을 만들어 처음부터 빈 연속 칸(열 수 × 2)을 찾습니다. 글자 줄은 첫 칸부터, 위 줄은 첫 칸 + 열 수부터라 고정 슬롯과 같은 배치를 그대로 씁니다. 자리가 없으면 「보임」 표시가 꺼진 항목 가운데 가장 오래된 것을 비우고 다시 찾고, 그래도 없으면 캔버스 슬롯으로 갑니다. 보이는 항목은 밀어내지 않습니다.

## 2. 처음 짠 코드의 버그

적용 전에 다시 읽어 셋을 고쳤습니다. 이어 빈 칸 수를 0 으로 시작하지 않았고, 비트 표를 `AND.w 표,Y` 로 읽었는데 그때 DB 가 `7E` 라 엉뚱한 곳을 읽었으며, 비트맵을 비우는 고리가 바로 뒤 임시 변수까지 썼습니다.

## 3. 확인

깨짐 검사에서 무기점 `01` 이 통과하고, 대신 무작위 입력 `battle12` 가 새로 걸렸습니다. 쓰러진 동료 「スラリン」(분홍)의 이름이었고, 색을 입히는 길 `WnNameAttr` 가 가나 이름을 받지 않아서였습니다. 고친 뒤 남은 것은 시험용 가게 `08` 하나입니다.

| 장면 | 결과 |
| --- | --- |
| 물건 여덟 개 팔기 목록 | 메시지 창에 비치지 않음(#599 는 「ブロンズ…」 가 비침) |
| 장비 비교 창 | #599 와 같은 프레임 같은 화면 |
| 무작위 입력 6벌 · 이름 검사 셋 · 단위 시험 · 전투 가나 복원 | 정상 |

## 남은 것

- 시험용 가게 `08`(9열 이름 여덟 = 144칸)은 가나 칸 104칸에 들어가지 않아 캔버스로 넘쳐 비침
- 창 열 수를 넘어 가나 대체가 없는 DQ5 이름(「じごくのサーベル」)은 필드에서 깨짐
