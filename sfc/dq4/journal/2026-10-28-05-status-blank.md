# 2026-10-28-05: 강함 보기의 빈 주문 칸과 라벨

강함 보기(つよさみる) 라벨을 한글로 바꾸려다, 그 화면의 다른 문제 하나를 고쳤고 라벨은 미뤘습니다. 결과는 [주문 목록](../docs/dq4-window-text-format.md#주문-목록)과 [남은 것](../docs/dq4-window-text-format.md#남은-것)에 있습니다.

## 1. 빈 주문 칸의 「슬라임」

일행 셋(09/00)에서 강함 보기 2쪽을 열면, 주문이 없는 주인공의 「전투 주문」 창에 「슬라임」·「노송나무 막대」 같은 조각이 보였습니다. #582·#583 롬도 같았습니다. 2쪽 창은 주문 목록 길(`04:B8F3`)인데, 주문이 없는 칸은 이름을 받지 않고 빈칸 문자열(`01`)을 찍습니다. `WnSpell` 은 그때 `$42`·`$43` 에 남아 있던 번호(몬스터 표 0번 「スライム」 등)로 그림을 그렸습니다. 찍을 문자열 첫 바이트가 `01` 이면 원래 길로 넘기자 빈 창이 됐습니다.

## 2. 라벨을 미룬 까닭

능력치 창 `07` 은 줄 머리 빈칸 + 가나 + `85`(:) 꼴의 오른쪽 정렬 라벨입니다. 빈칸과 가나를 빈칸 + `9E k` 로 바꾸는 규칙을 더하자 「힘 / 민첩 / 방어력 / 현명함 / 운 / 최대HP …」 가 맞게 나왔습니다. 그런데 1쪽 오른쪽 창의 「공격력」 아래(수비력·Ex·아래 테두리)가 그려지지 않았습니다.

| 시험 | 결과 |
| --- | --- |
| 라벨 없음(#583, 빈칸 수정만) | 끝까지 그려짐 |
| `06` 라벨 둘만 | 아래가 빠짐 |
| `07`·`06` 라벨 | 아래가 빠짐 |
| 버퍼 `7E:5000` 과 VRAM 견줌 | 버퍼는 맞음, VRAM 20번째 줄부터 옛 내용 |
| 대기열을 NMI 를 끄지 않는 꼴로(쌍 수를 `INC` 한 번, NMI 맨 앞 `00:8872` 에서 보냄) | 같음 |
| NMI 마다 보내는 양을 256바이트로 | 같음 |

라벨 수가 아니라 라벨을 하나라도 그리면 생겨서, 이번에는 바꾸지 않았습니다.

## 틀렸던 것들

- 라벨이 많아 대기열이 차고 기다리는 동안 게임 전송이 빠진다고 봤지만, 라벨 둘만 그려도 같았습니다.
- `WtQueue` 가 NMI 를 끄는 동안 VBlank 가 지나가 NMI 가 늦게 도는 탓이라고 봤지만, 끄지 않게 바꿔도 같았습니다.

## 남은 것

- 강함 보기 라벨: 게임이 창 아래쪽 타일맵을 언제 VRAM 으로 보내는지(`00:8E55`·`8E75` 의 줄 전송 요청)를 실측해야 함
- 강함 보기 2쪽 오른쪽 창 제목이 「강함」 으로 남음
