# 2026-10-27-15: 게임 안 BG3 타일맵을 빈 VRAM 자리로 옮기기

게임 안 창에 한글 타일을 넣을 칸이 모자라, BG3 타일맵이 차지하던 글자 칸 `180`~`1FF` 128칸을 비웠습니다. 타일맵을 장면마다 비어 있는 VRAM 자리로 옮깁니다. 자리 표와 바꾼 곳은 [BG3 타일맵 옮기기](../docs/dq4-window-text-format.md#bg3-타일맵-옮기기)에 있습니다.

## 1. 자리 고르기

DQ5 트랙이 실내 맵 363개의 VRAM 칸 쓰기를 잰 결과([48번 일지](../../dq5/journal/2026-10-26-48-bg3slot.md))가 출발점이었습니다. 실내 맵은 `4800` 대를 쓰지 않고, 필드는 `7800` 을 쓰지 않습니다. 전투를 따로 재 보니 실내 전투는 `3C00` 을 한 번도 쓰지 않았고, 다른 자리는 거의 다 썼습니다.

그래서 필드는 `7800`, 실내 맵은 `3C00` 에 두었습니다. 맵을 불러오며 `3C00` 을 쓰는 실내 맵은 9개였습니다. 그 가운데 `7800` 을 쓰지 않는 3개는 `7800` 에, 둘 다 쓰는 마을 6개는 `4800` 에 둡니다. 마을에서 전투가 시작되면 `7800` 으로 옮깁니다. 전투가 끝나면 엔진이 맵을 다시 불러오므로 자리도 맵 규칙대로 돌아옵니다.

## 2. 전투 중에는 화면이 꺼지지 않음

처음에는 전투 시작에서 바로 새 자리에 타일맵을 써 넣었습니다. 그러나 전투 중에는 `$2100` 이 `0F` 라 vblank 밖의 VRAM 쓰기가 버려졌습니다. 타일맵을 보내는 DMA(`00:8E1F` 전체 2KB, `8E55`·`8E75` 위·아래 줄)는 모두 vblank 에서 돕니다.

그래서 바라는 자리(`$0725`)와 지금 `$2109` 에 든 자리를 따로 두었습니다. 둘이 다르면 다음 전체 DMA 가 도는 vblank 에서 `$2109` 를 바꾸고 새 자리로 보냅니다. 타일맵 주소를 즉값 `1C00` 대로 쓰는 나머지 곳(`04:9849`, 전투 창 줄 주소 `22:8B4D` 등)은 지금 자리 기준으로 다시 계산합니다.

## 3. 마을 전투의 전환

마을 6곳은 조우가 없어, 09/00 을 `4800` 목록에 넣은 시험 롬으로 전투를 일으켰습니다. 처음에는 전투 시작에서 `$0725` 만 바꾸고 다음 전체 DMA 에서 자리를 바꿨습니다. 그러자 전환까지 약 40프레임 동안 BG3 에 검은 칸과 점이 보였습니다. 전투 시작 직후 VRAM 을 1K 워드 자리마다 재 보니, 전투는 16프레임 안에 `4000`~`6000` 을 썼습니다. 아직 화면에 걸린 `4800` 에 전투 그림이 들어간 것입니다. `3C00` 과 `6400`~`7C00` 은 전투 동안 쓰지 않았습니다.

보내기 요청 `$0BEC` 에 `80` 을 넣어도 전체 DMA 는 앞당겨지지 않았습니다. 그래서 전투 시작 훅에서 NMI 를 끄고 새 vblank 를 기다립니다. 화면을 끈 채 버퍼를 `7800` 에 올리고 `$2109` 를 바꾼 뒤, `$2100`·`$4200` 을 게임의 그림자 `$1D`·`$1E` 로 되돌립니다. 그 프레임의 NMI 는 건너뜁니다. 시험 롬의 전환 프레임이 원래 롬과 같아졌습니다.

## 4. 새 자리 채우기

맵을 불러올 때 원래 타일맵 지우기(`04:983E`)는 자리를 고르기 전에 옛 자리에서 일어납니다. 그대로 두면 필드에 들어갈 때 새 자리에 남은 앞 장면 그림이 창이 다시 그려질 때까지 보였습니다.

처음에는 새 자리를 0 으로 채웠습니다. 실내 364맵을 돌려 보니 02/08·06/00·17/00·1F/00·1F/01 에서 화면 타일맵이 끝까지 0 으로 남았습니다. 버퍼 `7E:5000` 에는 빈 칸 타일 1024바이트가 그대로 있었습니다. 이 맵들은 불러온 뒤 타일맵 전체를 다시 올리지 않습니다. 0 대신 버퍼를 올리도록 바꾸자 다섯 맵 모두 원래와 같은 화면이 됐습니다.

## 5. 검사

`dq4bg3slotcheck.py` 로 원래 롬과 새 롬을 실내 364맵에서 돌렸습니다.

```
363맵 도착(17/00 은 원래 롬에서도 못 감)
끝 프레임 vsbuf  원래·새 롬 모두 362맵 0, 29/00 만 둘 다 2
옛 자리 old      모든 맵·모든 기록 0
끝 화면 다름     세 번 돌려 44·38·33맵(A 입력 시점·애니메이션 차이)
```

끝 화면이 다른 맵을 열어 보면 같은 A 입력에 명령 창이 뜬 쪽과 「めいれいさせろ」 창이 뜬 쪽이 갈렸고, 두 롬 모두 창이 온전했습니다. 원래 롬끼리 돌려도 21맵 중 8맵이 달랐습니다.

조우율을 올린 실내 09/00 과 필드 04/0B 에서 싸워도 창이 원래대로 나왔고, 옛 자리 `1C00`~`1FFF` 는 바뀌지 않았습니다.

독립 리뷰에서 맵을 불러올 때 말고도 `$2109` 를 직접 쓰는 코드가 여럿 있다는 지적을 받았습니다. 실행 감시를 걸어 보니 위 필드·실내·전투 시험에서는 한 번도 돌지 않았습니다. 특수 화면 효과를 끝내며 즉값 `1C` 로 되돌리는 세 곳(`03:F3A9`·`03:F54D`·`22:E71B`)만 지금 자리로 되돌리게 고쳤습니다. 맵을 불러오며 새 자리를 채우는 DMA 7 은 NMI 전송 목록과 채널을 같이 씁니다. 그 순간 NMI 가 꺼져 있고 화면도 꺼져 있음을 MesenCE 상태로 확인했습니다.

MesenCE lua 의 메모리 쓰기 콜백은 VRAM 에 걸리지 않았습니다(원래 롬에서도 0번). 옛 자리 쓰기는 자리를 떠날 때 찍어 둔 내용과 견주는 방식으로 쟀습니다.

## 남은 것

- 비운 `180`~`1FF` 에 한글 타일을 그려 넣기
- `$2109` 를 직접 바꾸는 특수 장면(맵 17 의 mode 2 효과, 전투 뱅크의 32×64 BG3, mode 7 장면) 실측
- 마을 6곳의 실제 이벤트 전투
