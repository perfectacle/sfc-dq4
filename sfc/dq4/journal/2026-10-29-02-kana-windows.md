# 2026-10-29-02: 가나가 남은 창

가나 칸을 필드 슬롯으로 쓰고 나니, 본문에 가나가 남은 창은 필드에서 뜨면 깨집니다. 그런 창 여섯 개를 고정 문구로 바꾸고, 가나 칸 슬롯 배분을 메시지와 함께 뜨는 창에 맞췄습니다. 결과는 [가나 칸 슬롯](../docs/dq4-window-text-format.md#가나-칸-슬롯)에 있습니다.

## 1. 어느 창이 뜨나

선실 파파스의 대화 번호(`7E:36EB`)를 `00`~`3F` 로 바꿔 가며 A 를 25번 누르고, 창을 여는 `04:9C52` 를 지날 때의 A 를 모았습니다. A 는 창 번호가 아니라 레코드 주소라, 처음에는 주소 낮은 바이트를 창 번호로 잘못 읽었습니다. 창 표 `04:EB48` 로 주소를 창 번호로 되돌리니 다음과 같았습니다.

```
07: 00 32 59        동료 맡기는 곳(あずけにきた …)
0A: 00 32 75        ルイーダ(なかまをくわえる / はずす)
2E: 17 18 1B 1E 25 26 3C 87   전투
```

정적으로 훑은 창 가운데 `59`·`75` 가 열렸고, `4B`(つかう / そうび)·`4E`(たからばこ / アイテム)·`77`(기록)·`7E`(いれかえ / そうがえ / みる)는 열리는 장면을 찾지 못했습니다. 넷도 문구만 더하면 되므로 함께 바꿨습니다.

## 2. 문구

| 창 | 한글 |
| --- | --- |
| `59` | 맡기기 / 데려가기 / 상태 보기 / 헤어지기 / 그만 |
| `75` | 동료 넣기 / 동료 빼기 |
| `4B` | 쓰기 / 장비 |
| `4E` | 보물상자 / 아이템 |
| `77` | 모험의 서에 기록 / 이야기를 계속한다 |
| `7E` | 바꾸기 / 모두 바꾸기 / 보기 |

`59` 는 창 안쪽이 8열이라 「헤어지러 왔다」(10열)가 들어가지 않아 짧게 했고, `7E` 는 「모두 바꾸기」 가 들어가게 두 칸 넓혔습니다. `77` 첫 줄은 「ぼうけんのしょに　キロクする」 로 가나 덩이 사이에 빈칸이 있어, 레코드 고쳐 쓰기가 항목 머리 `FE` 바로 뒤 덩이만 바꾸고 「キロクする」 를 남겼습니다. 같은 줄에서 앞 문구 뒤 빈칸 다음에 오는 가나 덩이도 문구로 바꾸게 했고, 바뀐 롬 바이트는 `77` 레코드와 글자 그림 뱅크뿐이었습니다.

## 3. 메시지 안에 비친 「헤어지기」

`59` 를 띄우자 메시지 창 오른쪽 아래에 「헤어지기」 가, 왼쪽 아래에 깨진 무늬가 보였습니다. 타일맵을 덤프하니 다섯 문구 가운데 「헤어지기」 가 캔버스 안 중간 슬롯 `160` 에 있었습니다. 중간 문구(5~7열)가 셋인데 가나 칸 중간 슬롯은 둘뿐이었습니다.

```
줄 3  010 011 012 013        맡기기   (가나 작은)
줄 5  030 … 035              데려가기 (가나 중간)
줄 7  03E … 043              상태 보기(가나 중간)
줄 9  160 … 165              헤어지기 (캔버스 중간)
```

가나 칸 배분을 작은 4·중간 2·큰 2 에서 작은 5·중간 3·큰 1(`010`~`075`, 102칸)로 바꾸고, 슬롯 상한 24개를 지키려고 캔버스 안 필드 전용 `096` 을 뺐습니다. 다시 띄우자 메시지 창이 깨끗했고, 강함 보기(문구 17개)도 그대로였습니다.

| 장면 | 결과 |
| --- | --- |
| 대화 번호 07 | 「맡기기 / 데려가기 / 상태 보기 / 헤어지기 / 그만」, 메시지 창 깨끗 |
| 대화 번호 0A | 「동료 넣기 / 동료 빼기」 |
| 09/00 강함 보기 · 강함 보기 뒤 전투의 가나 복원 | 그대로 |
| 무작위 입력 6벌(전투 둘 포함) · 이름 검사 셋 · 단위 시험 | 모두 정상 |

## 틀렸던 것들

- `04:9C52` 의 A 를 창 번호로 읽었습니다. A 는 `04:EB48` 에서 꺼낸 레코드 주소였습니다.

## 남은 것

- `4B`·`4E`·`77`·`7E` 가 열리는 장면
- 아직 가나가 남은 창(`20`·`2D`·`82`·`83` 등)과 한글 표에 없는 이름
