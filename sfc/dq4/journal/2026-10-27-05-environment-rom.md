# 2026-10-27-05: 환경 맵을 DQ5 엔진에 넣기

새로 그린 바트랜드·이무르 환경 타일을 DQ5 롬의 실내 맵 자리 `03/00`·`19/02`에 넣었습니다. 게임 메모리로 다시 그린 맵이 오프라인 비교 맵과 픽셀까지 같습니다. 결과는 [환경 그래픽 문서](../docs/dq4-environment-format.md#dq5-엔진-삽입)에 있습니다.

![DQ5 엔진에 넣은 바트랜드(왼쪽)와 이무르(오른쪽)의 MesenCE 화면](../images/dq4-environment-rom.webp)

## 1. 새 CHR 을 어디서 읽게 할까

CHR 로더 `01:8C15` 는 CHR 번호를 `(id >> 10) + $1824` 뱅크, `(id & 3FF) * 32 + $1825` 주소에서 DMA 로 올립니다. 팔레트 니블은 `[$B1],Y` 로 읽습니다. CHR 번호가 12비트라 원래대로면 뱅크 `13`~`16` 밖으로 못 나가는데, 셋 다 맵 포인터 루틴 `01:92E2` 가 맵마다 써 넣는 RAM 값이었습니다.

```text
01:92F4  LDA #$16 / STA $1823    블록 정의 뱅크
01:92F9  LDA #$13 / STA $1824    CHR 뱅크
01:92FE  LDX #$8000 / STX $1825
01:9304  LDA #$2A / STA $B3 / LDX #$8781 / STX $B1   CHR 팔레트 니블
```

그룹 `50` 이상 맵은 이미 같은 자리에서 `17`·`1F`·`0F:CF83` 으로 바꿉니다. 그래서 루틴 끝 `01:936E` 에 훅을 걸어 바꾼 맵일 때만 이 값을 새 자료로 돌렸습니다.

블록 포인터 표 `7E:B000` 은 빌더 `01:8CD8` 이 뱅크 `16` 을 고정으로 훑어 만듭니다. 바꾼 맵에서는 새 블록 42개의 포인터를 `MVN` 으로 표 앞에 덮고, 다른 맵에 들어갈 때 표에 새 포인터가 남아 있으면 빌더를 다시 부릅니다.

## 2. 뱅크 50 의 레코드가 셀 버퍼를 망가뜨렸다

처음에는 맵 레코드를 dq5 뱅크 나누기 제안대로 `50:8000` 에, 블록 정의를 `41:8000` 에 두었습니다. 워프하니 걸을 수는 있는데 BG 가 검었습니다. 블록 리더 `01:8AEF` 에서 값을 찍어 보았습니다.

```text
8AEF A8=8000 AA=18 1823=41
8AEF A8=800B AA=18 1823=41
```

`$AA` 는 바로 앞의 `LDA $1823` 결과인데 `41` 이 아니라 `18` 이었습니다. 레코드를 읽는 동안 DB 가 레코드의 뱅크 `50` 이 되고, 뱅크 `40` 이상에는 `0000`~`1FFF` WRAM 거울이 없습니다. 그래서 `LDA $1823` 이 명령의 마지막 바이트 `18` 을 오픈 버스로 읽었습니다. 블록 리더도 DB 를 블록 뱅크로 둔 채 `$2180` WRAM 포트에 셀을 쓰니 뱅크 `41` 에서는 쓰기가 사라집니다. 블록 정의와 레코드를 `3D` 로 옮기자 맵이 그려졌습니다. DMA 로 읽는 CHR 과 롱 주소로 읽는 니블·팔레트는 `40`·`41` 에 그대로 둡니다.

## 3. 원래 맵의 장치가 새 맵을 덮었다

맵이 그려지자 연못에 검은 줄이 생기고 나무 윗부분이 깨졌습니다. 새 CHR 이 VRAM 에 있는지 세어 보니 이무르가 쓰는 87개 가운데 0~4번(물·나무 첫 타일)이 없었습니다. 처음 고른 `1A/00`(アルカパ)은 움직이는 타일 맵 표 `03:D82E` 에 있었습니다. 원래 블록 번호로 물 블록을 먼저 올리고 매 프레임 그 슬롯에 원래 물 그림을 써서, 가장 먼저 슬롯을 받은 새 CHR 을 덮었습니다.

다음으로 고른 `01/02` 에서는 2×3셀 세 곳이 달랐습니다. 맵 위 물체 표 `01:D2FC` 의 물체가 셀 위층에 공통 타일을 덮은 것이었습니다. 그래서 다음 장치가 없는 맵만 대상으로 삼았습니다.

- 움직이는 타일
- 미리 올리는 블록·슬롯 건너뛰기(`04:822D`)
- 맵별 루틴(`15:F907`)
- 맵 위 물체

그런 맵 가운데 크기가 맞는 `03/00`(76×73)과 `19/02`(60×48)을 골랐습니다.

## 4. 팔레트를 덮는 시점

`03/00` 에서는 잔디가 갈색이었습니다. CGRAM 을 견주니 1번 줄만 달랐습니다. 팔레트 로더 다음에 불리는 `01:996A` 가 맵별 표 `01:9A12` 로 줄을 갈아 끼우고 있었습니다. 팔레트 훅을 `01:93B2`(`JSR $996A`)로 옮겨 그 뒤에 덮자 일곱 줄이 모두 맞았습니다.

## 5. 검사

`dq4environmentromcheck.py` 는 배 선실 세이브스테이트에서 두 맵으로 워프해 WRAM·VRAM·CGRAM 을 덤프합니다. 바트랜드 셀 버퍼(76×82셀 × 8바이트)는 `7E:C000` 에서 `7F` 뱅크까지 이어지므로 WRAM 128KB 를 다 덤프합니다. 셀 버퍼의 타일 워드로 맵 전체를 다시 그려 오프라인 비교 맵과 견주었습니다.

```text
burland 03/00  398848 px  differences 0  walk-layer mismatches 0/6232  moved yes
imuru   19/02  186368 px  differences 0  walk-layer mismatches 0/2912  moved yes
control 01/03 after burland: cell buffer, block table, $1823-$1826 equal to original ROM
```

부팅 시험(`dq5boottest.py --scenes`)의 세이브스테이트 장면 넷(걷기·전투·메뉴·대화)은 해시까지 원래 롬과 같았습니다. 전원부터의 해시는 2프레임 달랐습니다. 원인을 나눠 보니 자료만 넣은 롬은 0프레임, 훅을 넣으면 1~3프레임이 달랐습니다. 아무 일 없이 `JMP` 로 돌아오기만 하는 훅도 10프레임이 달랐으므로, 맵을 불러올 때 사이클 수가 바뀌는 데서 오는 차이로 보고 `--allow-diff`(배 선실 도달)로 판정했습니다.

블록 표 되돌리기는 처음에 "원래 1번 포인터와 다르면"이었습니다. 이 조건은 전원 직후 표가 비어 있을 때도 빌더를 부르므로 "새 1번 포인터가 있으면"으로 바꿨습니다.

## 틀렸던 것들

- 맵 자료를 뱅크 `50` 에 둘 수 있다고 봤습니다. 로더가 DB 를 자료 뱅크로 둔 채 낮은 WRAM·I/O 를 절대 주소로 다룹니다.
- 팔레트 로더 직후에 덮으면 된다고 봤습니다. `01:996A` 가 그 뒤에 줄을 바꿉니다.
- 아무 실내 맵이나 바꿀 수 있다고 봤습니다. 움직이는 타일·맵 위 물체가 원래 블록 번호·공통 타일로 새 맵을 덮습니다.

## 남은 것

- 문 열림·물 애니메이션·출구·인물·상자·이벤트 연결. 바꾼 맵의 원래 인물·출구가 그대로 남아 있습니다.
- 다른 지역과 던전·필드 지형으로 확대.
