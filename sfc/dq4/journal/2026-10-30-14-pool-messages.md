# 2026-10-30-14: 인물 대사로 덮은 DQ5 메시지를 다른 길로 띄우는지

새 그룹 인물의 임시 대사는 DQ5 후반 마을 메시지 77개(`636`~`A6D`)를 덮어 씁니다. 고를 때는 대화 스크립트에 나오는 메시지만 뺐습니다. 이번에는 그 77개를 이벤트·인라인 스크립트나 코드가 띄우는지 찾았습니다. 결과는 [환경 그래픽 문서의 인물](../docs/dq4-environment-format.md#인물)에 있습니다.

## 1. 스크립트

이벤트 스크립트는 `dq5event.py` 가 아는 시작 주소 전부(이벤트 표·번호 표·코드·점프)와 `15:F150`~`F7CF` 를 FF 마다 나눈 것을 풀어 메시지 명령 `60` 을 모았습니다. 메시지는 22개였고 덮은 번호는 없었습니다. 인물 엔트리의 인라인 스크립트는 기본·대체 목록의 낮·밤 스크립트를 모두 풀었습니다. 스크립트 1,034개의 메시지 명령(`21`·`30`·`31`·`32`) 368곳, 메시지 334개 가운데 덮은 번호는 없었습니다.

풀 고르기(`dq4npcport.message_pool`)가 이 두 목록도 빼게 했습니다. 지금은 후보가 112개 그대로라 빌드 결과는 같습니다.

## 2. 코드

`24:8BAF` 를 `JSL` 로 부르는 곳은 없었습니다. 코드는 `24:8157` 을 거칩니다. 덮은 번호를 `LDA #`·`LDX #`·`LDY #` 로 싣는 바이트는 27곳이었는데, 앞뒤를 풀어 보니 메시지 번호를 싣는 것은 없었습니다. `24:A51E` 의 `LDX #$06B8` 은 진짜 명령이지만 X 는 뒤의 `STA $7E5000,X` 가 쓰는 버퍼 오프셋입니다. `21:BC6B` 의 `A9 BA` 는 표의 끝이고, 루틴은 `21:BC6D` 의 `PHP PHB REP #$10 PHK PLB` 부터입니다. 나머지는 자료이거나 다른 명령의 일부였습니다.

다음은 `BRK 97+n xx` 로 메시지 `n << 8 | xx` 를 띄우는 길입니다. 덮은 번호를 `00 97+n xx` 꼴로 찾으니 260여 곳이 나왔습니다(겹쳐 찾은 것 포함). 대부분 `LDY #$xx`·`STA [$00],Y` 앞뒤 바이트였습니다. 앞 16바이트의 여러 자리에서 풀어 들어와 그 `00` 이 명령 경계가 되는 것만 남겼습니다. 그러자 `20:D606`·`20:D719` 의 `BRK A1 56`(메시지 `A56`)이 진짜 명령으로 남았습니다. 앞에 `BRK 88`·`JSL $268401`·`STA $F5` 가 있는 전투 코드였습니다. 그런데 처리기 `00:90FD`~`9115` 는 `LDA #$00`~`#$06` 일곱 개뿐입니다. 그래서 메시지가 되는 것은 `BRK 97`~`9D` 이고 `BRK A1` 은 다른 처리기로 갑니다. 이 길로 띄울 수 있는 메시지는 `000`~`6FF` 입니다. 덮은 `6xx` 30개의 자리 가운데 경계가 맞은 네 곳은 텍스트 자료 뱅크 `24`·자료 뱅크 `1E` 의 바이트이거나 `STZ $9D00` 의 일부였습니다.

`JSL $248157` 을 직접 부르는 22곳 가운데 셋은 위 두 스크립트와 `BRK` 처리기이고, 둘(`01:88B5`·`88D6`)은 즉값 `2A8`·`2A9` 입니다. 나머지는 번호를 계산하므로 기준값과 더하는 값의 폭을 하나씩 봤습니다. 가장 큰 것은 묻기 대화의 `615`~`634` 였습니다. 가게 쪽 `06:E36E` 는 X 에 `$0F2B` 를 더하는데, 그 바이트를 쓰는 곳은 `STA` 넷과 `STZ` 셋이고 값은 0·1·2·7 이었습니다. X 로 번호를 받는 `06:C802` 는 부르는 곳이 `06:C7DE` 의 `LDX #$0576` 뒤 하나입니다.

## 남은 것

- 표에서 읽은 값으로 번호를 정하는 길(조사 값 `$1E73` 등)은 정적으로 폭만 봤고, 게임에서 덮은 메시지가 뜨는 장면이 없는지는 재지 않았습니다.
