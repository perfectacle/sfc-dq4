# 2026-11-05-01: 열린 버스 프로브를 장면 검사에도

호환성 프로브(`dq4compatcheck.py probe`)는 1장 걷기만 지났다. 가게·저장·일반 전투·창 글자의 높은 뱅크 코드처럼 걷기가 지나지 않는 길에도 같은 프로브를 붙였다. 결과는 [호환성 형식 문서 「장면 프로브」](../docs/dq4-compat-format.md#장면-프로브2026-11-05)에 옮겼다. 우리 패치 코드의 열린 버스·롬 거울 접근은 세 장면, 두 범위 모두에서 0건이었다.

## 1. 붙이는 법

장면 검사는 고치지 않았다. 대신 MesenCE 를 띄우는 곳 하나를 고쳤다.

- `dq4mesen.run`·`Runner` 는 환경 변수 `DQ4_OPENBUS_LOG` 가 있으면 띄우는 스크립트 앞에 `lua/dq4openbus.lua` 를 붙이고, 원래 스크립트를 `PROBE_TARGET` 으로 넘긴다(`with_openbus`). 장면 검사는 모두 이 둘로 MesenCE 를 띄우므로, 장면 검사를 그대로 띄우기만 하면 된다.
- 읽은 바이트 캐시(`dq4readset`)가 맞으면 MesenCE 를 띄우지 않아 접근이 적히지 않는다. 그래서 `DQ4_READSET=off` 로 띄운다.
- `lua/dq4openbus.lua` 는 `OPENBUS_RANGES`(「뱅크-뱅크:주소-주소」 를 쉼표로 이은 것)를 받는다. 없으면 전처럼 뱅크 `40`~`7D` 의 `0000`~`7FFF` 이고 기록 줄 꼴도 같다. 범위를 주면 주소까지 적는다.

`sfc/dq4/tools/dq4compatscenes.py` 가 장면 셋을 범위 둘로 띄운다.

- 장면: `dq4battlecheck`(전투), `dq4ch1savecheck`(저장·이어 하기·전멸), `dq4windowcheck --every`(가게·교회·여관·대화·전투 창).
- 범위 `high`: 걷기 프로브와 같은 뱅크 `40`~`7D` 아래 절반. 판정도 같다.
- 범위 `io`: 뱅크 `00`~`3F` 의 열린 버스 구역. 진짜 레지스터(PPU `2100`~`2183`, 조이패드 `4016`·`4017`, CPU `4200`~`421F`, DMA `4300`~`437F`)는 뺐다. 이 범위에서는 원래 DQ5 코드도 접근할 수 있다. 그래서 우리 코드의 접근만 실패로 친다. 우리 코드는 PC 뱅크가 `40` 이상이거나 PC 가 롬 장부(`ledger.json`)의 단계가 쓴 자리 안인 것이다.

범위를 나눈 것은 콜백 수 때문이다. 범위를 둘로 나눠 돌리자 시간 제한에 걸린 장면은 없었다. 가장 긴 `window` `io` 도 653초에 끝났다(프로브 없는 창 검사는 가드 기록 288초).

## 2. 결과

1장 롬 `cbd7add2`(main `d8d49388`)로 쟀다.

| 장면 | 범위 | 기록 줄 | 우리 코드 | 원래 DQ5 코드 |
| --- | --- | --- | --- | --- |
| `battle` | `high` | 1 | 0 | — |
| `battle` | `io` | 1 | 0 | 0 |
| `save` | `high` | 35 | 0 | — |
| `save` | `io` | 5 | 0 | 0 |
| `window` | `high` | 51 | 0 | — |
| `window` | `io` | 24,283 | 0 | 24,282 |

- `high` 의 기록은 원래 DQ5 저장 코드(뱅크 `25`)의 SRAM 읽기·쓰기와 높은 뱅크 BRK(`09`·`88`·`8B`)뿐이었다. 모두 허용 목록 안이다.
- `window` `io` 의 원래 DQ5 접근 24,282줄은 `06:F53D` 가 24,281줄, `06:F536` 이 1줄이고, 모두 뱅크 `3D` 의 `2000`~`7FFF` 를 읽었다. 기록의 PC 는 MesenCE 읽기 콜백의 `cpu.pc` 라 명령의 다음 주소다. 그래서 둘은 가게 목록을 `($00),Y` 로 훑어 키를 찾는 루틴(`06:F534`)의 두 읽기, `06:F534 LDA ($00),Y`(키 바이트)와 `06:F53B LDA ($00),Y`(다음 바이트)다.
  - 창 검사를 `--only talk` 로 대화 장면만 돌려도 같은 24,282줄이 나왔다.
  - 대화 장면은 방어구점 주인의 대화 번호를 `00`~`3F` 로 바꿔 시설 처리기를 여는 실험이다. 목록에 없는 키로 끝까지 훑은 것으로 본다.
  - DQ5 트랙도 대화 번호를 가게로 바꾼 실험에서 같은 자리의 읽기를 적었다.
  - 실제 가게 장면(`shopwho`·`shopflip`)에서는 나오지 않았다.
- 전투·저장 장면은 서장 캐시에서 출발해 서장의 접근은 다시 적지 않았다. 서장은 `dq4-openbus-probe` 가 본다.

## 3. 리뷰에서 고친 것

- 롬 장부의 뱅크를 넘는 범위(`3C:FFEA~3D:8000`, 창 글자 뱅크 `64`~`69` 의 범위 등)를 시작 뱅크만 읽어 빈 범위로 만들고 있었다. 이제 뱅크마다 나눈다.
- 해석하지 못한 기록 줄을 버리지 않고 실패로 친다(`io`, 그리고 `high` 가 쓰는 `dq4compatcheck.probe_problems`).
- 원래 DQ5 접근은 PC·접근 뱅크·주소 범위로 정한 허용 목록(`DQ5_ALLOWED`, 위 둘)만 허용하고, 그 밖은 실패로 친다. 결과에 고유 PC 집합을 둔다.
- `dq4windowcheck` 는 장면이 돌지 않아도 0 으로 끝날 수 있어 장면마다 끝까지 돌았는지를 따로 본다. 전투·저장 검사는 목표를 못 채우면 0 이 아닌 값으로 끝난다.
- `00`~`3F` 의 `6000`~`7FFF` 는 롬 머리(LoROM, SRAM 8KB)대로 SRAM 거울이 아니다(SRAM 은 `70`~`7D` 만).
- `DQ4_READSET=off` 는 읽기만 끄고 결과는 캐시에 넣는다. 캐시 키는 원래 스크립트로 정해져 프로브가 들어가지 않으므로, 쓰기도 끄는 `DQ4_READSET_STORE=off` 를 더해 장면 프로브가 쓴다.
- 가드를 다른 가드와 함께 돌리자 `window` `io` 의 `talk08` 이 하나씩 돌려도 종료 255 로 끝났다. 이 장면은 `06:F534` 가 수만 자리를 읽어 프로브가 그때마다 새 줄을 쓴다. 프로브가 줄마다 파일을 열고 닫던 것을, 한 번 열어 둔 파일에 쓰고 비우게 바꿨다. 다른 가드가 도는 동안 `talk08` 만 돌려 통과했다(97초).
- 다른 가드와 함께 창 검사를 처음 돌릴 때, 서장 끝 상태 캐시가 비어 있어 프로브를 붙인 채 서장을 걷다가 MesenCE 가 출력 없이 끝났다(「세이브스테이트 없음」, `mesen.log` 에는 초기화 안 된 메모리 읽기 경고만). 장면 프로브가 볼 것은 서장이 아니므로(서장은 `dq4-openbus-probe`), 롬마다 서장 끝 상태를 프로브 없이 먼저 만든다(`dq4ch1walkcheck.py --until prologue`).
- 시간을 줄이려고 (장면, 범위) 를 둘씩 함께 띄워 보았다(`--parallel 2`). 전체는 1,003초로 줄었지만 `save` `io` 의 두 장면과 `window` `io` 의 `talk08` 에서 MesenCE 가 종료 255 로 끝나 실패했다. 기록(`mesen.log`)에는 초기화 안 된 메모리 읽기 경고만 있었고, 까닭은 재지 않았다. 하나씩 돌리면 모두 통과하므로 기본은 하나씩(`--parallel 1`)으로 두었다. 하나씩 돌린 전체 시간은 약 1,456~1,485초다.

## 4. libretro

libretro(bsnes·snes9x)에서 장면이 끝까지 가는 것은 이미 가드가 있다.

- 가게 사기·팔기: `dq4-shop-scene`.
- 저장 기록과 이어 하기: `dq4-savefixture`.
- 일반 전투: `dq4-battle-scene`.
- 효과음 장면: `dq4-sfx-scene`.

넷 다 두 코어로 돌고, 이번 main 에서 통과했다(#1000 의 가드 실행). libretro 에는 MesenCE Lua 같은 메모리 콜백이 없어 프로브는 붙이지 않았다. 창 장면·저장 장면(`dq4ch1savecheck`)의 libretro 판은 없다.

## 5. 가드

새 가드 `dq4-compat-scenes` 를 두었다.

- 실행: 롬 빌드, 창 검사가 쓰는 기호 만들기, `dq4compatscenes.py`.
- paths: 진입 스크립트, 띄우는 장면 검사 넷과 그 import, 빌드 단계, 장면 가드들의 lua·asm.
- 시험 `test_dq4compatscenes.py` 가 보는 것:
  - 장부로 우리 코드를 가리는 법, io 판정.
  - io 범위가 진짜 레지스터를 빼고 빈 구역을 덮는지.
  - 장면 명령.
  - `dq4mesen.with_openbus` 가 `DQ4_OPENBUS_LOG` 가 있을 때만 프로브를 붙이는지.

## 남은 것

- 대화 번호 실험에서 `06:F534` 가 훑는 목록의 뱅크가 `3D` 가 되는 까닭(DB).
- `io` 범위의 뱅크 `80`~`BF` 거울.
- libretro 로만 도는 가게 사기·팔기 흐름의 MesenCE 판, 2장.
