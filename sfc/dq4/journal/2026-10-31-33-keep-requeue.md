# 2026-10-31-33: 1A 를 다시 넣는다던 것은 분기 범위였다

[31번 일지](2026-10-31-31-boss-hang.md)에서 버린 두 고침이 서장에서 멈춘 까닭을 「본 스레드가 `1A` 를 다시 넣어서」로 적었습니다. 확인해 보니 틀렸습니다. 함께 표시 코드가 다른 대기열 칸을 얼마나 늦추는지 재고, 최신 main 의 두 롬으로 1장 이어 걷기를 다시 돌렸습니다. 결과는 [함께 쓰는 샘플 살리기](../docs/dq4-sound-port-format.md#함께-쓰는-샘플-살리기2026-10-30)에 있습니다.

## 1. 누가 1A 를 넣나

전원부터 새 게임까지 같은 입력(A 연타, 이름 입력에서 Y)으로 1,700프레임을 돌렸습니다. 대기열에 넣는 `24:FF83` 과 `23:FE8F` 의 부른 자리, 대기열을 찍었습니다.

```
f1633 FE8F from 5F88AB                       맵 밝히기(dq4chapterbox 의 reveal)
f1633 FF83 cmd=1A … cur=04 tail=04
f1633 FF83 cmd=01 … q=…FF1AFF… tail=06       같은 FE8F 가 1A 뒤 01
f1633 mark slot=5 val=1A
```

지금 롬에서는 1,700프레임 동안 `1A` 가 둘뿐이었습니다. 표시 코드에 들어갈 때 Lua 로 `1A` 칸에 bit7 을 켜 봐도 같았습니다. 본 스레드는 `1A` 를 다시 넣지 않습니다.

## 2. 진짜 까닭

버린 고침을 다시 빌드했습니다. 받침을 빼고 표시 코드 앞에 bit7 을 켜는 19바이트를 넣은 판입니다. 같은 입력에서 `1A` 칸이 매 프레임 처음부터 다시 돌았고, `1A` 는 그래도 둘이었습니다. 표시 코드에 들어간 뒤의 PC 를 따라가니 `16` 의 대답도 `0A` 도 보내지 않고 `C3CB` 를 돌다 대기열 루프로 돌아갔습니다.

표시 코드 바이트를 보니 첫 분기가 `F0 8A` 였습니다. 곡이 적혀 있지 않으면 끝으로 가는 `BEQ` 인데, 앞에 넣은 코드로 거리가 128바이트를 넘었습니다. `dq5song._asm` 은 짧은 분기의 범위를 보지 않고 아래 바이트만 남겨, 뒤쪽 엉뚱한 자리로 뛰었습니다. bit7 판의 거리는 138바이트(`8A`)였습니다. `1D93` 판은 같은 분기 앞뒤로 26바이트를 넣었으므로 역시 닿지 않았을 것으로 봅니다(그 판의 바이트는 다시 보지 않음).

`#816` 의 받침 판은 그 분기가 `F0 7F`(127)로 겨우 닿습니다. 그래서 표시 코드와 곡 뒤 단계 끝 코드를 범위를 보는 `_asm_far` 로 짜도록 바꿨습니다. 롬은 바이트까지 같습니다(SHA-1 `17b6cd06…`). 앞으로 한 바이트라도 더 넣으면 빌드가 멈춥니다.

받침보다 근본적인 고침은 없다고 보았습니다. 표시 코드가 `C21E` 를 부르는 한 루프에 다시 들어가지 않게 막아야 합니다. bit7 은 다른 칸(다음 곡 `01`)을 표시 도중에 돌리게 되고, `1D93` 은 지금 칸을 거짓으로 둡니다(둘 다 코드 읽기).

## 3. 다른 칸이 기다리는 시간

`7E:1A94` 쓰기로 표시 코드가 켜진 동안을 쟀습니다. 대기열 칸 쓰기(WRAM `1D95`~)와 `2B:BF0D`(칸을 돌림)로는 칸마다 기다린 프레임을 쟀습니다. 처음에 CPU 주소 `7E:1D95` 에 쓰기 감시를 걸자 아무것도 잡히지 않았습니다. `24:FF83` 은 데이터 뱅크 `24` 의 거울로 쓰므로 WRAM 오프셋으로 걸어야 했습니다.

| 장면 | 표시 코드 | 기다린 칸 |
| --- | --- | --- |
| 성 아래 필드 보통 조우 18,000프레임(레벨 1 → 2) | 13번, 12번은 0프레임, 한 번 90프레임 | 다음 곡 `01` 90프레임. 효과음은 그 사이에 들어오지 않음 |
| 탑 위 보스 구간 | 58·28프레임 | 다음 곡 `01` 58·28프레임. 효과음 없음 |

표시 코드 밖에서 다른 칸은 0~8프레임 기다렸습니다(필드 장면 413칸 중 392칸이 0).

## 4. 두 롬으로 다시 걷기

main `21bcd32d` 에서 `dq4build.py`(곡)와 `--no-sound` 로 만든 두 롬으로 `dq4ch1walkcheck.py` 를 함께 돌렸습니다. 둘 다 26구간을 통과했습니다.
