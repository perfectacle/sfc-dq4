# 2026-11-01-06: 타이틀 그림 자료를 42~47 로 옮겨 30~3F 를 비우기

새 맵 레코드와 인물 목록은 엔진이 데이터 뱅크를 그 자료의 뱅크로 두고 낮은 WRAM 을 함께 읽으므로 `30`~`3F` 를 벗어날 수 없습니다. 5장 시작 지역을 넣은 1장 롬에서 그 안의 큰 빈 곳은 `37`·`39`(65,536바이트)뿐이었습니다. 5장 나머지(FC 맵 150개 안팎)는 들어가지 않습니다. 가장 많이 차지하던 것은 타이틀 그림 자료(`31:8000`~`36:9DBF`)였고, 사용자가 이것을 `40` 이상으로 옮기기로 정했습니다. 명세는 [타이틀 애니메이션](../docs/dq4-title-animation.md)과 [1장 첫머리의 두는 자리](../docs/dq4-chapter1-format.md#두는-자리)에 있습니다.

## 1. 옮길 수 있나

`dq4titlelayers.asm` 은 그림 자료를 DMA(`$4302`~`$4304` 에 주소와 뱅크 바이트)와 `lda.l`(long)로만 읽습니다. 데이터 뱅크는 `00` 으로 두고 자료에는 쓰지 않습니다. 뱅크가 박힌 곳은 asm 의 `Upload` 뱅크 인자와 즉값(`#$31`·`#$35`), long 주소(`$33xxxx`·`$31EB00`), 그리고 `dq4titlelayers.py` 가 만드는 용 차분 DMA 표·OAM 포인터 안의 뱅크 바이트(`FOREGROUND_BANK` 등 상수)입니다.

문제는 롬 크기였습니다. 타이틀 단계는 원본 1.5MB 를 2MB 로 늘리고(`30`~`3F` 는 원본 `20`~`2F` 의 거울), 4MB 로 늘리는 것은 그다음 서곡 단계였습니다. 그래서 타이틀 단계가 바로 4MB 로 늘리게 했습니다(`40`~ 은 0, 머리 크기 바이트 `0C`). 서곡 단계는 4MB 타이틀 롬을 받아 그대로 이어 씁니다(`dq4overture.TITLE_SIZE`).

## 2. 옮긴 곳

뱅크 `31`~`36` 을 1장 롬에서 비어 있던 `42`~`47` 로 하나씩 옮겼습니다. 타이틀 코드는 `30:8000` 그대로입니다(`03:FDFB` 의 `JML`).

| 자료 | 전 | 후 |
| --- | --- | --- |
| 하늘 CHR·타일맵·팔레트·OAM 포인터 | `31` | `42` |
| 전경 CHR | `32` | `43` |
| 용 차분 DMA 표 | `33` | `44` |
| OBJ 초기 두 페이지 | `34` | `45` |
| 앞 구름 OAM 표 | `35` | `46` |
| 차분 데이터·OAM | `36:8000`~`9DBF` | `47:8000`~`9DBF` |

## 3. 타이틀 화면이 같은지

main 그대로의 타이틀 롬과 옮긴 타이틀 롬을 `dq4titleintegrationcheck.lua` 로 300프레임부터 64프레임마다 16번 덤프해 견줬습니다.

- OAM·CGRAM 은 16번 모두 같았습니다.
- VRAM 은 `0x3760`~`0x47FF`(2,165바이트)만 달랐습니다. 하늘 CHR 이 정확히 `0x3760` 바이트라 그 뒤는 타이틀이 올리지 않는 칸입니다. 같은 롬을 두 번 돌려도 이 칸은 달랐으므로(2,166·2,169바이트), 초기화되지 않은 VRAM 입니다. 이 칸을 빼면 16번 모두 같았습니다.
- 화면 캡처 그림은 같은 롬을 두 번 돌려도 16장 가운데 10장 넘게 달라서(캡처가 VRAM 보다 몇 틱 늦음) 판단에 쓰지 않았습니다.

## 4. 비운 자리 쓰기

1장 빌드가 비워진 뱅크를 쓰게 했습니다(`dq4chapter1.RECORDS_AT`·`NPC_BANK`).

- 새 맵 레코드: `3A`, `30` 의 빈 곳(타이틀 코드 몫 `30:8000`~`8FFF` 뒤), 그리고 `31`·`32`·`33`·`34:8000`~`BFFF`·`36`·`37`·`39` 를 통째로 씁니다. 자리는 263,936바이트이고, 레코드 100개(98,692바이트)가 `32:C522` 에서 끝납니다.
- 인물 기본 목록: 환경 맵 뒤 `3F` 에서 통째로 빈 `35:8000` 으로 옮겼습니다(27,853바이트, `35:ECCC` 까지). 목록 하나는 한 뱅크 안이라 남는 곳(4,915바이트)은 그대로이고, `3F` 의 끝이 빕니다. 1장 빌드는 이 뱅크의 거울 바이트도 먼저 0 으로 둡니다(`group_ranges`).

## 5. 확인

- 메뉴 준비 루틴(`MenuInit`)은 그사이 main 이 `31:E9A0` 에 넣었는데, `phk`/`plb` 로 낮은 WRAM 을 절대 주소로 쓰는 코드라 `42` 로 옮길 수 없어 타이틀 코드 뒤(`30`)로 옮겼습니다. main 의 타이틀 롬과 가만히 둘 때 덤프 48개, A 를 눌러 메뉴로 넘어갈 때 45개를 견주어, 타이틀이 쓰지 않는 VRAM 칸 말고는 모두 같았습니다.
- 단위 테스트 587개(타이틀 롬이 4MB·머리 `0C`·`31`~`37` 이 원본 거울인지 포함), `tools/check_docs.py` 0 errors.
- 1장 롬(`dq4build.py`)에서 `dq4prologuecheck.py`(타이틀에서 새 게임), `dq4ch1walkcheck.py`, `dq4fieldcheck.py` 39장면, `dq4fieldtravelcheck.py` 61장면, `dq4npccheck.py --chapter1`(1~5장 맵 여덟) 통과.

## 남은 것

- 인물 목록은 기본·대체 두 목록이 한 뱅크씩이라(dq5 `dq5npcrelocate.py`), 남은 곳이 기본 4,915바이트·대체 3,380바이트입니다. 5장 인물을 넣으려면 목록을 그룹마다 다른 뱅크에 나누는 dq5 도구 쪽 변경이 필요합니다.
- `30` 은 타이틀 코드·서곡 사이의 빈 곳만 씁니다.
