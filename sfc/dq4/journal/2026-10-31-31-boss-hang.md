# 2026-10-31-31: 곡을 얹은 1장 롬이 전투 뒤 멈추던 것

[28번 일지](2026-10-31-28-ch1-walk.md)의 이어 걷기 검사가 곡 묶음을 얹은 롬(`dq4-ch1-sound.sfc`)에서 탑 위 보스를 이긴 뒤 멈췄습니다. 원인은 [함께 쓰는 샘플 살리기](../docs/dq4-sound-port-format.md#함께-쓰는-샘플-살리기2026-10-30)의 표시 코드였습니다. 그 코드가 부르는 샘플 보내기가 소리 대기열 루프를 다시 들어갔습니다. 고친 내용은 그 절에 있습니다.

## 1. 겹겹이 들어간 1A

보스 구간을 멈추기 전 세이브스테이트에서 다시 돌렸습니다. `2B:C0E0`(`JSR C118`)을 지날 때 스택 포인터를 찍었습니다. 보스 전까지는 늘 `0984` 였습니다. 레벨업 뒤 곡을 바꾸는 `1A` 에서는 `0984` → `0968` → `094C` … 로 한 번에 `1C` 씩 내려갔습니다.

두 번째 `C0E0` 직전까지 실행한 PC 를 모두 모았습니다. 흐름은 이랬습니다.

```
1A 칸: C0BB(04) → C118(15) → C0E3(09) → C0A3(16) → C0AD 표시 코드
  표시 코드 → C21E(샘플 보내기) → … → C2E6 JSR BED5(대기열 루프)
    BED5 → BF0D → 같은 1A 칸을 C0BB 부터 다시 → 다시 표시 코드 → …
```

`C21E` 는 샘플을 하나 보낼 때마다 대기열 루프를 불러 다른 칸을 돌립니다. 그런데 `1A` 칸은 아직 대기열에 남아 있습니다(`0A` 를 보내고 `C184` 가 지워야 빔). 루프는 그 칸을 처음부터 다시 돌렸습니다. 함께 쓰는 샘플이 있으면 겹마다 다시 표시 코드에 닿아 한 겹 더 들어갔습니다. 일곱 번째 `C0E0` 에서 스택이 `08DC` 까지 내려와 소리 손잡기 변수 `$08DA`·`$08DC` 를 덮었습니다. 그 뒤 `2B:C163` 의 `RTS` 가 `2B:C0E3` 대신 `2B:40E3` 으로 가, WRAM 을 실행했습니다.

## 2. 버린 고침 둘

| 고침 | 결과 |
| --- | --- |
| 표시하는 동안 `1A` 칸에 bit7 을 켬(루프는 bit7 칸을 건너뜀) | 새 게임 뒤 서장 맵이 검은 채 `C32F` 에서 대답을 기다림 |
| 표시하는 동안 지금 칸 `1D93` 을 꼬리 `1D91` 로 둠(루프가 빔) | 같은 자리에서 맵 번호 `00/00`, 스택 `FFCD` |

두 롬에서 소리 명령을 찍어 보니, `1A` 가 표시 코드까지 갔다가 같은 프레임에 다시 처음부터 돌기를 되풀이했습니다. 실행 PC 를 따라가니 본 스레드(`23:FE8F` → `24:FF83`)가 `1A` 를 거듭 넣고 있었습니다. 대기열의 `1A` 칸을 바꾸면 본 스레드가 그 칸을 알아보지 못하는 것으로 보입니다. 그래서 대기열은 건드리지 않았습니다.

`KEEP_CODE` 를 앞으로 옮긴 것만으로는 탈이 없었습니다. 옮기기만 한 롬은 서장을 통과했습니다.

> 고쳐 둠: 위 두 길이 멈춘 까닭은 본 스레드가 아니라 표시 코드 첫 분기가 범위를 넘은 것이었습니다([2026-10-31-33](2026-10-31-33-keep-requeue.md)).

## 3. 고침

표시 코드가 시작할 때 `7E:1A94` 를 켜고 끝에서 끕니다. `2B:C2E6` 의 `JSR BED5` 를 받침으로 바꿨습니다. 받침은 그 값이 켜져 있으면 루프를 부르지 않고 돌아갑니다. 표시하는 동안에만 다른 칸이 기다리고, 나머지 `C21E` 쓰임새는 그대로입니다. 코드가 18바이트 늘어 `KEEP_CODE` 를 `2B:EA48` 에서 `EA30` 으로 당겼습니다. IPL 꼬리는 `EA03` 에서 끝나고, 새 코드는 `2B:EA07`~`EAF7` 입니다.
