# 2026-10-31-49: 조우는 3/4, 전투 보상은 4/3 배

1장 롬의 조우를 FC 의 3/4 로 줄이고, 전투에서 얻는 경험치·금화를 4/3 배로 늘렸습니다. 원작과 일부러 다르게 한 첫 조정입니다. JRPG 특유의 노가다와 도망 반복을 줄이자는 사용자 결정이고, 걸은 거리당 얻는 양은 FC 와 같게 남깁니다. 결과는 [1장 형식 문서](../docs/dq4-chapter1-format.md#사용자-결정에-의한-원작과의-차이)에 있습니다.

## 1. 배율을 한 곳에

조우를 정하는 곳은 둘입니다. 필드는 DQ5 지형 조우율 표(`23:F1E0`)에 FC 지형 배수를 넣고(`dq4fieldencounter.terrain_rates`), 던전은 [FC 걸음 확률](2026-10-31-46-dungeon-step-chance.md) 훅이 FC 확률 표를 씁니다. 두 곳 모두 새 모듈 `dq4balance.py` 의 `ENCOUNTER = 3/4` 를 곱하고 반올림합니다. 0 이 아닌 값은 1 아래로 내려가지 않게 했습니다.

```
던전 기본 16   FC 01 03 07 0F → 01 02 05 0B
던전 기본 20   FC 02 04 09 12 → 02 03 07 0E
구역이 바뀐 걸음  55 → 40
필드 풀(낮/밤)  0B/0F → 08/0B,  언덕 1A/20 → 14/18
```

던전은 FC 가 실제로 쓰는 정수 확률(>> 8 한 값)에 3/4 를 곱했습니다. 곱하기 전 값에 곱하면 기본 16 이 `01 03 06 0B` 가 되어, 「FC 확률의 3/4」 라는 말과 어긋났습니다.

필드는 계수를 고르는 셈(`field_rate_index`)은 FC 배수 그대로 두고, 표에 넣는 값만 줄였습니다. DQ5 는 조우율 Y 로 기대 걸음 n = 256 / Y 를 정해 그 앞뒤로 확률을 바꾸므로, Y 를 3/4 로 하면 평균 거리가 정확히 4/3 배가 되지는 않습니다. `dq5_steps` 로 셈하니 1.26~1.35 배였습니다.

## 2. 보상을 더하는 곳 찾기

DQ5 문서에는 「이긴 무리의 경험치(필드 `72`)·금화(필드 `73`)를 더해 준다」까지만 있었습니다. 성 앞 필드 세이브스테이트(1장 걷기 검사의 `field` 구간 끝)에서 계수를 모두 `FF` 로 덮고, 좌우로 걷다가 멈추면 A 를 누르는 프로브로 싸웠습니다. 주인공 경험치 `7E:204B` 와 소지금 `7E:2019` 쓰기를 감시하니 둘 다 `21:912B`(여러 바이트 더하기)였습니다. 스택을 따라가면 경험치는 `25:891A`, 금화는 `25:8C39` 에서 불렸고, 둘 다 `$10FC`·`$10FF` 를 읽었습니다.

```
25:890B  LDA $10FC / STA $43 ...   ; 경험치 합 → 일행마다 더하기
25:8C18  LDA $10FF / ORA $1100 ... ; 금화 합
```

그런데 `7E:10FC` 쓰기를 감시하자 전투가 시작할 때 0 으로 지우는 것(`26:8071`)만 잡혔습니다. `25:88D7` 에서 DB 를 찍어 보니 `04` 였습니다. 낮은 WRAM 은 `00`~`3F` 뱅크의 거울로 쓰이므로, 거울 128곳을 모두 감시하자 몬스터를 쓰러뜨릴 때마다 `04:10FC` 에 쓰는 `28:821A`·`28:8256` 이 나왔습니다.

```
28:820C  BRK #$88 / .db $72        ; 필드 72 → $46
28:8210  REP #$20 / LDA $46 / CLC / ADC $10FC / STA $10FC   ; 넘치면 FFFFFF
28:8248  BRK #$88 / .db $73        ; 금화도 같은 꼴
```

이긴 뒤의 차례는 `20:80F0` 에 있었습니다. `20:8100` 부터 `JSL $2588D3`(경험치), `$258A8D`(레벨 업), `$258952`, `$258C0C`(금화)를 부릅니다.

## 3. 승리 처리 첫 호출에 훅

몬스터마다 4/3 을 곱하면 경험치 1·2 짜리 슬라임에서 반올림 손실이 큽니다. 그래서 합이 다 모인 `20:8100` 의 `JSL $2588D3` 를 `JSL 57:F000` 으로 바꿨습니다. 훅은 두 합 v 를 v + round(v / 3) 으로 고치고 `JML $2588D3` 합니다. 메시지도 `25:88D3` 안에서 합을 읽으므로 고친 값이 찍힙니다.

3 으로 나누기는 CPU 나눗셈기(16비트 ÷ 8비트)를 씁니다. 위 바이트부터 「앞 나머지 × 256 + 이 바이트」 를 3 으로 나누면 몫이 한 바이트에 들어갑니다(767 / 3 = 255). 몫은 높은 바이트부터 스택에 넣어, 더할 때 낮은 바이트부터 꺼냅니다. 마지막 나머지에 `CMP #$02` 를 하면 나머지가 2 일 때만 C 가 켜져, 그대로 반올림 올림이 됩니다. 자리는 던전 걸음 확률이 쓰는 뱅크 `57` 의 끝(`F000`)입니다.

## 4. 잰 것

같은 프로브를 고치기 전과 뒤의 롬으로 돌렸습니다(1만2천 프레임).

```
고치기 전  합 16/16 → 주인공 0→16, 금화 20→36
고친 뒤    합  7/8  → 9/11,  16/16 → 21/21,  6/4 → 8/5,  4/2 → 5/3
```

메시지도 「21포인트의 경험치를 얻었다!」였습니다. 1장 걷기 검사로 왕의 선물 장면을 다시 걸으며 `20:8100`·`57:F000` 실행을 감시했더니 불리지 않았고, 경험치는 133 → 3133 이었습니다.

조우는 `dq4dungeonencountercheck.py`(24장면, 훅이 확률을 정한 걸음 401번 모두 일치)와 `dq4fieldencountercheck.py`(25장면)가 통과했습니다. 필드로 들어간 탑은 `02 03 07 0E`, 동굴은 `01 02`, 구역 경계는 `40` 이었고, 필드의 Y 는 풀 `08`·언덕 `14` 였습니다. 1장 걷기 검사 26구간과 저장·이어 하기 검사 여섯 장면도 통과했습니다.

## 틀렸던 것들

- 전투 메시지 `24:8C39` 로 전투 중인지 가리려 했는데, 전투가 시작해 명령 창이 뜰 때까지는 메시지가 없었습니다. 그동안 좌우 입력을 계속 넣어 전투가 진행되지 않았습니다. 주인공 좌표가 60프레임 동안 그대로면 전투로 보도록 바꿨습니다.
- 저장·이어 하기 검사의 전멸 장면이 조우를 줄인 롬에서 실패했습니다(6,000프레임 동안 전투 없음). 이 장면은 DQ5 계수만 `FF` 로 덮었는데, 우물 아래는 던전 걸음 확률 훅이 확률을 정하므로 FC 표 그대로였습니다. 줄이기 전에는 운으로 통과한 셈입니다. 우물 끄기 검사처럼 훅의 표까지 `FF` 로 덮는 `dq4dungeonencountercheck.rates` 를 쓰게 고쳤습니다.

## 남은 것

- 필드 평균 거리는 4/3 배가 아니라 1.26~1.35 배입니다. 정확히 맞추려면 계수까지 다시 골라야 합니다.
- 실제로 플레이해 본 체감(레벨 곡선, 1장 보스 앞 레벨)은 재지 않았습니다. 몬스터는 아직 DQ5 대역이라 경험치·금화 값도 대역의 값입니다.
- 도망 성공률은 바꾸지 않았습니다.
