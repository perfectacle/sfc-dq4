# 2026-11-01-11: snes9x 에서 서장이 멈추던 BRK 16 의 DB

다른 에뮬레이터에서도 도는지 보려고 최신 main 의 1장 롬(`dq4-ch1-full.sfc`)을 libretro 코어 둘(bsnes 115, snes9x 1.63)에 걸었습니다. 입력과 판정은 서장 검사(`dq4prologuecheck.py`)와 같습니다. bsnes 는 MesenCE 와 같은 장면으로 통과했습니다. snes9x 는 이름 입력 뒤 새 게임을 시작하자(약 1120프레임) 화면이 검은 채 소리 없이 멈췄습니다. 고친 내용은 [서장 문서의 칼 여섯 합](../docs/dq4-prologue-format.md#칼-여섯-합)에 있습니다.

## 1. 어디서 멈추나

빌드 단계별 롬을 snes9x 에 걸었습니다. 메뉴 롬(`menu.sfc`)은 새 게임 뒤 DQ5 첫머리로 잘 갔습니다. 1장 롬은 소리를 얹기 전(`dq4-ch1.sfc`)부터 멈췄습니다. 입력 간격을 다섯 가지로 바꿔도 snes9x 는 늘 멈추고 bsnes 는 늘 지나갔습니다.

snes9x 상태 파일의 `REG` 블록으로 프레임마다 CPU 를 보았습니다. 멈춘 뒤 PC 는 `24:FE52`~`FE6D` 를 돌았고, DB 가 `5E` 였습니다. `24:FE44` 는 소리 대기열이 빌 때까지 기다리는 루틴입니다. 안쪽 고리는 머리 `$1D93` 에서 시작해 X 를 `& 0F` 로 돌리며 꼬리 `$1D91` 에 닿기를 기다립니다. 두 값을 DB 기준 절대 주소로 읽는데 DB 가 `5E` 라 WRAM 이 아니라 `5E:1D93`·`5E:1D91` 을 읽었습니다. snes9x 는 이 자리를 롬 거울로 두어 `4E`·`D0` 이 나왔습니다. X 는 0~F 만 돌므로 `D0` 과 같아질 수 없습니다.

DB 를 `5E` 로 둔 것은 BRK 핸들러(`00:8F92`)입니다. 핸들러는 DB 를 BRK 를 부른 코드의 뱅크로 둡니다. 서장 칼 여섯 합 루틴(뱅크 `5E`)이 합마다 `BRK 16 효과음 갈래` 를 불렀고, `BRK 16` 은 `00:92DE` 에서 `24:FEAC`(대기열에 넣기) 뒤 `24:FE44` 를 부릅니다. 1장 문서에 적어 둔 `BRK 95` 함정(`STA $0A00` 이 롬에 씀)과 같은 원인입니다.

## 2. MesenCE 에서는 왜 지나갔나

MesenCE 에 뱅크 `40`~`7D` 의 아래쪽 절반(`xx:0000`~`7FFF`) 읽기·쓰기를 PC 별로 적는 Lua 콜백을 붙여 서장 검사와 1장 걷기 검사를 다시 돌렸습니다. `24:FE52`·`24:FE55` 가 `5E:1D93`·`5E:1D91` 을 읽었고 값은 둘 다 `1D` 였습니다. 열린 버스라 직전에 읽은 피연산자 윗바이트가 남은 것입니다. 머리와 꼬리가 같으니 기다림을 그냥 건너뛰었습니다. bsnes 도 고치기 전에 통과했지만 이 자리에서 읽은 값은 재지 않았습니다. 실기는 카트가 이 자리를 어떻게 잇느냐에 따라 MesenCE 처럼 건너뛰거나 snes9x 처럼 멈출 것으로 보지만, 가설이고 재지 않았습니다.

1장 걷기 검사 전 구간에서 기록된 47줄 가운데 이 둘을 빼면 모두 DQ5 원래 코드(뱅크 `25`)가 SRAM `70:0000`~`1FFF` 을 읽고 쓴 것이었습니다. 다른 우리 코드에서는 같은 일이 나오지 않았습니다.

## 3. 고침

`BRK 16` 대신 같은 일을 직접 합니다(`dq4prologue._effect`). P·DB·D·A·X·Y 를 저장하고, DB·D 를 0 으로 둔 뒤 `LDA #효과음` / `LDX #갈래` / `JSL 24:FEAC` / `JSL 24:FE44` 를 하고 되돌립니다. 효과음 바꿔치기 훅은 `24:FEAC` 입구에 있어 그대로 걸립니다. 단위 테스트가 칼 루틴에 `00 16` 이 없고 두 길(칼 효과 자료가 있을 때와 없을 때)에 합마다 `JSL 24:FEAC` 가 있는지 봅니다.

이제 기다림이 실제로 돌아, 합마다 효과음이 SPC 쪽으로 넘어가기까지 1프레임을 더 기다립니다. snes9x 에서 대기열 꼬리가 바뀐 프레임으로 재니 합 사이가 31·61·31·21·61프레임이었습니다(원래 간격 30·60·30·20·60). 잰 다섯 간격에서 모두 5프레임 늘었고, 마지막 합 뒤 간격은 재지 않았습니다.

서장 검사의 출발점(2230프레임)은 그 앞 A 연타로 고정한 시각입니다. 연출이 길어지자 연타 하나가 조작이 풀린 뒤에 닿아 명령 창이 열린 채 걷기가 시작됐습니다. 그래서 첫 구간 앞에 창 닫기(B 두 번)를 넣었습니다.

## 4. 확인

- 서장 검사: MesenCE, bsnes 115, snes9x 1.63 모두 통과(맵 `3C/00`→`3C/01`→`3C/00`→`36/01`, 깃발 다섯).
- MesenCE 접근 기록: 고친 롬의 서장 검사에서 뱅크 `5E` 아래쪽 절반 읽기가 없어짐.
- MesenCE 1장 걷기 검사(`dq4ch1walkcheck.py`) 전 구간 통과.
- 단위 테스트 `test_dq4prologue`.

## 남은 것

- 실기·플래시 카트에서는 돌려 보지 않았습니다.
- 다른 에뮬레이터 검사는 저장소 밖의 임시 libretro 프런트엔드로 했습니다. CI 나 도구로 넣지 않았습니다.
- 접근 기록은 서장·1장 걷기 검사가 지나는 길만 봅니다. 전투·가게·저장 같은 다른 길에서 뱅크 `5E` 코드가 부르는 BRK 는 따로 재지 않았습니다.
- snes9x 로는 서장까지만 걸었습니다. 1장 걷기는 MesenCE 세이브스테이트와 워프를 써서 libretro 로 옮기지 않았습니다.
