# 2026-10-30-18: 메뉴를 나갈 때 메뉴 곡 줄이기

앞 일지(16)에서는 새 게임 훅이 `1A` 로 메뉴 곡을 끄게 했습니다. 그 판을 에뮬레이터로 돌리자 두 가지가 보고되었습니다. 이름 입력 화면에서 곡이 끊겼고, 대사 효과음이 사라진 것 같았습니다. 원인은 메뉴를 나갈 때 곡을 줄이는 명령이 DQ5 메뉴 곡 번호 `10` 을 그대로 쓰는 데 있었습니다. 서곡 빌드가 그 번호를 바꾸고, `1A` 는 뺐습니다. 명세는 [타이틀 서곡](../docs/dq4-overture-format.md)과 [1장 첫머리의 시작 연출 곡](../docs/dq4-chapter1-format.md#시작-연출-곡)에 있습니다.

## 1. 재는 법을 바꿈

앞에서는 지금 곡 변수 `$1D8B` 와 DSP KON 수를 셌습니다. KON 은 곡을 줄여도 계속 나오므로 소리가 나는지 가리지 못합니다. 이번에는 프레임마다 목소리별 ENVX(`x8`)와 음량(`x0`·`x1`)을 읽었습니다. 둘 다 0 이 아닌 프레임을 100프레임마다 셌습니다.

헤드리스 입력에도 문제가 있었습니다. MesenCE 저장 폴더에 앞 실행의 모험의 서가 남아 있었습니다. 그래서 A 연타가 이어하기로 들어가 이름 입력을 한 번도 거치지 않았습니다. 롬 이름을 실행마다 새로 지어 저장이 없는 상태로 「모험의 서를 만든다」→ 이름 입력 길을 탔습니다.

## 2. 원인

- **이름 입력에서 끊김**: 「모험의 서를 만든다」를 고르면 이름 입력 전에 시작 지점 표(`25:8321`)를 읽습니다. 새 게임 훅이 거기서 `1A` 를 보내 곡을 껐습니다(622프레임).
- **서술 동안 메뉴 곡**: 메뉴를 나갈 때 `00:A719` 의 `BRK 18 10 1E` 가 곡 `10` 을 줄입니다(BRK 처리기 입구 `00:8F80` 에서 스택으로 부른 자리를 잡음). 명령 `04` 는 지금 곡이 인자와 같을 때만 줄입니다. 메뉴 곡을 `23` 으로 바꾼 뒤로는 줄지 않았습니다. 맵 훅에서 `1A` 를 보내거나 `23:FE69` 로 줄여도 서술 동안 음악은 그대로 울렸습니다.
- **효과음**: 헤드리스에서는 쪽을 넘길 때의 `33` 과 대사의 `32` 가 효과음 목소리 7 에서 소리를 냈습니다. 서술 동안 `32` 가 없는 것은 `1A` 와 상관없이 모든 판이 같았습니다. 사라졌다는 소리가 무엇인지는 헤드리스로 가리지 못했습니다.

## 3. 고침

서곡 빌드가 `00:A71B`(곡 바이트)를 `23` 으로 바꿉니다(`MENU_FADE`). 처음에는 `00:A71A` 로 한 바이트 잘못 짚었습니다. 그러자 서곡 빌드가 원래 바이트 확인에서 멈췄는데, 빌드 스크립트의 `| tail` 이 오류를 묻어 옛 메뉴 롬으로 이어 빌드했습니다. 1장 훅의 `1A` 는 뺐습니다. 사운드 세트를 얹은 롬에서 다음과 같았습니다.

| 길 | 메뉴·이름 입력 | 상자·서술 | 방이 밝아진 뒤 |
| --- | --- | --- | --- |
| 이름 입력 | 곡이 이어짐(400~1000 칸 300~550) | 음악 0, 효과음은 쪽 넘김 때 | 성 곡, 대사 효과음 |
| 이어하기 | 메뉴 곡이 줄어 600 칸부터 0 | 음악 0 | 1000 칸부터 성 곡 |

## 남은 것

- 사라졌다는 효과음이 무엇이었는지 사용자와 확인하기.
- 이어하기 길도 메뉴를 나갈 때 곡이 줄어드는데, 저장한 맵에서 다시 시작할 때 맵 곡이 바로 나오는지 재기.
