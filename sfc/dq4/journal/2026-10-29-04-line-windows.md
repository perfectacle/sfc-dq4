# 2026-10-29-04: 한 줄 창과 전투에서 미룬 창 타일맵

본문에 가나가 남은 창 가운데 한 줄 창 셋(`2D`·`82`·`83`)과 창 `20` 을 한글로 바꿨습니다. 그러다 전투에서 창이 아예 뜨지 않는 문제를 찾아, 대기열과 창 타일맵 전송이 겹칠 때 전투에서는 대기열 쪽을 미루게 고쳤습니다. 결과는 [가나 칸 슬롯](../docs/dq4-window-text-format.md#가나-칸-슬롯)에 있습니다.

## 1. 남은 창 풀기

남은 창의 본문을 문자열로 풀었습니다.

```
20  １そのまま　{이름}… みる … おわり …
2D  じゅもんはつかえない
82  じゅもんを　まだ　おぼえていない
83  どうぐを　もっていない
89  　エラーデス！！         91  オーバーです　べ
93  ＨＰとＭＰ / こうげきカ / つよさみる / まんたん / いんちき
```

`89`·`91`·`93` 은 디버그로 보여 남겼습니다. `2D`·`82`·`83` 은 항목 머리 `FE` 가 없는 한 줄 창이라, 레코드 고쳐 쓰기가 손대지 않았습니다. 줄 전체를 문구 하나(`9E k`)로 바꾸는 `LINE_WINDOWS` 를 더했습니다. 빈칸 `01` 이 든 줄은 문구 키에 `　` 을 넣습니다.

| 창 | 한글 |
| --- | --- |
| `2D` | 주문을 못 쓴다(창 안쪽 10열이라 「주문을 쓸 수 없다」 11열을 줄임) |
| `82` | 아직 주문을 익히지 않았다 |
| `83` | 가진 도구가 없다 |
| `20` | 그대로 / 보기 / 끝 |

새 문구를 넣자 한글 그림 뱅크 `58` 이 넘쳤습니다. 지난번에 넣은 주문 표 가나 대체(DQ5 전용 주문과 몬스터 행동 19개)를 빼고 물건만 남겼습니다.

## 2. 전투에서 뜨지 않는 창

무작위 입력에 창 열기(`04:9C52`) 기록을 걸자 `83` 이 09/00 전투에서 열렸습니다. 도구가 없는 スラリン 이 「도구」 를 고른 장면입니다. 정해진 입력으로 같은 장면을 만들어 원래 롬과 견줬습니다. 원래 롬은 「どうぐを もっていない」 가 수십 프레임 떠 있다 닫혔는데, 새 롬은 메뉴만 어두워지고 창이 보이지 않았습니다.

창 타일맵을 보내는 `00:8DED` 와 `$0BEC`·`7E:3D5A` 를 기록했습니다.

```
원래  1127 008DED  $0BEC=80  3D5A=00
새    1127 008DED  $0BEC=00  3D5A=80   (그 뒤 008DED 없음)
```

창을 그린 NMI 에 우리 대기열(문구 그림)과 `$0BEC` 가 겹쳐, 게이트가 `$0BEC` 를 다음 NMI 로 미뤘습니다. 필드는 `00:8DED` 가 매 NMI 돌아 다음 NMI 에 보내지만, 전투 NMI 작업은 요청이 있을 때 한 번만 돌아 미룬 요청이 끝내 가지 않았습니다. 전투(`$1944` = `00:8952`)에서는 거꾸로 우리 대기열을 다음 NMI 로 미루게 했습니다. 고친 뒤 원래 롬과 같은 프레임에 「가진 도구가 없다」 가 뜨고 뒤 메뉴가 어두워졌습니다. 첫 프레임만 글자가 한 NMI 늦게 올라옵니다.

| 장면 | 결과 |
| --- | --- |
| 09/00 전투 → スラリン → 도구 | 「가진 도구가 없다」, 원래 롬과 같은 프레임 |
| 강함 보기 · 강함 보기 뒤 전투 가나 복원 | 그대로 |
| 무작위 입력 6벌(전투 둘 포함) · 이름 검사 셋 · 단위 시험 | 모두 정상 |

## 틀렸던 것들

- 처음에는 무작위 입력 화면에서 창이 안 보인 것을, 새 롬의 NMI 시간이 달라 입력이 다른 때 눌려 창이 바로 닫힌 것으로 봤습니다. 정해진 입력으로 원래 롬과 같은 장면을 만들자 창이 뜨지 않는 것이 분명했습니다.

## 남은 것

- `2D`·`82`·`20` 과 지난번의 `4B`·`4E`·`77`·`7E` 가 뜨는 장면
- 디버그로 보이는 창(`89`·`91`·`8D`~`90`·`93`)과 `9F` 자리 표시 창
