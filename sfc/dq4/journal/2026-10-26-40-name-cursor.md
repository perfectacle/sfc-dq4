# 2026-10-26-40: 자모판 방향 전환과 Start 이동

조합형 이름 입력의 방향 전환을 조사했습니다. 빠르게 위와 왼쪽을 이어 누르면 새 입력이 사라지거나, 한 방향을 계속 누르는데도 이동이 다시 시작됐습니다. 결과는 [조합형 이름 입력](../docs/dq4-name-entry-format.md)에 반영합니다.

## 1. 효과음과 입력을 분리하기

원래 커서 이동에 더한 효과음이 입력을 바꾸는지 의심했습니다. 같은 입력 네 가지를 효과음이 있는 롬과 제거한 롬에서 실행했지만 커서 처리 로그는 같았습니다. 효과음 호출 자체가 방향 값을 바꾼다는 근거는 없었습니다.

## 2. 그리는 동안 사라진 방향

1300프레임에 위로 이동하고 바로 다음 프레임에 왼쪽을 한 프레임 누르면, `$24`에는 왼쪽 값이 들어왔지만 커서가 움직이지 않았습니다. 커서 그리기가 끝난 뒤 `04:D222`에서 다음 프레임을 먼저 기다리면서 그 입력을 놓쳤습니다.

## 3. 한 방향만 떼어도 새 이동

위+왼쪽을 겹쳐 누르는 실행에서는 1507프레임에 입력 `0A`로 왼쪽 `9→8` 이동이 나왔습니다. 그다음 위만 떼어 입력이 `02`가 되자 1509프레임에 왼쪽 `8→4` 이동이 다시 나왔습니다. 왼쪽은 계속 누른 상태였습니다.

원래 반복 처리기는 전체 방향 비트가 바뀌면 새 입력처럼 다룹니다. 자모판의 `5`~`7`은 빈칸이라 두 번째 이동이 화면에서 더 큰 도약으로 보였습니다.

## 4. 빈칸과 줄 경계

맨 윗줄 왼쪽 끝에서 왼쪽을 누르면 색인 `0→21`로, 다음 줄의 「지우기」로 갔습니다. 원래 가나판의 빈칸 탐색이 두벌식 자모판의 배열과 맞지 않았습니다. 반복 처리와 별도로, 이동 경로도 자모판의 행·열에 맞춰야 했습니다.

## 5. 선택한 방향 하나로 반복하기

한글 자모판에서는 실제 눌린 방향 중 하나를 선택해 반복 상태를 관리하도록 바꿨습니다. 새로 누른 방향이 있으면 먼저 고르고, 그 방향을 계속 누르는 동안 다른 방향을 떼어도 반복 대기를 다시 시작하지 않습니다. 커서 그리기 중 들어온 전환은 다음 선택 처리에서 먼저 반영합니다.

한 프레임씩 위와 왼쪽을 누르는 실측에서 1300프레임 `11→0`, 1301프레임 `0→9`로 이동했습니다. 첫 반복은 16프레임, 그 뒤는 7프레임 간격이었습니다. 맨 윗줄의 왼쪽 경계도 같은 줄의 끝으로 돌아가게 했습니다.

## 6. Start는 「끝」으로 이동

물리 Start는 원본의 가공된 입력 `$24`에 들어가지 않으므로 원시 패드 값을 읽습니다. 한글 자모판에서 Start를 새로 누르면 「끝」으로 커서만 옮기고, 이름 확정은 A로 고르게 합니다. 기존 Y 완료는 유지합니다.

## 7. 회귀 검사

방향·Start 실측 52개, 기존 조합·삭제·Y 완료·새 게임 이름 실측 15개를 모두 통과했습니다. 모든 유효 칸에서 Start를 40프레임 유지해 이름·완료 버퍼가 바뀌지 않는지 확인하고, 이후 A를 누른 경우에만 반환하는지 따로 검사했습니다. 「끝」에서 Start를 누른 뒤 B로 삭제해도 커서가 같은 자리에 남았습니다.

이웃 표 검사와 실제 빌드를 포함한 단위 검사 28개도 통과했습니다. 검사 도구는 `dq4namecursorcheck.py`와 `dq4nameentrycheck.py`입니다.
