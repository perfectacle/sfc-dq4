# 2026-10-27-21: 간판 바탕과 열쇠 문, とびら 실측

환경 그래픽 todo 에 남아 있던 셋을 정리했습니다. 벽 위 간판의 바탕색, 열쇠 문의 잠금, 명령 창 とびら 로 문 열기입니다. 결과는 [환경 그래픽 문서](../docs/dq4-environment-format.md#문과-성문)에 있습니다.

## 1. 간판을 벽돌과 같은 줄로

여관·교회·무기점·방어구점·도구점 간판은 나무 줄(4번)에 그렸습니다. 투명한 바탕을 벽돌(2번 줄)로 채우면 4번 줄에 벽돌 색이 없어 가장 가까운 회갈색으로 바뀌었습니다(채널 합 오차 최대 109).

4번 줄의 빈칸을 세어 보니 벽돌 색 다섯을 넣을 자리가 없었습니다. 반대로 간판을 2번 줄로 옮겼습니다. 2번 줄에는 붉은 갈색 램프(`6d2921`·`b5604f`·`f7c69c`)가 있어 나무 판으로 쓸 수 있습니다. 4번 줄 색 번호를 2번 줄 번호로 바꾸는 표 하나로 다섯 간판을 옮겼고, 바탕을 바꾼 픽셀은 0개가 되었습니다.

## 2. 열쇠 문

FC 의 문 속성은 열쇠 단계별로 `94`(없음)·`95`(とうぞくのカギ)·`96`(まほうのカギ)·`97`(さいごのカギ)입니다. DQ5 의 문 항목 끝 바이트 아래 6비트는 잠금 종류입니다. 잠금 1·2·3 은 일행의 열쇠 단계(カギの技法·まほうのカギ·さいごのカギ)와 견줍니다([dq5 문 잠금](../../dq5/docs/dq5-map-format.md#문-잠금-01dcfc)). 단계가 같은 구조라 `95` → 잠금 1, `96` → 잠금 2 로 옮겼습니다. 바꾼 맵에서는 네 맵의 문 여섯이 잠금 문입니다.

## 3. とびら 실측

예전에는 명령 창 커서가 나오는 시점을 맞추지 못해 とびら 를 고르지 못했습니다. 이번에는 10프레임마다 화면을 찍어 보니, A 를 누른 뒤 60프레임쯤에 커서가 나왔습니다. 명령 창은 두 열이고 とびら 는 왼쪽 열 넷째 줄입니다.

```text
워프(문 바로 아래 칸) → 위 3 → 30프레임 → A → 80프레임 → 아래 ×3 → A
```

| 문 | 잠금 | 조건 | 결과 |
| --- | --- | --- | --- |
| イムル (42,37) | 0 | 열쇠 없음 | 열림, `7E:21C2` = `01` |
| `01/00` (16,3) | 1 | 열쇠 없음 | 「カギを　持っていない。」 |
| `01/00` (16,3) | 1 | `2199.1` | 열림 |
| `00/00` (42,35) | 2 | 열쇠 없음 | 「カギを　持っていない。」 |
| `00/00` (42,35) | 2 | `2199.1` | 「カギが　合わない！」 |

잠금 없는 문 넷(イムル 둘·바트랜드·ミントス)이 처음에는 모두 「その方向には　トビラがない！」 였습니다. 잠금 문만 열리니 잠금 0 이 문으로 안 보이는 줄 알았습니다. `01:D000`~`E1FF` 의 실행 주소를 두 실행에서 차례로 모아 견주니 `01:DA4D` 에서 갈렸습니다. 여기서 `$1E8F` 의 bit7·bit6 으로 앞 칸 좌표를 고치는데, 실패한 실행에서는 그 값이 위가 아니었습니다. 워프 뒤 60프레임 기다렸다가 위를 누르면 몇 번은 방향이 바뀌지 않았던 것입니다. 워프 직후 바로 위를 누르자 잠금 0 문이 열렸습니다(`01:DFAB`).

## 4. 검사

간판·잠금을 넣은 롬으로 46곳 모두 픽셀 차이 0, 물체 54개, 통행 차이 0, 이동, 물 순환, BG1 빈 타일 유지를 통과했습니다. 부팅 시험은 배 선실에 닿았고 네 장면 끝 상태가 원래 롬과 같았습니다.

## 틀렸던 것들

- 잠금 0 문이 とびら 로 안 열리는 것을 잠금 값 탓으로 봤습니다. 주인공이 위를 보지 않은 입력 타이밍 문제였습니다.

## 남은 것

- 열쇠 아이템 번호를 DQ4 열쇠에 맞추기, まほうのカギ 로 잠금 2 를 여는 실측.
- 마지막 열쇠 문 `97` 을 물체로 바꾸기(카운터에도 쓰이는 속성이라 가려야 함).
