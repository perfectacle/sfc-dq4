# 2026-10-31-04: 왕의 선물을 상태 창으로 — BRK 95 가 창을 못 연 까닭

FC 는 왕의 선물 동안 상태 창(ちから~Ex)을 띄우고 Ex 를 0 에서 3000 까지 올립니다. [지난 일지](2026-10-31-01-ch1-levelup.md)에서는 능력치 창 `07` 을 `BRK 95 07` 로 열면 창 없이 멈춰 서술 한 줄로 두었습니다. 이번에 원인을 찾아 상태 창을 넣었습니다. 결과는 [1장 첫머리 문서](../docs/dq4-chapter1-format.md#왕에게-보고와-1장-끝)의 「상태 창」에 있습니다.

## 1. 게임은 상태 창을 어떻게 여나

필드에서 명령 창 「상태 → 상태 보기」를 골랐습니다. 창을 여는 `04:9C52` 와 창 번호 `$0A00` 쓰기를 기록했습니다.

- `00:9489` 가 `$0A00` = `08` 을 쓰고, 레코드 셋(이름·능력 `EE30`, 능력치 `FECA`, 장비 `EDA8`)을 한 번에 열었습니다.
- 메뉴는 `BRK 95 06` 을 부릅니다. 핸들러 `00:940D` 가 06 을 받으면 `00:9477` 로 가서 `$0A48`=06·`$0A47`=07·`$0A00`=08 을 넣고 `JSL $049905` 를 부릅니다.
- `07` 은 그 셋 가운데 하나라, 홀로 열 창이 아니었습니다.

## 2. 왜 멈췄나

`BRK 95 06` 으로 바꿔도 창이 뜨지 않았습니다. 핸들러를 따라가니 `00:9419` 에서 읽은 `$0A00` 이 `FF` 였습니다.

- BRK 핸들러(`00:8F92`)는 DB 를 BRK 를 부른 코드의 뱅크로 둡니다.
- `00:9085` 는 창 번호를 `STA $0A00`(DB 기준)으로 씁니다.
- 우리 네이티브는 뱅크 `5E` 에 있습니다. `5E` 에는 WRAM 거울이 없어 그 쓰기가 롬으로 갔습니다.

원래 게임은 뱅크 00~3F 에서 부르므로 문제가 없습니다. 지난판의 `BRK 95 07`·`BRK 95 FF` 가 멈춘 것도 같은 까닭으로 봅니다. 그래서 BRK 를 쓰지 않고, DB 0 에서 세 자리를 쓴 뒤 `049905` 를 직접 부릅니다. 핸들러처럼 직접 페이지 `$00`~`$0F` 도 지킵니다.

## 3. 숫자 올리기

| 시도 | 결과 |
| --- | --- |
| 단계마다 능력치 창(07)만 다시 엶 | 숫자는 오르지만 왼쪽 이름 창이 사라짐 |
| 단계마다 창 셋을 다시 엶 | 창은 남지만 한 번에 약 30프레임, 그리는 동안 창 아래가 어두워짐 |
| 버퍼의 숫자 칸만 고치고 `04:9D5E` 로 줄 전송 | 매끄럽게 오름 |

경험치 줄은 창 타일맵 버퍼 `7E:5000` 의 25행 24~30열이고, 숫자 타일은 값 + 2 입니다. 처음에는 높은 바이트를 `2C` 로 써서 앞 빈칸이 어두운 칸으로 보였습니다. 활성 창은 `20` 이었습니다. 지금은 같은 줄 「:」 칸의 것을 씁니다.

한 단계가 2프레임이라 20씩 150번 올려, FC 와 같은 300프레임이 걸립니다.

## 남은 것

- FC 는 레벨업 메시지 동안에도 상태 창이 남습니다. 여기서는 레벨업 전에 닫습니다.
- 레벨이 오를 때 배운 주문 메시지.
