# 2026-10-31-17: 진행에 따라 바뀌는 1장 대사와 손님 호이민

FC 와 맞대 보니 막지는 않지만 어긋난 곳이 넷 남아 있었습니다. 41 동굴 병사는 일본어 자리 표시 「＜なにもない＞」를 띄웠습니다. 왕의 방 왕과 탑의 병사는 진행에 따라 바뀌는 대사가 없었습니다. 우물 아래 목소리는 하나가 빠졌고, 남은 것도 칸 하나에서 한 번만 떴습니다. 호이민은 전투에서 명령을 받았습니다. 명세는 [1장 첫머리의 「진행에 따라 바뀌는 대사」](../docs/dq4-chapter1-format.md#진행에-따라-바뀌는-대사)와 [「우물 아래와 호이민」](../docs/dq4-chapter1-format.md#우물-아래와-호이민)에 있습니다.

## 1. 동굴 병사의 차례는 말할 때가 아니라 나갈 때 오른다

FC 대화 `014` 는 보스를 이기기 전이면 `call+2 15:9D3E` 를 부릅니다. 이 루틴은 `$6281` 아래 두 비트를 차례로 보고 `0790`·`0791`·`0792` 중 하나를 띄웁니다.

```
15:9D3E  LDX #0 / LDA $6281 / AND #3 / BEQ → BRK 06 CB 04   ; 0 → 0790, $6281 |= 04
         INX / CMP #1 / BEQ → BRK 06 CB 04                   ; 1 → 0791
         INX / BNE → TXA / JMP $A695                         ; 2 → 0792, bit2 는 켜지 않음
```

`BRK 06 CB 04` 는 차례를 올리지 않습니다. 「이야기했음」(bit2)만 켭니다. 차례를 올리는 곳은 `15:9CF9` 였습니다. FC 쪽 기록(상점 형식)에 따르면 `15` 함수 `10` 이 맵에서 필드로 나갈 때(`1E:9311`) 불리고, 1장이면 이 자리에서 bit2 를 보고 아래 비트에 1 을 더합니다. 처음에는 「말을 걸 때마다 바뀐다」고 적었는데 틀렸습니다. 한 방문 안에서는 같은 대사이고, 다시 들어와야 바뀝니다.

DQ5 에는 그런 자리가 없습니다. 41 동굴은 두 출구가 모두 필드이므로, 동굴에 들어설 때 보이지 않는 인물이 「이야기했음」을 보고 차례를 올려도 같은 일입니다. 깃발은 시험하는 곳이 없는 비트 셋(`21BE` bit3, `21E4` bit3·4)을 썼습니다. 다른 워크트리와 열린 PR 이 이 비트를 쓰지 않는 것도 확인했습니다. 스크립트 인물은 이 해킹이 가지 않는 DQ5 `03/0A` 의 남은 넷을 빌렸습니다.

병사는 걸어 다니는 인물이라 처음에는 말이 닿지 않았습니다(`129` 「그 방향에는 아무도 없다」). 걸음 간격 `7E:3308` 을 0 으로 묶고 재니 이렇게 나왔습니다.

| 방문 | 메시지 | `21BE` `21E4` |
| --- | --- | --- |
| 1 | `DA3`(0790) | `08 00` |
| 2 | `DA4`(0791) | `08 08` |
| 3 | `DA5`(0792) | `00 10` |
| 4 | `DA5` | `00 10` |

동굴에도 조우가 생겨서(같은 날 다른 PR), 전투 뒤 인물 스크립트가 다시 돌아 한 방문 안에서 차례가 오르지는 않는지 재 보았습니다. 말을 건 뒤 동굴 안을 걸으며 싸웠고 전투 메시지가 85개 나왔습니다. 깃발은 `08 00` 그대로였습니다.

## 2. 왕과 탑의 병사

왕의 방 왕(`00B`)은 `item 6C`(そらとぶくつ)로 `0786`·`0785` 를 고르고, 둘 다 `060A` 로 이어집니다. DQ5 대화 조건 `11`(일행 누군가가 물건을 가짐)에 ソラトブクツ `CD` 를 주었습니다. 탑의 병사(`148`)는 `0797` 뒤 `party 08`(호이민) 이면 `0798`(「おまえが うらやましいよ。」)을 잇습니다. 1장에서 호이민은 합류한 뒤 떠나지 않으므로 합류 깃발로 봅니다.

## 3. 목소리 다섯 무리

FC 우물 아래 `3A/00` 의 인물 블록을 풀자 목소리 이벤트가 셋이었습니다.

```
$ uv run --locked python fc/dq4/tools/dq4npcblock.py rom/dq4.nes 3A 00 | grep -A1 이벤트
    +00 8a 05        이벤트 05 → 1D:$99F1
    +02 26 ec 02     메시지 02EC
    +00 8a 08        이벤트 08 → 1D:$9B36
    +02 26 ed 02     메시지 02ED
    +00 8a 07        이벤트 07 → 1D:$9B2F
    +02 26 ee 02     메시지 02EE
```

다섯 이벤트가 칸 표 둘(`1D:9A41`~, `9A7D`~)을 X 의 범위로 나눠 씁니다. 칸마다 바라볼 방향(`$3D`)이 있고, 뜬 뒤에는 그 무리의 칸을 모두 벗어날 때까지 `$627C` 비트로 막습니다. `08`(`02ED`)만 `A` = `40` 이라 `1D:9A31` 에서 구두 검사(`9B6B`, `BRK 66 73` 으로 `6C` 를 찾음)를 건너뜁니다. 지금까지 넣은 것은 `3B/00` (14,0C)과 `3B/03` (14,10) 두 칸이었고, 방향·구두를 보지 않으며, 인물 스크립트가 명령 `16`(멈춤)으로 끝나 한 번만 떴습니다.

무리마다 보이지 않는 인물 하나를 두고, 「칸·방향·구두」 루틴과 「모두 벗어남」 루틴을 번갈아 기다리게 했습니다. 처음 롬은 구두 판정이 거꾸로였습니다. 구두를 가지면 뜨고 안 가지면 뜨지 않았습니다. `BRK 88 90` 은 가지지 않았을 때 `$46` bit7 이 켜집니다.

걸어서 재니 주인공이 홀수 셀(41, 39, …)에 서서 짝수 셀만 보는 판정에 걸리지 않았습니다. 셀 X `AND #$FE`, (Y−1) `AND #$FE` 로 FC 칸을 구하게 고쳤습니다. 그 뒤로 반 칸 (41,25)에서도 뜨고, 왼쪽으로 걷다 오른쪽으로 갔다 다시 왼쪽으로 오면 두 번 떴습니다.

## 4. 호이민이 명령을 받지 않게

작전 `7E:2034` 가 5(めいれいさせろ)인 1장 롬에서 보스와 싸우며 주인공 명령만 넣었습니다. 호이민 기록 `+0` 이 `85` 이면 전투 메시지가 하나도 나오지 않았습니다. 호이민의 명령 창이 입력을 기다린 것입니다.

명령 입력에서 B 로 앞 사람에게 돌아가는 고리(`20:9210`)가 건너뛸 사람을 고르는 `20:9243` 은 `BRK 8B 80 2A`(레코드 `+0`)의 bit6 을 먼저 보고, 다음으로 `$1070` bit6 을 봅니다. `$1070` bit6 은 `26:82D9` 이 켜고, 작전이 5 면 끕니다. 「AI 로 싸우는 중」 표시입니다. 그러니 `+0` bit6(손님, 파파스처럼)이 켜진 사람은 작전과 상관없이 명령을 받지 않습니다. `+0` 을 `C5` 로 두자 차례가 돌아 「ホイミン의 공격!」이 나왔고, 다음 차례의 명령 창은 손님만 있을 때처럼 「싸우기·도망」이었습니다.

## 남은 것

- 호이민이 행동을 고르는 법은 아직 FC 와 다릅니다. かしこさ 가 6 이라 DQ5 가 「싸우기」와 배운 전투 주문 가운데 무작위로 고릅니다. FC 손님 레코드 `C5` 로 보면, 다친 동료가 있을 때만 ホイミ 를 거의 늘 쓰고 아니면 공격·방어입니다.
- 동료 이름 「ホイミン」 은 가나로 나옵니다.
