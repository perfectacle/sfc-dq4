# 2026-11-03-06: 효과음 장면의 회심을 시드 대신 판정 고정으로

효과음 장면 검사의 `battle-critical` 은 시드를 골라 회심을 기다렸는데, 롬이 바뀔 때마다 고른 시드에서 회심이 사라졌다. 검사 롬 사본에서 회심 판정 난수의 범위를 1 로 바꿔, 시드·롬 바이트와 상관없이 첫 공격이 회심이 되게 했다. 결과는 [사운드 포팅 「회심을 직접 일으키기」](../docs/dq4-sound-port-format.md#회심을-직접-일으키기2026-11-03) 에 반영했다.

## 1. 고치기 전

main 의 1장 롬(`dq4build.py --out work/ch1`, SHA-1 `be44767f`)으로 돌리자 두 코어 모두 실패했다.

```
failed bsnes  battle-critical    0C 37 01@1188♪nds, 0C 37 0B@None✕ 회심 미발생(시드 다시 고르기: dq4sfxscene.py --pick-critical-seed)
failed Snes9x battle-critical    0C 37 01@1187♪nds, 0C 37 0B@None✕ 회심 미발생(시드 다시 고르기: dq4sfxscene.py --pick-critical-seed)
```

회심 판정 난수는 전투에 드는 프레임 수에 따라 달라진다. 창 글자 패치처럼 NMI 에 드는 시간만 바꾼 변경에도 시드 84·55 에서 회심이 나지 않았다. 앞서도 48·19 에서 84·55 로 다시 골랐다.

## 2. 회심 판정 자리

DQ5 일지 [2026-10-25-117](../../dq5/journal/2026-10-25-117-damage3.md) 가 일행의 たたかう 에서 회심을 가르는 곳을 `20:C697` 로 찾았고, `20:C6B3` 의 `20` 을 `01` 로 덮어 늘 회심이 나는 것을 원본 DQ5 에서 확인했다. 1장 롬의 같은 자리를 원본 DQ5 와 견주니 `20:C697`~`C6CF` 가 바이트까지 같았다.

```
20:C6B2  A9 20        LDA #$20
20:C6B4  22 3A 95 00  JSL $00953A     ; (8비트 난수 × A) >> 8
20:C6B8  C9 00        CMP #$00
20:C6BA  F0 02        BEQ +2          ; 0 이면 LDA #$80 / STA $0DA8 / SEC
```

`00:953A` 는 `(8비트 난수 × A) >> 8` 이라([DQ5 데이터 형식](../../dq5/docs/dq5-data-format.md)) A = `20` 이면 0~31, A = `01` 이면 늘 0 이다. 0 은 원래 롬에서도 8비트 난수가 0~7 일 때(1/32) 나는 값이다. 판정 뒤 분기·회심 피해·효과음 `37-0B` 는 원래 코드 그대로 지난다.

## 3. 고친 것

`dq4sfxscene.py` 는 `critical` 장면의 검사 롬 사본에만 `1046B3` 을 `01` 로 쓴다(`critical_patch`). 자리 바이트 열 개(`A9 20 22 3A 95 00 C9 00 F0 02`)가 다르면 장면을 돌리기 전에 멈춘다. 코어마다 둔 시드(`CRITICAL_SEED`)와 시드 고르기(`--pick-critical-seed`)는 지웠다.

## 4. 결과

| 롬 | 시드 | snes9x `37-01` / `37-0B` | bsnes `37-01` / `37-0B` |
| --- | --- | --- | --- |
| `be44767f`, 판정 고정 | 0 | 1187 / 1238 | 1188 / 1239 |
| 빈 자리 `194D67` 한 바이트를 바꾼 사본 `6609bc4a` | 0 | 1187 / 1238 | 1188 / 1239 |
| `be44767f`, 판정 고정 | 1·7·42 | 1238(셋 모두) | 1239(셋 모두) |

두 코어 모두 첫 공격이 회심이었다. 공격 시작 51프레임 뒤에 `0C 37 0B` 가 대기열에 들어갔고, 목소리 7·6 이 함께 울렸다(목소리 7 은 잡음). 단위 테스트 `test_critical_patch_narrows_roll_only`·`test_critical_scene_uses_patch_not_seed` 가 바꾸는 바이트, 자리 확인, 회심 장면이 시드를 쓰지 않는 것을 지킨다.

## 남은 것

- 이 장면은 회심 난수 굴림을 다루지 않는다. 자리 바이트 확인은 판정 코드가 바뀐 것만 잡고, `00:953A` 가 0~31 을 고루 돌려주는지는 보지 않는다.

- 회심 판정 앞의 조건(`$100E` bit7, 필드 `41` 상태, `26:8D0A` 의 가진 물건)은 [2026-11-04-03](2026-11-04-03-critical-conditions.md) 에서 재고 `battle-critical` 이 확인하게 했다.
