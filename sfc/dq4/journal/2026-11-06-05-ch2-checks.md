# 2026-11-06-05: 2장 검사 틀

2장 사건을 여러 세션이 나눠 만들기 전에, 사건마다 구간 하나를 붙일 검사 틀 넷을 세웠다. 2장 걷기 검사(`dq4ch2walkcheck.py`), `dq4npccheck.py --chapter2`, `dq4heroblockcheck.py --chapter2`, 호환성 `dq4compatcheck.py walk --chapter2` 이다. 지금 있는 사건(첫머리·성 안 대화·벽 걷어차기·네 걸음 합류·텐페 제물 앞 절반)으로 넷 모두 통과했다. 붙이는 법은 [검사에 구간 붙이기](../docs/dq4-chapter2-format.md#검사에-구간-붙이기), libretro 쪽은 [호환성 검사의 2장 길](../docs/dq4-compat-format.md#2장-길)에 적었다.

## 1. 2장 출발 상태

2장은 1장 끝에서 넘어와야 일행 기록이 아리나로 바뀐다. 그래서 1장 검사의 서장 끝 상태(캐시)에서 1장 왕 보고 앞까지의 flag 를 두고, 1장 구간 `castle`·`king`(`--chapter2` 끝)을 걸은 뒤 첫머리 구간 `opening` 으로 제목 상자·서두·왕의 말을 넘겼다. 그 끝 상태를 「2장 출발 상태」로 캐시에 두고, 사건 묶음은 모두 여기서 순간이동으로 시작한다.

처음에는 A 를 40번 눌렀더니 첫머리 flag 는 꺼졌지만 메시지 기록에 `E9E`·`E9F` 가 여덟 번 되풀이됐다. 왕에게 다시 말을 걸어 「어찌 그러느냐, 아리나?」 물음이 되풀이된 것이다. 첫 `E9E` 는 12번째 A 바로 뒤에 떴으므로 A 를 열 번으로 줄였다.

```
messages E93@9 E94@557 E95@690 E9E@1369 E9F@1462 E9E@1761 …
press a:8 … f01257(11번째) f01355(12번째)
```

## 2. 사건 구간

구간 표 꼴은 1장 걷기 검사와 같고, flag 표에 2장 flag 아홉을 더했다. 1장 검사의 함수(`setup`·`segment`·`walk_unit`)가 1장 flag 표만 보던 것을 인자로 받게 했다(기본값은 그대로라 1장 걷기는 같은 기록을 냈다).

| 묶음 | 걸은 것 | 처음 시험 |
| --- | --- | --- |
| 크리프트 | (52,23)에서 위로 말 걸기 | 통과 |
| 브라이 | (22,27)에서 오른쪽 | `129`(「その方向には誰もいない」). 주인공이 (23,27)로 한 칸 걸어감. 브라이 셀이 (26,27)이라 (24,27)로 옮김 |
| 성문 병사 | (28,49)에서 아래로 | 통과, 「셋 다」 켜짐 |
| 벽 | (26,10)에서 오른쪽 → 예 | 통과. 필드에서도 `7E:00BC`·`00BD` 는 `3D/02` 그대로라 끝 맵 대신 필드인지와 셀 (78,149)을 봄 |
| 촌장·신부 | 아래에서 위로 → 예 | 통과, 제단 두 칸 아래 (44,31) |

`--repeat 2` 로 묶음마다 두 번 걸어 기록(`walk.txt`·`warp.txt`) SHA-1 을 견주게 했다. 첫 판은 6묶음 13구간 통과, 두 번 같음이었다.

## 3. 시드를 바꾸자 브라이가 비켜 섰다

시드 0·5·9 로 돌리자 5·9 에서 `brey` 만 실패했다. 기록은 `129` 셋이고 주인공은 (25,27)에서 끝났다. 브라이는 이동 간격 4 로 걸어 다니는 인물이라, 난수에 따라 말을 걸기 전에 자리를 떴다. 시드 0 에서 통과한 것은 운이었다.

1장 검사가 이무르 밤의 아이를 묶은 것처럼, 걸음 간격 `7E:3300 + 슬롯` 을 `00` 으로 묶었다. 낮의 `3D/01` 목록에서 브라이는 첫 인물이라 슬롯 `08` 이다. 묶은 뒤 시드 0·5·9·13·21 이 모두 통과했다.

## 4. 합류 뒤 묶음의 일행

텐페 묶음은 2장 출발 상태에서 시작하므로 일행이 아리나 하나였다. 1장 검사의 `PARTY`(`dq5warp.lua` buildParty)는 몬스터 동료 기록(`23:AED1`)만 만들어 사람 동료에 쓸 수 없다. 합류 네이티브(`dq4ch2event._join`)가 하는 일(일행 기록 1·2, 일행 수 3, 순서 0 1 2)을 `dq4ch2event.recruit_records` 로 만든 SET 으로 두게 했다. 텐페 촌장 묶음의 끝 화면 상태 창이 「아리나·크리프트·브라이」 H 16·18·16, M 0·7·10 이었다.

## 5. npccheck 의 23장면

`--chapter2` 는 2장 시작 상태로 옮긴 그룹(`dq4groupbuild.LINKS` 의 `"chapter": 2`, 곧 `3D`·`45`)만 골라 2장 flag 를 켜고 돈다. 처음에 151장면 가운데 23개가 실패했다. flag 를 켜지 않은 `--chapter1` 로 같은 맵을 돌려도 같은 23개가 실패해, 이 변경과 상관없이 main 에서 이미 깨져 있던 것이었다.

실패 장면마다 도착 셀과 인물 셀의 차를 늘어놓았다.

```
talk-3D00-10 OK  person (52, 21) hero (52, 24) d (0, 3)
talk-3D00-17 OK  person (54, 45) hero (52, 46) d (-2, 1)
talk-3D00-18 BAD person (54, 43) hero (54, 42) d (0, -1)
talk-3D01-5  BAD person (44, 19) hero (44, 18) d (0, -1)
talk-3D03-9  BAD person (34, 91) hero None(필드 142,117)
```

통과한 장면은 모두 아래에서 (0,3), 옆에서 (±2,1) 이고, 실패한 말 걸기는 모두 위에서 (0,−1) 이었다. `dq5warp.lua` 는 `TO` 의 한 셀 아래에 내린다. 아래쪽은 한 셀 더 떨어져도 위로 눌러 다가가지만, 위쪽은 인물 위 반과 겹쳐 아래를 봐도 아무도 없다. 마을 맨 아래 FC 줄 인물은 옆 칸에 내려도 한 셀 아래가 맵 밖이라 필드로 나갔다. 말 걸 칸의 셀보다 한 셀 위를 `TO` 로 주게 고치자(`warp_to`) 23장면이 모두 통과했고, 전체 151장면이 통과했다(156초).

## 6. heroblock 과 제단 앞

heroblock 2장 사례는 벽 앞 셀에 왼쪽·위·아래에서 들어서기, 아니요 뒤 비켰다 돌아와 다시 묻기, 걷어찬 뒤 세 방향 네 걸음 합류, 신부에게 세 쪽에서 말 걸기다. 신부 사례 셋은 끝에 (44,33)으로 걷지 못해 실패했다. 제단 앞 (44,31)에서 네 방향 모두 막혔고, A 를 누르면 명령 창이 떠 조작은 돌아와 있었다. 아직 보스 전투가 없는 자리라 그 칸이 막힌 것으로 보고, 신부 사례는 사건이 주인공을 옮겨 둔 셀만 보게 했다. 10사례 × 3시드가 통과했다.

## 7. libretro

호환성 `walk` 는 1장 구간 표를 직접 보던 것을 걷는 표·flag 표로 받게 하고, `--chapter2` 면 서장 → 왕 보고 → 첫머리를 한 코어에서 잇고 그 끝 상태에서 2장 묶음을 따로 걷게 했다. 처음에는 모든 구간이 통과했는데 전체가 실패로 나왔다. 기대 구간 수를 걷지 않는 1장 구간까지 넣은 표 길이(42)로 셌기 때문이라, 서장 1 + 2장 표 16 = 17 로 고쳤다. bsnes·snes9x 가 시드 0·5·9 에서 17/17 이었다(189초).

## 틀렸던 것들

- 브라이 구간이 시드 0 에서 통과해 결정적이라고 보았다. 걸어 다니는 인물이라 시드에 따라 실패했다.
- npccheck 의 23장면을 2장 flag 탓으로 의심했다. flag 없이도 같은 23개가 실패했고 원인은 순간이동 도착 자리였다.
- 신부 사례의 실패를 조작이 돌아오지 않은 것으로 보았다. 명령 창은 열렸고, 서 있는 칸이 막혀 있었다.

## 남은 것

- 보스·이벤트 전투 구간(롬 패치 선택은 첫 전투 사건이 두 검사에 함께 더함)과 지는 경우.
- 텐페 제단 앞 (44,31)이 막힌 칸인 것. 보스 전투가 붙은 뒤 다시 본다.
- heroblock 의 텐페 사례는 일행이 아리나 하나다.
- 2장 길의 열린 버스 프로브.
- E1~E5 뒤 2장 끝까지의 최종 통과.
