# 2026-10-31-62: 반 블록 걸친 문과 걸어서 여는 문

문 아래에서 반 블록 옆으로 비켜 서서 「문」 명령을 고르면 「그 방향에는 문이 없다!」가 나왔습니다. 문을 찾는 칸을 넓히고, 이어서 걸어 들어가면 문이 열리게 했습니다. 문 찾기는 [환경 그래픽의 「앞 문 찾기」](../docs/dq4-environment-format.md#앞-문-찾기)에, 걸어서 여는 문은 [1장 첫머리의 「걸어서 여는 문」](../docs/dq4-chapter1-format.md#걸어서-여는-문)에 있습니다. 걸어서 여는 것은 원작과 일부러 다르게 한 것입니다(사용자 결정).

## 1. NDS·FC 는 문을 어떻게 여나

FC 는 명령 창 7번째 「とびら」로 앞 블록의 문을 엽니다(`1E:$B2A6`, [블록 형식](../../../fc/dq4/docs/dq4-block-format.md)).

NDS 판은 desmume libretro(`95b4d798`)를 `ndsplay`·`ndswarp` 로 헤드리스로 돌려 화면을 봤습니다. 그림은 커밋하지 않고 원래 체크아웃의 `work/nds-door/` 에 두었습니다.
- 잠기지 않은 문은 방향키만 눌러도 열렸습니다. 이무르 집 `mai1f1` 의 `door01` 과 바트랜드 성 정문 `caf1` 의 `wdoor04` 에서, 문짝이 열리는 그림이 맵 이동보다 먼저 나왔습니다.
- 잠긴 문(`caf1` 의 `door02`)에 걸어 들어가면 명령 없이 「トビラには　カギが　かかっている！」가 뜨고, 문 앞에서 멈췄습니다.
- 문 명령이 있는지는 화면으로 보지 못했습니다. 롬을 풀어(`krpatch nds unpack`) `MESS/ja` 메시지 20,215줄을 찍었습니다. 「トビラ」·「とびら」가 든 34줄에 문 명령의 거절(「その方向には　トビラがない！」·「ここには　とびらがない。」)이 하나도 없었습니다. 메시지로 미루어 보면 없는 것으로 보입니다.

## 2. 문 명령이 앞 칸을 고르는 곳

`01:D8C2`(とびら)는 `01:D9CE` 로 주인공 칸 `$C1`·`$C2` 와 바라보는 방향 `7E:31E0` 을 `$1E8C`~`$1E8F` 에 옮깁니다. 그다음 `01:D9E5` 가 `DA4D`·`DB06`·`DB96`·`DC5C`·`DCC6`·`DA9E` 를 차례로 시험합니다. 2×3 문(종류 `3B` 등)은 `DA4D` 몫입니다.

```
01:DA4D  JSR $F02D        ; X,Y = $1E8C,$1E8D, A = $1E8F
         BPL ...          ; 위(bit7): INX DEY, 아래(bit6): INX INY, 옆이면 없음
         STX $1E71 ...    ; 1E8A = X-1, 1E8B = Y-2 (문 표 항목)
         LDA #$01 / JSL $25F9F4   ; 그 칸의 +7
         CMP #$BC ... #$CD        ; 2×3 종류면 문
```

이무르 `37/00` 의 셀 `+7` 을 훑으니 문마다 한 칸만 `BB`(`3B` | `80`)였습니다. 문 표 항목 (42,37) 의 문은 (43,39) 에만 있었습니다. (42,40) 에서 위를 보고 とびら 를 고르니 `$1E71` = (43,39), `$1E8A` = (42,37) 이고 문이 열렸습니다(`7E:21C2` = `01`). (43,40) 과 (41,40) 은 「トビラがない」였습니다. 주인공은 8픽셀(셀 하나)씩 걸으므로, X+1 한 칸만 보면 반 블록 비켜 선 자리를 놓칩니다. 옆(bit5·bit4)은 2×3 문을 아예 보지 않습니다.

## 3. 넓은 찾기

`DA4D` 를 `JSL $57F400 / RTS` 로 바꾸고, `57:F400` 이 방향마다 칸 목록을 차례로 봅니다. 위·아래는 X+1, X+2, X 이고, 옆은 X−1·X+3 열의 Y, Y+1 줄입니다. 맞은 칸으로 `$1E71`·`$1E8A`·`$1E76` 을 원래처럼 채우므로, 그 뒤의 잠금(`01:DCFC`)·열기(`01:DFAB`)는 바뀌지 않습니다. 고친 롬에서 (43,40) 의 とびら 도 열렸습니다. (41,40) 에서 위를 누르면 엔진의 모서리 미끄러짐이 (40,40) 으로 비켜 세워 문 옆으로 지나갑니다.

## 4. 걸어서 막히는 곳

문 아래 (42,41) 에서 위로 막힐 때와 아래로 걸을 때 실행된 PC 를 견줬습니다. 막혔을 때만 `00:A99C` 의 걸음 판정(앞 두 칸을 `00:AC4D` 로 봄)이 carry 를 켜고 돌아왔습니다.

```
00:81E5  JSR $A97D       ; 걸을 수 있나
00:81EB  LDA $C4 / ASL×4 / STA $7E31E0   ; 누른 방향 → 문 명령이 보는 방향
00:8203  BCS $81B7       ; 막힘
00:81B7  JSR $83B4       ; 막힘 소리 (BRK 19 34)
         STZ $195A
```

`81B7` 의 6바이트를 `JSL $01FF00 / NOP / NOP` 으로 바꿨습니다. `01:FF00` 은 실내에서 걸어 다닐 때만 동작합니다.
1. 문 찾기 넷(수문 `DCC6`·카운터 `DA9E` 는 뺌)을 부릅니다.
2. 잠금 종류가 4 미만이면 `DCFC` 로 판정하고, A = 0 이면 `DFAB` 로 엽니다.
3. 열지 않았으면 원래처럼 `83B4` 를 부르고 `$195A` 를 지웁니다.

`83B4` 는 RTS 로 끝나는 뱅크 00 루틴이라, 돌아올 자리(뱅크 01)와 뱅크 00 의 `RTL`(`00:880E`, `PLB PLP RTL` 의 끝)을 스택에 넣고 `JML` 합니다.

## 5. 서장·1장의 문 일곱 개

`dq4doorcheck.py` 는 FC 문 블록마다 걸을 수 있는 이웃 블록을 찾습니다. 그 블록 위 주인공 칸(`dq4groupbuild.cell`, Y = 2y+1)으로 순간이동해, 문 쪽으로 100프레임 누릅니다. 걷는 동안 `7E:21C2`~`21C5` 에 한 번이라도 켜진 비트를 봅니다. 22가지가 모두 기대대로였습니다(6절의 다시 밀기 포함).
- 잠금 0 은 열립니다.
- `36/01` (6,23) 잠금 1 은 열쇠가 없으면 막히고(6절의 메시지), `2199.1` 이면 열립니다.

옆문 넷(`36/00` (70,41), `37/00` (42,37)·(6,45), `37/01` (60,5))은 위아래가 벽인 세로 벽의 문입니다. 왼쪽·오른쪽 모두 걸어서 열렸습니다. 사용자가 본 「반 블록 걸친 채 문이 없다」는 이 옆문이나 반 블록 오른쪽 자리였습니다.

`37/00` (6,45) 의 오른쪽 셀을 덤프하면 문 세 줄의 `+1` 은 `18`·`11`·`91` 입니다. 막는 것은 bit7 이 켜진 맨 아랫줄뿐입니다. 주인공 `+0` 표시는 (8~9, 46~47) 이라, `$C1`·`$C2` 는 2×2 의 왼쪽 아래 칸입니다.

```
     x06      x07      x08      x09
y45 00.18.3B 00.18.3B 00.01.00 00.01.00
y46 00.11.3B 00.11.3B 01.01.00 01.01.00
y47 00.91.3B 00.91.BB 01.01.00 01.01.00     (+0.+1.+7)
```

## 6. 잠긴 문의 메시지

NDS 처럼 열쇠 없이 잠긴 문에 걸어 들어가면 메시지를 띄우고 막게 했습니다. 문 명령이 잠금 결과로 메시지를 고르는 `01:D8FC` 를 그대로 부릅니다.

```
01:D8FC  BRK 95 00        ; 메시지 창
         DEC A / BNE      ; 1 → BRK 98 87 (187), 2 → BRK 98 88 (188), 3 → BRK 9A 15 (315)
         BRL $F01E        ; BRK 0E (입력 기다림) / BRK 95 FF / RTS
```

`F01E` 의 RTS 로 끝나므로 `JSR $D8FC` 로 부를 수 있습니다. 같은 문에 계속 밀고 있으면 걸음 판정이 입력 창마다(8프레임) 막히므로, 한 번만 띄워야 합니다. 막힘 소리 `00:83B4` 는 이미 부딪힌 방향을 `$1958` 에 모아 새 방향에서만 소리를 냅니다(`LDA $1958 / AND $C4`, `TSB $1958`). 메시지도 이 비트를 봅니다. 띄울 때 비트를 켜 두므로, 그 밀기에서는 막힘 소리도 다시 나지 않습니다.

`36/01` (6,23)(잠금 1)에서 열쇠 없이 위로 밀었습니다. 「열쇠를 가지고 있지 않다.」가 뜨고 (6,26) 에서 멈췄습니다. `01:D8FC` 실행 횟수는 이렇습니다.
- 위를 누른 채 A 로 창을 닫고 100프레임 더 밀면 1번입니다.
- 한 칸 물러났다가 다시 밀면 2번입니다.

## 틀렸던 것들

- 처음에는 주인공 칸을 2×2 의 왼쪽 위로 보고, 아래에서 다가가는 자리를 (2fx, 2fy+2), 옆을 (2fx±2, 2fy) 로 잡았습니다.
  - 아래는 (2fx, 2fy+2) 에서도 막혀 열렸지만, 옆은 문 위 두 줄을 그냥 지나갔습니다.
  - 덤프로 칸이 왼쪽 아래인 것을 보고, FC 블록 위에 선 자리(Y = 2y+1)로 고쳤습니다.
  - 이무르 (42,37) 를 「아래에서」 열어 본 첫 실험은, 순간이동이 주인공을 벽 안에 세운 것이었습니다. 이 문은 위아래가 벽입니다.
- 아래를 볼 때 FC 문 위 벽 줄을 넘어 Y+3·Y+4 줄도 봤습니다.
  - 위에서 걸어 내려오면 문 위 두 줄에 들어가 맨 아랫줄에서 막히므로 Y+1 로 충분했습니다.
  - 먼 줄은 인물에 막혔을 때 너머의 문을 열 수 있어 뺐습니다.
- 막힘 소리 호출을 뱅크 00 끝 `00:FFA8` 의 받침에서 하려 했습니다.
  - 창 글자의 NMI 받침(`dq4windowname.NMI_STUB`)이 `00:FFA1`~`FFAD` 13바이트가 비어 있기를 검사하므로 그 자리를 쓸 수 없었습니다.
  - 그래서 뱅크 01 에서 `RTL` 을 거쳐 돌아오는 방식으로 바꿨습니다.
- 뱅크 01 끝 280바이트에 찾기·열기를 다 넣으니 68바이트 넘쳤습니다. 표와 찾기 루프를 뱅크 `57` 로 옮겼습니다.
- 문 패치를 그룹 빌드의 뒤쪽 패치로 얹었더니 거부됐습니다.
  - `dq5newmap` 검사가 「뱅크 3B 복사본의 FF00 가 뱅크 01 과 다름」으로 거부했습니다.
  - 문 표 패치가 뱅크 01 을 통째로 `3B` 에 복사하므로, 문 패치는 환경 롬에 함께 얹어야 했습니다.
- 1장 통합 롬은 그룹 빌드의 패치 가운데 `dq4chapter1.GROUP_PATCHES` 만 얹으므로, 처음 빌드한 롬에는 문 패치가 없었습니다.
- `37/00` (6,45) 오른쪽 사례가 「안 열림」으로 나온 것은 검사의 착오였습니다.
  - 주인공이 연 문을 지나 맵 왼쪽 끝으로 나가자 필드로 옮겨졌고, 그룹이 바뀌어 문 flag 가 지워졌습니다.
  - 끝의 flag 대신 걷는 동안 켜진 비트를 보게 고쳤습니다.

## 남은 것

- 옆문 옆을 반 블록 위(Y = 2fy)로 걸으면 닫힌 문의 위 두 줄을 지나갑니다. 고치기 전 롬도 같습니다. 뒤 장의 잠긴 옆문은 이 길로 돌아갈 수 있습니다.
- NDS 에 문 명령이 있는지는 화면으로 보지 못했습니다(메시지 근거만).
- 잠금 종류 4 이상(이야기 문)은 걸어 들어가도 메시지 없이 막습니다. 1장에는 없습니다.
- 성문(종류 `48`, 4×4)과 2장 뒤 맵의 문은 재지 않았습니다. 성문은 `DB06`·`DC5C` 의 원래 찾기 그대로입니다.
