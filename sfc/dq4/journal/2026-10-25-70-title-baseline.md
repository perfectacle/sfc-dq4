# 2026-10-25-70: 채택된 타이틀과 재사용 기준 정리

한글 정지 타이틀을 DQ5 롬에 연결한 뒤, 움직임과 성 주변의 겹침을 조정해 사용자가 실제 실행 화면에서 채택한 결과까지 정리합니다. 최종 기준은 성 왼쪽 아래 313픽셀을 제거한 롬이며 SHA-1은 `639b221dc9c388ecb786855eecaa312d670eda51`입니다. 빌드·관찰 명령과 다음 수정 지점은 [타이틀 애니메이션 명세](../docs/dq4-title-animation.md)에 모았습니다.

## 1. 한 장의 그림을 실제 롬에 넣기

사용자는 용·구름·붉은 한글 로고·금색 IV가 있는 타이틀 v2를 골랐습니다. 256×224 색 번호 PNG를 `tools/dq4art/title-ko.png`로 고정하고 이후 로고·부제의 RGB를 보존했습니다. 이 소스의 SHA-256은 `6db3d70380dd4727f3b083dae1fdb0cf501f07d84888b0462df565d65d5b392f`입니다.

[51번 일지](2026-10-25-51-title.md)는 정지 그림을 DQ5 타이틀에 연결한 단계입니다. 초기 타이틀은 Mode 1의 전체 화면 BG와 페이드·광택 연출을 사용했습니다. 이때의 화면 배치와 현재 레이어 애니메이션의 Mode 3 배치는 다릅니다.

NDS판은 실제 실행해 구름과 천공성, 용의 등장, 로고 변화, 입력 후 메뉴 전환을 참고했습니다. SFC용 용·구름은 별도로 제작했습니다. NDS의 그래픽·소리나 다른 팬 작업의 에셋을 그대로 이식한 결과는 아닙니다.

## 2. 움직임과 전송량을 분리해서 보기

정지 그림에 페이드만 더한 결과는 요청한 애니메이션을 충족하지 못했습니다. [52번 일지](2026-10-25-52-title-animation.md)에서는 자세를 바꾸는 용과 이동 구름을 만들고, 전체 화면 교체 방식에서 BG·OBJ 레이어 방식으로 옮겼습니다.

사용자가 움직임이 약 24fps처럼 끊긴다고 표현한 것은 체감 피드백입니다. 측정값으로 기록할 수 있는 초기 전체 화면 전송의 교체 속도는 약 7.5fps였습니다. 모든 그림을 매번 보내는 대신 로고·성을 BG1, 하늘을 BG2, 용을 OBJ로 나누고 바뀐 OBJ 타일만 전송했습니다. 매 게임 프레임 처리와 그림의 자세 수를 별개로 다뤄야 했습니다.

중간에 화면이 깨지는 문제는 데이터 전송이 귀선 시간에 들어가는지만 확인해서는 잡히지 않았습니다. 어셈블러 즉시값의 폭과 CPU 상태가 달라 뒤 명령까지 읽고, 일부 전송이 다음 ROM 뱅크를 참조했습니다. 명령 폭과 뱅크 경계를 검사하고 실제 화면도 대조했습니다.

미사용 32픽셀 OBJ를 Y=240에 놓았을 때는 위쪽으로 감겨 날개 끝의 표시 예산을 소비했습니다. Y=224로 숨기고, 화면 밖 반복 구름도 X만 숨기지 않도록 바꿨습니다. VRAM·OAM 일치는 필요한 검사지만 가시 화면의 완전함을 대신하지 못했습니다.

## 3. 부드러운 변형보다 작은 자세의 리듬

[64번 일지](2026-10-25-64-title-cohesion.md)에서는 큰 연속 날갯짓과 잘린 머리, 글자 주변에 남은 정지 하늘을 고쳤습니다. 몸통의 고정 사각형이 주둥이 끝 약 3픽셀을 잘라내고 있어, 알파 연결 요소 전체를 추출하도록 바꿨습니다.

날개는 작은 진폭의 12자세를 각각 약 10~11게임 프레임 유지합니다. 전체 주기는 128게임 프레임입니다. 처리와 스크롤은 매 게임 프레임 갱신하면서 그림에는 SFC풍의 자세 유지 리듬을 남겼습니다. 128개 위상을 128개의 다른 그림으로 설명하면 현재 구현을 잘못 이해하게 됩니다.

로고·IV·부제 주변은 넓은 폴리곤 대신 원래 글자·장식 마스크 10,256픽셀을 사용합니다. IV 사이와 부제 주변의 하늘 구멍은 움직이는 배경을 보여 줍니다. 뒤쪽 하늘의 수평 속도 경계도 제거해 화면 전체에서 한 속도로 움직입니다.

성 앞에는 별도의 둥근 64×32 구름을 둡니다. 성은 낮은 BG1 우선순위, 앞 구름은 OBJ, 글자는 높은 BG1 우선순위로 표시합니다. 로고 일부 타일은 검정을 포함해 16색을 모두 사용하므로, 투명색을 확보하기 위해 현재 전경은 Mode 3의 8bpp로 구성합니다. 색 번호 16을 불투명 검정으로 두어 원래 픽셀 색을 유지합니다.

## 4. 성 받침과 같은 타일의 표시 순서

[65번 일지](2026-10-25-65-castle-cloud.md)는 앞 구름이 지나간 뒤 성 아래가 휑해 보인다는 피드백을 반영했습니다. 원래 타이틀의 청보라 구름 1,195픽셀을 성 주변 마스크에 더해 고정 받침으로 남겼습니다. 별도 OBJ나 매 프레임 전송을 추가하지 않았습니다.

그러나 왼쪽 아래 조각이 주변과 따로 보였습니다. [66번 일지](2026-10-25-66-castle-edge.md)에서 확인한 원인은 8×8 타일 단위 우선순위였습니다. 부제 오른쪽 장식선 끝과 성 구름이 같은 타일 안에 있어, 성 구름 121픽셀도 높은 우선순위를 받았습니다. 실제 화면과 합성기가 모두 같은 오류를 재현했으므로 화면 일치 검사만으로는 찾을 수 없었습니다.

장식선 끝 30픽셀을 포함한 네 타일의 우선순위 비트만 낮췄습니다. 글자·마름모 등 10,226픽셀은 계속 높은 우선순위를 유지합니다. 원래 그림과 마스크는 보존했고, 장식선 끝만 성과 함께 앞 구름 뒤로 가도록 했습니다.

## 5. 최종 선택은 아래 조각 제거

우선순위를 수정한 뒤에도 사용자는 아래 조각이 여전히 같아 보인다며 제거를 요청했습니다. [67번 일지](2026-10-25-67-castle-trim.md)에서는 해당 조각 자체를 표시하지 않도록 바꿨습니다. 이번 사용자의 확인으로 그 제거본을 최종 시각 기준으로 채택합니다.

전경 마스크에서 x=180~207, y=185~223을 비웁니다. 실제 제거된 픽셀은 y=185~199에 있는 313개입니다. 해당 영역의 전경 잔여는 0픽셀이며, 부제·마름모와 오른쪽 성·구름 받침은 그대로입니다. 원본 PNG를 수정한 것이 아니라 롬으로 내보낼 마스크에서 제외했습니다.

현재 전경은 280타일입니다. 최대 타일 차분 1,376바이트에 기본 OAM 544바이트와 구름 OAM 68바이트를 더한 1,988바이트 전송 예산은 그대로입니다. 앞 구름의 가시 주사선은 최대 9스프라이트·33타일로 계산한 하드웨어 제한 안에 있습니다.

## 6. 음악과 메뉴 복귀의 출처

배경음악이 DQ4에서 가져온 것인지도 별도로 확인했습니다. 타이틀에서 들리는 음악은 DQ5 원본 메뉴곡이며, 곡 인자 `$10`과 사운드 명령 `$01`의 실행 시점을 관찰했습니다. 음악 데이터는 교체하지 않고 원래 메뉴 직전 재생을 타이틀 진입으로 옮겼습니다. 메뉴에서 중복으로 시작하지 않아 같은 곡이 이어집니다.

DQ5 초기화 뒤 CPU 주소 `03:FDFB`에서 확장 타이틀로 들어갑니다. A·Start 후 암전, 버튼 해제 대기, 원래 글꼴·팔레트·PPU와 WRAM 값 복원을 거쳐 DQ5 메뉴로 돌아갑니다. 타이틀 다음의 DQ5 게임 내용을 DQ4로 옮기는 것은 별도 작업입니다.

이전 `8fb4658…`의 1,001개 화면과 입력 유지·리셋·이름 입력 검증, 중간 두 수정본의 각 63개 화면은 별도 버전의 근거입니다. 최종 롬에서 다시 수행한 것으로 합산하지 않습니다. 빠른 실행 캡처는 VRAM보다 1틱 또는 3틱 늦게 표시된 경우가 있어, 캡처 파일 번호와 현재 메모리 위상을 구분했습니다.

기존 로컬 근거는 `work/castle-trim-verification/`에 보존했습니다. 이 폴더는 공개 저장소의 필수 입력이 아닙니다. 새 체크아웃에서 쓸 수 있도록 커밋된 `dq4titlelayers.py`, `dq4titlelayerpatch.py`, `dq4titlelayers.asm`, `dq4titleintegrationcheck.lua`를 기준으로 [재현 절차](../docs/dq4-title-animation.md#재현-빌드와-자동-검사)를 작성했습니다. 정지 시안·전체 화면 교체 실험과 현재 빌드 경로도 구분했습니다.

기록 정리 시점에도 커밋된 PNG와 잠긴 의존성으로 에셋과 롬을 새로 만들어 같은 SHA-1을 확인했습니다. 커밋된 Lua 프로브만으로 대기 표본 16개와 A 입력 후 메뉴 진입을 다시 관찰했습니다. 과거 작업 폴더의 임시 검증 스크립트는 빌드나 관찰의 필수 입력이 아닙니다.

## 틀렸던 것들

- 정지 그림이 채택됐다고 페이드만 있는 연출까지 완성된 것은 아니었습니다.
- 처리 프레임이 높으면 모든 날개 자세를 부드럽게 변형해야 한다고 본 판단이 잘못됐습니다. 사용자가 원한 SFC풍 리듬은 작은 자세를 잠시 유지하는 쪽이었습니다.
- 전송 예산과 VRAM 일치만으로 화면 깨짐·잘림이 없다고 판단할 수 없었습니다. 즉시값 폭, ROM 뱅크, OBJ 가시 주사선 제한을 함께 봐야 했습니다.
- 성을 구름에 가리게 했다고 구름이 지나간 뒤의 받침까지 자연스러운 것은 아니었습니다.
- 합성기가 실제 화면과 일치해도 같은 잘못된 우선순위를 구현할 수 있었습니다. 타일 단위 공유 영역과 구름에 가려져야 할 픽셀을 따로 검사해야 했습니다.
- 기술적으로 겹침을 수정했다는 이유로 사용자가 원하지 않는 조각을 계속 살릴 필요는 없었습니다. 최종 요청대로 조각을 제거한 결과가 채택됐습니다.

## 남은 것

- 실제 SFC 기기, 기존 저장 파일 불러오기, 게임 후반 전체 진행은 검증하지 않았습니다.
- 런타임·OAM·입력 처리를 다시 바꾸면 채택본을 출발점으로 버튼 유지·리셋·이름 입력을 새 롬에서 재검사합니다.
- 타이틀 이후 DQ5 게임 내용의 DQ4 이식은 별도 범위로 진행합니다.
