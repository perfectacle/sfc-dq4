# 2026-10-28-01: 메시지 캔버스와 명령 창 전용 칸

에뮬레이터 실측에서 나온 두 문제를 고쳤습니다. 메시지 동안 명령 창 글자가 비던 것과, 메시지 창의 빈 줄에 선이 보이던 것입니다. 결과는 [메시지 캔버스와 명령 창 전용 칸](../docs/dq4-window-text-format.md#메시지-캔버스와-명령-창-전용-칸)에 있습니다.

## 1. 선의 정체

「しらべる」 흐름에서는 조사할 때 명령 창이 먼저 닫혀, 우리 업로드는 메시지보다 앞에만 있었습니다. 그런데도 선이 남았습니다. VRAM 주소 기록으로 메시지 캔버스를 쓰는 곳을 찾으니 `00:8EB9` 하나였습니다. `00:8E98` 이 버퍼 `7E:5800` 을 `$2115` = `00` 으로, 곧 평면 0 만 칸 `096`~ 에 보냅니다. 「쓰기」 흐름에서 이 전송은 메시지 동안 매 프레임 `0750` 바이트, 캔버스 전체였습니다.

평면 0 은 매번 덮이니, 남는 것은 평면 1 입니다. 글자 줄은 평면 1 을 `FF` 로 올려 원래 글자 칸과 같지만, 위 줄 합성은 테두리 타일의 평면 1 무늬를 그대로 올립니다. 그 무늬가 메시지 창 빈 줄에 선으로 보였습니다.

## 2. 고치는 방향

캔버스 안의 칸은 메시지 동안 어차피 덮입니다. 그래서 두 가지로 나눴습니다.

- 메시지와 함께 보이는 일이 가장 많은 명령 창 여덟 문구는 캔버스 밖 `1D0`~`1FF` 48칸에 둡니다. 모두 세 열 이하라 문구마다 6칸이면 들어갑니다. 문구 번호마다 자리를 고정해 밀려나는 일이 없습니다. 같은 낱말이 다른 창이나 제목에 나오면 위 줄 합성이 달라지므로 번호를 따로 받습니다.
- 나머지 슬롯은 모두 캔버스 안에 두고, 게임이 캔버스를 보내기 직전(`00:8E9E`) 그 슬롯들의 평면 1 을 `FF` 로 되돌리고 비웁니다.

## 3. 돌아가는 자리

처음 롬은 목록·제목이 비고 전투가 까만 화면으로 멈췄습니다. 훅만 뺀 롬은 정상이었습니다. `JML` 네 바이트가 `00:8E9E`~`8EA1` 을 덮는데, `8EA1` 은 `LDA #$7E` 의 명령 바이트였습니다. 그 자리로 돌아가 `JML` 의 뱅크 바이트 `60`(`RTS`)을 실행하고 있었습니다. `LDA #$7E` 를 우리 쪽에서 하고 `8EA3` 으로 돌아가게 고쳤습니다.

| 장면 | 결과 |
| --- | --- |
| 조사 메시지(09/00) | 메시지 창에 선 없음 |
| 도구 → 쓰기 → 메시지 | 선 없음, 뒤의 명령 창 「대화 주문」 유지. 목록·제목은 메시지 동안 빔 |
| 전투 첫 창·주문 창 | 회귀 없음 |
| 선실 무작위 입력 8벌 × 8000프레임 | 모두 정상 |

## 틀렸던 것들

- 게임이 캔버스를 쓴 만큼만 보내 남은 칸에 우리 그림이 남는다고 봤지만, 실제로는 캔버스 전체의 평면 0 을 매번 보냈고 남은 것은 평면 1 이었습니다.

## 남은 것

- 메시지 동안 명령 창 밖의 창 글자(목록 이름·제목·「どうする」 등)가 빔. 가나 칸을 돌려받아야 풀림
- 주인공 혼자 「じゅもん」 을 고를 때 나오는 메시지 장면은 헤드리스로 띄우지 못함
