# 2026-10-26-37: 모험의 서 메뉴를 한글로

타이틀을 나간 뒤 게임을 시작하기 전의 모험의 서 메뉴(첫 메뉴, 칸 고르기, 예/아니요, 표시 속도, 스테레오)를 한글로 바꾸고, 커서를 움직일 때의 효과음과 첫 메뉴에서 B 를 막는 것을 더했습니다. 창 글자는 바이트가 곧 BG3 타일 번호라 한글을 넣을 칸이 없어서, 문구를 빌드할 때 통째로 그려 메뉴 동안 비어 있는 VRAM 에 올리고 창 레코드에서 접두 바이트로 가리키게 했습니다. 결과는 [모험의 서 메뉴 한글화](../docs/dq4-menu-format.md)에 있습니다.

## 1. 메뉴 흐름에 무엇이 나오나

채택된 서곡 롬을 전원부터 켜고 A·아래를 눌러 경로마다 찍었습니다. 기록이 없으면 첫 메뉴는 「ぼうけんのしょをつくる」 한 줄(창 `5E`)이고, 칸 고르기(`64`~`6A`) → 이름 입력 → 표시 속도(`63`) → 스테레오/모노(`86`) → 첫 맵입니다. 새 게임을 한 번 시작해 남은 SRAM 을 붙이면 다섯 항목 메뉴(`60`)와 기록 목록(`70`)이 나옵니다.

메시지 진입 `24:8BAF` 의 A 를 기록하니 메뉴에서 나오는 메시지는 지우기의 `1CE`·`1CF` 둘뿐이었고, 옮기기와 설정 바꾸기에는 메시지가 없었습니다. 그 옆 `1D0` 은 기록이 깨졌을 때의 문장입니다. 메시지는 허프만 트리를 다시 만들어야 하는 다른 길이라 이번에는 창 문구만 했습니다.

FC DQ4 의 같은 메뉴는 `dq4text.py windows` 그룹 1 에 있었습니다. 「ひょうじそくどをかえる」 와 기록 줄의 「しょう」·「レべル」 가 다르고 스테레오/모노는 없습니다. 문구는 FC 를 옮기고, 둘째 항목은 스테레오까지 묻는 DQ5 동작에 맞춰 「설정을 바꾼다」 로 했습니다.

## 2. 한글을 어디에 둘까

메뉴 화면 일곱 장의 VRAM 을 덤프하니 워드 `2000`~`7FFF` 가 모두 0 이었습니다. 타이틀 FadeOut 이 VRAM 을 다 지우고 메뉴로 넘어가고, 메뉴에는 BG1·BG2 그림이 없기 때문입니다. BG3 타일 번호는 10비트라 타일 `200`~`3FF`(512칸)를 가리킬 수 있습니다.

```
vnew/v01950.bin 1000:1016 1400:1024 1800:1024 1C00:1024 2000:0 2400:0 … 7C00:0
```

문자열을 8점 폭 열로 잘라 열 k 를 타일 `200+k`·`300+k` 에 두고, 창 레코드에는 `9F n k` 세 바이트만 씁니다. 「ぼうけんのしょをつくる」(탁점 접두 포함 12바이트)가 3바이트가 되니 레코드가 모두 짧아져 제자리에 들어갔습니다. 열 그림 8KB 는 FadeOut 의 마지막 `JML $03FE5C` 를 가로채 화면을 끈 채 DMA 로 올립니다.

## 3. 탁점은 위에, 한글은 아래로

창은 항목마다 두 줄을 쓰니 한글 12점을 위 줄로 올리면 되리라 생각했습니다. 그런데 메인 메뉴의 타일맵을 보니 첫 항목 ぼ 의 탁점이 테두리 줄의 `2092` 였습니다. 탁점은 글자 위 줄에 놓이고, 첫 항목의 위 줄은 테두리입니다.

```
 4 2C00 208C 208D 2092 208D …      테두리(+ぼ 의 탁점)
 5 2C00 208E 207C 202D 2012 …      ▶ぼうけんをする
 6 2C00 208E 2001 2001 2001 …      빈 줄
```

그래서 한글은 글자 줄에서 아래 빈 줄로 3점 내려 그리고, 마지막 항목 아래가 테두리가 되지 않게 창 높이를 하나 늘렸습니다.

## 4. 격자 무늬 바탕

첫 롬은 글자는 나왔지만 화면 바탕 전체가 격자 무늬였습니다. BG1·BG2 의 글자 바탕도 워드 `2000` 이라, 0 으로 채운 BG1·BG2 타일맵이 타일 0, 곧 열 0·1 의 그림을 4bpp 로 읽고 있었습니다. 열을 2 부터 쓰고 쓰지 않는 칸을 0 으로 두자 바탕이 검게 돌아왔습니다.

## 5. 게임 안에서도 여는 예/아니요

지우기 확인의 예/아니요는 메뉴 전용 창 `62` 가 아니라 교회 같은 곳에서도 쓰는 창 `32` 였습니다. 게임 안에서는 VRAM `2000` 이후가 맵 그림이라 열을 쓸 수 없습니다. 창 표를 읽는 곳은 뱅크 04 에 아홉 군데라 하나하나 훅을 걸기보다, 창 표 칸을 낮은 WRAM 거울 주소 `$1AC0` 으로 돌리고 그 자리 내용을 바꾸기로 했습니다. 메뉴에 들어갈 때 한글 레코드를 복사하고, 맵을 불러올 때(`2B:82BD`, BG3SC 를 쓰는 곳)마다 원래 레코드를 복사합니다.

이어하기로 첫 맵에 들어간 뒤 `7E:1AC0` 48바이트가 롬의 `32`·`62` 레코드와 바이트째 같았습니다. 메뉴에 있을 때(760프레임)는 한글 레코드였습니다.

## 6. 글꼴 고르기

Galmuri(OFL) BDF 세 가지로 롬을 만들어 같은 화면에서 견줬고, 사용자가 Galmuri11 을 골랐습니다. DQ5 트랙이 자모를 좌표로 정의한 시제품 글꼴은 `ㅢ` 가 없어 「모험의」 를 그리지 못했습니다. 직접 그린 글꼴은 조합형 이름 입력과 함께 다시 검토합니다.

## 7. 원래 롬과 견주기

같은 입력으로 기준 롬과 돌려, 새 게임은 첫 맵 화면 세 장, 이어하기는 세 장이 픽셀째 같았고, 남은 SRAM 8,192바이트도 같았습니다. 바뀌는 것은 메뉴 화면뿐입니다.

## 8. 커서 소리와 첫 메뉴의 B

사용자가 직접 띄워 보고 두 가지를 물었습니다. 커서를 움직여도 소리가 없고, 첫 메뉴에서 B 를 누르면 창이 사라졌다 다시 뜬다는 것입니다. 둘 다 기준 롬에서도 같았습니다. 커서를 네 번 움직이는 동안 DSP KON 은 곡 음뿐이었고, B 를 누르면 창이 12~16프레임 사라졌습니다. 사용자는 효과음을 게임 전체에 넣고, B 는 첫 메뉴에서만 막기로 정했습니다.

아무 입력 없는 실행과 아래·B 를 누른 실행의 뱅크 04 커버리지를 견주자, 선택 고리 `04:CB29` 와 네 방향 처리기, B 갈래 `04:CCA1 BVS $CD0A` 가 나왔습니다. 커서 자리 `$0AD7` 이 바뀌었을 때만 `BRK 19 33 00` 을 내는 트램펄린을 자리 옮기기 `JSR` 넷에 끼웠습니다. B 는 창 스택 맨 위가 `5E`·`5F`·`60` 이면 돌아가게 했습니다. 다시 재니 커서를 움직일 때마다 다음 프레임에 목소리 7 이 울렸고, 첫 메뉴의 B 는 아무 일도 하지 않았습니다. 하위 창과 게임 안 명령 창의 B 는 그대로 닫혔습니다.

## 틀렸던 것들

- 한글을 글자 줄 위로 올리려 했습니다. 첫 항목의 위 줄이 테두리라 아래로 내렸습니다(3절).
- 지우기 확인의 예/아니요가 창 `62` 라고 보고 `62` 만 고쳤습니다. 화면은 여전히 はい/いいえ 였고, 창 레코드 전체에서 はい 를 찾자 `32` 가 나왔습니다. `62` 는 いいえ/はい 순서라, 처음에 적은 「예/아니요」 순서도 틀렸습니다.
- 교회 저장의 칸 고르기가 메뉴의 `64`~`6A` 를 쓸 것이라 걱정했지만, 교회는 기록 목록 꼴 창이었습니다.

## 남은 것

- 조합형 이름 입력과 이름 입력 제목, 기록 목록의 이름
- 메뉴 메시지 `1CE`·`1CF`·`1D0`
- 창 `62` 가 게임 안에서 쓰이는지, `7E:1AC0`~`1AEF` 를 실행하지 않은 코드가 쓰는지
- 실제 SFC 기기
