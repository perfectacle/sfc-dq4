# 2026-10-31-61: 1장에서 끝내고 타이틀로

1장까지 배포하는 롬은 1장 끝에서 2장으로 넘어가지 않게 했습니다. 왕에게 보고하고 성 앞에 나서면 검은 화면에 끝맺음 서술 둘이 나오고, 2장 제목과 「― 다음에 계속 ―」을 띄운 뒤 버튼을 누르면 타이틀로 돌아갑니다. 사용자가 고른 문구이고 원작에는 없는 장면입니다. 2장 코드는 롬에 그대로 두고 `dq4build.py --chapter2` 로 다시 켭니다. 결과는 [1장 형식 문서](../docs/dq4-chapter1-format.md#1장에서-끝내기)에 반영했습니다.

## 1. 끝맺음 차례

성 앞 「1장 끝」 인물의 스크립트만 바꿨습니다. 지금까지는 FC 서술 0346 → 어둡게 → 2장으로 옮기기였습니다.

```
조작 막기 → 어둡게(darken) → 서술 ending_leave → 60프레임 쉼 → 서술 ending_far → 끝 상자
```

- 첫 서술은 「(이름)은 / 홀로 성을 나섰다. / 세상을 구할 용사를 / 찾아서.」 입니다. 1장 주인공의 이름은 이름 입력값이라, 「은/는」 을 받침으로 고르는 [조사 코드](../docs/dq4-josa-format.md)를 1장 대사 문자열에서도 쓸 수 있게 `{은}` 토큰을 받게 했습니다. 이름이 네 글자(4칸)여도 넘치지 않게 이름 줄을 따로 두었습니다.
- 둘째 서술은 「같은 무렵, / 멀리 산트하임 성.」 ▼ 「성벽 너머 세상을 꿈꾸는 / 한 공주가 있었다.」 입니다. 다음 장 주인공의 이름은 일부러 말하지 않습니다.
- 두 서술 사이 60프레임은 창도 없는 검은 화면입니다. 스크립트 명령 `21` 이 창을 닫고 돌아오기 때문입니다.

## 2. 끝 상자

1장·2장 제목 상자를 그리는 `dq4chapterbox` 에 장면을 하나 더했습니다. 같은 금테 상자에 「제2장 말괄량이 공주의 모험」, 한 행 아래 검은 바탕에 「― 다음에 계속 ―」 를 Galmuri11 흰 점으로 찍습니다. 남은 메시지 창이 비치지 않게 BG3 타일맵 버퍼를 모두 비우고 상자를 놓습니다. 누른 채인 A 로 바로 넘어가지 않게, 버튼을 놓기를 기다린 뒤 A·B·X·Y·START 를 기다립니다.

## 3. 소프트 리셋과 소리 드라이버

누르면 화면·NMI·HDMA 를 끄고 리셋 루틴 `00:8639` 로 갑니다. 처음 걱정한 것은 소리입니다. 리셋 루틴은 `24:FD6E` 에서 드라이버를 IPL 방식으로 올리는데, `00:FE79` 는 `$2140`·`$2141` 이 `AA BB` 가 될 때까지 끝없이 기다립니다. 게임 중의 SPC 는 IPL ROM 을 끄고(`$F1` = `01`) 드라이버를 돌리고 있어 그 값을 내지 않습니다.

드라이버를 풀어 보니 SPC 명령 `08` 이 `CALL $1076` / `JMP $09DB` 였습니다. `09DB` 는 올린 직후의 진입점(`$0200` → `JMP $09DB`)과 같습니다. `10A4` 가 직접 페이지·1 페이지·곡 자리 표를 비우고, 샘플 자리를 다시 잡고, CPU 의 `Chun` 을 기다렸다가 `SOFT` 로 답합니다. 리셋 루틴이 올리기 다음에 부르는 `24:FDF9` 가 바로 그 인사입니다. 그래서 `24:FD74` 의 `JSL $24FD85`(올리기)를 훅으로 바꿨습니다. 포트가 `AA BB` 면 원래대로 올리고, 아니면 `08` 을 보냅니다.

명령을 보내려면 차례 비트가 필요했습니다. 드라이버는 `$F4` bit0 이 자기 `$8E` bit0 과 달라지면 `$F5` 를 명령으로 읽지만, 답 `$F4` 에는 `$8E & E0` 만 내보냅니다. CPU 쪽 차례 `$08DA` 는 리셋이 이미 지웠습니다. 그래서 bit0 을 0, 1 차례로 써 보고 `$2140` 이 바뀌면 받은 것으로 봅니다.

## 4. 잰 것

곡과 인물 그림을 얹은 롬으로 1장 걷기 검사를 왕의 귀환까지 걷고, 성 앞에 들어선 세이브스테이트에서 A 를 60프레임마다 눌렀습니다.

| 프레임 | 일 |
| --- | --- |
| 85~235 | 첫 서술 |
| 265~355 | 둘째 서술(▼ 뒤 두 줄이 이어지고 창이 밀려 올라감) |
| 373 | 끝 상자(`5F:888F`) |
| 428 | 누름 → 리셋 `00:8639` |
| 469 | 리셋 훅이 답을 받음(`5F:8AD9`), `24:FDF9` 인사 |
| 471 | 소리 켜기 다음 `00:8680` |
| 610~ | 타이틀 |

- 리셋 뒤 SPC 곡 자리(`03A7`~`03BE`)는 +300·+600·+900 프레임 모두 곡 자리 0 이 켜지고 서곡 `10` 이 돌았습니다. 전원을 켠 뒤 같은 프레임과 +600·+900 이 바이트까지 같았습니다.
- 보고 전에 성 앞 교회에서 기록하고, 왕좌의 방 → 보고 → 끝 상자 → 리셋 → 타이틀에서 이어 하기를 했습니다. 이어 하기 루틴 `25:824F` 가 돌고 로고 장면은 불리지 않았습니다. `36/00` 신부 앞 (10,45)에 섰고, 보고 깃발은 꺼져 있었습니다(`2197` = `00`).
- 걷기 검사는 마지막 두 구간을 `king`(성 앞, 보고 깃발 켜짐, 2장 깃발 꺼짐)·`ending`(위 호출 차례, 리셋 뒤 `24:FD85` 없음)으로 바꿔 27구간이 되었습니다. 저장·이어 하기 검사 여섯 장면도 통과했습니다.

## 5. 함께 고친 것

새 스크립트가 `3F` 뱅크의 인물 자료를 `EACA` 에서 `EAE2` 까지 늘렸습니다. 그러자 인물 그림 단계(`dq4people.py`)가 고정 시작 `3F:EAE0` 에 타일을 쓰다 「비어 있지 않은 자리」로 멈췄습니다. 그 자리의 시작을 곡 롬에서 쓰인 끝 다음 16바이트 경계로 잡게 했습니다(`dq4people.tile_areas`).

## 남은 것

- 드라이버가 곡 자료를 받는 도중에 소프트 리셋이 오면 다시 시작 명령이 먹는지는 재지 않았습니다. 끝 상자에서는 곡을 줄인 뒤라 그런 때가 없습니다.
