# 2026-10-30-01: 환경 맵 훅이 지우던 Y 상위 바이트

DQ5 에 넣은 DQ4 환경 맵의 훅이 Y 레지스터 상위 바이트를 지워, 바꾸지 않은 원래 맵 두 곳(1A/00·19/00)에서 문이 사라지던 것을 고쳤습니다. 결과는 [환경 그래픽 문서의 훅 절](../docs/dq4-environment-format.md#훅)에 있습니다.

## 1. 문이 사라지는 맵

dq5 트랙이 문 표 늘리기를 dq4 환경 패치와 함께 실측하다가, 1A/00 (36,27)(종류 `3F`)·19/00 (32,47)(종류 `40`)의 문이 dq4 패치를 넣은 롬에서만 없어지는 것을 찾았습니다([dq5 빌드 문서](../../dq5/docs/dq5-build-format.md#dq4-환경-맵과-함께-쓰기)). `01:F42D` 를 원래 `LDX #$0009` 로 되돌리면 원본과 같았습니다.

## 2. 원인

문 물체 훅은 들어가면서 P·A·X 만 스택에 넣고 바꾼 맵 찾기 루틴을 부릅니다. 그 루틴은 `PHP SEP #$30` 으로 시작하므로, 인덱스가 8비트가 되는 순간 X·Y 상위 바이트가 0 이 됩니다. `PLP` 로 16비트에 돌아와도 상위 바이트는 돌아오지 않습니다. X 는 꺼내 되돌리지만 Y 는 그대로라, 맵의 문 목록 위치(`$D2FC,Y` 의 Y)가 `100` 을 넘는 맵은 그 아래 바이트만 남은 자리를 읽었습니다. 물 래퍼(`15:F7D0` 호출 셋)도 Y 를 넣지 않았습니다.

## 3. 고친 것

모든 훅이 `PHP REP #$30 PHA PHX PHY` 로 들어가 `PLY PLX PLA PLP` 로 나옵니다. 문 물체 훅은 바꾼 맵이면 그 맵 항목 주소를 `TAY` 대신 `STA $01,S` 로 스택의 Y 자리에 써서, `PLY` 가 그 값을 꺼냅니다. 공통 루틴은 791 → 796바이트입니다.

## 4. 확인

검사 도구 `dq4environmentromcheck.py` 에 두 맵을 배 선실에서 워프해 원래 롬과 셀 버퍼(사람 표시 bit0~2 제외)를 견주는 대조를 더했습니다.

```text
고치기 전 롬  1A/00,22,24 differ cells [(6, 39), (6, 40), (6, 41), (6, 57), (6, 58), (6, 59)]
             19/00,29,26 differ cells [(0, 2), (0, 3), (0, 4), (0, 6), (0, 7), (0, 8)]
고친 롬      doors-1A00_cell_buffer_equal: true, doors-1900_cell_buffer_equal: true
```

고치기 전 롬은 문 칸만이 아니라 엉뚱한 목록을 문으로 읽어 다른 칸에도 물체가 놓였습니다. 고친 롬은 바꾼 맵 46곳의 픽셀 차이 0, 걷는 층 불일치 0, 문 물체 54/54, 바트랜드 성문 열고 지나가기(18행), 대조 맵 01/03 같음까지 기존 검사도 모두 통과했습니다.
