# 2026-10-30-10: 맵을 불러오는 동안의 CPU

맵 곡이 화면 뒤에 늦는 것을 줄이려고, 맵을 불러오는 검은 화면 동안 CPU 가 노는 틈이 있는지 봤습니다. 틈은 없었고, 절반 이상을 맵 칸 기록을 같은 값으로 채우는 고리가 썼습니다. 결과는 [사운드 포팅 「맵을 불러오는 동안」](../docs/dq4-sound-port-format.md#맵을-불러오는-동안조사)에 있습니다.

## 1. VBlank 폴링 세기

`$4210`·`$4212` 를 읽을 때마다 프레임과 PC 를 세는 프로브로 성 `01/00` 워프를 쟀습니다. 321(`01 01` 이 들어감)~390 사이는 0번이었습니다. 그 앞뒤에는 프레임마다 `00:8897`(`$4210`)·`00:8BE8`(`$4212`)에서 한 번씩 읽었습니다. 맵을 불러오는 동안은 NMI 를 끄고 기다림 없이 돕니다.

## 2. 프레임마다 어디서 도는가

실행 주소를 4KB 단위로 프레임마다 세었습니다. 불러오는 동안 프레임마다 약 1만2천 명령으로, 프레임 전체를 쓰는 양입니다. 325~362 의 37프레임은 거의 `01:A000` 이었고, 326~341 은 프레임마다 11,767~11,769 명령으로 같았습니다.

## 3. 채우기 고리

명령마다 실행 횟수와 P 를 적어 `tools/listing.py` 로 풀었습니다. 326~341 에서 `01:A986` 고리가 5,828번 돌았습니다.

```
01:A986  SEP #$20 / LDY $AB / JSR $A9DC        ; A9DC = JMP ($1A6D), 값 A9DF
01:A9DF  PHB / LDA $AD / PHA / PLB             ; 데이터 뱅크 = $AD
         LDA $1844 → +1,Y / ($99 = 0 이면) LDA $1845 → +2,Y / LDA $1846 → +3,Y / $83|80 → +4,Y
         PLB / RTS
01:A98D  REP #$30 / $AB += $06(넘치면 INC $AD) / $12 -= $0C / BNE A986
```

칸마다 같은 4바이트를 쓰는 채우기입니다. 맵마다 18~35프레임 걸렸습니다(배 18, 동굴 30, 성 29, 마을 35).

## 4. 판단

이 고리를 칸당 약 140 → 50사이클로 다시 짜면(어림) 검은 화면이 맵마다 11~22프레임 줄어듭니다. 그러나 소리 일도 불러오기가 끝난 뒤에야 도므로 화면과 곡 사이 간격은 그대로입니다. 아낀 프레임에 곡을 직접 보내도 3~6KB 이고, 맵 곡은 15~20KB 를 곡 앞에 보내야 합니다. 맵 전환을 빠르게 하는 것은 곡과 별개의 엔진 수정이라 사용자 판단으로 하지 않았습니다.

## 남은 것

- `$1A6D` 의 다른 값과 `$99` ≠ 0 갈래(`01:AA06`)가 어떤 맵에서 쓰이는지
- 맵 곡을 더 앞당기려면 곡 앞에 보낼 바이트(시퀀스 3~14KB)를 줄이는 길
