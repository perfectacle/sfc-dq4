# 2026-11-04-05: 옮기지 않은 9C 성문 셋과 4장 オーりン 갈래

[환경 형식 문서](../docs/dq4-environment-format.md)의 「남은 것」 가운데 성문 두 줄을 정리했다.

- 아직 옮기지 않은 FC 맵의 `9C` 성문 셋(`31/04`·`33/01`·`3C/00`)은 생성기가 잠금 0 성문 하나씩으로 바꾼다. 이것을 시험으로 지킨다.
- 4장 キングレオ(`44`)의 `A2` 성문을 FC 에서 オーりン 이 여는 갈래는 판정 조건을 다시 정리했다. 포팅 롬에 넣는 설계를 문서에 남겼다. 넣으려면 4장 flag·オーりン 의 일행 레코드·메시지가 있어야 하는데, 셋 다 4장 이벤트 포팅에서 정해진다. 그래서 코드는 넣지 않았다.

## 1. FC 의 オーりン 판정

FC 쪽 판정은 이미 [FC 블록 문서](../../../fc/dq4/docs/dq4-block-format.md#문과-열쇠)에 정적 추적과 실측이 있다. 이번에는 새로 재지 않고 그 결과를 설계에 맞춰 정리했다.

- 「とびら」(`1E:$B2A6`) 는 4장(`$615A` = 3)이고 잠금 2 문(속성 `16`·`1A`·`1E`·`22`)이면 `BRK 63 63 03`(A = `09`)으로 オーりン 이 일행에 있는지 본다(`1E:$B381`).
- 셋째 바이트 `03` 은 살아 있는 레코드만 센다는 조건이고, 걷는 자리와 마차 자리를 다 센다.
- 있으면 메시지 03A5 「カギが　かかっている！ ▼ しかし　オーりンが　カギを　こじあけた。」 뒤 열쇠 없이 여는 길(`1E:$B32A`)로 간다.
- 실측은 둘이다.
  - `04/02` 의 `96` 문: 걷는 자리·마차 자리 オーりン 은 열림, 죽었거나 없으면 열쇠 검사, `$615A` = 2 면 검사를 건너뜀.
  - `44/00`(FC `00-00`)의 `A2` 성문: 4장 オーりン 이면 열림, オーりン 없음과 1장은 닫힘.

조건은 「장 번호가 4」, 「살아 있는 인물 `09` 가 일행이나 마차에 있음」, 「잠금이 2」 셋이다. 일행 멤버 비트나 이벤트 flag 는 보지 않는다. 잠금 1 문에는 걸리지 않는다.

## 2. 포팅 롬에 넣는 설계

포팅 롬의 열쇠 판정은 DQ5 의 `01:DCFC` 가 한다. 일행의 열쇠 단계 `$01` 을 물건(まほうのカギ `B8` 이면 2)으로 정한 뒤 잠금과 견준다. とびら 두 길과 걸어 부딪히는 `00:81B7` 훅이 모두 이 루틴을 지나므로, 갈래는 `01:DCFC` 한 곳에 넣으면 된다. 잠금이 2 이고 `$01` < 2 일 때 다음 둘을 보고, 맞으면 메시지를 띄운 뒤 열림을 돌려준다.

- 4장 flag.
- 살아 있는 オーりン 레코드가 일행에 있음.

FC 와 포팅 롬의 대응은 이렇다.

| FC | 포팅 롬 |
| --- | --- |
| 장 번호 `$615A` = 3 | 장 상자 flag(`dq4chapterbox`). 지금은 `CHAPTER1`·`CHAPTER2` 뿐이라 4장 flag 를 더해야 함 |
| 인물 `09` 가 살아 있는 일행·마차 레코드에 있음 | 4장 인물을 옮길 때 オーりン 에 줄 DQ5 일행 레코드. 살아 있음은 레코드 `+1` bit7(DQ5 필드 `3E`) |
| 메시지 03A5 | 4장 메시지와 함께 넣을 한글 메시지 하나 |

4장 flag 는 1·2장에서 켜지지 않으므로, 이 갈래를 넣어도 1·2장 동작은 바뀌지 않는다.

지금 넣지 않은 까닭은 셋이다.

- 4장 flag 비트가 정해지지 않았다.
- オーりン 의 DQ5 일행 레코드 번호가 정해지지 않았다.
- 메시지 자리가 정해지지 않았다.

셋 다 4장 이벤트 포팅에서 정해진다. 임시 값으로 넣으면 어떤 장면에서도 지나지 않는 코드가 되어 실측할 길이 없다.

## 3. 옮기지 않은 9C 성문 셋

FC 맵 279곳 가운데 지금 옮기지 않은 맵의 `9C` 는 셋이다. 지금 생성기(`dq4environmentrom.objects`)에 그 맵의 FC 데이터를 넣으면 셋 모두 잠금 0 성문 하나씩이 나왔다.

| 맵 | FC 칸 | 바뀐 물체(DQ5 칸, 종류, 잠금) |
| --- | --- | --- |
| `31/04` | (14,26)~(15,27) | (28,52), `48`, 0 |
| `33/01` | (7,5)~(8,6) | (14,10), `48`, 0 |
| `3C/00` | (46,10)~(47,11) | (92,20), `48`, 0 |

시험을 둘 더했다(`test_dq4environment.py`).

- `UnportedGateTests`: FC 롬이 있을 때 돈다. 세 맵이 아직 `MAPS` 에 없는지, 그 칸의 속성이 `9C` 인지, `objects` 가 위 물체 하나만 만드는지 본다. 그 맵을 옮기면 첫 확인이 실패하므로, 옮길 때 이 시험을 실제 열림 실측(`dq4gatecheck.py`)으로 바꿔야 한다는 것도 알려 준다.
- `GateObjectTests`: 롬 없이 돈다. 만든 맵에 2×2 성문 블록(`9C`·`9D`·`A2`)을 놓으면 4×4 성문 물체 하나(FC 칸 × 2, 잠금 0·1·2)가 되는지 본다.

## 남은 것

- 4장 オーりン 갈래를 넣는 일. 4장 flag·オーりン 의 일행 레코드·메시지를 정한 뒤 `01:DCFC` 에 넣고, `44/00` 의 `A2` 와 잠금 2 문에서 オーりン 있음·없음·1장을 잰다.
- `31/04`·`33/01`·`3C/00` 을 옮긴 뒤 그 성문이 실제로 열리는지(`dq4gatecheck.py`).
