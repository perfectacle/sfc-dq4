# 2026-11-03-08: 침대 검사의 출발 상태와 걸음 묶기 바로잡기

[07번 일지](2026-11-03-07-sleeper-hook-review.md)에서 결정적으로 고친 침대 검사(`dq4sleepercheck`)를 리뷰 지적대로 다시 보았습니다. 검사가 설명과 다르게 돌던 두 곳을 고쳤습니다. 훅 시험은 루틴 전체를 명령 단위로 훑게 바꿨습니다. 결과는 [환경 형식 문서 「인물」](../docs/dq4-environment-format.md#인물)에 있습니다.

## 1. 왕좌의 방 출발 상태

왕좌의 방 장면은 앞 장면이 `36/00` 에 도착했을 때 남긴 세이브스테이트에서 출발합니다. 07번 일지의 검사는 저장을 청한 장면 안에서 시도(`k`·`n`)마다 다시 저장해, 마지막 시도의 상태가 쓰였습니다. 처음 저장한 것만 쓰도록 바꿨습니다. 고친 뒤 `via.mss` 는 `3600-18-foot-00` 하나만 생겼습니다. 이 출발 상태는 `scenes()` 가 맵 순서로 늘어놓아 `36/00` 이 `36/01` 보다 먼저 도는 것에 기댑니다. 의도한 것이라 docstring 에 적었고, 저장한 상태가 없으면 검사가 멈춥니다.

## 2. 걸음 묶기의 시점

07번 일지에서는 인물 슬롯의 걸음 간격 `7E:3300`+슬롯을 `LATESET` 으로 0 으로 두었습니다. `dq5warp.lua` 는 `LATESET` 을 맵이 바뀌고 90프레임 뒤, 불러오기 단계가 끝날 때 씁니다. 그 사이에 돌아다니는 인물이 걸을 수 있었습니다.

`dq5warp.lua` 는 dq5 트랙 파일이라 고치지 않았습니다. 매 프레임 쓰는 `POKE` 는 바이트를 통째로 씁니다. 그러면 위 니블(걸음 간격)과 함께 아래 니블(같은 간격 인물끼리 걸음을 엇갈리게 하는 차례 번호, [DQ5 맵 형식](../../dq5/docs/dq5-map-format.md))까지 0 이 됩니다. 그래서 검사 프로브 앞에 작은 프로브 `lua/dq4holdwalk.lua` 를 두었습니다. 매 프레임 슬롯 `08`~`1F` 의 그 바이트를 읽어 위 니블만 0 으로 다시 쓰고, 그다음 원래 프로브를 그대로 돌립니다. 맵을 불러온 프레임부터 걸립니다. 묶은 실행이 끝날 때 위 니블은 모두 0 이었습니다. 아래 니블은 묶지 않은 실행과 달리 대부분 0 이었는데, 프로브가 쓰지 않은 값이라 걸음이 멈춘 동안 게임이 다시 매긴 것으로 보입니다(코드는 읽지 않음).

그룹 롬으로 끝 프레임의 인물 칸(슬롯 `08`~`1F` 의 `7E:3020`·`3080`)을 인물 목록의 처음 자리와 견줬습니다.

```text
                 걷는 인물  묶지 않음: 처음 자리를 떠난 칸   묶음
36/01 밤 장면 4개   5         3~5                           0
37/00 밤 장면 4개   6         6                             0
```

`(0,0)` 은 비어 있는 슬롯이라 셈에서 뺐습니다. `36/03` 의 `(6,9)` 는 묶든 묶지 않든 같은 칸이라 인물이 아닌 물체로 보입니다. 묶었을 때와 묶지 않았을 때 모두 16장면이 통과했습니다. 지금 배치에서는 걷는 인물이 침대 앞에 오지 않지만, 배치가 바뀌어도 결과가 걸음에 흔들리지 않습니다.

## 3. 훅 시험

- `05:8503` 을 앞·끝 몇 바이트만 보던 시험을, 갈래마다 명령을 따라가는 시험으로 바꿨습니다(`test_dq4sleepertalk.walk`). 스택은 바이트로 셉니다. `PHA`·`PLA` 는 M, `PHX`·`PHY` 는 X 너비, `PHD`·`PEA`·`PEI`·`PER` 은 2바이트입니다. `PHP` 는 그때의 M·X 를 쌓고 `PLP` 가 되돌립니다. 두 갈래가 만나는 곳마다 스택과 M·X 가 같아야 합니다. `RTS` 는 `05:859F` 하나이고 그때 스택이 들어올 때와 같습니다. 점프는 `05:8503`~`859F` 를 벗어나지 않고, `RTL`·`JML`·간접 점프·`TSX`/`TSC`/`TXS`/`TCS`·`XCE` 가 없습니다. 부르는 `05:85A0`·`05:85F8` 도 같은 규칙으로 훑습니다(`RTS` 는 여럿이어도 됨). 그 안의 `JSL $00D0A2` 는 맞춰 돌아온다고 봅니다. 들어올 때 M = X = 1 인지는 부르는 쪽 바이트로 봅니다. `05:82C6` `SEP #$30` 뒤 `05:82D5`~`82DC` 에 너비를 바꾸는 명령이 없고, `05:8370` 에서 `JSR $84FE` 여덟 곳까지 너비가 그대로입니다. 롬이 없는 CI 에서도 돌도록, 작은 합성 루틴으로 `walk()` 가 변이(`PLA`→`NOP`, 가운데 `RTS`, `RTL`, `TSX`, `XCE`, 짝 없는 `PLP`, 갈래 하나에만 쌓기·`REP`, 너비가 다른 쌓기·꺼내기)를 모두 잡는지도 봅니다(`WalkTest`).
- N/Z 시험은 「못 찾으면 부른 쪽이 A 를 스스로 둔다」 를 바이트로 봅니다. 방향마다 `JSR $84FE` / `BCS` / `DEC $00` 또는 `$01` / `JSR $84FE` / `BCS` / `LDA #$FF` / `RTS` 이고, 두 `BCS` 의 목적지는 `RTS` 입니다. 그 `RTS` 는 `05:8370` 을 거쳐 `05:82DC` 로 돌아가고, 거기서 A 를 쌓은 뒤 `CMP #$FF` 로 다시 견줍니다.
- `test_dq4chapter1` 의 침대 병사 기대 칸은 공식으로 다시 셈하지 않고 `(3,56)`·`(3,62)` 로 고정했습니다.
- 난수 고정 값 `RNG` 는 다른 모듈을 부르지 않는 `dq4pins.py` 로 옮겼습니다. `dq4ch1walkcheck.RNG` 는 그것을 그대로 읽습니다.
