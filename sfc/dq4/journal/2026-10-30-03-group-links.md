# 2026-10-30-03: バトランド 성·イムル 을 새 그룹으로 옮겨 출구 잇기

DQ5 실내 맵 자리를 빌려 넣었던 FC 맵 가운데 1장 バトランド 성(FC `02`)·イムル(FC `12`)을 그룹째 DQ5 새 그룹 `36`·`37` 에 넣고, 계단·성문·필드 출입을 FC 출구대로 이었습니다. 결과는 [환경 그래픽 문서의 그룹 연결](../docs/dq4-environment-format.md#그룹-연결)에 있습니다.

## 1. 왜 새 그룹인가

지금까지 FC 맵은 그림 확인용으로 DQ5 맵 자리를 하나씩 빌렸습니다. バトランド 02/00 은 03/00, 02/01 은 06/06 이라 두 맵이 다른 그룹에 있었고, FC 계단 짝(02/00↔02/03, 02/01↔02/02)을 옮길 수 없었습니다. 빌린 자리에는 원래 DQ5 인물·출구도 남아 있었습니다. 그래서 FC 그룹 하나를 새 그룹 하나에 맵 순서 그대로 넣기로 했습니다. dq5 트랙이 새 그룹을 필드와 잇는 도구(`dq5newmap`·`dq5exitreloc`·`dq5fieldtables`·`dq5npcrelocate`)를 이미 만들어 두었습니다.

`dq4environmentrom.py` 에 새 그룹 맵 표(`GROUPS`)를 더하고, 이 맵들은 레코드를 직접 쓰지 않고 `dq5map/1` 문서로 내 `dq5newmap.py` 의 `source` 로 넘깁니다. 바꾼 맵 찾기 표는 맵 번호(`$BC`·`$BD`)로만 찾으므로 새 번호도 그대로 받습니다. 빌렸던 03/00·19/02·06/06 은 원래 맵으로 돌아갔습니다.

## 2. 빌드 순서

`dq5newmap.py --door-bank` 는 뱅크 01 을 통째로 복사하므로, 환경 패치의 뱅크 01 끝(문 물체 항목)이 든 롬에서 만들어야 합니다. 처음에는 환경 패치를 넣은 롬 위에 나머지를 빌드하려 했는데 빌더가 받지 않았습니다.

```text
dq5build.py work/dq4-groups/env.sfc build: 원래 롬은 0x180000 바이트여야 함(지금 0x400000)
```

그래서 `dq5newmap.py` 만 환경 롬에서 만들고, 원래 롬에 모든 패치를 함께 빌드합니다. 새 그룹은 마지막 그룹 뒤라 밀리는 목록이 없어 겹침도 없었습니다. `dq4groupbuild.py` 가 이 순서를 묶습니다.

## 3. 계단

DQ5 출구는 셀 버퍼에서 `+4`·`+7` 이 `85` 등인 셀을 센 순서입니다. FC 계단 블록(속성 `08`·`09`)의 머리를 `09 00 05` 로 만들면 블록 오른쪽 아래 셀이 `85` 가 됩니다. 같은 그림이라도 계단 여부로 블록을 나누니 블록이 144 → 147개가 되었습니다. 출구 표시는 새 그룹 맵의 계단에만 넣습니다. 처음에는 모든 맵의 계단에 넣었는데, 독립 리뷰에서 빌린 자리 43곳 가운데 35곳에 FC 계단이 있어 밟으면 그 DQ5 맵의 원래 출구 목록을 따라 간다는 지적을 받았습니다(03/10 은 계단 3 에 원래 항목 1). 검사 도구에 맵마다 출구 표시 셀 수를 세는 항목을 더했습니다. 맵마다 FC 계단을 (Y, X) 순으로 놓은 차례가 출구 번호이고, FC `08:$B22E` 의 목적지를 같은 그룹 항목으로 옮겼습니다. 짝 계단끼리 서로를 가리키는지는 단위 테스트로 봅니다.

## 4. 성문과 성 아래 끝: 영역 이동

02/00 에서 성 안 02/01 로 가는 길은 계단이 아니라 FC 출구 표 `$05A0` 의 칸(성문 (12,0A)·(13,0A))이고, 돌아오는 길은 02/01 맵 아래 바깥 (0F,24)·(10,24)입니다. DQ5 영역 이동 레코드로 옮겼습니다.

처음에는 사각형을 FC 칸의 두 줄 높이로 만들었습니다. 성문으로 들어가니 02/01 (30,66)에 섰는데, 기대한 자리는 (30,70)이었습니다. 시간을 나눠 보니 맵 번호가 바뀐 뒤 위치가 바로 (30,66)으로 정해지고 움직이지 않았습니다. 누르던 키 탓이 아니었습니다. `2A:F636` 을 읽으니 사각형 높이가 1 이 아니면 `2A:F67C` 로 가서 도착 Y 를 비례로 정하고 폭 바이트를 `EOR #$FF` 로 씁니다. 원본의 `FA`~`FE` 폭이 이 세로 사각형 값이었습니다.

```text
2A:F636  LDY #$03 / LDA ($00),Y / DEY / DEY / SEC / SBC ($00),Y / DEC A / BNE $F67C   ; 높이-1 ≠ 0 → 세로
2A:F686  EOR #$FF                                                                  ; 세로는 폭을 뒤집어 씀
```

사각형을 한 줄로 바꾸고, 그 줄을 일행이 처음 밟는 줄로 정했습니다. 걷는 방향은 도착 쪽 끝점 플래그의 아래 2비트(02/01 도착 `80` = 위, 02/00 도착 `82` = 아래)입니다. 02/01 아래 바깥을 바깥 FC 칸의 아래 줄(73)에 두었을 때는 첫 바깥 줄(72)에서 필드로 나가기가 먼저 일어나 필드 (345,57)에 섰습니다. 위 줄(72)에 두자 성문으로 돌아왔습니다.

도착하면 엔진이 걷던 방향으로 한 걸음 더 갑니다. 02/01 에서 내려와 성문 칸 위에 도착해도 성문 아래 (36,23)으로 비켜나므로 다시 발동하지 않았습니다. 아래로 4~16프레임만 눌러도 모두 (36,23)이었습니다.

## 5. 필드

새 그룹은 일반 입구 표에 없으므로 맵 밖으로 나가면 보조 입구 표 항목의 (X, Y+1)에 섭니다. 필드 입구는 DQ4 필드가 없는 동안 빈 들판 (345,56)·(337,56)에 두었습니다. 그룹 도착은 FC 도착 레코드의 칸입니다. イムル 의 레코드 끝 바이트 `04` 를 처음에는 연결 표 플래그처럼 「bit2 = 한 칸 옮김」으로 보고 (0D,18)에 두었습니다. FC 에서 필드 입구로 걸어 들어가 보니 그대로 (0D,19)였습니다.

```text
f451 끝 63=12 64=00 65=00 42=9A 43=16 44=0D 45=19 28=0E
```

## 6. 확인

`dq4groupcheck.py` 26장면이 모두 통과했습니다. 계단 18곳은 짝 계단 칸으로, 성문은 성 안으로(사각형 오른쪽 끝 (38,23)에서 들어가면 도착도 오른쪽 끝 (32,70)), 성 아래는 성문 아래로, 두 그룹 모두 필드로 나가고 다시 들어왔습니다. 방향 키를 처음 누르면 몸만 돌고 한 셀에 8프레임이 걸려, 12·20프레임 누름으로는 계단 한 셀 앞에서 멈췄습니다. 32프레임으로 늘렸습니다.

배 선실 워프는 배 사다리 출구 항목을 덮는데, 출구 표를 옮겨 그 자리가 바뀝니다. 그래서 두 검사 모두 `dq5warp.lua` 에 `WARPEXIT` 를 줍니다. 필드 워프(`FIELD`)는 이 빌드가 옮기는 입구 표를 덮으므로, 필드 장면은 세이브스테이트에서 걸었습니다.

`dq4environmentromcheck.py` 는 같은 롬에서 50개 맵 모두 픽셀 차이 0, 통행 불일치 0, 문 물체 55/55였습니다. 빌렸다 되돌린 03/00·19/02·06/06 은 셀 버퍼가 원래 롬과 같았습니다. 성문을 연 채 위로 걸으면 성문을 지나 36/01 로 들어갔습니다.

## 틀렸던 것들

- 영역 이동 사각형을 FC 칸 두 줄 높이로 두면 된다고 보았습니다. 높이가 2 이상이면 세로 비례 도착이 되어 엉뚱한 줄에 섰습니다.
- 맵 아래 바깥 출구를 바깥 FC 칸의 아래 줄에 두었습니다. 첫 바깥 줄에서 필드로 나가기가 먼저 일어납니다.
- イムル 도착 레코드의 `04` 를 한 칸 옮김으로 읽었습니다. 레코드 칸 그대로였습니다.
- 환경 패치를 넣은 4MB 롬 위에 빌드할 수 있다고 보았습니다. 빌더는 원래 롬만 받습니다.
- 계단 출구 표시를 모든 맵에 넣었습니다. 빌린 자리 맵에서는 원래 DQ5 출구가 걸립니다.

## 남은 것

- 두 그룹의 인물(FC 위치·방향·움직임, 대사는 일본어 원문 임시)·상자·이벤트.
- 나머지 FC 그룹을 새 그룹으로 옮기기. 빌린 자리 43곳에는 원래 DQ5 인물·출구가 남아 있습니다.
- 그룹 도착 방향(지금 0)을 FC 방향과 맞추기, 옆으로 들어가는 FC 출구 표 칸(세로 영역 이동).
