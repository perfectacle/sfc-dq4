# 2026-11-03-07: 침대 발치 훅 다시 보기와 왕좌의 방 침대 병사

[04번 일지](2026-11-03-04-sleepers-stands-shop.md)의 침대 발치 훅(`05:84FE` → `05:FEF0`)을 리뷰 지적대로 다시 보았습니다. 훅을 부르는 코드와 불리는 코드가 훅에 기대도 되는지 확인했고, 훅 자리를 지키는 법도 보았습니다. 침대 검사(`dq4sleepercheck`)는 결정적으로 고쳤습니다. 1장 왕좌의 방 밤 침대 병사 둘은 FC 에서 재 보고 FC 처럼 눕혔습니다. 결과는 [환경 형식 문서 「인물」](../docs/dq4-environment-format.md#인물)과 [1장 형식 문서 「인물」](../docs/dq4-chapter1-format.md#인물)에 있습니다.

## 1. 훅이 바꾸는 플래그를 누가 읽나

훅은 처음 셀에 누운 인물이 없으면 `INC $00` 뒤에 `05:8503` 을 한 번 더 부르고 `DEC $00` 으로 끝납니다. 그래서 둘째 길에서는 N/Z 가 `05:8503` 이 남긴 값이 아니라 `DEC` 의 결과입니다. 원래 롬 뱅크 `05` 에서 `JSR $84FE`(`20 FE 84`)를 모두 찾았습니다. 방향마다 둘씩 여덟 곳입니다.

```text
05:83DF 05:83E6  위    05:842B 05:8432  아래
05:8476 05:847D  오른쪽 05:84DC 05:84E3  왼쪽
```

여덟 곳 모두 바로 뒤가 `BCS` 입니다. 못 찾으면 스스로 `LDA #$FF` 를 하고 돌아갑니다. 찾았을 때 돌려주는 A 는 부른 쪽(`05:82DF`)이 `CMP #$FF` 로 다시 견줍니다. N/Z 를 읽는 곳이 없어 `PHP`/`PLP` 로 감쌀 까닭이 없습니다.

## 2. 두 번 불러도 되는가

`05:8503` 의 앞과 끝을 디스어셈블했습니다.

```text
05:8503  STA $A2 / LDA $00 / PHA / LDA $01 / PHA     ; $00·$01 을 쌓음
…
05:8597  TAX / PLA / STA $01 / PLA / STA $00 / TXA / RTS
```

하나뿐인 `RTS` 앞에서 `$00`·`$01` 을 되돌리고 스택을 맞춥니다. 안에서 부르는 `05:85A0` 은 `PHP`/`PHB` 와 `PLB`/`PLP`, `05:85F8` 은 `$00` 을 Y 로 맡겼다 되돌려 모두 짝이 맞습니다. 스택 깊이를 읽는 `TSC`·`TSX` 는 없습니다. 그래서 훅의 `INC $00` / 부르기 / `DEC $00` 뒤 `$00` 은 부른 쪽이 둔 값 그대로입니다. 부른 쪽은 이 값에서 `DEC $00` 해 다음 셀을 봅니다. X·Y 는 덮이지만 원래 한 번 부를 때도 같습니다. 부른 쪽은 찾았을 때 A 만 씁니다.

## 3. 훅 자리

`05:FEF0`~`05:FEFE` 는 `dq5build.free_ranges` 가 내는 원래 롬 빈 자리 `05:FEA0`~`05:FFFF` 안이고, 가게 도우미 `05:FF00`(`dq4windowname.LOW_SPOT`) 앞입니다. DQ5 쪽 표 배치 도구(`dq5exitreloc`·`dq5chestreloc`)는 받은 주소가 빈 자리 안인지만 보고, 자리를 스스로 고르지 않습니다. 두 패치가 같은 바이트를 쓰면 `dq5build` 가 「겹침」 으로 멈추고, 단계끼리 덮어쓰면 롬 쓰기 장부가 잡습니다. `dq5build` 는 dq5 트랙 파일이라 손대지 않았습니다. 훅 자리가 빈 자리 안이고 `05:FF00` 앞인지는 시험으로 남겼습니다.

## 4. 가드 실행기의 빌드 폴더

`dq4-npc-talk`·`dq4-group-links`·`dq4-sleeper-talk` 는 모두 `work/dq4-groups` 에 그룹 롬을 빌드합니다. `tools/guards.py` 는 마지막 단계 앞에 `--out` 으로 무언가를 만드는 검사를 「빌드하는 검사」 로 보고, 이들을 나머지보다 먼저 하나씩 차례로 돌립니다(`run_all`). 그래서 같은 폴더를 함께 쓰지 않고, 폴더를 나누지 않았습니다.

## 5. 침대 검사를 결정적으로

`dq4sleepercheck` 는 난수를 두지 않고 출발 상태 그대로 순간이동했습니다. 돌아다니는 인물이 주인공 앞 줄에 들면 서 있는 인물 찾기(`05:8501`)가 먼저 대답할 수 있습니다. 이제 장면마다 난수 `7E:075B`~`075D` 를 시작과 도착 때 같은 값(`dq4ch1walkcheck.RNG`)으로 둡니다. 도착하면 인물 슬롯의 걸음 간격 `7E:3300`+슬롯을 0 으로 둡니다. 인물 슬롯의 시작 `7E:1994` 는 1장 롬과 그룹 롬 모두 `08` 이었습니다. 다르면 검사가 멈춥니다.

## 6. 왕좌의 방 밤 침대 병사

1장 롬의 왕좌의 방은 옮긴 FC 인물이 아니라 `dq4chapter1` 이 따로 쓴 목록입니다. 밤 침대의 병사 둘(FC (01,1C)·(01,1F))은 서 있는 엔트리라 침대 위에 섰습니다. FC 롬에서 `$62ED` = `80`(밤)으로 `02/01` 에 순간이동해 다섯 자리에서 말을 걸었습니다(`warp.lua` + `talk.lua`).

```text
                     (01,1C) 병사        (01,1F) 병사
발치 위 (01,y-1) 아래  슬롯 0D 05C9       슬롯 0E 051E
발치 아래 (01,y+1) 위  슬롯 0D 05C9       슬롯 0E 051E
침대 오른쪽 (03,y) 왼쪽 슬롯 0D 05C9       슬롯 0E 051E
머리맡 위 (02,y-1) 아래 02F0(아무도 없음)  02F0
머리맡 아래 (02,y+1) 위 02F0              02F0
```

화면에서도 둘은 침대에 누워 있었습니다. 그래서 둘을 옮긴 FC 누운 인물과 같은 누운 견본(`10:A4E9` 14번)으로, 자리 (2x+1, 2y)·오른쪽으로 두었습니다(`NIGHT_ABED`). 머리맡 쪽에서도 대답하는 것은 [04번 일지](2026-11-03-04-sleepers-stands-shop.md)의 사용자 결정과 같습니다.

`dq4sleepercheck --chapter1` 이 이 둘도 봅니다. 처음에는 네 장면이 대사 없이 끝났습니다. 1장 출발 상태가 왕좌의 방에 서 있는데, `dq5warp.lua` 는 맵 번호가 목적지로 바뀌는 것을 도착으로 봅니다. 그래서 같은 맵으로의 순간이동은 끝까지 「도착」 하지 못했고(`timeout phase=any`), 대화 입력도 들어가지 않았습니다. 04번 일지에서 「(01,1F) 병사는 어느 쪽에서도 대사가 없었다」 고 적은 것도 이 때문이라, 그때의 결과로는 말이 걸리는지 알 수 없었습니다. 이제 왕좌의 방 장면은 앞 장면이 `36/00` 에 도착했을 때 남긴 세이브스테이트에서 출발합니다.

```text
고치기 전 1장 롬(origin/main, SHA-1 879e1208)  16장면 중 왕좌의 방 4장면 129(아무도 없음)
고친 1장 롬                                    16/16 통과
그룹 롬                                        16/16 통과
```

## 7. 재발 방지

- `test_dq4sleepertalk`: `JSR $84FE` 여덟 곳 뒤가 모두 `BCS`, `05:8503` 의 `$00`·`$01` 쌓기·되돌리기 바이트, 훅 자리가 원래 롬 빈 자리 안이고 `05:FF00` 앞. 원본 롬이 머리 없는 1.5MB 인지(`lorom` 이 512바이트 머리를 빼지 않으므로).
- `test_dq4chapter1` `test_night_bed_guards_lie_like_the_ported_sleepers`: 밤 침대 병사 둘이 누운 견본·(2x+1, 2y)·오른쪽.
- 가드 `dq4-sleeper-talk` 가 1장 롬의 왕좌의 방 네 장면을 함께 보고, `dq4-map-people-rom-tests` 는 ok 14개를 셉니다.

## 틀렸던 것들
