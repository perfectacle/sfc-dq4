# 2026-10-28-06: 강함 보기 라벨과 창 타일맵 전송

앞 일지에서 미룬 강함 보기(つよさみる) 라벨을 한글로 바꿨습니다. 라벨을 그리면 1쪽 오른쪽 창 아래가 비던 까닭은, 우리 대기열과 게임의 창 타일맵 전송이 한 NMI 에 겹쳐 VBlank 를 넘긴 것이었습니다. 결과는 [전송: 게임 목록 대신 우리 대기열](../docs/dq4-window-text-format.md#전송-게임-목록-대신-우리-대기열)과 [강함 보기 라벨](../docs/dq4-window-text-format.md#강함-보기-라벨)에 있습니다.

## 1. 창 타일맵을 보내는 곳

BG3 를 옮길 때 찾은 VMADD 쓰기 중 `00:8E55`·`00:8E75` 는 같은 루틴 `00:8DE9` 안에 있습니다. 루틴은 `$0BEC` 를 보고 갈래를 고릅니다.

```
00:8DED  BIT $0BEC
00:8DF0  BMI $8DF5      ; bit7: 7E:5000 → 1C00, 0x800 바이트
00:8DF2  BVS $8E34      ; bit6: 위 0x1C0 바이트 + 7E:5540 부터 0x240 바이트
00:8DF4  RTS
...
00:8E90  STZ $0BEC
```

`$0BEC` 를 쓰는 곳은 `04:9D3C`(`LDA #$80`)와 `04:9D66`(`LDA #$40`), 읽는 곳은 `00:8DED` 하나입니다(롬 정적 검색). 필드 NMI 작업 `00:8926` 은 맨 먼저 `JSR $894F` → `JMP ($1946)` 로 이 루틴에 들어옵니다. 우리 대기열은 그보다 앞인 `00:FFA1` 받침에서 보냅니다.

## 2. 겹친 NMI

라벨을 켠 롬으로 강함 보기 1쪽을 열고, `dq5msg.lua` 의 `CALLS` 기록에 그때의 줄 번호(`ppu.scanline`)를 더해 찍었습니다.

```
343 049D3C  sl=201  $0BEC=0000 대기열=4   ; 게임이 2KB 전송을 건다
344 60CA99  sl=244  $0BEC=0080 대기열=4   ; NMI: 우리 대기열부터
344 008E88  sl=252  $0BEC=0080 대기열=0   ; 그 뒤 2KB DMA 시작
```

2KB DMA 는 바이트마다 8 마스터 클럭이라 약 12줄이 걸립니다. 줄 252 에서 시작하면 VBlank 끝(261)까지 9줄 남짓만 남습니다. 버퍼는 맞는데 VRAM 은 창 20번째 줄부터 옛 내용이던 것과 맞습니다. 라벨이 없을 때는 이 NMI 에 대기열이 비어 있어 DMA 가 일찍 시작했습니다.

## 3. 어느 쪽을 미룰까

먼저 `$0BEC` 가 걸린 NMI 에서는 대기열을 다음 NMI 로 미뤘습니다. 강함 보기는 끝까지 그려졌습니다. 그런데 선실에서 명령 창을 열자 아래 칸(도구·작전·문·조사)에 줄무늬가 남았습니다. 명령 창이 떠 있는 동안 게임이 매 프레임 `04:9D3C` 로 bit7 을 걸어(기록한 41~68 프레임 내내), 대기열 항목 여섯이 한 번도 나가지 못했습니다.

그래서 반대로 했습니다. 겹치면 대기열을 보내고, `$0BEC` 를 `7E:3D5A` 에 옮겨 0 으로 둡니다. 다음 NMI 에 그 값을 `$0BEC` 에 OR 해 되돌립니다. 받침은 대기열이 비었어도 미룬 값이 있으면 `WqNmiGate` 를 부릅니다. 대기열이 다 나간 다음 NMI 에 타일맵이 가므로, 새 글자 그림이 타일맵보다 먼저 VRAM 에 있게 됩니다.

| 장면 | 결과 |
| --- | --- |
| 강함 보기 1쪽 | 「힘 / 민첩 / 방어력 / 현명함 / 운 / 최대HP / 최대MP / 공격력 / 수비력」, 「성별 / 레벨」, 아래 테두리까지 그려짐 |
| 선실 명령 창 | 첫 장(48 프레임)부터 글자가 다 나옴 |
| 무작위 입력 6벌(선실 넷, 전투 둘, 8000 프레임) | 모두 `$1D/$1E` = `0F 81`. main 롬과 다른 장면은 라벨과 입력 흐름이 몇 프레임 어긋난 것뿐 |
| 이름 넣기·커서·게임 안 이름 검사 | VRAM 0 차이, 52건 통과, PASS 7 / FAIL 0 |

## 4. 라벨 레코드

`07` 은 `01 01 01 01 ちから 85 B4` 처럼 빈칸으로 오른쪽을 맞춘 꼴입니다. 빈칸 + 가나를 빈칸 + `9E k` 로 바꿔, 한글 열 수가 가나 칸 수보다 적은 만큼 빈칸을 더 둡니다. 가나 덩이를 읽는 `_runs` 는 가나 범위(`02`~`AF`)에 든 `85` 까지 먹어서, `85`·`86`·`87` 에서 끊게 했습니다.

## 틀렸던 것들

- 앞 일지에서 대기열을 NMI 맨 앞(`00:8872`)에서 보내 봤지만 같았습니다. 그 자리도 `$1944` 작업보다 앞이라 2KB DMA 를 더 늦출 뿐이었습니다.
- NMI 마다 256바이트까지만 보내도 같았습니다. 그만큼 보내고도 2KB DMA 가 VBlank 를 넘긴 것으로 보이지만, 그 실행의 줄 번호는 재지 않았습니다.
- `$0BEC` 가 걸린 NMI 에서 대기열을 미루면 명령 창처럼 매 프레임 요청이 걸리는 동안 글자가 올라가지 않습니다(3절).
