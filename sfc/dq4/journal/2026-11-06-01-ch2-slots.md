# 2026-11-06-01: 2장 사건을 나눠 만들 자리를 재고 나누기

2장의 남은 사건(텐페 뒤 절반, 프레놀·남쪽 동굴, 바자·왕 병·탑·사당, 엔돌 무술 대회, 빈 성·2장 끝, 동료 대화)을 여러 세션이 동시에 만들려면, 사건 코드·flag·대체 목록·대화 스크립트처럼 모두가 쓰는 자리를 먼저 재고 나눠야 했다. 재 보니 대화 스크립트 자리와 대체 목록 자리가 거의 차 있어 둘을 옮겼고, 사건 모듈을 한 줄로 끼우는 등록 장치와 보스 전투 진입 하나를 만들었다. 결과는 [2장 형식 문서의 「사건 등록과 자원 예약」](../docs/dq4-chapter2-format.md#사건-등록과-자원-예약)에 있다.

## 1. 남은 자리 재기

`dq4build.py --chapter2` 로 만든 롬에서 0 이거나 원본 거울 그대로인 바이트를 뱅크마다 셌다. `--keep` 으로 남긴 1장 단계 패치(`talk.dq5patch.json`·`npc.dq5patch.json`)에서 쓰는 양을 따로 읽었다.

```
talk.dq5patch.json 3C:E800 1713 덧붙인 스크립트
npc.dq5patch.json  35:8000 27825 기본 인물 그룹 포인터와 목록
npc.dq5patch.json  38:8000 29496 대체 인물 목록
```

대화 스크립트는 `3C:EEB1` 에서 끝나고 그 뒤 335바이트 다음이 여관 표(`3C:F000`)다. 대체 목록 뱅크 `38` 은 꼬리 3,272바이트가 남았다(롬의 마지막 0 아닌 바이트는 `38:FFED` 였지만 원본 `28` 의 거울 그대로라 빈 자리). 텐페 아침, 엔돌 2장 상태, 빈 성 같은 새 목록만으로도 넘칠 양이다. 뱅크 06 의 빈 자리도 처음 계획에 적힌 약 390바이트가 아니라, 1장 전투·팡파르와 창 이름 훅 사이 `06:FF57`~`FFAF` 89바이트뿐이었다.

## 2. 대화 스크립트와 대체 목록 옮기기

새 맵 레코드 자리(`RECORDS_AT`)는 `32:C566` 까지만 차서 `33`·`36`·`37` 이 통째로 비어 있었다. 대화 스크립트는 실행하는 동안 그 뱅크를 데이터 뱅크로 두므로 `30`~`3F` 의 한 뱅크여야 한다. `36` 을 대화 스크립트(`--extra-at 36:8000`)에, `37` 을 대체 목록 둘째 뱅크(`--alt 38:8000,37:8000`)에 주고 레코드 자리에서 뺐다. 롬 차이는 이것뿐이었다.

```
bank 36 +1706  대화 스크립트
bank 3C -1706  옛 자리
bank 38  2284  조건 표 7바이트 항목·찾기 루틴(두 뱅크 꼴)
bank 06  44    전투 진입 루틴, 대화 훅의 묶음 표 주소·스크립트 뱅크(3C → 36)
12:82FC  2     대체 목록 찾기 루틴 주소
```

## 3. flag 자리

`dq5flags.py` 전체 출력에 없는 비트는 195개였다. 그런데 `21DC`·`21DE` 의 빈 비트는 배의 필드 X·Y 를 16비트로 쓸 때 덮이고, 나머지 대부분은 `21F0`~`220C` 에 몰려 있었다. 이 자리는 DQ5 의 색인 쓰기 셋이 덮는다.

```
02:E050  LDX #$08 / TXA / STA $7E21EF,X / DEX / BPL    15/01 수수께끼 맵 루틴(15:FE8D 항목)
23:E201  LDX #$16 … STA $7E21F5,X / STA $7E21F6,X / DEX / DEX   23:E1FE, 부르는 곳은 02:9BFD(파파스가 쓰러지는 장면) 하나
05:E31D  STA $7E21FA,X / STA $7E21FB,X                   31/07 바위 맵
```

2장 첫머리가 이미 쓰는 `2208` 도 `23:E214` 의 범위 안이었다. 이 해킹의 맵 그룹은 `36`~`47` 뿐이라 세 장면은 돌지 않는다. 그래서 고정 주소로도 쓰이는 `21F5`·`21F6`·`21F8`~`21FB` 만 빼고 바이트째 세션에 나눴다. 스크립트가 다루는 flag 는 `2190`~`220F` 안이라 이보다 넓은 자리는 없다.

## 4. 이벤트 무리·몬스터·인물 스크립트

이벤트 무리 표의 `31`~`3A` 는 빈 꼴(`c0 00 ff …`)이었다. 덮을 DQ5 몬스터는 이벤트 무리에만 나오고 필드 조우(`dq4fieldencounter.MONSTERS`)와 1장 보스에 없는 것 가운데, 이름으로 보아 따로 짠 동작이 있을 것 같은 ミルドラース·ゲマ·ジャミ·상자 몬스터를 뺐다. HP 2046 인 몬스터의 HP 바꿔치기는 레코드 값으로 고르므로 덮으면 걸리지 않는다. 빌릴 인물 스크립트는 DQ5 목록의 한 벌짜리 스크립트 인물 가운데 이 해킹이 주소로 부르지 않는 552개에서 세션마다 목록 하나둘을 골랐다.

## 5. 등록 장치와 전투 진입

`dq4ch2event.EVENTS` 에 모듈 이름을 넣으면 메시지·대화·인물 스크립트·대체 목록·네이티브·훅·이벤트 토큰·전투 무리·몬스터를 빌드가 모은다. 메시지 번호는 빈 번호 없이 이어야 해서 미리 나누지 않고 등록 차례로 매긴다. 모듈이 없으면 번호는 전과 같다.

전투 진입은 1장 탑 위 보스의 `BRK 0E / LDA #무리 / JSL $01868B / CMP #$80` 을 뱅크 06 공용 루틴으로 옮기고, 이기면 `2208` bit7 을 켜게 했다. 커밋하지 않는 시험 모듈로 텐페 촌장 대화에 HP 1 로 덮은 몬스터의 무리를, 신부 대화에 강하게 덮은 몬스터의 무리를 걸었다.

```
f01000 「36포인트의 경험치를 얻었다! / 레벨 2에 올랐다!」
f01600 map 3D/03 cell 42,77 2208=90 21F0=01     이김 → 대화 스크립트가 21F0 bit0
f01200 map 3D/00 cell 54,21 2208=10 21F0=00     짐 → 전멸 처리, 산트하임 성
```

## 틀렸던 것들

- 뱅크 06 에 약 390바이트가 남았다고 보았다. 창 이름 훅(`06:FE64`~`FEEB`, `06:FFB0`~)이 그 뒤에 들어와 89바이트만 남았다. 그래서 전투마다 루틴을 두지 않고 공용 루틴 하나와 9바이트 입구로 나눴다.
- 대체 목록 뱅크가 꽉 찼다고 처음에 셌다(마지막 0 아닌 바이트 `38:FFED`). 그 꼬리는 원본 거울이었고 실제로는 3,272바이트가 남아 있었다. 그래도 2장 사건 몫에는 모자라 둘째 뱅크를 붙였다.

## 남은 것

- 지고 이어 가는 전투(무술 대회의 침대 `030D`)는 공용 루틴이 하지 않는다. DQ5 이벤트 전투 입구 `01:86A7`·`01:86C3` 이 지는 경우 어떻게 돌아오는지 재야 한다.
- 대체 목록이 실제로 `37` 로 넘어간 롬은 아직 없다.
- 동료 대화 대사가 몫을 넘으면 메시지 덩어리 셋째 자리가 필요하다.
