# DQ4 1장 첫머리

새 게임을 고르면 DQ5 프롤로그(태어나는 장면 → 『DRAGON QUEST V』 로고 → 배) 대신 DQ4 1장 「왕궁의 전사들」 첫머리가 한글로 시작하게 하는 명세입니다. 무대는 [그룹 연결](dq4-environment-format.md#그룹-연결)이 새 그룹 `36` 에 넣은 바트랜드 성이고, 맵·인물 그림은 새로 그리지 않습니다(맵은 환경 맵, 인물은 DQ5 세트). 도구는 `sfc/dq4/tools/dq4chapter1.py` 와, 검은 화면 장 제목 상자를 만드는 `sfc/dq4/tools/dq4chapterbox.py` 입니다.

| 넣는 것 | 자리 |
| --- | --- |
| 새 게임 첫 맵 | `25:8621` 표 항목 0 → `36/01`(FC `02/01` 왕좌의 방) 셀 (32,42) |
| 연출 | 검은 화면의 금테 장 제목 상자 → 검은 화면의 서술 → 왕좌의 방이 밝아짐 → 대신의 말 → 왕이 계단에서 내려와 연설 → 전사들이 아래 출구로 걸어 나감 |
| 시작 연출 코드 | `5F:8000`(훅 둘·네이티브 루틴 둘·상자 자료. 사운드 세트는 `6A`~`6F`·`72`~`7D` 를 씀). 훅 `25:834A`(새 게임 시작)·`2B:8293`(맵 불러오기) |
| 한글 대사 | 연출 3개, 왕좌의 방 15개, 성 앞 7개(FC 원문을 옮김) |
| 인물 | `36/01` 21명(연출 뒤 15명). 나머지 맵은 [인물](dq4-environment-format.md#인물)(`dq4npcport.py`) 그대로 |
| 맵 곡 | 그룹 `36` 맵 속성의 곡 바이트를 `01`(성 곡). 연출 전에는 이벤트 곡 `23`(インテルメッツォ)을 틀고, 왕좌의 방이 밝아질 때 성 곡으로 |

## 새 게임 첫 맵

전원부터 A 를 누르며 `$BC`·`$BD`(직접 페이지 `00:00BC`) 쓰기를 기록하자, 새 게임에서 처음 쓴 곳이 `25:8325`·`25:832E` 였습니다(프레임 362, 02/06). 그다음은 출산 방 02/07(`00:C015`), 로고 뒤 배 17/00(`0F:D962`)입니다.

`25:82D2` 가 `$195E` = `21` 을 쓰고 X = 0 으로 `25:8321` 에 갑니다. `25:8321` 은 `25:8621` 의 6바이트 표에서 X 번째 항목을 `$BC`·`$BD`·`$C1`·`$C2`·`$C3`·`$198E` 에 씁니다. 같은 표를 `25:82BE` 가 첫 바이트를 `$71` 과 견줘 고르므로, 저장 재개 자리 표로 보입니다(코드 읽기). 새 게임은 항목 0 을 씁니다.

| 항목 0 | `$BC` | `$BD` | `$C1`(X) | `$C2`(Y) | `$C3`(층) | `$198E` |
| --- | --- | --- | --- | --- | --- | --- |
| 원래 | `02` | `06` | 38 | 14 | `01` | `80` |
| 1장 | `36` | `01` | 32 | 42 | `01` | `80` |

(32,42) 는 FC (10,15), 줄 선 전사들 사이의 빈자리입니다. 처음 맵 02/06 이 아니면 태어나는 장면(`15:F000`)도, 로고(`0F:D93A` 의 `BRK 19 15 01`)도 돌지 않아 DQ5 로고 화면과 로고 곡이 나오지 않습니다. 같은 항목을 `$71` = `02` 인 재개에서도 쓰지만, 1장 첫머리에서는 그 재개가 생기지 않습니다.

## 메시지

`dq4chapter1.py messages` 가 [`dq4menupatch.py build --messages`](dq4-menu-format.md#다른-메시지-더하기)에 넘길 `dq4messages/1` 문서를 냅니다. 메뉴 빌드가 보행 메시지 3,200개의 허프만 트리를 다시 만들 때 함께 넣습니다.

| 번호 | 쓰임 | 원래 |
| --- | --- | --- |
| `1D1` | 서술 3쪽 「이것은 바트랜드라는 작은 나라의 왕궁 전사의 이야기다.」…(FC 오프닝 서술, `{1006}`) | 태어나는 장면 |
| `1D2` | 대신 「이제부터 임금님께서…」(FC `0301`) | 태어나는 장면 |
| `1D3` | 왕의 연설 5쪽(FC `0302`) | 태어나는 장면 |
| `6C6`~`6D4` | 왕좌의 방 인물 대사 15개. 대화 번호 `300`~`30E` | DQ5 마을 대사 |
| `647`·`64A`·`64B`·`678`·`679`·`67A`·`67C` | 성 앞 7명. `dq4npcport.py` 가 그 인물에게 준 번호에 일본어 원문 대신 한글 | DQ5 후반 마을 대사 |

- `messages` 는 `dq4npcport.py` 의 일본어 메시지(왕좌의 방 인물만 쓰던 것은 뺌)에 위 한글을 덮어 냅니다. 성 앞 7명은 FC 메시지 묶음(`078C`, `05E3`+`05E4`, `05E1`, `05E2`, `05E5`, `078D`, `05E0`)으로 찾습니다. 통합 롬은 메뉴 빌드가 보행 메시지 트리를 다시 만들므로 `dq4groupbuild.py` 의 대사 패치(`35:8000`)는 쓰지 않습니다.
- 대화 번호 T 가 `26D` 이상이면 메시지 T + `3C6` 을 띄웁니다([텍스트 형식의 대화 번호](../../dq5/docs/dq5-text-format.md)). 그래서 인물마다 스크립트 없이 대화 번호만 줍니다. 덮은 `6C6`~ 는 DQ5 마을 대사라 그 마을에 가면 한글 대사가 나옵니다.
- 말하는 이 표시는 DQ5 꼴(`{1003}` 이름 `「`)이고, 이름 없는 인물은 엔진이 `＊「` 를 붙입니다. 원작이 「ライアン」 으로 박은 자리는 이름 입력값 `{1012}` 입니다.
- 창은 한 쪽에 4줄, 한 줄에 `＊「`·들여쓰기 뒤 한글 14자까지입니다. 15자째에서 창 오른쪽을 넘어 다음 칸이 깨졌고, 한 쪽에 6줄을 넣자 쪽 넘김 없이 밀려 올라가다 빈 창만 남았습니다. 대사는 `/` 로 줄을 나눠 적고 도구가 14자(이름은 4자로 셈)·4줄을 검사합니다.
- 서술문은 해라체(「~다.」)로 옮깁니다. `{1006}` 은 쪽마다 다시 넣어야 합니다. 쪽 넘김(`1002`) 뒤 첫 코드가 `{1006}` 이 아니면 그 쪽에 `＊「` 가 붙었습니다(실측). 서술문은 들여쓰기가 없지만 몇 칸까지 들어가는지 재지 않아 대사와 같은 14칸으로 둡니다.
- `「`(`363`)·`…`(`366`)는 DQ5 글자, `.`·`?`·`!`·`,` 는 Galmuri11 부호입니다([메뉴 메시지의 글자](dq4-menu-format.md#글자)).
- 고유명사는 `nds/dq4/tables/adopt.tsv`(바트랜드·이무르·라이안·약초·프레아)를 따르고, 표에 없는 アレクス 는 「알렉스」로 옮겼습니다.

## 인물

`dq5npcrelocate.py` 문서에 `dq4npcport.py` 의 목록을 그대로 넣되 `36/01` 기본 목록만 이 연출 배치로 바꾸고, 대체 목록 하나를 더합니다. 엔트리는 원본 엔트리를 복사해 필드만 바꿉니다.

| 복사 원본 | 쓰는 인물 | 까닭 |
| --- | --- | --- |
| `05:8E43` 0번(03/00, 스크립트 없음) | 왕좌의 방의 스크립트 없는 인물 | 애니 값이 횃불의 `2/2` 라 `F/F`(DQ5 사람 인물 값)로 덮음. 덮지 않으면 제자리걸음이 빨랐음 |
| `05:A848` 0번(배, 스크립트 `05:A84F`) | 왕(연출) | |
| `05:A848` 3번·2번(배, `05:A899`·`05:A87B`) | 줄 선 전사 왼쪽·오른쪽 무리 | 1번(`05:A867`)은 누운 선원이라(기타 bit7) 복사하면 누워 그려짐 |

- 자리는 FC 블록 (x, y) 의 DQ5 셀 (2x, 2y), 층은 `layer` 0 입니다. 레코드 `layer` 1 은 인물 표 층 마스크 `31A0` = 2 가 되어 주인공(1)과 달라 말을 걸어도 「その方向には 誰もいない。」 였습니다.
- 그림 번호는 왕 `14`, 대신 `01`, 성 병사 `67`, 전사 `08`, 여인 `04`, 하녀 `82`, 학자 `09`, 남자 `29`, 이무르 사람 `0C`, 프레아 `15` 입니다(`dq5sprite.py` 시트에서 고름).
- FC 에서 카운터(1C,16) 너머의 학자는 DQ5 카운터 너머 말 걸기가 없어 앞 (1B,15)로 옮겼습니다.
- 문지기 둘은 FC (0F·10,1F)가 아니라 한 블록 바깥 (0E·11,1F)에 섭니다. 인물끼리는 가로 2셀 안으로 다가가지 못해(주인공은 지나감), FC 자리면 전사들이 문지기 줄에서 멈췄습니다.

### 연출

연출 플래그는 `7E:219E` & `04`(번호 `0E`, 원래 태어나는 장면이 켬)입니다. 대체 표 맨 앞에 「`36/01`, 이 비트가 켜졌으면 연출 뒤 목록」을 넣어, 다시 들어오면 연출이 되풀이되지 않고 전사들도 없습니다.

| 인물 | 스크립트 |
| --- | --- |
| 왕 (10,0D) | `3F` 조작 막기, `37` 장 제목 상자, `21` 서술, `37` 맵 밝히기, `21` 대신의 말, `13`·`14` (10,13)으로 걸어 내려옴, `21` 연설, `10` 플래그 켜기, `40` 조작 풀기, `16` |
| 전사 왼쪽 무리 3명 | `09` 플래그 기다림, `13`·`14` (0F,1A) → (0F,23), `28` 숨기기, `16` |
| 전사 오른쪽 무리 3명 | `09`, (11,1A) → (10,1A) → (10,23), `28`, `16` |

- FC 1장 연출(인물 블록 레코드 20)은 대신이 `0301` 을 말하고 왕이 (10,13)으로 내려와 `0302` 를 말합니다. 전사 레코드 12~19 는 이벤트 21 뒤 (0F·10,1A)를 거쳐 출구 (0F·10,23)으로 걸어가 맵에서 빠집니다.
- 스크립트 인물에 이동 간격 0 을 주면 스크립트가 돌지 않았습니다(원본 값 1 을 둠). 전사를 한 줄로 몰면 통로에서 서로 막혀 멈췄고, `1C`(주인공 통과)를 켜면 주인공 옆 전사가 반 셀 어긋난 채 멈췄습니다. 그래서 두 줄로 나누고 오른쪽 무리는 먼저 곧장 내려가 가운데 선 주인공을 지나지 않게 합니다.

### 검은 화면과 장 제목 상자

FC 는 이름 입력 뒤 검은 화면에 금테 상자 「第一章　王宮の戦士たち」를 페이드 인·아웃하고, 검은 화면의 메시지 창에 서술 두 쪽을 쓴 뒤 왕좌의 방을 밝힙니다(MesenCE 헤드리스, 이름 입력을 끝낸 세이브스테이트에서 A 를 50프레임마다 누르며 25프레임마다 찍음). 상자 nametable 은 열 4~29·행 8~13 이고, 테두리 `A1`~`A8`, 바탕 `9A`, 글자는 행 10~11 입니다.

| 단계 | 하는 일 | 근거 |
| --- | --- | --- |
| 맵 불러오기 | `2B:8293` 의 `LDA #$17 / STA $0733` 을 `JSL` 훅으로. 연출 전이면 주화면 층 그림자 `$0733` 과 뒤따르는 `$212C`·`$212D` 를 `04`(BG3 만)로. 맵·인물이 그려지지 않아 바탕색 0(`0000`, 검정)만 남음 | 맵을 불러올 때 `$0733` 을 쓰는 곳은 `2B:8298` 하나였음(481프레임, 낮은 WRAM 거울 뱅크 128개를 모두 감시). 원래 롬도 `29:80BD` 가 같은 값(`04`)으로 창만 남김 |
| 상자(`37`) | 화면을 끄고 NMI 를 막은 채 상자 타일을 BG3 캔버스 타일 `096`~ 에, 타일맵을 버퍼 `7E:5000` 과 VRAM `3C00` 에, 색을 CGRAM 4~11 과 버퍼 `7E:3914` 에 씀. `$1D` 를 1→15·14→0 으로 한 단계 1프레임, 사이 60프레임. 끝나면 타일맵을 빈 칸(`2C00`)으로, 쓴 캔버스 타일을 빈 캔버스(줄마다 `00 FF`)로, 팔레트를 되돌림 | 메시지 창 안쪽이 타일 `096`~`17F` 를 비트맵처럼 씀(VRAM 덤프). 캔버스를 비우지 않으면 서술 창 윗줄에 상자 조각이 남았음. 덮는 팔레트는 스택에 저장함. 맵을 불러올 때의 사본 `7E:3B14` 는 이 자리가 0 이었음 |
| 서술(`21`) | 검은 화면의 메시지 창 | |
| 맵 밝히기(`37`) | 맵 곡을 틀고(`23:FE8F`, `21DF` 를 지움) 지금 곡 `$1D8B` 가 맵 곡이 될 때까지(300프레임까지) 검은 채로 기다린 뒤 `$1D` = 0, `$0733`·`$212C`·`$212D` = `17`, `$1D` 를 1→15 | NMI 는 `$0733` 을 늘 `$212C` 로 쓰지 않음. `$0733` 만 `17` 로 두자 PPU 의 주화면 층이 `04` 그대로였음 |

- 인라인 명령 `37 lo hi bank` 는 네이티브 루틴을 `JSL` 로 부릅니다. 루틴 안에서 `BRK 09 n`(n 프레임 기다림)으로 프레임을 넘기므로 상태 변수가 없습니다.
- 메시지 코드 `1116`(맵 어둡게)은 팔레트 루틴(`03:A6CB`)이라 맵이 반쯤만 어두워져 쓰지 않았습니다.
- 상자 테두리와 바탕은 FC 롬 `1A:$8CB0` 의 1비트 타일을 [FC 그림](../../../fc/dq4/docs/dq4-fcgfx.md)의 평면 규칙으로 풀어 씁니다. 푼 26x6 타일을 FC 화면과 견주니 색 번호마다 한 가지 색이었습니다(0 검정, 1 금색·흰색, 2 파랑, 3 흰색). 테두리 `A1`~`A8` 은 plane 1 이 0 이라 1 이 금색, 바탕·글자 칸은 1·3 이 흰색입니다. SFC 에서는 테두리에 BG3 팔레트 1(`-, 금색, 파랑, 파랑`), 안쪽에 팔레트 2(`-, 흰색, 파랑, 흰색`)를 줍니다. 색 0 은 투명이지만 뒤에 그려지는 층이 없어 바탕색 검정이 보입니다.
- 제목 「제1장   왕궁의 전사들」은 Galmuri11 을 한 점 오른쪽으로 겹쳐 굵게 하고 상자 안 가운데에 둡니다. 그림자는 FC 와 같은 규칙입니다(점 아래 칸이 점이 아니면 검정). 상자 타일은 50장 안팎으로 캔버스 234장 안에 듭니다. 미리보기는 `dq4chapterbox.py preview --out PNG` 입니다.

### 두는 자리

인물 목록은 데이터 뱅크를 목록 뱅크로 두고 낮은 WRAM 을 읽으므로 `30`~`3F` 의 서로 다른 두 뱅크에 둬야 합니다. 통합 롬에서 `30`~`39` 는 타이틀, `3A`~`3C` 는 그룹 연결, `3D`~`3F` 는 환경 맵이 씁니다. 원래 롬에서 빌드하는 `dq4groupbuild.py` 는 새 맵 레코드를 `34:8000` 에 두지만 통합 롬의 `34` 는 타이틀 자료라, 1장 빌드는 `3A:8000` 으로 돌립니다.

| 목록 | 자리 | 크기 | 남은 자리 |
| --- | --- | --- | --- |
| 기본 | `3F:9C00` | 약 21KB | 환경 맵 레코드가 `3F:9B5B` 에서 끝남 |
| 대체·대체 표·루틴 | `39:9000` | 약 26KB | 타이틀 layer-payload 가 `39:8220` 에서 끝남 |

타이틀 빌드는 롬을 2MB 로 늘릴 때 `30`~`3F` 를 원본 `20`~`2F` 의 거울로 채웁니다(`dq4titlelayerpatch.py`). 그래서 패치를 얹을 때 거울 그대로인 바이트는 빈 자리로 보고, 그 밖의 0 아닌 바이트를 덮으면 멈춥니다. 타이틀 자료가 늘어 `39:9000` 에 닿으면 이 검사가 막습니다.

## 맵 곡

FC 는 맵 안에서 그룹 갈래(`$07BA`)로 곡을 고르고(`19:$803B`), 그룹 `02` 는 갈래 `00` → 곡 `03` 「王宮のメヌエット」 하나를 성 안·성 앞 모두에 씁니다([FC 소리 형식의 맵 곡](../../../fc/dq4/docs/dq4-sound-format.md#맵-곡)). 그룹 연결은 그룹 `36` 맵 속성을 DQ5 `03/00`(곡 `0A`, 마을)에서 복사했으므로, `dq4groupbuild.py` 의 `music` 으로 곡 바이트(속성 `+5`)만 `01` 로 바꿉니다. DQ5 곡 자리 `01` 은 원래 성 곡이고, [사운드 포팅](dq4-sound-port-format.md)의 45곡 빌드는 여기에 NDS 「王宮のメヌエット」 를 넣습니다.

| 맵 | 속성(조우 셋·전투 배경·주문 막기·곡) |
| --- | --- |
| DQ5 `03/00` | `FF FF FF 00 02 0A` |
| DQ5 `02/06` | `FF FF FF 00 0A 01` |
| `36/00`~`03` | `FF FF FF 00 02 01` |

### 시작 연출 곡

FC 는 이름 입력부터 상자·서술까지 곡 `1F`(インテルメッツォ)를 틀고, 서술 창이 닫히면 멈췄다가, 왕좌의 방이 밝아질 때 곡 `03`(王宮のメヌエット)을 틉니다. 지금 곡 `$BF >> 1` 의 쓰기를 기록하자 `1F` 가 516프레임에 `00`, 583프레임에 `03` 이 되었습니다(같은 실행의 화면: 상자 약 190~265, 서술 약 290~515, 방이 밝아짐 약 570~590).

DQ5 는 맵을 불러올 때 `00:CE61` 이 곡을 고릅니다(이 롬 458프레임, `01:8E7A` 가 부름). `7E:21DF` bit7 이 켜져 있으면 맵 곡 `$194B` 대신 `21DF & 7F` 를 틉니다(`00:CE71`). 이 값은 이벤트 명령 `C8`(`23:FE80`)이 쓰고 `C9`(`23:FE8F`)가 지웁니다. 곡을 고르는 때가 맵 훅(481프레임)보다 앞이라, 새 게임이 시작 지점 표를 읽은 직후인 `25:834A`(`LDA #$80 / STA $BE`)에 훅을 하나 더 겁니다. 이 훅은 연출 전이면 `21DF` = `80 | 23` 으로 둡니다. 곡 자리 `23` 은 사운드 세트가 NDS インテルメッツォ(`04`)를 넣는 자리입니다. 사운드를 얹지 않은 롬에서는 DQ5 의 `23` 번 곡이 나옵니다.

맵을 밝힐 때 성 곡을 틀면 곡 자료를 SPC 로 보내는 동안 소리가 없습니다. 맵을 불러올 때는 NMI 가 꺼져 있어 요청부터 시작까지 92프레임이었지만, 연출 중에는 더 걸렸습니다. 사운드 세트를 얹은 롬에서 잰 값입니다(`$1D8B` 쓰기, 전원부터).

| 판 | 서술 끝 | 앞 곡 멈춤 | 성 곡 시작 | 화면이 밝아짐 |
| --- | --- | --- | --- | --- |
| 곡을 줄여 끈(`23:FE69`) 뒤 50프레임 쉬고 성 곡 | 약 900 | 951 | 1181 | 950 |
| 바로 성 곡 | 900 | 918 | 1079 | 950 |
| 바로 성 곡, 곡이 시작될 때까지 기다림(지금) | 900 | 918 | 1019 | 1020~1035 |

곡을 줄여 끄면 `1A` 가 곡이 멈추기를 기다려 더 늦었습니다. 그래서 바로 성 곡을 요청하고, 곡이 시작될 때까지 화면을 검게 둡니다. 기다리는 동안은 전송이 101프레임으로 줄었습니다. 서술이 끝나고 밝아지기까지 120프레임으로 FC 의 검은 틈(67프레임)보다 깁니다.

- 이 롬은 새 게임을 고를 때(443프레임) 이름 입력 곡을 멈춥니다(`$1D8B` = `FF`). 그래서 インテルメッツォ 는 FC 와 달리 이름 입력부터가 아니라 왕좌의 방을 불러온 뒤 검은 화면에서 시작합니다.
- 맵 곡 루틴 첫머리의 `21A5` bit6(맵 곡 건너뛰기, `03:C729` 가 켬)은 `01:C2FA` 에서 동료 자리 맞추기(`00:D515`)도 건너뛰게 해서 쓰지 않았습니다.

## 빌드

```sh
export ASAR=/path/to/asar DQ4_GALMURI=/path/to/galmuri
uv run --locked python sfc/dq4/tools/dq4titlelayers.py --out "$PWD/work/ch1/title"
uv run --locked python sfc/dq4/tools/dq4titlelayerpatch.py --rom rom/dq5.sfc --input "$PWD/work/ch1/title" \
  --out "$PWD/work/ch1/title/title.sfc"
uv run --locked python sfc/dq4/tools/dq4overture.py build --nes rom/dq4.nes --rom rom/dq5.sfc \
  --title work/ch1/title/title.sfc --out work/ch1/overture.sfc
uv run --locked python sfc/dq4/tools/dq4chapter1.py messages -o work/ch1/messages.json   # rom/dq5.sfc·rom/dq4.nes 를 읽음
uv run --locked python sfc/dq4/tools/dq4menupatch.py build --rom work/ch1/overture.sfc \
  --messages work/ch1/messages.json --out work/ch1/menu.sfc
uv run --locked python sfc/dq4/tools/dq4chapter1.py build --rom work/ch1/menu.sfc --out work/ch1/dq4-ch1.sfc
uv run --locked python -m unittest discover -s sfc/dq4/tools -p 'test_dq4chapter*.py'
```

`dq4chapter1.py build` 는 `dq4groupbuild.py` 를 돌려 환경·새 맵·출구·입구·가게·여관 패치를 얻고, 그 인물 패치 대신 왕좌의 방을 바꾼 인물 패치(`dq5npcrelocate.py --new-map …`)를 만들어 메뉴 롬 위에 얹습니다. 메뉴 4초, 1장 7초쯤 걸립니다. 그다음 시작 연출 코드(`dq4chapterbox.py`, `rom/dq4.nes` 의 상자 타일과 `DQ4_GALMURI` 의 Galmuri11 을 씀)를 얹고, 새 게임 첫 맵 표를 바꾸고, 체크섬을 맞춥니다. `--keep 폴더` 를 주면 중간 패치 목록을 남깁니다. 소리는 이 롬을 `dq4soundset.py --base` 로 넘겨 얹습니다([사운드 포팅](dq4-sound-port-format.md)).

## 검증

MesenCE 헤드리스로 전원부터 타이틀 A, 메뉴 A, 이름 입력 Y 를 거쳐 확인했습니다.

| 장면 | 결과 |
| --- | --- |
| 새 게임 첫 맵 | `36/01` (32,42), DQ5 로고·배 없음 |
| 연출 | 장 제목 → 대신 → 왕이 (32,26)에서 (32,38)로 걸어옴 → 연설 5쪽. 끝나면 조작이 풀림 |
| 전사 퇴장 | 3,000프레임에 여섯 명 모두 (128,70)(숨김, 출구 줄 y 70) |
| 말 걸기 | 왕 「그대의 활약을 기대하고 / 있노라, (이름)여.」, 대신·남은 전사·학자 한글. 성 앞 7명의 메시지는 롬의 트리로 다시 풀어 한글임을 확인 |
| 출구 | 왕좌의 방 아래 통로 → `36/00` 성문 아래. 성문을 「문」 으로 열고 위로 걸으면 `36/01` 아래 통로. 다시 들어와도 연출 없음 |

## 남은 것

- NDS 리메이크의 서장(산골 마을 지하 훈련장, [NDS 늘어난 내용](../../../nds/dq4/docs/extras.md))은 넣지 않았습니다. 나중에 1장 앞에 더합니다.
- 서술문 한 줄에 들어가는 칸 수(들여쓰기가 없어 14칸보다 넓을 수 있음).
- 이름 입력부터 インテルメッツォ 가 이어지게 하기(지금은 새 게임을 고르면 한 번 멈춤).
- 맵을 밝히기 전 검은 틈(곡 자료를 보내는 약 100프레임)을 FC(67프레임)만큼 줄이기.
- `21DF` 이벤트 곡 자리와 맵 훅 두 개를 다른 장 시작에도 쓸 수 있게 장 번호로 나누기.
- 왕좌의 방 밤 인물(지금은 낮 목록만 바꿔 밤에는 비어 있음).
- 계단 위(왕의 방 `36/02`·`36/03`)와 성 앞 나머지 인물, 상자, 1장 이후 진행(이무르·호이민·보스). 성 앞 인물 가운데 FC 의 예/아니요 대사(따라오겠다는 노인)는 넣지 않았습니다.
- 「조사」 등 DQ5 시스템 메시지와 아직 일본어인 창.
- 덮은 DQ5 마을 대사 `6C6`~`6DB` 와 프롤로그 메시지 `1D1`~`1D3` 을 쓰는 원래 장면은 이제 한글 1장 대사가 나옴(1장 첫머리에서는 가지 않음).
- 인물끼리 가로 2셀 안으로 못 다가가는 조건을 코드로 확인하기(지금은 실측만).
- 연출 플래그 `219E` bit2 를 빌린 것. DQ5 진행 플래그와 겹치지 않는 자리 정하기.
