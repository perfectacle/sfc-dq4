# 읽은 롬 바이트 캐시

헤드리스 장면 검사의 MesenCE 실행 하나를 「그 실행이 실제로 읽은 롬 바이트」 단위로 캐시한다. 롬이 바뀌어도 장면이 읽은 바이트가 그대로면 다시 돌리지 않고 출력 파일을 펼친다. 도구는 `sfc/dq4/tools/dq4readset.py`(캐시), `sfc/dq4/tools/lua/dq4readset.lua`(머리말), `sfc/dq4/tools/dq4readsetcheck.py`(건전성 검사)다.

지금 이 캐시를 쓰는 곳은 창 글자 검사(`dq4windowcheck.py`)의 장면과 출발 상태(서장 시작·서장 걷기·순간이동)다.

## 왜 건전한가

검사 장면은 결정적이다(난수·시각·입력 고정). 실행 한 걸음은 (기계 상태, 그 걸음에 읽은 롬 바이트, 입력)으로 정해진다. 출발 상태와 입력이 같고, 지난 실행이 읽은 오프셋의 바이트가 지금 롬에서도 모두 같으면, 새 롬에서도 같은 주소를 같은 차례로 읽는다. 처음으로 다른 주소를 읽으려면 그 전에 다른 값을 읽었어야 하는데, 그 전 읽기는 모두 기록된 오프셋이고 값이 같다. 그래서 키를 계산하려고 먼저 돌릴 필요가 없다. 지난 실행의 읽은 집합으로 지금 롬을 해시해 견주면 된다.

## 읽은 집합

머리말 Lua 가 장면 스크립트보다 먼저 돌며 다음 셋의 합집합을 `READSET_OUT` 에 「시작 길이」(16진) 줄로 쓴다.

| 출처 | 얻는 법 |
| --- | --- |
| CPU 데이터 읽기, DMA 원본 읽기 | `emu.getAccessCounters(emu.memType.snesPrgRom, emu.counterType.readCount)`. 인자는 메모리 종류가 먼저다 |
| 실행한 명령(오퍼랜드 바이트 포함) | 같은 함수의 `execCount`. 실행 바이트는 readCount 에 잡히지 않는다 |
| Lua 의 `emu.read`·`readWord`·`read16`·`read32` | 카운터에 잡히지 않아 머리말이 감싸 따로 적는다. CPU 주소는 `emu.convertAddress` 로 롬 오프셋으로 바꾼다 |

- 카운터는 롬 파일 오프셋 단위라 LoROM 미러·뱅크를 따로 바꿀 필요가 없다.
- 첫 세이브스테이트를 불러올 때의 카운터를 밑값으로 두고, 그 뒤 늘어난 바이트만 센다. 상태가 기계 전체를 덮으므로 그 전의 읽기는 결과에 남지 않는다. 그보다 먼저 상태를 만든 적이 있으면 밑값을 두지 않는다.
- 장면이 `emu.resetAccessCounters` 를 부르면 지우기 전까지 읽은 것을 쌓아 둔다.
- `emu.stop` 뒤에도 한두 프레임이 더 돌며 스크립트가 기록을 더 쓴다(`dq5warp.lua`). 그래서 멈춘 뒤 프레임마다, 그리고 스크립트가 끝날 때 다시 쓴다.
- `READSET_HDMA` 를 주면 HDMA 가 켜질 때 롬에 있는 표 첫 바이트가 읽은 집합에 들었는지 `.readset.txt.hdma` 에 적는다(건전성 검사용).

## 키

두 단계로 찾는다.

```text
index_key = SHA-256(판, 장면 스크립트 이름, Lua 코드, 에뮬레이터, 환경 변수, 출발 파일, 롬 모양)
work/cache/readset/index/<앞 2자>/<index_key>.json = [항목, …]   최근에 맞은 것부터 8개
항목 = {ranges(읽은 구간, zlib), digest(지금 롬의 그 구간 해시), files(출력 상대 경로 → blob SHA-256), returncode, when}
```

| 키 칸 | 내용 |
| --- | --- |
| Lua 코드 | `tools/lua`·`sfc/dq4/tools/lua`·`sfc/dq5/tools/lua`·`LIBDIR` 의 모든 `.lua`, 장면 스크립트, 머리말. 하나라도 바뀌면 모든 장면이 빗나간다 |
| 에뮬레이터 | MesenCE 실행 파일의 크기·mtime, 명령줄 인자, 고정 인자(`--Snes.RamPowerOnState=AllZeros --Snes.EnableRandomPowerOnState=false`), 사용자 `settings.json` 의 `Snes`·`Emulation` 절 |
| 환경 변수 | 위 Lua 가 `os.getenv` 로 읽는 이름의 값만. 경로는 내용으로 바꾼다: 출력 폴더 안이면 상대 경로, 파일이면 해시(세이브스테이트는 롬 이름을 지운 해시), Lua 폴더면 `code`. `SHOT_DIR`·`READSET_*` 는 뺀다 |
| 출발 파일 | 돌리기 전에 출력 폴더에 있던 파일의 해시 |
| 롬 모양 | 롬 크기와 머리 `$7FD5~$7FD9`(매핑·종류·크기·SRAM·지역). 체크섬 `$7FDC~$7FDF` 는 빌드마다 바뀌고 결과에 닿지 않아 뺀다 |

찾을 때는 `index_key` 의 항목마다 지금 롬을 그 항목의 구간으로 해시해 `digest` 와 같은 첫 항목을 쓴다. 맞으면 `files` 를 출력 폴더에 펼친다. Python 이 출력으로 하는 판정은 캐시하지 않고 매번 돈다. 그래서 판정이 롬을 직접 읽어도 키에 넣지 않아도 된다. 장면 입력을 Python 이 롬에서 만들면(창 검사의 `SET`) 그 값이 환경 변수로 키에 들어간다.

## 세이브스테이트와 배터리 기록

- MesenCE 세이브스테이트 머리에는 띄운 롬 파일 이름이 들어 있다. `dq4mesen.unique_copy` 가 실행마다 이름을 다르게 지으므로 같은 실행이라도 상태 파일이 12바이트 다르다. 상태 해시는 이 이름 칸을 지우고 낸다(`state_hash`). 상태 안에 롬 SHA-1·CRC 는 없다.
- MesenCE 는 롬 파일 이름으로 배터리 기록(`.srm`)을 읽는다. 롬을 같은 이름으로 띄우면 앞 실행의 SRAM 을 읽어 결과가 달라진다. 그래서 캐시 실행은 롬을 복사해 띄우는 `dq4mesen.run` 만 쓰고, 복사하지 않는 `dq4mesen.testrunner` 는 쓰지 않는다. `dq4mesen.clear_saves` 는 그 이름의 `.srm` 과 `Debugger/<이름>.cdl` 을 지운다. `.cdl` 은 롬 크기만 해서 실행마다 쌓이면 디스크를 채운다.

## 환경 변수

| 이름 | 뜻 |
| --- | --- |
| `DQ4_READSET=off` | 캐시를 읽지 않고 모두 돌린다(새 결과는 씀). `tools/guards.py --no-cache` 가 켠다. 배포 관문은 이것으로 돈다 |
| `DQ4_READSET_VERIFY` | 캐시가 맞은 장면 가운데 이 비율(기본 0.05)을 다시 돌려 출력을 견준다. 다르면 그 항목을 지우고 검사를 멈춘다(키에 빠진 입력이 있다는 뜻) |
| `DQ4_READSET_CACHE` | 캐시 뿌리. 기본은 원래 체크아웃 `work/cache/readset`(워크트리끼리 함께 씀) |
| `DQ4_READSET_MAX_GB` | 캐시 상한(기본 20). 넘으면 오래 안 맞은 index 부터 지우고 가리키는 곳이 없는 blob 을 지운다 |

캐시는 `work/` 아래라 커밋되지 않는다. 롬·상태 파생물이므로 커밋하지 않는다(ROM-01).

## 건전성 검사

`dq4readsetcheck.py` 는 가벼운 장면 두 개(전원부터 서장 첫 장면까지, 그 상태에서 버튼을 눌러 걷고 창을 여는 것)마다 다음을 본다. `guards.toml` 의 `dq4-readset-soundness` 다.

- 결정성: 두 번 돌린 출력과 읽은 집합이 같다.
- 밖: 읽은 집합과 머리(`$7FB0~$7FFF`) 밖 바이트를 모두 뒤집은 롬에서도 출력·읽은 집합이 같고, 캐시가 맞는다.
- 안: 읽은 집합 안 바이트 하나를 바꾸면 캐시가 빗나간다.
- HDMA: HDMA 표 첫 바이트가 롬이면 읽은 집합에 들어 있다.

## 맞지 않는 경우

- 모든 장면이 지나는 코드(NMI, 공용 훅, 메인 루프)를 바꾸면 모두 다시 돈다.
- 코드가 자라 루틴 주소가 밀리면, 그 루틴을 부르는 훅의 JSL 오퍼랜드가 바뀐다. 그 훅을 지나는 장면은 모두 빗나간다.
- Lua 파일 하나, MesenCE, 사용자 MesenCE 설정이 바뀌면 모두 빗나간다.

## 남은 것

- libretro(bsnes·snes9x) 장면 검사에는 읽기 훅이 없어 이 캐시를 쓰지 못한다. bsnes 는 소스에서 빌드하므로(`dq4cores.py`) 버스 읽기에 비트맵을 다는 패치가 길이다.
