# DQ4 3장 북쪽 동굴과 금고

[3장 형식 문서](dq4-chapter3-format.md)의 사건 모듈 `dq4ch3safe` 문서입니다. 사건 등록·예약표·검사 틀은 그 문서, 검사 표는 `sfc/dq4/tools/dq4ch3safe_checks.py`, 가드는 `sfc/dq4/guards.d/` 에 있습니다.

## 북쪽 동굴과 금고

`dq4ch3safe`(S). FC 그룹 `3D` 는 `3E/03`~`09`(FC `3D/00`~`06`)입니다.

| 대상 | 값 |
| --- | --- |
| flag | `2202` bit0 물이 빠짐(FC `$62AA`&80), bit1 물음에 대답함, bit2 그 대답이 「예」(bit1·2 는 인물 스크립트가 곧 끔) |
| 인물 | `3E/04` 에 수문 단추 둘, `3E/09` 에 금고를 묻는 보이지 않는 인물(낮·밤). 스크립트는 `10:C8FF` 칸 0·1·4 |
| 대화 | `button`(FC `03B3`), `floor`(FC `0296` 바닥 글 → 「예」 면 `take` 철 금고·`reclose` → `037B`) |
| 사건 물건 | `3E/09` 상자(FC `3D/06` (04,03), 특수 내용 `EE`)가 철 금고 `BC`(`dq4chestport.SPECIAL`) |
| 훅 | `2A:F7AB`(출구 종류 40 갈래), `20:8162`(전멸 금화) |

- **수문 단추**: FC `3D/01` (14,0A)·(08,0E)(1D 이벤트 `26`)에 서면 묻습니다. 「예」 면 주인공을 아래로 걸린 뒤(이벤트 걸음은 벽·물을 지나감) 순간이동합니다. 오른쪽은 계단 바로 위 줄까지 걸어 `3E/03` 의 FC (0A,19) 계단 칸에, 왼쪽은 구덩이 바로 위 줄까지 걸어 bit0 을 켜고 `3E/06` 의 FC (08,0F) 에 섭니다. 「아니요」 면 그 칸을 떠났다가 다시 서야 또 묻습니다(FC `$6289` bit2 와 같음). FC 의 물살 그림과 떨어질 때 화면 흔들기는 없습니다.
- **물 빠진 층**: DQ5 출구 목적지 표 종류 `40`(같은 그룹, 도착 출구 번호)을 읽는 `2A:F7AB`(`LDA $01 / STA $BD / INY / BRA $F7D6`, 7바이트)를 `JSL` 훅 + `BRA $F7D8` 로 바꿉니다. 훅은 `$BD` 와 도착 출구 번호를 원래대로 정한 뒤, 그룹 `3E`·맵 `04` 이고 bit0 이면 맵 `05` 로, 출구 번호 1 이상은 하나 뒤로 바꿉니다(FC `08:$B397`, `3E/05` 에는 (09,09) 계단이 하나 더 있음). 출구 번호는 `2A:F7D6` 의 옵코드(`B1` 또는 출구 표를 옮긴 롬의 `B7`)를 보고 같은 읽기로 얻습니다.
- **금고 되돌리기**: FC 는 연 상자 칸을 しらべる 하면 묻습니다(`1E:$BC62` 의 `EE`, `1E:$B830`). DQ5 しらべる 는 인물 대화를 부르지 않아, 상자를 연 뒤 그 칸을 떠났다가 다시 밟으면 묻습니다. 「예」 면 철 금고를 빼고(`take`, 소지품에 없으면 맡긴 물건에서) 상자 열림 비트를 끕니다. 비트는 `25:FAB0` 과 같은 셈(`chest_maps` 를 훑어 앞 맵들의 상자 수 n, `7E:2210` + n/8 의 `25:FAE9`[n & 7])으로 찾으며 표 뱅크·주소는 `25:FAB5`·`25:FAC4` 의 즉값에서 읽습니다. 열린 상자 그림은 맵에 다시 들어와야 닫힌 그림이 되고, 그 전에도 다시 열 수 있습니다. 바닥 글이 말하는 「돌아갈 길」 을 여는 칸 바꿈은 FC 되돌리기에도 없습니다(되돌린 뒤 바뀌는 것은 `$627D` bit3·상자 열었음 비트·소지품뿐, [FC 상자 실측](../../../fc/dq4/docs/dq4-shop-format.md)).
- **전멸 때 금화**: DQ5 는 전투에서 진 뒤 `20:815C` 의 `BRK 9E` 가 금화를 `$46`~`$48` 에 읽고 `20:8162`~`8170` 이 그 반(잃는 몫)을 `$43`~`$45` 에 둔 다음 `20:8171` 의 `BRK 88` 이 금화에서 뺍니다. 이 15바이트를 `JSL` 훅 + `BRA $8171` 로 바꿔, 3장 flag 가 켜져 있고 일행 기록 0~3(일행 수 `7E:201D` 까지)의 소지품에 철 금고가 있으면 잃는 몫을 0 으로 둡니다. 맡긴 물건의 금고는 치지 않습니다(FC 와 같음). X·Y 는 원래 코드처럼 그대로 둡니다. FC 는 남는 금화를 반으로 내림하고, DQ5 는 잃는 몫을 내림해 남는 쪽이 올림입니다(1001 → 501, 코드 읽기).

FC 실측(`rom/dq4.nes`, 1장 왕좌의 방 상태에서 `$615A` = 2, 금화 1000, HP 1 로 `3D/00` 에서 전멸): 소지품에 `6B` 가 있으면 1000, 맡긴 물건(`$61DB`)에만 있으면 500, 없으면 500. 수문 (14,0A) 「はい」 뒤 `3D/00` (0A,19), (08,0E) 「はい」 뒤 `3D/03` (08,0F)·`$62AA` = `80`, 「いいえ」 면 `$6289` bit2 가 켜진 채 그 칸.

### 구르는 바위

금고 방 `3E/09` 에는 FC 처럼 `3E/07`(FC `3D/04`)의 구르는 바위로 왼쪽 구덩이를 메워야 닿습니다(FC 규칙·실측은 [FC 3장 사건 5b](../../../fc/dq4/docs/dq4-chapter3-format.md#사건-차례)). `dq4boulder`.

| 대상 | 값 |
| --- | --- |
| 바위 | DQ5 미는 바위 그림 `4B` 인물 넷(FC 2×2 칸에 하나씩), 처음 자리 FC (03,05). 낮·밤 목록 끝에 더함 |
| 부리는 인물 | 보이지 않는 인물(빌린 스크립트 `10:C8FF` 칸 6): 맵에 들 때 `reset`, 그 뒤 명령 `05` 로 `ctl` 을 되풀이 |
| 변수 | 변수 칸 `+14`~`+20`: 바위 X·Y(FC 칸), 상태(FC `$629A` 꼴: 아래 2비트 방향, bit5 막힘, bit6 반걸음, bit7 움직임), 메움 비트(bit0 왼쪽·bit1 가운데), 프레임 수, 주인공 FC 칸 |
| 훅 | `00:CE26`(영역 이동 실행기의 층 비교): 그룹 `3E`·맵 `07` 에서 메운 구덩이의 레코드(x0 `06`·`16`)는 옮기지 않음 |

- `ctl` 은 8프레임마다 불려 세 번에 한 번(24프레임) FC 한 차례(`step`, FC `1D:$9CDD`~`$9E2C` 와 같은 규칙)를 돕니다. 막힘은 일행 슬롯 0~(걷는 그림 수 − 1)을, 꺾기는 주인공을 봅니다. 주인공 셀 (X, Y)의 FC 칸은 (X >> 1, (Y − 1) >> 1)입니다.
- 멈춰 있고 처음 자리일 때 주인공이 (03~04,0E)에 서면 풀리고, 바위 아래 막이 블록 (03~04,07~08)을 위 바닥 셀로 덮습니다.
- 자리가 바뀌면 바위 인물마다 셀 차지 비트를 지우고(`00:DEB5`) 인물 표 `3020`·`30E0`·`3080`·`3140` 을 새 셀로 두고 다시 켭니다(`00:DF37`). 걷기 애니메이션 없이 칸째 옮깁니다(FC 도 블록을 다시 그려 칸째 움직임).
- 구덩이(Y `25`)에 닿으면 바위 인물을 치우고 구덩이 셀 4×4 를 네 줄 위 바닥 셀로 덮어 다시 그린 뒤 메움 비트를 켭니다. FC 는 구덩이에 바위 그림을 남기지만 여기서는 바닥으로 보입니다.
- 맵에 다시 들어오면 `reset` 이 처음 상태로 되돌려 구덩이가 다시 열립니다(FC 와 같음). 그래서 금고 방에서 돌아와 위로 걸으면 `3E/08` 로 떨어집니다.
- 바위 그림의 팔레트는 3장 그룹 인물 공용 줄을 그대로 쓰여 초록빛·흰빛으로 보입니다(FC 는 갈색 바위). 남은 것에 둠.

단위 테스트 `test_dq4boulder` 가 FC 실측 궤적 `dq4boulder-fc.tsv`(왼쪽·가운데 구덩이 두 길, 바위가 움직인 차례 178개)를 파이썬 모형과 w65816 로 돌린 `step` 에 넣어 같은 다음 상태가 나오는지, 둘째 일행이 막는 경우, 영역 이동 훅을 봅니다. 걷기 검사 `safe_cave` 묶음은 입구 층에서 순간이동 없이 수문 → `3E/06` → `3E/07` 바위 → 금고 상자 → 돌아와 떨어지기를, `safe_boulder_mid` 는 가운데 구덩이를 걷습니다. 주인공 막기 사례 `safe-boulder-6`·`7`·`8`(셀 X 마다 바위 앞에서 기다렸다 비켜 감)·`safe-boulder-pit`(구덩이 위에서 기다리면 떨어짐)이 있습니다.

### 여신상 동굴의 배

여신상 동굴(`48/02`~`07`, FC `40/00`~`05`)의 배는 FC 처럼 배 칸으로 걸어 들어가 타고, 땅 칸으로 걸으면 내리며 배는 마지막 물 칸에 남습니다(FC 규칙·실측은 [FC 3장 사건 16](../../../fc/dq4/docs/dq4-chapter3-format.md#사건-차례)). `dq4raft`, 코드는 `5D:F000`~ 에 S 의 훅으로 둡니다.

| 대상 | 값 |
| --- | --- |
| 배 | 배 맵 `48/02`·`05`·`06` 의 그림 `A1`(DQ5 세트 `55`, FC 겉모습 22 대역) 인물. 처음 자리 `48/02` FC (16,05)(단추 뒤에는 치움, FC `1C:$A55B`), `48/06` (1D,1B)(주인공 X 가 FC `0E` 로 들면 (0E,09), FC `1C:$A568`). `48/05` 는 탄 채 넘어올 때만 FC (02,1A)의 배를 씀 |
| flag `220A` | bit0 배에 탐(FC `$0515` = 1) |
| 변수 칸 | `+21`·`+22` 배 FC X·Y, `+23` 배 인물 슬롯(`FF` 없음), `+24` 탄 동안 맡긴 주인공 OBJ 속성 바탕(`33A0`) |
| 물 칸 표 | FC 맵의 속성 `83` 칸을 줄마다 (y, x0, x1) 로, 빌드 때 FC 롬에서 만듦 |
| 부리는 인물 | 배 맵마다 보이지 않는 인물(`10:C8FF` 칸 7). 맵에 들 때 `reset`, 그 뒤 명령 `05` 로 `ctl` |

- 이동 판정(`00:AC4D`)은 셀 +1 의 층 비트와 주인공 층 마스크(`7E:31A0`)의 AND 입니다. 이 동굴 맵의 셀 +1 은 `08`·`01`·`11` 뿐입니다(실측). 내린 동안은 배 칸의 셀 2×2 에만 bit0(층 1)을 켜, 주인공(마스크 `01`)이 배 칸에만 들고 배 칸 밖의 물로는 걸을 수 없습니다.
- `ctl` 은 내린 채 주인공 FC 칸이 배 칸이면 탐: 배 칸 bit0 을 끄고 주인공 마스크를 `03` 으로, 그 맵 물 칸 모두에 bit1(층 2)을 켭니다. 인물(마스크 `01`)은 bit1 칸에 들지 못합니다. 탄 동안 배 인물을 주인공 셀로 옮깁니다(차지 비트 없음). 주인공 셀에 bit1 이 없으면(땅) 내림: 마스크 `01`, 물 칸 bit1 을 다 끄고 배 칸에 bit0 을 켭니다. 마스크를 바꿀 때는 주인공 차지 비트를 지웠다가(`00:DEB5`) 새 마스크로 다시 켭니다(`00:DF37`).
- 마스크가 `03` 이면 같은 맵 사람에게 말을 걸어도 「아무도 없다」(`129`)만 떠서(실측) 내린 동안은 늘 `01` 입니다. 탈 수 있는 배 칸은 말 걸기 검사에서 뺍니다(`absent`, 다가서면 탐).
- `48/02` 에서 탄 채 FC x `18`·줄 `0E`·`0F` 에 서면 이벤트로 `48/05` FC (07,y+10)에 옮기고 탄 채 둡니다. 배 맵에 들 때 이 넘어오기가 아니면 탄 flag 를 끄고 배를 처음 자리에 둡니다. 동굴은 `48/02` 로만 들어오므로 탄 채 전멸·リレミト 로 나가도 다음에 들 때 내린 상태입니다.
- 쉬는 배는 우선순위 3 고정(`33A0` = `B0`)이라 물 위에 보입니다. 주인공 OBJ 는 `00:EE9E` 가 `33A0,Y` bit7 이 꺼져 있으면 셀 갈래(`00:EF82`)로 우선순위를 정해 물 칸에서 0 이 되고, OAM 색인이 배보다 앞서 그 화소가 배까지 물 뒤로 가립니다(일행이 있으면 배가 노 조각만 보임, 실측). 그래서 탈 때 주인공 `33A0` 을 `+24` 에 맡기고 `B0` 으로 두어 주인공이 물 위(배 위)에 보이게 하고, 내리면 되돌립니다. 맵에 들면 엔진이 주인공 `33A0` 을 다시 두므로(실측 `00`) 전멸·リレミト·계단으로 나가도 남지 않습니다. 따라 걷는 일행(용병·개)은 FC 처럼(40/00 실측: 칸 1 → 2 → 3 이 배 칸에 드는 차례로 한 걸음마다 하나씩 `$702x` = `81`, 내리면 주인공 걸음 하나마다 칸 1 → 2 차례로 다시 섬) 걷는 줄 칸 1~(`7E:1967` − 1)이 물 칸(셀 +1 bit3: 물 `08`, 땅 `01`·`11`)에 서 있는 동안 안 보이게 비트(`7E:3380` bit7)를 켭니다. `ctl` 이 매 프레임 칸마다 봅니다(`_followers_by_water`).

단위 테스트 `test_dq4raft` 가 물 칸 표(배 처음 자리·넘어가는 두 줄이 물), 코드 자리, w65816 로 돌린 `reset`·`ctl`(배 칸만 표시, 단추 뒤 치움, 탄 flag 지움, 섬 계단 자리, 탄 채 넘어옴, 타면 물 칸 모두, 따라옴과 내림, 넘어가기 이벤트)을 봅니다. 걷기 구간 `raft_entry` 묶음이 입구에서 배를 타고 `48/05` 로 넘어가 내리고, 단추 → `48/04` → `48/06` 배 → 섬 → `48/07` 상자에서 은의 여신상을 받기까지 순간이동 없이 걷습니다. 주인공 막기 `raft-water`·`raft-left-water` 는 배 옆 물 칸으로 밀어도 서 있고, 가드 `dq4-ch3-raft`(`dq4raftcheck.py`)는 탄 채 걸음 전투를 하고 돌아와 물을 지나가는지, 쉬는 배가 단추 전에는 화면에 보이고 단추 뒤에는 치워지는지, 용병·개를 데리고 탈 때 배 다음 칸에서 칸 1 만, 한 칸 더 가면 모두 숨고, 내려서 한 걸음이면 칸 1 만, 두 걸음이면 모두 다시 보이는지(`ride1`·`ride2`·`ride_dog`·`ride_dog1`) 봅니다.

## 남은 것

- 구르는 바위 인물의 팔레트(3장 그룹 인물 공용 줄)와 2×2 한 덩이 그림. 배 그림: FC 의 쉬는 배는 사람 없는 흰 돛·분홍 배(실측 화면)인데 지금은 DQ5 세트 `55`(통에 탄 사람)라, 스프라이트 차례에 뗏목 그림을 새로 그릴 것. 그때 탄 동안의 모양도 FC 처럼 「사람 탄 배」 한 장으로(지금은 물 위의 주인공 아래 배가 조금 보임).
