# DQ4 3장 넘김과 첫머리

[2장 끝](dq4-chapter2-format.md#빈-산트하임과-2장-끝)의 서술 뒤에 3장 「무기상인 톨네코」로 넘어가, 레이크나바 톨네코의 집(그룹 `3E`, FC `16/01`)에서 3장을 시작하는 명세입니다. 도구는 `sfc/dq4/tools/dq4ch3event.py` 이고 `dq4chapter1.py build` 가 얹습니다. 3장 코드와 인물은 모든 빌드에 들어 있고, 2장 끝 인물이 3장으로 넘기는 것은 `--chapter3` 빌드(`dq4build.py --chapter3`, `--chapter2` 를 함께 켬)뿐입니다. 그 밖의 빌드는 2장 끝에서 「제3장 무기상인 톨네코 / ― 다음에 계속 ―」 상자 뒤 타이틀로 돌아갑니다.

| 넣는 것 | 자리 |
| --- | --- |
| 톨네코 기록·이름, 넘김 이벤트, transfer, 방향 키 네이티브 | `5C:C000`~`CFFF`(`dq4ch2slots.CHAPTER3_CODE`) |
| flag | `7E:2208` bit3 3장 진행 중, bit5 첫머리 대기 |
| 장 상자 | `dq4chapterbox.CHAPTER3`(`box3`): 맵 `3E/01`, 첫머리 대기 flag 가 켜져 있을 때 |
| 첫머리 연출 인물 | `3E/01` 의 낮 네네(셀 (54,9)). 스크립트는 DQ5 `2B/00` 인물(`05:CC73` 0번, `05:CC7A`, 80바이트)을 빌림 |
| 주인공 그림 | `05:D9A1` 훅(`dq4ch2event._hero_picture`)에 3장 갈래: 그림 `7A` |
| 아리나 일행 맡긴 칸 | 맡긴 몬스터 칸 50~55(`7E:2846`~), 칸마다 `+1` 부터 25바이트 |
| 한글 대사 | FC `031C`(서두 서술 4쪽), `031E`(네네의 부름), `031F`(네네가 깨움) |
| 사건 모듈 | [사건 등록과 자원 예약](#사건-등록과-자원-예약) |

## 2장 끝에서 옮기기

`dq4ch2ending` 의 끝내는 인물 스크립트(`28 52 3F 37 darken_song 21 end 37 … 16`)의 마지막 `37` 이 `--chapter3` 이면 끝 상자 대신 `transfer` 를 부릅니다. `transfer` 가 하는 일:

1. 일행 기록 0~2(126바이트)와 주인공 이름(8바이트)을 맡긴 칸에 둡니다(`stash_pieces`).
2. 톨네코 기록·이름을 일행 기록 0 과 이름 칸에 씁니다. 맡긴 물건·맡긴 금화를 비우고, 필드 시간 `0050`, 금화 0 으로 둡니다.
3. 귀환 자리를 FC 3장 것(교회 `16/00`, 다녀온 비트 그룹 `16`)으로 둡니다(`dq4fieldtravel.chapter_slot_code`).
4. 일행 수 1, 순서 0, 마차 비트를 끄고, 2장 flag(`2208` bit4)를 끄고 3장 flag 둘을 켭니다.
5. 엔딩 곡을 멈추고(`24:FE91`) 이벤트를 겁니다: 맵 곡 건너뛰기(`dq4ch2event` 의 `skip_song`) 뒤 `90 3E 01 36 0B 01 80`(FC (1B,05)).

3장 동안 산트하임 성 앞마당(`3D/00`)은 2장 끝의 빈 성 목록(`ch2_ending_castle`)이라 끝내는 인물이 다시 서지 않습니다.

## 톨네코

| 기록 | 값 |
| --- | --- |
| HP·MP·すばやさ·ちから·みのまもり(FC たいりょく)·かしこさ·うんのよさ | FC 3장 시작 값(`dq4growth.first_record`): 20, 0, 5, 4, 10, 5, 3 |
| 다음 레벨 경험치 | 10 |
| 물건 | FC 소지품 표(`12:$9192` + 8 × 5)에서 DQ5 에 같은 이름이 있는 것: ぬののふく(DQ5 `42`, 장비) |

- 성장 표는 `dq4growth.TABLES` 다섯째(사람 0, 3장 flag)입니다. 표 다섯이 `57:D000`~`EFFF` 에 들어가지 않아 `57:9000` 으로 옮겼습니다(`dq4growth.GROWTH_AT`, 끝 `57:CE00` 은 장비 표).
- 장비 판정은 `dq4party.EQUIP_PEOPLE` 의 사람 0 둘째 줄(3장 flag → FC 장비 비트 5)입니다.
- 걷는 그림은 NDS 시트 `h118` 을 DQ4 가 쓰지 않는 그림 `7A`(세트 `46`)에 싣고, 팔레트 줄 7 을 3장 flag 로 3장 그룹(`3E`~`40`)과 필드에서 덮습니다(`dq4people`).
- 필드 곡은 3장 flag 가 켜져 있으면 `02` → `0E` 입니다(`dq4sound-game.args` 의 `--song-pick`).

## 사건 등록과 자원 예약

3장 사건은 모듈 파일 하나로 꽂습니다. 모듈 이름과 쓸 자원은 `sfc/dq4/tools/dq4ch3slots.py` 의 `SLOTS`(정본)에 미리 나눴고, `dq4ch3event.EVENTS` 는 `SLOTS` 차례대로 **파일이 있는** 모듈입니다. 그래서 사건 PR 은 등록 줄을 고치지 않고 파일을 더하기만 합니다. 메시지·대화·대화 호출 번호는 등록 차례로 이어 매기므로 코드에 번호를 적지 않습니다. 빌드는 모듈이 몫 밖의 flag·전투 무리·DQ5 몬스터를 적거나, 네이티브가 코드 자리를 넘거나, 새 목록 이름이 앞머리로 시작하지 않으면 멈춥니다.

### 모듈 하나를 더하는 법

1. `sfc/dq4/tools/<SLOTS 의 module>.py` 를 만듭니다. 쓰는 flag 를 `FLAGS` 에 적고, 아래 표에서 필요한 것만 둡니다.
2. 자원이 모자라면 `dq4ch3slots.py` 의 자기 줄만 고칩니다(예비 `SPARE` 에서 가져옴).
3. 이 문서의 자기 절(아래 「레이크나바」~「마을 사람」)에 인터페이스를 적고, `sfc/dq4/guards.toml` 에 `dq4-ch3-<이름>` 검사를 더합니다.

### 모듈이 내놓는 것

[2장 사건 모듈](dq4-chapter2-format.md#모듈이-내놓는-것)과 같은 이름(`FLAGS`, `MESSAGES`, `TALKS`·`talk_scripts(ctx)`, `scripts(ctx)`, `npc_lists(lists, ctx)`, `native(ctx)`, `hooks(ctx)`, `events(ctx)`, `start_messages(ctx)`, `state_messages(ctx)`, `BATTLES`, `MONSTERS`·`monster_doc(prg)`, `DATA_ENTRIES`·`CODE_ENTRIES`)에 하나를 더합니다.

| 이름 | 꼴 | 빌드가 하는 일 |
| --- | --- | --- |
| `CALLS` | `{이름: (장치 또는 자기 네이티브 이름, 인자 바이트)}` | 대화 호출 표에 칸을 더함. 대화 스크립트에서 `ctx.call(이름)` |

`ctx`(`dq4ch3event.Context`)는 2장 것에 더해 `ctx.calls`(`{이름: 표 칸}`), `ctx.vars_at`(자기 변수 칸 첫 주소)와 대화 명령 도우미 `ctx.say(메시지 이름)`, `ctx.call(이름)`, `ctx.flag_on(flag)`, `ctx.when(조건, 그러면, 아니면)`, 조건 `ctx.flag(flag)`·`ctx.has(물건)`(조건 `11`, 맡긴 물건은 보지 않음)·`ctx.paid()`, 목록 도우미 `ctx.retalk(lists, 맵, 셀, 대화, 시간대)` 를 줍니다. 대사는 `dq4chapter1.say`·`speak`·`narrate`, 이름을 쪽마다 다는 말은 `dq4ch2event._speaker_pages` 를 씁니다. `BATTLES` 는 `stub` 을 받지 않습니다(아래 「대화 호출」).

- flag 바이트는 2장 예비로 남았던 13바이트 전부입니다([flag 자리](dq4-chapter2-format.md#flag-자리)의 근거 그대로). FC 3장 진행 비트는 약 37개(`$627D`~`$628E`·`$62AA`, [FC 3장](../../../fc/dq4/docs/dq4-chapter3-format.md))라 모듈 몫 9바이트(72비트)에 들어갑니다. `2208` 은 여덟 비트를 모두 씁니다.
- 변수 칸은 조건으로 볼 일이 없는 값(날수·일삯·재고·납품 수·네네 매상)을 둡니다. 맡긴 몬스터 칸 49번(`7E:282C`)의 `+1`~`+25`(`7E:282D`~`2845`)이고, 저장 기록(`7E:2000`~`2A9F`) 안입니다. 칸 첫 바이트는 찬 칸 표시라 쓰지 않습니다. 몬스터를 맡기지 않는 이 해킹에서 칸은 앞에서부터 차고, 3장 넘김이 50~55 를 씁니다.
- 공용 flag `21FF`: bit0 마지막 대화 호출의 결과(`RESULT`), bit1 개 토마스가 따라옴(`DOG`), bit2·bit3 스콧·로렌스를 고용함(`SCOTT`·`LAWRENCE`). 공용 변수: `+0`·`+1` 용병 날수, `+2` 시계.
- 이벤트 무리·DQ5 몬스터는 FC 3장 사건에 전투가 없어 나누지 않았습니다(2장 예비 `37`~`3A`·`C5` 등 그대로).
- 빌릴 인물 스크립트는 이 해킹이 가지 않는 DQ5 맵의 목록에서 스크립트가 있고 한 시간대에만 놓이는 칸입니다. 낮·밤 두 벌 레코드는 `dq5npcrelocate` 가 받지 않습니다.

#### 메시지 자리

덧붙인 메시지 색인(`59:8000`, 16개마다 3바이트)은 21비트 주소라 `24:9E07` 이 뱅크에 `60` 을 OR 해 `60`~`7F` 만 가리킵니다. 그 뱅크들은 메뉴·곡 자료가 차지해 위 끝자리만 남았습니다(이 장치를 넣은 뒤 약 5.1KB).

| 어림 | 값 | 근거 |
| --- | --- | --- |
| 한글 글자 코드 하나 | 약 1.07바이트 | 견본 메시지 둘(코드 191개)을 넣자 셋째 자리가 205바이트 늘었음 |
| 2장 사건 메시지 | 132개, 코드 6,148개(약 6.6KB), 한 개에 약 50바이트 | 동료 대화 뺀 E1~E5 모듈 |
| 3장 사건 메시지 | FC 약 200개 → 약 10KB | FC 3장 사건·무기점·용병·굴 메시지 번호(FC 3장 문서) × 2장 실적 |
| 3장 마을 사람 | 옮긴 인물 메시지 115개 가운데 일본어 임시 111개(코드 5,701개) | 한글로 바꾸면 글자 수가 줄어 대략 비슷할 것(재지 않음) |

남은 자리로는 레이크나바(무기점 일·손님·톰 노인·네네, 약 55개)와 금고 정도가 들어갑니다. 늘리는 길은 셋입니다.

- 색인 뱅크 돌리기: `24:9E07` 의 `ORA #$60` 뒤에 `7E`·`7F` 를 빈 뱅크(`55`·`56`)로 바꾸는 변환을 더하고, `dq4menumsg.index_entry`·`place` 가 그 뱅크를 `7E`·`7F` 로 적습니다(64KB). 롬에서 메시지를 다시 읽는 sfc/dq5 의 `dq5textwrite.relocated`(훅 바이트 `20 8D 8C A5 F2 09 xx 85 F2 60` 만 받음)·`index_table`·`decode_check`(뱅크 OR 값으로 풂)와 그 시험(`test_dq5textwrite` 의 훅 바이트)을 dq5 트랙이 함께 고쳐야 합니다. `dq4romledgercheck` 가 `base_package` 로 롬 메시지를 풀기 때문입니다.
- DQ5 원래 메시지 비우기: 0~3199 가운데 DQ5 인물 대화 스크립트(대화 번호 `011` 이상)만 부르는 메시지는 이 해킹이 가지 않는 DQ5 맵의 것입니다. 그런 대화가 부르는 메시지는 1,257개(3,200 의 39%)입니다. 엔진 코드가 번호로 부르는 메시지·시설 대화(`000`~`010`, 30개)와 겹치는 것을 가려야 하고, 얻는 양은 재지 않았습니다(평균 길이로 수십 KB 어림).
- dq4 쪽만으로: 9E07 훅은 그대로 두고 `24:8BD7` 의 `JSR` 대상과 `24:8BC3` 의 색인 읽기를 dq4 훅으로 돌려, 어떤 번호 이상은 둘째 색인(다른 OR 값)에서 읽게 합니다. dq5 검사가 보는 첫 색인과 9E07 바이트는 그대로라 dq5 파일을 고치지 않지만, 둘째 색인 뒤 메시지는 `base_package` 가 보지 않으므로 dq4 쪽 풀이 검사를 따로 둬야 합니다(코드 읽기로만 가늠, 뱅크 24 빈 자리 미확인).

## 대화 호출

대화 스크립트의 `call` 은 뱅크 06 주소만 받습니다. 2장은 칸마다 입구를 두었고([사건 전투](dq4-chapter2-format.md#사건-전투), 다섯 칸 모두 씀), 3장은 입구 하나에 `call` 의 인자(`01 lo hi a b`, `06:B143` 이 `7E:0F30`·`0F31` 에 둠)로 표 칸을 고릅니다.

```
06:FE00  PHP / REP #$30 / PHA / PHX / PHY / JSL dispatch / PLY / PLX / PLA / PLP / RTS
dispatch PHP / REP #$30 / LDA $7E0F30 / AND #$00FF / ASL / ASL / TAX / PLP
         SEP #$20 / LDA 표+3,X / STA $7E0F31 / LDA 표+2,X / PHA / REP #$20 / LDA 표,X / DEC / PHA / RTL
표 5C:CC00 + 4k  주소(3) · 인자(1)
```

대화 명령은 `01 00 FE k 01` 입니다. 스크립트를 건너뛰는 `06:AFA9` 가 `00` 을 세 바이트로 세어 칸 번호 `k` 를 삼키고 끝의 `01` 을 한 바이트로 세므로, 칸 번호가 어떤 값이어도 경계가 맞습니다. 불린 루틴은 `7E:0F31` 에서 인자를 읽고 `RTL` 로 입구에 돌아옵니다.

FC 3장에는 대화로 시작하는 전투가 없습니다(용병은 동행, 떠돌이 상인은 걸음 조우). 그래서 2장의 대화 전투 입구(`06:FF81`+9k)는 늘리지 않았습니다. 3장 사건이 전투를 걸면 네이티브에서 `dq4ch2battle.far(무리)` 를 씁니다.

## 검증

가드 `dq4-ch3-open`(`dq4ch3opencheck.py`)이 2장 걷기 검사의 2장 출발 상태에서 우승 뒤 빈 왕좌의 방으로 가 계단으로 성 앞마당에 내려선 뒤, A 와 아래를 번갈아 눌러 3장 첫머리를 넘깁니다. 끝에 맵 `3E/01`, 3장 flag 켜짐, 2장 flag·첫머리 대기 꺼짐, 일행 수 1, 금화 0, 주인공 기록(HP 20·ちから 4·みのまもり 10)과 이름 첫 바이트, 물건 칸 1 의 도시락, 맡긴 칸의 아리나 HP 16, 변수 칸 첫·끝 바이트 0 을 봅니다. 이어 시작 칸에서 위의 네네에게 말을 걸어 도시락이 그대로이고 `2200` bit0 이 꺼져 있는지, 물건 칸 1 을 비운 뒤 다시 걸어 도시락을 받고 그 flag 가 켜지는지 봅니다.

단위 테스트 `test_dq4ch3slots` 는 예약표(몫끼리·2장 몫과 겹침, flag 자리, 변수 칸, 빌릴 목록, 앞머리, DQ5 가 예약 flag 를 쓰지 않음)와 등록 장치(가짜 모듈 둘의 메시지·대화·호출 번호, 몫 밖 flag·모르는 금화·장치·목록 이름에서 멈춤, 호출 명령이 모든 칸 번호에서 5바이트로 건너뛰어짐)를 봅니다.
