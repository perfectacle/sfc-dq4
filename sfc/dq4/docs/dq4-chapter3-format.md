# DQ4 3장 넘김과 첫머리

[2장 끝](dq4-chapter2-ending-format.md#빈-산트하임과-2장-끝)의 서술 뒤에 3장 「무기상인 톨네코」로 넘어가, 레이크나바 톨네코의 집(그룹 `3E`, FC `16/01`)에서 3장을 시작하는 명세입니다. 도구는 `sfc/dq4/tools/dq4ch3event.py` 이고 `dq4chapter1.py build` 가 얹습니다. 3장 코드와 인물은 모든 빌드에 들어 있고, 2장 끝 인물이 3장으로 넘기는 것은 `--chapter3` 빌드(`dq4build.py --chapter3`, `--chapter2` 를 함께 켬)뿐입니다. 그 밖의 빌드는 2장 끝에서 「제3장 무기상인 톨네코 / ― 다음에 계속 ―」 상자 뒤 타이틀로 돌아갑니다.

| 넣는 것 | 자리 |
| --- | --- |
| 톨네코 기록·이름, 넘김 이벤트, transfer, 방향 키 네이티브 | `5C:C000`~`CFFF`(`dq4ch2slots.CHAPTER3_CODE`) |
| flag | `7E:2208` bit3 3장 진행 중, bit5 첫머리 대기 |
| 장 상자 | `dq4chapterbox.CHAPTER3`(`box3`): 맵 `3E/01`, 첫머리 대기 flag 가 켜져 있을 때 |
| 첫머리 연출 인물 | `3E/01` 의 낮 네네(셀 (54,9)). 스크립트는 DQ5 `2B/00` 인물(`05:CC73` 0번, `05:CC7A`, 80바이트)을 빌림 |
| 주인공 그림 | `05:D9A1` 훅(`dq4ch2event._hero_picture`)에 3장 갈래: 그림 `7A` |
| 아리나 일행 맡긴 칸 | 맡긴 몬스터 칸 50~55(`7E:2846`~), 칸마다 `+1` 부터 25바이트 |
| 한글 대사 | FC `031C`(서두 서술 4쪽), `031E`(네네의 부름), `031F`(네네가 깨움) |
| 사건 모듈 | [사건 등록과 자원 예약](#사건-등록과-자원-예약) |

## 2장 끝에서 옮기기

`dq4ch2ending` 의 끝내는 인물 스크립트(`28 52 3F 37 darken_song 21 end 37 … 16`)의 마지막 `37` 이 `--chapter3` 이면 끝 상자 대신 `transfer` 를 부릅니다. `transfer` 가 하는 일:

1. 일행 기록 0~2(126바이트)와 주인공 이름(8바이트)을 맡긴 칸에 둡니다(`stash_pieces`).
2. 톨네코 기록·이름을 일행 기록 0 과 이름 칸에 씁니다. 맡긴 물건·맡긴 금화를 비우고, 필드 시간 `0050`, 금화 0 으로 둡니다.
3. 귀환 자리를 FC 3장 것(교회 `16/00`, 다녀온 비트 그룹 `16`)으로 둡니다(`dq4fieldtravel.chapter_slot_code`).
4. 일행 수 1, 순서 0, 마차 비트를 끄고, 2장 flag(`2208` bit4)를 끄고 3장 flag 둘을 켭니다.
5. 엔딩 곡을 멈추고(`24:FE91`) 이벤트를 겁니다: 맵 곡 건너뛰기(`dq4ch2event` 의 `skip_song`) 뒤 `90 3E 01 36 0B 01 80`(FC (1B,05)).

3장 동안 산트하임 성 앞마당(`3D/00`)은 2장 끝의 빈 성 목록(`ch2_ending_castle`)이라 끝내는 인물이 다시 서지 않습니다.

## 톨네코

| 기록 | 값 |
| --- | --- |
| HP·MP·すばやさ·ちから·みのまもり(FC たいりょく)·かしこさ·うんのよさ | FC 3장 시작 값(`dq4growth.first_record`): 20, 0, 5, 4, 10, 5, 3 |
| 다음 레벨 경험치 | 10 |
| 물건 | FC 소지품 표(`12:$9192` + 8 × 5)에서 DQ5 에 같은 이름이 있는 것: ぬののふく(DQ5 `42`, 장비) |

- 성장 표는 `dq4growth.TABLES` 다섯째(사람 0, 3장 flag)입니다. 표 다섯이 `57:D000`~`EFFF` 에 들어가지 않아 `57:9000` 으로 옮겼습니다(`dq4growth.GROWTH_AT`, 끝 `57:CE00` 은 장비 표).
- 장비 판정은 `dq4party.EQUIP_PEOPLE` 의 사람 0 둘째 줄(3장 flag → FC 장비 비트 5)입니다.
- 걷는 그림은 NDS 시트 `h118` 을 DQ4 가 쓰지 않는 그림 `7A`(세트 `46`)에 싣고, 팔레트 줄 7 을 3장 flag 로 3장 그룹(`3E`~`40`)과 필드에서 덮습니다(`dq4people`).
- 필드 곡은 3장 flag 가 켜져 있으면 `02` → `0E` 입니다(`dq4sound-game.args` 의 `--song-pick`).

## 사건 등록과 자원 예약

3장 사건은 모듈 파일 하나로 꽂습니다. 모듈 이름과 쓸 자원은 `sfc/dq4/tools/dq4ch3slots.py` 의 `SLOTS`(정본)에 미리 나눴고, `dq4ch3event.EVENTS` 는 `SLOTS` 차례대로 **파일이 있는** 모듈입니다. 그래서 사건 PR 은 등록 줄을 고치지 않고 파일을 더하기만 합니다. 메시지·대화·대화 호출 번호는 등록 차례로 이어 매기므로 코드에 번호를 적지 않습니다. 빌드는 모듈이 몫 밖의 flag·전투 무리·DQ5 몬스터를 적거나, 네이티브가 코드 자리를 넘거나, 새 목록 이름이 앞머리로 시작하지 않으면 멈춥니다.

### 모듈 하나를 더하는 법

1. `sfc/dq4/tools/<SLOTS 의 module>.py` 를 만듭니다. 쓰는 flag 를 `FLAGS` 에 적고, 아래 표에서 필요한 것만 둡니다.
2. 자원이 모자라면 `dq4ch3slots.py` 의 자기 줄만 고칩니다(예비 `SPARE` 에서 가져옴).
3. 자기 모듈 문서 `docs/dq4-chapter3-<이름>-format.md`(아래 「사건 모듈 문서」)에 인터페이스·검사 구간·「남은 것」 을 적고, 자기 조각 `sfc/dq4/guards.d/ch3-<이름>.toml` 에 `dq4-ch3-<이름>` 검사를 둡니다. 모듈 파일은 다른 검사들이 `"@ch3-modules"` 묶음으로 이미 잡으므로 그 검사들의 `paths` 는 고치지 않습니다. 걷기·주인공 막기 표는 옆 `<module>_checks.py` 에 둡니다(아래 「검사」).

### 모듈이 내놓는 것

[2장 사건 모듈](dq4-chapter2-format.md#모듈이-내놓는-것)과 같은 이름(`FLAGS`, `MESSAGES`, `TALKS`·`talk_scripts(ctx)`, `scripts(ctx)`, `npc_lists(lists, ctx)`, `native(ctx)`, `hooks(ctx)`, `events(ctx)`, `start_messages(ctx)`, `state_messages(ctx)`, `BATTLES`, `MONSTERS`·`monster_doc(prg)`, `DATA_ENTRIES`·`CODE_ENTRIES`)에 하나를 더합니다.

| 이름 | 꼴 | 빌드가 하는 일 |
| --- | --- | --- |
| `CALLS` | `{이름: (장치 또는 자기 네이티브 이름, 인자 바이트)}` | 대화 호출 표에 칸을 더함. 대화 스크립트에서 `ctx.call(이름)` |
| `absent(ctx)` | `{(맵, DQ5 셀 x, y, 밤)}` | 처음 상태 목록에서 빼거나 처음에 숨는 인물. `dq4ch3event.absent()` 로 모아 npccheck 가 말 걸지 않음 |

`ctx`(`dq4ch3event.Context`)는 2장 것에 더해 `ctx.calls`(`{이름: 표 칸}`), `ctx.vars_at`(자기 변수 칸 첫 주소)와 대화 명령 도우미 `ctx.say(메시지 이름)`, `ctx.call(이름)`, `ctx.flag_on(flag)`, `ctx.when(조건, 그러면, 아니면)`, 조건 `ctx.flag(flag)`·`ctx.has(물건)`(조건 `11`, 맡긴 물건은 보지 않음)·`ctx.paid()`, 목록 도우미 `ctx.retalk(lists, 맵, 셀, 대화, 시간대)` 를 줍니다. 대사는 `dq4chapter1.say`·`speak`·`narrate`, 이름을 쪽마다 다는 말은 `dq4ch2event._speaker_pages` 를 씁니다. `BATTLES` 는 `stub` 을 받지 않습니다(아래 「대화 호출」).

- flag 바이트는 2장 예비로 남았던 13바이트 전부입니다([flag 자리](dq4-chapter2-format.md#flag-자리)의 근거 그대로). FC 3장 진행 비트는 약 37개(`$627D`~`$628E`·`$62AA`, [FC 3장](../../../fc/dq4/docs/dq4-chapter3-format.md))라 모듈 몫 9바이트(72비트)에 들어갑니다. `2208` 은 여덟 비트를 모두 씁니다.
- 변수 칸은 조건으로 볼 일이 없는 값(날수·일삯·재고·납품 수·네네 매상)을 둡니다. 맡긴 몬스터 칸 49번(`7E:282C`)의 `+1`~`+25`(`7E:282D`~`2845`)이고, 저장 기록(`7E:2000`~`2A9F`) 안입니다. 칸 첫 바이트는 찬 칸 표시라 쓰지 않습니다. 몬스터를 맡기지 않는 이 해킹에서 칸은 앞에서부터 차고, 3장 넘김이 50~55 를 씁니다.
- 둘째 변수 칸은 같은 꼴로 맡긴 몬스터 칸 48번의 `+1`~`+25`(`7E:2813`~`282B`)입니다. 3장 출발 상태에서 0 이었습니다(헤드리스).
- 뱅크 `4E` 는 `4E:8000`~`BFFF` 가 3장 몬스터·떠돌이 상인(`dq4fieldencounter.CH3_CODE_AT`, `dq4ch3slots.MONSTERS_CODE`), `C000`~`CFFF` 가 엔돌, 나머지가 예비입니다. 거기 코드는 `JSL`·`RTL` 로 부릅니다. BRK 처리기는 BRK 가 놓인 뱅크를 DB 로 두어, `4E` 에서 BRK 를 바로 쓰면 낮은 WRAM 대신 롬을 읽습니다(실측: `BRK 95 34` 가 `04:DADA` 에서 끝없이 돎). 그래서 낮은 뱅크의 받침(`BRK …` / `RTL`, `dq4ch3slots.LOW_STUBS`)으로 부릅니다. `29:FF80`~ 는 원래 롬 빈 자리(`dq5build free`) 가운데 아무 도구도 쓰지 않던 곳입니다.
- 공용 flag `21FF`: bit0 마지막 대화 호출의 결과(`RESULT`), bit1 개 토마스가 따라옴(`DOG`), bit2·bit3 스콧·로렌스를 고용함(`SCOTT`·`LAWRENCE`). 공용 변수: `+0`·`+1` 용병 날수, `+2` 시계.
- 이벤트 무리·DQ5 몬스터는 FC 3장 사건에 전투가 없어 나누지 않았습니다(2장 예비 `37`~`3A`·`C5` 등 그대로).
- 빌릴 인물 스크립트는 이 해킹이 가지 않는 DQ5 맵의 목록에서 스크립트가 있고 한 시간대에만 놓이는 칸입니다. 낮·밤 두 벌 레코드는 `dq5npcrelocate` 가 받지 않습니다.

자리가 넘치면 메뉴 단계가 `메시지가 자리를 넘음: 메시지 N 부터 B바이트가 들어갈 곳이 없음(메시지 …바이트, 자리 …바이트, …)` 으로 멈춥니다. 메시지가 `55` 끝에서 `56` 으로 걸치기 시작하면 롬 장부 허용(`ledger-allow.toml`)에 `55:8000~56:FFFF` 의 `[[cross]]` 를 더합니다. 넷째 자리까지 차면 DQ5 원래 메시지 가운데 이 해킹이 가지 않는 맵의 대화만 부르는 것(0~3199 의 39%, 1,257개)을 비우는 길이 남습니다(엔진이 번호로 부르는 메시지·시설 대화와 겹치는 것을 가려야 함).

## 대화 호출

대화 스크립트의 `call` 은 뱅크 06 주소만 받습니다. 2장은 칸마다 입구를 두었고([사건 전투](dq4-chapter2-format.md#사건-전투), 다섯 칸 모두 씀), 3장은 입구 하나에 `call` 의 인자(`01 lo hi a b`, `06:B143` 이 `7E:0F30`·`0F31` 에 둠)로 표 칸을 고릅니다.

```
06:FE00  PHP / REP #$30 / PHA / PHX / PHY / JSL dispatch / PLY / PLX / PLA / PLP / RTS
dispatch PHP / REP #$30 / LDA $7E0F30 / AND #$00FF / ASL / ASL / TAX / PLP
         SEP #$20 / LDA 표+3,X / STA $7E0F31 / LDA 표+2,X / PHA / REP #$20 / LDA 표,X / DEC / PHA / RTL
표 5C:CC00 + 4k  주소(3) · 인자(1)
```

대화 명령은 `01 00 FE k 01` 입니다. 스크립트를 건너뛰는 `06:AFA9` 가 `00` 을 세 바이트로 세어 칸 번호 `k` 를 삼키고 끝의 `01` 을 한 바이트로 세므로, 칸 번호가 어떤 값이어도 경계가 맞습니다. 불린 루틴은 `7E:0F31` 에서 인자를 읽고 `RTL` 로 입구에 돌아옵니다.

FC 3장에는 대화로 시작하는 전투가 없습니다(용병은 동행, 떠돌이 상인은 걸음 조우). 그래서 2장의 대화 전투 입구(`06:FF81`+9k)는 늘리지 않았습니다. 3장 사건이 전투를 걸면 네이티브에서 `dq4ch2battle.far(무리)` 를 씁니다.

### 사건 모듈 PR 이 고치는 파일

사건 모듈 하나를 더하거나 고치는 PR 은 자기 파일만 고칩니다. 그래야 같은 장의 사건 PR 이 동시에 올라와도 서로 충돌하지 않습니다.

| 파일 | 내용 |
| --- | --- |
| `sfc/dq4/tools/dq4ch<장><이름>.py` | 사건 모듈. 자원은 그 장 예약표(`dq4ch3slots.SLOTS`)의 자기 줄 |
| `sfc/dq4/tools/dq4ch<장><이름>_checks.py` | 걷기 flag·구간, 기록 효과, 주인공 막기 사례, `PASS_NO_DEVICE`·`WALK_EXEMPT`(꼴은 `dq4eventchecks` 머리말) |

| `sfc/dq4/docs/dq4-chapter<장>-<이름>-format.md` | 인터페이스, 검사 구간과 사례, 「남은 것」 |

새 장(4장부터)은 장 틀 PR 한 번에 장 공용 파일을 만듭니다: 예약표·등록(`dq4ch4slots`·`dq4ch4event`), 모으는 곳 `dq4ch4checks.py`(`dq4eventchecks` 를 그 장 등록 차례로 부름), 장 걷기 검사, `guards.d/ch4.toml`(장 단위 가드와 `ch3-modules` 꼴의 묶음 `ch4-modules`), `dq4guardpaths` 의 `REGISTRIES`·`LISTED_GROUPS` 한 줄씩, 이 꼴의 장 형식 문서와 「사건 모듈 문서」 색인(예약표의 모듈마다 줄 하나를 빈 줄로 띄워 미리 두고, 모듈 PR 은 문서가 생길 때 자기 줄만 링크로 바꿈). 그 뒤 모듈 PR 은 위 표의 파일만 고칩니다. 장 걷기 검사의 고정 차례(`SEGMENT_ORDER`·`FLAG_ORDER`)는 나누기 전 표를 지키려는 것이라 새 장에는 두지 않고, 표는 등록 차례로 잇습니다.

## 검증

가드 `dq4-ch3-open`(`dq4ch3opencheck.py`)이 2장 걷기 검사의 2장 출발 상태에서 우승 뒤 빈 왕좌의 방으로 가 계단으로 성 앞마당에 내려선 뒤, A 와 아래를 번갈아 눌러 3장 첫머리를 넘깁니다. 끝에 맵 `3E/01`, 3장 flag 켜짐, 2장 flag·첫머리 대기 꺼짐, 일행 수 1, 금화 0, 주인공 기록(HP 20·ちから 4·みのまもり 10)과 이름 첫 바이트, 물건 칸 1 의 도시락, 맡긴 칸의 아리나 HP 16, 변수 칸 첫·끝 바이트 0 을 봅니다. 이어 시작 칸에서 위의 네네에게 말을 걸어 첫머리 직후 말(080A)뿐이라 도시락이 그대로이고 `2200` bit0 이 꺼져 있는지, `FRESH` 를 지우고 물건 칸 1 을 비운 뒤 다시 걸어 잠 → 아침 → 도시락을 받고 그 flag 가 켜지는지 봅니다. 공용 장치 시험은 대화 호출 표 칸 0(레이크나바의 잠)을 바꿔 같은 네네 대화(080B·080C 뒤)로 부릅니다.

단위 테스트 `test_dq4ch3slots` 는 예약표(몫끼리·2장 몫과 겹침, flag 자리, 변수 칸, 빌릴 목록, 앞머리, DQ5 가 예약 flag 를 쓰지 않음)와 등록 장치(가짜 모듈 둘의 메시지·대화·호출 번호, 몫 밖 flag·모르는 금화·장치·목록 이름에서 멈춤, 호출 명령이 모든 칸 번호에서 5바이트로 건너뛰어짐)를 봅니다.

## 검사

3장 사건이 늘 때마다 아래 검사에 그 사건의 구간·사례를 붙입니다. 모두 `dq4build.py --chapter3` 롬으로 돌고, 난수·시각·조우를 묶어 같은 입력이면 같은 기록을 냅니다([2장 검사](dq4-chapter2-format.md#검사에-구간-붙이기)와 같은 틀). 가드는 `dq4-ch3-*` 이고, 장 단위 검사는 [`guards.d/ch3.toml`](../guards.d/ch3.toml), 사건 모듈마다의 검사는 `guards.d/ch3-<모듈>.toml` 조각에 둡니다. 빌드가 모듈을 이름으로 들여(importlib) import 길로는 닿지 않으므로, `dq4-ch3-*` 와 3장 모듈이 싣는 롬 내용을 보는 검사(`dq4guardpaths.CH3_CONTENT_CHECKS`: 인물 그림·사건 중 팔레트 줄·줄바꿈 루틴·메시지 뱅크·롬 장부), `paths` 에 `"@ch3-modules"`(`guards.d/ch3.toml` 의 묶음: `dq4ch3*.py` 에서 검사 도구·검사 표를 뺀 것과 모듈만 닿는 `dq4boulder.py` 등)를 적고(모듈 `_checks` 표를 거쳐 import 로만 닿는 장면 검사는 `groups` 키에 같은 묶음, 배포 관문 몫), `dq4-ch3-*` 는 3장 맵·인물 목록 파일(`dq4npcport.py`·`dq4groupbuild.py`)도 적습니다. 새 모듈 파일 `dq4ch3<이름>.py` 는 묶음 glob 에 들어, 모듈 PR 이 다른 검사의 `paths` 를 고치지 않습니다. 모듈만 닿는 다른 이름의 도우미는 자기 조각에 `[groups]` `ch3-modules = ["…"]` 로 더합니다(같은 이름 묶음은 합쳐짐). `test_dq4guardpaths` 가 지키고, 빠진 것은 `dq4guardpaths.py` 가 찍습니다. 롬 장부 가드 `dq4-rom-ledger` 는 3장 롬 장부도 봅니다.

### 3장 출발 상태

2장 출발 상태(`dq4ch2walkcheck.head`)에서 [첫머리 검사](#검증)의 구간(`dq4ch3opencheck.segments` 의 `ch3_open` 까지: 빈 왕좌의 방 → 계단 → 2장 끝 → 3장 넘김 → 첫머리)을 시드 0 으로 걸은 끝 상태입니다. 톨네코 집 `3E/01` 침대(셀 (54,11)), 3장 flag 켜짐, 첫머리 대기 꺼짐, 조작 풀림. 서장 캐시와 같은 폴더(`work/cache/states/prologue/<롬 SHA-1>/ch3-start-<지문>.mss`, `DQ4_STATES_CACHE`)에 두고, 지문은 2장 출발 상태의 키에 `dq4ch3walkcheck.head` 의 코드, `dq4chapterwalk.py`, 머리 묶음 구간 표와 그 시작 flag, flag 표를 더한 것입니다. 사건 구간(`SEGMENTS`)은 넣지 않아 구간을 붙여도 머리를 다시 걷지 않습니다. 캐시는 `--repeat 2` 로 머리를 두 번 걸어 기록이 같을 때만 넣습니다. 호환성 검사는 코어마다 같은 머리를 걸어 `compat-<코어>-ch3` 로 둡니다.

### 붙이는 법

사건의 검사 표는 사건 모듈 옆 `dq4ch3<모듈>_checks.py` 하나에 둡니다(`dq4ch3checks` 머리말). 파일이 있으면 `SLOTS` 차례로 들어오므로, 사건을 더하거나 고치는 PR 은 자기 `_checks` 파일만 고칩니다. 3장 공용 자리·입력 조각(`TOWN`·`gold`·`items`·`SEARCH` 등)은 `dq4ch3walkparts.py`, 공용 구간(`house`~`town_in`)과 공용 flag 는 `dq4ch3walkcheck` 에 있습니다.

0. **차례**: 걷기 표는 묶음마다 앞 구간의 `want`·`off` 를 누적해 시작하고 flag 표 차례가 기록(WATCH·SET) 차례라, 잇는 차례가 결과에 닿습니다. `dq4ch3walkcheck.SEGMENT_ORDER`·`FLAG_ORDER` 는 모듈로 나누기 전의 차례를 고정한 것이고 새 모듈은 고치지 않습니다: 거기 없는 모듈·묶음은 `SLOTS` 차례로 뒤에 붙습니다. 한 모듈이 표를 여러 곳에 끼워야 하면 `SEGMENT_BLOCKS`·`FLAG_BLOCKS` 로 묶음을 나눕니다(`dq4ch3safe_checks`).
1. **flag**: `_checks` 의 `FLAGS` 에 한 줄(`'NAME': wc.flag(모듈.FLAG)`). 바이트 전체를 볼 칸은 `(주소, 0xFF)` 로 두고 선택 `bytes` 로 봅니다.
2. **걷기 구간**: `_checks` 의 `SEGMENTS` 에 사건 하나를 「순간이동 구간 하나 + 걷기 구간 여럿」 으로 더합니다. 순간이동 구간마다 새 묶음이고, 묶음 첫 구간에는 앞 구간들의 `want` 가 켜지고 `off` 가 꺼진 채로 놓입니다. 선택은 [2장 표](dq4-chapter2-format.md#걷기-검사에-구간-붙이기)와 같고 `set`(그 구간 시작에 한 번 두는 SET, 뒤 묶음에 잇지 않음)을 더했습니다. 일행·물건처럼 뒤 묶음까지 이어져야 하는 기록은 `_checks` 의 `effects(data)` 가 `구간 이름 → {'set': …}` 으로 냅니다. 출발 상태와 같은 맵(`3E/01`)으로 순간이동하면 `HOPS`(마을 왼쪽 가장자리)를 먼저 들릅니다. 순간이동은 `TO` 의 한 셀 아래에 내립니다. 사건 전투는 선택 `battle`(모듈 `BATTLES` 의 몬스터를 덮음, `dq4ch3walkcheck.battle_patch`).
3. **말 걸기 기대값**: npccheck 는 3장 flag 를 켜고 주인공 물건 칸을 톨네코 처음 소지품(`dq4ch3event.start` 의 `items`)으로 둔 상태에서 말을 겁니다. 사건이 말을 바꾼 인물은 `dq4ch3event.start_messages(first)`(`(맵, FC 대화 번호, 밤 또는 None) → 메시지 번호`)에, 처음 목록에서 뺀 인물은 `dq4ch3event.absent()` 에 둡니다. npccheck 는 두 함수가 있으면 씁니다. `first` 는 3장 메시지 첫 번호(`dq4chapter1.chapter3_message`)입니다. 그 밖의 인물은 옮긴 일본어 임시 대사의 번호(인물 보고서 `npc-report.json` 의 `message`)를 기대합니다.
4. **주인공 막기**: 주인공 칸으로 거는 사건은 `_checks` 의 `hero_cases()` 에 그 사건을 걸 수 있는 칸마다 사례를 둡니다(`warp`·`set`·`walk`·`want`·`free`·`hero_at`·`distinct`, 출발 상태와 같은 맵이면 `hop` 에 `dq4ch3walkparts.HOP`). `dq4heroblockcheck.chapter3_cases` 가 모읍니다. 1C 로 걷는데 겹침 피하기 장치를 쓰지 않는 인물 스크립트는 `_checks` 의 `PASS_NO_DEVICE` 에 까닭을 둡니다(`test_dq4heroblock`).
4-1. **물음 창**: 「예/아니요」 를 프레임 수로만 넘기지 않습니다. 앞 장·앞 모듈이 메시지를 더하면 창이 뜨는 때가 몇 프레임 달라져(엔돌 단추: 같은 글, 번호 +3 에 물음 창 f38 → f40) 누른 방향이 커서를 옮깁니다. 걷기 글에 `until:N`(창 번호 `7E:0A00` 이 바뀔 때까지, 많아야 N 프레임)과 `cursor:K`(커서 `7E:0AD7` 이 K 가 될 때까지 위·아래)를 쓰면 `lua/dq4walk.lua`(공유 `walk.lua` 에 이 둘을 더한 판)로 돕니다(`dq4ch1walkcheck.walk_driver`). 예: 칸에 올라서면 말 창 뒤 물음 창이 뜨는 단추는 `up:16;until:300;until:300;cursor:0;a:8`(필드는 8프레임마다 패드를 읽어 8프레임 누름은 놓칠 수 있음).
5. **호환성·인물 팔레트**: `dq4ch3walkcheck.SEGMENTS`(모은 표)를 그대로 걸으므로 따로 붙일 것이 없습니다. 가드는 `sfc/dq4/tools/dq4ch3*.py` glob 으로 `_checks` 파일을 이미 덮습니다.

```sh
uv run --locked python sfc/dq4/tools/dq4build.py --out work/ch3 --chapter3
MESENCE=… LIBDIR=… uv run --locked python sfc/dq4/tools/dq4ch3walkcheck.py --rom work/ch3/dq4-ch1-full.sfc \
    --out work/ch3walk --only town_side --seeds 0,5,9 --repeat 2
```

### 남은 것(검사)

- 첫머리 검사(`dq4-ch3-open`)와 걷기 검사의 머리가 같은 구간을 걷습니다. 첫머리 검사 뒤 구간(사건 견본)을 걷기 검사 구간으로 옮기면 첫머리 검사를 걷기 검사에 합칠 수 있습니다.
- 마을 안 인물 말 걸기는 npccheck 가 보고, 걷기 검사는 메시지 번호를 견주지 않습니다(2장과 같음).
- npccheck 의 인물 표 장면은 게임처럼 옮긴 대체 표(`npc-layout.json` 의 `override_table`)에서 그 장면 flag 로 맞는 첫 줄의 목록을 봅니다(`dq4npccheck.active_list`).
