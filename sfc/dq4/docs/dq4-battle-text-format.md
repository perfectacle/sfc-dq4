# 전투 메시지 한글

DQ5 전투 메시지 432개(`24:8C39`, [DQ5 전투 모드 메시지](../../dq5/docs/dq5-data-format.md))를 한글로 옮긴 명세입니다. 도구는 `sfc/dq4/tools/dq4battlemsg.py`(인코더·표)와 `dq4battletexts.py`(문장), 엔진은 `dq4battlemsg.asm` 이고, `dq4windowname.apply`(메뉴 빌드)가 창 이름 asm 과 함께 넣습니다. 글꼴은 이름과 같은 Galmuri9 입니다.

## 왜 엔진이 필요한가

전투 글은 바이트가 곧 BG3 타일 번호입니다. `24:86A5` 가 푼 버퍼 `7E:0E4B` 에서 한 바이트씩 꺼내 `E2` 미만이면 글자 격자(위 줄 `1DD5` 탁점, 아래 줄 `1DEF` 글자, 26칸 × 세 줄)에 쓰고, `24:A5D9` 가 격자를 타일맵 버퍼 `7E:5546` 으로 옮깁니다. 원래 글자 타일은 가나 138칸뿐이라, 한글은 그때그때 그려 빈 BG3 칸에 올려야 합니다. Galmuri9 한글은 9줄(1~9)·폭 9~10점이라 글자 줄 타일에 다 들어가지 않습니다. 맨 윗줄은 위 줄 타일의 7줄째에 둡니다(이름과 같은 방식).

## 칸 풀

전투 중 비는 BG3 칸을 행동마다 쟀습니다. 원본 DQ5 에서 주인공 주문(`cast.mss`, `11BE31` = 행동)과 몬스터 행동(`castm.mss`, `118011` 여섯 칸 = 행동) `00`~`C5` 를 각각 돌리며 프레임마다 VRAM `2000`~`3FFF` 를 읽어, 첫 전투 메시지 뒤에 바뀐 칸을 셌습니다(346실행).

| 칸 | 바꾼 행동 수 | 쓰는 것 |
| --- | --- | --- |
| `096`~`0AF` | 8 | ベギラゴン·メガンテ·メガザル·몬스터 행동 `13`~`15` 등 |
| `0B0`~`122` | 191~233 | 거의 모든 연출(공격 포함) |
| `123`~`162` | 4~10 | 큰 주문 연출(ベギラゴン·バギクロス·メガンテ·メガザル 등) |
| `163`~`165` | 0 | |
| `166`~`17C` | 5~6 | 큰 주문 연출 |
| `17D`~`17F` | 0 | |

원본에서 `180`~`1FF` 는 BG3 타일맵 자리라 연출이 글자 칸으로 쓰지 못합니다. DQ4 빌드는 타일맵을 옮겨([BG3 타일맵 옮기기](dq4-window-text-format.md#bg3-타일맵-옮기기)) 이 칸이 빕니다. `180`~`1CF` 는 상태 창 이름이 씁니다. 전투 배경 글자가 BG3 칸 `200`~`3FF` 자리(VRAM 워드 `2000`~`2FFF`)를 거의 다 채워 그쪽은 쓰지 않습니다.

- **풀 A(54칸, 늘 안전):** `1D0`~`1FF`, `163`~`165`, `17D`~`17F`.
- **풀 B(31칸):** `144`~`162`. 큰 주문 연출이 덮을 수 있어, 연출 끝(`22:D796`)에 화면에 있는 풀 B·C 칸을 다시 올립니다. 아래 칸은 올릴 때 둔 사본에서, 위 칸은 무늬로 다시 만듭니다. 사본은 DQ5 「맡긴 동료」 칸 자리(`7E:2332`~, 26바이트 × 56 = 1,456바이트)에 둡니다. DQ4 에는 몬스터 동료와 モンスターじいさん 이 없어 이 자리를 쓰는 곳이 없고, 다른 빈 WRAM 은 모자랐습니다(7F 뱅크는 아래 반이 세계 지도).
- **풀 C(76칸):** `099`~`0AF`(`0A7`·`0AC`·`0AF` 빼고), `123`~`143`, `166`~`17C`. 전투 중 BG3 타일맵이 가리키지 않고 큰 주문 연출만 덮는 칸입니다. 풀 B 와 같이 되살리고, 맨 나중(한 화면에 85칸 넘게 쓸 때)에만 씁니다. `096`~`098` 은 전투 화면이 쓰는 칸이라 뺐습니다.
  - `0A7`·`0AC`·`0AF` 는 「HP」·「MP」를 두 칸(`A7 AF`·`AC AF`)으로 찍는 원래 글자 칸입니다. 처음에는 풀에 넣어, 레벨업 능력치 줄이 한 화면에 85칸을 넘기자 그 칸에 한글 칸 그림이 찍혀 「최대 ..H가」처럼 보였습니다. 빼고 나서 「최대 HP가」·「최대 MP가」로 찍혔습니다(아래 「검증」).
- **코드:** 칸마다 격자 코드 하나를 짝짓습니다(161개). 원래 전투 글이 쓰지 않는 바이트 85개(코드가 따로 쓸 수 있는 `0C`~`0F`·`6E`·`7B`~`7F` 는 뺌)에, 가나 바이트 `10`~`7A`(`6E` 빼고)를 더했습니다. 가나 이름도 Galmuri 가나로 그리므로([이름](#이름)) 격자에 가나 바이트가 오지 않습니다. 빌드는 원문으로 둔 메시지(쓰레기 바이트인 `1A3`~`1AF` 빼고)가 코드를 쓰면 거부합니다.
- **WRAM:** 풀 번호마다 위 칸 무늬 1바이트, 「쓰는 중」·「테두리 바탕」은 1비트 표입니다. 아래 칸의 짝 위 칸 코드는 표에 두지 않고 글 큐에 [아래 코드, 위 코드(없으면 `00`)] 짝으로 넣어, `WnBattleChar` 가 아래 칸을 쓸 때 큐 머리에서 꺼냅니다.
- **고르기:** 구간·이름을 그릴 때마다 격자(156바이트)와 글 큐(`0ECB`, 64바이트)를 훑어 쓰는 코드를 표시하고 빈 코드를 앞에서부터 고릅니다. 줄이 올라가 보이지 않게 된 칸은 격자에 없으므로 따로 세지 않아도 돌아옵니다. 모자라면 빈칸 `01` 을 씁니다.

## 메시지 안의 한글 구간

빈 처리기(`24:86D3`)로 가던 제어 코드 `E3` 을 구간 접두로 씁니다. 꼴은 `E3 n 토큰…`(n = 토큰 바이트 수)입니다.

| 토큰 | 뜻 |
| --- | --- |
| `20`~`FF` | 글자 표 쪽 0 의 그 칸(자주 쓰는 글자부터) |
| `12`~`1F` x | 글자 표 쪽 (토큰 − `11`) 의 x 칸 |
| `10` p | 띄움 p 점(부호 있음. 좁은 문장 부호 뒤는 뒤로 당김) |
| `11` k | 조사 k(은/는·이/가·을/를·으로/로·과/와·아/야·이여/여) |

- 글자 표는 바이트 값으로 바로 찾는 256칸 쪽들이고, 끝 부호(`E7`·`EF`·`FE`) 칸은 비웁니다. `24:8C39` 가 끝 부호를 세어 앞 메시지를 건너뛰므로 구간 안에 끝 부호 바이트가 있으면 안 됩니다. 한 메시지는 128바이트(`24:8C21` 이 한 번에 푸는 양) 안이어야 해서, 글자마다 두 바이트로 두다가 가장 긴 메시지(`006`, `191`)가 넘쳐 글자 표를 넣었습니다.
- `24:86F2` 표는 뱅크 24 안 주소라, 디코더를 옮기면(`dq5battletextwrite.py`, 흐름 `4C:8000`) 쓰이지 않는 원래 전투 트리 자리 `24:9C2E` 에 `JML` 받침을 둡니다.
- 문장 부호 `!?.,…「」~` 는 Galmuri9 글리프를 가나 글리프 뒤(이름 입력 글리프 뱅크)에 더해 같은 띠에 그립니다. 숫자·`MP`·`HP`·`＊` 는 원래 글자 타일입니다.

## 그리기

| 단계 | 내용 |
| --- | --- |
| 띠 | 9줄 × 29바이트(`7E:A800`). 글리프(이름 입력의 16×16 칸)를 10점 간격으로 겹친다 |
| 열 | 열마다 아래 칸 8바이트(띠 줄 1~8)와 위 칸 무늬 1바이트(띠 줄 0). 둘 다 비면 `01` |
| 위 칸 | 무늬·바탕이 같은 위 칸은 함께 쓴다. 바탕은 빈칸, 또는 첫 줄이면 창 위 테두리 `8D` |
| 올리기 | 우리 NMI 대기열에 칸마다 항목. 아래 칸·빈 바탕 위 칸은 평면 0 만(평면 1 = `FF`), 테두리 바탕은 두 평면 |
| 큐 | 열 코드와 `FF` 를 `0ECB` 에 넣고 `24:872E` 로(이름 처리기와 같은 길) |

- **이어 그리기:** 이름이나 구간 뒤에 바로 구간(`E3`)이 오면 덜 찬 마지막 열을 올리지 않고 띠 첫 열로 넘깁니다. 이름과 조사 사이(「부하는」)가 칸 경계로 벌어지지 않습니다.
- **끝 띄움:** 구간이 띄움으로 끝나고 다음이 이름이면, 띄움을 뺀 칸 올림 틈이 3점 이상일 때 그 틈을 띄어쓰기로 씁니다(「눈알은 베기라곤을」). 숫자 앞은 숫자 타일이 바로 붙어 빼지 않습니다. 좁은 부호(「!」 등) 뒤의 당김(음수 띄움)은 띄움이 아닙니다. 이것까지 빼자 점 자리가 `FFxx` 로 깨져, 열 수를 큐가 찰 때까지 빈칸으로 세고 `$0F0D` 가 26 으로 찼습니다.
- **긴 줄:** 띠를 올리기 전에 지금 칸(`$0F0D`)과 띠의 열 수를 더해 26칸을 넘고 줄 첫 칸이 아니면, 원래 줄 바꿈(`24:A4F3`)으로 먼저 줄을 바꿉니다(`BmEmit`). 이름이 덜 찬 열을 넘겨 받은 구간이면 구간을 다 그려 폭을 잰 뒤, 넘치면 넘겨 받은 열만 앞 줄에 찍고 줄을 바꿔 구간을 다시 그립니다(`BmCarrySave`·`BmCarryWrap`). 그래서 이름째 다음 줄로 가지 않고 이름 끝이 앞 줄에 남습니다. 이때 구간의 첫 띄움(`10 05`) 앞까지가 지금 줄에 들면 거기서 나눕니다. 그 띄움 토큰 두 바이트 자리를 줄 바꿈 `FF` 과 남은 구간 머리(`E3` 길이)로 바꾸고 앞부분만 다시 그립니다. 그래서 이름 뒤 조사와 그 낱말이 이름 줄에 남습니다(「…노송나무 막대를 / 몸에 걸쳤다!」). 첫 띄움 자리와 점 자리는 `!bm_sp`·`!bm_sx`(`7E:A921`·`A922`)에 둡니다. 구간 앞의 `E3` 는 이미 꺼냈으므로 버퍼를 한 바이트 밀어도 메시지 바이트가 버려지지 않습니다. 넘김 검사는 끝 띄움을 줄인 뒤의 폭으로 합니다. 그래서 끝 띄움 처리는 버퍼를 당기기 전에, 구간 다음 바이트(`!bm_buf` + n + 1)를 보고 합니다.
- **띠 비우기:** 띠는 261바이트(홀수)라 두 바이트씩 지우면 맨 앞 바이트(줄 0 열 0)가 남습니다. 남은 점이 다음 띠 첫 칸의 위 칸 무늬에 섞여 「1`2」처럼 보여, 그 바이트를 따로 지웁니다.
- **칸 기다리기:** 전투 NMI 는 창 타일맵 요청(`$0BEC`)을 한 번만 처리하므로, 그 요청이 있으면 우리 대기열을 다음 NMI 로 미룹니다(`WqNmiGate`). 띠를 올린 뒤 바로 글자를 격자에 쓰면 타일맵이 먼저 가 한 프레임 동안 새로 고른 칸이 옛 그림으로 보였습니다(「레벨」 자리에 「레뀰!」). 그래서 `BmEmit` 끝에서 대기열이 빌 때까지 기다립니다(`BmDrain`). NMI 가 꺼져 있으면 VBlank 마다 직접 보내고, 켜져 있으면 약 10프레임까지만 기다립니다.
- **조사:** 마지막에 그린 글리프의 받침(글리프마다 0 없음·1 있음·2 ㄹ 표)으로 고릅니다. 가나 이름 뒤는 받침 없는 쪽입니다.
- **위 칸 쓰기:** `24:A4E0`(`WnBattleChar`)이 아래 칸 코드를 쓸 때 짝 위 칸 코드(`7E:A6F8`)를 위 줄에도 씁니다. 26칸을 넘는 글자는 버립니다(넘겨 쓰면 다음 줄 위 칸을 덮음).
- **타일 번호:** `24:A5E9`(`WnBattleCell`)이 코드를 표로 풀 칸 타일에 잇고 타일 bit8 을 켭니다.

### 첫 줄 위 칸

글 격자의 첫 줄 위 칸은 창 위 테두리 줄입니다. 빈 바탕 위 칸을 쓰자 테두리가 끊기고 「는」이 「든」처럼 보였습니다. 원래 게임은 첫 줄 탁점에 테두리+탁점 타일 `92`·`93` 을 쓰고, 줄이 올라갈 때(`24:A595` 고리) 둘째 줄의 `84`·`83` 을 `92`·`93` 으로 바꿔 첫 줄 위에 씁니다. 그래서 첫 줄에 쓸 때는 테두리 바탕 위 칸을 고르고, `24:A595` 고리를 `BmScroll` 로 바꿔 빈 바탕 위 칸도 같은 무늬의 테두리 바탕 칸으로 바꿉니다.

`24:A595` 고리가 든 `24:A569` 는 `24:A503` 의 `JSR` 로 불리므로, `BmScroll` 뒤에는 원래 고리 끝 `24:A5B2` 로 돌아가야 합니다. 이 분기를 24비트 숫자 주소(`BRA $24A5B2`)로 적자 asar 가 `80 B2` 를 넣어 `24:A54D`(▼ 기다림의 `PLP`/`RTL` 꼬리)로 갔습니다. 줄이 올라간 다음 프레임에 `RTL` 이 바이트 하나를 더 꺼내 `04:A506` 으로 돌아가 멈췄습니다. 넷째 줄이 생기는 전투(레벨업 줄)마다 그랬습니다. 라벨로 적어 `80 17` 이 되었습니다.

## 이름

`24:A83C`(이름을 큐로 옮기는 자리)에서 한글 이름(이름 입력 표시 바이트)은 `WnKorean` 이 글리프를 풀고, 그 밖의 이름은 이름 표(`4D:A000`, `[길이][바이트][토큰 수][토큰…]`)에서 같은 바이트를 찾아 한글로 그립니다. 표는 이름 표 3(주문·특기)·4(몬스터)·5(물건)의 일본어를 `adopt.tsv` 와 맞춘 것, 1장 보스로 빌린 번호의 이름, 몬스터 무리를 묶어 부르는 고정 문자열 `24:8950`(「まもののむれ」 → 「마물 무리」)입니다. 표에 없으면 가나 표(`60:E800`, 창 이름과 같은 것)로 Galmuri 가나를 그립니다(`BmKana`). 숫자 바이트 `02`~`0B` 는 문장 부호와 함께 더한 Galmuri 숫자를 글리프 폭 + 1점 간격으로(`BmDigitAdv`), 표에 없는 바이트는 띄움으로 그립니다.

## 전투 첫머리 창

전투 첫머리 「(이름)が　あらわれた！」는 `24:8C39` 메시지가 아닙니다. 창 25 를 그리는 `04:BFF5` 가 무리마다 한 줄씩, 이름 바이트(`$00` = 길이)를 `04:B235` 로 타일맵 버퍼 `($E0),Y`(Y = `$0E0B` + `$0A4C` × `40`)에 찍고 이어 상수 `04:C05B` 9바이트(「が　あらわれた！」)를 찍습니다. 첫 줄 탁점은 창 위 테두리+탁점(`94`)입니다.

- `04:BFF5` 를 `BmEncounter` 로 바꿉니다. 이름이 이름 표에 있으면 「(이름){이} 나타났다!」(`APPEAR`)를 띠로 그리고, 없으면 원래 길로 가나를 찍습니다.
- 전투가 막 시작해 연출이 BG3 칸 `0B0`~`17F` 를 아직 쓰지 않고, 창 25 는 명령 창이 뜨기 전에 닫힙니다. 그래서 줄 k(`$0A4C` / 2)마다 `0B0` + k × 52 에서 아래 칸 26·위 칸 26 을 고정으로 씁니다.
- 위 칸은 그 자리의 지금 타일(첫 줄은 창 위 테두리 `8D`)에 글자 맨 윗줄을 겹칩니다(`WnBaseRow`).
- 첫 줄의 위 칸 자리는 Y − `40` 이 음수라, `($E0),Y` 로 쓰자 뱅크를 넘어 `7F` 에 써져 글자 맨 윗줄이 빠졌습니다. 포인터와 오프셋을 16비트로 더해 `7E` 안에서 씁니다.
- 끝나면 원래처럼 `04:C044`(창 전송 요청·다음 줄)로 갑니다.

## 문장

`dq4battletexts.SOURCE` 에 번호마다 한글을 둡니다. 쓰이지 않는 `000`·`1A3`~`1AF` 는 원문 그대로입니다.

- 원문 제어 코드는 `{F7}` 꼴로, 줄 바꿈은 `/`(`FF`), 쪽 넘김은 `|`(`FD`)로 적습니다. 끝 부호와 그 앞의 효과음·흔들림 `F2` 는 원문을 따릅니다.
- 줄은 이름 7칸·숫자 3칸으로 세어 26칸 안이어야 하고, 넘으면 빌드가 거부합니다. 한글 이름 대부분이 일곱 칸 안입니다(물건·주문 몇은 아홉~열 칸).
- 일행을 묶어 부르는 `FA`(가나 「たち」)는 쓰지 않고 「일행」으로 적습니다. 숫자 뒤 조사는 받침을 알 수 없어 「에」·「의」처럼 받침과 무관한 말로 짭니다.

## 같이 고친 것

필드 이름 훅(`dq4msgnames`, `24:89BB`)은 한글이 없을 때 `24:89BD` 로 돌아갔는데, 그 자리는 훅의 `JML` 한가운데였습니다. 전투(`$70` bit7)에서는 늘 그 길이라, 주문 이름(`F4`)에서 이름 길이 `$00` = 0 인 채 원래 길이 256바이트를 큐로 옮겨 끝 `FF` 가 사라지고 메시지가 끝없이 찍혔습니다. 덮은 `JSR $889F` 를 훅이 대신하고 `24:89C0` 으로 돌아가게 고쳤습니다([조사 코드의 이름](dq4-josa-format.md#이름)).

## 전투 메시지 검사

`sfc/dq4/tools/dq4battlemsgcheck.py` 가 1장 상태에서 탑 위 보스와 싸우며 메시지를 띄울 때마다(`24:8C39`) 번호를 검사할 번호로 바꿔 끼웁니다(`lua/dq4battlemsgswap.lua`). 주인공은 HP 999·「라이언」이고, 이름·숫자 자리에는 그때 큐에 든 값이 들어갑니다. 40개씩 넷을 함께 돌려, 바꿔 넣은 번호 뒤로 다음 메시지가 오지 않으면 멈춤으로 봅니다. 메시지마다 화면과 격자 안의 풀 코드 수를 남깁니다.

```sh
MESENCE=… LIBDIR=… uv run --locked python sfc/dq4/tools/dq4battlemsgcheck.py --rom work/x/ch1.sfc --state work/ch1.mss --out work/battlemsgcheck
```

- 432개 가운데 메시지는 418개입니다. `000` 은 빈 메시지(`EF`)이고, `1A3`~`1AF` 는 원래 롬에서도 뜻 없는 바이트(「{FF}{FF}{FF}{FF}っ{F2}な　ト　イ」 등)라 옮기지 않고 검사하지 않습니다.
- `004`(「{EC}{이} 전투에 끼어들었다」)도 이제 끝까지 찍힙니다. `{EC}`(`24:8ABB`)는 일행 레코드(`7E:2040` + 42 × n) `+0` 이 `80`(킬러팬서)인 사람을 찾아 이름을 찍고, 없으면 이름 없이 돌아갑니다. 그래서 이 장면에서는 「이럴 수가, 가 / 전투에 끼어들었다!」입니다. 주인공 `+0` 을 `80` 으로 두면 「ボロン가」(이름이 가나라 받침 없는 쪽)가 찍혔고, 그 뒤 주인공이 킬러팬서로 다뤄져 전투가 이어지지 않았습니다. DQ4 에는 킬러팬서가 없어 이 메시지는 나오지 않습니다.
- 주인공 이름은 끝 바이트 `01` 까지 넣습니다(`7E:2007`). 이름 옮기기(`24:8A0F`)는 `01` 앞까지 읽으므로, 빠지면 세이브스테이트의 다음 바이트가 붙어 「라이언ㅂ」처럼 찍혔습니다.
- `--field` 는 보행 메시지(`24:8BAF`)를 같은 식으로 봅니다. 성 앞(`36/00` (38,25))에서 빈 곳에 「はなす」를 골라 뜨는 메시지를 번호마다 한 번 바꿔 끼우고, 100프레임 뒤 화면을 `sheet-field.png` 로 모읍니다. 바꿔 끼우는 입구는 `lua/dq4battlemsgswap.lua` 의 `ENTRY` 입니다.
- 연출 시작(`22:D73C`) 때 격자에 풀 C 코드가 있는 횟수도 셉니다(`effects_with_late_tiles`). 417개를 돌리며 연출 177번 가운데 1번이었습니다. 그래서 풀 C 도 되살립니다.
- 처음 돌렸을 때 85칸 풀을 다 쓴 화면이 417개 가운데 14개였고, 셋째 줄 글자가 빠졌습니다. 풀 C·가나 코드를 더한 뒤 가장 많이 쓴 화면이 95칸(늦게 찍은 긴 메시지는 112칸)이었습니다.
- 풀 C 를 더하자 `099`~`0AF` 칸이 상태 창 이름 자리(`199`~)로 그려졌습니다. `WnBattleCell` 이 풀 코드면 타일 bit8 을 늘 켰기 때문이라, 칸 번호대로 켜게 고쳤습니다.

## 남은 것

- 1장 조우가 빌려 쓰는 DQ5 몬스터(ドラキー·スカルサーペント·まほうつかい 등)와 adopt 표에 없는 물건·주문은 이름이 가나로 찍히고, 뒤 조사는 받침 없는 쪽입니다. 몬스터 이름은 DQ4 몬스터를 옮길 때 함께 바뀝니다.
- 줄을 나누는 곳은 구간의 첫 띄움뿐입니다. 첫 띄움 앞까지도 줄에 들지 않으면 이름 끝 열만 앞 줄에 남기고 구간째 다음 줄로 갑니다.
- DQ5 이야기 메시지(파파스·쟈미·마차·카지노 등)는 검사에서 끝까지 찍히는 것만 봤습니다. DQ4 에서 나오지 않는 장면이라 더 보지 않습니다.
- 맡긴 동료 칸은 모험의 서에 함께 기록되므로 사본 바이트가 기록에 남습니다. DQ4 는 이 칸을 읽지 않습니다.
