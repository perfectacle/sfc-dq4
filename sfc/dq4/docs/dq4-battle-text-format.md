# 전투 메시지 한글

DQ5 전투 메시지 432개(`24:8C39`, [DQ5 전투 모드 메시지](../../dq5/docs/dq5-data-format.md))를 한글로 옮긴 명세입니다. 도구는 `sfc/dq4/tools/dq4battlemsg.py`(인코더·표)와 `dq4battletexts.py`(문장), 엔진은 `dq4battlemsg.asm` 이고, `dq4windowname.apply`(메뉴 빌드)가 창 이름 asm 과 함께 넣습니다. 글꼴은 이름과 같은 Galmuri9 입니다.

## 왜 엔진이 필요한가

전투 글은 바이트가 곧 BG3 타일 번호입니다. `24:86A5` 가 푼 버퍼 `7E:0E4B` 에서 한 바이트씩 꺼내 `E2` 미만이면 글자 격자(위 줄 `1DD5` 탁점, 아래 줄 `1DEF` 글자, 26칸 × 세 줄)에 쓰고, `24:A5D9` 가 격자를 타일맵 버퍼 `7E:5546` 으로 옮깁니다. 원래 글자 타일은 가나 138칸뿐이라, 한글은 그때그때 그려 빈 BG3 칸에 올려야 합니다. Galmuri9 한글은 9줄(1~9)·폭 9~10점이라 글자 줄 타일에 다 들어가지 않습니다. 맨 윗줄은 위 줄 타일의 7줄째에 둡니다(이름과 같은 방식).

## 칸 풀

전투 중 비는 BG3 칸을 행동마다 쟀습니다. 원본 DQ5 에서 주인공 주문(`cast.mss`, `11BE31` = 행동)과 몬스터 행동(`castm.mss`, `118011` 여섯 칸 = 행동) `00`~`C5` 를 각각 돌리며 프레임마다 VRAM `2000`~`3FFF` 를 읽어, 첫 전투 메시지 뒤에 바뀐 칸을 셌습니다(346실행).

| 칸 | 바꾼 행동 수 | 쓰는 것 |
| --- | --- | --- |
| `096`~`0AF` | 8 | ベギラゴン·メガンテ·メガザル·몬스터 행동 `13`~`15` 등 |
| `0B0`~`122` | 191~233 | 거의 모든 연출(공격 포함) |
| `123`~`162` | 4~10 | 큰 주문 연출(ベギラゴン·バギクロス·メガンテ·メガザル 등) |
| `163`~`165` | 0 | |
| `166`~`17C` | 5~6 | 큰 주문 연출 |
| `17D`~`17F` | 0 | |

원본에서 `180`~`1FF` 는 BG3 타일맵 자리라 연출이 글자 칸으로 쓰지 못합니다. DQ4 빌드는 타일맵을 옮겨([BG3 타일맵 옮기기](dq4-window-text-format.md#bg3-타일맵-옮기기)) 이 칸이 빕니다. `180`~`1CF` 는 상태 창 이름이 씁니다. 전투 배경 글자가 BG3 칸 `200`~`3FF` 자리(VRAM 워드 `2000`~`2FFF`)를 거의 다 채워 그쪽은 쓰지 않습니다.

- **풀 A(54칸, 늘 안전):** `1D0`~`1FF`, `163`~`165`, `17D`~`17F`.
- **풀 B(31칸):** `144`~`162`. 큰 주문 연출이 덮을 수 있어, 연출 끝(`22:D796`)에 화면에 있는 풀 B 칸을 다시 올립니다. 아래 칸은 올릴 때 둔 사본(`7E:A600`~)에서, 위 칸은 무늬로 다시 만듭니다.
- **코드:** 칸마다 격자 코드 하나를 짝짓습니다. 원래 전투 글(메시지 432개·이름 표·탁점 `92`/`93`·숫자·채움 `8D`)이 쓰지 않는 바이트 95개 가운데, 코드가 따로 쓸 수 있는 `0C`~`0F`·`6E`·`7B`~`7F` 를 뺀 85개입니다. 빌드는 원래 글이 이 코드를 쓰면 거부합니다.
- **고르기:** 구간·이름을 그릴 때마다 격자(156바이트)와 글 큐(`0ECB`, 64바이트)를 훑어 쓰는 코드를 표시하고 빈 코드를 앞에서부터 고릅니다. 줄이 올라가 보이지 않게 된 칸은 격자에 없으므로 따로 세지 않아도 돌아옵니다. 모자라면 빈칸 `01` 을 씁니다.

## 메시지 안의 한글 구간

빈 처리기(`24:86D3`)로 가던 제어 코드 `E3` 을 구간 접두로 씁니다. 꼴은 `E3 n 토큰…`(n = 토큰 바이트 수)입니다.

| 토큰 | 뜻 |
| --- | --- |
| `20`~`FF` | 글자 표 쪽 0 의 그 칸(자주 쓰는 글자부터) |
| `12`~`1F` x | 글자 표 쪽 (토큰 − `11`) 의 x 칸 |
| `10` p | 띄움 p 점(부호 있음. 좁은 문장 부호 뒤는 뒤로 당김) |
| `11` k | 조사 k(은/는·이/가·을/를·으로/로·과/와·아/야·이여/여) |

- 글자 표는 바이트 값으로 바로 찾는 256칸 쪽들이고, 끝 부호(`E7`·`EF`·`FE`) 칸은 비웁니다. `24:8C39` 가 끝 부호를 세어 앞 메시지를 건너뛰므로 구간 안에 끝 부호 바이트가 있으면 안 됩니다. 한 메시지는 128바이트(`24:8C21` 이 한 번에 푸는 양) 안이어야 해서, 글자마다 두 바이트로 두다가 가장 긴 메시지(`006`, `191`)가 넘쳐 글자 표를 넣었습니다.
- `24:86F2` 표는 뱅크 24 안 주소라, 디코더를 옮기면(`dq5battletextwrite.py`, 흐름 `4C:8000`) 쓰이지 않는 원래 전투 트리 자리 `24:9C2E` 에 `JML` 받침을 둡니다.
- 문장 부호 `!?.,…「」~` 는 Galmuri9 글리프를 가나 글리프 뒤(이름 입력 글리프 뱅크)에 더해 같은 띠에 그립니다. 숫자·`MP`·`HP`·`＊` 는 원래 글자 타일입니다.

## 그리기

| 단계 | 내용 |
| --- | --- |
| 띠 | 9줄 × 29바이트(`7E:A800`). 글리프(이름 입력의 16×16 칸)를 10점 간격으로 겹친다 |
| 열 | 열마다 아래 칸 8바이트(띠 줄 1~8)와 위 칸 무늬 1바이트(띠 줄 0). 둘 다 비면 `01` |
| 위 칸 | 무늬·바탕이 같은 위 칸은 함께 쓴다. 바탕은 빈칸, 또는 첫 줄이면 창 위 테두리 `8D` |
| 올리기 | 우리 NMI 대기열에 칸마다 항목. 아래 칸·빈 바탕 위 칸은 평면 0 만(평면 1 = `FF`), 테두리 바탕은 두 평면 |
| 큐 | 열 코드와 `FF` 를 `0ECB` 에 넣고 `24:872E` 로(이름 처리기와 같은 길) |

- **이어 그리기:** 이름이나 구간 뒤에 바로 구간(`E3`)이 오면 덜 찬 마지막 열을 올리지 않고 띠 첫 열로 넘깁니다. 이름과 조사 사이(「부하는」)가 칸 경계로 벌어지지 않습니다.
- **끝 띄움:** 구간이 띄움으로 끝나고 다음이 이름이면, 띄움을 뺀 칸 올림 틈이 3점 이상일 때 그 틈을 띄어쓰기로 씁니다(「눈알은 베기라곤을」). 숫자 앞은 숫자 타일이 바로 붙어 빼지 않습니다.
- **조사:** 마지막에 그린 글리프의 받침(글리프마다 0 없음·1 있음·2 ㄹ 표)으로 고릅니다. 가나 이름 뒤는 받침 없는 쪽입니다.
- **위 칸 쓰기:** `24:A4E0`(`WnBattleChar`)이 아래 칸 코드를 쓸 때 짝 위 칸 코드(`7E:A6F8`)를 위 줄에도 씁니다. 26칸을 넘는 글자는 버립니다(넘겨 쓰면 다음 줄 위 칸을 덮음).
- **타일 번호:** `24:A5E9`(`WnBattleCell`)이 코드를 표로 풀 칸 타일에 잇고 타일 bit8 을 켭니다.

### 첫 줄 위 칸

글 격자의 첫 줄 위 칸은 창 위 테두리 줄입니다. 빈 바탕 위 칸을 쓰자 테두리가 끊기고 「는」이 「든」처럼 보였습니다. 원래 게임은 첫 줄 탁점에 테두리+탁점 타일 `92`·`93` 을 쓰고, 줄이 올라갈 때(`24:A595` 고리) 둘째 줄의 `84`·`83` 을 `92`·`93` 으로 바꿔 첫 줄 위에 씁니다. 그래서 첫 줄에 쓸 때는 테두리 바탕 위 칸을 고르고, `24:A595` 고리를 `BmScroll` 로 바꿔 빈 바탕 위 칸도 같은 무늬의 테두리 바탕 칸으로 바꿉니다.

## 이름

`24:A83C`(이름을 큐로 옮기는 자리)에서 한글 이름(이름 입력 표시 바이트)은 `WnKorean` 이 글리프를 풀고, 그 밖의 이름은 이름 표(`4D:9000`, `[길이][바이트][글리프 수][글리프…]`)에서 같은 바이트를 찾아 한글로 그립니다. 표는 이름 표 3(주문·특기)·4(몬스터)·5(물건)의 일본어를 `adopt.tsv` 와 맞춘 것, 1장 보스로 빌린 번호의 이름, 몬스터 무리를 묶어 부르는 고정 문자열 `24:8950`(「まもののむれ」 → 「마물 무리」)입니다. 표에 없으면 원래 길로 가나를 찍습니다.

## 문장

`dq4battletexts.SOURCE` 에 번호마다 한글을 둡니다. 쓰이지 않는 `000`·`1A3`~`1AF` 는 원문 그대로입니다.

- 원문 제어 코드는 `{F7}` 꼴로, 줄 바꿈은 `/`(`FF`), 쪽 넘김은 `|`(`FD`)로 적습니다. 끝 부호와 그 앞의 효과음·흔들림 `F2` 는 원문을 따릅니다.
- 줄은 이름 7칸·숫자 3칸으로 세어 26칸 안이어야 하고, 넘으면 빌드가 거부합니다. 한글 이름 대부분이 일곱 칸 안입니다(물건·주문 몇은 아홉~열 칸).
- 일행을 묶어 부르는 `FA`(가나 「たち」)는 쓰지 않고 「일행」으로 적습니다. 숫자 뒤 조사는 받침을 알 수 없어 「에」·「의」처럼 받침과 무관한 말로 짭니다.

## 같이 고친 것

필드 이름 훅(`dq4msgnames`, `24:89BB`)은 한글이 없을 때 `24:89BD` 로 돌아갔는데, 그 자리는 훅의 `JML` 한가운데였습니다. 전투(`$70` bit7)에서는 늘 그 길이라, 주문 이름(`F4`)에서 이름 길이 `$00` = 0 인 채 원래 길이 256바이트를 큐로 옮겨 끝 `FF` 가 사라지고 메시지가 끝없이 찍혔습니다. 덮은 `JSR $889F` 를 훅이 대신하고 `24:89C0` 으로 돌아가게 고쳤습니다([조사 코드의 이름](dq4-josa-format.md#이름)).

## 검증

MesenCE 헤드리스로 1장 빌드(`--no-prologue`)의 탑 위 보스(`39/04`)와 싸웠습니다. 주인공 이름은 `SET` 으로 「라이언」을 넣었습니다.

| 장면 | 결과 |
| --- | --- |
| 원래 롬 | 「피사로의 부하의 공격!」「라이언은 22의 데미지를 받았다!」「피사로의 부하는 기라를 외웠다!」「큰 눈알은 상황을 살피고 있다.」, 공격 연출 뒤에도 깨짐 없음, 창 위 테두리 그대로 |
| 두 몬스터 HP 1·수비 0 | 「피사로의 부하를 쓰러뜨렸다!」「마물 무리를 물리쳤다!」「100포인트의 경험치를 얻었다!」「라이언은 레벨 2에 올랐다!」. 넷째 줄에서 줄이 올라가 한글 줄이 첫 줄로 가도 테두리 그대로 |
| 두 몬스터 행동 모두 ベギラゴン | 「큰 눈알은 베기라곤을 외웠다!」「라이언은 107의 데미지를 받았다!」, 연출 동안·뒤 깨짐 없음. 풀 B 를 앞에 둔 시험 빌드에서도 같음 |
| 롬에서 다시 푼 메시지 | 432개 모두 넣은 바이트와 같음 |
| 회귀 | dq4 시험 전부, 서장 → 1장 걷기 검사(`dq4prologuecheck.py`) |

## 남은 것

- 풀 B 를 실제로 덮는 큰 주문을 주인공이 쓰는 장면(1장 주인공은 주문이 없음). 원본에서 덮은 것은 주인공이 쓴 ベギラゴン 등이고, 몬스터가 쓴 ベギラゴン 에서는 덮이지 않았습니다. 그래서 복원(`22:D796`)이 실제로 칸을 되살리는 것은 아직 보지 못했습니다.
- 한 화면에 칸이 85칸을 넘는 경우(세 줄을 긴 한글로 채움). 모자라면 빈칸으로 빠집니다.
- 줄이 올라가는 반 칸 사이 한 프레임, 새로 고른 칸이 옛 그림으로 보일 수 있음(대기열이 다음 NMI 로 밀릴 때).
- 가나로 남는 이름(adopt 표에 없는 DQ5 고유 이름), 일곱 칸을 넘는 이름으로 26칸을 넘는 줄(넘는 글자는 버림).
- DQ5 이야기 메시지(파파스·쟈미·마차·카지노 등)는 옮겼지만 장면에서 띄워 보지 않았습니다.
