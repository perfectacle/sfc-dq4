# DQ4 3장 몬스터

3장(「무기상인 톨네코」) 구역의 몬스터 능력치·편성·밤에만 나오는 칸·3장 전용 전투 뒤 물건을 FC 대로 옮긴 것입니다. FC 쪽 실측은 [FC 3장 「필드와 조우」·「전투 뒤 물건」](../../../fc/dq4/docs/dq4-chapter3-format.md#필드와-조우), 필드 조우 전반은 [조우](dq4-field-format.md#조우), 2장 몬스터 레코드 규칙은 [2장 전투 몬스터 능력치](dq4-sprite-format.md#2장-전투-몬스터-능력치)입니다. 도구는 `sfc/dq4/tools/dq4fieldencounter.py`(구역·훅)와 `dq4monport.py`(레코드·이름), 검사는 `dq4ch3monstercheck.py`(가드 `dq4-ch3-monsters`)입니다.

## 몬스터 번호

3장 구역(`dq4fieldencounter.CH3_ZONES`: 필드 `14`~`17`, 북쪽 동굴 `48`·`49`, 여신상 동굴 `4A`·`4B`)에 나오는 FC 몬스터 19종과 1장 구역(필드 `04`~`06`, 던전 `40`~`43`)의 14종은 모두 FC 레코드 값입니다. 2장에서 FC 값으로 옮긴 번호(`dq4monport.PORT`)를 함께 쓰고, 처음 넣은 9종은 따로 받은 번호입니다(`dq4monport.NUMBERED` = 3장 `CH3` 6종 + 1장 `CH1` 3종). 한 FC 몬스터는 어느 장 구역에서나 한 번호입니다(`dq4fieldencounter.MONSTERS`).

| FC | 이름 | DQ5 번호 | 그림 레코드 |
| --- | --- | --- | --- |
| `0A` | 버블 슬라임 | `C5` | `09` 에 NDS 그림 |
| `13` | 킬러 스콥 | `B6` | `45` 에 NDS 그림 |
| `17` | 에레프 로파 | `9D` | `9F` 에 NDS 그림 |
| `19` | 덕스 빌 | `A5` | `80` 에 NDS 그림 |
| `1E` | 릴리펏 | `E3` | `CD` 에 NDS 그림 |
| `21` | 거대한 닭 | `3D` | `8D` 에 NDS 그림 |
| `09` | 에어랫 | `07` | `C3` 에 NDS 그림 |
| `10` | 견습 악마 | `16` | `2C` 에 NDS 그림 |
| `22` | 픽시 | `21` | `97` 에 NDS 그림 |
| `29` | 큰 눈알 | `10` | `52`(1장 보스)에 NDS 그림 |

- `29` 는 3장 격투장 시합(`dq4shopport.arena`)에만 나와 `dq4monport.ARENA` 로 둡니다.
- 3장 6종 가운데 5종은 1장 필드(`0A`, 구역 `04`~`06`)와 1장 던전(`13`·`19`·`1E`·`21`, `41`~`43`·고정 무리 0·1)에도 나와 1장에서도 같은 번호입니다(사용자 결정 2026-11-17: 1장 걸음 전투의 대역 8종을 모두 FC 값으로). FC 몬스터 표는 한 벌이라 장마다 값이 다르지 않습니다.
- 레코드: 대역 레코드 25바이트에 `fc_entry` 를 덮습니다(PORT 와 같음). 행동 표에 ルカニ(FC `16`) → `53`, スカラ(FC `1C`) → `55`, ピオリム(FC `1E`, 픽시) → 새 행동 `C7`(DQ5 에 짝이 없어 [새 행동 번호](dq4-sprite-format.md#새-행동-번호-dq4monspecial)로 옮김)을 더했습니다. 몬스터용 주문 MP 를 FC 값으로 두므로 `55` 의 MP 가 2 → 3 입니다.
- 그림: 새 번호의 그림 레코드 포인터(`dq5mongfx.record_table` 의 2바이트)를 다른 번호의 것으로 둡니다(`dq4monport.picture_writes`). NDS 그림을 넣은 종은 `dq4monport.ART` 의 번호(빌드가 그 그림 자리에 NDS 그림을 덮음, [넣는 법](dq4-sprite-format.md#넣는-법-dq4monportpy-dq4monartpy)), 나머지는 대역의 것이라 그림·색·무리 조합 한도가 지금 대역과 같습니다. 표의 「그림 레코드」 에 번호만 있는 것이 대역입니다. NDS 그림 번호는 `NUMBERED` 의 둘째 값입니다.
- 이름: NDS 한글(`adopt.tsv`)을 번호로 전투 글 이름 표·창 이름 표에 넣습니다(`dq4monport.korean_names`).

## 빈 DQ5 몬스터 번호

새 FC 몬스터에 줄 DQ5 번호는 `dq4monport.free_numbers(dq5, prg)` 로 고릅니다. 01~E6 가운데 아래를 뺀 것입니다.

| 빼는 것 | 까닭 |
| --- | --- |
| 이 해킹이 쓰는 번호(`used_numbers`: 필드 조우 `MONSTERS`(뒷 장 대역 포함)·필드 번호·사건 번호·1장 보스·2장 사건 예약) | 겹침 |
| 싸우는 도중에 부르는 몬스터(`dq5monlimits.SUMMONED`, 8) | 큰 그림이 싸우는 도중에 풀림 |
| 격투장 시합 표 `23:DA97` 의 몬스터(97) | 뒷 장 카지노 |
| 동료가 되는 몬스터(레코드 동료확률 > 0, 40) | 몬스터 동료 표 |
| 능력치가 빈 레코드(8) | 이름만 있는 번호 |
| 가나 이름이 롬 안에서 겹치는 번호 | 전투 글이 이름 바이트로 한글을 찾음(`dq4battlemsg`) |
| FC 몬스터와 이름이 같은 번호 | 뒷 장이 그 DQ5 몬스터를 그대로 쓸 수 있음 |

1장 셋(`07` ガップリン·`16` スカンカー·`21` ベビーニュート, 보스·사건 몬스터가 아닌 앞 번호)을 쓰기 전 69개, 쓴 뒤 66개가 남습니다(대역에서 풀린 `10` スピニー 등 포함). 그림은 대역의 그림 레코드를 가리켜 원래 그림을 쓰지 않습니다.

## 편성

구역 레코드는 [조우](dq4-field-format.md#구역-레코드)의 규칙 그대로입니다. 더한 것은 FC 구역 `17` 의 칸 12 필드 편성 `0B`(ひとくいそう·ダックスビル 하나씩)입니다. 3장 필드 구역의 편성만 DQ5 칸 10 고정 무리로 옮기고(`field_formations`), 무리 번호는 던전 편성 뒤에 붙여(`dungeon_fixed(prg, fc, field)`) 던전 무리 번호가 그대로입니다. 지금 롬에서 무리 4 입니다. 편성 몬스터도 `MONSTERS` 번호입니다(1장 탑 무리 0·1 의 킬러 스콥 `B6`·덕스 빌 `A5`·릴리펏 `E3`·거대한 닭 `3D`, 북쪽 동굴 무리 2 의 버블 슬라임 `C5`, 여신상 동굴 무리 3 의 에레프 로파 `9D`).

## 밤에만 나오는 칸

FC 필드는 첫 무리를 고를 때 낮이면 칸 4·10·13, 밤이면 칸 0·6 을 뺍니다. 3장 구역에서 빠지는 칸은 낮의 `15` 칸 10(ホイミスライム 한 무리), `16`·`17` 칸 4·10(メラゴースト)뿐이고 밤에 빠지는 칸 0·6 은 비어 있습니다. 칸 마스크·무게·셋째 무리는 1~3장 모든 구역에 같은 훅으로 FC 대로 고릅니다([무리 고르기](dq4-field-format.md#무리-고르기)).

## 전투 뒤 물건

FC 3장은 몬스터 떨어뜨림 대신 16칸 표를 씁니다. `25:8966`(`LDA $1116` / `CMP #$FF` / `BNE`)을 `JSL` 훅 / `BNE` 로 바꿨습니다.

- 3장 flag 가 꺼져 있으면 원래 판정(후보 몬스터 `$1116`)으로 돌아갑니다.
- 켜져 있으면 쓰러뜨린 수 `$111A` 가 `FF`(하나도 못 쓰러뜨림)면 떨어뜨리지 않습니다. 아니면 `00:953E` 의 rand(16) 칸부터 16칸을 돌며 rand(256) < 문턱이면 그 칸 물건을 얻습니다. 문턱 0 칸(はがねのつるぎ·てつのよろい)은 일행 기록 0 의 레벨 `7E:2052` 입니다.
- 얻으면 `$46` = 물건, `$42` = 0(메시지 이름은 칸 0 의 몬스터, 섞인 무리면 아래처럼 마물 무리)으로 두고 `25:89AA`(떨어뜨릴 물건을 읽는 곳)로 돌아가 DQ5 떨어뜨림 메시지·가방 넣기를 씁니다. 코드는 `4E:8000`~(몫 끝 `CH3_CODE_END` = `4E:C000`, 그 뒤는 엔돌 몫)이고 BRK 를 쓰지 않습니다(BRK 처리기가 놓인 뱅크를 DB 로 둠).
- 물건 짝: `01` 2, `02` 6, `04` 7, `05` 1(てつのやり 빌린 자리), `06` 12, `25` 67, `26` 72, `27` 77, `28` 80, `3D` 117, `3E` 118, `46` 134, `47` 135, `53` 161, `54` 162, `56` 164(10진, `dq5_drop_items`).
- 모형은 `drop_roll`·`drop_chance`(레벨 1·10·20 에서 21.8·27.2·33.0%)입니다.

메시지·이름은 1·2장과 같은 [전투 뒤 떨어뜨림](#전투-뒤-떨어뜨림1장부터)을 지납니다.

## 전투 뒤 떨어뜨림(1장부터)

FC `12:$9217`·`$9246` 은 마지막으로 쓰러뜨린 몬스터 칸(`$7200`, `11:$91F1`)의 물건을 그 칸의 확률로 떨어뜨리고, 메시지는 무리가 모두 한 종류면 `01C7`「…は たからばこを もっていた！」(이름은 그 종류, Ａ·Ｂ 없음), 아니면 `01C8`「まもののむれは たからばこを もっていた！」 입니다. DQ5 는 처음 쓰러뜨린 종류만 후보로 두고 다른 종류를 쓰러뜨리면 떨어뜨리지 않으며(`20:A363`), 메시지는 `0B1`「…は たからばこを おとしていった！」 입니다.

- `20:A363` 을 쓰러뜨릴 때마다 후보 `$1116` 를 그 종류로 바꿉니다(`dq4fieldencounter.LAST_KILL`).
- 물건·확률·이름을 읽는 종류는 `$1113`(`20:A170`, 몬스터가 빠질 때마다라 도망도 바꿈) 대신 쓰러뜨릴 때마다 쓰는 `$111C`(`20:A33E`)입니다(`25:8977`·`8984`, `DROP_SPECIES`). FC 의 `$7200` 도 쓰러뜨릴 때만 바뀝니다.
- `25:89BF`(`BRK 9E B1`)을 `JML 0B:FFA0` 으로(`drop_msg_code`): 무리 몬스터 사본 `7E:1156`~`1159`(전투 시작 `26:82B4`·부르기 `20:DAC2` 가 씀. 전투가 끝날 때 무리 `7E:1001`~ 는 비고 그림 종류 `7E:117C`~ 는 도망친 종류가 빠짐)의 `FF` 아닌 것이 모두 같으면 `0B1`, 아니면 `1A8`「마물 무리는 보물상자를 가지고 있었다!」. `0B1` 의 한글도 FC 뜻「…은 보물상자를 가지고 있었다!」 입니다. 덮인 다음 `BRK 9E 00` 은 이 코드가 하고 `25:89C5`(`BRK 16 35 00`, 사운드 패치가 효과음을 `3F` 로 바꾸는 자리)로 `RTL` 로 돌아갑니다. BRK 를 가리키는 `JML` 은 롬 장부 검사가 빈 자리로 뛴 훅과 가르지 못해 막습니다.
- FC 도망 실측(같은 틀에 はさみくわがた(`03`)만 HP `FF`·행동 여섯을 にげだす(`47`)·AI 0 으로, 5전): スライム 을 쓰러뜨린 뒤 はさみくわがた 가 도망친 전투(3번째)도 떨어뜨린 것은 スライム 의 물건이었고, 도망친 무리가 있으면 메시지는 `01C8` 이었습니다(4전). 쓰러뜨린 몬스터 없이 끝나면 떨어뜨리지 않았습니다.
- FC 실측(1장 필드, `18:$8046` 몬스터 0~3F 를 메모리에서 HP 1·늘 떨어뜨림·물건 = ID + 1 로 덮음, 11전): 떨어뜨린 물건은 모두 마지막으로 쓰러뜨린 칸(`11:$91F1` 의 X)의 몬스터 것이었고, 메시지는 무리가 한 종류(같은 종류 두 무리 `07 07` 포함)면 `01C7`, 둘 이상이면 `01C8` 이었습니다.
- 확인: `dq4monspecialcheck.py` 의 `drop-mixed`(スライム + エアラット, 마지막에 쓰러뜨린 エアラット 의 물건과 `1A8`, 고치기 전 롬은 떨어뜨리지 않음)·`drop-same`(スライム 두 무리, 물건과 `0B1`)·`drop-flee`(エアラット 가 도망, 쓰러뜨린 スライム 의 물건과 `1A8`).

## 떠돌이 상인

FC 3장 필드는 무리를 고르기 전에 rand(10) = 0 이면 たびのしょうにん(`AD`)이고 싸우지 않습니다(`18:$9D19`). rand(256) < 16 이면 여관(1인 10G), 아니면 도구점(やくそう·どくけしそう·せいすい·キメラのつばさ, 가게 그룹 `FE/FE`)입니다. 인물을 더하지 않고 조우 갈래로 옮겼습니다.

| 자리 | 하는 일 |
| --- | --- |
| `23:E8EE` 훅 | 3장 flag 이고 3장 필드 구역이면 `00:953E` rand(10). 0 이면 이벤트 스크립트(`A0` 네이티브 하나, `FF`)를 `$19B3`~`$19B5` 에 두고 `$19AE` bit7 을 켜, 걸음 수 `$1A9A` 를 0 으로 하고 `23:E7C2` 를 조우 없음(`PLB` / `PLP` / `CLC` / `RTL`)으로 끝냄 |
| 이벤트 네이티브 | rand(256) < 16 이면 대화 번호 `06`(특수 기능 여관), 아니면 `02`(도구점)를 인물 칸 `1F`(필드에서 비어 있음, 실측)의 대화 번호 `7E:36FF`·`7E:371F` 에 두고 DB `7E` 로 `06:AF1C`(A = 칸)를 부름. 필드에서 다른 인물에게 말을 걸 때와 같은 길 |
| 가게·여관 키 | 필드의 `$BC/$BD` 는 `01/00`(실측)이라 `dq4shopport.MERCHANT_MAP` 줄에 상인 키(지금 `72`)를 그룹 줄 뒤에 붙임. 도구 목록은 FC `FE/FE`, 여관 값은 `dq4shop.inn_price`(10). 앞 키 번호는 그대로 |
| `06:E462` 훅 | 여관에서 깬 뒤 `LDA $BC` / `CMP #$01` 은 그룹 01(DQ5 ラインハット 여관)이면 `01/00` (50,83)에 세우고, 아니면 `00:C6D8` 로 지금 맵을 실내로 다시 불러옴. 필드의 `$BC` 도 01 이고 `C6D8` 은 `$BE` 를 `80` 으로 두어 필드에서 자면 `01/00` 그림이 그려졌음. 필드(`$BE` bit7 꺼짐)면 낮밤 바꾸기 `06:D905` 의 필드 갈래 `06:D98E`(`01:A04B` 필드 다시 그리기·밝히기)로 감. D905 의 `PHP`/`PHB` 와 RTL 이 `06:E47F` 의 RTS 로 가는 돌아갈 곳을 쌓아 E43A 를 부른 JSR 로 돌아감 |

- 대사는 DQ5 도구점·여관 대화의 흐름에 FC 공용 대사(`0200`~`021A`·`0231`~`0237`)를 옮긴 한글입니다. FC 상인은 마을 도구점·여관과 같은 대사를 쓰므로 모든 가게·여관을 함께 바꿨습니다([시스템 메시지](dq4-josa-format.md#시스템-메시지)). 밤 여관은 「이렇게 늦은 밤까지」(`071`).
- 3장에서 キメラのつばさ(본몰 감옥 사건에 씀)를 사는 곳은 상인 밖에도 FC 도구점 셋입니다: レイクナバ `16/00`, ボンモール `05/01`, エンドール `04/00`(`dq4shop.lookup`, 모두 옮긴 가게 키 `64`·`65`·`66`). 3장 전용 전투 뒤 물건 칸 F(4/256)도 있습니다.
