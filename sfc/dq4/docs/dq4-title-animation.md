# 용과 구름이 움직이는 타이틀

[한글 타이틀 연결](dq4-title-format.md)의 페이드와 광택만으로는 대기 중 움직임이 부족했던 점을 보완합니다. 원래 한글 로고·IV·부제의 픽셀을 기준으로 삼고, 용과 배경은 애니메이션용 제작물을 사용합니다.

## NDS에서 확인한 움직임

NDS 한글판의 실제 실행 영상 30~34초 구간을 비교했습니다. 날개는 위로 펼침·수평·아래로 접힘·회복을 약 2.2~2.4초에 반복했습니다. 구름의 가리지 않은 영역은 1초에 왼쪽으로 약 10~11픽셀, 4초에 약 44픽셀 이동했습니다. 로고와 부제는 고정돼 있습니다. 이 수치는 촬영 영상의 표본 비교이며 원작 코드에서 추출한 주기가 아닙니다.

## 제작물과 표시 방식

`tools/dq4art/title-animation/`에 하늘 배경, 투명 용 날개 자세, 반복 구름 띠와 생성 기록을 둡니다. 용은 자세마다 바운딩 박스에 맞춰 크기를 바꾸지 않고 같은 배율과 몸통 기준점으로 배치합니다. 날개 움직임에 작은 상하 부유를 더하고, 구름은 서로 다른 속도로 왼쪽으로 흐릅니다.

화면을 매번 통째로 전송하지 않고 SFC의 표시 레이어를 나눕니다.

- BG1은 원래 한글 로고·IV·부제와 성을 고정해 표시합니다.
- BG2는 성과 산을 제거한 하늘을 그리며 하드웨어 스크롤로 이동합니다.
- OBJ는 용의 몸통과 날개를 표시합니다. 몸통을 고정하고 어깨 관절을 기준으로 별도 날개를 변환해 중간 움직임을 만듭니다.

Mode 3의 BG1 8bpp와 BG2 4bpp를 사용합니다. 원래 글자의 일부 타일은 검정까지 16색을 모두 사용하므로 4bpp에서 투명색을 따로 확보하면 원래 색 하나를 잃습니다. BG1을 8bpp로 표시하고 검정을 사용하지 않는 색 번호 16에 대응시켜 원래 RGB를 보존합니다.

용은 전용 팔레트를 사용합니다. 바뀐 타일만 전송하며 전송량과 전송 구간 수를 함께 제한합니다. 날개는 128개 중간 자세를 매 게임 프레임 갱신하며 약 2.1초에 한 바퀴 돕니다. 위치와 화면 상태도 매 게임 프레임 갱신합니다. 기존 음악과 입력 경로는 이어 쓰고 버튼 해제를 기다린 뒤 메뉴로 돌아갑니다.

메뉴 복귀 시에는 암전 상태에서 VRAM을 정리하고 DQ5의 원래 글꼴 초기화를 다시 실행합니다. 타이틀이 사용한 팔레트와 스프라이트 설정도 원래 게임 경로에 맞춰 복원합니다.

## 재현

```sh
uv run --locked python sfc/dq4/tools/dq4titlelayers.py --out work/dq4-title-layers
ASAR=/path/to/asar uv run --locked python sfc/dq4/tools/dq4titlelayerpatch.py --rom rom/dq5.sfc --input work/dq4-title-layers --out work/dq4-title-smooth/dq4-title-smooth.sfc
```

정지 타이틀용 `dq4titleassets.py`와 독립 미리보기는 별도로 유지합니다. 레이어 방식의 통합 롬은 2MiB이며 결과 롬·IPS와 실행 캡처는 `work/`에만 보존합니다. 실제 SFC 기기와 전체 게임 진행 검증은 별도입니다.

## 프레임과 전송 검증

128개 용 타일 프레임은 모두 서로 다르며 연속으로 같은 자세를 유지하는 구간이 없습니다. 가장 큰 차이 전송은 2,080바이트·14구간이고, 544바이트 OAM을 더하면 한 게임 프레임에 최대 2,624바이트를 전송합니다. 구름 좌표는 매 프레임 계산하지만 저해상도 정수 좌표이므로 실제 픽셀 이동은 정해진 간격으로 일어납니다.

빠르게 실행하는 MesenCE 테스트 모드의 화면 캡처는 최근 표시 화면을 재사용할 수 있습니다. 캡처가 두 장씩 같다는 사실만으로 게임이 30Hz로 갱신된다고 판단하지 않습니다. 연속 301게임 프레임의 실제 OAM과 표시 중인 OBJ VRAM을 읽어 128개 위상이 한 프레임씩 진행하는지 대조합니다. 영상의 표시와 내부 메모리 갱신은 별도 근거로 확인합니다.

미사용 OBJ는 X 좌표를 화면 밖에 두는 것만으로는 충분하지 않습니다. 32픽셀 스프라이트의 Y가 240이면 위쪽으로 감기며 주사선 개수 제한에 영향을 줄 수 있습니다. 미사용 OBJ의 Y를 224로 두어 표시 영역 밖인 224~255줄에 머물게 합니다. 실제 화면과 에뮬레이터의 스프라이트 제한 플래그를 함께 확인합니다.

최종 2MiB 롬 SHA-1은 `4f4a83a6e7bd8c25cdf0f9e1247c7a936a1077aa`입니다. 독립 렌더러로 연속 화면 1,001장을 비교해 가시 영역 57,344픽셀이 모두 일치했고, 구름 순환 경계에서도 차이가 없었습니다. 연속 301프레임의 VRAM·OAM은 128개 위상 전체와 일치했습니다. 스프라이트 초과 플래그는 여전히 켜져 있으므로 플래그가 0이라고 주장하지 않으며, 검증한 가시 영역의 픽셀 손실이 없다는 결과와 구분합니다.
