# DQ4 2장 첫머리

[1장 끝](dq4-chapter1-format.md#왕에게-보고와-1장-끝)의 서술 뒤에 2장 「말괄량이 공주의 모험」으로 넘어가, 산트하임 왕좌의 방에서 2장을 시작하는 명세입니다. 무대는 [그룹 연결](dq4-environment-format.md#그룹-연결)이 그룹 `3D` 에 넣은 산트하임 성이고, 대사는 NDS 2장 대사(`MESS/ja/b0002000.mpt`)의 일본어 원문을 옮겼습니다. 도구는 `sfc/dq4/tools/dq4ch2event.py` 이고 `dq4chapter1.py build` 가 얹습니다.

| 넣는 것 | 자리 |
| --- | --- |
| 2장으로 옮기는 네이티브·아리나 기록·이름 | `5E:F000`~ |
| 주인공 그림 훅 | `05:D9A1`(주인공 갈래)을 `JSL` + `RTS` 로 |
| 깃발 | `7E:2208` bit4 2장 진행 중, bit6 첫머리 대기. 산트하임 성은 아래 「[산트하임 성](#산트하임-성)」 |
| 필드 걸음 훅 | `00:82CB`(`LDA $7E2190`)을 `JSL` 로. 걷어찬 뒤 네 걸음째에 두 사람 합류 |
| 첫머리 연출 인물 | `3D/01` 의 왕 자리. 스크립트는 DQ5 `21/09` 인물(`05:C6C3` 0번, `05:C6CA`)을 빌림 |
| 한글 대사 | NDS 서두 서술 3쪽, 부르는 소리 1쪽, 왕의 말 4쪽 |

## 일행: 주인공 기록을 아리나로

DQ5 사람 동료 칸(인물 번호가 이름 표·그림 표를 고름, [사람 합류](../../dq5/docs/dq5-data-format.md#일행에-들-때-join))에 아리나를 넣고 주인공(인물 `00`)을 빼면, 이름과 그림은 저절로 따라오지만 필드로 나갈 수 없었습니다. 1장 롬에서 배 선실 세이브스테이트로 일행 기록 0 만 인물 표 칸 4(ビアンカ)·5(サンチョ)·9(ヘンリー)로 덮고 `dq5warp.lua` 로 필드에 나가자 셋 모두 `01/00` 을 불러오다 멈췄습니다(3000프레임 `timeout phase=load`). 같은 덮기를 주인공 기록 뒤에 둔 일행(칸 0·4)은 필드 (78,154)까지 걸었습니다. 산트하임 왕좌의 방(`3D/01`)은 주인공 없는 일행으로도 들어가 걸을 수 있었습니다.

그래서 2장 동안 일행 기록 0 은 인물 `00` 그대로 두고, 값만 아리나로 덮습니다.

| 기록 | 아리나(FC 처음 기록 7 「ひめ」) |
| --- | --- |
| `+2`·`+E` HP, `+4`·`+10` MP | 16, 0 |
| `+6` すばやさ, `+7`~`+A` ちから·みのまもり·かしこさ·うんのよさ | 7, 12, 8, 4, 1(FC たいりょく 는 1장처럼 みのまもり 자리) |
| `+B`~`+D` 경험치, `+12` 레벨 | 0, 1 |
| `+14`·`+15` 장비 비트, `+16`~`+21` 물건 | `01 00`, きぬのローブ(DQ5 `62`) 하나 |
| `+23`~`+25` 배운 주문 | 0 |

나머지 바이트(`+1`, `+13` 최대 레벨, `+26`~`+28` 다음 레벨 경험치, `+29`)는 원래 롬의 주인공 틀(`23:C014` 칸 0)을 씁니다. 이름 `7E:2001`~ 8바이트는 「아리나」의 한글 이름 바이트([게임 안 이름](dq4-name-entry-format.md#게임-안-이름))로 씁니다.

1장의 라이안 기록과 이름 입력값은 사람 동료 칸(`7E:294A`, 32바이트 × 5)에 맡겨 둡니다. 칸 첫 바이트 bit7 이 찬 칸 표시라 칸마다 `+1` 부터 씁니다. 라이안 기록 42바이트는 칸 2 의 `+1`(`7E:298B`~, 31바이트)과 칸 3 의 `+1`(`7E:29AB`~, 11바이트)에 나눠 두고, 이름은 칸 4 의 `+1`(`7E:29CB`~)입니다. 이 칸을 쓰는 DQ5 장면(ルイーダ·결혼식·석상)은 이 해킹에 없고, 5장에서 라이안이 돌아올 때 되돌릴 자리입니다. 저장은 `7E:2000`~`2A9F` 를 옮기므로 이 칸도 저장됩니다(코드 읽기).

## 1장 끝에서 옮기기

1장 끝 인물의 스크립트는 서술 → 화면 어둡게(`darken`) 뒤 `37` 로 `transfer` 를 부릅니다. `transfer` 가 하는 일:

1. 라이안 기록·이름을 맡기고, 아리나 기록·이름을 씁니다.
2. 필드 시간 `$075E` 를 `0050`(아침), 금화 `7E:2019` 를 100 으로 둡니다(FC 2장 시작 금화).
3. 일행 수 `201D`·`201E`·`201F` 를 1, 순서 `2020`·`2028` 을 0, 마차 비트(`201C` bit7)를 끕니다.
4. 2장 깃발(`2208` bit4)과 첫머리 대기 깃발(`2208` bit6)을 켭니다.
5. 이벤트 스크립트를 겁니다: 맵 곡 건너뛰기(`21A5` bit6)를 켜는 네이티브(`A0`) 뒤 `90 3D 01 12 11 01 80`(맵 이동, FC (09,08) 왕 앞).

## 첫머리

`3D/01` 을 불러올 때 [장 제목 상자](dq4-chapter1-format.md#검은-화면과-장-제목-상자)의 맵 훅이 주화면을 BG3 만으로 둡니다. 장면 `dq4chapterbox.CHAPTER2` 는 맵 `3D/01` 에 깃발 없이 `since`(첫머리 대기 깃발)만 둡니다. 맵 훅은 장면마다 「그 맵이고, `flag` 가 있으면 꺼져 있고, `since` 가 있으면 켜져 있음」을 봅니다. 그래서 1장에 산트하임에 걸어 들어오거나 첫머리 뒤에 다시 들어와도 맵을 검게 불러오지 않습니다.

인물은 첫머리 대기 깃발이 켜져 있는 동안의 대체 목록 `ch2_opening` 입니다. [옮긴 인물](dq4-environment-format.md#인물) 목록 그대로에서 왕(FC (09,07) → 셀 (18,15))만 스크립트 인물로 바꿉니다. 왕의 스크립트:

| 명령 | 하는 일 |
| --- | --- |
| `3F` | 조작 막기 |
| `37` box2 | 검은 화면에 「제2장  말괄량이 공주의 모험」 상자 |
| `21` | 서두 서술 3쪽(NDS 2002·2003, FC 0305 앞 두 쪽) |
| `37` reveal | 맵 곡을 틀고 맵을 밝힘 |
| `21` | 「공주님! 아리나 공주님! 부왕께서 부르십니다!」(NDS 2004) |
| `21` | 왕의 말 4쪽(NDS 2008~2011, FC 0306) |
| `11` | 첫머리 대기 깃발 끄기 |
| `40`·`16` | 조작 풀기, 멈춤 |

처음에는 「2장 깃발 꺼짐 → 옮긴 목록 사본」, 「첫머리 마침 깃발 꺼짐 → 첫머리 목록」 두 대체 목록으로 1장의 걸음을 갈랐습니다. 1장 진행 대사가 들어간 뒤 대체 목록 자리 `39:9000` 이 28,676바이트로 한 뱅크(28,672바이트)를 4바이트 넘어 빌드가 멈췄습니다. 사본 목록을 없애려고 깃발 하나(첫머리 대기)를 옮길 때 켜고 끄는 꼴로 바꿨습니다.

## 주인공 그림

`05:D98F` 는 일행 순서마다의 그림 번호를 정합니다. 주인공 갈래 `05:D9A1`~`D9B5`(21바이트, `2190` bit6·`21BE` bit5 로 `2E`·`2D`·`3A`)를 `JSL` 네이티브 + `RTS` 로 덮습니다. 네이티브는 2장 깃발이 켜져 있으면 `30`(DQ5 어린 ビアンカ, 인물 04 의 그림)을, 아니면 원래와 같은 규칙으로 고른 그림을 A 에 두고 돌아갑니다. 아리나 그림은 [스프라이트](dq4-sprite-format.md) 일의 몫이고, 그때까지 이 그림을 대역으로 씁니다.

## 검증

1장 롬에서 배 선실 세이브스테이트로 `36/00` (32,72)에 보고 깃발(`2197|80`)·보스 깃발(`21B9|40`)을 켜고 내려, A 를 90프레임마다 누르며 100프레임마다 찍었습니다.

| 프레임 | 맵·셀 | `2208` | 화면 |
| --- | --- | --- | --- |
| 100 | `36/00` (32,72) | `00` | 1장 끝 서술 |
| 300 | `3D/01` (18,17) | `50` | 검은 화면의 2장 제목 상자, 이어 서두 서술 |
| 900 | `3D/01` (18,17) | `50` | 왕좌의 방이 밝아지고 「공주님! 아리나 공주님!」, 왕의 말 |
| 1500 | `3D/01` (18,17) | `10` | 조작이 풀림. 상태 창 「아리나 H 16 M 0 レ: 1」 |

- 일행 기록 0 은 `00 80 10 00 00 00 07 0C …`(HP 16, すばやさ 7, ちから 12), 일행 수 1, 금화 100, `$075E` = `0050` 이었습니다. 맡긴 칸에 원래 주인공 기록(`00 80 18 00 …`)이 남았습니다.
- 왕 아래 칸에 ビアンカ 그림의 주인공이 서고, B 로 창을 닫은 뒤 걸었습니다.
- 첫머리 뒤 왕에게 말을 걸면 옮긴 인물의 일본어 원문(「どうした アリーナ？」, FC 07A0)이 나옵니다.

## 산트하임 성

FC 2장의 차례는 왕이 여행을 막음 → 성문 병사·브라이·크리프트와 이야기 → 왕의 방 벽을 걷어차고 나감 → 필드 네 걸음째에 두 사람이 따라옴입니다([FC 2장 진행](../../../fc/dq4/docs/dq4-story-format.md#장마다-진행-순서--플래그) 1~5). 그룹 `3D` 의 FC 그룹 셋(`01`·`0E`·`0F`)은 `dq4groupbuild.LINKS` 에 `"chapter": 2` 를 주어 2장 시작 상태로 옮기고, 그 메시지는 `dq4ch2talk.TEXTS` 의 한글로 덮습니다(산트하임 30개·텐페·프레놀 22개, 그룹 `3D` 52개에 남은 일본어 0). 텐페 촌장의 부탁(FC 대화 `02C`)은 물음과 「예」 쪽 대답을 잇습니다(1장의 예·아니요 대사와 같은 방식).

| 깃발 | 자리 | FC |
| --- | --- | --- |
| 성문 병사와 이야기함 | `7E:219D` bit0 | `$627E`&`02` |
| 브라이와 이야기함 | `7E:2196` bit1 | `$627E`&`04` |
| 크리프트와 이야기함 | `7E:2196` bit3 | `$627E`&`08` |
| 셋 다 이야기함 | `7E:2197` bit2 | (FC 는 셋을 따로 봄) |
| 벽을 걷어참 | `7E:2197` bit6 | `$627F`&`02` |
| 두 사람이 동료가 됨 | `7E:21EA` bit1 | `$627F`&`01` |
| 벽 앞의 물음에 대답함 | `7E:21A3` bit0 | 맵을 옮기면 지워지는 칸 |

`219D` bit0 은 롬에서 켜는 곳도 보는 곳도 없고, `2196` bit1·bit3·`2197` bit2·bit6 은 DQ5 레ヌール城(`04/06`·`04/07`·`04/02`·`04/01`)의 인물 스크립트·맵 루틴만 봅니다(`dq5flags.py`). 1장이 빌린 `2196` bit0 과 같은 묶음입니다. `21EA` bit1 은 [DQ5 플래그](../../dq5/docs/dq5-flags.md#시험하는-곳이-없는-비트)의 보지 않는 비트입니다(`21EA` 는 bit7 과 `50/51` 맵 HDMA 의 bit0 만 읽힘). 처음 고른 `21E1` bit1·`2196` bit7 은 우물 아래 조우 스위치·성 앞 노인이 먼저 쓰게 되어 옮겼습니다.

- **대화 스크립트**: 성문 병사 둘(FC 대화 `021`·`022`), 브라이(`01F`), 크리프트(`023`), 낮의 왕(`01A`)은 2장 대화로 바꿉니다. 병사·브라이·크리프트는 자기 깃발을 켜고, 셋이 모두 켜졌으면 「셋 다」를 켭니다. 왕은 FC 07A0 → 예 07A1 / 아니요 07A2 입니다. 대사는 NDS `b0002`(2016~2018·2030~2032·2062·2070·2080~2082)를 옮겼습니다.
- **성문**: FC 문지기는 문간 (0E·0F,19)에 서서 막습니다. 옮긴 인물은 걸어 다녀 (26,51)·(30,50)으로 비켜 틈이 생겼으므로(실측) 이동 간격을 0 으로 둡니다. 두 사람이 합류한 뒤의 `3D/00` 은 문지기가 FC 한 칸씩 바깥으로 비켜서 「잘 돌아오셨습니다」(FC 0322)라고 하는 목록입니다.
- **벽 앞의 수리공**: FC `01/02` 인물 1((0D,04), 대화 `01D`)은 낮에 셋과 이야기하기 전까지 벽 앞에 서 있습니다(FC `1C:$A0F7`). 옮긴 수리공은 셀 (26,9), 벽 앞의 주인공은 (26,10)이라 칸을 막지 못했습니다(실측). 그래서 기본 목록의 「묻는 인물」은 밤에만 두고, 「셋 다」 목록은 수리공을 빼고 묻는 인물을 낮·밤 모두 둡니다. 밤에는 FC 처럼 셋과 이야기하지 않아도 걷어찰 수 있습니다.

### 벽 걷어차기

FC 는 `01/02` (0D,04)에서 오른쪽을 보고 しらべる 하면 발밑 특수 표 `EC`(`1E:$B8AD`)가 0308 「벽을 조사했다 … 걷어차겠습니까?」를 묻습니다. DQ5 의 「조사」는 앞에 선 인물의 대화를 부르지 않아(왕 앞에서 조사하자 「발밑을 조사했다!」), 보이지 않는 인물이 그 칸과 방향을 기다립니다.

| 명령 | 하는 일 |
| --- | --- |
| `09` | 2장 깃발을 기다림(1장에 걸어 들어와도 묻지 않음) |
| `05` `at_wall` | 주인공(슬롯 0)이 셀 (26,10)이고 `7E:31E0` 위 니블이 `1`(오른쪽)일 때까지 |
| `37` `talk_here` | 이 인물과의 대화(서장의 「대화 걸기」와 같은 루틴): 물음 → 예면 0390 「벽을 걷어찼다!」·걷어참 깃발. 어느 쪽이든 대답 깃발 |
| `09`·`11`·`06` | 대답 깃발을 기다렸다 끄고, 걷어참 깃발이면 아래로. 아니면 그 칸을 떠날 때까지(`away_wall`) 기다렸다 처음으로 |
| `3F`·`37` `open_wall`·`37` `kick` | 판자 벽 2×2 셀(28~29, 9~10)을 같은 줄 FC 두 칸 왼쪽 바닥 셀의 `+1`~`+7` 로 덮고 다시 그림(1장 철창 열기와 같은 꼴). 걸음 수를 0 으로 두고 이벤트 `01 04 91 FF`(오른쪽 네 셀, 필드로) |

- 이벤트 `91` 은 맵을 떠나 필드로 나가고, [입구별 도착](dq4-environment-format.md#입구별-도착)의 나가기 훅이 산트하임 나오는 칸 (78,149)에 세웠습니다(실측).
- FC 는 구멍을 지나 `01/01` 지붕 (19,03)으로 나간 뒤 필드로 나갑니다(FC 롬에서 `$627F` = `02` 로 `01/02` (0D,04)에 워프해 오른쪽으로 걸음). 포팅 롬은 구멍 너머 물 칸이 탑 벽에서 막혀 맵 끝까지 가지 못하고, 지붕으로 이을 영역 이동도 없어 곧바로 필드로 나가게 했습니다.
- 걷어찬 뒤 왕의 방에 들어오면 「걷어참」 목록의 보이지 않는 인물이 `open_wall` 만 부르고 숨어, 구멍이 열려 있습니다.

### 두 사람 합류

FC 는 그룹 `01` 에서 나가면 `1E:$919F` 가 `$6281` bit5 를 켜고, 필드 걸음마다 `1E:$9863` 이 세어 4 가 되면 030A 를 띄우고 두 사람을 일행에 넣습니다. 포팅 롬은 필드 걸음마다 도는 `00:8290` 의 시간 올리기 앞 `00:82CB`(`LDA $7E2190`, 4바이트)를 `JSL` 로 돌립니다. 네이티브는 2장 깃발·걷어참 깃발이 켜지고 합류 깃발이 꺼져 있으면 `7E:1C0A` 를 하나 올리고, 4 가 되면 합류 깃발을 켜고 합류 이벤트를 겁니다. 끝에 원래 명령을 하고 돌아갑니다.

| 합류 이벤트 | |
| --- | --- |
| `60` | 030A: 브라이·크리프트의 말, 「브라이와 크리프트가 동료가 되었다!」 |
| `A0` `join` | 기록 둘을 일행 기록 1·2 에 복사, 일행 수 3, 순서 0 1 2, 일행마다 `21:805A` 로 다음 레벨 경험치, 걷는 일행 그림을 다시 세움(1장 [따라 걷는 그림](dq4-chapter1-format.md#따라-걷는-그림)과 같은 루틴) |

## 남은 2장 맵

FC 그룹 넷(サラン `13`, 사막의 바자 `0C`, 西の塔 `2E`, 남쪽 동굴 `39`, 맵 14개)을 새 그룹 `45` 에 넣었습니다(4장이 먼저 `41`~`44` 를 씀)([그룹 연결](dq4-environment-format.md#그룹-연결)). 빌린 자리에 있던 `13/04`(`0A/02`)와 `2E/00`(`0B/03`)은 빌린 자리에서 뺐습니다. 네 그룹은 2장 시작 상태(`"chapter": 2`)로 인물·가게를 옮기고 메시지 35개를 한글로 덮었습니다(`dq4ch2talk.TEXTS`, 남은 일본어 0). 입구별 도착 훅의 표가 그룹이 늘어 `3C:FE00` 의 가게 키 루틴과 겹쳐, 훅을 비어 있는 `5B:8000` 으로 옮겼습니다.

- 탑과 동굴은 1장 탑(`33/00`, 곡 `0A`)·동굴(`21/02`, 곡 `09`)의 속성을 빌리고 FC 던전 구역(탑 `4E`·`4F`, 동굴 `4C`·`4D`)을 씁니다. 두 구역에만 나오는 FC 몬스터 여섯은 같은 구역의 다른 몬스터가 받은 DQ5 자리 표시를 씁니다(`dq4fieldencounter.MONSTERS`).
- 그룹 `45` 의 상자는 아직 넣지 않습니다(`dq4chestport.NO_CHESTS`). DQ5 는 일반 상자 번호를 표 전체로 매기고 열림 비트를 `7E:2210` 부터 두는데, 1~4장 상자를 놓은 뒤 이 그룹의 상자를 더하면 번호가 「두 칸 앞」 표가 쓰는 `7E:2228` 의 비트에 닿아 `dq5chestplace.py` 가 거부했습니다. 대체 표에는 남쪽 동굴의 おうごんのうでわ→ゴールドオーブ, うまのふん→やくそう 를 넣어 두었습니다.
- 바자 가게의 판매 조건에 FC 대화 스크립트의 시간 조건 `day` 가 붙어 있어, 상점 조건의 「낮」·「밤」으로 읽습니다.
- エンドール 쪽 여행의 문 사당(`1E`)은 FC 출구 종류 `0A`(여행의 문)를 옮길 DQ5 출구가 아직 없어 넣지 않았습니다.
- 검사: 인물 없는 그룹 빌드 롬에서 `dq4groupcheck.py --groups 45` 통과(계단·필드 출입·도착 머무르기). 1장 롬에서 `dq4npccheck.py --chapter1` 으로 `45/00`~`06`·`09` 43장면 통과(탑 꼭대기 `2E/00` (17,01)·(17,02)의 말 상대 없는 인물은 벽 칸이라 `STAGED`).

## 텐페 제물 사건(앞 절반)

텐페(`3D/03`, FC `0E/00`)에서 촌장에게 괴물 퇴치를 맡겠다고 하고, 신부에게 니나 대신 제물이 되겠다고 하면 바구니에 실려 마을 북쪽 제단 앞으로 옮겨집니다. 보스 전투는 아직 없습니다.

| FC | 포팅 |
| --- | --- |
| 촌장 (15,25) 대화 `02C`: 07C2 질문 → 예 07C3 + `$6281&10`, 아니요 07C4 | 대화 `chief`: 들음 flag 가 꺼져 있으면 07C2 질문 → 예 07C3 + 들음, 아니요 07C4. 켜져 있으면 NDS 3541·3542 |
| 신부 (0C,18) 대화 `029`: `$6281&10` 이면 07C5 질문 → 예 07C6 + 1C 이벤트 01 + `$6281&08`, 아니요 07C7 뒤 교회. `$6281&08` 이면 0347. 둘 다 아니면 교회 | 대화 `priest`: 대신 감 flag 가 켜져 있으면 0347. 아니고 들음이 켜져 있으면 07C5 질문 → 예 07C6 + 대신 감, 아니요 07C7 뒤 교회. 둘 다 아니면 교회 |
| 1C 이벤트 01: 바구니에 태워 제단으로 | 신부는 빌린 스크립트(`21/00` 목록 `05:C433` 칸 0, `05:C43A`)로 대신 감 flag 를 기다렸다가(`09`) 제단 flag 를 켜고(`10`) 바구니 이벤트를 겁니다(`37`) |

| flag | 자리 | 뜻 |
| --- | --- | --- |
| 들음 | `7E:2208` bit0 | 촌장의 부탁에 「예」(FC `$6281&10`) |
| 대신 감 | `7E:2208` bit1 | 신부에게 대신 가겠다고 함(FC `$6281&08`) |
| 제단 | `7E:2208` bit2 | 바구니에 실려 제단 앞으로 옮겨짐 |

세 비트는 `dq5flags.py` 로 DQ5 롬에서 켜는 곳·끄는 곳·보는 곳이 없는 것을 골랐습니다. 제단 flag 가 켜지면 `3D/03` 은 대체 목록 `ch2_tempe_altar` 를 씁니다. 그 목록의 신부는 대화만 `priest` 이고 스크립트가 없어, 옮긴 뒤 맵을 다시 불러와도 이벤트가 다시 걸리지 않습니다.

교회는 대화 스크립트의 `00` 명령으로 DQ5 교회 처리기 `06:E03E`(특수 대화 `05`, `06:DBDB` 표)를 부릅니다. 원래 길(`06:DBD2`)은 처리기 뒤 `STZ $0F20` 을 하지만, 스크립트에서 부르고 「나가기」로 끝낸 뒤에도 걷기·명령 창이 그대로 돌았습니다(실측). 처음에는 촌장에게 들은 뒤의 신부만 대체 목록으로 바꾸려 했으나, 대체 목록은 맵을 불러올 때만 고르므로 같은 방문 안에서 촌장 → 신부로 가면 교회가 나옵니다. 그래서 신부는 늘 이 대화이고 flag 로 갈립니다.

| 바구니 이벤트 | |
| --- | --- |
| `60` | 신부 「자, 어서 저 바구니 안으로……」(NDS 4006), 상인(4012), 남자(4014), 서술 「…제단으로 옮겨졌다.」「그리고 밤이 되었다……」 |
| `90 3D 03 2C 1F 01 80` | 텐페 셀 (44,31)(FC (16,0F))로 옮김. 걸기 전에 필드 시간 `7E:075E` 를 `00F8`(밤)으로 둡니다 |

대사는 NDS 2장 대사(`b0003000` 3534~3554, `b0004000` 4006~4014)의 일본어 원문을 옮기고 FC 와 견주었습니다. NDS 의 「준비는 됐는가?」(3551) 두 번째 질문과 신부의 말장난(4017~4019, 加護·カゴ)은 넣지 않았습니다.

### 제단에 닿았을 때

지금은 밤의 텐페 제단 두 칸 아래에 서고 아무 일도 일어나지 않습니다. FC 는 제단 슬롯 08~0A·13((15~18,0D))의 1D 이벤트 39·3A·3B 가 돌고, 슬롯 08 의 3B 가 1C 이벤트 02 로 전투 02(カメレオンマン 과 あばれこまいぬ 둘)를 겁니다. 이기면 034D, 아침, `$627F|=80`. 이 전투와 이긴 뒤의 마을은 다음 단계 몫이고, 제단 flag 를 보고 걸면 됩니다.

## 남은 것

- 텐페 보스 전투(제단 flag 를 보고 1C 이벤트 02)와 이긴 뒤의 마을, 텐페의 밤 색(그룹 `3D` 맵은 시간을 밤으로 두어도 어두워지지 않음), 제단으로 옮긴 뒤 신부의 말(지금은 0347 「자, 어서 저 바구니 안으로……」 그대로), 프레놀·바자·탑·무술 대회·빈 성의 사건, 여행의 문 사당([dq4 남은 일](../todo.md)).
- 두 사람의 처음 주문(FC 처음 주문 비트 크리프트 `02 00 01`·브라이 `01 00 00`)과 성장 표(지금은 ヘンリー·サンチョ 의 것).
- 합류 장면을 거쳐 두 사람이 뒤따르는지. 일행 기록 1·2 의 `+0` 만 `09`·`05` 로 둔 1장 롬 시험에서는 걷는 그림 `1967` = 3, ヘンリー `3B`·サンチョ `29` 가 뒤따랐습니다([1장 따라 걷는 그림](dq4-chapter1-format.md#따라-걷는-그림)).
- 걷어찬 구멍에서 지붕(`01/01`)으로 이어지는 FC 길.
- 벽을 걷어차지 않고 성문으로 돌아오는 길은 없습니다(문지기는 합류 뒤에만 비킴). FC 처럼 왕과 다시 이야기한 뒤 문지기가 길을 여는지(`$627B` bit1)는 보지 않았습니다.
- 산트하임 성 곡: 그룹 `3D` 맵 속성은 마을 곡 `0A` 라 밝힐 때 마을 곡이 납니다(FC 그룹 `01` 은 성 곡).
- 아리나·크리프트·브라이 그림과 아리나 레벨업 성장(지금은 DQ5 주인공 성장 표), 장비할 수 있는 물건. 아리나는 처음 입은 きぬのローブ 를 장비 창에서 다시 고르면 「아리나는 비단 로브를 장비할 수 없다.」가 나옵니다(DQ5 주인공 장비 표, 실측).
- 1장 가방(ふくろ) 물건과 1장 깃발은 그대로 남습니다.
- 저장을 불러온 뒤 그림 훅과 2장 깃발이 이어지는지(코드 읽기).
