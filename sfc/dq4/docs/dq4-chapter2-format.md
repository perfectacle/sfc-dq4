# DQ4 2장 첫머리

[1장 끝](dq4-chapter1-format.md#왕에게-보고와-1장-끝)의 서술 뒤에 2장 「말괄량이 공주의 모험」으로 넘어가, 산트하임 왕좌의 방에서 2장을 시작하는 명세입니다. 무대는 [그룹 연결](dq4-environment-format.md#그룹-연결)이 그룹 `3D` 에 넣은 산트하임 성이고, 대사는 NDS 2장 대사(`MESS/ja/b0002000.mpt`)의 일본어 원문을 옮겼습니다. 도구는 `sfc/dq4/tools/dq4ch2event.py` 이고 `dq4chapter1.py build` 가 얹습니다. 1장 끝에서 이 2장으로 넘어가는 것은 `--chapter2` 빌드(`dq4build.py --chapter2`)뿐입니다. 기본 빌드는 1장까지 배포하는 판이라 1장 끝에서 끝맺음 뒤 타이틀로 돌아갑니다([1장에서 끝내기](dq4-chapter1-format.md#1장에서-끝내기)). 2장 코드와 인물은 두 빌드에 모두 들어 있어, 깃발을 켜고 2장 맵으로 순간이동하는 실측은 기본 빌드로도 됩니다.

| 넣는 것 | 자리 |
| --- | --- |
| 2장으로 옮기는 네이티브·아리나 기록·이름 | `5E:F000`~ |
| 주인공 그림 훅 | `05:D9A1`(주인공 갈래)을 `JSL` + `RTS` 로 |
| 깃발 | `7E:2208` bit4 2장 진행 중, bit6 첫머리 대기. 산트하임 성은 아래 「[산트하임 성](#산트하임-성)」 |
| 필드 걸음 훅 | `00:82CB`(`LDA $7E2190`)을 `JSL` 로. 걷어찬 뒤 네 걸음째에 두 사람 합류 |
| 첫머리 연출 인물 | `3D/01` 의 왕 자리. 스크립트는 DQ5 `21/09` 인물(`05:C6C3` 0번, `05:C6CA`)을 빌림 |
| 한글 대사 | NDS 서두 서술 3쪽, 부르는 소리 1쪽, 왕의 말 4쪽 |

## 일행: 주인공 기록을 아리나로

DQ5 사람 동료 칸(인물 번호가 이름 표·그림 표를 고름, [사람 합류](../../dq5/docs/dq5-data-format.md#일행에-들-때-join))에 아리나를 넣고 주인공(인물 `00`)을 빼면, 이름과 그림은 저절로 따라오지만 필드로 나갈 수 없었습니다. 1장 롬에서 배 선실 세이브스테이트로 일행 기록 0 만 인물 표 칸 4(ビアンカ)·5(サンチョ)·9(ヘンリー)로 덮고 `dq5warp.lua` 로 필드에 나가자 셋 모두 `01/00` 을 불러오다 멈췄습니다(3000프레임 `timeout phase=load`). 같은 덮기를 주인공 기록 뒤에 둔 일행(칸 0·4)은 필드 (78,154)까지 걸었습니다. 산트하임 왕좌의 방(`3D/01`)은 주인공 없는 일행으로도 들어가 걸을 수 있었습니다.

그래서 2장 동안 일행 기록 0 은 인물 `00` 그대로 두고, 값만 아리나로 덮습니다.

| 기록 | 아리나(FC 처음 기록 7 「ひめ」) |
| --- | --- |
| `+2`·`+E` HP, `+4`·`+10` MP | 16, 0 |
| `+6` すばやさ, `+7`~`+A` ちから·みのまもり·かしこさ·うんのよさ | 7, 12, 8, 4, 1(FC たいりょく 는 1장처럼 みのまもり 자리) |
| `+B`~`+D` 경험치, `+12` 레벨 | 0, 1 |
| `+14`·`+15` 장비 비트, `+16`~`+21` 물건 | `01 00`, きぬのローブ(DQ5 `62`) 하나 |
| `+23`~`+25` 배운 주문 | 0 |

나머지 바이트(`+1`, `+13` 최대 레벨, `+26`~`+28` 다음 레벨 경험치, `+29`)는 원래 롬의 주인공 틀(`23:C014` 칸 0)을 씁니다. 이름 `7E:2001`~ 8바이트는 「아리나」의 한글 이름 바이트([게임 안 이름](dq4-name-entry-format.md#게임-안-이름))로 씁니다.

1장의 라이안 기록과 이름 입력값은 사람 동료 칸(`7E:294A`, 32바이트 × 5)에 맡겨 둡니다. 칸 첫 바이트 bit7 이 찬 칸 표시라 칸마다 `+1` 부터 씁니다. 라이안 기록 42바이트는 칸 2 의 `+1`(`7E:298B`~, 31바이트)과 칸 3 의 `+1`(`7E:29AB`~, 11바이트)에 나눠 두고, 이름은 칸 4 의 `+1`(`7E:29CB`~)입니다. 이 칸을 쓰는 DQ5 장면(ルイーダ·결혼식·석상)은 이 해킹에 없고, 5장에서 라이안이 돌아올 때 되돌릴 자리입니다. 저장은 `7E:2000`~`2A9F` 를 옮기므로 이 칸도 저장됩니다(코드 읽기).

## 1장 끝에서 옮기기

1장 끝 인물의 스크립트는 서술 → 화면 어둡게(`darken`) 뒤 `37` 로 `transfer` 를 부릅니다. `transfer` 가 하는 일:

1. 라이안 기록·이름을 맡기고, 아리나 기록·이름을 씁니다.
2. 필드 시간 `$075E` 를 `0050`(아침), 금화 `7E:2019` 를 100 으로 둡니다(FC 2장 시작 금화).
   맡긴 물건(`7E:2250`~`232F`, 물건 번호 `00`~`DF` 마다 개수)과 맡긴 금화(`7E:203A`, 16비트)를 0 으로 둡니다. FC 장 초기화가 가방(`$61DB`~, FC 는 맡긴 물건도 가방에 넣음)과 맡긴 돈(`$625B`)을 비우는 것(`15:$B39C`, [FC 가게 문서](../../../fc/dq4/docs/dq4-shop-format.md))과 같습니다. 그 뒤 칸(`2330`~)과 맡긴 동료 칸(`2332`~)은 건드리지 않습니다.
3. 일행 수 `201D`·`201E`·`201F` 를 1, 순서 `2020`·`2028` 을 0, 마차 비트(`201C` bit7)를 끕니다.
4. 2장 깃발(`2208` bit4)과 첫머리 대기 깃발(`2208` bit6)을 켭니다.
5. 이벤트 스크립트를 겁니다: 맵 곡 건너뛰기(`21A5` bit6)를 켜는 네이티브(`A0`) 뒤 `90 3D 01 12 11 01 80`(맵 이동, FC (09,08) 왕 앞).

## 첫머리

`3D/01` 을 불러올 때 [장 제목 상자](dq4-chapter1-format.md#검은-화면과-장-제목-상자)의 맵 훅이 주화면을 BG3 만으로 둡니다. 장면 `dq4chapterbox.CHAPTER2` 는 맵 `3D/01` 에 깃발 없이 `since`(첫머리 대기 깃발)만 둡니다. 맵 훅은 장면마다 「그 맵이고, `flag` 가 있으면 꺼져 있고, `since` 가 있으면 켜져 있음」을 봅니다. 그래서 1장에 산트하임에 걸어 들어오거나 첫머리 뒤에 다시 들어와도 맵을 검게 불러오지 않습니다.

인물은 첫머리 대기 깃발이 켜져 있는 동안의 대체 목록 `ch2_opening` 입니다. [옮긴 인물](dq4-environment-format.md#인물) 목록 그대로에서 왕(FC (09,07) → 셀 (18,15))만 스크립트 인물로 바꿉니다. 왕의 스크립트:

| 명령 | 하는 일 |
| --- | --- |
| `3F` | 조작 막기 |
| `37` box2 | 검은 화면에 「제2장  말괄량이 공주의 모험」 상자 |
| `21` | 서두 서술 3쪽(NDS 2002·2003, FC 0305 앞 두 쪽) |
| `37` reveal | 맵 곡을 틀고 맵을 밝힘 |
| `21` | 「공주님! 아리나 공주님! 부왕께서 부르십니다!」(NDS 2004) |
| `21` | 왕의 말 4쪽(NDS 2008~2011, FC 0306) |
| `11` | 첫머리 대기 깃발 끄기 |
| `40`·`16` | 조작 풀기, 멈춤 |

처음에는 「2장 깃발 꺼짐 → 옮긴 목록 사본」, 「첫머리 마침 깃발 꺼짐 → 첫머리 목록」 두 대체 목록으로 1장의 걸음을 갈랐습니다. 1장 진행 대사가 들어간 뒤 대체 목록 자리 `39:9000` 이 28,676바이트로 한 뱅크(28,672바이트)를 4바이트 넘어 빌드가 멈췄습니다. 사본 목록을 없애려고 깃발 하나(첫머리 대기)를 옮길 때 켜고 끄는 꼴로 바꿨습니다.

## 주인공 그림

`05:D98F` 는 일행 순서마다의 그림 번호를 정합니다. 주인공 갈래 `05:D9A1`~`D9B5`(21바이트, `2190` bit6·`21BE` bit5 로 `2E`·`2D`·`3A`)를 `JSL` 네이티브 + `RTS` 로 덮습니다. 네이티브는 2장 깃발이 켜져 있으면 `30`(DQ5 어린 ビアンカ, 인물 04 의 그림)을, 아니면 원래와 같은 규칙으로 고른 그림을 A 에 두고 돌아갑니다. 그림 `30` 의 세트는 NDS 아리나로 바꿨고, 실내에서 `02:CA5A` 가 두는 `2B` 는 인물 훅이 2장 깃발로 아리나 세트를 고릅니다([2장 인물](dq4-sprite-format.md#2장-인물)).

## 검증

1장 롬에서 배 선실 세이브스테이트로 `36/00` (32,72)에 보고 깃발(`2197|80`)·보스 깃발(`21B9|40`)을 켜고 내려, A 를 90프레임마다 누르며 100프레임마다 찍었습니다.

| 프레임 | 맵·셀 | `2208` | 화면 |
| --- | --- | --- | --- |
| 100 | `36/00` (32,72) | `00` | 1장 끝 서술 |
| 300 | `3D/01` (18,17) | `50` | 검은 화면의 2장 제목 상자, 이어 서두 서술 |
| 900 | `3D/01` (18,17) | `50` | 왕좌의 방이 밝아지고 「공주님! 아리나 공주님!」, 왕의 말 |
| 1500 | `3D/01` (18,17) | `10` | 조작이 풀림. 상태 창 「아리나 H 16 M 0 レ: 1」 |

- 일행 기록 0 은 `00 80 10 00 00 00 07 0C …`(HP 16, すばやさ 7, ちから 12), 일행 수 1, 금화 100, `$075E` = `0050` 이었습니다. 맡긴 칸에 원래 주인공 기록(`00 80 18 00 …`)이 남았습니다.
- 왕 아래 칸에 ビアンカ 그림의 주인공이 서고, B 로 창을 닫은 뒤 걸었습니다.
- 첫머리 뒤 왕에게 말을 걸면 옮긴 인물의 일본어 원문(「どうした アリーナ？」, FC 07A0)이 나옵니다.

## 산트하임 성

FC 2장의 차례는 왕이 여행을 막음 → 성문 병사·브라이·크리프트와 이야기 → 왕의 방 벽을 걷어차고 나감 → 필드 네 걸음째에 두 사람이 따라옴입니다([FC 2장 진행](../../../fc/dq4/docs/dq4-story-format.md#장마다-진행-순서--플래그) 1~5). 그룹 `3D` 의 FC 그룹 셋(`01`·`0E`·`0F`)은 `dq4groupbuild.LINKS` 에 `"chapter": 2` 를 주어 2장 시작 상태로 옮기고, 그 메시지는 `dq4ch2talk.TEXTS` 의 한글로 덮습니다(산트하임 30개·텐페·프레놀 22개, 그룹 `3D` 52개에 남은 일본어 0). 텐페 촌장의 부탁(FC 대화 `02C`)은 물음과 「예」 쪽 대답을 잇습니다(1장의 예·아니요 대사와 같은 방식).

| 깃발 | 자리 | FC |
| --- | --- | --- |
| 성문 병사와 이야기함 | `7E:219D` bit0 | `$627E`&`02` |
| 브라이와 이야기함 | `7E:2196` bit1 | `$627E`&`04` |
| 크리프트와 이야기함 | `7E:2196` bit3 | `$627E`&`08` |
| 셋 다 이야기함 | `7E:2197` bit2 | (FC 는 셋을 따로 봄) |
| 벽을 걷어참 | `7E:2197` bit6 | `$627F`&`02` |
| 두 사람이 동료가 됨 | `7E:21EA` bit1 | `$627F`&`01` |
| 벽 앞의 물음에 대답함 | `7E:21A3` bit0 | 맵을 옮기면 지워지는 칸 |

`219D` bit0 은 롬에서 켜는 곳도 보는 곳도 없고, `2196` bit1·bit3·`2197` bit2·bit6 은 DQ5 레ヌール城(`04/06`·`04/07`·`04/02`·`04/01`)의 인물 스크립트·맵 루틴만 봅니다(`dq5flags.py`). 1장이 빌린 `2196` bit0 과 같은 묶음입니다. `21EA` bit1 은 [DQ5 플래그](../../dq5/docs/dq5-flags.md#시험하는-곳이-없는-비트)의 보지 않는 비트입니다(`21EA` 는 bit7 과 `50/51` 맵 HDMA 의 bit0 만 읽힘). 처음 고른 `21E1` bit1·`2196` bit7 은 우물 아래 조우 스위치·성 앞 노인이 먼저 쓰게 되어 옮겼습니다.

- **대화 스크립트**: 성문 병사 둘(FC 대화 `021`·`022`), 브라이(`01F`), 크리프트(`023`), 낮의 왕(`01A`)은 2장 대화로 바꿉니다. 병사·브라이·크리프트는 자기 깃발을 켜고, 셋이 모두 켜졌으면 「셋 다」를 켭니다. 왕은 FC 07A0 → 예 07A1 / 아니요 07A2 입니다. 대사는 NDS `b0002`(2016~2018·2030~2032·2062·2070·2080~2082)를 옮겼습니다.
- **성문**: FC 문지기는 문간 (0E·0F,19)에 서서 막습니다. 옮긴 인물은 걸어 다녀 (26,51)·(30,50)으로 비켜 틈이 생겼으므로(실측) 이동 간격을 0 으로 둡니다. 두 사람이 합류한 뒤의 `3D/00` 은 문지기가 FC 한 칸씩 바깥으로 비켜서 「잘 돌아오셨습니다」(FC 0322)라고 하는 목록입니다.
- **벽 앞의 수리공**: FC `01/02` 인물 1((0D,04), 대화 `01D`)은 낮에 셋과 이야기하기 전까지 벽 앞에 서 있습니다(FC `1C:$A0F7`). 옮긴 수리공은 셀 (26,9), 벽 앞의 주인공은 (26,10)이라 칸을 막지 못했습니다(실측). 그래서 기본 목록의 「묻는 인물」은 밤에만 두고, 「셋 다」 목록은 수리공을 빼고 묻는 인물을 낮·밤 모두 둡니다. 밤에는 FC 처럼 셋과 이야기하지 않아도 걷어찰 수 있습니다.

### 벽 걷어차기

FC 는 `01/02` (0D,04)에서 오른쪽을 보고 しらべる 하면 발밑 특수 표 `EC`(`1E:$B8AD`)가 0308 「벽을 조사했다 … 걷어차겠습니까?」를 묻습니다. DQ5 의 「조사」는 앞에 선 인물의 대화를 부르지 않아(왕 앞에서 조사하자 「발밑을 조사했다!」), 보이지 않는 인물이 그 칸과 방향을 기다립니다.

| 명령 | 하는 일 |
| --- | --- |
| `09` | 2장 깃발을 기다림(1장에 걸어 들어와도 묻지 않음) |
| `05` `at_wall` | 주인공(슬롯 0)이 셀 (26,10)이고 `7E:31E0` 위 니블이 `1`(오른쪽)일 때까지 |
| `37` `talk_here` | 이 인물과의 대화(서장의 「대화 걸기」와 같은 루틴): 물음 → 예면 0390 「벽을 걷어찼다!」·걷어참 깃발. 어느 쪽이든 대답 깃발 |
| `09`·`11`·`06` | 대답 깃발을 기다렸다 끄고, 걷어참 깃발이면 아래로. 아니면 그 칸을 떠날 때까지(`away_wall`) 기다렸다 처음으로 |
| `3F`·`37` `open_wall`·`37` `kick` | 판자 벽 2×2 셀(28~29, 9~10)을 같은 줄 FC 두 칸 왼쪽 바닥 셀의 `+1`~`+7` 로 덮고 다시 그림(1장 철창 열기와 같은 꼴). 걸음 수를 0 으로 두고 이벤트 `01 04 91 FF`(오른쪽 네 셀, 필드로) |

- 이벤트 `91` 은 맵을 떠나 필드로 나가고, [입구별 도착](dq4-environment-format.md#입구별-도착)의 나가기 훅이 산트하임 나오는 칸 (78,149)에 세웠습니다(실측).

## 남은 2장 맵

FC 그룹 넷(サラン `13`, 사막의 바자 `0C`, 西の塔 `2E`, 남쪽 동굴 `39`, 맵 14개)을 새 그룹 `45` 에 넣었습니다(4장이 먼저 `41`~`44` 를 씀)([그룹 연결](dq4-environment-format.md#그룹-연결)). 빌린 자리에 있던 `13/04`(`0A/02`)와 `2E/00`(`0B/03`)은 빌린 자리에서 뺐습니다. 네 그룹은 2장 시작 상태(`"chapter": 2`)로 인물·가게를 옮기고 메시지 35개를 한글로 덮었습니다(`dq4ch2talk.TEXTS`, 남은 일본어 0). 입구별 도착 훅의 표가 그룹이 늘어 `3C:FE00` 의 가게 키 루틴과 겹쳐, 훅을 비어 있는 `5B:8000` 으로 옮겼습니다.

- 탑과 동굴은 1장 탑(`33/00`, 곡 `0A`)·동굴(`21/02`, 곡 `09`)의 속성을 빌리고 FC 던전 구역(탑 `4E`·`4F`, 동굴 `4C`·`4D`)을 씁니다. 두 구역에만 나오는 FC 몬스터 여섯은 같은 구역의 다른 몬스터가 받은 DQ5 자리 표시를 씁니다(`dq4fieldencounter.MONSTERS`).
- 그룹 `45` 의 상자 8개도 다른 그룹처럼 넣습니다([그룹 45 상자](#그룹-45-상자)). 대체 표에는 うまのふん→やくそう 를 넣어 두었습니다. 남쪽 동굴의 おうごんのうでわ 는 [사건 물건](#사건-물건과-도적의-열쇠-문)의 자기 자리 `C6` 로 갑니다.
- 바자 가게의 판매 조건에 FC 대화 스크립트의 시간 조건 `day` 가 붙어 있어, 상점 조건의 「낮」·「밤」으로 읽습니다.
- 여행의 문 사당 둘(`1E`·`1F`)은 그 뒤 `45/0E`·`45/0F` 로 넣었습니다([여행의 문 사당](#여행의-문-사당)).
- 검사: 인물 없는 그룹 빌드 롬에서 `dq4groupcheck.py --groups 45` 통과(계단·필드 출입·도착 머무르기). 1장 롬에서 `dq4npccheck.py --chapter1` 으로 `45/00`~`06`·`09` 43장면 통과(탑 꼭대기 `2E/00` (17,01)·(17,02)의 말 상대 없는 인물은 벽 칸이라 `STAGED`).

### 남은 것(텐페 뒤 절반)

- FC 는 전투 앞에 괴물(제단 슬롯 08~0A·13)이 일행 양옆으로 걸어 들어옵니다. 포팅은 쉼만 둡니다. 사건 인물 그림(카멜레온 맨 `10`, 날뛰는 석상 `31`)을 제단에 세우려면 텐페 한 맵의 OBJ VRAM 512타일을 먼저 잽니다.

## 사건 등록과 자원 예약

2장의 나머지 사건(텐페 뒤 절반, 프레놀·남쪽 동굴, 바자·왕 병·탑·사당, 엔돌 무술 대회, 빈 성·2장 끝, 동료 대화)은 세션마다 새 모듈로 만들어 `dq4ch2event.EVENTS` 에 이름 한 줄로 끼웁니다. 모듈끼리 같은 롬·WRAM 자리를 덮지 않게, 쓸 자원을 `sfc/dq4/tools/dq4ch2slots.py` 의 `SLOTS`(정본)에 미리 나눴습니다. 모자라면 그 표를 먼저 고치는 작은 PR 을 올립니다. `test_dq4ch2slots` 가 몫끼리·이미 쓰는 자원과 겹치지 않는지, 등록한 모듈이 자기 몫 안인지 봅니다.

### 모듈이 내놓는 것

모두 골라 씁니다. 함수는 `ctx`(`dq4ch2event.Context`)를 받습니다. `ctx.msg`·`ctx.talk` 는 이 모듈의 `{이름: 메시지 번호}`·`{이름: 대화 번호}`, `ctx.at` 은 이 모듈 네이티브의 `{이름: 주소}`(롬 없이 셈), `ctx.base` 는 `dq4ch2event.native()` 의 주소, `ctx.code_at` 은 예약한 코드 자리 첫 주소, `ctx.original` 은 원래 롬(주소만 셀 때는 `None`)입니다.

| --- | --- | --- |

| `MESSAGES` | `{이름: 부분 목록}` | `dq4ch2event.MESSAGES` 뒤에 등록 차례로 이어 붙임. 번호는 `ctx.msg` |

### flag 자리

스크립트가 다루는 flag 는 `7E:2190` + 번호(`00`~`7F`)뿐이라 `2190`~`220F` 안에서 골라야 합니다. 그 안에서 DQ5 가 비트로 쓰지 않는 자리는 `dq5flags.py` 로 셌을 때 195비트였지만 대부분 쓸 수 없습니다.

- `21DC`·`21DE` 의 빈 비트는 배의 필드 X·Y(`21DB`~`21DE`, `02:B9CB`·`B9D4` 등)를 16비트로 쓸 때 덮입니다. `21E0`·`21E5` 도 앞 바이트(`21DF`·`21E4`)를 바이트로 다시 쓰는 곳이 있습니다.
- `21EF`~`220F` 는 DQ5 가 색인 쓰기로만 덮습니다. `02:E053 STA $21EF,X`(X 8 부터 줄임)는 15/01 수수께끼 맵의 맵 루틴(`15:FE8D` 항목), `05:DF2A`·`E31D`·`E324` 의 `$21FA,X`·`$21FB,X` 는 31/07 바위 맵, `23:E20E`·`E214` 의 `$21F5,X`·`$21F6,X`(X `16` 부터 2씩 줄임)와 `23:E231`~ 의 `220D`~`220F` 는 `23:E1FE` 로, 이것을 부르는 곳은 파파스가 쓰러지는 장면 `02:9BFD` 하나입니다. 이 해킹의 맵 그룹은 `36`~`47`(`dq4groupbuild.LINKS`)이라 세 장면은 돌지 않습니다. 2장 첫머리의 `2208` 도 이 근거로 씁니다.
- 그래서 그 가운데 고정 주소로도 쓰이는 `21F5`·`21F6`·`21F8`~`21FB` 와 2장 첫머리가 비트째 쓰는 `2208` 을 빼고 `21F0`~`21F4`·`21F7`·`21FC`~`2207`·`2209`~`220C` 를 바이트째 나눴습니다. [1장](dq4-chapter1-format.md)은 같은 자리를 피했습니다. 이 해킹에 DQ5 15/01·31/07 이나 파파스 장면을 되살리는 일이 생기면 이 표를 다시 봐야 합니다.

`test_dq4ch2slots` 는 롬이 있으면 `dq5flags` 의 모든 출처에서 예약 바이트가 나오지 않는지, 롬 없이도 다른 도구가 예약 바이트를 롱 주소로 적지 않는지 봅니다.

### 사건 전투

`dq4ch2battle.py` 는 1장 탑 위 보스 진입(`dq4ch1event._battle`)을 일반화한 것입니다. 뱅크 06 의 공용 루틴(`06:FF58`, 41바이트)이 A(8비트) 의 무리 번호로 `01:868B` 를 부릅니다. 걸기 전에 `2208` bit7 을 끄고, 결과가 `80`(전멸)이 아니면 켭니다. 전멸이면 `01:868B` 가 보통 전투처럼 전멸 처리(`01:88ED`)를 합니다. 사건 flag 는 부른 쪽이 `2208` bit7 을 보고 켭니다.

```
06:FF58  PHP / SEP #$30 / PHB / PHK / PLB / PHA
         LDA $7E2208 / AND #$7F / STA $7E2208
         BRK 0E / PLA / JSL $01868B
         CMP #$80 / BEQ +10 / LDA $7E2208 / ORA #$80 / STA $7E2208
         PLB / PLP / RTL
06:FF81 + 9k  SEP #$20 / LDA #무리 / JSL $06FF58 / RTS        대화 입구 k(0~4)
```

| 부르는 곳 | 쓰는 것 |
| --- | --- |
| 대화 스크립트 | `dq4ch2battle.talk_call(k)`(`{"op": "call", "target": "FF81"}` 꼴. 대화의 `call` 은 뱅크 06 안 주소만 받음) 뒤 `{"op": "if", "cond": dq4ch2battle.won_cond(), …}` |
| 네이티브(인물 스크립트 `37`, 이벤트 코드) | `dq4ch2battle.far(무리)` 바이트(`SEP #$20 / LDA #무리 / JSL $06FF58`)를 자기 코드 안에. 그 뒤 `7E:2208` bit7 을 봄 |
| 인물 스크립트의 기다림·뛰기 | `09`·`06` 에 `0x78`·`0x80` |

무리는 모듈의 `BATTLES` 에 `{"group": 31, "members": ((몬스터, 마릿수), …), "stub": 0}` 으로 적습니다. 플래그 기본은 도망칠 수 없음·보스 곡(`42`, 1장 보스와 같음)이고 `"flags"` 로 바꿉니다. 곡 번호를 바꾸는 자리는 Z 세션 몫입니다.

## 사건 물건과 도적의 열쇠 문

2장 사건이 주고받는 물건 셋을 DQ5 물건 번호에 두었습니다. 사건 코드는 이 번호로 물건을 주고(일행에 넣기)·묻습니다(`BRK 88 90 n`·`BRK 90 90 n`, 대화 조건 `11`). 이름은 [채택 표](../../../nds/dq4/tables/adopt.tsv)의 것입니다.

| 물건 | FC 번호 | DQ5 번호 | 자리 | 이름(창) | 필드에서 쓰면 |
| --- | --- | --- | --- | --- | --- |
| おうごんのうでわ | `76` | `C6` | ゴールドオーブ 자리를 빌림 | 황금의 팔찌 | 「그러나 여기서는 아무 일도 일어나지 않았다!」(1A8) |
| とうぞくのカギ | `71` | `B7` | DQ5 의 같은 물건 그대로 | 도적의 열쇠 | 앞의 잠금 1 문을 엶. 문이 없으면 「그 방향에는 문이 없다!」 |
| さえずりのみつ | `75` | `BE` | あくまのおもちゃ 자리를 빌림 | 지저귐의 꿀 | 1A8 |

- 빌린 자리는 DQ5 의 대화 조건(`dq5talk` 조건 `11`, 216개 대화 스크립트를 모두 읽음)과 롬의 물건 조회(`00 88 90 n`·`00 90 90 n` 바이트)가 묻지 않는 열쇠 물건입니다. 같은 처리기를 쓰는 셋(`C6`·`CA`·`D1`) 가운데 `D1` ドラゴンオーブ 는 대화 `21A` 가 묻습니다. `C6`·`BE` 는 아무 데서도 묻지 않습니다.
- 이름은 제자리에 덮으므로 바이트 수가 같아야 합니다. DQ5 물건 이름의 탁음은 두 바이트(`84` + 글자)라 おうごんのうでわ 는 10바이트로 ゴールドオーブ 와 같고, さえずりのみつ 는 8바이트로 あくまのおもちゃ 와 같습니다. 창의 한글 이름은 번호로 덮는 표(`dq4windowtext.numbered_names`)가 `dq4itemport.korean_names` 로 넣습니다.
- `C6` 는 물건 표·처리기를 그대로 둡니다(도구 칸 `04`, k1 `1C` 팔 수 없음, 쓰면 `11:8BE4` → 메시지 1A8). `BE` 는 DQ5 에서 물건 표가 모두 0 인 빈 레코드라 k1~k4 를 `C6` 것으로, 필드 처리기(`11:8F5B` + (번호 − `A1`) × 2)를 `8BE4` 로 덮었습니다.
- `B7` 도 물건 표가 모두 0 이었습니다(장비 칸 0 무기, 팔 수 있음). k1~k4 를 まほうのカギ(`B8`)의 것(도구 칸, 팔 수 없음, 설명 4A6)으로 덮고, 필드 처리기는 DQ5 의 `11:8E43`(열쇠 단계 1 로 앞의 문을 엶) 그대로 둡니다. `B8` 의 처리기를 베끼면 잠금 2 문까지 열립니다.

### 잠금 1 문을 도적의 열쇠로

[DQ5 문 잠금](../../dq5/docs/dq5-map-format.md#문-잠금-01dcfc) `01:DCFC` 는 열쇠 단계 1 을 カギの技法 flag `2199.1` 로만 정합니다(`01:DD23` `BRK 0B 02 09 / BEQ / INC $01`). 그래서 도적의 열쇠를 가져도 걸어 들어가거나 「문」 명령으로는 잠금 1 문이 열리지 않고 187「열쇠를 가지고 있지 않다.」가 떴습니다(どうぐ 로 쓰는 길 `11:8E43` 만 열림). `01:DD23` 의 8바이트를 `JSL $57F800` + `NOP` 넷으로 바꾸고, `57:F800` 에서 flag 가 켜져 있거나 일행 누군가가 `B7` 을 가졌으면(`BRK 90 90 B7`, `01:DD07` 의 さいごのカギ 조회와 같은 꼴) `$01` 을 하나 올립니다(`dq4door.KEY`). BRK 처리기는 스택의 K 로 인자를 읽으므로 뱅크 `57` 에서도 그대로 돕니다.

## 2장 일행의 주문·성장·장비

아리나·크리프트·브라이의 레벨업 성장, 주문, 장비는 [성장 문서의 「2장 일행」](dq4-growth-format.md#2장-일행)에 있습니다. 다른 세션이 쓸 것만 적습니다.

- 성장 표: `dq4growth.TABLES` 의 넷(사람 0 은 2장 flag 로 라이안·아리나, 사람 9 크리프트, 사람 5 브라이). 표는 `57:D000`~`57:EDD7`, 장비 훅은 `57:CE00`~ 입니다. 사람 9·5 를 다른 인물로 바꾸면 이 표·`dq4party.RECRUITS`·`EQUIP_PEOPLE` 도 함께 바꿔야 합니다(`test_dq4party` 가 셋이 맞는지 봄).
- 합류 기록의 배운 주문 비트는 `dq4party.apply_recruits` 가 `dq4ch2event.apply` 뒤에 씁니다. `level_one` 이 그 자리를 0 으로 두지 않게 바꾸면 빌드가 멈춥니다.
- 2장 동안 사람 0·9·5 의 장비 판정은 FC 장비 비트 표를 봅니다. 새 물건을 DQ5 칸에 빌리면(`dq4itemport.BORROWED`) 그 FC 물건의 비트가 저절로 들어갑니다.
- 헤드리스 전투에서 세 사람을 쓰려면 `dq4battlescene.chapter2_party`(롬의 기록으로 일행 칸 0~2)와 차례 입력 `attack3`·`spell3`·`flee3` 를 씁니다.

| --- | --- | --- | --- |
| 산트하임 성 `3D/00`~`02` | `01`(0) | `03` 王宮のメヌエット | `01` |
| 텐페 `3D/03`, 프레놀 `3D/04`·`05` | `0E`·`0F`(1) | `0C` 街でのひととき | `06` |
| 사란 `45/00`~`04`, 사막의 바자 `45/05` | `13`·`0C`(1) | `0C` | `06` |
| 서쪽 탑 `45/06`~`0B` | `2E`(4) | `07` 呪われし塔 | `0A`(그대로) |
| 남쪽 동굴 `45/0C`·`0D` | `39`(5) | `06` 恐怖の洞窟 | `09`(그대로) |

밤 곡과 2장 필드 곡은 맵 바이트 하나로 낼 수 없어 곡 묶음 단계의 [곡 고르기](dq4-sound-port-format.md#곡-고르기-밤-곡장마다-필드-곡2026-11-06)가 정합니다. 밤(`$075E` ≥ `00F0`)이면 성 `01` → `30`, 마을 `06` → `31` 이고, 2장 flag(`7E:2208` bit4)가 켜져 있으면 필드 `02` → `05` おてんば姫の行進 입니다. 1장 그룹(바트랜드·이무르)도 같은 규칙으로 밤 곡이 됩니다.

### 사건이 곡을 켜는 법

| 하려는 것 | 쓸 것 |
| --- | --- |
| 곡을 튼다 | `LDA #곡 / JSL 24:FE9A`(또는 `BRK 0F 곡`). 성·마을·필드 곡 번호(`01`·`06`·`02`)를 주면 곡 고르기를 지나 밤·2장에 맞는 곡이 납니다. 밤 편곡을 시각과 상관없이 틀려면 `30`·`31` 을 바로 줍니다 |
| 사건 곡(보스·투기장·엔딩) | 곡 번호를 바로 줍니다. 고르기 표에 없는 번호는 그대로 갑니다 |
| 사건 곡이 끝난 뒤 맵 곡으로 | `LDA $194B / AND #$7F / JSL 24:FE9A`(1장 `dq4ch1event._fanfare` 와 같은 꼴). 입구에서 고르므로 밤이면 밤 곡이 돌아옵니다 |
| 맵 곡을 줄이거나 멈춤 | `24:FEC7`(`04`)·`24:FEBE`(`02`) 에 `$194B` 를 줘도 됩니다. 입구에서 골라 지금 울리는 밤 곡과 맞습니다 |
| 밤으로 바꾸고 곡도 | `$075E` 를 바꾼 뒤 맵을 다시 불러오면(이벤트 `90` 맵 이동) 맵 곡 루틴이 새 시각으로 고릅니다. 텐페 바구니 이벤트가 이 꼴이고, 도착한 텐페에서 `31` 이 울렸습니다(아래 [곡 검증](#곡-검증)의 바구니). 같은 맵에서 시각만 바꾸면 곡은 그대로이고, `00:CE61`(맵 곡 루틴)을 부르면 바뀔 것입니다(코드 읽기, 재지 않음) |

- 장 상자의 맵 밝히기(`dq4chapterbox`, 명령 `37` reveal)는 지금 곡 `$1D8B` 가 `$194B & 7F` 와 같아질 때까지(300프레임까지) 검게 기다립니다. 밤에 성·마을에서 밝히면 울리는 곡이 밤 곡이라 같아지지 않아 300프레임을 다 기다립니다(코드 읽기). 1장·2장 첫머리는 아침이라 걸리지 않습니다.
- 곡 고르기 표에 줄을 더하는 것은 곡 묶음 인자(`dq4sound-game.args` 의 `--song-pick`)입니다. 사건 모듈에서 표를 고치지 않습니다.

### 곡 검증

`dq4mapsongcheck.py` 가 검사 롬으로 만든 출발 상태에서 `dq5warp.lua` 로 순간이동하고 300프레임 뒤의 `$1D8B` 를 읽습니다. 밤은 `$075E` = `00F0` 을 매 프레임 붙들고, 2장 장면은 들어가기 전에 2장 flag 를 켭니다. 맵에 선 채 걷지 않아 난수·조우가 끼지 않습니다. 가드 `dq4-map-song` 입니다. 고치기 전 롬은 같은 검사를 `--chapter2` 빌드(곡 고르기·곡 바이트 전)로 돌린 값입니다. 고치기 전의 성·사란·탑 장면은 도착 칸이 맵 아래 끝이라 필드로 나간 판의 값이라 빼고, 안쪽 칸으로 옮긴 뒤 고친 롬으로만 쟀습니다.

## 이동·조우·저장

- ルーラ·キメラのつばさ: テンペ·フレノール·사막의 바자가 칸 12~14 로 목록에 나오고, サラン 은 목록에 나오지 않는 칸 15 입니다. 칸을 맵에 묶는 훅과 실측은 [그룹을 나눠 쓰는 칸](dq4-field-format.md#그룹을-나눠-쓰는-칸).
- 저장·이어 하기·전멸: 기록한 교회 칸(`7E:2033`)으로 이어 하고, 전멸해도 FC·NDS 처럼 그 교회로 갑니다. 1장 끝에서 2장으로 넘길 때 `transfer` 가 `7E:2033` 을 サラン 칸으로 둡니다(FC 2장 시작 귀환 자리). 사건이 다른 교회에서 다시 시작하게 하려면 `dq4fieldtravel.slot_of_fc` 의 칸을 `7E:2033` 에 씁니다.
- 조우: 2장 필드 구역은 1장과 같은 FC 구역 지도이고, 탑·동굴은 FC 던전 구역입니다. 곡 번호: 탑 `0A`, 동굴 `09`(그룹 `45` 의 LINKS `music`). 몬스터 값이 DQ5 표에 들어가는지는 [조우 「2장」](dq4-field-format.md#2장).

## 남은 것

- 텐페 보스 전투(제단 flag 를 보고 1C 이벤트 02)와 이긴 뒤의 마을, 텐페의 밤 색(그룹 `3D` 맵은 시간을 밤으로 두어도 어두워지지 않음), 제단으로 옮긴 뒤 신부의 말(지금은 0347 「자, 어서 저 바구니 안으로……」 그대로), 프레놀·바자·탑·무술 대회·빈 성의 사건, 여행의 문 사당([dq4 남은 일](../todo.md)).
- 합류 장면을 거쳐 두 사람이 뒤따르는지. 일행 기록 1·2 의 `+0` 만 `09`·`05` 로 둔 1장 롬 시험에서는 걷는 그림 `1967` = 3, ヘンリー `3B`·サンチョ `29` 가 뒤따랐습니다([1장 따라 걷는 그림](dq4-chapter1-format.md#따라-걷는-그림)).
- 걷어찬 구멍에서 지붕(`01/01`)으로 이어지는 FC 길.
- 벽을 걷어차지 않고 성문으로 돌아오는 길은 없습니다(문지기는 합류 뒤에만 비킴). FC 처럼 왕과 다시 이야기한 뒤 문지기가 길을 여는지(`$627B` bit1)는 보지 않았습니다.
- 1장 깃발은 그대로 남습니다(FC 도 장 시작에 이벤트 flag 를 지우지 않음, [성장 문서 「1장 가방과 flag」](dq4-growth-format.md#1장-가방과-flag)). 1장에 맡긴 물건·금화는 넘김에서 비웁니다([1장 끝에서 옮기기](#1장-끝에서-옮기기)).
- 저장을 불러온 뒤 그림 훅과 2장 깃발이 이어지는지(코드 읽기).

## 2장 맵의 밤 색

그룹 `3D`(산트하임·텐페·프레놀)와 `45`(사란·바자·서쪽 탑)의 맵은 시간대 `7E:075E` 가 `00F0` 이상일 때 밤 팔레트로 그려집니다. 남쪽 동굴 `45/0C`·`0D` 는 FC 처럼 밤에도 낮 색입니다. 장치는 맵 단위라 사건이 따로 켤 것은 없습니다. 맵을 불러오기 전에 `$075E` 를 밤으로 두면 됩니다. 텐페 바구니 이벤트는 이미 `90` 앞에서 `00F8` 로 둡니다. 이긴 뒤 아침으로 돌릴 때는 `$075E` 를 낮(예: `0050`)으로 두고 맵을 다시 불러옵니다. 팔레트 훅과 밤 색 규칙은 [환경 형식의 「밤 색」](dq4-environment-format.md#밤-색)에 있습니다.

### 2장 출발 상태

걷기·heroblock·호환성 검사의 사건 구간은 모두 「2장 출발 상태」에서 시작합니다. 서장 끝 상태(1장 검사의 캐시)에 1장 왕 보고 앞까지의 flag·동료를 두고 1장 구간 `castle`·`king`(`--chapter2` 끝)을 걸은 뒤, 첫머리 구간 `opening` 이 제목 상자·서두·왕의 말을 A 열 번으로 넘긴 상태입니다(왕좌의 방 `3D/01` (18,17), 일행은 아리나 하나, 2장 flag 켜짐, 첫머리 flag 꺼짐). A 를 열한 번 넘게 누르면 왕에게 다시 말을 걸어 물음이 되풀이됐습니다. 머리는 `castle` 첫머리에 1장에 맡긴 것(`dq4ch2walkcheck.CH1_BANK`: やくそう 3 개 `22F1`, 금화 2000 `203A` = 2)을 두고, `opening` 끝에 둘이 0 이고(`BANK_HERB`·`BANK_GOLD` 를 `off` 로) 아리나가 비단 로브를 가졌는지(`items`) 봅니다. 이 상태는 서장 캐시와 같은 폴더(`work/cache/states/prologue/<롬 SHA-1>/ch2-opening-<지문>.mss`)에 두고, 지문은 서장 캐시 키에 머리 구간 표와 머리를 걷는 코드를 더한 것입니다. 사건 구간을 붙여도 머리는 다시 걷지 않습니다.

### 걷기 검사에 구간 붙이기

1. **flag**: 사건 모듈([사건 등록과 자원 예약](#사건-등록과-자원-예약)으로 `dq4ch2event.EVENTS` 에 끼운 `dq4ch2<이름>.py`)이 쓰는 flag 를 `dq4ch2walkcheck.FLAGS` 에 이름 붙여 한 줄로 더합니다(`'NAME': flag(모듈.FLAG)`, 값은 `(7E:2190 + 첫 값, 마스크)`). flag 는 모듈의 `FLAGS` 에도 있어야 예약 바이트 안인지 시험이 봅니다.
2. **구간**: `dq4ch2walkcheck.SEGMENTS` 에 사건 하나를 「순간이동 구간 하나 + 걷기 구간 여럿」 으로 더합니다. 순간이동 구간마다 새 묶음이고, 묶음끼리는 함께 돕니다. 묶음 첫 구간에는 그 앞 모든 구간의 `want` 가 켜지고 `off` 가 꺼진 채로 놓이므로, 사건 차례대로 더하면 앞 사건을 걷지 않고도 그 상태에서 시작합니다.
3. **선택**: 꼴은 `dq4ch1walkcheck.SEGMENTS` 와 같습니다.

| 선택 | 뜻 |
| --- | --- |
| `want`·`off` | 끝에 켜져·꺼져 있을 flag 이름 |
| `map`·`field` | 끝 맵(`GG/MM`), 필드인지. 필드에서도 `7E:00BC`·`00BD` 는 떠난 맵 번호 그대로라 필드로 나가는 구간은 `field` 로 봅니다 |
| `cell` | 걷기 구간 끝에 주인공이 선 셀 `(x, y)`(`7E:3020`·`3080`) |
| `items` | 주인공이 가진 물건(DQ5 번호) |
| `poke` | 구간 동안 매 프레임 묶는 WRAM(`7E075E=F0;…`). 밤 구간은 1장 검사의 `NIGHT` 를 넣으면 시각도 밤으로 둡니다 |
| `maxf`·`changes`·`after` | 걷기 프레임 상한, 맵이 바뀔 횟수와 그 뒤 프레임 |

4. **순간이동 자리**: `dq5warp.lua` 는 `TO` 의 한 셀 아래에 내립니다(도착이 늘 `TO + (0,1)`). 인물 아래 칸에서 위로 말 걸려면 인물 셀 `(x, y)` 에 대해 `TO = (x, y + 1)`(도착 `y + 2`)입니다. 같은 맵 `3D/01` 로 순간이동하는 묶음은 `HOPS` 의 이웃 맵을 거칩니다.
5. **걸어 다니는 인물**: 말 상대가 걸어 다니면 난수에 따라 비켜 서서 시드마다 결과가 갈립니다. 구간의 `poke` 로 그 인물 슬롯의 걸음 간격 `7E:3300 + 슬롯` 을 `00` 으로 묶습니다(낮 목록 n 번째 인물 = 슬롯 `08 + n`). 브라이(`HOLD_BREY = 7E3308=00`)를 묶지 않았을 때 시드 5·9 에서 「その方向には誰もいない」(`129`)가 났습니다.
6. **기록에 남는 것**: 사건이 flag 말고 일행·물건 같은 기록을 바꾸면 `dq4ch2walkcheck.effects` 에 `구간 이름 → {'set': …}` 을 더합니다. 두 사람 합류(`join`)는 `dq4ch2event.recruit_records` 로 일행 기록 1·2, 일행 수 3, 순서 0 1 2 를 둡니다(상태 창 「아리나·크리프트·브라이」 H 16·18·16 확인). `dq5warp.lua` `PARTY` 는 몬스터 동료 기록만 만들어 사람 동료에 쓰지 않습니다.
7. **전투**: 걸음 전투는 조우 판정을 덮어 없앱니다. 보스·이벤트 전투 구간은 지금 틀에 없습니다. 사건 전투는 [사건 전투](#사건-전투)의 공용 루틴으로 걸리고 이겼는지는 `7E:2208` bit7 에 남으므로, 구간의 `want` 로는 모듈이 그 비트를 보고 켠 사건 flag 를 봅니다. 처음 붙이는 사건은 1장 검사의 `boss`(몬스터 HP 1·수비 0, 주인공 HP 묶기)처럼 모듈 `BATTLES` 의 그 무리만 약하게 하는 롬 패치 선택을 `dq4ch2walkcheck.walk_unit` 과 `dq4compatcheck.Walker.segments` 에 함께 더합니다. 지는 경우는 별도 구간으로 둡니다.
8. **돌리기**: `--only 구간` 으로 그 묶음만, `--seeds 0,5,9,13,21` 로 여러 시드를 돌려 모두 통과하는지 봅니다. 가드는 `--repeat 2` 입니다.

```sh

MESENCE=… LIBDIR=… uv run --locked python sfc/dq4/tools/dq4ch2walkcheck.py --rom work/ch2/dq4-ch1-full.sfc \
    --out work/ch2walk --only priest_side --seeds 0,5,9
```

### 다른 세 검사에 붙이기

- **npccheck**: 사건이 말을 바꾼 인물은 사건 모듈에 `start_messages(ctx)` 를 두어 장 시작 상태의 첫 메시지 표(`(맵, FC 대화 번호, 밤 또는 None) → 메시지 번호`, 번호는 `ctx.msg`)를 돌려줍니다. `dq4ch2event.start_messages` 가 등록 차례로 모듈의 표를 합치므로 `dq4ch2event.py` 는 고치지 않습니다. 검사는 2장 flag 만 켜고 다른 사건 flag 는 두지 않으므로, flag 로 바뀐 대체 목록(`later_states`)의 인물은 보지 않습니다. 그 인물은 걷기 검사 구간에서 말을 걸어 봅니다. 인물 폴더는 `dq4chapter1.py build --chapter2 --keep 폴더` 로 만들고, 그 롬은 `dq4build.py --chapter2` 의 `dq4-ch1.sfc` 와 SHA-1 이 같았습니다.
- **heroblock**: 주인공을 걷게 하거나 칸·방향으로 거는 사건이면 `dq4heroblockcheck.chapter2_cases` 에 그 사건을 걸 수 있는 칸마다 사례를 둡니다(`warp`·`set`(flag)·`walk`·`want`, 끝에 다시 걸을 칸 `free`, 사건이 옮겨 둔 셀 `hero_at`). 출발 상태는 2장 출발 상태입니다.
- **호환성**: `dq4ch2walkcheck.SEGMENTS` 를 그대로 걸으므로 따로 붙일 것이 없습니다. 새 선택을 걷기 검사에 더하면 `dq4compatcheck.Walker.check`·`segments` 에도 같은 판정을 더합니다(`cell` 은 더함).

### npccheck 의 순간이동 자리

처음 `--chapter2` 로 돌렸을 때 151장면 가운데 23개가 실패했고, flag 를 켜지 않은 `--chapter1` 로도 같은 23개가 실패했습니다. 실패한 말 걸기는 모두 인물 위 칸에서 아래로 말 거는 장면(도착이 인물 셀 − (0,1), 주인공이 인물 위쪽 반과 겹쳐 「その方向には誰もいない」)과 마을 맨 아래 FC 줄 인물(도착이 맵 밖 줄이라 필드로 나감)이었고, 통과한 아래쪽 장면은 모두 인물 셀 + (0,3) 에 섰습니다. 순간이동이 `TO` 의 한 셀 아래에 내리기 때문이라, `--chapter2` 에서는 `dq4npccheck.warp_to` 가 말 걸 FC 칸의 셀보다 한 셀 위를 `TO` 로 줍니다. 그룹 빌드 롬(`dq4groupbuild`, 가드 `dq4-npc-talk`)은 `TO` 그대로에 내려서, 같은 한 셀 위를 주면 655장면 가운데 263개가 「その方向には誰もいない」(`129`) 따위로 실패했습니다. 그래서 그쪽은 셀을 그대로 줍니다. 고친 뒤 같은 23장면을 포함한 151장면이 통과했습니다. 실패에 들었던 가게 넷(`45/03` 둘, `45/05` 둘)도 고친 뒤 통과했습니다.

### 남은 것(검사)

- 텐페 제단 앞 셀 (44,31)은 사방이 막혀 걸을 수 없습니다(조작은 돌아와 명령 창이 열림). 다음 단계의 보스 전투가 이 칸에서 시작하면 상관없지만, 전투 전에 걷게 되면 막힌 칸인지 다시 봅니다. heroblock 신부 사례는 끝 걸음 대신 옮겨진 셀만 봅니다.
- heroblock 의 텐페 사례는 일행이 아리나 하나입니다(걷기 검사는 합류 효과로 셋).
- 걷기 검사는 메시지 번호를 기준 파일과 견주지 않습니다. 1장처럼 기준 파일 하나를 두면 사건 세션들이 같은 파일을 함께 고쳐 부딪치므로, 메시지는 사건 모듈의 단위 테스트가 봅니다.
- 2장 길의 열린 버스 프로브(`dq4compatcheck.py probe`)는 1장 걷기만 붙입니다.
- 두 롬에서 `dq5warp.lua` 도착 칸이 한 셀 다른 까닭은 재지 않았습니다(2장 롬은 `TO + (0,1)`, 그룹 빌드 롬은 `TO`).
- 2장 끝까지 이어 걷는 최종 통과(E1~E5 뒤).

## 여행의 문 사당

FC 의 두 사당(`1E` 이쪽, `1F` 엔돌 쪽)을 그룹 `45` 끝에 넣었습니다([그룹 연결](dq4-environment-format.md#그룹-연결)). 곡은 FC 맵 갈래 3 의 不思議のほこら(FC 곡 `08`, DQ5 자리 `18`)입니다.

| 맵 | FC | 필드 입구 블록 | 필드에서 도착 | 필드로 나가는 칸 |
| --- | --- | --- | --- | --- |
| `45/0E` | `1E/00`(산트하임 쪽) | (57,4D) | (10,21) | 필드 (174,157) |
| `45/0F` | `1F/00`(엔돌 쪽) | (57,52) | (14,27) | 필드 (174,167) |

- 여행의 문(FC 블록 속성 `0A`, `1B:$A10F`)은 계단처럼 짝 칸으로 옮기는 DQ5 출구 블록입니다(`dq4environmentrom.STAIRS` 에 `0A`). `45/0E` (10,7)(FC (05,03)) → `45/0F` 의 문 (6,7)(FC (03,03)), 반대도 같습니다(`dq4groupcheck` 의 `stair-450E-0`·`stair-450F-0`). FC 의 소용돌이 연출(약 300프레임)은 없습니다.
- **엔돌 쪽으로 가는 길(E4 가 쓰는 도착지)**: `45/0F` 의 여행의 문에 내려 (6,7)에 서고, 사당 아래 입구로 나가면 필드 (174,167)입니다. 엔돌(`40/00`)의 필드 입구 블록은 (67,65)입니다(사당에서 걸어 닿는지는 재지 않음). 순간이동으로 시작할 때는 `45/0F,6,8`(엔돌 쪽 사당 문 아래)·필드 `174,167` 을 씁니다.
- 사당 병사(FC 슬롯 06, 대화 `037`)는 FC 에서 (03,08)에 서 있다가 나음 전이면 1D 이벤트 `10` 이 (04,06)(위 방으로 가는 틈)까지 걸어가 막습니다. 포팅은 처음 목록에서 그 칸 셀 (8,13)에 세우고(걸음 간격 0, 대사 07E0), 나음 flag 면 대체 목록 `ch2_king_shrine` 이 원래 칸 (6,17)에 07E1 「지나가십시오」로 둡니다. 그래서 `dq4npccheck` 는 처음 목록의 병사를 보지 않습니다(`absent`).
- 엔돌 쪽 사당 `45/0F` 의 인물(여관 주인·여행 상인·라이안 등)은 2장 시작 상태로 옮기고 대사를 `dq4ch2talk.TEXTS` 에 넣었습니다.

## 엔돌 무술 대회

사건 모듈 `sfc/dq4/tools/dq4ch2endor.py`(예약표 E4)입니다. 엔돌 투기장 `40/07`(FC `04/07`)·대기실 `40/0E`(FC `04/0E`)·마을 `40/00`(FC `04/00`)에서 FC 1D 이벤트 44~47·4A·4D·4E 차례대로 돕니다. 엔돌은 3장도 쓰므로 바꾸는 목록은 모두 2장 flag(`7E:2208` bit4) 또는 2장에서만 켜지는 아래 flag 로 고릅니다.

| 짐 | `7E:21F4` bit1 | `$6285&20` 의 짐 갈래 | 방금 대회 전투에서 짐. 대기실 침대 장면이 끔 |

### 일행 빼기와 되돌리기

- 빼기(대화 입구 1, `leave`): 일행 기록 `7E:2040`+42×n 은 그대로 두고 일행 수 `7E:201D`~`201F` 를 1, 순서 `7E:2020`·`2028` 첫 칸을 0(아리나)으로 씁니다. 원래 순서 첫 둘은 flag 바이트 위 니블에 맡기고 셋째는 되돌릴 때 `3 − 첫째 − 둘째` 로 셉니다. 기록을 옮기지 않으므로 장비·물건·HP·MP 는 그대로입니다.
- 되돌리기(`_restore`, 우승 뒤 인물 스크립트와 진 전투 뒤): 대회 중 flag 가 켜져 있을 때만 순서 셋·일행 수 3 을 다시 쓰고 대회 중·맡긴 순서를 지웁니다. 꺼져 있으면 아무것도 쓰지 않습니다.
- 대회는 링 인물의 대화 하나가 이어지는 동안(인물 스크립트가 `3F` 로 조작을 막은 채 판마다 `talk_here` 를 다시 부름) 끝나므로 교회·저장이 끼지 않습니다. 대회 중 상태로 링에 서면 링 인물이 이긴 수 번째 상대부터 잇습니다.

### 엔돌 검증

- 단위 테스트 `test_dq4ch2endor`: 빼기 → 되돌리기를 일행 순서 여섯 가지 모두로(일행 기록 바이트 그대로), 대회 밖 되돌리기는 아무것도 쓰지 않음, 이긴 판·진 판·이긴 수가 넘칠 때의 무리, 약초 칸 당기기와 장비 비트, FC 2장 시작 상태의 마을 대사, FC 특수 전투 07~0B 의 몬스터, 몬스터 행동이 DQ5 몬스터 행동 값인지.
- 걷기 검사(`dq4ch2walkcheck`, 일행 순서를 브라이·아리나·크리프트로 두고 들어감. 선택 `bytes` 로 끝의 일행 수·순서를 견줌): `endor_lose`(첫 상대에게 져 침대, 일행 되돌아옴), `endor_bout0`~`3`(이긴 수 k 로 시작해 k 번째를 이기고 다음에 져 침대, `bout0` 은 약초 둘을 모두 씀), `endor_held`(넷째·다섯째 사이마다 방향 키를 눌러도 우승까지), `endor_final`(우승, 일행 되돌아옴), `endor_messenger`(사자 flag).
- `dq4ch2walkcheck.battle_patch` 선택은 `weak:5A+lose:4C` 처럼 `+` 로 잇고 `:` 뒤에 몬스터를 적어 그 몬스터만 덮습니다. `weak` 는 `win` 에 공격 0·MP 0·행동 모두 たたかう 를 더한 것입니다.

### 엔돌 남은 것

- 링에 서는 상대 그림([2장 사건 인물 그림 표](dq4-sprite-format.md#2장-사건-인물-그림-표-dq4peopleevent_people)의 미스터 한 `60`·라고스 `89`·비비안 `1C`·사이몬 `1D`·베로린맨 `34`). 지금은 전투 화면의 DQ5 대역 몬스터만 보입니다.
- 투기장 대기실의 다른 출전자, 왕의 관람석 장면 같은 FC 연출. 사당에서 엔돌로 오는 길은 E3 몫입니다.

## 동료 대화

명령 창 「はなす」로 앞에 말 상대가 없을 때, 지금 맵·flag·시각·일행에 맞는 동료의 대사를 띄웁니다(NDS 리메이크의 동료 대화). DQ5 에는 동료와 이야기하는 메뉴 명령이 따로 없고, 「はなす」는 앞에 아무도 없으면 `05:D5B9` 에서 대화 창을 열고 메시지 `129`「その方向には誰もいない。」를 띄웁니다. 그 뒤 두 BRK(`05:D5BC` 의 메시지 `129`, 10프레임 기다림)를 [`dq4ch2partytalk`](../tools/dq4ch2partytalk.py) 네이티브 `JSL` 로 바꿉니다. 맞는 줄이 없으면 원래처럼 `129` 입니다. 코드와 표는 예약 `5C:8000`~ 에 있습니다.

| 자료 | 꼴 |
| --- | --- |
| 맵 표(`maps`) | 4바이트씩: 맵 바이트 둘(`7E:00BC`·`00BD`, 필드는 `FE FE`), 그 맵 줄 목록의 주소(같은 뱅크). `FF FF` 로 끝 |
| 줄 | 길이(이 바이트 포함), 우선순위, 말하는 인물, 시간(0 아무 때, 1 낮, 2 밤), 메시지(2바이트), 조건 수, 조건(3바이트씩). 길이 0 으로 끝 |
| 조건 | 종류, 값 둘. `1` flag 켜짐(`7E:2190` + 번호, 마스크), `2` 꺼짐, `3` 바이트 값이 같음, `4` 선두 인물, `5` 걷는 줄에 그 인물, `6` 걷는 줄에 그 인물 없음 |

- 말하는 인물은 일행 기록 `+0` 의 인물 번호입니다(아리나 `00`, 크리프트 `09`, 브라이 `05`). 그 사람이 걷는 줄(`7E:201E` 명)에 있고 HP 가 0 이 아니어야 합니다.
- 우선순위는 작을수록 먼저입니다. 맞는 줄 가운데 가장 작은 우선순위의 것만 고르고, 그 우선순위의 맞는 줄이 여럿이면 「はなす」마다 표 차례로 돌아가며 고릅니다(마지막으로 고른 차례 + 1 을 `7E:21FE` 에 둠).
- 줄을 더하려면 `dq4ch2partytalk.MESSAGES` 에 대사(이름 → `speak(…)`)를, `LINES` 에 `Line(맵, 말하는 인물, 대사 이름, priority=, time=, on=, off=, equal=, lead=, with_=, without=)` 을 더합니다. 맵은 `'GG/MM'` 또는 `FIELD` 이고, flag 는 사건 모듈의 `(번호, 마스크)` 를 그대로 씁니다. 대사 번호는 등록 차례로 자동입니다.
- 검사는 [`dq4ch2partytalkcheck.py`](../tools/dq4ch2partytalkcheck.py)(가드 `dq4-ch2-partytalk`)입니다. 2장 출발 상태에서 사례(`CASES`)마다 flag·일행·시각을 두고 순간이동한 뒤 빈 쪽을 보고 「はなす」를 고르고, 뜬 메시지 번호를 롬의 표에서 그 사례에 맞는 줄의 번호와 견줍니다. 사례를 더할 때는 말 상대가 없는 쪽을 보게 합니다.

### 남은 것(동료 대화)

- 지금 줄은 장치를 보이는 표본(산트하임 성, 텐페 이긴 앞뒤·낮밤, 프레놀 납치·구한 뒤, 왕이 나은 뒤의 왕좌의 방, 필드)입니다. NDS 2장 동료 대화 960레코드에서 옮길 범위와 한글 대사는 다음 단계입니다.
- 필드 줄(`FIELD`)은 검사 사례가 없습니다(2장 출발 상태에서 필드로 순간이동하는 구간이 없음).
- 「はなす」를 마차 쪽으로 고를 때(DQ5 는 `129`)도 같은 갈래로 가는지는 재지 않았습니다(2장에는 마차가 없음).
