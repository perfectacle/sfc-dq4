# 게임 안 창 한글 조사

게임 안 창(상태 창·도구 목록·전투)에 한글을 찍기 전에, 이름이 창으로 가는 길과 장면마다 남는 BG3 타일 칸을 실측한 조사입니다. 구현한 것은 [BG3 타일맵 옮기기](#bg3-타일맵-옮기기)와 [상태 창 이름](#상태-창-이름)입니다. 기준 롬은 [글꼴](dq4-menu-format.md#글꼴)을 Galmuri9 로 바꾼 메뉴 빌드(SHA-1 `cd599f5bf9daa1b0426527034eecfb6dfd6c4dc7`)입니다.

## 왜 창이 문제인가

창 글자는 바이트가 곧 BG3 타일 번호입니다([메뉴 한글화](dq4-menu-format.md#글자-그리는-길)). 원래 글자 타일은 `01`~`8A` 의 가나·숫자·기호 138칸뿐이라, 한글은 문자열마다 그림을 그려 빈 타일 칸에 올려야 합니다. 주인공 이름만의 문제가 아닙니다. 동료 이름·도구·주문·몬스터 이름처럼 창에 찍히는 한글은 모두 같은 길을 지나야 합니다.

## 이름이 창으로 가는 길

선실 세이브스테이트(`work/state/ship.mss`)와 전투 세이브스테이트(`work/state/bt00-dq5spell2.mss`)에서 명령 창·つよさ·전투 공격을 실행하며 실행 감시를 걸었습니다(`sfc/dq5/tools/lua/dq5msg.lua` 의 `CALLS`).

| 길 | 쓰는 곳 | 하는 일 |
| --- | --- | --- |
| `04:ABCF` | 필드·전투의 상태 창 맨 위 이름 | 이름 4바이트를 `STA ($DC),Y` 로 타일맵 버퍼에 그대로 씀. `84`·`83` 이면 한 줄 위(`$DC − 40`)에 탁점 타일 `92`·`93` 을 덮어씀 |
| `24:A83C` | 전투 메시지의 이름(`$70` bit7) | 이름 바이트를 그대로 `7E:0ECB` 에 옮기고 `FF` 로 끝냄. 전투 글은 바이트를 BG3 타일로 찍음([DQ5 「1바이트 부호」](../../dq5/docs/dq5-hangul-format.md#1바이트-부호)) |
| `04:B33A` → `04:B3A2` 표 | 창 문자열의 `B0` 이상 자리 표시 | `B0`~`CF`, `D0`~ 를 표로 갈라 숫자·이름 등을 찍음. 이름을 찍는 코드 번호는 아직 다 가르지 못함 |

필드 상태 창의 이름은 위 테두리 아래 글자 줄 하나(8점)에 4타일로 찍힙니다. 바로 아래가 구분선입니다. 화면 y 좌표로 위 테두리 선 아래부터 구분선 위까지 148~162 의 15점이 비어 있어, 9점 글꼴은 테두리 줄과 구분선 줄의 타일까지 함께 그려야 들어갑니다(탁점 `92`·`93` 이 테두리 줄을 덮는 것과 같은 방식).

## 장면마다 BG3 타일

`sfc/dq4/tools/dq4bg3tiles.py` 로 VRAM 덤프에서 BG3 타일맵(워드 `1C00`, 32×32)이 가리키는 칸을 셌습니다. 장면마다 한 프레임의 덤프이고, 가리키지 않는 칸에도 이전 그림이 남아 있었습니다. BG3 글자 칸은 `000`~`17F` 384칸이고 `1C00` 부터 타일맵입니다.

| 장면 | 프레임 | 쓰는 칸 | 타일맵이 가리키지 않는 칸 |
| --- | --- | --- | --- |
| 필드 명령 창 + 상태 창 | 100 | 37 | `093`~`17F` 전부와 안 쓰는 가나 |
| つよさ | 260 | 33 | `091`~`17F` 전부와 안 쓰는 가나 |
| 대화 메시지 | 200 | 238 | `001`~`08B`, `08F`~`095` |
| 도구 목록 | 190 | 35 | `093`~`17F` 전부와 안 쓰는 가나 |
| 도구 목록 + 메시지 | 340·400 | 267 | 안 쓰는 가나·숫자(`002`~`011` 등)와 `093`~`095` 뿐 |
| 전투 명령 | 60 | 36 | `099`~`17F` 전부와 안 쓰는 가나 |
| 전투 메시지 | 150 | 22 | `099`~`17F` 전부와 안 쓰는 가나 |
| 전투 주문 | 100 | 27 | `099`~`17F` 전부와 안 쓰는 가나 |

- 보행 메시지가 뜨면 글자 캔버스가 `096`~`17F` 234칸을 모두 씁니다. 메시지 창과 이름이 든 상태 창은 함께 뜨지 않았습니다(상태 창은 메시지가 뜨면 닫힘). 그러나 도구 목록 창(도구 이름)은 「…を 道具として 使ってみた。」 메시지와 함께 떠 있었습니다. 이때 남는 칸은 가나 타일뿐입니다.
- 전투 메시지는 1바이트 타일이라 캔버스를 쓰지 않았고, 전투 중에는 `099`~`17F` 가 비었습니다.

## 가나 칸을 한글 칸으로

창 글자 타일 `01`~`8A`(`04:E528`, 1bpp)를 그려 갈랐습니다.

| 칸 | 내용 |
| --- | --- |
| `02`~`0B` | 숫자 0~9 |
| `0C`~`0F` | H M P G |
| `10`~`7A` | 가나(작은 가나·ー 포함), `79`·`7A` 는 ？！ |
| `7B`~`8A` | ▼ ▶ ⇒ ✝ 눈, ※ ◎ / 。 탁점 반탁점 : Ex Lv ー ＊ E |

이름 부호 표 `24:B270` 의 `01`~`7E` 가운데 가나는 105칸이었습니다. 창 글자를 모두 한글로 옮긴다는 전제에서는 창이 가나를 쓰지 않으므로, 이 100칸 남짓을 한글 타일을 그때그때 그려 넣는 칸으로 돌릴 수 있습니다. 메시지가 떠 있어도 이 칸은 캔버스와 겹치지 않습니다.

## 글꼴 크기와 타일 수

도구 목록은 항목마다 글자 줄과 그 위 탁점 줄을 쓰는 16점 간격입니다(도구 목록 장면 타일맵 4·6줄 글자, 5줄 탁점). 창 안쪽은 4~26줄, 16~25열(10열)이었습니다. 이름 폭을 BDF 로 쟀습니다.

| 이름 | Galmuri7(7×7) | Galmuri9(9×9) |
| --- | --- | --- |
| 크리프트 | 32점, 4열 | 40점, 5열 |
| 가죽 갑옷 | 35점, 5열 | 44점, 6열 |
| 노송나무 몽둥이 | 59점, 8열 | 74점, 10열 |

- Galmuri7 은 8점 글자 줄 하나에 들어가 한 열이 타일 1칸입니다. Galmuri9 는 위 탁점 줄까지 두 줄을 써서 한 열이 2칸입니다.
- 예를 들어 6열짜리 이름 8개면 Galmuri7 은 48칸, Galmuri9 는 96칸입니다. 같은 이름이면 Galmuri9 가 열도 한두 개 많아 차이가 더 벌어집니다. Galmuri9 는 가나 칸 100칸 남짓을 목록 하나가 거의 다 씁니다. 상태 창 이름(넷이면 Galmuri9 로 5열 × 2줄 × 4 = 40칸)이나 다른 창과 겹치면 모자랍니다.
- 도구 창 안쪽 10열 가운데 첫 열은 커서 자리라, 「노송나무 몽둥이」(Galmuri9 10열)는 그대로 들어가지 않습니다.

## BG3 타일맵 옮기기

타일맵이 글자 칸 `180`~`1FF`(VRAM 워드 `1C00`~`1FFF`)를 차지하므로, 타일맵을 장면마다 비어 있는 VRAM 자리로 옮겨 이 128칸을 한글 타일용으로 비웠습니다. 코드는 `sfc/dq4/tools/dq4bg3slot.py` 이고 `dq4menupatch.py build` 가 마지막에 붙입니다(`60:8300`~).

DQ5 엔진은 평소 BG3SC(`$2109`)를 맵을 불러올 때 그림자 `$0725` 와 함께 씁니다. 어느 자리가 비는지는 DQ5 트랙이 VRAM 1K 워드 칸마다 쓰기와 가리킴(켠 BG 타일맵·화면 안 OBJ 가 가리키는 칸)을 잰 자료로 정했습니다. 자료는 실내 맵 364개의 도착·보행, 전투 61벌(배경 49·큰 몬스터 9·셋 섞기 3), 특수 장면 35벌입니다. 처음 배정은 실내 맵 도착 직후의 쓰기만 본 자료([48번 일지](../../dq5/journal/2026-10-26-48-bg3slot.md))로 정했다가, 3C00 을 쓰거나 가리키는 맵을 놓쳐 01/00 성 탑 그림이 깨졌습니다.

| 장면 | BG3SC | 타일맵 자리(워드) | 까닭 |
| --- | --- | --- | --- |
| 타이틀·메뉴 | `1C` | `1C00` | 맵을 불러오기 전 |
| 필드(`$BE` bit7 = 0) | `78` | `7800` | 필드 16벌은 `7800`·`7C00` 을 쓰지도 가리키지도 않음 |
| 실내 맵 대부분 | `3C` | `3C00` | 맵도 전투도 `3C00` 을 쓰지 않음. 전투 61벌은 `3C00`·`7000`~`7C00` 을 쓰지 않음 |
| `3C00` 을 쓰거나 가리키는 실내 맵 | `7C` | `7C00` | 01/00·01/01·02/06·12/00·1F/00·20/00·21/00·21/05·21/08·22/00·51/54 |
| 같은 까닭, `7C00` 은 쓰는 맵 | `78` | `7800` | 00/0A·32/00 |
| `7000`~`7C00` 이 모두 차는 맵 | `48`·`4C` | `4800`·`4C00` | 19/00·19/05·1A/00·1C/00·1F/01 은 `48`, 19/02 는 `4C`(맵이나 슬롯 화면이 `4400`·`4800` 을 씀) |
| 위 `48`·`4C` 맵에서 전투 | `78` | `7800` | 전투는 시작하고 16프레임 안에 `4000`~`5C00` 을 씀. 전투가 끝나면 맵을 다시 불러와 돌아옴 |

01/00·19/02·1F/01·02/06 은 그 맵에서 일어나는 특수 장면(보스전·융단·세계 지도, 카지노 슬롯, 결혼식, 엔딩)이 쓰거나 가리키는 칸도 피했습니다.

바꾼 곳은 다음과 같습니다.

| 자리 | 원래 | 바꾼 뒤 |
| --- | --- | --- |
| `60:8284`(메뉴 패치의 맵 훅) | `LDA #$1C` / `STA $0725` | 위 표대로 자리를 고름. 자리가 바뀌면 타일맵 버퍼 `7E:5000` 2KB 를 DMA 7 로 새 자리에 올림(맵을 불러오는 중이라 화면이 꺼져 있음) |
| `26:8030`(전투 시작) | `JSL $04E2A1` | 지금 자리가 `40`~`5C` 면 NMI 를 끄고 새 vblank 를 기다려, 화면을 끈 채 버퍼를 `7800` 에 올리고 `$2109` 를 `78` 로. `$2100`·`$4200` 은 그림자 `$1D`·`$1E` 로 되돌림 |
| `00:8E1F` | 타일맵 2KB 전체 DMA 의 `STA $2116` | `$0725` 와 지금 자리가 다르면 이 vblank 에 `$2109` 를 바꾸고 새 자리로 보냄 |
| `00:8E55`·`00:8E75` | 위·아래 줄 DMA 의 `STA $2116` | 주소가 `1C00`~`1FFF` 면 지금 자리로 다시 계산 |
| `04:9849` | 높은 바이트 `STA $2117` | 같은 계산(8비트) |
| `22:8B4D`·`8B6F`·`8BC6` | `LDA #$1CE0` / `STA $0F5E`(전투 창 줄 주소) | 같은 계산 |
| `03:F3A9`·`03:F54D`·`22:E71B` | `LDA #$1C` / `STA $2109`(특수 화면 효과를 끝내며 되돌림) | 지금 자리로 되돌림 |

- 원하는 자리(`$0725`)와 지금 `$2109` 에 든 자리(`7E:1ABC`, `^ 1C` 로 두어 0 이면 `1C`)를 따로 둡니다. 둘이 다르면 전체 DMA 가 도는 vblank 에서 `$2109` 와 함께 바꿉니다.
- 전투 시작에서는 화면이 켜져 있습니다(`26:8030` 에서 `$2100` = `0F`, NMI 켜짐). 처음에는 `$0725` 만 바꾸고 다음 전체 DMA 를 기다렸습니다. 그러나 09/00 을 `48` 에 둔 시험 롬에서 싸워 보니, 전투가 `4800` 에 올린 그림이 전환까지 약 40프레임 동안 BG3 로 보였습니다. 보내기 요청 `$0BEC` 에 `80` 을 넣어도 전체 DMA 는 앞당겨지지 않았습니다. 그래서 전투 시작에서 vblank 를 기다려 바로 바꿉니다. 이때 NMI 한 번을 건너뜁니다.
- 맵을 불러오며 새 자리를 채울 때(`60:8284`)는 화면이 꺼져 있고 NMI 도 꺼져 있었습니다(MesenCE 상태 실측). DMA 7 은 NMI 전송 목록도 쓰는 채널이라 이 조건이 필요합니다.
- `21BF` bit5 갈래의 `4C00` 은 원래대로 둡니다.
- 맵을 불러올 때 새 자리를 비우지 않으면 앞 장면의 그림이 보였고, 0 으로 채우면 02/08·06/00·17/00·1F/00·1F/01 에서 창이 비었습니다. 이 맵들은 불러온 뒤 타일맵 전체를 다시 올리지 않아서, 옛 자리와 같은 내용인 버퍼를 올립니다.

검사는 `dq4bg3slotcheck.py` 로 합니다. 배 선실 세이브스테이트에서 실내 맵 364개로 순간이동해 명령 창을 열고 30프레임마다 `lua/dq4bg3slotwarp.lua` 가 다음을 적습니다.

- 그 자리 타일맵의 0 아닌 바이트 수
- 화면에 쓰는 자리의 타일맵과 버퍼 `7E:5000` 이 다른 바이트 수(`vsbuf`)
- 타일맵이 `1C00` 을 떠날 때 찍어 둔 옛 자리 `1C00`~`1FFF` 에서 그 뒤 바뀐 바이트 수(`old`)

```
MESENCE=... uv run --locked python sfc/dq4/tools/dq4bg3slotcheck.py --old 원래롬 --new 새롬 \
  --state work/state/ship.mss --out 새폴더 [--maps 01/00,17/00] [--jobs 10]
```

| 항목 | 결과 |
| --- | --- |
| 도착 | 363맵(17/00 은 원래 롬에서도 못 감) |
| 끝 프레임 `vsbuf` | 원래·새 롬 모두 362맵 0, 29/00 만 둘 다 2 |
| `old` | 모든 맵·모든 기록에서 0 |
| 끝 화면이 원래와 다른 맵 | 세 번 돌려 44·38·33맵. A 입력 시점에 따라 명령 창과 「めいれいさせろ」 창이 갈리거나 커서 깜빡임·맵 애니메이션이 다른 것. 원래 롬끼리도 21맵 중 8맵이 달랐음 |

조우율을 올린(`ROMPATCH=8523=FF`) 실내 09/00(`3C`)과 필드 04/0B(`78`) 전투에서 창이 원래대로 나오고 옛 자리는 바뀌지 않았습니다. DQ5 트랙의 전투 61벌 실측 도구(`dq5vramslots.lua`)를 새 롬으로 돌렸더니, 61벌 모두 전투 중 `1C00` 을 쓰지도 가리키지도 않았고 BG3 는 `7800` 에 있었습니다(원래 롬은 61벌 모두 `1C00` 을 씀). `48`·`4C` 맵은 조우가 없어, 09/00 을 `48`·`4C` 목록에 넣은 시험 롬으로 전투 전환을 쟀습니다. 전환 프레임 화면이 원래 롬과 같았습니다. 마을에서는 명령 창 열고 닫기와 계단 이동이 정상이었습니다.

BG3SC 를 직접 쓰는 다른 코드(`03:F362`·`03:F3A4`·`03:F548`·`22:E70B`·`22:E717`·`00:A86F`·`00:8A67`·`02:E681`·`02:EFA1`·`11:BBE5`·`11:C070`·`1D:B56C`)는 위 필드·실내·전투 시험에서 한 번도 돌지 않았습니다(실행 감시). 즉값 `1C` 로 되돌리는 세 곳만 고쳤고, 효과 자체는 아직 띄워 보지 못했습니다.

## 상태 창 이름

필드 상태 창(창 `02`)과 전투 상태 창·전투 명령 창 제목의 주인공 이름을 Galmuri9 한글로 찍습니다(`sfc/dq4/tools/dq4windowname.asm`·`.py`, `dq4menupatch.py build` 가 `dq4bg3slot` 다음에 부름, 코드 `60:C000`~). 사용자 결정으로 이름 칸을 4칸에서 5칸으로 넓혔습니다.

| 항목 | 내용 |
| --- | --- |
| 칸 넓히기 | 일행 열은 사람마다 너비 +5(`04:A394 ADC #$05`)·x −5(`04:A3A4 SBC #$05`)·내용 열 간격 10바이트(`04:B18E ADC #$000A`). 셋을 6·6·`0C` 로, 창 `02` 머리 너비를 6 → 7 로, 너비 6 일 때 `04:ABCF` 로 가던 지름길 `04:AB58 CMP #$06` 을 7 로 바꿈. 머리 너비만 바꾸면 효과 없음 |
| 이름 판별 | `04:ABCF` 를 `JML WnName` 으로. 첫 두 바이트가 한글 표시(`85`~`9A`, `10`~`7E`, [이름 입력](dq4-name-entry-format.md))면 한글, 아니면 원래 경로 `04:ABD6` |
| 글리프 | 이름 입력이 넣은 Galmuri9 16×16 칸(뱅크 `62`~`64`, n = (첫 바이트 − 85) × 111 + (둘째 − 10))에서 넉 자를 10점 간격으로 40점 띠 9줄에 겹침 |
| 높이 | 글자 높이 9점이 이름 줄(8점)을 넘으므로 맨 윗줄을 위 테두리 타일(`8D`)의 7줄째에 합성. 테두리 타일 그림은 롬 `04:E978`~(`8B`~`95`, 타일당 평면 0·1 각 8바이트), 가나 칸은 1bpp `04:E528`~ |
| 타일 칸 | 이름 줄 5칸 + 위 줄 합성 5칸 = 10타일을 BG3 칸 `180`~`1CF` 에. 타일맵 버퍼 자리(`$DC` + Y)마다 한 자리, 여덟 자리를 돌려 씀(`7E:1C40` 표) |
| 올리기 | `7E:3E00` 에 160바이트를 만든 뒤 NMI 전송 목록(`7E:4000`, 항목 수 `7E:0758`, 머리 `[80][VRAM 워드][워드 수]`)에 붙이고 `$1A` bit7 을 켠 다음 `JSL 00:958A` 로 NMI 를 기다림 |
| WRAM | `7E:1C40`~`1D1D`(자리 표·띠·글리프 사본·포인터·임시), `7E:3E00`~`3E9F`. 11개 장면 접근 카운터로 접근이 없던 자리(증명은 아님) |

`00:958A` 를 기다리는 까닭: 창을 그리는 동안 `04:9D41`~`9D49` 가 매 프레임 `$19` 워드를 `AND #$7FFF` 로 다시 써서 `$1A` bit7 을 지웁니다. 목록만 붙이고 돌아오면 NMI 가 목록을 보내지 않아(항목 수 1 그대로), 처음 연 창의 이름 칸에 옛 VRAM 내용이 보였습니다. 이름 입력(`NeUpload`)이 같은 순서를 씁니다. `00:958A` 는 저 RAM 을 절대 주소로 읽을 수 있어 DB = 00 으로 부릅니다.

### 실측

세이브스테이트는 BG3SC 를 옮기기 전 값을 갖고 있어, 그대로 쓰면 타일맵이 칸 `180`~ 자리(VRAM 워드 `1C00`)에 남아 이름 타일과 겹칩니다. 그래서 `sfc/dq5/tools/lua/dq5warp.lua` 로 09/00 에 순간이동해 맵을 다시 불러온 상태를 저장한 뒤(`SAVE` 는 `SHOT_DIR` 아래 파일 이름) `dq5msg.lua` 로 창을 열었습니다. 이름은 `POKE` 로 `7E:2001`~ 에 넣습니다(뱅크 없이 `2001` 로 쓰면 00:2001 이라 WRAM 이 아님).

```
LIBDIR=$LIBDIR SHOT_DIR=$PWD/work/sn/warp STATE=work/state/party4-wagon.mss TO="09/00,10,10" SETTLE=30 \
  POKE=7E2001=97,7E2002=33,7E2003=8C,7E2004=37,7E2005=99,7E2006=29,7E2007=98,7E2008=27 SAVE=st.mss MAXF=2500 \
  $MESENCE --testrunner 롬 sfc/dq5/tools/lua/dq5warp.lua
LIBDIR=$LIBDIR SHOT_DIR=... STATE=work/sn/warp/st.mss POKE=... PRE="wait:30,a:8,wait:90,b:8,wait:60,a:8,wait:90" \
  SHOTS=42,60,280 MAXF=290 $MESENCE --testrunner 롬 sfc/dq5/tools/lua/dq5msg.lua
```

| 장면 | 결과 |
| --- | --- |
| 혼자(`ship.mss` 에서 워프), 명령 창 열기·닫기·다시 열기 | 「크리프트」, 첫 프레임부터 깨짐 없음, 위 테두리 합성 정상 |
| 일행 3명(`party4-wagon.mss` 에서 워프) | 사람마다 6칸 열, 「크리프트 スラリン ホイミン」 |
| 두 자 「크리」, 가나 「ああああ」 | 한글은 앞 두 칸, 가나는 원래 경로 그대로 |
| 실내 09/00 전투(`ROMPATCH=8523=FF`), 일행 3명 | 전투 상태 창이 6칸 열로 넓어지고 이름 「크리프트」, 「こうげき」 명령 창 제목도 「크리프트」 |

전투 상태 창(창 `03`·`04`)과 전투 명령 창 제목도 `04:ABCF` 를 지나 같은 렌더러를 탑니다. DQ5 엔진의 전투·걷는 일행은 셋까지라 넷째 열은 띄우지 못했습니다.

### 목록 이름

창 문자열의 자리 표시 `D0`(`04:B790`)은 이름 하나를 공통 출력 `04:B79B` 로 찍습니다. 원래 코드는 글자마다 `04:B235` 로 `($E0),Y` 에 쓰고 `PLX` 뒤 `04:BFF2` 로 갑니다. 이 자리는 이름 입력이 먼저 `NeListHook`(모험의 서 목록)으로 훅해 두었으므로, `WnList` 가 다시 훅하고 메뉴 플래그(`7E:1BB0` = `A5`)거나 한글이 아니면 빌드 때 롬에서 읽은 이전 JML 대상으로 넘깁니다. 한글이면 상태 창과 같은 렌더러를 포인터 `$E0` 로 돌립니다.

| 창 | 모양 | 처리 |
| --- | --- | --- |
| 「누구」 고르기 `0C`·`0E`·`11`·`13`·`2C`·`36`·`38`·`3D`·`4F`·`6F`·`7A`(너비 9), `4A`·`7F`(너비 8) | 본문 `… D0 DD FF`. `DD`(`04:BA14`)는 이름 바로 뒤에 상태 표시 타일(`7E`·`80`·`7F`·`81`, 없으면 `01`) 한 칸을 찍음 | 창을 한 칸 왼쪽으로 옮겨 너비 +1(오른쪽에는 이어서 열리는 도구·주문 창이 붙어 있음). 이름 뒤 Y 를 10 나아가 상태 표시가 다섯째 칸을 덮지 않게 함 |
| HPとMP(`7B` 류), こうげき力 | 이름 뒤 내용의 자리가 정해져 있음 | 원래처럼 Y 를 8 나아감. 다섯째 칸은 열 사이 빈칸에 걸침(「HP와 MP」 창 `03`·`04` 는 한 사람 몫을 7 로 넓힘, [경험치 줄과 HP와 MP 창](#경험치-줄과-hp와-mp-창)) |

어느 쪽인지는 `04:B79B` 에 들어올 때 X 가 가리키는 창 문자열(뱅크 04)의 다음 바이트가 `DD` 인지로 가릅니다. 창 번호는 창 표 `04:EB48` 읽기를 감시해 장면마다 쟀습니다(つよさ→だれの `0C`, じゅもん `2C`, どうぐ `0E`, そうび `13`).

| 장면(일행 3명 + 마차 1명, 09/00) | 결과 |
| --- | --- |
| つよさ → HPとMP | 「1: 크리프트」, 위 줄 라벨 「1:」과 합성 정상 |
| つよさ → こうげき力 | 「1크리프트」, 레벨·こうげき·しゅび 열 원래 자리 |
| つよさ → つよさみる(だれの), じゅもん, どうぐ, そうび | 「크리프트」 넉 자 모두, 오른쪽 창과 겹치지 않음 |

### 이름 색

쓰러짐·독·HP 가 적을 때 이름에 색을 입히는 길이 따로 있습니다. `04:AB58` 지름길을 타지 않으면 `$EC`·`$46`·`$47` 을 보고 `$ED`(`28`·`24` 등)를 정한 뒤 `04:AB73` 부터 글자마다 높은 바이트 `$ED` 와 함께 16비트로 씁니다. `04:AB73` 도 훅해 같은 렌더러로 그리고, 이름 줄 타일맵 낱말의 높은 바이트를 `$ED` 로 둡니다(`7E:1D42`). 목록 길은 `04:B235` 와 같이 `$EC` bit6 이면 `$ED` 를 씁니다. 전투에서 주인공이 쓰러지자 상태 창 이름이 빨간 「크리프트」, HP 가 적을 때 노란 「크리프트」로 나왔습니다.

### 전투 메시지 이름

전투 글은 바이트가 곧 BG3 타일 번호입니다. 이름은 `24:A83C` 가 `$01`~ 의 바이트를 글 큐 `0ECB`~(DB = `04`·`20`)로 옮기고 `FF` 로 끝냅니다. `24:8738` 이 큐 머리를 꺼내 `E2` 이상이면 제어 코드(`24:86F2` 표), 아니면 `24:A4A4` 로 글 버퍼에 씁니다. 글 버퍼는 줄마다 26칸 × 두 줄(위 `1DD5`, 아래 `1DEF`, 줄 간격 `34`)이고, `84`·`83` 탁점만 위 줄에 갑니다. `24:A5D9` 가 버퍼를 타일맵 버퍼 `7E:5546`~ 의 **낮은 바이트**로만 옮깁니다.

| 자리 | 처리 |
| --- | --- |
| `24:A83C` → `WnBattle` | 한글이면 같은 렌더러로 10타일(아래 줄 5 + 위 줄 5)을 BG3 칸 `1D0`+자리×10 에 올리고, 큐에 코드 `B0`+자리×10 ~ 를 (10×글자 수 + 7) / 8 개 넣음. 자리는 이름 바이트로 찾는 4자리(`7E:1D20`) |
| `24:A4E0` → `WnBattleChar` | 아래 줄에 쓰는 바이트가 이름 아래 줄 코드면 위 줄에 +5 코드를 함께 씀 |
| `24:A5E9` → `WnBattleCell` | 코드 `B0`~`D7` 이면 낮은 바이트 +`20`, 높은 바이트 bit0(타일 bit8)을 켜 `1D0`~`1F7` 을 가리키게 함. 다른 바이트는 bit0 을 끔(줄이 올라가며 자리가 바뀜) |

몬스터 동료 이름(이름 표 `0A`)은 표 자체를 한글 표시 바이트로 바꾼 것만 이 길을 탑니다. 지금은 1장의 「호이민」 하나이고, 상태 창·목록·필드 메시지도 주인공 이름처럼 찍습니다([1장 첫머리의 「우물 아래와 호이민」](dq4-chapter1-format.md#우물-아래와-호이민)).

처음에는 코드 그대로 칸 `B0`~`D7` 에 그림을 뒀습니다. 전투 중 BG3 타일맵이 가리키는 칸은 `96`~`99`·`A0`·`A1` 뿐이었지만, 주인공이 공격하자 연출이 칸 `B0`~`122`(VRAM 바이트 `2B00`~`322F`)를 덮어 「크리프트の こうげき!」 의 이름이 줄무늬가 됐습니다. 그래서 그림은 상태 창 이름 뒤의 빈 칸 `1D0`~ 로 옮기고 타일 bit8 은 타일맵으로 옮기는 자리에서 붙였습니다.

| 장면(실내 09/00 전투, 일행 3명, 입력 네 가지) | 결과 |
| --- | --- |
| 「…の こうげき! / 크리프트は 8の ダメージを うけた!」, 「크리프트は きぜつした!」 | 한글 이름, 줄이 올라가도 그대로 |
| 「크리프트の こうげき!」 뒤 공격 연출 20프레임 간격 16장 | 깨짐 없음 |
| 적의 メラ·ルカニ 뒤 메시지 | 깨짐 없음 |
| 주인공 주문 바기·바기마·스카라·베호이미·베호마(주인공 MP `7E:2044`·`2050` = `30`, 주문 비트 `2063`·`2064` = `FF`) | 연출 동안과 뒤 10~20프레임 간격 VRAM 덤프에서 `1D0`~`1F7` 그림이 첫 메시지 뒤로 바뀌지 않음, 「크리프트は バギマを となえた!」 등 이름 그대로 |

## 창 글자

이름 표 문자열(도구·주문·몬스터 이름)과 창 고정 문구를 Galmuri9 로 찍는 공통 엔진입니다. 지금은 도구 목록(`D3`)과 주문 목록(`D6`, 필드·전투), 명령 창·つよさ·さくせん·「どうする」·전투 명령 창과 창 제목의 고정 문구, 전투 몬스터 목록·전투 도구 창(`E6`·`C9`)이 켜져 있습니다. 사용자 결정으로 목록 글꼴도 Galmuri9 이고, 도구 창 8줄 시안에서 Galmuri7(칸 46개)보다 Galmuri9(칸 109개)를 골랐습니다.

### 한글 표

`sfc/dq4/tools/dq4windowtext.py` 가 롬의 이름 표(`21:955D`, `BRK 88 2B`)를 **일본어 이름**으로 `nds/dq4/tables/adopt.tsv` 의 DS 일본어와 잇습니다(가타카나·히라가나, 빈칸 차이는 무시). 번호로 잇지 않는 것은 DQ4 데이터를 옮겨 번호가 바뀌어도 그대로 쓰기 위해서입니다. 맞지 않는 DQ5 고유 이름은 표에 넣지 않아 가나로 찍힙니다. DS 가 FC 이름을 바꾼 줄(근거 칸 「FC:いばらのむち」 등)은 FC 이름으로도 찾습니다. 롬의 이름이 FC 이름과 같기 때문입니다(いばらのムチ → 가시 채찍, モーニングスター → 모닝스타, ブーメラン → 부메랑). FC 물건에 빌려준 DQ5 물건 자리(`dq4itemport.BORROWED`, [가게](dq4-environment-format.md#물건-값과-빌린-자리))는 번호로 덮습니다.

| 이름 표 | 이름 수 | 맞은 수 |
| --- | --- | --- |
| 5 도구 | 256 | 99(FC 이름 셋, 빌린 자리 하나) |
| 3 주문·특기 | 256 | 122(일곱 열 넘는 1개는 가나) |
| 4 몬스터 | 240 | 29(전투 몬스터 목록 아홉 칸) |

그림은 뱅크 `58` 에 둡니다. `58:8000 + 표 × 200` 에 번호마다 그림 주소(0 = 없음), `58:9000` 에 고정 문구의 캔버스 밖 전용 칸 표, `58:9200`~ 에 `[열 수][열마다 위 줄 7줄째 1바이트 + 글자 줄 8바이트]`(1bpp). 글자 맨 윗줄은 위 줄 타일의 7줄째이고, 위 줄의 나머지 일곱 줄은 늘 비어 두지 않습니다(열마다 16바이트로 두다가 작전 이름을 더하자 뱅크의 32KB 를 넘어 9바이트로 줄임).

### 찍는 길

`D3`(`04:B82F`)가 `BRK 88 2B`(`$42` = 번호, `$43` = 표)로 DP `$00`(길이)·`$01`~ 에 이름을 받고, `04:BADB` → `04:B808` 이 글자마다 `04:B235` 로 `($E0),Y` 에 씁니다. `04:B808` 을 `WnText` 로 바꿔, 표에 한글이 있으면 다음을 합니다.

| 단계 | 내용 |
| --- | --- |
| 칸 | 큰 20칸·중간 14칸·작은 8칸 슬롯과 캔버스 밖 전용 칸([칸 슬롯 나누기](#칸-슬롯-나누기)). 같은 버퍼 자리(`$E0 + Y`)·같은 크기면 같은 슬롯, 아니면 그 크기에서 가장 오래 쓰지 않은 슬롯 |
| 그림 | 글자 줄 열 칸, 위 줄 열 칸. 위 줄은 지금 그 자리 타일(테두리·가나·빈칸)의 그림에 글자 맨 윗줄을 겹친다 |
| 전송 | 우리 대기열(`7E:3EB0`~`3FFF`)에 넣고 NMI 가 보낸다. 글자 줄은 평면 0 만 넣고 NMI 가 평면 1 을 `FF` 로 채운다 |
| 타일맵 | 글자 줄·위 줄 낱말. 높은 바이트는 우선·팔레트만 살리고, 색(`$EC` bit6 이면 `$ED`)이 있으면 글자 줄에 쓴다 |
| 돌려주기 | Y 는 원래처럼 **탁점(`84`·`83`)을 뺀 바이트 수 × 2** 만큼, A 에는 마지막 글자 바이트. `04:BFF2` 는 `PLB / PLP / RTS` 라 창 해석이 이 둘을 그대로 이어 쓴다. 한글이 가나보다 짧으면 남는 칸을 빈칸 `01` 로 |

### 전송: 게임 목록 대신 우리 대기열

NMI(`00:885D`)는 `$19` bit0 을 끄고, `$19` bit7 이 꺼져 있으면 `JMP ($1944)` → `00:8926` 에서 `JSR $894F` → `JMP ($1946)` 로 작업 하나를 돌립니다. `$1946` 은 평소 `00:8DE9` 이고, 게임이 목록을 보낼 때만 `00:8CEF`(`$19` bit2 가 켜져 있으면 `00:8CF9` 로 목록을 보냄)로 바뀌었다가 돌아옵니다(`00:882C`·`00:885A` 쓰기 실측). 즉 NMI 전송 목록은 게임이 프레임 끝에 한 번 쓰는 장치입니다.

창을 그리는 도중 이 목록에 그림을 끼우자(이름 작업과 같은 방법), 도구 창의 첫 그리기는 됐지만 목록을 활성화하는 단계로 넘어가지 못해 메뉴가 닫힌 것처럼 됐습니다. 전송만 빼면 원래 흐름이었고, 항목을 1워드로 줄여도 흐름이 달라졌습니다. 그래서 NMI 가 `$1944` 작업으로 가는 `00:887C`(`JMP ($1944)`)를 `JMP $FFA1` 로 바꿔, 받침이 우리 대기열이 있을 때만 `JSL WqNmi` 로 DMA 채널 0 으로 보낸 뒤 `JMP ($1944)` 로 잇게 했습니다. 처음에는 필드 작업(`00:8926`)에만 걸어 전투(`$1944` = `00:8952`)에서 그림이 안 갔고, 받침이 늘 `WqNmi` 를 부르게 했을 때는 전투 화면에 8×8 검은 칸이 생겼습니다(NMI 가 길어져 게임의 VRAM 쓰기 하나가 VBlank 를 넘긴 것으로 봄). 비어 있으면 바로 넘기게 하자 사라졌습니다. 게임 목록(`$0758`·`$1A`·`$19`)은 건드리지 않습니다. 대기열이 차면 NMI 를 끈 채 다음 VBlank 를 기다려(`$4212` bit7) 직접 보내고, 그 프레임의 게임 NMI 는 `$4210` 을 읽어 건너뜁니다. 처음에는 NMI 가 비워 주기를 기다리다 65536번 돌면 넘어갔는데, 넘어갈 때 항목 수(`7E:3D62`)를 남긴 채 쓸 자리만 0 으로 되돌려 NMI 가 옛 머리를 읽을 수 있었습니다.

창 타일맵은 `00:8DE9` 가 보냅니다. `$0BEC` bit7 이면 버퍼 `7E:5000` 2KB 전체를, bit6 이면 위 7줄(`00:8E55`)과 21~29번째 줄(`00:8E75`)을 보내고 `$0BEC` 를 0 으로 둡니다. 요청은 `04:9D35`(bit7)·`04:9D5E`(bit6)가 걸고, `$0BEC` 를 읽는 곳은 `00:8DED` 하나입니다. 우리 대기열은 `$1944` 작업보다 먼저 가므로, 둘이 한 NMI 에 겹치면 2KB DMA(약 12줄)가 VBlank 끝을 넘겨 창 아래쪽 줄이 VRAM 에 가지 않습니다. 강함 보기 1쪽에서 대기열 항목 넷을 보낸 NMI 의 타일맵 DMA 가 줄 252 에서 시작했고, 화면에는 창 20번째 줄부터 옛 내용이 남았습니다. 그래서 `WqNmiGate` 는 겹치면 대기열을 보내고 `$0BEC` 를 `7E:3D5A` 에 옮겨 두었다가 다음 NMI 에 되돌립니다. 대기열 쪽을 미루면 안 됩니다. 명령 창이 떠 있는 동안 게임이 매 프레임 bit7 을 걸어(기록한 41~68 프레임 내내), 명령 창 문구 여섯 항목이 끝내 올라가지 않았습니다.

### 주문 목록

`D6`(`04:B8B9`)은 주문 이름(표 3)을 받아 `04:B8F2`(`PHX / LDX #0 / LDA #5 / STA $00 / BRL $B7A3`)에서 **탁점이 아닌 글자 다섯**을 찍습니다. `04:BD4F`·`04:BD9F` 도 스스로 `PHX` 를 한 뒤 `BRL $B8F3` 으로 `LDX #0` 부터 들어오므로, `PHX` 다음 자리 `04:B8F3` 을 `WnSpell` 로 바꿔 `WnText` 와 같은 길을 타고, Y 는 늘 10, A 는 다섯째 글자 바이트를 돌려줍니다. 주문이 없는 칸은 이름을 받지 않고 빈칸 문자열(`01`)을 찍어 `$42`·`$43` 에 앞서 받은 이름이 남아 있으므로, 찍을 문자열 첫 바이트가 `01` 이면 원래 길로 넘깁니다(강함 보기 2쪽 「전투 주문」 창에 「슬라임」 이 그려졌음). `D6` 을 본문에 쓰는 창은 `28`(머리 `4F 04 88 B1`, 너비 8 = 이름 다섯 칸)뿐이라 너비를 10 으로 넓혔습니다. 한글 주문 이름은 3~4열 63개, 6~7열 56개이고, 10열인 「얼어붙은 눈보라」(몬스터 특기)는 가나로 둡니다. 전투 주문 창(「크리프트のじゅもん」)도 `04:B8F3` 을 지나 두 줄 배치 그대로 한글이 됩니다.

### 고정 문구

명령 창(`01`)과 도구의 「どうする」 창(`10`)의 가나 항목을 한글로 바꿨습니다. 빌드 때 `dq4windowtext.fixed_records` 가 창 레코드에서 항목 머리 `FE` 바로 뒤의 가나를 일본어로 읽어 문구 표와 잇고, 그 자리를 접두 `9E k`(고정 문구 `k`)와 빈칸 `01` 로 바꿉니다. 그림은 이름 표가 쓰지 않는 종류 7(`58:8E00`~ 색인)에 이름과 같은 꼴로 둡니다.

#### 칸 슬롯 나누기

목록 이름만 그릴 때는 20칸 슬롯 12개였습니다. 명령 창 여덟 문구가 그대로 들어오면 도구 목록 여덟 줄과 함께 20칸 슬롯 16개가 필요해, 큰 슬롯 20칸(10열) 8개와 작은 슬롯 8칸(4열)으로 나눴습니다. 네 열까지는 작은 슬롯을 씁니다. 제목까지 바꾸자 「どうする」 장면에서 문구 13개(명령 창 8, 제목 2, 「どうする」 3)가 함께 보여, 작은 슬롯을 15개로 늘렸습니다. 늘린 셋(`096`~`0AD`)은 전투에서 전투 글자 칸이라 필드에서만 씁니다. 전투인지는 NMI 작업 `$1944` 가 `00:8952` 인지로 가립니다.

메시지 창이 뜨면 타일맵이 캔버스 `096`~`17F` 234칸을 모두 가리킵니다(09/00 에서 「쓰기」 뒤 메시지 화면의 VRAM 덤프). 처음에는 작은 슬롯을 `17F` 아래로만 두어, 명령 창과 「どうする」 가 작은 슬롯을 다 쓴 뒤 「천 옷」 이 `128` 에 그려졌고 메시지가 뜨자 지워졌습니다. 그래서 한때 캔버스 밖의 `1F8`·`1D0`·`1E4` 를 목록 이름에 먼저 줬습니다.

### 전투 몬스터 목록과 전투 도구 창

전투 몬스터 목록 창(`1B`, 본문 `FE E6 01 88 C8 2A 16`)에서 `C8`(`04:B67B`)은 마릿수(「1ひき」의 숫자), `E6`(`04:BBB2`)이 이름입니다. `E6` 은 `BRK 88 2B`(`$43` = 4 몬스터 표, `$42` = 번호)로 이름을 받은 뒤 `04:BC08`(`REP #$10 / LDX #0 / LDA #9 / STA $00 / BRL $B7A3`)에서 탁점이 아닌 글자 아홉을 찍습니다(커버리지 리스팅). `C9`(`04:B6A0`)도 `BRL $BC08` 로 같은 자리에 오고, 전투 도구 창(「크리프트のどうぐ」)이 이 길로 도구 이름(`$43` = 5)을 찍었습니다(`CALLS` 기록).

| 자리 | 처리 |
| --- | --- |
| `04:BC08` → `WnMonster` | 주문 목록과 같은 고정 글자 수 길. `!wt_mode` 에 고정 글자 수(0 = 길이 바이트, 5 = 주문, 9 = 몬스터·전투 도구)를 둠. 부른 쪽이 이미 `PHX` 를 함 |

### 교회·맡기는 곳·예/아니요

#### 강함 보기 라벨

능력치 창 `07` 과 성별·레벨 창 `06` 은 줄 머리 빈칸 `01` 몇 개 + 가나 + `85`(:) 꼴로 라벨을 오른쪽에 맞춥니다. `LABEL_WINDOWS` 의 창에서 이 꼴의 줄을 찾아, 빈칸과 가나를 빈칸 + `9E k` 로 바꿔 「:」 자리를 그대로 둡니다. 가나 덩이는 `85`·`86`·`87` 에서 끊습니다. 라벨 이름은 `adopt.tsv` 의 능력치 표(힘·민첩·방어력·현명함·운·최대HP·최대MP·공격력·수비력, 성별·레벨)를 씁니다. DQ5 창은 「しゅびカ」 처럼 力 자리에 가타카나 カ 를 씁니다. 능력치 창 `07` 은 지금은 이 길 대신 왼쪽 라벨·한 줄 경험치 배치로 다시 만듭니다([경험치 줄과 HP와 MP 창](#경험치-줄과-hp와-mp-창)).

성별 값은 `06` 의 `D1`(`04:B7C3`)이 찍습니다. `BRK 88 2C` 로 받은 값을 `$42` 에, `$43` = 2 를 두고 `BRK 88 2B` 로 이름 표 2 의 문자열을 받은 뒤, `04:B7D7`(`PHX / LDX #0 / LDA #3 / STA $00 / BRL $B7A3`)에서 석 자를 찍습니다(선실 상태에서 강함 보기를 연 커버리지). 이름 표 2 는 「おとこ / おんな / ？？？」 뒤에 몬스터 종족 이름이 이어집니다. `04:B7D7` 을 `LDA #3 / STA $00 / BRL $B808` 로 바꿔 `WnText` 길로 넘기고, 한글 표에 종류 2(「남자 / 여자」, 석 열)를 더했습니다. 두 고리 모두 `PLX / BRL $BFF2` 로 끝납니다. 2쪽 오른쪽 창(`2A`)의 제목은 원래 롬도 「コマンド」 라 「명령」 이 맞습니다.

#### 슬롯 크기 셋과 안 보이는 슬롯

작전 창을 열자 큰 슬롯이 필요한 문구가 아홉(작전 여섯, 「대열 바꾸기」·「작전 짜기」, 지금 작전)이라 여덟뿐인 큰 슬롯에서 「대열 바꾸기」 가 밀려났습니다. 다섯~일곱 열 문구도 20칸을 통째로 쓰고 있어, 큰 20칸 6개·중간 14칸 5개·작은 8칸 2개(+ 필드 전용 3개)로 나눴습니다. 맞는 크기가 없으면 더 큰 슬롯을 빌립니다.

전투에서는 필드 전용 슬롯을 못 써 13개뿐이라, 오른쪽 위 작전 창 윗줄이 주문 목록의 「바기마」 로 바뀌었습니다. 가장 먼저 그린 작전 줄이 가장 오래돼 밀려났고, 이미 닫힌 「싸우기 / 작전 / 도망」 의 슬롯은 남아 있었습니다. 그래서 다시 쓸 슬롯을 「빈 슬롯 → 이미 안 보이는 슬롯 → 가장 오래된 슬롯」 순으로 고릅니다. 안 보이는 슬롯은 그 슬롯을 그린 버퍼 자리(`wt_keys`)의 타일이 더는 그 슬롯의 첫 칸이 아닌 것입니다. 같은 등급 안에서는 높은 칸부터 고릅니다. 메시지가 캔버스를 `096` 부터 채워, 낮은 칸(필드 전용 `096`~)에 둔 제목이 메시지 동안 「크리」 처럼 메시지 글자 조각으로 보였기 때문입니다.

#### VBlank 를 넘긴 대기열

「방어력」 이 빠진 것은 슬롯 수가 아니라 전송 때문이었습니다. 「방어력」 슬롯(`0A6`)의 타일맵은 맞았지만 그림이 비어 있었고, `VMADD=1` 기록에서는 우리 대기열 DMA 가 `1530`(글자 줄)·`1550`(위 줄)에 한 번씩 갔습니다. 대기열 DMA 의 주사선을 재니 252~261 을 지나 0·1 까지 이어졌습니다. VBlank 가 끝난 뒤의 VRAM 쓰기는 버려집니다. 강함 보기처럼 한 프레임에 문구 서넛을 그리면 NMI 가 늦게 우리 게이트에 닿는 프레임에 끝 항목이 빠졌고, 슬롯 순서를 바꾸자 빠지는 문구가 「방어력」 이 됐을 뿐입니다.

`WqNmi` 는 이제 항목마다 V 카운터(`$213F` → `$2137` → `$213D` 두 번)를 읽어, 225 미만이거나 259 이상이면 남은 항목을 다음 NMI 로 넘깁니다(다음 항목 자리 `7E:3D5C`). `$2137` 래치는 `$4201` bit7 이 켜져 있어야 하는데, 게임은 부팅 때 `00:8711` 에서 `$4201` = `FF` 로 둡니다. 대기열이 차서 NMI 를 끄고 직접 보내는 길은 대기열이 빌 때까지 VBlank 마다 되풀이합니다. 고친 뒤 대기열 DMA 는 주사선 240~260 에서 끝났고, 「방어력」 이 나왔습니다. 빈 슬롯은 같은 크기 안에서 가나 칸 슬롯부터 고릅니다. 가나 칸은 메시지 캔버스 밖이라 메시지가 떠도 덮이지 않고, `WqClean` 의 비트 표에서도 빠집니다.

| --- | --- |
| `WtClass` | 크기 0·1·2 에 `$10` 을 더하면 필드 전용. 가나 칸 슬롯과 `09E`~`0AD` 슬롯이 `$10`~`$12`. `WtFits` 는 전투(`$1944` = `00:8952`)면 필드 전용을 건너뜀 |

전투에 들어갈 때 게임은 가나 칸을 다시 올리지 않고, 전투 메시지와 몬스터 목록은 그 가나 1바이트 타일을 그대로 씁니다. 그래서 전투에 들어가면 가나 그림을 되돌립니다. 게임이 올린 가나 칸은 평면 0 = `04:E528` 의 1bpp, 평면 1 = `FF` 였습니다(VRAM 덤프와 롬을 견줘 105칸 일치). 따로 그림을 둘 필요 없이 롬에서 바로 보냅니다.

`$0BEC` 를 미뤄 두는 바이트(`3D5A`)를 함께 쓰므로, 게이트는 bit7·6 만 `$0BEC` 로 되돌리고, 대기열과 겹쳐 `$0BEC` 를 미룰 때도 덮어쓰지 않고 OR 로 넣습니다. 처음에는 덮어써, 강함 보기를 닫은 뒤 `3D5A` 가 0 이 되어 전투에서 가나가 깨졌습니다.

메시지와 함께 뜨는 창 가운데 예/아니요 `32`, 교회 `3C`, 맡기는 곳 `51`·`52`·`54` 는 전용 칸 대신 일반 슬롯으로 옮겼습니다. 도구 → 버리기의 「예 / 아니요」 가 명령 창과 함께 떠, 같은 전용 칸 `1D0`~ 을 쓰는 명령 창 「대화 / 주문」 자리에 「예 / 아니요」 가 비쳤습니다. 전용 칸에는 명령 창 `01` 과 가게 `33` 만 남습니다. 예/아니요 창 `62`(いいえ / はい)도 `32` 처럼 한 칸 넓혀 고정 문구로 바꿨습니다.

### 창 글자 깨짐 검사

`tools/dq4windowcheck.py` 가 MesenCE 로 선실 대화 번호 `00`~`3F` 64장면과 무작위 입력 여덟 벌(선실 넷, 09/00 필드 둘·전투 둘)을 돌려, 30~50프레임마다 VRAM·슬롯 키(`7E:3D70`)·나이(`7E:3D14`)·`$0725`·`$1944` 를 덤프하고 BG3 타일맵 화면 28줄의 칸을 두 규칙으로 봅니다. 가나 타일(`010`~`078`)을 가리키는데 그림이 롬 가나와 다르고 우리 키 자리(글자 줄·위 줄)가 아니면 「가나」, 필드에서 살아 있는 캔버스 안 슬롯을 우리 자리가 아닌 칸이 가리키면 「비침」 입니다. 걸린 프레임은 빨간 네모를 그린 `sheet-*.png` 로 모읍니다. 처음 돌렸을 때 걸린 것과 처리는 다음과 같습니다.

`WtVis` 는 VRAM 을 건드리지 않아 NMI 끝(`00:8885`, VBlank 일 뒤)에서 돕니다. 처음에는 게이트에서 돌려 슬롯 26개를 재는 시간만큼 게임의 2KB 타일맵 DMA 가 밀렸고, 메시지 창 아래쪽 줄이 화면으로 가지 않아 메시지가 닫힌 뒤에도 상태 창이 남았습니다. 게이트는 보낼 줄(`$0BEC` bit7·6)만 `7E:3DBE` 에 모읍니다. 받침 `00:FFA1` 은 `JML WqNmiEntry` / `JMP ($1944)` 로 줄이고, 대기열·미룬 요청·`$0BEC` 가운데 하나라도 있으면 게이트를 부릅니다. 부분 전송(bit6)은 0~6줄과 21~29줄입니다(`00:8E55`·`00:8E75`).

고친 뒤 남은 것은 다음 셋입니다. 09/00 의 몬스터 동료 이름(이름 표 `0A`, DQ5 데이터)은 가나라 필드에서 걸렸습니다. 이것은 가나 이름도 한글 이름처럼 Galmuri9 로 그리게 해 풀었습니다. `dq4windowname.kana_glyphs` 가 롬의 가나 부호(`10`~`7F`, 탁점 `84`·반탁점 `83` 접두)를 글자로 풀어 Galmuri9 가나 글리프를 이름 글리프 뒤(2,403번~)에 쓰고, 바이트 → 글리프 번호 표(평·탁점·반탁점 각 128워드)를 `60:E800` 에 둡니다. `WnName`·`WnList` 는 첫 바이트가 `10` 이상이면 받고, `WnKorean` 이 가나 이름을 한 바이트씩 표로 해독합니다. 상태 창·「누구의」 목록·전투 상태 창에 「スラリン」·「ホイミン」·「ドラきち」 가 나왔습니다. 일행 창 셋째 사람의 이름 다섯째 열은 창 오른쪽 위 모서리와 겹쳐, 다섯째 열 맨 윗줄에 점이 있는 글자(「ン」)면 모서리에 점이 생깁니다. 선실 대화 `08`(「ひのきのぼう」 일곱 줄인 시험용 가게)은 9열 이름 여덟 개가 큰 슬롯 다섯을 넘어 메시지 창에 비치고 아래 창 이름이 밀립니다. 무기점 `01` 에서 한 프레임, 목록 일곱째 문구가 캔버스로 넘쳐 비칩니다.

「대열 바꾸기」 의 창 `46`(왼쪽, 줄마다 코드 `DF`)·`45`(오른쪽, `F1`)는 「번호 이름 Lv:」 줄이라 이름 다섯째 칸을 「Lv:」 가 덮어 「크리프ㅡ」 처럼 잘렸습니다(한글 이름도). `WnList` 가 지금 그리는 창 번호(`$0A00`)가 `45`·`46` 이면 이름 뒤 Y 를 10 나아가고, 두 창을 한 칸씩 넓혔습니다(`46` 은 왼쪽으로 옮겨, `45` 는 오른쪽으로만). 정보 창 `47` 의 「せいべつ :」 는 `LABEL_WINDOWS` 에 넣었습니다. 몬스터 동료의 종족 이름(정보 창 첫 줄, `D2` 가 이름 표 4 를 씀)은 한글 그림 뱅크에 남은 자리(572바이트)가 모자라 가나로 둡니다.

### 경험치 줄과 HP와 MP 창

사용자가 패치 롬을 돌려 보고 셋을 짚었습니다.

- **「HP와 MP」 창:** 창 `03`(앞 세 사람)·`04`(넷째부터)의 머리 너비 6 은 한 사람 몫입니다. 이름 다섯째 칸이 열 사이 빈칸에 걸치므로, 맨 오른쪽 사람은 오른쪽 테두리를 덮었습니다(혼자일 때 「1:」 옆 흰 막대, 일행 셋일 때 「ホイミン」 의 「ン」). 상태 창처럼 한 사람 몫을 7 로 넓혔습니다. 창 번호는 `CALLS=049C52` 로 창을 여는 레코드 주소(`ED5B`·`ED7F`)를 모아 창 표로 되돌려 찾았습니다.
- **경험치 줄:** 능력치 창 `07` 의 마지막 줄 `86 85 BC FF` 은 「Ex」 를 한 칸에 그린 타일 `86`, 「:」, 일곱 자리 경험치(`BC`, 값 칸 여덟 칸)입니다. 창 안쪽이 10열이라 라벨이 한 칸뿐이어서 왼쪽에 붙어 있었습니다. 사용자 결정으로 라벨을 모두 왼쪽에 붙이고, 콜론을 가장 긴 라벨(「최대 HP」 5열) 다음 열에, 값을 오른쪽 끝에 맞춰 「경험치 :」 도 한 줄에 넣었습니다(`dq4windowtext.exp_record`). 창은 오른쪽으로 네 칸 넓혀 안쪽 14열입니다(왼쪽은 이름 창). 줄마다 콜론 뒤에 빈칸이 늘어 레코드가 97바이트에서 115바이트가 되므로, 원래 롬도 0 인 뱅크 `04` 끝 `04:FECA`~`04:FFFF`(310바이트)로 옮기고 창 표 `04:EB48` 의 `07` 포인터를 바꿨습니다.

### 「누가」 창과 전용 칸 빌리기

1장 이무르 방어구점에서 일행 둘(주인공·호이민)로 물건을 사면, 「어느 분께서 쓰시겠습니까?」 다음에 「누가」 창과 고른 사람의 소지품 창이 물건 목록·메시지 창과 함께 뜹니다. 이때 메시지 창 셋째 줄에 「노송나무 막대」 와 깨진 조각이 비쳤습니다([조사 코드 검증](dq4-josa-format.md#검증)에서 남긴 것). 세이브스테이트는 `dq4ch1walkcheck.py` 의 시작 상태에서 `dq5warp.lua` 로 `TO=37/00,34,8`·`PARTY=05` 를 줘 카운터 앞(셀 34,9)에 세운 것입니다.

비친 프레임(820)의 슬롯을 덤프했습니다.

가나 칸 104칸 가운데 90칸이 아직 보이는 창의 글자이고, 빈 칸은 `16`~`1B`(6칸)와 `76`~`77`(2칸)으로 나뉘어 있습니다. 일곱 열인 「노송나무 막대」(14칸)가 들어갈 자리가 없어 캔버스 안 큰 슬롯 `100` 에 그려졌습니다. 메시지 창은 캔버스 `096`~`17F` 를 모두 가리키고, 첫 줄만 쓴 메시지라 셋째 줄 칸에는 게임이 그림을 다시 보내지 않아 우리 그림이 그대로 보였습니다. 빈 칸을 모아도 104칸을 꼭 채워 여유가 없습니다.

이 장면에서 캔버스 밖 `1D0`~`1FF` 는 비어 있습니다. 그곳을 쓰는 명령 창 `01` 과 가게 창 `33` 이 닫혀 있기 때문입니다. 필드 전용 캔버스 슬롯 셋(`096`·`09E`·`0A6`, 작은 슬롯)을 이 칸으로 옮겼습니다. 옮기기 전 슬롯도 캔버스 안이라 메시지 창에 비쳤습니다.

### 목록이 가나 칸을 넘칠 때

가게 팔기 목록은 메시지 「어느 물건을 팔아 주시겠어요?」 와 함께 주인공의 가진 물건 12칸을 한 줄씩 띄웁니다. 1장에서 갖출 만한 꾸러미(철 창·철 갑옷·철 방패·철 투구, 약초 둘, 키메라의 날개, 하늘을 나는 구두, 성수, 해독초, 생명의 나무 열매, 힘의 씨앗)를 `7E:2056`~ 에 넣고 선실 도구점(대화 `02`)에서 팔기를 고르니, 앞 이름들이 가나 칸 104칸을 채우고 뒤 이름은 캔버스 슬롯으로 갔습니다. 목록 창이 뜬 뒤에도 메시지 창 양옆에 그 그림이 비쳤습니다(14칸, 13프레임). 12칸을 가장 긴 이름(키메라의 날개·하늘을 나는 구두·생명의 나무 열매·이상한 나무 열매·노송나무 막대 등)으로 채우면 넘치는 이름이 일곱이고 59칸이 비쳤습니다.

넘친 이름이 메시지 창에 비치지 않을 자리를 찾으려고 팔기 장면의 BG3 타일맵을 덤프했습니다. 메시지 창은 화면 18~26줄·3~28열에 캔버스 `096`~`17F` 를 한 줄 26칸씩 차례로 가리킵니다. 목록 창은 화면 9~21열을 덮어, 캔버스 각 줄의 7~19번째 칸(13칸)이 목록 창에 가립니다. 가게 사기의 장비 비교 창은 메시지 창의 마지막 줄(화면 26줄)을 덮지 않아, 가리는 자리는 캔버스 앞 여덟 줄로 잡았습니다. 처음에 아홉 줄로 잡자 무기점(`talk2B`)에서 그 줄에 둔 중간 슬롯 「장비 불가」 가 비쳤습니다.

그래서 필드에서는 캔버스 슬롯 표를 전투와 따로 둡니다(`WtSlotF`·`WtUpperF`·`WtClassF`). 슬롯 번호·크기 묶음·`!wt_dirty` 비트는 전투 표와 같고, 칸 자리만 다릅니다.

### 보이는 슬롯에 다른 문구

가게 사기 목록에서 커서를 옮기면 동료 창(`3A`)의 상태가 「소지 중」 ↔ 「없음」 으로 바뀝니다. 바뀌는 순간 2프레임 동안 「ㅂㅂㅂㅂ 소시[」·「없음 ㅡ」 처럼 글자가 깨졌습니다([2026-11-01-18](../journal/2026-11-01-18-shop-status-tear.md)). 상태 문구는 같은 버퍼 자리(키)에 다시 그리므로 `WtAlloc` 이 같은 슬롯을 내주고, 새 그림은 우리 대기열로 다음 NMI 에 올라갑니다. 게임의 창 타일맵(`$0BEC`)은 그보다 2프레임 늦게 가서, 그동안 옛 문구의 타일맵(「소지 중」 은 위 줄 받침까지 다섯 칸)이 새 그림을 가리켰습니다.

슬롯마다 둔 보임 바이트 `!wt_vis`(`7E:3DAC`)의 bit0 만 보임으로 쓰고, bit1~7 에 그린 문구의 표식(그림 자리 `!wt_ptr` 의 7비트 해시)을 둡니다. `WtAlloc` 은 같은 키의 슬롯이 보이는 중이고 표식이 다르면 그 슬롯을 건너뛰고 새 슬롯을 받습니다. 옛 슬롯은 같은 키로 남아, 게임이 새 타일맵을 보내면 `WtVis` 가 그 키 자리가 새 슬롯을 가리키는 것을 보고 옛 슬롯을 안 보인다고 표시합니다. 같은 문구를 다시 그리거나 안 보이는 슬롯이면 원래처럼 그 슬롯에 그립니다. 해시 자리는 이름 그리기(`WnKorean`)의 임시값 `!wn_s`(`7E:1D0C`)와 함께 씁니다. 둘은 겹쳐 돌지 않습니다.

`dq4windowcheck.py --shop` 에 장면 `shopflip`(도구점 목록에서 약초 ↔ 해독초, 매 프레임)과 규칙 「바뀜」 을 더했습니다. 바로 앞 프레임과 이 프레임에 슬롯이 보이고 키 자리 타일맵 두 줄이 그대로인데 슬롯 그림이 바뀌면 걸립니다.

### 가게 목록의 값과 G

가게 사기 목록(창 `39`)은 줄마다 `FE EE 01 01 01 CB FF` 입니다. 커서, 물건 이름(`EE`, 9열), 빈칸 셋, 값(`CB`)입니다. `CB`(`04:B6D6`)는 줄 번호 `$0BA2` 로 가게 물건을 받아 `BRK 94 02` 로 값을 `$46`~`$48` 에 두고, `04:C0AB` 로 자릿수를 나눈 뒤 `04:B4D8` 에서 `$03`~`$07` 다섯 자리를 찍습니다. 빈칸 하나를 값 뒤의 `0F` 로 바꿔 「약초 8G」 꼴로 했습니다. `0F` 는 골드 창(`05`, `0F BB`)의 「G」 글자입니다. 창 안쪽 18열은 그대로입니다. 오른쪽에 골드 창이 붙어 있어 넓히지 않았습니다.

팔기 목록은 창 `37`(`89 02 0F`)입니다. 레코드 첫 바이트의 bit7 이 서면 별칭이고, 셋째 바이트의 창(`0F`, 물건 목록)을 첫 두 바이트의 자리(x 9, y 2)에 엽니다. 창 표를 읽는 자리 가운데 별칭을 따로 푸는 곳은 셋입니다: 창 열기 `04:9C5C`, 그리기 `04:9FBB`, 크기 셈 `04:A8C2`. 셋 모두 `$DA` 에 별칭 레코드 주소를 두고 `LDA $EB48,X` 로 대상 레코드를 읽습니다(커버리지). 창 `0F` 는 필드 도구 창(별칭 `12`·`50`)과 함께 쓰고, `37` 은 맡기는 곳(`06:E5E5`)도 엽니다. 그래서 세 자리를 `JSR ShopListRes` 로 바꿨습니다. `$DA` 가 `37` 이고 가게(`$0F20` 이 4 미만)일 때만 새 레코드를 돌려주고, 창의 x(`$0A43`)를 사기 목록과 같은 2 로 둡니다. `$0F20` 은 가게 처리기가 정하는 종류입니다(`06:DBDB` 표: 도구점 `E01F` = 0, 방어구점 `E026` = 1, 무기점 `DC04` = 2, 맡기는 곳 `E4DE` = 6).

새 레코드는 `0F` 와 같은 머리에 너비 20, 본문 `FE D3 01 D9 FF` 입니다. `D3`(`04:B82F`)은 `BRK 88 46`(「누가」 창 줄 `$E4` → 사람)과 `BRK 88 2E`(`$42` = 사람, `$43` = 칸. 칸은 지금 그리는 줄 `$0B9E`)로 물건을 받아 이름을 찍습니다. `D9` 는 원래 DQ5 디버그 창 `6C` 만 쓰는 코드인데, 메뉴 패치가 `6C` 를 다시 써 지금은 아무 창도 쓰지 않습니다. 그 갈래(`04:B3A2` 표)를 `ShopSellPrice` 로 돌렸습니다. 같은 두 `BRK 88` 로 물건을 다시 받아 다음 순서로 찍습니다.

1. `BRK 94 06` 의 C 가 서면 팔 수 없는 물건이라 「판매불가」 를 찍습니다(고정 문구, Galmuri9 여섯 열).
2. 팔 수 있으면 `BRK 94 02` 값의 3/4(`06:DF75` 와 같은 셈)를 다섯 자리로 찍고 「G」 를 붙입니다. 셈의 임시값은 `04:C0AB` 가 곧 덮는 `$03`~`$05` 에 둡니다. `06:DF75` 처럼 `$0F28`~ 에 두면, 예/아니요 사이에 목록을 다시 그릴 때 가게가 실제로 치르는 값(`06:DF23` 이 `$0F28`~ 을 읽어 `BRK 88 4A`)을 마지막 줄 값으로 덮습니다.

`D3` 은 이름 뒤 Y 를 원래 가나 길이만큼만 나아가므로(「약초」 는 Y `0C`, 줄 첫 칸 `$E0` 기준), 값은 Y `18`(안쪽 12열)부터 찍어 오른쪽 끝을 맞춥니다. 처리기와 레코드는 뱅크 `04` 끝 `04:FF40`~ 에 두고, 경험치 줄 레코드의 자리(`EXP_SPOT`)는 그 앞까지로 줄였습니다.

### 가게 동료 창의 가진 개수

가게 사기 목록 아래 동료 창(`3A`)은 사람마다 고른 물건(`$0F22`)의 상태를 찍습니다. 「소지 중」 을 고르는 곳은 둘입니다: 장비류 `04:C3B1`, 도구 `04:C508`. 둘 다 `LDY #$000A / BRL $C440` 입니다. `C440` 은 문자열 버퍼 `$00`~`$0F` 를 빈칸 `01` 로 채운 뒤 `04:C511` 표(`INLINE_STRINGS` 로 `9E k` 고정 문구)에서 `Y` 번째 문구를 `$01`~ 로 베끼고, `04:C45A`(`PLY / RTS`)로 끝납니다. 두 자리를 `JML ShopHeldCount` 로 바꿨습니다. 그 사람 소지품 12칸에서 같은 물건을 세어 `$01` = `9E`, `$02` = 「 N개 소지」 문구 번호를 넣고 `04:C45A` 로 돌아갑니다. 사람은 `BRK 88 46`(줄 `$E4` → 사람)으로, 칸마다 물건은 `BRK 88 2E`(`$42` = 사람, `$43` = 칸)로 받습니다. 두 자리는 `BRK 88 33`(`04:C313`)이 그 사람 소지품에서 물건을 찾은 뒤, 장비 중인지(`04:C31C`~)와 장비할 수 있는지를 가른 다음에만 옵니다. 장비할 수 없는 물건은 원래대로 「장비 불가」 가 나옵니다(아래 표).

`ShopHeldCount` 는 처음에 창 코드가 있는 뱅크 `60` 에 두었습니다. BRK 처리기가 DB 를 부른 뱅크로 두므로, [가게 도구 여러 개 사기](#가게-도구-여러-개-사기)에서 가게의 BRK 도우미를 모두 원래 롬도 빈 뱅크 `05` 끝으로 옮겼습니다. `dq4brkscan.ALLOWED` 는 `BRK 88` 을 높은 뱅크에서 써도 되는 명령으로 두지만 명령 번호로만 가르고, 여기서 쓰는 하위 명령(`46`·`2E`·`49`)을 열린 버스 프로브로 따로 잰 것은 아니라 미리 옮긴 것입니다.

문구는 「 1개 소지」~「 12개 소지」 열두 개(`HELD_COUNT`, 번호가 이어지게 둠)입니다. 가장 넓은 「 12개 소지」 가 일곱 열로 「 장비 불가」 와 같아 창은 그대로입니다. 열두 문구 그림이 678바이트라 뱅크 `58` 의 남은 600바이트(서곡 단계 롬 기준)를 넘었습니다. 이름처럼 고정 문구도 같은 그림은 한 번만 두게 하니(전용 칸 창 문구가 일반 번호로 또 나오는 것 등) 502바이트가 줄어 들어갔고, 889바이트가 남습니다. 같은 그림이면 그림 자리도 같아 슬롯 표식([보이는 슬롯에 다른 문구](#보이는-슬롯에-다른-문구))도 같습니다.

### 가게 사기 전 확인

원래 사기는 물건을 고르면 008 「{I} 말이죠. 알겠습니다!」, 일행이 둘 이상이면 「누가」 를 거쳐 곧바로 돈을 뺐습니다. 사기 스크립트(`06:DC2F`~, 커버리지)는 도구 갈래와 장비 갈래가 따로 값을 `$0F28`~ 에 두고(`06:DCDF`·`06:DDFC`, 같은 13바이트) `JSR $F5E9` 로 돈을 뺍니다. `F5E9` 는 `06:F602`(`BRK 88 49` 로 가진 돈을 받아 값과 견줌, 모자라면 C)가 통과해야 뺍니다.

두 자리를 `JSR ShopBuyConfirm`(`06:FFB0`~)으로 바꿨습니다. 값을 둔 뒤 `F602` 로 돈이 되는지 보고, 되면 다음 순서로 묻습니다.

1. 값을 `$F5`~`$F7` 에 둡니다(팔기 058 처럼 {N} 이 읽음).
2. `BRK 95 00` 으로 창을 닫습니다.
3. 메시지 묶음 `19`(064~067, 원작에서 끝 코드만 있는 빈 묶음, 사기 스크립트도 쓰지 않음)를 `06:DFC4` 로 띄웁니다. 「{N}골드인데 사시겠어요?」 처럼 가게마다 말투가 다릅니다.
4. 예/아니요(`BRK 95 32`)를 묻습니다.

「예」 거나 돈이 모자라면 돌아가 원래대로 돈을 빼거나 020 「돈이 모자란」 으로 갑니다. 「아니요」 면 돌아갈 자리를 버립니다(B 로 닫으면 `$E8` 이 `FF` 라 같은 갈래로 가지만 화면으로는 보지 않았음). 팔기 「아니요」(`06:DF48`)처럼 창을 닫고 묶음 `18`(060 「그래요? 그거 아쉽네요…」, 방어구점은 `DFC4` 가 `BRK 97 60` 으로 가름)을 띄운 뒤 물건 목록 `06:DC2F` 로 갑니다. 그 사이 스크립트는 스택을 쌓지 않습니다(`DC51`~`DC62` 의 `PHA`·`PLA` 는 짝이 맞음). 008·009 의 「알겠습니다!」·「감사합니다.」 는 확인 앞이라 뺐습니다.

처음에는 이 흐름을 뱅크 `60` 코드로 짜 `JSL` 로 불렀습니다. 메시지(`JSL $248157`)는 돌아왔지만 `BRK 95 32`·`BRK 95 00` 은 돌아오지 않아 화면이 멈췄습니다. 뱅크 `06` 끝(`06:FF40` 합류 팡파르 뒤의 빈자리)으로 옮기니 돌았습니다. BRK 처리기는 DB 를 부른 코드의 뱅크로 두고, 뱅크 `40` 이상에는 낮은 WRAM 거울이 없습니다. `BRK 95` 는 창 번호를 DB 기준 `STA $0A00` 으로 써서 높은 뱅크에서 부르면 안 되는 명령입니다(`dq4brkscan.FORBIDDEN`, [호환성](dq4-compat-format.md)). 그 전에 `BRK 95 00` 없이 메시지를 띄웠을 때도 멈췄습니다. 「누가」·소지품 창이 열린 채라 메시지가 찍히지 않았고, 예/아니요가 메시지 끝을 기다렸습니다.

### 가게 도구 여러 개 사기

도구(종류 4 이상) 갈래는 사기 전 확인 앞에서 개수를 묻습니다. 장비는 산 뒤 그 사람에게 「바로 장비하시겠어요?」 를 묻는 흐름이 이어지고, 같은 장비를 여럿 사는 것은 보통 다른 사람에게 주려는 것이라 지금처럼 하나씩입니다.

도구 갈래의 값 저장(`06:DCDF`)은 `JSR ShopBuyTool`(`06:FE64`~, 대화 훅 뒤의 빈자리)로 갑니다. 「누가」 를 고른 뒤라 소지품 주인 `$0F23` 이 정해져 있습니다.

1. 최대 개수를 셉니다(`ShopQtyMax`). 그 사람 빈칸(12 − `BRK 89 80 2F` 의 가진 수)과 9 가운데 작은 수까지, 가진 돈(`BRK 88 49`)에서 값을 몇 번 뺄 수 있는지 셉니다.
2. 최대가 2 이상이면 창을 닫고 「몇 개 사시겠어요?」 를 띄운 뒤 수 창 `5C` 를 엽니다. 문구는 원작에서 비어 있고 부르는 곳이 없는 메시지 `9C`·`9D`·`AB`·`C3` 을 가게 종류마다 고릅니다. 창은 맡기는 곳 등과 함께 쓰는 다섯 자리 입력이고, 커서가 맨 끝 자리에서 시작해 위·아래로 개수를 고릅니다.
3. 창이 닫히면 `$E8` 이 0 이면 고른 것입니다. 자리마다 숫자는 `$0AFE`~`$0B02` 에 남습니다(`06:EF06` 이 이것을 값으로 바꾸는 자리, 원래 `5C` 를 쓰는 `06:EE54`). 끝 자리를 개수로 쓰고, 앞 자리가 0 이 아니거나 최대보다 크면 최대로 맞춥니다. 0 이거나 B 면 사기 전 확인의 「아니요」 와 같은 길입니다.
4. 개수 × 값(`ShopQtyTotal`)으로 사기 전 확인(`ShopBuyConfirm`)에 갑니다. 「{N}골드인데 사시겠어요?」 의 {N} 이 합계입니다. 「예」 면 `06:F5E9` 가 합계를 뺍니다.
5. 개수는 물건을 줄 때까지 `$0F21` 에 둡니다. 물건을 주는 자리 앞(`06:DD39`)의 `JSR ShopGiveExtra` 가 하나 모자라게 `BRK 89 80 30` 으로 더 주고, 마지막 하나는 원래 코드가 줍니다. `$0F21` 은 팔기(`06:DEA7`)·필드 도구 메뉴(`05:806F`) 등이 사람 번호로도 씁니다. 장비 갈래도 「바로 장비하시겠어요?」 에 아니요거나 장비할 수 없으면 `06:DE77` → `06:DCFF` 로 `06:DD39` 를 지납니다. 그래서 장비 갈래의 값 저장(`06:DDFC`)은 `ShopBuyEquip` 이 `$0F21` = 1 을 둔 뒤 확인으로 갑니다.

BRK 를 부르는 도우미(`ShopQtyMax`·`ShopQtyTotal`·`ShopHeldCount`)는 뱅크 `05` 끝(`05:FF00`~, 원래 롬도 비어 있고 아무 도구도 쓰지 않는 자리)에 둡니다. 처음에 창 코드가 있는 뱅크 `60` 에 두었다가, 저장소의 호환성 가드가 「뱅크 `40` 이상 코드의 BRK 는 DB 가 그 뱅크가 되어 열린 버스를 읽는다」(#904)고 알려 주어 옮겼습니다. `BRK 94` 는 `dq4brkscan.ALLOWED` 에 없고, `BRK 88`·`89` 도 여기서 쓰는 하위 명령을 따로 잰 것은 아닙니다. 수 창이 앞 자리에 맡기는 곳에서 넣은 숫자를 남기는지는 재지 않았습니다(남으면 최대로 맞춰짐).

### 가게 같은 물건 여러 개 팔기

팔기에서 고른 물건과 같은 물건을 그 사람이 더 갖고 있으면 개수를 묻습니다. 팔기 스크립트는 물건을 고른 뒤 `06:DF06` 에서 한 개 값을 내고(`06:DF5B`, 산 값의 3/4 를 `$0F28`~ 와 메시지의 {N} `$F5`~ 에), 058 「{N}골드에 사들일게요」 와 예/아니요를 묻습니다. 「예」 면 `$0F28`~ 만큼 돈을 더하고(`BRK 88 4A`), `06:DF35` 에서 사람 `$0F21`·칸 `$0F23` 으로 `BRK 89 80 32` 를 불러 그 칸을 뺍니다. 빼면 뒤 칸이 앞으로 당겨집니다(약초·해독초·약초에서 첫 약초를 팔면 해독초·약초, 실측).

두 자리를 `JSL` 로 바꿨습니다. 코드는 원래 롬도 비어 있고 공용 빈자리 표에만 있는 `12:FEB0`~ 에 둡니다(뱅크 `40` 아래라 BRK 가 WRAM 을 읽음). 팔기에서 `$0F21` 은 사람이라 개수는 `$0F2C` 에 둡니다. 여관과 `06:E03E` 처리기가 0 으로 지우기만 하고 팔기 흐름에서는 읽지 않는 자리입니다.

1. `ShopSellQty`(`06:DF06`)가 원래처럼 한 개 값을 낸 뒤 같은 물건 수를 셉니다. 고른 칸 말고 그 사람 칸에서 `BRK 88 2E`(`$42` 사람, `$43` 칸 → `$46` 물건, `$47` 장비 중)로 같은 물건이고 장비하지 않은 것을 세어 1 을 더합니다(9 까지).
