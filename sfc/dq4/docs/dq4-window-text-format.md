# 게임 안 창 한글 조사

게임 안 창(상태 창·도구 목록·전투)에 한글을 찍기 전에, 이름이 창으로 가는 길과 장면마다 남는 BG3 타일 칸을 실측한 조사입니다. 구현한 것은 [BG3 타일맵 옮기기](#bg3-타일맵-옮기기)와 [상태 창 이름](#상태-창-이름)입니다. 기준 롬은 [글꼴](dq4-menu-format.md#글꼴)을 Galmuri9 로 바꾼 메뉴 빌드(SHA-1 `cd599f5bf9daa1b0426527034eecfb6dfd6c4dc7`)입니다.

## 왜 창이 문제인가

창 글자는 바이트가 곧 BG3 타일 번호입니다([메뉴 한글화](dq4-menu-format.md#글자-그리는-길)). 원래 글자 타일은 `01`~`8A` 의 가나·숫자·기호 138칸뿐이라, 한글은 문자열마다 그림을 그려 빈 타일 칸에 올려야 합니다. 주인공 이름만의 문제가 아닙니다. 동료 이름·도구·주문·몬스터 이름처럼 창에 찍히는 한글은 모두 같은 길을 지나야 합니다.

## 이름이 창으로 가는 길

선실 세이브스테이트(`work/state/ship.mss`)와 전투 세이브스테이트(`work/state/bt00-dq5spell2.mss`)에서 명령 창·つよさ·전투 공격을 실행하며 실행 감시를 걸었습니다(`sfc/dq5/tools/lua/dq5msg.lua` 의 `CALLS`).

| 길 | 쓰는 곳 | 하는 일 |
| --- | --- | --- |
| `04:ABCF` | 필드·전투의 상태 창 맨 위 이름 | 이름 4바이트를 `STA ($DC),Y` 로 타일맵 버퍼에 그대로 씀. `84`·`83` 이면 한 줄 위(`$DC − 40`)에 탁점 타일 `92`·`93` 을 덮어씀 |
| `24:A83C` | 전투 메시지의 이름(`$70` bit7) | 이름 바이트를 그대로 `7E:0ECB` 에 옮기고 `FF` 로 끝냄. 전투 글은 바이트를 BG3 타일로 찍음([DQ5 「1바이트 부호」](../../dq5/docs/dq5-hangul-format.md#1바이트-부호)) |
| `04:B33A` → `04:B3A2` 표 | 창 문자열의 `B0` 이상 자리 표시 | `B0`~`CF`, `D0`~ 를 표로 갈라 숫자·이름 등을 찍음. 이름을 찍는 코드 번호는 아직 다 가르지 못함 |

필드 상태 창의 이름은 위 테두리 아래 글자 줄 하나(8점)에 4타일로 찍힙니다. 바로 아래가 구분선입니다. 화면 y 좌표로 위 테두리 선 아래부터 구분선 위까지 148~162 의 15점이 비어 있어, 9점 글꼴은 테두리 줄과 구분선 줄의 타일까지 함께 그려야 들어갑니다(탁점 `92`·`93` 이 테두리 줄을 덮는 것과 같은 방식).

## 장면마다 BG3 타일

`sfc/dq4/tools/dq4bg3tiles.py` 로 VRAM 덤프에서 BG3 타일맵(워드 `1C00`, 32×32)이 가리키는 칸을 셌습니다. 장면마다 한 프레임의 덤프이고, 가리키지 않는 칸에도 이전 그림이 남아 있었습니다. BG3 글자 칸은 `000`~`17F` 384칸이고 `1C00` 부터 타일맵입니다.

| 장면 | 프레임 | 쓰는 칸 | 타일맵이 가리키지 않는 칸 |
| --- | --- | --- | --- |
| 필드 명령 창 + 상태 창 | 100 | 37 | `093`~`17F` 전부와 안 쓰는 가나 |
| つよさ | 260 | 33 | `091`~`17F` 전부와 안 쓰는 가나 |
| 대화 메시지 | 200 | 238 | `001`~`08B`, `08F`~`095` |
| 도구 목록 | 190 | 35 | `093`~`17F` 전부와 안 쓰는 가나 |
| 도구 목록 + 메시지 | 340·400 | 267 | 안 쓰는 가나·숫자(`002`~`011` 등)와 `093`~`095` 뿐 |
| 전투 명령 | 60 | 36 | `099`~`17F` 전부와 안 쓰는 가나 |
| 전투 메시지 | 150 | 22 | `099`~`17F` 전부와 안 쓰는 가나 |
| 전투 주문 | 100 | 27 | `099`~`17F` 전부와 안 쓰는 가나 |

- 보행 메시지가 뜨면 글자 캔버스가 `096`~`17F` 234칸을 모두 씁니다. 메시지 창과 이름이 든 상태 창은 함께 뜨지 않았습니다(상태 창은 메시지가 뜨면 닫힘). 그러나 도구 목록 창(도구 이름)은 「…を 道具として 使ってみた。」 메시지와 함께 떠 있었습니다. 이때 남는 칸은 가나 타일뿐입니다.
- 전투 메시지는 1바이트 타일이라 캔버스를 쓰지 않았고, 전투 중에는 `099`~`17F` 가 비었습니다.

## 가나 칸을 한글 칸으로

창 글자 타일 `01`~`8A`(`04:E528`, 1bpp)를 그려 갈랐습니다.

| 칸 | 내용 |
| --- | --- |
| `02`~`0B` | 숫자 0~9 |
| `0C`~`0F` | H M P G |
| `10`~`7A` | 가나(작은 가나·ー 포함), `79`·`7A` 는 ？！ |
| `7B`~`8A` | ▼ ▶ ⇒ ✝ 눈, ※ ◎ / 。 탁점 반탁점 : Ex Lv ー ＊ E |

이름 부호 표 `24:B270` 의 `01`~`7E` 가운데 가나는 105칸이었습니다. 창 글자를 모두 한글로 옮긴다는 전제에서는 창이 가나를 쓰지 않으므로, 이 100칸 남짓을 한글 타일을 그때그때 그려 넣는 칸으로 돌릴 수 있습니다. 메시지가 떠 있어도 이 칸은 캔버스와 겹치지 않습니다.

## 글꼴 크기와 타일 수

도구 목록은 항목마다 글자 줄과 그 위 탁점 줄을 쓰는 16점 간격입니다(도구 목록 장면 타일맵 4·6줄 글자, 5줄 탁점). 창 안쪽은 4~26줄, 16~25열(10열)이었습니다. 이름 폭을 BDF 로 쟀습니다.

| 이름 | Galmuri7(7×7) | Galmuri9(9×9) |
| --- | --- | --- |
| 크리프트 | 32점, 4열 | 40점, 5열 |
| 가죽 갑옷 | 35점, 5열 | 44점, 6열 |
| 노송나무 몽둥이 | 59점, 8열 | 74점, 10열 |

- Galmuri7 은 8점 글자 줄 하나에 들어가 한 열이 타일 1칸입니다. Galmuri9 는 위 탁점 줄까지 두 줄을 써서 한 열이 2칸입니다.
- 예를 들어 6열짜리 이름 8개면 Galmuri7 은 48칸, Galmuri9 는 96칸입니다. 같은 이름이면 Galmuri9 가 열도 한두 개 많아 차이가 더 벌어집니다. Galmuri9 는 가나 칸 100칸 남짓을 목록 하나가 거의 다 씁니다. 상태 창 이름(넷이면 Galmuri9 로 5열 × 2줄 × 4 = 40칸)이나 다른 창과 겹치면 모자랍니다.
- 도구 창 안쪽 10열 가운데 첫 열은 커서 자리라, 「노송나무 몽둥이」(Galmuri9 10열)는 그대로 들어가지 않습니다.

## BG3 타일맵 옮기기

타일맵이 글자 칸 `180`~`1FF`(VRAM 워드 `1C00`~`1FFF`)를 차지하므로, 타일맵을 장면마다 비어 있는 VRAM 자리로 옮겨 이 128칸을 한글 타일용으로 비웠습니다. 코드는 `sfc/dq4/tools/dq4bg3slot.py` 이고 `dq4menupatch.py build` 가 마지막에 붙입니다(`60:8300`~).

DQ5 엔진은 평소 BG3SC(`$2109`)를 맵을 불러올 때 그림자 `$0725` 와 함께 씁니다. 어느 자리가 비는지는 DQ5 트랙이 VRAM 1K 워드 칸마다 쓰기와 가리킴(켠 BG 타일맵·화면 안 OBJ 가 가리키는 칸)을 잰 자료로 정했습니다. 자료는 실내 맵 364개의 도착·보행, 전투 61벌(배경 49·큰 몬스터 9·셋 섞기 3), 특수 장면 35벌입니다. 처음 배정은 실내 맵 도착 직후의 쓰기만 본 자료([48번 일지](../../dq5/journal/2026-10-26-48-bg3slot.md))로 정했다가, 3C00 을 쓰거나 가리키는 맵을 놓쳐 01/00 성 탑 그림이 깨졌습니다.

| 장면 | BG3SC | 타일맵 자리(워드) | 까닭 |
| --- | --- | --- | --- |
| 타이틀·메뉴 | `1C` | `1C00` | 맵을 불러오기 전 |
| 필드(`$BE` bit7 = 0) | `78` | `7800` | 필드 16벌은 `7800`·`7C00` 을 쓰지도 가리키지도 않음 |
| 실내 맵 대부분 | `3C` | `3C00` | 맵도 전투도 `3C00` 을 쓰지 않음. 전투 61벌은 `3C00`·`7000`~`7C00` 을 쓰지 않음 |
| `3C00` 을 쓰거나 가리키는 실내 맵 | `7C` | `7C00` | 01/00·01/01·02/06·12/00·1F/00·20/00·21/00·21/05·21/08·22/00·51/54 |
| 같은 까닭, `7C00` 은 쓰는 맵 | `78` | `7800` | 00/0A·32/00 |
| `7000`~`7C00` 이 모두 차는 맵 | `48`·`4C` | `4800`·`4C00` | 19/00·19/05·1A/00·1C/00·1F/01 은 `48`, 19/02 는 `4C`(맵이나 슬롯 화면이 `4400`·`4800` 을 씀) |
| 위 `48`·`4C` 맵에서 전투 | `78` | `7800` | 전투는 시작하고 16프레임 안에 `4000`~`5C00` 을 씀. 전투가 끝나면 맵을 다시 불러와 돌아옴 |

01/00·19/02·1F/01·02/06 은 그 맵에서 일어나는 특수 장면(보스전·융단·세계 지도, 카지노 슬롯, 결혼식, 엔딩)이 쓰거나 가리키는 칸도 피했습니다.

바꾼 곳은 다음과 같습니다.

| 자리 | 원래 | 바꾼 뒤 |
| --- | --- | --- |
| `60:8284`(메뉴 패치의 맵 훅) | `LDA #$1C` / `STA $0725` | 위 표대로 자리를 고름. 자리가 바뀌면 타일맵 버퍼 `7E:5000` 2KB 를 DMA 7 로 새 자리에 올림(맵을 불러오는 중이라 화면이 꺼져 있음) |
| `26:8030`(전투 시작) | `JSL $04E2A1` | 지금 자리가 `40`~`5C` 면 NMI 를 끄고 새 vblank 를 기다려, 화면을 끈 채 버퍼를 `7800` 에 올리고 `$2109` 를 `78` 로. `$2100`·`$4200` 은 그림자 `$1D`·`$1E` 로 되돌림 |
| `00:8E1F` | 타일맵 2KB 전체 DMA 의 `STA $2116` | `$0725` 와 지금 자리가 다르면 이 vblank 에 `$2109` 를 바꾸고 새 자리로 보냄 |
| `00:8E55`·`00:8E75` | 위·아래 줄 DMA 의 `STA $2116` | 주소가 `1C00`~`1FFF` 면 지금 자리로 다시 계산 |
| `04:9849` | 높은 바이트 `STA $2117` | 같은 계산(8비트) |
| `22:8B4D`·`8B6F`·`8BC6` | `LDA #$1CE0` / `STA $0F5E`(전투 창 줄 주소) | 같은 계산 |
| `03:F3A9`·`03:F54D`·`22:E71B` | `LDA #$1C` / `STA $2109`(특수 화면 효과를 끝내며 되돌림) | 지금 자리로 되돌림 |

- 원하는 자리(`$0725`)와 지금 `$2109` 에 든 자리(`7E:1ABC`, `^ 1C` 로 두어 0 이면 `1C`)를 따로 둡니다. 둘이 다르면 전체 DMA 가 도는 vblank 에서 `$2109` 와 함께 바꿉니다.
- 전투 시작에서는 화면이 켜져 있습니다(`26:8030` 에서 `$2100` = `0F`, NMI 켜짐). 처음에는 `$0725` 만 바꾸고 다음 전체 DMA 를 기다렸습니다. 그러나 09/00 을 `48` 에 둔 시험 롬에서 싸워 보니, 전투가 `4800` 에 올린 그림이 전환까지 약 40프레임 동안 BG3 로 보였습니다. 보내기 요청 `$0BEC` 에 `80` 을 넣어도 전체 DMA 는 앞당겨지지 않았습니다. 그래서 전투 시작에서 vblank 를 기다려 바로 바꿉니다. 이때 NMI 한 번을 건너뜁니다.
- 맵을 불러오며 새 자리를 채울 때(`60:8284`)는 화면이 꺼져 있고 NMI 도 꺼져 있었습니다(MesenCE 상태 실측). DMA 7 은 NMI 전송 목록도 쓰는 채널이라 이 조건이 필요합니다.
- `21BF` bit5 갈래의 `4C00` 은 원래대로 둡니다.
- 맵을 불러올 때 새 자리를 비우지 않으면 앞 장면의 그림이 보였고, 0 으로 채우면 02/08·06/00·17/00·1F/00·1F/01 에서 창이 비었습니다. 이 맵들은 불러온 뒤 타일맵 전체를 다시 올리지 않아서, 옛 자리와 같은 내용인 버퍼를 올립니다.

검사는 `dq4bg3slotcheck.py` 로 합니다. 배 선실 세이브스테이트에서 실내 맵 364개로 순간이동해 명령 창을 열고 30프레임마다 `lua/dq4bg3slotwarp.lua` 가 다음을 적습니다.

- 그 자리 타일맵의 0 아닌 바이트 수
- 화면에 쓰는 자리의 타일맵과 버퍼 `7E:5000` 이 다른 바이트 수(`vsbuf`)
- 타일맵이 `1C00` 을 떠날 때 찍어 둔 옛 자리 `1C00`~`1FFF` 에서 그 뒤 바뀐 바이트 수(`old`)

```
MESENCE=... uv run --locked python sfc/dq4/tools/dq4bg3slotcheck.py --old 원래롬 --new 새롬 \
  --state work/state/ship.mss --out 새폴더 [--maps 01/00,17/00] [--jobs 10]
```

| 항목 | 결과 |
| --- | --- |
| 도착 | 363맵(17/00 은 원래 롬에서도 못 감) |
| 끝 프레임 `vsbuf` | 원래·새 롬 모두 362맵 0, 29/00 만 둘 다 2 |
| `old` | 모든 맵·모든 기록에서 0 |
| 끝 화면이 원래와 다른 맵 | 세 번 돌려 44·38·33맵. A 입력 시점에 따라 명령 창과 「めいれいさせろ」 창이 갈리거나 커서 깜빡임·맵 애니메이션이 다른 것. 원래 롬끼리도 21맵 중 8맵이 달랐음 |

조우율을 올린(`ROMPATCH=8523=FF`) 실내 09/00(`3C`)과 필드 04/0B(`78`) 전투에서 창이 원래대로 나오고 옛 자리는 바뀌지 않았습니다. DQ5 트랙의 전투 61벌 실측 도구(`dq5vramslots.lua`)를 새 롬으로 돌렸더니, 61벌 모두 전투 중 `1C00` 을 쓰지도 가리키지도 않았고 BG3 는 `7800` 에 있었습니다(원래 롬은 61벌 모두 `1C00` 을 씀). `48`·`4C` 맵은 조우가 없어, 09/00 을 `48`·`4C` 목록에 넣은 시험 롬으로 전투 전환을 쟀습니다. 전환 프레임 화면이 원래 롬과 같았습니다. 마을에서는 명령 창 열고 닫기와 계단 이동이 정상이었습니다.

BG3SC 를 직접 쓰는 다른 코드(`03:F362`·`03:F3A4`·`03:F548`·`22:E70B`·`22:E717`·`00:A86F`·`00:8A67`·`02:E681`·`02:EFA1`·`11:BBE5`·`11:C070`·`1D:B56C`)는 위 필드·실내·전투 시험에서 한 번도 돌지 않았습니다(실행 감시). 즉값 `1C` 로 되돌리는 세 곳만 고쳤고, 효과 자체는 아직 띄워 보지 못했습니다.

## 상태 창 이름

필드 상태 창(창 `02`)과 전투 상태 창·전투 명령 창 제목의 주인공 이름을 Galmuri9 한글로 찍습니다(`sfc/dq4/tools/dq4windowname.asm`·`.py`, `dq4menupatch.py build` 가 `dq4bg3slot` 다음에 부름, 코드 `60:C000`~). 사용자 결정으로 이름 칸을 4칸에서 5칸으로 넓혔습니다.

| 항목 | 내용 |
| --- | --- |
| 칸 넓히기 | 일행 열은 사람마다 너비 +5(`04:A394 ADC #$05`)·x −5(`04:A3A4 SBC #$05`)·내용 열 간격 10바이트(`04:B18E ADC #$000A`). 셋을 6·6·`0C` 로, 창 `02` 머리 너비를 6 → 7 로, 너비 6 일 때 `04:ABCF` 로 가던 지름길 `04:AB58 CMP #$06` 을 7 로 바꿈. 머리 너비만 바꾸면 효과 없음 |
| 이름 판별 | `04:ABCF` 를 `JML WnName` 으로. 첫 두 바이트가 한글 표시(`85`~`9A`, `10`~`7E`, [이름 입력](dq4-name-entry-format.md))면 한글, 아니면 원래 경로 `04:ABD6` |
| 글리프 | 이름 입력이 넣은 Galmuri9 16×16 칸(뱅크 `62`~`64`, n = (첫 바이트 − 85) × 111 + (둘째 − 10))에서 넉 자를 10점 간격으로 40점 띠 9줄에 겹침 |
| 높이 | 글자 높이 9점이 이름 줄(8점)을 넘으므로 맨 윗줄을 위 테두리 타일(`8D`)의 7줄째에 합성. 테두리 타일 그림은 롬 `04:E978`~(`8B`~`95`, 타일당 평면 0·1 각 8바이트), 가나 칸은 1bpp `04:E528`~ |
| 타일 칸 | 이름 줄 5칸 + 위 줄 합성 5칸 = 10타일을 BG3 칸 `180`~`1CF` 에. 타일맵 버퍼 자리(`$DC` + Y)마다 한 자리, 여덟 자리를 돌려 씀(`7E:1C40` 표) |
| 올리기 | `7E:3E00` 에 160바이트를 만든 뒤 NMI 전송 목록(`7E:4000`, 항목 수 `7E:0758`, 머리 `[80][VRAM 워드][워드 수]`)에 붙이고 `$1A` bit7 을 켠 다음 `JSL 00:958A` 로 NMI 를 기다림 |
| WRAM | `7E:1C40`~`1D1D`(자리 표·띠·글리프 사본·포인터·임시), `7E:3E00`~`3E9F`. 11개 장면 접근 카운터로 접근이 없던 자리(증명은 아님) |

`00:958A` 를 기다리는 까닭: 창을 그리는 동안 `04:9D41`~`9D49` 가 매 프레임 `$19` 워드를 `AND #$7FFF` 로 다시 써서 `$1A` bit7 을 지웁니다. 목록만 붙이고 돌아오면 NMI 가 목록을 보내지 않아(항목 수 1 그대로), 처음 연 창의 이름 칸에 옛 VRAM 내용이 보였습니다. 이름 입력(`NeUpload`)이 같은 순서를 씁니다. `00:958A` 는 저 RAM 을 절대 주소로 읽을 수 있어 DB = 00 으로 부릅니다.

### 실측

세이브스테이트는 BG3SC 를 옮기기 전 값을 갖고 있어, 그대로 쓰면 타일맵이 칸 `180`~ 자리(VRAM 워드 `1C00`)에 남아 이름 타일과 겹칩니다. 그래서 `sfc/dq5/tools/lua/dq5warp.lua` 로 09/00 에 순간이동해 맵을 다시 불러온 상태를 저장한 뒤(`SAVE` 는 `SHOT_DIR` 아래 파일 이름) `dq5msg.lua` 로 창을 열었습니다. 이름은 `POKE` 로 `7E:2001`~ 에 넣습니다(뱅크 없이 `2001` 로 쓰면 00:2001 이라 WRAM 이 아님).

```
LIBDIR=$LIBDIR SHOT_DIR=$PWD/work/sn/warp STATE=work/state/party4-wagon.mss TO="09/00,10,10" SETTLE=30 \
  POKE=7E2001=97,7E2002=33,7E2003=8C,7E2004=37,7E2005=99,7E2006=29,7E2007=98,7E2008=27 SAVE=st.mss MAXF=2500 \
  $MESENCE --testrunner 롬 sfc/dq5/tools/lua/dq5warp.lua
LIBDIR=$LIBDIR SHOT_DIR=... STATE=work/sn/warp/st.mss POKE=... PRE="wait:30,a:8,wait:90,b:8,wait:60,a:8,wait:90" \
  SHOTS=42,60,280 MAXF=290 $MESENCE --testrunner 롬 sfc/dq5/tools/lua/dq5msg.lua
```

| 장면 | 결과 |
| --- | --- |
| 혼자(`ship.mss` 에서 워프), 명령 창 열기·닫기·다시 열기 | 「크리프트」, 첫 프레임부터 깨짐 없음, 위 테두리 합성 정상 |
| 일행 3명(`party4-wagon.mss` 에서 워프) | 사람마다 6칸 열, 「크리프트 スラリン ホイミン」 |
| 두 자 「크리」, 가나 「ああああ」 | 한글은 앞 두 칸, 가나는 원래 경로 그대로 |
| 실내 09/00 전투(`ROMPATCH=8523=FF`), 일행 3명 | 전투 상태 창이 6칸 열로 넓어지고 이름 「크리프트」, 「こうげき」 명령 창 제목도 「크리프트」 |

전투 상태 창(창 `03`·`04`)과 전투 명령 창 제목도 `04:ABCF` 를 지나 같은 렌더러를 탑니다. DQ5 엔진의 전투·걷는 일행은 셋까지라 넷째 열은 띄우지 못했습니다.

### 목록 이름

창 문자열의 자리 표시 `D0`(`04:B790`)은 이름 하나를 공통 출력 `04:B79B` 로 찍습니다. 원래 코드는 글자마다 `04:B235` 로 `($E0),Y` 에 쓰고 `PLX` 뒤 `04:BFF2` 로 갑니다. 이 자리는 이름 입력이 먼저 `NeListHook`(모험의 서 목록)으로 훅해 두었으므로, `WnList` 가 다시 훅하고 메뉴 플래그(`7E:1BB0` = `A5`)거나 한글이 아니면 빌드 때 롬에서 읽은 이전 JML 대상으로 넘깁니다. 한글이면 상태 창과 같은 렌더러를 포인터 `$E0` 로 돌립니다.

| 창 | 모양 | 처리 |
| --- | --- | --- |
| 「누구」 고르기 `0C`·`0E`·`11`·`13`·`2C`·`36`·`38`·`3D`·`4F`·`6F`·`7A`(너비 9), `4A`·`7F`(너비 8) | 본문 `… D0 DD FF`. `DD`(`04:BA14`)는 이름 바로 뒤에 상태 표시 타일(`7E`·`80`·`7F`·`81`, 없으면 `01`) 한 칸을 찍음 | 창을 한 칸 왼쪽으로 옮겨 너비 +1(오른쪽에는 이어서 열리는 도구·주문 창이 붙어 있음). 이름 뒤 Y 를 10 나아가 상태 표시가 다섯째 칸을 덮지 않게 함 |
| HPとMP(`7B` 류), こうげき力 | 이름 뒤 내용의 자리가 정해져 있음 | 원래처럼 Y 를 8 나아감. 다섯째 칸은 열 사이 빈칸에 걸침 |

어느 쪽인지는 `04:B79B` 에 들어올 때 X 가 가리키는 창 문자열(뱅크 04)의 다음 바이트가 `DD` 인지로 가릅니다. 창 번호는 창 표 `04:EB48` 읽기를 감시해 장면마다 쟀습니다(つよさ→だれの `0C`, じゅもん `2C`, どうぐ `0E`, そうび `13`).

| 장면(일행 3명 + 마차 1명, 09/00) | 결과 |
| --- | --- |
| つよさ → HPとMP | 「1: 크리프트」, 위 줄 라벨 「1:」과 합성 정상 |
| つよさ → こうげき力 | 「1크리프트」, 레벨·こうげき·しゅび 열 원래 자리 |
| つよさ → つよさみる(だれの), じゅもん, どうぐ, そうび | 「크리프트」 넉 자 모두, 오른쪽 창과 겹치지 않음 |

### 이름 색

쓰러짐·독·HP 가 적을 때 이름에 색을 입히는 길이 따로 있습니다. `04:AB58` 지름길을 타지 않으면 `$EC`·`$46`·`$47` 을 보고 `$ED`(`28`·`24` 등)를 정한 뒤 `04:AB73` 부터 글자마다 높은 바이트 `$ED` 와 함께 16비트로 씁니다. `04:AB73` 도 훅해 같은 렌더러로 그리고, 이름 줄 타일맵 낱말의 높은 바이트를 `$ED` 로 둡니다(`7E:1D42`). 목록 길은 `04:B235` 와 같이 `$EC` bit6 이면 `$ED` 를 씁니다. 전투에서 주인공이 쓰러지자 상태 창 이름이 빨간 「크리프트」, HP 가 적을 때 노란 「크리프트」로 나왔습니다.

### 전투 메시지 이름

전투 글은 바이트가 곧 BG3 타일 번호입니다. 이름은 `24:A83C` 가 `$01`~ 의 바이트를 글 큐 `0ECB`~(DB = `04`·`20`)로 옮기고 `FF` 로 끝냅니다. `24:8738` 이 큐 머리를 꺼내 `E2` 이상이면 제어 코드(`24:86F2` 표), 아니면 `24:A4A4` 로 글 버퍼에 씁니다. 글 버퍼는 줄마다 26칸 × 두 줄(위 `1DD5`, 아래 `1DEF`, 줄 간격 `34`)이고, `84`·`83` 탁점만 위 줄에 갑니다. `24:A5D9` 가 버퍼를 타일맵 버퍼 `7E:5546`~ 의 **낮은 바이트**로만 옮깁니다.

| 자리 | 처리 |
| --- | --- |
| `24:A83C` → `WnBattle` | 한글이면 같은 렌더러로 10타일(아래 줄 5 + 위 줄 5)을 BG3 칸 `1D0`+자리×10 에 올리고, 큐에 코드 `B0`+자리×10 ~ 를 (10×글자 수 + 7) / 8 개 넣음. 자리는 이름 바이트로 찾는 4자리(`7E:1D20`) |
| `24:A4E0` → `WnBattleChar` | 아래 줄에 쓰는 바이트가 이름 아래 줄 코드면 위 줄에 +5 코드를 함께 씀 |
| `24:A5E9` → `WnBattleCell` | 코드 `B0`~`D7` 이면 낮은 바이트 +`20`, 높은 바이트 bit0(타일 bit8)을 켜 `1D0`~`1F7` 을 가리키게 함. 다른 바이트는 bit0 을 끔(줄이 올라가며 자리가 바뀜) |

처음에는 코드 그대로 칸 `B0`~`D7` 에 그림을 뒀습니다. 전투 중 BG3 타일맵이 가리키는 칸은 `96`~`99`·`A0`·`A1` 뿐이었지만, 주인공이 공격하자 연출이 칸 `B0`~`122`(VRAM 바이트 `2B00`~`322F`)를 덮어 「크리프트の こうげき!」 의 이름이 줄무늬가 됐습니다. 그래서 그림은 상태 창 이름 뒤의 빈 칸 `1D0`~ 로 옮기고 타일 bit8 은 타일맵으로 옮기는 자리에서 붙였습니다.

| 장면(실내 09/00 전투, 일행 3명, 입력 네 가지) | 결과 |
| --- | --- |
| 「…の こうげき! / 크리프트は 8の ダメージを うけた!」, 「크리프트は きぜつした!」 | 한글 이름, 줄이 올라가도 그대로 |
| 「크리프트の こうげき!」 뒤 공격 연출 20프레임 간격 16장 | 깨짐 없음 |
| 적의 メラ·ルカニ 뒤 메시지 | 깨짐 없음 |

## 남은 것

- `04:B3A2` 자리 표시 가운데 이름을 찍는 코드 가르기, 가게·교회·「だれに」 목록처럼 이름 목록과 메시지가 함께 뜨는 장면 실측(이번 세이브스테이트로는 일행이 한 명이라 못 띄움)
- 가나 칸을 한글 칸으로 쓸 때 칸을 잡고 놓는 방식(창을 열고 닫을 때), 고정 문구(명령 창 「はなす」 등)를 미리 그려 둘 칸
- 석 자 출력 `D1`(`04:B7C3`)을 쓰는 창 `06`·`47`·`17`·`26`·`27`, `CF`(`04:B77A`), `0D` 의 이름. 가게·여관·교회·전투 등 12개 세이브스테이트에서 3000프레임씩 메뉴를 눌러도 `04:B7C3`·`04:B77A` 는 한 번도 불리지 않았음(つよさみる 본 창은 DQ5 배치인 창 `07`·`08` 이고 이름은 `04:B79B` 로 찍힘). 가게·교회·여관에서 뜨는 고르기 창은 아직 띄워 보지 않음
- 전투 메시지 이름: 주문·특기 연출이 BG3 칸 `1D0`~`1F7` 을 덮는지(이번에 본 것은 공격·メラ·ルカニ 뿐), 전투 이름 자리 4개를 넘는 이름(마차 교대로 다섯째 한글 이름)이 같은 화면에 함께 뜰 때
- ベネット 지도 장면(`21BF.5`)이 VRAM `1C00`~`1FFF` 를 지도로 덮어, 장면 뒤 이름 타일을 다시 그려야 함. 장면 뒤 `$0725` 가 옮긴 자리로 돌아오는지, ブオーン 장면
- 상태 창 이름의 칸 `1D0`~`1FF` 는 아직 비어 있음
- BG3SC 를 직접 바꾸는 특수 장면 실측: 맵 17 의 mode 2 효과(`03:F34D`, 이벤트 명령 `02:A35C`), 전투 뱅크의 32×64 BG3(`22:E70D` 의 `19`, 이때 `1800`~`1BFF` 위 절반은 옮기지 않음), mode 7 장면(`00:A86F`, `$0725` = `58`)
- 이번 시험에서 돌지 않은 VRAM 주소 쓰기(`00:8D2F`·`00:A438` 등)와 가게·교회·이름 입력·엔딩 장면의 BG3 타일맵 쓰기
- 창 글자 크기 결정: 창 목록은 8점 높이 글꼴이 타일을 절반만 씀
