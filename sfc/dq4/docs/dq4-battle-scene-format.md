# 전투 장면 검사

1장 롬에서 전투 한 판을 수 초 안에 다시 만들어 결과를 WRAM 으로 판정합니다. 도구는 `sfc/dq4/tools/dq4battlescene.py`, 회귀 가드는 [`guards.toml`](../guards.toml) 의 `dq4-battle-scene` 입니다. 출발점은 [저장 기록](dq4-savefixture-format.md)으로 만들고, libretro snes9x 1.63 `fae2fea`·bsnes 115 `63ee22f7`([코어](dq4-compat-format.md#코어))에서 돌립니다. 걷기 검사의 걸음 전투(`dq4battlecheck.py`, MesenCE)는 그대로 두고, 이 검사는 그 옆에서 주문·도구·도망·전멸·레벨업·보스를 봅니다. 과정은 [2026-11-01-45 일지](../journal/2026-11-01-45-battle-scene.md)에 있습니다.

모든 장면이 기본 묶음(가드)에 듭니다. 알려진 문제를 재는 장면을 더하면 `KNOWN_ISSUES` 에 넣어 `--scenes` 로 고릅니다.

## 전투 붙이기

조우 루틴 `23:E7C2` 를 cheat 로 덮습니다. 걷기 검사의 `force_patch` 가 쓰는 무리 바이트(`7E:1001`~`100C`) 뒤에 구역 레벨 `$100F` 와 무리 플래그 `$1000` 을 씁니다. 원래 조우 루틴이 구역 레코드 `+0` 에서 `$100F` 를 채우는데 덮은 코드는 그 일을 하지 않아, 앞 값이 남으면 도망이 「주인공 레벨 ≥ 구역 레벨 + 5」 로 늘 성공할 수 있습니다([DQ5 にげる](../../dq5/docs/dq5-data-format.md#전투-시작-때-쓰는-값)). `7E:1001`~`1008` 을 걸기 전에 0 으로 두고, 정한 무리가 보이는 프레임을 전투가 걸린 때로 봅니다. 그때 cheat 를 풀어 롬의 「조우 없음」(`CLC`/`RTL`)으로 돌아갑니다.

보스 장면은 덮지 않고 말을 걸어 붙이며, `7E:1001`~`1002` 가 `E2 52`(보스 무리)가 된 때를 전투가 걸린 때로 봅니다.

## 차례와 메시지

입력은 프레임 수가 아니라 창 번호 `7E:0A00` 으로 맞춥니다.

| `7E:0A00` | 뜻(실측) |
| --- | --- |
| `FF` → `17` | 차례가 옴. 두 프레임 뒤 `1B` |
| `1B` | 싸우기/도망 창이 입력을 기다림(커서 `7E:0AD7`) |
| `17`·`1E` | 공격/방어/도구 창. 주문이 없는 라이안은 한 줄 세 칸 |
| `24` | 물건 창. 한 줄에 두 칸(천 옷·노송나무 막대 / 약초) |
| `18`·`26` | 몬스터 행동·전투 메시지 |
| `01` | 맵의 명령 창 |

- 차례가 오면 그 프레임부터 장면의 차례 입력을 정한 간격(20·50·80프레임 …)으로 누릅니다. 공격 `A A A`, 방어 `A ↓ A`, 도망 `↓ A`, 약초 `A ↓ ↓ A ↓ A A` 입니다.
- 차례 입력이 끝난 뒤에는 입력 창(`17`·`1B`·`1E`·`24`)이 아닐 때 30프레임마다 A 를 눌러 메시지를 넘깁니다.
- 전투가 끝나 맵에 돌아오면 이 A 가 맵 명령 창 `01` 을 엽니다. 전투 창(`00`·`FF`·`01` 이 아닌 창)을 한 번 본 뒤의 이 프레임을 「조작이 돌아온 때」(끝)로 봅니다. 전멸은 맵 번호가 바뀐 프레임을 끝으로 봅니다.
- 끝난 뒤 열린 명령 창을 B 로 닫고, 보스 뒤 대화(아이들)·교회 신부 대화를 넘긴 다음(창이 `01` 이면 B, `FF` 면 누르지 않음, 그 밖이면 A 또는 B) 한 방향으로 24프레임 걸어 칸이 바뀌는지 봅니다.

전투가 끝났는지를 WRAM 의 다른 값으로 보려던 것은 맞지 않았습니다(아래 「틀렸던 것들」).

## 실측

1장 롬(`dq4build.py`, SHA-1 `2690c55f…`)에서 기본 장면 11개를 시드 0~31 로 돌려 두 코어 704판이 모두 통과했습니다. 가드(시드 0·1·2, 두 번씩)는 (장면, 코어, 시드)마다 프로세스를 나눠 `--jobs`(기본 `HEADLESS_SLOTS`)개씩 함께 돌려 약 3분입니다(2026-11-07, 7자리에서 162초. 장면·코어 단위로 `--jobs 4` 일 때는 342초). 시드마다 따로 띄워도 시드마다의 요약 해시·분포·성장 표가 한 프로세스에서 이어 돌린 것과 같았습니다. 아래 프레임은 시드 0·1·2 의 것입니다.

같은 시드도 코어마다 결과가 다릅니다(선제·도망 횟수·피해). 두 코어의 프레임 타이밍이 달라 난수가 다르게 쓰이는 것으로 보입니다. 그래서 분포는 코어마다 따로 셉니다.

### 분포

`--seeds` 의 시드 집합에서 선제(`$1000` bit1)·기습(bit0, 첫 창이 뜬 프레임에 읽음)·회심·도망 실패를 셉니다(`results.json` 의 `distribution`). 정확한 개수는 기대값으로 두지 않습니다. 전투와 상관없는 롬 변경에도 개수가 바뀌기 때문입니다(효과음 음량만 바꾼 main 을 합쳐 다시 빌드하자 bsnes `attack` 의 시드 0·1·2 회심이 0 → 1). 확률이 문서로 정해진 것만 통계 구간으로 봅니다.

| 무엇 | 근거 | 판정(표본이 작으면 건너뛰고 로그) |
| --- | --- | --- |
| 회심 | 1/32(`20:C697`, 난수 0~31 이 0) | 보통 공격 30번 이상: 이항 분포 양쪽 99.9% 구간(예: 374번이면 2~24번) |

## 실측으로 드러난 것

- **새 게임 첫 기록의 맵 곡 건너뛰기**: 밑판은 손대지 않은 실제 플레이의 기록입니다. 새 게임을 고르면 게임이 약 964프레임(서장 첫머리의 검은 화면)에 칸을 하나 기록하는데, 그 칸의 `7E:21A5` 가 `40`(bit6 = 맵 곡 건너뛰기, [맵 밝히기](dq4-chapter1-format.md))입니다. 그 기록으로 이어 하면 바트랜드에서 1,500프레임 동안 소리(RMS)가 0 이고 `$1D8B` 가 `FF` 였습니다(`nosong` 장면은 탑으로 옮긴 뒤 900프레임도 `FF`, 전투 뒤 승리 곡 `1F` 가 남음). 처음에는 새 게임을 고른 뒤 교회에서 기록하기 전에 꺼서 이어 하는 플레이어가 겪는다고 보았습니다. 그 기록을 고치지 않고 이어 하면 서장 마을 `3C/01` 에 서서 서장 상자가 다시 뜨고, 밝히기가 비트를 꺼 선 뒤 481프레임에 곡 `06` 이 울렸습니다. 곡이 끝내 없는 것은 기록의 자리를 상자가 없는 곳으로 옮긴 경우였습니다. 끈 기록은 이어 하자 곧 성 곡 `01` 이 울렸고 탑에 순간이동하면 `0A` 였습니다. 지금은 이어 할 때 시작 훅이 장 상자가 기다리지 않는 자리면 이 비트를 끄므로([시작 연출 곡](dq4-chapter1-format.md#시작-연출-곡)) 모든 장면이 밑판을 그대로 쓰고, `nosong` 이 기본 묶음에서 이 비트를 켠 기록을 잽니다. 과정은 [2026-11-02 일지](../journal/2026-11-02-03-newgame-song.md)에 있습니다.
- **전투 도구 창 제목**: 물건 창 제목이 「(이름)のどうぐ」 로 일본어가 남아 있었습니다. 제목에 이름 코드 `E0` 과 한 칸 코드 `E2` 가 붙어 창 글자 빌드가 한글로 바꾸지 않았습니다. 이름·한 칸 코드가 든 제목도 늘이게 고쳐([창 글자 깨짐 검사 76장면](dq4-window-text-format.md#깨짐-검사-76장면을-모두-통과시키기)) 「(이름)의 도구」 가 됐고, `herb` 장면이 물건 창 `24` 가 뜬 지 20프레임 뒤 창 타일맵 버퍼(`7E:5000`)의 위 테두리·제목 줄(x 5~29, y 20·21)에 가나 칸(`010`~`077`)이 없는지 봅니다.
- **레벨업 성장**: 1장 라이안은 DQ5 주인공 성장 곡선(사람 0)으로 오르고 MP 도 올랐습니다(레벨 10 에서 최대 HP 76·MP 28·ちから 38·すばやさ 21·かしこさ 21·うんのよさ 4·みのまもり 11·다음 경험치 4718, FC 곡선은 82·0·34·13·6·11·41·2398). FC 곡선 값 표와 훅으로 고쳐 `growth` 장면을 기본 묶음에 넣었습니다([라이안 성장](dq4-growth-format.md)).
- **떨어뜨린 물건**: snes9x 시드 0 의 약초 장면에서 이긴 뒤 스ライム 이 やくそう 를 떨어뜨려 셋째 칸이 다시 찼습니다. 그래서 물건이 줄었는지는 몬스터가 다 쓰러진 프레임의 물건 칸으로 봅니다.

## 틀렸던 것들

- 처음에는 `7E:0070`·`00E6` 이 전투 동안 0 이 아니다가 맵으로 돌아오면 0 이 되는 것으로 끝을 보려 했습니다. 몬스터가 도망쳐 끝난 전투에서는 맵 곡이 돌아온 뒤에도 그대로였습니다(직접 페이지 임시값).
- `7E:2E60`·`2F2B` 는 전투를 만들 때 켜지고 이긴 전투에서는 끝날 때 0 이 됐지만, 도망친 전투에서는 남았습니다.
- 맵 곡이 돌아온 프레임을 끝으로 보면, 이긴 전투는 금화·레벨업 메시지가 아직 남아 금화가 늘기 전이었습니다.
- 물건 창을 한 줄 한 칸으로 보고 아래를 두 번 눌러 셋째 물건을 고르려 했는데, 창이 두 칸씩이라 첫 물건으로 돌아와 「천 옷을 도구로 써 보았다!」 가 떴습니다.
- 보스 뒤에 A 만 눌러 대화를 넘기자 bsnes 에서는 아이 대화보다 먼저 맵 명령 창이 열려, A 가 「대화」 로 보스 자리에 말을 걸어 보스 전투가 다시 걸렸습니다. 창 번호를 보고 누르도록 고쳤습니다.

## 사용법

```sh
uv run --locked python sfc/dq4/tools/dq4build.py --out work/ch1
uv run --locked python sfc/dq4/tools/dq4cores.py
uv run --locked python sfc/dq4/tools/dq4battlescene.py --rom work/ch1/dq4-ch1-full.sfc --out work/battlescene --seeds 0,1,2
# 배포 전 32개
uv run --locked python sfc/dq4/tools/dq4battlescene.py --rom work/ch1/dq4-ch1-full.sfc --out work/battlescene32 \
    --seeds $(seq -s, 0 31) --repeat 1
```

`--scenes attack,boss` 로 장면을, `--core snes9x` 로 코어를 고릅니다. 장면·코어마다 프로세스 하나가 이어 하기·순간이동을 한 번 하고, 그 상태를 시드마다 다시 불러 씁니다. 결과는 `OUT/results.json`(줄마다 장면·코어·시드·판정·문제, 분포, 장면별 요약)과 `OUT/<장면>-<코어>/seed<N>-end.png`·`-after.png` 입니다.

장면 프로세스는 자리를 잡은 때부터 120초 + 반복 한 번의 시간 × `--repeat` 안에 끝나야 하고, 넘기면 결과 없이 꺼져 「프로세스가 결과를 남기지 않음」 으로 실패합니다. 반복 한 번의 시간은 장면의 `seconds`(기본 60초)입니다. `party2` 는 레벨업 글이 셋 몫이라 3만 4천 프레임 남짓이고 bsnes 로는 한 번에 130초쯤 걸려 200초로 둡니다.

## 남은 것

- 전투 끝을 WRAM 한 바이트로 가르는 값. 지금은 맵 명령 창을 여는 A 로 봅니다.
- 선제·기습 확률 번호: 덮은 조우 루틴이 구역 레코드 `+4` 를 읽지 않아 `26:8329` 가 어느 번호를 쓰는지 재지 않았습니다. bsnes `flee` 시드 2 는 `$1000` 아래 두 비트가 모두 켜진(`3`) 채 시작해 첫 도망이 실패했습니다. 두 비트가 함께 켜지면 어느 쪽이 이기는지 확인하지 않았습니다.
- FC 가 경험치를 일행 수로 나누는지. 1장 롬은 살아 있는 일행 모두가 같은 양을 받습니다(DQ5 `25:88D3`).
- 필드 걸음 전투·마을 밖 곡, 주인공이 직접 외우는 주문(1장 라이안은 배우지 않음), 몬스터 주문을 맞는 피해의 범위 판정.
- MesenCE 에서 같은 장면(저장 기록으로 이어 하기가 MesenCE 에서 아직 없음).
