# 여관·교회·저장 칸 장면 검사

여관에서 묵기, 교회의 되살리기·해독·저주 풀기·계시·기도(저장), 타이틀의 기록 복사·지우기, 빈 SRAM 과 체크섬이 틀린 칸, 낮밤 경계를 장면 하나씩 libretro bsnes·snes9x 에서 돌려 WRAM·SRAM 값으로 판정합니다. 도구는 `sfc/dq4/tools/dq4townscene.py`, 회귀 가드는 [`guards.toml`](../guards.toml) 의 `dq4-town-scene` 입니다. 장면은 [저장 기록](dq4-savefixture-format.md)으로 이무르(`37/00`)에서 이어 해 시작합니다. 실측은 1장 롬(`dq4build.py` 출력 `dq4-ch1-full.sfc`, SHA-1 `c6cb51e6…`), snes9x 1.63 `fae2fea`·bsnes 115 `63ee22f7`([코어](dq4-compat-format.md#코어))로 했습니다.

## 고르기 창 알아보기

| 자리 | 내용 |
| --- | --- |
| `7E:0AD7` | 고르기 창의 커서 칸. 교회 메뉴(0~5), 예/아니요(0·1), 기록 목록(쓰인 칸 차례), 타이틀 메뉴(0~4)가 모두 씀 |
| `7E:0F20` | 여관 처리기가 도는 동안 `09`, 교회 처리기는 `0C`, 끝나면 `00` |
| `7E:0F28` | 여관이 셈한 값(1인 값 × 일행 수). 「하룻밤에 …골드」 쪽에서 쓰임 |
| `7E:00F6` | 계시가 띄우는 남은 경험치(3바이트). 「앞으로 경험치 …만 더」 쪽에서 나타남 |

창이 떴는지를 알려 주는 WRAM 표지는 찾지 못했습니다. 교회 기도 대화 1,500프레임 동안 5프레임마다 WRAM 128KB 를 남기고, 그 프레임이 고르기 창이었는지(아래 프로브)와 견줘도 두 쪽을 가르는 바이트가 없었습니다. 그래서 5프레임마다 상태를 저장하고 아래(움직이지 않으면 위)를 눌러 `7E:0AD7` 이 바뀌는지 본 뒤 상태를 되돌립니다. 바뀌면 창이 입력을 기다리는 것이고, 정해 둔 칸까지 커서를 옮긴 뒤 A 를 누릅니다. 그 밖의 프레임에는 40프레임마다 A 로 글을 넘깁니다.

두 가지를 지켜야 했습니다.

- 필드 명령 창은 `7E:007F & 7` = 0 인 프레임에만 입력을 읽으므로 A 를 8프레임 누릅니다. 4프레임이면 명령 창의 「이야기하기」 가 빠져 다음 프로브가 같은 창을 또 봤습니다.
- 글 넘기기 A 를 누르고 있는 동안 창이 뜨면, 이어 누른 A 는 새 입력이 아니라서 먹히지 않습니다. 고르기 전에 12프레임 손을 뗍니다. 떼지 않았을 때 여관의 「예」 가 먹히지 않고 다음 창에서 B 가 눌려 묵지 않았습니다.

- bsnes 에서 여관의 잠드는 연출(검은 화면, 소리 손잡기를 기다림) 도중에 상태를 저장·되돌리면 그 손잡기가 풀리지 않아 멈췄습니다(`7E:08D8`~ = `C0 00 00 00 00 00 7C C3 2B C0 01 06`). 같은 입력을 프로브 없이 넣으면 끝까지 갔으므로 게임이 아니라 검사의 탓입니다. 여관은 답을 다 쓴 뒤로 프로브하지 않습니다(`converse(default=None)`). snes9x 는 멈추지 않았습니다.

목록은 쓰인 칸만 차례로 보여 주므로, 칸 3 을 고를 때 칸 1·3 이 쓰여 있으면 커서 1 입니다.

## 장면(`check`)

| 장면 | 시작 | 고르는 것 | 판정 |
| --- | --- | --- | --- |
| `inn_stay` | 주인공 HP 5, 호이민(HP 1, MP 0), 금화 100, 낮 | 이야기하기, 예 | 금화가 FC 이무르 1인 값(`dq4shop.inn_price`, 6G) × 2 만큼 줄고 `7E:0F28` 도 12, 모두 HP·MP 가득, 시각 `0050` |
| `inn_night` | 같고 밤(`7E:2033` bit7, 시각 `0190`) | 같음 | 위와 같고 시각 `0190` → `0050` |
| `inn_poor` | 금화 11(12 에 1 모자람) | 이야기하기, 예 | 금화·HP·MP·시각 그대로 |
| `inn_refuse` | 금화 100 | 이야기하기, 아니요 | 그대로 |
| `church_revive` | 호이민 죽음(`+1` = `00`, HP 0) | 되살리기, 호이민, 예 | `+1` bit7, HP 가 0 이 아님, 금화가 레벨 × 10 만큼 줄어듦 |
| `church_cure` | 주인공 독(`+1` = `A0`) | 해독, 주인공, 예 | `+1` = `80`, 금화 5 줄어듦 |
| `church_uncurse` | 주인공 저주(`+1` = `88`) | 저주 풀기, 주인공, 예 | `+1` = `80`, 금화 레벨 × 10 줄어듦 |
| `church_oracle` | 경험치 `000100`, 다음 레벨 `00ABCD` | 계시를 듣기 | 남은 `AACD` 가 대화 중 `7E:0000`~`1FFF` 에 새로 나타남(말하기 전부터 있던 자리는 뺌) |
| `save_slot1`~`3` | 칸 1 만 쓰임, 금화를 `3000 + 칸` 으로 고침 | 기도하기, 예, 칸 n, (모험을 계속) 예 | 칸 n 이 쓰는 칸·체크섬이 맞고 쓴 프레임의 WRAM `7E:2000`~`2A9D` 와 같고 다른 칸은 그대로. 그 SRAM 으로 전원부터 칸 n 을 골라 이어 하면 이무르 교회 앞에 서고 WRAM 이 기록 칸과 같으며(맵에 들어설 때 고치는 `2193`·`21C7`·`21CB`·`21CC` 빼고) 금화가 `3000 + 칸` |
| `title_copy` | 칸 1 만 쓰임 | 모험의 서를 복사한다, 칸 1 | 칸 2 가 칸 1 과 같고 체크섬이 맞음, 칸 1 그대로 |
| `title_erase` | 칸 1·2 쓰임 | 모험의 서를 지운다, 칸 2, 예 | 칸 2 의 쓰는 칸 비트가 꺼지고 칸 1 그대로 |
| `title_blank` | SRAM 모두 0 | 새 게임 입력(저장 기록 밑판과 같음) | 머리가 쓰이고 쓰인 칸이 하나 |
| `badsum` | 칸 1(금화 1111)·칸 2(금화 2222, 마지막 기록, 체크섬 1비트 틀림) | 이어 하기 입력 | 칸 2 가 지워지고(비트·`AA0` 바이트 0) 칸 1 로 이어 해 금화 1111 |

여관은 위로 한 걸음 걸어 카운터 앞 (34,40)에서 말합니다. 이어 하면 서는 교회 신부 앞 (50,9) 에서 이무르 여관 주인(34,37)이 있는 자리로는 순간이동(`dq4compatcheck.Walker.warp`)으로 갑니다.

### 기록과 이어 하기에서 본 것

- 기도로 칸 n 에 기록하면 그 칸의 상태가 `C0`, 앞서 `C0` 이던 칸은 `40` 이 됩니다(칸 2 에 기록: `40 C0 00`). 그래도 다음에 켜서 「모험을 한다」 를 고르면 기록 목록의 커서는 첫 쓰인 칸(칸 1)에 섰습니다. 이어 하기 입력이 A 만 누르면 마지막 기록이 아니라 칸 1 로 이어 하므로, 검사는 칸을 직접 고릅니다.
- 빈 SRAM 에서 새 게임 입력을 넣으면 칸 2 를 씁니다(964프레임). 밑판 SRAM 을 만들 때와 같은 칸입니다.
- 기록 칸의 내용은 쓴 프레임의 WRAM 과 바이트까지 같았습니다(세 칸, 두 코어).

## 알려진 실패

`KNOWN` 에 둔 장면은 그 문제로만 실패하면 `known` 으로 쳐 전체가 통과합니다. 고쳐져 통과하거나 다른 문제가 생기면 실패하므로, 고친 PR 이 목록에서 빼야 합니다. `--no-known` 은 이 처리를 끕니다.

### 소리 롬에서 교회 치료 뒤 멈춤

되살리기·해독·저주 풀기는 상태와 금화가 바뀐 뒤 「오오 신이시여! …주소서!」 쪽에서 멈춥니다. `7E:0F20` 이 `0C` 그대로이고, A 를 40프레임마다 눌러 4,000프레임이 지나도 넘어가지 않았습니다. 프로브 없이 같은 입력을 다시 넣어도 같았고(상태 되돌리기 탓이 아님), 두 코어가 같습니다. 소리를 넣기 전 롬은 끝까지 갑니다.

교회 코드(`06:E03E`~, 원본 DQ5 와 바이트가 같음)는 세 치료 갈래에서 `LDA #$1E / JSL $25FD00`(`06:E17C`·`06:E29A`·`06:E308`)으로 곡 `1E` 를 부르고, 기도는 `06:E10E` 에서 곡 `20` 을 부릅니다. [곡 대응표](dq4-sound-port-format.md)는 `1E` 자리에 NDS 「コロシアム楽屋」(곡 `11`)를, NDS 「教会治療」(곡 `28`)를 `25` 자리에 넣었습니다. 기도의 `20`(「冒険の書（セーブ）」)은 멈추지 않습니다. 짧은 징글을 기다리는 자리에 되풀이하는 곡이 들어가 끝나기를 기다리다 멈추는 것으로 보입니다(코드 읽기와 대응표, 끝을 기다리는 루틴은 재지 않음). 멈췄을 때 `7E:08D8`~ 는 `C0 00 01 00 80 00 FD BE 2B 00 00 0D`, 소리 전 롬은 `E0 00 00 00 00 00 DB BE 2B 01 00 01` 이었습니다.

### 필드에서 시각 색이 바뀌지 않음

아래 「낮밤 경계」 의 `dusk`·`dawn`·`cross` 입니다.

## 낮밤 경계(`daynight`)

| 장면 | 하는 일 | 판정 |
| --- | --- | --- |
| `dusk` | 필드에서 시각 `7E:075E` 를 `00ED`~`00F2` 하나씩에 붙든 채 600프레임까지 걷기 | 팔레트 버퍼 2·3번 줄 색 1~13(`7E:3956`·`3976`), 인물 11·12번 줄(`7E:3A76`·`3A96`), 밤 인물 표지 `7E:1AA1` 이 시각 표(`01:A16B`) 벌과 같아짐 |
| `dawn` | 같고 `01FC`~`0002` | 같음 |
| `cross` | 붙들지 않고 `00EA` 에서 `00F3` 을, `01F9` 에서 `0003` 을 넘을 때까지 걷기 | 넘긴 뒤 버퍼가 표와 같고, 해 질 녘에 `7E:1AA1` 이 켜짐 |
| `town_edge` | 바트랜드에서 시각을 `00EF`(낮 끝)·`00F0`(밤 첫 값)에 붙든 채 이무르로 순간이동 | 인물 대화 번호 목록이 낮·밤으로 이어 한 이무르의 목록과 같고, 낮·밤 목록이 다름 |

시각 표 읽기: `01:A16B` 의 `[하한 16비트][색인 × 2]` 항목 10개를 뒤에서부터 보아 하한이 시각 이하인 첫 항목의 색인으로 `01:A189` 의 벌 주소를 고릅니다. 색인 `0C` 이상이면 인물 줄은 `01:A422`(밤), 아니면 `01:A45E` 입니다. 1장 롬의 표·벌은 원본 DQ5 와 같습니다(`01:A199`·`A19A` 의 세계 1 벌만 다름). 필드는 이무르에서 이어 해 바트랜드 출구 앞 `36/00` (28,81)으로 순간이동한 뒤 아래로 걸어 나갑니다.

| 장면 | snes9x | bsnes |
| --- | --- | --- |
| `town_edge` | 통과: `00EF` 에 16명(낮, `006 94A 005 …`), `00F0` 에 10명(밤, `006 955 005 …`) | 같음 |
| `dusk` | 알려진 실패: `00ED` 만 맞고 `00EE`~`00F2` 는 600프레임 걸어도 낮 벌 `A24D` 그대로 | 같음 |
| `dawn` | 알려진 실패: `01FC`~`0001` 이 낮 벌 그대로, `0002` 만 맞음 | 같음 |
| `cross` | 알려진 실패: `00EA` → `0002` 까지 2,255프레임 걸어도 버퍼가 낮 벌 하나, `7E:1AA1` 0 | 같음 |

필드에서 시각을 `0120` 에 붙든 채 걷고, 바트랜드에 들어갔다 다시 나와도(필드를 다시 불러옴) 화면·버퍼 모두 낮 색이었습니다. 시간 멈춤 `7E:2190` bit1 은 꺼져 있고 시각은 걸음마다 올랐습니다. 갱신을 부르는 `02:AD2A`(`LDX $19C3 / LDA $7F / AND $02AC27,X / CMP #$02 / BNE / LDA $1949 / BNE / JSL $01A055`)와 `01:A055`(처음에 `JSR $A090` 으로 색을 고름)·`02:AC27` 표는 원본과 바이트가 같고, `$19C3` = 1, `$1949` = 0 이었습니다. 걷기 도구의 조우 끄기(`23:E7C2`)를 cheat 로 되돌려도, `7E:2190` bit6·`$1948` 을 어른 값으로 두어도 같았습니다. 소리 전 롬(`dq4-ch1.sfc`)도 같습니다. [필드 문서](dq4-field-format.md)의 「(328,95) 에서 `075E=0100` 으로 서자 어두워짐」 은 MesenCE 실측이라, 1장 롬의 문제인지 이 검사의 진입 방식(libretro, 이어 하기)의 차이인지 가리지 못했습니다(「남은 것」).

## 옛 롬의 기록(`oldsave`)

`DQ4_ASSETS`(비공개 에셋 저장소)의 이력에서 1장 IPS 를 꺼내(기본은 가장 오래된 커밋) 원본 DQ5 에 입히고, 그 롬의 새 게임 기록을 지금 롬으로 이어 한 결과를 `results.json` 에 남깁니다. 판정은 하지 않습니다.

| 옛 IPS | 옛 롬 | 결과 |

새 게임 기록만으로는 두 판의 형식 차이가 드러나지 않습니다. 옛 판에서 진행한 기록(flag·일행이 바뀐 칸)은 옛 롬을 걸어야 만들 수 있어 넣지 않았습니다.

## 사용법

```sh
uv run --locked python sfc/dq4/tools/dq4build.py --out work/ch1
uv run --locked python sfc/dq4/tools/dq4cores.py
uv run --locked python sfc/dq4/tools/dq4townscene.py check --rom work/ch1/dq4-ch1-full.sfc --out work/townscene --jobs 4
uv run --locked python sfc/dq4/tools/dq4townscene.py daynight --rom work/ch1/dq4-ch1-full.sfc --out work/townnight --jobs 4
DQ4_ASSETS=… uv run --locked python sfc/dq4/tools/dq4townscene.py oldsave --rom work/ch1/dq4-ch1-full.sfc --out work/oldsave
```

`--only 장면…` 으로 일부만, `--core bsnes|snes9x` 로 한 코어만, `--seeds 0,5` 로 난수 시드(`dq4ch1walkcheck.rng_for`)를 여럿 돌립니다. 장면마다 프로세스 하나가 코어 하나를 열고(같은 dylib 을 한 프로세스에서 여러 번 열지 않음), 결과는 `<out>/seed<시드>/<코어>/<장면>/result.json`·`end.png` 와 `<out>/results.json` 입니다. 여관 값의 기준은 FC 롬(`--dq4`, 기본 `rom/dq4.nes`)입니다.

## 남은 것

- 소리 롬의 교회 치료 멈춤: 곡 `1E` 를 끝까지 기다리는 루틴과 대응표의 `1E`·`25` 를 고치는 일(소리 쪽).
- 필드 시각 색: MesenCE 에서 같은 롬으로 걸어 CGRAM 이 바뀌는지, `02:AD2A` 를 부르는 쪽이 1장 필드에서 도는지(`01:A055` 실행 감시).
- 기록 목록의 처음 커서가 마지막 기록 칸이 아닌 것: 원본 DQ5 도 같은지.
- 계시의 남은 경험치가 메시지 숫자 자리로 쓰이는 길(`7E:00F6` 은 직접 페이지 임시 값으로 보임).
- 다른 마을(바트랜드 여관 4G)·밤 교회 첫 말, 전멸 뒤 교회 복귀는 [1장 저장 검사](dq4-chapter1-format.md#저장과-이어-하기)(`dq4ch1savecheck.py` 의 `wipe`)가 봅니다.
- 옛 판에서 진행한 기록을 지금 롬으로 이어 하기.
