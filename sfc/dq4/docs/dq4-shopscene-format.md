# 가게 장면 검사

1장 이무르 가게에서 사기·팔기·취소를 장면마다 몇 초 안에 돌리고, 끝난 뒤 WRAM 값으로 판정합니다. 도구는 `sfc/dq4/tools/dq4shopscene.py`, 회귀 가드는 [`guards.toml`](../guards.toml) 의 `dq4-shop-scene` 입니다. 장면은 [저장 기록](dq4-savefixture-format.md)으로 이무르에서 이어 하기로 시작하고, libretro snes9x 1.63 `fae2fea`·bsnes 115 `63ee22f7`([코어](dq4-compat-format.md#코어)) 둘 다에서 돌립니다. 개수 창은 [개수 창에서 쓰는 돈·남는 돈 보이기](dq4-window-text-format.md#개수-창에서-쓰는-돈남는-돈-보이기) 뒤의 동작(1 에서 시작, 끝에서 멈춤)을 봅니다. 가게 동작의 명세는 [창 글자 문서의 가게 절들](dq4-window-text-format.md#가게-목록의-값과-g)에 있고, 이 검사는 그 장면들을 기계적으로 다시 봅니다.

## 출발점

장면마다 새 게임 밑판 칸에 이어 할 자리 이무르(칸 7), 금화, 주인공 소지품을 고쳐 SRAM 을 만들고(`SaveSlot.set`), 이어 하기로 이무르 교회 앞 (50,9)에 섭니다. 그다음 `dq4compatcheck.Walker.warp` 로 같은 맵 `37/00` 안의 가게 앞으로 옮깁니다. 일행은 주인공(라이안) 혼자라 「누가」 창은 뜨지 않습니다. 새 게임 밑판의 소지품은 천 옷(`42`)·노송나무 막대(`00`)이고 둘 다 장비(비트 `0003`)입니다.

| 가게 | 순간이동 자리 | 실제로 서는 칸 | 카운터 앞 칸 | `$0F20` |
| --- | --- | --- | --- | --- |
| 도구점 | (18,48) | (18,49) | (18,49) | 0 |
| 방어구점 | (34,8) | (34,12) | (34,11) | 1 |

같은 맵 안의 순간이동은 도착 판정(`(x, y)` 가 목표와 같음)을 채우지 못해 근처 칸에 세웁니다. 도착한 뒤 위를 8프레임 누릅니다. 도구점은 카운터에 막혀 돌아서기만 하고, 방어구점은 한 칸 올라서 카운터를 봅니다. 위를 6프레임 누르면 돌아서고, 4프레임이면 돌아서지 않았습니다. 방어구점에서 위를 더 누르면 카운터 그림이 있는 (34,10)까지 올라섭니다(아래 [남은 것](#남은-것)).

## 판정에 쓰는 WRAM

| 자리 | 내용 |
| --- | --- |
| `7E:0A00` | 마지막으로 연 창 번호. 8프레임 그대로인 값을 「지금 창」 으로 봄. 지나온 창에서 지나가도 되는 창을 뺀 열이 장면마다 정한 열과 정확히 같아야 함 |
| `7E:0AD7` | 창 커서. 가게 창은 0 사기·1 팔기·2 나가기, 팔기 목록은 물건 칸 번호 |
| `7E:0B02` | 개수 창 `5C` 의 끝 자리 숫자 타일(`02`~`0B` = 0~9). 가게에서는 1 에서 시작해 1~최대에서 멈춤 |
| `7E:0F20` | 가게 종류(0 도구·1 방어구·2 무기) |
| `7E:0F21` | 사기: 개수(장비는 1), 팔기·필드 메뉴: 사람 번호 |
| `7E:0F22` | 사기 목록 커서의 물건 |
| `7E:0F2C` | 개수 창이 떠 있는 동안 최대 \| `40`(열림) \| `80`(팔기), 팔기에서는 이어서 개수. 다 쓰면 0 |
| `7E:2019` | 금화(3바이트) |
| `7E:2054` | 주인공 장비 비트(16비트, bit n = 물건 칸 n) |
| `7E:2056` | 주인공 물건 12칸, 빈 칸 `FF` |

가게 흐름에서 본 창 번호입니다(snes9x·bsnes 같음).

| `$0A00` | 창 |
| --- | --- |
| `01` | 명령 창(대화·주문…) |
| `02` | 상태 창. 가만히 서 있으면 「명령을 내려줘」 와 함께 뜸 |
| `33` | 가게 창(사기·팔기·나가기) |
| `34` | 가게에 말을 건 직후 잠깐 |
| `35` | 목록을 둔 채 뜬 메시지(사기 목록에서 물건을 고른 뒤 「약초 말이죠.」, 팔기를 고른 뒤 「어느 물건을…」) |
| `37` | 팔기 목록 |
| `39`·`3A` | 사기 목록과 그 아래 동료 창(동료 창이 뒤에 그려져 보통 `3A` 로 남음) |
| `5C` | 개수 창 |
| `32` | 예/아니요 |
| `58` | 금화 창을 다시 그림(사고판 뒤) |
| `00` | 메시지 창 |
| `FF` | 창을 닫음 |

`7E:0B04` 도 입력을 받는 창을 따라가는 것처럼 보였지만, 팔기에서 개수 창을 닫은 뒤 예/아니요가 떠도 A 를 누를 때까지 `5C` 로 남아 쓰지 않았습니다. 창을 다시 그릴 때 `$0A00` 이 1~4프레임 다른 값이 되므로(사기 목록에서 물건을 고르면 `35` → `3A` → `35`) 8프레임 그대로여야 그 창으로 봅니다.

메시지 번호를 담는 자리는 찾지 못했습니다. 장비한 물건을 팔 때 058 앞에 뜨는 알림(메시지 `3D`)과 058 사이에 값이 `3D` 에서 `58` 로 바뀌는 바이트가 `7E:0000`~`1FFF` 에 없었습니다. 그래서 알림은 「누르지 않으면 ▼ 에서 멈추는지」 로 봅니다.

## 입력 열

장면은 아래 단계를 차례로 밟습니다. 프레임 수를 세어 기다리는 단계는 없습니다.

| 단계 | 하는 일 |
| --- | --- |
| `to(버튼, 창…)` | 그 창이 될 때까지 버튼을 2프레임 누르고 15프레임 쉼. 처음 창과 지나가도 되는 창(`00`·`02`·`34`·`35`·`58`·`FF`) 밖의 창에 서면 실패 |
| `pick(자리, 값)` | 그 자리가 값이 될 때까지 아래(또는 위)를 누름(사기 목록 `$0F22`, 팔기 목록·가게 창 `$0AD7`) |
| `press(버튼, n)` | n 번 누름(개수 창 위·아래) |
| `wait(창, n)` | 누르지 않고 n 프레임 안에 그 창이 되는지 |
| `stays(n)` | 누르지 않고 n 프레임 동안 창이 그대로인지(▼ 기다림) |
| `see(자리, 값)` | 지금 값(개수 창 최대 `$0F2C`, 끝 자리 `$0B02`) |
| `poke(자리, 값)` | 앞 흐름이 남긴 값을 흉내 냄(`$0F21` = 3) |

두 가지를 실측으로 정했습니다.

- `to` 는 창 번호가 목표가 된 그 프레임에 손을 뗍니다. 8프레임 그대로이기를 기다리며 계속 누르면 새 창이 그 버튼을 받습니다. 금화 5 로 약초를 고르면 「돈이 모자란」 뒤 가게 창 `33` 이 뜨는데, 기다리는 동안 누른 A 가 「사기」 를 골라 사기 목록으로 돌아가 같은 흐름을 되풀이했습니다.
- 필드에서 A 는 8프레임에 한 번만 받습니다. 방어구점 카운터 앞에서 걸음이 끝난 뒤 20·28·60프레임째에 누른 A(2프레임)는 명령 창을 열었고 30·40프레임째는 아무 일도 없었습니다. 누르는 주기를 16 으로 두면 누르는 자리가 늘 같아 600프레임 넘게 명령 창이 열리지 않았습니다. 주기를 17 로 두어 누르는 자리가 8 의 나머지를 모두 돌게 했습니다.

## 장면

모두 이무르, 주인공 혼자, 시드 0. 「끝」 은 장면이 끝난 창입니다. 프레임은 카운터 앞에 선 뒤 끝까지, 시간은 한 번 돈 시간(이어 하기·순간이동 포함, 헤드리스 자리를 기다린 시간 뺌)입니다.

| 장면 | 처음 | 입력 | 판정(금화·물건·장비 비트·그 밖) | snes9x | bsnes |
| --- | --- | --- | --- | --- | --- |
| `buy-one` 사기 1개 | 금화 10 | 약초 → 예 | 2, 약초 하나 늘고, 개수 창 안 거침, `$0F2C` 0 | 590f | 607f |
| `buy-multi` 여러 개 | 금화 1000 | 약초 → 개수 창(`$0F2C` = `49`, 처음 1) 위 두 번 = 3 → 예 | 976, 약초 셋, `$0F21` 1·`$0F2C` 0 | 711f | 728f |
| `buy-qty-cap` 개수 1~최대 | 금화 20 | 약초 → 개수 창(최대 2) 위 세 번 = 2, 아래 세 번 = 1, 위 한 번 = 2 → 예 | 4, 약초 둘 | 812f | 829f |
| `buy-short` 금화 모자람 | 금화 5 | 약초 | 5, 그대로, 창 차례 명령·가게·사기 목록·가게 | 551f | 568f |
| `buy-bag-full` 가방 가득 | 12칸(해독초 10) | 약초 | 1000, 그대로, 창 차례 명령·가게·사기 목록·가게 | 628f | 645f |
| `buy-no` 사기 취소 | 금화 10 | 약초 → B | 10, 그대로, 가게 창 안 거치고 사기 목록 | 550f | 567f |
| `buy-back` 목록에서 뒤로 | 금화 10 | 사기 목록에서 B | 그대로, 가게 창 | 384f | 401f |
| `sell-one` 팔기 1개 | 약초·해독초 | 약초 → 누르지 않고 예/아니요 → 예 | 26, 해독초만, 개수 창 안 거침 | 595f | 612f |
| `sell-multi` 팔기 여러 개 | 약초 셋·해독초 | 약초 → 개수 창(`$0F2C` = `C3`) 위 세 번 = 3 → 예 | 38, 해독초만, `$0F2C` 0 | 729f | 746f |
| `sell-equipped` 장비한 물건 | 약초 | 천 옷 → 누르지 않으면 400프레임 그대로(알림 ▼) → 예 | 27, 노송나무 막대·약초, 장비 비트 `0001`(칸이 당겨짐) | 1039f | 1056f |
| `sell-qty-no` 팔기 취소 | 약초 둘 | 약초 → 위 한 번 = 2 → B | 20, 그대로, `$0F2C` 0, 가게 창 안 거치고 팔기 목록 | 638f | 655f |
| `sell-back` 목록에서 뒤로 | 약초 | 팔기 목록에서 B | 그대로, 가게 창 | 416f | 433f |
| `armor-equip` 사고 바로 장비 | 금화 1000 | 나무 모자 → 예 → 「바로 장비하시겠어요?」 예 | 880, 나무 모자, 장비 비트 `0007` | 781f | 798f |
| `armor-cannot-equip` 장비 못 하는 장비 | 금화 1000, `$0F21` = 3 | 체인 메일(`$0F21` 이 3 인지 봄) → 「장비하실 수 없습니다만」 예 → 「350골드」 예 | 650, 체인 메일 한 벌 | 659f | 676f |

한 장면은 snes9x 약 1초, bsnes 약 5~6초입니다. 장면마다 같은 입력을 두 번 돌려 두 번 다 통과하고 창 차례(프레임 포함)·끝 프레임·끝 WRAM 128KB 의 SHA-1 이 같아야 통과입니다. 14장면 × 두 코어 × 두 번을 `--jobs 4` 로 약 45~60초에 돌았습니다(다른 세션이 헤드리스 자리를 쓰지 않을 때). 시드 5·9 로도 snes9x 14장면이 통과했습니다.

`armor-cannot-equip` 은 [가게 도구 여러 개 사기](dq4-window-text-format.md#가게-도구-여러-개-사기)의 「장비 갈래도 `$0F21` = 1 을 둔 뒤 확인으로」 를 지킵니다. 장비할 수 없는 장비는 「바로 장비하시겠어요?」 없이 `06:DE77` → `06:DCFF` 로 물건을 주는 `06:DD39` 를 지납니다. 사기 목록에서 `$0F21` = 3 을 두고, 체인 메일을 고른 뒤 예/아니요 앞에서 그 값이 남아 있는지(`see`) 확인합니다. `ShopBuyEquip`(1장 롬 `06:FFF3`)의 `LDA #$01 / STA $0F21` 5바이트를 `EA` 로 되돌린 롬에서는 두 코어 모두 「물건 42 00 4D 4D 4D(기대 42 00 4D)」 로 실패했습니다(350골드에 세 벌, 두 번째 실행도 같음). 같은 롬에서 `armor-equip` 은 통과했습니다.

## 사용법

```sh
uv run --locked python sfc/dq4/tools/dq4cores.py
uv run --locked python sfc/dq4/tools/dq4shopscene.py --rom work/ch1/dq4-ch1-full.sfc --out work/shopscene
# 장면 몇 개만, 한 코어만, 한 번만
uv run --locked python sfc/dq4/tools/dq4shopscene.py --rom work/ch1/dq4-ch1-full.sfc --out work/shopscene \
    --only buy-multi,sell-equipped --core snes9x --once
uv run --locked python sfc/dq4/tools/dq4shopscene.py --rom work/ch1/dq4-ch1-full.sfc --out work/x --list
```

`--out` 아래 `seed-N/<코어>/<장면>/run1·run2/` 에 창이 바뀔 때마다 찍은 그림(`NN-창.png`)과 `end.png`, 전체 결과 `results.json` 이 남습니다. 그림은 증거로만 두고 판정에는 쓰지 않습니다. `--jobs` 는 4 를 넘기지 않습니다.

## 남은 것

- 일행이 둘 이상일 때의 「누가」 창(`35`), 동료에게 사 주기·동료 소지품 팔기, 동료 창 `3A` 의 「N개 소지」 문구.
- 무기점·다른 마을 가게, 맡기는 곳(1장 맵에 없음), 팔 수 없는 물건(054), 개수 창의 B, 사기에서 여러 개를 고른 뒤 아니요.
- 메시지 번호를 담는 WRAM 자리. 찾으면 장착 알림·금화 모자람·가방 가득을 메시지 번호로 가를 수 있음(지금은 금화·물건이 그대로이고 개수 창·예/아니요를 거치지 않는 것으로만 봄).
- 방어구점에서 위를 길게 누르면 주인공이 카운터 그림이 있는 (34,10)에 올라섭니다. 거기서도 가게에 말을 걸 수 있습니다. 원작 FC 에서 그 칸이 막혀 있는지와 그 칸의 충돌 값은 보지 않았습니다.
- MesenCE 에서 같은 장면 돌리기.
