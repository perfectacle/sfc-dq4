# DQ4 포팅 그래픽 핸드오프

## 한글 타이틀과 오프닝

[한글 타이틀](docs/dq4-title-format.md)은 작은 부제의 v2가 사용자 확인을 받았습니다. `tools/dq4art/title-ko.png`를 보존하며 한글 로고·IV·부제의 기준으로 사용합니다. 첫 통합의 페이드·광택만으로는 움직임이 부족하다는 피드백을 받아 별도 용 날개 프레임과 구름 레이어를 사용하는 연출을 추가합니다. 정지 그림의 채택과 새 애니메이션의 시각적 채택은 구분합니다. 연속 128자세의 용과 분리된 구름 표현은 시각 피드백에서 보완 요청을 받았습니다. 작은 진폭의 단계별 날갯짓, 완전한 머리 윤곽, 글자만 남기는 마스크와 성 앞 구름은 후속 시각 피드백에서 긍정적으로 평가받았습니다. 구름이 지나간 뒤 성 주변이 비어 보인다는 보완 요청에 따라 성 밑동의 구름 받침을 조정합니다. 받침 수정본의 채택은 별도 확인이 필요합니다. 독립 미리보기 롬과 DQ5 통합 롬을 혼동하지 않으며 게임·저장 처리는 DQ5의 기존 경로를 이어 씁니다.

다른 제작물은 전체 형태와 구성을 먼저 넓힌 뒤 세부 색·도트를 모아서 검토합니다. 타이틀의 로고와 부제는 사용자가 실제 에뮬레이터에서 확인한 픽셀을 기준으로 유지하고, 움직이는 용과 배경의 새 제작물은 별도로 검토합니다. 기존 인물의 시안·채택 상태 기록은 그대로 구분합니다.

## 롬 삽입 작업

라이안 정면 정지 자세를 DQ5 어린 주인공 세트 `82`에 넣는 도구와 비교 갤러리는 [롬 에셋 문서](docs/dq4-rom-assets-format.md)에서 다룹니다. 공용 팔레트를 보존하기 위해 색을 바꾼 결과는 미확인 시안입니다. 기존 라이안 정면의 채택과 색 변경본의 채택을 구분합니다.

다음 시각 검토는 갤러리의 원래 라이안 정면과 ROM 적용 색 비교입니다. 고유색을 보존하는 팔레트 배정, 라이안의 다른 방향·보행, 다른 인물은 후속 작업입니다. 아래의 반려 기록과 Lua 메모리 교체 실험은 이전 단계의 기록으로 보존합니다.

> 2026-10-25 후속: 스프라이트 제작 방법을 정했습니다. SFC DQ5 인물을 실측한 격자 규칙으로 다시 그린 라이안 정면이 확인됐고, 같은 규칙으로 9명을 그렸습니다. [DQ4 포팅용 인물 스프라이트 규격](docs/dq4-sprite-format.md)과 [sprites 스킬](../../.agents/skills/sprites/SKILL.md)을 보세요. 아래는 그 전 상태의 기록입니다.

2026-10-25 사용자 피드백을 기준으로 정리합니다. **타이틀과 일러스트는 보존합니다. 스프라이트는 최종 16×24 수정본까지 반려됐으며, 제작 방법부터 다시 정해야 합니다.** 이번 정리는 새 그림 제작이나 기존 스프라이트 채택을 뜻하지 않습니다.

### 라이안 식별 오류를 반복하지 않기

초기 DS 시트에서 다른 인물을 라이안으로 잘못 골랐습니다. 로컬 `work/reference/ds-ragnar-zoom.png`는 **파일 이름과 달리 잘못 식별한 참고 이미지이므로 사용하지 않습니다.** 이 오류가 초기 제작물의 외형에도 반영됐습니다.

사용자가 바로잡아 준 라이안은 분홍색 투구와 갑옷, 투구 중앙의 붉은 돌출부, 짙은 콧수염, 은색의 작은 어깨 갑옷, 주황·금색 테두리가 있는 붉은 망토가 특징입니다. 큰 금색 어깨 구슬이나 날개 모양 투구 장식을 붙이지 않습니다. DS 그림은 복장 확인에 사용하고, SFC의 작은 도트 표현은 DQ5 원작을 기준으로 판단합니다.

## 시도와 반려 이유

1. **초기 ASCII 기반 도트 제작**: 단순한 기하학적 형태와 강한 윤곽 때문에 원작 DQ의 느낌이 없고 일반적인 인디 게임처럼 보인다는 피드백을 받았습니다. 맵도 초기 버전이 반려됐습니다.
2. **A/B 비교**: 사용자는 B가 낫다고 했습니다. B의 형태를 바탕으로 여러 안을 만들었으며, 더 둥글고 촘촘한 명암의 스프라이트 참고 시트도 제공받았습니다.
3. **B1/B2/B3 비교**: 사용자는 B3를 가장 선호했습니다. 고해상도 시안의 분위기를 선택한 단계이며, 실제 SFC 도트의 완성도는 아직 확인하지 않은 상태였습니다.
4. **32×48 SFC 표시와 보행**: 독립 롬과 DQ5 필드에 띄웠지만, 실제 맵과 비교하면 인물이 너무 컸습니다.
5. **16×24 축소와 수정**: 크기는 맞췄지만 원작과 다른 얼굴과 과한 광택이 남았습니다. 사용자는 큰 흰자·동공 표현을 특히 지적했습니다.
6. **작은 눈점·콧수염·갑옷 재수정**: 얼굴과 명암을 고쳐 다시 띄웠으나, 최종 피드백은 여전히 반려였습니다. 눈 몇 픽셀만 고치는 방식으로 해결됐다고 판단하지 않습니다.

이미지 생성 시안의 분위기를 작은 격자로 축소하고 부분 수정하는 방법은 이번 결과에서 충분하지 않았습니다. 16×24 안에서 머리·얼굴·몸·색 덩어리를 처음부터 설계하는 과정이 필요합니다. 이는 다음 제작 방법을 정할 때 검토할 방향이지, 이미 성공한 해결책이 아닙니다.

## MesenCE 실험의 실제 범위

아래 항목은 **로컬 `work/`에만 있는 실험**입니다. 저장소를 새로 복제하면 실행 파일·그림·롬·세이브스테이트가 생기지 않으며, 추적 중인 도구만으로 전부 재현할 수 없습니다. 경로는 인수인계용 위치 기록입니다.

| 로컬 경로 | 실험 |
| --- | --- |
| `work/ragnar-sfc-sample/` | B3를 32×48, 15색+투명색으로 표시한 독립 SFC 롬. BG 정지 화면이며 DQ5 삽입 아님 |
| `work/ragnar-walk-sample/` | 독립 보행 샘플과 방향별 그림·검증 기록 |
| `work/ragnar-dq5-probe/` | 32×48 그림을 실제 DQ5 필드에서 Lua로 교체한 보행 실험 |
| `work/ragnar-dq5-small/` | 16×24, 4방향×3자세로 줄인 실험. 마지막 얼굴 수정본도 반려됨 |

마지막 실험은 DQ5의 보행·충돌·화면 스크롤을 그대로 사용하고 Lua에서 VRAM·OAM·CGRAM을 교체합니다. 새로운 DQ4 맵을 넣은 것이 아닙니다. **IPS 패치나 일반 에뮬레이터에서 실행되는 영구 삽입본도 아닙니다.** 원본 롬과 기존 세이브스테이트 파일은 바꾸지 않았습니다.

16×24 실험의 구현은 다음과 같습니다.

- 8×8 OBJ 여섯 개로 인물을 구성하고 원래 인물의 위치와 발 기준을 유지합니다. OAM 슬롯 0~5를 쓰고 6~7은 숨깁니다.
- VRAM 바이트 범위 `D000`~`D0BF`, OBJ 팔레트 3(CGRAM 바이트 `160`~`17F`)을 런타임에 씁니다.
- 필드 맵 `01/00`과 기존 주인공의 OAM 조각을 확인한 경우만 교체합니다. 마을·전투·다른 인물까지 지원하지 않습니다.
- 이동 좌표의 변화를 보고 정지·두 보행 자세를 고릅니다. 방향은 WRAM `7E:31E0`의 상위 비트로 고릅니다.
- 자동 검증을 끈 실행은 시작 입력을 잠시 비운 뒤 수동 조작을 받습니다. 메뉴를 닫은 별도 시작 세이브스테이트를 사용합니다.
- 검증 경로에서 조우를 막기 위해 런타임 롬의 파일 오프셋 `11EA44`부터 8바이트를 0으로 씁니다. 해당 경로에서 전투 없이 걸은 결과이며, 모든 지역의 조우를 해결했다는 뜻은 아닙니다.

로컬 파일과 준비된 시작 상태가 남아 있다면 `work/ragnar-dq5-small/play.command`가 실행 진입점입니다. `MESENCE`에 설치된 [MesenCE](https://github.com/nesdev-org/MesenCE) 실행 파일 경로를 지정합니다. 이 런처는 로컬 실험용이며 새 환경의 재현 절차로 간주하지 않습니다. 기존 샘플을 보더라도 반려된 그림임을 먼저 밝힙니다.

로컬 실험 보관본은 주 작업 폴더의 `work/dq4-graphics-handoff-2026-10-25/`에 있습니다. `user-references/`의 제공 이미지와 `ragnar-b3-concept-board.png`도 로컬 참고 자료이며 PR에 포함하지 않습니다. 보관본의 런처는 이전 폴더 구조를 가정하므로 그 위치에서 바로 실행할 수 없습니다. 다시 실험하려면 필요한 실험 폴더를 저장소 `work/` 아래로 복원하고, 준비된 `work/state/field-free.mss`와 실험별 시작 상태, 사용자가 보유한 롬, `MESENCE` 설정을 별도로 확인해야 합니다. 이 보관본은 이동 가능한 배포 패키지가 아닙니다.

PPU 출력과 예상 이미지의 픽셀 일치, 4방향 이동 기록은 **변환·표시·입력 연결의 확인**입니다. 픽셀 비교가 통과한 것을 원작과의 화풍 일치나 사용자 채택으로 표현하지 않습니다.

## 다음 작업의 출발점

현재 요청은 핸드오프 정리입니다. 새 스프라이트 제작 방법은 결정되지 않았습니다. 다음 작업에서는 아래 대안을 비교해 방법을 정합니다.

- 픽셀 아티스트가 최종 16×24 격자에서 직접 제작하는 방법을 검토합니다.
- [Aseprite](https://www.aseprite.org/) 같은 도트 편집기에서 원작과 나란히 보며 소수의 색 덩어리부터 수작업하는 방법을 검토합니다.
- 이미지 생성은 복장·분위기 시안에 한정하고, 최종 작은 도트는 별도로 제작하는 역할 분리를 검토합니다.

어떤 방법이든 먼저 **라이안 정면 한 장**만 실제 크기로 만듭니다. DQ5 원작 인물과 같은 배경·같은 배율로 비교하고, 확대 그림도 함께 봅니다. 작은 눈과 콧수염이 분리되는지, 머리와 몸의 비율·윤곽·명암·지면 접점이 원작에 어울리는지를 확인합니다. 정면이 채택되기 전에는 전체 인물·전체 보행 시트로 확대하지 않습니다.

정면을 채택한 뒤 측면·후면과 보행을 만들고, 격자·팔레트·발 위치·방향별 부피를 검증합니다. 그다음 로컬 보행 연결을 정리해 다시 MesenCE에서 확인합니다. 엔진의 압축·포인터·타일 배치·팔레트 충돌·장면 전환을 조사한 뒤에야 영구 패치로 옮깁니다. 타이틀·일러스트의 긍정 평가는 이 스프라이트 검증과 별도로 보존합니다.
