# 핸드오프: 게임 안 창 한글 이름 (2026-10-27)

게임 안 상태 창·전투 상태 창에 한글 이름을 Galmuri9 로 찍는 작업의 인계 문서입니다. 브랜치 `feat/dq4-status-name` 은 **초안**입니다. 어셈블은 되지만 MesenCE 로 한 번도 돌려 보지 않았습니다. 그대로 머지하면 `dq4menupatch.py build` 결과가 바뀌므로, 검증 전에는 머지하지 않습니다.

## 사용자 결정

- 창 이름은 **Galmuri9**, 이름 칸은 **4칸 → 5칸**으로 넓힌다(시안 a). 4칸 유지 + Galmuri7 섞기(b), 전부 Galmuri7(c)는 고르지 않았다.
- 시안 그림은 작업 폴더 `work/sn/mock/`(커밋 안 함)에 있다. 일행 3명·필드 혼자·전투 상태 창 세 장, 합성 스크립트 `work/sn/mock.py`.

## 실측한 것

| 항목 | 결과 |
| --- | --- |
| 이름이 깨지는 까닭 | 이름 8바이트(한글 4자, `7E:2001`~)인데 창은 앞 4바이트를 그대로 BG3 타일로 찍음. 「크리프트」 → 「やrり」 |
| 일행 열 창 | 창 `02`(04:ED44, 머리 `16 73 c6 49`)가 필드 상태 창. 일행이 한 명 늘 때마다 `04:A394 ADC #$05`(너비 +5)·`04:A3A4 SBC #$05`(x −5), 내용 열 간격은 `04:B18E ADC #$000A`(5칸 × 2바이트). 머리 너비만 바꾸면 효과 없음 |
| 이름 출력 둘 | 일행 열 창은 `04:ABCF`(너비 6 일 때 `04:AB58 CMP #$06` 지름길, 4바이트). 목록·つよさ 류는 공통 출력 `04:B79B`(`CF`=B77A, `D0`=B790 은 4자, `D1`=B7C3 은 3자) |
| 이름 쓰는 창 | 02(상태), 03·04(전투 상태, 머리 bit5 라 `04:A335` 다른 경로), 06·47(つよさ), 17·26·27, 목록 0C·0D·0E·11·13·2C·36·38·3D·4A·4F·6F·7A·7F |
| 상태 창 높이 | 위 테두리 `8D`(선 1~2줄, 3~7줄 빔) / 이름 줄 / 구분선 `90`(선 3줄). 빈 높이 16점. Galmuri9 한글은 진행 10·높이 9 → 맨 윗줄을 테두리 타일 7줄에 합성 |
| 테두리 타일 롬 | 가나 1bpp `04:E528`(01~8A, 둘째 평면 FF) 바로 뒤 `04:E978`부터 8B~95 가 타일당 16바이트(평면0 8 + 평면1 8) |
| 글리프 | 이름 입력이 넣은 Galmuri9 16×16 칸 2,403자(뱅크 62~64, n = (첫 바이트 − 85) × 111 + (둘째 − 10), `dq4nameentry.GLYPHS` 순) |
| 빈 WRAM | 11개 장면(필드·전투·가게·여관·주문 등) 접근 카운터로 `7E:1C33`~`1D8A`, `7E:3D14`~`3FFF` 접근 없음. 증명 아님 |
| 넓히기 시험 | 세 상수를 6·6·0C, 창 02 너비 7 로 바꾼 롬에서 일행 3명 창이 x 10 부터 사람마다 6칸으로 정상 배치(`work/sn/p4c-s6/big.png`) |

## 지금 코드(브랜치)

- `sfc/dq4/tools/dq4windowname.asm`·`.py`: `dq4menupatch.build` 가 `dq4bg3slot` 다음에 부름. 코드 `60:C000`~(60:C000~FFFF 비어 있음).
  - 위 세 상수와 `04:AB58` 을 6 기준으로, 창 02 머리 너비 7.
  - `04:ABCF` → `WnName`: 첫 두 바이트가 한글 표시면 글리프 넷을 10점 간격으로 40점 띠에 합성. 이름 줄 5칸 + 위 테두리 합성 5칸 = 10타일을 BG3 칸 `180`~`1CF`(타일맵 버퍼 주소마다 한 자리, 8자리 돌려 씀)에 그린다. `7E:3E00` 에 만든 뒤 NMI 를 끄고 NMI 전송 목록(`7E:4000`, `$0758`·`$0759`, `$1A` bit7)에 붙인다. 타일맵 낱말은 우선·팔레트만 살림. 끝나면 Y += 10, `04:ABF4` 로.
  - WRAM: `7E:1C40`~`1D17`(자리 표·띠·글리프 사본·임시).
- 빌드는 된다(`DQ4_WINDOWNAME_SYMBOLS` 로 심볼). 동작은 미검증.

2. 의심 지점: 이름 버퍼가 DP `$01`~`$08` 에 8바이트 다 들어오는지, `$DC`+Y 가 7E 버퍼 주소인지, NMI 전송 목록 크기, 첫 프레임 깜빡임.
3. **전투 상태 창**(03·04): 일행 여럿 전투에서 `04:B18E` 간격 변경이 전투 창 배치를 깨지 않는지(조우: `ROMPATCH=8523=FF`, 실내 09/00·필드 04/0B). 전투 창 너비도 5칸 이름에 맞게.
4. **목록·つよさ**: `04:B79B` 공통 출력(메뉴 기록 목록은 이미 `NeListHook` 이 훅, 게임 안은 원래 경로)에 같은 렌더러, 해당 창들 너비.
5. **전투 메시지 이름**: `24:A83C`(바이트를 그대로 `7E:0ECB` 로)는 여전히 깨짐.
