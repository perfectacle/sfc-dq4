# DQ4(FC) 이름·아이템·몬스터·주문·성장 표

메뉴와 전투에 나오는 이름 목록, 아이템·몬스터·주문 표, 레벨업 성장 곡선입니다. 디코더는 [tools/dq4data.py](../tools/dq4data.py), 실험 과정은 [2026-10-25-04 일지](journal/dq4/2026-10-25-04-data.md)(이름·아이템·몬스터 첫 확인)와 [2026-10-25-15 일지](journal/dq4/2026-10-25-15-stats.md)(주문·레벨업·몬스터 나머지·아이템 플래그)에 있습니다. 글자 바이트는 [dq4-text-format.md](dq4-text-format.md#글자-바이트) 와 같습니다. 근거가 실측이 아니라 코드 읽기인 줄에는 「코드 읽기」라고 적었습니다.

```sh
uv run python tools/dq4data.py rom/dq4.nes spells      # 주문 60개: MP, 대상, 배우는 인물·레벨
uv run python tools/dq4data.py rom/dq4.nes levels 6    # ライアン 1~99레벨 경험치·능력치 기준값
uv run python tools/dq4data.py rom/dq4.nes items       # 아이템 종류·강도·가격·장비 인물·플래그
uv run python tools/dq4data.py rom/dq4.nes monsters    # 몬스터 능력치·드롭
```

## 인물 번호와 장 시작 값

인물 번호 0~7 은 勇者, クリフト, ミネア, マーニャ, ブライ, トルネコ, ライアン, アリーナ 이고, 인물 레코드(`$6001 + 30 × 번호`)·일행 순서 `$616A`·장 번호 `$615A`·장 시작 루틴 `12:$8EAE` 는 [dq4-save-format.md](dq4-save-format.md#인물-레코드-6001--30--번호) 에 있습니다. 장 시작 때의 힘·속도·체력·지혜·운·최대 MP 는 아래 성장 곡선 레코드의 초깃값(1레벨 값)이고, 최대 HP 만 곡선(체력 × 2)이 아니라 따로 둔 표 `12:$A296` 에서 옵니다(ライアン 곡선 26, 실제 27). 이름 입력 세이브스테이트에서 장 시작 루틴 직전에 `$615A` 를 0~4 로 바꾸어 돌린 레코드 8개가 이 계산과 모두 같았습니다.

## 성장 곡선

경험치와 능력치는 레벨마다 표를 두지 않고 인물마다 작은 레코드에서 계산합니다(`12:$9FC6`, `dq4data.curve`). 포인터 표 `12:$A108` 의 8개가 능력치 번호 순서입니다.

| 번호 | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 능력치 | 경험치 | 힘 | 속도 | 체력 | 지혜 | 운 | HP | MP |
| 레코드 | `$A130` | `$A158` | `$A188` | `$A1B8` | `$A1E8` | `$A218` | (체력 × 2) | `$A248` |

레코드는 인물마다 경험치 5바이트, 능력치 6바이트입니다.

| 바이트 | 내용 |
| --- | --- |
| 0-4 의 bit7 | 다섯 비트를 모은 초깃값(바이트 0 이 bit0). 능력치는 1레벨 값, 경험치는 2레벨에 필요한 경험치 |
| 0 bit6-5 | 비율 표 `12:$A266` 의 줄 `r`. 시작 칸 = `r × 6`(능력치는 + `18`) |
| 0 bit4-0, 1-4 bit6-0 | 구간 경계 레벨 다섯 개. 레벨이 경계를 넘을 때마다 비율 표의 다음 칸으로 |
| 5 | 능력치의 레벨당 증가 기준 |

레벨 L 의 값은 시작 레벨(능력치 2, 경험치 3)부터 L 까지 증가분을 더한 것입니다. 능력치 증가분은 `(바이트5 × 비율 + 8) >> 4`, 경험치 증가분은 `앞 증가분 × 비율 >> 4` 입니다(앞 증가분의 처음은 초깃값). 비율 표는 경험치 칸 `20 18 14 12 10 10`, `1E 18 14 12 10 10` …, 능력치 칸 `08 10 18 20 08 08`, `00 10 08 10 20 20`, `10 10 20 10 00 00`, `10 10 20 08 00 00` 입니다.

예(`levels` 출력):

| 인물 | 2레벨 경험치 | 10레벨 | 20레벨 | 99레벨 |
| --- | --- | --- | --- | --- |
| 勇者 | 19 | 3290 | 47929 | 7394160 |
| ライアン | 12 | 1579 | 34062 | 6407275 |
| アリーナ | 16 | 1844 | 35539 | 6690700 |

경험치가 다음 레벨 값 이상이면 전투 뒤에 레벨이 오릅니다. ライアン 경험치를 7 과 8 로 두고 4 를 주는 전투를 이기면 11 은 1레벨 그대로, 12 는 2레벨이 되었습니다. 레벨 99(`CMP #$63`)에서 멈춥니다(코드 읽기).

## 레벨업

`12:$9D36` 이 일행마다 다음 레벨 경험치를 곡선으로 구해 `$6E19 + 3 × 번호` 에 두고, 레벨이 오르면 `12:$9DB3` 이 힘, 속도, 체력, 지혜, 운, HP, MP 순으로 하나씩 올립니다(MP 는 0~4번만). 0번을 처리할 때 `$618E` bit6 이 서 있으면 레코드 번호 8(`$60F1`)을 고치지만 성장 곡선은 0번 것을 씁니다(코드 읽기, 여자 勇者 로 보임). 새 레벨을 L, 지금 값을 c 라 할 때:

1. 목표 `T = 곡선(L) + L/2 + 10`(나머지 버림). `c ≥ T` 면 증가는 0 또는 1(난수, 코드 읽기).
2. 아니면 기준 `d` = 그 레벨의 곡선 증가분. HP 는 방금 오른 체력 증가량 × 2.
3. 난수 `R` = 0~15 난수 32개의 합 + 16 − 128(0~255 를 벗어나면 다시 뽑음, `10:$A241`). 증가 = `d × R / 121`(나머지 버림).

`R` 의 평균이 128 이라 증가는 평균 `d × 1.06` 정도입니다. 값이 목표 `T` 를 넘으면 증가가 0~1 로 줄어 곡선에서 크게 벗어나지 않습니다.

## 주문

### 소비 MP 와 대상

`13:$B967` 에 주문 ID 순으로 1바이트씩(60개, 뒤 4바이트는 `1F`), 읽는 곳은 `13:$B953` 입니다.

| 비트 | 내용 | 근거 |
| --- | --- | --- |
| 4-0 | 소비 MP | ホイミ(`23`)를 필드에서 쓰면 MP 7→4. 롬 바이트를 `25` 로 바꾸면 7→2, `2B`(11)면 MP 가 모자라 못 씀 |
| 6-5 | 대상 범위: 0 고정(자신·일행 전체), 1 하나, 2 그룹, 3 모두 | 코드 읽기(`13:$B937` 이 1·2 일 때만 대상 고르기) + 값 분포(メラ 1, ギラ 2, イオ 3, スクルト 3, フバーハ 0) |
| 7 | 적에게 거는 주문 | 값 분포(공격·방해 주문만 1) |

メガンテ·メガザル 은 1, マホトラ·アバカム 은 0 입니다(남은 MP 를 모두 쓰는 주문 등을 따로 처리하는지는 확인 못 함).

### 배우는 레벨

`12:$A118` 과 `$A124` 에 0~4번(勇者, クリフト, ミネア, マーニャ, ブライ)의 포인터가 있습니다. `$A118` 쪽은 주문 64개의 비트 마스크 8바이트(바이트 n bit k = 주문 `8n + k`), `$A124` 쪽은 마스크에 선 주문마다 1바이트로 bit6-0 이 배우는 레벨입니다. bit7 이 선 주문은 지혜에 따라 늦어집니다(`12:$9ED2`).

- 지혜 보정 `B`(`12:$9F59`): 지혜 곡선 값 `T`(위 목표가 아니라 곡선 그대로)와 지금 지혜 `c` 를 비교해 `c > T + 10` 이면 0, `T − 15 ≤ c ≤ T + 10` 이면 1, 그보다 낮으면 2.
- 레벨 L 에서 bit7 이 없는 주문은 `레벨 ≤ L` 이면 배움. bit7 이 있으면 `레벨 + B ≤ L` 이면 배우고, `레벨 − 1 + B ≤ L` 이면 반쯤의 확률(난수 bit7 이 0)로 배움.

예(`spells` 출력, `*` = bit7): ホイミ クリフト 1·ミネア 1, ザキ クリフト 18\*, ルーラ 勇者 7·マーニャ 8·ブライ 9, ベホマズン 勇者 32\*. メガンテ 와 アバカム 은 아무도 레벨로 배우지 않습니다.

## 아이템

뱅크 `10` 의 표들을 아이템 ID 로 찾습니다(`10:$8B1E`~`$8C9B` 의 함수들).

| 표 | 내용 | 근거 |
| --- | --- | --- |
| `$9E17` | 강도 1바이트. 무기는 공격력, 갑옷·방패·투구는 수비력 | 「つよさ」 화면: ライアン 힘 7 + どうのつるぎ 12 = こうげき力 19, 속도 4 / 2 + かわのよろい 12 = しゅび力 14 |
| `$8E19` | bit6-0 가격의 앞자리, bit7 플래그(뜻은 모름) | |
| `$8D1B` | bit1-0 가격의 자릿수. 가격 = (`$8E19` & 7F) × 10^(`$8D1B` & 3)(`10:$8BED`, 코드 읽기). bit7-2 는 플래그(아래) | |
| `$8D9A` | bit7·bit6 플래그, bit5-0 사용 효과 번호로 보임(장비 대부분 `1B`) | |
| `$8C9C` | 아이템 `00`~`52` 의 장비 인물 비트(bit = 인물 번호) | 코드 읽기(`10:$8B3B`) |
| `$8B37` | 종류 경계 `24 3D 46 50`: 0 무기(`00`~`23`), 1 갑옷(`24`~`3C`), 2 방패(`3D`~`45`), 3 투구(`46`~`4F`), 4 그 밖(`50`~). `7F` 는 빈칸 | 코드 읽기(`10:$8B1E`) |

장비 판정(`10:$8B3B`, 코드 읽기): 인물 번호 8 이상이나 아이템 `53` 이상은 장비 못 함. かわのドレス·ピンクのレオタード·ひかりのドレス·きんのかみかざり(`30 31 3B 4D`)는 ミネア·マーニャ·アリーナ 와, `$615C` bit0 이 선 勇者 만 `$8C9C` 를 봅니다. 나머지는 `$8C9C` 의 인물 비트입니다. 예: てつのつめ `80`(アリーナ), てつのおうぎ `08`(マーニャ), せいぎのそろばん `20`(トルネコ), てんくうのつるぎ `01`(勇者), ぬののふく `FF`. 장 시작 아이템 중 장비한 것은 모두 주인의 비트가 서 있습니다.

`$8D1B` bit7-2 는 `10:$8C4F`(인자 0~5 → bit2~7)로 읽습니다. 값 분포로 본 뜻(확인 못 함):

| 비트 | 선 아이템 | 뜻으로 보이는 것 |
| --- | --- | --- |
| 2 | やくそう, キメラのつばさ, 씨앗·열매, せかいじゅのは, ときのすな | 쓰면 없어짐 |
| 3 | まじんのかなづち, もろばのつるぎ, みなごろしのけん, ゾンビメイル, まじんのよろい, じゃしんのめん | 저주 |
| 4 | 가격 0 인 중요한 물건, はぐれメタル 장비, ちいさなメダル | 팔 수 없음 |
| 5, 6, 7 | 열쇠·편지 같은 중요한 물건에 섞여 섬 | 모름 |

## 몬스터

`18:$8046` 부터 22바이트씩, 몬스터 ID 순입니다. 전투의 필드 읽기 함수(`10:$A67C`: 필드 번호 → `$AAA9` → 바이트 위치 `$AB4D`·길이 `$AB6A`, 처리 `$AADD`)가 이 레코드를 이렇게 나눕니다. 전투 RAM 은 적마다 `$7274 + 14 × n`(n = 0~7, `10:$AB3D` 의 포인터)에 속도(+0), 공격력(+1-2), 수비력(+3-4), HP(+10-11)가 들어갑니다.

| 바이트 | 내용 | 근거 |
| --- | --- | --- |
| 0-1 | 경험치(16비트) | 전투 두 번: おおみみず 둘 6, スライム+おおみみず 4 |
| 2 | 속도 | 전투 RAM +0: スライム 3, おおみみず 2 |
| 3 | 최대 MP 로 보임 | 코드 읽기(필드 `08`). 주문을 안 쓰는 몬스터는 0 |
| 4, 15 bit1-0 | 최대 HP(10비트). 전투에서는 이 값 이하로 정해짐 | 전투 RAM +10: おおみみず 11·9, スライム 8. 롬의 바이트 15 bit0 을 세우면 おおみみず HP 가 `0105`(261) |
| 5, 16 bit1-0 | 공격력(10비트) | 전투 RAM +1: 9, 10. 바이트 16 bit1 을 세우면 +2 가 `02` |
| 6, 17 bit1-0 | 수비력(10비트) | 전투 RAM +3: 5, 6. 바이트 17 bit0 을 세우면 +4 가 `01` |
| 7, 18 bit1-0 | 골드(10비트) | 전투 두 번: おおみみず 둘 12, スライム+おおみみず 8. 위 비트는 코드 읽기 |
| 8 | bit6-0 떨어뜨리는 아이템(`7F` 없음), bit7 플래그 | 롬의 바이트 8 을 `55`, 바이트 20 을 `40` 으로 바꾸고 이기니 せいすい(`55`)가 소지품에 들어옴 |
| 9-14 | bit6-0 행동 번호 6개. bit7 은 둘씩 묶어 2비트 값 셋(필드 `1F`~`21`) | 코드 읽기 |
| 15-19 의 bit7-2 | 2비트 값 15개(필드 `22`: 번호 i → 바이트 `15 + i/4`, bit `2(i%4)` 부터). 내성으로 보임 | 코드 읽기 |
| 20 | bit7-6, bit5-3, bit2-0 의 세 값. bit2-0 은 드롭 확률 | 위 실험, `12:$922D` |
| 21 | bit7-6, bit5-3, bit2-0 의 세 값 | 코드 읽기 |

드롭(`12:$9217`, 코드 읽기 + 위 실험): 아이템이 `7F` 가 아니고 바이트 20 bit2-0 이 0 이면 반드시, 1~6 이면 난수(0~255)가 `12:$9286` 의 `20 10 08 04 02 01` 보다 작을 때, 7 이면 1/256 에 다시 1/16(1/4096)입니다. 예: スライム やくそう 2/256, メタルキング はぐれメタルへルム 1/4096.

예: スライム 경험치 1, 골드 2, HP 8, 공격력 9, 수비력 5, 속도 3. はぐれメタル HP 5, 수비력 1023, 경험치 10050.

## 확인

- 1장 세이브스테이트(`work/state/dq4-ch1-field.mss`, `dq4-ch1-battle.mss`)에서 [tools/lua/fc/statspoke.lua](../tools/lua/fc/statspoke.lua) 로 RAM(레코드, `$616A`, 경험치)이나 롬 바이트를 한 번 바꾸고 전투를 만들어 이김.
- 레벨업: 인물마다 레코드를 1레벨 값으로 써 넣고 경험치 5000 으로 싸워 10~13레벨까지 올리며 [tools/lua/fc/statsstack.lua](../tools/lua/fc/statsstack.lua) 로 `12:$9DE7`·`$9E09`·`$9E23`·`$9D64`·`$9E8C`·`$9F06` 을 기록. 0~5·7번은 레코드를 바꿔서, ライアン 은 경험치 20000 으로 17레벨까지 올려 목표값 626, 기준 증가분 626, 증가량 626, 다음 레벨 경험치 143, 지혜 보정 56, 주문 습득 56 건이 계산과 모두 같았고, 끝 레코드의 능력치가 처음 값 + 기록한 증가량과 같았음.
