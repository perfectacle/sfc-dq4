# DQ4(FC) 상점·여관·보물상자 형식

가게 창에 늘어서는 품목, 여관 값, 가게 인물이 고르는 가게 종류, 그리고 보물상자와 발밑 숨은 물건(しらべる)의 위치·내용물·열었음 플래그입니다. 디코더는 [tools/dq4shop.py](../tools/dq4shop.py)·[tools/dq4chest.py](../tools/dq4chest.py), 실험 과정은 [2026-10-25-10 일지](journal/dq4/2026-10-25-10-shop.md) 에 있습니다. 주소 표기는 [dq4-ram-format.md](dq4-ram-format.md), 아이템 ID·이름·가격은 [dq4-data-format.md](dq4-data-format.md), 맵 장소(그룹 `$63`/순번 `$64`)는 [dq4-map-format.md](dq4-map-format.md) 를 따릅니다.

## 대화 값과 가게 종류

인물에게 말을 걸면 `1C:$96C7` 이 인물 레코드에서 대화 번호([dq4-script-format.md](dq4-script-format.md#대화-번호))를 꺼내 `$00:$01` 에 두고, `15:$9962` 가 `$01` = 0 이고 `$00` < 7 이면 메시지 대신 가게 처리 `15:$9CBF` 로 보냅니다. 7 이상은 스크립트(`15:$999E`, 표 `15:$98F6`), `$0161` 이상은 예/아니오 창과 메시지입니다.

| 값 | 처리 | 하는 일 |
| --- | --- | --- |
| 1 | `15:$B84A` | 무기점. `$07C5` = 1 |
| 2 | `15:$B858` | 도구점. `$07C5` = 2 |
| 3 | `15:$B851` | 방어구점. `$07C5` = 3 |
| 4 | `15:$BBF0` | 맡기는 곳(메시지 `0238` 「ここは もちものと おかねの あずかりじょです。」) |
| 0·5 | `15:$B550` | 교회(메시지 `021B`/`021C`, `$62ED` 로 낮·밤) |
| 6 | `15:$BF28` | 여관(메시지 `0231`~`0237`) |

무기·도구·방어구 셋은 가게 창을 열기 전에 `15:$B217` 이 품목을 RAM 에 담습니다.

| RAM | 내용 |
| --- | --- |
| `$07BD`~`$07C4` | 품목 ID(최대 8개, 표에서 bit7 은 지움) |
| `$07C4` | 품목 수(마지막 품목에 bit7 이 있는 줄일 때 씀) |
| `$07C5` | 가게 종류 1~3 |

### 가게 인물

대화 번호는 인물 레코드([dq4-map-format.md](dq4-map-format.md#인물)) 머리 바이트 1 의 bit4-2(위 3비트)와 바이트 4(아래 8비트)입니다([dq4-script-format.md](dq4-script-format.md#대화-번호)). 가게 인물은 대화 번호가 1~6 이라 바이트 4 가 곧 가게 종류입니다. 아래 10명은 실제로 말을 걸어 값(`15:$9962` 에서 본 `$00`)이나 열린 가게가 바이트 4 와 같았습니다.

| 맵 | 인물 칸 | 바이트 4 | 확인 |
| --- | --- | --- | --- |
| `02/00` | (0D,16) | `01` | `$00`=`01`, 무기점 창 |
| `02/00` | (18,15) | `02` | `$00`=`02`, 도구점 창 |
| `02/00` | (05,14) | `05` | `$00`=`05` |
| `02/00` | (15,21) | `06` | `$00`=`06`, 「ひとばん 4ゴールドですが」 |
| `12/00` | (0F,03) | `01` | 무기점 창 |
| `04/00` | (22,11) | `02` | 도구점 창 |
| `13/00` | (24,04) | `01` | 무기점 창 |
| `0C/00` | (16,05) | `03` | 방어구점 창 |
| `13/00` | (06,17) | `06` | 「ひとばん 2ゴールドですが」 |
| `0C/00` | (1B,0E) | `06` | 「ひとばん 6ゴールドですが」 |

대화 번호가 7 이상인 인물도 스크립트 안에서 가게를 열 수 있습니다. `02/00` 방어구점 인물(레코드 자리 (1F,16))은 대화 번호가 `0D` 였고, 스크립트 `0D − 7`(`15:$8082`)을 거쳐 `15:$B851` 방어구점으로 갔습니다. `dq4shop.py G K` 는 대화 번호가 0~6 인 인물만 냅니다(0 도 `$B550` 교회로 감). 스크립트로 여는 가게는 `tools/dq4talk.py G K` 로 봅니다.

## 무기·도구·방어구 목록

`15:$B222` 가 `$07C5` 로 18:`$802C` + 2 × (종류 − 1) 의 포인터를 꺼냅니다.

| 종류 | 포인터 | 목록 시작 |
| --- | --- | --- |
| 1 무기 | `18:$802C` | `18:$B418` |
| 3 방어구 | `18:$8030` | `18:$B49A` |
| 2 도구 | `18:$802E` | `18:$B530` |

세 목록은 무기 → 방어구 → 도구 순으로 이어 붙어 있고, 줄 하나는 이렇습니다.

| 바이트 | 뜻 |
| --- | --- |
| 0 | 그룹 `$63`. `FF` 면 어느 장소에나 맞는 줄이고 순번 바이트가 없음 |
| 1 | 순번 `$64` |
| 2~ | 품목 ID. 마지막 품목은 bit7 이 켜짐 |

`15:$B2CB` 는 줄을 차례로 읽어 (그룹, 순번)이 지금 장소와 같거나 그룹이 `FF` 인 첫 줄을 고릅니다. 맞지 않는 줄은 bit7 이 켜진 바이트까지 건너뜁니다. 목록 끝을 따로 표시하지 않아서, 무기 목록에 없는 장소면 방어구·도구 목록까지 이어서 찾고, 끝의 `FF` 줄(`79` うまのふん 다섯 개)에서 멈춥니다. 무기 20줄, 방어구 20줄, 도구 24줄이 있습니다. 도구 목록에는 맵 목록에 없는 그룹 `FE`(순번 `FE`) 줄도 있습니다.

품목이 종류를 꼭 따르지는 않습니다. `13/00` 무기점은 みかわしのふく·てっかめん 을, `13/00` 방어구점은 やくそう 를 팝니다(화면 확인).

### 덧붙임(`15:$B26B`)

| 장소·종류 | 조건 | 바뀌는 것 |
| --- | --- | --- |
| `16/00` 무기 | `$62E7`·`$62E8`·`$62E9` 가 0 이 아닌 것마다 | `15:$A4A4` 의 `0B` ブーメラン·`04` くさりがま·`23` はじゃのつるぎ 를 뒤에 붙임 |
| `09/00` 무기 | `$62ED` < `$78` 일 때(`15:$9CE5`) | 목록을 `06 23 07 10`(はがねのつるぎ·はじゃのつるぎ·バトルアックス·りりょくのつえ)으로 바꿈 |

두 덧붙임은 코드 읽기만 했습니다.

### 가격

가게 창의 가격은 [dq4-data-format.md](dq4-data-format.md) 의 아이템 가격 공식 (`10:$8E19` & 7F) × 10^(`10:$8D1B` & 3) 과 같았습니다. 5개 가게 창 27품목(`02/00` 무기 4, `12/00` 무기 5, `04/00` 도구 6, `13/00` 무기 6, `0C/00` 방어구 6)을 화면에서 읽어 모두 맞았습니다.

## 여관

`15:$BF71` 이 `BRK 87 8F`(뱅크 18 함수 07 의 주소를 `$DA` 에 꺼냄)로 표 `18:$B5CD` 를 얻습니다. 줄은 3바이트(그룹, 순번, 1인 값)이고 `FF` 로 끝나며 31줄입니다.

- 그룹이 `FE` 이면 표를 보지 않고 10.
- 그룹 `10` 에서 `$45` < `$14` 이면 그 줄 대신 10.
- 요금 = 1인 값 × `BRK 62 23 01`(뱅크 10 함수 2, `10:$80D1`) 이 돌려준 A(`0F:$C827` 곱셈). 1장 라이안 혼자일 때 A = 1 이었습니다.

## 보물상자

상자는 맵 블록의 「종류」로 정해지고, 내용물은 맵마다가 아니라 게임 전체에 하나뿐인 표에서 순번으로 찾습니다.

| 단계 | 루틴 | 내용 |
| --- | --- | --- |
| 블록 종류 | `08:$8055` → `$8464` | 맵 로드 때 블록 32개의 종류 바이트를 `$6F40`~`$6F5F` 에 씀. 값 = `08:$8ADB` + 맵 번호(`$0028`, 6비트) × 64 의 2바이트 기술자 `(b0 & 7) << 8 \| b1` 로 `08:$A80D`(포인터 `08:$8235`) + 3 × 그 값의 셋째 바이트. `b0 & 7` = 7 인 블록은 따로 처리(`08:$847A`) |
| 상자 판정 | `1E:$B3FE` | しらべる 때 발밑 블록 종류 & 7F 가 `04` 이면 상자(`1E:$B447`), 아니면 발밑 표 |
| 맵 안 순번 | `08:$B4E5` | 맵 버퍼 `$7800` 에서 지금 칸 앞(가로 줄 순서)에 있는 종류 `04` 칸의 수 |
| 전체 순번 | `1E:$B72E`·`$B741` | 개수 표(포인터 `1E:$BDBE`)에서 (그룹, 순번)이 지금 장소보다 앞인 줄의 개수 합 + 맵 안 순번 → `$6278`/`$6279` |
| 내용물 | `1E:$B7B2` | 내용 표(포인터 `1E:$BDC0`)[전체 순번] |
| 열었음 | `1E:$B791` | `$625D` + (순번 >> 3) 의 비트 `80 >> (순번 & 7)` |

개수 표는 3바이트(그룹, 순번, 상자 수) 82줄이고 `FF` 로 끝납니다. 상자는 모두 160개, 열었음 플래그는 `$625D`~`$6270` 의 20바이트입니다.

내용 바이트는 이렇게 읽습니다.

| 값 | 뜻 |
| --- | --- |
| `00`~`7F` | 아이템 ID |
| `80`~ (특수 목록에 없음) | 금화 (값 & 7F) × 40(`1E:$B47F`) |
| 특수 목록(`1E:$BC34`: 개수, 값들) | `FF` 빈 상자(메시지 `0297`), `FE` ミミック(`0299`), `FD` ひとくいばこ(`029A`), `EF` バロンのつのぶえ, `EE` てつのきんこ, `E3` やみのランプ, `E2` パデキアのたね, `E0` しんじるこころ. 처리 루틴은 `1E:$BC3D` 표(코드 읽기) |

## 발밑 숨은 물건

상자가 아닌 칸에서 しらべる 하면 `1E:$B4DB` 가 표 `1E:$BF59` 를 찾습니다. 줄은 5바이트(그룹, 순번(아래 5비트), X, Y, 내용)이고 `FF` 로 끝나며 25줄입니다.

| 내용 | 뜻 |
| --- | --- |
| `00`~`7F` | 아이템 ID(이 롬의 표에는 없음) |
| `A0`~`AA` | 한 번만 주울 수 있는 물건. `1E:$BDB3`[값 & 0F] 의 아이템(bit7 이면 금화 × 40). 주웠음 플래그 `$6272` + (n >> 3) 의 비트 `80 >> (n & 7)`, n = 값 & 0F |
| 특수 목록(`1E:$BC55`) | `E1`~`EE`, `F1` 등. 장면마다 처리가 따로 있음(코드 미해석) |

## 남은 것

- 스크립트를 거쳐 가게를 여는 인물까지 넣은, 맵마다 어느 인물이 어느 가게인지 완전한 표(`dq4talk.py` 의 스크립트 해석과 묶기).
- 교회(값 5)와 맡기는 곳(값 4)의 요금·메뉴. 여관 곱수 `10:$80D1` 이 무엇을 세는지(일행 수로 보임, 1명일 때만 봄).
- 그룹 `FE` 가 어떤 장소인지(도구 목록과 여관에만 나옴).
- 덧붙임 두 곳(`16/00`·`09/00`)을 화면으로 확인하지 않음.
- `dq4chest.py check` 의 다른 3곳: `3D/01`(상자 칸 1)·`40/01`(4)·`40/03`(5)은 개수 표에 줄이 없음. 같은 블록을 상자가 아닌 데 쓰는지, `08:$8710`(BRK `11 87`, 맵에 들어갈 때 블록 정의를 바꿈)이 바꾸는지 모름. 개수 표에만 있는 `48/01`·`48/02`·`48/05`·`48/06`·`48/07` 은 맵 목록에 없어 칸을 모름.
- `08:$8710` 이 로드 뒤 `$6F40` 의 일부 블록 종류를 바꿈(`02/00` 블록 `12` 가 롬 값 `80` 에서 `04` 로). 어떤 조건으로 무엇을 바꾸는지.
- 상자 특수 내용과 발밑 특수 내용(`E0`~`FF`)마다의 처리, ミミック·ひとくいばこ 전투.
