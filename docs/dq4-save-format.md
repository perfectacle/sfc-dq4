# DQ4(FC) 저장 데이터·이벤트 플래그·장 시작

FC 「드래곤 퀘스트 IV」 일본판 Rev A(`rom/dq4.nes`)의 배터리 백업 SRAM(`$6000`~`$7FFF`) 구조, 이벤트 플래그 영역, 장(章)을 시작할 때 롬에서 읽는 표입니다. 주소 표기는 [dq4-handoff.md](dq4-handoff.md#조심할-것) 를 따르고, 필드 RAM 은 [dq4-ram-format.md](dq4-ram-format.md) 에 있습니다. 실험 과정은 [2026-10-25-11 일지](journal/dq4/2026-10-25-11-event.md) 에 있습니다.

근거가 실측이 아니라 코드 읽기인 줄에는 「코드 읽기」라고 적었습니다. 덤프를 푸는 도구는 `tools/dq4event.py` 입니다.

```sh
uv run python tools/dq4event.py rom/dq4.nes sram work/x/end.sram     # 작업 영역·모험의 서 3칸, CRC 검사
uv run python tools/dq4event.py rom/dq4.nes chapters                 # 1~5장 시작 표
uv run python tools/dq4event.py rom/dq4.nes chars --compare work/x/end.sram
```

## SRAM 배치

게임은 진행 상태를 SRAM 의 작업 영역에 바로 두고, 저장할 때 그 영역을 모험의 서 칸에 통째로 복사합니다.

| 주소 | 크기 | 내용 | 근거 |
| --- | --- | --- | --- |
| `$6001`~`$62EE` | `$2EE` | 작업 영역. 인물 레코드, 골드, 장, 일행, 이벤트 플래그 등 저장되는 모든 값 | 교회에서 저장한 직후 1번 칸의 사본과 바이트가 모두 같음 |
| `$62EF`~`$65DE` | `$2F0` | 모험의 서 1: CRC 아래·위 바이트 + 작업 영역 사본 | 저장할 때 쓰이는 바이트(`probe/writes.lua`) |
| `$65DF`~`$68CE` | `$2F0` | 모험의 서 2(같은 형식) | 빈 칸이 `4B` 로 차 있는 것, 칸 주소 계산 `12:$AD1C`(코드 읽기) |
| `$68CF`~`$6BBE` | `$2F0` | 모험의 서 3 | 같음 |
| `$6BBF`~`$6BD8` | 13 × 2 | `MANABU YAMANA` 두 벌. `12:$AC93` 이 `12:$AD78` 에서 복사 | SRAM 덤프. 초기화 확인용 서명으로 보임(코드 읽기) |
| `$6BD9`~ | | 저장하지 않는 작업 RAM(인물 표 `$6F60`, 맵 버퍼 `$7800` 등) | |

### 체크섬

칸의 첫 두 바이트는 사본 `$2EE` 바이트의 CRC 입니다(아래 바이트 먼저).

- 계산: CRC-16, 다항식 `1021`, 위 비트부터, 시작값 `3A3A`, 마지막 XOR 없음. `12:$ACA2` 가 시작값을 `$12`/`$13` 에 넣고 바이트마다 `1F:$C8AD` 를 부릅니다.
- 검사: `12:$ACC4` 가 다시 계산해 칸의 두 바이트와 뺄셈으로 비교합니다(코드 읽기).
- 빈 칸: 칸 앞 5바이트가 모두 `4B` 이면 빈 칸입니다(`12:$ACF8`). 빈 칸 전체가 `4B` 로 차 있습니다.

| 확인 | 결과 |
| --- | --- |
| 바트랜드 교회에서 저장한 1번 칸 | 적힌 CRC `5AD0`, 다시 계산 `5AD0` |
| 1번 칸의 `$6290` 을 `02`→`0B` 로 바꾸고 CRC 를 `C9C7` 로 맞춰 불러오기 | 정상으로 불러와 귀환 자리 `0B`(`0E/00` (0C,19))에서 시작 |
| 같은 바꾸기에서 CRC 를 그대로 두고 불러오기 | 「おきのどくですが　ぼうけんのしょ　1ばんは　きえてしまいました。」 |

## 작업 영역

### 인물 레코드 `$6001` + 30 × 번호

레코드 번호는 직업 이름 목록([dq4-data-format.md](dq4-data-format.md))의 순번과 같습니다: `0` ゆうしゃ(주인공), `1` しんかん(クリフト), `2` うらないし(ミネア), `3` おどりこ(マーニャ), `4` まほうつかい(ブライ), `5` ぶきや(トルネコ), `6` せんし(ライアン), `7` ひめ(アリーナ). 장 시작 루틴이 0~7 만 초기화합니다(`12:$8EFF`~`$9017`).

| 자리 | 크기 | 내용 | 근거 |
| --- | --- | --- | --- |
| `+00` | 1 | `80` 이면 레코드가 쓰임 | 장 시작 루틴이 `80` 을 씀 |
| `+01` | 2 | HP | 상태 화면: `1B 01` 을 써서 HP 283 |
| `+03` | 2 | MP | 상태 화면: `2A 01` 을 써서 MP 298 |
| `+05` | 1 | 레벨 | 상태 화면 |
| `+06`~`+0A` | 5 | ちから, すばやさ, たいりょく, かしこさ, うんのよさ | 상태 화면(ライアン 7, 4, 13, 1, 2) |
| `+0B` | 1 | 모름. `05` 를 써도 상태 화면에 바뀐 것이 없음 | 상태 화면 |
| `+0C` | 2 | 최대 HP | 상태 화면: `1B 01` 을 써서 283 |
| `+0E` | 2 | 최대 MP | 상태 화면: `21 03` 을 써서 801 |
| `+10` | 3 | 경험치 | 상태 화면: `45 23 01` 을 써서 74565 |
| `+13`~`+1A` | 8 | 소지품. 아래 7비트 = 아이템 ID, bit7 = 장비(화면의 「E」), `FF` = 빈 칸 | 상태 화면(`82` = E どうのつるぎ, `A6` = E かわのよろい) |
| `+1B`~`+1D` | 3 | 주문 비트로 보임. 장 시작 때 `12:$8FC8` 이 `BRK 38 0F` 로 배우게 함 | 코드 읽기. 값은 クリフト·ミネア `02 00 01`, マーニャ·ブライ `01 00 00` |

### 그 밖의 값

| 주소 | 내용 | 근거 |
| --- | --- | --- |
| `$6157`~`$6159` | 골드. `$6157`/`$6158` 에 `39 30` 을 써서 G12345 | 상태 화면. 셋째 바이트는 장 시작 루틴이 0 으로 씀(코드 읽기) |
| `$615A` | 장 − 1(1장 `00` ~ 5장 `04`) | 디버그 장 고르기로 1~5장을 시작해 확인(아래) |
| `$615B` | 장 시작 때 0 | 코드 읽기 |
| `$615D`~`$6160` | 주인공 이름 4바이트(글자 바이트, `00` = 빈 칸) | 세이브스테이트의 이름 `0B 0B 0B 00` 이 모험의 서 목록에 「あああ」로 나옴 |
| `$6165`~`$6169` | 장마다 `12:$9179` 에서 복사하는 5바이트. 뜻은 모름 | 1~5장 시작 뒤 값이 표와 같음 |
| `$616A`~`$616D` | 걷는 일행 4자리. bit7 + 레코드 번호 | 장 시작 뒤 선두만 들어 있음(1장 `86` ライアン) |
| `$6172`~`$6177` | 마차 등 나머지 6자리로 보임 | `$615A`=6 모드에서 `84 85 86 87` 이 들어감 |
| `$618E` | `$615A`=5 이상이면 `20` | 코드 읽기, 6 모드에서 실측 |
| `$6282` | 끝낸 장 비트. 장 시작에서 1장 `00`, 2장 `80`, 3장 `C0`, 4장 `E0`, 5장 `F0` | 실측. 장별 시작 루틴(`1E:$A4BE` 등)이 씀. 장이 끝날 때 `1A:$B908` 이 `SEC`·`ROR` 로 한 비트 더함(코드 읽기) |
| `$6290` | 귀환 자리 번호(아래 표). 저장하면 그 교회 자리가 들어감 | 바트랜드 교회 저장 뒤 `02` |
| `$6291` | 플래그 번호 `16`. bit7 = 이 장의 시작 처리를 했음 | bit7 을 0 으로 두고 저장·불러오기 하면 `$615A` 의 장을 처음부터 시작 |

`$627B`~`$62EE` 는 이벤트 플래그 영역입니다(아래). `$6290`·`$6291` 도 이 영역 안에 있어 플래그 명령으로 다룹니다.

## 이벤트 플래그 `$627B`~`$62EE`

플래그는 (번호 n, 마스크 m) 쌍입니다. 주소 = `$627B` + n, 비트 = m. BRK 특수 형식 4바이트 `00 n op m` 으로 다룹니다([dq4-bank-format.md](dq4-bank-format.md#특수-형식)). `1F:$C463` 이 `op` 를 보고 `1F:$C4A1` 로 가서 복귀 주소를 하나 늘린 뒤(BRK+4 로 복귀) 아래를 합니다.

| `op` | 하는 일 | 루틴 | 실측 |
| --- | --- | --- | --- |
| `CB` | `$627B+n` \|= m | `1F:$C4CA` | `1E:$A354` `00 16 CB 80` → `$6291` `00`→`80`, `1E:$A399` `00 0D CB 40` → `$6288` `00`→`40` |
| `DB` | `$627B+n` &= m | `1F:$C4E1` | `1E:$A41B` `00 0D DB BF` → `$6288` `40`→`00`, `1E:$A3D8` `00 10 DB 00` → `$628B` `FF`→`00` |
| `EB` | `$627B+n` & m 을 계산해 Z 플래그로 돌려줌(쓰지 않음) | `1F:$C4B6` | `16:$87F1` `00 16 EB 10` 이 매 프레임 실행됨(`probe/trace.lua`, X=`16`) |

실측은 2장 시작을 `tools/lua/fc/eventflags.lua` 로 기록한 것입니다. 이 영역을 직접 읽고 쓰는 코드도 있습니다: 불러오기 때 `12:$AC47` 이 칸에서 영역 전체를 복사하고, `0F:$DC0E` 가 `$627E` 에 비트를 켜며(맵에 들어갈 때), 대화 스크립트의 명령 `17`·`18`·`19` 와 조건 `1A`~`1C` 도 같은 (n, m) 을 씁니다([dq4-script-format.md](dq4-script-format.md)).

`dq4event.py ops` 는 롬에서 `00 n CB/DB/EB m`(n ≤ `73`) 모양을 모두 찾습니다(435곳). 바이트 모양만 보므로 데이터가 섞일 수 있습니다. 예를 들어 `--flag 16` 은 장 시작(`1E:$A354` 켜기 `80`)과 장 끝(`1A:$B92C` 끄기 `7F`)을 함께 보여 줍니다.

## 장 시작

### 흐름

1. 불러오기 뒤 `1E:$A34C` 가 `$6291` bit7 을 봅니다. 켜져 있으면 저장한 자리로 돌아갑니다(`1E:$A3A1`).
2. 꺼져 있으면 `BRK 16 CB 80` 으로 켜고, `BRK 12` 함수 `17`(`12:$8EAE`)로 장 초기화, `1E:$A480` 장별 처리, `1E:$A578` 이 시작 자리를 `$63`/`$64`/`$44`/`$45` 에 씁니다(`1E:$A595`).
3. 장이 끝나면 `1A:$B8FF`~ 가 `$6282` 에 비트를 더하고 `$615A` 를 1 늘리고 `BRK 16 DB 7F` 로 `$6291` bit7 을 끕니다(코드 읽기). 그래서 다음 불러오기에서 다음 장이 시작됩니다.

### 장 초기화 `12:$8EAE`

| 하는 일 | 표 | 값 |
| --- | --- | --- |
| `$610F`~`$6156`, `$615B`, `$618E` 를 0 으로 | | |
| 선두 `$616A` = 표[장], `$616B`~`$6177` = 0 | `12:$913E` | `86 87 85 83 80` |
| 인물 i 의 처음 장 = 표[i]. 그 장이면 레코드 i 를 아래로 초기화 | `12:$9136` | `04 01 03 03 01 02 00 01` |
| HP·최대 HP = 표[i], 레벨 1, `+00`=`80` | `12:$A296` | `19 12 12 10 10 14 1B 10` |
| 능력치 6개(`+0E` 최대 MP·MP, `+06`~`+0A`) = 표 6개(포인터 `12:$9151`) 각각의 `6i`~`6i+4` 바이트 bit7 을 모은 5비트(앞 바이트가 아래 비트). ライアン·アリーナ(6, 7)는 MP 0 | `12:$A248` 등 | `chars` 출력 |
| 주문(0~4번만, `BRK 38 0F`) | `12:$9165`, `12:$916F` | 코드 읽기 |
| 소지품 8칸 = 표[8i] | `12:$9192` | `chars` 출력 |
| 골드 = 표[장], 위 두 바이트 0 | `12:$91D9` | 50, 100, 0, 100, 0 |
| `$6165`~`$6169` = 표[5 × 장] | `12:$9179` | |
| 4장이면 `$07C6`~`$07C8`, `$62E7`~`$62E9` 를 0 으로 | | 코드 읽기 |
| 모든 레코드의 소지품에서 아이템 `6B`·`6C`·`5D` 를 빼고 앞으로 당김 | | 코드 읽기 |

### 1~5장 시작 표

| 장 | 시작 장소 (X,Y) `1E:$A599` | 선두 | 골드 | 처음 귀환 자리 `1E:$A75E` | 초기화 인물 |
| --- | --- | --- | --- | --- | --- |
| 1 | `02/01` (10,15) | ライアン | 50 | `02` | ライアン |
| 2 | `01/01` (09,08) | アリーナ | 100 | `10` | クリフト, ブライ, アリーナ |
| 3 | `16/01` (1B,05) | トルネコ | 0 | `12` | トルネコ |
| 4 | `15/03` (0C,0F) | マーニャ | 100 | `11` | ミネア, マーニャ |
| 5 | `14/00` (05,11) | 주인공 | 0 | `05` | 주인공 |

다섯 장 모두 아래 디버그 장 고르기로 시작해, `1E:$A595` 에서 `$63`/`$64`/`$44`/`$45` 가 표와 같고, 장 시작 뒤 `$615A`·골드·`$616A`·`$6290`·`$6165`~ 가 표와 같고, 그 장에서 초기화되는 인물 8명의 레코드(주문 비트 빼고)가 `chars` 계산과 모두 같았습니다. 2·3장은 시작 뒤 이벤트로 일행이 바뀌므로(예: 2장은 처음에 アリーナ 혼자) `$616A` 는 선두만 확인했습니다.

### 디버그 장 고르기

`1E:$A35B` 가 장을 시작하기 전에 고정 뱅크 `$C000` 의 롬 바이트를 읽어 bit3 이 0 이면 `1F:$F102` 의 「シナリオ」 창(1~5)을 띄웁니다. 제품판은 `FF` 라 나오지 않습니다.

- 좌우(`$14` bit6·bit7)로 `$615A` 를 0~4 사이에서 바꾸고, A 로 그 장을 시작합니다.
- B 는 `$615A` = 6 을 돌려줍니다. 장 초기화가 인물 8명을 모두 초기화하고, 일행 `80 81 82 83`, 나머지 `84 85 86 87`, 골드 90, 주인공 HP·MP `FFFF`, `$615A` 를 4 로 고쳐 5장 자리(`14/00`)에서 시작합니다(`12:$8EC3`, `12:$9066`).

테스트러너에서 PRG ROM 메모리 `3C000`·`7C000`(고정 뱅크 `0F`·`1F` 의 `$C000`)을 `F7` 로 바꿔 창을 보고, 1~5장과 B 를 모두 시작했습니다. 롬 파일은 고치지 않습니다. 성 앞마당 세이브스테이트에서 교회로 걸어가 `$6291` 을 0 으로 둔 채 저장하고, 리셋해 불러온 뒤 3장을 고르는 명령입니다.

```sh
export MESENCE=... LIBDIR=$(uv run krpatch fc lua)
d=$PWD/work/ch3; mkdir -p $d
W="y=12,x=13,y=1C,x=05,y=16,up:2,wait:10,a:6,wait:40,a:6,wait:300"   # 교회 신부 앞
S="a:6,wait:80,a:6,wait:80,a:6,wait:80,wait:60,a:6,wait:200"          # 기도 → 저장
T="reset:1,wait:600,start:4,wait:60,a:4,wait:60,a:4,wait:60,a:4,wait:60,a:4,wait:40"   # 불러오기
A=""; for i in $(seq 45); do A="${A}a:6,wait:44,"; done                # 장 머리말 넘기기
STATE=$PWD/work/state/dq4-ch1-courtyard.mss SEQ="$W,$S,$T,right:2,wait:20,right:2,wait:20,a:4,wait:60,${A}wait:60" \
  TAIL=30 POKEAT="5:6291=00" PRGPOKE="3C000=F7;7C000=F7" SHOT_DIR=$d \
  "$MESENCE" --testrunner --nes.ramPowerOnState=AllZeros $PWD/rom/dq4.nes $PWD/tools/lua/fc/eventwalk.lua
cat $d/walk.txt    # end ... at 1B,05 map 16/01
```

`$d/end.mss` 가 그 장을 조작할 수 있는 세이브스테이트입니다.

## 귀환 자리 표 `1E:$A76D`

5바이트 레코드 22개: 그룹, 순번, X, Y, 끝 바이트(아래 2비트 방향, 위 6비트는 `1E:$AEFE` 7바이트 레코드 번호이고 그 레코드의 3~6바이트를 `$6195`~`$6198` 에 씀). `$6290` 이 번호입니다. 불러오기 때 `1E:$A690` 이 이 표로 자리를 정하고, 교회에서 저장할 때 `1E:$A73F` 가 현재 `$63`/`$64` 와 같은 레코드를 찾아 번호를 `$6290` 에 씁니다(코드 읽기).

| 번호 | 확인 |
| --- | --- |
| `02` | `02/00` (05,16): 바트랜드 교회에서 저장한 뒤 `$6290`=`02`, 불러오면 그 자리 |
| `0B` | `0E/00` (0C,19): 칸의 `$6290` 을 `0B` 로 바꿔 불러오면 그 자리 |
