# 2026-10-25-37: 호출 분석의 BRK 길이 고치기

`tools/dq4talk.py` 의 `brk_len` 이 BRK 특수 형식(`b2` 아래 4비트 `3`)의 길이를 틀리고 있었습니다. 고치니 호출 분석이 루틴을 끝까지 따라가, 부르는 곳을 몰랐던 이벤트 `2D` 의 호출처와 이벤트 `2B` 의 뒷부분이 나왔습니다. 결과는 [dq4-script-format.md](../../dq4-script-format.md) 의 「호출 문장」·「이벤트 표」 에 있습니다.

## 1. 길이 표가 둘이었다

호출 분석(`call_tags`)과 이벤트 분석(`event_ops`)은 루틴을 한 명령씩 읽다가 BRK 를 만나면 문장 길이만큼 건너뜁니다. `dq4talk.brk_len` 은 `b2 >> 4` 가 2·4·6·8 이면 BRK+4, 아니면 BRK+3 으로 쳤습니다. [dq4-bank-format.md](../../dq4-bank-format.md) 의 실측 표(호출 위치 191곳)와 견주면 세 곳이 다릅니다.

| `b2` | 옛 `dq4talk` | 실측 |
| --- | --- | --- |
| `83` | 4 | 5 |
| `93` | 3 | 4 |
| `C3`·`D3` | 3 | 4 |

상자 분석의 `dq4chest.brk_len` 은 같은 표를 따로 갖고 있어 맞았고, `tools/dq4bank.py` 에도 `x3_length` 로 같은 규칙이 있었습니다. `dq4talk.brk_len` 이 `dq4bank.x3_length` 를 쓰게 하고, `dq4chest.brk_len` 은 `dq4talk.brk_len` 을 그대로 쓰게 해서 표를 하나로 모았습니다.

## 2. 바뀐 결과

`15:$AE4E`(대화 `13B` 가 부르는 루틴)는 앞에서 `BRK 46 93 07` 을 씁니다. 옛 길이로는 이것을 BRK+3 으로 넘겨 `07` 부터 잘못 읽었고, 뒤에 있는 `LDA #$2D` · `BRK 07 CF`(이벤트 `2D`)를 놓쳤습니다.

```
15:AE5F  00 46 93 07   BRK 46 93 + 셋째 바이트
...
         a9 2d 00 07 cf   LDA #$2D, BRK 07 CF
```

```
$ uv run python tools/dq4talk.py rom/dq4.nes calls      # 고친 뒤
15:AE4E  이벤트(1C:$BF74 표), 아이템, 창, 메시지 이벤트 2D  ← 13B+A70A
호출 126곳, 루틴 100개: … 메시지 11, 이벤트(1C:$BF74 표) 37, …
```

메시지 갈래 루틴 하나가 이벤트 갈래로 옮겨 갔습니다(12 → 11, 36 → 37). `events` 에서는 「부르는 곳 없음」 이던 이벤트 `2D` 에 대화 `13B` 가 붙었습니다. 이벤트 `2B`(마지막 전투)는 뒷부분까지 읽혀 플래그 `$6288` |= 80, 메시지 `04B0`·`04B1`·`04C0`·`04B2`(マスタードラゴン), `$65` = `01` 이 더해졌습니다. `dq4talk.py all`·`dq4chest.py all`·`dq4shop.py people`·`dq4event.py events` 의 출력은 고치기 전과 같았습니다.

1장 왕좌의 방에서 왕에게 `TID=13B` 로 말을 걸어 보았는데, `$AE4E` 의 앞 갈래에서 빠져 인자의 메시지 `0AA7`·`0AA8` 만 나왔습니다. 이벤트 `2D` 로 가는 갈래는 아직 코드 읽기입니다.
