# 2026-10-24-01: FC DQ4 실험 환경과 첫 RAM

FC DQ4 를 분석할 도구를 툴킷에 `krpatch fc` 로 넣고(v0.5.0), 1장 시작 장면의 세이브스테이트를 만들어 주인공 좌표·맵 번호 RAM 과 뱅크 전환 루틴을 찾았습니다. 결과는 [dq4-ram-format.md](../../dq4-ram-format.md) 에 있습니다.

## 1. 툴킷에 FC 도구 넣기

SFC 용 Lua 는 메모리 타입이 `snesMemory` 라 그대로 못 씁니다. FC 용으로 [kr-patch-toolkit](https://github.com/perfectacle/kr-patch-toolkit) 에 iNES 헤더 읽기(`fc info`), 6502 디스어셈블러(`fc dis`), 커버리지 리스팅(`fc listing`), MesenCE Lua(`boot`, `seq`, `mkstate`, 프로브 `cover`·`reads`·`writes`·`trace`·`watch`)를 넣었습니다. 프로브에 `DRIVER=$LIBDIR/seq.lua` 를 주면 세이브스테이트에서 시작하므로, dq5 트랙의 `seqlib.sh` 처럼 폴더를 따로 만들 필요가 없습니다.

FC 롬은 매퍼가 같은 뱅크를 다른 주소에 둘 수 있어서, 주소를 PRG ROM 오프셋과 CPU 주소 두 가지로 적습니다. 먼저 MesenCE 가 그 둘을 어떻게 넘기는지 확인했습니다.

```
exec FFD8 -> convertAddress: memType=nesPrgRom address=0x3FFD8
write 0502=4C statepc=C06C lastexec=C069
```

- PRG ROM 메모리 타입에 건 콜백도 인자는 CPU 주소입니다. 오프셋은 `emu.convertAddress` 로 구합니다.
- 쓰기 콜백 때의 `cpu.pc` 는 다음 명령을 가리킵니다. 쓴 명령은 직전 실행 콜백의 주소로 잡습니다.

## 2. 부팅에서 1장 시작까지

전원을 켜고 A 를 40프레임마다 누르면 오프닝 크레디트 뒤 「ぼうけんのしょをつくる」와 이름 입력 화면이 나옵니다. 그런데 같은 입력을 조금만 바꿔도 장면이 수백 프레임씩 밀렸습니다(A 를 크레디트 중에 누르면 크레디트가 빨리 끝남). 그래서 장면마다 세이브스테이트를 끊어 이어 갔습니다.

1. 이름 입력 화면(750프레임)
2. 커서를 아래 5칸, 오른쪽 9칸 옮겨 「おわり」
3. A 34번으로 왕의 대사를 넘기고 B 로 명령 창 닫기 → 왕좌의 방에서 라이안을 움직일 수 있음

이 과정을 [tools/dq4state.sh](../../../tools/dq4state.sh) 로 만들었습니다. 롬만 있으면 `work/state/dq4-ch1-throne.mss` 와 `dq4-ch1-courtyard.mss` 를 다시 만들고, 마지막 좌표·맵 번호를 찍어 같은 장면인지 보여 줍니다.

```
throne: end x=10 y=15 map=0D
courtyard: end x=12 y=0A map=0A
```

## 3. 좌표

세이브스테이트에서 아래·오른쪽으로 16, 32프레임씩 걸은 RAM 을 비교해, 한 방향으로만 움직이는 바이트를 골랐습니다. 프레임마다 값을 찍어 보니 한 칸에 16프레임이고, `$0044`/`$0045` 가 걸음을 시작할 때, `$00EC`/`$00ED` 가 8프레임 늦게 바뀌었습니다.

```
f00032 x=10 y=16 ... ey=0E
f00040 x=10 y=16 ... ey=0F
f00128 x=0F y=1A
```

## 4. 맵 번호

아래로 곧장 걸으면 병사에 막혔고, 한 칸 왼쪽으로 비켜 내려가니 464프레임에 좌표가 (0F,24) 에서 (12,0A) 로 튀며 성 밖으로 나왔습니다. 나가기 전 다섯 덤프에서는 같고 나간 뒤 달라진 바이트 중 `$0028` 과 `$0550` 이 둘 다 `0D`→`0A` 였습니다.

성 밖에서 위로 걸으면 막혔습니다. 「とびら」 명령은 「ここには とびらが ない」였고, 열린 문은 한 칸 오른쪽이었습니다. 문 아래 칸에서 위로 걸어 들어가니 왕좌의 방 (10,23) 에 도착하며 두 바이트가 `0D` 로 돌아왔습니다.

쓰기 프로브로 전환 때 두 값을 쓰는 곳을 잡았습니다.

```
0550-0550 pc=B708 prg=23708 first=472 n=1 addr=0550 val=0A
0028-0028 pc=E94E prg=3E94E first=472 n=1 addr=0028 val=0A
```

`$E94E` 바로 앞은 `BRK` 와 데이터 두 바이트(`00 05 87`)이고, `$B708` 앞은 `LDA #$17` 후 `JSR $C3EA` 입니다. DQ4 가 `BRK` 로 다른 뱅크 루틴을 부르고 `$C3EA` 로 다른 뱅크 바이트를 읽는 것으로 보이지만 아직 코드 읽기만 했습니다.

## 5. 출구 표

도착 좌표를 쓰는 `1B:$8050` 은 `$05A3,X`~`$05A5,X` 를 읽습니다. 두 맵의 `$05A0` 부근을 7바이트씩 끊어 보니, 나간 칸·도착 칸이 걸어서 본 것과 맞았습니다.

```
왕좌의 방  0F 24 .. 00 12 0A 82 | 10 24 .. 00 13 0A 82
성 밖      12 0A .. 01 0F 23 80 | 13 0A .. 01 10 23 80
```

(0F,24) 에서 나가 (12,0A) 에, (13,0A) 에서 들어가 (10,23) 에 도착한 것과 같습니다.

## 6. 뱅크 전환

같은 쓰기 프로브에 `8000-FFFF` 를 주면 매퍼 레지스터 쓰기가 보입니다. 고정 영역 `$FFAC` 부터 `STA $FFFF` 다섯 번(PRG 뱅크), 이어서 `STA $BFFF` 다섯 번(CHR 0 레지스터, 이 보드에서는 256KB 절반 선택)이 매 프레임 돌았습니다. 커버리지에서도 같은 고정 영역 코드가 PRG `3Cxxx` 와 `7Cxxx` 양쪽에서 실행됐습니다. 두 절반의 끝 뱅크(`0F`, `1F`)를 비교하니 뱅크 전환 루틴과 벡터는 같고 16KB 중 6548바이트는 달랐습니다.

## 틀렸던 것들

- ROM 읽기 프로브 첫 판은 BMI 대기 루프 하나가 4백만 번 「읽기」로 잡혔습니다. 6502 는 1바이트 명령 다음 바이트, 분기 목적지(페이지를 넘으면 엉뚱한 주소까지), 복귀 주소, 인터럽트가 걸릴 때 다음 명령을 더미로 읽고 벡터도 읽습니다. 메모리 피연산자가 있는 명령의 읽기만 세게 고친 뒤에는 `LDA $84F5,X` 같은 표 읽기만 남았습니다.
- PRG ROM 에 건 콜백이 오프셋을 넘긴다고 보고 첫 커버리지를 모았더니 오프셋이 `0800A` 처럼 CPU 주소와 같았습니다.
- 성 밖에서 위로 막힌 것을 닫힌 문으로 봤지만, 서 있던 칸이 문 옆이었습니다.

## 남은 것

- 출구 표 +2, +3, +6 의 뜻, 목적지 맵 번호를 정하는 곳, 표를 채우는 롬 데이터.
- `$0028` 이 필드와 다른 마을에서도 맵 번호인지.
- `BRK` 뱅크 호출과 `$C3EA` 의 인자 형식, 뱅크별 내용 표.
