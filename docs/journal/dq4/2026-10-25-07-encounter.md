# 2026-10-25-07: 적 조우 표

걸을 때 전투가 날지와 어떤 무리가 나올지를 정하는 표를 풀었습니다. 필드 구역 지도 3개, 구역 레코드 101개, 무게 줄 8개, 고정 편성 16개, 던전 목록 2개, 특수 전투 34개입니다. 결과는 [dq4-encounter-format.md](../../dq4-encounter-format.md) 에, 디코더는 `tools/dq4encounter.py`, 실험 스크립트는 `tools/lua/fc/enc.lua` 에 있습니다.

## 1. 무리를 쓰는 곳

필드 세이브스테이트에서 `tools/dq4state.sh` 의 battle 단계 입력(왼쪽, 위아래 오가기)을 재생하며 `probe/writes.lua` 로 `$6E40-6E5F` 쓰기를 잡았습니다.

```
6E40-6E5F pc=A0FB prg=620FB first=37 n=22 addr=6E45 val=FF     (걸음마다 비움)
6E40-6E5F pc=9EBB prg=61EBB first=373 n=1 addr=6E45 val=00     (スライム)
6E40-6E5F pc=9EC1 prg=61EC1 first=373 n=1 addr=6E46 val=07     (おおみみず)
6E40-6E5F pc=9EC6 prg=61EC6 first=373 n=1 addr=6E49 val=01
```

`$6E45`~`$6E48` 이 무리 4개의 몬스터 ID, `$6E49`~`$6E4C` 가 마릿수입니다. 쓰는 코드는 뱅크 18 입니다.

## 2. 걸음마다 도는 루틴

전투 직전 80프레임의 실행 커버리지(`probe/cover.lua`)로 `krpatch fc listing --range 60000-63FFF` 를 만들고, 실행 안 된 갈래는 `krpatch fc dis` 로 메웠습니다. 진입점은 뱅크 18 함수 00(`$9BE6`)입니다.

- `$9C64`: `($43 & F0) | ($42 >> 4)` 로 256바이트 지도를 읽어 구역 번호. 지도 포인터는 `$615A`(장 − 1)로 고름.
- `$9C88`: 구역 × 16 + `$92AA` 의 레코드. 바이트 0 bit7-5 가 기본 조우율.
- `$9CCC`·`$9CB2`: 기본 조우율 × (`$6E42` 에 따른 2/4/8 또는 16) × 지형 배수(`$7140` 으로 표를 찾음) >> 8.
- `$9D06`: 난수 < 조우율 이면 전투.
- `$9D9C`~`$9E09`: 칸 14개에서 무게로 하나를 고름. `$9E0D` 가 칸 번호(0~4, 5, 6~10, 11, 12~13)로 무리 만드는 법을 나눔.

`$C827` 은 16비트 × 8비트 곱셈, `10:$A1F6`(`BRK 17 0F`)은 rand(N) = N × 난수 >> 8 입니다.

## 3. 표

레지스터에 들어가는 포인터는 `$A237`~`$A246` 에 모여 있었습니다. 구역 레코드(`$92AA`)를 몬스터 이름으로 찍어 보니 구역 00~03 은 바다 몬스터, 04~06 은 1장 성 주변(スライム, おおみみず …), 34~3F 는 끝판 몬스터였습니다. 표 경계는 모두 다음 표 시작과 맞았습니다.

```
같음 구역 레코드 끝 = 고정 편성 시작: 98FA / 98FA
같음 고정 편성 끝 = 뱅크 18 함수 02: 995A / 995A
같음 특수 전투 끝 = 선제 표 $A45C: A45C / A45C
같음 3장 지도 128바이트 끝 = 던전 목록: A73D / A73D
같음 장 1~4 던전 목록 끝(FF 다음) = 5장 목록: A779 / A779
그룹 크기 $A474 와 맵 표(17:$B181) 그룹별 맵 수: 73/73 같음
```

던전 목록 레코드 길이는 `$A474[그룹]` 이고, 이 값이 맵 표의 그룹별 맵 수와 같았습니다. 맵 안에서는 지형 배수 대신 `0F` 를 씁니다.

`$62ED` 를 걸으며 보니 걸음마다 1 늘었고, `0F:$CDE6` 이 `CC` 에서 0 으로 되돌리며 다른 카운터를 늘립니다. 조우 루틴은 이 값이 78 이상이면 다른 지형 배수와 다른 칸 마스크를 씁니다. 이벤트 스크립트가 이 값에 `8C`·`00` 을 쓰는 곳이 있어 낮·밤 시계로 보았습니다.

특수 전투 루틴은 뱅크 18 함수 01(`$A1AD`)이고 8바이트 레코드 34개를 A 번호로 찾습니다. `LDA #번호 ; BRK 01 8F` 로 롬을 찾으니 뱅크 1C·1D·1E 이벤트 스크립트에 21군데가 있었습니다(05 ピサロのてさき, 03 キングレオ …).

## 4. 전투를 여러 번 일으키기

`tools/lua/fc/enc.lua` 는 시행마다 세이브스테이트를 다시 불러 기다리는 프레임 수를 바꾼 뒤(난수가 달라짐) 필드 좌표 `$42`/`$43` 을 한 번 옮기고 위아래로 걷습니다. 조우 판정(`$9D09`)마다 조우율과 난수를, 무리가 정해지면(`$A11A`) 구역·칸·무리를 적습니다.

```sh
STATE=$PWD/work/state/dq4-ch1-field.mss TRIALS=20 WAITSTEP=5 POS=90,15 SHOT_DIR=$PWD/work/enc-z05 \
  "$MESENCE" --testrunner --nes.ramPowerOnState=AllZeros $PWD/rom/dq4.nes $PWD/tools/lua/fc/enc.lua
uv run python tools/dq4encounter.py rom/dq4.nes check work/enc-z05/enc.txt
```

자리는 `dq4field.py` 로 위아래 7칸이 타일 2·4 인 곳을 구역마다 골랐습니다. 구역 04(두 곳, 그리고 `POKE1=62ED=90` 으로 밤)·05·06·09·0C·12·14 에서 240번 싸웠습니다.

```
구역 05: 나온 몬스터 スライム, はさみくわがた, おおみみず, エアラット, きりかぶおばけ
work/enc-z05/enc.txt: 판정 304번(난수 < 조우율 20번), 전투 20번, 다름 0
구역 0C: 나온 몬스터 ホイミスライム, かまいたち, プテラノドン, さまようよろい, がいこつけんし, さそりアーマー, メタルスライム
work/enc-z0C/enc.txt: 판정 315번(난수 < 조우율 20번), 전투 20번, 다름 0
```

조우 판정 3975번 모두 조우율이 식과 같았고, 전투 240번 모두 지도의 구역, 마스크 안의 칸, 그 칸의 몬스터와 마릿수 범위 안이었습니다. 구역 04 에서 낮 50번은 칸 4·10 이 한 번도 안 나왔고, 밤 30번은 칸 0 이 안 나오고 칸 4·10 이 8번 나왔습니다. 구역 0C 의 칸 12 는 고정 편성 09(さまようよろい + ホイミスライム)였습니다.

## 틀렸던 것들

- 처음에는 `$6E42` 를 판정(`$9D09`) 때 읽어 조우율 식과 10번 어긋났습니다. `$9CCC` 가 배수를 고른 뒤 바로 1 을 더하므로, 고르기 전(`$9CCC`)에 읽어야 합니다.
- 그룹 크기 표를 `dq4map.maps` 와 비교하니 그룹 48 하나가 달랐습니다. `maps` 는 다음 그룹 포인터로 길이를 재서 마지막 그룹 48(맵 10개)을 빼먹습니다. 그룹 48 은 `FF` 앞까지 레코드를 세면 10 으로 같습니다.
- `TRIALS=60` 으로 한 번에 돌리면 `enc.txt` 가 나오지 않았습니다. 30번씩 나눠 돌립니다.

## 남은 것

- 던전 안에서 실제 전투로 던전 목록 확인, 그룹 `3A`·`3F` 의 특수 처리.
- 배일 때 구역(`$9C81` 이 지도 값이 아니라 `$07` 을 읽음), 5장 지도 bit7-6.
- 특수 전투를 실제로 일으켜 보기, 다른 꼴로 부르는 번호(00·01·07~0B·1C~21).
- `$6E44`(선제·기습), 구역 레코드 바이트 1, 성수(`$6E41`)·`$6BEB` 의 실측.
- `dq4map.maps` 가 그룹 48(맵 10개)을 빼먹는 것.
