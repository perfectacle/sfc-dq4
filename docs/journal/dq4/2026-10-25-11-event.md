# 2026-10-25-11: 저장 데이터·이벤트 플래그·장 시작

배터리 SRAM 의 모험의 서 구조와 체크섬, 인물 레코드, 이벤트 플래그 명령, 1~5장을 시작할 때 읽는 표를 풀었습니다. 결과는 [dq4-save-format.md](../../dq4-save-format.md) 에 있고, 덤프를 푸는 도구는 `tools/dq4event.py` 입니다. 장 시작을 실측하다가 제품판에 남은 디버그 「シナリオ」 장 고르기 창도 찾았습니다.

## 1. 저장할 때 쓰이는 바이트

1장 성 앞마당 세이브스테이트에서 왼쪽 위 교회까지 걸어가 신부에게 기도하고 「きろく」 를 고르는 동안 `probe/writes.lua` 로 `$6000`~`$7FFF` 쓰기를 모았습니다. 걸음 입력은 좌표를 목표로 걷는 `tools/lua/fc/eventwalk.lua` 로 줬습니다.

저장 직후 SRAM 을 보면 `$62EF` 부터 `$2F0` 바이트가 1번 칸이고, 앞 두 바이트 뒤가 `$6001`~`$62EE` 와 바이트까지 같았습니다. 2·3번 칸 자리(`$65DF`, `$68CF`)는 `4B` 로 차 있었습니다. 칸 앞 두 바이트를 만드는 곳은 `12:$ACA2` 로, `$12`/`$13` 에 `3A` 를 넣고 바이트마다 `1F:$C8AD` 를 부릅니다. `$C8AD` 는 위 비트부터 밀며 넘친 비트가 서면 아래 바이트에 `21`, 위 바이트에 `10` 을 XOR 하는 CRC-16(다항식 `1021`)입니다. 파이썬으로 옮겨 계산하니 적힌 값과 같았습니다.

```
slot 0x62ef 적힌 5AD0 계산 5AD0
slot==work True
```

체크섬을 게임이 정말 검사하는지 보려고, 저장한 세이브스테이트를 불러 3프레임째에 칸의 `$6290`(귀환 자리 번호) 하나만 바꾸고 리셋해 불러왔습니다. CRC 를 그대로 두면 「ぼうけんのしょ　1ばんは　きえてしまいました。」 가 나오고, 계산한 CRC(`C9C7`)를 같이 쓰면 정상으로 불러와 `0E/00` (0C,19)에서 시작했습니다. 이 자리는 귀환 자리 표 `1E:$A76D` 의 `0B` 번 레코드와 같습니다.

## 2. 인물 레코드

왕좌의 방에서 상태 화면을 연 채로 ライアン 레코드(`$60B5`)의 바이트를 바꿔 화면 숫자를 읽었습니다. `+01` `1B 01` 이 HP 283, `+03` `2A 01` 이 MP 298, `+0C` 최대 HP, `+0E` `21 03` 이 최대 MP 801, `+10` `45 23 01` 이 경험치 74565 로 나왔습니다. 소지품 `82 A6` 은 화면의 「E どうのつるぎ」·「E かわのよろい」 라 bit7 이 장비 표시입니다.

ライアン 의 레코드 번호가 6 인 것이 직업 이름 목록의 せんし 순번과 같아서, 장 시작 루틴을 읽어 보니 번호 0~7 을 그대로 인물 번호로 씁니다.

## 3. 장 시작 루틴과 표

`$615A` 를 절대 주소로 가리키는 명령 96군데 중 이어하기 뒤 `1E:$A36B` 가 값을 쓰고 바로 `BRK 12` 함수 `17`(`12:$8EAE`)을 부르는 것을 따라갔습니다. 이 루틴은 인물마다 처음 나오는 장 표(`12:$9136`)를 보고 그 장의 인물만 HP 표, 비트로 묶은 능력치 표 6개, 소지품 표로 초기화하고, 장마다 선두·골드·5바이트를 씁니다. 능력치는 표 바이트의 bit7 다섯 개를 모은 5비트 값이라 표 자체는 다른 용도(레벨 업 표로 보임)와 같이 쓰는 것 같습니다.

앞서 일한 방식은 SRAM 의 `$615A` 를 바꾸고 `$6291` 을 0 으로 둔 채 교회에서 저장한 뒤 리셋해 불러오는 것이었습니다. `$6291` bit7 이 꺼져 있으면 `1E:$A34C` 가 장 시작으로 가기 때문입니다. 이렇게 1~5장을 모두 시작해 시작 자리를 쓰는 `1E:$A595` 를 추적했습니다.

```
ch0 A595 63=02 64=01 44=10 45=15 615A=00
ch1 A595 63=01 64=01 44=09 45=08 615A=01
ch2 A595 63=16 64=01 44=1B 45=05 615A=02
ch3 A595 63=15 64=03 44=0C 45=0F 615A=03
ch4 A595 63=14 64=00 44=05 45=11 615A=04
```

`1E:$A599` 의 4바이트 × 5 표와 같습니다.

## 4. 디버그 「シナリオ」 창

`1E:$A34C` 뒤를 읽다가 장 시작 직전에 `LDA $C000; AND #$08; BNE` 가 있는 것을 봤습니다. `$C000` 은 고정 뱅크의 롬 바이트라 제품판에서는 늘 `FF` 이고, 0 이면 `1F:$F102` 를 부릅니다. `$F102` 는 창을 그리고 패드 `$14` 를 읽어 `$615A` 를 늘리고 줄이는 고르기 루프입니다.

테스트러너 안에서 PRG ROM 메모리 `3C000`·`7C000` 을 `F7` 로 바꾸는 `PRGPOKE` 를 `eventwalk.lua` 에 넣고 같은 저장·불러오기를 하니, 불러오기 직후 「シナリオ　1 2 3 4 5」 창이 떴습니다. 오른쪽을 누르면 커서가 옮겨 가고 A 로 그 장이 시작됩니다. 이 방법으로 1~5장을 다시 시작해 `dq4event.py chars --compare` 로 대조했습니다.

```
== 2 end 6424 at 09,08 map 01/01
장 2($615A=01)  골드 100  ...  귀환 자리 10  $6291=80
일행 $616A: 87 00 00 00
      비교: 같음   (クリフト)
      비교: 같음   (ブライ)
      비교: 같음   (アリーナ)
```

다섯 장에서 초기화되는 8명 모두 레코드가 계산과 같았습니다. B 를 누르면 `$615A`=6 이 돌아오는데, 이때는 8명 전원이 일행·마차에 들어가고 주인공 HP·MP 가 `FFFF` 인 채 5장 자리에서 시작했습니다. 시험용 모드로 보입니다.

## 5. 이벤트 플래그

`docs/dq4-bank-format.md` 에서 「코드 읽기」로 남아 있던 BRK 특수 형식 `CB`·`DB`·`EB` 를 2장 시작에서 실제로 잡았습니다. `tools/lua/fc/eventflags.lua` 는 `$627B`~`$62EE` 읽기·쓰기를 기록하고, 고정 뱅크의 플래그 처리기(`$C4BC`~`$C4EF`)에서 온 접근이면 그 BRK 주소를 같이 적습니다.

```
1403 w 6291 00>80 pc=C4D5 bank=1E brk=A354    00 16 CB 80
1827 w 6288 00>40 pc=C4D5 bank=1E brk=A399    00 0D CB 40
1895 w 6288 40>00 pc=C4EC bank=1E brk=A41B    00 0D DB BF
1895 w 628B FF>00 pc=C4EC bank=1E brk=A3D8    00 10 DB 00
```

주소 = `$627B` + 둘째 바이트, `CB` 는 넷째 바이트를 OR, `DB` 는 AND 입니다. `EB` 는 `16:$87F1` 의 `00 16 EB 10` 이 매 프레임 `$C4C1` 을 지나는 것을 `probe/trace.lua` 로 봤습니다. 장 시작이 켜는 `$6291` bit7 은 장 끝 루틴의 `1A:$B92C` `00 16 DB 7F` 가 끕니다.

## 틀렸던 것들

- 처음에는 1장 초반 대화(왕, 병사, 여관)에서 플래그가 바뀌기를 기대했지만 `$627D` 를 매 걸음 같은 값으로 쓰는 것 말고는 쓰기가 없었습니다. 말을 건 인물들이 플래그를 켜지 않는 인물이었을 뿐이고, 대화 쪽 플래그는 대화 스크립트가 다룹니다([dq4-script-format.md](../../dq4-script-format.md), 성 앞 노인이 `$6289` 를 켬). 장 시작 처리가 BRK 플래그 명령을 여러 번 쓰므로 거기서 잡았습니다.
- 칸 바이트를 세이브스테이트를 불러온 0프레임째에 바꾸면 반영되지 않았습니다. 불러오기가 그 뒤에 일어나기 때문이라 3프레임째로 옮겼습니다.
- 디버그 창 실험에서 `seq 0` 이 macOS 에서 `1 0` 을 내 오른쪽을 두 번 누른 탓에 1장 대신 3장이 시작됐습니다. 반복 횟수는 `while` 로 셌습니다.

## 남은 것

- 인물 레코드 `+0B` 의 뜻, `+1B`~`+1D` 가 주문 비트인지.
- `$6165`~`$6169`, `$618E`, `$6172`~`$6177` 의 뜻과 2장에서 일행이 들어오는 이벤트.
- 이벤트 플래그 번호마다의 뜻. 대화 스크립트의 플래그 명령과의 대응.
- 귀환 자리 표의 나머지 20개, 장 끝 루틴을 실제 장면에서 확인하는 것.
