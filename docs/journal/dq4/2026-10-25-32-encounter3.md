# 2026-10-25-32: 적 조우의 남은 것 2

[앞 일지](2026-10-25-21-encounter2.md)가 남긴 조우 문제를 마저 풀었습니다. 그룹 3F 의 특수 처리, 정상 경로로 탄 배의 구역, 3장 일행이 필드 아래쪽에 갈 수 있는지, 특수 전투 00·01·1C~21 을 부르는 곳, 성수류 아이템·주문, `$6E44` 의 bit6, 구역 56 의 기습 비율, `1E:$A5AD` 가 도는 때입니다. 결과는 [dq4-encounter-format.md](../../dq4-encounter-format.md) 에 있습니다.

## 1. 실험 스크립트 넓히기

`tools/lua/fc/enc.lua` 에 몇 가지를 더했습니다.

- `PRE="right:40"`: 걷기 전에 한 방향을 먼저 누름(옆 칸의 배에 오르기).
- `ROUTE="A9,46;..."`: 필드 좌표를 차례로 맞추며 걷고, 막히면 「pth 막힘」을 적음. 처음에 이름을 `PATH` 로 했다가 셸의 `PATH` 와 겹쳐 바꿨습니다.
- `POKE`(프레임마다 쓰기, 독늪에서 HP 유지), `PRG`(메모리상 PRG 바꾸기, 디버그 스위치 `$C000`).
- 기록 줄: `$07` 을 마지막으로 쓴 곳(`shp`), 특수 전투 진입과 복귀 주소(`fn01`), 인물 블록 명령 21(`s21`). `stp` 줄 끝에 `$42 $43 $0515` 를 붙였습니다.

## 2. 그룹 3F

앞 일지는 3F/00 에 워프하자마자 필드로 걸어 나갔습니다. 이번에는 5장 시작 세이브스테이트(명령 창을 B 로 닫은 것)에서 블록 0A 바닥인 (10,02)로 들어가 무작위로 걸었습니다. 165걸음 동안 판정은 0번이었습니다.

`$9F7F` 의 `BRK 62 23 40` 은 뱅크 10 의 일행 처리기 `62`(`10:$9862`)로, 조건 비트 `40` 인 걷는 일행 수를 돌려줍니다. 그 수가 1 이고 `BRK 63 63 40`(A = 0) 이 주인공을 찾아야 이어지는데, 기록하니 주인공 혼자일 때 `$9F8F` 까지 갔습니다.

```
26 9F83 A=01 ... 6E0C=09 616A=80 616B=00     일행 1명
26 9F8D A=00 P=07                            주인공을 찾음(C=1)
26 9F83 A=02 ... 616B=86                     둘이면 여기서 빠짐
```

그런데도 판정이 없는 까닭은 던전 목록이었습니다. 1~4장·5장 두 목록 모두 그룹 `3F` 가 없습니다. 특수 처리는 지나도 쓸모가 없는 셈입니다. 블록 속성 `B0` 이 내는 메시지 `04C2` 는 「3にん　いなければ とても　とびらを　こわせそうにない。」 였습니다.

## 3. 정상 경로로 탄 배

배를 타는 코드를 거꾸로 찾았습니다. `$0515` 를 쓰는 곳 가운데 `0F:$CE7B` 가 걸음 끝에 `$0527` 을 옮기고, `$0527` = 1 은 `0F:$CFD6` 이 씁니다. 조건은 「걸으려는 칸의 속성이 `83` 이고 그 칸이 (`$6195`, `$6196`)」 입니다. 그래서 배 자리만 해안 옆 바다 칸으로 쓰고 걸어 들어가게 했습니다. `$0515` 는 게임이 1 로 바꿨습니다.

`$9C81` 에서 `$07` 을 마지막으로 쓴 곳을 함께 적었습니다.

```
1631 00 61C88     18:$9C88 = 앞 걸음의 구역
  86 02 40189     10:$8189 = 효과 처리기가 영 페이지를 되돌림
  32 0C 40189
```

`$07` 은 앞 걸음에 이 루틴이 둔 구역입니다. 배에 오른 첫 걸음에는 효과 처리기가 되돌린 값이 남는데, 이것도 배에 타기 직전 육지 걸음의 구역(02, 0C)이었습니다. 필드 구역은 6비트라 bit7-6 은 늘 0 이고, 배 위 전투 20번이 모두 구역 00 이었습니다. 지도 값을 읽으려던 코드가 `$07` 을 잘못 읽는 것으로 보입니다.

## 4. 3장 일행과 필드 아래쪽

필드 0 의 통행 속성으로 칸을 이어 봤습니다. 입구 칸까지 지나게 하면 Y 90 까지 닿지만, 입구 칸을 빼면 エンドール 쪽에서는 Y 5D 가 끝이었습니다. 남쪽으로 가는 길목은 그룹 `21`(입구 (B2,4D)) 하나였고, 이곳은 사막 여관입니다. 대사 「この　さばくも　ばしゃなら　こえられると　おもったのに」 가 그대로 조건이었습니다.

`$63` = `21` 을 비교하는 곳은 `1E:$9219` 하나였습니다. `$6292` bit0 이 꺼져 있으면 Y = 0F 에서 블록 02 의 속성을 `10` 으로 바꿉니다. 이 비트는 마차 주인의 대화 `097` 이 켭니다.

```
$6292 = 0: 21/00 (00,0A) → (00,0E) 에서 멈춤
$6292 = 1: 맵을 나가 필드 (B2,59)
필드 (B2,4E) → ROUTE 로 86걸음 → (AD,84)
```

3장 시작 세이브스테이트의 `$6292` 는 `00` 입니다. 3장 지도가 128바이트에서 끝나는 것은 3장 일행이 그 아래에 갈 수 없기 때문입니다.

처음 길 찾기는 입구 칸을 지나는 길을 골라 (B2,4D) 에서 21 에 들어가 버렸습니다. 이것으로 그 칸이 유일한 길목이라는 것을 알았습니다.

## 5. 특수 전투를 부르는 곳

앞 일지는 `0F:$DA8A` 를 스크립트 명령으로만 적었습니다. 이 명령은 인물 블록 해석기 `0F:$D884` 의 명령 표 `0F:$DEF5` 21번입니다. 블록을 바이트 모양으로 훑으니 `21 01` 같은 후보가 나왔지만, 모두 길이 0 인 블록을 지나 다음 레코드 머리를 읽은 것이었습니다. 처리기마다 블록 주소를 몇 바이트 넘기는지 세어 길이 표를 만들었습니다. 블록 길이 안에서만 풀고 점프 대상은 끝 명령까지 따라가니 블록 1587개, 3000바이트에서 모르는 명령이 0, 명령 21 도 0번이었습니다.

그래서 다른 길을 찾았습니다.

- 상자: 내용 `FE` 처리기 `1E:$B868` 이 `LDA #00 ; BEQ` 로 `BRK 01 8F` 에 갑니다. `LDA #번호` 바로 뒤가 아니라서 앞 검색에서 빠졌습니다. `03/02` 상자 (0F,07)을 열자 `$A1AD` 에 A = 00 이 들어왔습니다.
- 1C~21: `1C:$BF74` 이벤트 표의 20번(`1C:$B968`)이 `TYA ; BRK 01 8F` 였습니다. 이벤트 20 을 부르는 곳은 `15:$B159` 하나이고, 그룹 `03`(デスパレス)에서 말을 걸 때 `08:$B725` 가 인물 겉모습을 `08:$B756` 표에서 찾아 Y 를 정합니다.

```
B74D A=2A → A1AD A=1C     (19,0A) ライノソルジャー
B74D A=37 → A1AD A=1E     (09,0F)
B74D A=0D → A1AD A=1F     (17,05)
B74D A=35 → A1AD A=20     (20,04)
B74D A=34 → A1AD A=21     (09,1A)
```

- 앞 일지에서 45/01 을 걷다 난 どぐうせんし 는 06 이었습니다. 독늪에서 죽지 않게 HP 를 프레임마다 쓰고, 디버그 스위치 bit6 으로 보통 조우를 끈 채 걸으니 8번 중 3번 특수 전투가 났고 복귀 주소가 `1D:$9C87`(`LDA #06 ; BRK 01 8F` 뒤)였습니다.

01 을 부르는 곳은 끝내 찾지 못했습니다.

## 6. 성수와 トヘロス, においぶくろ

뱅크 12 의 세 곳은 아이템·주문 처리기 표에서 찾았습니다. 아이템 목록 `12:$B6BB` 에서 `55` せいすい 가 `$B1F5`, `5E` においぶくろ 가 `$B4DB`, 주문 목록 `12:$AA14` 에서 `3B` トヘロス 가 `$A6EF` 였습니다. 실제로 써 봤습니다.

- せいすい·においぶくろ: ライアン 소지품 첫 칸에 넣고 どうぐ → つかう. 「ライアンは　せいすいを　ふりまいた！」 뒤 `$6E41` = `7F`, においぶくろ 는 「ふしぎな　においが　たちこめる！」 뒤 `$6BEB` = `32`.
- トヘロス: ライアン 은 「じゅもんが　つかえない」 라, 일행 선두를 주인공 레코드로 바꾸고 주문 비트를 모두 켰습니다. 필드 주문 목록 셋째의 トヘロス 를 고르니 `$6E41` = `FF`.

끝날 때 메시지는 bit7 이 고릅니다. `$6E41` = `81` 이면 「トヘロスのこうかが　なくなった。」, `01` 이면 「せいすいのこうかが　なくなった。」 였습니다.

## 7. `$6E44` 와 구역 56

1장 첫 전투 세이브스테이트에서 `$6E44` 를 프레임마다 쓰고 にげる 를 골랐습니다. 기다림을 넷으로 바꿔 난수를 달리했습니다.

```
00: 도망 2번, 실패 2번
80: 00 과 같음
40: 실패 4번(「しかし　まわりこまれてしまった！」)
```

bit6 은 도망칠 수 없음입니다. 특수 전투가 늘 `C0` 인 까닭입니다. bit7 은 이긴 전투의 메시지·경험치·골드가 같아 뜻을 찾지 못했습니다.

구역 56 은 앞 일지가 01/00 에서 걷지 못했던 곳입니다. 같은 구역의 `01/01` (0A,0C)로 들어가 HP 를 유지하며 걸으니 전투 113번이 났고, 기습·선제를 적은 107번이 91·2·14 로 기대(90.7·3.3·13.0)와 맞았습니다.

## 8. `1E:$A5AD`

이 함수를 부르는 곳은 `1E:$A3C6` 하나이고, 그 함수는 `1E` 함수 22 입니다. 함수 22 는 리셋 뒤 시작 루틴 `0F:$C968` 에서 본 루프 직전에 불립니다. 워프로 맵에 들어갈 때, 필드로 나갈 때, 전투를 이길 때는 돌지 않았고, 45/01 독늪에서 전멸해 교회에서 깨어날 때 돌았습니다.

## 틀렸던 것들

- 3F/00 착지 문제는 자리 문제가 아니었습니다. 맵 안에서 걸어도 그룹 3F 는 목록에 없어 판정이 나지 않습니다.
- 앞 형식 문서는 배 위 구역이 늘 00 인 것을 1100여 걸음의 관찰로만 적었습니다. `$07` 을 쓰는 곳을 보니 구조적으로 00 입니다.
- `bosses` 가 투기장 표를 여덟 바이트까지 읽어, 표 뒤의 코드 `20`(JSR)을 특수 전투 20 의 부르는 곳으로 찍었습니다. 표는 다섯 바이트입니다.
- 명령 21 을 바이트 모양으로 찾은 후보는 블록 길이를 넘어 다음 레코드를 읽은 것이었습니다.

## 남은 것
