# 2026-10-25-37: 몬스터 AI 네 갈래와 가중치, 남은 몬스터 바이트, 동료 작전 AI

앞 일지([2026-10-25-27](2026-10-25-27-stats2.md))에서 남긴 몬스터 AI 와 레코드의 모르는 바이트를 전투에서 쟀고, DQ4 의 핵심인 동료 AI(さくせん)의 입구와 구조를 찾았습니다. 몬스터가 행동을 고르는 가중치 표, AI 종류마다 지우는 칸, 바이트 13·14(HP 재생)·20 bit5-3(회심)·21(시작 상태)이 정해졌고, 동료 AI 는 작전 번호 `$615B`, 인물별 주문 칸, 저장되는 몬스터 학습 표 `$619B` 까지 나왔습니다. 결과는 [dq4-data-format.md](../../dq4-data-format.md#ai-종류) 에 있고, `tools/dq4data.py` 에 `ai` 를 더하고 `monsters` 출력을 넓혔습니다.

## 1. 실험 틀

앞 일지와 같은 1장 필드 세이브스테이트(クリフト 5레벨)에서 조우 비교를 메모리에서 `CLC; NOP` 으로 바꾸고, 전투 시작 `18:$A11A` 에서 무리를 スライム 8마리로 덮었습니다. 몬스터 레코드는 `statspoke.lua` 의 `ROMONCE` 로 메모리에서만 바꿉니다. HP·수비력을 1023 으로 올리면 전투가 끝나지 않아 한 번에 수백 턴을 모을 수 있습니다.

```sh
ROMONCE="61D09=18,EA;6004A=FF;6004C=FF;6004F=2B,2C,2D,30,31,32;60055=03;60057=03;6005A=05" \
PCPOKE="A11A@18:6E45=00,FF,FF,FF,08,00,00,00" AT=B165 LOG="0006,000A,0096" …  statsstack.lua
```

A 를 1000번 누르는 입력은 30초 남짓 걸렸고, 3000번으로 늘리면 테스트러너가 아무것도 남기지 않고 끝났습니다. 그래서 1000번짜리를 시작 대기 프레임만 바꿔 여러 번 돌려 합쳤습니다(입력이 같으면 결과도 같기 때문).

## 2. 행동 가중치

`$6D8C`·`$6DC2` 에 쓰는 곳을 `probe/writes.lua` 로 찾으니 전투 시작의 `18:$995E`·`$99AD`·`$99B3` 이었고, 그 위 `18:$9A21` 이 바이트 9·10 bit7 의 값 × 6 으로 `18:$9AA9` 의 표를 읽었습니다.

```
고르는 법 0: 2B 2B 2B 2A 2A 2A     1: 43 39 2F 25 1C 13     2: D1 1D 0A 04 02 01
```

칸에 메시지만 나오는 행동 여섯 개(`3C`~`43`)를 넣고 고른 칸 `$06` 을 세었습니다.

```
0: 124 154 151 122 137 128     (816번)
1: 224 193 169 123  77  62     (848번, 표대로면 223 190 156 123 93 63)
2: 747 107  36  16   7   7     (920번, 표대로면 754 105 36 14 7 4)
3: 144 144 144 144 144 144     (차례)
```

같은 행동을 여러 칸에 두면 `18:$9A72` 가 한 칸으로 합치고 가중치를 더한다는 것도 이때 보였습니다(ホイミ ×3 은 칸 0 하나가 됨).

## 3. AI 종류 네 갈래

`10:$AD06` 이 바이트 20 bit7-6 으로 `$AEB5`·`$AEF7`·`$AF4D`·`$B074` 로 나뉩니다. 넷 다 칸마다 「이 행동이 쓸모 있나」를 보고 쓸모없으면 `10:$B1CC` 가 그 칸의 가중치를 0 으로 지웁니다. ホイミ 셋 + 공격 셋으로 바이트 20 만 바꿔 보았습니다.

```
                      AI 0          AI 1          AI 2          AI 3
MP 0, 거의 안 깎임     ホイミ 149/288  ホイミ 0/264    0/510         0/517
MP 255, 깎임          ホイミ 134/264  16/256         5/483         6/474
```

AI 0 은 MP 가 없어도 반쯤 ホイミ 를 골랐고, AI 1~3 은 MP 가 모자라거나 아무도 다치지 않았으면 고르지 않았습니다. ホイミ 를 고른 27번에서 가장 약한 몬스터의 HP 는 88~99(최대 200)였고 100 이상에서는 0번이라, 평가 루틴 `10:$B9E9` 의 조건이 「최대 HP 의 절반 미만」입니다.

도망(번호 `47`)으로 바꿔 보니 AI 0 은 바로 도망쳤고 AI 1 은 176번 중 한 번도 도망치지 않았습니다. 도망 평가 `10:$BC09` 는 `$75` − `$7396` ≥ 5 를 봅니다. `$75` 에 쓰는 곳은 `10:$9961`(일행 레코드 +05 의 최댓값), `$7396` 은 `18:$A11D`(구역 레벨 `$6E01`)였습니다. ライアン·クリフト 레벨을 5 로 두면 차이 4 라 도망 0번, 9·10·50 이면 도망이 나왔습니다.

AI 0 이 지우는 목록 `10:$AE7A` 는 `$72E9` bit7 일 때만 씁니다. `$72E9` 에 `80` 을 쓰는 곳은 투기장 시합(`18:$ABB1`)이라, 몬스터끼리 싸울 때 도망·동료 부르기·되살리기를 막는 목록입니다. 몬스터 행동 결정 입구 `10:$ACAA` 에서 `$72E9`=`80` 을 넣으니 AI 0 도 도망치지 않았습니다.

## 4. 바이트 13·14: 턴마다 HP 재생

필드 번호 `21` 을 읽는 곳을 찾으니 `11:$AAFE`(`BRK 21 B3`) 하나였습니다. 값 × 2 로 `11:$AB31` 의 쌍을 찾아 `rand(폭) + 기본` 을 필드 `02` 에 더합니다. 처음에는 속도라고 짐작하고 행동 순서를 보았는데 속도 0 의 スライム 은 값 3 에서도 늘 마지막이었습니다. HP 를 기록하니 바로 보였습니다.

```
값 0: 727E=9D → 9D → 8F → 83          (그대로 깎임)
값 3: 727E=9D → C8, BB → C8, BD → …   (턴마다 91~109 회복, 최대 200)
```

값이 있는 몬스터 14종은 거의 보스입니다(エスターク 3, レッドドラゴン 2 등).

## 5. 바이트 20 bit5-3: 회심

필드 `24` 를 읽는 `11:$A645` 는 보통 공격 루틴 안의 `11:$A62E` 였습니다. 문턱 Y(`11:$A66E`)를 기록하니 공격하는 쪽이 일행일 때만 이 값을 썼습니다.

```
바이트 20 bit5-3 = 0: 일행 공격 Y=00, 몬스터 공격 Y=04
                 = 2: 일행 공격 Y=08, 몬스터 공격 Y=04
                 = 7: 일행 공격 Y=1C, 몬스터 공격 Y=04
```

곧 일행의 회심 확률은 맞는 몬스터마다 4 × 값 / 256 이고, 몬스터의 통한의 일격은 늘 4/256 입니다. 값 7 에서 일행 공격 44번 중 6번이 회심 갈래로 갔습니다.

## 6. 바이트 21: 시작 상태

필드 `26`·`27` 은 `12:$8540` 이 읽습니다. スライム 의 바이트 21 을 `07`·`47`·`87`(확률 칸 0 = 반드시)로 두고 전투를 여니 「スライムが あらわれた。」 뒤 메시지가 마리마다 `001F`(ねむっている)·`0020`(しびれて うごけない)·`0021`(こんらんしている)이었습니다. 확률 표 `12:$85BD` 는 `FF 7F 1F 0F 07 03 00` 입니다. `dq4data.py monsters` 로 보면 エスターク 가 「시작 잠 256/256」이라 처음부터 잠든 채로 나오는 것과 맞습니다.

## 7. 동료 AI 의 입구

1장 세이브스테이트에서는 ライアン·クリフト 모두 명령 창이 떴습니다. `$615A` 만 4(5장)로 바꾸니 두 사람 다 창 없이 행동했고, `$7325` 에 쓰는 곳이 `13:$9119` 로 바뀌었습니다. 뱅크 `13` 함수 `00`(`13:$8038`)이 입구입니다.

```
13:8088  LDA $615B / STA $6E80      ; 작전 번호
13:805B  LDA $6E80 / CMP #$04 / BEQ → $A8C6 (いろいろやろうぜ)
         LDA $75E8 / ASL / … JMP ($8078,X)   ; 인물별 루틴
```

인물별 루틴(クリフト `$AFF0` 등)은 `13:$A54D` 를 칸 번호로 여러 번 부르고, `$A54D` 는 `13:$A68A + 12 × 번호` 의 주문 칸에서 주문을 꺼내 배웠는지·MP 가 되는지 본 뒤 평가합니다. クリフト 의 칸은 ザキ ザラキ マホトーン マヌーサ スカラ スクルト ホイミ ベホイミ ベホマ ベホマラー ザオラル ザオリク 이고, スカラ·スクルト 둘은 `13:$9135` 를 통과할 때만 봅니다.

적의 다음 행동도 미리 셈합니다. `13:$845A` 가 `18[12]` 로 몬스터마다 2절의 가중치 표를 만들고 몬스터 × 6칸을 평가합니다.

## 8. 몬스터 학습

뱅크 `13` 에서 저장 영역(`$6001`~`$62EE`)에 쓰는 곳은 `13:$B0B0` 의 `STA $619B,X` 하나였습니다. `13[0B]` 가 5장 전투 뒤 나온 종마다 2비트 단계를 확률 `FF 80 40`/256 으로 올립니다.

```
850  B0B0 619B=0000 → 0040     おおみみず(ID 7): $619C bit7-6 = 1
850  B0B0 619B=0040 → 0140     スライム(ID 0):  $619B bit1-0 = 1
2051 B0B0 …          → 0280     둘 다 2
```

이 단계는 주문이 걸릴지를 어림하는 `13:$9276` 에서 씁니다. 단계가 낮으면 난수 폭이 커서 내성이 있는 몬스터에게도 주문을 씁니다.

## 9. 작전별로 고른 행동

勇者·クリフト·マーニャ·ブライ 를 20레벨 능력치, HP·MP 999, 주문 모두로 써 넣고, 내성 3 인 スライム 8마리(HP·수비력 1023)와 작전마다 싸웠습니다.

```
작전 0: クリフト ザキ5 ザラキ7 공격6   マーニャ ルカニ12 공격6   ブライ メダパニ11 ルカニ1 공격6
작전 2: クリフト ザラキ9 공격8         マーニャ ルカニ9 공격8    ブライ メダパニ9 공격8
작전 4: 세 사람이 7~12가지 주문에 흩어짐(ホイミ·ザオリク·ドラゴラム·バイキルト …)
작전 5: 모두 공격 20
```

학습 단계 0 이라 ザキ 에 내성 3 인 몬스터에게도 ザラキ 를 계속 썼습니다. 勇者 의 HP 를 바꿔 첫 턴의 クリフト 를 보니 いのちをだいじに 는 330 에서 ベホマ, 360 에서 ザラキ 였고, みんながんばれ·ガンガンいこうぜ 는 220 에서 ベホマ, 250 에서 공격 주문이었습니다(최대 999, 한 번씩).

## 10. 최대 MP 상한

ブライ 를 최대 MP 999, 경험치 30000 으로 두고 1레벨에서 레벨업시키며 `12:$9E33` 을 기록했습니다. 최대 MP 에 + 1 이 들어간 뒤에도 레코드 +0E 는 `E7 03`(999) 그대로였습니다.

## 틀렸던 것들

- `11:$AAF6` 이 쓰는 필드 `02` 를 속도로 짐작했습니다. 속도 0 인 몬스터가 값 3 에서도 늘 마지막에 움직여서 아니라는 것을 알았고, HP 를 기록해 재생이라는 것을 찾았습니다.
- 회심 갈래에서 `$96` 을 공격하는 쪽으로 읽어 「몬스터의 통한 확률」로 보았습니다. 문턱 Y 를 공격자별로 나누어 보니 이 값을 쓰는 쪽은 일행이었습니다.
- ホイミ 실험을 처음에는 MP 0 인 スライム 으로 해서, AI 1 이 회복을 거의 안 하는 것이 HP 조건 때문인지 MP 때문인지 갈리지 않았습니다. MP 를 255 로 두고 다시 했습니다.
- 동료 AI 주문 칸의 시작을 `13:$A68A + 12 × (번호 − 1)` 로 잡았다가 クリフト 자리에 코드 바이트가 나왔습니다. 0번(勇者) 자리를 비워 둔 `+ 12 × 번호` 였습니다.
- 한 실험에 에뮬레이터를 24개 한꺼번에 띄우니 하나도 결과를 남기지 않았습니다. 12개씩 나누어 돌렸습니다.
