# 2026-10-25-27: 전투 행동·주문 위력·내성·몬스터 AI·아이템 플래그

앞 일지([2026-10-25-15](2026-10-25-15-stats.md))에서 코드만 읽고 남긴 것들을 전투에서 쟀습니다. 전투의 모든 행동이 행동 ID 1바이트로 처리되고, 그 ID 로 처리 루틴·위력·성공률 표를 찾는다는 것이 나왔습니다. 몬스터 레코드의 행동 번호·MP·HP·내성·행동 수, 아이템 플래그 네 비트, 장비 판정, 레벨업의 목표값 넘김과 상한도 확인했습니다. 결과는 [dq4-data-format.md](../../dq4-data-format.md#전투-행동) 에 있고, `tools/dq4data.py` 에 `actions` 를 더하고 `monsters`·`items` 를 넓혔습니다.

## 1. 원하는 몬스터와 싸우기

디버그 전투 테스트 창은 무리를 고른 뒤 전투로 넘어가지 않아서([dq4-debug.md](../../dq4-debug.md)) 다른 길을 찾았습니다. 조우 판정 `18:$9D09` 의 `CMP $0E` 를 메모리에서 `CLC; NOP`(`18 EA`, PRG `61D09`)으로 바꾸면 걸음마다 전투가 나고, 전투 시작 `18:$A11A` 에서 무리 칸 `$6E45`~`$6E4C` 를 덮어쓰면 그 몬스터가 나옵니다. PC 가 닿을 때 메모리에 쓰는 [statspc.lua](../../../tools/lua/fc/statspc.lua) 를 새로 썼습니다.

```sh
PCPOKE="A11A@18:6E45=00,07,FF,FF,03,02,00,00" PCNEXT=tools/lua/fc/statspoke.lua \
  ROMONCE="61D09=18,EA" ONCE="605B=80,E7,03,…;616A=83,00" …
```

`ONCE` 로 マーニャ(레코드 3) 같은 인물 레코드를 HP·MP 999, 주문 비트 `FF FF FF` 로 써 넣고 `$616A` 를 그 인물만으로 바꾸면 1장 필드에서 그 인물 혼자 싸웁니다. 세이브스테이트는 クリフト 5레벨 필드(`work/dq4-stats/stats-cristo-field.mss`)를 썼습니다.

## 2. 행동 ID 와 처리 루틴

スライム 의 HP(`$727E`)에 쓰는 곳을 `probe/writes.lua` 로 찾으니 `10:$AA87`(필드 쓰기)이었고, 스택을 따라가니 뱅크 `11` 이 전투 본체였습니다. 데미지 `$7361` 은 보통 공격이면 `11:$99F9`, ブライ 의 ヒャド 면 `13:$B5A3` 이 썼습니다. 그 바로 앞을 `probe/cover.lua` 로 덮어 보니 `11:$8C78` 이 `$7324` 의 값 × 2 로 `11:$A3FA` 의 주소 표를 찾아 뛰었습니다. `$7324` 는 ブライ 가 ヒャド 를 고르면 `09`, スライム 차례에는 `$7328` 이 `43` 이었습니다. 이 값이 행동 ID 이고, `00`~`3B` 는 주문 ID 그대로입니다.

표를 같은 주소끼리 묶으면 `$9AD2` 에 メラ~ミナデイン 과 몬스터 행동 몇 개, `$9FDD` 에 ホイミ~ベホマズン 과 やくそう 같은 것이 모였습니다.

## 3. 위력 표

`13:$B573` 은 행동 ID 로 `13:$B74D` 의 2바이트 쌍을 찾아 `기본 + rand(폭)` 을 합니다. `rand` 는 `10:$A1F6` 으로 8비트 난수 × 폭 의 윗바이트입니다. マーニャ 의 ギラ 로 スライム 셋을 세 번 때리며 `13:$B599`(기본·폭), `10:$A201`(난수), `13:$B5A1`(결과)을 기록했습니다.

```
B599 A=09 00=10   A201 A=5B   B5A1 A=13      16 + ⌊9 × 0x5B / 256⌋ = 19
B599 A=09 00=10   A201 A=E6   B5A1 A=18      16 + 8 = 24
B599 A=09 00=10   A201 A=21   B5A1 A=11      16 + 1 = 17
```

아홉 번 모두 식과 같았습니다. 쌍은 일행 칸 28개 뒤에 몬스터 칸 28개가 있고, メラゴースト 의 メラ 는 기본 7·폭 6(몬스터 칸)이었습니다. 표의 앞 19칸은 DQ4 의 주문 위력(メラ 8~14, メラミ 70~90, ギラ 16~24 …)과 맞습니다.

## 4. 대상 범위와 회복량

スライム 셋 + おおみみず 둘에게 マーニャ 가 メラ·ギラ·イオ 를, ブライ 가 ヒャダイン 을 쓰고 다섯 마리의 HP 를 보았습니다.

```
メラ      f560: 0008 0000 0006 000A 000B          한 마리
ギラ      f580~f740: スライム 셋만 0                무리 하나
イオ      f580~f880: 다섯 모두 0                    모두
```

`13:$B967` bit6-5 가 1·2·3 일 때 하나·무리·모두이고, クリフト 의 ホイミ(bit7 = 0)는 대상 창에 일행 이름이 나왔습니다. 회복은 `13:$B5E4` 가 행동 ID 30개 표(`$B62F`)로 칸을 찾아 `$B7E3` 의 쌍을 씁니다. ホイミ 세 번이 기본 30·폭 11 에 난수 `46 6E 8A` 로 33, 34, 35 였습니다. 이 표에는 씨앗의 상승치(1+3 등)와 マホトラ 의 MP 도 들어 있습니다.

## 5. 성공률과 내성

ブライ 가 ヒャド 를 쓸 때 몬스터 레코드의 필드 `22`(내성 2비트) 읽기가 `13:$B6A9` 에서 나왔습니다. `13:$B66B` 는 `13:$B80B` 의 행동 ID 마다 1바이트에서 bit4-0 을 「내성 칸」으로 보고, `13:$B736` 으로 2비트 자리를 찾아 그 값 r 로 `13:$B803` 의 `FF D8 66 00` 을 확률로 씁니다. スライム 의 바이트 16 을 메모리에서 바꿔 ヒャド 를 여섯 번씩 썼습니다.

```
바이트 16 = 0C(ヒャド 3): B71D 00=00 → 여섯 번 다 실패, 데미지 계산 없음
바이트 16 = 08(ヒャド 2): B71D 00=66 → 두 번 성공(10, 16), 네 번 실패
```

이것으로 내성 칸 15개가 각각 어느 주문인지(イオ, ギラ, メラ, デイン, バギ, ヒャド, マヌーサ, ラリホー, ザキ, ニフラム, マホトラ, マホトーン, メダパニ, ルカニ, メガンテ)와 레코드의 자리가 정해졌습니다.

## 6. 몬스터 행동 번호와 행동 ID 196개

ホイミスライム 의 행동 바이트는 `25 25 25 25 32 32` 인데 전투에서 `$7328` 은 `29`(ホイミ)와 `43` 이었습니다. `$7328` 에 쓰는 곳(`10:$B165`)을 보니 고른 번호를 `10:$A2D7` 이 바꿉니다. 번호 `2A` 미만은 42바이트 표, `2A` 는 `F7`, 그 위는 + `11` 입니다.

몬스터 행동 ID 의 뜻은 표가 아니라 코드에 있어서, メラゴースト 와 싸우며 `10:$B168` 에서 `$7328` 을 `3C`~`FF` 로 바꿔 그 차례의 메시지를 `16:$8656` 에서 모았습니다. 196번을 여섯 개씩 나란히 돌렸습니다.

```
4D 0100 / 0017  [F6]は ひのたまを はきだした！ / [F6]は [F8]のダメージを うけた！
53 0106 / 0166  [F6]は あまい いきをはいた！ / [F6]は ねむってしまった！
58 001D         [F6]は にげだした！
6D 0042 / 0017  [F6]は はじけとんだ！ / …ダメージを うけた！
```

숨결 `4D`~`52` 는 `$9AD2` 로 가는데 행동 ID × 2 로는 표 밖이라, 그때 `13:$B599` 의 값을 보았습니다. `4D` 는 기본 6·폭 5 로 표의 칸 `13` 이었고, `13:$B5AD` 가 `4D`~`6C` 에서 `3A` 를 빼고 나머지 11개는 `13:$B5CE` 의 표로 바꾸는 것이 보였습니다.

## 7. 몬스터의 MP·HP·행동 수·고르는 법

- MP: 전투 시작 때 `10:$A51D` 가 바이트 3 을 전투 RAM +12 로 옮깁니다. メラゴースト(MP 2)는 メラ 한 번에 0 이 되고 그 뒤로는 공격만 했습니다. 롬 값을 6 으로 바꾸면 6 → 4 → 2 → 0 이었습니다.
- HP: 바로 앞 `10:$A4E8` 이 최대 HP 에서 `rand(최대 HP / 4 + 1)` 을 뺍니다. スライム(8)이 6·7·8, おおみみず(11)가 9·10·11 로 나왔습니다.
- 행동 수: `10:$ACAA` 가 바이트 11·12 의 bit7 로 0~3 을 만듭니다. メタルスコーピオン(값 1)은 `$ACC6` 의 Y 가 0, 0, 1 로 셋째 턴에 두 번 행동했습니다.
- 고르는 법: 바이트 9·10 의 bit7 이 3 이면 여섯 칸을 차례로 씁니다. がいこつけんし 는 `20 43 20 43 43 43` 을 순서대로 했습니다.

## 8. 전투에서 아이템 쓰기

マーニャ 의 첫 소지품 칸에 아이템 `00`~`7E` 를 하나씩 넣고 전투 どうぐ 로 썼습니다. 행동 ID 는 `11:$907B` 의 아이템 40개 표에 있으면 `$90A3` 의 값, 없으면 `7F`(「つかった！」→「なにも おこらなかった！」)였습니다. 쓴 뒤 소지품 칸이 `FF` 가 된 16개가 모두 `$8D1B` bit2 였습니다.

```
53 やくそう      act 94 slot FF  [F6]は [F7]をつかった！ / [F6]のキズが かいふくした！
11 いかづちのつえ act 83 slot 11  [F6]は [F7]を ふりかざした！ / つえから いかづちが ほとばしる！
50 ほしふるうでわ act 93 slot D0  [F6]は [F7]をみにつけた！
```

## 9. 장비·팔기·버리기

필드 「そうび」 창의 목록에는 장비할 수 없는 무기도 다 나와서, 고른 뒤의 메시지로 판정을 보았습니다. ライアン 은 せいぎのそろばん·てんくうのつるぎ·てつのつめ·ピンクのレオタード 가 「そうびできない」, はがねのつるぎ 는 こうげき力 47 이었습니다. 勇者 는 `$615C`=`00` 이면 ピンクのレオタード 를 못 입고 `01` 이면 입었습니다. まじんのかなづち 는 「のろわれていた」로 bit3 이 저주였습니다.

성 아래 마을 무기점(`shopwalk.lua` 로 (0D,18))에서 팔고, 필드 どうぐ 「すてる」 로 버렸습니다.

| 아이템 | `$8D1B` bit | 팔기 | 버리기 |
| --- | --- | --- | --- |
| はぐれメタルよろい | 4 | 11250G | 「すてるなんて とんでもない！」 |
| はぐれメタルのけん, ちいさなメダル | 4, 5 | 「うるのは やめといた ほうが いい」 | 「とんでもない！」 |
| まじんのかなづち | 3 | 450G | 「すててもいいですか？」 |
| やくそう | 2, 7 | 6G | 「すててもいいですか？」 |

bit4 가 버릴 수 없음, bit5 가 팔 수 없음입니다. 파는 값은 가격의 ¾ 이었습니다.

## 10. 레벨업의 목표값 넘김과 상한

ライアン 의 힘·체력을 254, 속도를 255, 최대 HP 를 998 로 두고 1레벨에서 경험치 1000 으로 4레벨까지 올렸습니다. 목표값을 넘은 넷의 증가는 모두 0 이나 1 이었고(힘 0·1·0, 체력 0·0·1, HP 1·0·1), 끝 레코드는 힘·속도·체력 255, 최대 HP 999 였습니다.

`$618E` bit6 을 켜고 같은 일을 하면 전투가 빈 창에서 멈추고, 필드에서는 명령 창이 열리지 않았습니다. 레코드 8 로 레벨업하는 갈래는 볼 수 없었습니다.

## 틀렸던 것들

- 몬스터 레코드의 행동 바이트를 행동 ID 로 읽었는데, ホイミスライム 의 `25` 가 ホイミ(`29`)가 되는 것을 보고 번호 → ID 변환(`10:$A2D7`)을 찾았습니다.
- 위력 칸을 행동 ID × 2 로 보면 숨결 행동의 기본·폭이 `255+255` 같은 값이 되었습니다. 실제 값을 찍어 보고 칸 바꾸기(`13:$B5AD`)를 찾았습니다.
- メラゴースト 의 첫 メラ 에서 MP 가 줄지 않아 바이트 3 이 MP 가 아닌가 했는데, 그 턴은 「まだこちらに きづいていない」 턴이라 몬스터가 행동하지 않은 것이었습니다.
- 앞 일지는 bit4 를 「팔 수 없음」으로 짐작했는데, 실제로는 bit4 만 선 はぐれメタルよろい 는 팔리고 버려지지 않았습니다. 팔 수 없음은 bit5 였습니다.
- bit7 둘을 묶은 2비트 값의 순서를 거꾸로 잡아 メタルスコーピオン 을 「늘 두 번」으로 읽었습니다. 두 번 행동한 턴이 이어진 것은 우연이었고, `10:$ACBA` 를 기록하니 값은 1(1~2번)이었습니다.
- `seq.lua` 의 `WATCH` 는 4바이트까지만 읽어서 `e=7274:14` 처럼 길게 주면 엉뚱한 값이 나왔습니다.

## 남은 것

- `$8D1B` bit7, `$8D9A` bit7·bit6·bit5-0, `$8E19` bit7 의 뜻.
- 남은 MP 를 모두 쓰는 주문의 MP 처리, 데미지 외 주문(ルカニ·スカラ·ザオラル 등)의 효과량 표.
- 몬스터 바이트 13·14 bit7, 20 bit5-3, 21 의 세 값. AI 종류 네 갈래의 뜻과 확률 가중치. 메시지가 나오지 않은 행동 ID 9개.
- 레코드 +0B, 최대 MP 상한, `$618E` bit6 과 레코드 8.
