## 1. 쓰기 감시가 안 잡히던 까닭

앞 일지에서 `$112B`·`$10F6` 쓰기를 CPU 주소로 감시하면 아무것도 잡히지 않았습니다. Mesen 의 메모리 콜백에 메모리 종류 `snesWorkRam` 을 주고 WRAM 오프셋(`0x10F6`)으로 걸자 잡혔습니다.
전투 코드는 데이터 뱅크가 `00`·`7E` 가 아니어서(뱅크 `20`·`21` 의 하위 미러), CPU 주소 콜백에 그 주소가 넘어오지 않는 것으로 보입니다.

```lua
emu.addMemoryCallback(cb, emu.callbackType.write, 0x10F6, 0x10F6, emu.cpuType.snes, emu.memType.snesWorkRam)
```

## 2. 대상 수를 정하는 표

두 그룹 전투(앞 일지의 세이브스테이트)에서 파파스가 イオ·メラ·ギラ 를 걸 때 `$10F6`·`$1037` 을 읽고 쓰는 곳을 모았습니다.
행동을 고를 때(`21:B1AE`)는 셋 다 대상 바이트 `$1037` 에 그룹(`90`·`80`)을 넣었습니다. 실행할 때 `$10F6` 은 셋 다 한 마리(`82`)였고, メラ 는 `20:9762` 에서 그대로 한 마리에게, イオ 는 `20:97BF` 를 지나 `$10F6` 을 다시 쓰며 모두를 돌았습니다.

```
イオ  f01609 r 2097BF 10F6=82 → f01667 w 2097AF 10F6=80 …
メラ  f01609 r 209762 10F6=82
```

`20:975F`·`9771`·`97BC` 를 가리키는 2바이트 값을 롬에서 찾자 `26:8867`(メラ)·`26:886D`(ギラ)·`26:8873`(イオ)이 나왔습니다. `26:8865` 가 행동마다 2바이트인 「대상 펼치기 루틴」 표였습니다.
メラ 칸을 イオ 의 루틴으로, イオ 칸을 メラ 의 루틴으로 바꾸자 그대로 따랐습니다.

```
26:8867 = BC97 (メラ → 97BC) → 070 069 069 069 069 06C 069 06C (다섯 마리)
26:8873 = 5F97 (イオ → 975F) → 070 069                          (한 마리)
```

メラ 칸을 그룹 루틴(`9771`)으로 바꾸면 「となえた」 뒤에 멈췄습니다. 행동을 고를 때 정한 대상이 한 마리(bit7 꺼짐)여서 그룹 루틴이 기대하는 값과 맞지 않는 것으로 보입니다.

## 3. 내성 5E·60·61

파파스의 행동을 メガンテ(`15`)·どくのいき(`96`)·なめまわし(`A1`)로 바꾸면 파파스가 몬스터에게 그대로 썼습니다. 내성을 3 과 0 으로 바꿔 비교했습니다.

```
5E メガンテ     3: 079 ×5   0: 07F ×5 (くだけちった)
60 どくのいき   3: 042 ×3   0: 041 ×3 (どくに おかされた)
61 なめまわし   3: 079      0: 17C (とりはだが たってしまった)
```

5F 는 `LDX #5F` 로 넘기는 처리 루틴이 없어 쓰이지 않는 것으로 보입니다.

## 4. 동료가 되는 조건

`BRK #0B 40 21` 은 `00:93BA` 에서 `7E:2190 + 21` 과 `40` 을 AND 하는 플래그 검사였습니다. 디버그 비트 없이 확률 칸만 1 로 하고 아래 값을 `POKE` 했습니다.

| `7E:21B1` | `$1010` | `$100F` | 결과 |
| --- | --- | --- | --- |
| `40` | `80` | 그대로 | 동료가 됨 |
| | `80` | 1 | 안 됨 |
| `40` | | 1 | 안 됨 |
| `40` | `80` | 8 | 동료가 됨 |
| `40` | `80` | 9 | 안 됨 |

주인공 Lv1 에서 구역 레벨이 레벨보다 8 이상 높으면 동료가 되지 않습니다.

## 5. 물건 플래그

비트 하나씩 읽는 루틴(`21:A49D`~`A61F`)을 다른 뱅크에서 부르는 길을 찾으려고 BRK 처리기(`00:8F80`)를 읽었습니다. `80` 이상은 비교 사슬이고, `BRK #94` 가 `00:917D` 로 가서 뒤 바이트를 `21:A3FF` 표의 번호로 씁니다.
롬에서 `00 94 n` 을 찾아 n 별로 부르는 곳을 모으고, 그 근처 메시지를 [대화 메시지 디코더](../../../tools/dq5text.py)로 읽었습니다.

- n = 6(k1 bit3): 상점 팔기 `06:DEF2`. 켜져 있으면 메시지 `054`「それは 手ばなさない方が よろしいのでは？」·`055`「そのように 貴重な物は お引き取りできません」, 꺼져 있으면 `050`「ですね。すこし お待ちを！」.
- n = 10(k2 bit7): 상점 `06:DD50`. 켜져 있으면 메시지 `034`「これは 戦いのときに 道具として 使っても 効力のある 品物ですよ！」.
- n = 12(k2 bit3): 장비 `05:DDFF`. 켜진 물건은 もろばのつるぎ·みなごろしのけん·まじんのよろい·さまようよろい·はめつのたて 다섯 개입니다.

상점 팔기 화면에서 실측하려고 선실 파파스를 도구점(대화 번호 `02`)으로 바꿔 「うる」까지 갔지만, 메시지 `004`「お買い上げですね。どれに いたしましょう？」 뒤에 물건 목록이 뜨지 않아 거기서 멈췄습니다.
