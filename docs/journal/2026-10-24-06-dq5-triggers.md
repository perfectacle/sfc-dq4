# 2026-10-24-06: 영역 이동(트리거)

[앞 일지](2026-10-24-05-dq5-edge-exit.md) 끝에 출구 셀 수와 목적지 항목 수가 맞지 않는 맵이 5개 남았습니다.
그중 06/05(출구 셀 1, 항목 2)의 가장자리로 걸어 나가 남는 항목이 쓰이는지 보려다, 출구 셀도 목적지 표도 아닌 세 번째 이동 장치를 찾았습니다.
결과는 [dq5-map-format.md 의 「영역 이동」](../dq5-map-format.md#영역-이동-00cdec) 에 있습니다.

## 1. 문에 막히고, 엉뚱한 맵으로

06/05 를 글자 격자로 찍는 도구(`tools/attrgrid.py`)를 만들어 아래쪽에 열린 통로 세 곳을 찾았습니다.
가운데 통로로 날아가 아래로 걸었더니 닫힌 문 앞(y=58)에서 막혔습니다.

오른쪽 아래 통로(x=50~51)로 다시 날아갔는데, 이번엔 처음에 `ROMPATCH` 문자열에 공백이 들어가 마지막 바이트(`$BC`)가 빠지는 바람에
`A0/05` 라는 엉뚱한 맵으로 갔습니다. 공백을 빼고 다시 걸으니 (50,58) 에 들어서자마자 06/03 으로 넘어갔습니다.
06/03 은 06/05 의 출구 목록에 없는 맵입니다.

## 2. 사각형 레코드

그 순간 `$BC`/`$BD` 를 쓴 곳은 `2A:F50E`/`F513` 이었고, `$00` 이 가리키는 12바이트 레코드(`2A:DD82`)에서 값을 꺼내고 있었습니다.

```
32 3A 33 3B 01 80 06 03 09 20 01 01
x0 y0 x1 y1 방향 플래그 $BC $BD X  Y  폭 방향
```

바로 앞 레코드는 06/03 의 (9,32) → 06/05 의 (50,58) 로, 서로 짝이었습니다.
걸을 때마다 `00:CDEC` 가 이 맵의 레코드를 차례로 보며 x0 ≤ X < x1, y0 ≤ Y < y1 이고 바라보는 방향이 `+4` 와 같은지 검사합니다.

## 3. 색인 찾기

레코드 목록 위치(`$183A`/`$183C`/`$183D`)도 쓰기 감시에 걸리지 않아, 맵을 불러올 때 뱅크 `$2A` 를 읽는 곳을 모았습니다.
`01:9430` 이 `2A:EB0E` 에서 `[$BC][$BD][개수]` 를 찾고, 앞 항목들의 개수를 더해 `2A:D812 + 12 × 합` 을 레코드 위치로 씁니다.

```
maps 198, records 405, records end 2AEB0E (index at 2AEB0E)
```

레코드가 끝나는 곳이 정확히 색인 시작이고, 색인 끝(`2A:ED60` 의 `FF`) 다음이 출구 목적지 표입니다. 세 표가 한 덩어리로 붙어 있습니다.

## 4. 가장자리 출구의 정체

06/05 의 레코드를 보니 `(29,60)~(31,60)` 처럼 y=60, 즉 맵 높이(60) 바로 밖에 놓인 것이 있었습니다. 앞에서 문에 막혔던 통로가 바로 이 출구로 가는 길이었습니다.
전체 405개 중 114개가 맵 밖에 걸쳐 있어, 실내 맵의 가장자리 출구는 대부분 이 레코드입니다.
03/00 에도 필드로 나가는 레코드(16~59, 56)가 있었는데, 앞 실험에서는 그 줄 아래에서 출발했기 때문에 이 레코드를 지나지 않고 맨 아래까지 가서 `00:CC0F` 경로로 나갔습니다.

## 5. 남은 불일치

18/00 은 출구 셀이 4개인데 목적지 항목이 3개입니다. 남는 네 번째 셀 (38,49) 옆으로 날아가 오른쪽으로 걸었지만 들어서지 못했습니다.
쓰이지 않는 셀로 보입니다. 나머지 4개 맵의 여분 항목은 아직 쓰이는 경우를 찾지 못했습니다.

이 과정에서 셀 `+1` 아래 니블이 1·8·9 말고도 2·3·A·B 값을 가진다는 것을 봤습니다. 층(높이)으로 보여서 셀 속성을 확인할 때 다룹니다.

## 틀렸던 것들

- 실내 맵 가장자리 출구 = `00:CC0F` 경로: 대부분은 맵 밖의 영역 이동 레코드였다.
- 셀 `+1` 아래 니블은 1·8·9 뿐: 2·3·A·B 도 있다.
- `ROMPATCH` 에 공백: 바이트가 빠졌다.
