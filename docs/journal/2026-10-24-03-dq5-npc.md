# 2026-10-24-03: 인물과 낮·밤

[앞 일지](2026-10-24-02-dq5-map-attributes.md)에서 맵 레코드 안에 인물 데이터가 없다는 것을 확인했습니다.
DQ4 맵을 옮기려면 사람·병사 같은 인물이 어디에 어떻게 저장되는지도 알아야 해서 이번에는 그쪽을 찾았습니다.
결과는 [dq5-map-format.md 의 「인물」](../dq5-map-format.md#인물-128000) 에 있습니다.

## 1. 인물 표에서 거꾸로

[DQバイナリ改造 @Wiki](https://w.atwiki.jp/dq_binary/pages/23.html) 의 RAM 표에 인물 데이터가 `7E:3000-` 에 `$20` 간격으로
(슬롯 08 부터 마을 사람) 있다고 적혀 있습니다. 이번에는 위키가 맞았습니다.
맵이 바뀌는 순간 X 좌표(`7E:3028-`)·그림(`7E:3228-`)에 쓰는 코드를 감시하니 `1E:DB4F`~`1E:DC59` 한 루틴이 5명을 놓고 있었습니다.

그런데 이 루틴은 이미 직접 페이지(`$02`~`$0E`)에 풀려 있는 값을 인물 표 여러 칸에 나눠 넣을 뿐이었습니다.
호출한 곳(`calls.lua`)은 `12:82F5` 였고, 뱅크 `$12` 의 실행 리스팅을 읽으니 구조가 한 번에 나왔습니다.

```
12:803F  그룹 목록 = 05:(D4B2 + $BC*2), $BD 개 맵 목록을 건너뜀
12:8067  맵 목록: 엔트리 크기(12:8093)만큼 넘기다 00 이면 다음 맵
12:8155  엔트리 하나 → 낮/밤 판정 → 필드를 $02~$0E 에 → JSL 1E:DB44
```

## 2. 낮과 밤

엔트리를 읽기 직전에 `JSL 21:8000` 이 있었습니다. 팔레트 로더에서 이미 본 루틴으로, `7E:075E ≥ $F0` 이면 캐리를 켭니다.
캐리가 꺼져 있으면 `12:8161`, 켜져 있으면 `12:8227` 로 갈리고, 둘은 엔트리 첫 바이트 위 2비트를 반대로 봅니다.

| bit7-6 | `12:8161`(캐리 0) | `12:8227`(캐리 1) |
| --- | --- | --- |
| `80` | 놓음 | 건너뜀 |
| `40` | 건너뜀 | 놓음 |
| `C0` | 첫 번째 값으로 놓음 | 두 번째 값으로 놓음 |

DQ5 에는 낮과 밤이 있으니 `$075E` 는 시간이고 두 번째 값은 밤일 것이라고 짐작했습니다. 확인하려고
`atpc.lua` 에 매 프레임 값을 덮어쓰는 `POKE` 를 넣고 `7E075E=F0` 으로 고정해 첫 맵을 띄웠습니다.

```sh
SHOT_DIR=$PWD/work/night MAXF=700 EVERY=0 PERIOD=40 TAP=a FROM=360 AT=12803C POKE=7E075E=F0 \
  "$MESENCE" --testrunner "$PWD/rom/dq5.sfc" "$PWD/tools/lua/atpc.lua"
python tools/dq5npc.py rom/dq5.sfc 02 06 --night --compare work/night/at_12803C.bin
```

```
  slot 08: ours (3, 32, 24) game (3, 32, 24) OK
  slot 09: ours (7, 32, 24) game (7, 32, 24) OK
```

낮에 융단 옆에 있던 사람 대신 병사 둘이 침대 자리에 놓였고, WRAM 팔레트 버퍼도 두 번째 목록과 7줄 모두 같아졌습니다.
CGRAM 자체는 이 시점에 아직 갱신 전이라 처음엔 낮·밤 어느 쪽과도 맞지 않아 당황했는데, 로더가 쓰는 곳은 WRAM 버퍼(`[$1EAE]+$20`)였습니다.

## 3. 걸어간 사람

처음 비교에서 02/07 의 한 명이 X 가 28 이 아니라 23 이었습니다. 비교에 쓴 WRAM 이 맵 전환 몇 초 뒤의 것이었고,
그 사람은 인라인 스크립트(엔트리 bit5)로 이미 걸어간 뒤였습니다. 인물을 다 놓은 직후(`12:803C`)의 덤프로 바꾸자 모두 같았습니다.

## 4. 전부 검사

엔트리 길이(`12:8093`)를 옮기는 데서 한 번 틀렸습니다. 두 벌 엔트리는 필드마다 「둘이면 +1, 다음 필드 +1」인데,
마지막 필드(이동)만 「둘이면 +1」로 끝납니다. 고친 뒤 54개 그룹을 이어 읽으니 각 그룹 끝이 다음 그룹 시작과 정확히 맞닿고,
마지막 그룹은 그룹 포인터 표(`05:D4B2`) 바로 앞에서 끝났습니다. 엔트리는 1,077개(둘 다 521, 낮만 437, 밤만 119)입니다.

## 틀렸던 것들

- 인물 로더(`1E:DB44`)가 데이터를 읽는다: 이미 풀린 값을 나눠 넣을 뿐이었다. 호출자가 파서.
- 밤 팔레트를 CGRAM 으로 확인: 아직 업로드 전이었다. WRAM 버퍼로 확인.
- 두 벌 엔트리 길이: 마지막 필드에 +1 을 하나 더 했다.
