# 2026-10-24-07: 셀 속성과 맵 머리 확인

앞 일지들에서 가설로 남긴 셀 속성(통행·가구·가림)과, 뜻을 몰랐던 맵 머리 `+0`/`+3`/`+4` 를 확인했습니다.
결과는 [dq5-map-format.md](../dq5-map-format.md) 의 머리 표와 셀 버퍼 표에 반영했습니다.

## 1. 이동 판정 찾기

배 안을 걷는 동안 셀 버퍼를 읽는 코드를 모으고(`rprofw.lua`), 이미 본 인물 가림 판정(`2B:B8xx`)을 빼니 `00:AC8F`~`00:AD35` 가 남았습니다.
리스팅을 읽으니 목표 셀의 `+1` 을 인물의 `7E:31A0` 과 AND 해서 0 이면 막고, `+1` bit7 이면 또 막습니다.
`7E:31A0` 은 주인공이 `01`, 인물은 엔트리에서 `1E:DD98` 표(`01 02 04 80`)로 받는 값이었습니다. 층 마스크입니다.

## 2. 층을 바꿔 걸어 보기

`7E31A0` 을 매 프레임 고정해 같은 자리에서 왼쪽으로 걸었습니다.

```
mask=01: end x=04 y=0B
mask=02: end x=09 y=0B
```

1층(`01`)이면 바닥(값 1)으로 다섯 칸 갔고, 2층(`02`)으로 고정하자 한 칸도 못 갔습니다.
`+1` 아래 니블은 bit0-2 가 걸을 수 있는 층, bit3 이 위층에 가려지는 칸이라, 앞서 본 8(벽)은 「어느 층도 아닌 칸」, 9 는 「1층이면서 가려지는 칸」입니다.
18/00 처럼 2·3·A·B 값이 섞인 맵은 층이 여럿인 곳입니다.

## 3. 가구는 두 칸 앞에서 멈춘다

짐칸 (3,24) 에서 오른쪽으로 걸었습니다. 통(`+1` = `91`)은 x=11 부터인데 주인공은 x=9 에서 멈췄습니다.
인물은 가로 2칸을 차지하고 좌표는 왼쪽 칸이라, x=10 으로 가려면 x=11 까지 써야 하기 때문입니다.
출구 도착이 출구 셀의 한 칸 왼쪽인 것도 같은 이유입니다.

## 4. 맵 머리

머리 값이 들어가는 RAM 을 읽는 코드를 ROM 에서 찾고(`LDA $xxxx` 꼴 검색), 리스팅으로 확인했습니다.

- `+4`(`$1827`/`$1828`): 화면 그리기(`00:B900`~)에서 셀 `+0` 의 구역 비트가 주인공 구역 마스크(`7E:3720`)와 겹치는 칸만 위층을 그리고,
  나머지 칸을 어떻게 그릴지 `$1827` 로 정합니다. 배에서 선실에 있을 때 짐칸이 통 없는 빈 바닥으로 보이고, 내려가면 통이 보이던 것이 이 장치입니다.
- `+3`: `01:98A4`·`01:98BA` 표로 맵 바깥 칸의 타일 워드와 그리는 루틴(`00:BAD6` 등)을 고릅니다. 실내 맵 243개는 `0`(타일 0) 입니다.
- `+0` bit0-2(`$1821`): 실내 맵은 모두 1 이고 `00:8B35` 가 매 프레임 봅니다. 맵 종류로 보입니다.
- `+0` bit3-5(`$1A33`): 그룹마다 0~6 인데, 정적 검색으로도, 배·맵 전환·필드·전투 시작·던전 보행 동안의 읽기 감시로도 읽는 곳을 찾지 못했습니다.
  던전 성질(주문 제한 등)일 수 있어 아직 해 보지 않은 상황에서 다시 봐야 합니다.

## 틀렸던 것들

- 탐색(BFS)으로 출구 셀 도달 여부 판단: 층을 1·8·9 로만 가정해서 틀렸다.
- 1층 바닥 끝까지 걸어갈 수 있다: 인물이 2칸이라 한 칸 앞에서 멈춘다.
