# DQ4(FC) 인물 대화 스크립트

마을·성의 인물에게 말을 걸었을 때 어떤 메시지가 나올지 정하는 대화 번호와 대화 스크립트입니다. 디코더는 [tools/dq4talk.py](../tools/dq4talk.py), 실측 프로브는 [tools/lua/fc/talk.lua](../tools/lua/fc/talk.lua), 실험 과정은 [2026-10-25-09 일지](journal/dq4/2026-10-25-09-talk.md) 에 있습니다. 해석기와 스크립트는 모두 뱅크 `15` 에 있고, 주소는 그 뱅크의 CPU 주소입니다. 인물 레코드는 [dq4-map-format.md](dq4-map-format.md#인물), 메시지 번호는 [dq4-text-format.md](dq4-text-format.md) 와 같습니다.

근거를 「실측」과 「코드 읽기」로 나눴습니다. 실측은 맵 4곳(1장 바트랜드 성 02/01·02/00, 마을 12/00, 04/00)에서 인물 57명(장 번호·대답을 바꾼 것 포함 86번)에게 말을 걸어 게임이 낸 메시지 번호와 디코더 예측을 맞춘 것입니다([확인](#확인)).

## 흐름

말 걸기(「はなす」)로 앞 칸에 인물이 있으면 `15:$98F8` 에 A = 인물 슬롯(6~), Y = 말 건 자리 값으로 들어옵니다. 앞에 아무도 없으면 이 루틴을 지나지 않고 메시지 `02F0`(そのほうこうには　だれもいない。)이 나옵니다.

1. `$9925`: `$E9` = Y, `$E8` = 슬롯. Y 는 카운터 너머(두 칸 앞)에서 말 걸면 `00`, 바로 앞이면 `22` 였습니다(실측, 12/00 여관 주인).
2. 대화 번호: `1C:$96C7`(BRK 뱅크 1C 함수 01)이 슬롯의 인물 레코드에서 [대화 번호](#대화-번호)를 꺼내 `$00`(아래)·`$01`(위)에 둡니다.
3. `$9962` 가 대화 번호로 갈래를 고릅니다.

| 대화 번호 | 하는 일 | 근거 |
| --- | --- | --- |
| `000`~`006` | 서비스: `$9CBF` 에 A = 번호. 1 무기점 `$B84A`, 2 도구점 `$B858`, 3 방어구점 `$B851`, 4 `$BBF0`, 6 `$BF28`(여관), 0·5 `$B550` | 실측: `$9CBF` 에서 A = 1·2·3·5·6 |
| `007`~`160` | 스크립트 346개. 시작 주소는 `$98F6` 의 워드가 가리키는 `$9642` + 2×(번호 − 7) | 실측 |
| `161`~`178` | 예/아니오: 메시지 m = 번호 − `161` + `500` 을 내고 예/아니오 창, 「はい」 면 m+1, 「いいえ」 면 m+2(`$9C92`) | 실측: `161` → `0500`, `0501`/`0502` |
| `179`~ | 메시지 하나: 번호 − `161` + `500` | 실측 |

메시지는 `$9919` 에서 BRK 뱅크 16 함수 04 로 나가고, 그 안에서 `16:$8656`(X:A = 메시지 번호)을 지납니다.

## 대화 번호

인물 레코드(머리 7바이트)에서 `1C:$96C7` 이 꺼냅니다.

| 값 | 비트 | 근거 |
| --- | --- | --- |
| 대화 번호 위 3비트 | 머리 바이트 1 의 bit4-2 | 실측(57명) |
| 대화 번호 아래 8비트 | 머리 바이트 4 | 실측(57명) |
| 같이 돌려주는 A(`$03`) | bit7 = 바이트 5 bit7 의 반대, bit6 = 바이트 0 bit7, bit5-0 = 바이트 3 >> 2 | 코드 읽기 |

`$03` 의 아래 6비트(바이트 3 의 위 6비트)는 겉모습으로 보입니다. `tools/dq4talk.py G K` 가 「겉모습」 으로 찍지만 화면의 그림과는 아직 맞춰 보지 않았습니다.

맵 860명의 대화 번호는 568가지이고, 메시지 하나 290, 스크립트 269, 서비스 5, 예/아니오 4 입니다.

## 스크립트

문장을 차례로 실행합니다(`$9BA8`). 맨 처음과 `06` 뒤는 블록이고, 블록은 문장마다 다음 바이트가 `3E`·`3F` 면 끝납니다(`$9C2E`).

| 바이트 | 길이 | 뜻 | 근거 |
| --- | --- | --- | --- |
| `40`~`7F` `nn` | 2 | 메시지 (b & `3F`) << 8 \| `nn` 출력(`$9919`) | 실측 |
| `3F` | 1 | 스크립트 끝(갈래 안이면 그 조건만 빠져나옴) | 실측 |
| `07` `c` … | 2+ | [조건](#조건). `c` 의 bit7 = 결과 뒤집기, bit5-0 = 조건 종류. 뒤에 인자, then 갈래, `0B` 가 오면 else 갈래 | 실측 |
| `06` | 1 | 갈래 안에서 블록 시작(조건 뒤가 `06` 이 아니면 문장 하나가 갈래) | 실측 |
| `18` `i` `m` | 3 | 이벤트 플래그 켜기: `$627B+i` \|= m | 실측: 02/00 노인, `$6289` `00` → `10` |
| `17` `i` `m` | 3 | `$627B+i` &= m | 코드 읽기(스크립트 전체 1곳) |
| `19` `i` `v` | 3 | `$627B+i` = v | 코드 읽기(쓰는 스크립트 없음) |
| `12` `n` | 2 | 서비스 n(`$9C63` → `$9CBF`). 돌아와 스크립트를 잇지 않음 | 실측: 12/00 여관 카운터 너머 → 6 |
| `00` `lo` `hi` | 3 | 뱅크 15 루틴 `hi:lo` 호출(`$9C42`). 일행에 넣기·이벤트 등 | 코드 읽기 |
| `01` `lo` `hi` `a` `b` | 5 | 위와 같고 인자 2바이트는 불린 루틴이 읽음(`$9C25` 에서 Y += 2) | 코드 읽기 |

스크립트 346개 전부를 이 규칙으로 읽으면 못 읽는 바이트가 0개입니다(`tools/dq4talk.py all`). 쓰인 횟수: 메시지 951, 조건 588, 플래그 켜기 47, 호출 78·48, 서비스 23, `17` 1.

### 조건

`$99CE` 가 종류마다 루틴을 불러 A 를 받고, `$9A4C` 에서 A = 0 이면 then 갈래, 아니면 else 갈래로 갑니다(뒤집힌 조건 `$DC` = `FF` 면 반대). 아래 「참」 은 then 갈래를 탄다는 뜻입니다.

| 종류 | 인자 | 참 | 쓴 횟수 | 근거 |
| --- | --- | --- | --- | --- |
| `02` | 0 | `$E9` = 0(카운터 너머에서 말 걺) | 16 | 실측 |
| `03` | 1 | 일행 조건 n(BRK `63 63 40` → 뱅크 10 함수 6) | 43 | 실측 결과만, 뜻은 남은 것 |
| `05` | 0 | 예/아니오 창(`$B7DD`, A = `48`)에서 「はい」 | 50 | 실측 |
| `11` | 1 | 아이템 n 관련(`$A794` → BRK `66 73`) | 12 | 코드 읽기 |
| `13` | 1 | 일행 조건 n(BRK `63 73`, `$615A` ≥ 4 면 다른 검사) | 16 | 코드 읽기 |
| `14` | 0 | 낮(`$62ED` < `78`) | 76 | 실측(낮만) |
| `16` | 1 | 장 `$615A` = n − 1 | 143 | 실측: `$615A` = `04` 로 바꾸면 「5장」 갈래 |
| `1A` | 2 | `$627B+i` ≠ v | — | 코드 읽기 |
| `1B` | 2 | `$627B+i` & m ≠ 0 | 230 | 실측 |
| `1C` | 2 | (`$627B+i` \| m) ≠ 0 | — | 코드 읽기 |
| `1E` | 0 | BRK `29 73`(X = 0) | 2 | 코드 읽기 |

예: 02/00 성 앞 노인(대화 `00A`, `15:$803D`)

```
07 1B 0E 10      if flag& 0E 10         이미 따라왔으면
47 89              msg 0789
0B 06            else (블록)
47 87              msg 0787
07 05              if yes
06                   (블록)
18 0E 10             flag|= 0E 10
47 88                msg 0788
00 36 9D             call 15:9D36
3E                   (블록 끝)
0B                 else
47 8A                msg 078A
3E               (블록 끝)
3F               스크립트 끝
```

## 쓰는 법

```sh
uv run python tools/dq4talk.py rom/dq4.nes 12 00               # 맵의 인물마다 자리·겉모습·대화 번호·스크립트·대사
uv run python tools/dq4talk.py rom/dq4.nes 12 00 --ram end.ram # RAM 덤프로 조건을 풀어 나올 메시지만
uv run python tools/dq4talk.py rom/dq4.nes id 11C              # 대화 번호 하나
uv run python tools/dq4talk.py rom/dq4.nes all                 # 모든 스크립트를 풀어 못 읽은 명령 수
```

실측은 `tools/lua/fc/talk.lua` 를 프로브로 돌립니다. `talk.txt` 에 대화 진입(슬롯·Y), 조건 결과, 서비스, 메시지 번호를 찍고 진입 때 RAM(`talk_N.bin`)을 남깁니다. `SLOT` 을 주면 진입 때 A 를 바꿔 아무 인물에게나 말을 건 것처럼 돌립니다. 맵 이동은 [dq4-warp.md](dq4-warp.md) 의 `warp.lua` 를 드라이버로 씁니다.

```sh
LIBDIR=$(uv run krpatch fc lua) SLOT=0C DRIVER=$PWD/tools/lua/fc/warp.lua MAP=04/00 X=0B Y=1C DIR=0 \
  SEQ="a:6,wait:40,a:6,wait:150,a:6,wait:80,a:6,wait:80" TAIL=300 MAXF=900 SHOT_DIR=$PWD/work/t \
  "$MESENCE" --testrunner --nes.ramPowerOnState=AllZeros "$PWD/rom/dq4.nes" "$PWD/tools/lua/fc/talk.lua"
uv run python tools/dq4talk.py rom/dq4.nes compare work/t      # 「いいえ」 를 골랐으면 --no
```

`compare` 는 덤프의 플래그·장·시간과 기록한 Y 로 조건을 풀고, 롬만으로 못 푸는 조건(`03`·`11`·`13`·`1E`)은 기록된 결과를 따릅니다. 풀 수 있는 조건이 기록과 다르면 「다름」 입니다.

`tools/lua/fc/talkseek.lua` 는 세이브스테이트에서 인물에게 걸어가 말을 거는 입력 드라이버입니다(인물이 움직여서 닿지 못하는 일이 많아, 맵 4곳의 확인은 `SLOT` 으로 했습니다).

## 남은 것

- 조건 `03`·`13`(일행 조건, 뱅크 10 함수 6·7)과 `11`(아이템), `1E` 의 정확한 뜻. 지금은 실측 기록으로만 따름.
- 서비스 0·4·5 의 정체(4 `$BBF0`, 0·5 `$B550`). 교회·은행·우편 등으로 보임.
- 호출 문장(`00`·`01`, 126곳)이 부르는 루틴의 뜻(일행에 넣기, 이벤트 시작 등).
- 밤(`$62ED` ≥ `78`)의 갈래와 밤 인물 목록(레코드 블록2)에서의 대화 번호.
- 겉모습(바이트 3 위 6비트)과 화면 그림, 레코드 바이트 2 의 뜻.
- `1C:$96CE` 가 장소 3A/04 에서 `$64` 를 03 으로 바꾸는 이유(대화 번호를 다른 순번에서 찾는 것으로 보임).
