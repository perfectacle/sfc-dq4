# DQ4(FC) 인물 대화 스크립트

마을·성의 인물에게 말을 걸었을 때 어떤 메시지가 나올지 정하는 대화 번호와 대화 스크립트입니다. 디코더는 [tools/dq4talk.py](../tools/dq4talk.py), 실측 프로브는 [tools/lua/fc/talk.lua](../tools/lua/fc/talk.lua), 실험 과정은 [2026-10-25-09 일지](journal/dq4/2026-10-25-09-talk.md) 와 그 뒤의 [2026-10-25-19 일지](journal/dq4/2026-10-25-19-talk2.md) 에 있습니다. 해석기와 스크립트는 모두 뱅크 `15` 에 있고, 주소는 그 뱅크의 CPU 주소입니다. 인물 레코드는 [dq4-map-format.md](dq4-map-format.md#인물), 메시지 번호는 [dq4-text-format.md](dq4-text-format.md) 와 같습니다.

근거를 「실측」과 「코드 읽기」로 나눴습니다. 실측은 게임이 낸 메시지 번호와 디코더 예측을 맞춘 것입니다. 맵 6곳의 낮·밤 인물에게 말을 걸고, 일행·소지품·장·시간을 RAM 으로 만들어 대화 번호를 바꿔 넣은 스크립트를 돌렸습니다([확인](#확인)). 지금 `compare` 는 롬과 RAM 덤프만으로 모든 조건을 풀고, 프로브가 기록한 조건 결과를 빌리지 않습니다.

## 흐름

말 걸기(「はなす」)로 앞 칸에 인물이 있으면 `15:$98F8` 에 A = 인물 슬롯(6~), Y = 말 건 자리 값으로 들어옵니다. 앞에 아무도 없으면 이 루틴을 지나지 않고 메시지 `02F0`(そのほうこうには　だれもいない。)이 나옵니다. 기둥·장식처럼 인물 표에 있지만 말할 수 없는 것은 대화 번호 `008`(스크립트가 메시지 `02F0` 하나)입니다.

1. `$9925`: `$E9` = Y, `$E8` = 슬롯. Y 는 카운터 너머(두 칸 앞)에서 말 걸면 `00`, 바로 앞이면 `22` 였습니다(실측, 12/00 여관 주인).
2. 대화 번호: `1C:$96C7`(BRK 뱅크 1C 함수 01)이 슬롯의 인물 레코드에서 [대화 번호](#대화-번호)를 꺼내 `$00`(아래)·`$01`(위)에 둡니다.
3. `$9962` 가 대화 번호로 갈래를 고릅니다.

| 대화 번호 | 하는 일 | 근거 |
| --- | --- | --- |
| `000`~`006` | [서비스](#서비스): `$9CBF` 에 A = 번호 | 실측: A = 0~6 |
| `007`~`160` | 스크립트 346개. 시작 주소는 `$98F6` 의 워드가 가리키는 `$9642` + 2×(번호 − 7) | 실측 |
| `161`~`178` | 예/아니오: 메시지 m = 번호 − `161` + `500` 을 내고 예/아니오 창, 「はい」 면 m+1, 「いいえ」 면 m+2(`$9C92`) | 실측: `161` → `0500`, `0501`/`0502` |
| `179`~ | 메시지 하나: 번호 − `161` + `500` | 실측 |

메시지는 `$9919` 에서 BRK 뱅크 16 함수 04 로 나가고, 그 안에서 `16:$8656`(X:A = 메시지 번호)을 지납니다.

`$9CBF` 는 A 가 4·6·1·3·2 인지 차례로 보고, 어느 것도 아니면 교회로 갑니다. 그래서 0 과 5 는 같은 교회입니다. 0 을 쓰는 인물은 없습니다.

| n | 갈래 | 하는 일 | 근거 |
| --- | --- | --- | --- |
| 0, 5 | `$B550` | 교회(`021B` 「そなたが　ここにきたのも」, 기록 `0228`·`0229`) | 실측: 5 는 02/00·05/01·04/00 신부, 0 은 대화 번호를 `000` 으로 바꿔 |
| 1 | `$B84A` | 무기점 | 실측 |
| 2 | `$B858` | 도구점 | 실측 |
| 3 | `$B851` | 방어구점 | 실측 |
| 4 | `$BBF0` | 맡기는 곳(`0238` 「もちものと　おかねの　あずかりじょです」) | 실측: 대화 번호를 `004` 로 바꿔. 쓰는 인물은 04/00 ネネ(대화 `075`, 5장 카운터 너머) 하나 |
| 6 | `$BF28` | 여관 | 실측 |

## 대화 번호

인물 레코드에서 `1C:$96C7` 이 꺼냅니다. 슬롯 k 는 목록에서 지금 시간에 나오는 레코드만 센 k−6 번째입니다(`1C:$96FC`·`$9798`): 낮(`$62ED` < `78`)은 F bit4, 밤은 F bit3 인 레코드. 레코드의 F·머리·덧붙은 바이트는 [dq4-map-format.md](dq4-map-format.md#인물) 의 「머리」 와 같습니다. 덧붙은 바이트는 F bit4·bit3 이 모두 켜진 레코드에만 있고, F bit0 이 꺼져 있으면 바이트 7, bit1 이 꺼져 있으면 그다음, bit2 가 꺼져 있으면 그다음 두 바이트입니다.

| 값 | 낮 | 밤 | 근거 |
| --- | --- | --- | --- |
| 대화 번호 | (바이트 1 bit4-2) << 8 \| 바이트 4 | F bit1 이 꺼져 있으면 (바이트 1 bit1-0) << 8 \| 덧붙은 바이트(F bit0 이 꺼져 있으면 8, 켜져 있으면 7). 켜져 있으면 낮과 같음 | 실측: 낮 맵 7곳, 밤 맵 2곳 19명 |
| X, Y | 바이트 5, 6 의 bit6-0 | F bit4 가 켜져 있고 bit2 가 꺼져 있으면 덧붙은 두 바이트, 아니면 낮과 같음(`1C:$9907`) | 실측: 밤 19명 중 18명이 RAM `$6F60`/`$6F80` 과 같음(1명은 걸어서 한 칸 옮김) |
| 그림 번호 | ((바이트 0 bit7) << 6 \| 바이트 3 >> 2) + `0F`, 바이트 1 bit6 이면 \| `80` | F bit0 이 꺼져 있으면 (바이트 1 bit7, 바이트 7), 켜져 있으면 낮과 같은 바이트. `80` 은 바이트 1 bit5 | 실측: RAM 그림 표와 93명 같음(아래) |
| 방향 | 바이트 3 bit1-0 → `$7000` | 그림 번호와 같은 바이트 | 코드 읽기(`1C:$99B3`) |
| 움직임 | 바이트 2 bit7-4 → `$7040` 위 4비트 | 바이트 2 bit3-0 | 실측: 8 미만인 73명 중 72명(아래) |

`1C:$96C7` 이 A(`$03`)로 돌려주는 값은 그림 번호에서 `0F` 를 뺀 아래 7비트(bit6 = 바이트 0 bit7, bit5-0 = 바이트 3 >> 2)에 bit7 = 바이트 5(밤은 6) bit7 의 반대를 붙인 것입니다(코드 읽기). `tools/dq4talk.py G K` 의 「겉모습」 이 이 값입니다.

레코드를 세는 목록은 맵에 들어갈 때 `1C:$9B00` 이 정해 `$3A`/`$3B` 에 둔 것입니다(보통은 뱅크 05 의 목록, 이벤트가 진행되면 [이벤트 목록](#이벤트-목록)). `1C:$96CE` 는 장소 `3A/04` 에서 `$64` 를 잠깐 `03` 으로 바꾸지만, `$96FC` 는 `$64` 를 읽지 않고 `$3A`/`$3B` 만 봅니다. 대화 번호에는 영향이 없는 것으로 읽힙니다(코드 읽기). 실측으로는 3A/04 슬롯 6 이 자기 목록 그대로 대화 `008`(→ `02F0`)이었는데, 3A/03 의 첫 레코드도 `008` 이라 둘을 가르지는 못했습니다.

맵 레코드 낮 860명·밤 727명과 이벤트 목록 372명의 대화 번호는 861가지이고, 메시지 하나 502, 스크립트 346(스크립트 전부), 서비스 5, 예/아니오 8 입니다.

### 이벤트 목록

`1C:$9D0E` 의 워드가 가리키는 `1C:$9D10` 부터 6바이트 줄 56개(`FF` 로 끝)가 있습니다. 맵에 들어갈 때 `1C:$9CC1` 이 줄을 차례로 보고, (그룹, 순번)이 같고 플래그 `$627B` + 바이트 3 & 바이트 2 가 켜진 첫 줄의 목록(뱅크 1C, 주소 = 바이트 4·5)을 씁니다. 레코드 형식은 뱅크 05 목록과 같습니다. 밤 목록이 아니라 이야기 진행에 따른 목록입니다.

| 바이트 | 내용 |
| --- | --- |
| 0, 1 | 그룹, 순번 |
| 2 | 플래그 마스크 |
| 3 | 플래그 번호(`$627B` + n) |
| 4, 5 | 목록 주소(뱅크 1C) |

쓰는 플래그는 대부분 끝낸 장 비트 `$6282`(`07`: `10` = 4장까지 끝냄, `40` = 2장까지 끝냄)와 `$62A1` bit5, `$6283` bit7 입니다. 줄을 고른 뒤 `1C:$9C6F` 가 무르는 경우가 있습니다: `$62A5` bit7 이 꺼져 있고 `$6282` bit4 나 `$6287` bit7 이 켜져 있을 때, 장소 04/01, 12/02, 02/xx(02/03 빼고), `$6295` bit1 이 켜진 15/02 는 보통 목록으로 돌아갑니다(04/01 은 `$6286` bit0 을 켬). 플래그 시험 BRK `n EB m` 은 비트가 꺼져 있으면 Z = 1 입니다([dq4-save-format.md](dq4-save-format.md)).

| 조작(워프, `SET`) | 장소 | 결과 |
| --- | --- | --- |
| `$6283` = `80` | 02/01 | 목록 `1C:$8184` 12명, 자리 12명 모두 같음 |
| `$6283` = `80`, `$6282` = `10` | 02/01 | 무름: 보통 목록 21명 |
| `$6283` = `80` | 02/00 | 목록 `1C:$841E` 12명 |
| `$6282` = `10` | 04/00 | 목록 `1C:$8ACE` 16명. `$615A` = `04` 로 12명에게 말을 걸어 메시지 12번 모두 같음 |
| `$6282` = `10` | 12/00 | 목록 `1C:$9142` 18명 |
| 없음 | 04/00 | 보통 목록 15명 |

인물 수는 인물 표에서 `FF` 가 아닌 슬롯 수입니다(`80`,`80` 은 숨은 인물). 자리는 덤프가 도착 300프레임 뒤라, 걷는 인물을 빼고 맞췄습니다.

### 그림과 움직임

맵에 들어갈 때 `1C:$99B3` 이 그림 번호를 `$9A37` 에 넘깁니다. `$9A37` 은 그 맵에서 쓰는 그림 표 `$6E5E`(16칸, `FF` 는 빈 칸)에서 같은 번호를 찾거나 빈 칸에 넣고, 새로 넣을 때 BRK `04 87`(뱅크 08 함수 04)로 그림을 읽습니다. 인물 표 `$6FE0` 에는 그 칸 번호 + 4(`$07BA` bit7 이면 + 6)가 들어갑니다(코드 읽기). 맵 5곳 덤프 7개(낮 5, 밤 2)에서 인물 93명의 `$6E5E[$6FE0 − 4]` 가 위 식의 그림 번호와 모두 같았습니다. 화면에서는 같은 칸(`$6FE0` = 05, 그림 `11`)을 쓰는 왕좌의 방 병사 둘이 같은 팔레트 3 과 같은 타일 구역(`78`~`85`)으로 그려졌습니다(바라보는 방향에 따라 `78`~`7A` 와 `83`~`85`).

바이트 2 의 니블은 `1C:$9A74` 가 받습니다. 8 미만이면 `$7040` 의 위 4비트가 되고(아래 4비트는 걸음 상태), 8 이상이면 `$DF` 부근의 공용 값을 씁니다(코드 읽기). 움직임 1 은 왕·병사처럼 서 있는 인물입니다. 한 명 다른 것은 1장 세이브스테이트의 슬롯 6(바이트 2 = `0x`, RAM `31`)으로, 세이브스테이트를 만들기 전에 게임이 바꾼 값으로 보입니다(같은 맵을 워프로 새로 읽은 덤프에서는 `00`).

## 스크립트

문장을 차례로 실행합니다(`$9BA8`). 맨 처음과 `06` 뒤는 블록이고, 블록은 문장마다 다음 바이트가 `3E`·`3F` 면 끝납니다(`$9C2E`).

| 바이트 | 길이 | 뜻 | 근거 |
| --- | --- | --- | --- |
| `40`~`7F` `nn` | 2 | 메시지 (b & `3F`) << 8 \| `nn` 출력(`$9919`) | 실측 |
| `3F` | 1 | 스크립트 끝(갈래 안이면 그 조건만 빠져나옴) | 실측 |
| `07` `c` … | 2+ | [조건](#조건). `c` 의 bit7 = 결과 뒤집기, bit5-0 = 조건 종류. 뒤에 인자, then 갈래, `0B` 가 오면 else 갈래 | 실측 |
| `06` | 1 | 갈래 안에서 블록 시작(조건 뒤가 `06` 이 아니면 문장 하나가 갈래) | 실측 |
| `18` `i` `m` | 3 | 이벤트 플래그 켜기: `$627B+i` \|= m | 실측: 02/00 노인, `$6289` `00` → `10` |
| `17` `i` `m` | 3 | `$627B+i` &= m | 코드 읽기(스크립트 전체 1곳) |
| `19` `i` `v` | 3 | `$627B+i` = v | 코드 읽기(쓰는 스크립트 없음) |
| `12` `n` | 2 | 서비스 n(`$9C63` → `$9CBF`). 돌아와 스크립트를 잇지 않음 | 실측: 12/00 여관 카운터 너머 → 6 |
| `00` `lo` `hi` | 3 | 뱅크 15 루틴 `hi:lo` 호출(`$9C42`). [호출 문장](#호출-문장) | 실측(루틴 6개) |
| `01` `lo` `hi` `a` `b` | 5 | 위와 같고 인자 2바이트는 불린 루틴이 읽음(`$9C25` 에서 Y += 2) | 코드 읽기 |

스크립트 346개 전부를 이 규칙으로 읽으면 못 읽는 바이트가 0개입니다(`tools/dq4talk.py all`). 쓰인 횟수: 메시지 951, 조건 588, 플래그 켜기 47, 호출 78·48, 서비스 23, `17` 1.

### 조건

`$99CE` 가 종류마다 루틴을 불러 A 를 받고, `$9A4C` 에서 A = 0 이면 then 갈래, 아니면 else 갈래로 갑니다(뒤집힌 조건 `$DC` = `FF` 면 반대). 아래 「참」 은 then 갈래를 탄다는 뜻입니다.

| 종류 | 인자 | 참 | 쓴 횟수 | 근거 |
| --- | --- | --- | --- | --- |
| `02` | 0 | `$E9` = 0(카운터 너머에서 말 걺) | 16 | 실측 |
| `03` | 1 | 걷는 일행에 [인물](#인물-번호) n 이 있고 살아 있음 | 43 | 실측 |
| `05` | 0 | 예/아니오 창(`$B7DD`, A = `48`)에서 「はい」 | 50 | 실측 |
| `11` | 1 | 일행 누군가가 아이템 n 을 가짐(장비 여부 무관, 1~5장 모두 마차 포함) | 12 | 실측 |
| `13` | 1 | 일행의 인물 n 이 죽어 있음. 1~4장은 마차도, 5장(`$615A` ≥ 4)은 걷는 일행만 | 16 | 실측 |
| `14` | 0 | 낮(`$62ED` < `78`) | 76 | 실측(낮·밤) |
| `16` | 1 | 장 `$615A` = n − 1 | 143 | 실측: `$615A` = `04` 로 바꾸면 「5장」 갈래 |
| `1A` | 2 | `$627B+i` ≠ v | — | 코드 읽기 |
| `1B` | 2 | `$627B+i` & m ≠ 0 | 230 | 실측 |
| `1C` | 2 | (`$627B+i` \| m) ≠ 0 | — | 코드 읽기 |
| `1E` | 0 | 일행 선두가 남자 | 2 | 실측 |

일행·인물 조건은 뱅크 10 의 일행 루틴을 BRK 특수 형식(`b2` 아래 4비트 `3`, [dq4-bank-format.md](dq4-bank-format.md#특수-형식))으로 부릅니다. `b2` = `63`·`73` 은 뱅크 10 함수 6·7 인데 둘 다 `10:$810B` 이고, `b1` 이 `$6E0B` 에 들어가 `10:$9E67` 의 처리기 표를 고릅니다. `63` 은 셋째 바이트를 `$6E0A`(일행을 셀 때의 조건 비트)에 두고 BRK+4 로, `73` 은 셋째 바이트 없이 BRK+3 으로 돌아옵니다. A 는 `$6F` 를 거쳐 처리기에 `$76` 으로 갑니다(코드 읽기).

| `b1` | 처리기 | 하는 일 |
| --- | --- | --- |
| `63` | `10:$9880` | 일행에서 인물 번호 A 를 찾음. 찾으면 C = 1, X = 그 자리 |
| `42` | `10:$964A` | 자리 X 의 상태. 레코드 바이트 0 bit7 이 꺼져 있으면 1(죽음), 그 밖의 상태 비트면 2~, 아무것도 아니면 0 |
| `6A` | `10:$9319` | 자리 X 가 마차에 있으면 1 로 보임 |
| `66` | `10:$99A3` | 일행 소지품(레코드 +13~+1A 의 아래 7비트)에서 아이템 A 를 찾음 |
| `29` | `10:$881F` | 자리 X 의 성별(1 = 여자) |
| `2E`·`30` | | 아이템 A 주기, `66` 이 찾은 아이템 빼기(아래 [호출 문장](#호출-문장)) |

조건마다 루틴은 이렇습니다.

- `03`(`$9AF5`): `63 63 40` 으로 찾고, `42 63 40` 이 1 이 아니면 참. 셋째 바이트 `40` 이 `10:$826D` 에서 마차 쪽 찾기를 막습니다. 마차에 있는 인물은 거짓이었습니다(5장, 마차에 アりーナ).
- `13`(`$9AD1`): `63 73` 으로 찾고(걷는 일행, 다음 마차), 5장이면 `6A 73` 이 1(마차)일 때 거짓, 그 뒤 `42 73` 이 1 이면 참.
- `11`(`$A794`): `66 73` 이 찾으면 참. 5장에 마차의 アりーナ가 가진 아이템 `1E` 로 참이 나왔습니다.
- `1E`(`$9AC3`): X = 0 으로 `29 73`. 주인공(레코드 번호 & 7 = 0)은 `$615C` bit0, 손님(레코드 번호 9 이상)은 레코드 바이트 5 = `CB`, 그 밖은 `46` 의 비트(2 ミネア·3 マーニャ·7 アりーナ 가 여자)입니다.

마차 자리를 셀지는 `10:$8498` 이 `$618E` 로 정합니다. bit5(마차 있음)가 꺼졌거나 bit7 이면 세지 않고, 아래 3비트가 0 이면 셉니다. 그 밖은 마차의 맵(`$618F`)·`$41`·`$07BA` 를 보므로 디코더는 정하지 않고 「?」 로 둡니다(코드 읽기, 실측은 `$618E` = `00`·`20` 만).

### 인물 번호

일행 자리는 `$616A`~`$616D`(걷는 4자리)와 `$6172`~(마차)이고 값은 bit7 + 레코드 번호입니다([dq4-save-format.md](dq4-save-format.md)). 조건의 인물 번호 n 은 레코드 번호 9 미만이면 그 번호 & 7, 9 이상(손님, 레코드 `$610F` + 6 × (번호 − 9))이면 레코드 바이트 5 가 `C5` 이상일 때 바이트 5 − `BD`, 아니면 바이트 5 + `20` 입니다(`10:$884C`, 코드 읽기).

| n | 인물 | 스크립트에서 |
| --- | --- | --- |
| `00` | 주인공 | 5장 「ひつぎに　はいっている　おかたは」 |
| `02` | ミネア | 「ミネアちゃん！」 |
| `03` | マーニャ | 「マーニャちゃん！」 |
| `04` | ブライ | 「あなたも　パデキアを？」(4번 없을 때) |
| `05` | トルネコ | 「あなた！　あなたなのね！」(ネネ) |
| `06` | ライアン | 「ライアンさま」 |
| `07` | アりーナ | 「ひめさまが……！」 |
| `08`·`09` | 손님. `09` = オーりン(「オーりンさん　だよね？」) | 코드 읽기 |

예: 02/00 성 앞 노인(대화 `00A`, `15:$803D`)

```
07 1B 0E 10      if flag& 0E 10         이미 따라왔으면
47 89              msg 0789
0B 06            else (블록)
47 87              msg 0787
07 05              if yes
06                   (블록)
18 0E 10             flag|= 0E 10
47 88                msg 0788
00 36 9D             call 15:9D36
3E                   (블록 끝)
0B                 else
47 8A                msg 078A
3E               (블록 끝)
3F               스크립트 끝
```

## 호출 문장

`00`·`01` 문장 126곳이 뱅크 15 루틴 100개를 부릅니다. `tools/dq4talk.py calls` 가 루틴마다 안에서 부르는 곳(3단 JSR 까지)을 보고 갈래를 붙입니다. 한 루틴이 여러 일을 하면 표의 위쪽 갈래로 셉니다.

| 갈래 | 알아보는 곳 | 루틴 | 예 |
| --- | --- | --- | --- |
| 잠·자리 옮김 | `$44`·`$45`·`$63`·`$64`·`$62ED` 쓰기 | 9 | 나무꾼 집 `$A6A4`(대화 `088`): 잠든 뒤 `$62ED` `90` → `28`(아침), 자리 (0E,05) 로 맵을 다시 읽음(실측) |
| 서비스 | 상점·여관·교회 갈래로 점프 | 2 | `$9D2A`(방어구점), `$ADB7`(상점 넷) |
| 이벤트 | BRK `07 CF`(뱅크 1C 함수 07, `1C:$AD5F`). A = 이벤트 번호, `1C:$BF74` 의 포인터 표. `$B0FF` 도 이 꼴 | 36 | 이벤트 `00` → 특수 전투 `05`(대화 `016`), `14` → 특수 전투 `0E`(대화 `0C6`), `15` → ブライ 가 일행에 듦(`$616B` = `84`, 대화 `0AE`)(실측) |
| 맵 이벤트 | BRK `07 DF`(`1D:$B74D`, 장소 `$63`·장 `$615A` 로 표 `1D:$B8CA` 를 찾음) | 4 | `$A4E1`(대화 `00F` 등 6곳) |
| 아이템 | BRK `2E 73`(주기), `30 73`(빼기), `66 73`(찾기) | 14 | パデキアのたね: `$AB8D` 가 소지품 `7E` 를 `7B` 로 바꿈(실측, 대화 `0B1`) |
| 인물 움직임 | 인물 표 `$7040`+슬롯 쓰기 | 9 | `$A4B7`(7곳): 말 건 인물(`$E8`)의 `$7040` = `11`(움직임 1, 제자리). 왕좌의 방 슬롯 8 에 실행하니 `$7048` `41` → `11`, 그 뒤 900프레임 동안 자리 (1E,16) 그대로(실측) |
| 창·메시지 | `$B7DD`(창)·`$9919`(메시지) 만 | 19 | `$AEF2`(7곳): 인자의 메시지 번호를 냄 |
| 그 밖 | 위 어느 것도 아님 | 7 | `$D20B`(고정 뱅크의 키 기다림), `$AFDC`(BRK `11 DF`) |

BRK `07 CF` 를 부르는 루틴 46개 중 32개는 이벤트 번호를 상수(`LDA #n`)로 넘기고, 14개는 A 를 다른 데서 받습니다. 이벤트 표 `1C:$BF74` 의 각 번호가 하는 일은 3개만 실측했습니다.

## 쓰는 법

```sh
uv run python tools/dq4talk.py rom/dq4.nes 12 00               # 맵의 인물마다 자리·겉모습·대화 번호·스크립트·대사
uv run python tools/dq4talk.py rom/dq4.nes 12 00 --ram end.ram # RAM 덤프로 조건을 풀어 나올 메시지만
uv run python tools/dq4talk.py rom/dq4.nes id 11C              # 대화 번호 하나
uv run python tools/dq4talk.py rom/dq4.nes all                 # 모든 스크립트를 풀어 못 읽은 명령 수
uv run python tools/dq4talk.py rom/dq4.nes 02 01 --night       # 밤 목록
uv run python tools/dq4talk.py rom/dq4.nes calls               # 호출 문장이 부르는 루틴의 갈래
```

실측은 `tools/lua/fc/talk.lua` 를 프로브로 돌립니다. `talk.txt` 에 대화 진입(슬롯·Y), 대화 번호, 조건 결과, 서비스, 이벤트(`1C:$AD5F`·`1D:$B74D`)·특수 전투(`18:$A1AD`), 메시지 번호를 찍고 진입 때 RAM(`talk_N.bin`)을 남깁니다. 환경 변수:

- `SLOT=0C` 또는 `SLOT=06,07,08`: 진입 때 A 를 바꿔 아무 인물에게나 말을 건 것처럼 돌립니다. 여럿이면 N번째 말 걸기에 N번째 슬롯.
- `TID=00B,01A`: N번째 말 걸기의 대화 번호를 바꿉니다(`15:$9942`, 갈래 직전의 `$00`/`$01`). 한 인물 앞에서 아무 스크립트나 돌릴 수 있습니다.
- `SET="616A=8087;60D3=80"`: 첫 말 걸기의 RAM 덤프 전에 한 번 씁니다. 일행·소지품·장·시간을 만들 때 씁니다.

맵 이동은 [dq4-warp.md](dq4-warp.md) 의 `warp.lua` 를 드라이버로 씁니다. 왕좌의 방 세이브스테이트라면 `seq.lua` 로 「up:16」 뒤 A 를 거듭 누르면 왕에게 계속 말을 겁니다(명령 창 → はなす → 대사).

```sh
LIBDIR=$(uv run krpatch fc lua) SLOT=0C DRIVER=$PWD/tools/lua/fc/warp.lua MAP=04/00 X=0B Y=1C DIR=0 \
  SEQ="a:6,wait:40,a:6,wait:150,a:6,wait:80,a:6,wait:80" TAIL=300 MAXF=900 SHOT_DIR=$PWD/work/t \
  "$MESENCE" --testrunner --nes.ramPowerOnState=AllZeros "$PWD/rom/dq4.nes" "$PWD/tools/lua/fc/talk.lua"
uv run python tools/dq4talk.py rom/dq4.nes compare work/t      # 「いいえ」 를 골랐으면 --no
```

`compare` 는 덤프의 플래그·장·시간·일행·인물 레코드와 기록한 Y 로 조건을 풀고, 덤프의 플래그로 이벤트 목록을 고르고, 밤이면 밤 레코드를 씁니다. `TID` 로 바꾼 대화 번호는 기록(`tid` 줄)을 따릅니다. 마차 자리를 셀지 정하지 못한 조건만 기록된 결과를 따르고 그 수를 따로 셉니다. 풀 수 있는 조건이 기록과 다르면 「다름」 입니다.

`tools/lua/fc/talkseek.lua` 는 세이브스테이트에서 인물에게 걸어가 말을 거는 입력 드라이버입니다(인물이 움직여서 닿지 못하는 일이 많아, 맵 4곳의 확인은 `SLOT` 으로 했습니다).

## 남은 것

- 마차를 셀지 정하는 `$618E` 의 다른 값(아래 3비트, bit7)과 마차의 맵 `$618F`. 실측은 `00`·`20` 만이라 디코더는 그 밖을 「?」 로 둠. 손님(인물 번호 8·9) 조건과 `09` 가 참인 경우.
- 이벤트 표 `1C:$BF74` 의 번호마다 하는 일(실측은 `00`·`14`·`15`), 맵 이벤트 `1D:$B74D` 의 표, 이벤트 번호를 A 로 받는 14곳. 호출 루틴 「그 밖」 7개.
- 이벤트 목록을 무르는 `1C:$9C6F` 의 조건 중 `$62A5`·`$6287`·`$6295` 갈래(실측은 `$6282` bit4 로 무른 02/01 하나).
- 움직임 니블의 뜻(1 = 제자리 말고는 모름)과 8 이상의 공용 값 `$DF`~.
- 그림 번호와 CHR 그림의 대응(뱅크 08 함수 04 가 읽는 곳).
- `1C:$96CE` 가 3A/04 에서 `$64` 를 바꾸는 까닭. 대화 번호에는 영향이 없어 보이고, 같은 BRK 를 부르는 다른 곳에서 쓰이는지 모름.
