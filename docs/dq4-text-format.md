# DQ4(FC) 대사 텍스트

FC DQ4 의 대사·내레이션·전투 문구가 롬에 어떻게 들어 있는지입니다. 디코더는 [tools/dq4text.py](../tools/dq4text.py), 실험 과정은 [2026-10-25-01 일지](journal/dq4/2026-10-25-01-text.md) 에 있습니다. 주소 표기는 [dq4-ram-format.md](dq4-ram-format.md) 를 따릅니다.

## 한눈에

- 메시지는 번호(16비트)로 부르고, 32개씩 묶은 **블록**의 시작 위치만 표에 있습니다. 블록 안에서는 앞 메시지를 끝까지 읽어 건너뜁니다.
- 본문은 **6비트 부호**를 3바이트에 4개씩 채운 비트열입니다. 부호를 표로 바꾸면 **글자 바이트**가 되고, 글자 바이트는 그대로 BG 타일 번호(폰트는 CHR `$1000`)입니다.
- 부호 `3C` 는 히라가나·가타카나 표를 바꾸고, `3D`~`3F` 는 뒤 부호와 함께 **사전 단어**(뱅크 `1B`)를 넣습니다.
- 제어 바이트 `ED`~`FF` 는 줄바꿈·버튼 기다림·쉼·소리·이름/숫자 치환입니다. 치환 인자는 메시지 밖 RAM `$F9`~ 에서 옵니다.
- 이름 목록과 메뉴 문구는 같은 글자 바이트를 압축 없이 씁니다. 폰트는 `18:$B840` 의 1비트 타일 141개입니다.
- 롬 전체에 메시지 2633개(`0000`~`0AE2`, 빈 번호 있음)가 있습니다. 본문은 뱅크 `00`~`04` 와 `1B:$A500`~`$BB93` 에 있고, 바로 뒤 `1B:$BB94` 부터 사전입니다.

## 메시지 번호에서 시작 위치

`16:$8656`(A=번호 아래 바이트, X=위 바이트)이 합니다.

| 단계 | 내용 |
| --- | --- |
| 블록 | `번호 >> 5`. 시작 포인터 = `16:$88B0 + 블록 × 2`(블록 88개) |
| 뱅크 | `16:$8960` 의 `1C 2C 3A 47 53` 과 비교해 블록이 작아지는 첫 순번(0~4). 5 이면 뱅크 `1B` |
| 블록 안 | `번호 & 1F` 개의 메시지를 끝 부호 `39` 까지 읽어 건너뜀(`0F:$DF6D`) |

블록 `05`~`07` 은 블록 `08` 과 포인터가 같아 비어 있고, 블록 `04`, `0F`, `27` 은 32개를 채우지 않습니다(뒤 번호를 읽으면 다음 블록 글이 나옴).

## 6비트 부호

`0F:$DF99` 가 읽습니다. 포인터 `$49/$4A`, 뱅크 `$51`, 단계 `$5E`(4로 나눈 나머지)입니다.

| 단계 | 부호 | 다음 바이트로 |
| --- | --- | --- |
| 0 | 바이트0 bit7-2 | 넘어가지 않음 |
| 1 | 바이트0 bit1-0, 바이트1 bit7-4 | 넘어감 |
| 2 | 바이트1 bit3-0, 바이트2 bit7-6 | 넘어감 |
| 3 | 바이트2 bit5-0 | 넘어감 |

포인터가 `$BFD8` 이 되면 다음 뱅크 `$8000` 으로, 뱅크 `04` 다음은 뱅크 `1B` `$A500` 으로 갑니다(`0F:$DFD5`).

## 부호 → 글자 바이트

`16:$86BA`. 가나 모드 `$0566`(0=히라가나, 1=가타카나)마다 `16:$8765` 의 64바이트 표를 씁니다.

| 부호 | 하는 일 |
| --- | --- |
| `00`~`3B` | 표의 글자 바이트. 결과가 `F0` 이면 사전 0번 단어 |
| `39` | 메시지 끝(표로는 `F9`) |
| `3C` | 가나 모드 바꾸기 |
| `3D`~`3F` + 부호 c | 사전 단어. 그룹 = `(부호 − 3D) × 2 + c bit5`, 그룹 안 순번 = `c & 1F` |

사전은 `16:$87E5` 의 그룹 포인터 6개(뱅크 `1B`, 단어 192개)에서 시작하고, 단어마다 글자 바이트가 `FE` 로 끝납니다. 0번 단어는 `FB 70 6F`(▼＊「)라 가타카나 모드의 `F0` 이 「넘기고 다음 말」을 한 부호로 씁니다. 그 밖에 「なんと」「せかい」「ございま」 같은 자주 쓰는 말과 숫자 0~9 가 들어 있습니다.

## 글자 바이트

화면에서 읽어 정했습니다(CHR `$1000` 폰트와 대사 창).

| 바이트 | 글자 |
| --- | --- |
| `00` | 공백 |
| `01`~`0A` | 0~9 |
| `0B`~`3C` | あいうえお … わをん っゃゅょ (50음 순) |
| `3D`, `3E` | 탁점·반탁점. **꾸미는 글자 앞**에 오고, 화면에서는 윗줄 같은 칸에 찍힘 |
| `3F` | 。 |
| `40`~`69` | アイエオカキクコサシスソタテトナニヌネノハヒフホマミムメモラルレロンャッ ド ー じ だ ど ぶ (가타카나는 일부만 있고 없는 글자는 히라가나로 씀, 예: 「アりーナ」) |
| `6A`~`72` | ° 〝 ． ？ ！ 「 ＊ ： … |
| `73`~`7F` | † 해골 M P Ex A~H |
| `ED`~`FF` | 제어(아래) |

### 제어 바이트

`16:$8091` 이 `8D` 이상을 `16:$80AF` 의 처리기 표(`~바이트 × 2`)로 보냅니다. 메시지에 나오는 것은 `ED`~`FF` 뿐입니다. 표는 `tools/dq4text.py rom controls` 가 처리기 주소·쓰는 메시지 수와 함께 찍습니다.

| 바이트 | 처리기 | 뜻 | 메시지 수 | 근거 |
| --- | --- | --- | --- | --- |
| `ED` | `16:$81BF` | 몬스터 깜빡임. `$0592` 의 몬스터 칸으로 `1E:$8D0D` 를 부름 | 6 | 실측 |
| `EE n` | `16:$8198` | 소리. `n < 40` 이면 소리 `n` 을 내고 끝날 때까지 기다림(`0E` 는 기다리지 않음), `n ≥ 40` 이면 효과음 `n + 40` | 31 | 실측 |
| `EF` | `16:$82D0` | `$0554` 에 준비된 글자열(`FF` 끝)을 그대로 찍음. 메시지를 부르는 쪽이 채움 | 23 | 실측 |
| `F0` | `16:$80F7` | `FC` 와 같음 | 0 | 코드 읽기 |
| `F1` | `16:$8175` | 이어지는 줄의 들여쓰기를 0 으로. 메시지 첫 바이트면 자동 `＊「` 도 붙이지 않음(아래) | 154 | 실측 |
| `F2` | `16:$82C3` | 인자 하나를 건너뛰고 `$00/$01` 이 가리키는 길이 붙은 이름(뱅크 `0B`)을 찍음 | 0 | 코드 읽기 |
| `F3` | `16:$82B0` | 주문 이름에서 마지막 글자를 뺀 것 | 0 | 코드 읽기 |
| `F4` | `16:$80E9` | 30프레임 쉼 | 174 | 실측 |
| `F5` | `16:$82A0` | 주문 이름(인자 = 주문 ID) | 6 | 실측 |
| `F6` | `16:$820A` | 이름. 인자 `n < 80` 이면 동료 `n & 0F`, 아니면 몬스터 칸 `n & 07` 의 이름 뒤에 `(n >> 3) & 0F` 가 0~7 일 때 `Ａ`~`Ｈ` | 469 | 실측 |
| `F7` | `16:$81FA` | 아이템 이름(인자 = 아이템 ID) | 71 | 실측 |
| `F8` | `16:$81C8` | 숫자. `$FD`~`$FF`(24비트)를 10진으로, 앞 0 은 뺌 | 70 | 실측 |
| `F9` | `16:$8118` | 메시지 끝. 커서가 줄 시작 칸이 아니면 줄을 바꾸고 끝 | 2633 | 앞 일지 |
| `FA` | `16:$8112` | 줄을 바꾸고 끝 | 0 | 코드 읽기 |
| `FB` | `16:$810B` | `FC` 처럼 줄을 바꾸고 ▼ 를 깜빡이며 A·B 를 기다림 | 918 | 화면 |
| `FC` | `16:$80F7` | 줄바꿈. 커서가 줄 시작 칸(`$55`)이면 바꾸지 않음 | 1980 | 코드 읽기, 화면 |
| `FD` | `16:$8104` | 언제나 줄을 바꾸고 ▼ 기다림 | 0 | 코드 읽기 |
| `FE` | `16:$80F1` | 언제나 줄바꿈 | 1 | 실측 |
| `FF` | `16:$80D5` | 끝. 줄바꿈도 `。` 도 없음 | 20 | 실측 |

가타카나 모드의 부호 `39` 는 `F9` 가 아니라 `FA` 로 바뀝니다(`16:$8765` 표의 뒤 64바이트). 끝 부호는 모드와 상관없이 `39` 라 메시지 경계는 그대로입니다.

치환 제어(`F2`, `F3`, `F5`, `F6`, `F7`)는 인자를 메시지 안이 아니라 RAM `$F9` 부터의 인자 목록에서 하나씩 꺼냅니다(`16:$82E9`, 순번 `$5B`). 메시지를 부르는 쪽이 `$F9`~ 를 채우고, 숫자는 `$FD`~`$FF` 에 둡니다. 글자는 `$0554` 에 `FF` 끝으로 만든 뒤 한 글자씩 보통 글자처럼 찍습니다. 이름은 [이름 목록](dq4-data-format.md#이름-목록)(뱅크 `0B`, 길이 붙은 글자 바이트)에서 꺼내고(`16:$82F0`), ID 는 목록 순번 − 1 입니다. 동료 이름은 `BRK 2A 53`(뱅크 `10` 함수 `05`)이 `$72`~`$75` 에 4글자로 둡니다.

`F6` 의 몬스터 쪽은 `$6E45 + 칸` 의 몬스터 ID 로 이름을 찾습니다. `BRK 29 C3` 이 carry 를 켜면 몬스터 대신 동료 이름에 `もどき` 를 붙이는 갈래가 있습니다(코드 읽기, 화면 미확인).

메시지 끝 `F9` 앞 글자가 `！ ？ 。` 나 제어 `FB FE F4 FF` 가 아니면, 게임이 `。` 를 붙여 찍습니다(`16:$805A`). 디코더는 화면에 나오는 대로 붙여 보여 줍니다.

## 창에 찍는 흐름

`16:$8028`(뱅크 `16` 함수 `04`)이 메시지 하나를 찍습니다: `16:$8656`(시작 위치) → `16:$85C5`(앞 8글자 미리 읽기) → `16:$8036`(한 글자씩).

| 항목 | 내용 | 근거 |
| --- | --- | --- |
| 자동 `＊「` | `$058B ≥ 5`(왕에게 말을 걸 때 `06`)이고 첫 바이트가 `F1` 이 아니면 `70 6F` 를 앞에 넣고 들여쓰기 3 | `16:$85C5`. 메시지 `060A`(본문은 `そなたの…`)가 화면에 `＊「そなたの…` 로 나옴 |
| 들여쓰기 | 줄이 시작될 때 앞 8글자 안에 `「`(`6F`)가 끝 계열 제어(`F9 FA FB FD FF`)보다 먼저 있으면 그 뒤 줄들을 2칸 들여씀, 없으면 0 | `16:$85FF`, `16:$817A`. `＊「` 뒤 `FC` 가 줄을 바꾸지 않는 까닭도 이것(커서 2 = 들여쓰기 2) |
| 줄 폭 | 커서 `$0551` 이 `$54` 에 닿으면 저절로 다음 줄. 필드 창 `$54 = 16`(22칸), 전투 창 `18`(24칸) | `16:$838B` 코드 읽기, RAM 덤프. 메시지 본문에 22칸을 넘는 줄은 전투 문구(23~24칸) 10개뿐 |
| 줄 수 | 줄 번호 `$0552` 가 2씩 늘고 `09` 가 되면 한 줄 올려 `07` 로 | `16:$83B0` 코드 읽기 |
| 글자 소리 | 공백·`＊`·`「`·`…` 이 아닌 글자마다 `BRK 96 FB`(효과음 `96`) | `16:$8373`, 실측(글자마다 `1F:$C01F` 에 A=`96`) |

## 대사 외 문자열

| 종류 | 형식 | 근거 |
| --- | --- | --- |
| 전투 문구 | 대사와 같은 메시지(`0000`~`01FF` 쪽). 같은 `16:$8656` 으로 찍음 | 전투에서 `16:$8656` 진입 X:A 가 `019E`, `001A`, `004C`, `0006`, `0017` |
| 이름 목록 | 길이 1바이트 + 글자 바이트, 압축 없음(뱅크 `0B`) | [dq4-data-format.md](dq4-data-format.md#이름-목록), `16:$82F0` |
| 메뉴·창 문구 | 압축 없는 글자 바이트. 탁점은 대사처럼 앞 바이트 `3D`. 창 정의 표 `16:$A572`(그룹 2개: `$A578` 의 `70` 개, `$A674` 의 `14` 개)가 항목 문자열 주소를 가리키고, 항목 길이는 다음 주소까지. `80` 이상은 창 명령 | 명령 창을 연 nametable 에서 `コマンド`(`47 58 61 64`), `はなす`, `じゅもん`, `つよさ`, `さくせん` 이 롬 `16:$B07D`~ 의 바이트 그대로 나옴. 창 명령의 뜻은 남은 것 |

글자 바이트 표는 셋 다 같습니다.

## 폰트

글자 바이트 `00`~`8C` 의 타일(141개)은 PRG `18:$B840` 에 글자마다 8바이트(1비트 평면 하나)로 있습니다. CHR `$1000 + 글자 × 16` 의 앞 8바이트가 이 값이고 뒤 8바이트(둘째 평면)는 0 입니다. 왕좌의 방 대사, 전투, 명령 창, 이름 입력의 CHR 덤프에서 141개가 모두 같았습니다. 뒤 `18:$BCF8`~ 는 라틴 대문자 모양의 다른 글꼴로, 부팅 101~160프레임(타이틀 무렵)에 `$C3EA` 로 읽힙니다.

CHR 은 RAM(8KB)이라 폰트를 바꾸려면 PRG 의 이 자리를 고치면 됩니다. 글자 바이트 `8D` 이상은 `16:$8091` 이 제어 처리기로 보내므로, 대사 창에 글자로 찍을 수 있는 타일 번호는 `00`~`8C` 141개가 전부입니다.

## 다시 넣을 때의 제약

FC 롬에 글을 다시 넣을 때 지켜야 하는 것입니다. SFC 로 옮길 때는 원문을 이 형식에서 뽑기만 하면 됩니다.

| 항목 | 값 |
| --- | --- |
| 본문 자리 | 뱅크 `00`~`04` 의 `$8000`~`$BFD7`(각 16344바이트)와 `1B:$A500`~`$BB93`. 합 87500바이트, 빈 곳 없음. 뱅크마다 `$BFD8` 부터는 리셋 조각이라 비트열이 그 앞에서 다음 뱅크로 넘어감 |
| 시작 포인터 | `16:$88B0` 의 16비트 주소 88개(32개 단위 블록). 뱅크는 주소에 없고 블록 번호를 `16:$8960` 의 경계 `1C 2C 3A 47 53` 과 비교해 정함. 블록 시작은 바이트 경계 |
| 메시지 길이 | 길이 필드 없음(끝 부호 `39`). 지금 가장 긴 것은 글자 바이트 583개. 블록 안 뒤 메시지일수록 앞 메시지를 모두 읽어 건너뛰므로 느려짐 |
| 글자 수 | 6비트 부호 하나가 글자 60개(`00`~`3B`)를 가리키고, 표가 2개(가나 모드)라 바로 쓸 수 있는 글자는 117종. 더 많은 글자는 사전 단어나 모드 전환이 필요 |
| 사전 | 단어 192개(그룹 6개 × 32), `1B:$BB94`~`$BF13`(896바이트), 그룹 포인터 `16:$87E5`. 단어는 `FE` 끝 글자 바이트라 내용·길이를 바꿔도 됨. 뒤 `1B:$BF14`~`$BFD7` 196바이트가 비어 있음 |
| 창 폭 | 필드 22칸, 전투 24칸. 줄을 넘기면 저절로 접히지만 단어 경계는 보지 않음 |

## 대사 창 줄 버퍼

글자는 RAM `$06AA` 부터 3줄짜리 버퍼에 들어갑니다. 줄마다 탁점 행 22바이트, 글자 행 22바이트입니다(`16:$830F`: `3D`·`3E` 는 22바이트 앞 칸에). 필드의 대사 창은 이 버퍼에서 그리고 nametable 덤프에는 남지 않아, 디코더 비교는 이 버퍼로 합니다.

## 확인

- 오프닝 내레이션·왕의 연설을 A 를 한 번씩 눌러 가며 RAM 을 10번 덤프: `tools/dq4text.py MSG --compare end.ram` 으로 창 줄 버퍼의 모든 줄(28줄)이 메시지 `0300`~`0302` 에 순서대로 있음.
- 같은 장면에서 nametable(내레이션은 nametable 에 찍힘) 세 줄이 메시지 `0300` 의 3~5번 줄과 바이트까지 같음.
- `16:$8656` 진입 때 `X:A` 가 `0301`, `0302` 로, 화면에 나온 메시지 번호와 같음(`probe/trace.lua`).
- 블록 87개 중 81개는 32번째 메시지 끝이 다음 블록 시작 포인터와 정확히 같음. 나머지 6개는 위의 덜 찬 블록.
- 마지막 메시지 `0AE2`(엔딩) 끝이 `1B:$BB93`, 사전 시작이 `1B:$BB94`.

- 제어 바이트: `tools/lua/fc/textforce.lua` 로 왕좌의 방에서 왕에게 말을 건 순간 `16:$8656` 의 X:A 를 바꾸고 인자(`$F9`~, `$FD`~, `$0554`~)를 써서 띄움. 창 줄 버퍼에 나온 글은 아래와 같음.

| 메시지 | 바꾼 RAM | 창에 나온 글 |
| --- | --- | --- |
| `000C`(`F6`·`F8`) | `F9=00 FD=39 FE=30 FF=00` | `ライアンは` / `12345ポイントのけいけんちをかくとく。` |
| `015E`(`F6`·`F5`) | `F9=01`(`FA=00`) | `あああは　メラを　となえた！`(동료 1 의 이름 `あああ`, 주문 0 = `メラ`) |
| `002D`(`F6`·`F7`) | `F9=53`(`FA=00`) | `あああは　ひのきのぼうを　てにとった！`(동료 3 도 `あああ`, 아이템 0 = `ひのきのぼう`) |
| `0072`(`EF`) | `0554=10 0555=12 0556=FF` | `ミネアは　かくの　カードをひいた！` |
| `001F`(`F6`, 전투 중) | `F9=80` / `F9=89` | `しかし　スライムＡは…` / `しかし　おおみみずＢは…` |

- `EE`: `030A`(`EE 1A`)에서 소리 루틴 `1F:$C01F` 가 A=`1A` 로 불리고 글이 201프레임 멈췄다가 이어짐. `0449`(`EE 4E`)에서는 A=`8E`.
- `ED`: 전투 중 `0465` 를 띄우면 `1E:$8D18`(숨김)·`$8D2C`(보임)가 칸 0 에 6번씩 번갈아 불리고, 몬스터 자리 화소 수가 525 → 484 → 516 으로 바뀜.
- `F4`: `038F` 의 `ぐ[F4]　ぐふっ！` 에서 `ぐ` 와 다음 글자 사이 33프레임.
- `FE`: `0466`(첫 바이트 `FE`)은 창 둘째 줄부터 찍힘. `FF`: `0007` 이 `。` 없이 끝남.
- 전투 창은 폭이 24칸이라 디코더의 `buffer_lines`(22칸 가정)로 읽으면 탁점 자리가 어긋남. 위 표의 전투 줄은 글자 행 기준.
- `F1`: `0389` 의 대사 줄들은 2칸 들여 찍히고, `F1` 뒤 `しかし　へんじは　なかった……。` 만 0칸에서 시작.

## 남은 것

- `F0`, `F2`, `F3`, `FA`, `FD` 는 메시지에 없어 화면으로 확인하지 못함(코드 읽기만).
- `F6` 의 `もどき` 갈래가 언제 쓰이는지.
- 메시지 번호를 고르는 쪽: 맵·인물·이벤트에서 어떤 번호를 부르는지.
- 창 정의 표 `16:$A572` 의 창 명령(`80` 이상) 뜻과 창 하나하나의 모양.
- 폰트를 `18:$B840` 에서 CHR 로 옮기는 루틴(읽기 프로브에 바로 잡히지 않음).
- `$058B` 의 다른 값(대화 종류)과 자동 `＊「` 가 붙는 장면 목록.
