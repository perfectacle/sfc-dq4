# DQ4(FC) 대사 텍스트

FC DQ4 의 대사·내레이션·전투 문구가 롬에 어떻게 들어 있는지입니다. 디코더는 [tools/dq4text.py](../tools/dq4text.py), 실험 과정은 [2026-10-25-01 일지](journal/dq4/2026-10-25-01-text.md) 에 있습니다. 주소 표기는 [dq4-ram-format.md](dq4-ram-format.md) 를 따릅니다.

## 한눈에

- 메시지는 번호(16비트)로 부르고, 32개씩 묶은 **블록**의 시작 위치만 표에 있습니다. 블록 안에서는 앞 메시지를 끝까지 읽어 건너뜁니다.
- 본문은 **6비트 부호**를 3바이트에 4개씩 채운 비트열입니다. 부호를 표로 바꾸면 **글자 바이트**가 되고, 글자 바이트는 그대로 BG 타일 번호(폰트는 CHR `$1000`)입니다.
- 부호 `3C` 는 히라가나·가타카나 표를 바꾸고, `3D`~`3F` 는 뒤 부호와 함께 **사전 단어**(뱅크 `1B`)를 넣습니다.
- 롬 전체에 메시지 2633개(`0000`~`0AE2`, 빈 번호 있음)가 있습니다. 본문은 뱅크 `00`~`04` 와 `1B:$A500`~`$BB93` 에 있고, 바로 뒤 `1B:$BB94` 부터 사전입니다.

## 메시지 번호에서 시작 위치

`16:$8656`(A=번호 아래 바이트, X=위 바이트)이 합니다.

| 단계 | 내용 |
| --- | --- |
| 블록 | `번호 >> 5`. 시작 포인터 = `16:$88B0 + 블록 × 2`(블록 88개) |
| 뱅크 | `16:$8960` 의 `1C 2C 3A 47 53` 과 비교해 블록이 작아지는 첫 순번(0~4). 5 이면 뱅크 `1B` |
| 블록 안 | `번호 & 1F` 개의 메시지를 끝 부호 `39` 까지 읽어 건너뜀(`0F:$DF6D`) |

블록 `05`~`07` 은 블록 `08` 과 포인터가 같아 비어 있고, 블록 `04`, `0F`, `27` 은 32개를 채우지 않습니다(뒤 번호를 읽으면 다음 블록 글이 나옴).

## 6비트 부호

`0F:$DF99` 가 읽습니다. 포인터 `$49/$4A`, 뱅크 `$51`, 단계 `$5E`(4로 나눈 나머지)입니다.

| 단계 | 부호 | 다음 바이트로 |
| --- | --- | --- |
| 0 | 바이트0 bit7-2 | 넘어가지 않음 |
| 1 | 바이트0 bit1-0, 바이트1 bit7-4 | 넘어감 |
| 2 | 바이트1 bit3-0, 바이트2 bit7-6 | 넘어감 |
| 3 | 바이트2 bit5-0 | 넘어감 |

포인터가 `$BFD8` 이 되면 다음 뱅크 `$8000` 으로, 뱅크 `04` 다음은 뱅크 `1B` `$A500` 으로 갑니다(`0F:$DFD5`).

## 부호 → 글자 바이트

`16:$86BA`. 가나 모드 `$0566`(0=히라가나, 1=가타카나)마다 `16:$8765` 의 64바이트 표를 씁니다.

| 부호 | 하는 일 |
| --- | --- |
| `00`~`3B` | 표의 글자 바이트. 결과가 `F0` 이면 사전 0번 단어 |
| `39` | 메시지 끝(표로는 `F9`) |
| `3C` | 가나 모드 바꾸기 |
| `3D`~`3F` + 부호 c | 사전 단어. 그룹 = `(부호 − 3D) × 2 + c bit5`, 그룹 안 순번 = `c & 1F` |

사전은 `16:$87E5` 의 그룹 포인터 6개(뱅크 `1B`, 단어 192개)에서 시작하고, 단어마다 글자 바이트가 `FE` 로 끝납니다. 0번 단어는 `FB 70 6F`(▼＊「)라 가타카나 모드의 `F0` 이 「넘기고 다음 말」을 한 부호로 씁니다. 그 밖에 「なんと」「せかい」「ございま」 같은 자주 쓰는 말과 숫자 0~9 가 들어 있습니다.

## 글자 바이트

화면에서 읽어 정했습니다(CHR `$1000` 폰트와 대사 창).

| 바이트 | 글자 |
| --- | --- |
| `00` | 공백 |
| `01`~`0A` | 0~9 |
| `0B`~`3C` | あいうえお … わをん っゃゅょ (50음 순) |
| `3D`, `3E` | 탁점·반탁점. **꾸미는 글자 앞**에 오고, 화면에서는 윗줄 같은 칸에 찍힘 |
| `3F` | 。 |
| `40`~`69` | アイエオカキクコサシスソタテトナニヌネノハヒフホマミムメモラルレロンャッ ド ー じ だ ど ぶ (가타카나는 일부만 있고 없는 글자는 히라가나로 씀, 예: 「アりーナ」) |
| `6A`~`72` | ° 〝 ． ？ ！ 「 ＊ ： … |
| `73`~`7F` | † 해골 M P Ex A~H |
| `ED`~`FF` | 제어(아래) |

### 제어 바이트

`16:$8091` 이 `8D` 이상을 `16:$80AF` 의 처리기 표(`~바이트 × 2`)로 보냅니다. 실제로 쓰는 것은 `ED`~`FF` 입니다.

| 바이트 | 뜻 | 근거 |
| --- | --- | --- |
| `F9` | 메시지 끝 | 끝 부호 `39` 의 글자 바이트 |
| `FC` | 줄바꿈. 커서가 줄 시작 칸(`$55`)이면 바꾸지 않음 | 처리기 `16:$80F7` 코드 읽기. `＊「` 바로 뒤 `FC` 가 화면에서 줄을 바꾸지 않음 |
| `FB` | 버튼을 기다린 뒤 넘김(화면에 ▼) | 화면 |
| `F6` | 이름이 들어감(「〈F6〉は　どうぐを　もっていない。」) | 문맥 추정 |
| `F7` | 도구 이름(「〈F6〉は　〈F7〉を　てにとった！」) | 문맥 추정 |
| `F5` | 주문 이름(「〈F6〉は　〈F5〉を　となえた！」) | 문맥 추정 |
| `F8` | 숫자(「〈F8〉ポイントの　けいけんちを　かくとく。」) | 문맥 추정 |
| `EF` | 다른 이름(「ミネアは　〈EF〉の　カードを　ひいた！」) | 문맥 추정 |
| `ED`, `EE`, `F1`, `F4`, `FE`, `FF` | 모름 | |

메시지 끝 `F9` 앞 글자가 `！ ？ 。` 나 제어 `FB FE F4 FF` 가 아니면, 게임이 `。` 를 붙여 찍습니다(`16:$805A`). 디코더는 화면에 나오는 대로 붙여 보여 줍니다.

## 대사 창 줄 버퍼

글자는 RAM `$06AA` 부터 3줄짜리 버퍼에 들어갑니다. 줄마다 탁점 행 22바이트, 글자 행 22바이트입니다(`16:$830F`: `3D`·`3E` 는 22바이트 앞 칸에). 필드의 대사 창은 이 버퍼에서 그리고 nametable 덤프에는 남지 않아, 디코더 비교는 이 버퍼로 합니다.

## 확인

- 오프닝 내레이션·왕의 연설을 A 를 한 번씩 눌러 가며 RAM 을 10번 덤프: `tools/dq4text.py MSG --compare end.ram` 으로 창 줄 버퍼의 모든 줄(28줄)이 메시지 `0300`~`0302` 에 순서대로 있음.
- 같은 장면에서 nametable(내레이션은 nametable 에 찍힘) 세 줄이 메시지 `0300` 의 3~5번 줄과 바이트까지 같음.
- `16:$8656` 진입 때 `X:A` 가 `0301`, `0302` 로, 화면에 나온 메시지 번호와 같음(`probe/trace.lua`).
- 블록 87개 중 81개는 32번째 메시지 끝이 다음 블록 시작 포인터와 정확히 같음. 나머지 6개는 위의 덜 찬 블록.
- 마지막 메시지 `0AE2`(엔딩) 끝이 `1B:$BB93`, 사전 시작이 `1B:$BB94`.

## 남은 것

- 제어 바이트 `ED`, `EE`, `F1`, `F4`, `FE`, `FF` 의 뜻, `F5`~`F8`·`EF` 가 어느 RAM 값을 넣는지.
- `＊「` 가 겹칠 때의 규칙(`70 6F FC 70 6F` 가 화면에 한 번만 나옴).
- 메시지 번호를 고르는 쪽: 맵·인물·이벤트에서 어떤 번호를 부르는지.
- 이름 입력·메뉴·상점 같은 창의 고정 문구가 같은 형식인지(이번엔 대사 창만 봄).
