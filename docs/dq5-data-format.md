# DQ5(SFC) 게임 데이터 형식

상점 품목과 물건 가격처럼 DQ4 데이터로 바꿔 넣을 표를 정리한 문서입니다. 찾아낸 과정은 일지에 있습니다.

- [2026-10-25-04: 물건 표](journal/dq5/2026-10-25-04-items.md)

기준과 검증:

- 기준 롬: `rom/dq5.sfc`([README](../README.md) 의 SHA-1). 주소 표기는 [dq5-map-format.md](dq5-map-format.md) 와 같습니다.
- 구현: [tools/dq5shop.py](../tools/dq5shop.py), [tools/dq5item.py](../tools/dq5item.py), [tools/dq5monster.py](../tools/dq5monster.py). 물건 이름은 [이름 문자열](dq5-text-format.md#이름-문자열-21955d) 5번 표입니다.
- 선실에서 무기점 처리기의 키를 바꿔 그룹 `00`·`01`·`21` 무기점 목록을 띄우니 품목과 가격 17개가 모두 표와 같았습니다.

## 가게 종류 (`06:DBD2`)

인물 대화 번호 `000`~`010` 은 `06:DBDB` 점프 표의 처리기로 갑니다([dq5-text-format.md 「대화」](dq5-text-format.md#대화-06af62)).
선실의 파파스 슬롯에 대화 번호를 넣고 말을 걸어 첫 메시지를 보았습니다.

| 대화 번호 | 가게 | 첫 메시지 | 목록 종류(`7E:0F20`) |
| --- | --- | --- | --- |
| `01` | 무기점 | 002「ここは　武器の店だ。」 | 2 |
| `02` | 도구점 | 000「ここは　道具屋。」 | 0 |
| `03` | 방어구점 | 001「ここは　防具屋でございます。」 | 1 |
| `04` | 맡기는 곳 | 0B9「お金と　持ち物の　預かり所です」 | |
| `05`·`0F` | 교회 | 07E·07F | |
| `06`·`10` | 여관 | 070·077 | |
| `07` | 몬스터 맡기기 | 0E9 | 7 |
| `08` | よろず屋 | 003「ここは　よろず屋だよ。」 | 3 |
| `09` | 작은 메달 | 482 | 4 |
| `0A` | ルイーダの店 | 470 | 0A |
| `0B` | 코인 판매 | 468 | 0B |
| `0C` | 코인 교환 | 461 | 5 |
| `0D` | 슬라임 레이스 | 10D | 0D |
| `0E` | 격투장 | 112 | 0E |

목록 종류 값은 처리기 첫머리의 `LDA #n / STA $0F20` 을 읽은 것입니다(코드 읽기, 무기점 2 는 실측).

## 상점 (`06:F49C`)

```
04:FBD5 + 종류 * 2 = 목록들의 시작(뱅크 04). 종류 0 도구, 1 방어구, 2 무기, 3 よろず屋
목록 = [키][물건 번호 …][FF] 가 이어짐. 06:F534 가 키가 7E:0F25 와 같은 첫 목록을 찾는다
```

- 무기·도구·방어구점의 키는 맵 그룹 `$BC` 입니다(`06:DC37` `LDA $BC / STA $0F25`). よろず屋 는 처리기마다 키를 고정합니다(예 `15`·`16`).
- 같은 키의 목록이 둘 이상이면 `06:F4CB` 가 뒤의 목록을 더 찾습니다. 그룹 `1A`·`01`·`22`·`21` 은 `7E:2190 & 40`(이야기 진행으로 보임),
  `21` 은 그다음 `7E:21A9 & 20`, 그룹 `19` 의 방어구점은 주인공 Y 좌표(`$C2 < 1D`)로 고릅니다(코드 읽기).
- 목록은 종류 0 이 11개, 1 이 15개, 2 가 17개, 3 이 5개이고 `04:FBDD`~`04:FD54` 에 빈틈없이 이어집니다.

## 물건 가격 (`21:A447`)

```
가격 = 23:B081[물건] × 21:A47B[23:B159[물건] & 3]
21:A47B = 1, 10, 100, 1000 (16비트 넷)
```

물건 표는 216개(`23:B081`~`23:B158`)이고, `23:B159` 와 `23:B231` 도 물건마다 1바이트입니다(`23:B231 & 07` 은 `21:A42A` 가 다른 곳에 쓰지만 뜻 미확인).
예: どうのつるぎ(`06`) = 27 × 10 = 270G, チェーンクロス(`1D`) = 12 × 100 = 1200G, やくそう(`A1`) = 8 × 1 = 8G.

## 물건 표 (`23:B081`)

물건 216개(`00`~`D7`)의 속성이 1바이트 표 9개로 나란히 있습니다. 표 k 의 물건 i 는 `23:B081 + k*D8 + i` 입니다.

| k | 시작 | 뜻 | 확인 |
| --- | --- | --- | --- |
| 0 | `23:B081` | 가격 바탕 | 가격 17개 |
| 1 | `23:B159` | bit0-1 가격 배수, 나머지 플래그(미확인) | 가격 17개 |
| 2 | `23:B231` | bit0-2 장비 칸: 0 무기 70, 1 갑옷 51, 2 방패 17, 3 투구 21, 4 도구 50, 5~7 장신구 7 | 목록·이름으로 |
| 3·4 | `23:B309`·`23:B3E1` | 미확인 | |
| 5 | `23:B4B9` | 공격력(무기) / 수비력(갑옷·방패·투구) | 무기 4개, 갑옷 2개 |
| 6 | `23:B591` | 장비할 수 있는 인물 비트. bit7 = 주인공 | 무기 6개 |
| 7·8 | `23:B669`·`23:B741` | 미확인 | |

표 9개는 `23:B818` 에서 끝납니다. 확인은 상점 화면의 「こうげきりょく」「しゅびりょく」 미리보기로 했습니다.
ひのきのぼう(공격력 2)를 든 주인공이 13 이라 기본값은 11 이고, たけのやり 16(5)·かしのつえ 20(9)·どうのつるぎ 24(13) 으로 나왔습니다.
とがったホネ(장비 비트 0)와 りりょくのつえ(bit7 꺼짐)는 「そうびできない」였습니다. ぬののふく(4)를 입은 수비력 7 에서 てつのよろい 28(25)·せいどうのよろい 24(21) 이었습니다.

## 몬스터 (`23:8000`)

몬스터 레코드는 `23:8000` 부터 25바이트씩, 이름 표 4번과 같은 순서로 236개입니다(スライム = 0). 게임은 레코드를 직접 읽지 않고
필드 읽기 루틴 `21:8B00` 의 묶음 2 로 읽습니다.

```
필드 번호 f → 21:8D96[f] = 설명자 d → 21:8C86 + d*2: [bit0-2 길이, bit3-6 묶음, bit7 간접][레코드 안 오프셋]
묶음 k 의 기준 주소 = 21:8D6A + k*3, 레코드 크기 = 21:8D8B[k]   (묶음 2 = 23:8000, 25바이트)
읽은 뒤 후처리 JMP (21:8E8C + f*2). 위 비트를 덧붙일 때는 필드 오프셋 + X + 1 바이트를 읽는다(21:A333)
```

묶음 2(몬스터) 필드는 `55`·`5B`·`5F`·`63`·`67`~`77` 입니다. 뜻을 확인한 것:

| 필드 | 값 | 뜻 | 확인 |
| --- | --- | --- | --- |
| `55` | 바이트3 \| (바이트10 & 7) << 8 | HP | 슬라임(7) 의 바이트3 을 200 으로 바꾸자 5,000프레임 동안 한 마리도 쓰러지지 않음(원래 9번) |
| `72` | 바이트5 \| 바이트6 << 8 | 경험치 | 슬라임 셋 전투의 「それぞれ　3ポイント」 |
| `73` | 바이트7 \| ((바이트8 >> 2) & 3) << 8 | 금화 | 같은 전투의 「3ゴールド」 |

나머지는 비트 배치만 압니다(코드 읽기): `63` = 바이트1 \| 바이트8 bit7 << 8, `67` = 바이트2 \| 바이트8 bit6 << 8(`1FF` 이면 `7FF`), `5F` = 바이트0, `5B` = 바이트4.

전투 모드 메시지(`24:8C39`, 색인 `24:AECD`)는 보행 모드와 같은 허프만 방식(1 → `24:9C2E`, 0 → `24:9D18`, 처음 X = `E8`, 잎은 값 & FF)이고,
글자는 이름 문자열과 같은 1바이트 부호입니다(끝 `E7`·`EF`·`FE`, `F7`·`FB` 등은 이름·숫자 자리). 승리 메시지는 `AF`(경험치)·`B0`(금화)입니다.

## 남은 것

- 몬스터 필드 `5B`·`5F`·`63`·`67`~`71`·`74`~`77` 의 뜻(공격력·수비력·민첩·행동·내성·떨어뜨리는 물건으로 보임)
- 물건 표 k1 의 플래그, k3·k4·k7·k8, 장비 비트의 나머지 인물. `21:8B00` 필드 읽기(`21:8D96`·`21:8C86`·`21:8D6A`)가 이 표들을 어떻게 쓰는지
- 목록 종류 4(`04:A11A`)·5(`04:A3A2`)의 형식, 여관·교회 값
