# DQ5(SFC) 맵 구조 분석

기준 롬: `rom/dq5.sfc`(README 의 SHA-1). 주소는 LoROM CPU 주소, RAM 은 `7E:xxxx`(직접 페이지 D=0 기준이라 `$BC` 는 `7E00BC`).
도구: MesenCE `--testrunner` + `tools/lua/*.lua`, 디스어셈블은 `krpatch snes dis --mapper lorom`.

## 맵 번호

`$BC`(그룹)·`$BD`(그룹 안 번호) 두 바이트가 맵 번호다. 오프닝 글래스트 성 출산 방이 `$BC=02, $BD=07`.

- `$BC < $50`: 마을·성·던전(이하 「실내 맵」)
- `$BC ≥ $50`: 필드(월드맵). 별도 경로(`1F:CEB6` 표, 좌표 기반 청크)라 아직 보지 않았다.

## 실내 맵 포인터 (`01:92E2`)

```
DB      = $0F
$1823   = $16        ; 블록 정의 뱅크
$1824   = $13        ; 타일 그래픽 뱅크, $1825 = $8000 시작
$B1-$B3 = 2A:8781    ; 팔레트로 추정(018C45 가 2A8781- 를 읽음)
Y       = 0F:8ED7[$BC*2]          ; 그룹 표(16비트 포인터, 뱅크 0F)
$A5-$A7 = long 0F:(Y + $BD*3)     ; 맵 데이터 포인터
```

그룹 표는 `$BC=00`~`35` 가 유효하다(`35` 는 4개). 맵은 약 330개, 데이터는 뱅크 `$18`~`$1E`.
예: `$BC=02` 그룹 표 `0F:8B17`, 11개, `$BD=07` → `18:E171`.

## 맵 데이터

맵 데이터 앞부분은 머리(크기 등, 아직 미해독)이고 `01:A79A` 가 뒤따르는 배치 비트스트림을 푼다.
`$BF`=폭, `$C0`=높이(셀 단위), `$183F`=폭×높이. 예시 맵은 `18:E17A` 부터 약 `$1A6` 바이트를 읽는다.

### 배치 비트스트림 (`01:A824` 루프)

- 비트는 바이트의 MSB 부터 읽는다(`01:AC66`, 상태 `$81`, 포인터 `$A5-$A7`, 뱅크 끝에서 다음 뱅크 `$8000` 으로 넘어감).
- `01:AEA4` 는 가변 길이 수를 읽는다(형식 미해독).
- 명령(앞 비트):
  - `0`   → 수 하나를 읽고 셀 하나를 채운다(`01:A839` → `01:A9DC`)
  - `10`  → 블록 하나를 놓는다(`01:A8E4` → `01:8ACB`)
  - `110` → 사각형 범위를 채운다(`01:A858`, 폭으로 나눠 좌표 계산)
  - `111` → 끝

결과는 `7EC000-7EF0FF`(뒤로 `7F` 뱅크까지) 셀 버퍼에 들어간다. 맵 전환 때 `01:9932` 등이 `7EC000-7EFFFF`·`7F0000-7FFFFF`·`7E6000-7E7FFF` 를 비운다.

### 블록 (`01:8ABB` / `01:8ACB`)

블록 번호 → `7EA000`/`7EB000` 의 16비트 포인터(뱅크 `$1823`).

```
+0  bit0-2 폭-1, bit3-5 높이-1, bit6-7 플래그
+1  bit4-7 종류($99), bit0-3 ($85)
+2  팔레트·우선순위($83)
+3  폭×높이 개의 16비트: bit0-11 CHR 번호, bit14-15 뒤집기
```

CHR 이 아직 올라가지 않았으면(`7E6000[chr]==0`) `01:8C15` 가 타일 그래픽(`13:8000-15:E87F`, `01:8C62` 에서 읽음)을 가져온다.
예시 맵은 블록 114개를 놓았다.

## 그 밖에 맵 전환 때 읽는 데이터

| 읽는 PC | 범위 | 추정 |
| --- | --- | --- |
| `1F:D2B3` 등 | `04:8271-2B:9AE6`, `0C:8000-0E:B970` | 압축 그래픽 풀기 |
| `01:B8AE-B8DA` | `18:E326-18:E484` | 맵 데이터 뒷부분(사람·이벤트 배치로 추정) |
| `17:9818` | `17:982F-17:9A59` | 미확인 |
