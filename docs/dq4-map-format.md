# DQ4(FC) 마을·던전 맵

필드(세계 지도)가 아닌 맵 269개의 블록 배치와 출구 표입니다. 디코더는 [tools/dq4map.py](../tools/dq4map.py), 실험 과정은 [2026-10-25-02 일지](journal/dq4/2026-10-25-02-map.md) 에 있습니다. 주소 표기는 [dq4-ram-format.md](dq4-ram-format.md) 를 따릅니다.

## 장소 번호

맵은 **(그룹, 순번)** 두 바이트로 가리킵니다. 지금 있는 곳은 RAM `$63`(그룹)·`$64`(순번)입니다. 예: 바트랜드 성 앞마당은 `02/00`, 왕좌의 방은 `02/01` 입니다.

| 표 | 위치 | 내용 |
| --- | --- | --- |
| 그룹 표 | `17:$B181`(`BRK 81 7F` = 뱅크 17 함수 1 의 주소) | 그룹마다 레코드 목록의 16비트 포인터. `FFFF` 로 끝남(그룹 `00`~`49`) |
| 레코드 | 그룹 포인터 + 순번 × 3 | 맵 번호 1바이트, 맵 데이터 포인터 2바이트 |

맵 번호는 레코드 첫 바이트이고 RAM `$0550`·`$0028` 에 들어갑니다(`08:$B708`, `0F:$E94E`). 269개 맵에 70가지 값뿐이라 장소가 아니라 맵 종류(지형 세트)로 보입니다(예: `03` 을 쓰는 맵이 29개).

맵 데이터는 (그룹, 순번) 순서로 뱅크 `09` → `0A` → `0B` 에 이어 붙어 있습니다. 뱅크는 `0F:$E9AB` 가 정합니다: `(2C,08)` 미만이면 `09`, `(45,04)` 미만이면 `0A`, 나머지 `0B`.

## 맵 데이터

머리 3바이트 뒤에 비트열이 옵니다(`0F:$E957`).

| 바이트 | 내용 |
| --- | --- |
| 0 | 폭(블록 수) |
| 1 | 높이 |
| 2 | bit7-6 + 2 = 블록 값의 비트 수, bit4-0 → RAM `$0520`(뜻은 모름) |

비트열은 바이트마다 bit7 부터 읽습니다(`0F:$E618`). 위치는 `폭 × 높이 − 1` 을 나타내는 데 필요한 비트 수(왕좌의 방 32×36 이면 11비트)로, 왼쪽 위부터 가로로 센 칸 번호입니다. 포인터가 `$BFD8` 에 닿으면 다음 뱅크로 넘어갑니다(뱅크 `0B` 는 `$801A` 부터).

해제 결과는 RAM `$7800` 부터 폭 × 높이 바이트입니다. 한 바이트에 아래 5비트 블록 번호, 위 3비트 속성이 들어갑니다.

### 첫 패스: 블록 번호

1. 블록 비트 수만큼 읽은 값으로 맵 전체를 채운다(`$E5BF`).
2. 2비트 명령을 되풀이한다(`$E588`).

| 명령 | 하는 일 |
| --- | --- |
| `0` | 쓸 값을 정한다(`$E672`). 값 하나를 읽고, 이어지는 2비트가 `0` 이 아니면 그 명령으로. `0` 이면 1비트를 더 읽어 1 이면 **패스 끝**, 0 이면 값 셋을 더 읽어 **2×2 무늬**(왼쪽 위·오른쪽 위·왼쪽 아래·오른쪽 아래) |
| `1` | 사각형(`$E6A1`). 위치 둘(왼쪽 위, 오른쪽 아래)을 읽어 채운다. 2×2 무늬면 2칸 간격으로 |
| `2` | 길(`$E793`). 위치와 방향 2비트(0 위, 1 오른쪽, 2 아래, 3 왼쪽)를 읽고 점을 찍은 뒤, 1비트씩 읽어 0 이면 그 방향으로 한 칸(2×2 무늬면 두 칸) 가며 찍는다. 1 이면 2비트 부명령: `0` 오른쪽으로 돌고 한 칸, `1` 왼쪽으로 돌고 한 칸, `2` 갈림길(1비트로 방향을 정하고 지금 자리를 쌓아 둔 뒤 돌고 한 칸), `3` 1비트가 0 이면 새 길(위치·방향부터), 1 이면 쌓아 둔 자리로 돌아감(쌓인 것이 없으면 길 끝) |
| `3` | 점 하나(`$E78A`). 위치를 읽어 찍는다 |

### 둘째 패스: 위 3비트

첫 패스가 끝나면 2비트를 읽어(`$E5A3`) 0 이 아니면 그 수를 값의 비트 수로 삼아 같은 명령을 한 번 더 돌립니다. 이때는 칸의 위 3비트만 바꿉니다(`값 << 5`). 사각형 명령은 2×2 무늬여도 한 칸 간격으로 씁니다(`$E6F7`).

해제가 끝나면 `$E562` 부터 BRK 로 뱅크 `1E`·`1D`·`1B` 의 뒤처리를 부릅니다. 아래 확인은 그 전(`$E560`) 시점입니다.

## 출구 표 `$05A0`

현재 맵의 출구가 7바이트씩 들어 있고 첫 바이트 `FF` 로 끝납니다.

| 오프셋 | 내용 |
| --- | --- |
| +0, +1 | 출구 칸 X, Y |
| +2, +3 | 목적지 그룹·순번(→ `$63`, `$64`) |
| +4, +5 | 도착 X, Y |
| +6 | 모름(`82`, `80` 을 봄) |

왕좌의 방(`02/01`)의 두 항목은 목적지 `02/00`, 앞마당(`02/00`)의 두 항목은 `02/01` 이었고, 걸어서 오간 결과와 같습니다.

## 확인

- `tools/lua/fc/atpc.lua` 로 해제 직후(`0F:$E560`) RAM 을 덤프해 비교: 앞마당 `02/00`(38×41) 1558바이트 0 차이, 왕좌의 방 `02/01`(32×36) 1152바이트 0 차이.
- `tools/dq4map.py check`: 맵 269개를 모두 풀었을 때 268곳 모두 해제가 끝난 자리가 다음 맵의 시작 포인터와 같음.

## 남은 것

- 블록 번호(5비트)와 위 3비트가 어떤 그래픽·통행·이벤트가 되는지(맵 번호별 블록 정의).
- 해제 뒤 BRK 뒤처리(뱅크 `1E` 함수 `11`·`20`·`29`, `1D` 함수 `03`, `1B` 함수 `01`)가 버퍼를 바꾸는지.
- 출구 표 `$05A0` 을 채우는 롬 데이터, +6 의 뜻. 인물 배치.
- `$0520` 의 뜻. 필드(세계 지도)의 형식.
